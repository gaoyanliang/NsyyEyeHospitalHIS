**设计说明：**

| 决策 | 理由 |
|---|---|
| **不使用物理外键** | 跨模块（M16-02 → M16-01 → M07/M04）已有大量逻辑关联，物理外键会导致分库分表与批处理困难。引用完整性由应用层 + 定时校验任务保证 |
| `settlement_ids` 用 JSONB | 一次支付可对应多张结算单（合并收款），单独建关联表会增加 JOIN；JSONB 配合 GIN 索引可满足 `@>` 查询 |
| `cash_effect` 与 `pay_amount` 分离 | 扫码支付 399 元，`pay_amount = 399`，但现金箱影响 `cash_effect = 0`。这两个数不能混 |
| 点钞明细存 JSONB | 面额固定 8 种，建表收益低；且交班后不可改，JSONB 快照语义正合适 |
| 日报表物理落库 | 财务查 3 年日报时不能扫全年流水，必须预聚合 |

### 4.2 表：`m16_cashier_session`（收费员班次表）

**用途：** 记录收费员从开班到交班的一次完整收银周期，是现金对账的基本单位。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | IDENTITY | 主键 |
| `session_no` | VARCHAR(32) | N | — | 班次号，格式 `B` + `YYYYMMDD` + 4 位序号，如 `B202610210001` |
| `operator_id` | BIGINT | N | — | 收费员职工 ID，引用 `mdm_employee.id` |
| `operator_name` | VARCHAR(64) | N | — | 收费员姓名快照 |
| `operator_no` | VARCHAR(32) | Y | NULL | 收费员工号快照 |
| `workstation_id` | BIGINT | N | — | 窗口/工位 ID，引用 `md_workstation.id` |
| `workstation_name` | VARCHAR(64) | N | — | 窗口名称快照，如「1 号收费窗口」 |
| `dept_id` | BIGINT | Y | NULL | 所属收费科室 ID |
| `dept_name` | VARCHAR(64) | Y | NULL | 科室名称快照 |
| `business_date` | DATE | N | — | 营业日期（跨日班次仍记开班日） |
| `opening_float` | NUMERIC(12,2) | N | 0.00 | 备用金（开班零钞），`CHECK >= 0` |
| `cash_income` | NUMERIC(12,2) | N | 0.00 | 现金收入合计 |
| `cash_expense` | NUMERIC(12,2) | N | 0.00 | 现金支出合计（现金退费） |
| `expected_cash` | NUMERIC(12,2) | N | 0.00 | 应有现金 = 备用金 + 现金收入 − 现金支出 |
| `actual_cash` | NUMERIC(12,2) | Y | NULL | 实有现金（点钞结果），未交班为 NULL |
| `difference` | NUMERIC(12,2) | Y | NULL | 差异 = 实有 − 应有 |
| `difference_type` | VARCHAR(16) | Y | NULL | `EVEN` 相符 / `OVER` 长款 / `SHORT` 短款 |
| `shortage_reason` | VARCHAR(500) | Y | NULL | 长短款说明，差异非 0 时必填 |
| `non_cash_amount` | NUMERIC(12,2) | N | 0.00 | 非现金收款合计（微信/支付宝/POS/储值） |
| `non_cash_detail` | JSONB | Y | NULL | 非现金分渠道明细 `{"WECHAT": 4200.00, "ALIPAY": 1250.00}` |
| `denomination_json` | JSONB | Y | NULL | 点钞明细 `[{"denom": 100, "count": 30}]` |
| `settle_count` | INTEGER | N | 0 | 收款笔数 |
| `refund_count` | INTEGER | N | 0 | 退款笔数 |
| `total_income` | NUMERIC(12,2) | N | 0.00 | 本期总收入（含非现金） |
| `total_refund` | NUMERIC(12,2) | N | 0.00 | 本期总退款 |
| `status` | VARCHAR(16) | N | `'OPEN'` | `OPEN` 进行中 / `CLOSED` 已关闭 / `VOID` 已作废 |
| `opened_at` | TIMESTAMP | N | `CURRENT_TIMESTAMP` | 开班时间 |
| `closed_at` | TIMESTAMP | Y | NULL | 交班时间 |
| `closed_by` | BIGINT | Y | NULL | 实际执行交班的人（可能为主管代交） |
| `closed_by_name` | VARCHAR(64) | Y | NULL | 交班人姓名快照 |
| `handover_to` | BIGINT | Y | NULL | 交接给谁（跨班现金交接） |
| `is_offline` | BOOLEAN | N | `FALSE` | 该班次是否启用过离线模式 |
| `remark` | VARCHAR(500) | Y | NULL | 备注 |
| `device_fingerprint` | VARCHAR(128) | Y | NULL | 开班设备指纹 |
| `trace_id` | VARCHAR(64) | Y | NULL | 链路追踪 ID |
| `created_at` | TIMESTAMP | N | `CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | BIGINT | Y | NULL | 创建人 |
| `updated_at` | TIMESTAMP | N | `CURRENT_TIMESTAMP` | 更新时间（触发器维护） |
| `updated_by` | BIGINT | Y | NULL | 更新人 |
| `is_deleted` | BOOLEAN | N | `FALSE` | 逻辑删除标记 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| `pk_m16_cashier_session` | PRIMARY KEY | `id` | — |
| `uk_m16_session_no` | UNIQUE | `session_no` | 班次号唯一 |
| `uk_m16_session_ws_open` | UNIQUE PARTIAL | `workstation_id` WHERE `status='OPEN'` | **一窗口同时只允许一个在岗班次** |
| `uk_m16_session_op_open` | UNIQUE PARTIAL | `operator_id` WHERE `status='OPEN'` | **一收费员同时只允许一个在岗班次** |
| `idx_m16_session_op_date` | BTREE | `operator_id`, `business_date` DESC | 收费员查历史班次 |
| `idx_m16_session_date` | BTREE | `business_date`, `status` | 日报按日汇总 |
| `idx_m16_session_ws_date` | BTREE | `workstation_id`, `business_date` | 窗口日报 |
| `idx_m16_session_status` | BTREE | `status`, `opened_at` | 查找超时未交班班次 |
| `idx_m16_session_diff` | BTREE | `difference_type`, `business_date` WHERE `difference <> 0` | 长短款审查 |

**约束说明**

```sql
-- 班次状态枚举
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_status
    CHECK (status IN ('OPEN', 'CLOSED', 'VOID'));

-- 差异类型枚举
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_diff_type
    CHECK (difference_type IS NULL
           OR difference_type IN ('EVEN', 'OVER', 'SHORT'));

-- 备用金不可为负
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_float
    CHECK (opening_float >= 0);

-- 各金额字段不可为负
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_amounts
    CHECK (cash_income >= 0 AND cash_expense >= 0
           AND non_cash_amount >= 0 AND total_income >= 0
           AND total_refund >= 0);

-- 交班后必须有实有现金与差异
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_closed_fields
    CHECK (status <> 'CLOSED'
           OR (actual_cash IS NOT NULL AND difference IS NOT NULL
               AND difference_type IS NOT NULL AND closed_at IS NOT NULL));

-- 差异非 0 必须有说明
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_shortage_reason
    CHECK (difference IS NULL OR difference = 0
           OR (shortage_reason IS NOT NULL AND length(trim(shortage_reason)) > 0));

-- 应有现金 = 备用金 + 现金收入 − 现金支出（交班后校验）
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_expected
    CHECK (status <> 'CLOSED'
           OR expected_cash = opening_float + cash_income - cash_expense);

-- 差异 = 实有 − 应有
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_difference
    CHECK (status <> 'CLOSED'
           OR difference = actual_cash - expected_cash);

-- 交班时间不早于开班时间
ALTER TABLE m16_cashier_session
    ADD CONSTRAINT ck_m16_session_time
    CHECK (closed_at IS NULL OR closed_at >= opened_at);

COMMENT ON TABLE m16_cashier_session IS '收费员班次表：一次开班到交班的收银周期';
COMMENT ON COLUMN m16_cashier_session.session_no IS '班次号，格式 B+YYYYMMDD+4位序号';
COMMENT ON COLUMN m16_cashier_session.opening_float IS '备用金：开班时抽屉里的零钞金额';
COMMENT ON COLUMN m16_cashier_session.expected_cash IS '应有现金=备用金+现金收入-现金支出';
COMMENT ON COLUMN m16_cashier_session.actual_cash IS '实有现金：交班点钞结果';
COMMENT ON COLUMN m16_cashier_session.difference IS '差异=实有现金-应有现金，正为长款负为短款';
COMMENT ON COLUMN m16_cashier_session.cash_effect IS '该流水对现金箱的影响额，非现金支付为 0';
COMMENT ON COLUMN m16_cashier_session.denomination_json IS '点钞明细 JSON 数组，元素含 denom 与 count';
COMMENT ON COLUMN m16_cashier_session.is_offline IS '该班次期间是否曾启用离线收费模式';
```

**状态机**

```
        开班
         │
         ▼
    ┌─────────┐  交班（差异=0 或已填说明）   ┌──────────┐
    │  OPEN   ├────────────────────────────►│  CLOSED  │
    │ 进行中   │                             │ 已关闭    │
    └────┬────┘                             └──────────┘
         │                                        ▲
         │ 异常作废（需主管权限）                   │
         ▼                                        │
    ┌─────────┐                                   │
    │  VOID   │───────────────────────────────────┘
    │ 已作废   │   （作废后重开新班次）
    └─────────┘
```

| 当前 | 事件 | 目标 | 触发方 | 校验 |
|---|---|---|---|---|
| `OPEN` | 交班 | `CLOSED` | 收费员 / 主管 | 无 PENDING 支付；差异非 0 需说明 |
| `OPEN` | 作废 | `VOID` | 主管 | 需 `m16:cashier:manage`；需说明原因 |
| `CLOSED` | — | — | — | 终态，不可再变更 |
| `VOID` | — | — | — | 终态 |

**量级估算**

| 项 | 估算 | 依据 |
|---|---|---|
| 收费员数 | 20 人 | 二级医院门诊收费窗口 8~12 个，含替班 |
| 每人每日班次 | 1~2 | 早班/晚班 |
| 年记录数 | **14,600 行/年** | 20 × 2 × 365 |
| 单行大小 | ≈ 800 B（含 JSONB） | — |
| 年增长 | ≈ 11 MB | 可忽略 |

**分区：** 不分区。10 年累计约 15 万行，单表完全可承受。

```
   └────┬────┘
        │
        ├── 渠道返回失败 ──────► ┌──────────┐

        │                       └──────────┘
```

|---|---|---|---|---|

| `PENDING` | 收银员取消 | `CANCELLED` | 收银台 | 只允许取消 `PENDING` |
| `SUCCESS` | — | — | — | 终态，退费走 M16-08 |

### 4.4 表：`m16_cashier_record`（班次收款流水表）

**用途：** 班次期间每一笔影响现金箱的操作记录。这是**交班对账的唯一依据**。

**为什么不能直接查 `m16_payment`：**

| 问题 | 说明 |
|---|---|
| 退费不在 `m16_payment` | 退费是 `m16_refund`（M16-08），班次需要汇总两者 |
| 调整/交接不在 `m16_payment` | 主管调库、跨班交接需要独立记录 |
| `cash_effect` 语义 | 支付表的 `pay_amount` 不等于现金箱变动 |

**所以 `m16_cashier_record` 是"班次视角的流水账"，与支付表是 1:N 但语义不同。**

| 字段名 | 类型 | 允许空 | 默认 | 说明 |

| `session_no` | VARCHAR(32) | N | — | 班次号快照 |
| `record_no` | INTEGER | N | — | 班次内流水序号，从 1 递增 |
| `record_type` | VARCHAR(16) | N | — | `PAY` 收款 / `REFUND` 退款 / `ADJUST` 调整 / `HANDOVER` 交接 |
| `payment_id` | BIGINT | Y | NULL | 支付流水 ID（`record_type='PAY'` 时必填） |
| `payment_no` | VARCHAR(32) | Y | NULL | 支付流水号快照 |

```sql
-- 流水类型枚举
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_type
    CHECK (record_type IN ('PAY', 'REFUND', 'ADJUST', 'HANDOVER'));

-- 收款流水必须有支付单，退款流水必须有退款单
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_ref
    CHECK (
        (record_type = 'PAY' AND payment_id IS NOT NULL)
        OR (record_type = 'REFUND' AND refund_id IS NOT NULL)
        OR (record_type IN ('ADJUST', 'HANDOVER'))
    );

-- 退款金额必须为负
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_refund_sign
    CHECK (record_type <> 'REFUND' OR pay_amount < 0);

-- 收款金额必须为正
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_pay_sign
    CHECK (record_type <> 'PAY' OR pay_amount > 0);

-- 现金流水的 cash_effect 必须与金额方向一致
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_cash
    CHECK (
        pay_method <> 'CASH'
        OR (record_type = 'PAY' AND cash_effect = pay_amount)
        OR (record_type = 'REFUND' AND cash_effect = pay_amount)
        OR record_type IN ('ADJUST', 'HANDOVER')
    );

-- 非现金流水 cash_effect 恒为 0
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_noncash
    CHECK (pay_method = 'CASH' OR record_type IN ('ADJUST', 'HANDOVER')
           OR cash_effect = 0);

-- 调整与交接必须填备注
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_remark
    CHECK (record_type NOT IN ('ADJUST', 'HANDOVER')
           OR (remark IS NOT NULL AND length(trim(remark)) > 0));

-- 班次内流水序号必须为正
ALTER TABLE m16_cashier_record
    ADD CONSTRAINT ck_m16_record_seq
    CHECK (record_no >= 1);

COMMENT ON TABLE m16_cashier_record IS '班次收款流水表：班次期间每一笔影响现金箱的操作，交班对账的唯一依据';
COMMENT ON COLUMN m16_cashier_record.record_no IS '班次内流水序号，从1递增，与session_id构成唯一';
COMMENT ON COLUMN m16_cashier_record.record_type IS 'PAY收款/REFUND退款/ADJUST调整/HANDOVER交接';
COMMENT ON COLUMN m16_cashier_record.pay_amount IS '交易金额，收款为正退款为负';
COMMENT ON COLUMN m16_cashier_record.cash_effect IS '对现金箱的影响额：现金收款为正，现金退款为负，非现金恒为0';
COMMENT ON COLUMN m16_cashier_record.is_offline IS '是否来自离线模式补传';
```

```sql
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_status
    CHECK (status IN ('PENDING', 'SYNCED', 'CONFLICT', 'FAILED'));

-- 支付金额必须为正
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_amount
    CHECK (pay_amount > 0 AND received_amount >= pay_amount);

-- 找零 = 实收 − 支付
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_change
    CHECK (change_amount = received_amount - pay_amount);

-- 已补传必须有支付流水与时间
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_synced
    CHECK (status <> 'SYNCED'
           OR (payment_id IS NOT NULL AND synced_at IS NOT NULL));

-- 冲突必须有原因
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_conflict
    CHECK (status <> 'CONFLICT'
           OR (conflict_reason IS NOT NULL
               AND length(trim(conflict_reason)) > 0));

-- 失败必须有原因
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_fail
    CHECK (status <> 'FAILED'
           OR (fail_reason IS NOT NULL AND length(trim(fail_reason)) > 0));

-- 设备指纹不可为空
ALTER TABLE m16_offline_record
    ADD CONSTRAINT ck_m16_offline_device
    CHECK (length(trim(device_fingerprint)) > 0);
```

## 附录 B 金额与计数口径

| 字段 | 口径 | 计算公式 |
|---|---|---|
| `opening_float` | 备用金 | 开班录入 |
| `cash_income` | 现金收入 | Σ `m16_cashier_record.cash_effect` WHERE `record_type='PAY'` |
| `cash_expense` | 现金支出 | ABS(Σ `cash_effect` WHERE `record_type='REFUND'`) |
| `expected_cash` | 应有现金 | `opening_float + cash_income - cash_expense` |
| `actual_cash` | 实有现金 | Σ(`denom` × `count`) |
| `difference` | 差异 | `actual_cash - expected_cash` |
| `non_cash_amount` | 非现金收款 | Σ `pay_amount` WHERE `pay_method <> 'CASH'` AND `record_type='PAY'` |
| `total_income` | 总收入 | `cash_income + non_cash_amount` |
| `cash_effect` | 现金箱影响 | 现金收款 = `pay_amount`；现金退款 = `pay_amount`（负）；非现金 = 0 |

**关键：`pay_amount` 与 `cash_effect` 不是一回事。** 扫码支付 399 元，`pay_amount = 399`，`cash_effect = 0`。前者进日报，后者进现金箱对账。
