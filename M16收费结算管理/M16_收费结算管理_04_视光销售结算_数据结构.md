## 4. 数据结构设计

### 4.1 ER 关系图

```
                        ┌──────────────────────────────┐
                        │      m16_optical_order       │
                        │      视光销售单（主表）        │
                        │  order_no / status / total   │
                        └───┬────────┬─────────┬───────┘
                            │1       │1        │1
                            │        │         │
                 ┌──────────▼──┐  ┌──▼─────────▼──────────┐
                 │m16_optical_ │  │m16_optical_settlement_│
                 │   item      │  │        rel            │
                 │ 明细（N）    │  │  结算关联（N）          │
                 └─────────────┘  └──┬──────────┬─────────┘
                                     │1         │1
                                     │          │
                            ┌────────▼───┐  ┌───▼────────────────┐
                            │m16_settle- │  │m16_optical_payment │
                            │ ment       │  │ 收款记录（N）        │
                            │ (M16-01)   │  └────────────────────┘
                            └────────────┘
                            ┌────────────┐
                            │m16_payment │
                            │ (M16-02)   │
                            └────────────┘

                 ┌──────────────────────┐    ┌────────────────────────┐
                 │ m16_optical_return   │    │m16_optical_daily_summary│
                 │ 退换货（N，1 单可多退）│    │ 日报预聚合（按日×销售员） │
                 └──────────────────────┘    └────────────────────────┘

                 ┌──────────────────────┐
                 │  m16_optical_config  │  参数配置（独立）
                 └──────────────────────┘
```

**设计说明：**

1. **一单多结算**：`m16_optical_settlement_rel` 是与 M16-01 结算单的多对一关联。定金、尾款各生成一张结算单，退换产生的冲红结算单也挂在这张表。用关联表而不是在销售单上挂 `settlement_id` 字段，是因为订单与结算单是 1:N。

2. **收款记录与结算关联分离**：`m16_optical_settlement_rel` 记录"哪张结算单属于哪一阶段"，`m16_optical_payment` 记录"这笔结算收了多少钱、走的什么渠道"。这样一张结算单被拆成多次支付（混合支付）时，关联表仍是一行，收款表是多行。

3. **退换货不在销售单上打平**：`m16_optical_return` 独立存退换单，销售单只置 `status='RETURNED'`。原因是一次销售可能部分退换多次（先退镜片、后换镜架），需要保留每次退换的判定依据与审批链。

4. **无物理外键**：与 M16 全局策略一致，关联靠应用层校验 + 每日核对任务。`m16_optical_item.order_id`、`m16_optical_settlement_rel.order_id` 等均不建 `FOREIGN KEY`。

**约束说明：**

```sql
-- 销售单号唯一
CREATE UNIQUE INDEX uk_m16_optical_order_no
    ON m16_optical_order (order_no);

-- 内部契约幂等：一个 M10 单据只能生成一张销售单
CREATE UNIQUE INDEX uk_m16_optical_source
    ON m16_optical_order (source, source_id)
    WHERE source IS NOT NULL AND source_id IS NOT NULL
      AND is_deleted = FALSE;

-- 状态枚举
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_status
    CHECK (status IN ('DRAFT', 'PARTIAL', 'PAID', 'DELIVERED',
                      'RETURNED', 'CANCELLED'));

-- 加工状态枚举
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_proc
    CHECK (processing_status IN ('NONE', 'PENDING', 'PROCESSING',
                                 'OUTSOURCING', 'READY', 'DELIVERED'));

-- 金额恒等式：应收 = 折扣前 - 折扣
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_total
    CHECK (total_amount = gross_amount - discount_amount);

-- 金额非负
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_nonneg
    CHECK (gross_amount >= 0 AND discount_amount >= 0
       AND total_amount >= 0 AND deposit_amount >= 0
       AND paid_amount >= 0 AND refunded_amount >= 0);

-- 折扣不得超过原价
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_discount
    CHECK (discount_amount <= gross_amount);

-- 定金比例必须在 [0, 1]
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_ratio
    CHECK (deposit_ratio >= 0 AND deposit_ratio <= 1);

-- 定金不得超过应收总额
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_deposit_limit
    CHECK (deposit_amount <= total_amount);

-- 已收不得超过应收
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_paid_limit
    CHECK (paid_amount <= total_amount);

-- 已退不得超过已收
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_refund_limit
    CHECK (refunded_amount <= paid_amount);

-- 顾客识别：有患者 ID 或有手机号，二者必居其一
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_customer
    CHECK (patient_id IS NOT NULL OR customer_phone IS NOT NULL);

-- 顾客姓名必填
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_name
    CHECK (length(btrim(customer_name)) > 0);

-- 状态与时间一致：付清必须有付清时间
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_paid_at
    CHECK ((status IN ('PAID', 'DELIVERED', 'RETURNED'))
           = (paid_at IS NOT NULL));

-- 状态与时间一致：交付必须有交付时间
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_delivered_at
    CHECK ((status IN ('DELIVERED', 'RETURNED'))
           = (delivered_at IS NOT NULL));

-- 质保卡号与交付同生命周期
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_warranty_card
    CHECK ((delivered_at IS NOT NULL) = (warranty_card_no IS NOT NULL));

-- 作废必须有原因
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_cancel
    CHECK ((status = 'CANCELLED') = (cancelled_at IS NOT NULL));

ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_cancel_reason
    CHECK ((status = 'CANCELLED') = (cancel_reason IS NOT NULL));

-- 退换必须有时间
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_returned
    CHECK ((status = 'RETURNED') = (returned_at IS NOT NULL));

-- 到货时间与加工状态一致
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_arrived
    CHECK (processing_status <> 'READY' OR arrived_at IS NOT NULL);

-- 预计到货日只对有加工的商品有意义
ALTER TABLE m16_optical_order
    ADD CONSTRAINT ck_m16_optical_order_expected
    CHECK (processing_status = 'NONE' OR expected_ready_date IS NOT NULL);
```

> **⚠️ 关于 `ck_m16_optical_order_total`：**
>
> 这条 CHECK 把"应收 = 折扣前 − 折扣"变成数据库层面的硬约束。应用层任何一次更新只要三个字段不同时赋值，写入就直接失败。
>
> 好处是**防止折扣计算错位**（历史系统里出现过改折扣不改应收的事故）；代价是应用层修改任一折扣相关的字段都必须同时算好三个值。SQLAlchemy 的 ORM 更新是整行 UPDATE，天然满足。

> **⚠️ 关于 `ck_m16_optical_order_paid_at`：**
>
> 这条看起来只是"状态与时间一致"，它真正的作用是**防止状态机跳过付款直接置 PAID**。任何把 `status` 改成 `PAID` 却不写 `paid_at` 的操作都会被数据库拒绝。
>
> 注意：`RETURNED` 状态要求 `paid_at` 非空，因为退换的前提是已经付过钱。

**状态机：**

```
                        ┌──────────┐
              开单 ────► │  DRAFT   │ 草稿
                        └────┬─────┘
                   收定金 │    │ 收全款
                          ▼    ▼
                   ┌─────────┐ ┌────────┐
                   │ PARTIAL │ │  PAID  │ 已付清
                   │ 已付定金 │ │        │
                   └────┬────┘ └───┬────┘
              收尾款 │   │          │
                     ▼   │          │
                   ┌────────┐       │
                   │  PAID  │◄──────┘
                   └────┬───┘
                  取镜 │
                        ▼
                  ┌───────────┐
                  │ DELIVERED │ 已交付
                  └─────┬─────┘
                  退换 │
                        ▼
                  ┌──────────┐
                  │ RETURNED │ 已退换
                  └──────────┘

  旁支：DRAFT ──作废──► CANCELLED（仅 DRAFT 可作废）
```

**加工状态机：**

```
     NONE（纯现货单，不进入加工）
       │
     PENDING ──开始加工──► PROCESSING ──加工完成──► READY ──取镜──► DELIVERED
        │                     │                       ▲
        └──转外协──► OUTSOURCING ──外协回厂──► PROCESSING
                        │
                        └──外协直送──► READY
```

**分区：** 不分区。表规模小，`idx_m16_optical_order_status` 与部分索引足以支撑查询。

    USING gin (product_name gin_trgm_ops);

-- 未到货的定制行（取镜前校验用）
CREATE INDEX idx_m16_optical_item_pending
    ON m16_optical_item (order_id)
    WHERE is_custom = TRUE AND arrived_at IS NULL
      AND is_deleted = FALSE;

-- 商品类型枚举
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_type
    CHECK (product_type IN ('FRAME', 'LENS', 'ACCESSORY', 'SERVICE'));

-- 眼别枚举
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_eye
    CHECK (eye_side IS NULL
           OR eye_side IN ('OD', 'OS', 'OU', 'NA'));

-- 镜片必须指明眼别，非镜片不得有眼别
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_eye_lens
    CHECK ((product_type = 'LENS') = (eye_side IS NOT NULL
                                      AND eye_side <> 'NA'));

-- 折扣率必须在 (0, 1]
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_rate
    CHECK (discount_rate > 0 AND discount_rate <= 1);

-- 折扣来源枚举
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_source
    CHECK (discount_source IS NULL
           OR discount_source IN ('MEMBER', 'COUPON', 'MANUAL', 'NONE'));

-- 数量必须为正
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_qty
    CHECK (quantity > 0);

-- 单价不得为负
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_price
    CHECK (unit_price >= 0);

-- 行级金额恒等式：折扣前 = 单价 × 数量
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_gross
    CHECK (gross_amount = ROUND(unit_price * quantity, 2));

-- 行级金额恒等式：折扣金额 = 折扣前 - 成交
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_discount
    CHECK (discount_amount = gross_amount - amount);

-- 成交金额非负
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_amount
    CHECK (amount >= 0);

-- 已退数量不得超过原数量
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_returned
    CHECK (returned_qty >= 0 AND returned_qty <= quantity);

-- 加工天数非负
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_days
    CHECK (processing_days >= 0);

-- 质保月数非负
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_warranty
    CHECK (warranty_months >= 0);

-- 定制行才有到货时间；非定制行到货时间必须为空
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_arrived
    CHECK (NOT is_custom OR arrived_at IS NULL OR processing_days >= 0);

-- 已交付行必须到货
ALTER TABLE m16_optical_item
    ADD CONSTRAINT ck_m16_optical_item_delivered
    CHECK (NOT is_delivered OR NOT is_custom OR arrived_at IS NOT NULL);
```

> **⚠️ 关于 `ck_m16_optical_item_gross` 与 `ck_m16_optical_item_discount`：**
>
> 两条 CHECK 把行级算价钉死在数据库里：
> - `gross_amount = ROUND(unit_price × quantity, 2)`
> - `discount_amount = gross_amount - amount`
>
> 加上 `m16_optical_order.ck_m16_optical_order_total`，整条金额链就是：行 → 单 → 结算，每一级都有 CHECK 兜底。**应用层算错任何一个字段，写入即失败。**

> **⚠️ 关于 `ck_m16_optical_item_eye_lens`：**
>
> 这条约束把"镜片必须有眼别，非镜片不得有眼别"变成硬约束。原因是历史上出现过镜架行了写了眼别，导致按眼别统计时镜架数量翻倍的问题。
>
> 注意：`ACCESSORY`（镜盒）如果顾客买了两只不同颜色的镜盒，不能用眼别区分，应该开两行并写 `remark`。

| 年明细行 | ≈ 60,000 |

| `idx_m16_optical_settle_order` | B-Tree | `order_id` | 按单查结算 |

-- 定金与尾款各只能有一张（退款可多张）
CREATE UNIQUE INDEX uk_m16_optical_settle_stage
    ON m16_optical_settlement_rel (order_id, settle_stage)
    WHERE settle_stage IN ('DEPOSIT', 'FINAL')
      AND is_deleted = FALSE;

-- 结算阶段枚举
ALTER TABLE m16_optical_settlement_rel
    ADD CONSTRAINT ck_m16_optical_settle_stage
    CHECK (settle_stage IN ('DEPOSIT', 'FINAL', 'REFUND'));

-- 定金与尾款金额必须为正，退款必须为负
ALTER TABLE m16_optical_settlement_rel
    ADD CONSTRAINT ck_m16_optical_settle_amount
    CHECK ((settle_stage = 'REFUND' AND amount < 0)
           OR (settle_stage <> 'REFUND' AND amount > 0));
```

> **⚠️ 关于 `uk_m16_optical_settle_stage`：**
>

```sql

    ON m16_optical_payment (payment_id)
    WHERE payment_id IS NOT NULL;

-- 支付状态枚举
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_status
    CHECK (status IN ('PENDING', 'SUCCESS', 'FAILED', 'CANCELLED'));

-- 结算阶段枚举
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_stage
    CHECK (settle_stage IN ('DEPOSIT', 'FINAL', 'REFUND'));

-- 收款为正，退款为负
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_amount
    CHECK ((settle_stage = 'REFUND' AND amount < 0)
           OR (settle_stage <> 'REFUND' AND amount > 0));

-- 现金支付必须有实收与找零，且 实收 - 金额 = 找零
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_cash
    CHECK (payment_method <> 'CASH'
           OR (received_amount IS NOT NULL
               AND change_amount IS NOT NULL
               AND received_amount - amount = change_amount));

-- 非现金的找零必须为 0 或空
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_noncash_change
    CHECK (payment_method = 'CASH'
           OR change_amount IS NULL
           OR change_amount = 0);

-- 现金实收必须 ≥ 金额
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_received
    CHECK (received_amount IS NULL OR received_amount >= amount);

-- 失败必须有原因，成功不得有原因
ALTER TABLE m16_optical_payment
    ADD CONSTRAINT ck_m16_optical_pay_fail
    CHECK ((status = 'FAILED') = (fail_reason IS NOT NULL));
```

> **⚠️ 关于 `ck_m16_optical_pay_cash`：**
>
> 现金收款的恒等式 `实收 − 金额 = 找零` 在数据库层面强制。历史上现金长短款的争议大多源于"找零算错"，这条约束让算错的插入根本进不来。

> **⚠️ 金额符号约定：**
>
> `amount` 带符号：收款为正，退款为负。这样日报只需 `SUM(amount)` 即可得到净收入，不需要按阶段分别加减。`settle_stage` 只用于展示与分类，不参与金额计算。

    ON m16_optical_return USING gin (item_ids);

    ADD CONSTRAINT ck_m16_optical_return_action
    CHECK (action IN ('EXCHANGE', 'PARTIAL_REFUND', 'FULL_REFUND'));

-- 判定结果枚举
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_decision
    CHECK (decision IN ('FULL_REFUND', 'REFUND_WITH_FEE',
                        'EXCHANGE_OR_REFUND', 'REPAIR_ONLY', 'REFUSE'));

-- 状态枚举
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_status
    CHECK (status IN ('APPROVING', 'APPROVED', 'COMPLETED',
                      'REJECTED', 'CANCELLED'));

-- 明细行不能为空
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_items
    CHECK (jsonb_array_length(item_ids) > 0);

-- 手续费率必须在 [0, 1]
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_fee
    CHECK (refund_fee_rate >= 0 AND refund_fee_rate <= 1);

-- 退款金额 = 退款基数 × (1 - 手续费率)
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_amount
    CHECK (refund_amount = ROUND(refund_base_amount
                                 * (1 - refund_fee_rate), 2));

-- 退款金额非负
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_amount_nonneg
    CHECK (refund_amount >= 0 AND refund_base_amount >= 0);

-- 拒绝的退换不允许有退款金额
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_refuse
    CHECK (decision <> 'REFUSE' OR refund_amount = 0);

-- 换新必须有新的销售单
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_exchange
    CHECK (status <> 'COMPLETED' OR action <> 'EXCHANGE'
           OR exchange_order_id IS NOT NULL);

-- 完成必须有完成时间
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_completed
    CHECK ((status = 'COMPLETED') = (completed_at IS NOT NULL));

-- 审批通过必须有审批人与时间
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_approved
    CHECK (status IN ('APPROVING', 'CANCELLED')
           OR (approved_by IS NOT NULL AND approved_at IS NOT NULL));

-- 驳回必须有原因
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_reject
    CHECK ((status = 'REJECTED') = (reject_reason IS NOT NULL));

-- 质量问题必须填问题描述
ALTER TABLE m16_optical_return
    ADD CONSTRAINT ck_m16_optical_return_issue
    CHECK (NOT is_quality_issue OR length(btrim(coalesce(issue_desc, ''))) > 0);
```

> **⚠️ 关于 `ck_m16_optical_return_amount`：**
>
> 退款金额不是独立输入的，而是由"基数 ×（1 − 手续费率）"推导。这条 CHECK 保证**退换金额永远可复算**：事后审计只要看 `refund_base_amount` 与 `refund_fee_rate` 就能验证 `refund_amount` 是否正确，不需要还原当时的商品价格。

> **⚠️ 判定快照字段：**
>
> `is_processed` / `is_quality_issue` / `days_since_order` / `in_warranty` 都是**判定当时的快照**，不是实时计算值。原因：退换纠纷常发生在数月之后，届时商品早已交付，无法从当前数据还原"当时是否在质保期"。存快照才可解释。

    ON m16_optical_daily_summary (stat_date, COALESCE(seller_id, 0));

-- 金额恒等式
ALTER TABLE m16_optical_daily_summary
    ADD CONSTRAINT ck_m16_optical_daily_total
    CHECK (total_amount = gross_amount - discount_amount);

-- 计数与金额非负
ALTER TABLE m16_optical_daily_summary
    ADD CONSTRAINT ck_m16_optical_daily_nonneg
    CHECK (order_count >= 0 AND item_count >= 0
       AND gross_amount >= 0 AND discount_amount >= 0
       AND total_amount >= 0 AND paid_amount >= 0
       AND unpaid_amount >= 0 AND refund_amount >= 0
       AND return_count >= 0 AND deposit_order_count >= 0);

-- 客单价 = 总金额 / 单数（单数为 0 时客单价必须为 0）
ALTER TABLE m16_optical_daily_summary
    ADD CONSTRAINT ck_m16_optical_daily_avg
    CHECK ((order_count = 0 AND avg_order_amount = 0)
           OR (order_count > 0
               AND avg_order_amount = ROUND(total_amount / order_count, 2)));
```

> **⚠️ 聚合口径说明：**
>
> - `total_amount`（当日应收）按 **下单日** 归属
> - `paid_amount`（当日实收）按 **收款日** 归属
> - 两者不是同一批订单，因此 `paid_amount` 与 `total_amount` 当天通常不相等
> - 这样设计的理由：销售日报要回答两个不同的问题——"今天卖了多少"和"今天收了多少钱"

| 表 | 字段 | 类型 | 精度说明 |
|---|---|---|---|
| `m16_optical_order` | `gross_amount` | NUMERIC(14,2) | 明细 `gross_amount` 之和 |
| | `discount_amount` | NUMERIC(14,2) | 明细 `discount_amount` 之和 |
| | `total_amount` | NUMERIC(14,2) | **CHECK = gross − discount** |
| | `deposit_ratio` | NUMERIC(5,4) | 比例，4 位小数 |
| | `deposit_amount` | NUMERIC(14,2) | = ROUND(total × ratio, 2) |
| | `paid_amount` | NUMERIC(14,2) | 累计已收 |
| | `refunded_amount` | NUMERIC(14,2) | 累计已退 |

| | `discount_rate` | NUMERIC(5,4) | 折扣率 |
| | `gross_amount` | NUMERIC(14,2) | **CHECK = ROUND(price × qty, 2)** |
| | `discount_amount` | NUMERIC(14,2) | **CHECK = gross − amount** |
| | `amount` | NUMERIC(14,2) | 成交金额 |
| `m16_optical_settlement_rel` | `amount` | NUMERIC(14,2) | 带符号，退款为负 |
| `m16_optical_payment` | `amount` | NUMERIC(14,2) | 带符号，退款为负 |
| | `received_amount` | NUMERIC(14,2) | 现金实收 |
| | `change_amount` | NUMERIC(14,2) | **CHECK = 实收 − 金额** |
| `m16_optical_return` | `refund_base_amount` | NUMERIC(14,2) | 退款基数 |
| | `refund_fee_rate` | NUMERIC(5,4) | 手续费率 |
| | `refund_amount` | NUMERIC(14,2) | **CHECK = base × (1 − fee)** |
| `m16_optical_daily_summary` | `total_amount` | NUMERIC(14,2) | **CHECK = gross − discount** |
| | `avg_order_amount` | NUMERIC(14,2) | **CHECK = ROUND(total / count, 2)** |

> **统一规则：**
> 1. 金额一律 `NUMERIC`，**禁止 `FLOAT`/`DOUBLE`**。
> 2. 单价 4 位小数（镜片按片计价），金额 2 位小数。
> 3. **行级先舍入再累加**：`amount = ROUND(unit_price × quantity × rate, 2)` 后求和才一致。
> 4. 舍入一律 `ROUND_HALF_UP`（四舍五入），禁止银行家舍入。
> 5. 带符号金额：收款正、退款负，日报 `SUM(amount)` 即净收入。

| `RETURN_APPROVE` | 退换审批 | `m16_optical_return` | 需主管 |
| `RETURN_EXECUTE` | 退换执行 | `m16_optical_return` | → COMPLETED |
| `CONFIG_UPDATE` | 参数修改 | `m16_optical_config` | 需管理权限 |

## 附录 E：建表依赖顺序与 Alembic 迁移顺序

```
第 1 层（无依赖，先建）
  └── m16_optical_config

第 2 层（主表）
  └── m16_optical_order

第 3 层（依赖主表）
  ├── m16_optical_item
  ├── m16_optical_settlement_rel
  └── m16_optical_payment

第 4 层（依赖主表，审批链）
  └── m16_optical_return

第 5 层（依赖全部，预聚合）
  └── m16_optical_daily_summary
```

**Alembic 迁移脚本顺序：**

```python
# migrations/versions/xxxx_m16_04_optical_01_config.py
#   1. 建 m16_optical_config + 初始化 13 条参数
# migrations/versions/xxxx_m16_04_optical_02_order.py
#   2. 建 m16_optical_order（含金额恒等式与状态时间一致性 CHECK）
# migrations/versions/xxxx_m16_04_optical_03_item.py
#   3. 建 m16_optical_item + trgm 索引（需先 CREATE EXTENSION pg_trgm）
# migrations/versions/xxxx_m16_04_optical_04_settlement.py
#   4. 建 m16_optical_settlement_rel（含 stage 部分唯一索引）
# migrations/versions/xxxx_m16_04_optical_05_payment.py
#   5. 建 m16_optical_payment（含现金恒等式 CHECK）
# migrations/versions/xxxx_m16_04_optical_06_return.py
#   6. 建 m16_optical_return（含退款金额可复算 CHECK）
# migrations/versions/xxxx_m16_04_optical_07_summary.py

```
