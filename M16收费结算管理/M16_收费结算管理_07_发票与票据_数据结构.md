## 4. 数据结构设计

### 4.1 ER 关系图

**设计说明：**

1. **无物理外键。** 遵循 M16 全局策略。开票在高并发下需要避免外键锁等待。

2. **自关联实现红冲。** 红票与蓝票在同一张表 `m16_invoice` 中，通过 `is_red_invoice` + `original_invoice_id` 区分与关联。理由：
   - 红票与蓝票的字段结构完全一致（都有号码、金额、税额、状态、版式文件）
   - 分两张表会导致「查一张票的全部关联票」需要 UNION
   - 报表「净开票额 = 蓝票合计 − 红票合计」只需一次聚合

   > 代价是必须在查询时始终带 `is_red_invoice` 条件。因此所有列表查询都默认加 `is_red_invoice=FALSE`，红票单独台账。

3. **号码段主数据在 M01-06。** `m16_invoice.number_segment_id` 只是引用，本子模块不维护 `md_invoice_number_segment`。

4. **`m16_invoice_print` 与 `m16_invoice_delivery` 分开。** 打印是纸质票的物理动作（可能有重打），交付是电子票的送达动作（短信/邮件/二维码）。两者的失败原因、重试策略、审计要求都不同。

5. **`m16_invoice_log` 只读。** 触发器禁止 UPDATE/DELETE，保证审计链不可篡改。

6. **分区策略。** `m16_invoice` / `m16_invoice_item` / `m16_invoice_log` 按年 RANGE 分区，保留 15 年（与《医疗机构病历管理规定》门急诊记录 ≥15 年、税收征管法发票存根 ≥10 年取较长者）。

**约束说明**

```sql
-- 票种枚举
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_type
    CHECK (invoice_type IN ('ELECTRONIC', 'PAPER', 'SPECIAL', 'FINANCE'));

-- 开票点枚举
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_point
    CHECK (invoice_point IN ('OUTPATIENT', 'INPATIENT', 'OPTICAL'));

-- 抬头类型枚举
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_title_type
    CHECK (title_type IN ('PERSONAL', 'ENTERPRISE'));

-- 状态枚举
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_status
    CHECK (status IN ('PENDING', 'ISSUING', 'ISSUED', 'DELIVERED',
                      'FAILED', 'VOIDED', 'RED_FLUSHED',
                      'PARTIAL_RED', 'SUSPENDED', 'CANCELLED'));

-- 红票必须有原票，蓝票不得有
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_red_ref
    CHECK ((is_red_invoice = FALSE AND original_invoice_id IS NULL
            AND red_reason IS NULL)
        OR (is_red_invoice = TRUE AND original_invoice_id IS NOT NULL
            AND red_reason IS NOT NULL));

-- 红票金额必须为负，蓝票为正（待开票阶段允许 0 过渡）
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_amount_sign
    CHECK ((is_red_invoice = TRUE AND amount <= 0)
        OR (is_red_invoice = FALSE AND amount >= 0));

-- 金额恒等：不含税 + 税额 = 价税合计
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_amount_balance
    CHECK (amount_without_tax + tax_amount = amount);

-- 税率合理区间（%）
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_tax_rate
    CHECK (tax_rate >= 0 AND tax_rate <= 100);

-- 免税票税额必须为 0
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_tax_free
    CHECK (is_tax_free = FALSE OR tax_amount = 0);

-- 已开具必须有号码、开票日期与开票人
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_issued
    CHECK (status NOT IN ('ISSUED', 'DELIVERED', 'PARTIAL_RED',
                          'RED_FLUSHED', 'VOIDED')
        OR (invoice_no IS NOT NULL
            AND issue_date IS NOT NULL
            AND issued_at IS NOT NULL
            AND issued_by IS NOT NULL));

-- 失败必须有原因
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_failed
    CHECK (status NOT IN ('FAILED', 'SUSPENDED')
        OR fail_reason IS NOT NULL);

-- 作废必须有时间、人、原因
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_voided
    CHECK (status <> 'VOIDED'
        OR (voided_at IS NOT NULL
            AND voided_by IS NOT NULL
            AND void_reason IS NOT NULL));

-- 红冲额非负且不超过本票金额
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_red_amount
    CHECK (red_amount >= 0 AND red_amount <= amount);

-- 部分红冲必须有红冲额
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_partial
    CHECK (status <> 'PARTIAL_RED' OR red_amount > 0);

-- 全额红冲时红冲额必须等于本票金额
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_red_full
    CHECK (status <> 'RED_FLUSHED' OR red_amount = amount);

-- 电子发票必须有版式文件
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_electronic_file
    CHECK (invoice_type <> 'ELECTRONIC'
        OR status NOT IN ('ISSUED', 'DELIVERED', 'PARTIAL_RED',
                          'RED_FLUSHED')
        OR pdf_file_id IS NOT NULL);

-- 单位抬头必须有税号
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_enterprise
    CHECK (title_type <> 'ENTERPRISE'
        OR status IN ('PENDING', 'CANCELLED')
        OR tax_no IS NOT NULL);

-- 电子发票必须有手机或邮箱（待开票阶段除外）
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_contact
    CHECK (invoice_type <> 'ELECTRONIC'
        OR status IN ('PENDING', 'CANCELLED', 'FAILED')
        OR mobile IS NOT NULL
        OR email IS NOT NULL);

-- 纸质票必须有号码段
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_paper_segment
    CHECK (invoice_type NOT IN ('PAPER', 'FINANCE')
        OR status IN ('PENDING', 'CANCELLED')
        OR number_segment_id IS NOT NULL);

-- 重试次数非负有界
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_retry
    CHECK (retry_count >= 0 AND retry_count <= 10);

-- 打印次数非负
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_print_count
    CHECK (print_count >= 0 AND reprint_count >= 0);

-- 查验状态枚举
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_verify
    CHECK (verify_status IN ('NOT_VERIFIED', 'VERIFIED',
                             'VERIFY_FAILED', 'NOT_FOUND'));

-- 二维码令牌格式：32 位十六进制
ALTER TABLE m16_invoice
    ADD CONSTRAINT ck_m16_invoice_qr
    CHECK (qr_token IS NULL OR qr_token ~ '^[0-9a-f]{32}$');

COMMENT ON COLUMN m16_invoice.invoice_no IS '发票号码：电子票 20 位由税务平台返回，纸质票 8 位由号码段分配';
COMMENT ON COLUMN m16_invoice.is_red_invoice IS '红字发票标识；红票金额为负，amount 恒 <= 0';
COMMENT ON COLUMN m16_invoice.original_invoice_id IS '红票关联的原蓝票 ID，蓝票为空';
COMMENT ON COLUMN m16_invoice.red_amount IS '本票（蓝票）累计已红冲金额，红票恒为 0';
COMMENT ON COLUMN m16_invoice.amount_without_tax IS '不含税金额，由 amount/(1+税率) 倒算，保证三者恒等';
COMMENT ON COLUMN m16_invoice.tax_rate IS '主税率（百分比），混合税率时 has_mixed_tax=TRUE 并按明细取';
```

**状态机**

```
PENDING ──► ISSUING ──► ISSUED ──► DELIVERED
              │            │           │
              ▼            │           │
           FAILED ──►ISSUING           │
              │            │           │
              ▼            ▼           ▼
          CANCELLED    PARTIAL_RED ◄──┘
                           │
                           ▼
                      RED_FLUSHED
ISSUED/DELIVERED ──► VOIDED（仅纸质、当月、未交付）
红票 ISSUED ──► SUSPENDED（换开时蓝票失败）
```

**两条资金安全约束的设计动机**

**`uk_m16_invoice_settle_blue` —— 防重复开票**

同一笔 1,180 元，如果开两张蓝票，患者能拿去报销两次，税务上属于虚开。这个约束把「查一次再插入」的 TOCTOU 窗口堵死。注意它的 `WHERE` 子句排除了 `VOIDED` / `CANCELLED` / `RED_FLUSHED` —— 因为作废或全额红冲后业务员需要重新开票，这是合法的。

**`uk_m16_invoice_no` —— 防重号**

发票号重复在税务上是重大事故。这个索引包含 `invoice_no IS NOT NULL` 条件，因为 `PENDING` 状态下号码尚未分配，多个待开票记录不能互相冲突。

**分区与唯一索引的冲突及取舍**

`m16_invoice` 若按 `issue_date` 分区，PostgreSQL 要求唯一索引必须包含分区键。但：

- `uk_m16_invoice_settle_blue` 加 `issue_date` 会削弱约束（同一结算单可能被塞进不同分区）
- `uk_m16_invoice_no` 加 `issue_date` 会削弱号码唯一性

**结论：`m16_invoice` 不分区。** 理由：年 14 万行 × 15 年 = 210 万行，单表完全可承受（约 1.5 GB）。资金凭证的唯一性远比查询性能重要。若 15 年后需归档，用 `INSERT INTO archive SELECT` + `DELETE` 的离线迁移。

**税额倒算的正确写法**

```
不含税 = ROUND(含税 / (1 + 税率), 2)
税额   = 含税 − 不含税
```

**反例（错误写法）：**

```
税额   = ROUND(含税 × 税率, 2)
不含税 = 含税 − 税额
```

对 800 元、13% 税率：
- 正确：不含税 707.96、税额 92.04（707.96 + 92.04 = 800.00 ✅）
- 错误：税额 = 800 × 0.13 = 104.00、不含税 = 696.00（696 + 104 = 800 ✅ 但数值偏离税局口径 10 元）

第二种算法把「价内税」当成「价外税」算了。税务系统会校验 `不含税 × (1+税率) ≈ 含税`，2 分以内容差，10 元直接拒收。

**`ck_m16_invoice_seglog_count` 是台账完整性的核心**

`used_count + void_count + remain_count = total_count` 这个恒等式保证号码段不漏账。任何一次错误计数都立刻被数据库拒绝，而不是等到月底对账才发现差了几十张。

| 每年动作数 | 约 130 次（每段 3 次操作） |
| 年行数 | 约 130 行 |

```python
    email: Optional[str] = Field(None, max_length=128)
    remark: Optional[str] = Field(None, max_length=200)

    @classmethod
    def check_title(cls, v):
        v = v.strip()
        if not v:
            raise ValueError("抬头不能为空白")
        if any(ch in v for ch in "<>"):
            raise ValueError("抬头含非法字符")
        return v

    @field_validator("mobile")
    @classmethod
    def check_mobile(cls, v):
        if v is None:
            return v
        if not v.isdigit() or len(v) != 11 or not v.startswith("1"):
            raise ValueError("手机号格式不正确")
        return v

    @model_validator(mode="after")
    def check_consistency(self):
        if self.title_type == "ENTERPRISE" and not self.tax_no:
            raise ValueError("单位抬头必须提供纳税人识别号")
        if self.invoice_type == "ELECTRONIC" \
                and not self.mobile and not self.email:
            raise ValueError("电子发票需提供手机号或邮箱")
        return self
```

**离线归档策略**

`m16_invoice` 不分区，但保留 15 年后需要归档：

```sql
-- 建议：按 issue_date 逐年迁移到 m16_invoice_archive
CREATE TABLE m16_invoice_archive (LIKE m16_invoice INCLUDING ALL);

INSERT INTO m16_invoice_archive
SELECT * FROM m16_invoice
 WHERE issue_date < DATE '2012-01-01';

DELETE FROM m16_invoice
 WHERE issue_date < DATE '2012-01-01';
```

> **归档前必须确认：** 该年度全部发票已 `RED_FLUSHED` 或 `VOIDED` 或超过红冲时限（《增值税发票管理办法》规定红冲时限为开票后 3 年）。`m16_invoice_item` 同步归档。
