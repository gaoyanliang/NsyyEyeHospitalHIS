**设计说明：**

1. **两个只增表**：`m16_deposit` 与 `m16_inpatient_charge` 都只增不删，任何"修改"都通过新增负数记录实现（红冲）。这是财务数据的铁律。
2. **账户是派生还是存储**：`m16_deposit_account` 的余额字段是**冗余存储**，可随时由 `m16_deposit` 重算。存储是为了避免每次查询都扫流水表，每日 03:00 有核对任务修正。
3. **结算明细不是必须**：`m16_inpatient_settlement_item` 存的是"结算那一刻各类别的金额快照"。即使记账明细后来被冲销，结算单上的数字也不变（结算已锁定）。
4. **无物理外键**：全部靠应用层维护 + 快照冗余，理由见汇总文档。

### 4.2 `m16_deposit_account` 预交金账户

**用途：** 一个住院号对应一个预交金资金池，存储累计金额与可用余额。

**字段定义：**

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | 否 | 自增 | 主键 |
| `admission_id` | BIGINT | 否 | — | 住院记录 ID（M05，无物理外键） |
| `admission_no` | VARCHAR(32) | 是 | NULL | 住院号（冗余） |
| `patient_id` | BIGINT | 否 | — | 患者 ID（M03） |
| `patient_name` | VARCHAR(64) | 是 | NULL | 患者姓名（冗余） |
| `dept_id` | BIGINT | 是 | NULL | 科室 ID（冗余，便于按科室统计） |
| `dept_name` | VARCHAR(64) | 是 | NULL | 科室名称（冗余） |
| `bed_no` | VARCHAR(32) | 是 | NULL | 床号（冗余） |
| `status` | VARCHAR(16) | 否 | `'ACTIVE'` | 账户状态：`ACTIVE` 正常 / `FROZEN` 冻结 / `CLOSED` 已结清 |
| `total_deposit` | NUMERIC(14,2) | 否 | `0.00` | 累计充值 |
| `total_refund` | NUMERIC(14,2) | 否 | `0.00` | 累计退还 |
| `frozen_amount` | NUMERIC(14,2) | 否 | `0.00` | 冻结金额 |
| `available_balance` | NUMERIC(14,2) | 否 | `0.00` | 可用余额 = total_deposit − total_refund − frozen_amount |
| `accumulated_charge` | NUMERIC(14,2) | 否 | `0.00` | 已发生费用净额（含冲销） |
| `warn_threshold` | NUMERIC(14,2) | 是 | NULL | 预警阈值（元），NULL 则用比例计算 |
| `frozen_reason` | VARCHAR(256) | 是 | NULL | 冻结原因 |
| `last_deposit_at` | TIMESTAMP | 是 | NULL | 最近充值时间 |
| `last_charge_at` | TIMESTAMP | 是 | NULL | 最近记账时间 |
| `last_reconciled_at` | TIMESTAMP | 是 | NULL | 最近余额核对时间 |
| `closed_at` | TIMESTAMP | 是 | NULL | 结清时间 |
| `remark` | VARCHAR(512) | 是 | NULL | 备注 |
| `created_at` | TIMESTAMP | 否 | `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | TIMESTAMP | 是 | NULL | 更新时间 |
| `is_deleted` | BOOLEAN | 否 | `FALSE` | 逻辑删除 |

**索引设计：**

| 索引名 | 类型 | 字段 | 用途 |
|---|---|---|---|
| `pk_m16_deposit_account` | 主键 | `id` | — |
| `uk_m16_deposit_account` | 唯一（部分） | `admission_id` WHERE `is_deleted = FALSE` | 一住院一账户 |
| `idx_m16_deposit_acc_patient` | B-Tree | `patient_id`, `status` | 按患者查 |
| `idx_m16_deposit_acc_status` | B-Tree | `status`, `dept_id` | 在院患者列表 |
| `idx_m16_deposit_acc_warn` | B-Tree | `dept_id` WHERE `status = 'ACTIVE'` | 预警扫描 |
| `idx_m16_deposit_acc_recon` | B-Tree | `last_reconciled_at` | 核对任务 |

**约束说明：**

```sql
-- 一个住院号只能有一个账户
CREATE UNIQUE INDEX uk_m16_deposit_account
    ON m16_deposit_account (admission_id)
    WHERE is_deleted = FALSE;

-- 状态枚举
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_status
    CHECK (status IN ('ACTIVE', 'FROZEN', 'CLOSED'));

-- 金额不得为负（frozen/refund 均不能是负数）
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_nonneg
    CHECK (total_deposit >= 0
       AND total_refund >= 0
       AND frozen_amount >= 0);

-- 余额恒等式：可用余额必须等于 充值 - 退还 - 冻结
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_balance
    CHECK (available_balance = total_deposit - total_refund - frozen_amount);

-- 累计退还不得超过累计充值
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_refund_limit
    CHECK (total_refund <= total_deposit);

-- 冻结金额不得超过 充值 - 退还
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_frozen_limit
    CHECK (frozen_amount <= total_deposit - total_refund);

-- 结清必须有时间
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_closed
    CHECK ((status = 'CLOSED') = (closed_at IS NOT NULL));

-- 冻结必须有原因
ALTER TABLE m16_deposit_account
    ADD CONSTRAINT ck_m16_deposit_acc_frozen_reason
    CHECK ((status = 'FROZEN') = (frozen_reason IS NOT NULL));
```

> **⚠️ 关于 `ck_m16_deposit_acc_balance`：**
>
> 这条 CHECK 让"余额恒等式"成为数据库层面的硬约束。任何更新账户的操作必须同时更新三个输入字段与结果字段，否则写入直接失败。
>
> 好处是**防止应用层算错导致账不平**；代价是应用层必须在一个 UPDATE 语句里同时赋值四个字段（SQLAlchemy 的 ORM 更新天然满足，因为是整行 UPDATE）。

**状态机：**

```
    ┌─────────┐  首次充值  ┌─────────┐  出院结算   ┌──────────┐
    │ (无记录) ├──────────►│ ACTIVE  ├───────────►│  CLOSED  │
    └─────────┘            │ 正常    │            │ 已结清    │
                           └────┬────┘            └──────────┘
                                │                  ▲
                          冻结（结算中/审查）        │ 出院结算成功
                                │                  │
                                ▼                  │
                           ┌──────────┐            │
                           │  FROZEN  │────────────┘
                           │ 已冻结    │  解冻回 ACTIVE（中途结算成功后）
                           └──────────┘
```

**量级估算：**

| 项 | 值 |
|---|---|
| 年出院人次 | 6,000 |
| 每住院 1 行 | 6,000 行/年 |
| 单行大小 | ≈ 350 B |
| 年增长 | ≈ 2 MB |
| 保留期 | 15 年（含出院后） |
| 15 年总量 | ≈ 30 MB |

**分区：** 不分区。表规模小，全表索引即可。

### 4.3 `m16_deposit` 预交金流水

**用途：** 记录每一笔预交金的充值、退还、调整，是账户余额的唯一事实来源。

**字段定义：**

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | 否 | 自增 | 主键 |
| `deposit_no` | VARCHAR(32) | 否 | — | 预交金流水号 `YJ` + yyyyMMdd + 4 位 |
| `account_id` | BIGINT | 否 | — | 账户 ID（`m16_deposit_account.id`） |
| `admission_id` | BIGINT | 否 | — | 住院记录 ID |
| `admission_no` | VARCHAR(32) | 是 | NULL | 住院号（冗余） |
| `patient_id` | BIGINT | 否 | — | 患者 ID |
| `patient_name` | VARCHAR(64) | 是 | NULL | 患者姓名（冗余） |
| `deposit_type` | VARCHAR(16) | 否 | — | `DEPOSIT` 充值 / `REFUND` 退还 / `TRANSFER_IN` 转入 / `TRANSFER_OUT` 转出 / `ADJUST` 调整 |
| `amount` | NUMERIC(14,2) | 否 | — | 金额（充值正数、退还负数） |
| `balance_before` | NUMERIC(14,2) | 否 | — | 变动前可用余额 |
| `balance_after` | NUMERIC(14,2) | 否 | — | 变动后可用余额 |
| `payment_method` | VARCHAR(32) | 是 | NULL | 支付方式代码（来自 `md_payment_method`） |
| `payment_method_name` | VARCHAR(64) | 是 | NULL | 支付方式名称（冗余快照） |
| `payment_id` | BIGINT | 是 | NULL | 支付流水 ID（M16-02 `m16_payment.id`） |
| `payment_no` | VARCHAR(32) | 是 | NULL | 支付流水号（冗余） |
| `refund_of_deposit_id` | BIGINT | 是 | NULL | 退还时指向原充值记录 |
| `refund_channel` | VARCHAR(16) | 是 | NULL | `ORIGINAL` 原路 / `CASH` 现金 / `NEW_ACCOUNT` 新账户 |
| `pay_status` | VARCHAR(16) | 否 | `'SUCCESS'` | `PENDING` / `SUCCESS` / `FAILED` / `CANCELLED` |
| `receipt_no` | VARCHAR(32) | 是 | NULL | 预交金收据号 `YJQ` + yyyyMMdd + 4 位 |
| `approval_id` | BIGINT | 是 | NULL | 退款审批单 ID（M16-08） |
| `cashier_id` | BIGINT | 是 | NULL | 收费员 ID |
| `cashier_name` | VARCHAR(64) | 是 | NULL | 收费员姓名（冗余） |
| `received_at` | TIMESTAMP | 否 | — | 收付时间 |
| `remark` | VARCHAR(512) | 是 | NULL | 备注 / 退款原因 |
| `trace_id` | VARCHAR(64) | 是 | NULL | 链路追踪 ID |
| `created_at` | TIMESTAMP | 否 | `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | TIMESTAMP | 是 | NULL | 更新时间 |
| `is_deleted` | BOOLEAN | 否 | `FALSE` | 逻辑删除（**实际不使用**，见约束） |

**索引设计：**

| 索引名 | 类型 | 字段 | 用途 |
|---|---|---|---|
| `pk_m16_deposit` | 主键 | `id` | — |
| `uk_m16_deposit_no` | 唯一 | `deposit_no` | 流水号唯一 |
| `idx_m16_deposit_admission` | B-Tree | `admission_id`, `received_at` DESC | 查某住院流水 |
| `idx_m16_deposit_account` | B-Tree | `account_id`, `received_at` DESC | 账户流水 |
| `idx_m16_deposit_patient` | B-Tree | `patient_id`, `received_at` DESC | 患者流水 |
| `idx_m16_deposit_payment` | B-Tree | `payment_id` WHERE `payment_id IS NOT NULL` | 支付关联 |
| `idx_m16_deposit_refund_of` | B-Tree | `refund_of_deposit_id` WHERE `refund_of_deposit_id IS NOT NULL` | 退款追溯 |
| `idx_m16_deposit_day` | B-Tree | `(received_at::date)`, `deposit_type` | 日报统计 |

**约束说明：**

```sql
-- 流水号唯一
CREATE UNIQUE INDEX uk_m16_deposit_no
    ON m16_deposit (deposit_no);

-- 类型枚举
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_type
    CHECK (deposit_type IN ('DEPOSIT', 'REFUND',
                            'TRANSFER_IN', 'TRANSFER_OUT', 'ADJUST'));

-- 支付状态枚举
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_pay_status
    CHECK (pay_status IN ('PENDING', 'SUCCESS', 'FAILED', 'CANCELLED'));

-- 金额符号：充值必须正、退还必须负
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_amount_sign
    CHECK (
        (deposit_type IN ('DEPOSIT', 'TRANSFER_IN') AND amount > 0)
        OR
        (deposit_type IN ('REFUND', 'TRANSFER_OUT') AND amount < 0)
        OR
        (deposit_type = 'ADJUST' AND amount <> 0)
    );

-- 余额变动必须与金额一致
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_balance_delta
    CHECK (balance_after = balance_before + amount);

-- 成功才有收据
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_receipt
    CHECK ((pay_status = 'SUCCESS') OR (receipt_no IS NULL));

-- 退款必须指向原充值且必须有原因
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_refund_ref
    CHECK ((deposit_type = 'REFUND')
           = (refund_of_deposit_id IS NOT NULL AND remark IS NOT NULL));

-- 退款渠道仅对退款有效
ALTER TABLE m16_deposit
    ADD CONSTRAINT ck_m16_deposit_refund_channel
    CHECK ((deposit_type = 'REFUND') = (refund_channel IS NOT NULL));

-- 流水不可删除、不可更新金额（只能用触发器实现）
CREATE OR REPLACE FUNCTION fn_m16_deposit_immutable()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION 'm16_deposit 不允许删除，只能红冲';
    END IF;

    IF NEW.amount <> OLD.amount
       OR NEW.deposit_type <> OLD.deposit_type
       OR NEW.admission_id <> OLD.admission_id THEN
        RAISE EXCEPTION 'm16_deposit 的金额、类型、住院号不可修改';
    END IF;

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_m16_deposit_immutable
    BEFORE UPDATE OR DELETE ON m16_deposit
    FOR EACH ROW EXECUTE FUNCTION fn_m16_deposit_immutable();
```

> **⚠️ 关于 `is_deleted`：** 本表虽然保留该字段（与全局规范一致），但**业务上永不置为 TRUE**。预交金流水的撤销必须通过新增 `ADJUST` 负数流水实现，不能逻辑删除。触发器禁止物理 DELETE。

**量级估算：**

| 项 | 值 |
|---|---|
| 年出院 6,000 人次 | 人均充值 1.5 笔 + 退还 0.5 笔 ≈ 2 笔 |
| 年行数 | ≈ 12,000 行 |
| 中途结算额外退还 | +3,000 行 |
| 单行大小 | ≈ 500 B |
| 年增长 | ≈ 15 MB |
| 15 年总量 | ≈ 225 MB |

**分区：** 建议按 `received_at` 年度 RANGE 分区（与 `m16_payment` 一致，便于按年归档）。

```sql
-- 分区示例（2026 年）
CREATE TABLE m16_deposit_2026 PARTITION OF m16_deposit
    FOR VALUES FROM ('2026-01-01') TO ('2027-01-01');
```

```sql
-- 流水号唯一
CREATE UNIQUE INDEX uk_m16_inpcharge_no
    ON m16_inpatient_charge (charge_no);

-- 记账幂等：同一来源只能有一条 NORMAL 记账
-- 这是防止重复收费的最后一道防线
CREATE UNIQUE INDEX uk_m16_inpcharge_source
    ON m16_inpatient_charge (source_type, source_id)
    WHERE status = 'NORMAL' AND is_deleted = FALSE;

-- 来源类型枚举
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_source_type
    CHECK (source_type IN ('ORDER', 'SURGERY', 'DAILY', 'MANUAL', 'TRANSFER'));

-- 状态枚举
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_status
    CHECK (status IN ('NORMAL', 'REVERSED', 'REVERSAL'));

-- 费用类别枚举
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_category
    CHECK (charge_category IN ('BED', 'CLINIC', 'NURSING', 'EXAM', 'LAB',
                               'OPERATION', 'ANESTHESIA', 'DRUG', 'MATERIAL',
                               'TREATMENT', 'BLOOD', 'OTHER'));

-- 正常记账金额必须为正；冲销记录必须为负
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_amount_sign
    CHECK (
        (status IN ('NORMAL', 'REVERSED') AND amount > 0)
        OR (status = 'REVERSAL' AND amount < 0)
    );

-- 金额 = 单价 × 数量（行级先舍入）
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_amount_calc
    CHECK (amount = ROUND(unit_price * quantity, 2));

-- 冲销记录必须指向原记录；非冲销记录不得有该字段
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_reversal_ref
    CHECK ((status = 'REVERSAL') = (reversal_of_charge_id IS NOT NULL));

-- 已冲销的记录必须有冲销时间
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_reversed_time
    CHECK ((status = 'REVERSED') = (reversed_at IS NOT NULL));

-- 冲销记录本身不得被再次冲销、不得已结算
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_reversal_settle
    CHECK (status <> 'REVERSAL' OR settled_settlement_id IS NULL);

-- 单价不得为负（冲销靠数量负数，不靠单价负数）
ALTER TABLE m16_inpatient_charge
    ADD CONSTRAINT ck_m16_inpcharge_price_nonneg
    CHECK (unit_price >= 0);
```

> **⚠️ `ck_m16_inpcharge_amount_calc` 注意事项：**
>
> PostgreSQL 的 `ROUND(numeric, int)` 使用**四舍五入**（round half away from zero），与 Python `Decimal.quantize(ROUND_HALF_UP)` 一致，但**与 Python 内置 `round()` 不同**（后者是银行家舍入）。
>
> 应用层必须使用 `Decimal` + `ROUND_HALF_UP`，否则 `0.125 → 0.12` vs `0.13` 会导致 CHECK 失败。

**量级估算：**

| 项 | 值 |
|---|---|
| 在院 100 人 | 日均 100 人 |
| 日结项（床位/诊查/护理） | 3 条 × 100 人 = 300 条/天 |
| 医嘱项 | 人均 20 条/住院 × 6,000 / 365 ≈ 330 条/天 |
| 冲销 | 约 3% |
| **日行数** | ≈ 650 条/天 |
| **年行数** | ≈ 240,000 行 |
| 单行大小 | ≈ 600 B |
| 年增长 | ≈ 145 MB |
| 15 年总量 | ≈ 2.2 GB |

**分区：** **推荐按 `charge_date` 年度 RANGE 分区**，理由：

1. 查询天然带日期范围（明细列表、日报、月报）
2. 15 年数据量 2.2 GB，分区后单分区 145 MB，索引常驻内存
3. 历史年度可脱离归档

```sql
CREATE TABLE m16_inpatient_charge_2026 PARTITION OF m16_inpatient_charge
    FOR VALUES FROM ('2026-01-01') TO ('2027-01-01');
```

> **注意：** 分区表的唯一索引必须包含分区键。因此 `uk_m16_inpcharge_source` 实际需改为 `(source_type, source_id, charge_date)` 唯一 —— 但这会破坏幂等（同来源不同日期可重复）。**折中方案：** 幂等检查在应用层用 `admission_id + source_type + source_id` 定位，分区表上建普通索引而非唯一索引，唯一性由 `m16_inpatient_charge_idem`（一张不分区的幂等键小表）保证。若不做分区，则保留上述唯一索引。

### 4.5 `m16_inpatient_settlement` 住院结算记录

**用途：** 记录每一次结算（出院/中途/转科/日间手术），是"算清楚"的结果留存。

**字段定义：**

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | 否 | 自增 | 主键 |
| `settlement_no` | VARCHAR(32) | 否 | — | 结算单号 `ZYS` + yyyyMMdd + 4 位 |
| `billing_no` | VARCHAR(32) | 是 | NULL | M16-01 计费单号（`m16_settlement.settlement_no`） |
| `admission_id` | BIGINT | 否 | — | 住院记录 ID |
| `admission_no` | VARCHAR(32) | 是 | NULL | 住院号（冗余） |
| `patient_id` | BIGINT | 否 | — | 患者 ID |
| `patient_name` | VARCHAR(64) | 是 | NULL | 患者姓名（冗余） |
| `dept_id` | BIGINT | 是 | NULL | 科室 ID |
| `dept_name` | VARCHAR(64) | 是 | NULL | 科室名称（冗余） |
| `settle_type` | VARCHAR(16) | 否 | — | `DISCHARGE` 出院 / `INTERIM` 中途 / `TRANSFER` 转科 / `DAY_SURGERY` 日间手术 |

| `period_start` | DATE | 否 | — | 账期开始日期 |

| `inpatient_days` | INTEGER | 是 | NULL | 住院天数 |
| `total_amount` | NUMERIC(14,2) | 否 | `0.00` | 本期正常记账合计（不含冲销） |
| `reversal_amount` | NUMERIC(14,2) | 否 | `0.00` | 本期冲销合计（正数表示冲掉了多少） |

| `deposit_amount` | NUMERIC(14,2) | 否 | `0.00` | 本期可用于抵扣的预交金 |
| `settle_amount` | NUMERIC(14,2) | 否 | `0.00` | 结算差额绝对值，等于净额与预交金之差的绝对值 |
| `settle_direction` | VARCHAR(16) | 否 | — | `PAYABLE` 应补交 / `REFUNDABLE` 应退还 / `EVEN` 无需补退 |

| `refund_no` | VARCHAR(32) | 是 | NULL | 退款单号（M16-08） |
| `settle_mode` | VARCHAR(16) | 否 | `'SELF_PAY'` | `SELF_PAY` 自费 / `INSURANCE` 医保 / `COMMERCIAL` 商保 |

| `insurance_settle_no` | VARCHAR(64) | 是 | NULL | **⚠️ 预留**：医保结算流水号 |
| `status` | VARCHAR(16) | 否 | `'SETTLING'` | `SETTLING` 结算中 / `SETTLED` 已结算 / `CANCELLED` 已作废 |

| `settled_by` | BIGINT | 是 | NULL | 结算操作人 |

**索引设计：**

| 索引名 | 类型 | 字段 | 用途 |
|---|---|---|---|
| `pk_m16_inpatient_settlement` | 主键 | `id` | — |
| `uk_m16_inpsettle_no` | 唯一 | `settlement_no` | 单号唯一 |
| `uk_m16_inpsettle_billing` | 唯一（部分） | `billing_no` WHERE `billing_no IS NOT NULL` | 一计费单一住院结算 |
| `uk_m16_inpsettle_period` | 唯一（部分） | `admission_id`, `period_start`, `period_end` WHERE `status='SETTLED' AND is_deleted=FALSE` | **账期不重叠** |
| `idx_m16_inpsettle_admission` | B-Tree | `admission_id`, `period_no` | 查某住院所有结算 |
| `idx_m16_inpsettle_date` | B-Tree | `(settled_at::date)`, `settle_type`, `status` | 日报 |
| `idx_m16_inpsettle_patient` | B-Tree | `patient_id`, `settled_at` DESC | 患者结算历史 |

**约束说明：**

```sql
-- 单号唯一
CREATE UNIQUE INDEX uk_m16_inpsettle_no
    ON m16_inpatient_settlement (settlement_no);

-- 一个计费单只能对应一条住院结算
CREATE UNIQUE INDEX uk_m16_inpsettle_billing
    ON m16_inpatient_settlement (billing_no)
    WHERE billing_no IS NOT NULL AND is_deleted = FALSE;

-- 同一住院同一账期只能有一条有效结算（防重复结算）
CREATE UNIQUE INDEX uk_m16_inpsettle_period
    ON m16_inpatient_settlement (admission_id, period_start, period_end)
    WHERE status = 'SETTLED' AND is_deleted = FALSE;

-- 结算类型枚举
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_type
    CHECK (settle_type IN ('DISCHARGE', 'INTERIM', 'TRANSFER', 'DAY_SURGERY'));

-- 状态枚举
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_status
    CHECK (status IN ('SETTLING', 'SETTLED', 'CANCELLED'));

-- 结算方向枚举
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_direction
    CHECK (settle_direction IN ('PAYABLE', 'REFUNDABLE', 'EVEN'));

-- 结算模式枚举
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_mode
    CHECK (settle_mode IN ('SELF_PAY', 'INSURANCE', 'COMMERCIAL'));

-- 账期顺序正确
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_period_order
    CHECK (period_end >= period_start);

-- 净额 = 总额 - 冲销
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_net
    CHECK (net_amount = total_amount - reversal_amount);

-- 差额绝对值 = |净额 - 预交金|
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_amount
    CHECK (settle_amount = ABS(net_amount - deposit_amount));

-- 结算方向与差额符号一致
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_direction_match
    CHECK (
        (net_amount > deposit_amount AND settle_direction = 'PAYABLE')
        OR (net_amount < deposit_amount AND settle_direction = 'REFUNDABLE')
        OR (net_amount = deposit_amount AND settle_direction = 'EVEN')
    );

-- 补交必须有收据；退还必须有退款单；二者不能同时发生
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_paid
    CHECK (
        (settle_direction = 'PAYABLE' AND paid_amount = settle_amount
         AND payment_method IS NOT NULL)
        OR (settle_direction = 'REFUNDABLE' AND refund_amount = settle_amount)
        OR (settle_direction = 'EVEN'
            AND paid_amount = 0 AND refund_amount = 0)
    );

-- 已结算必须有结算时间与人
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_settled
    CHECK ((status = 'SETTLED')
           = (settled_at IS NOT NULL AND settled_by IS NOT NULL));

-- 作废必须有原因
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_cancel
    CHECK ((status = 'CANCELLED') = (cancel_reason IS NOT NULL));

-- 医保模式必须有医保金额
ALTER TABLE m16_inpatient_settlement
    ADD CONSTRAINT ck_m16_inpsettle_insurance
    CHECK (settle_mode = 'SELF_PAY'
           OR (insurance_amount IS NOT NULL AND self_pay_amount IS NOT NULL));
```

**金额计算示例：**

```
net_amount      = 12,800.00   （费用净额）
deposit_amount  = 10,000.00   （可用预交金）
settle_amount   = |12,800.00 - 10,000.00| = 2,800.00
settle_direction = PAYABLE（因为 12,800 > 10,000）
paid_amount     = 2,800.00
refund_amount   = 0.00
```

**量级估算：**

| 项 | 值 |
|---|---|
| 年出院 6,000 | 出院结算 6,000 条 |
| 中途结算 | 约 10% × 6,000 = 600 条 |
| 转科结算 | 约 3% = 180 条 |
| 年行数 | ≈ 6,800 行 |
| 单行大小 | ≈ 800 B |
| 年增长 | ≈ 5.5 MB |
| 15 年总量 | ≈ 82 MB |

**分区：** 不分区。

### 4.6 `m16_inpatient_settlement_item` 结算明细

**用途：** 结算那一刻各费用类别的金额快照。即使原始记账后来被冲销，结算单的构成不变。

**字段定义：**

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | 否 | 自增 | 主键 |
| `settlement_id` | BIGINT | 否 | — | 结算记录 ID |
| `settlement_no` | VARCHAR(32) | 是 | NULL | 结算单号（冗余） |
| `charge_category` | VARCHAR(16) | 否 | — | 费用类别 |
| `charge_category_name` | VARCHAR(32) | 是 | NULL | 类别名称（冗余快照） |
| `item_count` | INTEGER | 否 | `0` | 该类别的记账条数 |
| `gross_amount` | NUMERIC(14,2) | 否 | `0.00` | 该类别正常记账合计 |
| `reversal_amount` | NUMERIC(14,2) | 否 | `0.00` | 该类别冲销合计 |

```sql
END;
```

## 附录 B：金额字段汇总

| 表 | 字段 | 类型 | 精度说明 |
|---|---|---|---|
| `m16_deposit_account` | `total_deposit` | NUMERIC(14,2) | 累计充值，精确到分 |
| | `total_refund` | NUMERIC(14,2) | 累计退还 |
| | `frozen_amount` | NUMERIC(14,2) | 冻结 |
| | `available_balance` | NUMERIC(14,2) | **CHECK 恒等式** |
| | `accumulated_charge` | NUMERIC(14,2) | 累计费用 |
| `m16_deposit` | `amount` | NUMERIC(14,2) | 带符号 |
| | `balance_before/after` | NUMERIC(14,2) | **CHECK 增量一致** |
| `m16_inpatient_charge` | `unit_price` | NUMERIC(12,4) | 单价 4 位小数 |
| | `amount` | NUMERIC(14,2) | **CHECK = ROUND(price × qty, 2)** |
| `m16_inpatient_settlement` | `net_amount` | NUMERIC(14,2) | **CHECK = total − reversal** |
| | `settle_amount` | NUMERIC(14,2) | **CHECK = ABS(net − deposit)** |

> **统一规则：**
> 1. 金额一律 `NUMERIC`，**禁止 `FLOAT`/`DOUBLE`**。
> 2. 单价 4 位小数（药品按每片 0.0250 计价），金额 2 位小数。
> 3. **行级先舍入再累加**：`amount = ROUND(unit_price × quantity, 2)`，求和时才一致。
> 4. 舍入一律 `ROUND_HALF_UP`（四舍五入），禁止银行家舍入。

## 附录 C：关键部分索引

```sql
-- 记账幂等（最关键的索引）
CREATE UNIQUE INDEX uk_m16_inpcharge_source
    ON m16_inpatient_charge (source_type, source_id)
    WHERE status = 'NORMAL' AND is_deleted = FALSE;

-- 一住院一账户
CREATE UNIQUE INDEX uk_m16_deposit_account
    ON m16_deposit_account (admission_id)
    WHERE is_deleted = FALSE;

-- 一账期一结算
CREATE UNIQUE INDEX uk_m16_inpsettle_period
    ON m16_inpatient_settlement (admission_id, period_start, period_end)
    WHERE status = 'SETTLED' AND is_deleted = FALSE;

-- 一计费单一住院结算
CREATE UNIQUE INDEX uk_m16_inpsettle_billing
    ON m16_inpatient_settlement (billing_no)
    WHERE billing_no IS NOT NULL AND is_deleted = FALSE;

-- 在院患者预警扫描
CREATE INDEX idx_m16_deposit_acc_warn
    ON m16_deposit_account (dept_id)
    WHERE status = 'ACTIVE';
```
