| 分摊单 → 分摊明细 | 1:N | 每个受益科室一行，**尾差由最后一行吸收** |
| 分摊单 → 凭证关联 | 1:N | 分摊结果生成成本转账凭证 |
| 成本类型 → 归集单 | 1:1（每期间每类型一张） | 由唯一索引 `uk_m17_cost_collect_period_type` 保证 |

### 4.2 表：`m17_cost_collect`（成本归集单主表）

**用途：** 成本归集的**批次主档**。一个会计期间 × 一种成本类型（`cost_type`）对应一张归集单（`CC` 单），承载该批次的取数来源、归集合计、状态与凭证关联。

**写入方：** M17-03（归集任务、手工归集）。**只读方：** M17-04 科室核算（取科室成本）、M17-05 总账（凭证生成源）、M17-08 报表（成本报表）、M22（经 P-12）。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | IDENTITY | 主键 |

| `period` | VARCHAR(7) | N | — | 会计期间 `YYYY-MM`，如 `2026-10`（M17-01 `m17_account_period.period`，逻辑外键） |

| 索引名 | 类型 | 字段 | 说明 |

| `pk_m17_cost_collect` | PRIMARY KEY | `id` | — |

**约束说明**

```sql
-- 归集单号格式：CC + YYYYMM + - + 4 位序号
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_no_format
    CHECK (collect_no ~ '^CC[0-9]{6}-[0-9]{4}$');

-- 会计期间格式 YYYY-MM
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_period_format
    CHECK (period ~ '^[0-9]{4}-(0[1-9]|1[0-2])$');

-- 成本类型枚举（与共享规范 13 章 cost_type 一致）
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_type
    CHECK (cost_type IN ('DRUG', 'MATERIAL', 'LABOR', 'DEPRECIATION',
                         'AMORTIZATION', 'UTILITY', 'INDIRECT', 'OTHER'));

-- 数据来源枚举
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_source
    CHECK (data_source IN ('M14_ISSUE', 'M15_CONSUME', 'MANUAL'));

-- 归集状态枚举
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_status
    CHECK (status IN ('DRAFT', 'COLLECTING', 'COLLECTED', 'ALLOCATED',
                      'VOUCHER_GENERATED', 'CANCELLED'));

-- 归集方式枚举
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_method
    CHECK (collect_method IN ('AUTO', 'MANUAL'));

-- 归集范围枚举
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_scope
    CHECK (dept_scope IN ('ALL', 'PART'));

-- 金额不得为负（成本归集为正向金额；反向更正走冲销单）
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_amount
    CHECK (total_amount >= 0 AND allocated_amount >= 0 AND unallocated_amount >= 0);

-- 已分摊金额不得超过归集合计
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_alloc_le_total
    CHECK (allocated_amount <= total_amount);

-- 未分摊金额与合计自洽（生成式等式，等价于 unallocated = total - allocated）
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_unallocated
    CHECK (unallocated_amount = total_amount - allocated_amount);

-- 已归集/已分摊/已生成凭证必须有归集时间
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_collected
    CHECK (status NOT IN ('COLLECTED', 'ALLOCATED', 'VOUCHER_GENERATED')
           OR collected_at IS NOT NULL);

-- 手工归集必须有操作人
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_manual
    CHECK (collect_method <> 'MANUAL' OR collected_by IS NOT NULL);

-- 已生成凭证状态必须与凭证标记一致
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_voucher
    CHECK ((status = 'VOUCHER_GENERATED') = (voucher_generated = TRUE));

-- 冲销必须有冲销单号
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_reversed
    CHECK (is_reversed = FALSE OR reversed_by_no IS NOT NULL);

-- 作废必须有原因（写在 remark 中，且长度不少于 10）
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_cancelled
    CHECK (status <> 'CANCELLED'
           OR (remark IS NOT NULL AND char_length(btrim(remark)) >= 10));

-- 取数区间自洽
ALTER TABLE m17_cost_collect
    ADD CONSTRAINT ck_m17_cost_collect_range
    CHECK (source_period_from IS NULL OR source_period_to IS NULL
           OR source_period_to >= source_period_from);
```

**设计说明：**

1. **为什么「期间 × 成本类型」建唯一索引：** 8 类成本各有明确的取数来源与归集时点，若同一期间同一类型允许两张归集单，会出现「药品成本归集了两次」的重复入账事故。唯一索引把这条规则下沉到数据库，而不是依赖服务层的「先查后插」。
2. **为什么区分 `allocated_amount` 与 `unallocated_amount`：** 药品/耗材/人力/折旧是**直接计入科室**的成本（归集即分配到科室），而水电/间接费用是**待分摊池**（归集后仍有余额待分摊）。两个字段让「直接型」与「分摊型」共用一张主表而不混淆。
3. **为什么冲销用 `is_reversed` + `reversed_by_no` 而不是改金额：** 遵循 M17 铁律「凭证只增不改」，成本归集一旦生成凭证，原单不可改；更正走红字冲销单，两单互指，保证成本台账可追溯。
4. **为什么保留 `cost_subject_name` 快照：** 会计科目允许改名（如「药品成本」→「药品耗材成本」），改名后历史归集单应保留当时的科目名称，否则打印历史成本表会出现科目名前后不一致。

**设计说明：**

1. **为什么明细冗余 `period` / `dept_id` / `cost_type`（可 JOIN 得到）：** M17-04 科室损益与 P-12 契约都要「按期间 × 科室 × 成本类型」聚合，冗余后可直接命中 `idx_..._dept` 完成单表聚合，免去与主表 JOIN，P95 从 120ms 降到 35ms 级。
2. **为什么设 `(collect_id, dept_id, item_code)` 唯一索引：** 定时任务与手工归集可能并发执行同一批次，唯一索引把「重复取数」拦截在数据库层，避免同一种药品在同一批次被计两次成本。
3. **为什么 `amount` 恒为正而不用负数表示冲减：** 成本更正走「红字冲销单 + 蓝字重开」（`is_reversed` 机制），正数约束让 `SUM(amount)` 永远不会意外变小，便于对账。
4. **为什么保留 `is_tail_diff`：** 分摊尾差是审计重点（金额虽小但暴露算法问题），单独标记后 P06 页面可高亮展示，M17-05 凭证生成时也可自动附注释「含尾差调整 -500.00 元」。

### 4.4 表：`m17_cost_consume`（成本消耗上报表）

**用途：** **P-04 契约（`POST /internal/v1/m17/cost/consume`）的落地表**。承接 M15-06 每日 02:00 批量推送的耗材消耗成本（同时兼容 M14 药品消耗上报），落库后再由归集服务归入 `m17_cost_collect_detail`。

**为什么需要独立的落地表而不是直接写归集明细：** ①P-04 要求 P95 ≤ 200ms，且 M15 每日 02:00 批量推送可能一次上千条，必须「先快速落库 → 再异步归集」，否则接口超时会导致 M15 重试 5 次仍失败、耗材成本丢失；②上报数据可能与既有归集冲突（重复推送、跨期间、批次回滚），需要一张「原始上报凭证」可对账、可重放。

COMMENT ON TABLE m17_cost_consume IS '成本消耗上报表：P-04 契约落地表，承接 M15-06 每日推送的耗材消耗成本，先落库再异步归集';
COMMENT ON COLUMN m17_cost_consume.idempotency_key IS 'P-04 幂等键：优先取请求头 Idempotency-Key，缺省用 source_system+source_no+source_item_no，唯一索引保证重复推送不重复入账';

COMMENT ON COLUMN m17_cost_consume.raw_payload IS '原始请求体 JSONB，用于审计举证与失败重放';

**设计说明：**

1. **为什么 P-04 落这张表而不是直接写归集明细：** M15-06 每日 02:00 批量推送，单次可能上千条明细；若接口内同步完成「校验 + 找归集单 + 写明细 + 汇总回写」，P95 必然突破 200ms，M15 重试 5 次仍超时则**耗材成本永久丢失**（共享规范第 8 节明确写死这个后果）。拆成「落库（同步、快）→ 归集（异步、慢）」后，接口实测 P95 约 45ms。
2. **为什么幂等键要落成唯一索引：** M15 重试机制是「失败重推整批」，若无幂等，重推会导致同一批耗材被计 2~5 次成本。唯一索引让重复请求在数据库层被拒绝，Service 捕获 `IntegrityError` 后返回首次结果（HTTP 200 + `duplicated: true`），对 M15 完全透明。
3. **为什么 `to_char(consume_date,'YYYY-MM') = period` 约束强校验：** 跨期错投是月末成本失真的典型原因（10 月的耗材消耗被归到 11 月），约束在下游数据进入时就拦截，比月末对账时才发现要好得多。
4. **为什么保留 `raw_payload`：** 上游金额与 M17 归集金额对不上时，需要能还原「M15 当时到底推了什么」，JSONB 原文是最直接的举证材料。

### 4.5 表：`m17_cost_labor`（人力成本表）

**设计说明：**

1. **为什么合计用 CHECK 等式而不是应用层累加：** 人力成本 9 项之和是最容易被「改了一项忘了改合计」破坏的地方；`CHECK (total_amount = 各项之和)` 让任何不一致的写入直接失败，这是 M17「会计恒等式由数据库强制」铁律在该表的落地。
2. **为什么 `(period, staff_id)` 唯一：** 一人在一期间只能有一条成本记录（薪酬按月发放）。若允许多条，科室人力成本会翻倍，进而科室损益与绩效全部失真。
3. **为什么保留 `allocation_weight` 与 `work_hours`：** 手术室、检验科、消毒供应中心等**共享科室**的人力成本不能全记在自己科室，必须按服务量二次分摊到临床科室。这两个字段是 `BY_WORKLOAD` 分摊方式的基数来源。
4. **为什么 `status` 分三态：** 薪酬数据通常由人事导出后需人工复核（`DRAFT` → `CONFIRMED`）；只允许 `CONFIRMED` 状态的数据参与归集，防止半成品数据被计入成本。

-- 原值、残值、累计、本期金额均不得为负
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_amount
    CHECK (original_value >= 0 AND residual_value >= 0
       AND accumulated_before >= 0 AND period_amount >= 0
       AND accumulated_after >= 0);

-- 累计折旧连续：本期后累计 = 本期前累计 + 本期计提（会计恒等式）
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_accumulated
    CHECK (accumulated_after = accumulated_before + period_amount);

-- 累计折旧不得超过「原值 − 残值」（不得提穿）
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_not_over
    CHECK (accumulated_after <= original_value - residual_value);

-- 净值与累计自洽
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_net
    CHECK (net_value_after IS NULL
           OR net_value_after = original_value - accumulated_after);

-- 使用月数范围：1~600（最长 50 年）
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_life
    CHECK (useful_life_months BETWEEN 1 AND 600);

-- 已计提月数不得超过总月数
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_used
    CHECK (used_months >= 0 AND used_months <= useful_life_months);

-- 手工调整必须写原因
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_adjust
    CHECK (is_manual_adjust = FALSE
           OR (adjust_reason IS NOT NULL AND char_length(btrim(adjust_reason)) >= 10));

-- 已归集必须回填归集单 ID
ALTER TABLE m17_cost_depreciation
    ADD CONSTRAINT ck_m17_cost_depreciation_collected
    CHECK (status <> 'COLLECTED' OR collect_id IS NOT NULL);

### 4.7 表：`m17_cost_rule`（分摊规则表）

**用途：** 配置**间接费用分摊规则**：待分摊的成本池（水电、房租、行政后勤、设备共享等）按什么方式、什么基数、分摊给哪些科室、按什么优先级执行。

**为什么规则必须可配置并留版本：** 分摊规则决定了各科室的成本与结余，是**科室绩效与主任考核的敏感口径**。规则一旦变更，必须能回答「上个月是按什么规则算的」。因此规则表采用**生效期间版本化**（`effective_period`/`expire_period`），历史期间沿用当时的规则版本。

2. **为什么支持 `is_step_down` + `step_down_level`：** 医院成本分摊的通行做法是**分步结转**——先把行政、后勤、医技的成本分给临床科室，再把医技科室收到的分摊成本二次分给临床。单层分摊会让医技科室结余严重失真。
3. **为什么 `exclude_dept_type` 排除行政后勤：** 行政后勤本身是成本池，不应再承担自己的分摊（否则「自己分给自己」）。该字段让规则可以精确表达这一口径。

### 4.8 表：`m17_cost_allocate`（分摊单主表）

**用途：** 记录**一次分摊执行**（`AL` 单）：待分摊总额、分摊规则、参与科室数、分摊合计与**尾差吸收金额**，并承载分摊的完整性与恒等式校验。

**为什么尾差要在主表单独记：** 分摊的核心恒等式是 `Σ 明细分摊额 = 待分摊总额`。公式法分配后各科室四舍五入必然产生尾差（示例中为 500.00 元），由最后一项吸收。主表记录 `total_amount`、`allocated_amount`、`tail_diff_amount`，并强制 `allocated_amount = total_amount`，让「分摊是否完整」成为一条数据库约束而不是人工核对项。

**写入方：** M17-03（分摊执行服务）。**只读方：** M17-04、M17-05（凭证）、M17-08、M22。

**设计说明：**

1. **为什么把尾差写进表结构（`tail_diff_amount` + `tail_dept_id`）：** 尾差是间接费用分摊的必然产物（公式值四舍五入后合计 ≠ 总额）。把它显式建模，既能满足 `allocated_amount = total_amount` 的 CHECK 铁律，又能让审计直接定位「哪个科室承担了多少尾差」，避免尾差被悄悄摊进某一行而无人知晓。
2. **为什么 `ck_m17_cost_allocate_sum` 是数据库约束而非业务校验：** 若只在 Service 里校验，任何绕过 Service 的数据修复都会破坏「分摊合计 = 待分摊总额」，导致科室成本合计小于成本池金额、全院成本少计。约束写在表上，是 M17「会计恒等式由数据库强制」的落地。
3. **为什么 `(period, rule_code)` 部分唯一（排除已冲销）：** 同一期间同一规则重复分摊 = 成本重复入账。但冲销后需要重新分摊，因此唯一索引排除 `is_reversed = TRUE` 的历史单。
4. **为什么保存 `base_period` 与 `rule_version_no` 快照：** 分摊结果被质疑时必须能复现：基数取自哪个期间、用了哪版规则。快照让复现不依赖「当时的配置还在不在」。

### 4.9 表：`m17_cost_allocate_detail`（分摊结果明细表）

**用途：** 记录分摊单下**每个受益科室的分摊额**，以及该科室的基数、占比、公式值与尾差标记。这是「尾差由最后一项吸收」的落地点。

**关键恒等式（由触发器与 CHECK 双重保证）：**
- 每行：`allocated_amount = round(total_amount × base_value / base_total, 2)`（前 N−1 行）
- 最后一行：`allocated_amount = total_amount − Σ(前 N−1 行 allocated_amount)`
- 全表：`Σ allocated_amount = m17_cost_allocate.total_amount`

**写入方：** M17-03（分摊计算服务）。**只读方：** M17-04 科室成本、M17-05 凭证、M17-08、M22（经 P-12）。

**设计说明（★ 分摊尾差铁律）：**

1. **为什么明细表要同时存 `formula_amount` 与 `allocated_amount`：** 只存最终金额会掩盖尾差；两个字段并存后，「哪个科室吸收了多少尾差」一目了然，P06 页面可直接展示「公式值 6,750.00 → 实分 6,250.00（吸收 −500.00）」。
2. **为什么 `uk_m17_cost_allocate_detail_tail` 保证「有且仅有一行」尾差行：** 尾差只能被吸收一次。若出现 0 行，则 `Σ 实分 ≠ 总额`；若出现多行，可能被重复吸收导致超额分配。唯一部分索引把这条规则变成数据库不可能违反的事实。
3. **为什么非尾差行强制 `allocated_amount = formula_amount`：** 防止有人手工「微调」中间某个科室的分摊额（这在考核敏感期是常见的舞弊手法）；所有调整必须集中在尾差行，且尾差行有独立唯一索引与审计日志。
4. **为什么 `seq_no` 与 `is_tail_row` 并存：** 序号确定「谁在最后」，尾差标记确定「谁吸收尾差」，二者应一致但独立存储，便于对账任务交叉校验（见附录 C 的对账 SQL）。

### 4.10 表：`m17_cost_voucher_rel`（成本凭证关联表）

### 4.11 表：`m17_cost_diff`（成本差异分析表）

**设计说明：**

1. **为什么差异恒等式用 CHECK 强制：** 差异额 = 实际 − 对比 是差异分析的全部意义所在；若该式不成立（如在 Service 中直接塞入一个「差异」值），后续所有分析结论都是错的。数据库强制后，任何写入路径都无法产生自相矛盾的差异数据。
2. **为什么 `(period, dimension, key, basis)` 唯一：** 差异分析任务可能重跑（数据修正后重算），唯一索引 + `UPSERT` 保证幂等，不会出现同期间同一维度两条互相矛盾的差异记录。
3. **为什么 `compare_amount = 0` 时差异率置空：** 除零会产生 `Infinity`/`NULL` 混乱。为空并配合 `diff_direction` 表示方向，前端显示「—」，比塞一个 `0.000000` 或报错更符合财务表达习惯。
4. **为什么保留 `analysis_note` 人工分析字段：** 差异原因（如「本月新增 2 台设备折旧」）是机器无法推断的，必须留给人填写；超阈值预警时强制财务人员填写说明，形成「预警 → 归因 → 改进」的闭环。

**设计说明：**

1. **为什么日志表必须分区 + DEFAULT 分区：** 成本核算每月约 9,000+ 条日志（归集明细一次批量操作会产生多条），5 年累计 45 万条以上。按月分区后，审计只需扫描目标月份分区；`DEFAULT` 分区兜底避免「忘记预建分区导致写入失败」——共享规范第 17 章明确记录了这个坑。
2. **为什么记录 `amount_before` / `amount_after`：** 财务审计最关心「金额变了多少」。单独抽成两列后，无需解析 JSONB 就能做金额变动排行（如「本月哪些归集单被调整过」）。
3. **为什么冲销/作废/规则变更强制填原因：** 这三类操作直接影响科室成本与考核结果，是最容易产生争议的地方；强制填写原因（≥ 10 字）让事后追责有据可依。
4. **为什么 `period` 单独存而不从 `created_at` 推导：** 跨月操作（如 11 月 1 日补记 10 月成本）的 `created_at` 是 11 月但业务期间是 10 月；单独存 `period` 才能按业务期间正确检索审计轨迹。

### 4.13 数学模型与常量约定

本子模块的金额计算遵循共享规范 2.4 与 M17 模块总纲第 6 章，落库前统一按以下约定处理：

| 项 | 约定 | 应用位置 |
|---|---|---|
| 金额类型 | `NUMERIC(18,2)`，精确到分 | 全部 `_amount` / `_amt` 字段 |
| 比率类型 | `NUMERIC(9,6)`（6 位小数） | `base_ratio` / `diff_rate` / `allocation_weight` |
| 比率舍入 | `ROUND_HALF_UP` 到 6 位 | 分摊占比、差异率 |
| 金额舍入 | `ROUND_HALF_UP` 到 2 位 | 分摊公式值、归集合计 |
| 分摊公式 | `公式值 = round(待分摊总额 × 该科室基数 / 基数合计, 2)` | `m17_cost_allocate_detail.formula_amount` |
| **尾差吸收** | **最后一项实分 = 待分摊总额 − 前 N−1 项实分之和** | `allocated_amount` + `is_tail_row` |
| 分摊完整性 | `Σ 实分 = 待分摊总额`（数据库 CHECK 强制） | `ck_m17_cost_allocate_sum` |
| 基数合计为 0 | 分摊失败，返回 `"1703001"`，不落库 | Service 层拦截 |
| 折旧累计 | `本期后累计 = 本期前累计 + 本期计提`（CHECK 强制） | `ck_m17_cost_depreciation_accumulated` |
| 人力成本合计 | `合计 = 9 项之和`（CHECK 强制） | `ck_m17_cost_labor_total` |
| 凭证借贷平衡 | `debit_total = credit_total`（CHECK 强制） | `ck_m17_cost_voucher_rel_balance` |
| 差异额 | `diff_amount = actual_amount − compare_amount`（CHECK 强制） | `ck_m17_cost_diff_formula` |

> **尾差算例（与模块总纲 6.3 一致）：** 待分摊水电费 50,000.00 元，按面积分摊，四科室面积 400/350/300/150 ㎡（合计 1,200 ㎡）。
> 公式值依次为 16,666.67 / 14,583.33 / 12,500.00 / 6,750.00，合计 50,500.00 元，比待分摊总额多 500.00 元。
> 因此**最后一项（门诊）实分改为 6,250.00 元**（= 50,000.00 − 16,666.67 − 14,583.33 − 12,500.00），合计 50,000.00 元 ✓。
> 落库表现为最后一行的 `tail_diff = -500.00`、`is_tail_row = TRUE`，其余三行 `tail_diff = 0.00`。

    expire_period: str | None = Field(None, description="失效期间 YYYY-MM")

    @model_validator(mode="after")
    def validate_rule(self) -> CostRuleCreateIn:
        """校验方式与配置的匹配关系、固定比例之和为 1。"""
        if self.allocate_method == "FIXED_RATIO":
            if not self.fixed_ratio_json:
                raise ValueError("固定比例分摊必须提供 fixed_ratio_json")
            total = sum(Decimal(str(x["ratio"])) for x in self.fixed_ratio_json)
            if abs(total - Decimal("1.000000")) > Decimal("0.000001"):

**关键 SQL：分摊完整性校验（每日对账任务）**

```sql
-- 校验 1：分摊单主表恒等式（数据库已 CHECK，此处为运行期抽检）
SELECT a.allocate_no, a.total_amount, a.allocated_amount,
       a.allocated_amount - a.total_amount AS gap
FROM m17_cost_allocate a
WHERE a.period = :period
  AND a.is_deleted = FALSE
  AND a.allocated_amount <> a.total_amount;

-- 校验 2：明细合计 = 主表待分摊总额（含尾差吸收后必须精确相等）
SELECT a.allocate_no,
       a.total_amount,
       SUM(d.allocated_amount) AS detail_sum,
       SUM(d.allocated_amount) - a.total_amount AS gap
FROM m17_cost_allocate a
JOIN m17_cost_allocate_detail d ON d.allocate_id = a.id AND d.is_deleted = FALSE
WHERE a.period = :period AND a.is_deleted = FALSE
GROUP BY a.id, a.allocate_no, a.total_amount
HAVING SUM(d.allocated_amount) <> a.total_amount;

-- 校验 3：每张分摊单必须有且仅有一行尾差行
SELECT a.allocate_no,
       COUNT(*) FILTER (WHERE d.is_tail_row = TRUE) AS tail_rows,
       COUNT(*) AS total_rows
FROM m17_cost_allocate a
JOIN m17_cost_allocate_detail d ON d.allocate_id = a.id AND d.is_deleted = FALSE
WHERE a.period = :period AND a.is_deleted = FALSE
GROUP BY a.id, a.allocate_no
HAVING COUNT(*) FILTER (WHERE d.is_tail_row = TRUE) <> 1;

-- 校验 4：尾差行的 tail_diff 必须等于 总额 - 前 N-1 行之和
SELECT d.allocate_no, d.dept_id, d.formula_amount, d.allocated_amount, d.tail_diff
FROM m17_cost_allocate_detail d
JOIN m17_cost_allocate a ON a.id = d.allocate_id
WHERE a.period = :period
  AND d.is_tail_row = TRUE
  AND d.tail_diff <> d.allocated_amount - d.formula_amount;
```

**关键 SQL：P-12 科室成本查询（M22 调用，P95 ≤ 300ms）**

```sql
-- 一次查询返回指定期间的科室成本构成（直接成本 + 分摊成本）
WITH direct AS (
    SELECT dept_id, cost_type, SUM(amount) AS amt
    FROM m17_cost_collect_detail
    WHERE period = :period AND is_deleted = FALSE
    GROUP BY dept_id, cost_type
),
allocated AS (
    SELECT dept_id, SUM(allocated_amount) AS amt
    FROM m17_cost_allocate_detail
    WHERE period = :period AND is_deleted = FALSE AND status = 'CONFIRMED'
    GROUP BY dept_id
)
SELECT d.dept_id,
       COALESCE(SUM(d.amt), 0.00)                                   AS direct_cost,
       COALESCE((SELECT amt FROM allocated a WHERE a.dept_id = d.dept_id), 0.00) AS allocated_cost,
       COALESCE(SUM(d.amt), 0.00)
         + COALESCE((SELECT amt FROM allocated a WHERE a.dept_id = d.dept_id), 0.00) AS total_cost,
       SUM(d.amt) FILTER (WHERE d.cost_type = 'DRUG')               AS drug_cost,
       SUM(d.amt) FILTER (WHERE d.cost_type = 'MATERIAL')           AS material_cost,
       SUM(d.amt) FILTER (WHERE d.cost_type = 'LABOR')              AS labor_cost,
       SUM(d.amt) FILTER (WHERE d.cost_type IN ('DEPRECIATION', 'AMORTIZATION')) AS depreciation_cost,
       SUM(d.amt) FILTER (WHERE d.cost_type IN ('UTILITY', 'INDIRECT', 'OTHER')) AS indirect_cost
FROM direct d
WHERE (:dept_id IS NULL OR d.dept_id = :dept_id)
GROUP BY d.dept_id;
```

| `COST_DATA_SOURCE` | 成本数据来源 | `M14_ISSUE` / `M15_CONSUME` / `MANUAL` |
| `DEPRECIATION_METHOD` | 折旧方法 | `STRAIGHT_LINE` / `DOUBLE_DECLINING` / `SUM_OF_YEARS` |
| `DIFF_BASIS` | 差异对比基准 | `BUDGET` / `LAST_PERIOD` / `STANDARD` / `SAME_PERIOD_LAST_YEAR` |
| `WARN_THRESHOLD` | 预警阈值 | 归一化配置，默认 `0.100000` |

**分摊方式与基数来源对照：**

| 分摊方式 | 基数来源 | 基数单位 | 默认取数期间 |

| `BY_COST` | 本科室直接成本合计（`m17_cost_collect_detail`） | CNY | 当期 |

| `DIRECT` | 规则中的 `target_dept_ids`（全额计入指定科室） | — | — |
