### 0.3 三条铁律（违反即返工）

| # | 铁律 | 原因 |
|---|---|---|
| **1** | **数量口径三处一致**：页面总览树 `P0x` = 第 5 章 `### 5.x P0x` 标题；表清单 = `### 4.x 表：` 标题；接口总览 `API-01` 起连续无断号且每项有 `#### API-xx` 详述 | 全仓统一标准，交叉引用依赖编号稳定 |
| **2** | **本模块自己算钱**：M17 是全院唯一有权做「金额归集、分摊、结转」的模块。但**原始金额不自己算**——收入取自 M16 日结、成本取自 M14/M15、数量取自业务模块。M17 只做「取数 + 归集 + 分摊 + 凭证化」 | 上游已经算出金额，重算必然对不上账 |
| **3** | **技术栈 PostgreSQL 16**：不得出现 `AUTO_INCREMENT` / `TINYINT` / `DATETIME` / `ENGINE=` / `VARCHAR2` | 全仓已统一 PostgreSQL，MySQL 语法是硬错误 |

> **M17 专属铁律（第 4 条）：会计恒等式必须由数据库强制。** 借贷不平衡的分录**不允许落库**。每张凭证表必须有 `CHECK (debit_total = credit_total)`，每个期间必须有「期初 + 本期发生 = 期末」的校验。这不是业务规则，是数据库约束——写在表上，不是写在 Service 里。

> **M17 专属铁律（第 5 条）：凭证只增不改。** 已过账（`POSTED`）的凭证**不得 UPDATE、不得 DELETE**。更正只能走「红字冲销 + 蓝字重开」两张新凭证。表上 `REVOKE UPDATE, DELETE`，Service 层不提供修改接口。

## 1. M17 模块定位与子模块划分

### 1.1 一句话定位

**M17 财务核算管理是全院唯一的「会计账本」**：把 M16 收到的钱、M14/M15 花掉的钱、M05/M06/M09 产生的业务量，按会计科目和核算项目归集成**收入、成本、科室损益、绩效**，产出**总账、明细账、科目余额表**，并与银行/支付渠道对账，最终支撑医院财务核算与院领导决策。

### 1.2 与 M16 / M14 / M15 / M05 / M06 / M09 的六方边界（最容易搞错的六方分工）

| 维度 | M16 收费结算 | M14 药房药库 | M15 物资耗材 | M05/M06/M09 | **M17 财务核算** |
|---|---|---|---|---|---|
| **核心职责** | 收钱、开发票、日结 | 药品出入库 | 耗材出入库 | 产生业务量 | **记账、核算、报表** |
| **金额权威源** | ✅ 实收/实退 | ✅ 药品成本价 | ✅ 耗材成本价 | — | ❌ 只引用不重算 |
| **会计分录** | ❌ 不做 | ❌ 不做 | ❌ 不做 | ❌ 不做 | ✅ **唯一负责方** |
| **日结封账** | ✅ `m16_daily_close` | — | — | — | 只读，用于取数 |
| **月末结账** | — | — | — | — | ✅ `m17_period_close` |
| **科室损益** | — | — | — | — | ✅ `m17_dept_profit` |
| **绩效核算** | — | — | — | 提供工作量 | ✅ 权重与计算 |
| **银行对账** | 支付渠道流水 | — | — | — | ✅ 银行流水 vs 账面 |

**关键分工一句话：**

- **M16 管「收了多少」，M17 管「这笔钱记到哪个科目」。** M16 日结给出 `total_income` / `by_pay_method` / `by_dept`，M17 把它拆成「借：银行存款/库存现金，贷：医疗收入-门诊收入」。
- **M14/M15 管「出库多少成本」，M17 管「成本归到哪个科室」。** M14 给出期间出库成本，M17 按消耗科室分摊。
- **M05/M06/M09 管「做了多少业务」，M17 管「这些业务值多少绩效」。** 工作量由业务模块给，权重与公式由 M17 配。

### 1.3 八个子模块划分

| 编号 | 子模块 | 核心职责 | 对应总体设计 |
|---|---|---|---|
| **M17-01** | 会计基础与科目体系 | 会计科目表、核算项目、会计期间、凭证字、汇率、期初余额、账簿启用 | 「收入、成本、核算、对账、绩效」的基础 |
| **M17-02** | 收入核算与凭证 | 从 M16 日结取数，生成收入凭证、门诊/住院/视光/屈光分业务线收入归集 | **收入核算** |
| **M17-03** | 成本核算与归集 | 药品成本（M14）、耗材成本（M15）、人力成本、设备折旧、间接费用分摊 | **成本核算** |
| **M17-04** | 科室核算与损益 | 科室收入、科室成本、科室结余、内部转移价格、科室损益表 | **科室核算** |
| **M17-05** | 总账与期末结账 | 总账、明细账、科目余额表、试算平衡、月末结账、年结、凭证审核与过账 | 账簿体系 |
| **M17-06** | 银行对账与资金核对 | 银行流水导入、自动匹配、未达账项、余额调节表、支付渠道对账、长短款 | **对账** |
| **M17-07** | 绩效核算 | 绩效方案、权重配置、科室/个人绩效计算、绩效发放台账、绩效调整 | **绩效** |
| **M17-08** | 财务报表与经营分析 | 资产负债表、收入费用总表、现金流量表、科室损益报表、财务指标分析、报表导出 | **报表** |

### 2.4 时间与金额

| 类型 | 规则 | 示例 |
|---|---|---|
| 时间戳 | `TIMESTAMP`，东八区，精确到秒 | `2026-10-31 14:30:00` |
| 日期 | `DATE` | `2026-10-31` |
| 会计期间 | `VARCHAR(7)` 格式 `YYYY-MM` | `2026-10` |
| **金额** | `NUMERIC(18,2)`，**一律 2 位小数** | `1234567.89` |
| 比率/权重 | `NUMERIC(9,6)`（6 位小数，避免分摊尾差） | `0.333333` |
| 单价 | `NUMERIC(14,4)`（4 位小数） | `12.5000` |
| 数量 | `NUMERIC(14,2)` | `1.00` |

> **金额尾差铁律：** 任何按比例分摊的金额，**最后一项必须吸收尾差**，保证 `Σ分摊额 = 待分摊总额`（精确到分）。这是月末对不上账的第一大原因。

### 2.5 幂等与并发

| 场景 | 方案 |
|---|---|
| 写接口 | 支持 `Idempotency-Key` 请求头，Redis `m17:idem:{biz}:{key}` TTL 24h |
| 凭证号生成 | Redis `INCR` + 数据库 `UNIQUE` 双重保险 |
| 结账并发 | 会计期间行锁 `SELECT ... FOR UPDATE` |
| 科目余额更新 | 乐观锁 `version` 字段 |
| 报表重算 | Redis 分布式锁 `m17:lock:report:{period}` |

### 2.6 数据库硬规范

| 项 | 规则 |
|---|---|
| 主键 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| 布尔 | `BOOLEAN`，默认 `FALSE` |
| 时间戳 | `TIMESTAMP`（不用 `TIMESTAMPTZ`，全系统统一东八区） |
| 枚举 | `VARCHAR(32)` + `CHECK` 约束，**不建 PostgreSQL ENUM 类型** |
| 逻辑删除 | `is_deleted BOOLEAN DEFAULT FALSE` |
| 物理外键 | **不建**，由应用层与校验脚本保证 |
| 索引 | 部分索引 `WHERE is_deleted = FALSE` 必备 |
| 分区 | 凭证表按月 `RANGE` 分区，**必须有 `DEFAULT` 分区** |
| 约束命名 | `ck_{表名}_{语义}` |
| 索引命名 | `idx_{表名}_{字段}` / `uk_{表名}_{语义}` |

### 13.1 M17 会计期间状态 ↔ M16 日结封账状态 映射

| M17 `period.status` | M16 `daily_close.status` | 说明 |
|---|---|---|
| `NOT_OPEN` | — | 期间未启用 |
| `OPEN` | `DRAFT` / `PENDING` / `CONFIRMED` | M16 日结可继续处理 |
| `CLOSED` | `FROZEN` | M16 日结已封账，**不得再改** |
| `LOCKED` | `FROZEN` + 年结完成 | 年度封存，任何修改都需反结账 |

> **规则：** M17 结账后必须回调 M16 锁账。M16-09 U-07 `GET /internal/v1/m17/period/{date}` 就是查这个。**若 M17 返回已结账而 M16 仍允许修改日结，属于严重财务事故（已结账期间的收入被篡改）。**

## 17. 常见坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 页面总览写了 P09，第 5 章只写到 P08 | 先列总览，再逐页写，最后用脚本核对 |
| 2 | 接口总览跳号（API-12 直接到 API-14） | 分组标题行不占编号，写完用脚本扫 |
| 3 | 第 4 章留了表定义 | 详细设计第 4 章只放指引块 |
| 4 | 表数与指引块写的 N 不一致 | 数据结构文件写完 → 回填 N |
| 5 | 错误码用 M16 号段 `"1601xxx"` | M17 一律 `"170Nxxx"` |
| 6 | **收入自己从 M16 明细重算** | 一律取 `m16_daily_close` 汇总，不重算 |
| 7 | **凭证允许修改** | 已过账只能红冲，不得 UPDATE |
| 8 | **分摊后不吸收尾差** | 最后一项 = 总额 − 前 N-1 项之和 |
| 9 | 用 `DELETE` 物理删表记录 | 一律 `is_deleted = TRUE`（凭证表物理禁止） |
| 10 | 枚举中文值（`'已过账'`） | 枚举一律英文大写，中文放附录字典 |
| 11 | **P-03 期间查询路径写错** | 必须 `GET /internal/v1/m17/period/{date}`，一字不差 |
| 12 | **P-04 成本上报路径写错** | 必须 `POST /internal/v1/m17/cost/consume`，一字不差 |
| 13 | **P-05 绩效推送路径写错** | 必须 `POST /internal/v1/m17/performance/base`，一字不差 |
| 14 | 凭证号在应用层拼字符串 | 用 Redis `INCR` + 数据库 `UNIQUE` |
| 15 | 表格单元格里写了裸竖线（绝对值符号） | 写 `abs(x)`，或改用文字描述 |
| 16 | 借贷方向写「借/贷」但字段存中文 | 字段存 `D`/`C`，展示时翻译 |
| 17 | 结账后忘记回调 M16 锁账 | 结账成功后发 `m17.period.closed` 事件 |
| 18 | 金额用 `FLOAT` | 一律 `NUMERIC(18,2)` |
