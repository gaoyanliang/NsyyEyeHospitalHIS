## 2. 全局命名与建表规范

### 2.1 字段类型标准

| 语义 | PostgreSQL 类型 | SQLAlchemy | Pydantic |
|---|---|---|---|
| 主键 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `BigInteger, primary_key=True` | `int` |
| 单号/编码 | `VARCHAR(32)` / `VARCHAR(64)` | `String(32)` | `str` |
| 金额 | `NUMERIC(18,2)` | `Numeric(18, 2)` | `Decimal` |
| 单价 | `NUMERIC(14,4)` | `Numeric(14, 4)` | `Decimal` |
| 比率/权重 | `NUMERIC(9,6)` | `Numeric(9, 6)` | `Decimal` |
| 数量 | `NUMERIC(14,2)` | `Numeric(14, 2)` | `Decimal` |
| 会计期间 | `VARCHAR(7)` | `String(7)` | `str` |
| 枚举 | `VARCHAR(32)` + CHECK | `String(32)` | `str` |
| 时间戳 | `TIMESTAMP` | `TIMESTAMP` | `datetime` |
| 日期 | `DATE` | `Date` | `date` |
| 布尔 | `BOOLEAN` | `Boolean` | `bool` |
| 扩展属性 | `JSONB` | `JSONB` | `dict` |

### 2.2 必备字段

**业务主表（有生命周期）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `created_at` | TIMESTAMP | 创建时间 |
| `created_by` | BIGINT | 创建人 |
| `updated_at` | TIMESTAMP | 更新时间 |
| `updated_by` | BIGINT | 更新人 |
| `is_deleted` | BOOLEAN | 逻辑删除 |
| `version` | SMALLINT | 乐观锁版本 |

**流水表（只增不改）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `created_at` | TIMESTAMP | 创建时间 |
| `created_by` | BIGINT | 创建人 |

> 流水表**不含** `updated_at` / `updated_by` / `is_deleted` / `version`，并在表用途里注明「只增不改」，同时 `REVOKE UPDATE, DELETE`。

### 2.3 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 表 | `m17_{子模块语义}_{实体}` 单数 | `m17_account_subject` |
| 主键索引 | `pk_{表名}` | `pk_m17_account_subject` |
| 唯一索引 | `uk_{表名}_{语义}` | `uk_m17_account_subject_code` |
| 普通索引 | `idx_{表名}_{字段}` | `idx_m17_voucher_period` |
| 检查约束 | `ck_{表名}_{语义}` | `ck_m17_voucher_balance` |
| 分区表 | `{表名}_p{yyyymm}` / `{表名}_pdefault` | `m17_voucher_p202610` |

## 3. 会计恒等式的数据库强制

> **这是 M17 与普通业务模块最大的技术差异：会计恒等式不是「业务规则」，是「数据库约束」。**

### 3.1 凭证级借贷平衡

```sql
-- 每张凭证借贷必相等，精确到分
ALTER TABLE m17_voucher
    ADD CONSTRAINT ck_m17_voucher_balance
    CHECK (debit_total = credit_total);
```

**为什么放在数据库而不是 Service：**

| 层 | 是否够了 |
|---|---|
| 前端校验 | ❌ 可绕过 |
| Service 校验 | ❌ 多入口、批量导入、数据修复都会绕过 |
| **数据库 CHECK** | ✅ 任何路径都拦得住 |

### 3.2 明细级合计一致

```sql
-- 凭证主表合计 = 明细合计（由触发器或应用层在事务内校验）
ALTER TABLE m17_voucher
    ADD CONSTRAINT ck_m17_voucher_entry_count
    CHECK (entry_count > 0 AND entry_count >= 2);
```

### 3.3 科目余额连续

```sql
-- 借方余额科目：期末 = 期初 + 借方发生 - 贷方发生
ALTER TABLE m17_ledger_balance
    ADD CONSTRAINT ck_m17_ledger_balance_debit
    CHECK (balance_direction <> 'DEBIT'
        OR end_balance = open_balance + period_debit - period_credit);

-- 贷方余额科目：期末 = 期初 + 贷方发生 - 借方发生
ALTER TABLE m17_ledger_balance
    ADD CONSTRAINT ck_m17_ledger_balance_credit
    CHECK (balance_direction <> 'CREDIT'
        OR end_balance = open_balance + period_credit - period_debit);
```

### 3.4 已过账凭证不可变

```sql
-- 已过账凭证禁止 UPDATE / DELETE
REVOKE UPDATE, DELETE ON m17_voucher FROM app_user;
REVOKE UPDATE, DELETE ON m17_voucher_entry FROM app_user;

-- 更正只能通过红字冲销凭证实现
-- 冲销凭证的 source = 'REVERSAL'，并以 reverse_of_voucher_id 指向原凭证
```

### 3.5 三道防线对照

| 防线 | 位置 | 拦截什么 |
|---|---|---|
| 第 1 道 | Pydantic Schema | 格式、必填、长度 |
| 第 2 道 | Service 事务 | 状态机、期间是否结账、科目是否末级 |
| 第 3 道 | **数据库 CHECK / REVOKE** | **借贷不平衡、余额断链、篡改已过账凭证** |

## 4. 分区策略

### 4.1 分区表清单

| 表 | 分区键 | 粒度 | 保留策略 |
|---|---|---|---|
| `m17_voucher` | `period` | 月 | 永久 |
| `m17_voucher_entry` | `period` | 月 | 永久 |
| `m17_bank_statement` | `trans_date` | 月 | 10 年 |
| `m17_ledger_detail` | `period` | 月 | 永久 |

### 4.2 分区 DDL 模式（必须有 DEFAULT 分区）

```sql
CREATE TABLE m17_voucher (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY,
    voucher_no   VARCHAR(32) NOT NULL,
    period       VARCHAR(7)  NOT NULL,
    debit_total  NUMERIC(18,2) NOT NULL DEFAULT 0.00,
    credit_total NUMERIC(18,2) NOT NULL DEFAULT 0.00,
    PRIMARY KEY (id, period)
) PARTITION BY RANGE (period);

-- 按月分区
CREATE TABLE m17_voucher_p202610 PARTITION OF m17_voucher
    FOR VALUES FROM ('2026-10') TO ('2026-11');

-- ★ 必须有 DEFAULT 分区，否则写入未知期间会报错
CREATE TABLE m17_voucher_pdefault PARTITION OF m17_voucher DEFAULT;
```

> **坑：** 忘记 `DEFAULT` 分区 → 新月份第一批凭证写入直接失败，且错误信息不明显（`no partition of relation found for row`）。自动化建分区任务必须在每月 25 日预建下月分区。

## 6. 建表顺序与依赖

### 6.1 全局建表顺序

```
第 1 批（无依赖）
  m17_account_subject        会计科目表
  m17_account_aux_item       核算项目
  m17_account_period         会计期间
  m17_account_voucher_word   凭证字

第 2 批（依赖第 1 批）
  m17_account_opening        期初余额（依赖科目 + 期间）
  m17_account_exchange_rate  汇率
  m17_account_book           账簿

第 3 批（业务表，依赖科目与期间）
  m17_revenue_* / m17_cost_* / m17_perf_*

第 4 批（凭证与账簿，依赖全部业务表）
  m17_voucher                凭证主表（分区）
  m17_voucher_entry          凭证明细（分区）
  m17_ledger_detail          明细账（分区）
  m17_ledger_balance         科目余额
  m17_ledger_trial           试算平衡

第 5 批（报表，只读派生）
  m17_report_*
```

### 6.2 关键依赖说明

| 表 | 依赖 | 原因 |
|---|---|---|
| `m17_ledger_balance` | `m17_account_subject`、`m17_account_period` | 余额 = 科目 × 期间 |
| `m17_voucher_entry` | `m17_voucher`、`m17_account_subject` | 分录必须挂科目 |
| `m17_dept_profit` | `m17_account_period`、M01 科室 | 科室 × 期间 |
| `m17_perf_result` | `m17_perf_scheme`、`m17_account_period` | 方案 × 期间 |

## 8. Alembic 迁移策略

### 8.1 迁移文件命名

```
alembic/versions/
├── m17_0001_create_account_base.py       # M17-01 基础表
├── m17_0002_create_revenue.py            # M17-02
├── m17_0003_create_cost.py               # M17-03
├── m17_0004_create_dept.py               # M17-04
├── m17_0005_create_voucher_ledger.py     # M17-05（含分区）
├── m17_0006_create_bank_recon.py         # M17-06
├── m17_0007_create_performance.py        # M17-07
└── m17_0008_create_report.py             # M17-08
```

### 8.2 执行顺序

```bash
alembic upgrade m17_0001   # 必须先建科目与期间
alembic upgrade m17_0002   # 再建业务表
...
alembic upgrade m17_0008
```

### 8.3 分区表迁移注意

```python
# 分区表不能在 upgrade 里用 op.create_table 建主表后忘记建分区
def upgrade() -> None:
    op.execute("""
        CREATE TABLE m17_voucher (...)
        PARTITION BY RANGE (period)
    """)
    # 预建未来 12 个月分区 + DEFAULT
    ...
```

> Alembic 对分区表支持有限，**分区表用原生 SQL 建**，不要用 `op.create_table`。
