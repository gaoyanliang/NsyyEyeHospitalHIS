| 关系 | 基数 | 说明 |
|---|---|---|
| 科室配置 → 收入/成本/转移/分摊 | 1:N | 一个科室在多个期间有多条归集记录 |

**约束说明**

```sql
-- 科室类型枚举（6 类）
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_type
    CHECK (dept_type IN ('CLINICAL', 'MEDICAL_TECH', 'PHARMACY',
                         'NURSING', 'ADMIN', 'LOGISTICS'));

-- 状态枚举
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_status
    CHECK (status IN ('ACTIVE', 'INACTIVE'));

-- 科室层级范围
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_level
    CHECK (dept_level BETWEEN 1 AND 3);

-- 生效区间必须有序
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_effective
    CHECK (effective_to IS NULL OR effective_to >= effective_from);

-- 甲级医院要求：行政/后勤类科室不得作为收入中心
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_revenue_by_type
    CHECK (dept_type NOT IN ('ADMIN', 'LOGISTICS') OR is_revenue_center = FALSE);

-- 内部服务提供方必须是医技类（检查/检验/消毒供应等）
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_provider_type
    CHECK (is_internal_provider = FALSE OR dept_type = 'MEDICAL_TECH');

-- 分摊基数不得为负
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_base
    CHECK ((allocate_base_area IS NULL OR allocate_base_area >= 0)
       AND (allocate_base_headcount IS NULL OR allocate_base_headcount >= 0)
       AND (allocate_base_workload IS NULL OR allocate_base_workload >= 0));

-- 结余目标可为负（部分科室政策允许亏损），但结余率目标须在合理区间
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_target_rate
    CHECK (target_surplus_rate IS NULL
        OR (target_surplus_rate >= -1.000000 AND target_surplus_rate <= 1.000000));

-- 绩效系数必须在 0.500000 ~ 2.000000 之间
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_perf
    CHECK (perf_coefficient >= 0.500000 AND perf_coefficient <= 2.000000);

-- 上级科室不能是自己
ALTER TABLE m17_dept_config
    ADD CONSTRAINT ck_m17_dept_config_parent_self
    CHECK (parent_dept_id IS NULL OR parent_dept_id <> dept_id);
```

**设计说明**

1. **为什么按 `effective_from` 版本化：** 科室类型、分摊基数（面积/人数）会随年度调整变化。若只存当前值，跨期对比时无法还原「当时用的是哪个面积」。版本化后任意期间的归集与分摊都可精确复现。
2. **`is_internal_provider` 只能医技类：** 内部转移价格的本质是「医技科室向临床科室提供服务」，由 CHECK 约束 `ck_m17_dept_config_provider_type` 强制。这样杜绝了「行政科室内转自定价」这类财务造假路径。
3. **行政/后勤不得为收入中心：** `ck_m17_dept_config_revenue_by_type` 保证这两类科室不产生收入，其成本全部通过分摊进入临床。这符合医院科室核算的行业惯例。

### 4.3 表：`m17_dept_revenue`（科室收入归集表）

**用途：** 把 M17-02 归集好的收入按「科室 × 会计期间 × 业务线 × 收入科目」拆到科室。这是 `m17_dept_profit.revenue_amount` 的唯一数据来源。

**关键设计：不重算金额。** 本表的 `revenue_amount` 直接取自 M17-02 的收入凭证/归集结果（`m17_revenue_collect`）与 M16 日结汇总，**本模块只做「按科室重新分组」**，不做任何金额加法以外的运算。若科室维度缺失，按 `m17_dept_config` 的默认映射规则推导，并标记 `is_estimated = TRUE`。

**写入方：** M17-04（P02 科室收入归集，Celery 任务）。**只读方：** M17-04 损益计算、M17-08 科室损益报表、M22（P-07）。

**设计说明**

1. **`uk_m17_dept_revenue_key` 是归集幂等的基石：** 同一期间、同科室、同业务线、同科目、同来源单号只允许一条有效记录。重复跑归集任务时靠唯一索引冲突识别，而不是靠应用层「先查再插」——后者在并发下必然产生重复归集，月末收入翻倍。
2. **退费走独立字段而非负数：** `revenue_amount` 恒为非负，退费进 `cost_refund_amount`，净额由 CHECK 强制 `net = revenue − refund`。这样统计口径清晰：「本月收入 1,850,000.00，退费 32,000.00，净收入 1,818,000.00」。
3. **`is_estimated` 透明化推算：** 部分科室在 M16 日结中没有直接科室归属（如「门诊」大科室下的细分专业）。本模块按 `m17_dept_config` 的权重推算，但必须标记并按推算规则留痕，供财务复核。这比静默分摊更符合审计要求。

### 4.4 表：`m17_dept_cost`（科室成本归集表）

**用途：** 把 M17-03 归集好的**直接成本**（药品、耗材、人力、折旧、水电等）按「科室 × 期间 × 成本类型 × 成本科目」拆到科室。这是 `m17_dept_profit.direct_cost_amount` 的唯一数据来源。

**关键概念：直接成本 vs 分摊成本。** 直接成本指能明确归属到某科室的成本（该科室开单消耗的药品、该科室的设备折旧、该科室人员的工资）；分摊成本指无法直接归属、需按规则分摊的公共成本（全院水电、行政人力、物业管理）。本表只存**直接成本**，分摊成本见 `m17_dept_allocation`。

**写入方：** M17-04（P03 科室成本归集）。**只读方：** M17-04 损益计算、M17-07 绩效（科室成本率）、M17-08 报表。

**设计说明**

1. **直接成本与内部转移成本分开标记：** 二者在损益表的含义不同。直接成本是科室真实消耗的资源；内部转移成本是本应计入本科室、但因由医技科室提供服务而发生的账面转移。分开标记后，可单独分析「某临床科室有多少成本其实是医技服务带来的」（`cost_nature = 'TRANSFER'` 汇总即得）。
2. **`ck_m17_dept_cost_amount_formula` 闭环校核金额：** 当数量与单价都存在时，强制 `cost_amount = round(quantity × unit_price, 2)`，容差 0.01 元用于吸收 4 位单价舍入。这防止了「改了数量忘改金额」的脏数据——与 M17-01 的余额校验同理。
3. **与 M17-03 的分工：** M17-03 负责「全院成本归集」（按成本类型汇总，不拆科室）；本表负责「按科室拆分」。若 M17-03 已给出科室维度，本表直接透传；若未给出（如折旧按全院计提），本表按 `m17_dept_config` 的资产归属或面积权重拆分，并标记 `is_estimated`。

### 4.5 表：`m17_dept_transfer`（内部转移价格表）

**用途：** 定义并记录**内部转移价格**。医技科室（检验科、影像科、消毒供应中心等）为临床科室提供检查/检验/消毒等服务时，按内部价结算：**医技科室确认内部收入，临床科室确认内部成本**。这是科室损益表能反映「谁真正创造了价值」的关键机制。

**核心恒等式（本表强制）：**

```
transfer_amount = out_revenue_amount = in_cost_amount
即：转出科室（医技）的内部收入 = 转入科室（临床）的内部成本 = 转移金额
```

这不是重复存储，而是**双向记账的显式校验**：任何一侧被单独修改都会被数据库拒绝。

**写入方：** M17-04（P04 内部转移价格页）。**只读方：** M17-04 损益计算、M17-07 绩效（科室间贡献）、M17-08 报表。

**设计说明**

1. **双向记账的显式校验 `ck_m17_dept_transfer_balance`：** 这是本子模块最关键的约束之一。内部转移的经济实质是「同一笔金额在医技科室记收入、在临床科室记成本」。若二者不等，全院汇总时会出现收入与成本差额，导致「全院科室结余合计 ≠ 全院总结余」。数据库强制二者相等，从根本上杜绝这类期末对不上账的问题。
2. **`pricing_method` 覆盖四种定价方式：** 医院实务中，检查检验的内部价常用「成本加成」，部分项目受物价管控用「核定价」，特殊服务可能「协商定价」。记录定价方式便于合规审查（如物价部门检查是否超核定价）。
3. **`uk_m17_dept_transfer_key` 的幂等设计：** 一次工作量数据可能被重复导入（M07 重推、任务重跑）。唯一键含 `source_ref_no`，同一来源单号在同一期间同一方向同一服务只允许一条，防止内部收入与成本被重复计入。
4. **为什么需要 `is_estimated`：** M07 的工作量数据有时不含科室成本对象（如未开单的纯工作量），此时按 `m17_dept_config` 的权重推算转入科室，必须标记供复核。

### 4.6 表：`m17_dept_allocation`（间接费用分摊结果表）

**用途：** 记录**待分摊总额（费用池）按分摊规则分摊到各科室的结果**。一行 = 「费用池 × 期间 × 接收科室」。这是 `m17_dept_profit.allocated_cost_amount` 的唯一数据来源。

**核心算法（共享规范 §6.3 + 尾差吸收铁律）：**

```
step 1  某科室公式值 = 待分摊总额 × (该科室分摊基数 / 全部分摊基数之和)
step 2  前 N-1 个科室按 step 1 四舍五入到分（ROUND_HALF_UP）
step 3  最后一个科室 = 待分摊总额 − 前 N-1 个科室之和（吸收尾差）
step 4  校验 Σ 实际分摊额 = 待分摊总额（精确到分，由 CHECK 保证）
```

**写入方：** M17-04（P05 损益计算时执行分摊，Celery 任务 `m17.dept.allocation`）。**只读方：** M17-04 损益、M17-08 报表、质控审查。

**设计说明**

1. **尾差不靠应用层「记得处理」，而靠唯一索引 + CHECK：** `uk_m17_dept_allocation_tail` 保证每个池只有一个尾差吸收项，`ck_m17_dept_allocation_tail_flag` 保证该标记只能落在真正承担尾差的那一行。若应用层算漏了尾差，`Σ allocated_amount ≠ pool_amount`，会在汇总校验（§8.5）中被发现。
2. **`allocate_ratio` 用 `NUMERIC(9,6)` 而非 2 位小数：** 共享规范 §2.4 要求比率 6 位小数。若用 0.33 这类的 2 位小数，12 个科室按 1/12 分摊会累积约 0.4 元的误差。6 位小数的相对误差在 1e-6 量级，配合尾差吸收后完全无误差。
3. **`formula_amount` 与 `allocated_amount` 并存：** 前者是「按公式该分多少」，后者是「实际分了多少」。二者的差 `tail_diff_amount` 就是尾差。这个设计让尾差可见、可审计，而不是悄悄合并进分摊额。
4. **`ck_m17_dept_allocation_no_cycle`：** `DIRECT`（直接计入）方式意味着不参与按比例分摊，此时 `allocate_base = base_total`。这防止了「甲科室分摊给乙科室、乙又分摊回甲」的循环分摊导致金额虚增。

### 4.7 表：`m17_dept_profit`（科室损益表）★ 核心表

**用途：** 科室损益的**唯一权威表**，一行 = 「科室 × 会计期间」。承载共享规范 §6.4 的核心公式：

```
科室结余 = 科室收入 − 科室直接成本 − 科室分摊成本
```

**算例（共享规范 §6.4，屈光科室 2026-10）：**

| 项目 | 金额（元） | 来源 |
|---|---|---|
| 科室收入 | 1,850,000.00 | `m17_dept_revenue` 汇总 |
| 科室直接成本 | 980,000.00 | `m17_dept_cost` 汇总 |
| 科室分摊成本 | 320,000.00 | `m17_dept_allocation` 汇总 |
| **科室结余** | **550,000.00** | 1,850,000.00 − 980,000.00 − 320,000.00 |
| **结余率** | **0.297297** | 550,000.00 ÷ 1,850,000.00，保留 6 位小数 |

**数据库强制：** `ck_m17_dept_profit_formula` 约束 `surplus_amount = revenue_amount - direct_cost_amount - allocated_cost_amount`，任何路径都无法写入不等式的数据。

**写入方：** M17-04（P05 损益计算）。**只读方：** M17-07 绩效（科室结余 × 权重）、M17-08 报表（科室损益报表）、**M22（P-07 契约）**、院领导驾驶舱。

```sql
-- 各项成本与收入不得为负（结余可为负 = 亏损）
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_non_negative
    CHECK (revenue_amount >= 0 AND revenue_external_amount >= 0
       AND revenue_internal_amount >= 0 AND revenue_refund_amount >= 0
       AND direct_cost_amount >= 0 AND allocated_cost_amount >= 0
       AND total_cost_amount >= 0
       AND drug_cost_amount >= 0 AND material_cost_amount >= 0
       AND labor_cost_amount >= 0 AND depreciation_amount >= 0
       AND transfer_cost_amount >= 0 AND other_direct_cost_amount >= 0
       AND allocated_utility_amount >= 0 AND allocated_admin_amount >= 0
       AND allocated_other_amount >= 0);

-- 结余率合理区间（允许亏损，但不能低于 -1 即成本超过收入的一倍以上视为数据异常）
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_rate_range
    CHECK (surplus_rate >= -1.000000 AND surplus_rate <= 1.000000);

-- 成本率必须在 0 ~ 2 之间
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_cost_rate_range
    CHECK (cost_rate >= 0.000000 AND cost_rate <= 2.000000);

-- 目标达成率 = 结余 / 目标（目标为 0 时不得计算）
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_achievement
    CHECK ((target_surplus_amount IS NULL AND target_achievement_rate IS NULL)
        OR (target_surplus_amount IS NOT NULL AND target_achievement_rate IS NOT NULL
            AND target_surplus_amount <> 0.00
            AND abs(target_achievement_rate
                - round(surplus_amount / target_surplus_amount, 6)) <= 0.000001));

-- 已发布必须有发布时间
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_published
    CHECK (status <> 'PUBLISHED' OR publish_at IS NOT NULL);

-- 已确认必须有确认人与时间
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_confirmed
    CHECK (status NOT IN ('CONFIRMED', 'PUBLISHED')
        OR (confirm_by IS NOT NULL AND confirm_at IS NOT NULL));

-- 上级科室不能是自己
ALTER TABLE m17_dept_profit
    ADD CONSTRAINT ck_m17_dept_profit_parent_self
    CHECK (parent_dept_id IS NULL OR parent_dept_id <> dept_id);
```

**设计说明**

1. **`ck_m17_dept_profit_formula` 是本子模块最重要的约束：** 共享规范铁律 4 要求「会计恒等式必须由数据库强制」。科室结余是 M17-07 绩效和 M17-08 报表的共同基础，若允许写入不等式的值，绩效与报表会互相矛盾且无人能追溯哪个对。数据库强制后，即使 Service 层有 bug，也只能写进平衡的数据。
2. **三个从属恒等式同样强制：** `total_cost = direct + allocated`、`revenue = external + internal`、`surplus_rate = surplus / revenue`。这三条把「分项与合计」「金额与比率」全部锁死，杜绝「改了合计忘了比率」的常见错误。
3. **`data_status` 区分终稿与暂估：** 月末时 M16 日结可能尚未封账。此时可先算 `PROVISIONAL` 供管理层参考，正式结账后重算为 `FINAL`。报表对两种状态分别标注，避免「暂估数据被当成终稿决策」。
4. **`surplus_rate` 允许负值：** 亏损科室的结余率为负（如 −0.150000 表示亏损 15%）。`ck_m17_dept_profit_rate_range` 只拦 −1 以下的异常值（意味着成本超过收入一倍以上，通常是数据错误）。
5. **`idx_m17_dept_profit_period` 带 `surplus_amount DESC`：** P-07 契约最典型的查询是「某期间科室按结余排名」。把排序键放进索引，可让 Top N 查询走索引有序扫描，无需排序步骤，满足 P95 ≤ 300ms。

3. **明细与汇总的一致性由 §8.5 的校验保证：** 数据库无法在 CHECK 里做跨表聚合，故「Σ明细 = 汇总」由 Service 层在生成明细后立即校验，并在月末结账前再执行一次全量核对（见 §8.5）。

### 4.9 表：`m17_dept_compare`（科室对比分析表）

```sql
    ADD CONSTRAINT ck_m17_dept_compare_base
    CHECK ((compare_type = 'RANK' AND base_period IS NULL)
        OR (compare_type <> 'RANK' AND base_period IS NOT NULL
            AND base_period <> period));

ALTER TABLE m17_dept_compare
    ADD CONSTRAINT ck_m17_dept_compare_revenue_delta
    CHECK (base_revenue_amount IS NULL OR revenue_delta_amount IS NULL
        OR revenue_delta_amount = cur_revenue_amount - base_revenue_amount);

-- ★ 结余增减额 = 本期 − 基期
ALTER TABLE m17_dept_compare
    ADD CONSTRAINT ck_m17_dept_compare_surplus_delta
    CHECK (base_surplus_amount IS NULL OR surplus_delta_amount IS NULL
        OR surplus_delta_amount = cur_surplus_amount - base_surplus_amount);

        OR abs(surplus_rate_delta - (cur_surplus_rate - base_surplus_rate)) <= 0.000001);

    ADD CONSTRAINT ck_m17_dept_compare_revenue_growth
    CHECK (base_revenue_amount IS NULL OR revenue_growth_rate IS NULL
        OR (base_revenue_amount <> 0.00
            AND abs(revenue_growth_rate

ALTER TABLE m17_dept_compare
    ADD CONSTRAINT ck_m17_dept_compare_negative
    CHECK ((is_negative = TRUE AND cur_surplus_amount < 0.00)
        OR (is_negative = FALSE AND cur_surplus_amount >= 0.00));

    CHECK ((rank_in_scope IS NULL AND rank_total IS NULL)
        OR (rank_in_scope IS NOT NULL AND rank_total IS NOT NULL
            AND rank_in_scope >= 1 AND rank_in_scope <= rank_total));

ALTER TABLE m17_dept_compare
    ADD CONSTRAINT ck_m17_dept_compare_percentile
    CHECK (rank_in_scope IS NULL OR rank_percentile IS NULL
        OR (rank_total > 0
            AND abs(rank_percentile
                - round(1.000000 - (rank_in_scope - 1)::NUMERIC / rank_total, 6))
                <= 0.000001));

-- 本期金额不得为负（结余可为负）
ALTER TABLE m17_dept_compare
    ADD CONSTRAINT ck_m17_dept_compare_amount
    CHECK (cur_revenue_amount >= 0.00 AND cur_total_cost_amount >= 0.00);
```

**设计说明**

1. **对比结果落库而非实时算：** 环比需要跨两个期间聚合 `m17_dept_profit`，排名需要对全科室排序。在 120 个核算单元、36 个月历史下，实时计算 P95 会超过 800ms，无法满足 P-07 的 300ms SLA。落库后查询退化为单表索引扫描。
2. **`compare_scope` 固化对比口径：** 「结余排名第 3」这个结论只有在说明「在什么范围内排名」时才有意义。若排名时含行政科室、查看时不含，同一科室会显示两个不同名次。`compare_scope` 把口径写进快照，任何时间查看都一致。
3. **`rank_percentile` 比原始排名更有可比性：** 全院 120 个科室的第 3 名与 30 个临床科室的第 3 名，实际水平差异很大。百分位消除了范围差异，适合跨期比较「排名是否在进步」。

```sql
-- 保留策略：DETACH 36 个月前的分区并归档冷存储
```

**设计说明**

1. **保留 36 个月而非 24 个月：** 财务审计通常追溯 3 个完整会计年度。业务日志（如 M11）保留 24 个月足够，但财务核算日志需满足「年度审计 + 税务检查」的周期要求。
2. **`amount_before` / `amount_after` / `amount_delta` 三字段：** 财务审计最关心「改了多少钱」。把变更前后的金额与差额都落库，审计时无需去业务表反查历史值，也无需解析 JSONB。
3. **`batch_no` 支撑批次追溯：** 一次归集或分摊任务产生数百条日志。按批次号查询可完整还原「这次任务改了哪些数据」，这是月度复算与差异定位的关键。
4. **DEFAULT 分区是硬要求：** 若缺少 DEFAULT 分区，一旦某月分区未预建，写日志会直接报错——而日志写入在业务事务内，会导致整个归集任务失败。共享规范 §2.6 明确要求必须有 DEFAULT 分区兜底。

```python
    @classmethod
    def check_period(cls, v: str) -> str:
        """校验会计期间格式 YYYY-MM。"""
        if len(v) != 7 or v[4] != "-" or not (v[:4] + v[5:]).isdigit():

            raise ValueError("会计期间月份必须在 01~12 之间")
        return v
```

## 附录 C：关键索引与查询

### C.1 查询一：科室损益排名（P-07 核心）

```sql
-- 入参：$period、$dept_type（可空）、$limit
SELECT dept_id, dept_code, dept_name, dept_type,
       revenue_amount, direct_cost_amount, allocated_cost_amount,
       total_cost_amount, surplus_amount, surplus_rate, cost_rate,
       data_status
FROM m17_dept_profit
WHERE period = $period
  AND status <> 'VOIDED'
  AND is_deleted = FALSE
  AND ($dept_type IS NULL OR dept_type = $dept_type)
ORDER BY surplus_amount DESC
LIMIT $limit;
```

**走索引：** `idx_m17_dept_profit_period (period, surplus_amount DESC)`，带排序键可免排序直接扫描。

### C.2 查询二：科室损益汇总（P-07 的 summary 字段）

```sql
SELECT count(*)                                   AS dept_count,
       COALESCE(sum(revenue_amount), 0)           AS total_revenue,
       COALESCE(sum(direct_cost_amount), 0)       AS total_direct_cost,
       COALESCE(sum(allocated_cost_amount), 0)    AS total_allocated_cost,
       COALESCE(sum(total_cost_amount), 0)        AS total_cost,
       COALESCE(sum(surplus_amount), 0)           AS total_surplus,
       count(*) FILTER (WHERE surplus_amount < 0) AS negative_dept_count,
       count(*) FILTER (WHERE data_status = 'PROVISIONAL') AS provisional_count
FROM m17_dept_profit
WHERE period = $period
  AND status <> 'VOIDED'
  AND is_deleted = FALSE;
```

**说明：** 汇总用一次聚合完成，避免 N+1 查询。`total_surplus` 必须等于 `total_revenue − total_cost`（§8.5 校验）。

### C.3 查询三：科室损益形成四步穿透

```sql
-- 第一步：收入
SELECT sum(net_revenue_amount) AS revenue_amount,
       sum(revenue_amount)     AS gross_revenue,
       sum(cost_refund_amount) AS refund_amount
FROM m17_dept_revenue
WHERE period = $period AND dept_id = $dept_id
  AND status <> 'VOIDED' AND is_deleted = FALSE;

-- 第二步：直接成本
SELECT sum(cost_amount) AS direct_cost_amount
FROM m17_dept_cost
WHERE period = $period AND dept_id = $dept_id
  AND status <> 'VOIDED' AND is_deleted = FALSE;

-- 第三步：分摊成本
SELECT sum(allocated_amount) AS allocated_cost_amount
FROM m17_dept_allocation
WHERE period = $period AND dept_id = $dept_id
  AND status <> 'VOIDED' AND is_deleted = FALSE;

-- 第四步：损益表落库结果（应与前三步运算一致）
SELECT surplus_amount
FROM m17_dept_profit
WHERE period = $period AND dept_id = $dept_id AND status <> 'VOIDED';
```

**走索引：** `idx_m17_dept_revenue_period_dept`、`idx_m17_dept_cost_period_dept`、`idx_m17_dept_allocation_period_dept` 三条复合索引，每步均为索引扫描 + 一次聚合。

### C.4 查询四：内部转移价格双向对账

```sql
-- 转出科室内部收入 与 转入科室内部成本 必须逐笔相等
SELECT t.out_dept_id, t.in_dept_id, t.service_type,
       sum(t.out_revenue_amount) AS out_total,
       sum(t.in_cost_amount)     AS in_total,
       sum(t.out_revenue_amount) - sum(t.in_cost_amount) AS diff
FROM m17_dept_transfer t
WHERE t.period = $period
  AND t.status IN ('CONFIRMED', 'POSTED')
  AND t.is_deleted = FALSE
GROUP BY t.out_dept_id, t.in_dept_id, t.service_type
HAVING sum(t.out_revenue_amount) <> sum(t.in_cost_amount);
```

**说明：** 正常情况下该查询返回 0 行（CHECK 已保证逐笔相等）。若返回行，说明存在绕过约束的历史数据，需人工核查。

### C.5 查询五：分摊平衡校验

```sql
-- 每个费用池：Σ实际分摊额 必须等于 待分摊总额
SELECT period, pool_code,
       max(pool_amount)          AS pool_amount,
       sum(allocated_amount)     AS allocated_total,
       max(pool_amount) - sum(allocated_amount) AS diff,
       count(*) FILTER (WHERE is_tail_absorber) AS tail_absorber_count
FROM m17_dept_allocation
WHERE period = $period
  AND status <> 'VOIDED'
  AND is_deleted = FALSE
GROUP BY period, pool_code
HAVING max(pool_amount) <> sum(allocated_amount)
    OR count(*) FILTER (WHERE is_tail_absorber) <> 1;
```

**走索引：** `idx_m17_dept_allocation_pool (period, pool_code)`。

### C.6 查询六：科室收入按业务线分布

```sql
SELECT biz_line,
       sum(net_revenue_amount) AS net_revenue_amount,
       count(DISTINCT dept_id) AS dept_count
FROM m17_dept_revenue
WHERE period = $period
  AND dept_id = $dept_id
  AND revenue_type = 'EXTERNAL'
  AND status <> 'VOIDED'
  AND is_deleted = FALSE
GROUP BY biz_line
ORDER BY net_revenue_amount DESC;
```

**走索引：** `idx_m17_dept_revenue_biz_line (period, biz_line)`。

### C.7 查询七：损益明细下钻

```sql
SELECT line_type, line_seq, subject_code, subject_name,
       cost_type, biz_line, pool_code, item_name, quantity,
       amount, amount_ratio
FROM m17_dept_profit_detail
WHERE profit_id = $profit_id
  AND is_deleted = FALSE
ORDER BY line_type, line_seq;
```

**走索引：** `idx_m17_dept_profit_detail_profit (profit_id, line_type, line_seq)`，与排序键一致。

### C.8 查询八：亏损科室清单

```sql
SELECT dept_id, dept_name, dept_type, revenue_amount,
       total_cost_amount, surplus_amount, surplus_rate, data_status
FROM m17_dept_profit
WHERE period = $period
  AND surplus_amount < 0
  AND status <> 'VOIDED'
  AND is_deleted = FALSE
ORDER BY surplus_amount ASC;
```

**走索引：** `idx_m17_dept_profit_negative (period, dept_id) WHERE surplus_amount < 0`。

### C.9 查询九：科室环比对比
