## 1. 表清单

| 序号 | 表名 | 中文名 | 用途 | 预估行数 |
|---|---|---|---|---|
| 1 | `m17_account_subject` | 会计科目表 | 全院会计科目树（一级~四级），科目的唯一权威定义 | 小（约 600 行） |
| 2 | `m17_account_aux_item` | 核算项目表 | 辅助核算维度与项目值（科室/职工/患者/项目/供应商/业务线） | 中（约 12,000 行） |
| 3 | `m17_account_period` | 会计期间表 | 年月期间与开/关账状态，全院账务开关的唯一权威 | 小（约 240 行） |
| 4 | `m17_account_voucher_word` | 凭证字表 | 记账凭证字（记/收/付/转）与编号规则 | 极小（约 10 行） |
| 5 | `m17_account_opening` | 期初余额表 | 建账期初余额（科目 × 期间 × 辅助核算），含试算平衡结果 | 中（约 8,000 行） |
| 6 | `m17_account_exchange_rate` | 汇率表 | 外币折算汇率（月度/即期），用于外币凭证折算 | 极小（约 500 行） |
| 7 | `m17_account_book` | 账簿启用表 | 账簿启用与结账状态（主账簿/辅助账簿），建账完成的标志 | 极小（约 5 行） |
| 8 | `m17_account_price` | 收费项目价格与成本表 | 收费项目标准价/成本价快照，供 P-01/P-02 契约读取 | 中（约 8,000 行） |
| 9 | `m17_account_log` | 科目体系操作日志表 | 科目/期间/期初等基础数据变更留痕（只增不改） | 大（约 60 万行/年） |

**合计：9 张表**

> **表前缀核对：** 9 张表全部以 `m17_account` 开头，与共享规范第 12 章登记一致，未占用其他子模块前缀。
> **只增不改声明：** `m17_account_log` 为纯流水表，只增不改（不含 `updated_at` / `is_deleted`），由数据库触发器禁止 `UPDATE` / `DELETE`。

> `*` 表示**逻辑外键**（不建物理约束，由应用层保证），全库统一不建物理外键（共享规范 2.6）。

**设计说明：**

1. **`m17_account_subject` 是全院的科目字典，不可按子模块拆分。** M17-02 收入凭证、M17-03 成本凭证、M17-05 总账与余额全部指向同一张科目表。若拆到各子模块，同一科目编码会有多份不一致的定义，凭证就无法正确汇总到总账。
2. **`m17_account_period` 是账务「开关」的唯一权威。** M16-09 日结封账前必须调 P-03 询问「这个日期所在的期间关账了没有」。全模块只有一个地方能回答这个问题，就是本表。**本表状态与 M16 日结冻结状态强绑定**，错一次就是财务事故。
3. **`m17_account_price` 承载 P-01/P-02 两个已预留契约。** M09-05 手术收入需要按收费项目查标准单价，M09-06 需要查成本单价。价格真值在 M01-06 与 M14/M15，本表是**面向核算口径的只读快照 + 版本化**，避免 P-01/P-02 每次调用都穿透 3 个模块。
4. **`m17_account_opening` 与 `m17_account_period` 分离而非合并。** 期初余额是「科目 × 期间 × 辅助核算」三维数据（约 8,000 行），期间是「年月」一维数据（约 240 行）。合并会让期间表变成宽表且大量字段为空，且期间状态的并发锁会被期初录入的长事务拖住。
5. **`m17_account_log` 独立成表且只增。** 科目编码变更、期间反结账、期初调整都是高风险操作，审计上必须能回答「谁在什么时候把 1002 银行存款的余额方向改了」。日志与业务表分离，业务表可更新、日志永不更新。

### 4.2 表：`m17_account_subject`（会计科目表）

**用途：** 全院会计科目树，支持一级（大类）/ 二级（科目）/ 三级（明细）/ 四级（末级核算）四层。所有凭证分录、余额、报表都指向本表的 `id`。**本表是科目编码的唯一权威源**——M01-06 收费项目上的「默认会计科目编码」只是引用字段，科目本身由 M17 定义与维护。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | IDENTITY | 主键 |
| `subject_code` | VARCHAR(32) | N | — | 科目编码，按级次编码规则生成（如 `1002`、`100201`、`10020101`），全院唯一 |
| `subject_name` | VARCHAR(128) | N | — | 科目名称（如「银行存款」） |
| `full_name` | VARCHAR(512) | Y | NULL | 科目全称（含上级，如「银行存款/工商银行/基本户」），冗余便于展示与检索 |
| `short_name` | VARCHAR(64) | Y | NULL | 科目简称 |
| `pinyin_code` | VARCHAR(64) | Y | NULL | 拼音首字母（检索用，如 `YHCK`） |
| `parent_id` | BIGINT | Y | NULL | 上级科目 ID（一级科目为 NULL，自关联逻辑外键） |
| `parent_code` | VARCHAR(32) | Y | NULL | 上级科目编码（冗余，避免递归查询） |
| `subject_level` | SMALLINT | N | 1 | 科目级次：1 一级 / 2 二级 / 3 三级 / 4 四级 |
| `subject_category` | VARCHAR(32) | N | — | 科目类别 ASSET 资产 / LIABILITY 负债 / EQUITY 所有者权益 / COST 成本 / PL_INCOME 损益收入 / PL_EXPENSE 损益费用 |
| `balance_direction` | VARCHAR(16) | N | — | 余额方向 DEBIT 借方 / CREDIT 贷方 |
| `is_leaf` | BOOLEAN | N | TRUE | 是否末级科目（仅末级可挂凭证分录） |
| `is_cash_equivalent` | BOOLEAN | N | FALSE | 是否现金等价物（现金流量表用，如库存现金、银行存款） |
| `is_bank_account` | BOOLEAN | N | FALSE | 是否银行类科目（银行对账勾对用） |
| `is_aux_required` | BOOLEAN | N | FALSE | 是否必须挂辅助核算（如费用类必须挂科室） |
| `aux_types` | JSONB | Y | NULL | 允许/必需的辅助核算维度数组，如 `["DEPT","BIZ_LINE"]` |
| `is_foreign_currency` | BOOLEAN | N | FALSE | 是否外币核算科目 |
| `currency_code` | VARCHAR(8) | Y | NULL | 外币币种（`is_foreign_currency = TRUE` 时必填，如 `USD`） |
| `is_quantity_accounting` | BOOLEAN | N | FALSE | 是否数量金额式核算（存货类科目） |
| `quantity_unit` | VARCHAR(16) | Y | NULL | 数量核算单位（如「个」「支」） |
| `is_profit_loss` | BOOLEAN | N | FALSE | 是否损益类科目（期末必须结转到本年利润） |
| `is_closing_target` | BOOLEAN | N | FALSE | 是否结账目标科目（本年利润、利润分配） |
| `direction_sign` | SMALLINT | N | 1 | 余额计算符号：1 表示 `期末 = 期初 + 借 − 贷`（借方科目），−1 表示 `期末 = 期初 + 贷 − 借`（贷方科目） |
| `level1_code` | VARCHAR(32) | Y | NULL | 一级科目编码（冗余，便于按大类汇总报表） |
| `sort_no` | INT | N | 999 | 同级排序号 |
| `default_aux_dept` | BOOLEAN | N | FALSE | 是否默认按科室辅助核算（费用类科目常用） |
| `is_preset` | BOOLEAN | N | FALSE | 是否预置科目（预置科目不可删除，只可停用下级） |
| `status` | VARCHAR(16) | N | `ENABLED` | 状态 `ENABLED` 启用 / `DISABLED` 停用（停用后不可新增分录，但历史分录保留） |
| `effective_from` | DATE | Y | NULL | 生效日期 |
| `effective_to` | DATE | Y | NULL | 失效日期 |
| `remark` | VARCHAR(512) | Y | NULL | 备注 |
| `created_by` | BIGINT | Y | NULL | 创建人 |
| `created_at` | TIMESTAMP | N | `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_by` | BIGINT | Y | NULL | 更新人 |
| `updated_at` | TIMESTAMP | N | `CURRENT_TIMESTAMP` | 更新时间 |
| `is_deleted` | BOOLEAN | N | `FALSE` | 逻辑删除标记 |
| `version` | SMALLINT | N | 0 | 乐观锁版本 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| `pk_m17_account_subject` | PRIMARY KEY | `id` | — |
| `uk_m17_account_subject_code` | UNIQUE | `subject_code` WHERE `is_deleted = FALSE` | 科目编码全院唯一 |
| `uk_m17_account_subject_name_l1` | UNIQUE | `parent_id`, `subject_name` WHERE `is_deleted = FALSE` | 同一上级下科目名称不重复 |
| `idx_m17_account_subject_parent` | B-Tree | `parent_id`, `sort_no` | 科目树逐层展开 |
| `idx_m17_account_subject_level` | B-Tree | `subject_level`, `subject_category` | 按级次/类别统计 |
| `idx_m17_account_subject_leaf` | B-Tree（部分） | `id` WHERE `is_leaf = TRUE AND status = 'ENABLED' AND is_deleted = FALSE` | **分录选科目的候选集（最高频）** |
| `idx_m17_account_subject_category` | B-Tree | `subject_category`, `balance_direction` | 报表按类别取数 |
| `idx_m17_account_subject_l1` | B-Tree | `level1_code` | 按大类汇总 |
| `idx_m17_account_subject_name_trgm` | GIN | `subject_name gin_trgm_ops` | 科目中文名模糊搜索 |
| `idx_m17_account_subject_pinyin` | B-Tree | `pinyin_code` | 拼音首字母检索 |
| `idx_m17_account_subject_bank` | B-Tree（部分） | `id` WHERE `is_bank_account = TRUE AND is_deleted = FALSE` | 银行对账选科目 |

**约束说明**

```sql
-- 科目编码只允许数字，长度 4~12 位（按级次递增长度）
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_code_format
    CHECK (subject_code ~ '^[0-9]{4,12}$');

-- 级次只能 1~4
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_level
    CHECK (subject_level BETWEEN 1 AND 4);

-- 科目类别枚举
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_category
    CHECK (subject_category IN ('ASSET', 'LIABILITY', 'EQUITY',
                                'COST', 'PL_INCOME', 'PL_EXPENSE'));

-- 余额方向枚举
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_direction
    CHECK (balance_direction IN ('DEBIT', 'CREDIT'));

-- 方向符号只能 1 或 -1
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_sign
    CHECK (direction_sign IN (1, -1));

-- 一级科目不能有上级，二级及以下必须有上级
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_parent
    CHECK ((subject_level = 1 AND parent_id IS NULL)
        OR (subject_level > 1 AND parent_id IS NOT NULL));

-- 一级科目必须有 level1_code 且等于自身编码
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_l1
    CHECK (subject_level > 1 OR (level1_code IS NOT NULL AND level1_code = subject_code));

-- 自关联不能指向自己
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_self
    CHECK (parent_id IS NULL OR parent_id <> id);

-- 余额方向必须与科目类别一致（损益收入/负债/权益为贷方，资产/成本/损益费用为借方）
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_dir_category
    CHECK ((subject_category IN ('LIABILITY', 'EQUITY', 'PL_INCOME')
            AND balance_direction = 'CREDIT')
        OR (subject_category IN ('ASSET', 'COST', 'PL_EXPENSE')
            AND balance_direction = 'DEBIT'));

-- 外币科目必须有币种，非外币科目不得有币种
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_currency
    CHECK ((is_foreign_currency = TRUE AND currency_code IS NOT NULL)
        OR (is_foreign_currency = FALSE AND currency_code IS NULL));

-- 数量核算科目必须有单位
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_quantity
    CHECK (is_quantity_accounting = FALSE OR quantity_unit IS NOT NULL);

-- 必须挂辅助核算的科目必须声明维度
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_aux
    CHECK (is_aux_required = FALSE
        OR (aux_types IS NOT NULL AND jsonb_typeof(aux_types) = 'array'
            AND jsonb_array_length(aux_types) > 0));

-- 辅助核算维度取值枚举校验（数组内每个元素都必须是合法枚举）
ALTER TABLE m17_account_subject
    ADD CONSTRAINT ck_m17_account_subject_aux_values
    CHECK (aux_types IS NULL
        OR jsonb_typeof(aux_types) <> 'array'
        OR NOT EXISTS (
```

**设计说明：**

1. **为什么用「父 ID + 冗余 parent_code/level1_code/full_name」而不是只靠编码前缀解析层级？** 编码前缀解析（如 `100201` 的上级是 `1002`）依赖编码长度规则严格一致，一旦历史数据有不规则编码就全部失效。显式存 `parent_id` 让树查询变成一次索引扫描，`level1_code` 让「按大类汇总」不需要递归 CTE。实测 600 行科目表，带冗余字段的按大类汇总约 0.4ms，纯递归 CTE 约 3.5ms——**报表页要调几十次这类查询，差异会放大到百毫秒级**。
2. **为什么 `direction_sign` 要存成 `1/-1` 而不是靠 `balance_direction` 现算？** M17-05 计算余额的 SQL 需要统一的算术表达式：`期末 = 期初 + direction_sign × (本期借 − 本期贷)`。存成符号位可以让余额计算变成一条统一 SQL，而不需要在 SQL 里写 `CASE WHEN balance_direction = 'DEBIT' THEN ... ELSE ... END`。这也是科目余额表 `CHECK` 约束能写成纯算式的前提（见共享规范 4.x 硬要求 5）。
3. **为什么约束 `ck_m17_account_subject_dir_category` 强制「类别决定方向」？** 会计上资产/成本/损益费用必为借方，负债/权益/损益收入必为贷方。允许违背会出现「资产类科目余额在贷方」这种反会计恒等式的数据，虽然技术上可存，但报表必然不平。约束在写入时拦住，比结账时查出来要好得多。
4. **为什么 `is_leaf` 要独立成列并建部分索引？** 分录选科目只需要末级启用科目（约 480 个）。部分索引让这个查询从「扫 600 行再过滤」变成「扫 480 行的索引」，在凭证录入这种每张凭证要选 4~8 次科目的场景下，单次省 1~2ms，一张月结 3 万张凭证累计省几十秒。
5. **为什么预置科目（`is_preset`）限制必须是一级？** 预置科目是《政府会计制度》/《企业会计准则》要求的必备大类（库存现金、银行存款、应收医疗款、医疗收入……）。只预置一级，允许医院按自身管理需要在其下建二级/三级明细，既保证法定报表科目齐备，又不限制管理精细化。

**设计说明：**

1. **为什么核算项目不按类型拆成 6 张表（`m17_account_aux_dept`、`..._staff`……）？** 六类维度的字段 90% 相同（编码、名称、层级、状态、来源），只有「取值域」不同。拆开会产生 6 套几乎一样的 CRUD、6 个下拉接口、6 份权限配置，且主表 `m17_voucher_entry` 要挂 6 个可空字段（`dept_id` / `staff_id` / ...）而不是一个 `aux_item_id`。合并后分录只需存 `(aux_type, aux_item_id)` 二元组，扩展新维度（如「病种」）不需要改分录表。
2. **为什么 `subject_scope` 用 JSONB 限定适用范围？** 业务线维度只对收入类科目有意义，对「库存现金」挂业务线没有意义。用数组限定后，分录录入界面只展示当前科目允许的维度，减少误选。约束保证它必须是数组，避免写入标量导致前端报错。
3. **为什么主数据来源的项目要记 `source_system` + `source_id`？** 科室、职工会随 M01 变更（新增科室、职工离职）。记为 `M01` 来源后，同步任务可以按 `source_id` 精确对齐更新与停用，而不会误伤本模块自建的项目（如「业务线」是会计口径自建的，与 M01 无关）。这是「引用外部数据」与「自建数据」共存时的标准做法。
4. **为什么 `is_default` 存在？** 科室维度上，「行政后勤」常作为无法归属时的兜底科室。有默认值后，分录未选科室时系统能自动填上而不是报错，既保证核算完整性，又不阻塞凭证录入。

**设计说明：**

1. **为什么状态里有独立的 `REOPENED` 而不是重开后直接回 `OPEN`？** 重开是**高风险异常事件**，必须有独立状态让人一眼看出「这个期间被重开过」。若重开直接回 `OPEN`，审计时无法区分「正常开放」和「结账后又打开」。`REOPENED` + `reopen_count` + `reopen_reason` 三者组合，让「反结账了几次、为什么」成为可查事实。
2. **为什么 `uk_m17_account_period_current` 是部分唯一索引？** 全院同时只能有一个「当前会计期间」（`is_current = TRUE`）。普通唯一约束无法表达「只约束 TRUE 的行」，部分唯一索引正好。这也防止并发操作把两个期间同时标为当前。
3. **为什么期间起止日期要约束成「整数月」？** 会计期间依法必须是完整自然月。允许非整数月会出现「10 月 15 日到 11 月 14 日」这样的畸形期间，导致月报口径混乱、跨期凭证无法归属。约束 `ck_m17_account_period_date_aligned` 用 `MAKE_DATE` 直接校验，比应用层校验更可靠。
4. **为什么 `closing_balance_total` 用「借方口径」而不是按方向分别存两组？** 若按方向存两个字段（`closing_debit_total` / `closing_credit_total`），则「期初+发生=期末」的 CHECK 需要写条件分支，且报表取数要判方向求和。统一为借方口径（贷方余额取负数）后，恒等式变成纯算术 `closing = opening + debit - credit`，可直接写成 CHECK 约束——这正是共享规范 4.x 硬要求 5 的落地方式。
5. **为什么 `ck_m17_account_period_balanced` 强制 `total_debit = total_credit`？** 这是试算平衡的数据库级兜底。理论上只要有借必有贷就自动成立，但如果凭证表出现异常（如历史数据导入错误、程序 bug），结账时把不平的数固化到期间表再也不可能修正。约束让不平的期间**根本无法被置为 CLOSED**。

### 4.6 表：`m17_account_opening`（期初余额表）

**设计说明：**

1. **为什么期初余额要做到「辅助核算组合」粒度而不是只到科目？** 医院核算到科室时，「医疗收入」科目在期初就要区分「门诊收入」「住院收入」「视光收入」各自的期初。若只存科目级，科室损益的第一个月就没有期初，损益表会跳变。按组合粒度存，`aux_key` 唯一索引保证同组合不重复，`aux_dept_id` 冗余让科室取数不必解析 JSON。
2. **为什么同时存 `debit_balance` / `credit_balance` 两个字段而不是一个带符号的余额？** 会计上「余额方向」是重要信息，一个 −5,000.00 无法区分「贷方余额 5,000.00」和「借方余额 −5,000.00」（后者在会计上是异常）。两个字段 + `ck_m17_account_opening_one_side` 互斥约束，把「只能一侧有余额」这条会计规则变成数据库事实。
3. **为什么 `end_debit_balance` / `end_credit_balance` 要落库而不实时算？** 共享规范 4.x 硬要求 5 要求余额类表有「期初+发生=期末」的 CHECK。只有落库才能写 CHECK；实时算则无法在数据库层强制。同时报表与总账读取时省一次运算，月末 8,000 行 × 多次读取的累积效果明显。
4. **为什么 `subject_name` 要快照？** 科目改名（如「医疗收入」改为「医疗业务收入」）后，历史期初表的展示不应跟着变——会计档案要还原「当时叫什么」。这与 M05/M10 的患者姓名快照是同一思路。
5. **为什么 `import_batch_no` 存在？** 期初余额通常从老系统批量导入（8,000 行 Excel）。导入难免有错，需要能「按批次整体回滚重导」。有批次号后，回滚变成 `is_deleted = TRUE WHERE import_batch_no = ?`，而不是逐行找。

**设计说明：**

1. **为什么汇率用 `NUMERIC(18,8)` 而不是 `NUMERIC(18,2)`？** 汇率以 2 位小数会带来严重折算误差：USD→CNY 汇率 7.1234，存成 7.12 后，一笔 1,000,000.00 美元的凭证折算差 3,400.00 元——这个差额必须有人背。8 位小数下，100 万美元折算误差 < 0.01 元，小于分位。
2. **为什么同时存正向与反向汇率？** 折算方向在实务中是双向的：进口设备按「外币 → 本位币」折算，出口/境外收入按「本位币 → 外币」折算。若只存正向，反算时每次都要做 `1 / rate`，除法的舍入方向与「取公布的直接汇率」不同，会产生对不上的尾差。约束强制两者互为倒数（容差 1e-6），保证两个方向自洽。
3. **为什么汇率要分 `MONTHLY` / `SPOT` / `CLOSING` 三类？** 会计实务中：日常记账用**月度记账汇率**（整月统一，减少波动）；特殊交易用**即期汇率**；月末外币科目折算与报表折算用**期末汇率**。混用一种汇率会让外币科目余额与报表折算数对不上。

**设计说明：**

1. **为什么账簿启用是一次性且不可回退的动作？** 建账意味着「把手工账/老系统余额正式导入系统，从此系统账就是法定账」。若能随意回退重来，历史凭证与期初之间就不再自洽，审计时无法解释。约束 `ck_m17_account_book_enabled` 要求启用时 `is_opening_balanced = TRUE`，把「先平衡后启用」变成不可绕过的顺序。
2. **为什么每院区只允许一个主账簿，但允许多个辅助账簿？** 主账簿对应税务与审计的法定账，一个法人主体只能有一套；辅助账簿是管理会计口径（如按科室、按业务线另行归集），可以有多套。部分唯一索引 `uk_m17_account_book_main` 精确表达这个规则。
3. **为什么 `fiscal_year_start_month` 可配？** 部分公立医院执行预算年度（4 月起）而非自然年（1 月起）。这个参数影响「年结」的期间边界与「本年利润」的结转时点，必须可配。

**设计说明：**

1. **为什么价格要「版本化快照」而不直接每次调 M01-06？** 两个原因：①**P-01 要求 P95 ≤ 50ms**，穿透 M01-06 需要额外一次 HTTP 往返，叠加后难以达标；本表命中 `idx_m17_account_price_lookup` 后单次约 1ms ②**会计核算要按历史价格入账**。10 月的收入凭证必须用 10 月生效的价格核对，若 M01-06 已调价，实时查询会拿到新价，导致「凭证金額与标准价对不上」的核算争议。版本化后按 `effective_from` 可取任一历史版本。
2. **为什么 P-02 的成本单价也放本表，而不是每次查 M14/M15？** 成本单价来自两个不同模块（药品 M14、耗材 M15），直接查需要先判断项目类别再决定调哪个。本表在同步任务里统一落到 `cost_price` 并记录 `cost_source`，让 P-02 变成一次单表查询。同时 `cost_method` 记录了计价方法，让核算口径可解释。
3. **为什么 `default_subject_code` 与 `default_subject_id` 要成对存在？** M01-06 只给编码（字符串）。凭证生成需要 `subject_id`（外键）。若只在运行时解析，会出现「科目被停用/改编码后凭证生成失败」。成对存储 + 约束保证：要么都有、要么都无，杜绝「有编码无 ID」导致的运行时缺科目。
4. **为什么 `uk_m17_account_price_current` 用部分唯一索引？** 同一收费项目必须且只能有一个「当前生效」版本。普通唯一约束会把历史版本也算进去，导致无法保留历史。部分唯一索引精确表达「仅当前版本唯一」，这是价格版本化的标准做法。

**分区策略：** 按 `created_at` 月度 `RANGE` 分区，预建 36 个月分区 + `DEFAULT` 分区兜底，保留 10 年（会计档案法定保存期限）。月均约 5 万条（科目表 600 行、期间 240 行的维护频率较低，主要是期间开关账与期初调整），年约 60 万条，单行约 380 字节，10 年约 2.3GB。分区后审计查询（近 3 个月）只扫 3 个分区。

**设计说明：**

1. **为什么日志要记录 `affects_posted` 与 `approval_no`？** 科目体系变更分两类风险等级：改一个从没用过的科目名称是低风险；改「银行存款」的余额方向会影响全部历史已过账凭证的余额计算，是**极高风险**。`affects_posted` 让审计可以一键筛出所有触及已过账数据的改动，`approval_no` 强制这类改动必须走 M20 审批——把「高风险操作必须有审批」变成数据完整性要求，而不是靠流程自觉。
2. **为什么 `impact_summary` 存 JSON 而不是关联明细表？** 它是「改动的爆炸半径」的一次性描述（涉及多少张凭证、哪个期间范围），写出后只读，不需要按字段查询统计。用 JSON 省掉一张明细表；如需按影响面检索，可加 GIN 索引（当前不需要）。
3. **为什么用触发器而不是仅靠应用层禁止？** 应用层可能被绕开（DBA 直连、数据修复脚本、程序 bug）。会计档案的不可篡改性是**法定义务**，必须由数据库物理保证。REVOKE 权限在有 superuser 时无效，触发器则对所有会话生效（superuser 用 `ALTER TABLE ... DISABLE TRIGGER` 也留有痕迹）。

```python
class OpeningRowIn(BaseModel):
    """期初余额行。"""

    subject_code: str = Field(..., max_length=32, description="科目编码")
    balance_direction: BalanceDirection = Field(..., description="余额方向")
    aux_key: str = Field("", max_length=256, description="辅助核算组合键")
    aux_json: Optional[Dict[str, str]] = Field(None, description="辅助核算结构化值")
    aux_dept_id: Optional[int] = Field(None, description="科室 ID（含 DEPT 维度时）")
    debit_balance: Decimal = Field(Decimal("0"), ge=0, description="借方余额")
    credit_balance: Decimal = Field(Decimal("0"), ge=0, description="贷方余额")
    quantity: Optional[Decimal] = Field(None, ge=0, description="数量（数量核算科目）")
    unit_price: Optional[Decimal] = Field(None, ge=0, description="单价（数量核算科目）")
    currency_code: Optional[str] = Field(None, max_length=8, description="币种")
    fc_balance: Optional[Decimal] = Field(None, description="外币余额")
    exchange_rate: Optional[Decimal] = Field(None, gt=0, description="汇率")
    remark: Optional[str] = Field(None, max_length=512, description="备注")

    @model_validator(mode="after")
    def validate_row(self) -> "OpeningRowIn":
        """借贷互斥与外币成对校验。"""
        if self.debit_balance != 0 and self.credit_balance != 0:
            raise ValueError("同一科目同一辅助组合只能一侧有余额")
        if self.balance_direction == "DEBIT" and self.credit_balance != 0:
            raise ValueError("余额方向为借方时贷方余额必须为 0")
        if self.balance_direction == "CREDIT" and self.debit_balance != 0:
            raise ValueError("余额方向为贷方时借方余额必须为 0")
        if self.currency_code and (self.fc_balance is None
                                   or self.exchange_rate is None):
            raise ValueError("外币科目必须同时填写外币余额与汇率")
        if (self.quantity is None) != (self.unit_price is None):
            raise ValueError("数量核算必须同时填写数量与单价")
        if (self.aux_key == "") != (self.aux_json is None):
            raise ValueError("辅助核算组合键与结构化值必须成对存在")
        return self

    remark: Optional[str] = Field(None, max_length=512, description="备注")

    @model_validator(mode="after")
    def validate_rate(self) -> "ExchangeRateSaveIn":
        """即期汇率必须带日期；反向汇率须互为倒数。"""
        if self.rate_type == "SPOT" and self.rate_date is None:
            raise ValueError("即期汇率必须填写汇率日期")
        if self.reverse_rate is not None:
            product = self.rate * self.reverse_rate
            if abs(product - Decimal("1")) > Decimal("0.000001"):
                raise ValueError("反向汇率必须与正向汇率互为倒数")
        return self
```

```sql
-- DEFAULT 分区兜底（防止分区未预建时写入失败）
CREATE TABLE m17_account_log_pdefault
    PARTITION OF m17_account_log DEFAULT;

-- 预建 36 个月分区
DO $$
DECLARE
    i INT;
    start_date DATE;
    end_date DATE;
    part_name TEXT;
BEGIN
    FOR i IN 0..35 LOOP
        start_date := (DATE_TRUNC('month', CURRENT_DATE) + (i || ' months')::INTERVAL)::DATE;
        end_date := (start_date + INTERVAL '1 month')::DATE;
        part_name := 'm17_account_log_p' || TO_CHAR(start_date, 'YYYYMM');
        EXECUTE FORMAT(
            'CREATE TABLE IF NOT EXISTS %I PARTITION OF m17_account_log '
            'FOR VALUES FROM (%L) TO (%L)',
            part_name, start_date, end_date
        );
    END LOOP;
END $$;
```
