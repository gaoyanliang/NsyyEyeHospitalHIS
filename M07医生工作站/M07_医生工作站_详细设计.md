## 1. 模块概述

### 1.1 模块定位

医生工作站是**门诊诊疗的核心操作界面**。它回答："**医生在诊室里做什么？**"

```
┌──────────────────────────────────────────────────────────────────────┐
│                        门诊业务主链路                                  │
└──────────────────────────────────────────────────────────────────────┘

  M04 门诊管理                    ★ M07 医生工作站 ★                 M14 药房
┌──────────────┐              ┌────────────────────────────┐    ┌──────────┐
│ 挂号          │─────────────►│ 01 接诊                    │    │ 调剂发药  │
│ 分诊          │              │   ↓                        │    │          │
│ 叫号          │◄─────────────│ 02 诊断                    │    │          │
│ 收费          │              │   ↓                        │    │          │
└──────────────┘              │ 03 医嘱下达 ───┐            │    └──────────┘
                              │   ↓            │            │          ▲
                              │ 04 报告查看 ◄──┤            │          │
                              │   ↓            │            │          │
                              │ 05 处方与用药 ─┼────────────┼──────────┘
                              │   ↓            │            │
                              │ 06 文书签署 ───┘            │
                              │   ↓                        │
                              │ 07 工作量统计（只读）        │
                              └────────────────────────────┘
                                          │
                    ┌─────────────────────┼─────────────────────┐
                    ▼                     ▼                     ▼
              ┌──────────┐          ┌──────────┐          ┌──────────┐
              │ M12 检查  │          │ M13 检验  │          │ M09 手术  │
              └──────────┘          └──────────┘          └──────────┘
```

### 1.2 模块设计原则

| 原则 | 说明 |
|---|---|
| **数据流单向** | 接诊 → 诊断 → 医嘱 → 执行 → 回写，不逆向修改 |
| **状态权责分离** | M07 只管下达，执行状态由下游回写 |
| **内容与操作分离** | M07 做业务操作，M18 做内容与知识 |
| **快照优于引用** | 文书存快照，保证法律效力 |
| **只读统计** | 工作量模块只读不写业务数据 |
| **口径固化** | 所有统计口径写死在文档，可追溯 |

## 3. 业务模型

### 3.1 门诊诊疗主流程

```
┌──────────────────────────────────────────────────────────────────────┐
│                        一次完整门诊就诊                                │
└──────────────────────────────────────────────────────────────────────┘

【M04 门诊】
  挂号 ──► 缴费 ──► 分诊 ──► 排队
                              │
                              ▼
【M07-01 接诊】         叫号 ──► 医生接诊
                                  · 创建/打开会话
                                  · 加载患者完整档案（过敏史、既往史）
                                  · 显示待出报告、危急值
                              │
                              ▼
【M07-02 诊断】          主诉 ──► 检查 ──► 诊断
                                             · 主诊断（1 个，必填）
                                             · 次诊断（N 个）
                                             · 眼别（右/左/双）
                                             · 诊断依据
                              │
                              ▼
【M07-03 医嘱】          开检查/检验/治疗 ──► 提交
                                             · 五类医嘱
                                             · 医嘱套餐
                                             · 合理性校验
                              │
                              ├──── 患者缴费（M16）────┐
                              │                       ▼
                              │              【M12/M13 执行】
                              │                       │
                              │                       ▼
                              │  【M07-04 报告查看】◄─┘
                              │      · 报告列表
                              │      · 结构化数据
                              │      · 危急值处置
                              │      · 历史对比
                              │              │
                              ▼              ▼
【M07-05 处方】          开药 ──► 用法用量 ──► 签名
                                             · 眼科滴眼特定
                                             · 抗菌药分级
                                             · 合理用药审核
                                             · CA 电子签名
                              │
                              ▼
【M07-06 文书】          病历 ──► 签名 ──► 打印
                                             · 门诊病历
                                             · 处方笺
                                             · 申请单
                                             · 诊断证明
                              │
                              ▼
【M07-01 完成就诊】      8 项校验 ──► 完成
                            V-01 主诊断        （阻断）
                            V-02 编码有效      （阻断）
                            V-03 无未保存医嘱  （阻断）
                            V-04 处方已签名    （阻断）
                            V-05 视力已填      （警告）
                            V-06 病历已签名    （阻断）
                            V-07 报告已查看    （警告）

                              │
                              ▼
【M07-07 统计】          日终汇总 ──► 工作量
```

### 3.2 会话（Encounter）模型

```
m07_encounter（一次就诊会话）
├── 患者：王五 P202610200001

├── 医生：张明华
├── 科室：白内障科

│
├── 诊断（M07-02）    N 条
├── 医嘱（M07-03）    N 条
```


### 3.3 医嘱状态机（跨模块核心契约）

```
        ┌──────────┐
        │  DRAFT   │  草稿              ← M07
        └────┬─────┘
             │ issue                  ← M07
             ▼
        ┌──────────┐
        │  ISSUED  │  已下达（待缴费）    ← M07
        └────┬─────┘
             │ on_paid                ← 仅 M16
             ▼
        ┌──────────┐
        │   PAID   │  已缴费（待执行）
        └────┬─────┘
             │ on_executing           ← 仅执行方
             ▼
        ┌──────────┐
        │EXECUTING │  执行中
        └────┬─────┘
             │ on_completed           ← 仅执行方
             ▼
        ┌──────────┐
        │COMPLETED │  已完成
        └──────────┘
             │
             │ on_refunded            ← 仅 M16
             ▼
        ┌──────────┐
        │ REFUNDED │  已退费
        └──────────┘
```

> **铁律：** M07 **不直接**把医嘱置为 `PAID`/`COMPLETED`，**必须**由下游回写。

### 3.4 眼科核心约束

#### 3.4.1 眼别（Laterality）

| 代码 | 名称 | 说明 |
|---|---|---|
| `OD` | 右眼 | Oculus Dexter |
| `OS` | 左眼 | Oculus Sinister |
| `OU` | 双眼 | Oculus Uterque |
| `NA` | 不适用 | 全身性项目 |

**约束：**

| 场景 | 要求 |
|---|---|
| 按眼别计价的检查 | 眼别必填，`OU` 自动数量 ×2 |
| 手术 | 必须 `OD` 或 `OS`（单眼） |
| 滴眼液 | 必须指定眼别 |
| 检验（血糖） | `NA` |

| 字段 | 值 |
|---|---|
| 途径 | `TOPICAL_EYE`（滴眼） |
| 单次剂量 | `1` |
| 剂量单位 | `滴` |
| 频次 | `QID`（每日 4 次） |
| 眼别 | `OD`（右眼） |
| 疗程 | `7` 天 |

**用法文本自动生成：**


**5 条阻断项全部落地为真实数据校验**（不再是空壳）：

```sql
-- V-01 主诊断
SELECT count(*) FROM m07_diagnosis
WHERE encounter_id = ? AND diagnosis_type = 'PRIMARY'
  AND status = 'ACTIVE' AND is_deleted = FALSE;

-- V-08 未处置危急值
SELECT count(*) FROM m07_critical_value
WHERE encounter_id = ? AND status <> 'HANDLED';
```

## 11. 异常处理与日志

### 11.1 异常处理总原则

| 原则 | 说明 |
|---|---|
| **业务异常用错误码** | 不抛 500 |
| **依赖故障降级** | 不阻断主流程（除安全相关） |
| **安全优先** | 过敏史查不到时**拒绝开方** |
| **全量留痕** | 关键操作都写日志 |
| **可重试** | 幂等接口支持重试 |

### 11.2 降级策略汇总

| 依赖 | 故障行为 | 影响 |
|---|---|---|
| M01 主数据 | 用缓存（30 分钟），过期拒绝 | 无法开单 |
| M01 诊断字典 | 用缓存，**禁止自由文本** | 无法录诊断 |
| M03 过敏史 | **拒绝开方** | 无法开药（安全优先） |
| M03 患者信息 | 用会话快照 | 信息可能陈旧 |
| M04 挂号 | 允许接诊，异步同步 | 挂号状态滞后 |
| M18 病历 | 用简化模板 | 病历不完整 |
| M18 合理用药 | 仅本地基础校验 | **风险（记录告警）** |
| M12/M13 报告 | 兜底拉取（5 分钟） | 报告延迟 |
| PACS | 仅缩略图 | 原图不可阅 |
| M14 药房 | 处方挂起 SIGNED | 无法发药 |
| M16 收费 | 医嘱挂起 ISSUED | 无法执行 |
| Redis | 直连 DB | 锁失效（靠唯一约束） |
| 打印服务 | 导出 PDF 手动打印 | 需人工 |
| Celery | 手动触发 | 汇总延迟 |
