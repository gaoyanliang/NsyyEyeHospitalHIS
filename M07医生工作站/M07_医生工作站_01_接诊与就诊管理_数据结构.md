## 4. 数据结构设计

### 4.1 ER 关系图

```
┌──────────────────────────────────────────────────────────────────────┐
│ 上游（引用，不建物理外键）                                             │
│  m04_registration（M04-03）、m04_triage（M04-04）                     │
│  mpi_patient（M03-01）、mdm_employee / mdm_department（M01）           │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ 叫号到诊
                               ▼
┌──────────────────────────────────┐
│ m07_encounter_queue（接诊队列）    │
│  · queue_date / doctor_id        │
│  · priority_weight               │
│  · status（WAITING…SKIPPED）      │
└───────────────┬──────────────────┘
                │ 打开就诊
                ▼
┌──────────────────────────────────┐
│ m07_encounter（就诊会话）★核心    │
│  · encounter_no / encounter_date │
│  · registration_id（唯一）        │
│  · 编辑锁持有者                    │
│  · status（OPEN…CANCELLED）      │
└───┬────────┬─────────┬───────────┴──────────┬────────────┐
    │ 1:1    │ 1:N     │ 1:N                  │ 1:N        │
    ▼        ▼         ▼                      ▼            ▼
┌────────┐┌────────┐┌──────────┐        ┌──────────┐  ┌──────────┐
│draft   ││log     ││transfer  │        │diagnosis │  │ order    │
│（草稿） ││（日志） ││（转科）   │        │（M07-02）│  │（M07-03）│
└────────┘└────────┘└──────────┘        └──────────┘  └──────────┘

支撑表：
┌──────────────────────────┐
│ m07_encounter_config     │
│ （接诊配置，单行）         │
└──────────────────────────┘
```

**设计说明：**

- `m07_encounter` 与 `m04_registration` 是 **1:1**（一个挂号只有一个就诊会话）
- `m07_encounter_queue` 是接诊队列快照，**每医生每日每患者一条**
- `m07_encounter_draft` 是草稿持久化（Redis 为热缓存）
- `m07_encounter_transfer` 记录转科轨迹
- 诊断、医嘱等表由 M07-02~05 定义，通过 `encounter_id` 关联

**约束说明**

```sql
ALTER TABLE m07_encounter
    ADD CONSTRAINT ck_m07_encounter_no
    CHECK (encounter_no ~ '^EN[0-9]{8}[A-Z0-9]{4}$');

ALTER TABLE m07_encounter
    ADD CONSTRAINT ck_m07_encounter_status
    CHECK (status IN ('OPEN', 'IN_PROGRESS', 'SUSPENDED', 'CLOSING',
                       'CLOSED', 'TRANSFERRED', 'CANCELLED'));

ALTER TABLE m07_encounter
    ADD CONSTRAINT ck_m07_encounter_level
    CHECK (triage_level IS NULL
           OR triage_level IN ('L1','L2','L3','L4','L5'));

ALTER TABLE m07_encounter
    ADD CONSTRAINT ck_m07_encounter_suspend
    CHECK (suspend_reason IS NULL
           OR suspend_reason IN ('EXAM', 'PAYMENT', 'RESTROOM',
                                  'CONSULT', 'EQUIPMENT', 'HEARTBEAT_TIMEOUT',
                                  'OTHER'));

ALTER TABLE m07_encounter
    ADD CONSTRAINT ck_m07_encounter_next
    CHECK (next_action IS NULL
           OR next_action IN ('DISCHARGE', 'ADMIT', 'FOLLOWUP'));

-- 已关闭必须有时间
ALTER TABLE m07_encounter
    ADD CONSTRAINT ck_m07_encounter_closed
    CHECK (status <> 'CLOSED' OR closed_at IS NOT NULL);

-- 一挂号一会话
CREATE UNIQUE INDEX uk_m07_encounter_reg
    ON m07_encounter (registration_id)
    WHERE is_deleted = FALSE;

-- 活跃会话查询
CREATE INDEX idx_m07_encounter_active
    ON m07_encounter (doctor_id, status)
    WHERE status IN ('OPEN', 'IN_PROGRESS', 'SUSPENDED');
```

**状态机**

```
        ┌──────────┐
        │  OPEN    │  已打开
        └────┬─────┘
             │ 首次录入
             ▼
        ┌──────────────┐
        │ IN_PROGRESS  │  进行中
        └──────┬───────┘
               │
      ┌────────┼────────────┬──────────────┐
      │ 暂停    │ 完成        │ 转科          │ 作废
      ▼        ▼            ▼              ▼
┌──────────┐┌──────────┐┌──────────┐┌──────────┐
│SUSPENDED ││  CLOSED  ││TRANSFERRED││CANCELLED│
└────┬─────┘└──────────┘└──────────┘└──────────┘
     │ 恢复
     └──────────► IN_PROGRESS
```

**量级估算：**

| 项 | 数值 |
|---|---|
| 日会话数 | ≈300 条 |
| 年会话数 | ≈11 万条 |
| 单行大小 | ≈1.2 KB |
| 年存储 | ≈132 MB |

**分区：** 按 `encounter_date` 年度分区，保留 **15 年**。
