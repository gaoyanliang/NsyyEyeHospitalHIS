## 1. 设计约定

### 1.1 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 表名 | `m07_{业务}_{后缀}` | `m07_encounter` |
| 主键 | `pk_{表名}` | `pk_m07_encounter` |
| 唯一索引 | `uk_{表名}_{语义}` | `uk_m07_encounter_reg` |
| 普通索引 | `idx_{表名}_{语义}` | `idx_m07_encounter_patient` |
| 约束 | `ck_{表名}_{语义}` | `ck_m07_encounter_status` |
| ORM 类 | `M07{PascalCase}` | `M07Encounter` |
| Schema 类 | `{PascalCase}` | `EncounterCreate` |
| 错误码 | 数字区间 | `54701`（M07-01） |

### 1.2 字段规范

| 类型 | 规范 |
|---|---|
| 主键 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` |
| 外键 | `BIGINT`（**不建物理外键**，应用层保证） |
| 布尔 | `BOOLEAN`，默认 `TRUE`/`FALSE` |
| 时间 | `TIMESTAMP`（无时区） |
| 日期 | `DATE` |
| 金额 | `NUMERIC(12,2)` 或 `NUMERIC(14,2)` |
| 数量 | `NUMERIC(12,4)` |
| 百分比 | `NUMERIC(6,4)`（存 0~100） |
| 编码 | `VARCHAR(64)` |
| 名称 | `VARCHAR(200)` |
| 枚举 | `VARCHAR(16)` + `CHECK` |
| JSON | `JSONB` |
| 长文本 | `TEXT` |

### 1.3 必备字段

每张业务表必须包含：

```sql
is_deleted   BOOLEAN   NOT NULL DEFAULT FALSE   -- 逻辑删除
created_at   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
updated_at   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP  -- 触发器维护
```

**说明：** 日志类表（`*_log`、`*_print`、`*_read`）无 `is_deleted`/`updated_at`，因为不可修改。

### 1.4 通用索引

```sql
-- 全部业务表
CREATE INDEX idx_{table}_date ON {table} ({date_field});

-- 有逻辑删除的表
CREATE INDEX idx_{table}_active ON {table} (id)
    WHERE is_deleted = FALSE;
```

### 1.5 中文检索

```sql
-- 需要名称模糊搜索的表
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX idx_{table}_name
    ON {table} USING gin ({name_field} gin_trgm_ops);
```

**适用表：** `m07_order`（item_name）、`m07_report`（conclusion）、`m07_prescription_item`（drug_name）。

### 1.6 时间戳触发器

```sql
CREATE OR REPLACE FUNCTION fn_update_timestamp()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 每张含 updated_at 的表
CREATE TRIGGER trg_{table}_updated
    BEFORE UPDATE ON {table}
    FOR EACH ROW EXECUTE FUNCTION fn_update_timestamp();
```

### 1.7 无物理外键策略

**为什么不用物理外键：**

| 理由 | 说明 |
|---|---|
| 分库分表友好 | 未来可能按模块分库 |
| 微服务解耦 | 跨模块引用不同库 |
| 写入性能 | 避免外键检查开销 |
| 灵活删除 | 逻辑删除不受约束 |

**替代保障：**

- 应用层校验（Service 层）
- 数据库 `CHECK` 约束（同表内）
- 定时数据一致性校验任务

### 4.3 数据一致性保障

由于无物理外键，通过以下手段保证一致性：

| 手段 | 说明 |
|---|---|
| **Service 层校验** | 写入前查询外部数据是否存在 |
| **快照冗余** | 关键字段冗余存储（如 `item_name`、`drug_name`） |
| **定时校验任务** | 每日检查孤儿数据 |
| **MQ 事件驱动** | 主数据变更时通知 |

**孤儿数据校验示例：**

```sql
-- 检查会话引用的患者是否存在
SELECT e.id, e.patient_id
FROM m07_encounter e
LEFT JOIN mpi_patient p ON p.id = e.patient_id
WHERE e.created_at >= CURRENT_DATE - INTERVAL '1 day'
  AND p.id IS NULL;
```

**冗余快照的意义：** 即使主数据改名或删除，历史文书仍能正确显示当时的名称。

## 5. 状态机汇总

### 5.1 会话状态（`m07_encounter`）

```
WAITING → CALLED → VISITING → COMPLETED
   ↓                    ↓
CANCELLED          TRANSFERRED
```

| 状态 | 说明 |
|---|---|
| `WAITING` | 候诊中 |
| `CALLED` | 已叫号 |
| `VISITING` | 接诊中 |
| `COMPLETED` | 已完成 |
| `TRANSFERRED` | 已转诊 |
| `CANCELLED` | 已取消 |

### 5.2 医嘱状态（`m07_order`）

```
DRAFT → ISSUED → PAID → EXECUTING → COMPLETED
                    ↓        ↓
                REFUNDED  REFUNDED
                    │
ISSUED/PAID ──► CANCELLED / STOPPED / REJECTED
ISSUED ──► ABANDONED（超时）
```

**权责：**

| 状态变更 | 触发方 |
|---|---|
| `DRAFT → ISSUED` | M07 |
| `ISSUED → PAID` | **M16** |
| `PAID → EXECUTING` | **执行方** |
| `EXECUTING → COMPLETED` | **执行方** |
| `→ REFUNDED` | **M16** |
| `→ CANCELLED/STOPPED` | M07 |
| `→ REJECTED` | 执行方 |

### 5.3 报告状态（`m07_report`）

```
DRAFT → PRELIMINARY → FINAL → AMENDED
                         ↓
                     RETRACTED
```

### 5.4 危急值状态（`m07_critical_value`）

```
DETECTED → NOTIFIED → ACKNOWLEDGED → HANDLED
              ↓
          ESCALATED → ACKNOWLEDGED
```

**强制规则：** `status <> 'HANDLED'` 阻断完成就诊。

### 5.5 处方状态（`m07_prescription`）

```
DRAFT → SIGNED → REVIEWED → DISPENSED
          ↓         ↓
      RETURNED  CANCELLED
          ↓
        DRAFT
```

### 5.6 文书状态（`m07_document`）

```
DRAFT → GENERATED → SIGNED → PRINTED
                                     ↓（补打保持 PRINTED）
                      ↓
                  CANCELLED
```

### 5.7 申请单状态（`m07_exam_request`）

```
CREATED → PENDING → EXECUTING → COMPLETED
             ↓          ↓
         REVOKED   CANCELLED
```

### 5.8 打印类型（`m07_document_print`）

| 类型 | 说明 | 次数上限 |
|---|---|---|
| `FIRST` | 首次打印 | 1 |
| `REPRINT` | 补打 | 3 |
| `REGENERATE` | 重打 | 不限（需授权） |
| `ADMIN` | 行政补打 | 不限 |

### 5.9 抗菌药会诊状态（`m07_antibiotic_consult`）

```
PENDING → APPROVED
     ↓
  REJECTED / EXPIRED
```

### 5.10 状态机一致性校验

**必须保证：**

```sql
-- 已缴费必须有收费单号
ALTER TABLE m07_order ADD CONSTRAINT ck_m07_order_paid
    CHECK (status NOT IN ('PAID','EXECUTING','COMPLETED')
           OR (paid_at IS NOT NULL AND billing_no IS NOT NULL));

-- 已签名必须有签名信息
ALTER TABLE m07_prescription ADD CONSTRAINT ck_m07_rx_signed
    CHECK (status = 'DRAFT'
           OR (signed_at IS NOT NULL AND signature_hash IS NOT NULL));

-- 已处置必须有措施
ALTER TABLE m07_critical_value ADD CONSTRAINT ck_m07_critical_handled
    CHECK (status <> 'HANDLED'
           OR (handled_at IS NOT NULL
               AND length(btrim(handle_measure)) >= 5));
```

### 6.3 索引设计原则

| 原则 | 说明 |
|---|---|
| **前导列高选择性** | 复合索引把 `encounter_id`/`doctor_id` 放前面 |
| **覆盖查询** | 列表查询尽量走索引覆盖 |
| **部分索引** | 只索引常用子集（如待办），体积小、命中快 |
| **避免过度索引** | 写多读少的表少建索引 |
| **定期审查** | 每月检查未使用索引 |

### 6.4 索引监控 SQL

```sql
-- 查找未使用的索引
SELECT schemaname, relname AS table_name,
       indexrelname AS index_name,
       idx_scan AS scans,
       pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM pg_stat_user_indexes
WHERE schemaname = 'public'
  AND relname LIKE 'm07_%'
  AND idx_scan = 0
  AND indexrelname NOT LIKE 'pk_%'
  AND indexrelname NOT LIKE 'uk_%'
ORDER BY pg_relation_size(indexrelid) DESC;

-- 查找缺失索引（顺序扫描多的大表）
SELECT relname, seq_scan, seq_tup_read / NULLIF(seq_scan, 0) AS avg_rows
FROM pg_stat_user_tables
WHERE schemaname = 'public'
  AND relname LIKE 'm07_%'
  AND seq_scan > 1000
  AND seq_tup_read / NULLIF(seq_scan, 0) > 1000
ORDER BY seq_tup_read DESC;
```

### 7.3 分区维护任务

```sql
-- 每月自动建下一年分区
CREATE OR REPLACE FUNCTION fn_m07_create_next_partition()
RETURNS void AS $$
DECLARE
    next_year INT := EXTRACT(YEAR FROM CURRENT_DATE) + 1;
    part_name TEXT;
BEGIN
    -- 示例：m07_order
    part_name := 'm07_order_' || next_year;

    IF NOT EXISTS (
        SELECT 1 FROM pg_class WHERE relname = part_name
    ) THEN
        EXECUTE format(
            'CREATE TABLE %I PARTITION OF m07_order
             FOR VALUES FROM (%L) TO (%L)',
            part_name,
            next_year || '-01-01',
            (next_year + 1) || '-01-01'
        );
    END IF;
END;
$$ LANGUAGE plpgsql;
```

**调度：** 每年 12 月 1 日执行。

### 7.4 归档策略

| 数据年龄 | 处理 |

| 0~2 年 | 在线（热数据） |

| 5~15 年 | 在线（冷数据，只归档查询） |
