**本子模块的铁律（与本文件所有设计一一对应）：**

1. **业务本体不在本模块。** 手术排程、术前核对、器械清点、麻醉用药执行、生命体征采集归 M09；本模块只存**病历文书记录侧**的内容——主刀术中所见、手术经过文字叙述、麻醉文字陈述、术后医嘱摘要。表名一律 `m18_opr_`，通过 `m09_*_id` 逻辑外键关联 M09 的业务记录，**不建任何 `m09_*` 表**。
2. **专科检查不复制原始值。** 验光、眼压、OCT、视野、角膜地形图、IOL Master 的数值分别属于 M10/M11/M12/M13，本模块只存**引用（`record_id` + `source_module`）+ 诊断性结论文字**。唯一的例外是打印快照 `snapshot_*` 字段，其边界与固化时机在 `m18_opr_specialty_exam` 一节逐条论证。
3. **病历事实表不可删除。** 本子模块 8 张业务表全部属病历正文，`REVOKE DELETE`，不设 `is_deleted`（唯一例外是 `m18_opr_config` 配置表与 `m18_opr_oper_log` 日志表）。
4. **封存触发器必须挂载。** 按 `M18_电子病历与知识库_数据结构设计汇总.md` §3.3，`m18_opr_*` 全部正文表必须挂 `trg_fn_m18_seal_guard()`，封存后任何写入被数据库拒绝。
5. **时间一律 `TIMESTAMP` 不带时区**（全院统一 Asia/Shanghai），不用 `TIMESTAMP WITH TIME ZONE`。
6. **`content_hash` 一律 `VARCHAR(64)` SHA-256 小写十六进制**，禁 MD5。本模块只**引用** `m18_emr_record.content_hash`，不重复计算、不重复存储。

**边界红线（以下表一律不得在本子模块创建）：**

| 禁止创建的表 | 归属 | 理由 |
|---|---|---|
| `m18_surgery_record` | 手术记录业务本体 | 归 M09（校验器 `FORBIDDEN_TABLES` 直接报错） |
| `m09_surgery_record` / `m09_anesthesia_record` | 手术、麻醉业务本体 | 归 M09，本模块只通过逻辑外键引用 |
| `m18_order` / `m18_diagnosis` / `m18_prescription` | 医嘱、诊断、处方 | M18 只做内容与知识，不做操作 |
| `m18_document_signature` / `m18_consent_sign` | 签署状态 | 签署状态权威在 M07-06 `m07_document` |
| `m18_emr_record` / `m18_emr_record_field` | 病历正文事实表 | 由 M18-02 首建，本模块只引用 |
| `m18_emr_amendment` / `m18_emr_seal` / `m18_emr_document` | 更正、封存、文书 | 由 M18-06 首建，本模块只引用 |
| `m12_*` / `m10_*` / `m11_*` / `m13_*` 任何副本表 | 检查、视光、屈光、检验原始数据 | 专科检查只存引用与结论，不复制原始值 |
| `m18_opr_vital_series` 一类时序表 | 生命体征逐点数据 | 监护系统与 M09 的职责，麻醉记录只存数据源引用 |

> **关于「不单独建表」的备选方案。** 任务书提示，手术记录也可以直接挂在 `m18_emr_record` 的 `record_type` 上而不单独建表。本设计**选择单独建表**，理由有三：①`m18_emr_record` 由 M18-02 定义，本模块无权改其结构，术中所见、手术经过、术后医嘱摘要若塞进 `m18_emr_record_field` 的通用段落，会造成「字段语义靠 `section_type` 字符串约定」的弱耦合，质控与统计无法建索引；②术前讨论的主持人资质、日间手术的时限追踪都需要强类型字段与 CHECK 约束，通用段落做不到；③M09 的 P-02 同步需要按 `m09_surgery_id` 精确反查病历段落，单独建表可建唯一索引，通用段落只能全表扫 `section_type`。代价是本模块的表与 `m18_emr_record` 必须维持 1:1 关系，这一致性由 `uk_m18_opr_surgery_record_m09` 唯一约束与 §8.2 的事务规则共同保证。

### 4.2 表：`m18_opr_preop_discussion`

**用途：** 术前讨论记录。一次手术一条，记录讨论时间、主持人（必须副主任医师及以上）、参加人员与职称、讨论意见、手术方案确认、风险与对策。术前讨论是病历质控硬指标，重大手术必须讨论，缺此项直接判甲级病历缺陷。

**强制项：**

- **主持人资质校验依据。** `host_title_code` 的取值来自 M01 主数据职称字典（`U-08 GET /internal/v1/mdm/staff/{id}` 取 `title_code` 快照），校验通过后再调 `U-12 GET /internal/v1/staff/{id}/practice-check` 确认执业资格在有效期内。两项都通过才置 `host_title_verified = TRUE`。
- **不校验的后果。** 质控抽查时发现主持人仅为住院医师或主治医师，属于「重大手术未按规定讨论」缺陷，整份病历判 `GRADE_C`（按 `M18-CALC-02`，一处 CRITICAL 一票否决）。因此本表用 CHECK 把「低于副主任医师」挡在数据库层，不依赖应用层自觉。
- **`is_completed` 是给 M05 与统计侧的直接查询字段。** `m05.home` 每屏要校验 8 项前置条件，若每次都去解析 `attendee_json` 与 `opinion_text` 判断讨论是否完成，单次查询要 30ms 以上；`is_completed + completed_at` 是冗余但必需的可索引标志。部分索引 `idx_m18_opr_preop_discussion_incomplete` 让「未完成清单」查询走索引扫描。

### 4.6 表：`m18_opr_implant_writeback`

**「快照 vs 引用」的边界与更新时机（本节最关键的设计论证）：**

| 项目 | 引用（默认做法） | 快照（例外做法） |
|---|---|---|
| 存什么 | `source_module` + `source_record_id` + `conclusion_text` | 额外把当时取到的关键数值写入 `snapshot_json` |
| 何时取数 | 每次打开病历页面时实时调上游 | 仅在 `snapshot_taken_at` 那一次取数 |
| 数值变化时 | 病历显示最新值 | 病历显示冻结值 |
| 适用场景 | 电子病历在线查阅、质控抽取、统计 | **文书已定稿签署并打印归档后**，需要保证打印件与纸质件一致 |
| 本设计的默认 | 是 | 否 |

**为什么默认用引用而不是快照：** 若每次打开病历都把检查数值复制一份进本表，那么 M12 因仪器重新标定而更正报告时，M18 里就多出一份永远不会更新的旧值；同一患者的电子病历里出现「OCT 中心厚度 512 微米（M12）」与「OCT 中心厚度 508 微米（M18 快照）」两个口径，医师无法判断信谁。原始检查值的权威永远在 M10/M11/M12/M13，M18 一旦复制就产生了第二个真相源。

**什么情况下允许快照：** 患者 3 月后复查，3 月前那次就诊的病历已定稿签署并打印归档；此时该次病历的纸质打印件与电子件必须逐字一致，若只存引用，M12 的数据一旦更正，已归档病历的显示值就会变，与纸质件不符——**已签署病历的不可篡改要求高于「引用最新值」的便利**。此时在定稿签署的那个事务里写一次 `snapshot_json` 与 `snapshot_hash`，`snapshot_reason` 写明理由，此后 `snapshot_json` 只读不更新。**快照只在病历经 `FINALIZED → SIGNED` 转换时由系统固化，不允许医师手动触发。**

- 该表**不分区**：3 年约 54 万行，病程类明细表按汇总文件 §4 的裁决不分区。

  ADD CONSTRAINT ck_m18_opr_day_surgery_record_deadline
    CHECK ((discharge_at IS NULL AND complete_deadline_at IS NULL)
           OR (discharge_at IS NOT NULL
               AND complete_deadline_at = discharge_at + INTERVAL '24 hours'));

-- 超时判定与超时分钟数自洽
ALTER TABLE m18_opr_day_surgery_record
  ADD CONSTRAINT ck_m18_opr_day_surgery_record_overdue
    CHECK ((is_overdue = FALSE AND overdue_minutes IS NULL)
           OR (is_overdue = TRUE
               AND overdue_minutes IS NOT NULL
               AND overdue_minutes > 0
               AND record_complete_at IS NOT NULL));

-- 待补齐项数组与计数一致
ALTER TABLE m18_opr_day_surgery_record
  ADD CONSTRAINT ck_m18_opr_day_surgery_record_pending
    CHECK (coalesce(array_length(pending_items, 1), 0) = pending_item_count);

-- 补齐完成时不得还有待补齐项
ALTER TABLE m18_opr_day_surgery_record
  ADD CONSTRAINT ck_m18_opr_day_surgery_record_complete
    CHECK (record_complete_at IS NULL OR pending_item_count = 0);

-- 归档状态与时间点自洽
ALTER TABLE m18_opr_day_surgery_record
  ADD CONSTRAINT ck_m18_opr_day_surgery_record_archive
    CHECK (archive_status IN ('NOT_PUSHED', 'PUSHING', 'PUSHED',
                              'REJECTED', 'CONFIRMED'));

ALTER TABLE m18_opr_day_surgery_record
  ADD CONSTRAINT ck_m18_opr_day_surgery_record_archive_time
    CHECK ((archive_status = 'NOT_PUSHED' AND archive_pushed_at IS NULL)
           OR (archive_status <> 'NOT_PUSHED' AND archive_pushed_at IS NOT NULL));

-- 归档确认必须有归档批次号
ALTER TABLE m18_opr_day_surgery_record
  ADD CONSTRAINT ck_m18_opr_day_surgery_record_confirmed
    CHECK (archive_status <> 'CONFIRMED'
           OR (m18_archive_id IS NOT NULL AND archive_confirmed_at IS NOT NULL));
```

**强制项：**

- **日间手术病历时限与住院的差异，本表用三组字段显式表达：**

| 对比项 | 住院病历 | 日间手术病历（本表） |
|---|---|---|
| 病程记录频次 | 每天至少一次，病危每天一次以上 | `min_course_count = 1`，`max_course_interval_hours = 0`（不约束间隔） |
| 补齐时限 | 归档批次按出院日 + 归档窗口 | `complete_deadline_at = discharge_at + 24 小时`（法定） |
| 归档触发 | M05-05 出院办理时推送 | M06-06 离院结算时推送，且**不依赖 M09/M18 在线**，允许离线补推 |

- **系统如何区分两者：** 靠 `record_type = 'DAY_SURGERY'`（共享规范 §13 的 `record_type` 枚举定死，不得自创 `SURGERY` 或 `DAY`）。本表的 CHECK 把 `record_type` 锁死为 `DAY_SURGERY`，住院病历记录在 `m18_ipd_*`（M18-03 定义），两者物理隔离，不会出现「同一张表里混杂两种时限规则」的歧义。
- **`offline_push_accept` 恒为 TRUE**：M06-06 的归档推送在 M09/M18 不可达时先入队，恢复后补推；本表必须接受补推，且 `archive_retry_count` 记录重试次数，不能因为「晚到」而拒绝。
- `REVOKE DELETE ON m18_opr_day_surgery_record FROM app_m18;`
- 挂载封存只读触发器。

- **必须有 `p_default` DEFAULT 分区。** 分区表若只有按月的具体分区，跨月补录或时间戳异常的行会直接插入失败（`no partition of relation found for row`），业务侧表现为「偶发保存失败」，每月 1 日凌晨概率最高。共享规范 §17 常见坑 #22。
- **`SEAL_BLOCKED` 是本表最值得盯的动作类型。** 封存后仍有人尝试写入，说明要么是前端缓存了旧状态，要么是有人绕过页面直接调接口——两种情况都必须在安全审计里可见。
- 日志表不加 `REVOKE DELETE`（按留存期清理），但**只允许 `m18_archiver` 账号执行归档迁移后的删除**（汇总 §10.2）。

| 项目 | 内容 |
|---|---|
| 字段位置 | `m09_implant_item.m18_written`、`m09_implant_item.m18_written_at`（`M09手术麻醉管理/M09_手术麻醉管理_05_植入物使用与扫码绑定_数据结构.md:396-397`） |
| 写入方 | **M09-05 自己写**。原始证据：`M09_手术麻醉管理_05_植入物使用与扫码绑定_详细设计.md:3405-3406` 的 `item.m18_written = True` / `item.m18_written_at = item.implanted_at`，位于 `_writeback_emr(item_id)` 内、`await EmrClient.append_implant_section(db, payload)` 之后 |

| 静默失效的防范 | `m18_opr_implant_writeback` 保留 `m09_flag_confirmed` / `m09_flag_confirm_attempts` / `m09_flag_last_error` 三个回执字段，配合部分索引 `idx_m18_opr_implant_writeback_flag_lost` 让「M09 侧没置上」这件事在 M18 侧可见；CELERY 补偿任务按 `m09_implant_item_id` 回查 M09 侧 `m18_written` 实际值 |
| `m18_written_at` 语义提醒 | 它等于 `implanted_at`（植入时刻），**不是回写时刻**。对账时不能拿它和 `m18_opr_implant_writeback.record_written_at` 做时序比较 |

```

代价：`uk_m18_opr_implant_writeback_item` 唯一索引单点查找，1 次索引扫描。

**C.2 待补偿回写扫描（CELERY 每分钟）**

```sql
SELECT id, writeback_no, m09_implant_item_id, m09_flag_confirm_attempts
FROM m18.m18_opr_implant_writeback
WHERE write_status IN ('RECEIVED', 'WRITTEN', 'FLAG_FAILED')
  AND compensable = TRUE
  AND next_retry_at <= CURRENT_TIMESTAMP
ORDER BY next_retry_at
LIMIT 200;
```

代价：走 `idx_m18_opr_implant_writeback_pending` 部分索引，索引规模与「未完成回写」数量同阶（正常情况个位数）。

**C.3 M09 标志丢失巡检（每小时，静默失效的唯一出口）**

```sql
SELECT m.writeback_no, m.m09_implant_item_id, m.m09_flag_confirm_attempts,
       m.first_received_at, m.m09_flag_last_error
FROM m18.m18_opr_implant_writeback m
WHERE m.m09_flag_confirmed = FALSE
  AND m.write_status <> 'ABANDONED'
  AND m.first_received_at < CURRENT_TIMESTAMP - INTERVAL '2 hours'
ORDER BY m.first_received_at
LIMIT 100;
```

代价：`idx_m18_opr_implant_writeback_flag_lost`。**这条查询为空是常态；不为空就是告警项。**

**C.4 逾期未写病程扫描（APScheduler 每小时）**

```sql
SELECT c.id, c.course_no, c.deadline_at, c.author_staff_id
FROM m18.m18_opr_postop_first_course c
WHERE c.written_at IS NULL
  AND c.deadline_at < CURRENT_TIMESTAMP
ORDER BY c.deadline_at
LIMIT 500;
```

代价：`idx_m18_opr_postop_first_course_deadline` 部分索引。

**C.5 术前讨论未完成（供 M05-06 病案首页与质控侧联查）**

```sql
SELECT encounter_id, discussion_no, planned_surgery_level, created_at
FROM m18.m18_opr_preop_discussion
WHERE is_completed = FALSE
  AND encounter_id = ANY(:encounter_ids);
```

代价：`idx_m18_opr_preop_discussion_incomplete`。

| 约束 | 说明 |
|---|---|
