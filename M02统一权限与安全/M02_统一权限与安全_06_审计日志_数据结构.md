## 4. 数据结构设计

### 4.1 ER 关系图

```
                    ┌──────────────────────────────────────┐
                    │ 事件产生方（全部模块）                 │
                    │ M02-01~05 + M03~M23                  │
                    └──────────────┬───────────────────────┘
                                   │ 写入
                                   ▼
                    ┌──────────────────────────────────────┐
                    │ sys_audit_log（审计日志主表）          │
                    │  · audit_id 唯一                       │
                    │  · hash / prev_hash（哈希链）          │
                    │  · before_json / after_json           │
                    │  · risk_level                         │
                    └──────────┬───────────────────────────┘
                               │
        ┌──────────────────────┼──────────────────────┐
        │                      │                      │
        ▼                      ▼                      ▼
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│sys_audit_chain_  │  │sys_audit_integrity│  │sys_audit_archive_│
│anchor（锚点）     │  │_verify（校验记录） │  │task（归档任务）   │
└──────────────────┘  └──────────────────┘  └──────────────────┘

配置与规则：
┌──────────────────────────────┐  ┌──────────────────────────────┐
│ sys_audit_config             │  │ sys_audit_rule               │
│ （审计配置，单行）             │  │ （高危规则）                  │
└──────────────────────────────┘  └──────────────────────────────┘
```

**设计说明：**

- `sys_audit_log` 为**只增不改**的审计主表，按 `occurred_at` 月度分区
- `hash` / `prev_hash` 构成**哈希链**，防篡改
- `sys_audit_chain_anchor` 独立保存**日终锚点**，与主表分离保护
- `sys_audit_integrity_verify` 记录每次校验结果
- `sys_audit_archive_task` 记录归档任务
- `sys_audit_rule` 定义高危操作判定规则
- `sys_audit_config` 单行全局配置

**约束说明**

```sql
-- 只允许两种审计类型
ALTER TABLE sys_audit_log
    ADD CONSTRAINT ck_audit_type
    CHECK (audit_type IN ('SECURITY', 'OPERATION'));

-- 风险等级
ALTER TABLE sys_audit_log
    ADD CONSTRAINT ck_audit_risk
    CHECK (risk_level IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL'));

-- 结果
ALTER TABLE sys_audit_log
    ADD CONSTRAINT ck_audit_result
    CHECK (result IN ('SUCCESS', 'FAILED'));

-- 审计日志只增不改（应用层 + 数据库层双重保护）
REVOKE UPDATE, DELETE ON sys_audit_log FROM his_app;
```

**只增不改保护（可选）：**

```sql
-- 若无法使用权限控制，可用规则阻止
CREATE RULE no_update_audit_log AS ON UPDATE TO sys_audit_log
    DO INSTEAD NOTHING;
CREATE RULE no_delete_audit_log AS ON DELETE TO sys_audit_log
    DO INSTEAD NOTHING;
```

> **注意**：使用 RULE 后，归档删除也需临时禁用规则或使用分区 DROP。

**分区策略**

```sql
-- 按 occurred_at 月度 RANGE 分区
CREATE TABLE sys_audit_log (
    ...
) PARTITION BY RANGE (occurred_at);

-- 示例分区
CREATE TABLE sys_audit_log_2026_04 PARTITION OF sys_audit_log
    FOR VALUES FROM ('2026-04-01') TO ('2026-05-01');
CREATE TABLE sys_audit_log_2026_05 PARTITION OF sys_audit_log
    FOR VALUES FROM ('2026-05-01') TO ('2026-06-01');

-- 归档 = 分区 DETACH 后导出，再 DROP
ALTER TABLE sys_audit_log DETACH PARTITION sys_audit_log_2026_01;
```

**保留期：**
- 安全审计：**3 年**
- 操作审计：**10 年**
- 热表窗口：**90 天**

**量级估算：**

| 项 | 数值 |
|---|---|
| 日增事件 | ≈86,000 条 |
| 年增事件 | ≈3,100 万条 |
| 单条大小 | ≈2 KB |
| 热表（90 天） | ≈780 万条 / 16 GB |
| 全量（3 年安全） | ≈930 万条 / 19 GB |
| 全量（10 年操作） | ≈3.1 亿条 / 620 GB（归档压缩后 ≈80 GB） |

### 4.3 表：`sys_audit_chain_anchor`（哈希链锚点表）

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | IDENTITY | 主键 |
| chain_date | DATE | N | - | 链日期（当日） |
| hash_value | CHAR(64) | N | - | 日终哈希（当日最后一条的 hash） |
| prev_anchor | CHAR(64) | Y | NULL | 前一日锚点（链式） |
| record_count | BIGINT | N | 0 | 当日记录数 |
| first_record_id | BIGINT | Y | NULL | 当日首条记录 ID |
| last_record_id | BIGINT | Y | NULL | 当日末条记录 ID |
| computed_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 计算时间 |
| computed_by | VARCHAR(64) | Y | NULL | 计算者（SYSTEM/人工） |
| is_sealed | BOOLEAN | N | TRUE | 是否已封存 |
| remark | VARCHAR(500) | Y | NULL | 备注 |

**索引：** `uk_anchor_date(chain_date)` 唯一；`idx_anchor_hash(hash_value)`。

**说明：**

- 每日 00:05 由定时任务计算前一日锚点
- `prev_anchor` 形成**跨天链路**
- **独立于主表保护**（单独授权，仅审计管理员可写）
- 若主表分区被 DROP，锚点仍在（用于事后取证）

class AuditRuleBase(BaseModel):
    rule_name: str = Field(..., min_length=1, max_length=128)
    rule_type: Literal["HIGH_RISK", "ANOMALY", "ALERT"] = "HIGH_RISK"
    event_codes: Optional[List[str]] = None
    condition_expr: Optional[dict] = None
    risk_level: Optional[RISK_LEVEL] = None
    alert_enabled: bool = False
    alert_channels: Optional[List[str]] = None
    alert_receivers: Optional[List[int]] = None
    suppress_minutes: int = Field(10, ge=0, le=1440)
    threshold: Optional[int] = Field(None, ge=1)
    window_minutes: Optional[int] = Field(None, ge=1, le=1440)
    is_enabled: bool = True
    sort_no: int = 999
    description: Optional[str] = Field(None, max_length=500)

    @model_validator(mode="after")
    def validate_rule(self):
        if self.alert_enabled and not self.alert_channels:
            raise ValueError("启用告警时必须指定告警渠道")
        if self.alert_enabled and not self.alert_receivers:
            raise ValueError("启用告警时必须指定接收人")
        if self.rule_type == "ANOMALY" and not self.threshold:
            raise ValueError("异常规则必须设置阈值")
        return self
