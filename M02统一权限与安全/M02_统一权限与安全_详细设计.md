## 1. 模块概述

### 1.1 模块定位

M02 统一权限与安全是全院系统的**身份与信任中枢**。它回答两个问题：

1. **"你是谁？"** —— 认证（Authentication）
2. **"你能做什么？"** —— 授权（Authorization）

并在其外层提供**安全防护**与**审计追溯**。

```
┌──────────────────────────────────────────────────────────────────────┐
│  M03~M23 全部 21 个业务模块（3,000+ 接口）                            │
└────────────────────────────┬─────────────────────────────────────────┘
                             │ 每个请求
                             ▼
┌──────────────────────────────────────────────────────────────────────┐
│  M02 统一权限与安全                                                   │
│                                                                       │
│  最外层：安全策略与风控（IP/限流/恶意检测/风控）                        │
│       ↓                                                               │
│  身份层：认证登录 → 会话Token                                         │
│       ↓                                                               │
│  授权层：权限运行时引擎（功能/数据/字段）                               │
│       ↓                                                               │
│  增强层：二次验证                                                     │
│       ↓                                                               │
│  追溯层：审计日志                                                     │
└────────────────────────────┬─────────────────────────────────────────┘
                             │ 依赖
                             ▼
┌──────────────────────────────────────────────────────────────────────┐
│  M01 主数据管理（角色/菜单/权限定义/数据范围/字段规则）                 │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.2 模块目标

| 目标 | 指标 |
|---|---|
| **全覆盖** | 每个接口都鉴权，每个写操作都审计 |
| **高性能** | 鉴权 P95 ≤ 10ms，登录 P95 ≤ 500ms |
| **高可用** | 99.9%，依赖故障可降级 |
| **强安全** | 满足三级等保安全审计要求 |
| **易接入** | 业务模块 2 行代码接入鉴权 |
| **可追溯** | 任意操作可查"谁在何时对什么做了什么" |
| **可运维** | 权限模拟器、风控看板、审计报表 |

### 1.3 建设优先级依据

总体设计第 8.1 节：
> 1. **基础层**：主数据管理MDM、**统一权限与安全**、集成平台、系统管理。

M02 是基础层的第二个模块，因为：
- M03~M23 **每一个模块**都依赖它
- 先建 M02，后续模块设计时可直接引用其契约，避免回补

### 1.4 关键业务角色

| 角色 | 职责 | 关注子模块 |
|---|---|---|
| 全部系统用户 | 使用系统 | 02 登录、05 二次验证 |
| 系统管理员 | 账号与运维 | 01 账号、03 会话、04 权限 |
| 信息科长 | 安全策略 | 04 权限、05 MFA、06 审计、07 风控 |
| 审计员 | 合规追溯 | 06 审计 |
| 院长 | 监督 | 06 审计报表、07 紧急封禁 |
| 开发人员 | 接入 | 04 权限引擎装饰器 |
| 运维 | 部署监控 | 全部 |

### 4.2 接口契约

**M01 提供给 M02（M02 消费）：**

| 接口 | 用途 | SLA |
|---|---|---|
| `GET /internal/v1/auth/{staff_id}/permission-context` | 权限上下文 | P95 ≤ 100ms |
| `GET /internal/v1/auth/version` | 权限版本 | P95 ≤ 10ms |
| `GET /internal/v1/auth/dept-tree` | 科室树 | P95 ≤ 30ms |
| `GET /internal/v1/auth/staff-by-roles` | 角色关联职工 | P95 ≤ 50ms |
| `POST /internal/v1/auth/check-permission` | 权限校验（备用） | P95 ≤ 50ms |

**M02 提供给全模块：**

| 接口 | 用途 | SLA |
|---|---|---|
| `POST /internal/v1/account/verify-credential` | 校验凭据 | P95 ≤ 150ms |
| `POST /internal/v1/session/create` | 创建会话 | P95 ≤ 100ms |
| `POST /internal/v1/token/validate` | 校验 Token | P95 ≤ 20ms |
| `POST /internal/v1/perm/check` | 权限判定 | P95 ≤ 10ms |
| `POST /internal/v1/perm/filter-sql` | 数据权限 SQL | P95 ≤ 5ms |
| `POST /internal/v1/perm/mask-fields` | 字段脱敏 | P95 ≤ 5ms |
| `POST /internal/v1/mfa/verify` | 二次验证 | P95 ≤ 100ms |
| `POST /internal/v1/audit/record` | 写入审计 | P95 ≤ 30ms |
| `POST /internal/v1/sec/check-ip` | IP 检查 | P95 ≤ 5ms |

### 4.3 关键约定

1. **M01 是权限定义的权威源**，M02 只缓存不修改。
2. **M02 不重复定义 `mdm_*` 表**，通过内部接口读取。
3. **权限变更后 M01 主动通知 M02**（`POST /internal/v1/perm/cache/invalidate`）。
4. **M02 的审计与风控数据不回传 M01**。
5. **跨模块不建物理外键**，由应用层校验。

### 5.3 请求处理链路

```
请求
  ↓
[SecurityMiddleware]   ← M02-07 IP/限流/恶意检测
  ↓

  ↓
[PermissionMiddleware] ← M02-04 权限判定
  ↓
[AuditMiddleware]      ← M02-06 审计采集
  ↓
路由处理
  ↓
响应（含字段脱敏）
  ↓

```

**中间件顺序（关键）：**

| 顺序 | 中间件 | 理由 |
|---|---|---|
| 1 | 安全策略 | 最先拦截恶意请求 |
| 2 | 鉴权 | 确定身份 |
| 3 | 权限 | 判定权限 |
| 4 | 审计 | 记录结果 |
| — | 业务 | — |
| — | 脱敏 | 响应处理 |

## 6. 核心流程

### 6.1 登录流程

```
用户输入登录名+密码+验证码
        ↓
POST /api/v1/auth/login
        ↓
┌───────────────────────────────────────────┐
│ M02-07 安全策略                            │
│  1. IP 白/黑名单检查                       │
│  2. 时段检查                               │
│  3. 限流检查                               │
│  4. 恶意请求检测                           │
└───────────────────┬───────────────────────┘
                    ↓
┌───────────────────────────────────────────┐
│ M02-02 认证                                │
│  1. 图形验证码校验                         │
│  2. 调用 M02-01 verify-credential          │
│     （账号状态 + 密码 bcrypt 比对）         │
└───────────────────┬───────────────────────┘
                    ↓
              密码正确？
             ┌────┴────┐
            否          是
             ↓           ↓
      记录失败      ┌──────────────────────┐
      返回统一错误  │ M02-07 风控评分       │
                    │  地点/时间/设备/行为  │
                    └──────────┬───────────┘
                               ↓
                        风险等级？
                    ┌──────┼──────┐
                  LOW    HIGH   CRITICAL
                    ↓      ↓       ↓
                  直通  二次验证  阻断
                         ↓
                  ┌──────────────────────┐
                  │ M02-03 创建会话       │
                  │  签发 Access+Refresh  │
                  └──────────┬───────────┘
                             ↓
                  ┌──────────────────────┐
                  │ M02-01 record-success │
                  │ M02-06 写入审计        │
                  └──────────┬───────────┘
                             ↓
                        返回 Token
```

### 6.2 请求鉴权流程

```
请求携带 Access Token
        ↓
M02-07 安全策略（IP/限流/恶意/风控）
        ↓ 通过
M02-03 校验 Token
  ├─ 验签（kid + HS256）
  ├─ 过期检查（exp/nbf）
  ├─ 黑名单检查（jti）
  ├─ 会话状态检查
  └─ 账号状态检查
        ↓ 有效
M02-04 权限判定
  ├─ 取权限上下文（缓存 5min）
  ├─ 超管？→ 通过
  ├─ perm_code ∈ perm_codes？→ 通过
  └─ 否则 → 403
        ↓ 通过
需要二次验证？
  ├─ perm_code ∈ second_factor_ops
  └─ 会话已验证（15min）？
        ├─ 否 → 428 → M02-05
        └─ 是 → 继续
        ↓
业务处理
  ├─ 数据权限注入（SQL WHERE）
  └─ 字段脱敏（响应）
        ↓
M02-06 审计（异步）
```

### 6.3 权限变更生效流程

```
M01 管理员修改角色权限
        ↓
M01 更新 mdm_role_permission
        ↓
M01 更新权限版本号
  → menu_version = "v2:20260401-142345"
        ↓
M01 调用 M02-04
  POST /internal/v1/perm/cache/invalidate
  { scope: "ROLE", role_ids: [12], reason: "..." }
        ↓
M02-04 失效相关用户缓存
  DEL sys:perm:ctx:{staff_id}  (× N)
  SET sys:perm:version = 新版本
        ↓
下次请求
  → 缓存未命中
  → 调用 M01 拉取新权限上下文
  → 写入缓存
        ↓
权限变更生效（≤5 分钟，主动失效则立即）
```

### 6.4 审计写入流程

```
业务操作完成
        ↓
@audit_log 装饰器捕获
  ├─ 变更前快照（capture_before）
  ├─ 变更后快照（capture_after）
  └─ 计算 diff
        ↓
组装审计记录
        ↓
AuditWriter.enqueue()
  ├─ 队列未满 → 入内存队列
  └─ 队列已满 → 降级同步写入
        ↓
批量刷盘（100 条 或 1 秒）
        ↓
计算哈希链
  hash = SHA256(记录内容 + prev_hash)
        ↓
写入 sys_audit_log
        ↓
次日 00:05 计算日终锚点
  → sys_audit_chain_anchor
        ↓
每日 02:00 完整性校验
  → 重算哈希链
  → 任一处不匹配即告警
```

## 12. 风险与对策

| 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|
| **M01 权限服务不可用** | 全院无法鉴权 | 中 | 缓存降级 30 分钟 |
| **权限上下文过期导致误拒** | 用户被拒绝 | 中 | 版本校验 + 主动失效 |
| **数据权限遗漏** | 医疗隐私事故 | **高** | 代码审查 + 强制规范 + 自动化检查 |
| **接口未声明权限** | 越权访问 | 中 | 默认拒绝 + 每日扫描 |
| **审计日志写入影响性能** | 业务变慢 | 中 | 异步批量 + 队列降级 |
| **风控误报影响正常业务** | 用户体验差 | 中 | 观察模式 + 阈値调优 |
| **Redis 故障** | 性能下降 | 低 | 直连 DB |
| **密钥泄露** | Token 可伪造 | 低 | 90 天轮换 + 加密存储 |
| **审计数据量过大** | 存储压力 | 高 | 分区 + 归档 + 采样 |
| **等保测评不通过** | 无法上线 | 中 | 提前对照条款自测 |

### 12.1 最大风险：数据权限遗漏

**为什么最大：** 一旦某个查询接口忘记注入数据权限，医生可能看到其他科室患者数据，构成**医疗隐私事故**。

**对策（多重保障）：**

| 层次 | 措施 |
|---|---|
| 设计 | 规定所有查询必须用 `apply_data_scope_to_stmt` |
| 开发 | 提供标准代码模板 |
| 代码审查 | 每个 PR 必查数据权限 |
| 自动化 | 静态扫描：查询接口是否含 `apply_data_scope` |
| 测试 | 越权测试用例（不同科室账号交叉验证） |
| 监控 | 异常跨科室访问告警 |
