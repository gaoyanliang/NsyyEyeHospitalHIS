## 1. 模块概述

### 1.1 模块定位

M09-04 回答一个问题：**「进去的东西，是不是都出来了？」**

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│                      M09-04 在手术全流程中的位置                                      │
└──────────────────────────────────────────────────────────────────────────────────────┘

   M06-04           M09-01          M09-02           M09-03          M09-04
   Time-Out   →   接收/评估   →   麻醉记录    →   手术记录   →   ★器械清点★
   四方核对                                                       │
                                                                  ├─ 术前清点（缝合前）
   器械护士从器械室领包 ────────────────────────────────────────► ├─ 关腔前清点
                                                                  ├─ 关腔后清点
                                                                  └─ 缝合后清点
                                                                        │
                                                                        ▼
                                                              ┌───────────────────┐
                                                              │ 结论：相符 / 不符  │
                                                              └─────────┬─────────┘
                                                                        │
                                              ┌─────────────────────────┼──────────────────┐
                                              ▼                         ▼                  ▼
                                        M09-03 手术记录          M06-05 复苏          X 光复核
                                        instrument_count_ok      （不符则不得离室）    （不符必须）
```

**一句话：M09-04 是手术室最后一道物理安全闸门——器械、纱布、缝针一件都不能留在患者体内。**

### 1.2 为什么独立成子模块

**理由一：器械清点是独立法定护理记录，不是手术记录的附属。**

《手术室护理实践指南》明确要求：

- **手术开始前**：清点器械、纱布、缝针、特殊物品，与器械卡核对，双人签名
- **关闭体腔前**：再次清点，确认数量与术前一致
- **关闭体腔后**：第三次清点
- **手术结束后**：第四次清点，确认与术前一致

四次清点，每次都要**巡回护士与器械护士双人执行、双人签名**。若把清点塞进手术记录（M09-03），会出现两个问题：

1. 手术记录是主刀签署的，而清点是护士签署的——**签字主体不同，不能合并**
2. 手术记录是术后 24 小时内补写，而清点必须在术中实时完成——**时效性完全不同**

**理由二：器械清点的数据结构与手术记录毫无共同点。**

手术记录是「一次书写、一次签名」的成品文书。器械清点是「四次清点、每次 80~150 件物品、每件都要有数量」的矩阵结构：

| 维度 | 手术记录（M09-03） | 器械清点（M09-04） |
|---|---|---|
| 记录对象 | 手术过程（文字） | 物品数量（数字矩阵） |
| 书写时机 | 术后 24 小时内 | 术中四次，实时 |
| 签署主体 | 主刀 | 巡回护士 + 器械护士 |
| 数据结构 | 1 行 + JSONB 要素 | N 次清点 × M 类物品 × 数量 |
| 校验重点 | 要素完整性、时限 | **数量比对、前后一致性** |

合并后会出现「手术记录表里有 80 个数量字段」或「清点数据塞进 JSONB 无法对比」。前者是灾难，后者丧失核心能力——**清点的全部价值就在于"术前 12 把止血钳，关腔前 11 把"这个比对**。

**理由三：器械不符的处置流程与手术记录完全不同。**

清点不符时：

- **不得关闭切口 / 不得离开手术室**
- 立即启动 X 光复核（器械护士 + 巡回护士 + 主刀 + 放射科）
- 若确认遗留体内，需再次手术取出，走医疗不良事件上报（24 小时内报医务科，重大事件报卫健部门）
- 器械护士与巡回护士承担直接责任

这个流程是**独立应急响应链**，不是「记录改一改」。它需要独立的状态机、独立的告警、独立的上报路径。

**理由四：器械清点合格率是等级评审核心指标。**

《三级医院评审标准（2022 年版）》手术室质量指标包含「手术器械清点正确率」，要求 **100%**。数据来源必须是结构化的清点记录，不能靠事后翻手术记录。

### 1.4 概念辨析

| 概念 | 含义 | 易混淆点 |
|---|---|---|
| **清点（Count）** | 逐个核对物品数量是否与器械卡一致 | 不等于「看一眼」——必须逐件点数 |
| **器械卡** | 器械包内的物品清单（名称 + 规格 + 数量） | 不等于「器械包名称」——一个包里 40~80 件 |
| **器械包** | 一套打包灭菌的器械（白内障包、玻切包、斜视包） | 一个手术可能开多个包 |
| **术前清点** | 手术开始前，打开器械包后的第一次清点 | 也叫「初始清点」，是后续比对的基准 |
| **关腔前清点** | 关闭切口前（眼科多为关闭结膜/巩膜前） | 眼科无「体腔」，仍执行同一流程 |
| **关腔后清点** | 关闭切口后 | |
| **缝合后清点** | 皮肤/结膜缝完后的最终清点 | 与关腔后清点常合并，但眼科要求分开 |
| **纱布清点** | 纱布、棉片、棉签单独清点（**最易遗留**） | 纱布与器械分开计数，不合并 |
| **缝针清点** | 缝合针数量核对 | 缝合针最易断在组织内 |
| **不符（Miscount）** | 数量与术前清点不一致 | 不等于「遗失」——可能掉在地上、在垃圾袋里 |
| **器械卡不符** | 开包时数量就与器械卡不一致 | 这是**灭菌供应环节**的问题，不是术中问题 |

### 1.5 模块目标

| 指标 | 现状 | 目标 | 说明 |
|---|---|---|---|
| 器械清点执行率 | 92% | **100%** | 每台次四次清点全部完成 |
| 双人签名完整率 | 78% | **100%** | 每次清点两人签名 |
| 清点不符发生率 | 未统计 | **≤0.3%** | 年 20,000 台次，≤60 次 |
| 逐件扫码率 | 0% | **≥85%** | 关键器械逐件扫码 |
| 不符处置闭环率 | — | **100%** | 24 小时内完成原因分析与上报 |
| 清点耗时（单次 120 件） | 6~8 分钟 | **≤4 分钟** | 扫码 + 分类核对 |
| X 光复核执行率 | — | **100%** | 不符时必须执行 |

## 3. 业务模型

### 3.1 器械包与器械卡模型

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                          器械包结构                                            │
└──────────────────────────────────────────────────────────────────────────────┘

  m09_instrument_kit（器械包）
  ┌────────────────────────────────────────────────────────────────────────┐
  │ KIT-CATARACT-01  白内障基础包   标准件数 42  灭菌有效期 30 天          │
  └────────────────────┬───────────────────────────────────────────────────┘
                       │ 1:N
                       ▼
  m09_instrument_item（器械卡明细）
  ┌──────────┬──────────────┬────────┬────────┬──────────────┐
  │ 序号      │ 名称          │ 规格   │ 标准数量 │ 是否关键器械  │
  ├──────────┼──────────────┼────────┼────────┼──────────────┤
  │ 1        │ 开睑器        │ 小儿   │ 1      │ 是（扫码）    │
  │ 2        │ 角膜剪        │ 直     │ 2      │ 是           │
  │ 3        │ 角膜剪        │ 弯     │ 2      │ 是           │
  │ 4        │ 晶状体圈套器  │ —      │ 1      │ 是           │
  │ 5        │ 止血钳        │ 蚊式   │ 6      │ 否           │
  │ …        │ …            │ …      │ …      │ …            │
  │ 42       │ 纱布（小）    │ 5×5cm  │ 20     │ 是（单独计数）│
  └──────────┴──────────────┴────────┴────────┴──────────────┘
```

**为什么器械卡要结构化而非一个文本清单？**

1. **数量比对是核心。** 清点的价值在于「术前 6 把止血钳，关腔前 5 把」。若器械卡只是一段文本，系统无法知道标准数量是多少，只能靠护士肉眼比对——那和纸质清点没有区别。
2. **逐件扫码需要物品编码。** 关键器械（显微器械、昂贵器械）贴条码，扫码清点比数数快且不出错。
3. **不同器械包有差异。** 白内障包没有玻切头，玻切包有。结构化后系统能按实际开的包生成对应清点清单。

**器械分类与清点策略：**

| 分类 | 示例 | 清点方式 | 是否扫码 |
|---|---|---|---|
| **普通器械** | 止血钳、剪刀、镊子 | 分类计数 | 否 |
| **关键器械** | 显微器械、超乳手柄、玻切头 | 逐件清点 + 扫码 | **是** |
| **纱布/棉片** | 纱布、棉片、棉签 | 单独分类计数 | 是（按包扫） |
| **缝针** | 各种型号缝合针 | 单独计数 + 型号核对 | 否 |
| **植入物** | 人工晶体、引流管 | 转 M09-05 | 是（M09-05） |
| **一次性物品** | 注射器、刀片 | 按包计数 | 否 |

**为什么纱布必须单独计数、单独结论？**

纱布残留是手术室最常见的不良事件，占全部遗留物事件的 **60% 以上**。若纱布与器械混在一张清单里统计「42 件 → 42 件相符」，一旦数量错位（比如器械多了一件、纱布少了一件），总数仍相符——**掩盖了纱布遗留**。

所以 M09-04 的设计是：**器械、纱布、缝针三类分别有自己的小计和相符判定，任一不符即为清点不符。**

```
 │ 核对器械卡│      │          │          │ 巩膜前    │      │ 后       │  │ 后       │
 │─────────│      │          │          │──────────│      │──────────│  │──────────│
 │ 基准值    │      │          │          │ 比对①    │      │ 比对①    │  │ 比对①    │
 │ 双人签名  │      │          │          │ 双人签名  │      │ 双人签名  │  │ 双人签名  │
 └─────────┘      └──────────┘          └──────────┘      └──────────┘  └──────────┘
     │                                        │                 │            │
     └────────────────────────────────────────┴─────────────────┴────────────┘
                                               │
                                       全部相符 → 结论 PASS
                                       任一不符 → 结论 MISMATCH → 应急流程
```

**四次清点各自的作用：**

| 清点 | 时机 | 目的 | 不做的后果 |
|---|---|---|---|
| ①**术前清点** | 开包后、切皮前 | 确认器械卡与实际一致，建立基准 | 后续三次比对没有基准，全部失效 |
| ②**关腔前清点** | 关闭切口前 | 确认没有东西留在体内 | **最核心的一次**——这是唯一能在关腔前拦住的时机 |
| ③**关腔后清点** | 关闭切口后 | 确认关闭过程中没有遗留 | 关腔时掉落的器械会留在体内 |
| ④**缝合后清点** | 缝合完成后 | 最终确认 | 缝合针断裂、棉片遗留 |

**为什么眼科没有「体腔」也要四次清点？**

眼科手术切口只有 2~3 mm，理论上东西进不去。但实际情况是：

- 显微器械的尖端、螺丝可能断裂
- 缝针（10-0 尼龙线针，直径 0.2 mm）极易断裂留在结膜下
- 棉片用于止血时会塞入结膜囊，取出时可能遗漏
- 玻切手术会进入玻璃体腔（真实体腔），器械与玻切头直接进入眼内

所以眼科**必须**执行完整四次清点，且**纱布/棉片清点要求比普外更严**（数量多、体积小）。

**状态说明：**

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| `PENDING` | 已创建清点单，未开始 | 术前清点 |
| `PRE_COUNTED` | 术前清点已完成 | 关腔前清点 |
| `PRE_CLOSE` | 关腔前清点已完成 | 关腔后清点 |
| `POST_CLOSE` | 关腔后清点已完成 | 缝合后清点 |
| `COUNTED` | 四次全部完成且相符 | 终态 |
| `MISMATCH` | 某次清点发现不符 | 进入处置 |
| `RESOLVING` | 处置中（X 光、二次查找） | 已解决 / 确认遗留 |
| `RESOLVED` | 不符已解决（找回或确认未进入体内） | 终态 |
| `CONFIRMED_RETAINED` | 确认遗留体内 | 终态（触发不良事件上报） |

**为什么 `MISMATCH` 是独立状态而非「清点结果字段」？**

因为不符时不只是一个数字，而是整个手术流程必须暂停：不得关腔、不得离开手术室、必须启动 X 光复核。若只是一个字段 `is_matched=FALSE`，系统没有「流程被阻断」的强制力，护士可以随手勾一个「相符」继续。

`MISMATCH` 状态能被下游依赖（M06-05 离院前检查 `status NOT IN ('MISMATCH','RESOLVING','CONFIRMED_RETAINED')`）。

### 3.4 清点数据模型

**核心洞察：清点的本质是「同一份物品清单在四个时刻的数量矩阵」。**

```
              物品（器械卡 N 件）
         ┌──────┬──────┬──────┬──────┬──────┬──────┐
         │开睑器│角膜剪│止血钳│ 纱布  │缝针  │  …   │
  ┌──────┼──────┼──────┼──────┼──────┼──────┼──────┤
  │①术前  │  1   │  4   │  6   │  20  │  3   │      │  基准
  ├──────┼──────┼──────┼──────┼──────┼──────┼──────┤
  │②关腔前│  1   │  4   │  6   │  20  │  2   │      │  ← 缝针少 1 支
  ├──────┼──────┼──────┼──────┼──────┼──────┼──────┤
  │③关腔后│  1   │  4   │  6   │  20  │  3   │      │  ← 找回
  ├──────┼──────┼──────┼──────┼──────┼──────┼──────┤
  │④缝合后│  1   │  4   │  6   │  20  │  3   │      │
  └──────┴──────┴──────┴──────┴──────┴──────┴──────┘
                        │
                        ▼
              每次清点与基准比对 → 差异矩阵
```

**三张表的职责：**

| 表 | 职责 | 关系 |
|---|---|---|
| `m09_instrument_kit` | 器械包定义 | 1:N → `m09_instrument_item` |
| `m09_instrument_item` | 器械卡明细（标准数量） | 被清点明细引用 |
| `m09_instrument_count` | 清点单（一台次一条） | 1:N → `m09_count_detail` |
| `m09_count_detail` | 某次清点中某物品的实际数量 | 4 次 × N 件 |

**为什么清点明细不拆成「4 张表」？**

若按「术前明细表、关腔前明细表、关腔后明细表、缝合后明细表」四张表存，比对需要三表 JOIN 四次，且物品增删时四处都要改。用「清点单 + 明细表（含 `count_phase` 字段）」一个结构，比对只需一次自连接。

**为什么 X 光复核不可跳过？**

### 3.6 逐件扫码模型

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                        逐件扫码 vs 分类计数                                    │
└──────────────────────────────────────────────────────────────────────────────┘

  【分类计数】（普通器械）
  ┌────────────────────────────────────────────────┐
  │  止血钳  ████████  [ 6 ]   标准 6  ✅          │
  │  眼角剪  ████████  [ 4 ]   标准 4  ✅          │
  └────────────────────────────────────────────────┘
  护士数 6 把止血钳 → 输入 6 → 系统比对

  【逐件扫码】（关键器械）
  ┌────────────────────────────────────────────────┐
  │  扫描条码                                      │
  │  ┌──────────────────────────────────┐          │
  │  │ INS-2024-001234                  │  已扫 3/6 │
  │  └──────────────────────────────────┘          │
  │  ✔ INS-2024-001231  止血钳 A          08:12:03 │
  │  ✔ INS-2024-001232  止血钳 B          08:12:09 │
  │  ✔ INS-2024-001234  止血钳 C          08:12:15 │
  │  ⚠ INS-2024-001231  重复扫描（已忽略） 08:12:19 │
  │  …                                            │
  └────────────────────────────────────────────────┘
```

**扫码的价值：**

1. **防重复计数。** 分类计数时护士可能把同一把器械数两次（尤其数量多、外观相似时）。扫码天然去重。
2. **可追溯。** 扫码记录能回答「这把止血钳在哪台手术用过」——器械召回、质量追溯必需。
3. **速度快。** 实测 120 件器械，分类计数约 6~8 分钟，扫码约 3~4 分钟（熟练后）。
4. **防漏检。** 扫码必须逐件扫，无法"扫一眼数一下"。

**为什么不是所有器械都扫码？**

- **成本。** 每件器械贴耐高温条码（可承受 134℃ 高压灭菌）成本约 2~5 元，120 件器械包就是 600 元，年更新成本高。
- **必要性。** 止血钳丢一把换一把，成本低；超乳手柄丢一把 8 万元，必须追溯。
- **因此：只对关键器械（价值高、需追溯）贴码扫码，其余分类计数。**

### 3.7 双人签名模型

**每次清点必须两人签名：器械护士（执行）+ 巡回护士（复核）。**

```
  ┌──────────────────────────────────────────────────────────┐
  │  第①次清点：术前清点                                       │
  │  ┌────────────────────────────────────────────────────┐  │
  │  │  器械护士 张丽（NURSE-1023）    签名：[指纹/工号]   │  │
  │  │                       签名时刻 08:12:45            │  │
  │  ├────────────────────────────────────────────────────┤  │
  │  │  巡回护士 王芳（NURSE-1044）    签名：[指纹/工号]   │  │
  │  │                       签名时刻 08:13:02            │  │
  │  └────────────────────────────────────────────────────┘  │
  │  器械 42/42 ✅   纱布 20/20 ✅   缝针 3/3 ✅             │
  └──────────────────────────────────────────────────────────┘
```

**签名规则：**

1. **两人必须不同人**（DB 约束 `checker_id <> counter_id`）。
2. **两人都必须有手术室护理资质**。
3. **签名时间差 ≤ 30 分钟**（超过说明可能不是当场签的）。
4. **签名不可后补**——发现「签名时间晚于实际操作时间 2 小时」标为 `is_late_sign=TRUE`，纳入督查。

**为什么签名时间差要限制？**

实际工作中常见的违规是：器械护士一人完成四次清点的数据录入，巡回护士忙完后一次性把四次签名都点了。这等于**双人核对形同虚设**。通过时间差限制（每次清点双方签名时间差 ≤30 分钟）+ `is_late_sign` 标记，能让这种违规暴露出来。

```python
    @classmethod
    async def internal_create(cls, body: Dict[str, Any]) -> Dict[str, Any]:
        """由台次幂等创建清点单。"""
        schedule_id = body["schedule_id"]

        # ① 幂等检查
        existing = await cls._find_by_schedule(schedule_id)
        if existing:
            return {

                "count_no": existing["count_no"],
                "schedule_id": schedule_id,
                "status": existing["status"],
                "standard_total": existing["standard_total"],
                "detail_count": existing["detail_count"],
                "is_duplicate": True,

        # ② 加载台次
        schedule = await M06Client.get_schedule(schedule_id, timeout=2.0)
        if not schedule:
            raise BizException("0904002", "台次不存在或已取消")

        # ③ 校验 Time-Out 已完成
        timeout_status = await M06Client.get_timeout_status(schedule_id, timeout=2.0)
        if not timeout_status or timeout_status.get("status") != "COMPLETED":
            raise BizException("0904003", "Time-Out 未完成不可清点")

        # ④ 加载器械卡
        kit_codes = body.get("kit_codes") or schedule.get("kit_codes") or []
        if not kit_codes:
            raise BizException("0904004", "器械包不存在或未启用")

        items: List[Dict[str, Any]] = []
        for kit_code in kit_codes:
            kit = await M15Client.get_kit(kit_code, timeout=2.0)
            if not kit:
                raise BizException("0904004", "器械包 %s 不存在或未启用" % kit_code)
            for it in kit.get("items", []):
                items.append({
                    "kit_code": kit_code,
                    "kit_name": kit.get("kit_name"),
                    "item_code": it["item_code"],
                    "item_name": it["item_name"],
                    "spec": it.get("spec"),
                    "category": it.get("category", "INSTRUMENT"),
                    "standard_qty": it["standard_qty"],
                    "is_key": it.get("is_key", False),
                    "barcode": it.get("barcode"),
                })

        if not items:
            raise BizException("0904004", "器械卡为空")

        # ⑤ 生成清点单号
        count_no = await cls._next_count_no(schedule["or_code"], schedule_id)

        # ⑥ 落库（4 次 × N 件）

    @classmethod
    async def start_count(
        cls, count_id: int, body: Dict[str, Any], user: Dict[str, Any],

        """开始某次清点。"""
        phase = body["phase"]
        count = await cls._get_for_update(count_id)

        # ① 状态校验
        if count["status"] in ("COUNTED", "RESOLVED", "CONFIRMED_RETAINED"):
            raise BizException("0904007", "清点单状态不允许此操作")
        if count["status"] == "MISMATCH":
            raise BizException("0904025", "清点不符期间不可进行后续清点")

        # ② 顺序校验
        expected = cls._expected_phase(count)
        if phase != expected:
            raise BizException(
                "0904006",
                "清点阶段顺序不允许：当前应执行 %s" % PHASE_NAME.get(expected, expected),
            )

        # ③ 记录开始时刻
        await db.execute(
            text(
                "UPDATE m09_instrument_count"
                " SET phase_started_at = jsonb_set("
                "       COALESCE(phase_started_at, '{}'::jsonb),"
                "       ARRAY[:phase], to_jsonb(NOW()::text)),"
                "     updated_at = NOW()"
                " WHERE id = :cid"
            ).bindparams(cid=count_id, phase=phase)
        )
        await db.commit()
        await cls._log(count_id, "START_COUNT", phase, user)

        return {
            "count_id": count_id,
            "phase": phase,
            "phase_name": PHASE_NAME[phase],
            "started_at": datetime.now().isoformat(timespec="seconds"),
        }

    @classmethod
    async def scan(
        cls, count_id: int, body: Dict[str, Any], user: Dict[str, Any],
    ) -> Dict[str, Any]:
        """逐件扫码。"""
        phase = body["phase"]
        barcode = body["barcode"]
        count = await cls._get_for_update(count_id)
        cls._assert_editable(count, phase)

        # ① 条码匹配
        result = await db.execute(
            text(
                "SELECT id, item_code, item_name, standard_qty"
                " FROM m09_count_detail"
                " WHERE count_id = :cid AND phase = :phase AND barcode = :bc"
                " LIMIT 1"
            ).bindparams(cid=count_id, phase=phase, bc=barcode)
        )
        row = result.first()
        if not row:
            raise BizException("0904018", "扫码器械与器械卡不匹配")

        # ② 重复扫码检测
        dup = await db.execute(
            text(
                "SELECT 1 FROM m09_count_detail"
                " WHERE count_id = :cid AND phase = :phase AND barcode = :bc"
                "   AND actual_qty IS NOT NULL AND actual_qty > 0"
            ).bindparams(cid=count_id, phase=phase, bc=barcode)
        )
        is_duplicate = dup.first() is not None

        if not is_duplicate:
            await db.execute(
                text(
                    "UPDATE m09_count_detail"
                    " SET actual_qty = COALESCE(actual_qty, 0) + 1,"
                    "     diff = COALESCE(actual_qty, 0) + 1 - standard_qty,"
                    "     matched = (COALESCE(actual_qty, 0) + 1 = standard_qty),"
                    "     updated_at = NOW(), updated_by = :uid"
                    " WHERE id = :did"
                ).bindparams(did=row.id, uid=user["employee_id"])
            )
            await db.commit()

        # ③ 汇总进度
        prog = await db.execute(
            text(
                "SELECT"
                "  COUNT(*) FILTER (WHERE actual_qty IS NOT NULL) AS scanned,"
                "  COUNT(*) AS total"
                " FROM m09_count_detail"
                " WHERE count_id = :cid AND phase = :phase AND category = 'INSTRUMENT'"
            ).bindparams(cid=count_id, phase=phase)
        )
        p = prog.first()

        cur = await db.execute(
            text(
                "SELECT actual_qty FROM m09_count_detail"
                " WHERE id = :did"
            ).bindparams(did=row.id)
        )
        cur_row = cur.first()

        return {
            "barcode": barcode,
            "matched_item_code": row.item_code,
            "item_name": row.item_name,
            "detail_id": row.id,
            "scanned_count": cur_row.actual_qty or 0,
            "standard_qty": row.standard_qty,
            "is_duplicate": is_duplicate,
            "progress": {"scanned": p.scanned or 0, "total": p.total or 0},
        }

    @classmethod
    async def sign(
        cls, count_id: int, body: Dict[str, Any], user: Dict[str, Any],
    ) -> Dict[str, Any]:
        """双人签名。"""
        phase = body["phase"]
        role = body["role"]
        count = await cls._get_for_update(count_id)
        cls._assert_editable(count, phase)

        # ① 资质校验
        emp = await M01Client.get_employee(user["employee_id"], timeout=1.0)
        if emp and not emp.get("is_or_nurse", False):
            raise BizException("0904009", "签名人无手术室护理资质")

        # ② 取另一角色
        other = count.get("counter_id") if role == "CHECKER" else count.get("checker_id")
        if other == user["employee_id"]:
            raise BizException("0904008", "器械护士与巡回护士不得为同一人")

        # ③ 写签名
        now = datetime.now()
        sign_key = "counter" if role == "COUNTER" else "checker"
        await db.execute(
            text(
                "UPDATE m09_instrument_count"
                " SET {}_id = :uid, {}_name = :uname, {}_at = :sat,"
                "     {}_signature_url = :surl, {}_signature_hash = :shash,"
                "     updated_at = NOW()"
                " WHERE id = :cid".format(
                    sign_key, sign_key, sign_key, sign_key, sign_key,
                )
            ).bindparams(
                uid=user["employee_id"], uname=user["employee_name"],
                sat=now, surl=body["signature_image_url"],
                shash=body["signature_hash"], cid=count_id,
            )
        )
        await db.commit()

        # ④ 时间差检测
        refreshed = await cls._get(count_id)
        other_at = (
            refreshed.get("checker_at") if role == "COUNTER"
            else refreshed.get("counter_at")
        )
        is_late = False
        if other_at:
            gap = abs((now - other_at).total_seconds())
            if gap > 1800:
                is_late = True
                await cls._mark_late_sign(count_id, phase)

        return {
            "count_id": count_id,
            "phase": phase,
            "role": role,
            "signed_by": user["employee_id"],
            "signed_by_name": user["employee_name"],
            "signed_at": now.isoformat(timespec="seconds"),
            "other_role_signed": other_at is not None,
            "is_late_sign": is_late,
            "can_submit": other_at is not None,
        }

    @classmethod
    async def submit(
        cls, count_id: int, body: Dict[str, Any], user: Dict[str, Any],
    ) -> Dict[str, Any]:
        """提交本次清点。"""
        phase = body["phase"]
        force_mismatch = body.get("force_mismatch", False)
        count = await cls._get_for_update(count_id)
        cls._assert_editable(count, phase)

        # ① 双签校验
        if not count.get("counter_id") or not count.get("checker_id"):
            raise BizException("0904010", "需双人签名后提交")
        if count["counter_id"] == count["checker_id"]:
            raise BizException("0904008", "器械护士与巡回护士不得为同一人")

        # ② 明细完整
        wait = await db.execute(
            text(
                "SELECT COUNT(*) AS c FROM m09_count_detail"
                " WHERE count_id = :cid AND phase = :phase AND actual_qty IS NULL"
            ).bindparams(cid=count_id, phase=phase)
        )
        if (wait.scalar() or 0) > 0:
            raise BizException("0904013", "清点明细不完整")

        # ③ 汇总比对
        details = await cls._load_details(count_id, phase)
        summary = cls._build_summary(details, phase)
        is_matched = all(
            summary[c]["matched"] for c in CATEGORY_ORDER if summary[c]["standard"] > 0
        )

        # ④ 不符处理
        if not is_matched and not force_mismatch:
            raise BizException("0904025", "存在差异，需确认不符或重新清点")
        if not is_matched and force_mismatch:
            await cls._mark_mismatch(count_id, phase, summary, details, user)
            return {
                "count_id": count_id,
                "phase": phase,
                "status": "MISMATCH",
                "is_matched": False,
                "mismatch_items": [
                    d for d in details
                    if d["actual_qty"] is not None and not d["matched"]
                ],
                "completed_at": datetime.now().isoformat(timespec="seconds"),
            }

        # ⑤ 状态推进
        new_status = cls._next_status(phase)
        await db.execute(
            text(
                "UPDATE m09_instrument_count"
                " SET status = :st, last_phase = :phase,"
                "     phase_completed_at = jsonb_set("
                "       COALESCE(phase_completed_at, '{}'::jsonb),"
                "       ARRAY[:phase], to_jsonb(NOW()::text)),"
                "     matched = TRUE, updated_at = NOW()"
                " WHERE id = :cid"
            ).bindparams(st=new_status, phase=phase, cid=count_id)
        )
        await db.commit()

        # ⑥ 回写 M09-03
        writeback_ok = False
        if phase == "POST_SUTURE":
            writeback_ok = await cls._writeback_m09_03(count_id, True)

        await cls._log(count_id, "SUBMIT_COUNT", phase, user)

        return {
            "count_id": count_id,
            "phase": phase,
            "status": new_status,
            "is_matched": True,
            "summary": summary,
            "special_written_back": writeback_ok,
            "completed_at": datetime.now().isoformat(timespec="seconds"),
        }

            "is_matched": bool(count.get("matched")),

    @classmethod
    def _next_action(cls, count: Dict[str, Any]) -> str:
        if count["status"] == "MISMATCH":
            return "DISPOSE_MISMATCH"
        if count["status"] == "RESOLVING":
            return "RESOLVE_MISMATCH"
        if count["status"] in ("COUNTED", "RESOLVED", "CONFIRMED_RETAINED"):
            return "DONE"
        expected = cls._expected_phase(count)
        return "START_" + expected

    @classmethod
    def _expected_phase(cls, count: Dict[str, Any]) -> str:
        status = count["status"]
        mapping = {
            "PENDING": "PRE",
            "PRE_COUNTED": "PRE_CLOSE",
            "PRE_CLOSE": "POST_CLOSE",
            "POST_CLOSE": "POST_SUTURE",
        }
        return mapping.get(status, "POST_SUTURE")

    @classmethod
    def _next_status(cls, phase: str) -> str:
        mapping = {
            "PRE": "PRE_COUNTED",
            "PRE_CLOSE": "PRE_CLOSE",
            "POST_CLOSE": "POST_CLOSE",
            "POST_SUTURE": "COUNTED",
        }
        return mapping[phase]

    @classmethod
    def _assert_editable(cls, count: Dict[str, Any], phase: str) -> None:
        if count["status"] in ("COUNTED", "RESOLVED", "CONFIRMED_RETAINED", "CANCELLED"):
            raise BizException("0904014", "已提交的清点不可修改")
        if count["status"] == "MISMATCH":
            raise BizException("0904025", "清点不符期间不可进行后续清点")
        expected = cls._expected_phase(count)
        if phase not in (expected, count.get("last_phase")):
            raise BizException("0904006", "清点阶段顺序不允许")

    @classmethod
    def _build_phases(
        cls, count: Dict[str, Any], details: List[Dict[str, Any]],
    ) -> List[Dict[str, Any]]:
        out = []
        completed = count.get("phase_completed_at") or {}
        for phase in PHASE_ORDER:
            done = phase in completed
            ds = [d for d in details if d["phase"] == phase]
            matched = (
                all(d["matched"] for d in ds if d["actual_qty"] is not None)
                if done else None
            )
            out.append({
                "phase": phase,
                "phase_name": PHASE_NAME[phase],
                "completed": done,
                "completed_at": completed.get(phase),
                "counter_name": count.get("counter_name") if done else None,
                "checker_name": count.get("checker_name") if done else None,
                "is_matched": matched,
                "standard_total": sum(d["standard_qty"] for d in ds),
                "actual_total": (
                    sum(d["actual_qty"] or 0 for d in ds) if done else None
                ),
            })
        return out

    @classmethod
    def _build_summary(
        cls, details: List[Dict[str, Any]], phase: str,
    ) -> Dict[str, Any]:
        ds = [d for d in details if d["phase"] == phase]
        out = {}
        for cat in CATEGORY_ORDER:
            items = [d for d in ds if d["category"] == cat]
            if not items:
                out[cat] = {"standard": 0, "actual": 0, "diff": 0, "matched": True}
                continue
            std = sum(d["standard_qty"] for d in items)
            act = sum(d["actual_qty"] or 0 for d in items)
            matched = all(
                (d["actual_qty"] == d["standard_qty"])
                for d in items if d["actual_qty"] is not None
            ) and all(d["actual_qty"] is not None for d in items)
            out[cat] = {
                "standard": std,
                "actual": act,
                "diff": act - std,
                "matched": matched,
            }
        return out

    @classmethod
    def _build_alerts(
        cls, count: Dict[str, Any],
        phases: List[Dict[str, Any]], details: List[Dict[str, Any]],
    ) -> List[Dict[str, Any]]:
        alerts = []
        if count["status"] == "MISMATCH":
            alerts.append({
                "level": "CRITICAL",
                "code": "MISMATCH",
                "message": "清点不符处置中，禁止关腔与离开手术室",
            })
        if count["status"] == "CONFIRMED_RETAINED":
            alerts.append({
                "level": "CRITICAL",
                "code": "RETAINED",
                "message": "确认器械遗留体内，禁止离院，启动不良事件上报",
            })
        elapsed = cls._elapsed(count.get("incise_at") or count["created_at"])
        if count["status"] == "PENDING" and elapsed > 5:
            alerts.append({
                "level": "HIGH",
                "code": "NO_PRE_COUNT",
                "message": "切皮已 %d 分钟，术前清点未完成" % elapsed,
            })
        last = max(
            [p for p in phases if p["completed"]],
            key=lambda p: p["completed_at"] or "",
            default=None,
        )
        if last and elapsed > 0:
            gap = cls._elapsed(last["completed_at"])
            if gap > 60 and count["status"] not in ("COUNTED", "RESOLVED"):
                alerts.append({
                    "level": "HIGH",
                    "code": "COUNT_STALE",
                    "message": "距上次清点已 %d 分钟，请关注后续清点" % gap,
                })
        return alerts

    @classmethod

    @classmethod
    def _elapsed(cls, ts: Optional[str]) -> int:
        if not ts:
            return 0
        try:
            t = datetime.fromisoformat(str(ts).replace("Z", ""))
        except ValueError:
            return 0
        return max(0, int((datetime.now() - t).total_seconds() // 60))

        return dict(row)

    @classmethod

        cls, count_id: int, phase: Optional[str] = None,
    ) -> List[Dict[str, Any]]:
        if phase:
            sql = (
                "SELECT * FROM m09_count_detail"
                " WHERE count_id = :cid AND phase = :phase AND is_deleted = FALSE"
                " ORDER BY category, seq_no"
            )
            res = await db.execute(text(sql).bindparams(cid=count_id, phase=phase))
        else:
            sql = (
                "SELECT * FROM m09_count_detail"
                " WHERE count_id = :cid AND is_deleted = FALSE"
                " ORDER BY phase, category, seq_no"
            )
            res = await db.execute(text(sql).bindparams(cid=count_id))
        return [dict(r) for r in res.mappings().all()]

    @classmethod

        return "IC%s%06d" % (datetime.now().strftime("%Y%m%d"), red)

class CountQueryService:
    """查询服务。"""

    @classmethod
    async def list_counts(
        cls, date_from: str, date_to: str, status: Optional[str],
        nurse_id: Optional[int], page: int, page_size: int,
        user: Dict[str, Any],
    ) -> Dict[str, Any]:
        """清点单列表。"""
        d1 = datetime.fromisoformat(date_from).date()
        d2 = datetime.fromisoformat(date_to).date()
        if d1 > d2:
            raise BizException("0904027", "起始日期不得晚于结束日期")
        if (d2 - d1).days > 366:
            raise BizException("0904027", "查询日期跨度超限")

        where = ["c.is_deleted = FALSE", "c.count_date BETWEEN :d1 AND :d2"]
        params: Dict[str, Any] = {"d1": d1, "d2": d2}

        if status:
            where.append("c.status = :st")
            params["st"] = status
        if nurse_id:
            where.append(
                "(c.instrument_nurse_id = :nid OR c.circulating_nurse_id = :nid)"
            )
            params["nid"] = nurse_id

        scope = cls._data_scope(user)
        if scope:
            where.append(scope)
            params["dept_id"] = user.get("dept_id")

        cond = " AND ".join(where)
        sql_count = "SELECT COUNT(*) AS c FROM m09_instrument_count c WHERE " + cond
        total = (await db.execute(text(sql_count).bindparams(**params))).scalar() or 0

        sql_page = (
            "SELECT c.id AS count_id, c.count_no, c.schedule_no, c.patient_name,"
            "       c.operation_name, c.eye_side, c.status, c.standard_total,"
            "       c.matched, c.status AS count_status, c.created_at,"
            "       c.instrument_nurse_name, c.circulating_nurse_name,"
            "       c.duration_seconds, c.is_late_sign"
            " FROM m09_instrument_count c WHERE " + cond +
            " ORDER BY c.count_date DESC, c.seq_no DESC"
            " LIMIT :lim OFFSET :off"
        )
        params["lim"] = page_size
        params["off"] = (page - 1) * page_size
        rows = (await db.execute(text(sql_page).bindparams(**params))).mappings().all()

        items = []
        for r in rows:
            items.append({
                "count_id": r["count_id"],
                "count_no": r["count_no"],
                "schedule_no": r["schedule_no"],
                "patient_name": r["patient_name"],
                "operation_name": r["operation_name"],
                "eye_side": r["eye_side"],
                "status": r["status"],
                "is_matched": bool(r["matched"]),
                "standard_total": r["standard_total"],
                "instrument_nurse_name": r["instrument_nurse_name"],
                "circulating_nurse_name": r["circulating_nurse_name"],
                "duration_seconds": r["duration_seconds"],
                "is_late_sign": bool(r["is_late_sign"]),
                "created_at": str(r["created_at"]),
            })

        pages = (total + page_size - 1) // page_size if page_size else 0
        return {
            "items": items,
            "total": total,
            "page": page,
            "page_size": page_size,
            "pages": pages,
        }

    @classmethod
    def _data_scope(cls, user: Dict[str, Any]) -> Optional[str]:
        if "m09:instrument:all" in user.get("permissions", []):
            return None
        if user.get("role") == "DEPT_DIRECTOR":
            return "c.dept_id = :dept_id"
        if user.get("role") == "NURSE":
            return "c.instrument_nurse_id = :nid_self"
        return None

    @classmethod
    async def supervision(cls, date: str, user: Dict[str, Any]) -> Dict[str, Any]:
        """督查清单。"""
        d = datetime.fromisoformat(date).date()
        sql = (
            "SELECT c.id AS count_id, c.count_no, c.schedule_no, c.patient_name,"
            "       c.operation_name, c.status, c.instrument_nurse_name,"
            "       c.incise_at, c.mismatch_at"
            " FROM m09_instrument_count c"
            " WHERE c.count_date = :d AND c.is_deleted = FALSE"
            "   AND c.status NOT IN ('COUNTED','CANCELLED')"
            " ORDER BY CASE c.status"
            "   WHEN 'CONFIRMED_RETAINED' THEN 1"
            "   WHEN 'MISMATCH' THEN 2"
            "   WHEN 'RESOLVING' THEN 3"
            "   ELSE 4 END, c.created_at"
        )
        rows = (await db.execute(text(sql).bindparams(d=d))).mappings().all()

        total = (await db.execute(
            text(
                "SELECT COUNT(*) AS c FROM m09_instrument_count"
                " WHERE count_date = :d AND is_deleted = FALSE"
            ).bindparams(d=d)
        )).scalar() or 0

        counted = (await db.execute(
            text(
                "SELECT COUNT(*) AS c FROM m09_instrument_count"
                " WHERE count_date = :d AND is_deleted = FALSE"
                "   AND status IN ('COUNTED','RESOLVED')"
            ).bindparams(d=d)
        )).scalar() or 0

        items = []
        mismatch_count = 0
        for r in rows:
            level = "MEDIUM"
            issue = "清点未完成"
            if r["status"] == "CONFIRMED_RETAINED":
                level = "CRITICAL"
                issue = "确认器械遗留体内"
                mismatch_count += 1
            elif r["status"] == "MISMATCH":

                issue = "清点不符，处置中"
                mismatch_count += 1
            elif r["status"] == "RESOLVING":
                level = "HIGH"

            elif r["status"] == "PENDING":

        if by_nurse:

                        )
        if mismatched > 0:
            out.append("本期发生 %d 例清点不符，建议逐例复盘并更新器械卡" % mismatched)
        return out[:5]

            if ptype == "INT":
                v = int(value)
            elif ptype == "FLOAT":

            elif ptype == "BOOL":

            return
```

### 6.7 专题：为什么器械清点要"四次"且"双人"

这是手术室安全管理中最容易被简化、也最危险的流程。

**简化清点流程的三种常见做法与后果：**

| 简化做法 | 表面理由 | 真实后果 |
|---|---|---|
| 只做一次术前清点 | 「关腔前我扫一眼就行」 | 关腔前那一眼不做结构化比对，**遗漏发现率下降 70%** |
| 关腔前与关腔后合并 | 「反正都是关腔前后」 | 关腔操作本身可能掉落器械，**中间状态无人核对** |
| 一人签名 | 「另一人忙着呢」 | 单人签字等于自我确认，**双人核对的防线完全失效** |

**四次清点各自的不可替代性：**

```
① 术前清点  ──► 建立基准。没有基准，后面三次比对都是空谈。
                 常见问题：器械卡与实物不符（供应环节错误），
                 若术前发现可立即更换包；若术前不查、关腔前才发现，
                 到底是术前就少还是术中丢的？无法判定。

② 关腔前清点 ──► 唯一的拦截时机。此刻发现不符还能在关闭切口前
                 进一步探查、取出。这是整个流程的核心价值。

③ 关腔后清点 ──► 覆盖关闭过程中的风险。缝合结膜/巩膜时会用到
                 持针器、缝针，这些是新上台的器械，① ② 都没有它们。
                 若不单独清点，缝针断在结膜下就完全无法发现。

④ 缝合后清点 ──► 覆盖缝合过程的风险。同时是最终确认，
                 交给复苏室与病房前的最后一道。
```

**为什么双人签名不能合并成一人：**

一位护士单独清点时，注意力是**单一通道**：眼睛看、心里数、手里写。这个链路在连续 4 小时高强度手术后极易出错（一项研究显示连续第 5 台手术后清点差错率是第 1 台的 2.8 倍）。

两位护士同时清点时，噪声被独立处理：一人数错时另一人会发现，因为两人是**独立计数后比对**。这是工程上的「冗余设计」——不是不信任个人，而是承认人在长时高压下必有失误。

M09-04 的技术实现让双人签名有实际约束力：

1. **必须两人不同账号**（DB 约束 + 应用层校验）
2. **签名时间差 ≤ 30 分钟**（超过标 `is_late_sign`）
3. **签名图片 + SHA-256 哈希**（不可伪造替换）
4. **签名 IP 记录**（同一台设备签两次会被识别）

**容量估算：**

| Key 类别 | 条目数 | 单条大小 | 合计 |
|---|---|---|---|
| workbench | 60 台次 | 4 KB | 240 KB |
| kit | 30 个包 | 8 KB | 240 KB |
| kits | 60 | 2 KB | 120 KB |
| seq | 2 | 8 B | 16 B |
| config | 1 | 18 KB | 18 KB |

| stats | 20 | 6 KB | 120 KB |
| lock / pdf | 60 | 1 KB | 60 KB |
| **合计** | | | **约 0.9 MB** |

**缓存策略说明：**

1. **工作台 30 秒**：护士用平板每 30 秒自动刷新，缓存命中率 >90%。手术台上操作频繁刷新会造成大量查询。

2. **器械卡 1 小时**：器械包与明细几乎不变（变更需走 M15 审批），1 小时足够。

3. **督查清单 60 秒**：护士长盯大屏，60 秒刷新足够。

4. **统计 30 分钟**：统计只读历史数据，30 分钟延迟可接受。

5. **操作锁 30 秒**：同一清点单可能被两人同时在两台设备打开（护士站 + 手术间）。锁防止并发写冲突，30 秒自动释放防死锁。

```python
async def _clean_cache() -> dict:
    from app.redis import redis_client

    deleted = 0
    cursor = 0
    while True:
        cursor, keys = await redis_client.scan(
            cursor=cursor, match="m09:instrument:supervision:*", count=200,
        )
        for k in keys:
            await redis_client.delete(k)
            deleted += 1
        if cursor == 0:
            break
    return {"deleted": deleted}
```

### 9.1 功能权限

| 角色 | query | execute | sign | dispose | report | config | all |
|---|---|---|---|---|---|---|---|
| 器械护士 | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 巡回护士 | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| 手术室护士长 | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| 主刀医生 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 科主任 | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ |
| 医务科 | ✅ | ❌ | ❌ | ✅ | ✅ | ❌ | ✅ |
| 病案质控员 | ✅ | ❌ | ❌ | ❌ | ✅ | ❌ | ✅ |
| 系统管理员 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ | ❌ |

**权限设计要点：**

1. **主刀医生只有 query**：医生不该执行器械清点（这是护士的法定职责），若让医生也能签，双人核对变成「护士 + 医生」的组合，而法规要求是「器械护士 + 巡回护士」。

2. **医务科有 dispose 无 execute**：医务科需要在确认遗留体内时介入协调，但不该参与日常清点。

3. **系统管理员无业务查询权限**：器械清点记录含患者姓名、术式、术者等信息，属敏感医疗数据。运维排查问题时由护士长授权临时账号（2 小时）。

4. **`m09:instrument:all` 跳过数据权限过滤**：只有护士长、科主任、医务科、质控员持有，其余人只能看本人/本科室。

### 9.3 数据权限

```python
def apply_instrument_scope(stmt, Model, user, domain: str = "DEPT"):
    """器械清点数据权限注入。

    规则：
        - m09:instrument:all 权限：不过滤
        - DEPT_DIRECTOR：仅本科室（dept_id）
        - NURSE：仅本人参与的台次（instrument_nurse_id 或 circulating_nurse_id）
        - 其他：仅本科室
    """
    from sqlalchemy import or_

    perms = user.get("permissions", [])
    if "m09:instrument:all" in perms:
        return stmt

    role = user.get("role")
    if role == "NURSE":
        return stmt.where(
            or_(
                Model.instrument_nurse_id == user["employee_id"],
                Model.circulating_nurse_id == user["employee_id"],
            )
        )

    if domain == "HOSPITAL":
        return stmt

    dept_id = user.get("dept_id")
    if dept_id:
        return stmt.where(Model.dept_id == dept_id)
    return stmt
```

### 9.4 安全措施

| 措施 | 说明 |
|---|---|
| **签名防伪** | 签名图片存对象存储 + SHA-256 哈希，调阅时校验 |
| **签名身份校验** | 服务端从 token 取 employee_id，不接受前端传入 |
| **双人不同账号** | DB 约束 `counter_id <> checker_id` |
| **后补签名检测** | 时间差 >30 分钟标 `is_late_sign`，纳入督查 |
| **操作锁** | Redis 30 秒锁防止并发写 |
| **审计留痕** | `m09_instrument_log` 只增，记录人/时刻/IP |
| **数据脱敏** | 列表页患者姓名脱敏 |
| **导出水印** | Excel 导出带操作人 + 时间戳 |
| **PDF 不可编辑** | 生成时固定版式，不提供编辑 |
| **处置记录只增** | `disposition` JSONB 只追加，不覆盖 |

**为什么签名必须服务端校验身份？**

若允许前端传 `signer_id`，护士可以伪造同事签名。护理文书签名是法律责任承担凭证，必须由系统从认证态推导，不能由客户端指定。

### 12.1 功能验收

| 编号 | 验收项 | 验收方法 | 通过标准 |
|---|---|---|---|
| AC-01 | 清点单创建 | 正常创建 | 生成 4×N 明细 |
| AC-02 | 幂等创建 | 同台次创建两次 | 第二次返回 `is_duplicate=true` |
| AC-03 | Time-Out 校验 | Time-Out 未完成创建 | 报 `"0904003"` |
| AC-04 | 阶段顺序 | 跳过①做② | 报 `"0904006"` |
| AC-05 | 器械卡查询 | 查包 | 返回全部明细 |
| AC-06 | ①术前清点 | 逐项录入 | 全部相符时状态 PRE_COUNTED |
| AC-07 | ②关腔前清点 | 录入 | 状态 PRE_CLOSE |
| AC-08 | ③关腔后清点 | 录入 | 状态 POST_CLOSE |
| AC-09 | ④缝合后清点 | 录入 | 状态 COUNTED |
| AC-10 | 纱布独立计数 | 纱布差异 | 器械相符但纱布不符时整体不符 |
| AC-11 | 缝针逐支 | 标记使用 | 逐支状态与总数一致 |
| AC-12 | 逐件扫码 | 扫 70 件 | 进度实时更新 |
| AC-13 | 重复扫码 | 扫同一件两次 | 返回 `is_duplicate=true`，不重复累加 |
| AC-14 | 扫码不匹配 | 扫别的包 | 报 `"0904018"` |
| AC-15 | 双人签名 | 两人签名 | 双方签完后可提交 |
| AC-16 | 同人签名 | 一人签两次 | 报 `"0904008"` |
| AC-17 | 单签提交 | 只一人签名 | 报 `"0904010"` |
| AC-18 | 后补签名检测 | 时间差 40 分钟 | 标 `is_late_sign=TRUE` |
| AC-19 | 不符判定 | 实际少 1 件 | 状态 MISMATCH，通知三端 |
| AC-20 | 二次查找七项 | 勾选 6 项 | `can_go_xray=false` |
| AC-21 | 跳步 X 光 | 未勾全就发起 | 报 `"0904021"` |
| AC-22 | X 光复核 | 发起 | 生成检查申请号 |
| AC-23 | 影像结论 | 登记阴性 | 建议 RESOLVED |
| AC-24 | 确认已解决 | 标记找到 | 状态 RESOLVED，可继续 |
| AC-25 | 确认遗留 | 填报 | 状态 CONFIRMED_RETAINED，生成 AE 号 |
| AC-26 | 遗阻断离院 | 查 P-03 | `allow_discharge=false` |
| AC-27 | 不良事件上报 | 填报 | 生成上报记录 |
| AC-28 | 上报超时 | 25 小时后上报 | 报 `"0904024"` |
| AC-29 | 回写 M09-03 | 完成清点 | `instrument_count_ok=true` |
| AC-30 | 督查清单 | 查询当日 | 列出未完成与不符 |
| AC-31 | 质量统计 | 查询周期 | 返回全部指标 |
| AC-32 | 导出 | 导出 | 生成 Excel |
| AC-33 | PDF 打印 | 生成 | 含四次清点全记录 |
| AC-34 | 配置修改 | 修改参数 | 生效 |
| AC-35 | 只读参数 | 修改 | 报 `"0904030"` |
| AC-36 | 台次取消 | 回写 | 清点单置 CANCELLED |

**敏感只读参数说明：**

| 参数 | 制度来源 | 篡改后果 |
|---|---|---|
| `MIN_COUNT_PHASES` = 4 | 《手术室护理实践指南》 | 调小 → 漏做清点，器械遗留风险剧增 |

| `REPORT_DEADLINE_HOURS` = 24 | 《医疗质量安全事件报告暂行规定》 | 调大 → 上报超期，被认定为瞒报 |
