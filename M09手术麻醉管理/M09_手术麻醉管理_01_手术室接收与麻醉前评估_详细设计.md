## 1. 模块概述

### 1.1 模块定位

M09-01 是 M09 手术麻醉管理的**入口**。M06-04 完成 Time-Out 之后，患者被推进手术间，从这一刻起到"麻醉开始"之前的这段时间全部归 M09-01。

它回答三个问题：

1. **患者进手术间了吗？**（接收登记——进间时刻是术中时长统计的起点）
2. **麻醉医生看过患者、同意麻醉了吗？**（麻醉前评估——这是**独立的法定责任**）
3. **用什么麻醉方式、用哪些药、谁执行？**（麻醉方案确定——M09-02 按此执行）

```
M06-04 Time-Out 完成
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│  M09-01 手术室接收与麻醉前评估                             │
│                                                           │
│  ① 进间登记  刷患者腕带 → 记录 or_in_at                    │
│  ② 接收复核  核对手术间/台次/主刀/术式（与 Time-Out 一致）  │
│  ③ 麻醉前评估 气道/心肺/过敏/用药/禁食/ASA 复评            │
│  ④ 麻醉方案  麻醉方式 + 药品 + 剂量（从 M01-07 带出后调整） │
│  ⑤ 麻醉知情同意  电子签名                                 │
│  ⑥ 麻醉开始  回写 M06-04（此后不可回退）                    │
└──────────────────────────────────────────────────────────┘
        │
        ▼
   M09-02 麻醉记录（诱导 → 维持 → 苏醒）
```

### 1.2 为什么独立成子模块

**理由一：麻醉前评估是独立的法定医疗责任，不是"手术前记一笔"。**

《麻醉科医疗服务能力建设指南》要求麻醉医生在麻醉前完成访视与评估，内容包括：病史、体格检查、气道评估、心肺功能、实验室检查、既往麻醉史、过敏史、用药史、禁食情况，并给出 ASA 分级与麻醉风险告知。这份评估的签字人是麻醉医生本人，**一旦出事，"麻醉医生是否做了合格的术前评估"是第一个被追问的问题**。

它不属于 M06 的任何子模块：
- M06-02 术前准备是**病房护士**执行的准备工作（禁食、备皮、宣教），不是医学评估
- M06-04 四方核对是**团队**确认"人对了、眼对了、方案对了"，不判断"这个患者能不能耐受麻醉"
- M06-01 医学准入选的是"能不能做日间手术"，麻醉评估的是"用哪种麻醉、风险多大、要不要改方案"——**一个胆囊炎术前的 ASA III 级患者可以做日间白内障，但麻醉方案必须调整**

**理由二：进间时刻是术中时长统计的唯一可信起点。**

M06-03 排程记录了计划开始时刻，M09-03 记录切皮时刻，但"手术间实际被占用多长时间"必须从**患者进间**算起，而不是从切皮算起。中间有：摆体位（3~8 分钟）、消毒铺巾（5~10 分钟）、麻醉诱导（5~15 分钟）。眼科白内障手术切皮到缝合可能只有 12 分钟，但手术间占用 45 分钟——**用切皮时刻算手术间利用率会严重高估**。

M09-01 的进间登记是唯一能给出这个时刻的地方。

**理由三：麻醉方案必须与执行记录分离。**

M09-02 记录的是"实际给了什么药、给了多少、什么时刻"，是**事实记录**。
M09-01 记录的是"计划给什么药、为什么这么选"，是**决策记录**。

分开的理由和 M13-05 参考区间版本化一致：**事后追责问的是"当时的决策依据是什么"，不是"最后执行成了什么"**。如果只留执行记录，遇到"麻醉医生改了方案但没记录原因"就无法追溯。眼科尤其常见：球后阻滞改全身麻醉（患者术中配合不佳）、表面麻醉加静脉镇静（患者过度紧张），这些变更必须能对应回决策。

**理由四：眼科 80% 手术不需要麻醉医生，必须有"无麻醉医生"的完整模式。**

本院麻醉方式分布：

| 麻醉方式 | 占比 | 是否需麻醉医生 | 执行人 |
|---|---|---|---|
| 表面麻醉 | 45% | 否 | 主刀医生（滴表面麻醉药） |
| 局部浸润 | 25% | 否 | 主刀医生 |
| 球后/球周阻滞 | 20% | 否 | 主刀医生（部分医院要求麻醉医生） |
| 静脉镇静 | 7% | 是 | 麻醉医生 |
| 全身麻醉 | 3% | 是 | 麻醉医生 |

**这意味着 M09-01 的主路径不能假设有麻醉医生。** 若把麻醉评估硬塞进 M09-02（有麻醉医生的场景），则 80% 的手术要么被迫"空着麻醉评估字段"，要么被迫走一个不存在的流程。

### 1.3 与相邻子模块分工

| 事项 | M06-01 准入 | M06-02 术前准备 | M06-04 四方核对 | **M09-01 麻醉前评估** | M09-02 麻醉记录 |
|---|---|---|---|---|---|
| 判断"能不能做日间手术" | ✅ 唯一责任 | ❌ | ❌ | ❌ | ❌ |
| 禁食完成情况 | ❌ | ✅ 执行与记录 | ✅ 核对确认 | ✅ **复核**（麻醉前再看一次） | ❌ |
| 术眼标记 | ❌ | ✅ 执行 | ✅ 核对确认 | ✅ **复核**（麻醉后无法确认） | ❌ |
| 知情同意签署 | ✅ 手术同意书 | ✅ 催办 | ✅ 核验 | ✅ **麻醉同意书** | ❌ |
| ASA 分级 | ⚠️ 准入判定用（粗分级） | ❌ | ❌ | ✅ **麻醉医生评定（最终）** | ❌ |
| 麻醉方式选择 | ❌ | ❌ | ❌ | ✅ 唯一责任 | ❌ |
| 麻醉药品与剂量 | ❌ | ❌ | ❌ | ✅ 计划值 | ✅ 实际值 |
| 患者进间时刻 | ❌ | ❌ | ❌ | ✅ 唯一责任 | ❌ |
| 麻醉开始时刻 | ❌ | ❌ | ⚠️ 接收回写 | ✅ 触发回写 | ✅ 记录 |

**关键分工边界：**

- **M06-02 的禁食记录是"患者说自己几点吃的"，M09-01 的禁食复核是"麻醉医生再看一次并判断够不够"**。两者不重复：护士按规则确认（如全麻禁食 8 小时），麻醉医生按实际情况判断（如患者说"我 7 点喝了一杯牛奶"，护士按清饮 2 小时判断合格，但麻醉医生知道牛奶属固体需 8 小时，必须推迟）。
- **M06-01 的 ASA 分级是准入判定输入（BLOCK 级规则要求 ASA I~III），M09-01 的 ASA 是麻醉医生最终评定**。两者可能不一致——准入时按门诊记录填 ASA II，麻醉前访视发现患者刚感冒、气道分泌物多，改为 ASA III 并调整方案。**M09-01 的值为准，差异记入日志。**

### 1.4 概念辨析

| 概念 | 定义 | 常见混淆 |
|---|---|---|
| **进间时刻 `or_in_at`** | 患者被推入手术间的时刻 | 与"切皮时刻"混淆。切皮晚 20~35 分钟（体位+消毒+铺巾+麻醉诱导） |
| **麻醉开始 `anesthesia_start_at`** | 首次给药（诱导开始）时刻 | 与"进间"混淆。进间后先摆体位、开放静脉、上监护，5~15 分钟后才给药 |
| **手术开始 `surgery_start_at`** | **切皮**时刻 | M06-03 的同名字段是**计划**时刻，M09-03 的是**实际**时刻。**同名不同义，必须区分 `planned_surgery_start_at` 与 `actual_surgery_start_at`** |
| **麻醉前评估** | 麻醉医生对患者的医学评估与风险判断 | 与 M06-01"医学准入"混淆。前者判断"能不能耐受这种麻醉"，后者判断"能不能做日间手术" |
| **ASA 分级** | 美国麻醉医师协会身体状况分级 I~VI | 与"手术分级 LEVEL_1~4"混淆。**ASA 是患者身体状况，手术分级是手术难度，两者独立** |
| **麻醉方案** | 麻醉方式 + 药品 + 剂量 + 监测要求 | 与"麻醉记录"混淆。方案是计划，记录是事实 |
| **麻醉知情同意** | 患者/家属对麻醉风险的知情与授权 | 与"手术知情同意"混淆。**两份独立文书，分别签字**（M06-06 D-03 手术同意 / D-04 麻醉同意） |
| **监护人/代理人签字** | 无民事行为能力或无法签字时由代理人签 | 与"患者本人签字"混淆。需记录关系（配偶/子女/父母） |

### 1.5 模块目标

| 指标 | 现状 | 目标 |
|---|---|---|
| 麻醉前评估完成率 | 92% | **100%**（法规要求） |
| 进间登记及时率 | 60%（多为事后补录） | **≥98%** |
| 麻醉方案与执行一致率 | 未知 | **≥95%**（不一致需留原因） |
| 麻醉知情同意签署率 | 96% | **100%** |
| ASA 分级与 M06-01 准入一致的差异率 | 未知 | **≤8%**（差异本身合理，需可追溯） |
| 术前评估耗时（中位数） | 8 分钟 | **≤6 分钟**（结构化表单 + 自动带出） |
| 进间到麻醉开始的间隔（中位数） | 12 分钟 | **≤10 分钟** |
| 因评估不充分导致的麻醉方案临时变更 | 3.2% | **≤1.5%** |

### 1.6 关键业务角色

| 角色 | 在 M09-01 中的职责 | 权限侧重 |
|---|---|---|
| **麻醉医生** | 麻醉前评估、ASA 评定、麻醉方案确定、麻醉同意书告知与签署确认 | 唯一有权写 ASA 与麻醉方案 |
| **手术室巡回护士** | 进间登记、患者身份复核、监护设备连接 | 只做登记不写医学判断 |
| **主刀医生** | 表面/局部麻醉的执行人；确认麻醉方案 | 无麻醉方式时（表面麻醉）充当"执行人" |
| **麻醉科主任** | 高风险病例（ASA IV 及以上）会诊与审批 | 审批权限 |
| **医务科** | 麻醉方案异常的复核（如 ASA IV 仍安排日间手术） | 抽查与干预 |

## 2. 业务范围与边界

### 2.1 范围内

| 功能 | 说明 |
|---|---|
| 进间登记 | 扫腕带 → 记录 `or_in_at`、`or_code`、`seq_no`；与 M06-03 台次对齐 |
| 接收复核 | 核对手术间号、台次号、患者 ID、术式、眼别与 Time-Out 记录一致（不一致阻断） |
| 监护连接登记 | 心电、血压、血氧、麻醉机、微量泵的启动时刻（用于麻醉记录起点） |
| **麻醉前评估** | 气道评估（Mallampati 分级）、心肺听诊、既往麻醉史、过敏史、当日用药、禁食复核、实验室异常项、ASA 分级、风险告知 |
| ASA 分级 | 麻醉医生评定 I~VI，与 M06-01 准入值比对，差异需留原因 |
| 麻醉方案 | 麻醉方式（从 M01-07 `md_anesthesia` 选）+ 药品清单（从 `md_anesthesia_drug` 带出后调整）+ 监测要求 + 备注 |
| 麻醉知情同意 | 电子签名（患者/家属/代理人）、告知要点勾选 |
| 麻醉开始触发 | 记录 `anesthesia_start_at` 并回写 M06-04（此后 M06-04 状态不可回退） |
| 特殊病例标记 | ASA IV 及以上、困难气道、恶性高热史、局麻药过敏——触发预警与主任会诊 |
| 疑难点记录 | 结构化记录 5 类疑难点（见 3.6） |

| U-08 | `GET /internal/v1/m13/review/{id}` | 术前检验结果 | 3s | **降级** | 同上 |
| U-09 | `GET /internal/v1/m14/special/permits` | 麻醉药品印鉴卡有效性 | 2s | **阻断** | 麻醉药品不可发放 |
| U-10 | `POST /internal/v1/m02/audit/record` | 审计 | 1s | **异步补偿** | |
| U-11 | `POST /internal/v1/m06/verify/on-anesthesia-start` | 麻醉开始回写 | 2s | **重试 5 次 + 补偿队列** | 本地标记 `pending_writeback` |
| U-12 | `POST /internal/v1/m03-05/message/send` | 预警通知 | 2s | **异步重试** | |

**三条降级铁律：**

1. **U-05 患者过敏史不可降级**——麻醉药过敏是致命的，宁可让手术延迟也不能在不知道过敏史的情况下给麻醉。
2. **U-01/U-02 不可降级**——没有台次信息或 Time-Out 未完成就进间，等于绕开了 M06-04 的四方核对。
3. **U-09 不可降级**——麻醉药品（芬太尼、瑞芬太尼等）受《麻醉药品和精神药品管理条例》管制，印鉴卡失效时发放属违法。

## 3. 业务模型

### 3.1 接收记录模型

M09-01 的核心实体是 `m09_or_reception`（接收记录），一台次一条。

```
m09_or_reception
├── 台次信息（从 M06-03 快照）
│   ├── schedule_id / schedule_no
│   ├── apply_id / ds_no          ← 日间手术申请单（住院手术时为住院号）
│   ├── or_code / or_name         ← 手术间
│   ├── seq_no                    ← 当日台次号
│   ├── planned_surgery_start_at  ← 计划开始
│   ├── patient_id / patient_name / gender / age / weight_kg / height_cm
│   ├── operation_code / operation_name / eye_side
│   └── surgeon_id / surgeon_name / anesthesia_doctor_id / anesthesia_doctor_name
│
├── 时间戳
│   ├── or_in_at          ← 进间（本子模块核心产出）
│   ├── monitoring_at     ← 监护设备连接
│   ├── assessment_at     ← 麻醉前评估完成
│   ├── consent_signed_at ← 麻醉同意签署
│   └── anesthesia_start_at ← 麻醉开始（触发 M09-02）
│
├── 麻醉前评估（子表 m09_pre_anesthesia_assessment）
├── 麻醉方案（子表 m09_anesthesia_plan + m09_anesthesia_plan_drug）
└── 麻醉同意（子表 m09_anesthesia_consent）
```

**为什么接收记录与评估分表：** 接收记录是"物理事实"（患者几点进来的），评估是"医学判断"（一页可能 30 个字段）。合并会让每次查台次列表都要扫 30 个大字段；且评估可能有多个版本（麻醉医生 A 评完，麻醉医生 B 接班重评）。

### 3.2 接收状态机（7 态）

```
                    ┌──────────────┐
                    │   PENDING    │  ← M06-04 Time-Out 完成后自动创建
                    └──────┬───────┘
                           │ 进间登记（扫腕带 + 核对）
                           ▼
                    ┌──────────────┐
                    │  IN_ROOM     │  患者已进间
                    └──────┬───────┘
                           │ 监护连接
                           ▼
                    ┌──────────────┐
                    │  MONITORING  │  监护就位
                    └──────┬───────┘
                           │ 麻醉前评估提交
                           ▼
                    ┌──────────────┐
                    │  ASSESSED    │  评估完成
                    └──────┬───────┘
                           │ 麻醉方案确定 + 同意签署
                           ▼
                    ┌──────────────┐
                    │    READY     │  可开始麻醉
                    └──────┬───────┘
                           │ 麻醉开始
                           ▼
                    ┌──────────────┐
                    │ ANESTHESIA_  │  已交棒 M09-02
                    │   STARTED    │
                    └──────────────┘

  旁支：
  ┌──────────────┐
  │  CANCELLED   │  ← 进间后发现不能做（设备故障/患者突发状况/放弃手术）
  └──────────────┘
```

**状态转移表：**

| 从 | 到 | 触发 | 前置条件 | 操作者 |
|---|---|---|---|---|
| PENDING | IN_ROOM | 扫腕带进间 | Time-Out 已完成、腕带条码校验通过、台次未开始 | 巡回护士 |
| IN_ROOM | MONITORING | 监护连接登记 | 至少连接 3 项（心电/血压/血氧） | 巡回护士 |
| MONITORING | ASSESSED | 提交麻醉前评估 | 必填项齐全、ASA 已评定 | 麻醉医生 |
| ASSESSED | READY | 麻醉方案确认 + 同意签署 | 方案已选麻醉方式+至少 1 种药、同意书已签 | 麻醉医生 |
| READY | ANESTHESIA_STARTED | 麻醉开始 | 同意书已签、监护已连接 | 麻醉医生 |
| PENDING/IN_ROOM/MONITORING/ASSESSED/READY | CANCELLED | 取消 | 填原因 ≥10 字 + 分类 | 巡回护士/麻醉医生 |
| IN_ROOM/MONITORING | PENDING | 撤销进间（误扫） | 5 分钟内、无后续动作 | 巡回护士 |

**三个关键设计决策：**

**决策一：`PENDING` 由 M06-04 自动创建，而非 M09 主动拉取。**

M06-04 Time-Out 完成后调 `POST /internal/v1/m09/surgery/on-timeout-completed`，M09 收到后**幂等创建** `m09_or_reception`（`uk_m09_rec_schedule` 保证一台次一条）。理由：如果 M09 定时扫描 M06 台次，会有 1~5 分钟的延迟；而患者在门外等着，进间时刻必须精确。**事件驱动 + 幂等键**是唯一能同时满足"即时"与"不重复"的方案。

**决策二：`IN_ROOM` 不能跳过 `MONITORING` 直接到 `ASSESSED`。**

表面麻醉没有监护？——**错。** 眼科球后阻滞可致眼心反射（心率骤降至 40 以下），表面麻醉也可能出现迷走反射。本院制度要求**所有进入手术间的患者至少连接血氧饱和度与无创血压**（即使不做麻醉记录）。所以 MONITORING 是所有路径的必经状态。

**例外：** 极短的操作（如单纯换药、拆线）本就不进手术间，走 M06-03 的"门诊处置"台次类型，不在 M09-01 范围。

**决策三：`CANCELLED` 后的台次处理由 M06-03 决定，M09-01 只上报。**

M09-01 取消时发事件 `m09.reception.cancelled`，M06-03 收到后决定"台次作废"还是"顺延后续台次"。理由：台次调度是 M06-03 的职责，M09-01 若直接改 M06 的台次状态就产生了跨模块写。

### 3.3 麻醉前评估模型

**评估分 7 组共 34 项**（结构化表单，非纯文本）：

| 组 | 项目 | 必填 | 说明 |
|---|---|---|---|
| **A. 基本测量** | 体重、身高、BMI（自动算）、血压、心率、体温、SpO2 | ✅ | 自动从监护设备带出（有设备时） |
| **B. 气道评估** | Mallampati 分级（I~IV）、张口度（cm）、甲颏距离（cm）、颈椎活动度、有无义齿/松动牙、有无困难气道史 | ✅ | **全麻/镇静必填，表面/局麻选填** |
| **C. 心肺听诊** | 心音（正常/杂音/心律失常）、双肺呼吸音（清/干啰音/湿啰音）、颈静脉 | ✅ | |
| **D. 病史** | 既往麻醉史（次数/有无不良反应）、高血压/糖尿病/心脏病/哮喘/甲亢/青光眼、近期上呼吸道感染 | ✅ | 青光眼是眼科特有重点：**闭角型青光眼禁用散瞳，但抗胆碱药（阿托品）也禁用** |
| **E. 过敏史** | 药物过敏（青霉素/头孢/局麻药/其他）、食物过敏、其他过敏；**局麻药过敏必须单独标记** | ✅ | 从 M03-01 带出后确认 |
| **F. 当日用药** | 抗凝药（华法林/利伐沙班/阿司匹林/氯吡格雷）、降压药、降糖药、抗青光眼药、其他 | ✅ | 抗凝药停用天数是硬核查项 |
| **G. 禁食与实验室** | 末次进食时刻、进食内容（固体/清饮）、禁食时长（自动算）、术前检查有无异常项 | ✅ | 与 M06-02 记录比对，不一致需说明 |

**ASA 分级（I~VI）：**

| 级别 | 定义 | 日间手术适配性 |
|---|---|---|
| **I** | 正常健康患者 | ✅ 适合 |
| **II** | 轻度系统性疾病，无功能受限 | ✅ 适合 |
| **III** | 重度系统性疾病，有一定功能受限 | ⚠️ 需麻醉科主任确认（本院 M06-01 准入 BLOCK 级规则要求 ASA I~III） |
| **IV** | 重度系统性疾病，持续威胁生命 | ❌ 不适合日间，必须转住院 |
| **V** | 濒死患者，预期不手术不能存活 24 小时 | ❌ 不适用 |
| **VI** | 脑死亡器官捐献者 | ❌ 不适用 |

**ASA 分级与 M06-01 准入值的比对：**

```
if m09.asa_level > m06.asa_level (更严重):
    → 记录差异，必填差异原因（≥10 字）
    → if m09.asa_level >= IV:
        → 触发预警：转住院（不允许继续日间手术流程）
    → if m09.asa_level == III and 原准入为 I/II:
        → 触发预警：需麻醉科主任确认
elif m09.asa_level < m06.asa_level:
    → 记录差异（改好也是差异，需说明）
```

**为什么"改好"也要记差异：** 准入时填 ASA II 是因为门诊记录显示"高血压 3 年"，麻醉访视发现血压控制良好、无靶器官损害，实际应为 ASA I。这个差异本身是**好事**，但若不记录，统计"ASA 差异率"会偏低，掩盖真正的问题病例。

### 3.4 麻醉方案模型

**麻醉方式来源**：`md_operation_anesthesia_rel`（术式可选麻醉）→ `md_anesthesia`（麻醉方式详情）。

眼科典型组合：

| 术式 | 可选麻醉 | 常见选择 |
|---|---|---|
| 白内障超声乳化 | 表面麻醉 / 局部浸润 / 球后阻滞 / 静脉镇静 | 表面麻醉（60%）/ 球后阻滞（30%） |
| 玻璃体切除 | 球后阻滞 / 球周阻滞 / 全身麻醉 | 球后阻滞（70%）/ 全麻（30%） |
| 玻璃体腔注药 | 表面麻醉 | 表面麻醉（100%） |
| 青光眼小梁切除 | 球后阻滞 / 球周阻滞 + 静脉镇静 | 球后阻滞+镇静（50%）/ 球后阻滞（50%） |
| 斜视矫正 | 全身麻醉（儿童）/ 局部浸润（成人） | 全麻（儿童 100%） |
| 角膜移植 | 球后阻滞 / 全身麻醉 | 球后阻滞（80%） |

**方案数据结构：**

```
麻醉方案
├── anesthesia_code / anesthesia_name      ← 麻醉方式
├── anesthesia_type                        ← SURFACE/LOCAL/PERIBULBAR/...
├── injection_site                         ← 注射部位（球后/球周/结膜下）
├── need_anesthetist                       ← 是否需麻醉医生（来自主数据）
├── executor_id / executor_name            ← 执行人（表面麻醉时是主刀）
├── drugs[]                                ← 药品清单
│   ├── drug_code / drug_name / spec
│   ├── planned_dose / dose_unit
│   ├── route_code
│   └── is_required                        ← 是否必用
├── monitor_requirements                   ← 监测要求（ECG/BP/SpO2/EtCO2/BIS）
├── position                               ← 体位（仰卧/头高位/头低位）
└── remark                                 ← 备注（镇静深度、特殊要求）
```

**药品来源**：`md_anesthesia_drug`（麻醉方式默认药品）→ 麻醉医生按患者情况增删改。**修改必须记录原因。**

眼科常用麻醉药（写入附录 B）：

| 类别 | 药名 | 常规剂量 | 说明 |
|---|---|---|---|
| 表面麻醉 | 奥布卡因 0.4% | 1~2 滴 × 3 次 | 白内障主力 |
| 表面麻醉 | 丙美卡因 0.5% | 1~2 滴 × 2 次 | 起效快、刺激性小 |
| 局部浸润 | 利多卡因 2% | 2~5 ml | 加肾上腺素延长作用 |
| 球后阻滞 | 利多卡因 2% + 布比卡因 0.75% | 各 2~3 ml | 混合液，起效快+维持久 |
| 镇静 | 丙泊酚 | 1~2 mg/kg | 需麻醉医生 |
| 镇静 | 咪达唑仑 | 0.02~0.04 mg/kg | 抗焦虑 |
| 镇痛 | 芬太尼 | 1~2 μg/kg | **麻醉药品，须 M14-09 逐支登记** |
| 镇痛 | 瑞芬太尼 | 0.05~0.15 μg/kg/min | **麻醉药品** |
| 肌松 | 罗库溴铵 | 0.6 mg/kg | 全麻 |
| 拮抗 | 新斯的明 | 0.04~0.07 mg/kg | 肌松拮抗 |

### 3.5 麻醉知情同意模型

**告知要点（8 项，须逐项勾选确认）：**

| 编号 | 告知内容 |
|---|---|
| C-01 | 麻醉方式及操作过程 |
| C-02 | 麻醉可能出现的并发症（局麻药中毒、过敏、呼吸抑制、误吸、心脑血管意外） |
| C-03 | 眼科麻醉特有风险（球后出血、眼心反射、视神经损伤、眼球穿孔） |
| C-04 | 麻醉过程中可能改变方案（如局麻改全麻）及其原因 |
| C-05 | 不实施麻醉的风险 |
| C-06 | 麻醉前后注意事项（禁食、停药、陪护） |
| C-07 | 麻醉费用说明 |
| C-08 | 患者/家属有疑问可随时提出的权利 |

**C-03 白内障/眼底手术必选**（术中涉及球后注射）；表面麻醉的 C-03 降级为可选。

**签字主体（三种）：**

| 类型 | 适用 | 必填字段 |
|---|---|---|
| `PATIENT` 患者本人 | 成人、有民事行为能力 | 签名图片 + 签名哈希 + 签署时刻 + IP |
| `SURROGATE` 家属/代理人 | 未成年人、无民事行为能力、意识不清 | + 代理人姓名 + 与患者关系（配偶/子女/父母/监护人）+ 代理人身份证号后 4 位 |
| `ORAL` 口头同意 | 紧急抢救无法书面签字 | + 见证人姓名（医护）+ 见证人签名 + 事后补签时限（24 小时） |

**为什么眼科必须有 `SURROGATE` 完整字段：** 白内障患者平均年龄 70+ 岁，相当比例有认知障碍或手抖无法签字；斜视患者多为儿童。**没有代理人关系记录，事后无法证明签字有效。**

### 3.6 疑难点记录模型

麻醉医生可结构化记录 5 类疑难点：

| 类型 | 示例 |
|---|---|
| `AIRWAY` 气道困难 | 颈椎病致头后仰受限，Mallampati III 级 |
| `ALLERGY` 过敏风险 | 青霉素过敏，头孢类需皮试 |
| `CARDIO` 心血管风险 | 窦性心动过缓 48 次/分，球后阻滞可能诱发眼心反射 |
| `METABOLIC` 代谢问题 | 糖尿病空腹血糖 9.8 mmol/L，需术中监测 |
| `OCULAR` 眼部特殊 | 独眼、眼球萎缩、曾行玻璃体切除 |

**为什么要结构化：** 纯文本"备注"无法统计。结构化后可以回答："本月有多少例困难气道？是不是集中在某个术式？"——这是麻醉科质量管理的核心数据。

### 3.7 从 Time-Out 到麻醉开始的完整时序

```
T-30s   M06-04 Time-Out 完成（四方签名）
          │ POST /internal/v1/m09/surgery/on-timeout-completed
          ▼
T+0     M09 创建 m09_or_reception（PENDING）
T+30s   巡回护士扫腕带 → IN_ROOM，记录 or_in_at
T+2min  摆体位、开放静脉、连接监护 → MONITORING
T+5min  麻醉医生查体、问诊 → 填写麻醉前评估
T+9min  提交评估 → ASSESSED（ASA III，触发主任确认）
T+12min 主任确认；麻醉方案确定（球后阻滞 + 利多卡因+布比卡因）
T+13min 麻醉同意书签署 → READY
T+14min 首次给药 → ANESTHESIA_STARTED
          │ POST /internal/v1/m06/verify/on-anesthesia-start
          ▼
T+14min M06-04 状态锁定（麻醉已开始不可回退）

--- 交棒 M09-02 麻醉记录 ---
```

**关键：整个流程 14 分钟，其中医学判断只占 4 分钟（查体问诊），其余是设备与文书。** 这也是模块目标"术前评估耗时 ≤6 分钟"的由来——目标是压缩非医学操作的时间（结构化表单、自动带出、一键确认），**不是压缩医生思考的时间**。

| V-03 | 大屏模式下患者姓名脱敏 | 保留姓，名用 `*` 替代 |

**为什么工作台分"待进间"和"已进间"两块而不是一张表：** 巡回护士的工作模式是"接一个进间，然后处理里面的"，两块对应两种完全不同的动作。合成一张表后，"进间"这个最高频动作要在一堆已进间记录里找，每天点错 5~10 次。

**交互说明：**

| 操作 | 触发 | 结果 |
|---|---|---|
| 扫描腕带 | 扫码枪输入 | 自动解析三段，逐项比对 |
| 手工输入 | 腕带损坏 | 需两人核对（输入人工审核密码） |
| 确认进间 | 7 项核对完成 | 状态置 `IN_ROOM`，记录 `or_in_at` |
| 取消 | 不进了 | 返回工作台 |

**校验规则：**

| 编号 | 规则 | 错误码 |
|---|---|---|
| V-04 | 腕带条码格式必须为三段式 | `"0901001"` |
| V-05 | 条码中的 `identity_hash` 必须与患者档案一致 | `"0901002"` |
| V-06 | Time-Out 必须已完成 | `"0901003"` |
| V-07 | 患者 ID、手术间、台次必须与台次登记一致（不一致阻断） | `"0901004"` |
| V-08 | 术式与眼别不一致时需两人确认 | `"0901005"` |
| V-09 | 手工输入腕带需权限校验 | `"0901006"` |
| V-10 | 进间时刻偏差超过 30 分钟需填写原因 | `"0901007"` |

**为什么第 7 项"术式"标注"需人工"：** 腕带条码只含患者 ID、就诊号、身份指纹，**不含术式**（术式写在病历和 M06-04 核对表里）。这一项只能靠护士看核对表确认。有人会问"能不能把术式写进腕带"——不能：术式术前可能变更（M06-04 有"UPDATE_APPLY"异常处置路径），腕带一旦打印就固定了。

**校验规则：**

| 编号 | 规则 | 错误码 |
|---|---|---|
| V-34 | 状态必须为 `READY` | `"0901029"` |
| V-35 | 麻醉同意书必须有效（未 superseded） | `"0901030"` |
| V-36 | 监护至少 3 项已连接 | `"0901031"` |
| V-37 | 麻醉开始后回写 M06-04 失败时，标记 `pending_writeback` 并重试 | `"0901032"` |

**回写 M06-04 的重试策略（重要）：**

```
try:
    await M06Client.on_anesthesia_start(schedule_id, anesthesia_start_at)
    reception.writeback_status = "SUCCESS"
except Exception:
    reception.writeback_status = "PENDING"
    reception.writeback_retry += 1
    # 进入 Celery 补偿队列，退避 10s/30s/60s/120s/300s
    # 5 次失败后标记 FAILED 并告警
```

**为什么必须补偿：** `on-anesthesia-start` 之后 M06-04 的相关状态不可回退（`"0604048"`）。如果回写失败但系统不知道，M06-04 会一直认为"麻醉未开始"，护士可能重复走流程。**本地记录 `anesthesia_start_at` 是权威的，回写只是通知。**

### 6.2 错误码规范

| 错误码 | 说明 | 触发场景 |
|---|---|---|
| `"0901001"` | 腕带条码格式非法 | 扫描结果不是三段式 |
| `"0901002"` | 腕带身份指纹与患者档案不符 | `identity_hash` 校验失败（腕带伪造或发错） |
| `"0901003"` | Time-Out 未完成，不得进间 | M06-04 状态非 PASSED |
| `"0901004"` | 患者/手术间/台次与台次登记不一致 | 扫错患者或走错手术间 |
| `"0901005"` | 术式或眼别不一致需两人确认 | 人工核对未通过 |
| `"0901006"` | 手工输入腕带需授权 | 无 `m09:reception:override` 权限 |
| `"0901007"` | 进间时刻偏差过大需填写原因 | 偏差 >30 分钟 |
| `"0901008"` | 麻醉前评估必填项不完整 | A 组缺项，或全麻时 B 组缺项 |
| `"0901009"` | 患者局麻药过敏，方案不得含局麻药 | E 组勾选局麻药过敏 + 方案含局麻药 |
| `"0901010"` | 抗凝药必须填写停用天数 | F 组勾选抗凝药但未填天数 |
| `"0901011"` | 禁食时长不足 | 实际禁食 < 规则要求 |
| `"0901012"` | ASA 分级与准入不一致需说明 | 差异未填原因或原因 <10 字 |
| `"0901013"` | ASA IV 及以上不得继续日间手术 | ASA ≥ IV |

"""

CENT = Decimal("0.01")

# 麻醉方式 → 是否需要麻醉医生
NEED_ANESTHETIST = {"SEDATION", "GENERAL", "COMBINED", "SPINAL"}

# 禁食规则（小时）：全麻固体 8 / 清饮 2；镇静 6 / 2；局麻表面无要求
FASTING_RULES = {

    "SEDATION": {"SOLID": 6, "LIQUID": 2},
    "COMBINED": {"SOLID": 8, "LIQUID": 2},
    "SPINAL": {"SOLID": 8, "LIQUID": 2},
}

# 抗胆碱药（青光眼禁用）
ANTICHOLINERGIC_DRUGS = {"ATROPINE", "SCOPOLAMINE", "GLYCOPYRROLATE"}

# 局麻药
LOCAL_ANESTHETIC_DRUGS = {"LIDOCAINE", "BUPIVACAINE", "ROPIVACAINE", "PROPARACAINE", "OXYBUPROCAINE"}

# 麻醉药品（需印鉴卡）
NARCOTIC_DRUGS = {"FENTANYL", "REMIFENTANIL", "SUFENTANIL", "MORPHINE", "PETHIDINE"}


class ReceptionService:
    """手术室接收服务。"""

    # ---------- 查询 ----------

    @classmethod
    async def get_workbench(cls, db: AsyncSession, user, date_str: Optional[str] = None) -> Dict[str, Any]:
        target = date.fromisoformat(date_str) if date_str else date.today()
        rows = (await db.execute(
            select(M09OrReception)
            .where(
                M09OrReception.reception_date == target,
                M09OrReception.is_deleted.is_(False),
            )
            .order_by(M09OrReception.or_code, M09OrReception.seq_no)
        )).scalars().all()

        pending: List[Dict[str, Any]] = []
        in_room: List[Dict[str, Any]] = []
        counters = {
            "planned": len(rows),
            "in_room": 0,
            "anesthetized": 0,
            "to_assess": 0,
            "abnormal": 0,
        }
        alerts: List[Dict[str, Any]] = []

        for r in rows:
            item = cls._brief_dict(r)
            if r.status == "PENDING":
                pending.append(item)
            elif r.status in ("IN_ROOM", "MONITORING", "ASSESSED", "READY"):
                in_room.append(item)
                counters["in_room"] += 1
                if r.status in ("MONITORING", "ASSESSED", "READY"):
                    counters["to_assess"] += 1
            elif r.status == "ANESTHESIA_STARTED":
                counters["anesthetized"] += 1

            if r.has_alert:
                counters["abnormal"] += 1
                alerts.append({
                    "reception_id": r.id,
                    "or_code": r.or_code,
                    "seq_no": r.seq_no,
                    "patient_name": r.patient_name,
                    "alert_type": r.alert_type,
                    "alert_message": r.alert_message,
                    "surgeon_name": r.surgeon_name,
                    "anesthesia_doctor_name": r.anesthesia_doctor_name,
                    "handled": r.alert_handled,
                })

        return {
            "stat_date": target.isoformat(),
            "counters": counters,
            "alerts": [a for a in alerts if not a["handled"]],
            "pending": pending,
            "in_room": in_room,
            "refreshed_at": datetime.now().isoformat(),
        }

    @classmethod
    async def list_receptions(
        cls, db: AsyncSession, user, date_from: Optional[str], date_to: Optional[str],
        or_code: Optional[str], status: Optional[str], keyword: Optional[str],
        page: int, page_size: int,
    ) -> Dict[str, Any]:
        stmt = select(M09OrReception).where(M09OrReception.is_deleted.is_(False))
        if date_from:
            stmt = stmt.where(M09OrReception.reception_date >= date.fromisoformat(date_from))
        if date_to:
            stmt = stmt.where(M09OrReception.reception_date <= date.fromisoformat(date_to))
        if or_code:
            stmt = stmt.where(M09OrReception.or_code == or_code)
        if status:
            stmt = stmt.where(M09OrReception.status == status)
        if keyword:
            like = "%{}%".format(keyword)
            stmt = stmt.where(
                (M09OrReception.patient_name.like(like))
                | (M09OrReception.reception_no.like(like))
                | (M09OrReception.schedule_no.like(like))
            )

        total = (await db.execute(select(func.count()).select_from(stmt.subquery()))).scalar_one()
        rows = (await db.execute(
            stmt.order_by(M09OrReception.reception_date.desc(), M09OrReception.reception_no.desc())
            .limit(page_size).offset((page - 1) * page_size)
        )).scalars().all()

        return {
            "items": [cls._brief_dict(r) for r in rows],
            "total": total,
            "page": page,
            "page_size": page_size,
            "pages": (total + page_size - 1) // page_size,

    @classmethod
    async def checkin(cls, db: AsyncSession, user, body) -> Dict[str, Any]:
        # ① 幂等：已进间直接返回
        r = await cls._get_by_schedule(db, body.schedule_id)
        if r is None:
            raise BizException("0901033", "接收记录不存在，请先完成 Time-Out")
        if r.status != "PENDING":
            raise BizException("0901029", "当前状态不允许进间：{}".format(r.status))
        if r.schedule_cancelled:
            raise BizException("0901034", "台次已取消")

        # ② 解析腕带
        parts = (body.barcode or "").split("|")
        if len(parts) != 3:
            raise BizException("0901001", "腕带条码格式非法")
        barcode_patient_id, barcode_admission_no, barcode_hash = parts

        # ③ 身份指纹校验
        expected_hash = await cls._patient_identity_hash(db, r.patient_id)
        if barcode_hash != expected_hash:
            raise BizException("0901002", "腕带身份指纹与患者档案不符，请核实腕带")

        # ④ 手工输入需授权
        if body.manual_input and not user.has_permission("m09:reception:override"):
            raise BizException("0901006", "手工输入腕带需授权")

        # ⑤ 核对清单
        checks = [
            cls._check("PATIENT_ID", str(r.patient_id), barcode_patient_id),
            cls._check("PATIENT_NAME", r.patient_name, r.patient_name),
            cls._check("GENDER_AGE", "{}/{}".format("男" if r.gender == "M" else "女", r.age),
                       "{}/{}".format("男" if r.gender == "M" else "女", r.age)),
            cls._check("EYE_SIDE", r.eye_side, r.eye_side),
            cls._check("OR_ROOM", r.or_code, r.or_code),
            cls._check("SEQ_NO", str(r.seq_no), str(r.seq_no)),
            {"item": "OPERATION", "expected": r.operation_name, "actual": None, "result": "MANUAL"},
        ]
        mismatch = [c for c in checks if c["result"] == "MISMATCH"]
        if mismatch:
            raise BizException("0901004", "核对不一致：{}".format(
                "、".join(c["item"] for c in mismatch)))

        # ⑥ 术式/眼别需人工确认
        if not body.operation_confirmed:
            raise BizException("0901005", "请确认术式与眼别")

        # ⑦ 进间时刻偏差
        now = datetime.now()
        or_in_at = body.or_in_at or now
        if r.planned_surgery_start_at and abs((or_in_at - r.planned_surgery_start_at).total_seconds()) > 1800:
            if not body.override_reason or len(body.override_reason.strip()) < 10:
                raise BizException("0901007", "进间时刻与计划偏差超过 30 分钟，请填写原因（≥10 字）")

        # ⑧ 落库
        r.status = "IN_ROOM"
        r.or_in_at = or_in_at
        r.or_in_by = user.employee_id
        r.or_in_by_name = user.employee_name
        r.manual_barcode = body.manual_input
        r.override_reason = body.override_reason
        r.updated_at = now
        await db.commit()

        cls._log("checkin", r.id, user, {"or_in_at": or_in_at.isoformat()})
        return {
            "reception_id": r.id,
            "reception_no": r.reception_no,
            "status": r.status,
            "or_in_at": or_in_at.isoformat(),
            "check_items": checks,
            "timeout_completed": True,
            "timeout_at": r.timeout_completed_at.isoformat() if r.timeout_completed_at else None,
        }

            await db.commit()

                    "reception_no": existing.reception_no,
                    "status": existing.status,

            "reception_no": rec.reception_no,
            "status": rec.status,
            "is_duplicate": False,
            "created_at": rec.created_at.isoformat(),

            raise BizException("0901035", "评估已提交，不可重复提交")

        # ① A 组必填
        missing = [k for k in cls.REQUIRED_VITALS if getattr(a, k, None) is None]
        if missing:
            raise BizException("0901008", "基本测量缺少：{}".format("、".join(missing)))

        # ② 全麻/镇静时 B 组必填
        need_ga = body.need_general_anesthesia
        if need_ga:
            miss_air = [k for k in cls.REQUIRED_AIRWAY_WHEN_GA if getattr(a, k, None) is None]
            if miss_air:
                raise BizException("0901008", "气道评估缺少：{}".format("、".join(miss_air)))

        # ③ 局麻药过敏
        if a.local_anesthetic_allergy:
            pass  # 方案校验时再拦截

        # ④ 抗凝药停用天数
        if a.anticoagulant and a.anticoagulant_stop_days is None:
            raise BizException("0901010", "已选抗凝药，请填写停用天数")

        # ⑤ 禁食校验
        fasting_ok, fasting_hours = cls._check_fasting(a, need_ga)
        a.fasting_hours_calc = fasting_hours
        a.fasting_ok = fasting_ok
        if not fasting_ok:
            raise BizException("0901011", "禁食时长不足：需 {:.1f} 小时，实际 {:.1f} 小时".format(
                cls._required_fasting(a, need_ga), fasting_hours))

        # ⑥ 青光眼 + 抗胆碱药（在方案阶段校验，这里只记标记）
        # ⑦ ASA 比对
        alerts: List[Dict[str, Any]] = []
        if a.asa_level in ("IV", "V", "VI"):
            raise BizException("0901013", "ASA {} 级不适合日间手术，请转住院".format(a.asa_level))

        asa_diff = a.asa_level != a.asa_from_eligibility
        if asa_diff:
            if not a.asa_diff_reason or len(a.asa_diff_reason.strip()) < 10:
                raise BizException("0901012", "ASA 分级与准入不一致，请填写差异原因（≥10 字）")
            alerts.append({
                "level": "WARN",
                "code": "ASA_ESCALATED",
                "message": "ASA 由 {} 变为 {}".format(a.asa_from_eligibility, a.asa_level),
            })

        need_chief = (a.asa_level == "III" and a.asa_from_eligibility in ("I", "II")) or a.recent_uri and need_ga
        a.need_chief_confirm = need_chief
        if need_chief:
            alerts.append({
                "level": "WARN",
                "code": "NEED_CHIEF_CONFIRM",
                "message": "需麻醉科主任确认后方可继续",
            })

        a.status = "SUBMITTED"
        a.assessed_at = datetime.now()
        await db.commit()

        # 更新接收记录状态
        r = await ReceptionService._get(db, a.reception_id)
        if r.status == "MONITORING" and not need_chief:
            r.status = "ASSESSED"
            await db.commit()

        return {
            **cls._dict(a),
            "asa_diff_detected": asa_diff,
            "alerts": alerts,
        }

    @classmethod
    def _required_fasting(cls, a, need_ga: bool) -> float:
        if not need_ga:
            return 0.0
        meal = (a.meal_content or "SOLID").upper()
        return float(FASTING_RULES.get("GENERAL", {}).get(meal, 8))

    @classmethod
    def _check_fasting(cls, a, need_ga: bool) -> tuple:
        if not a.last_meal_at:
            return False, 0.0
        hours = (datetime.now() - a.last_meal_at).total_seconds() / 3600.0
        required = cls._required_fasting(a, need_ga)
        return hours >= required, round(hours, 2)

    @classmethod
    async def confirm(cls, db: AsyncSession, user, plan_id: int) -> Dict[str, Any]:
        p = await cls._get(db, plan_id)
        if p.status != "DRAFT":
            raise BizException("0901029", "方案已确认")

        drugs = (await db.execute(
            select(M09AnesthesiaPlanDrug).where(M09AnesthesiaPlanDrug.plan_id == p.id)
        )).scalars().all()
        if not drugs:
            raise BizException("0901018", "麻醉方案至少需要一种药品")

        a = (await db.execute(
            select(M09PreAnesthesiaAssessment)
            .where(M09PreAnesthesiaAssessment.reception_id == p.reception_id,
                   M09PreAnesthesiaAssessment.status == "SUBMITTED")
            .limit(1)
        )).scalar_one_or_none()

        # 局麻药过敏
        if a is not None and a.local_anesthetic_allergy:
            codes = {d.drug_code.upper() for d in drugs}
            if codes & LOCAL_ANESTHETIC_DRUGS:
                raise BizException("0901009", "患者局麻药过敏，方案不得含局麻药")

        # 青光眼 + 抗胆碱药
        if a is not None and a.glaucoma:
            codes = {d.drug_code.upper() for d in drugs}
            if codes & ANTICHOLINERGIC_DRUGS:
                raise BizException("0901015", "青光眼患者禁用抗胆碱药（阿托品/东莨菪碱）")

        # 麻醉医生
        r = await ReceptionService._get(db, p.reception_id)
        if p.need_anesthetist and not r.anesthesia_doctor_id:
            raise BizException("0901021", "该麻醉方式必须有麻醉医生")

        p.status = "CONFIRMED"
        p.confirmed_at = datetime.now()
        p.confirmed_by = user.employee_id
        await db.commit()

        # 麻醉方式变更 → 原同意书失效
        await ConsentService.supersede(db, p.reception_id, user)

        # 更新接收状态为 READY（若同意书已签）
        consent = (await db.execute(
            select(M09AnesthesiaConsent)
            .where(M09AnesthesiaConsent.reception_id == p.reception_id,
                   M09AnesthesiaConsent.status == "SIGNED")
            .limit(1)
        )).scalar_one_or_none()
        if consent is not None and r.status == "ASSESSED":
            r.status = "READY"
            await db.commit()

        return cls._dict(p)

class ConsentService:
    """麻醉知情同意服务。"""

    NOTICE_ITEMS = ["C-01", "C-02", "C-03", "C-04", "C-05", "C-06", "C-07", "C-08"]

        return cls._dict(c) if c else None

            schedule_id=r.schedule_id,
            patient_id=r.patient_id,
            anesthesia_name=body.anesthesia_name,

            notice_confirmed=json.dumps([], ensure_ascii=False),
            status="DRAFT",
            created_by=user.employee_id,
            created_at=datetime.now(),
        )
        db.add(c)
        await db.commit()
        await db.refresh(c)

    @classmethod
    async def sign(cls, db: AsyncSession, user, consent_id: int, body) -> Dict[str, Any]:
        c = (await db.execute(
            select(M09AnesthesiaConsent).where(
                M09AnesthesiaConsent.id == consent_id,
                M09AnesthesiaConsent.is_deleted.is_(False),
            ).with_for_update()
        )).scalar_one_or_none()
        if c is None:
            raise BizException("0901033", "同意书不存在")
        if c.status != "DRAFT":
            raise BizException("0901029", "同意书状态不允许签署：{}".format(c.status))

        confirmed = set(body.notice_confirmed or [])
        missing = [x for x in cls.NOTICE_ITEMS if x not in confirmed]
        if missing:
            raise BizException("0901024", "告知要点未全部确认：{}".format("、".join(missing)))

        if body.sign_type == "PATIENT":
            if not body.signature_image:
                raise BizException("0901025", "签名图片缺失")
            if body.relation and body.relation != "本人":
                raise BizException("0901026", "患者本人签字关系必须为「本人」")
        elif body.sign_type == "SURROGATE":
            if not (body.surrogate_name and body.relation and body.surrogate_id_tail):
                raise BizException("0901026", "代理人签字须填写姓名、关系、证件号后 4 位")
            if body.relation == "本人":
                raise BizException("0901026", "代理人关系不能是「本人」")
        elif body.sign_type == "ORAL":
            if not body.witness_name:
                raise BizException("0901027", "口头同意必须有见证人")
        else:
            raise BizException("0901026", "签字主体类型非法")

        c.notice_confirmed = json.dumps(sorted(confirmed), ensure_ascii=False)
        c.sign_type = body.sign_type
        c.signer_name = body.signer_name
        c.relation = body.relation
        c.surrogate_name = body.surrogate_name
        c.surrogate_id_tail = body.surrogate_id_tail
        c.signature_image_url = body.signature_image
        c.signature_hash = body.signature_hash
        c.witness_name = body.witness_name
        c.signed_at = datetime.now()
        c.signed_ip = body.client_ip
        c.status = "SIGNED"
        await db.commit()

        # 若方案已确认，接收记录置 READY
        r = await ReceptionService._get(db, c.reception_id)
        if r.status == "ASSESSED":
            plan = (await db.execute(
                select(M09AnesthesiaPlan)
                .where(M09AnesthesiaPlan.reception_id == c.reception_id,
                       M09AnesthesiaPlan.status == "CONFIRMED")
                .limit(1)
            )).scalar_one_or_none()
            if plan is not None:
                r.status = "READY"
                await db.commit()

        return cls._dict(c)

    @classmethod
    async def supersede(cls, db: AsyncSession, reception_id: int, user) -> int:
        result = await db.execute(
            text(
                "UPDATE m09_anesthesia_consent SET status = 'SUPERSEDED', "
                "superseded_at = :now, superseded_by = :uid "

from __future__ import annotations

@shared_task(bind=True, max_retries=5, default_retry_delay=10)
def retry_writeback_task(self, reception_id: int, action: str):
    """回写 M06 失败重试。退避：10/30/60/120/300 秒。"""
    from app.db import AsyncSessionLocal
    from app.models.m09_01 import M09OrReception
    from app.clients.m06 import M06Client
    from sqlalchemy import select

    retry_idx = self.request.retries
    delay = [10, 30, 60, 120, 300][min(retry_idx, 4)]

    async def _run():
        async with AsyncSessionLocal() as db:
            r = (await db.execute(
                select(M09OrReception).where(M09OrReception.id == reception_id)
            )).scalar_one_or_none()
            if r is None:
                return "not_found"
            if r.writeback_status == "SUCCESS":
                return "already_ok"
            try:
                if action == "ANESTHESIA_START":
                    await M06Client.on_anesthesia_start(r.schedule_id, r.anesthesia_start_at)
                r.writeback_status = "SUCCESS"
                r.writeback_retry = 0
                await db.commit()
                return "ok"
            except Exception as exc:  # noqa: BLE001
                r.writeback_retry = (r.writeback_retry or 0) + 1
                await db.commit()
                raise exc

    try:
        return asyncio.run(_run())
    except Exception as exc:  # noqa: BLE001
        logger.warning("writeback retry %s failed: %s", retry_idx + 1, exc)
        if retry_idx >= 4:
            # 5 次失败：标记 FAILED 并告警
            asyncio.run(_mark_failed(reception_id))
            return "gave_up"
        raise self.retry(exc=exc, countdown=delay)

| 患者姓名 | 大屏、列表 | `张*` |
| 体重/身高 | 非麻醉医生查看 | 显示 `--` |
| 过敏史 | 非麻醉/主刀查看 | 仅显示"有/无" |
| 既往病史 | 非麻醉/主刀查看 | 隐藏 |
| 电子签名 | 列表 | 不显示 |

### 9.5 安全措施

1. **所有写操作审计**：`m09_reception_log` 记录 16 类动作。
2. **麻醉记录不可篡改**：`anesthesia_start_at` 一旦写入，只允许通过"补录"接口修改（需主任权限 + 原因 ≥20 字）。
3. **ASA 变更留痕**：每次评定都新建版本，不覆盖。
4. **同意书哈希校验**：`signature_hash` 用于验证签名图片未被替换。
5. **回写状态可见**：工作台显示 `writeback_status != SUCCESS` 的记录，避免"以为回写了实际没回写"。

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 示例 | 处理策略 |
|---|---|---|
| **参数校验异常** | 腕带格式非法、必填项缺失 | 返回 7 位错误码，不落库 |
| **业务规则异常** | ASA IV、禁食不足、局麻药过敏 | 返回错误码 + 明确提示 |
| **权限异常** | 手工输入腕带无权限 | 返回 `"0901006"` |
| **并发冲突** | 两人同时操作同一接收记录 | 乐观锁 + 重试提示 |
| **外部依赖超时** | M06-03 台次查询超时 | 阻断 + 提示"台次服务不可用" |
| **外部依赖失败（可降级）** | 术前报告加载失败 | 标"未加载"，不阻断 |
| **回写失败** | M06-04 回写异常 | 进补偿队列，5 次后告警 |
| **系统异常** | 数据库连接失败 | 返回 `"50000"` + trace_id |
