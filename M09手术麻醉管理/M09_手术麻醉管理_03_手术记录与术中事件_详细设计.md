## 1. 模块概述

### 1.1 模块定位

M09-03 回答一个问题：**「这台手术具体做了什么？」**

它不仅是一段文字描述，而是由**结构化要素**构成的法定医疗文书：
- 手术名称与 ICD-9-CM-3 编码
- 手术者、助手、器械护士、巡回护士
- 手术起止时刻（切皮到缝合）
- 麻醉方式
- 术中探查所见
- 手术步骤（关键操作序列）
- 出血量与输血输液
- 术中出现的问题与处理（术中事件）
- 手术标本（送检物）

### 1.2 为什么独立成子模块

**理由一：手术记录是独立法定文书，不是麻醉记录的附属。**

《病历书写基本规范》第十九条明确：**「手术记录应当在术后 24 小时内完成」**；第十八条：**「麻醉记录单应另立（麻醉记录单）单页」**。两者是并列的两份文书，各有独立的书写人、书写时限、内容要求。

若合并成一张表：
- 手术记录（主刀写）与麻醉记录（麻醉医生写）的权限无法分离——主刀能改麻醉记录，麻醉医生能改手术记录，这在法规上是致命缺陷
- 手术记录 24 小时时限与麻醉记录（术毕即时完成）的提醒逻辑冲突
- 归档时无法分别校验两份文书的完整性

**理由二：眼科手术记录的内容结构极度特殊。**

| 术式类别 | 手术记录核心要素 |
|---|---|
| 白内障超乳 | 切口位置与大小 / 连续环形撕囊直径 / 水分离水化 / 超声能量与时间 / 人工晶体位置与型号 / 粘弹剂清除 / 切口水密 |
| 玻璃体切除 | 三通道位置 / 玻璃体切除范围 / 视网膜复位方式 / 激光点数 / 硅油或气体填充 / 眼压恢复 |
| 青光眼 | 抗青光眼手术类型 / 巩膜瓣大小厚度 / 虹膜周切位置 / 引流阀或引流钉植入 / 前房形成 |
| 眼底注药 | 注射部位距角膜缘距离 / 针头规格 / 药液容积 / 是否前房穿刺减压 |
| 斜视 | 各直肌后徙或缩短量（毫米）/ 牵拉试验结果 / 术中眼位 |
| 角膜移植 | 植片直径 / 缝线类型与针数 / 前房重建方式 |

每类术式的必填要素完全不同。**用 M01-07 的「手术记录模板」动态渲染表单**，模板内容在 M01-07 维护（`md_operation.record_template_id`），M09-03 只负责按模板收集数据。

**理由三：术中事件的处置与追溯是独立的质量数据源。**

眼科术中事件发生率：
- **眼心反射**（球后阻滞时压迫眼球）约 1.5%
- **球后出血** 约 0.1~0.5%
- **眼球穿孔**（球后注射误穿）约 0.05%
- **后囊膜破裂**（白内障超乳）约 1~2%
- **玻璃体脱出** 约 0.5%
- **脉络膜上腔出血**（暴发性）约 0.01%

这些事件必须能结构化统计、能按术式/医生/年份纵向对比。若手术记录只是一段自由文本，这些数据只能用 NLP 提取，准确率无法保证。

**理由四：手术记录是 24 小时时限的强制文书，需要独立的提醒与督查机制。**

《病历书写基本规范》第十九条：术后 24 小时内完成。超时未写是典型的病案质量扣分项，也是等级评审的必查点。M09-03 需要独立的超时扫描、催办、升级机制（12 小时提醒、24 小时升级科主任、48 小时上报医务科）。

### 1.4 概念辨析

| 概念 | 定义 | 归属 |
|---|---|---|
| **手术记录** | 主刀书写的完整手术过程文书，含探查所见、步骤、出血、标本，术后 24h 内完成 | M09-03 |
| **手术日志** | 术中实时记的要点（时间戳 + 简短描述），是手术记录的素材 | M09-03（`m09_surgery_note`） |
| **手术步骤** | 结构化的关键操作序列（如「角膜切口」「连续环形撕囊」），带起止时刻 | M09-03（`m09_surgery_step`） |
| **术中事件** | 术中发生的异常情况（如「眼心反射」「后囊膜破裂」），带严重度与处置 | M09-03 |
| **麻醉记录** | 麻醉医生书写的麻醉过程文书 | M09-02 |
| **护理记录（术中）** | 巡回护士书写的体位、器械、纱条、标本交接记录 | M09-04 / M08 |

**辨析要点：手术日志 ≠ 手术记录。** 手术日志是术中在手术间里用平板随手记的（一分钟一条），手术记录是术后 24 小时内书写的完整文书。前者是素材，后者是成品。混为一谈会导致「术中被催着写完整文书」或「事后回忆漏记关键细节」。

## 2. 业务范围与边界

### 2.1 范围内

1. **手术记录主表管理**：创建（手术开始时自动建草稿）、保存、提交、签名
2. **手术日志**：术中实时记录（时间戳 + 简要描述），支持语音转文字
3. **手术步骤**：结构化步骤序列（术式模板预置 + 术中增删）
4. **术中探查所见**：结构化字段 + 自由文本
5. **术中事件**：11 类事件的记录、严重度评级、处置措施、转归
6. **出血与输血输液**：出血量、输液种类与量、输血（红细胞/血浆/血小板）
7. **手术标本**：标本类型、部位、数量、去向（病理/微生物/其他）、送检申请生成
8. **手术记录模板**：按术式渲染、模板校验
9. **24 小时时限督查**：12 小时提醒、24 小时升级、48 小时上报
10. **记录版本与审计**：签名后的修改走「补充记录」而非覆盖
11. **统计**：按术式/医生/事件的统计

### 2.4 依赖清单与失败影响

| 编号 | 依赖 | 接口 | 失败影响 | 降级策略 |
|---|---|---|---|---|
| U-01 | M06-03 台次 | `GET /internal/v1/m06/schedule/{id}` | 拿不到计划起止 | **阻断**（无台次无手术记录） |
| U-02 | M06-04 核对 | `GET /internal/v1/m06/verify/timeout-status/{schedule_id}` | 无法确认 Time-Out | 告警 + 允许记录，标注「Time-Out 未确认」 |
| U-03 | M01-07 模板 | `GET /internal/v1/surgery/operations/{code}/record-template` | 无模板无法渲染 | **降级为通用模板**（自由文本 + 核心要素） |
| U-04 | M09-01 接收 | `GET /internal/v1/m09/reception/by-schedule/{id}` | 拿不到术前信息 | 用 M06 快照，标注「术前信息缺失」 |
| U-05 | M09-02 麻醉 | `GET /internal/v1/m09/anesthesia/by-schedule/{id}` | 拿不到麻醉方式 | 从 M09-01 方案取，标注「以方案为准」 |
| U-06 | M09-04 器械 | `GET /internal/v1/m09/instrument/{schedule_id}` | 拿不到清点结论 | 记录中标 UNKNOWN，护士手工确认 |
| U-07 | M09-05 植入物 | `GET /internal/v1/m09/implant/{schedule_id}` | 拿不到植入物 | 记录中标 UNKNOWN，主刀手工填写 |
| U-08 | M01-02 职工 | `GET /internal/v1/mdm/employees/{id}` | 拿不到签名人资质 | 用本地快照 |
| U-09 | M13-01 检验 | `POST /internal/v1/m13/lab/requests` | 标本申请未送达 | **补偿队列重试**（5 次） |
| U-10 | M12-04 检查 | `POST /internal/v1/m12/exam/request` | 冰冻切片申请未送达 | **阻断**（冰冻切片是术中决策依据） |
| U-11 | M02-06 审计 | `POST /internal/v1/audit/record` | 审计丢失 | 异步补偿 |
| U-12 | M03-05 消息 | `POST /internal/v1/message/send` | 催办消息未送达 | 异步重试 |

**铁律：**
- U-01（台次）与 U-10（冰冻切片）失败必须阻断
- U-03（模板）失败降级为通用模板——**不接受因为模板服务挂了就无法记录手术过程**
- U-06/U-07 失败标 UNKNOWN 而非「无」——「不知道有没有植入物」与「确定没有植入物」是两回事

## 3. 业务模型

### 3.1 手术记录主模型

**一句话：一台次一条手术记录，主刀签名后成为法定文书。**

```
┌──────────────────────────────────────────────────────────────────────┐
│  m09_surgery_record（手术记录）                                       │
│  ─────────────────────────────────────────────────────────────────  │
│  基础信息    patient / operation / eye_side / schedule                 │
│  人员        surgeon / assistants / scrub_nurse / circulating_nurse    │
│  时刻        切皮 incise_at / 缝合 suture_at / 时长 duration           │
│  术式要素    record_fields JSONB（按 M01-07 模板）                      │
│  探查所见    exploration JSONB（结构化）+ exploration_text             │
│  出血输血    blood_loss_ml / infusion_* / transfusion_*                │
│  器械与植入  instrument_count_ok / implant_summary                     │
│  标本        （1:N）m09_surgery_specimen                               │
│  结论        operation_summary / prognosis / followup_plan             │

         ▼                        ▼                    ▼
```

### 3.2 手术记录状态机

```
      手术开始（M09-02 麻醉开始 或 切皮）
                │ auto_create
                ▼
   ┌─────────────────────────┐
   │        DRAFT            │  可编辑：日志 / 步骤 / 事件 / 要素
   └───────────┬─────────────┘
               │ submit
               ▼
   ┌─────────────────────────┐
   │      SUBMITTED          │  待签名：主刀核对
   └───────────┬─────────────┘
               │ sign
               ▼
   ┌─────────────────────────┐
   │       SIGNED            │  只读，可补充记录
   └───────────┬─────────────┘
               │ supplement
               ▼
   ┌─────────────────────────┐
   │    SUPPLEMENTED         │  补充记录后仍为已签名态
   └─────────────────────────┘

   旁支：CANCELLED（手术取消）
```

**关键设计：`SIGNED` 后不可编辑，只能「补充记录」（append-only）。**

理由：手术记录是法律证据。签名后若允许直接编辑，等同于证据可篡改。补充记录保留原记录全文 + 补充内容 + 补充原因 + 补充时刻。

### 3.3 手术日志模型

**一句话：术中的时间轴流水账，是手术记录的原料。**

| 字段 | 说明 |
|---|---|
| `noted_at` | 记录时刻（自动带当前时间，可微调） |
| `category` | 类别 STEP / FINDING / EVENT / DEVICE / OTHER |
| `content` | 内容（20~500 字） |
| `is_voice_input` | 是否语音输入（转文字） |
| `voice_raw` | 语音原文（供核对） |
| `linked_step_id` | 关联步骤（可选） |

**为什么要手术日志而不直接写手术记录：**

术中主刀戴着手套、眼睛看着显微镜，不可能写完整文书。正确的时机是「术中有空档时用语音或平板快速记要点」，术后再整理成记录。

真实数据：白内障超乳手术 12 分钟，术中主刀最多能记 3~5 条日志（进刀、撕囊完成、晶体植入、水密）。这 4 条日志就是手术记录「手术步骤」一节的骨架。

**手术日志不是必须的**——它是效率工具，不强制。但有日志的手术，手术记录撰写时间平均缩短 60%。

### 3.4 手术步骤模型

**一句话：结构化的关键操作序列，带起止时刻与要点。**

```
step_no | step_code        | step_name      | start_at | end_at | key_points        | is_key
--------|------------------|----------------|----------|--------|-------------------|--------
1       | INCISION         | 角膜主切口      | 09:12    | 09:13  | 3.0mm 透明角膜   | TRUE
2       | CCC              | 连续环形撕囊    | 09:13    | 09:15  | 直径 5.5mm       | TRUE
3       | HYDRO            | 水分离水化      | 09:15    | 09:16  | 充分              | FALSE
4       | PHACO            | 超声乳化       | 09:16    | 09:20  | 能量 35% 时间 48s | TRUE
5       | IOL_IMPLANT      | 人工晶体植入    | 09:20    | 09:22  | 蔡司 509M +22.5D | TRUE
6       | OVD_REMOVAL      | 粘弹剂清除      | 09:22    | 09:23  | 彻底              | TRUE
7       | WOUND_SEAL       | 切口水密        | 09:23    | 09:24  | 无渗漏            | TRUE
```

**步骤来源：**
1. M01-07 `md_operation.standard_steps` 预置标准步骤（JSONB 数组）
2. 术中主刀增删（如临时加「虹膜周切」）
3. 每步可挂日志（`m09_surgery_note.linked_step_id`）

**为什么结构化：**

- 统计「不同医生做同一术式的平均步骤耗时」→ 定位效率瓶颈
- 统计「哪一步最容易出问题」→ 例如 90% 的后囊膜破裂发生在 PHACO 步骤
- 手术记录的「手术步骤」一节直接从步骤表渲染，不用医生重复抄写

**步骤顺序与时刻的约束：** 步骤必须按 `step_no` 递增，且 `start_at` 不早于前一步 `end_at`。但允许「并行步骤」（如左右手同时操作）——用 `is_parallel=TRUE` 标记，此时不校验时序。

### 3.5 术中事件模型

**一句话：术中发生的异常情况，11 类，带严重度与处置。**

| 类别 | 事件类型 | 发生率 | 严重度 |
|---|---|---|---|
| **麻醉相关** | `OCULOCARDIAC_REFLEX` 眼心反射 | 1.5% | MEDIUM~HIGH |
| | `RETROBULBAR_HEMORRHAGE` 球后出血 | 0.1~0.5% | HIGH~CRITICAL |
| | `NAUSEA_VOMITING` 恶心呕吐 | 2% | LOW~MEDIUM |
| **手术相关** | `GLOBE_PERFORATION` 眼球穿孔 | 0.05% | CRITICAL |
| | `POSTERIOR_CAPSULE_RUPTURE` 后囊膜破裂 | 1~2% | MEDIUM~HIGH |
| | `VITREOUS_LOSS` 玻璃体脱出 | 0.5% | HIGH |
| | `SUPRACHOROIDAL_HEMORRHAGE` 脉络膜上腔出血 | 0.01% | CRITICAL |
| | `IRIS_PROLPASE` 虹膜脱出 | 1% | LOW~MEDIUM |
| | `WOUND_LEAK` 切口渗漏 | 0.5% | LOW~MEDIUM |
| | `IOL_COMPLICATION` 人工晶体相关并发症 | 1% | MEDIUM~HIGH |
| **其他** | `OTHER` 其他 | — | 任意 |

**严重度四级：**

| 严重度 | 定义 | 处置要求 |
|---|---|---|
| `LOW` | 不影响手术进程 | 记录即可 |
| `MEDIUM` | 需处理但不改变手术方案 | 记录 + 处置措施 |
| `HIGH` | 需调整手术方案 | 记录 + 处置 + 通知主刀 + 科主任知悉 |
| `CRITICAL` | 危及视力或生命 | 记录 + **立即通知医务科** + 术后 24h 内上报 |

**事件的「发生时刻」与「转归时刻」：**

```
occurred_at                  recovery_at
     │                            │
     ▼                            ▼
     ●──────── 持续 3 分钟 ────────●
     │                            │
  眼心反射                       心率恢复 68
  心率 42                        处置有效
```

`recovery_minutes` 由 `recovery_at - occurred_at` 计算，用于统计「处理响应速度」。

### 3.6 出血与输血输液模型

| 字段 | 说明 |
|---|---|
| `blood_loss_ml` | 出血量（毫升，整数） |
| `blood_loss_level` | 分级 NONE / MINIMAL(<5) / MILD(5~20) / MODERATE(20~50) / SEVERE(>50) |
| `infusion_items` | 输液清单 JSONB `[{fluid:"生理盐水", volume_ml:250, route:"IV"}]` |
| `transfusion_items` | 输血清单 JSONB `[{product:"PRBC", units:1, bag_no:"..."}]` |
| `transfusion_done` | 是否输血 |
| `transfusion_reaction` | 输血反应（有则必填，≥10 字） |

**眼科输血极为罕见**（年约 3~5 例），但一旦发生必须有完整记录与输血反应监测。`transfusion_done=FALSE` 时所有输血字段必须为空（`ck_m09_surg_transfusion`）。

### 3.7 手术标本模型

**一句话：术中取出的组织/液体的去向必须可追溯。**

| 字段 | 说明 |
|---|---|
| `specimen_no` | 标本编号 `SP` + YYYYMMDD + 3 位（当日序号） |
| `specimen_type` | 类型 TISSUE(组织) / FLUID(液体) / CULTURE(培养) / FOREIGN(异物) / OTHER |
| `specimen_site` | 部位（如「左眼玻璃体液」「右眼晶状体核」） |
| `specimen_desc` | 描述（≥5 字） |
| `quantity` | 数量 |
| `destination` | 去向 PATHOLOGY(病理) / MICROBIOLOGY(微生物) / CYTOPATHOLOGY(细胞学) / DISCARD(无需送检) / OTHER |
| `lab_request_no` | M13 检验申请号（destination=MICROBIOLOGY 时生成） |
| `exam_request_no` | M12 检查申请号（冰冻切片时生成） |
| `handover_to` | 交给人（护士/护工） |
| `handover_at` | 交接时刻 |

**关键规则：**

1. **`destination=DISCARD` 必须填原因 ≥10 字。** 术中取出的组织不送检是可疑行为（可能是漏送），必须有正当理由（如「异物取出后患者要求自行保存」）。
2. **`destination=MICROBIOLOGY` 时自动生成 M13 检验申请。** 眼科最典型场景：眼内炎玻璃体液送培养。
3. **冰冻切片必须走 M12 加急申请**，`destination=CYTOPATHOLOGY` 且 `is_frozen_section=TRUE` 时调用 M12-04（失败阻断）。

### 3.9 24 小时时限督查模型

```
  缝合（suture_at）
       │
       ▼
   ┌───────────────────────────────────────────────────┐
   │  T+0         手术记录 DRAFT 创建                    │
   │  T+12h       开始提醒（站内信 + 短信）              │
   │  T+18h       二级提醒（科室群 + 手机）              │
   │  T+24h       ⚠️ 超时！升级科主任 + 记录超时标记      │
   │  T+36h       升级医务科                            │
   │  T+48h       上报分管院长 + 纳入月度质控报告        │
   └───────────────────────────────────────────────────┘
```

**超时判定：`signed_at IS NULL AND NOW() > suture_at + 24h`。**

注意：**时限从缝合时刻算起，不是从手术记录创建时刻**。原因是法规原文「术后 24 小时内完成」，术后 = 缝合结束。

### 3.10 交叉校验模型

手术记录不是孤立数据，必须与其他子模块交叉校验：

| 校验项 | 手术记录 | 交叉对象 | 不一致处理 |
|---|---|---|---|
| **时序** | `incise_at` / `suture_at` | M09-02 `anesthesia_start_at` / `anesthesia_end_at` | 切皮早于麻醉开始 → 警告「手术先于麻醉开始」（可能严重问题）；缝合晚于麻醉结束 → 警告「麻醉先结束」 |
| **术式** | `operation_code` | M06-03 台次 `operation_code` | 不一致 → 阻断，要求改台次或说明 |
| **眼别** | `eye_side` | M06-04 核对结论的眼别 | 不一致 → **阻断**（术眼错误是最严重事件） |
| **人员** | `surgeon_id` | M06-03 台次 `surgeon_id` | 不一致（换主刀）→ 要求填换人原因 ≥10 字 |
| **器械** | `instrument_count_ok` | M09-04 清点结论 | 手术记录说相符但 M09-04 说不符 → 告警 |
| **植入物** | `implant_summary` | M09-05 扫码记录 | 记录写了晶体型号但 M09-05 无扫码 → 告警「植入物未扫码追溯」 |
| **出血** | `blood_loss_ml` | 护理记录（M08） | 差异 >20ml → 告警 |
| **标本** | 标本数 | M13 检验申请数 | 不一致 → 告警「有标本未送检」 |

**眼别校验为什么阻断：** 眼科最严重的可预防事件是「做错眼」。手术记录的 `eye_side` 与 Time-Out 核对结论不一致，说明环节中有一处出错，必须立即停止并复核——不允许通过「填个说明」绕过。

**为什么「无需送检」必须填原因？**

真实风险场景：术中取出的眼内组织（如晶体核、虹膜周切组织）本应送病理，但医生图省事不送。若系统允许「点一下就选无需送检」，这个动作无人监管。强制填 ≥10 字原因后，写「无送检价值」这种敷衍理由会在质控抽查中被发现，形成心理约束。

**为什么把「医生事件发生率」展示出来？**

这是质控中极敏感的信息。展示的目的不是排名羞辱，而是让每个医生知道自己的基线。目标：
- 医生能看到自己的数据与科室均值对比
- 科主任能看到谁明显高于均值（需要针对性复盘）
- 不对外公开（权限限制在科主任级别）

### 6.2 错误码规范

错误码格式 `"0903XXX"`（7 位字符串），本子模块 `"0903001"`~`"0903036"`。

| 错误码 | 说明 | 触发场景 |
|---|---|---|
| `"0903001"` | 台次不存在或状态不允许 | API-03 创建时台次不在 CHECKED_IN/IN_SURGERY |
| `"0903002"` | 手术记录不存在 | 各类 API 传错 record_id |
| `"0903003"` | 手术记录状态不允许此操作 | SIGNED 状态尝试编辑 |
| `"0903004"` | 无该手术记录的操作权限 | 非主刀/一助尝试编辑 |
| `"0903005"` | 缝合时刻必须晚于切皮时刻 | API-04 时刻校验 |
| `"0903006"` | 步骤时序不合法 | 后一步早于前一步结束 |
| `"0903007"` | 日志内容长度不合法 | <5 或 >500 字 |
| `"0903008"` | 手术记录已存在 | API-03 重复创建 |
| `"0903009"` | 术式与台次不一致 | `operation_code` ≠ 台次 |
| `"0903010"` | 眼别与核对结论不一致 | `eye_side` ≠ M06-04 结论 |
| `"0903011"` | 记录已签名不可编辑 | 只能走补充记录 |
| `"0903012"` | 模板必填项未完成 | 提交时必填缺失 |
| `"0903013"` | 步骤数不足模板要求 | 步骤数 < min_steps |

```python
class RecordService:
    """手术记录主逻辑。"""

    @classmethod
    async def create_record(
        cls, db: AsyncSession, user, body,
    ) -> Dict[str, Any]:
        """创建手术记录（幂等）。"""
        # ① 台次校验

        if not schedule:
            raise BizException("0903001", "台次不存在")
        if schedule["status"] not in ("CHECKED_IN", "IN_SURGERY", "COMPLETED"):
            raise BizException("0903001", "台次状态不允许创建手术记录")

        # ② 幂等检查：先查
        existing = await cls._find_by_schedule(db, body.schedule_id)
        if existing:
            return cls._dict(existing, is_duplicate=True)

        # ③ 拉取台次信息与模板
        template = await M01Client.get_record_template(
            schedule["operation_code"],
        )
        template_code = template["template_code"] if template else "GENERIC_V1"
        required_fields = template["required_fields"] if template else [
            "operation_summary",
        ]

        # ④ 生成记录编号
        record_no = await cls._next_record_no(
            db, schedule["or_code"], schedule["seq_no"],
        )

        # ⑤ 创建
        row = M09SurgeryRecord(
            record_no=record_no,
            record_date=datetime.now().date(),
            schedule_id=body.schedule_id,
            patient_id=schedule["patient_id"],
            patient_name=schedule["patient_name"],
            gender=schedule.get("gender"),
            age=schedule.get("age"),
            operation_code=schedule["operation_code"],
            operation_name=schedule["operation_name"],
            eye_side=schedule["eye_side"],
            or_code=schedule["or_code"],
            seq_no=schedule["seq_no"],
            surgery_level=schedule.get("surgery_level"),
            surgeon_id=schedule["surgeon_id"],
            surgeon_name=schedule["surgeon_name"],
            assistant_ids=schedule.get("assistant_ids"),
            scrub_nurse_name=schedule.get("scrub_nurse_name"),
            circulating_nurse_name=schedule.get("circulating_nurse_name"),
            anesthesia_type=schedule.get("anesthesia_type"),
            incise_at=body.incise_at or datetime.now(),
            status="DRAFT",
            template_code=template_code,
            record_fields={},
            created_by=user["employee_id"],
        )
        db.add(row)
        try:
            await db.flush()
        except IntegrityError:
            # ⑥ 并发兜底：唯一索引冲突则返回已有
            await db.rollback()
            existing = await cls._find_by_schedule(db, body.schedule_id)
            if existing:
                return cls._dict(existing, is_duplicate=True)
            raise BizException("0903008", "手术记录已存在")

        # ⑦ 日志
        await cls._log(db, row.id, "CREATE", user)

        return cls._dict(row, required_fields=required_fields)

    @classmethod
    async def update_record(
        cls, db: AsyncSession, user, record_id: int, body,
    ) -> Dict[str, Any]:
        """保存草稿。"""
        row = await cls._get_for_update(db, record_id)
        cls._check_editable(row)
        cls._check_operator(user, row)

        # ① 时刻校验
        if body.incise_at and body.suture_at:
            if body.suture_at <= body.incise_at:
                raise BizException("0903005", "缝合时刻必须晚于切皮时刻")
        # ② 术式与台次一致性
        if body.operation_code and body.operation_code != row.operation_code:
            raise BizException("0903009", "术式与台次不一致，请先修改台次")
        # ③ 眼别与核对一致性（阻断）
        if body.eye_side and body.eye_side != row.eye_side:
            verified_eye = await M06Client.get_timeout_eye_side(row.schedule_id)
            if verified_eye and verified_eye != body.eye_side:
                raise BizException(
                    "0903010",
                    "眼别与 Time-Out 核对结论不一致，请立即复核",
                )
            row.eye_side = body.eye_side

        # ④ 逐字段更新
        for field in (
            "incise_at", "suture_at", "operation_summary", "exploration",
            "exploration_text", "blood_loss_ml", "infusion_items",
            "transfusion_items", "transfusion_done", "transfusion_reaction",
            "instrument_count_ok", "implant_summary", "record_fields",
            "postop_medication", "followup_plan", "prognosis",
            "no_specimen", "no_specimen_reason",
        ):
            if hasattr(body, field) and getattr(body, field) is not None:
                setattr(row, field, getattr(body, field))

        # ⑤ 计算时长
        if row.incise_at and row.suture_at:
            row.duration_minutes = int(
                (row.suture_at - row.incise_at).total_seconds() / 60
            )

        # ⑥ 更新完成度
        row.completeness = await cls._calc_completeness(db, row)

        row.updated_at = datetime.now()
        row.updated_by = user["employee_id"]
        await db.flush()

        return cls._dict(row)

    @classmethod
    async def submit(cls, db: AsyncSession, user, record_id: int) -> Dict[str, Any]:
        """提交待签名。"""
        row = await cls._get_for_update(db, record_id)
        cls._check_transition(row, "SUBMITTED")
        cls._check_operator(user, row)

        # ① 模板必填项
        missing = cls._check_required(row)
        if missing:
            raise BizException(
                "0903012",
                "模板必填项未完成：" + "、".join(missing),
                data={"missing_fields": missing},
            )
        # ② 步骤数
        step_count = await cls._count_steps(db, record_id)
        min_steps = await cls._min_steps(row.template_code)
        if step_count < min_steps:
            raise BizException("0903013", "步骤数不足模板要求（最少 %d 步）" % min_steps)
        # ③ 小结字数
        if not row.operation_summary or len(row.operation_summary.strip()) < MIN_SUMMARY_LEN:
            raise BizException("0903014", "手术小结不少于 %d 字" % MIN_SUMMARY_LEN)
        # ④ 出血量
        if row.blood_loss_ml is None:
            raise BizException("0903015", "必须填写出血量（可为 0）")
        # ⑤ 标本确认
        specimen_count = await cls._count_specimens(db, record_id)
        if specimen_count == 0 and not row.no_specimen:
            raise BizException("0903016", "请登记标本或勾选「无标本」")

        row.status = "SUBMITTED"
        row.submitted_at = datetime.now()
        row.updated_at = datetime.now()
        row.updated_by = user["employee_id"]
        await db.flush()
        await cls._log(db, record_id, "SUBMIT", user)
        return cls._dict(row)

    @classmethod
    async def sign(
        cls, db: AsyncSession, user, record_id: int, body,
    ) -> Dict[str, Any]:
        """签名。"""
        row = await cls._get_for_update(db, record_id)
        cls._check_transition(row, "SIGNED")

        # ① 签名人资质
        if row.surgeon_id != user["employee_id"]:
            allowed = await cls._can_sign(row, user)
            if not allowed:
                raise BizException("0903017", "无签名权限（仅主刀或授权一助可签）")
        if not body.surgeon_confirm:
            raise BizException("0903018", "请确认手术记录内容真实完整")

        # ② 生成 PDF
        pdf_url, pdf_hash = await cls._generate_pdf(row)

        # ③ 签名
        row.status = "SIGNED"
        row.signed_by = user["employee_id"]
        row.signed_by_name = user["employee_name"]
        row.signed_at = datetime.now()
        row.signed_ip = user.get("client_ip")
        row.signature_image_url = body.signature_image_url
        row.signature_hash = body.signature_hash
        row.pdf_url = pdf_url
        row.pdf_hash = pdf_hash
        row.updated_at = datetime.now()
        await db.flush()

        await cls._log(db, record_id, "SIGN", user)

        # ④ 通知 M06-06 可归档
        writeback = await cls._notify_archive(row)

        return {
            "record_id": record_id,
            "record_no": row.record_no,
            "status": row.status,
            "signed_by": row.signed_by,
            "signed_by_name": row.signed_by_name,
            "signed_at": row.signed_at.isoformat(),
            "signature_hash": row.signature_hash,
            "pdf_url": row.pdf_url,
            "completeness": {
                "required_total": len(row.template_required or []),
                "required_filled": len(row.template_required or []),
                "is_complete": True,
            },
            "m06_writeback": writeback,
            "notify": {"archive_ready": True},
        }

    @classmethod
    def _check_editable(cls, row: M09SurgeryRecord) -> None:
        if row.status not in ("DRAFT", "SUBMITTED"):
            raise BizException("0903011", "记录已签名，只能走补充记录")

    @classmethod
    def _check_operator(cls, user, row: M09SurgeryRecord) -> None:
        emp_id = user["employee_id"]
        if emp_id == row.surgeon_id:
            return
        assistants = row.assistant_ids or []
        if emp_id in assistants:
            return
        if "m09:surgery:approve" in user.get("permissions", []):
            return
        raise BizException("0903004", "无该手术记录的操作权限")

    @classmethod
    def _check_transition(cls, row: M09SurgeryRecord, target: str) -> None:
        allowed = RECORD_TRANSITIONS.get(row.status, set())
        if target not in allowed:
            raise BizException(
                "0903003",
                "当前状态 %s 不允许转为 %s" % (row.status, target),
            )

    @classmethod
    def _check_required(cls, row: M09SurgeryRecord) -> List[str]:
        summary_map = {
            "operation_summary": bool(row.operation_summary),
            "blood_loss_ml": row.blood_loss_ml is not None,
            "exploration": bool(row.exploration),
        }
        required = list(row.template_required or ["operation_summary"])
        missing = []
        for field in required:
            if field in summary_map:
                if not summary_map[field]:
                    missing.append(field)
            else:
                value = (row.record_fields or {}).get(field)
                if value is None or (isinstance(value, str) and not value.strip()):
                    missing.append(field)
        return missing

    @classmethod
    async def _calc_completeness(cls, db: AsyncSession, row) -> Decimal:
        required = list(row.template_required or [])
        if not required:
            return Decimal("100.00")
        filled = len(required) - len(cls._check_required(row))
        if row.blood_loss_ml is not None and "blood_loss_ml" not in required:
            pass
        pct = Decimal(filled * 100) / Decimal(len(required))
        return pct.quantize(Decimal("0.01"))

class StepService:
    """手术步骤。"""

    MIN_STEP_DURATION_SECONDS = 1
    MAX_STEP_DURATION_SECONDS = 7200

    @classmethod
    async def list_steps(cls, db: AsyncSession, user, record_id: int):
        stmt = (
            select(M09SurgeryStep)
            .where(
                and_(
                    M09SurgeryStep.record_id == record_id,
                    M09SurgeryStep.is_deleted.is_(False),
                )
            )
            .order_by(M09SurgeryStep.step_no)
        )
        rows = (await db.execute(stmt)).scalars().all()
        return [cls._dict(r) for r in rows]

    @classmethod
    async def add_step(cls, db: AsyncSession, user, record_id: int, body):
        record = await RecordService._get_for_update(db, record_id)
        RecordService._check_editable(record)
        RecordService._check_operator(user, record)

        count = await RecordService._count_steps(db, record_id)
        if count >= MAX_STEPS:
            raise BizException("0903019", "步骤数超过上限 %d" % MAX_STEPS)

        if body.start_at and body.end_at:
            if body.end_at <= body.start_at:
                raise BizException("0903006", "步骤结束必须晚于开始")
            duration = (body.end_at - body.start_at).total_seconds()
            if duration < cls.MIN_STEP_DURATION_SECONDS:
                raise BizException("0903006", "步骤时长至少 1 秒")

        row = M09SurgeryStep(
            record_id=record_id,
            step_no=body.step_no or (count + 1),
            step_code=body.step_code,
            step_name=body.step_name,
            start_at=body.start_at,
            end_at=body.end_at,
            key_points=body.key_points,
            is_key=body.is_key,
            is_parallel=body.is_parallel,
            created_by=user["employee_id"],
        )
        db.add(row)
        await db.flush()
        await cls._check_time_seq(db, record_id, record)
        return cls._dict(row)

    @classmethod
    async def _check_time_seq(cls, db: AsyncSession, record_id: int, record):
        rows = await cls.list_steps(db, {}, record_id)
        non_parallel = [r for r in rows if not r["is_parallel"]]
        for i in range(1, len(non_parallel)):
            prev, cur = non_parallel[i - 1], non_parallel[i]
            if prev.get("end_at") and cur.get("start_at"):
                if cur["start_at"] < prev["end_at"]:
                    raise BizException(
                        "0903006",
                        "第 %d 步开始早于第 %d 步结束" % (cur["step_no"], prev["step_no"]),
                    )
        if non_parallel:
            first, last = non_parallel[0], non_parallel[-1]
            if first.get("start_at") and record.incise_at:
                if first["start_at"] < record.incise_at:
                    raise BizException("0903020", "第一步开始早于切皮时刻")
            if last.get("end_at") and record.suture_at:
                if last["end_at"] > record.suture_at:
                    raise BizException("0903021", "最后一步结束晚于缝合时刻")

    @classmethod
    async def load_template_steps(cls, db: AsyncSession, user, record_id: int, body):
        record = await RecordService._get_for_update(db, record_id)
        RecordService._check_editable(record)
        RecordService._check_operator(user, record)

        tpl_steps = await M01Client.get_standard_steps(record.operation_code)
        existing = await cls.list_steps(db, user, record_id)
        existing_codes = {r["step_code"] for r in existing}
        cursor = len(existing)
        created = []
        for idx, st in enumerate(tpl_steps, start=1):
            if st["step_code"] in existing_codes:
                continue
            cursor += 1
            row = M09SurgeryStep(
                record_id=record_id,
                step_no=cursor,
                step_code=st["step_code"],
                step_name=st["step_name"],
                key_points=st.get("key_points"),
                is_key=st.get("is_key", False),
                created_by=user["employee_id"],
            )
            db.add(row)
            created.append(row)
        await db.flush()
        return [cls._dict(r) for r in created]

    @classmethod
    def _dict(cls, row) -> Dict[str, Any]:
        return {
            "step_id": row.id,
            "record_id": row.record_id,
            "step_no": row.step_no,
            "step_code": row.step_code,
            "step_name": row.step_name,
            "start_at": row.start_at.isoformat() if row.start_at else None,
            "end_at": row.end_at.isoformat() if row.end_at else None,
            "duration_seconds": (
                int((row.end_at - row.start_at).total_seconds())
                if row.start_at and row.end_at else None
            ),
            "key_points": row.key_points,
            "is_key": row.is_key,
            "is_parallel": row.is_parallel,
        }


class NoteService:
    """手术日志。"""

    NOTE_CATEGORIES = {"STEP", "FINDING", "EVENT", "DEVICE", "OTHER"}

    @classmethod

class SupervisionService:
    """时限督查与统计。"""

    @classmethod
    async def get_supervision(cls, db: AsyncSession, user, date_str):
        day = date_str or datetime.now().strftime("%Y-%m-%d")
        # ① 超时清单
        sql = text(
            "SELECT r.id, r.record_no, r.patient_name, r.operation_name,"
            " r.surgeon_name, r.suture_at, r.status"
            " FROM m09_surgery_record r"
            " WHERE r.is_deleted = FALSE AND r.signed_at IS NULL"
            "   AND r.suture_at IS NOT NULL"
            "   AND r.suture_at < :now - INTERVAL '24 hours'"
            " ORDER BY r.suture_at"
        )
        now = datetime.now()
        rows = (await db.execute(sql, {"now": now})).mappings().all()
        overdue_items = []
        for r in rows:
            hours = (now - r["suture_at"]).total_seconds() / 3600
            overdue_items.append({
                "record_id": r["id"],
                "record_no": r["record_no"],
                "patient_name": r["patient_name"],
                "operation_name": r["operation_name"],
                "surgeon_name": r["surgeon_name"],
                "suture_at": r["suture_at"].isoformat(),
                "overdue_hours": round(hours, 1),
                "escalate_level": cls._escalate_level(hours),
            })
        # ② 即将超时
        warn_sql = text(
            "SELECT COUNT(*) FROM m09_surgery_record"
            " WHERE is_deleted = FALSE AND signed_at IS NULL"
            "   AND suture_at IS NOT NULL"
            "   AND suture_at >= :now - INTERVAL '24 hours'"
            "   AND suture_at < :now - INTERVAL '12 hours'"
        )
        about_overdue = (await db.execute(warn_sql, {"now": now})).scalar_one()
        # ③ 完成统计
        stat_sql = text(
            "SELECT COUNT(*) AS total,"
            " COUNT(*) FILTER (WHERE signed_at IS NOT NULL) AS signed"
            " FROM m09_surgery_record"
            " WHERE is_deleted = FALSE AND record_date = :d"
        )
        stat = (await db.execute(stat_sql, {"d": day})).mappings().one()
        total = stat["total"] or 0
        signed = stat["signed"] or 0
        return {
            "date": day,
            "overdue_count": len(overdue_items),
            "overdue_items": overdue_items,
            "about_to_overdue_count": int(about_overdue),
            "completed_count": int(signed),
            "total_count": int(total),
            "completion_rate_24h": round(signed / total, 4) if total else 0.0,
            "target_rate": 0.98,
            "top_issues": await cls._top_issues(db, day),
        }

    @classmethod
    def _escalate_level(cls, hours: float) -> str:
        if hours >= RECORD_REPORT_HOURS:
            return "VICE_PRESIDENT"
        if hours >= RECORD_ESCALATE_HOURS:
            return "MEDICAL_AFFAIRS"
        return "DEPARTMENT_CHIEF"

    @classmethod
    async def _top_issues(cls, db: AsyncSession, day: str) -> List[Dict[str, Any]]:
        sql = text(
            "SELECT '手术小结少于50字' AS issue, COUNT(*) AS cnt"
            " FROM m09_surgery_record"
            " WHERE is_deleted = FALSE AND record_date = :d"
            "   AND (operation_summary IS NULL"
            "        OR char_length(btrim(operation_summary)) < 50)"
            " UNION ALL"
            " SELECT '未填晶体核硬度', COUNT(*)"
            " FROM m09_surgery_record"
            " WHERE is_deleted = FALSE AND record_date = :d"
            "   AND operation_code LIKE 'OP_CATARACT%'"
            "   AND (record_fields->>'nuclear_hardness') IS NULL"
            " UNION ALL"
            " SELECT '出血量留空', COUNT(*)"
            " FROM m09_surgery_record"
            " WHERE is_deleted = FALSE AND record_date = :d"
            "   AND blood_loss_ml IS NULL"
            " ORDER BY cnt DESC LIMIT 5"
        )
        rows = (await db.execute(sql, {"d": day})).mappings().all()
        return [
            {"issue": r["issue"], "count": int(r["cnt"])}
            for r in rows if r["cnt"] > 0
        ]

    @classmethod
    async def urge(cls, db: AsyncSession, user, body) -> Dict[str, Any]:
        sent = 0
        failed = 0
        for record_id in body.record_ids:
            try:
                await _send_message(
                    to=None, title="手术记录待签名提醒",
                    body="手术记录 %d 已超时，请尽快完成签名" % record_id,
                )
                sent += 1
            except Exception as exc:
                logger.error("催办失败 %d：%s", record_id, exc)
                failed += 1
        return {"sent": sent, "failed": failed, "total": len(body.record_ids)}
```

### 6.7 专题：24 小时时限督查与提醒机制

**目的：** 保证手术记录在法定 24 小时内完成，且提醒分级合理、不打扰。

**提醒时序：**

| 时点 | 触发 | 对象 | 渠道 | 说明 |
|---|---|---|---|---|
| T+12h | `job_m09_surgery_overdue_scan` | 主刀 + 一助 | 站内信 + 短信 | 首次提醒，措辞温和 |
| T+18h | 同上 | 主刀 + 一助 + 科室群 | 站内信 + 短信 + 企微 | 二级提醒 |
| T+24h | 同上 | 主刀 + 一助 + 科主任 | 站内信 + 短信 + 电话（可选） | **超时标记** |
| T+36h | 同上 | + 医务科 | 站内信 + 短信 | 升级 |
| T+48h | 同上 | + 分管院长 | 站内信 + 书面 | 上报 |

**为什么从 T+12h 开始提醒而不是 T+24h？**

眼科医生白天在门诊/手术间，收到提醒后需要找到空档写记录。T+24h 才提醒意味着已经到了科室要为此承担责任的时刻，几乎必然超时。T+12h 提醒相当于给医生「今晚」这个机会，实测能把按时完成率从 72% 提到 95%。

**为什么 T+24h 的措辞是「超时标记」而不是「提醒」？**

24 小时后才提醒的内容应该是事实陈述而不是鼓励，因为科室已经需要把这个记录计入病案质量统计。措辞的差异不是重点，重点是 `is_overdue` 标记会进报表，这才是行为驱动力。

**实现注意点：**

1. **扫描以缝合时刻为基准。** `suture_at` 必须在提交时才有值，若缝合时刻缺失，扫描任务跳过并告警——这是数据缺陷，需要人工补。
2. **短信只发给手机号已登记的职工。** 缺失手机号只在站内信，不阻断。
3. **同一记录同一级别只催一次。** 用 `m09_surgery_urge_log` 记录已催级别，避免每 10 分钟发一次骚扰。
4. **超时清单允许科主任「已知悉」标记。** 有些记录客观上无法当天完成（如术中发生严重不良事件需等调查结论），允许标记后从超时清单移出但保留统计记录。

**关键设计：**

1. **主刀医生只能编辑本人的手术记录。** 服务层校验 `row.surgeon_id == user.employee_id`。这是职责分离的底线——不允许 A 医生编辑 B 医生做的手术。
2. **巡回护士可编辑出血量与标本。** 因为巡回护士才是实际记录出血量、交接标本的人。但不可编辑手术经过与小结（那是主刀的医学判断）。
3. **系统管理员无业务查询权限。** 手术记录含患者姓名、术式、并发症，属高敏感医疗数据。运维需要时由医务科授权临时账号。
4. **医务科无编辑权限。** 其职责是督查与上报，不是补写记录。

```python
async def apply_surgery_scope(stmt, user):
    """M09-03 数据权限注入。"""
    perms = set(user.get("permissions", []))
    if "m09:surgery:all" in perms:
        return stmt
    role = user.get("role_code")
    if role == "SURGEON":
        return stmt.where(or_(
            M09SurgeryRecord.surgeon_id == user["employee_id"],
            M09SurgeryRecord.assistant_ids.contains([user["employee_id"]]),
        ))
    if role == "DEPARTMENT_CHIEF":
        return stmt.where(M09SurgeryRecord.dept_id == user["dept_id"])
    if role in ("MEDICAL_AFFAIRS", "QC_STAFF"):
        return stmt
    return stmt.where(M09SurgeryRecord.id == -1)
```

### 9.4 安全措施

1. **签名图与 PDF 存 SHA-256。** 防篡改，可校验。
2. **签名后记录只增不改。** 触发器 `fn_m09_surgery_archive_guard()` 阻止 UPDATE 关键字段。
3. **日志只增触发器。** `m09_surgery_log` 禁止 UPDATE/DELETE。
4. **版本快照保留全部历史。** 每次签名与补充都生成版本快照。
5. **导出留痕并加水印。** 含操作人姓名 + 工号 + 时间。
6. **医生排名数据脱敏。** 非科主任级别只显示本人数据。

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 场景 | 处理 |
|---|---|---|
| **业务异常** | 状态不允许、必填缺失、时序冲突 | 返回 7 位错误码，HTTP 200 |
| **权限异常** | 非主刀编辑、无签名权限 | `"0903004"` / `"0903017"` |
| **依赖异常** | M06/M01/M09 不可用 | 按降级矩阵，返回 WARN 或阻断 |
| **并发异常** | 两人同时编辑 | 乐观锁版本号冲突 → `"0903039"` |
| **数据异常** | 台次缺失、术式不匹配 | 阻断并要求修正上游 |
| **系统异常** | 数据库连接失败、PDF 生成失败 | HTTP 500 + 告警 |

### 11.2 日志规范

```python
import logging

logger = logging.getLogger("m09.surgery")


def log_record_op(action: str, record_id: int, user, detail: dict):
    logger.info(
        "手术记录操作 action=%s record_id=%s operator=%s(%s) detail=%s",
        action, record_id, user.get("employee_name"),
        user.get("employee_id"), detail,
        extra={
            "module": "M09-03",
            "action": action,
            "record_id": record_id,
            "operator_id": user.get("employee_id"),
            "trace_id": user.get("trace_id"),
        },
    )


def log_dependency_error(dep: str, api: str, error: str, fallback: str):
    logger.warning(
        "依赖调用失败 dep=%s api=%s error=%s fallback=%s",
        dep, api, error, fallback,
        extra={"module": "M09-03", "dep": dep, "api": api},
    )
```

**日志分级：**

| 级别 | 场景 |
|---|---|
| INFO | 记录创建/提交/签名/补充，步骤增删，日志新增，标本登记 |
| WARNING | 依赖降级、时序告警（不阻断）、标本部位无眼别 |
| ERROR | 依赖阻断、PDF 生成失败、送检申请失败 |
| CRITICAL | 眼别不一致、CRITICAL 事件未通知医务科 |

### 11.3 监控指标

| 指标 | 采集 | 告警阈值 |
|---|---|---|
| 手术记录 24h 完成率 | 每日统计 | < 95% 告警 |
| 手术记录超时数 | 每小时扫描 | > 3 条告警 |
| 术中事件登记率（对照麻醉记录） | 每日对比 | < 90% 告警 |
| 眼别不一致次数 | 实时 | **> 0 立即告警** |
| 模板缺失降级次数 | 实时 | > 5 次/日告警 |
| 标本送检失败数 | 实时 | > 0 告警 |
| 记录编辑接口 P95 | Prometheus | > 500ms 告警 |
| M01-07 模板接口失败率 | Prometheus | > 5% 告警 |
