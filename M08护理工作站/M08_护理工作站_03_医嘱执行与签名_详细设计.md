## 1. 模块概述

### 1.1 模块定位

M08-03 是护理医嘱从「计划要做」到「确实做了」的落地环节。护士在这里登记执行结果、完成双人核对、签署电子签名，并把结果回写 M07 让医嘱闭环。

```
┌──────────────────────────────────────────────────────────────────────┐
│                            M08 护理工作站                              │
├──────────────┬──────────────┬───────────────┬────────────────────────┤
```

### 1.2 为什么独立成子模块

| # | 理由 | 展开说明 |
|---|---|---|
| 1 | **执行记录是不可变的法定证据** | 《医疗纠纷预防和处理条例》第十六条要求病历资料可追溯。执行记录一旦签名，任何修改都必须留痕。这与计划（可重算）在生命周期上是根本对立的 |
| 2 | **签名是独立的法律行为** | 《电子签名法》第十四条：可靠的电子签名与手写签名或盖章具有同等的法律效力。签名需要身份认证、时间戳、不可否认性，这套机制必须与其他业务流程隔离 |
| 3 | **回写 M07 有两个接口和两种语义** | `on-executing`（开始执行，P95 ≤ 50ms）与 `on-completed`（完成，P95 ≤ 100ms）是两个不同时点、不同结果的契约。混在 M08-01 里会让 M08-01 同时承担「排任务」和「签证据」两种职责 |
| 4 | **双人核对是一条独立的业务流** | 输血、麻醉药品、高危药品需要两名护士分别核对并签名。这是「两个人 × 两个时点 × 一套职责分离规则」的完整模型，不是任务队列的一个属性 |
| 5 | **执行异常需要独立处置** | 患者拒绝、执行失败、部分执行、执行后不良反应——每一种都有各自的后续动作（退费/换药/上报），需要独立的状态机与审批 |

**反证：如果并入 M08-01 会怎样？**

- M08-01 的核心表 `m08_task` 有 41 个字段，再加执行字段（实际时间、实际剂量、双签人、核对项 JSON、签名 PKI 信息）会超过 70 个字段，一张表三套语义
- 「任务」是每 30 秒刷新的高频读表，而「执行记录」是极少改写的证据表。放在一起会导致证据表被高频扫描，且容易在「刷新任务」的代码里误改执行记录
- M08-01 的完成动作只需把任务置 `COMPLETED`，若执行记录也在 M08-01，就无法保证「先有执行记录再完成任务」这个顺序（M08-01 已强制要求 `complete` 必须携带 `execution_no`，正是为此预留）

### 1.4 概念辨析

| 概念 | 定义 | 与相邻概念的差别 |
|---|---|---|
| **执行点（Exec Point）** | M08-02 展开出的「理论上该做的一次」 | 是应该做的；执行记录是实际做的 |
| **任务（Task）** | M08-01 聚合出的待办项 | 一个任务可能对应多个执行点（VITAL/ASSESS/PREPARE 可合并） |
| **执行记录（Execution）** | 护士实际做了一次并签名的凭证 | 不可修改，只可「作废 + 新建」 |
| **执行明细（Execution Item）** | 一次执行中逐项的结果（一次换药可能涉及 3 个部位） | 一次执行 = 1 条主记录 + N 条明细 |
| **执行异常（Exception）** | 执行未按计划完成的情形 | 是执行记录的子类型，不是独立单据 |
| **签名** | 护士确认「这是我做的」的法律行为 | 签名后不可改，作废也需理由 |
| **核对** | 执行前对患者身份、药品、剂量、途径的一致性检查 | 核对的记录是执行记录的组成部分 |
| **双人核对** | 两名护士分别核对并签名 | 有 SoD 要求：两人不能是同一人 |

**最容易混淆的四组：**

1. **执行点 vs 执行记录**：执行点是「06:00 该滴左眼一次」，执行记录是「06:08 张护士在 3 床滴了左眼 1 滴」。一个执行点理论上产生 0 或 1 条执行记录（跳过则不产生，但会更新执行点状态为 `SKIPPED`）。

2. **执行异常 vs 执行失败**：执行异常是执行记录的一种结果（`result = EXCEPTION`），仍然是一条完整的、已签名的记录（「我去了、我尝试了、患者拒绝了」）。执行失败是「根本没能执行」（如设备坏了）——此时不产生执行记录，只把执行点置 `SKIPPED` 并填说明。两者的关键区别是：**有没有人到过床边**。

3. **签名 vs 登录**：登录证明「账号在用」，签名证明「这个人确认了这件事」。M08-03 采用「二次口令 + 生物识别可配」的签名方式，不能拿登录态直接当签名。

4. **作废 vs 修改**：执行记录不能修改。发现记录错误只能「作废原记录（原因 ≥10 字 + 护士长审批）+ 新建正确记录」。作废后原记录仍在库中，状态为 `VOIDED`。

## 2. 业务范围与边界

### 2.1 范围内

1. **执行登记**：记录实际执行时间、实际剂量/数量、实际途径、实际部位/眼别
2. **患者身份核对**：扫码核对腕带/就诊卡、双项核对（姓名 + 床号 / 姓名 + 出生日期）
3. **执行核对项**：按医嘱类型动态生成核对清单（如换药需核对部位、敷料、消毒方式）
4. **双人核对**：扫描/高危药品 + 输血 + 特殊治疗需两名护士分别核对与签名
5. **电子签名**：二次口令（+ 可选指纹/人脸），生成签名摘要、时间戳
6. **执行异常登记**：患者拒绝、患者不在、执行失败、部分执行、不良反应
7. **拍照留证**：换药前后、穿刺点、敷料外观（可选，按医嘱要求）
8. **回写 M07**：执行开始调 `on-executing`，执行完成调 `on-completed`
9. **执行记录查询**：按患者/病区/护士/时间/医嘱类型查询
10. **执行记录作废**：护士长审批，保留原记录
11. **执行质量统计**：执行及时率、异常率、双签合规率、按护士/病区汇总
12. **执行记录打印**：护理执行单（部分医院要求纸质签字留档）

### 2.2 范围外

| 能力 | 归属 | 理由 |
|---|---|---|
| 开具/停止/修改护理医嘱 | M07-03 | 医嘱是医生行为 |

## 3. 业务模型

### 3.1 执行登记模型

一次完整的护理执行包含 **4 个阶段、12 个字段组**：

```
① 进入执行页
   ├─ 任务/执行点定位（task_id / point_id / order_id）
   └─ 加载医嘱快照（item_name / 剂量 / 途径 / 眼别 / 频次）

② 核对阶段（必须完成才能进入下一阶段）
   ├─ 患者身份核对（扫码腕带 / 扫码就诊卡 / 双项手输）
   ├─ 执行前核对项（按医嘱类型动态生成）
   └─ 高危/特殊药品额外核对（双人）

③ 执行阶段
   ├─ 实际执行时间（默认当前，允许回溯 ≤ 2 小时，需理由）
   ├─ 实际剂量/数量（默认计划值，可改但需理由）
   ├─ 实际途径（默认计划值）
   └─ 执行说明（自由文本，异常时必填）

④ 签名阶段
   ├─ 护士身份二次认证
   ├─ 生成签名摘要（SHA-256 over 执行数据）
   ├─ 调 M02-05 签名服务（时间戳 + 证书）
   └─ 写入执行记录 → 回写 M07
```

**为什么核对必须在执行前？**

如果允许「先签名后核对」，护士可以一次性勾完所有核对项再去执行，核对就退化成形式。M08-03 的接口设计中，`POST /executions/verify` 与 `POST /executions/{id}/sign` 是两次独立调用，且 `verify` 中记录核对发生时的服务器时间，`sign` 时校验「核对时间 → 签名时间」的间隔在 30 秒 ~ 30 分钟之间（太短说明连续点击，太长说明核对已失效）。

### 3.2 核对项模型

核对项不是固定清单，而是按医嘱类型动态生成：

| 医嘱类型 | 核对项 | 是否必须 |
|---|---|---|
| **TREATMENT**（换药） | 患者身份、部位、敷料类型、消毒方式、异物遗留检查 | 全部必须 |
| **TREATMENT**（冲洗） | 患者身份、冲洗液种类、冲洗液温度、眼别、压力 | 全部必须 |
| **TREATMENT**（注射） | 患者身份、药品、剂量、途径、注射部位、有效期 | 全部必须 |
| **TREATMENT**（激光配合） | 患者身份、眼别、遮挡、设备参数、知情同意 | 全部必须 |
| **OPER**（术前准备） | 患者身份、术眼标记、禁食确认、术前用药、义齿摘除 | 全部必须 |
| **高危药品** | 上述 + 药品名称、剂量、浓度、给药速度、双人签名 | 全部必须 + 双签 |
| **麻醉/一类精神** | 上述 + 批号、双人签名、空安瓿回收 | 全部必须 + 双签 |
| **输血** | 上述 + 血型、交叉配血结果、血袋号、输血开始/结束时间、双签 | 全部必须 + 双签 |

**核对项配置化：**

核对项模板存 `m08_execution_check_template`（独立配置表，在 M08 数据结构汇总中统一维护），管理员可按医嘱类型与项目编码配置。默认模板内置在代码中（`DEFAULT_CHECK_TEMPLATES`），配置表只存「与默认的差异」，减少初始化负担。

**核对结果三种：**

- `OK`：符合
- `WARN`：不符合但可继续（如敷料略湿但可继续观察）
- `BLOCK`：不符合必须中止（如药名与医嘱不符、患者身份不符）

`BLOCK` 出现时，**不允许签名**，必须走「执行异常登记」路径。

### 3.3 患者身份核对模型

眼科患者高度同质化（多为老年白内障、同名同姓概率高），身份核对是重中之重。

**四种核对方式（按可靠性排序）：**

| 方式 | 操作 | 可靠性 | 适用场景 |
|---|---|---|---|
| **腕带扫码** | 扫腕带条码，系统自动比对 patient_id | ★★★★★ | 住院、日间手术（有腕带） |
| **就诊卡扫码** | 扫就诊卡条码 | ★★★★ | 门诊（无腕带） |
| **双项手输** | 手输姓名 + 床号（住院）或 姓名 + 出生日期（门诊） | ★★★ | 扫码失败时兜底 |
| **双人确认** | 患者自述 + 家属确认（无卡无腕带） | ★★ | 极少数场景，需护士长授权 |

**核对通过判定：**

```
扫码方式：扫码结果 patient_id == 医嘱 patient_id，且本次核查时间距医嘱开具 < 24 小时
          （超过 24 小时视为「久未核对」，需重新核对）
双项手输：两项全部匹配（姓名精确匹配，床号/出生日期精确匹配）
```

**核对失败的处理：**

- 第 1 次失败：提示「核对不符，请重新核对」
- 第 2 次失败：**锁定**，必须护士长授权才能继续（防止「反复试到蒙对」）
- 记录每次失败的尝试（`m08_execution_check_attempt`），用于质量分析

**腕带归属说明：** 住院与日间手术的腕带由 M06-04 生成（`m06_wristband`），M08-03 只读调用 `GET /internal/v1/m06/wristband/by-patient/{patient_id}` 获取条码用于比对，**不生成腕带**。门诊患者无腕带，使用就诊卡或双项核对。

### 3.4 双人核对模型

**必须双人核对的场景：**

1. 高危药品（`mdm_drug.is_high_risk = TRUE`）
2. 麻醉药品、一类精神药品
3. 输血及血液制品
4. 高浓度电解质（如 10% 氯化钾）
5. 按医嘱要求（`need_double_check = TRUE`）

**双人核对流程：**

```
护士 A（执行护士）                       护士 B（核对护士）
      │                                        │
      │ ① 发起双人核对请求                       │
      ├───────────────────────────────────────►│
      │                                        │
      │ ② A 完成核对并签名                       │
      │                                        │
      │                                        │ ③ B 独立核对（不能再扫同一张单）
      │                                        │    核对后签名
      │◄───────────────────────────────────────┤
      │                                        │
      │ ④ 两人签名齐全 → 允许执行                 │
      ▼                                        ▼
```

**SoD 三条硬规则：**

| 规则 | 说明 | 实现方式 |
|---|---|---|
| SoD-01 | 执行护士与核对护士不能是同一人 | `m08_execution_nurse.checker_id <> executor_id` 约束 |
| SoD-02 | 两人的核对时间差 ≥ 5 秒 | 防止「一人连点两次」 |
| SoD-03 | 两人不能同时用同一台设备的同一会话 | 后端校验 `session_id` 不同 |

**为什么时间差要 ≥ 5 秒？**

双人核对的实质是「两个人分别看了同一件东西」。若两人签字时间差 < 5 秒，说明极可能是同一个人在代签，或两人没有实际核对就各点一下。5 秒是经验值：一个人看药名、剂量、浓度、途径、有效期至少需要 5 秒。

**双人核对记录：**

双签记录存 `m08_execution_nurse`，每行一名护士的签名（含核对时间、核对项结果、签名摘要）。一次执行有 1 或 2 行。

### 3.5 电子签名模型

**签名要素（对齐《电子签名法》第十四条"可靠电子签名"的四要件）：**

| 要件 | 实现 |
|---|---|
| 签名制作数据属于签名人专有 | 二次口令 + 可选生物识别，登录态不作为签名依据 |
| 签署时签名制作数据仅由签名人控制 | 二次口令由本人输入，不缓存、不代填 |
| 签署后对签名的任何改动能够被发现 | 签名摘要 = SHA-256(执行记录关键字段规范化串) |
| 签署后对数据电文内容和形式的任何改动能够被发现 | 摘要落库 + M02-05 时间戳；作废与原记录建立关联 |

**签名摘要的计算范围：**

```python
SIGN_FIELDS = (
    "execution_no", "point_id", "task_id", "order_id", "order_no",
    "patient_id", "item_code", "actual_qty", "actual_unit",
    "actual_route_code", "actual_eye_side", "executed_at",
    "executor_id", "check_result",
)
```

规范化串 = 按 上表顺序 用 `|` 拼接，`None` 转空串，时间转 ISO8601 到秒。摘要 = `SHA-256(utf8(串) + "|" + salt)`，`salt` 为医院级常量（存 M01-11 系统参数，不对护士暴露）。

**签名时间戳来源：**

优先 M02-05 返回的可信时间戳（RFC 3161）；M02-05 不可用时用服务器时间，并在记录中标记 `signature_source = 'LOCAL'`，供质控抽查。

### 3.6 执行状态机

```
                          ┌─────────────────┐
                          │   PENDING       │  待执行（执行点已排）
                          └────────┬────────┘
                                   │ 打开执行页
                                   ▼
                          ┌─────────────────┐
                          │   CHECKING      │  核对中
                          └────────┬────────┘
                                   │ 核对通过
                         ┌─────────┴──────────┐
                         │                    │
                核对 BLOCK ▼                    ▼ 核对 OK
                 ┌─────────────────┐   ┌─────────────────┐
                 │   EXCEPTION     │   │   EXECUTING     │  执行中
                 │  （核对失败）     │   └────────┬────────┘
                 └─────────────────┘            │
                                       ┌────────┼─────────┬───────────┐
                                       ▼        ▼         ▼           ▼
                              ┌──────────┐ ┌────────┐ ┌────────┐ ┌──────────┐
                              │ COMPLETED│ │PARTIAL │ │EXCEPTION│ │ REFUSED  │
                              │ 已完成    │ │部分完成 │ │执行异常  │ │患者拒绝   │
                              └──────────┘ └────────┘ └────────┘ └──────────┘
                                       │        │         │           │
                                       └────────┴─────────┴───────────┘
                                                    │
                                                    ▼  签名
                                          ┌─────────────────┐
                                          │    SIGNED       │  已签名（终态）
                                          └────────┬────────┘
                                                   │ 护士长作废
                                                   ▼
                                          ┌─────────────────┐
                                          │    VOIDED       │  已作废（终态）
                                          └─────────────────┘
```

**状态说明：**

| 状态 | 含义 | 是否终态 |
|---|---|---|
| `PENDING` | 执行点已排，未开始 | 否 |
| `CHECKING` | 正在核对（已打开执行页，未提交核对） | 否 |
| `EXECUTING` | 核对通过，执行中 | 否 |
| `COMPLETED` | 按计划完成 | 否（待签名） |
| `PARTIAL` | 部分完成（如只滴了单眼、换了 3 个部位中的 2 个） | 否（待签名） |
| `REFUSED` | 患者拒绝 | 否（待签名） |
| `EXCEPTION` | 执行异常（患者不在、执行失败、不良反应） | 否（待签名） |
| `SIGNED` | 已签名，完成 | **是** |
| `VOIDED` | 已作废 | **是** |

**为什么 `SIGNED` 是独立状态而不是一个字段？**

「已执行但未签名」的记录在系统里是半成品：不能回写 M07、不能计入绩效、不能作为证据。若只用 `is_signed` 布尔字段，查询「今日已完成的执行」时容易漏掉 `is_signed` 条件。独立状态让所有查询天然正确。

**为什么 `REFUSED` 也要签名？**

患者拒绝是重要的临床事实。护士签名确认「我到了床边、我说明了、患者拒绝了」——这与「护士偷懒没去」在系统里的表现（无记录）必须区分开。签名后的 `REFUSED` 记录是医疗纠纷中的关键证据。

### 3.7 执行异常模型

**六类异常：**

| 异常类型 | 含义 | 后续动作 | 是否需照片 |
|---|---|---|---|
| `PATIENT_ABSENT` | 患者不在床（去做检查、外出） | 任务转回待认领，稍后重试 | 否 |
| `PATIENT_REFUSED` | 患者拒绝执行 | 通知医生，医生决定是否停医嘱 | 否 |
| `EXEC_FAILED` | 执行失败（静脉穿刺失败、设备故障） | 记录失败原因，任务转回待重试 | 否 |
| `PARTIAL_DONE` | 部分完成（只做了单眼 / 只换了部分部位） | 记录已完成部分，剩余转回待办 | 是（可选） |
| `ADVERSE_REACTION` | 执行后出现不良反应（过敏、渗漏） | 立即通知医生、登记 ADR、拍照 | **是** |
| `OTHER` | 其他（需详细说明 ≥10 字） | 由护士长判断 | 否 |

**异常与执行结果的关系：**

- 异常**总是**产生执行记录（因为人到过床边）
- `PATIENT_ABSENT` 是唯一例外：若护士未离开护士站直接从系统发现患者不在，可只把执行点置 `SKIPPED`，不产生执行记录
- 有异常的执行记录，`result` 字段为 `EXCEPTION`，`exception_type` 记录具体类型

### 3.8 回写 M07 模型

**两个回写时点：**

| 时点 | 接口 | 触发条件 | 语义 |
|---|---|---|---|
| 执行开始 | `POST /internal/v1/m07/orders/on-executing` | 核对通过、进入 `EXECUTING` | 让医生看到「护士正在执行」 |
| 执行完成 | `POST /internal/v1/m07/orders/on-completed` | 签名成功、`SIGNED` | 让医嘱闭环、触发计费 |

**回写请求体（`on-completed`）：**

```json
{
  "order_id": 88231,
  "order_no": "OR202610270031",
  "executor_module": "M08",
  "executed_at": "2026-10-27T06:08:23",
  "result_ref": {
    "execution_id": 51288,
    "execution_no": "EX20261027000512",
    "result": "COMPLETED",
    "actual_qty": 1.0000,
    "actual_unit": "滴",
    "actual_eye_side": "OS",
    "exception_type": null,
    "nurse_names": ["张丽", "王芳"],
    "signed_at": "2026-10-27T06:09:01"
  },
  "remark": "左眼滴入 1 滴，患者配合良好"
}
```

**回写失败处理（三层）：**

```
① 同步调用（默认）
   ├─ 成功 → 更新 m08_execution.writeback_status = 'SUCCESS'
   └─ 失败 → 进入 ②

② 补偿队列（m08_execution 自身为队列，按 writeback_status 扫描）
   ├─ 每 30 秒扫描 writeback_status IN ('PENDING','FAILED') AND retry_count < 10
   ├─ 指数退避：1, 2, 4, 8, 16, 32, 64, 128, 256, 512 秒
   └─ 重试 10 次仍失败 → ③

③ 人工兜底
   ├─ writeback_status = 'DEAD'
   ├─ 告警给护士长（页面提示「N 条记录未回写」）
   └─ 提供「手工重试」按钮
```

**为什么不在签名事务里同步回写？**

M07 的 `on-completed` P95 ≤ 100ms，但网络抖动时可能到 1 秒。若放在签名事务里，护士点「签名」要等 1 秒才看到成功，体验差且失败时整个签名回滚（执行记录丢失）。正确做法是：**签名先落库并提交，然后异步回写**。签名是护士的行为证据，回写是系统间的通知——证据优先。

**M07 侧的回写语义（引用 M07-03 契约）：**

- `on-executing`：M07 把 `m07_order.status` 从 `PAID` 置为 `EXECUTING`，写 `executing_at`
- `on-completed`：M07 把状态置为 `COMPLETED`，写 `executed_at`、`result_ref`、`executor_module`
- **M07 保证幂等**：同一 `order_id` 重复 `on-completed` 返回成功且不改变状态

M08-03 侧也做幂等：`m08_execution.idempotency_key = "EXEC:%d" % point_id`（一个执行点只能有一条有效执行记录，重复签名由唯一索引拒绝）。

### 3.9 执行记录作废模型

**为什么允许作废？**

护士执行完了才发现扫错患者、或用错了药——此时记录已是错误的，不能改（证据不可改），只能作废后重做。

**作废规则：**

| 规则 | 说明 |
|---|---|
| 谁能作废 | 护士长（`m08:execution:void` 权限），护士本人不能 |
| 时限 | 签名后 24 小时内；超 24 小时需护理部主任审批 |
| 原因 | ≥10 字，必须说明错在哪 |
| 附件 | 若因「扫错患者」，需上传正确患者的执行记录编号 |
| 作废后动作 | ①原记录 `status = VOIDED` ②执行点回退为 `PLANNED` ③通知 M07 撤销回写（调 `on-completed` 的逆向接口 `on-execution-voided`，如 M07 未提供则人工介入）④新记录关联 `void_of_execution_id` |
| 作废留痕 | 全量写 `m08_execution_log`，永久保留 |

**M07 逆向回写缺失的处理：**

M07-03 契约中未定义 `on-execution-voided`（截至本文档编写时）。M08-03 的处理：
1. 尝试调用 `POST /internal/v1/m07/orders/on-execution-voided`（前瞻接口）
2. 若返回 404，则把作废信息写入 `m08_execution.writeback_note`，并在「未处理告警」中列出，由护士长联系医生手工处理

**这是本文档登记的一条跨模块文档债：T-M08-03-01 M07-03 需补充 `on-execution-voided` 契约。**

### 3.10 执行质量指标

| 指标 | 公式 | 目标 |
|---|---|---|
| **执行及时率** | 实际执行时间在计划时间 ±(提前 30min / 延后 60min) 内的记录数 ÷ 总记录数 | ≥ 95% |
| **异常率** | `result = EXCEPTION` 的记录数 ÷ 总记录数 | ≤ 3% |
| **拒绝率** | `result = REFUSED` ÷ 总记录数 | ≤ 1% |
| **双签合规率** | 需双签的执行中两人不同的比例 | 100% |
| **身份核对率** | 有核对记录的执行比例 | 100% |
| **签名及时率** | 签名时间距执行结束时间 ≤ 10 分钟的比例 | ≥ 98% |
| **作废率** | 作废记录数 ÷ 总记录数 | ≤ 0.5% |
| **回写成功率** | `writeback_status = 'SUCCESS'` ÷ 总记录数 | ≥ 99.9% |

```python
    # ---------- 创建 ----------

    async def create(self, body, user: dict) -> dict:
        """创建执行记录。

        幂等：一个执行点只能有一条有效执行记录。
        """
        point = await self._get_point(body.point_id)
        if point.status in ("EXECUTED", "CANCELLED"):
            raise BizException("0803001", "执行点不存在或已失效")

        exist = await self.db.scalar(
            select(M08Execution).where(
                M08Execution.point_id == body.point_id,
                M08Execution.status.notin_(("VOIDED",)),
            )
        )
        if exist:
            return await self.get_detail(exist.id, user)

        order = await self._fetch_order(body.order_id)
        patient = await self._fetch_patient(order["patient_id"])
        exec_no = await self._next_execution_no()

        row = M08Execution(
            execution_no=exec_no,
            point_id=body.point_id,
            plan_id=point.plan_id,
            task_id=body.task_id,
            order_id=body.order_id,
            order_no=order["order_no"],
            patient_id=order["patient_id"],
            patient_name=patient["patient_name"],
            patient_sex=patient.get("sex"),
            patient_age=patient.get("age"),
            ward_id=point.ward_id,
            bed_no=patient.get("bed_no"),
            item_code=order["item_code"],
            item_name=order["item_name"],
            spec=order.get("spec"),
            dose_plan=order.get("dosage"),
            dose_unit_plan=order.get("dose_unit"),
            route_code_plan=order.get("route_code"),
            eye_side_plan=order.get("eye_side", "NA"),
            planned_time=point.planned_time,
            need_double_check=await self._need_double_check(order),
            status="CHECKING",
            created_by=user["employee_id"],
        )
        self.db.add(row)
        await self.db.flush()
        await self._log(row.id, "CREATE", user, None, "CHECKING")
        await self.db.commit()
        return await self.get_detail(row.id, user)

    async def _get_point(self, point_id: int) -> M08ExecPoint:
        point = await self.db.get(M08ExecPoint, point_id)
        if not point:
            raise BizException("0803001", "执行点不存在或已失效")
        return point

    async def _fetch_order(self, order_id: int) -> dict:
        try:
            return await M07Client.get_order(order_id)
        except Exception:
            logger.exception("拉取医嘱失败 order_id=%s", order_id)
            raise BizException("0803009", "医嘱服务不可用")

    async def _fetch_patient(self, patient_id: int) -> dict:
        try:
            return await M03Client.get_patient_brief(patient_id)
        except Exception:
            logger.warning("患者简要降级 patient_id=%s", patient_id)
            return {"patient_name": "", "sex": None, "age": None, "bed_no": None}

    async def _need_double_check(self, order: dict) -> bool:
        if order.get("need_double_check"):
            return True
        drug_type = order.get("drug_management_class") or ""
        return drug_type in DOUBLE_CHECK_REQUIRED_TYPES or bool(
            order.get("is_high_risk")
        )

    async def _next_execution_no(self) -> str:
        key = "m08:exec:seq:%s" % datetime.now().strftime("%Y%m%d")
        seq = await redis_client.incr(key)
        if seq == 1:
            await redis_client.expire(key, 172800)
        return "EX%s%05d" % (datetime.now().strftime("%Y%m%d"), seq % 100000)

    # ---------- 患者身份核对 ----------

    async def verify_patient(self, execution_id: int, body, user: dict) -> dict:
        row = await self._get_editable(execution_id)

        attempts = await self._count_verify_attempts(row.id)
        if attempts >= MAX_PATIENT_VERIFY_ATTEMPTS and not row.patient_verify_unlocked:
            raise BizException("0803005", "身份核对已锁定，需护士长授权")

        matched = await self._do_match(body, row)
        passed = bool(matched and matched["patient_id"] == row.patient_id)

        await self._save_verify_attempt(row.id, body, matched, passed, user)

        if not passed:
            return {
                "verified": False,
                "method": body.method,
                "matched_patient_id": matched.get("patient_id") if matched else None,
                "matched_patient_name": matched.get("patient_name") if matched else None,
                "attempt_count": attempts + 1,
                "is_locked": attempts + 1 >= MAX_PATIENT_VERIFY_ATTEMPTS,
            }

        row.patient_verify_method = body.method
        row.patient_verify_at = datetime.now()
        row.patient_verify_result = "OK"
        await self.db.commit()

        return {
            "verified": True,
            "method": body.method,
            "matched_patient_id": matched["patient_id"],
            "matched_patient_name": matched["patient_name"],
            "attempt_count": attempts + 1,
            "verified_at": row.patient_verify_at.isoformat(),
            "is_locked": False,
        }

    async def _do_match(self, body, row: M08Execution) -> dict | None:
        if body.method in ("WRISTBAND", "CARD"):
            barcode = (body.barcode or "").strip()
            if not barcode:
                return None
            try:
                return await M03Client.resolve_barcode(barcode)
            except Exception:
                logger.warning("条码解析失败 barcode=%s", barcode)
                return None

        if body.method == "MANUAL_TWO":
            patient = await M03Client.get_patient_brief(row.patient_id)
            name_ok = (body.input_name or "").strip() == patient.get("patient_name")
            if patient.get("bed_no"):
                second_ok = (body.input_second or "").strip() == patient["bed_no"]
            else:
                second_ok = (body.input_second or "").strip() == str(
                    patient.get("birth_date")
                )
            if name_ok and second_ok:
                return {
                    "patient_id": row.patient_id,
                    "patient_name": patient.get("patient_name"),
                }
            return {"patient_id": None, "patient_name": None}

        return None

    async def _count_verify_attempts(self, execution_id: int) -> int:
        return await self.db.scalar(
            select(func.count()).select_from(M08ExecutionCheck).where(
                M08ExecutionCheck.execution_id == execution_id,
                M08ExecutionCheck.check_type == "PATIENT_IDENTITY",
            )
        ) or 0

    async def _save_verify_attempt(
        self, execution_id: int, body, matched: dict | None, passed: bool, user: dict
    ) -> None:
        row = M08ExecutionCheck(
            execution_id=execution_id,
            check_type="PATIENT_IDENTITY",
            check_method=body.method,
            check_value=(body.barcode or body.input_name or "")[:128],
            matched_patient_id=matched.get("patient_id") if matched else None,
            check_result="OK" if passed else "BLOCK",
            checked_by=user["employee_id"],
            checked_at=datetime.now(),
        )
        self.db.add(row)
        await self.db.flush()

    async def unlock_patient(self, execution_id: int, user: dict) -> dict:
        row = await self._get(row.id if hasattr(row, "id") else execution_id)
        row.patient_verify_unlocked = True
        row.unlocked_by = user["employee_id"]
        row.unlocked_at = datetime.now()
        await self._log(row.id, "UNLOCK_PATIENT", user, row.status, row.status)
        await self.db.commit()
        return {"execution_id": row.id, "unlocked": True}

    # ---------- 核对项 ----------

    async def get_check_items(self, execution_id: int) -> dict:
        row = await self._get(execution_id)
        key = self._template_key(row)
        items = DEFAULT_CHECK_TEMPLATES.get(key, [])
        done = await self._done_check_codes(execution_id)

        return {
            "execution_id": execution_id,
            "template_key": key,
            "items": [
                {
                    "code": code,
                    "name": name,
                    "required": required,
                    "done": code in done,
                }
                for code, name, required in items
            ],
            "patient_verified": row.patient_verify_result == "OK",
        }

    def _template_key(self, row: M08Execution) -> str:
        name = row.item_name or ""
        if "换药" in name:
            return "TREATMENT_DRESSING"
        if "冲洗" in name:
            return "TREATMENT_IRRIGATION"
        if "注射" in name:
            return "TREATMENT_INJECTION"
        if "激光" in name:
            return "TREATMENT_LASER"
        if "术前" in name:
            return "OPER_PREPARE"
        return "TREATMENT_DRESSING"

    async def _done_check_codes(self, execution_id: int) -> set[str]:
        rows = await self.db.scalars(
            select(M08ExecutionCheck).where(
                M08ExecutionCheck.execution_id == execution_id,
                M08ExecutionCheck.check_type == "CHECK_ITEM",
            )
        )
        return {r.check_code for r in rows}

    async def submit_check(self, execution_id: int, body, user: dict) -> dict:
        row = await self._get_editable(execution_id)
        if row.patient_verify_result != "OK":
            raise BizException("0803004", "患者身份核对未通过")

        template = DEFAULT_CHECK_TEMPLATES.get(self._template_key(row), [])
        required = {c for c, _, r in template if r}
        given = {i.code for i in body.items if i.result == "OK"}
        missing = required - given
        if missing:
            raise BizException("0803006", "核对项未全部完成：" + ",".join(sorted(missing)))

        blocks = [i.code for i in body.items if i.result == "BLOCK"]
        if blocks:
            raise BizException("0803007", "核对结果为不符，请登记异常")

        now = datetime.now()
        for item in body.items:
            self.db.add(
                M08ExecutionCheck(
                    execution_id=execution_id,
                    check_type="CHECK_ITEM",
                    check_code=item.code,
                    check_result=item.result,
                    checked_by=user["employee_id"],
                    checked_at=now,
                )
            )
        row.check_result = "WARN" if any(i.result == "WARN" for i in body.items) else "OK"
        row.checked_at = now
        row.status = "EXECUTING"
        await self._log(execution_id, "SUBMIT_CHECK", user, "CHECKING", "EXECUTING")
        await self.db.commit()

        # 异步回写 M07 on-executing
        await writeback_m07_task.delay(execution_id, "EXECUTING")

        return {
            "execution_id": execution_id,
            "status": "EXECUTING",
            "check_result": row.check_result,
            "checked_at": now.isoformat(),
        }

    # ---------- 双人核对 ----------

    async def request_double_check(self, execution_id: int, user: dict) -> dict:
        row = await self._get_editable(execution_id)
        if not row.need_double_check:
            return {"required": False, "execution_id": execution_id}

        self.db.add(
            M08ExecutionNurse(
                execution_id=execution_id,
                nurse_id=user["employee_id"],
                nurse_name=user["employee_name"],
                nurse_role="EXECUTOR",
                signed_at=None,
            )
        )
        await self.db.commit()
        return {"required": True, "execution_id": execution_id, "status": "WAITING_CHECKER"}

    async def submit_double_check(self, execution_id: int, body, user: dict) -> dict:
        row = await self._get(execution_id)
        if row.executor_id and row.executor_id == user["employee_id"]:
            raise BizException("0803016", "执行人与核对人不能是同一人")

        executor = await self.db.scalar(
            select(M08ExecutionNurse).where(
                M08ExecutionNurse.execution_id == execution_id,
                M08ExecutionNurse.nurse_role == "EXECUTOR",
            )
        )
        now = datetime.now()
        if executor and executor.signed_at:
            gap = (now - executor.signed_at).total_seconds()
            if gap < DOUBLE_CHECK_MIN_GAP_SECONDS:
                raise BizException("0803017", "两人签名时间间隔过短")

        digest = self._digest(
            {
                "execution_id": execution_id,
                "checker_id": user["employee_id"],
                "checked_at": now.isoformat(timespec="seconds"),
            }
        )

        self.db.add(
            M08ExecutionNurse(
                execution_id=execution_id,
                nurse_id=user["employee_id"],
                nurse_name=user["employee_name"],
                nurse_role="CHECKER",
                signature_digest=digest,
                signed_at=now,
            )
        )
        row.double_check_complete = True
        row.checker_id = user["employee_id"]
        row.checker_name = user["employee_name"]
        await self._log(execution_id, "DOUBLE_CHECK_SUBMIT", user, row.status, row.status)
        await self.db.commit()

        return {
            "checker_id": user["employee_id"],
            "checker_name": user["employee_name"],
            "checked_at": now.isoformat(),
            "check_result": "OK",
            "signature_digest": digest,
            "gap_seconds": int((now - executor.signed_at).total_seconds())
            if executor and executor.signed_at
            else 0,
            "double_check_complete": True,
        }

        await self._log(execution_id, "START", user, "CHECKING", "EXECUTING")
        await self.db.commit()
        return {
            "execution_id": execution_id,
            "status": "EXECUTING",
            "started_at": row.execution_started_at.isoformat(),
        }

    async def record(self, execution_id: int, body, user: dict) -> dict:
        row = await self._get_editable(execution_id)
        now = datetime.now()

        executed_at = body.executed_at
        if executed_at > now:
            raise BizException("0803018", "执行时间不能晚于当前时间")
        if now - executed_at > timedelta(minutes=MAX_TIME_BACKWARD_MINUTES):
            if not body.delay_reason:
                raise BizException("0803019", "执行时间过早，请确认")
        if row.planned_time and executed_at < row.planned_time - timedelta(
            minutes=MAX_TIME_EARLY_MINUTES
        ):
            raise BizException("0803019", "执行时间过早，请确认")

        if body.actual_qty is None or body.actual_qty <= Decimal("0"):
            raise BizException("0803020", "实际数量必须大于 0")

        plan_qty = row.dose_plan or Decimal("0")
        if plan_qty and body.actual_qty != plan_qty and not body.qty_reason:
            raise BizException("0803021", "实际数量与计划不一致时必须说明")

        if body.remark and len(body.remark) > MAX_REMARK_LEN:
            raise BizException("0803022", "异常说明不足 10 字")

        row.executed_at = executed_at
        row.actual_qty = body.actual_qty
        row.actual_unit = body.actual_unit or row.dose_unit_plan
        row.actual_route_code = body.actual_route_code or row.route_code_plan
        row.actual_eye_side = body.actual_eye_side or row.eye_side_plan
        row.remark = body.remark
        row.result = "COMPLETED"
        row.status = "COMPLETED"
        await self._log(execution_id, "RECORD", user, "EXECUTING", "COMPLETED")
        await self.db.commit()

        return {
            "execution_id": execution_id,
            "status": "COMPLETED",
            "result": "COMPLETED",
            "executed_at": executed_at.isoformat(),
        }

    async def register_exception(self, execution_id: int, body, user: dict) -> dict:
        row = await self._get_editable(execution_id)
        if body.exception_type not in EXCEPTION_TYPES:
            raise BizException("0803022", "异常说明不足 10 字")
        if len(body.note or "") < MIN_EXCEPTION_NOTE_LEN:
            raise BizException("0803022", "异常说明不足 10 字")
        if body.exception_type == "ADVERSE_REACTION":
            count = await self._count_attachments(execution_id)
            if count <= 0 and not body.attachment_ids:
                raise BizException("0803023", "不良反应必须上传照片")
        if body.follow_up not in FOLLOW_UP_ACTIONS:
            raise BizException("0803022", "异常说明不足 10 字")

        row.exception_type = body.exception_type
        row.exception_note = body.note
        row.follow_up_action = body.follow_up
        row.result = "EXCEPTION" if body.exception_type != "PARTIAL_DONE" else "PARTIAL"
        row.status = row.result
        await self._log(execution_id, "EXCEPTION", user, "EXECUTING", row.status)
        await self.db.commit()

        return {
            "execution_id": execution_id,
            "status": row.status,
            "exception_type": body.exception_type,
            "follow_up": body.follow_up,
        }

    async def add_attachment(self, execution_id: int, file, user: dict) -> dict:
        row = await self._get_editable(execution_id)
        count = await self._count_attachments(execution_id)
        if count >= MAX_ATTACHMENTS:
            raise BizException("0803024", "附件数量或大小超出限制")

        content = await file.read()
        if len(content) > MAX_ATTACHMENT_BYTES:
            raise BizException("0803024", "附件数量或大小超出限制")

        sha = hashlib.sha256(content).hexdigest()
        path = await self._store_file(execution_id, sha, file.filename, content)

        att = M08ExecutionAttachment(
            execution_id=execution_id,
            file_name=file.filename,
            file_path=path,
            file_size=len(content),
            content_type=file.content_type,
            sha256=sha,
            uploaded_by=user["employee_id"],
        )
        self.db.add(att)
        await self.db.flush()
        await self.db.commit()
        return {"attachment_id": att.id, "file_name": file.filename, "file_size": len(content)}

    async def _count_attachments(self, execution_id: int) -> int:
        return await self.db.scalar(
            select(func.count()).select_from(M08ExecutionAttachment).where(
                M08ExecutionAttachment.execution_id == execution_id,
                M08ExecutionAttachment.is_deleted.is_(False),
            )
        ) or 0

    # ---------- 签名 ----------

    async def sign(self, execution_id: int, body, user: dict) -> dict:
        row = await self._get_editable(execution_id)

        if row.status not in ("COMPLETED", "PARTIAL", "REFUSED", "EXCEPTION"):
            raise BizException("0803002", "执行记录状态不允许此操作")

        if not row.patient_verify_at:
            raise BizException("0803004", "患者身份核对未通过")
        gap = (datetime.now() - row.patient_verify_at).total_seconds()
        if gap > CHECK_VALID_MAX_SECONDS:
            raise BizException("0803008", "核对已超时，请重新核对")

        if row.need_double_check and not row.double_check_complete:
            raise BizException("0803015", "双人核对未完成")

        await self._verify_sign_password(user["employee_id"], body.signature_password)

        digest = self._sign_digest(row)
        ts = await self._call_sign_service(row, digest, user)

        now = datetime.now()
        row.status = "SIGNED"
        row.signed_at = now
        row.signature_digest = digest
        row.signature_source = ts.get("source", "LOCAL")
        row.timestamp_serial = ts.get("serial")
        row.signed_by = user["employee_id"]
        row.signed_by_name = user["employee_name"]
        row.writeback_status = "PENDING"

        self.db.add(
            M08ExecutionNurse(
                execution_id=execution_id,
                nurse_id=user["employee_id"],
                nurse_name=user["employee_name"],
                nurse_role="SIGNER",
                signature_digest=digest,
                signed_at=now,
            )
        )
        await self._log(execution_id, "SIGN", user, "COMPLETED", "SIGNED")
        await self.db.commit()

        # 更新执行点
        await self.db.execute(
            update(M08ExecPoint)
            .where(M08ExecPoint.id == row.point_id)
            .values(
                status="EXECUTED",
                executed_at=row.executed_at,
                executed_by=user["employee_id"],
                executed_by_name=user["employee_name"],
                execution_no=row.execution_no,
                execution_source="M08-03",
            )
        )
        await self.db.commit()

        # 异步回写 M07
        await writeback_m07_task.delay(execution_id, "SIGNED")

        return {
            "execution_id": execution_id,
            "execution_no": row.execution_no,
            "status": "SIGNED",
            "executed_at": row.executed_at.isoformat() if row.executed_at else None,
            "signed_at": now.isoformat(),
            "signature_digest": digest,
            "signature_source": row.signature_source,
            "timestamp_serial": row.timestamp_serial,
            "writeback": {"status": "PENDING", "on_executing": True, "on_completed": None},
            "order_status": "EXECUTING",
            "point_status": "EXECUTED",
        }

    async def _verify_sign_password(self, employee_id: int, password: str) -> None:
        key = "m08:sign:fail:%s" % employee_id
        fails = int(await redis_client.get(key) or 0)
        if fails >= MAX_SIGN_PASSWORD_FAILS:
            raise BizException("0803013", "签名口令错误次数过多，请 5 分钟后重试")

        try:
            ok = await M02Client.verify_sign_password(employee_id, password)
        except Exception:
            logger.exception("签名服务不可用 employee_id=%s", employee_id)
            raise BizException("0803011", "签名服务不可用，无法完成执行")

        if not ok:
            await redis_client.incr(key)
            await redis_client.expire(key, SIGN_LOCK_SECONDS)
            raise BizException("0803012", "签名口令错误")

        await redis_client.delete(key)

    def _sign_digest(self, row: M08Execution) -> str:
        parts = []
        for field in SIGN_FIELDS:
            value = getattr(row, field, None)
            if value is None:
                parts.append("")
            elif isinstance(value, datetime):
                parts.append(value.strftime("%Y-%m-%dT%H:%M:%S"))
            elif isinstance(value, Decimal):
                parts.append(str(value))
            else:
                parts.append(str(value))
        payload = "|".join(parts)
        return hashlib.sha256(payload.encode("utf-8")).hexdigest()

    def _digest(self, data: dict) -> str:
        payload = "|".join("%s=%s" % (k, data[k]) for k in sorted(data))
        return hashlib.sha256(payload.encode("utf-8")).hexdigest()
```

### 6.7 专题：签名可靠性与回写一致性

**问题：** 签名已落库但 M07 回写失败时，系统处于什么状态？

**分析四种可能的处理策略：**

| 策略 | 做法 | 风险 | 结论 |
|---|---|---|---|
| A 同步事务 | 签名与回写同一事务 | M07 慢则护士等待；M07 挂了签名全部失败，执行记录丢失 | ❌ |
| B 两阶段提交 | 跨服务 2PC | PostgreSQL 与 HTTP 服务无法 2PC；复杂度极高 | ❌ |
| C 本地消息表 | 签名事务内写 outbox，异步投递 | 需要额外 outbox 表与投递器 | ✅（但重） |
| **D 状态字段 + 补偿扫描** | 签名事务内置 `writeback_status='PENDING'`，扫描器重试 | 状态机简单；最坏情况需人工兜底 | **✅ 采用** |

**采用 D 的理由：**

1. **只涉及一个下游**（M07），不需要通用 outbox 方案
2. **`m08_execution` 本身就是天然的 outbox 表**——`writeback_status` 字段就是投递状态
3. **扫描器的查询成本极低**——部分索引 `idx_m08_exec_writeback (writeback_status) WHERE writeback_status IN ('PENDING','FAILED')`，稳态只有几行

**扫描器实现要点：**

```python
# 每 30 秒执行
PENDING_STATUS = ("PENDING", "FAILED")
BACKOFF = (1, 2, 4, 8, 16, 32, 64, 128, 256, 512)

async def scan_writeback() -> None:
    """扫描待回写记录并重试。"""
    rows = await fetch_pending(limit=100)
    for row in rows:
        if row.retry_count >= MAX_RETRY:
            await mark_dead(row.id)
            continue
        delay = BACKOFF[min(row.retry_count, len(BACKOFF) - 1)]
        if row.last_retry_at and (now() - row.last_retry_at).seconds < delay:
            continue
        await retry_one(row)
```

**为什么先 `on-executing` 再 `on-completed`？**

M07 的状态机要求 `PAID → EXECUTING → COMPLETED`，不能跳步。若只发 `on-completed`，M07 会拒绝（状态不合法）。因此 M08-03 在 `submit_check` 成功后立即异步发 `on-executing`（此时 M07 置 `EXECUTING`），在 `sign` 成功后发 `on-completed`。

**若 `on-executing` 失败而 `on-completed` 成功会怎样？**

M07 收到 `on-completed` 时若当前状态是 `PAID`（未经过 EXECUTING），按 M07-03 契约会直接置 `COMPLETED`（幂等兼容）。这是 M07 侧的设计（见 M07-03 §6.4）。M08-03 通过 `writeback_note` 记录「跳过了 EXECUTING」，供质控核查。

**容量估算：**

| Key 模式 | 单值大小 | 数量 | 占用 |
|---|---|---|---|
| `m08:execution:{id}` | 约 2 KB | 800（活跃） | 1.6 MB |
| `m08:execution:by-order:{order_id}` | 约 3 KB | 400 | 1.2 MB |
| `m08:exec:seq:*` | 20 B | 2 | 40 B |
| `m08:exec:lock:*` | 40 B | 20 | 0.8 KB |
| `m08:exec:verify:*` | 200 B | 50 | 10 KB |
| `m08:sign:fail:*` | 20 B | 30 | 0.6 KB |
| `m08:exec:check-tpl:*` | 5 KB | 8 | 40 KB |
| `m08:exec:stat:*` | 1 KB | 12 | 12 KB |
| **合计** | | | **约 2.9 MB** |

**为什么执行记录详情要缓存？**

护士在 P02 执行登记页会反复进出（核对 → 拍照 → 回来继续）。每次拉详情要做 3 次查询（主表 + 核对记录 + 附件）。缓存后从 12ms 降到 2ms。TTL 300 秒足够覆盖一次执行过程。

**缓存失效策略：**

- 任何写操作（`update`/`submit_check`/`record`/`sign`/`void`）后删除 `m08:execution:{id}`
- `by-order` 缓存在 `sign` 后失效

```python
from celery import shared_task

from app.core.db import AsyncSessionLocal
from app.modules.m08_03.clients import M07Client

logger = logging.getLogger(__name__)


@shared_task(bind=True, max_retries=10, default_retry_delay=30)
def writeback_m07_task(self, execution_id: int, stage: str) -> dict:
    """回写 M07（on-executing / on-completed）。

    Args:
        execution_id: 执行记录 ID
        stage: EXECUTING / SIGNED

    Returns:
        回写结果
    """
    import asyncio

    async def _run() -> dict:
        async with AsyncSessionLocal() as db:
            row = await db.get(M08Execution, execution_id)
            if not row:
                return {"ok": False, "reason": "not_found"}
            if row.writeback_status == "SUCCESS":
                return {"ok": True, "reason": "already_success"}

            payload = {
                "order_id": row.order_id,
                "order_no": row.order_no,
                "executor_module": "M08",
                "executed_at": row.executed_at.isoformat() if row.executed_at else None,

                    "exception_type": row.exception_type,
                    "signed_at": row.signed_at.isoformat() if row.signed_at else None,
                },
                "remark": row.remark,
            }

            try:
                if stage == "EXECUTING":
                    await M07Client.on_executing(payload)
                else:
                    await M07Client.on_completed(payload)
                row.writeback_status = "SUCCESS"
                row.writeback_at = datetime.now()
                row.writeback_retry = 0
            except Exception as exc:
                row.writeback_status = "FAILED"
                row.writeback_retry = (row.writeback_retry or 0) + 1
                row.writeback_error = str(exc)[:500]
                await db.commit()
                raise

            await db.commit()
            return {"ok": True, "stage": stage}

    import asyncio

    return asyncio.run(_run())
```

### 9.2 权限矩阵

| 责任护士 | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |

**为什么系统管理员没有任何权限？**

执行记录含患者诊断、用药、部位照片——这是最敏感的临床数据。IT 岗位不应看到。运维排查走「审计日志只读」且姓名已脱敏。

|---|---|

| 护士长 | 本病区及其下级（`DEPT_TREE`） |
| 护理部干事 / 质控专员 | 全院（`HOSPITAL`） |

### 9.4 脱敏规则

| 字段 | 脱敏规则 | 适用角色 |
|---|---|---|
| `patient_name` | 保留姓，名用 `*` | 质控专员以外的非临床角色 |
| `bed_no` | 不脱敏 | — |
| `remark` | 不脱敏 | — |
| 附件照片 | 质控专员查看时加水印（含工号与时间） | 质控专员 |

### 9.5 安全措施

| 措施 | 说明 |
|---|---|
| **签名二次认证** | 登录态不能作为签名依据，必须输口令 |
| **签名摘要** | SHA-256 over 14 个关键字段 + salt |
| **可信时间戳** | M02-05 RFC 3161 时间戳 |
| **执行时间限制** | 不允许未来时间、不允许跨日 |
| **身份核对锁定** | 连续 2 次不符锁定，需护士长解锁 |
| **附件安全** | 类型白名单（jpg/png）、大小限制、病毒扫描、SHA-256 去重 |
| **敏感操作审计** | 签名/作废/解锁/导出全部写审计 |
| **防重放** | `idempotency_key` 唯一索引 |
| **会话绑定** | 双人核对要求两人 `session_id` 不同 |
| **操作留痕** | `m08_execution_log` 只增，全量记录状态变更 |

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 示例 | 处理方式 |
|---|---|---|
| **参数校验异常** | 缺字段、格式错 | 返回 `"0803xxx"`，前端表单提示 |
| **业务规则异常** | 核对未通过、双签缺失 | 返回 `"0803xxx"`，前端引导操作 |
| **依赖服务异常** | M07 不可用、M02-05 不可用 | 阻断或降级，记 ERROR 日志 |
| **数据一致性异常** | 执行点已被其他记录占用 | 返回 `"0803001"`，提示刷新 |
| **并发冲突** | 同时签名 | 乐观锁 + 唯一索引，后到者报 `"0803014"` |
| **系统异常** | DB 超时、Redis 不可用 | 返回 `50000`，记 ERROR + 告警 |
