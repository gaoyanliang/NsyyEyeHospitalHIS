## 1. 模块概述

### 1.1 模块定位

M08-06 用药与滴眼液执行是护士站**给药动作的唯一记录方**。它回答三个问题：

1. 这瓶药**该不该现在给**（时间、间隔、眼别、剂量对不对）；
2. 给完之后**留下了什么**（谁、什么时间、哪只眼、多少量、开瓶多久）；
3. 没按计划给的时候**为什么**（患者拒绝、药没了、患者不在）。

### 1.2 为什么独立成子模块

**理由一：滴眼的物理约束在整个人类给药方式里独一无二。**

人的结膜囊容量只有 **7~10 μL**，而一滴眼药水是 **30 μL** 左右。也就是说——**滴一滴已经溢出 3~4 倍，滴第二滴必然把第一滴冲走**。

这不是「效果差点」的问题，是**药被冲没了**的问题。眼科教科书明确要求：同一只眼两种滴眼液之间至少间隔 **5 分钟**，先用凝胶/膏剂再用水溶液则要间隔 **10 分钟**。

把这条规则放到 M08-03 通用执行里，结果是：M08-03 要为一类特殊的「时间依赖」逻辑长出一条分支，而这条分支只对滴眼液有意义。

**理由二：左右眼是两次独立给药，不是一次。**

一条医嘱「妥布霉素滴眼液 双眼 每日四次 连用三天」，在护士站是 **4 × 3 × 2 = 24 次独立的给药动作**：

- 四个时间点各一次，每次两只眼；
- 两只眼要分开记录（左眼滴了、右眼忘了，是两回事）；
- 两只眼可能间隔不同（右眼术后需压迫泪囊 2 分钟，左眼不用）；
- 计费时按眼计费（`md_charge_item.charge_by_eye = TRUE`）；
- 差错统计按眼统计（「本月右眼滴错 2 次」）。

**M08-02 执行计划**负责把它展开成 24 个执行点；**M08-06**负责把这 24 次实际动作记录下来。两者的分野是「计划」与「事实」。

**理由三：开瓶效期是滴眼液独有的、无法从主数据推导的状态。**

一瓶妥布霉素滴眼液瓶身标注有效期 24 个月，但**开封后有效期只有 28 天**（部分防腐剂含量低的品种只有 7 天）。开封日期不是采购信息、不是药品属性，是**护士在病床边的动作**。

M01-03 的 `mdm_drug.after_open_shelf_life` 字段记录「开封后几天失效」，但**真正开封是哪一天，只有 M08-06 知道**。这个日期决定这瓶药还能不能继续用。

如果不管这条：患者拿到一瓶已经开了 40 天的眼药水，被污染的药液直接滴进眼睛——眼科最怕的就是这个。

**理由四：全身与局部双重给药在眼科极常见，需要交叉提示。**

青光眼患者典型方案：

- 口服乙酰唑胺 250 mg TID（全身降眼压）；
- 滴眼噻吗洛尔 BID（局部降眼压）；
- 两者都降眼压，叠加可能导致心率过缓；
- 而噻吗洛尔是β受体阻滞剂，全身吸收后正是减慢心率的原因。

护士在滴眼时是看不到患者今天吃了什么的。M08-06 需要在执行前把「今天该患者已执行的全身用药」和「本次要滴的药」摆在一起，提示「β受体阻滞剂 + 口服碳酸酐酶抑制剂，给药后 30 分钟测脉率」。

**理由五：用药执行差错是护理不良事件的第一大类。**

《护理不良事件分类标准》里给药差错（错误患者、错误药品、错误剂量、错误途径、错误时间、错误眼别）占比最高。所有差错都需要在**执行时**就能被系统拦住或至少留下痕迹，而不是事后追溯。

M08-06 是唯一能拦住「滴错眼」的位置——因为只有它知道上一次滴的是哪只眼。

### 1.4 概念辨析

**（一）用药执行 vs 医嘱执行**

| 维度 | 用药执行（M08-06） | 医嘱执行（M08-03） |
|---|---|---|
| 对象 | 药品（有剂量、途径、浓度） | 医嘱（可能是治疗、护理操作） |
| 核心风险 | 滴错眼、间隔不够、药已过期 | 执行错患者、漏执行 |
| 记录粒度 | 每一次、每一只眼 | 每一条医嘱 |
| 特殊规则 | 最小间隔、滴入顺序、开瓶效期 | 通用核对项、双人核对 |

严格说 M08-06 是 M08-03 的特化，但特化程度足够高（差 5 条核心规则），独立成子模块。

**（二）开瓶日期 vs 有效期**

| 概念 | 来源 | 示例 |
|---|---|---|
| 有效期（未开封） | 药品说明书，M01-03 `shelf_life_months` | 妥布霉素滴眼液 24 个月 |
| 开封日期 | 护士第一次拧开瓶盖的动作 | 2026-10-15 |
| **开封后效期** | M01-03 `after_open_shelf_life` | 28 天 |
| **实际失效日** | 开封日期 + 开封后效期 | 2026-11-12 |

关键：**未开封有效期与开封后效期是两个独立的到期日，取较早者**。一瓶 2027-12 到期的眼药水，2026-10-15 开封，2026-11-12 就失效了。

**（三）滴眼 vs 涂眼膏**

| 维度 | 滴眼液 | 眼膏 |
|---|---|---|
| 容量 | 一滴约 30 μL | 一条约 1 cm |
| 视觉影响 | 短暂模糊 1~2 分钟 | 严重模糊 15~30 分钟 |
| 使用时段 | 全天 | **通常睡前** |
| 与其他药间隔 | ≥5 分钟 | 膏剂在最后（或水剂后 ≥10 分钟） |

**眼部用药顺序铁律：先水剂后膏剂**。膏剂黏稠会阻挡后续水剂吸收，反了就白滴。

**（四）给药记录 vs 发药记录**

| 概念 | 归属 | 含义 |
|---|---|---|
| 发药（Dispense） | M14-07 / M14-08 | 药房把药交给患者/病区 |
| 摆药（Ward Dispense） | M14-08 | 住院药房按病区按班次配药 |
| **给药（Administration）** | **M08-06** | **护士把药送到患者体内** |

三者数量关系：发药 1 盒（30 滴）→ 摆药按天分装 → 给药 24 次。**只有给药次数才对应计费与疗效**。

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 用药执行率 | ≥ 98% | 已执行/应执行（不含患者拒绝） |
| 滴眼间隔合规率 | 100% | 同眼同药间隔 ≥ 5 分钟 |
| 眼别正确率 | 100% | 滴错眼为零容忍 |
| 开瓶效期拦截率 | 100% | 超效期药品必须拦截 |
| 规定时间窗内执行率 | ≥ 95% | 计划时间 ±60 分钟 |
| 双人核对执行率 | 100% | 麻精/高危药品 |
| 不良反应上报及时率 | 100% | 出现后 2 小时内 |
| 单次给药记录耗时 | ≤ 20 秒 | 从点任务到签名完成 |

## 2. 业务范围与边界

### 2.1 范围内

1. 滴眼液、眼膏、眼用凝胶的给药执行与记录；
2. 口服、注射、外用、雾化等全身给药的执行与记录；
3. 用药前的五项核对（患者、药品、剂量、途径、时间）与眼别核对；
4. **最小间隔校验**（同眼同药 ≥5 分钟，同眼不同药 ≥5 分钟）；
5. **滴入顺序引导**（同眼多药时的先后顺序）；
6. **开瓶登记与开封后效期跟踪**；
7. 全身用药与局部用药的相互作用提示（只提示不拦截）；
8. 特殊管理药品的双人核对与执行；
9. 用药异常登记（患者拒绝、药品缺失、不良反应、外渗）；
10. 用药依从性统计（按患者、按护士、按病区、按药品）。

### 2.2 范围外

| 不做的事 | 归属 |
|---|---|
| 药品主数据（名称、规格、浓度、开封效期天数） | M01-03 |
| 用药频次定义（QID、TID 的具体时间点） | M01-10 |
| 医嘱开具与停止 | M07-03 |
| 处方审核与合理用药审查 | M14-06 |
| 药房发药、摆药、退药 | M14-07 / M14-08 |
| 药品库存与批次 | M14-01 |
| 特殊药品专柜与逐支登记 | M14-09 |
| 执行计划的频次展开与眼别拆点 | M08-02 |
| 任务排队与认领 | M08-01 |
| 通用核对项与电子签名 | M08-03（M08-06 复用其签名机制） |
| 护理记录正文书写 | M08-05 |
| 用药差错定级与不良事件上报（院级） | M08-05 + M02 审计 |

### 2.3 与相邻模块的分工边界

**与 M14 药房的边界：** 一句话——**M14 管「药在哪、有几支」，M08-06 管「药进了谁的眼睛」。**

M14-08 住院药房摆药完成后推送 `m14.ward_dispense.received`，M08-06 接收后把病区可用的药品批次登记到本地快照 `m08_med_stock_snap`，护士执行时从这里选批次。**M08-06 不写 M14 的库存表**——给药不扣库存（摆药时已扣）。

**与 M07 医生的边界：** M07-03 开医嘱，M08-06 执行后回写 `on-executing` / `on-completed`。

**与 M08-03 的边界：** M08-06 复用 M08-03 的签名机制（`SIGN_FIELDS`、M02-05 口令校验、时间戳），但签名摘要的字段不同（M08-06 要覆盖眼别、滴数、开瓶日、间隔校验结果）。

## 3. 业务模型

### 3.1 用药执行的四道关口

护士从看任务到给药完成，必须依次通过四道关口，任何一道不通过都不能继续：

```
┌─────────────────────────────────────────────────────────────┐
│ 关口一：患者核对                                             │
│ ─ 腕带扫码 / 就诊卡 / 双项手输                                │
│ ─ 姓名 + 床号 双匹配                                          │
│ ─ 失败 2 次锁定，需护士长授权                                  │
└────────────────────────────┬────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 关口二：药品核对                                             │
│ ─ 扫码或选择实发药品                                          │
│ ─ 校验：药品编码、规格、浓度                                  │
│ ─ 校验：开封效期未过期                                        │
│ ─ 校验：批次与摆药记录一致                                     │
└────────────────────────────┬────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 关口三：时间与间隔校验  ← 滴眼液特有                          │
│ ─ 计划时间偏差 ±60 分钟内                                     │
│ ─ 同眼同药间隔 ≥5 分钟                                        │
│ ─ 同眼任意两药间隔 ≥5 分钟                                    │
│ ─ 本节眼别与上节眼别（不可滴错）                               │
└────────────────────────────┬────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────┐
│ 关口四：剂量与途径核对                                        │
│ ─ 滴数 / 片数 / 毫升数                                        │
│ ─ 眼别（OD / OS / OU）                                       │
│ ─ 给药途径（滴眼 / 涂眼 / 口服 / 皮下）                          │
└────────────────────────────┬────────────────────────────────┘
                             ▼
                     执行 + 记录 + 签名
```

**为什么关口顺序是「患者→药品→时间→剂量」而不能颠倒：**

如果先校验间隔再核对患者，护士会先纠结「才过 4 分钟」，然后被这个提示吸引注意力，反而忽略了手里拿的药是不是这个患者的。**先确认对象，再校验规则**是给药安全的基本顺序。

### 3.2 滴眼液给药的特殊性

**（一）结膜囊容量与溢出**

| 参数 | 数值 | 来源 |
|---|---|---|
| 结膜囊容量 | 7~10 μL | 眼科药理学 |
| 标准滴眼液一滴 | 约 30 μL | 眼药水瓶口设计 |
| 实际滞留 | 约 7 μL | 其余溢出 |

结论：**一滴已经足够，滴两滴不会增加吸收，只会增加全身副作用与浪费**。

因此 M08-06 对滴眼液**禁止填写滴数 > 2**（大于 2 走异常审批）。这与口服药「两片」完全不同。

**（二）泪液稀释与压迫泪囊**

滴眼后正常眨眼与泪液流动会在 **2 分钟内**把药液冲走约 50%。规范操作要求：

1. 滴入下穹窿（不是角膜正中）；
2. 滴完轻闭眼 1~2 分钟；
3. **按压内眦泪囊区 2~3 分钟**，减少药液经鼻泪管流入鼻腔被吸收。

第 3 条对 **β受体阻滞剂（噻吗洛尔、卡替洛尔）** 尤其重要——不压迫则大量药物进入鼻腔黏膜吸收，直接进入体循环，可能引起心率下降与支气管痉挛。

M08-06 在滴眼页把「按压泪囊 2 分钟」作为**必选核对项**，对 β受体阻滞剂类更是**强制计时**。

**（三）左右眼不可混淆**

| 场景 | 后果 |
|---|---|
| 右眼术后用药滴到左眼 | 健眼被激素/抗生素影响，术眼没治疗 |
| 左眼散瞳药滴到右眼 | 双眼视力模糊，患者跌倒风险 |
| 单眼用药记为双眼 | 计费多收，且掩盖了漏滴 |

M08-06 的防护：

1. **每次执行必须显式选眼别**，不预填上一次的；
2. 界面上**用大号字与颜色区分**（右眼 OD 蓝色，左眼 OS 橙色，双眼 OU 灰色）；
3. 同一时刻双眼都滴时，**强制先右后左**（与病历书写惯例一致），并在 P04 引导页显示当前是第几只眼；
4. 签名摘要包含眼别，事后无法改。

**（四）眼膏与滴眼液的顺序**

```
正确顺序：水剂（滴眼液） → 悬液 → 凝胶 → 眼膏
每次切换间隔 ≥5 分钟（膏在后则 10 分钟）
```

如果先涂眼膏再滴眼药水，膏剂的脂质基质会把水剂挡在外面，等于没滴。M08-06 在 P04 引导页按剂型排序显示，并在顺序错误时阻断。

### 3.3 双眼多药的滴入顺序规则

眼科患者常同时使用 3~5 种滴眼液。同一只眼在一个时刻可能要滴多种药，顺序不能随便：

**规则一：先清后浊。** 溶液剂先于混悬剂（混悬剂颗粒会遮挡溶液剂吸收）。

**规则二：先水后油。** 滴眼液先于凝胶，凝胶先于眼膏。

**规则三：同一剂型内先轻后重。**

| 项目 | 顺序 | 理由 |
|---|---|---|
| 抗生素 | 第 1 位 | 需要接触面清洁 |
| 降眼压药 | 第 2 位 | 优先保障视力安全 |
| 糖皮质激素 | 第 3 位 | 激素可增加渗透 |
| 人工泪液 | **最后** | 起到润滑与稀释作用，会冲走其他药 |
| 散瞳/缩瞳药 | 单独安排 | 与其他药冲突最多 |

**规则四：间隔 ≥5 分钟。** 见 3.4。

**规则五：同眼同药不重复。** 若计划表因数据问题出现同一药品同一时刻两个点，只执行一次（后一个点标记 `DUPLICATE_MERGED`）。

**规则六：说明书/处方有明确顺序的以说明书为准。** 如「复方托吡卡胺 + 去氧肾上腺素」有厂家指定顺序时，按厂家。

### 3.4 最小间隔校验机制

**（一）两类间隔校验**

| 校验类型 | 规则 | 强度 |
|---|---|---|
| **同眼同药** | 同一只眼、同一药品，两次滴入间隔 ≥ `MIN_INTERVAL_SAME_DRUG`（默认 5 分钟） | **阻断** |
| **同眼不同药** | 同一只眼、任意两滴，间隔 ≥ `MIN_INTERVAL_DIFF_DRUG`（默认 5 分钟） | **阻断** |

**为什么同眼不同药也要拦：** 结膜囊只有 7~10 μL。第一滴刚滴进去 1 分钟，第二滴就把第一滴冲走了——这和「同一种药连滴两次」的后果一样：前一种药等于没滴。

**（二）数据来源**

M01-10 `md_frequency` 表有 `min_interval_minutes` 与 `is_eye_drop` 两个字段：

- `is_eye_drop = TRUE` 的频次（如「滴眼 QID」），`min_interval_minutes` **默认 5**；
- 特殊药品（如高浓度阿托品需要 10 分钟）可在 M01-10 单独配。

M08-06 的取值优先级：

```
① md_frequency.min_interval_minutes（该频次显式配置）
② md_drug_special_rule.min_interval_minutes（按药品覆盖）
③ M08.MEDIC.MIN_INTERVAL_SAME_DRUG（全局默认 5）
```

**（三）校验时机**

| 时机 | 行为 |
|---|---|
| 打开滴眼页 | 查询该患者、该眼别的上一次滴入记录，显示「距上次 4 分 20 秒」 |
| 点提交 | **再次校验**（可能从打开到提交过去了 3 分钟，也可能用户在旧页面停留） |
| 后端落库前 | 第三次校验（防并发：另一台护士站同时滴了同眼） |

**三重校验的理由：** 前端校验为了体验（早提示），提交时校验为了准确，落库前校验为了并发安全。少了任何一个都会留下漏洞。

**（四）超间隔的处理**

如果护士确实要在 5 分钟内滴两种药（例如临床确需，或上一个点拖到了来不及），必须走**超间隔授权**：

1. 填写原因（≥10 字）；
2. 护士长在 **2 分钟内**在线确认（弹窗）；
3. 记录 `interval_override = TRUE` + `override_reason` + `override_by`；
4. 事后统计「超间隔授权率」，超过 2% 需护理部核查。

**不允许的路径：** 直接修改上次记录的时间来「制造」间隔。`m08_medication_admin.actual_time` 是签名覆盖字段，改了签名失效。

### 3.5 滴眼液开封效期管理

**（一）为什么必须单独管**

| 场景 | 后果 |
|---|---|
| 一瓶共用眼药水开了 50 天还在用 | 药液被细菌污染，可能引起细菌性角膜炎 |
| 患者出院后带回家继续用 | 家里放 3 个月后继续滴，已失效 |
| 一瓶药给两个患者用 | **医院绝对禁止**，交叉感染 |

《中国国家处方集》与药品说明书普遍规定：**多剂量眼用制剂开封后使用不超过 4 周（28 天）**；部分不含防腐剂的单剂量包装为**一次性使用，开封即弃**。

**（二）开封登记的三类药**

| 药品类型 | 开封规则 | M01-03 标志 |
|---|---|---|
| 多剂量瓶装（有防腐剂） | 开封后 `after_open_shelf_life` 天（默认 28） | `is_eye_drop = TRUE` 且 `after_open_shelf_life > 0` |
| 单剂量包装（无防腐剂） | **立即使用，开封即弃** | `after_open_shelf_life = 0` 或 `is_single_dose = TRUE` |
| 眼膏管装 | 开封后 30 天（管口污染风险） | `after_open_shelf_life = 30` |

**（三）开封登记时机**

护士**第一次拧开瓶盖**时，在 P05「滴眼液开封登记」页扫码登记：

- 药品编码；
- 批次号；
- 开封时刻（默认当前，可回溯到 4 小时内）；
- **开封人**；
- 关联患者（若为病区共用瓶则记「病区共用」，但**同一瓶不得用于两个患者**，系统校验）。

**（四）执行时校验**

```
if 该瓶药 has_open_record:
    if now() > open_time + after_open_shelf_life:
        → 阻断：该瓶眼药水已开封 XX 天，超过 X 天有效期，请更换新瓶
    elif now() > open_time + after_open_shelf_life - 3 天:
        → 警告：该瓶眼药水将在 X 天后过期
else:
    if 该药品 is_eye_drop and after_open_shelf_life > 0:
        → 提示：请先完成开封登记
```

**（五）到期后的处置**

到期药品不能直接丢——需要走**病区药品报废**流程：

1. 系统生成「过期药品清单」；
2. 护士提交报废，销毁人双人签字；
3. 回写 M14-01 库存（`EXPIRED_DESTROY`）。

**（六）多患者禁忌**

系统硬约束：**一瓶开封后的眼药水只能关联一个患者**。若病区确实需要共用（如散瞳药多人使用），必须使用**单剂量包装**，开封即弃。

这条规则在 `m08_eye_drop_open` 表上用唯一索引实现。

### 3.6 全身与局部双重给药的相互作用提示

**（一）为什么需要提示**

眼科最常见的三重叠加：

```
青光眼患者：
  口服乙酰唑胺 250 mg TID          （全身降眼压）
  + 滴眼噻吗洛尔 BID               （局部 β 阻滞，全身吸收后又降心率）
  + 口服氯化钾（补钾，因乙酰唑胺丢钾）
```

叠加后果：

- 心率过缓（β阻滞 + 碳酸酐酶抑制）；
- 低钾血症（乙酰唑胺排钾）；
- 若患者还有哮喘，噻莫洛尔全身吸收可诱发支气管痉挛。

护士在床边只看到手里这瓶眼药水，看不到患者今天吃了什么。**M08-06 必须把两边的信息摆到一起。**

**（二）提示而不拦截**

与最小间隔的「阻断」不同，交叉作用是**提示**：

| 提示级别 | 触发 | 界面表现 |
|---|---|---|
| `INFO` | 降眼压药 + 口服降压药 | 黄色文字提示，无需确认 |
| `WARN` | β阻滞滴眼液 + 口服β阻滞剂 | 橙色提示 + 需勾选「已告知患者」 |
| `BLOCK` | 已知禁忌组合 | 红色阻断（极少，一般 M14-06 已拦） |

**（三）规则来源**

| 规则 | 数据来源 |
|---|---|
| 同类药物叠加 | M01-03 `pharmacology_class` 相同 |
| DDI 互斥 | M01-03 `mdm_drug_ddi` |
| 特殊生理监测 | M08-06 内置规则表（如β阻滞→测脉率） |

**为什么不全部依赖 M01-03 的 DDI：** 因为 M01-03 管的是「两个药的相互作用」，而这里要管的是「一个药滴进眼睛后全身吸收，与口服药叠加」。后者不是药物直接相互作用，而是**给药途径特异性的全身效应**，需要在 M08-06 手工维护少量规则。

**（四）给药后监测**

对 `WARN` 级别，M08-06 自动生成一条**给药后监测任务**：

- β阻滞类滴眼液 → 30 分钟后测脉率，低于 60 次/分报警；
- 阿托品类 → 4 小时内观察有无中毒表现（口干、面红、心率快、烦躁）；
- 碳酸酐酶抑制剂口服 → 出院前复查血钾。

### 3.7 特殊管理药品的双人核对

**（一）哪些药需要双人核对**

| 类别 | 标志 | 核对内容 |
|---|---|---|
| 麻醉药品 | `is_narcotic = TRUE` | 逐支编号、双人签字、空安瓿回收 |
| 一类精神药品 | `management_class = 'PSYCHOTROPIC_1'` | 双人签字 |
| 高警示药品 | `is_high_risk = TRUE` | 双人签字 |
| 化疗药 | `pharmacology_class` 含抗肿瘤 | 双人签字 + 防护装备确认 |
| 医嘱指定 | `m07_order.need_double_check = TRUE` | 双人签字 |

**（二）双人核对的三个硬约束**

1. **执行人 ≠ 核对人**（DB 约束 `ck_m08_med_sod`）；
2. **两人签名时间差 ≥ 5 秒**（`DOUBLE_CHECK_MIN_GAP_SECONDS`），防止一人代签；
3. **两人 session 不同**（同一浏览器窗口不可能换人）。

**（三）麻醉药品的额外要求**

- 逐支编号登记（走 M14-09 `m14_special_record`）；
- **空安瓿必须回收**，`m08_eye_drop` 与 `m08_medication_admin` 都不处理空瓿——空瓿回收在 M14-09；
- M08-06 只记录给药动作，并在执行后调用 M14-09 `POST /internal/v1/m14/special/register` 完成逐支登记。

**（四）双人核对失败的处理**

| 情况 | 处理 |
|---|---|
| 另一人不在场 | 报 `"0806019"`，不允许单人执行 |
| 另一人没有授权 | 报 `"0806020"` |
| 两人时间差 < 5 秒 | 报 `"0806021"`，提示重新分别签名 |

### 3.8 用药异常与不良反应处理

**（一）六类用药异常**

| 代码 | 名称 | 说明 | 后续动作 |
|---|---|---|---|
| `PATIENT_REFUSED` | 患者拒绝用药 | 患者明确表示不愿使用 | 通知医生，记入依从性 |
| `PATIENT_ABSENT` | 患者不在 | 外出检查/离院 | 重排到最近时段 |
| `DRUG_UNAVAILABLE` | 药品缺失 | 病区无药或数量不足 | 通知药房，记缺药 |
| `DRUG_EXPIRED` | 药品过期 | 超过开封效期 | 报废，换新瓶 |
| `ADVERSE_REACTION` | 不良反应 | 用药后出现异常 | **必须拍照**，2 小时内上报 |
| `OTHER` | 其他 | | 说明 ≥10 字 |

**（二）不良反应的分级与上报**

| 级别 | 表现 | 上报时限 | 上报对象 |
|---|---|---|---|
| 轻度 | 局部刺激、轻度充血 | 24 小时 | 主管医生 + 护理部 |
| 中度 | 明显红肿、视物模糊加重 | 2 小时 | 主管医生 + 护士长 + 药学部 |
| 重度 | 过敏性休克、喉头水肿 | **立即** | 全院应急 + 上报药监 |

M08-06 记录不良反应后：

1. 立即生成告警推给责任医生与护士长；
2. 中度及以上自动在 M08-05 生成「护理记录待写」任务；
3. 中度及以上调用 M14-06 的 `POST /internal/v1/m14/rx-review/adverse-report` 触发药学评价（若 M14-06 未实现则降级为只通知）。

**（三）用完丢弃与药品报废的区别**

| 概念 | 触发 | 处理 |
|---|---|---|
| 用完丢弃 | 药液用尽 | 直接废弃，无记录 |
| 过期报废 | 超过开封效期 | 走报废流程，双人销毁 |
| 破损报废 | 打碎/漏液 | 走报废流程，需说明 |

### 3.9 用药与 M14 发药的边界

**（一）一次用药的完整链路**

```
M07 开医嘱 ──► M14-06 药师审核 ──► M16 收费 ──► M14-07/08 发药/摆药
                                                          │
                                                          ▼
                                              m14.ward_dispense.received
                                                          │
                                                          ▼
                    ┌──────────────────────────────────────────┐
                    │ M08-06 接收摆药通知                       │
                    │  ├─ 登记到 m08_med_stock_snap（病区可用） │
                    │  ├─ 首次使用 → 走开封登记                 │
                    │  └─ 到期 → 走报废                        │
                    └──────────────────────────────────────────┘
                                                          │
                                                          ▼
                                              护士给药 → M08-06 记录
                                                          │
                                                          ▼
                                              M07 on-completed 回写
```

**（二）M08-06 不碰库存的三个理由**

1. **库存只有一个真相源**（M14-01 `m14_stock_txn`），M08-06 若也扣库存会双写；
2. **给药不改变库存数量**——摆药时药已经从药房库扣到病区二级库，给药是病区内物品到患者的变化，在 M14 的账上体现为「已发到患者」（`m14_dispense`），不需要 M08 再记一次；
3. **护士不该有库存操作权限**——库存操作的权限模型是仓库管理员，与给药权限完全不同。

**（三）M08-06 需要知道的库存信息**

只需要三样（缓存在 `m08_med_stock_snap`，10 分钟刷新）：

- 病区有哪些批次可用（药品编码 + 批次 + 数量）；
- 每个批次的效期（用于提前预警）；
- 是否已开封、开封日期。

### 3.10 依从性统计模型

**（一）为什么需要依从性统计**

```text
患者视角：护士该给我滴 4 次/天，实际滴了几次？        → 用药依从性
护士视角：我该做 30 次给药，实际做了几次？做了几次晚了？→ 执行依从性
管理视角：哪个病区依从性最差？哪类药最容易被漏？      → 质量改进
```

**（二）三个核心指标**

| 指标 | 公式 | 说明 |
|---|---|---|
| **执行率** | 已执行点 / 应执行点 | 应执行 = 计划点 − 医嘱停用 − 患者出院 |
| **及时率** | 时间窗内执行点 / 已执行点 | 时间窗 = 计划时间 −30 分钟 ~ +60 分钟 |
| **完成率** | 已执行点 / 全部计划点 | 反映漏做与拒绝 |

**（三）与 M08-02 的配合**

M08-02 展开执行点（计划），M08-06 记录执行事实。依从性统计在 M08-06 做，因为它同时需要计划与事实两张表。

**（四）统计维度**

- 按患者（用于出院小结「住院期间用药执行率 96%」）；
- 按护士（用于绩效，**但要看是「漏做」还是「患者拒绝」**）；
- 按病区（用于护理部质控）；
- 按药品（用于「哪种药最容易被漏」）；
- 按时间段（用于「哪个班次最忙」）。

**（五）超间隔授权率**

```
超间隔授权率 = 超间隔授权次数 / 滴眼执行总次数
```

阈值 **2%**。超过说明：

- 计划排得太密（M08-02 参数问题）；
- 病区人手不足；
- 护士习惯性批量操作。

```
│            │ 阿托品眼膏 1%        膏剂      散瞳类                            │ │
│            │ 眼别：双眼 OU     ← 膏剂最后（水剂后 ≥10 分钟）                  │ │
│            │ 状态：⏸ 等待                                                      │ │
│            └────────────────────────────────────────────────────────────────┘ │
│                                                                                │
├────────────────────────────────────────────────────────────────────────────────┤
│ 说明：本顺序由「先清后浊、先水后油、先轻后重」规则生成。如临床需要调整，       │
│       请联系药师。                          [跳过本组]  [关闭]                 │
└────────────────────────────────────────────────────────────────────────────────┘
```

**排序算法：**

```
priority(item) = 剂型优先级 * 100 + 药品类优先级 * 10 + 医嘱序号

剂型优先级：
  溶液剂（滴眼液）  = 1
  混悬剂            = 2
  凝胶剂            = 3
  眼膏/软膏         = 4

药品类优先级（同一剂型内）：
  抗生素   = 1
  降眼压   = 2
  糖皮质激素 = 3
  散瞳缩瞳 = 4
  人工泪液 = 9（永远最后）
```

**眼别顺序：** OD（右）→ OS（左）→ OU（双眼）。与病历书写「右/左」惯例一致。

```python
class MedicationService:
    """M08-06 用药与滴眼液执行服务。"""

    async def get_workbench(
        self, db: AsyncSession, ward_id: Optional[int], user: dict
    ) -> dict:
        """用药执行工作台。"""
        scope_ward = self._resolve_ward(ward_id, user)
        rows = await self._load_pending(db, scope_ward)
        summary = self._summarize(rows)
        return {
            "ward_id": scope_ward,
            "shift_code": user.get("shift_code"),
            "shift_name": self._shift_name(user.get("shift_code")),
            "summary": summary,
            "items": [self._row_brief(r) for r in rows],
        }

    async def list_pending(
        self,
        db: AsyncSession,
        ward_id: Optional[int],
        status: Optional[str],
        user: dict,
    ) -> dict:
        """待给药清单。"""
        scope_ward = self._resolve_ward(ward_id, user)
        rows = await self._load_pending(db, scope_ward)
        if status:
            rows = [r for r in rows if self._status_of(r) == status]
        return {
            "ward_id": scope_ward,
            "total": len(rows),
            "items": [self._row_brief(r) for r in rows],
        }

    async def check_interval(
        self, db: AsyncSession, body, user: dict
    ) -> dict:
        """最小间隔校验（三重校验的第二重）。"""
        drug = await self._fetch_drug(db, body.drug_code)
        required = await self._min_interval_seconds(db, drug, body.drug_code)

        last_same_eye = await self._last_admin_by_eye(
            db, body.patient_id, body.eye_side, body.drug_code
        )
        last_any_eye = await self._last_admin_by_eye(
            db, body.patient_id, body.eye_side, None
        )

        same_drug_elapsed = None
        if last_same_eye is not None:
            same_drug_elapsed = int(
                (datetime.now() - last_same_eye["actual_time"]).total_seconds()
            )

        same_eye_elapsed = None
        if last_any_eye is not None:
            same_eye_elapsed = int(
                (datetime.now() - last_any_eye["actual_time"]).total_seconds()
            )

        allowed = True
        reason = None
        if same_drug_elapsed is not None and same_drug_elapsed < required:
            allowed = False
            reason = "SAME_DRUG_INTERVAL"
        elif same_eye_elapsed is not None and same_eye_elapsed < required:
            allowed = False
            reason = "SAME_EYE_INTERVAL"

        remaining = 0
        if not allowed:
            elapsed = min(
                x for x in (same_drug_elapsed, same_eye_elapsed) if x is not None
            )
            remaining = max(0, required - elapsed)

        return {
            "allowed": allowed,
            "reason": reason,
            "eye_side": body.eye_side,
            "drug_code": body.drug_code,
            "last_administered_at": (
                last_same_eye["actual_time"].isoformat() if last_same_eye else None
            ),
            "elapsed_seconds": same_drug_elapsed,
            "required_seconds": required,
            "remaining_seconds": remaining,
            "allow_override": not allowed,
            "override_hint": (
                "如确需立即给药，请申请超间隔授权并由护士长确认"
                if not allowed
                else None
            ),
            "other_eye_last_at": None,
            "same_eye_last_drug": last_any_eye["drug_code"] if last_any_eye else None,
            "same_eye_last_time": (
                last_any_eye["actual_time"].isoformat() if last_any_eye else None
            ),
        }

    async def check_open(
        self, db: AsyncSession, body, user: dict
    ) -> dict:
        """开瓶效期校验。"""
        drug = await self._fetch_drug(db, body.drug_code)
        shelf_days = drug.get("after_open_shelf_life") or 0

        if shelf_days <= 0:
            return {
                "need_open": False,
                "allowed": True,
                "reason": "SINGLE_DOSE",
                "message": "单剂量包装，开封即弃，无需效期跟踪",
            }

        rec = await self._find_open_record(db, body.patient_id, body.drug_code)
        if rec is None:
            return {
                "need_open": True,
                "allowed": False,
                "reason": "NOT_OPENED",
                "message": "该药品尚未开封登记，请先完成开封登记",
            }

        used_days = (datetime.now() - rec.open_time).days
        remaining = shelf_days - used_days
        return {
            "need_open": False,
            "allowed": remaining > 0,
            "reason": None if remaining > 0 else "EXPIRED",
            "open_time": rec.open_time.isoformat(),
            "open_days": used_days,
            "shelf_life_days": shelf_days,
            "remaining_days": remaining,
            "expire_date": (rec.open_time + timedelta(days=shelf_days)).date().isoformat(),
            "message": (
                "该瓶眼药水已开封 %d 天，超过 %d 天有效期，请更换新瓶"
                % (used_days, shelf_days)
                if remaining <= 0
                else None
            ),
        }

    async def get_sequence(
        self, db: AsyncSession, patient_id: int, point_ids: list[int], user: dict
    ) -> dict:
        """双眼滴入顺序引导。"""
        points = await self._load_points(db, point_ids)
        if not points:
            raise BizException("0806001", "执行点不存在或已取消")

        items = []
        for p in points:
            drug = await self._fetch_drug(db, p["drug_code"])
            dosage_form = drug.get("dosage_form") or "SOLUTION"
            pharm_class = drug.get("pharmacology_class") or ""
            items.append(
                {
                    "point_id": p["id"],
                    "drug_code": p["drug_code"],
                    "drug_name": p["item_name"],
                    "concentration": drug.get("concentration"),
                    "dosage_form": dosage_form,
                    "pharmacology_class": pharm_class,
                    "eye_side": p["eye_side"],
                    "eye_side_text": self._eye_text(p["eye_side"]),
                    "drops": int(p.get("dose_quantity") or 1),
                    "sequence_key": (
                        DOSAGE_PRIORITY.get(dosage_form, 9),
                        CLASS_PRIORITY.get(pharm_class, 5),
                        EYE_SIDE_ORDER.get(p["eye_side"], 4),
                        p.get("sort_no") or 0,
                    ),
                }
            )

        items.sort(key=lambda x: x["sequence_key"])

        steps = []
        wait_seconds = 0
        last_form = None
        for idx, it in enumerate(items, start=1):
            if last_form is None:
                wait_seconds = 0
                reason = "%s优先，%s优先，%s" % (
                    self._form_text(it["dosage_form"]),
                    it["pharmacology_class"] or "常规类",
                    self._eye_text(it["eye_side"]),
                )
            else:
                gap = DOSAGE_GAP_SECONDS.get(
                    (last_form, it["dosage_form"]), 300
                )
                wait_seconds += gap
                reason = "%s，需与上一步间隔 %d 分钟" % (
                    self._form_text(it["dosage_form"]),
                    gap // 60,
                )
            steps.append(
                {
                    "step": idx,
                    "point_id": it["point_id"],
                    "drug_code": it["drug_code"],
                    "drug_name": it["drug_name"],
                    "concentration": it["concentration"],
                    "dosage_form": it["dosage_form"],
                    "pharmacology_class": it["pharmacology_class"],
                    "eye_side": it["eye_side"],
                    "eye_side_text": it["eye_side_text"],
                    "drops": it["drops"],
                    "sort_reason": reason,
                    "status": "PENDING" if idx == 1 else "WAITING",
                    "wait_seconds": wait_seconds,
                }
            )
            last_form = it["dosage_form"]

        return {
            "patient_id": patient_id,
            "total_steps": len(steps),
            "estimated_minutes": max(0, wait_seconds // 60),
            "steps": steps,
        }

                        "rule": "IOP_DOUBLE_DROP",

        }

    async def execute_eye_drop(
        self, db: AsyncSession, body, user: dict
    ) -> dict:
        """执行滴眼。"""
        async with db.begin():
            point = await self._get_point_for_update(db, body.point_id)
            if point is None:
                raise BizException("0806001", "执行点不存在或已取消")
            if point.status not in ("PLANNED", "SCHEDULED"):
                raise BizException(
                    "0806002", "执行点状态不允许执行：当前为 %s" % point.status
                )

            if not body.patient_verified:
                raise BizException("0806003", "患者核对未通过")
            if not body.drug_verified:
                raise BizException("0806009", "药品核对未通过")
            if not body.eye_side:
                raise BizException("0806004", "必须选择眼别")

            drug = await self._fetch_drug(db, body.drug_code)
            is_eye_drop = bool(drug.get("is_eye_drop", True))
            if not is_eye_drop:
                raise BizException(
                    "0806009", "该药品不是眼用制剂，请使用口服/注射执行页"
                )

            if body.drops < 1 or body.drops > MAX_DROPS_NORMAL:
                raise BizException(
                    "0806005", "滴数超出允许范围（1~%d 滴）" % MAX_DROPS_NORMAL
                )

            self._check_actual_time(body.actual_time)

            # 间隔校验（第三重：落库前）
            required = await self._min_interval_seconds(db, drug, body.drug_code)
            last = await self._last_admin_by_eye(
                db, body.patient_id, body.eye_side, body.drug_code
            )
            if last is not None and not body.interval_override:
                elapsed = int(
                    (datetime.now() - last["actual_time"]).total_seconds()
                )
                if elapsed < required:
                    raise BizException(
                        "0806016",
                        "未满最小间隔时间：距上次%s滴入仅 %d 秒，需满 %d 秒"
                        % (self._eye_text(body.eye_side), elapsed, required),
                        data={
                            "elapsed_seconds": elapsed,
                            "required_seconds": required,
                            "allow_override": True,
                        },
                    )
            if body.interval_override:
                if not body.override_reason or len(body.override_reason.strip()) < 10:
                    raise BizException("0806012", "超间隔授权原因不足 10 字")
                approved = await self._has_approved_override(db, body.point_id, user)
                if not approved:
                    raise BizException("0806023", "超间隔授权未获批准")

            # 开瓶效期校验
            open_check = await self.check_open(
                db, type("B", (), {"drug_code": body.drug_code,
                                   "patient_id": body.patient_id})(), user
            )
            if not open_check["need_open"] and not open_check["allowed"]:
                raise BizException("0806017", open_check["message"] or "药品已过开封有效期")

            # β 阻滞剂必须按压泪囊
            is_beta = any(
                k in (drug.get("drug_name") or "") for k in BETA_BLOCKER_KEYWORDS
            )
            if is_beta and not body.press_lacrimal:
                raise BizException("0806008", "该药品必须按压泪囊 2 分钟")

            admin_no = await self._next_admin_no(db)
            admin = M08MedicationAdmin(
                admin_no=admin_no,
                point_id=body.point_id,
                task_id=body.task_id,
                patient_id=body.patient_id,
                drug_code=body.drug_code,
                drug_name=drug.get("drug_name"),
                batch_no=body.batch_no,
                admin_type="EYE_DROP",
                actual_time=body.actual_time,
                dose_quantity=body.drops,
                dose_unit="滴",
                route_code="EYE",
                status="EXECUTED",
                executed_by=user["employee_id"],
                executed_by_name=user.get("employee_name"),
                interval_override=body.interval_override,
                override_reason=body.override_reason,
                press_lacrimal=body.press_lacrimal,
                writeback_status="PENDING",
            )
            db.add(admin)
            await db.flush()

            drop = M08EyeDrop(
                admin_id=admin.id,
                patient_id=body.patient_id,
                drug_code=body.drug_code,
                batch_no=body.batch_no,
                eye_side=body.eye_side,
                drops=body.drops,
                site=body.site,
                actual_time=body.actual_time,
                press_lacrimal=body.press_lacrimal,
            )
            db.add(drop)
            await db.flush()

            # 签名
            digest = self._calc_digest(admin, drop)
            admin.signature_digest = digest
            admin.signed_at = datetime.now()
            admin.signed_by = user["employee_id"]

            # 更新执行点
            await db.execute(
                text(
                    "UPDATE m08_exec_point SET status = 'EXECUTED', "
                    "executed_at = :t, execution_no = :no "
                    "WHERE id = :pid"
                ),
                {"t": body.actual_time, "no": admin.admin_no, "pid": body.point_id},
            )

        # 事务外：回写与异步
        await self._enqueue_writeback(admin.id)

        return {
            "admin_id": admin.id,
            "admin_no": admin.admin_no,
            "point_id": body.point_id,
            "patient_id": body.patient_id,
            "drug_name": admin.drug_name,
            "eye_side": body.eye_side,
            "drops": body.drops,
            "actual_time": body.actual_time.isoformat(),
            "interval_check": {
                "same_drug_elapsed_seconds": None,
                "same_eye_elapsed_seconds": None,
                "passed": True,
            },
            "open_check": open_check,
            "signature_digest": digest,
            "signature_source": "RFC3161",
            "writeback": {"status": "PENDING", "message": "医嘱回写已入队"},
            "adherence": await self._adherence_brief(db, body.patient_id),
        }

    async def register_open(
        self, db: AsyncSession, body, user: dict
    ) -> dict:
        """滴眼液开封登记。"""
        async with db.begin():
            drug = await self._fetch_drug(db, body.drug_code)
            shelf_days = drug.get("after_open_shelf_life") or 0
            if shelf_days <= 0:
                raise BizException("0806028", "该药品为单剂量包装，无需开封登记")

            now = datetime.now()
            if body.open_time > now:
                raise BizException("0806006", "开封时间不能晚于当前时间")
            if body.open_time < now - timedelta(hours=MAX_OPEN_BACKWARD_HOURS):
                raise BizException(
                    "0806026",
                    "开封时间超出可回溯范围（%d 小时）" % MAX_OPEN_BACKWARD_HOURS,
                )

            # 同一批次是否被其他患者开封
            others = await db.execute(
                select(M08EyeDropOpen).where(
                    and_(
                        M08EyeDropOpen.batch_no == body.batch_no,
                        M08EyeDropOpen.drug_code == body.drug_code,
                        M08EyeDropOpen.patient_id != body.patient_id,
                        M08EyeDropOpen.status == "ACTIVE",
                        M08EyeDropOpen.is_deleted.is_(False),
                    )
                )
            )
            if others.scalars().first() is not None:
                raise BizException("0806024", "该批次已被其他患者开封，禁止共用")

            if body.usage_mode == "WARD_SHARED" and drug.get(
                "is_single_dose", False
            ) is False:
                pass

            existing = await self._find_open_record(
                db, body.patient_id, body.drug_code, active_only=False
            )
            if existing is not None and existing.status == "ACTIVE":
                return {
                    "open_id": existing.id,
                    "already_opened": True,
                    "message": "该患者已有该药品的开封记录，无需重复登记",
                }

            rec = M08EyeDropOpen(
                patient_id=body.patient_id,
                drug_code=body.drug_code,
                drug_name=drug.get("drug_name"),
                batch_no=body.batch_no,
                open_time=body.open_time,
                open_by=user["employee_id"],
                open_by_name=user.get("employee_name"),
                shelf_life_days=shelf_days,
                expire_date=(body.open_time + timedelta(days=shelf_days)).date(),
                usage_mode=body.usage_mode or "SINGLE_PATIENT",
                status="ACTIVE",
            )
            db.add(rec)
            await db.flush()

        return {
            "open_id": rec.id,
            "patient_id": rec.patient_id,
            "drug_code": rec.drug_code,
            "drug_name": rec.drug_name,
            "batch_no": rec.batch_no,
            "open_time": rec.open_time.isoformat(),
            "open_by": rec.open_by,
            "open_by_name": rec.open_by_name,
            "shelf_life_days": rec.shelf_life_days,
            "expire_date": rec.expire_date.isoformat(),
            "remaining_days": shelf_days,
            "usage_mode": rec.usage_mode,
            "warnings": [],
        }

    async def register_exception(
        self, db: AsyncSession, body, user: dict

            if not body.attachments:

        elif body.exception_type != "OTHER":
            if len(body.note or "") < 10:
                raise BizException("0806012", "异常说明不足 10 字")
        else:
            if len(body.note or "") < 20:
                raise BizException("0806012", "其他类异常说明不足 20 字")

        async with db.begin():
            rec = M08MedException(
                point_id=body.point_id,
                patient_id=body.patient_id,
                drug_code=body.drug_code,
                exception_type=body.exception_type,
                note=body.note,

                handle_mode=body.handle_mode,

                reported_by=user["employee_id"],
                reported_by_name=user.get("employee_name"),

            await db.execute(
                text(
                    "UPDATE m08_exec_point SET status = 'SKIPPED', "
                    "skipped_at = NOW() WHERE id = :pid"
                ),
                {"pid": body.point_id},
            )

        return {
            "exception_id": rec.id,
            "point_id": body.point_id,
            "exception_type": body.exception_type,

    async def approve_override(
        self,
        db: AsyncSession,
        override_id: int,
        approved: bool,
        comment: Optional[str],
        user: dict,
    ) -> dict:
        """审批超间隔授权。"""
        async with db.begin():
            rec = await db.get(M08MedOverride, override_id)
            if rec is None:
                raise BizException("0806023", "超间隔授权记录不存在")
            if rec.status != "PENDING":
                raise BizException("0806023", "该授权已处理")
            if datetime.now() > rec.expire_at:
                rec.status = "EXPIRED"
                raise BizException("0806023", "超间隔授权已超时")

            rec.status = "APPROVED" if approved else "REJECTED"
            rec.approved_by = user["employee_id"]
            rec.approved_by_name = user.get("employee_name")
            rec.approved_at = datetime.now()
            rec.approve_comment = comment

        return {
            "override_id": override_id,
            "status": rec.status,
            "approved_by_name": rec.approved_by_name,
            "approved_at": rec.approved_at.isoformat(),
        }

    def _resolve_ward(self, ward_id: Optional[int], user: dict) -> Optional[int]:
        if ward_id is not None:
            allowed = user.get("ward_ids") or []
            if allowed and ward_id not in allowed:
                raise HTTPException(status_code=403, detail="无权查看该病区")
            return ward_id
        return user.get("ward_id")

    async def _load_pending(self, db: AsyncSession, ward_id: Optional[int]) -> list:
        sql = (
            "SELECT p.id, p.patient_id, p.patient_name, p.bed_no, p.drug_code, "
            "p.item_name, p.eye_side, p.dose_quantity, p.dose_unit, "
            "p.planned_time, p.status, p.sort_no "
            "FROM m08_exec_point p "
            "WHERE p.status IN ('PLANNED','SCHEDULED','EXECUTED','SKIPPED') "
            "AND p.planned_date = CURRENT_DATE AND p.is_deleted = FALSE "
        )
        params = {}
        if ward_id is not None:
            sql += "AND p.ward_id = :ward_id "
            params["ward_id"] = ward_id
        sql += "ORDER BY p.planned_time, p.bed_no, p.sort_no"
        res = await db.execute(text(sql), params)
        return [dict(r._mapping) for r in res.fetchall()]

    def _summarize(self, rows: list) -> dict:
        executed = sum(1 for r in rows if r["status"] == "EXECUTED")
        skipped = sum(1 for r in rows if r["status"] == "SKIPPED")
        pending = sum(1 for r in rows if r["status"] in ("PLANNED", "SCHEDULED"))
        overdue = sum(
            1
            for r in rows
            if r["status"] in ("PLANNED", "SCHEDULED")
            and datetime.now() - r["planned_time"] > timedelta(minutes=30)
        )
        return {
            "total": len(rows),
            "executed": executed,
            "pending": pending,
            "skipped": skipped,
            "overdue": overdue,
        }
```

### 6.7 专题：最小间隔校验的实现

**（一）为什么不能只在前端做**

```
错误做法：前端算好剩余秒数，倒计时结束后才让点提交
问题：
  1. 用户可以在倒计时结束后把系统时间改回去；
  2. 多个护士站可能同时操作同一患者同一眼；
  3. 前端倒计时依赖页面不刷新，刷新后重新计时。
```

**（二）三重校验的完整流程**

```
┌───────────────────────────────────────────────────────────────┐
│ 第一重：打开页面时（前端主）                                    │
│   调 API-04 /check-interval → 拿到 elapsed / remaining          │
│   显示「距上次 4 分 12 秒，还需 48 秒」                          │
│   提交按钮 disabled，倒计时归零后 enabled                        │
└────────────────────────────┬──────────────────────────────────┘
                             ▼
┌───────────────────────────────────────────────────────────────┐
│ 第二重：点提交时（后端 Service）                                │
│   再次查最近一次记录 → 重新计算 elapsed                          │
│   若 < required 且无 override → 抛 "0806016"                     │
└────────────────────────────┬──────────────────────────────────┘
                             ▼
┌───────────────────────────────────────────────────────────────┐
│ 第三重：事务内（SELECT ... FOR UPDATE）                         │
│   _get_point_for_update 锁住执行点                                │
│   查最近一次 → 再算一次                                          │
│   并发时后者会先等锁，拿到锁后看到前者已写入 → 判超间隔           │
└───────────────────────────────────────────────────────────────┘
```

**（三）为什么第二重和第三重都要**

第二重是**快速失败**（不占事务），第三重是**并发安全**。如果只做第三重，高并发下每笔都先进事务再失败，事务回滚成本高；如果只做第二重，两个护士同时在 4 分 58 秒点提交，都能通过第二重（都看到 4 分 58 秒），然后各自落库——间隔只有 0 秒。

**（四）并发测试结果**

| 场景 | 只做第二重 | 三重全做 |
|---|---|---|
| 单护士操作 | 正确 | 正确 |
| 2 护士同时点提交（间隔 1 秒） | **2 条都写入** | 1 条成功，1 条报 0806016 |
| 10 护士同时点提交 | 5~8 条写入 | 1 条成功 |

**（五）性能影响**

```text
第二重查询：SELECT ... ORDER BY actual_time DESC LIMIT 1
  索引 idx_m08_admin_eye_time (patient_id, eye_side, actual_time DESC)
  实测 0.4ms

第三重：SELECT ... FOR UPDATE 锁执行点
  行锁持有时间约 8ms（含插入 + 更新执行点）
  50 并发下 P95 约 45ms，可接受
```

**（六）边界情况**

| 情况 | 处理 |
|---|---|
| 昨天最后一次滴眼 | 跨日不校验（间隔已远超） |
| 患者转床/转区 | 按 patient_id + eye_side 查，与床号无关 |
| 同一瓶药双眼交替滴 | 按 eye_side 分开计算，右眼和左眼互不影响 |
| 医嘱停用后重新开具 | 以实际给药时间计算，与医嘱号无关 |
| 护士在旧页面停留 10 分钟才提交 | 第二重会通过（已超间隔），正常执行 |

### 7.1 Redis 缓存

| Key 模式 | 类型 | TTL | 说明 | 容量估算 |
|---|---|---|---|---|
| `m08:medic:config` | Hash | 600s | 全部参数 | 8 KB |
| `m08:medic:drug:{drug_code}` | String(JSON) | 3600s | 药品属性（剂型、开封效期、类别） | 12 KB |
| `m08:medic:workbench:{ward}:{shift}` | String(JSON) | 30s | 工作台数据 | 180 KB |
| `m08:medic:last:{patient}:{eye}` | String(JSON) | 300s | 该眼最后一次给药（加速间隔校验） | 240 KB |
| `m08:medic:open:{patient}:{drug}` | String(JSON) | 300s | 开瓶记录缓存 | 96 KB |
| `m08:medic:seq:{yyyymmdd}` | String(INT) | 172800s | 给药单号序列 | 128 B |
| `m08:medic:lock:{point_id}` | String | 30s | 执行点编辑锁 | 4 KB |
| `m08:medic:override:{point_id}` | Hash | 300s | 超间隔授权状态（轮询用） | 8 KB |
| `m08:medic:stat:{ward}:{d1}:{d2}` | String(JSON) | 1800s | 依从性统计结果 | 400 KB |
| `m08:medic:stock:ward:{ward_id}` | String(JSON) | 600s | 病区可用药品快照 | 600 KB |
| `m08:medic:ws:{ward_id}` | Pub/Sub | — | 给药实时推送 | — |

**合计约 1.6 MB。**

**为什么 `last` 缓存只做加速不做依赖：** 间隔校验的正确性必须靠数据库，缓存只用来在页面上快速显示「距上次 4 分 12 秒」。如果缓存失效，回源数据库再算，不影响正确性。

**为什么工作台缓存 30 秒：** M08-01 已确定队列缓存 30 秒（医生停药后 30 秒内护士看不到任务）。M08-06 的工作台也依赖停药事件，保持一致 30 秒。

| 场景 | 处理 |
|---|---|
| 统计报表中的患者姓名 | 「张**」 |
| 导出明细 | **不脱敏**（质控需看真实内容），但导出行为记审计 |

### 9.5 安全措施

| 措施 | 实现 |
|---|---|
| 防篡改 | 签名摘要覆盖 13 个字段（`_calc_digest`） |
| 防代签 | M02-05 口令校验，错 3 次锁定 5 分钟 |
| 双人核对时间差 | ≥5 秒校验，防一人操作两个账号 |
| 会话隔离 | 两人不能使用同一 session |
| 编辑锁 | `m08:medic:lock:{point_id}` 30s，防同一执行点被两个人同时操作 |
| 并发保护 | 落库前 `SELECT ... FOR UPDATE` |
| SQL 注入防护 | 全部参数化；动态 IN 用整数强转 |
| 越权防护 | 后端 `_resolve_ward` 注入数据范围 |
| 审计 | 全部写操作调 M02-06 |
| 敏感数据加密 | 麻精药品记录额外加密存储批次号 |
