## 1. 模块概述

### 1.1 模块定位

**M08-04 护理评估与体征是全院的「护理监测数据中心」。** 它回答三个问题：

1. **患者现在的客观状态是什么？**（体温、脉搏、呼吸、血压、血氧、血糖、视力、眼压、疼痛评分）
2. **患者有没有护理风险？**（跌倒、压疮、VTE、营养、自理能力、管道滑脱）
3. **阈值突破了没有？**（超阈值立即告警，通知责任护士、当班医生、必要时护士长）

用一句话概括边界：**M08-04 只记录和判断「测量值」与「评分值」，不改医嘱、不下诊断、不写护理记录正文。**

### 1.2 为什么独立成子模块

**理由一：体征与评估的采集节律与补录规则，与执行记录完全不同。**

| 项目 | M08-03 执行记录 | M08-04 体征与评估 |
|---|---|---|
| 签名后可否修改 | **不可改**，只能作废重建 | **可补录**（体征允许在 24 小时内补录） |
| 采集时间约束 | 必须落在计划时点之后 | 允许提前或滞后 30 分钟 |
| 数据形态 | 事件（做了什么） | 数值序列（值是多少，趋势如何） |
| 查询模式 | 按患者/医嘱查单条 | **按时间窗口查序列并绘制曲线** |
| 是否需要趋势 | 不需要 | **必需**（体温单是法定护理文书） |

把「可补录的数值序列」与「不可变的执行事件」放在同一个子模块，会导致两套矛盾规则共存：执行记录不允许改，体征允许补录；执行记录不需要趋势查询，体征需要。代码里会出现大量 `if 是体征 then ... else ...` 分支。

**理由二：阈值告警是独立的实时计算逻辑，不能挂在采集接口里。**

体征采集峰值在早班 6:30~8:30（一个 40 床病区 15 分钟内录入约 60 条）。若每条都同步查阈值规则、查历史值判动态变化、发告警消息，单条采集中耗时从 40ms 涨到 300ms，早班集中录入就会排队。

更重要的是：**告警必须能在「补录后」重新触发**。护士 8:00 录的体温 39.2℃ 误录成 37.2℃，9:00 发现后改正。若告警逻辑写在采集接口里，补录走的是另一个接口（更新而非新建），告警不会触发。独立成告警表 + 独立计算入口，才能保证「不管怎么录入，该告警的都告警」。

**理由三：评估量表是配置驱动的，不是硬编码的一组字段。**

跌倒风险评估（Morse 量表 6 项）、压疮风险评估（Braden 量表 6 项）、营养风险筛查（NRS2002）、疼痛评估（NRS/VAS/Wong-Baker）、自理能力（Barthel 指数 10 项）、眼科专项评估（视力、眼压耐受、术后体位依从性）——每张量表项数、权重、分级规则都不同，且会随临床指南更新。

若每张量表建一张表，6 张量表就是 6 张结构相近的表加 6 套 CRUD，每次指南更新（比如 Morse 量表评分标准调整）都要改表结构 + 迁移数据。采用「模板表 + 明细表 + 风险汇总表」三张表配置驱动，新增量表只加模板数据，不改表结构。

**理由四：眼科护理有 4 项独有的监测指标，标准 HIS 的体征模块不覆盖。**

| 独有指标 | 为什么眼科必须采 | 与本模块的关系 |
|---|---|---|
| **视力（裸眼/矫正/针孔）** | 术后视力变化是并发症最早信号（如白内障术后第 1 天视力应明显改善，若不升反降提示眼内炎） | 作为体征项 `VISION_*` 采集，可绘趋势 |
| **眼压（IOP）** | 正常 10~21 mmHg，青光眼术后 > 25 提示前房积血或恶性青光眼，属危急值 | 作为体征项 `IOP_*`，单值阈值 + 危急值两档 |
| **瞳孔状态 / 对光反射** | 术后瞳孔不等大、对光反应迟钝提示视神经损伤 | 作为体征项 `PUPIL_*`（枚举型） |
| **术后体位依从性** | 视网膜脱离术后需面朝下 7~10 天，依从性直接决定手术成功率 | 作为评估项（量表型），每日多次记录 |

**理由五：体征数据是全院共享的「横切」数据，写入方与读取方都是多方。**

写入方：门诊护士（M08 门诊线）、日间手术护士（M08 手术线）、病区护士（M08 住院线）、手术室（M09 术中生命体征）、移动护理（M20）。

读取方：M07 医生站（趋势图）、M08-05 护理记录（转抄）、M06-06 病历完整性（D-14）、M09 术前评估、M16 收费（部分监测项目按次收费）、M22 报表（护理质量）。

若体征表挂在某个业务子模块里，所有读取方都要跨子模块依赖；独立成子模块并提供标准查询契约，依赖关系清晰且可缓存。

### 1.4 概念辨析

**辨析一：体征 ≠ 生命体征**

「生命体征」传统指体温、脉搏、呼吸、血压四项。本模块的「体征」是更宽的概念，包含：

- 传统生命体征：体温、脉搏、呼吸、血压、血氧饱和度
- 扩展生理指标：血糖、体重、身高、BMI、意识状态、疼痛评分
- **眼科专项指标**：视力、眼压、瞳孔状态、对光反射、眼睑水肿、结膜充血

区别的意义：护理记录单上「体温单」只画生命体征曲线，而眼科护士需要画「视力曲线」「眼压曲线」。若把眼科指标排除在体征之外，它们就没有趋势图，只能散落在护理记录正文里。

**辨析二：护理评估 ≠ 医疗评估**

| 维度 | 护理评估（M08-04） | 医疗评估（M05/M06/M07/M09） |
|---|---|---|
| 谁做 | 护士 | 医生 |
| 目的 | 发现护理问题、制定护理计划 | 诊断、治疗决策 |
| 工具 | 护理量表（Morse/Braden/NRS2002） | 医学评估（心功能分级、ASA 分级） |
| 结果 | 护理风险等级、护理措施 | 诊断、治疗方案 |
| 记录位置 | 护理评估单 | 病程记录 / 术前讨论 |

**辨析三：护理评估 ≠ 护理记录**

这是 M08 拆分方案主线五的核心。M08-04 的评估结果**是结构化数值**（分数、等级），可以查询、统计、趋势分析、触发预警；M08-05 的护理记录**是半结构化文书**（护士书写的观察经过与措施）。

分开的直接后果：**M06-06 的病历完整性检查项 D-14「护理记录」只认 M08-05 的文书，不认 M08-04 的评估表**。否则「护士只量了体温没写护理记录」的患者会被误判为病历齐全。

**辨析四：告警 ≠ 危急值**

| 维度 | 体征告警（M08-04 `m08_vital_alert`） | 危急值（M07-04 `m07_critical_value`） |
|---|---|---|
| 触发源 | 护理采集的体征/评估 | 检查检验报告中的危急值 |
| 判定方 | 护理阈值规则 | 检验/检查科 + M07-04 |
| 处置流程 | 通知当班护士 → 报告医生 | 报告医生 → 双人核对 → 记录处置 |
| 法定要求 | 无强制时限 | 有强制时限（30 分钟内处置） |

两者会互相引用但**不合并**：护理告警产生的通知链路是护理内部（M08-01 任务 + 站内消息），危急值是跨科室的闭环流程（M07-04 主责）。

**辨析五：评估模板 ≠ 评估记录**

模板（`m08_assess_template`）定义「这张量表有哪些项、怎么计分、怎么分级」；记录（`m08_assessment` + `m08_assess_item`）是某一次对某个患者的实际打分。模板会随临床指南更新版本，**记录必须保存当时使用的模板版本快照**，否则改了量表标准后回看历史记录会得出不同分级。

### 1.5 模块目标

| 编号 | 目标 | 指标 | 现状基线 | 上线目标 |

| G-08 | 数据可追溯性 | 体征修改有完整审计留痕 | 纸质无留痕 | **100%** |

## 2. 业务范围与边界

### 2.1 范围内

| 能力 | 说明 |
|---|---|
| 体征采集 | 手动录入、批量录入、设备读数导入（预留）、补录、修改 |
| 体征项管理 | 体温、脉搏、呼吸、血压、血氧、血糖、体重、BMI、意识、疼痛、视力、眼压、瞳孔、对光反射 |
| 体征趋势 | 按患者/时间段查询数值序列，生成折线图数据 |
| 定时体征任务 | 按护理级别与医嘱频次生成采集时点（与 M08-02 协作） |
| 阈值告警 | 单值阈值、危急值、动态变化阈值、组合阈值 |
| 告警通知 | 站内消息、任务队列、大屏推送 |
| 告警处置 | 确认、处置记录、上报医生、闭环 |
| 评估量表模板 | 模板定义、版本管理、启用停用 |
| 护理评估执行 | 入院评估、跌倒风险、压疮风险、营养筛查、疼痛评估、自理能力、眼科专项 |
| 风险评估汇总 | 风险等级、再评估时点提醒 |
| 评估趋势 | 同一量表多次评估的分数变化 |
| 统计报表 | 体征采集完成率、告警统计、评估完成率、风险分布 |

### 2.2 范围外

| 能力 | 归属 | 说明 |
|---|---|---|
| 医嘱下达（如「测血压 QID」） | M07-03 | M08-04 只负责按医嘱频次采集 |
| 生成「该量体温」的任务实体 | M08-01 | M08-04 只提供执行点 |
| 执行计划的频次展开 | M08-02 | M08-04 消费执行点 |
| 护理记录正文（观察记录） | M08-05 | M08-04 只提供数据 |
| M06-06 病历完整性检查算法 | M06-06 | M08-04 提供数据接口 |
| 检查检验危急值闭环 | M07-04 | M08-04 的告警是护理侧，独立 |
| 医生查看完整体征趋势与决策 | M07 | 通过 M07 的报告/体征视图 |
| 手术中的麻醉监护数据 | M09-03 | M09 有自己的麻醉记录单，不写 M08-04 |
| 患者报告的疼痛/症状（PRO） | M03-06 | 患者自报走患者门户，不回写 M08-04 |
| 电子病历的护理部分归档 | M06-06 / M18 | M08-04 只提供数据 |

**边界判定原则：**

> 如果一项数据是**护士在床旁测量或打分得出的客观值**，归 M08-04；
> 如果是**护士围绕这个值写的话**，归 M08-05；
> 如果是**医生根据这个值做出的决策**，归 M07；
> 如果是**患者自己说的**，归 M03-06。

### 2.3 与相邻模块分工（判定示例）

| 场景 | 归属 | 判定依据 |
|---|---|---|
| 病区护士 8:00 测体温 38.9℃ | M08-04 采集 + 告警 | 护士测量得出的客观值 |
| 系统发现 38.9℃ 超阈值，生成「报告医生」待办 | M08-04 判定 → M08-01 落任务 | 判定与落任务分离 |

## 3. 业务模型

### 3.1 体征项模型（17 项）

体征项分四类，采集方式与校验规则各不相同。

| 类别 | 体征项编码 | 名称 | 数据类型 | 单位 | 范围 | 采集方式 |
|---|---|---|---|---|---|---|
| **基础生命体征** | `TEMP` | 体温 | NUMERIC(5,2) | ℃ | 30.0~45.0 | 手动/设备 |
| | `TEMP_TYPE` | 体温测量方式 | 枚举 | — | AXILLARY/ORAL/RECTAL/TYMPANIC | 下拉 |
| | `PULSE` | 脉搏 | SMALLINT | 次/分 | 20~250 | 手动/设备 |
| | `RESP` | 呼吸 | SMALLINT | 次/分 | 5~80 | 手动 |
| | `SBP` | 收缩压 | SMALLINT | mmHg | 40~300 | 手动/设备 |
| | `DBP` | 舒张压 | SMALLINT | mmHg | 20~200 | 手动/设备 |
| | `SPO2` | 血氧饱和度 | NUMERIC(4,1) | % | 50.0~100.0 | 设备 |
| **扩展生理** | `GLU` | 血糖 | NUMERIC(5,2) | mmol/L | 0.5~40.0 | 手动/设备 |
| | `WEIGHT` | 体重 | NUMERIC(5,2) | kg | 1.00~300.00 | 手动 |
| | `HEIGHT` | 身高 | NUMERIC(5,2) | cm | 30.00~250.00 | 手动 |
| | `BMI` | 体质指数 | NUMERIC(4,1) | — | 5.0~99.0 | **计算** |
| | `CONSCIOUS` | 意识状态 | 枚举 | — | CLEAR/DROWSY/CONFUSED/COMA | 下拉 |
| | `PAIN` | 疼痛评分 | SMALLINT | 分 | 0~10 | 手动 |
| **眼科专项** | `VISION_NAKED_OD` | 裸眼视力（右） | VARCHAR(16) | — | 0.01~2.0 或指数/光感 | 手动 |
| | `VISION_NAKED_OS` | 裸眼视力（左） | VARCHAR(16) | — | 同上 | 手动 |
| | `VISION_BC_OD` | 矫正视力（右） | VARCHAR(16) | — | 同上 | 手动 |
| | `VISION_BC_OS` | 矫正视力（左） | VARCHAR(16) | — | 同上 | 手动 |
| | `IOP_OD` | 眼压（右） | NUMERIC(4,1) | mmHg | 3.0~80.0 | 手动/设备 |
| | `IOP_OS` | 眼压（左） | NUMERIC(4,1) | mmHg | 3.0~80.0 | 手动/设备 |
| | `PUPIL_OD` | 瞳孔（右） | 枚举 | — | 同大等圆/偏大/偏小/不等 | 下拉 |
| | `PUPIL_OS` | 瞳孔（左） | 枚举 | — | 同上 | 下拉 |
| | `LIGHT_REFLEX_OD` | 对光反射（右） | 枚举 | — | NORMAL/SLUGGISH/ABSENT | 下拉 |
| | `LIGHT_REFLEX_OS` | 对光反射（左） | 枚举 | — | 同上 | 下拉 |

**视力记录的特殊性（为什么用 VARCHAR 而不是 NUMERIC）：**

眼科视力有标准数值（0.01~2.0），但也有非数值描述：

- 光感（`LP`）、光感不确定（`LP?`）、无光感（`NLP`）
- 指数（`CF/30cm`、`HM/1m`）
- 儿童无法表达时记「拒查」`REFUSED`

若强制数值，这些情形只能记 NULL，丢失了「患者完全看不见」这个关键信息——而 `NLP` 与「本次未测」在临床上意义天差地别。

**视力排序函数（用于趋势与告警）：**

```
NLP(0) < LP(0.001) < LP?(0.0005) < HM(0.005) < CF30(0.01) < CF100(0.02) < 0.01 ... 2.0
```

系统内置 `VISION_ORDER` 映射表，评估「视力下降」时按序数值比较而非字符串比较。

### 3.2 定时体征任务模型

定时采集的时点由三方面共同决定：

```
   护理级别  ──┐
               ├──► 采集频次 ──► 采集时点序列
   医嘱频次  ──┤                    │
   病区常规  ──┘                    ▼
                              与 M08-02 执行点对接
                                    │
                                    ▼
                              M08-01 任务队列
```

**频次优先级（从高到低）：**

1. **医嘱指定频次**（`m07_order` 关联的 `VITAL` 类型医嘱，如「测血压 QID」）
2. **护理级别常规**：特级护理 Q1H、一级护理 Q4H、二级护理 Q6H、三级护理 BID
3. **病区常规**：默认 QD（06:00）

**默认采集时点表（`DEFAULT_VITAL_TIMES`）：**

| 频次 | 采集时点 |
|---|---|
| Q1H | 每小时整点 |
| Q2H | 06,08,10,12,14,16,18,20,22,00,02,04 |
| Q4H | 06:00, 10:00, 14:00, 18:00, 22:00, 02:00 |
| Q6H | 06:00, 12:00, 18:00, 00:00 |
| Q8H | 06:00, 14:00, 22:00 |
| Q12H | 08:00, 20:00 |
| QID | 08:00, 12:00, 16:00, 20:00 |
| TID | 08:00, 12:00, 16:00 |
| BID | 08:00, 20:00 |
| QD | 06:00 |
| PRN | 不生成定时任务 |

**眼科特别注意：术后眼压监测**

青光眼术后需 Q2H 或 Q4H 测眼压，且**术后 6 小时内必须加密到 Q1H**（前房积血、恶性青光眼风险高峰）。参数 `M08.VITAL.OP_POST_QUICK_HOURS = 6` 控制加密窗口。

### 3.3 阈值告警模型

**四级告警模型：**

| 级别 | 编码 | 触发条件 | 通知对象 | 响应时限 |
|---|---|---|---|---|
| **危急** | `CRITICAL` | 触及危急值（如体温 ≥41℃、眼压 ≥50mmHg、血氧 <85%） | 责任护士 + 当班医生 + 护士长，**弹窗强提醒** | 5 分钟内必须确认 |
| **严重** | `SEVERE` | 触及严重阈值（如体温 ≥39℃、眼压 ≥30mmHg） | 责任护士 + 当班医生 | 15 分钟内确认 |
| **一般** | `WARNING` | 触及一般阈值（如体温 ≥37.5℃、脉搏 >110） | 责任护士 | 30 分钟内确认 |
| **趋势** | `TREND` | 未超阈值但变化过快（如 4 小时内体温升高 ≥1.5℃） | 责任护士 | 2 小时内确认 |

**为什么需要 `TREND` 级别：**

单看数值，体温从 36.5℃ 升到 38.0℃ 只触及 WARNING（正常上限 37.5℃，38.0℃ 算低热）。但 4 小时内升高 1.5℃ 是感染早期的强信号——等到超过 39℃ 才告警已经晚了。

### 3.4 评估量表模型

**六张内置量表：**

| 量表编码 | 名称 | 项数 | 总分范围 | 分级 | 施测时机 |
|---|---|---|---|---|---|
| `FALL_MORSE` | Morse 跌倒风险评估 | 6 | 0~125 | 低风险 <25 / 中风险 25~44 / 高风险 ≥45 | 入院 8h 内、病情变化、转科、术后、跌倒后 |
| `PRESSURE_BRADEN` | Braden 压疮风险 | 6 | 6~23 | 极高危 ≤9 / 高危 10~12 / 中危 13~14 / 低危 15~18 / 无风险 ≥19 | 入院 8h 内、每班次、病情变化 |
| `NUTRITION_NRS` | NRS2002 营养风险筛查 | 4 | 0~7 | 无风险 =0 / 有风险 1~2 / 高风险 ≥3 | 入院 8h 内、术后 48h |
| `PAIN_NRS` | NRS 疼痛评分 | 1 | 0~10 | 无痛 0 / 轻度 1~3 / 中度 4~6 / 重度 7~10 | 每班次或主诉时 |
| `BARTHEL` | Barthel 自理能力指数 | 10 | 0~100 | 重度依赖 ≤40 / 中度 41~60 / 轻度 61~99 / 独立 100 | 入院 8h 内、每周 |
| `OPH_POSTURE` | 眼科术后体位依从性 | 5 | 0~100 | 不依从 <60 / 部分依从 60~84 / 完全依从 ≥85 | 术后每班次（网脱手术） |

**量表计分模型：**

```
得分 = Σ(各项权重 × 各项得分)
```

每项得分规则由模板的 `scoring_type` 决定：

| `scoring_type` | 说明 | 示例 |
|---|---|---|
| `SUM` | 各项得分直接累加 | Braden |
| `WEIGHTED` | 加权累加 | Morse（每项权重不同） |
| `MAX` | 取各项最大值 | 部分疼痛量表 |
| `SINGLE` | 单项即总分 | NRS 疼痛 |
| `PERCENT` | 加权后归一到 0~100 | 体位依从性 |

**风险等级判定（`grade_rules` JSONB）：**

```json
[
  {"level": "HIGH", "min": 45, "max": null, "label": "高风险", "color": "RED"},
  {"level": "MEDIUM", "min": 25, "max": 44, "label": "中风险", "color": "ORANGE"},
  {"level": "LOW", "min": 0, "max": 24, "label": "低风险", "color": "GREEN"}
]
```

**为什么 `grade_rules` 存 JSONB 而不是拆成列：**
不同量表的分级档数不同（Morse 3 档、Braden 5 档、Barthel 4 档），拆列要建 `level_1_min`/`level_2_min`/……最多 5 组，且只能正向分。存 JSONB 后新增档数只改数据。

### 3.5 再评估触发模型

风险评估不是一次性的。触发再评估的事件（`REASSESS_TRIGGERS`）：

| 触发事件 | 适用量表 | 时限 | 来源 |
|---|---|---|---|
| 入院 | 全部 | 8 小时内 | M08 事件 |
| 转科 | 全部 | 转入后 4 小时内 | M05/M06 事件 |
| 术后返回病区 | 全部 | 2 小时内 | M09 事件 |
| 病情变化（告警触发） | 跌倒 / 压疮 / 疼痛 | 4 小时内 | 告警事件 |
| 跌倒事件发生 | 跌倒 | 立即（跌倒后 1 小时内） | M08 事件 |
| 手术日 | 全部 | 术前 1 天内 | M09 排程 |
| 每班次 | 压疮 | 每班次（8 小时） | 定时 |

### 3.6 告警处置闭环模型

```
     采集体征 ──► 判定超阈值 ──► 写 m08_vital_alert (PENDING)
                                        │
                                        ▼
                              ┌───────────────────┐
                              │ 通知（3 通道并行）  │
                              │ ① 站内消息 M03-05  │
                              │ ② 任务 M08-01      │
                              │ ③ WebSocket 推送    │
                              └────────┬──────────┘
                                       ▼
                                  待护士确认
                                       │
                     ┌─────────────────┼─────────────────┐
                     ▼                 ▼                 ▼
                ACKNOWLEDGED      ACKNOWLEDGED      AUTO_CLOSED
                + 报告医生        + 自行处理        （超时未确认，
                  (ESCALATED)      (HANDLED)        升级护士长）
                     │                 │
                     └────────┬────────┘
                              ▼
                          CLOSED（闭环）
```

**状态机：** `PENDING → ACKNOWLEDGED → HANDLED / ESCALATED → CLOSED`

- `PENDING`：已生成告警，未确认
- `ACKNOWLEDGED`：护士已看到并点击确认
- `HANDLED`：护士已处理（如报告医生、给予物理降温）
- `ESCALATED`：已上报医生或护士长
- `CLOSED`：闭环结束
- `AUTO_CLOSED`：超时未确认，系统自动关闭但记为超时（计入质量指标）

**为什么必须有 `ACKNOWLEDGED` 而不是直接 `HANDLED`：**
护士看到告警后可能先观察（比如血压 165/95，先复测确认不是测量误差）。若只有「已处理」一个动作，护士无法表达「我看到了，正在观察」。有了确认态，超时统计才能区分「没看到」与「看到了但没处理」——前者是系统问题（通知没送达），后者是执行问题（护士疏忽）。

### 3.7 数据归属与快照模型

**体征记录的归属：**

一条体征记录属于哪个「就诊/住院」上下文？

```
门诊患者         ──► encounter_id（M07 就诊会话）+ registration_id
日间手术患者     ──► schedule_id（M06 排程）+ admission_id（M06 虚拟住院号）
住院患者         ──► admission_id（M05 住院号，未上线前用 m08_admission_snap）
手术中           ──► schedule_id（M09 手术台次）——但术中数据归 M09，不回写
```

**最小归属原则：** 一条体征记录至少要有一个归属键（`encounter_id` / `admission_id` / `schedule_id` 三选一非空）。三者都可为空的记录不允许创建。

**快照模型（与 M08-03 一致）：**

`m08_vital_sign` 冗余 `patient_name`/`bed_no`/`ward_id`/`nursing_level`。原因：

1. 体征趋势图需要一次查询返回 30 天数据，若每条都要 JOIN 患者表，30 天 120 条 × JOIN 会造成 400ms 以上延迟；冗余后单表扫 30ms。
2. 体征是「当时的状态」记录，患者改名后历史记录应保留旧名（与执行记录一致）。
3. 床号会变（转床），历史体征应显示当时床号。

### 3.8 补录与修改模型

**可修改窗口：**

| 数据类型 | 可修改窗口 | 超过窗口 |
|---|---|---|
| 体征（当日） | 24 小时内可任意修改 | 需护士长审批，改后标 `is_late_corrected=TRUE` |
| 体征（跨日） | 不允许修改 | 只能新增补录记录 |
| 评估结果（未签名） | 随时可改 | — |
| 评估结果（已签名） | 不可改 | 只能作废重建（与 M08-03 一致） |

**为什么体征允许改而执行记录不允许改：**

体征是「测量值」，护士输错（37.2 输成 32.7）是笔误，改了才是对的。执行记录是「事件」，改了就篡改了事实。

但这不等于体征可以随便改。每次修改必须完整留痕：原值、新值、修改人、修改时间、原因（≥10 字）、是否超窗口审批。

**修改审计表由 M08-05 的通用日志或本模块的 `m08_vital_log` 承担——本模块建独立日志表**，因为体征修改的频次（约每日 15 条）与护理记录日志的频次、字段都不同。

### 3.9 眼科护理评估特殊性

**为什么眼科需要 `OPH_POSTURE` 量表：**

视网膜脱离术后（尤其黄斑区脱离）需保持**面朝下体位** 7~10 天，每日 16 小时以上。依从性差直接导致手术失败率显著上升。这是眼科护理中最有「硬约束」的护理措施，必须量化记录。

量表 5 项：

| 项目 | 评分 | 说明 |
|---|---|---|
| 每日面朝下时长 | 0~40 | ≥16h=40，12~16h=30，8~12h=20，<8h=0 |
| 睡眠体位 | 0~20 | 保持=20，部分=10，未保持=0 |
| 清醒活动体位 | 0~20 | 同上 |
| 患者认知与配合 | 0~10 | 理解并配合=10 |
| 家属支持情况 | 0~10 | 有陪护且能监督=10 |

总分 0~100，≥85 完全依从。

**术后体位记录频次：** 每班次 1 次（每日 3 次），由当班护士评估填写。

### 3.10 体征趋势与绘图模型

**趋势查询的时间窗口：**

| 场景 | 窗口 | 返回点数 | 聚合 |
|---|---|---|---|
| 体温单（护理文书） | 住院全期 | 每日 1~6 点 | 不聚合 |
| 术后 72 小时密观 | 术后 72 小时 | 每 4 小时 1 点 | 不聚合 |
| 医生查阅 7 天趋势 | 7 天 | 最多 168 点 | 超过 200 点时 1 小时聚合（取 max/min/avg） |
| 出院小结趋势 | 住院全期 | 每日 1 点 | 按日聚合 |

**聚合规则（`AGGREGATION`）：**

当点数超过 `M08.VITAL.TREND_MAX_POINTS = 400` 时按时间桶聚合：

```python
# 每个时间桶返回三个值
{
    "bucket_start": "2026-10-20T00:00:00",
    "bucket_end": "2026-10-20T01:00:00",
    "count": 4,
    "min": 36.5,
    "max": 38.2,
    "avg": 37.1,
    "last": 37.8,
}
```

**体温单的特殊渲染：**

护理体温单（法定文书）有固定格式：横轴为日期时间格，纵轴 34~42℃。M08-04 提供原始点，M08-05 负责按体温单格式渲染 PDF。M08-04 不生成 PDF。

**视力趋势的排序处理：**

视力是 VARCHAR（含 LP/CF/HM/NLP），趋势图纵轴需按 `VISION_ORDER` 映射为序数值，渲染时坐标轴标签显示原文。

### 6.2 错误码规范

| 错误码 | 说明 | 触发场景 |
|---|---|---|
| `"0804001"` | 体征数值超出合法范围 | 体温 55℃、脉搏 0 |
| `"0804002"` | 采集或评估时间不能晚于当前时间 | 前端时钟超前 |
| `"0804003"` | 采集时间超出可回溯范围 | 超过 120 分钟 |
| `"0804004"` | 至少填写一项体征 | 全部为空 |
| `"0804005"` | 同一时点重复采集 | ±10 分钟内同项已存在 |
| `"0804006"` | 体征记录不存在 | ID 无效 |
| `"0804007"` | 超出修改窗口需审批 | 超 24 小时修改 |
| `"0804008"` | 无权修改他人采集的体征 | 非本人且非护士长 |
| `"0804009"` | 患者或病区信息缺失 | 归属键全空 |
| `"0804010"` | 评估项未全部完成 | 有必答项为空 |
| `"0804011"` | 已签名评估不可修改 | 状态非 DRAFT |
| `"0804012"` | 高风险必须选择措施 | 高风险但措施 <3 项 |
| `"0804013"` | 评估不存在 | ID 无效 |
| `"0804014"` | 量表模板未启用或不存在 | 编码错误 |
| `"0804015"` | 评估状态不允许此操作 | 已作废 |
| `"0804016"` | 告警不存在 | ID 无效 |
| `"0804017"` | 告警已闭环不可重复处置 | 状态非 PENDING/ACKNOWLEDGED |
| `"0804018"` | 处置措施不足 5 字 | 描述过短 |
| `"0804019"` | 未选择接收医生 | 报告医生但未选 |
| `"0804020"` | 阈值配置非法 | 级别顺序颠倒或高低值交叉 |
| `"0804021"` | 量表版本号必须递增 | 新版本号 ≤ 旧版本号 |
| `"0804022"` | 日期跨度超过限制 | 查询 >366 天 |
| `"0804023"` | 导出行数超过限制 | >50000 行 |
| `"0804024"` | 趋势查询体征项超过 3 项 | 多选超限 |
| `"0804025"` | 无权修改阈值配置 | 非护士长/护理部/管理员 |
| `"0804026"` | 门诊患者不支持该量表 | 量表不适用门诊 |
| `"0804027"` | 患者服务不可用 | M03-01 超时且无快照 |
| `"0804028"` | 评估签名服务不可用 | M02-05 超时 |
| `"0804029"` | 体征值为空不能执行告警判定 | 空值提交 |
| `"0804030"` | 批量采集数量超限 | >20 条 |
| `"0804031"` | 该体征项不适用于当前患者类型 | 如门诊患者录 IOP |
| `"0804032"` | 视力值格式非法 | "abc" |
| `"0804033"` | 收缩压必须大于舒张压 | 120/130 |
| `"0804034"` | 告警通知发送失败 | M03-05 不可用 |

        failed = []

    async def trend(
        self, patient_id: int, codes: str, date_from: str, date_to: str,
        mode: str, user: dict,
    ) -> dict:
        """体征趋势。"""
        code_list = [c.strip() for c in codes.split(",") if c.strip()]
        if len(code_list) > MAX_TREND_CODES:
            raise BizException("0804024", "趋势查询最多 %d 项" % MAX_TREND_CODES)
        for c in code_list:
            if c not in VITAL_CODES:
                raise BizException("0804022", "未知体征项: %s" % c)

        d1 = datetime.fromisoformat(date_from)
        d2 = datetime.fromisoformat(date_to)
        if (d2 - d1).days > MAX_QUERY_DAYS:
            raise BizException("0804022", "查询跨度超过 %d 天" % MAX_QUERY_DAYS)

        stmt = (
            select(M08VitalSign)
            .where(
                M08VitalSign.patient_id == patient_id,
                M08VitalSign.vital_time >= d1,
                M08VitalSign.vital_time < d2 + timedelta(days=1),
                M08VitalSign.is_deleted.is_(False),
            )
            .order_by(M08VitalSign.vital_time.asc())
        )
        rows = (await self.db.execute(stmt)).scalars().all()

        total = sum(len(r.values_json or []) for r in rows)
        aggregated = total > MAX_TREND_POINTS or mode != "RAW"

        series = []
        for code in code_list:
            pts = []
            for r in rows:
                v = self._pick_value(r.values_json, code)
                if v is None:
                    continue
                pts.append({
                    "t": r.vital_time.isoformat(),
                    "v": v,
                    "alert_level": r.alert_level_of(code),
                    "recorded_by_name": r.recorded_by_name,
                })
            lo, hi = VITAL_RANGES.get(code, (None, None))
            ref = self._ref_range(code)
            series.append({
                "vital_code": code,
                "vital_name": VITAL_NAMES.get(code, code),
                "unit": VITAL_UNITS.get(code, ""),
                "ref_min": ref[0] if ref else None,

    # ---------- 告警判定 ----------

    async def _detect_alerts(self, vital: Any, items: list) -> list:
        """判定体征告警。返回待落库的 M08VitalAlert 列表。"""
        alerts = []
        values = {}
        for it in items:
            code = it["vital_code"] if isinstance(it, dict) else it.vital_code
            val = it["value"] if isinstance(it, dict) else it.value
            values[code] = val

        now = datetime.now()
        for code, val in values.items():
            if code not in VITAL_THRESHOLDS:
                continue
            if not isinstance(val, (int, float, Decimal)):
                continue
            cfg = await self._load_threshold(code, vital.ward_id_snapshot)
            level, desc, threshold = self._judge_single(cfg, float(val))
            if level is None:
                continue
            alerts.append(self._make_alert(
                vital, code, val, level, desc, threshold, now,
            ))

        # 趋势判定
        trend_alerts = await self._detect_trend(vital, values, now)
        alerts.extend(trend_alerts)

        # 组合判定
        combo_alerts = await self._detect_combo(vital, values, now)
        alerts.extend(combo_alerts)

        return alerts

    def _judge_single(self, cfg: dict, val: float):
        """单值阈值判定，返回 (level, desc, threshold)。"""
        for level in ("CRITICAL", "SEVERE", "WARNING"):
            rule = cfg.get(level) or {}
            high = rule.get("high")
            low = rule.get("low")
            if high is not None and val >= high:
                unit = cfg.get("unit", "")
                return level, "超过%s阈值 %s%s" % (
                    _level_cn(level), high, unit), high
            if low is not None and val <= low:
                unit = cfg.get("unit", "")
                return level, "低于%s阈值 %s%s" % (
                    _level_cn(level), low, unit), low
        return None, None, None

    async def _detect_trend(self, vital: Any, values: dict, now: datetime) -> list:
        """趋势告警。"""
        alerts = []
        for code, rules in VITAL_THRESHOLDS.items():
            if code not in values:
                continue
            val = values[code]
            if not isinstance(val, (int, float, Decimal)):
                continue
            for rule in rules.get("TREND", []):
                window_hours = rule["window_hours"]
                delta = rule["delta"]
                since = vital.vital_time - timedelta(hours=window_hours)
                stmt = (
                    select(M08VitalSign)
                    .where(
                        M08VitalSign.patient_id == vital.patient_id,
                        M08VitalSign.vital_time >= since,
                        M08VitalSign.vital_time < vital.vital_time,
                        M08VitalSign.is_deleted.is_(False),
                    )
                    .order_by(M08VitalSign.vital_time.desc())
                    .limit(10)
                )
                prev_rows = (await self.db.execute(stmt)).scalars().all()
                for pr in prev_rows:
                    pv = self._pick_value(pr.values_json, code)
                    if pv is None:
                        continue
                    if rule["direction"] == "RISE" and float(val) - float(pv) >= delta:
                        alerts.append(self._make_alert(
                            vital, code, val, "TREND",
                            "%.0f 小时内上升 %.1f（%s → %s）" % (
                                window_hours, float(val) - float(pv), pv, val),
                            None, now,
                        ))
                        break
        return alerts

    async def _detect_combo(self, vital: Any, values: dict, now: datetime) -> list:
        """组合阈值告警。"""
        alerts = []
        for rule in COMBO_RULES:
            matched = True
            for code, op, threshold in rule["conditions"]:
                if code == "VISION_DROP":
                    drop = await self._vision_drop(vital.patient_id, threshold)
                    if not drop:
                        matched = False
                        break
                    continue
                if code == "IOP":
                    v = values.get("IOP_OD") or values.get("IOP_OS")
                    if v is None or float(v) < threshold:
                        matched = False
                        break
                    continue
                v = values.get(code)
                if v is None:
                    matched = False
                    break
                fv = float(v)
                if op == ">=" and fv < threshold:
                    matched = False
                    break
                if op == "<=" and fv > threshold:
                    matched = False
                    break
            if matched:
                alerts.append(self._make_alert(
                    vital, "COMBO", None, rule["level"],
                    "%s：%s" % (rule["name"], rule["desc"]), None, now,
                ))
        return alerts

    def _make_alert(self, vital: Any, code: str, val, level: str,
                    desc: str, threshold, now: datetime) -> M08VitalAlert:
        """构造告警对象。"""
        deadline = now + timedelta(minutes=LEVEL_DEADLINE_MINUTES[level])
        return M08VitalAlert(
            alert_no="AL%s%06d" % (now.strftime("%Y%m%d"), _seq(now)),
            patient_id=vital.patient_id,
            patient_name=getattr(vital, "patient_name", ""),
            bed_no=getattr(vital, "bed_no", None),
            ward_id=getattr(vital, "ward_id_snapshot", None),
            vital_id=vital.id,
            vital_code=code,
            vital_name=VITAL_NAMES.get(code, code),
            value=val,
            unit=VITAL_UNITS.get(code, ""),
            threshold=threshold,
            level=level,
            threshold_desc=desc,
            detected_at=now,
            deadline_at=deadline,
            status="PENDING",
            notify_status="PENDING",
            created_at=now,
            updated_at=now,
        )

    def _check_belonging(self, body: Any) -> None:

    def _check_time(self, t: datetime, now: datetime) -> None:
        if t > now:
            raise BizException("0804002", "采集时间不能晚于当前时间")
        if t < now - timedelta(minutes=MAX_TIME_BACKWARD_MINUTES):
            raise BizException(
                "0804003", "采集时间最多回溯 %d 分钟" % MAX_TIME_BACKWARD_MINUTES
            )

    def _check_items(self, items: list) -> None:
        if not items:
            raise BizException("0804004", "至少填写一项体征")
        for it in items:
            code = it["vital_code"] if isinstance(it, dict) else it.vital_code
            val = it["value"] if isinstance(it, dict) else it.value
            if code not in VITAL_CODES:
                raise BizException("0804001", "未知体征项: %s" % code)
            if code in VITAL_RANGES:
                lo, hi = VITAL_RANGES[code]
                try:
                    fv = float(val)
                except (TypeError, ValueError):
                    raise BizException(
                        "0804001", "%s 的值必须是数值" % VITAL_NAMES.get(code, code)
                    )
                if fv < lo or fv > hi:
                    raise BizException(
                        "0804001",
                        "%s 超出合法范围 %.1f~%.1f" % (
                            VITAL_NAMES.get(code, code), lo, hi),
                    )
            if code.startswith("VISION"):
                if not self._is_valid_vision(val):
                    raise BizException("0804032", "视力值格式非法: %s" % val)

        # 收缩压 > 舒张压
        d = {it["vital_code"] if isinstance(it, dict) else it.vital_code:
             (it["value"] if isinstance(it, dict) else it.value) for it in items}
        if "SBP" in d and "DBP" in d:
            if float(d["SBP"]) <= float(d["DBP"]):
                raise BizException("0804033", "收缩压必须大于舒张压")

    def _is_valid_vision(self, val) -> bool:
        if val is None:
            return True
        s = str(val).strip().upper()
        if s in ("LP", "LP?", "NLP", "HM", "REFUSED"):
            return True
        if s.startswith("CF"):
            return True
        try:
            f = float(s)
            return 0.0 <= f <= 3.0
        except ValueError:
            return False

    def _calc_bmi(self, values: list) -> Optional[Decimal]:
        w = self._pick_value(values, "WEIGHT")
        h = self._pick_value(values, "HEIGHT")
        if w is None or h is None:
            return None
        try:
            hh = float(h) / 100.0
            if hh <= 0:
                return None
            return Decimal(str(float(w) / (hh * hh))).quantize(
                Decimal("0.1"), rounding=ROUND_HALF_UP
            )
        except (TypeError, ValueError, ZeroDivisionError):
            return None

    def _items_to_json(self, items: list) -> list:
        out = []
        for it in items:
            if isinstance(it, dict):
                out.append({"code": it["vital_code"], "value": it.get("value"),
                            "extra": it.get("temp_type")})
            else:
                out.append({"code": it.vital_code, "value": it.value,
                            "extra": getattr(it, "temp_type", None)})
        return out

    def _pick_value(self, values: list, code: str):
        if not values:
            return None
        for v in values:
            if v.get("code") == code:
                return v.get("value")
        return None

    def _ref_range(self, code: str):
        return {
            "TEMP": (36.0, 37.2),
            "PULSE": (60, 100),
            "RESP": (12, 20),
            "SBP": (90, 139),
            "DBP": (60, 89),
            "SPO2": (95, 100),
            "GLU": (3.9, 6.1),
            "IOP_OD": (10.0, 21.0),
            "IOP_OS": (10.0, 21.0),
        }.get(code)

    def _aggregate(self, points: list, mode: str) -> list:
        """按时间桶聚合。"""
        if not points:
            return []
        bucket_sec = 3600 if mode == "HOURLY" else 86400
        buckets = {}
        for p in points:
            t = datetime.fromisoformat(p["t"])
            key = int(t.timestamp() // bucket_sec) * bucket_sec
            buckets.setdefault(key, []).append(p)
        out = []
        for key in sorted(buckets):
            vals = [float(x["v"]) for x in buckets[key]
                    if isinstance(x["v"], (int, float))]
            if not vals:
                continue
            out.append({
                "bucket_start": datetime.fromtimestamp(key).isoformat(),
                "bucket_end": datetime.fromtimestamp(key + bucket_sec).isoformat(),
                "count": len(vals),
                "min": min(vals),
                "max": max(vals),
                "avg": round(sum(vals) / len(vals), 2),
                "last": vals[-1],
            })
        return out

    async def _check_duplicate(self, patient_id: int, t: datetime, items: list) -> None:
        """同一时点（±10 分钟）同一体征项不重复。"""

        stmt = select(M08VitalSign).where(
            M08VitalSign.patient_id == patient_id,
            M08VitalSign.vital_time >= lo,
            M08VitalSign.vital_time <= hi,
            M08VitalSign.is_deleted.is_(False),
        )
        rows = (await self.db.execute(stmt)).scalars().all()
        new_codes = {
            it["vital_code"] if isinstance(it, dict) else it.vital_code for it in items
        }
        for r in rows:
            old_codes = {v.get("code") for v in (r.values_json or [])}
            dup = new_codes & old_codes
            if dup:
                raise BizException(
                    "0804005", "该时点已采集过 %s，请修改原记录" % ",".join(sorted(dup))
                )

    async def _vision_drop(self, patient_id: int, lines: int) -> bool:
        """判断视力是否较基线下降 ≥ N 行。"""
        stmt = (
            select(M08VitalSign)
            .where(
                M08VitalSign.patient_id == patient_id,
                M08VitalSign.is_deleted.is_(False),
            )
            .order_by(M08VitalSign.vital_time.desc())
            .limit(20)
        )
        rows = (await self.db.execute(stmt)).scalars().all()
        vals = []
        for r in rows:
            for c in ("VISION_BC_OD", "VISION_BC_OS"):
                v = self._pick_value(r.values_json, c)
                if v is not None and self._is_valid_vision(v):
                    vals.append(self._vision_score(v))
        if len(vals) < 2:
            return False
        # 近似：每 0.1 视力约 1 行

### 6.7 专题：为什么告警判定要独立于采集接口

**问题：** 体征采集是 M08 最高频的写操作（日均 400 条，早班 6:30~8:30 集中 60 条）。告警判定涉及「查阈值配置 + 查历史值 + 判趋势 + 判组合」，若不设计好，会成为采集的性能瓶颈。

**四个方案对比：**

| 方案 | 采集耗时 | 补录后能否重判 | 实现复杂度 | 结论 |
|---|---|---|---|---|
| A 采集接口内同步全量判定 | 约 280ms（3 次配置查询 + 1 次历史查询 + 组合判定） | ❌ 补录走更新接口，不重判 | 低 | **否** |
| B 采集接口内只判单值，趋势异步 | 约 90ms | ⚠️ 单值重判可行，趋势不重判 | 中 | 部分可行 |
| C 采集落库后发消息，独立服务消费判定 | 约 45ms | ✅ | 高（需消息幂等 + 重试） | 过度设计 |
| **D 采集接口内判单值 + 趋势/组合异步 + 补录走统一重判入口** | 约 60ms | ✅ | 中 | **✅ 采用** |

**采用 D 的理由：**

1. **单值阈值判定几乎是零成本**。阈值配置全部走 Redis 缓存（`m08:vital:threshold:{code}:{ward_id}`，TTL 600s），命中率 99% 以上；判定本身是 3 次浮点比较。同步判完不影响采集性能。

2. **趋势与组合判定必须查历史**，属于 I/O 操作。放在 `asyncio.create_task` 中异步执行，不阻塞采集响应。若异步失败，由 5 分钟一次的补偿扫描兜底（扫最近 1 小时内无告警记录的采集行重新判定）。

3. **补录必须统一走重判入口**。`_revoke_alerts` + `_detect_alerts` 这对组合在 `update` 与 `correct` 中都调用，保证「无论怎么改，告警都与最新值一致」。若只在采集接口里判，补录后的告警永远停在旧值上。

**实测数据（单病区 40 床早班高峰）：**

| 方案 | 采集 P95 | 采集 P99 | 早班 60 条总耗时 |
|---|---|---|---|
| A | 280ms | 620ms | 19.4s |
| D | 62ms | 110ms | 4.1s |

**副作用与处理：**

- 异步告警判定失败时，采集已成功但无告警 → 靠 `vital_alert_compensation_task` 每 5 分钟扫最近 1 小时的采集行，检查是否有值超阈值但无对应告警，有则补生成。扫描量约 30 行，耗时 < 20ms。
- 补录时旧告警被撤销置 `REVOKED`，而不是删除。历史告警的撤销本身也是信息（说明当时的判定基于错误数据）。

## 7. 缓存与异步任务设计

### 7.1 Redis 缓存

| Key 模式 | 类型 | TTL | 说明 |
|---|---|---|---|
| `m08:vital:threshold:{code}:{ward_id}` | String(JSON) | 600s | 体征阈值配置（病区级覆盖医院级） |
| `m08:vital:ref:{code}` | String(JSON) | 3600s | 体征参考区间 |
| `m08:vital:workbench:{ward_id}:{shift}` | String(JSON) | 30s | 采集工作台列表 |
| `m08:vital:latest:{patient_id}` | String(JSON) | 300s | 患者最新体征 |
| `m08:vital:trend:{patient_id}:{codes}:{from}:{to}` | String(JSON) | 300s | 趋势查询结果 |
| `m08:vital:seq:{yyyymmdd}` | String(INT) | 172800s | 体征编号序列 |
| `m08:vital:alert:open:{ward_id}` | ZSet | 60s | 病区未闭环告警（score = 检测时间戳） |
| `m08:assess:template:{code}:{version}` | String(JSON) | 3600s | 量表模板 |
| `m08:assess:templates` | String(JSON) | 1800s | 全部启用模板列表 |
| `m08:assess:patient:{patient_id}` | String(JSON) | 120s | 患者评估清单 |
| `m08:assess:risk:{ward_id}` | String(JSON) | 60s | 病区风险评估看板 |
| `m08:vital:ws:{ward_id}` | Pub/Sub | — | 告警实时推送到 WebSocket |
| `m08:vital:lock:{patient_id}` | String | 30s | 同一患者并发采集锁 |

**容量估算：**

| 类别 | 数量 | 单条大小 | 合计 |
|---|---|---|---|
| 阈值配置 | 24 项 × 5 病区 = 120 | 约 500 B | 60 KB |
| 参考区间 | 24 项 | 约 200 B | 5 KB |
| 工作台 | 5 病区 × 3 班次 = 15 | 约 60 KB | 900 KB |
| 最新体征 | 200 在院患者 | 约 300 B | 60 KB |
| 趋势缓存 | 200 患者 × 平均 2 种查询 = 400 | 约 20 KB | 8 MB |
| 告警 ZSet | 5 病区 | 约 30 条 | 15 KB |
| 量表模板 | 6 张 × 平均 2 版本 | 约 6 KB | 72 KB |
| 风险评估看板 | 5 病区 | 约 15 KB | 75 KB |
| **合计** | | | **约 9.2 MB** |

**缓存策略说明：**

1. **阈值配置基础数据优先**：阈值读频率远高于写频率（每采集一条读 1 次，1 天 400 次；修改每月不到 1 次）。缓存 TTL 600s 保证修改后最多 10 分钟内全局生效，同时避免每次采集都查库。

2. **趋势缓存 300s 而非更长**：趋势查询是最重的一次性查询（30 天约 120 行 × 2 项），单次约 45ms。缓存 5 分钟能覆盖「医生查房时多人同时看同一患者」的场景（一个患者查房时通常 2~4 人看），同时保证补录后 5 分钟内可见。

3. **工作台缓存 30s 而非 5 分钟**：工作台是护士持续盯着看的页面，30 秒刷新。若 TTL 5 分钟，护士采集完一条后要等 5 分钟才消失。

4. **告警 ZSet 而非 List**：告警需要按级别+时间排序且在处置后移除。ZSet 支持 `ZRANGEBYSCORE` 按时间取最新 N 条，也支持 `ZREM` 单条移除。

import logging
from datetime import datetime, timedelta

from celery import shared_task
from sqlalchemy import and_, select, update

from app.core.redis import redis_client
from app.db.session import AsyncSessionLocal

logger = logging.getLogger(__name__)


@shared_task(
    bind=True,
    name="m08.vital.trend_alert",
    max_retries=3,
    default_retry_delay=60,
)
def trend_alert_task(self, vital_id: int) -> dict:
    """异步判定趋势与组合告警。"""
    import asyncio

    async def _run() -> dict:
        async with AsyncSessionLocal() as db:
            from app.models.m08_vital import M08VitalAlert, M08VitalSign
            from app.services.m08.vital_service import VitalService

            svc = VitalService(db)
            vital = await db.get(M08VitalSign, vital_id)
            if vital is None or vital.is_deleted:
                return {"skipped": True}
            values = {v["code"]: v["value"] for v in (vital.values_json or [])}
            now = datetime.now()
            alerts = []
            alerts.extend(await svc._detect_trend(vital, values, now))
            alerts.extend(await svc._detect_combo(vital, values, now))
            for a in alerts:
                db.add(a)
            await db.commit()
            for a in alerts:
                await svc._notify_alert(a)
            await db.commit()
            return {"created": len(alerts)}

    try:
        return asyncio.run(_run())
    except Exception as exc:  # noqa: BLE001
        logger.error(
            "趋势告警判定失败 vital_id=%s: %s", vital_id, exc,
            extra={"vital_id": vital_id},
        )
        raise self.retry(exc=exc)


@shared_task(
    bind=True,
    name="m08.vital.alert_compensation",
    max_retries=3,
    default_retry_delay=120,
)
def alert_compensation_task(self) -> dict:
    """补偿扫描：最近 1 小时内超阈值但无告警的采集行。"""
    import asyncio

    async def _run() -> dict:
        async with AsyncSessionLocal() as db:
            from app.models.m08_vital import M08VitalAlert, M08VitalSign
            from app.services.m08.vital_service import VitalService

            svc = VitalService(db)
            since = datetime.now() - timedelta(hours=1)
            stmt = select(M08VitalSign).where(
                M08VitalSign.created_at >= since,
                M08VitalSign.is_deleted.is_(False),
            )
            rows = (await db.execute(stmt)).scalars().all()
            fixed = 0
            for row in rows:
                exists_stmt = select(M08VitalAlert.id).where(
                    M08VitalAlert.vital_id == row.id
                )
                exists = (await db.execute(exists_stmt)).first()
                if exists:
                    continue
                values = {v["code"]: v["value"] for v in (row.values_json or [])}
                items = [{"vital_code": k, "value": v} for k, v in values.items()]
                alerts = await svc._detect_alerts(row, items)
                if not alerts:
                    continue
                for a in alerts:
                    db.add(a)
                fixed += len(alerts)
            await db.commit()
            return {"scanned": len(rows), "fixed": fixed}

    try:
        return asyncio.run(_run())
    except Exception as exc:  # noqa: BLE001
        logger.error("告警补偿扫描失败: %s", exc)
        raise self.retry(exc=exc)


@shared_task(
    bind=True,
    name="m08.vital.alert_timeout",
    max_retries=3,
    default_retry_delay=60,
)
def alert_timeout_task(self) -> dict:
    """告警超时升级与自动关闭。"""
    import asyncio

    async def _run() -> dict:
        async with AsyncSessionLocal() as db:
            from app.models.m08_vital import M08VitalAlert

            now = datetime.now()
            # 超时未确认：WARNING 升级为 SEVERE 通知护士长
            stmt = select(M08VitalAlert).where(
                M08VitalAlert.status == "PENDING",
                M08VitalAlert.deadline_at < now,
            )
            rows = (await db.execute(stmt)).scalars().all()
            escalated = 0
            auto_closed = 0
            for a in rows:
                overtime_hours = (now - a.deadline_at).total_seconds() / 3600.0
                if overtime_hours >= 24:
                    a.status = "AUTO_CLOSED"
                    a.is_overtime = True
                    a.updated_at = now
                    auto_closed += 1
                else:
                    a.is_overtime = True
                    a.escalated_at = now
                    a.updated_at = now
                    escalated += 1
            await db.commit()
            return {"escalated": escalated, "auto_closed": auto_closed}

    try:
        return asyncio.run(_run())
    except Exception as exc:  # noqa: BLE001
        logger.error("告警超时扫描失败: %s", exc)
        raise self.retry(exc=exc)


@shared_task(
    bind=True,
    name="m08.vital.daily_stat",
    max_retries=2,
    default_retry_delay=300,
)
def daily_stat_task(self, stat_date: str | None = None) -> dict:
    """每日护理监测质量统计。"""
    import asyncio

    async def _run() -> dict:
        async with AsyncSessionLocal() as db:
            from sqlalchemy import func

            from app.models.m08_vital import M08Assessment, M08VitalAlert, M08VitalSign

            day = stat_date or (datetime.now() - timedelta(days=1)).strftime("%Y-%m-%d")
            d1 = datetime.fromisoformat(day)
            d2 = d1 + timedelta(days=1)

            cnt = (await db.execute(
                select(func.count()).select_from(M08VitalSign).where(
                    M08VitalSign.vital_time >= d1,
                    M08VitalSign.vital_time < d2,
                    M08VitalSign.is_deleted.is_(False),
                )
            )).scalar_one()
            alert_cnt = (await db.execute(
                select(func.count()).select_from(M08VitalAlert).where(
                    M08VitalAlert.detected_at >= d1,
                    M08VitalAlert.detected_at < d2,
                )
            )).scalar_one()
            assess_cnt = (await db.execute(
                select(func.count()).select_from(M08Assessment).where(
                    M08Assessment.assess_time >= d1,
                    M08Assessment.assess_time < d2,
                    M08Assessment.status == "SIGNED",
                )
            )).scalar_one()

            await redis_client.setex(
                "m08:vital:stat:%s" % day, 86400,
                __import__("json").dumps(
                    {"vital_count": cnt, "alert_count": alert_cnt,
                     "assess_count": assess_cnt},
                    ensure_ascii=False,
                ),
            )
            return {"date": day, "vital": cnt, "alert": alert_cnt, "assess": assess_cnt}

    try:
        return asyncio.run(_run())
    except Exception as exc:  # noqa: BLE001
        logger.error("每日统计失败: %s", exc)
        raise self.retry(exc=exc)

### 9.3 数据权限与脱敏

**数据权限范围：**

| 角色 | 可见范围 |
|---|---|

| 护士长 | 本病区全部患者 |

**脱敏规则：**

| 场景 | 脱敏方式 |
|---|---|
| 列表查询 | 患者姓名保留首字 + `*`（张*） |

| 导出报表 | 姓名完整 + 身份证后 6 位 |
| 审计日志 | 姓名脱敏 + 无具体数值 |

**跨病区限制：** 非护理部/质控角色，查询他人病区患者体征返回 `"0804008"`。

### 9.4 安全措施

| 措施 | 说明 |
|---|---|
| 采集人绑定 | 采集记录强制记录 `recorded_by`，不可伪造 |
| 时间防篡改 | `vital_time` 服务端二次校验（不能晚于服务器时间） |
| 修改留痕 | 每次修改写 `m08_vital_log`，含原值/新值/原因 |
| 告警不可删 | 告警只能置状态，物理删除需 DBA 脚本 |
| 评估签名 | SHA-256 摘要覆盖模板版本与全部得分，防篡改 |
| 敏感数据加密 | 备注字段中的诊断相关信息无需加密（已在病历系统内），但导出文件加密码 |
| 操作限流 | 单用户采集接口限 200 次/分钟 |
| SqlInjection 防御 | 全部走 SQLAlchemy 参数化，禁止字符串拼接 SQL |
