**设计说明：**

1. **正文段落独立成表（`m08_nursing_record_section`），而非主表里的 JSONB。** 与 M08-04 的体征不同：

   - 护理记录段落需要**按段统计**（「本月 S 段平均字数」「补录的段落集中在哪一段」）；
   - 签名摘要要覆盖**每一段全文**，逐段存储便于逐段比对；
   - 段落数量固定（3~5 段）不稀疏，无 JSONB 节省空间的优势；
   - 需要按 `section_code` 建索引做质控分析（如「多少条记录的 A 段为空」）。

2. **`(template_code, template_version)` 是快照而非外键。** 模板升级到 V2 后，V1 时期的护理记录仍按 V1 的段落要求判定完整性。这是法定文书的基本要求。

3. **`uk_m08_record_signed` 部分唯一索引防重复签名。** 同一患者、同一日期、同一班次、同一记录类型，只能有一条 SIGNED 记录。DRAFT 可以有多条（护士可能开了多个草稿窗口）。部分索引条件为 `status = 'SIGNED'`。

4. **`m08_nursing_record_log` 只增不改。** 触发器强制。日志记录「改了什么」，不记录「看了什么」（查询不写日志）。

5. **`m08_record_print` 独立成表而非在主表加打印次数字段。** 打印需要留痕到「谁、什么时间、打了几份、哪个打印机、成功与否」，这些是一次打印一条的记录，不是主表的一个计数器。

6. **不建外键。** 与其他 M08 子模块一致：高频写入 + 部分表可能归档，一致性由应用层保证。段落的 `record_id` 与主表的一致性由服务层在同一事务内保证。

7. **`auto_summary` 存 JSONB 而非独立表。** 它是「渲染时刻的源数据快照」，整体写入整体读取，从不单独查询。存 JSONB 最合适。

### 4.2 表：`m08_record_template`

**用途：** 护理文书模板。五种记录类型各一套，支持版本化与科室维度覆盖。

**字段定义：**

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | 否 | IDENTITY | 主键 |
| `template_code` | VARCHAR(32) | 否 | — | 模板编码 |
| `template_name` | VARCHAR(128) | 否 | — | 模板名称 |
| `version` | INT | 否 | — | 版本号 |
| `record_type` | VARCHAR(16) | 否 | — | 所属记录类型 |
| `description` | VARCHAR(500) | 是 | NULL | 模板说明 |
| `sections_def` | JSONB | 否 | — | 段落定义数组 |
| `problems_def` | JSONB | 是 | NULL | 护理问题清单数组 |
| `problems_required` | BOOLEAN | 否 | FALSE | 护理问题是否必选 |
| `min_total_chars` | INT | 否 | 0 | 全记录最少总字数 |
| `record_time_editable` | BOOLEAN | 否 | TRUE | 记录时间是否可改 |
| `dept_scope` | VARCHAR(64) | 是 | NULL | 适用科室（逗号分隔，空=全部） |
| `shift_scope` | VARCHAR(64) | 是 | NULL | 适用班次（逗号分隔，空=全部） |
| `is_active` | BOOLEAN | 否 | TRUE | 是否启用 |
| `is_builtin` | BOOLEAN | 否 | FALSE | 是否内置（内置不可删） |
| `is_default` | BOOLEAN | 否 | FALSE | 是否该类型默认模板 |
| `sort_no` | SMALLINT | 否 | 100 | 排序号 |
| `remark` | VARCHAR(500) | 是 | NULL | 备注 |
| `created_by` | BIGINT | 是 | NULL | 创建人 |
| `created_at` | TIMESTAMP | 否 | NOW() | 创建时间 |
| `updated_by` | BIGINT | 是 | NULL | 更新人 |
| `updated_at` | TIMESTAMP | 否 | NOW() | 更新时间 |
| `is_deleted` | BOOLEAN | 否 | FALSE | 软删除 |

**索引设计：**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| `pk_m08_record_template` | 主键 | `id` | — |
| `uk_m08_record_tpl_key` | 唯一（部分） | `(template_code, version)` WHERE `is_deleted = FALSE` | 版本唯一 |
| `uk_m08_record_tpl_active` | 唯一（部分） | `(template_code)` WHERE `is_active = TRUE AND is_deleted = FALSE` | **同一模板仅一个启用版本** |
| `idx_m08_record_tpl_type` | B-Tree | `(record_type, is_active)` | 按类型查列表 |
| `idx_m08_record_tpl_sort` | B-Tree | `(sort_no, template_code)` | 列表排序 |

**约束说明：**

```sql
-- 记录类型枚举
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_type
  CHECK (record_type IN ('GENERAL', 'CRITICAL', 'OR', 'DISCHARGE_GUIDE', 'EDUCATION'));

-- 版本号正数
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_version
  CHECK (version >= 1);

-- 段落定义必须是数组且非空
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_sections
  CHECK (jsonb_typeof(sections_def) = 'array' AND jsonb_array_length(sections_def) >= 1);

-- 段落数上限
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_sections_max
  CHECK (jsonb_array_length(sections_def) <= 10);

-- 护理问题清单必须是数组
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_problems
  CHECK (problems_def IS NULL OR jsonb_typeof(problems_def) = 'array');

-- 最少总字数非负
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_min_chars
  CHECK (min_total_chars >= 0);

-- 内置模板编码限定
ALTER TABLE m08_record_template
  ADD CONSTRAINT ck_m08_record_tpl_builtin
  CHECK (is_builtin = FALSE
         OR template_code IN ('GENERAL_NURSING', 'CRITICAL_NURSING', 'OR_NURSING',
                              'DISCHARGE_GUIDE', 'HEALTH_EDU'));

-- 同模板同时只有一个启用版本
CREATE UNIQUE INDEX uk_m08_record_tpl_active
  ON m08_record_template (template_code)
  WHERE is_active = TRUE AND is_deleted = FALSE;

-- 同版本唯一
CREATE UNIQUE INDEX uk_m08_record_tpl_key
  ON m08_record_template (template_code, version)
  WHERE is_deleted = FALSE;

COMMENT ON TABLE m08_record_template IS 'M08-05 护理文书模板，版本化定义';
COMMENT ON COLUMN m08_record_template.sections_def IS '段落定义数组，形如 [{"code":"SUBJECTIVE","name":"主观资料","required":true,"placeholder":"患者主诉：","min_length":10,"max_length":800,"auto_fill":null,"sort_no":1}]';
COMMENT ON COLUMN m08_record_template.problems_def IS '护理问题清单，形如 [{"code":"PAIN","name":"疼痛"},{"code":"INFECTION","name":"感染风险"}]';
COMMENT ON COLUMN m08_record_template.min_total_chars IS '全记录最少总字数，0 表示不限制';
COMMENT ON COLUMN m08_record_template.dept_scope IS '适用科室 ID，逗号分隔；为空表示全部科室';
COMMENT ON COLUMN m08_record_template.shift_scope IS '适用班次，逗号分隔；为空表示全部班次';
```

**预置 5 张模板（V1）：**

| template_code | template_name | record_type | 段落 | 最少总字数 | 问题必选 |
|---|---|---|---|---|---|
| `GENERAL_NURSING` | 一般护理记录 | `GENERAL` | S/O/A/P | 60 | FALSE |
| `CRITICAL_NURSING` | 危重护理记录 | `CRITICAL` | S/O/E/A/P | 120 | TRUE |
| `OR_NURSING` | 手术护理记录 | `OR` | 术前/O/E/术中/术后 | 150 | FALSE |
| `DISCHARGE_GUIDE` | 出院指导记录 | `DISCHARGE_GUIDE` | 指导内容/注意事项/复诊安排 | 80 | FALSE |
| `HEALTH_EDU` | 健康教育记录 | `EDUCATION` | 教育主题/教育内容/掌握情况 | 60 | FALSE |

**设计要点：**

1. **为什么用 JSONB 存段落定义而非建子表。**
   段落定义是「一次编写、整体读取」的配置。打开记录页就要拿到全部段落结构，JSONB 一次读出比 JOIN 五张表快。段落不会单独查询或按段落统计（统计走 `m08_nursing_record_section` 的实际内容表）。若建子表，每次打开记录页要多一次 JOIN，还得维护两张表的版本一致性。

2. **`uk_m08_record_tpl_active` 保证同一模板只有一个启用版本。**
   若两个版本同时启用，评估时不知道该用哪个版本判定完整性。新版本启用必须先停用旧版本。

3. **`is_builtin` 限定编码枚举。**
   内置五张模板编码固定，防止误改编码破坏已有的记录引用。

4. **`dept_scope` 用逗号分隔字符串而非 JSONB 数组。**
   它有三种语义：NULL（全部）、具体列表。用逗号分隔字符串可以用 `LIKE` 或 `string_to_array` 判断，比 `jsonb_array_contains` 更直观，且长度短（一般 1~3 个科室）。若将来需要按科室建索引再改 JSONB。

**量级估算：**

| 项目 | 数值 |
|---|---|
| 模板数 | 5 张 × 平均 2 版本 = 10 条 |
| 单行长度 | 约 5 KB（含 sections_def） |
| 合计 | 约 50 KB |

**分区：** 不分区。

**状态机：**

```
        ┌──────────┐
        │  DRAFT   │  草稿
        └────┬─────┘
             │ 签名
             ▼
        ┌──────────┐
        │  SIGNED  │  已签名（只读）
        └────┬─────┘
             │ 护士长作废
             ▼
        ┌──────────┐
        │  VOIDED  │  已作废
        └──────────┘
```

**设计要点：**

1. **为什么 `uk_m08_record_signed` 只约束 SIGNED。**
   DRAFT 可能有多条（护士可能开了多个窗口），只有签名后的记录才是「这一班次的正式记录」。若约束所有状态，护士开两个草稿窗口就会报错。

2. **为什么 `record_date` 冗余存而非查询时 `DATE(record_time)`。**
   统计与索引都按日期聚合。`DATE(record_time)` 无法走索引，必须建表达式索引；冗余列更直观，且配合 `ck_m08_record_date` 保证一致。

3. **`is_late` 与 `cross_shift` 互斥。**
   一条记录不可能既是「班次后 30 分钟内补写」（归上一班次）又是「超 30 分钟」（归当前班次）。

4. **`total_chars` 冗余存。**
   统计「平均字数」要扫几千行并 SUM 关联表。冗余存后 `AVG(total_chars)` 直接走索引。

5. **`archived` 字段存在但归档动作在 M06-06。**
   M08-05 接收 `m06.record.archived` 事件后置位。归档后的记录加强只读（即使护士长也不能作废）。

6. **`version` 乐观锁。**
   两个窗口同时改同一草稿时，后提交的会检测到 version 不匹配并报 `"0805039"`。不用悲观锁是因为草稿编辑时间长（可能 5 分钟），悲观锁会长时间占行。

```sql
-- 段落编码枚举（六种标准段 + 三种专用段）

  ADD CONSTRAINT ck_m08_section_code
  CHECK (section_code IN ('SUBJECTIVE', 'OBJECTIVE', 'EYE', 'ASSESSMENT', 'PLAN',

                          'GUIDE_CONTENT', 'PRECAUTION', 'FOLLOW_UP',

-- 段落中文名不能为空字符串

  ADD CONSTRAINT ck_m08_section_name
  CHECK (char_length(btrim(section_name)) >= 1);

-- 字数非负
ALTER TABLE m08_nursing_record_section
  ADD CONSTRAINT ck_m08_section_chars
  CHECK (char_count >= 0);

-- 字数必须与正文长度一致（中文字符按 1 计）
ALTER TABLE m08_nursing_record_section
  ADD CONSTRAINT ck_m08_section_count_match
  CHECK (char_count = COALESCE(char_length(text_content), 0));

-- 排序号正数
ALTER TABLE m08_nursing_record_section
  ADD CONSTRAINT ck_m08_section_sort
  CHECK (sort_no > 0);

COMMENT ON TABLE m08_nursing_record_section IS 'M08-05 护理记录段落正文，SOAP 各段独立存储';
COMMENT ON COLUMN m08_nursing_record_section.text_content IS '段落正文，签名时字体锁定，是签名摘要的覆盖对象之一';
COMMENT ON COLUMN m08_nursing_record_section.char_count IS '段落字数，等于 char_length(text_content)，由约束强制一致';
COMMENT ON COLUMN m08_nursing_record_section.is_auto_filled IS '段落初始内容是否来自自动汇总（护士可修改，此处仅记录初始来源）';
```

**设计要点：**

1. **`ck_m08_section_count_match` 强制字数与正文一致。**
   签名摘要覆盖 `text_content` 而不覆盖 `char_count`。若 `char_count` 与正文不一致，统计会失真。约束强制一致，应用层只需保证写正文时同步写字数。

2. **`idx_m08_section_text_trgm` 支持正文检索。**
   质控抽查需要按关键词找记录（如「找出所有写了『已告知』的记录检查健康教育是否落实」）。中文 `tsvector` 需要分词扩展（zhparser/pg_jieba），运维复杂；`pg_trgm` 三元组索引在 15 万行规模下 `LIKE '%关键词%'` 从 45ms 降到 3ms。

3. **`is_auto_filled` 只记录初始来源。**
   护士可能改了自动汇总的内容。该字段反映「这段最初是否由系统填充」，不是「现在是否还是系统内容」。后者无法判定，也不重要——重要的是「护士有没有认真写」。

```python
class RecordCreateIn(BaseModel):
    """创建护理记录。"""

    patient_id: int = Field(..., ge=1)
    patient_name: Optional[str] = Field(None, max_length=64)
    ward_id: int = Field(..., ge=1)
    bed_no: Optional[str] = Field(None, max_length=16)
    encounter_id: Optional[int] = Field(None, ge=1)
    admission_id: Optional[int] = Field(None, ge=1)
    schedule_id: Optional[int] = Field(None, ge=1)
    record_type: RecordType
    template_code: str = Field(..., max_length=32)
    record_time: datetime
    sections: list[SectionIn] = Field(..., min_length=1, max_length=10)
    problems: list[str] = Field(default_factory=list, max_length=20)
    remark: Optional[str] = Field(None, max_length=500)
    auto_summary: Optional[dict] = None

    @model_validator(mode="after")
    def _check_belonging(self) -> "RecordCreateIn":
        if not (self.encounter_id or self.admission_id or self.schedule_id):
            raise ValueError("必须提供就诊/住院/手术归属之一")
        return self

    @field_validator("sections")
    @classmethod
    def _check_unique_section(cls, v: list[SectionIn]) -> list[SectionIn]:
        codes = [s.code for s in v]
        if len(set(codes)) != len(codes):
            raise ValueError("段落编码不能重复")
        return v
```

## 附录 C：关键部分索引

| 索引名 | 表 | 条件 | 目的 |
|---|---|---|---|
| `uk_m08_record_tpl_key` | `m08_record_template` | `is_deleted = FALSE` | 模板版本唯一 |
| **`uk_m08_record_tpl_active`** | `m08_record_template` | `is_active = TRUE AND is_deleted = FALSE` | **同模板仅一个启用版本** |
| `uk_m08_record_no` | `m08_nursing_record` | `is_deleted = FALSE` | 记录编号唯一 |
| **`uk_m08_record_signed`** | `m08_nursing_record` | `status = 'SIGNED' AND is_deleted = FALSE` | **同患者同班次同类型仅一条有效签名** |
| **`idx_m08_record_admission`** | `m08_nursing_record` | `admission_id IS NOT NULL` | **M06-06 D-14 判定主力索引** |
| `idx_m08_record_draft` | `m08_nursing_record` | `status = 'DRAFT' AND is_deleted = FALSE` | 草稿清理 |
| `idx_m08_record_void` | `m08_nursing_record` | `status = 'VOIDED'` | 作废审计 |
| `idx_m08_record_unsigned` | `m08_nursing_record` | `status = 'DRAFT'` | 未签名看板 |
| `uk_m08_section_code` | `m08_nursing_record_section` | — | 同记录同段落唯一 |
| `idx_m08_section_record` | `m08_nursing_record_section` | — | 按记录取全部段落（主力） |
| `idx_m08_section_text_trgm` | `m08_nursing_record_section` | — | 正文关键词检索 |
| `idx_m08_print_queued` | `m08_record_print` | `status = 'QUEUED'` | 僵尸任务扫描 |
| `idx_m08_print_failed` | `m08_record_print` | `status = 'FAILED'` | 失败统计 |

**关键索引的收益与代价：**

| 索引 | 年维护成本（写） | 查询收益 |
|---|---|---|
| `uk_m08_record_signed` | 每插入 1 行多 1 次 B-Tree 写，约 0.3ms | 签名前查重从 8ms → 0.2ms |
| `idx_m08_record_admission` | 约 0.2ms/行 | D-14 判定从 45ms → 1.2ms |
| `idx_m08_section_text_trgm` | 约 3ms/行（GIN 写入贵） | 关键词检索从 45ms → 3ms |

`idx_m08_section_text_trgm` 是唯一「写代价明显高于读收益」的索引。若正文检索需求不强（如质控不做关键词抽查），可考虑不建，节省约 2.1 GB 存储与每次插入 3ms。本设计保留它，因为「按关键词抽查护理记录」是质控的核心手段之一。
