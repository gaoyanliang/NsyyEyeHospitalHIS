## 1. 模块概述

### 1.1 模块定位

M04 门诊管理是医院信息系统中**患者接触最频繁、并发最高、业务链条最长**的核心模块。它承载患者从"**想来看病**"到"**看完离开**"的完整闭环。

### 1.2 一句话概括

> **M04 把"号"管明白**：谁在什么时候有号、谁能挂到、挂到之后去哪、什么时候轮到、最后数据对不对。

### 1.3 核心价值

| 价值 | 说明 |
|---|---|
| **防超卖** | 号源唯一权威来源，分布式并发下不超卖 |
| **防黄牛** | 实名 + 黑名单 + 频率限制 |
| **保安全** | 五级分诊，危重不漏诊 |
| **提效率** | 叫号自动化，患者不必站着排队 |
| **保公平** | 特殊人群优先有政策依据、可审计 |
| **可追溯** | 全流程留痕，数据可核对 |

## 3. 业务模型

### 3.1 号源模型（M04-01，全模块基石）

#### 3.1.1 号源三层结构

```
排班模板 m04_schedule_template
   │ 按周规则 + 科室 + 医生 + 班次
   ▼ 生成
排班 m04_schedule
   │ 某日某医生某班次
   ▼ 生成
号源 m04_reg_slot
   │ 每个号一个序号（1~N）
   ▼ 占用
挂号 / 预约
```

#### 3.1.2 防超卖模型（最关键）

```
┌─────────────────────────────────────────────────────────────┐
│  Redis（权威）                                               │
│  m04:slot:stock:{schedule_id}  →  剩余号源数（String）        │
│  DECR 原子操作；结果 < 0 立即 INCR 回滚                       │
└────────────────────────┬────────────────────────────────────┘
                         │ 扣减成功
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  PostgreSQL（持久化）                                        │
│  m04_reg_slot                                                │
│  SELECT ... FOR UPDATE SKIP LOCKED                           │
│  WHERE status='AVAILABLE' ORDER BY slot_no ASC               │
└────────────────────────┬────────────────────────────────────┘
                         │ 定期对账
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  对账 m04_slot_reconcile_log                                 │
│  Redis 库存 vs DB 可用数，差异记录 + 告警                     │
└─────────────────────────────────────────────────────────────┘
```

> **铁律：Redis 不可用时，拒绝挂号，绝不降级为"只查 DB"。**
> 宁可暂时不能挂号，也不能超卖。

#### 3.1.3 号源内部接口（唯一入口）

| 接口 | 说明 | 调用方 |
|---|---|---|
| `POST /internal/v1/m04/slot/reserve` | 占用号源（返回 slot_no） | 02、03、06 |
| `POST /internal/v1/m04/slot/confirm` | 确认占用（预约转挂号） | 02、03 |
| `POST /internal/v1/m04/slot/release` | 释放号源 | 02、03 |
| `GET /internal/v1/m04/slot/available` | 查询可用号源 | 02、03、M03-06 |

### 3.2 预约模型（M04-02）

#### 3.2.1 预约 vs 挂号

| 维度 | 预约 | 挂号 |
|---|---|---|
| 语义 | **占位**，未就诊 | **就诊**，已确认 |
| 收费 | 不收费 | 收费 |
| 产出 | 预约单 | 挂号单 + 就诊号 + 队列号 |
| 状态 | `BOOKED` | `REGISTERED` |
| 号源 | 占用 | 占用（预约转挂号时确认） |

#### 3.2.2 改约事务（核心）

```
begin
  ① reserve(新号源)      → 成功？失败则整体回滚
  ② release(旧号源)
  ③ update appointment
commit
```

> **任何一步失败：新号源回滚，原预约不变。**

#### 3.2.3 信用分模型

| 行为 | 分值变化 |
|---|---|
| 正常履约 | +1（上限 100） |
| 爽约 | -10 |
| 迟到取消 | -5 |
| 提前取消（>24h） | 0 |

| 信用分区间 | 限制 |
|---|---|
| ≥90 | 无限制 |
| 60~89 | 不可预约热门号 |
| <60 | **禁止预约**，需现场挂号 |

### 3.3 挂号模型（M04-03）

#### 3.3.1 挂号状态机

```
        ┌──────────────┐
        │  REGISTERED  │  已挂号（待收费）
        └──────┬───────┘
               │
      ┌────────┼────────────┬──────────────┐
      │ 已收费  │ 退号        │ 作废          │
      ▼        ▼            ▼              ▼
┌──────────┐┌──────────┐┌──────────┐┌──────────┐
│  PAID    ││ REFUNDED ││CANCELLED ││          │
└────┬─────┘└──────────┘└──────────┘└──────────┘
     │ 就诊开始（M07）
     ▼
┌──────────┐
│IN_VISIT  │
└────┬─────┘
     │ 完成
     ▼
┌──────────┐
│COMPLETED │
└──────────┘
```

#### 3.3.2 退号铁律

```
退号 → 先调 M16 退费
        ├─ 失败 → 退号不生效（返回 54219）
        └─ 成功 → 才更新状态 + 释放号源
```

> **绝不能出现"退了号但没退钱"。**

#### 3.3.3 挂号费稽核

```
挂号单数  ==  号源占用数  ==  收费单数
     │            │              │
     └────────────┴──────────────┘
                  │
           差异 → m04_reg_fee_audit 记录 + 告警
```

### 3.4 分诊模型（M04-04）

#### 3.4.1 五级分诊

| 级别 | 名称 | 响应时限 | 权重 | 眼科典型场景 |
|---|---|---|---|---|
| L1 | 濒危 | 立即 | 1000 | 化学伤、眼球穿孔、突发失明 |
| L2 | 危重 | ≤10 分钟 | 800 | 急性闭角型青光眼、视网膜中央动脉阻塞 |
| L3 | 急症 | ≤30 分钟 | 600 | 眼外伤、新发闪光感、飞蚊骤增 |
| L4 | 亚急症 | ≤60 分钟 | 400 | 视力渐进下降、眼压升高 |
| L5 | 非急症 | 按序 | 200 | 常规复查、验光咨询 |

#### 3.4.2 级别覆盖（只升不降）

| 条件 | 最低级别 |
|---|---|
| 绿色通道 | L2 |
| 急诊挂号 | L2 |
| 高龄 ≥80 | L4 |
| 儿童 ≤3 | L4 |
| 军残/优抚 | L4 |

> **规则：覆盖只能让数字变小（更紧急），不能变大。**

#### 3.4.3 队列排序

```
排序键 = (priority_weight DESC, triaged_at ASC)
priority_weight = 级别权重 + 加分
加分 = 绿色通道 200 + 军残 100 + 高龄 50 + 儿童 50
```

### 3.5 叫号模型（M04-05）

#### 3.5.1 叫号状态机

```
WAITING ──呼叫──► CALLING ──┬─到诊──► ENTERING ──► IN_VISIT ──► COMPLETED
                            │
                            ├─超时──► NO_ANSWER ──┬─复叫──► CALLING
                            │                     └─过号──► PASSED
                            │
                            └─跳过──► SKIPPED
                                        │
PASSED ──重新排队──► REQUEUED ──────────┘
```

#### 3.5.2 降级策略

| 组件 | 故障 | 降级 |
|---|---|---|
| WebSocket | 断线 | HTTP 轮询（3s） |
| TTS 语音 | 不可用 | **静音**，屏显仍工作 |
| 短信 | 不可用 | 跳过，屏显仍工作 |
| **屏显** | 不可用 | **不可降级**（核心） |

### 3.6 特殊号模型（M04-06）

#### 3.6.1 凭证状态机

```
PENDING ──核验通过──► VERIFIED ──到期──► EXPIRED
   │                    │
   ├─核验失败──► REJECTED │ 撤销
   │              │       ▼
   └──重新核验────┘    REVOKED
```

#### 3.6.2 加号审批路径

| 类型 | 数量 | 路径 |
|---|---|---|
| 绿色通道/急危重 | ≤3 | **自动通过** |
| 医生/科室加号 | ≤5 | 科主任 |
| 患者请求 | — | 科主任 → 医务科 |
| 特批 | — | 科主任 → 医务科 → 院领导 |

#### 3.6.3 跨年次数（惰性重置）

```
使用前检查 annual_year == 当前年
  ├─ 相等 → 直接累加
  └─ 不等 → annual_used = 0，annual_year = 当前年
```

> 不想依赖每年清零任务，避免漏跑卡住患者。

### 3.7 统计模型（M04-07）

#### 3.7.1 核心口径（全院唯一）

| 指标 | 定义 |
|---|---|
| 挂号人次 | 当日挂出号数（含退号前） |
| 退号人次 | 当日退号数 |
| **有效挂号人次** | 挂号 - 退号 |
| **就诊人次** | 实际就诊人次（状态 ≥ IN_VISIT） |
| **就诊人数** | 去重患者数 |
| 过号人次 | 叫号未就诊 |
| 爽约人次 | 预约未到 |

**人次 vs 人数：**

```
患者张明上午看白内障、下午看眼底病
  → 2 人次，1 人数
医务人员关注"人次"（工作量），管理者关注"人数"（服务人群）
```

## 8. 业务规则与校验

### 8.1 跨子模块核心规则

| 编号 | 规则 | 说明 | 违反后果 |
|---|---|---|---|
| **R-01** | 号源唯一来源 | 只有 M04-01 能改号源 | 超卖 |
| **R-02** | Redis 权威 | Redis 不可用时拒绝挂号 | 超卖 |
| **R-03** | 退号先退费 | M16 退费成功才更新挂号 | 钱账不符 |
| **R-04** | 覆盖只升不降 | 优先级覆盖只能变紧急 | 危重被降级 |
| **R-05** | 一挂号一分诊 | 一个挂号只能有 1 条有效分诊 | 重复入队 |
| **R-06** | 一诊室一在叫 | 一个诊室同时只有一个 CALLING | 叫号混乱 |
| **R-07** | 凭证全局唯一 | 同一凭证号不能被两个患者使用 | 冒用 |
| **R-08** | 日志一挂号一行 | `registration_id` 唯一 | 统计重复 |
| **R-09** | 已就诊不可退号 | 状态 ≥ IN_VISIT 拒绝退号 | 数据不一致 |
| **R-10** | 危重必填原因 | L1~L3 必须填分级原因 | 无法追溯 |
