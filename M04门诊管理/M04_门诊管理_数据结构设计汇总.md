## 2. 全局设计规范

### 2.1 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 表名 | `m04_{子域}_{实体}`，小写下划线 | `m04_reg_slot` |
| 字段名 | 小写下划线 | `schedule_date` |
| 主键 | `id` | `id BIGINT` |
| 业务主键 | `{实体}_no` | `registration_no` |
| 外键字段 | `{实体}_id` | `registration_id` |
| 布尔字段 | `is_{属性}` / `has_{属性}` | `is_special`, `is_deleted` |
| 时间字段 | `{动作}_at`（时间戳）/ `{属性}_date`（日期） | `created_at`, `schedule_date` |
| 金额字段 | `{属性}_amount` / `{属性}_fee` / `{属性}_total` | `discount_fee`, `actual_total` |
| 索引 | `idx_m04_{表简写}_{字段}` | `idx_m04_triage_date` |
| 唯一索引 | `uk_m04_{表简写}_{字段}` | `uk_m04_triage_reg` |
| 约束 | `ck_m04_{表简写}_{规则}` | `ck_m04_triage_level` |

> **注意：** 子模块前缀已包含在表名中，索引名中不再重复子模块序号，避免超长。

### 2.2 字段类型规范

| 用途 | 类型 | 说明 |
|---|---|---|
| 主键 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 支持批量导入指定 ID |
| 外键 | `BIGINT` | 不建物理外键（微服务解耦） |
| 业务单号 | `VARCHAR(32)` | `RG`/`AP`/`TR`/`CL` + 日期 + 序号 |
| 名称 | `VARCHAR(64)` / `VARCHAR(128)` | 患者名 64，科室名 128 |
| 编码 | `VARCHAR(32)` | 各类 code |
| 状态 | `VARCHAR(16)` | 大写下划线枚举 |
| 长文本 | `TEXT` | 主诉、处置措施 |
| 短备注 | `VARCHAR(500)` | — |
| 金额 | `NUMERIC(10,2)` / `NUMERIC(12,2)` | 单价 10,2；合计 12,2 |
| 时长 | `NUMERIC(6,1)` | 分钟，1 位小数 |
| 百分比 | `NUMERIC(5,2)` | 0~100，2 位小数 |
| 日期 | `DATE` | 无时间 |
| 时间 | `TIMESTAMP` | 不带时区（应用层统一东八区） |
| 布尔 | `BOOLEAN` | 字面量 `TRUE`/`FALSE` |
| 扩展数据 | `JSONB` | 体征、参数、快照 |

### 2.3 标准字段

**所有业务表必须包含：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `created_at` | TIMESTAMP | 创建时间，`DEFAULT CURRENT_TIMESTAMP` |
| `updated_at` | TIMESTAMP | 更新时间，由触发器维护 |

**可软删除的表额外包含：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `is_deleted` | BOOLEAN | `DEFAULT FALSE` |

**用于审计的表额外包含：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `created_by` | BIGINT | 创建人 |
| `created_by_name` | VARCHAR(64) | 创建人姓名（冗余，避免关联） |

**说明：**

- **流水类表（挂号、分诊、叫号、日志）不做软删除**，用状态字段表达（`CANCELLED` / `REFUNDED` / `VOID`）
- **配置类表使用软删除**，保留历史配置可追溯
- `*_name` 冗余字段用于**列表展示免关联**，允许不一致（定期由校正任务同步）

### 2.4 状态字段规范

| 规范 | 说明 |
|---|---|
| 类型 | `VARCHAR(16)`，不用 `ENUM`（便于扩展） |
| 值 | 全大写下划线：`IN_VISIT`、`NO_ANSWER` |
| 约束 | `CHECK (status IN (...))` 枚举约束 |
| 中文名 | 由 ORM 的 `__STATUS_LABELS__` 字典映射，**不入库** |
| 默认值 | 必须显式指定，如 `DEFAULT 'PENDING'` |

### 2.5 触发器规范

```sql
-- 更新时间触发器（所有表共用）
CREATE OR REPLACE FUNCTION fn_set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 为每张表绑定
CREATE TRIGGER trg_m04_triage_updated_at
    BEFORE UPDATE ON m04_triage
    FOR EACH ROW
    EXECUTE FUNCTION fn_set_updated_at();
```

> **注意：** SQLAlchemy 的 `onupdate=func.now()` 也设置了更新时间，两者等价，触发器作为**兜底**（防止绕过 ORM 的更新）。

### 2.6 外键策略

**M04 内部不建物理外键，跨模块同样不建。**

| 原因 | 说明 |
|---|---|
| 性能 | 高并发写时不触发外键检查 |
| 解耦 | 微服务化时可拆分库 |
| 一致性 | 由应用层事务 + 定期对账保证 |
| 分区 | 分区表外键性能差 |

**替代措施：**

| 措施 | 说明 |
|---|---|
| 应用层校验 | Service 层查询目标存在 |
| 定期对账 | `m04_slot_reconcile_log`、`m04_data_check` |
| 逻辑约束 | `ON DELETE` 由业务状态机控制 |

**例外：** 表内部的**唯一索引**照常建立（这不算外键）。

## 3. 跨表关系与数据流

### 3.1 主数据流（挂号到就诊）

```
m04_schedule（排班）
      │ 1:N
      ▼
m04_reg_slot（号源）◄──────── m04_appointment（预约）
      │                            │ 转挂号
      │ 占用                        ▼
      ▼                      m04_registration（挂号）
m04_registration ──────────────────┘
      │ 1:1
      ▼
m04_clinic_log（门诊日志）
      │
      ├── 1:1 ──► m04_triage（分诊）
      │               │ 1:N
      │               ▼
      │           m04_queue_entry（队列）
      │               │ 1:N
      │               ▼
      │           m04_call_record（叫号）
      │
      └── 汇总 ──► m04_daily_report（日报）
```

### 3.2 关键一对一关系

| 关系 | 说明 | 实现 |
|---|---|---|
| `m04_registration` : `m04_clinic_log` | 一挂号一日志 | `registration_id` 唯一 |
| `m04_registration` : `m04_triage` | 一挂号一分诊 | 部分唯一索引（排除 `CANCELLED`） |
| `m04_triage` : `m04_triage_critical_handle` | 一分诊一危重处置 | `triage_id` 唯一 |
| `m04_appointment` : `m04_registration` | 一预约一转挂号 | `appointment_id` 可空唯一 |
| `m04_special_cert` : 患者类型 | 同患者同类型一条 | 部分唯一索引 |

### 3.3 关键一对多关系

| 父表 | 子表 | 说明 |
|---|---|---|
| `m04_schedule` | `m04_reg_slot` | 一排班 N 号源 |
| `m04_schedule` | `m04_schedule_period` | 一排班 N 班次段 |
| `m04_triage` | `m04_queue_entry` | 一分诊 N 队列记录（改诊室） |
| `m04_triage` | `m04_call_record` | 一分诊 N 次叫号 |
| `m04_add_quota_apply` | `m04_add_quota_approval` | 一申请 N 审批节点 |
| `m04_special_cert` | `m04_special_usage` | 一凭证 N 次使用 |
| 任意流水表 | `*_log` 表 | N 次变更 |

### 3.4 跨模块引用

| M04 表 | 引用对象 | 来源模块 | 引用字段 |
|---|---|---|---|
| `m04_schedule` | 科室、医生 | M01 | `dept_id`、`doctor_id` |

## 4. 索引与性能设计

### 4.1 索引命名规范

| 类型 | 前缀 | 示例 |
|---|---|---|
| 主键 | `pk_` | `pk_m04_triage` |
| 唯一索引 | `uk_` | `uk_m04_triage_no` |
| 普通索引 | `idx_` | `idx_m04_triage_date` |
| 部分索引 | `idx_` 或 `uk_` + 注释说明 | `idx_m04_check_failed` |
| GIN 索引 | `idx_` | `idx_m04_log_name` |

### 4.2 核心索引清单

| 表 | 索引 | 类型 | 用途 |

| `m04_data_check` | `idx_m04_check_failed` | 部分索引 | `WHERE status='FAILED'` |

### 4.3 索引设计原则

| 原则 | 说明 |
|---|---|
| **避免冗余** | 复合索引 `(a, b)` 已覆盖 `a` 单列查询，不再单独建 `a` |
| **高频优先** | 优先给 WHERE + ORDER BY 组合建索引 |
| **部分索引** | 状态类字段用部分索引减小体积（如 `WHERE status='CALLING'`） |
| **GIN 慎用** | 中文模糊搜索用 `pg_trgm` + GIN，但只给必要字段 |
| **写放大** | 单表索引不超过 8 个 |
| **定期维护** | 每月 `REINDEX` 高频表；监控 `pg_stat_user_indexes` 未使用索引 |

### 4.4 关键查询与索引匹配

**队列排序查询（最热）：**

```sql
SELECT id, queue_no, patient_name, triage_level, priority_weight
FROM m04_queue_entry
WHERE room_id = $1
  AND queue_date = CURRENT_DATE
  AND status = 'WAITING'
ORDER BY priority_weight DESC, triaged_at ASC
LIMIT 50;
```

**索引：** `idx_m04_queue_order(room_id, queue_date, status, priority_weight DESC, triaged_at)`

**号源分配查询（最热）：**

```sql
SELECT id, slot_no
FROM m04_reg_slot
WHERE schedule_id = $1
  AND status = 'AVAILABLE'
ORDER BY slot_no ASC
LIMIT 1
FOR UPDATE SKIP LOCKED;
```

**索引：** `idx_m04_slot_avail(schedule_id, slot_no) WHERE status = 'AVAILABLE'`

**日报聚合查询（最重）：**

```sql
SELECT
    COUNT(*) AS reg_count,
    COUNT(*) FILTER (WHERE status = 'REFUNDED') AS refund_count,
    AVG(wait_minutes) AS avg_wait
FROM m04_clinic_log
WHERE log_date = $1;
```

**索引：** `idx_m04_log_date(log_date, dept_id, status)`

### 5.3 分区自动维护

```python
# app/tasks/m04/partition_tasks.py
"""分区自动维护任务"""


def ensure_next_partition_task():
    """每月创建下一年度分区"""
    from datetime import date
    from sqlalchemy import text
    from app.core.database import engine

    next_year = date.today().year + 1

    partitions = [
        ("m04_clinic_log", "log_date", f"m04_clinic_log_p{next_year}"),
        ("m04_triage", "triage_date", f"m04_triage_p{next_year}"),
    ]

    created = []
    with engine.begin() as conn:
        for table, col, pname in partitions:
            start = f"{next_year}-01-01"
            end = f"{next_year + 1}-01-01"
            conn.execute(text(
                f"CREATE TABLE IF NOT EXISTS {pname} "
                f"PARTITION OF {table} "
                f"FOR VALUES FROM ('{start}') TO ('{end}')"
            ))
            created.append(pname)

    return {"created": created}
```

```
│  · 数据核对（每日 10 项）                                      │
│  · 违反 → 告警 + 人工处理                                     │
└─────────────────────────────────────────────────────────────┘
```
