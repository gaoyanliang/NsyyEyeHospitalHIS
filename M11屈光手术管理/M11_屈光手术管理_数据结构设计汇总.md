## 1. 全局数据结构规范

### 1.1 硬性技术规范

| 项 | 规范 |
|---|---|
| 数据库 | **PostgreSQL 16** |
| 主键 | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`（SQLAlchemy `Identity()`） |
| 外键 | **不建物理外键**（跨模块零外键，模块内也不建，靠应用层校验） |
| 时间 | `TIMESTAMP`（无时区，库内统一 Asia/Shanghai）/ `DATE` |
| 布尔 | `BOOLEAN`，默认 `TRUE` / `FALSE` |
| JSON | `JSONB`，需要检索时加 GIN 索引 |
| 金额 | `NUMERIC(14,4)`；**M11 只存 M16 快照**，字段名带 `_snap` / `_ref` 后缀 |
| 屈光度 | `NUMERIC(6,2)`，步进 0.25D |
| 角膜厚度 | `NUMERIC(6,2)`，单位 μm |
| 眼轴长度 | `NUMERIC(6,2)`，单位 mm |
| 逻辑删除 | `is_deleted BOOLEAN NOT NULL DEFAULT FALSE`，**禁止物理 DELETE** |
| 乐观锁 | `version INT NOT NULL DEFAULT 0` |
| 触发器 | `updated_at` 由 `trg_set_updated_at` 统一维护 |
| 注释 | 每张表、每个关键字段必须有 `COMMENT ON` |

### 1.2 表命名规范

格式：`m11_{子模块域}_{实体}`

| 子模块 | 表前缀 | 说明 |

| M11-06 | `m11_postop_` | 术后随访计划、任务、到访、视力记录、角膜恢复 |
| M11-07 | `m11_complication_` / `m11_quality_` | 并发症、分级、上报、闭环、质量指标 |

### 1.3 标准审计字段（每张表必带）

| 字段 | 类型 | 说明 |
|---|---|---|
| `created_by` | BIGINT | 创建人 ID |
| `created_at` | TIMESTAMP | 创建时间，默认 `CURRENT_TIMESTAMP` |
| `updated_by` | BIGINT | 更新人 ID |
| `updated_at` | TIMESTAMP | 更新时间，触发器维护 |
| `is_deleted` | BOOLEAN | 逻辑删除，默认 `FALSE` |
| `version` | INT | 乐观锁，默认 `0` |

> **例外：** 只增流水表（并发症上报、变更日志、审批留痕）不带 `is_deleted` 与 `version`，因为不允许删除、不允许并发覆盖。

### 1.4 命名约定

| 对象 | 命名规则 | 示例 |
|---|---|---|
| 表 | `m11_{域}_{实体}` | `m11_plan_main` |
| 主键 | `id` | `id` |
| 业务单号 | `{实体}_no` | `plan_no`、`reservation_no` |
| 唯一索引 | `uk_{表名去前缀}_{语义}` | `uk_plan_main_no` |
| 普通索引 | `idx_{表名去前缀}_{列缩写}` | `idx_plan_main_patient` |
| 部分索引 | 同上，加 `WHERE` | `WHERE is_deleted = FALSE` |
| 唯一约束 | `uk_*` | — |
| CHECK 约束 | `ck_{表名去前缀}_{语义}` | `ck_plan_rsb` |
| 触发器 | `trg_{表名去前缀}_{动作}` | `trg_plan_main_updated` |

## 4. 索引策略

### 4.1 必须建立的索引类型

| 索引类型 | 适用场景 | 示例 |
|---|---|---|
| 业务单号唯一索引 | 所有有单号的表 | `uk_consult_main_no ON m11_consult_main(consult_no) WHERE is_deleted = FALSE` |
| 患者维度索引 | 按患者查 | `idx_plan_main_patient ON m11_plan_main(patient_id, created_at DESC) WHERE is_deleted = FALSE` |
| 状态 + 时间索引 | 待办列表 | `idx_reservation_status ON m11_reservation_main(status, surgery_date) WHERE is_deleted = FALSE` |
| 外键关联索引 | 主从表关联 | `idx_postop_task_plan ON m11_postop_task(plan_id)` |
| 中文模糊检索 | 姓名、备注 | `GIN (patient_name gin_trgm_ops)` 需 `CREATE EXTENSION IF NOT EXISTS pg_trgm` |
| JSONB 检索 | 配置、快照 | `GIN (node_snapshot jsonb_path_ops)` |
| 部分索引 | 只查有效记录 | `WHERE is_deleted = FALSE` |
| 表达式索引 | 函数查询 | `ON m11_consult_main (DATE(created_at))` |

### 4.2 索引设计原则

1. **每个唯一索引必须带 `WHERE is_deleted = FALSE`** —— 否则逻辑删除后无法重建同号记录
2. **复合索引列序：等值列在前、范围列在后** —— `(status, surgery_date)` 优于 `(surgery_date, status)`
3. **单表索引不超过 6 个** —— 过多会拖慢写入
4. **不使用前缀索引** —— PostgreSQL 不支持 MySQL 那种前缀索引语义
5. **大表分区后，索引建在分区上** —— 父表索引会自动传递

| `m11_plan_ablation` | `ck_plan_ablation_rsb` | `rsb_um >= 0`（业务上 <250 拒绝，DB 层只做非负） |
| `m11_plan_ablation` | `ck_plan_ablation_oz` | `optical_zone_mm BETWEEN 4.5 AND 8.0` |
| `m11_plan_main` | `ck_plan_main_eye_side` | `eye_side IN ('OD','OS','OU','NA')` |
| `m11_plan_main` | `ck_plan_main_type` | `refractive_type IN (...)` 10 个术式 |
| `m11_preop_exam` | `ck_preop_exam_admission` | `admission_result IN ('PASS','HOLD','REJECT','PENDING')` |
| `m11_postop_vision` | `ck_postop_vision_va` | `ucva_decimal BETWEEN 0 AND 2.0` |
| `m11_complication_main` | `ck_complication_grade` | `grade IN ('GRADE_1','GRADE_2','GRADE_3','GRADE_4')` |
| `m11_reservation_main` | `ck_reservation_status` | `status IN (...)` |

### 6.2 唯一性约束

| 场景 | 唯一键 |
|---|---|
| 业务单号 | `(xxx_no) WHERE is_deleted = FALSE` |
| 患者有效档案 | `(patient_id) WHERE is_deleted = FALSE AND status = 'ACTIVE'` |
| 随访任务 | `(plan_id, node_code) WHERE is_deleted = FALSE` |
| 幂等键 | 由 Redis `m11:idem:{biz}:{key}` 兜底，DB 层面用业务唯一索引 |

### 6.3 禁用约束

| 禁止 | 原因 |
|---|---|
| 物理外键 `FOREIGN KEY` | 跨模块微服务解耦，跨库不可行 |
| `ON DELETE CASCADE` | 禁止物理删除，级联无意义 |
| 唯一索引不带 `is_deleted` 条件 | 逻辑删除后无法重建同号 |

### 9.2 迁移文件规范

| 项 | 规范 |
|---|---|
| revision 命名 | `m11_{子模块号}_{描述}` |
| 顺序 | 严格按第 8 节建表顺序 |
| 执行顺序 | 第一批 → 第九批 |
| `upgrade()` | 建表 → 建索引 → 建约束 → 建触发器 → 加注释 |
| `downgrade()` | `drop_table`（仅开发环境允许） |
| 幂等 | 用 `CREATE TABLE IF NOT EXISTS` 不够，Alembic 自带版本管理即可 |
| 数据迁移 | 与结构迁移分离（结构在前，数据在后） |

## 附录 C：常用查询模式

### C.1 按患者取有效屈光档案

```sql
SELECT r.*
FROM m11_refractive_record r
WHERE r.patient_id = :patient_id
  AND r.status = 'ACTIVE'
  AND r.is_deleted = FALSE
ORDER BY r.created_at DESC
LIMIT 1;
```

### C.2 取患者当前有效手术方案

```sql
SELECT p.*
FROM m11_plan_main p
WHERE p.patient_id = :patient_id
  AND p.status = 'AUDITED'
  AND p.expire_date >= CURRENT_DATE
  AND p.is_deleted = FALSE
ORDER BY p.audited_at DESC
LIMIT 1;
```

### C.3 术后随访到期清单（P-12）

```sql
SELECT t.*
FROM m11_postop_task t
WHERE t.status = 'PLANNED'
  AND t.due_date BETWEEN :start_date AND :end_date
  AND t.is_deleted = FALSE
ORDER BY t.due_date, t.id;
```

### C.4 咨询转化漏斗

```sql
SELECT
    COUNT(*) FILTER (WHERE status IN ('SCREENED','EXAM_BOOKED','EXAM_DONE','PLAN_MADE','SURGERY_BOOKED','SURGERY_DONE','CONVERTED')) AS screened_cnt,
    COUNT(*) FILTER (WHERE status IN ('EXAM_DONE','PLAN_MADE','SURGERY_BOOKED','SURGERY_DONE','CONVERTED')) AS exam_done_cnt,
    COUNT(*) FILTER (WHERE status IN ('SURGERY_DONE','CONVERTED')) AS surgery_done_cnt,
    COUNT(*) AS total_cnt
FROM m11_consult_main
WHERE created_at >= :period_start
  AND created_at < :period_end
  AND is_deleted = FALSE;
```
