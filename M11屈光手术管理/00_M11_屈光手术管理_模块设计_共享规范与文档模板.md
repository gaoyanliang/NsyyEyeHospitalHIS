### 0.3 三条铁律（违反即返工）

| # | 铁律 | 原因 |
|---|---|---|
| **1** | **数量口径三处一致**：页面总览树 `P0x` = 第 5 章 `### 5.x P0x` 标题；表清单 = `### 4.x 表：` 标题；接口总览 `API-01` 起连续无断号且每项有 `#### API-xx` 详述 | 全仓统一标准，交叉引用依赖编号稳定 |
| **2** | **钱与库存都不自己算**：金额计算一律调 M16；耗材/植入物库存一律以 M15 为权威源 | M16/M15 已各有一套引擎，重复实现必然对不上账 |
| **3** | **技术栈 PostgreSQL 16**：不得出现 `AUTO_INCREMENT` / `TINYINT` / `DATETIME` / `ENGINE=` / `VARCHAR2` | 全仓已统一 PostgreSQL，MySQL 语法是硬错误 |

> **M11 专属铁律（第 4 条）**：**手术记录不在 M11**。M11 管「咨询 → 术前检查 → 屈光档案 → 手术方案 → 预约 → 术后随访」，**术中执行（手术记录、麻醉记录、器械清点、植入物扫码）归 M09**，排程排班归 M06/M09。M11 只写 `m11_surgery_reservation`（预约与术前准备）与术后随访，术中数据只读引用。

## 1. M11 模块定位与子模块划分

### 1.1 一句话定位

> **M11 回答「这个近视/散光患者能不能做屈光手术、该做哪种术式、角膜切削多少、晶体选多少度、什么时候做、做完恢复得怎么样」。**

M11 承接总体设计第 5.4 节的**屈光闭环**：

```
咨询 → 术前检查 → 屈光档案 → 手术方案 → 预约 → 手术 → 术后随访 → 会员转化
M11-01  M11-02     M11-03     M11-04    M11-05  M06/M09  M11-07    M03-03/M19
```

### 1.2 与 M01-07 / M06 / M09 / M10 / M16 的五方边界（最容易搞错的五方分工）

读懂这五句话，M11 就设计对了：

| 问题 | 权威方 | 说明 |
|---|---|---|
| **「有哪些屈光术式（SMILE/FS-LASIK/TransPRK/ICL）、手术分级、医师授权、术前检查项、随访规则」** | **M01-07 手术主数据** | M11 **只读**，不新建术式；开方案前必调 `full-config` 与 `auth/check` |
| **「这台手术什么时候做、在哪个手术间、谁主刀、护士器械清点、术中记录、麻醉记录、植入物扫码追溯」** | **M06 日间手术 / M09 手术麻醉** | M11 **不写术中数据**；M11 生成预约后推给 M06/M09 |
| **「验光结果、视力健康档案、配镜史」** | **M10 视光业务** | M11 **只读**（P-01/P-02/P-25），术后复查可写 M10 的视力档案（通过 M10 提供的接口） |
| **「收了多少钱、方案定价、套餐、退款、发票」** | **M16 收费结算** | M11 **不碰钱**；方案报价调 M16 试算，实收在 M16 |
| **「这个患者能不能做、术前检查够不够、角膜切削多少、晶体度数多少、术后视觉质量怎么样」** | **M11（本模块）** | 术前评估、屈光档案、手术方案、晶体计算、术后随访 |

> **一句话记忆：** M01 定义「有哪些术式」，M06/M09 定义「手术怎么开」，M10 定义「眼睛原本什么状态」，M16 定义「钱」，**M11 定义「这个人适不适合做、做成什么样」**。

## 2. 全局技术约定

### 2.1 技术栈（与 README 7.1 一致，不得增删主项）

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.11+ | 类型注解全量 |
| Web 框架 | FastAPI | 自动 OpenAPI |
| ORM | SQLAlchemy 2.0 | `Mapped` / `mapped_column` 声明式 |
| 数据库 | **PostgreSQL 16** | 严禁 MySQL 语法 |
| 缓存 | Redis 7 | 只缓存可重建数据 |
| 异步任务 | Celery | 长任务、外部回调 |
| 定时任务 | APScheduler | 随访扫描、统计快照 |
| 校验 | Pydantic V2 | `model_config` / `field_validator` |
| 迁移 | Alembic | 每个子模块一个 revision |

### 2.2 统一响应格式

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "trace_id": "01J8F3K2M9XQ7V4N6R8T2W5Y"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int / string | `0` 成功；非 0 为错误码（7 位字符串或系统码） |
| `message` | string | 成功固定 `"success"`，失败为中文提示 |
| `data` | object / array / null | 业务数据 |
| `trace_id` | string | 链路追踪 ID，长度 26 |

### 2.3 分页格式（统一定义，不得自创）

**请求：** `?page=1&page_size=20`（`page` 从 1 起，`page_size` 默认 20，上限 200）

**响应：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "page_size": 20,
    "pages": 0
  },
  "trace_id": "01J8F3K2M9XQ7V4N6R8T2W5Y"
}
```

### 2.4 时间与金额

| 项 | 约定 |
|---|---|
| 时间字段类型 | `TIMESTAMP`（带时分秒，不带时区，库内统一 Asia/Shanghai） |
| 日期字段类型 | `DATE` |
| API 时间格式 | ISO 8601 `2026-10-31T14:30:00` |
| API 日期格式 | `2026-10-31` |
| **金额** | `NUMERIC(14,4)`；**M11 不产生金额真值**，只存 M16 返回的快照（字段名带 `_snap` 后缀） |
| **屈光度** | `NUMERIC(6,2)`，`-4.25D` 格式，步进 0.25D |
| **角膜厚度** | `NUMERIC(6,2)`，单位 μm（微米是整数，但保留 2 位便于某些设备输出） |
| **眼轴长度** | `NUMERIC(6,2)`，单位 mm |
| **角膜曲率** | `NUMERIC(6,2)`，单位 D（屈光度）或 mm，由 `k_unit` 字段区分 |

### 2.5 幂等与并发

| 场景 | 做法 |
|---|---|
| 内部契约写接口（`/internal/v1/m11/...`） | 必须支持 `Idempotency-Key` 请求头，Redis 键 `m11:idem:{biz}:{key}` TTL 24h |
| 对外写接口（`/api/v1/m11/...`） | 支持 `Idempotency-Key`，无则用「业务唯一键 + 乐观锁」兜底 |
| 单号生成 | Redis `INCR m11:code:{prefix}:{yyyyMMdd}`，每日 03:00 与 DB 最大值对账 |
| 并发编辑 | `version INT` 乐观锁列，`UPDATE ... WHERE version = :old_version` |
| 数据库兜底 | 业务唯一索引（不靠"先查后插"，靠唯一索引 + 捕获 `IntegrityError`） |

### 2.6 数据库硬规范

| 规范 | 说明 |
|---|---|
| 主键 | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`（SQLAlchemy `Identity()`） |
| 时间 | `TIMESTAMP` / `DATE`，默认 `CURRENT_TIMESTAMP` |
| 布尔 | `BOOLEAN`，默认 `TRUE` / `FALSE` |
| JSON | `JSONB` + GIN 索引（需要检索时） |
| 逻辑删除 | `is_deleted BOOLEAN NOT NULL DEFAULT FALSE`，**禁止物理 DELETE** |
| 部分索引 | `CREATE INDEX ... WHERE is_deleted = FALSE` |
| 中文模糊检索 | `pg_trgm` 扩展 + `GIN (name gin_trgm_ops)` |
| 分区 | 大表按 `RANGE (created_at)` 月度分区，**必须有 `DEFAULT` 分区兜底** |
| CHECK 约束 | 命名 `ck_{表名去前缀}_{语义}`，如 `ck_m11_plan_kscope` |
| 物理外键 | **不建**（跨模块零外键，模块内也不建，靠应用层校验） |
| 触发器 | `updated_at` 由 `trg_set_updated_at` 统一维护 |
| 注释 | 每张表、每个字段必须有 `COMMENT ON` |

## 17. 常见坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 页面总览写了 P10，第 5 章只写到 P08 | 先列总览，再逐页写，最后用脚本核对 |
| 2 | 接口总览跳号（API-12 直接到 API-14） | 分组标题行不占编号，写完用脚本扫 |
| 3 | 第 4 章留了表定义 | 详细设计第 4 章只放指引块 |
| 4 | 表数与指引块写的 N 不一致 | 数据结构文件写完 → 回填 N |
| 5 | 错误码用 M10 号段 `"1001xxx"` | M11 一律 `"110Nxxx"` |
| 6 | 金额自己算（`plan_price * qty`） | 调 M16 试算，实收在 M16 |
| 7 | 术中记录写进 M11 | 术中归 M06/M09，M11 只读摘要 |
| 8 | 用 `DELETE` 物理删表记录 | 一律 `is_deleted = TRUE` |
| 9 | 枚举中文值（`'已审核'`） | 枚举一律英文大写，中文放附录字典 |
| 10 | 屈光术式自创编码 | 必须用 M01-07 3.1.4 的 10 个术式码 |
| 11 | **P-01 晶体计算路径写错** | 必须 `GET /internal/v1/m11/iol-calculation/{patient_id}`，一字不差 |
| 12 | 术前准入口径自己判断 | 调用 M01-07 `auth/check` + 本模块禁忌规则，两者都过才 `PASS` |
| 13 | 把屈光档案和 M10 视力档案当同一件事 | 屈光档案是 M11 独有（术式决策用），视力档案是 M10 独有；互相只读引用 |
| 14 | 角膜厚度单位混用（mm vs μm） | 一律 μm；`520μm` 不写 `0.52mm` |
| 15 | 表格单元格里写了裸竖线（绝对值符号） | 写 `abs(x)`，或改用文字描述 |
