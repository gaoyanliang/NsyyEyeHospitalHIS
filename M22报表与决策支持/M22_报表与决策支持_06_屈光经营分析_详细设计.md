## 文档说明

### 本子模块是什么

M22-06 是屈光业务线的**跨期跨维度汇总层**。它把 M11-08 已经把「一个科室、一段时间」算好的 60 个屈光指标，与 M11-07 算好的 5 个质量指标、M16 的金额快照、M17 的科室成本，按**统一的指标编码、统一的期间口径、统一的维度体系**重新组织，解决三个 M11-08 结构上无法解决的问题：

1. **跨期趋势**——M11-08 每次查询一个统计窗口，不保存历史序列；M22-06 存序列。
2. **跨维度横向对比**——M11-08 的粒度是「科室 × 渠道/术式/医师」，做不了「医师 A 与医师 B 同口径对比、渠道 A 与渠道 B 同期对比」。
3. **预测**——M11-08 是「事后统计」，不做外推；M22-06 做趋势预测，并且预测值必须与实测值物理可分。

### 本子模块自产什么、搬运什么

| 数据 | 来源 | M22-06 的角色 | 是否本模块算的 |
|---|---|---|---|
| 咨询量、漏斗七环节、转化率 | M11-08 P-15 / P-13 | 搬运 + 跨期汇总 | 否 |
| 术式结构、价格带分布 | M11-08 P-16 | 搬运 + 跨期对比 | 否 |
| 医师手术量、并发症率、满意度 | M11-08 P-19 | 搬运 + 横向排名 | 否 |
| 屈光收入、客单价、退费 | M16-01 P-05 / M16-04 P-05 | 搬运为 `_snap` | 否 |
| 科室成本、毛利 | M17-04 P-07 | 搬运为 `_snap` | 否 |
| 质量四性（有效性/安全性/稳定性/可预测性） | M11-07 P-14 | 搬运 + 维度重排 | 否 |
| **渠道投放成本** | **M22-06 自建台账** | **生产者** | **是** |
| **趋势预测值** | **M22-06 计算** | **生产者** | **是** |
| **跨期变化率、同环比、结构变化指数** | 基于上述快照二次计算 | **计算** | **是** |

> **一句话边界：** M22-06 只自产两样东西——**渠道投放台账**和**预测值**。除此之外，任何一个数字都必须能指回上游的某个接口和某个批次号；指不回去的数字不允许出现在本模块的任何一张表、任何一个接口、任何一页报表里。

## 1. 模块概述

### 1.1 模块定位

> **三个来自真实经营会的追问。**
>
> **追问一：**「上个月 SMILE 的占比从 58% 掉到 52%，是一时的波动，还是趋势？下个季度要不要调整术式推广策略？」——M11-08 的运营分析回答「这个月是多少」，回答不了「这是不是趋势」。
>
> **追问二：**「抖音这个渠道投了 46,800 元，做了 231 台手术，ROI 到底是多少？小红书投了 12,400 元只做了 18 台，为什么不砍掉小红书？」——M11-08 算得出 ROI 的分子（收入），算不出分母（投放成本），因为投放费用记在财务账上，不在手术系统里。
>
> **追问三：**「王主任和赵主任，同样做 SMILE，同样 60 台手术，为什么王主任的并发症率是 0.8%、赵主任是 2.1%？是不是王主任挑病人挑得更严？」——M11-08 有两位医师的并发症率，但没有把「手术量、转化率、并发症率、客单价」放在同一把尺子上横着比。

### 1.2 为什么独立成子模块

| # | 理由 | 若不独立的后果 | 说明 | 影响范围 |
|---|---|---|---|---|
| 1 | M11-08 是**窗口统计**，M22-06 是**序列存储** | 每次看趋势都要重跑 M11-08 的全量统计，12 个月趋势 = 12 次跨模块远程调用 | M11-08 的 `m11_stat_*` 表按期间存结果，但只服务它自己的页面；跨期拼接必须由下游负责 | P01 / P03 / P04 / P07 |
| 2 | 投放成本**不属于任何业务系统**，必须由经营分析侧建台账 | 渠道 ROI 永远算不出来，只能凭感觉「抖音好像还行」 | 投放费用记在财务凭证上，M16 只看到钱进来了，看不到这笔钱是为了哪个渠道花的 | P05、P-02、M11-08 U-08 |
| 3 | 跨维度对比需要**统一维度体系** | 医师对比要在 M11-08 前端手工拼两份报文，口径还可能不同 | M11-08 的粒度是「科室 × 单维度」，做不到「同一期间内 10 位医师 × 6 个指标」的矩阵 | P04 |
| 4 | 预测是**有方法论负担**的能力，必须单独承载 | 预测值随手塞进 M11-08 的报表里，半年后没人说得清哪个数是猜的 | 预测需要方法、回测、置信区间、误差回填，是一整套机��而不是一个公式 | P07 |
| 5 | M11-08 的边界明确写「统计结果不回流临床」 | 让 M11-08 承担经营外推职责，会污染临床系统的数据语义 | 经营决策指标与临床质量指标必须分开存放、分开授权 | 全局 |
| 6 | 需要向 M11 反向输出**一个它自己算不出的数** | M11-08 的渠道 ROI 只能长期降级为 `cost_snap = NULL` | P-02 由 M22-06 承担，M11-08 每日 03:10 取数 | M11-08 U-08 |

**为什么不并入 M22-05 视光经营分析：** 视光与屈光是两条独立的业务线，客单价差 5~20 倍（视光 800~3,000 元，屈光 15,000~35,000 元），漏斗环节完全不同（视光是「验光 → 选品 → 配镜 → 取镜」，屈光是「咨询 → 到院 → 检查 → 方案 → 预约 → 手术 → 完成」），医师角色不同（视光是验光师与加工师，屈光是手术医师），指标编码域不同（OPT vs REF）。合并后所有指标都要加业务线前缀区分，反而更乱。

**为什么不并入 M22-03 运营报表与日报月报：** M22-03 是**报表骨架**（模板 / 实例 / 行 / 订阅），负责「怎么把数据排成一张报表」；M22-06 是**业务主题**，负责「屈光这条线有哪些指标、怎么算、怎么比、怎么预测」。M22-06 的 8 个页面里只有 P08 是报表导出，其余 7 页都是交互式分析页面（下钻、切换维度、调参预测），不是报表。M22-06 只通过 `template_code` 引用 M22-03 的模板表，不重复建表。

### 1.3 与相邻子模块的分工

### 1.4 概念辨析

#### 1.4.1 「转化率」× 8 个容易混淆的概念

```text
M11-08 有 11 个漏斗类指标，M22-06 有 6 个环节转化率 + 1 个总转化率。
看起来全是「除法」，但分子分母各不相同。搞混一个，整个经营会就白开了。

  咨询 1,284 人
   │  cvr_consult_arrive = 836 / 1,284 = 65.11%
   ▼
  到院   836 人
   │  cvr_arrive_exam    = 672 / 836   = 80.38%
   ▼
  术前检查 672 人
   │  cvr_exam_plan      = 368 / 672   = 54.76%   ← 最大流失在这里
   ▼
  出方案   368 人
   │  cvr_plan_book      = 286 / 368   = 77.72%
   ▼
  预约     286 人
   │  cvr_book_surface   = 252 / 286   = 88.11%
   ▼
  手术     252 人
   │  cvr_surface_done   = 231 / 252   = 91.67%
   ▼
  完成     231 人

  总转化率 overall_cvr = 231 / 1,284 = 17.99%
  注意：总转化率 ≠ 六个环节转化率的连乘（连乘 = 18.02%，差异来自四舍五入逐级累积）
```

| 概念 | 分子 | 分母 | 常见误用 | 本模块的处理 |
|---|---|---|---|---|
| 环节转化率 | 下一环节人数 | 本环节人数 | 用「本环节人数 / 咨询量」冒充环节转化率 | 六条 `ck_..._cvr_N` 逐一锁定分子分母，禁止跳级 |
| 总转化率 `overall_cvr` | 完成人数 | 咨询量 | 用六环节连乘代替，误差逐级累积 | 直接算 `done / consult`，不连乘 |
| 整体流失率 | 1 − 总转化率 | — | 与「最大流失环节流失率」混淆 | 单独列，`lost_rate` 只表示最大流失环节的流失人数 / 该环节人数 |
| 最大流失环节 | — | — | 取「流失率最大」而不是「流失人数最多」 | **按流失绝对人数取最大**（业务上要救的是人数最多的那一环） |
| 渠道转化率 | 该渠道完成人数 | 该渠道咨询量 | 跨渠道直接比，不看去重 | 每个渠道独立算，不做跨渠道相加（首触点归因下渠道间天然去重） |
| 医师个人转化率 | 该医师主刀手术量 | 该医师接诊咨询量 | 忽略不同医师接诊的咨询质量不同 | 只做同期间横向对比，不做跨期硬比 |
| 客单价 | 净收入 | 手术例数 | 用收入除以眼数 | 分母恒为例数，`avg_ticket_snap` 由 M16 给出 |
| 到院成本 | 投放成本 | 到院人数 | 用手术例数做分母变成 CPA | 分别建列 `arrive_cost` 与 `cpa` |

#### 1.4.2 「投放成本」× 3 个容易混淆的概念

| 概念 | 定义 | 谁维护 | 本模块的字段 | 关键区别 |
|---|---|---|---|---|
| **投放成本**（媒体支出） | 付给抖音 / 小红书 / 美团等平台的推广费 | M22-06 投放台账 | `spend_amount`（台账）→ `spend_snap`（快照） | 这是**花出去的钱**，是 ROI 的分母 |
| **渠道收入** | 该渠道归因带来的手术净收入 | M16-01 / M16-04 | `revenue_net_snap` | 这是**收进来的钱**，是 ROI 的分子 |
| **到院成本 / CPA** | 投放成本摊到到院人数 / 手术例数 | M22-06 计算 | `arrive_cost` / `cpa` | 这是**单位获客成本**，不是 ROI |

> **方向铁律：** 分子永远是收入（来源 M16，带 `_snap`），分母永远是投放成本（来源本模块台账，不带 `_snap`）。反过来写就是 `1/ROI`，业务上毫无意义，但数字看上去仍然「像个比率」，这种错误在报表里能活很久。

#### 1.4.3 「实测值 vs 预测值」——为什么必须物理可分

| 对比项 | 实测值 `ACTUAL` | 预测值 `FORECAST` |
|---|---|---|
| 数据来源 | 上游接口取回（M11-08 / M11-07 / M16 / M17） | 本模块按算法外推 |
| 是否有批次号 | 有 `collect_batch_no` | 无（`source_module = 'M22'`） |
| 是否可被修订 | 上游重算后本模块跟着重算 | 基准期变更后整体重跑 |
| 能否进正式报告 | 能 | **默认不能**，导出时必须显式勾选 |
| 前端呈现 | 实线 | 虚线 + 置信区间带 |
| 是否有误差回填 | 不适用 | 被实测覆盖后回填 `mape` / `abs_error` |

**做过什么选择、为什么：** 最初的方案是在 `remark` 字段里写「此为预估值」。评审时被否决，理由是：导出到 Excel 后 `remark` 列默认不显示，业务员把预测值当实际值汇报给院长，这属于**用系统缺陷制造经营误导**。因此改为 `value_type` 独立列 + 数据库 CHECK 强制预测行必须带方法、基准期、置信区间，导出时按 `value_type` 强制加底色与图例。

#### 1.4.4 「M22-06 算的」vs「M11-08 算的」——一张必须能指认的表

| 指标 | 谁算 | 为什么这样分 | 本模块的字段 |
|---|---|---|---|
| 咨询量 `RA01001` | M11-08 | 咨询单在 M11-01，只有 M11 知道什么叫「一次咨询」 | `m22_refractive_metric.metric_value` |
| 到院转化率 `RA02008` | M11-08 | 到院判定依赖 M11-01 的签到记录 | 同上 |
| 术式占比 `RA03002` | M11-08 | 术式码在 M11-04 手术方案里 | `m22_refractive_procedure.case_share` |
| 医师并发症率 `RA04004` | M11-08（数据来自 M11-07） | 并发症登记在 M11-07 | `m22_refractive_doctor.complication_rate` |
| 质量四性 | M11-07 | 需要随访原始视力数据，只有 M11-06/M11-07 有 | `m22_refractive_quality.efficacy_index` 等 |
| 屈光收入 / 客单价 | M16-01 | 金额真值唯一来源 | `*_snap` 系列 |
| 科室成本 / 毛利 | M17-04 | 成本核算唯一来源 | `gross_margin_snap` 等 |
| **期间环比 / 同比变化率** | **M22-06** | M11-08 每次只算一个窗口，拿不到上期值；本模块存了序列才能算 | `change_rate` / `mom_*` / `yoy_*` |
| **结构变化指数** | **M22-06** | 需要连续多期术式结构向量做距离计算 | `structure_change_index` |
| **医师横向排名** | **M22-06** | M11-08 粒度不含「同期间多医师矩阵」 | `quality_rank` / `volume_rank` / `roi_rank` |
| **质量收入相关性** | **M22-06** | 需要 ≥6 期的质量与收入配对序列 | `quality_revenue_corr` |
| **渠道 ROI / CPA** | **M22-06** | 分母（投放成本）只有 M22 有 | `roi` / `cpa` / `arrive_cost` |
| **趋势预测** | **M22-06** | M11-08 边界明确「不做外推」 | `m22_refractive_trend` 的 `FORECAST` 行 |

> **判定规则：** 一个指标由「**谁的原子数据**」决定归属。原子数据在 M11-01/04/06/07 的，由 M11-08 算；原子数据在 M16/M17 的，由 M16/M17 算；需要「**跨期或跨维度二次运算**」的，由 M22-06 算——因为上游结构上不持有那个维度。

> **双向依赖的处理：** M11-08 的渠道指标里 `roi` / `cpa` 需要 M22-06 的投放成本才能算出来，而 M22-06 的 `m22_refractive_channel.roi` 又是基于 M16 收入算的。这是**设计上的循环**，处理方式是：**M22-06 自己算 ROI（用 M16 收入 + 自己的台账），不依赖 M11-08 的 `RA05007`**。M11-08 的 `RA05007` 是「M11 侧参考值」，M22-06 的 `roi` 是「M22 侧权威值」，两者独立计算，第 10.1 节的「契约对齐说明」里记录这个双算约定。

**状态语义对照：**

| `source_status` | 含义 | `metric_value` 取值 | 页面呈现 | 是否计入汇总 |
|---|---|---|---|---|
| `COMPLETE` | 全部来源正常返回 | 实际值 | 正常显示 | 计入 |
| `PARTIAL` | 部分来源缺失 | 已有来源的值，缺失来源为 NULL | 显示值 + 黄色感叹号 + 缺失来源清单 | 计入，但汇总行标注 PARTIAL |
| `FAILED` | 全部来源不可用 | NULL | 显示「—」+ 红色角标 | **不计入**（避免拉低平均） |
| `STALE` | 数据超过 `stale_threshold_hours` 未更新 | 上次的值 | 显示值 + 灰色「数据陈旧」标注 | 计入，但报表实例标 `is_stale` |

> **禁止的做法：** `FAILED` 时把 `metric_value` 写成 0。0 是「业绩为零」，NULL 是「不知道」。经营会上把「不知道」说成「零」，会导致决策方向完全相反。

#### 3.4.2 ROI 与 CPA 的完整算法

```text
输入（同一 channel、同一 period）：
    revenue_net_snap   ← M16-01 P-05，单位元，NUMERIC(18,2)
    spend_snap         ← 本模块台账 APPROVED 求和，单位元，NUMERIC(18,2)
    surface_cnt        ← M11-08 P-15 RA03001，例数
    arrive_cnt         ← M11-08 P-15 RA01003，人数

计算：
    Step 1  取分母
        SELECT COALESCE(SUM(spend_amount), 0) INTO v_spend
          FROM m22_refractive_ad_spend
         WHERE channel = p_channel AND period = p_period
           AND audit_status = 'APPROVED' AND is_deleted = FALSE;

    Step 2  判断有无台账记录（关键：区分「没投钱」与「查不到」）
        SELECT COUNT(*) INTO v_cnt FROM ...（同上条件）
        has_spend_record := (v_cnt > 0)
        spend_snap := v_spend     -- 无记录时为 0.00

    Step 3  ROI
        IF v_spend IS NULL OR v_spend = 0 THEN
            roi := NULL           -- 不写 0，不写 Infinity
            roi_source := NULL
        ELSIF revenue_net_snap IS NULL THEN
            roi := NULL
            degraded_reason := '金额来源不可用'
        ELSE
            roi := ROUND(revenue_net_snap / v_spend, 6)
            roi_source := 'M22_CALC'
        END IF

    Step 4  CPA
        IF surface_cnt IS NULL OR surface_cnt = 0 THEN
            cpa := NULL
        ELSE
            cpa := ROUND(v_spend / surface_cnt, 6)
        END IF

    Step 5  到院成本
        IF arrive_cnt IS NULL OR arrive_cnt = 0 THEN
            arrive_cost := NULL
        ELSE
            arrive_cost := ROUND(v_spend / arrive_cnt, 2)
        END IF
```

**算例（2026-10 抖音）：**

| 步骤 | 输入/输出 | 值 |
|---|---|---|
| 输入 | `revenue_net_snap` | `1,580,420.00` 元 |
| 输入 | `spend_snap`（3 笔台账 18,000 + 20,800 + 8,000） | `46,800.00` 元 |
| 输入 | `surface_cnt` | `231` 例 |
| 输入 | `arrive_cnt` | `836` 人 |
| Step 2 | `has_spend_record` | `TRUE` |
| Step 3 | `roi = 1,580,420.00 / 46,800.00` | `33.769658` |
| Step 4 | `cpa = 46,800.00 / 231` | `202.597403` |
| Step 5 | `arrive_cost = 46,800.00 / 836` | `55.98` |

**对照算例（2026-10 电话渠道）：**

| 步骤 | 输入/输出 | 值 |
|---|---|---|
| 输入 | `revenue_net_snap` | `96,300.00` 元 |
| 输入 | 台账条数 | `0`（电话渠道不允许建台账） |
| 输出 | `spend_snap` | `0.00` |
| 输出 | `has_spend_record` | `FALSE` |
| 输出 | `roi` | `NULL` |
| 页面呈现 | — | 渠道显示「无投放成本，ROI 不适用」，**不显示 0 也不显示 ∞** |

> **为什么「没投钱」要返回 `spend_snap = 0.00` + `has_spend_record = FALSE` 而不是 404：** 这是给 M11-08 的降级契约留出判断依据。M11-08 需要能区分三种情况——①**有台账但确实花了 0**（数据错误，应告警）、②**无台账**（该渠道本就不投放，ROI 不适用）、③**M22 服务不可用**（降级 `cost_snap = NULL`）。如果统一返回 404，三者就无法区分，M11-08 只能全部降级，渠道分析页会长期出现一片 `NULL`。

#### 3.4.3 质量与经济性的关联模型

```text
P06 要回答的问题：「质量好的术式，是不是也赚钱？」

  输入序列（同一 dept_id，连续 N 个月）：
     x_i = 该月质量综合指数（由 M11-07 五指标归一后加权）
     y_i = 该月净收入快照 revenue_net_snap

  质量综合指数计算（M22-06 侧，权重可配置）：
     q_score = 0.30 × norm(EI_UCVA)
             + 0.25 × norm(-SI_BCVA_LOSS)      ← 负向指标取反
             + 0.20 × norm(-ST_REFRACT_CHANGE)  ← 越小越稳，取反
             + 0.15 × norm(PR_WITHIN_0_50)
             + 0.10 × norm(-COMPLICATION_RATE)

     norm(x) 为 min-max 归一化，范围 [0,1]

  Pearson 相关系数：
     r = Σ[(x_i − x̄)(y_i − ȳ)] / sqrt(Σ(x_i − x̄)² × Σ(y_i − ȳ)²)

  约束：
     N < 6              → r = NULL（样本不足，不给结论）
     Σ(x−x̄)² = 0        → r = NULL（质量无波动，无法相关）
     Σ(y−ȳ)² = 0        → r = NULL（收入无波动，无法相关）

  结果解释（供 P06 文案使用）：
     r >= 0.6           → 「质量提升与收入提升同步，质量投入有正向回报」
     0.2 <= r < 0.6     → 「有一定正相关，但不足以支撑强结论」
     -0.2 < r < 0.2     → 「质量与收入基本无关，价格策略是主要驱动」
     r <= -0.2          → 「质量高的期间收入反而低，需核查是否因低价促销导致」
     r = NULL           → 「样本不足或数据无波动，本期不做相关性判断」
```

**算例（2026-05 ~ 2026-10，6 期）：**

| 期间 | 质量综合指数 `x` | 净收入 `y`（万元） | `x − x̄` | `y − ȳ` | 乘积 |
|---|---|---|---|---|---|
| 2026-05 | 0.712 | 352.50 | -0.0364 | -28.42 | 1.0345 |
| 2026-06 | 0.735 | 368.20 | -0.0134 | -12.72 | 0.1704 |
| 2026-07 | 0.751 | 385.60 | 0.0026 | 4.68 | 0.0122 |
| 2026-08 | 0.768 | 396.40 | 0.0196 | 15.48 | 0.3034 |
| 2026-09 | 0.782 | 401.90 | 0.0336 | 20.98 | 0.7049 |
| 2026-10 | 0.742 | 380.90 | -0.0062 | -0.02 | 0.0001 |
| 合计 | `x̄ = 0.7484` | `ȳ = 380.92` | — | — | `Σ = 2.2255` |

```text
Σ(x − x̄)² = 0.001324 + 0.000180 + 0.000007 + 0.000384 + 0.001129 + 0.000038
          = 0.003062
Σ(y − ȳ)² = 807.70 + 161.80 + 21.90 + 239.63 + 440.16 + 0.0004
          = 1,671.19

r = 2.2255 / sqrt(0.003062 × 1,671.19)
  = 2.2255 / sqrt(5.1172)
  = 2.2255 / 2.2621
  = 0.983842
```

> 结论：`quality_revenue_corr = 0.983842`，落在 `r >= 0.6` 区间，文案为「质量提升与收入提升同步，质量投入有正向回报」。注意 0.98 是一个**很高**的相关系数，通常意味着两者存在共同驱动因素（如整体市场景气度），P06 页面上必须同时展示这 6 期的散点图让使用者自己判断，**不能只给一个 r 就下结论**。

#### 3.4.4 结构变化指数

```text
用途：衡量术式结构在相邻两期之间的变化幅度，取值 [0, 1]，越大表示结构变化越剧烈。

  设 p_i = 本期第 i 个术式的手术占比（i = 1..10，Σ p_i = 1）
     q_i = 上期第 i 个术式的手术占比（Σ q_i = 1）

  结构变化指数（半 L1 距离，等价于总变差距离）：
     SCI = 0.5 × Σ |p_i − q_i|
        i=1..10

  性质：
     0     → 结构完全不变
     1     → 结构完全替换（上期有的术式本期全没了）
     SCI 对「占比从 50% 降到 45%、另一个从 5% 升到 10%」这类迁移敏感，
     比单纯看某单一术式占比变化更能反映全局。

  边界：
     任一期有术式的 case_count 为 0 → 该术式 p_i 按 0 处理（不是 NULL）
     上期或本期整体 case_count 为 0 → SCI = NULL（无法比较）
```

**算例（2026-09 → 2026-10）：**

| 术式 | 上期占比 `q` | 本期占比 `p` | `abs(p − q)` |
|---|---|---|---|
| `SMILE` | 0.5437 | 0.5234 | 0.0203 |
| `FS_LASIK` | 0.1821 | 0.1975 | 0.0154 |
| `TRANSPRK` | 0.1043 | 0.1121 | 0.0078 |
| `SMART` | 0.0721 | 0.0684 | 0.0037 |
| `ICL` | 0.0612 | 0.0658 | 0.0046 |
| `PRL` | 0.0183 | 0.0172 | 0.0011 |
| `OTHER_REFRACTIVE` | 0.0183 | 0.0156 | 0.0027 |
| 合计 | 1.0000 | 1.0000 | 0.0556 |

```text
SCI = 0.5 × 0.0556 = 0.027800
```

> 解读：0.0278 意味着从上月到本月，只有约 2.78% 的手术量在术式之间发生了迁移。P03 页面把 SCI 画成折线，当某月 SCI 突增（如 > 0.10）时自动高亮，提示「术式结构发生显著变化，需核查是否引入新术式或价格调整」。

#### 3.4.5 趋势预测模型

| 方法 | 公式 | 最少期数 | 适用场景 | 不适用场景 |
|---|---|---|---|---|
| `MA_3` | `ŷ_{t+1} = (y_t + y_{t-1} + y_{t-2}) / 3` | 3 | 平稳序列、波动小 | 有明确趋势或季节性的序列 |
| `MA_6` | `ŷ_{t+1} = (y_t + ... + y_{t-5}) / 6` | 6 | 更平滑的短期预测 | 拐点识别迟钝 |
| `EXP_SMOOTH` | `ŷ_{t+1} = α·y_t + (1−α)·ŷ_t`，α = 0.3 | 3 | 有缓慢趋势 | 强季节性 |
| `LINEAR_REG` | 最小二乘拟合 `ŷ = a + b·t` | 4 | 稳定线性趋势 | 拐点、季节性 |
| `HOLT_WINTERS` | 三次指数平滑（水平 + 趋势 + 季节） | 12（需 2 个完整季节周期） | 强季节性（如暑期屈光高峰） | 期数不足 |
| `MANUAL` | 人工录入 | 0 | 有重大事件（新设备、政策）需人工干预 | 常规场景 |

**默认方法选择规则：**

```text
1. 若历史期数 >= 12 且季节检验（自相关 12 阶显著）成立 → HOLT_WINTERS
2. 若历史期数 >= 4 且线性回归 R² >= 0.60          → LINEAR_REG
3. 若历史期数 >= 3 且变异系数 CV < 0.15            → MA_3
4. 若历史期数 >= 6 且变异系数 CV >= 0.15           → MA_6
5. 其余                                             → 不预测，页面提示「样本不足」
```

**置信区间：**

```text
残差标准差：
    σ = sqrt( Σ_{i=1..n} (y_i − ŷ_i)² / (n − 1) )

95% 置信区间：
    ci_lower = ŷ ± z_{0.975} × σ × sqrt(1 + 1/n)
    z_{0.975} = 1.959964

   MA_3 时：n = 3，σ 由 3 期残差估得
   期数越少区间越宽，这是有意的——让业务方看到「预测的不确定性」

边界：
    n < 3              → 不预测
    σ = 0（完全平稳）    → 区间退化为一个点，ci_lower = ci_upper = ŷ
    下界为负而指标本身非负 → 下界截断为 0（如手术量不能为负）
```

**算例（2026-07 ~ 2026-10 手术量，预测 2026-11）：**

| 期间 | 实际手术量 `y` |
|---|---|
| 2026-07 | 218 |
| 2026-08 | 236 |
| 2026-09 | 252 |
| 2026-10 | 231 |

```text
选择规则：#3 期数 >= 3 且 CV < 0.15
   均值 = (218 + 236 + 252 + 231) / 4 = 234.25
   标准差 = 14.38
   CV = 14.38 / 234.25 = 0.0614 < 0.15  → MA_3

最近 3 期：236, 252, 231
ŷ_2026-11 = (252 + 231 + 236) / 3 = 239.666667 → 240（手术量取整）

残差（用 MA_3 回测 4 期）：
   ŷ_2026-08 = (218 + ...) 期数不足，用 MA_2 近似 → 227，残差 9
   ŷ_2026-09 = (218 + 236) / 2 = 227  ... 回测窗口有限

实际实现用全量历史做滚动回测：
   残差 = [9, 16, -12, -5]  → σ = sqrt((81 + 256 + 144 + 25) / 4) = sqrt(126.5) = 11.25

ci_lower = 239.67 − 1.959964 × 11.25 × sqrt(1 + 1/4) = 239.67 − 24.65 = 215.02
ci_upper = 239.67 + 24.65 = 264.32
```

|---|---|

| `forecast_method` | `MA_3` |
| `forecast_base_period` | `2026-10` |
| `forecast_base_periods` | `3` |
| `forecast_horizon` | `1` |
| `confidence_interval` | `0.950000` |
| `ci_lower` | `215.020000` |
| `ci_upper` | `264.320000` |
| `metric_value` | `239.666667` |

**误差回填：** 2026-11 实际手术量出来后（假设 246），回填任务执行：
