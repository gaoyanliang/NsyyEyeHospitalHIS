### 1.2 字段通用规范

| 项 | 规范 |
|---|---|
| 主键 | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| 业务编号 | `{表名关键词}_no VARCHAR(32)`，带部分唯一索引 |
| 布尔 | `BOOLEAN NOT NULL DEFAULT FALSE`，用 `TRUE` / `FALSE` |
| 时间 | `TIMESTAMP`（不带时区，全院统一 Asia/Shanghai） |
| 金额 | `NUMERIC(14,2)` 或 `NUMERIC(12,2)`，**禁止 FLOAT** |
| 单价 | `NUMERIC(12,4)`（药品可精确到 0.0001 元/支） |
| 数量 | `NUMERIC(14,4)`（滴眼液可按 0.5 支拆零） |
| JSON | `JSONB` |
| 枚举 | `VARCHAR(32)` + CHECK 约束，不用 PG ENUM |
| 审计字段 | `created_at` / `created_by` / `updated_at` / `updated_by` / `is_deleted` |
| 幂等键 | `idempotency_key VARCHAR(128)` + 部分唯一索引 |
| 租户 | `org_id BIGINT`（本期单院区，预留） |

### 1.3 枚举实现方式

**不用 PostgreSQL ENUM 类型，用 VARCHAR + CHECK。**

理由：

1. PG ENUM 增加枚举值需要 `ALTER TYPE`，在事务里改表结构有锁风险
2. PG ENUM 无法在 SQLAlchemy 里优雅映射，Alembic 迁移复杂
3. VARCHAR + CHECK 改约束只需 `DROP CONSTRAINT` + `ADD CONSTRAINT`

示例：

```sql
ALTER TABLE m14_stock_batch
    ADD CONSTRAINT ck_m14_stock_batch_status
    CHECK (status IN ('NORMAL','NEAR_EXPIRY','EXPIRED','HOLD','REJECTED','RECALLED','DESTROYED'));
```

### 1.4 时间语义

| 字段名 | 含义 | 示例 |
|---|---|---|
| `occurred_at` | 业务实际发生时间 | 患者实际取药时间 |
| `created_at` | 记录写入时间 | 数据库插入时间 |
| `effective_date` | 生效日期 | 价格生效日 |
| `expiry_date` | 失效/过期日期 | 药品有效期 |

**`occurred_at` 与 `created_at` 可能相差很大**（离线补录、事后补单），报表一律用 `occurred_at`。

### 1.5 软删除

全部业务表支持软删除（`is_deleted BOOLEAN`），但：

| 表类型 | 是否软删除 | 理由 |
|---|---|---|
| 业务单据表 | ✅ | 作废后要能查 |
| 只增流水表 | ❌ | 不允许删除，用冲销 |
| 日志表 | ❌ | 不允许删除 |
| 主数据表 | ✅ | 停用后保留历史 |
| 快照表 | ❌ | 只增不改 |

**部分唯一索引必须带 `WHERE is_deleted = FALSE`**，否则软删除后无法重建同编号记录：

```sql
CREATE UNIQUE INDEX uk_m14_dispense_no
    ON m14_dispense (dispense_no)
    WHERE is_deleted = FALSE;
```

## 4. 索引策略

### 4.1 索引命名规范

| 类型 | 前缀 | 示例 |
|---|---|---|
| 主键 | `pk_` | `pk_m14_stock_batch` |
| 唯一索引 | `uk_` | `uk_m14_dispense_no` |
| 普通索引 | `idx_` | `idx_m14_stock_batch_drug` |
| 部分索引 | `idx_...` + `_条件` | `idx_m14_stock_batch_avail` |
| 外键索引 | `idx_` + `_fk` | `idx_m14_dispense_item_fk` |
| GIN 全文索引 | `idx_` + `_trgm` | `idx_m14_dispense_name_trgm` |

### 4.2 关键索引设计

**① 库存可用批次查询（最高频，P95 ≤ 30ms）**

```sql
CREATE INDEX idx_m14_stock_batch_avail
    ON m14_stock_batch (warehouse_id, drug_id, expiry_date)
    WHERE qty_available > 0
      AND status IN ('NORMAL', 'NEAR_EXPIRY');
```

这是 FEFO 分配的核心索引。部分索引让索引只包含可用批次，大小约为全表 1/5。

**② 发药批次按批号追溯（药监召回核心）**

```sql
CREATE INDEX idx_m14_dispense_batch_no
    ON m14_dispense_batch (batch_no, created_at DESC);
```

药监飞检时问「批号 240815 发给了谁」，这条索引保证 1 秒内出结果。

**③ 待办任务扫描**

```sql
CREATE INDEX idx_m14_rx_review_pending
    ON m14_rx_review (priority, queue_at)
    WHERE status = 'PENDING';

CREATE INDEX idx_m14_dispense_call_queue
    ON m14_dispense (prepared_at)
    WHERE status = 'CHECKED';

CREATE INDEX idx_m14_receipt_pending
    ON m14_receipt (created_at)
    WHERE inbound_status = 'PENDING' AND status = 'CONFIRMED';
```

部分索引只扫在途记录，避免随历史数据增长而变慢。

**④ 中文模糊搜索**

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX idx_m14_dispense_name_trgm
    ON m14_dispense USING GIN (patient_name gin_trgm_ops);
```

| 场景 | 处理 |
|---|---|
| 报表全表扫描 | 走 L1 预聚合表，不查明细 |

### 4.4 生成列

```sql
ALTER TABLE m14_stock_batch
    ADD COLUMN qty_available NUMERIC(14,4)
    GENERATED ALWAYS AS (qty_on_hand - qty_locked) STORED;
```

**为什么用生成列？** 可用量 = 在手量 − 锁定量的逻辑永远不该由应用层算。生成列保证：

1. 任何写入路径都不可能写出不一致的可用量
2. 不需要在应用代码里重复这个公式
3. 可以直接在生成列上建索引

## 5. 分区与归档

### 5.1 分区原则

| 原则 | 说明 |
|---|---|
| 只给流水/日志/明细分区 | 主表每单一行，不需要分区 |
| 按时间 RANGE | 便于按时间滚动删除 |
| 预建足够分区 | 避免运行时分区的 DDL 锁 |
| 分区键进主键 | PostgreSQL 强制要求 |

### 5.2 分区表清单

|---|---|---|---|---|---|

| `m14_stock_snapshot` | `snapshot_date` | 月 | 36 | 5 年 | 124 万 |
| `m14_split_record` | `created_at` | 月 | 36 | 3 年 | 14.6 万 |
| `m14_issue_log` | `started_at` | 月 | 36 | 热 180 天 | 2.9 万 |
| `m14_rx_review_log` | `created_at` | 月 | 36 | 3 年 | 82.8 万 |
| `m14_stocktake_log` | `created_at` | 月 | 36 | 3 年 | 1 万 |

### 5.3 分区建表模板

```sql
CREATE TABLE m14_stock_txn (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY,
    txn_no VARCHAR(32) NOT NULL,
    warehouse_id BIGINT NOT NULL,
    drug_id BIGINT NOT NULL,
    batch_id BIGINT NOT NULL,
    batch_no VARCHAR(64) NOT NULL,
    txn_type VARCHAR(32) NOT NULL,
    direction VARCHAR(8) NOT NULL,
    quantity NUMERIC(14,4) NOT NULL,
    qty_before NUMERIC(14,4) NOT NULL,
    qty_after NUMERIC(14,4) NOT NULL,
    idem_key VARCHAR(128),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id, created_at)
) PARTITION BY RANGE (created_at);
```

**注意：** 分区表主键必须包含分区键，所以是 `(id, created_at)`。

### 5.4 分区与唯一索引的冲突（重要取舍）

PostgreSQL 要求分区表的唯一索引**必须包含分区键**。若 `m14_stock_txn` 的幂等键 `idem_key` 要唯一，索引必须写成：

```sql
CREATE UNIQUE INDEX uk_m14_stock_txn_idem
    ON m14_stock_txn (created_at, idem_key);
```

这样跨月重复提交不会被拦截（`created_at` 不同）。**退化为「每月唯一」。**

**解法：应用层拼接月份戳**

```python
def build_idem_key(raw_key, occurred_at):
    month = occurred_at.strftime("%Y%m")
    return "{0}:{1}".format(month, raw_key)
```

这样「每月内唯一」等价于「全局唯一」——因为同一个业务请求的 `occurred_at` 月份唯一。

**这个取舍已写入各子模块数据结构文档。**

### 5.5 归档流程

```
① 结转准备
   └─ 创建归档库表（结构同主表）

② 数据结转
   INSERT INTO archive.m14_stock_txn_archive
   SELECT * FROM m14_stock_txn
   WHERE created_at >= :start AND created_at < :end;

③ 行数校验 ★ 铁律
   归档表行数 必须 == 被删行数，不等则中止

④ 分区脱离与删除
   ALTER TABLE m14_stock_txn DETACH PARTITION m14_stock_txn_2023_01;
   DROP TABLE m14_stock_txn_2023_01;
```

**归档铁律：** 归档表行数与被删行数完全一致才可删主表。少一行意味着丢了某次数量变化的解释，账实再也不可能对上。

### 6.1 数值自洽约束（最重要的一类）

```sql

    CHECK (
        (direction = 'IN'  AND qty_after = qty_before + quantity)
     OR (direction = 'OUT' AND qty_after = qty_before - quantity)

    ADD CONSTRAINT ck_m14_stock_batch_lock

-- 发药明细：调配数 + 缺药数 = 处方数

    ADD CONSTRAINT ck_m14_drug_return_qty_balance
    CHECK (ABS(reusable_qty + scrap_qty - return_qty) < 0.0001);

-- 拆零：数量守恒
```

### 6.4 只增表保护触发器

```sql
CREATE OR REPLACE FUNCTION fn_m14_stock_txn_immutable()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION 'm14_stock_txn 为只增表，禁止 DELETE';
    END IF;
    IF NEW.quantity <> OLD.quantity
       OR NEW.direction <> OLD.direction
       OR NEW.txn_type <> OLD.txn_type
       OR NEW.batch_id <> OLD.batch_id
       OR NEW.drug_id <> OLD.drug_id
       OR NEW.warehouse_id <> OLD.warehouse_id
       OR NEW.qty_before <> OLD.qty_before
       OR NEW.qty_after <> OLD.qty_after THEN
        RAISE EXCEPTION 'm14_stock_txn 为只增表，禁止修改数量与关键字段';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_m14_stock_txn_immutable
    BEFORE UPDATE OR DELETE ON m14_stock_txn
```

```sql
    ON m14_xxx_config (param_code, scope, COALESCE(scope_id, 0));
```

**`COALESCE(scope_id, 0)` 的必要性：** PostgreSQL 唯一索引认为 NULL 互不相等，若 `scope_id` 可为 NULL，同一 `param_code` + `GLOBAL` 能插入两次，读取时 `first()` 拿到哪个不确定。

### B.3 金额计算三条铁律

**① 行级先舍入再累加**

```python
# 正确
line_amount = money(unit_price * quantity)
total = sum(line_amount for line in lines)

# 错误
total = money(sum(unit_price * quantity for line in lines))
```

**② 税额倒算不是正算**

```python
# 正确：含税 → 不含税
amount_without_tax = money(amount / (Decimal("1") + tax_rate))
tax_amount = amount - amount_without_tax

# 错误：把价内税当价外税
tax_amount = money(amount * tax_rate)   # 1000 元 13% 算成 130，实际应是 115.04
```

**③ money 函数统一入口**

```python
CENT = Decimal("0.01")

def money(value):
    return Decimal(str(value)).quantize(CENT, rounding=ROUND_HALF_UP)
```
