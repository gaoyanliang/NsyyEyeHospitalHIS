## 1. 模块概述

### 1.1 模块定位

**M14-05 盘点与库存调整** 负责回答一个问题：

> **"账上的数和柜子里的数不一样了，到底差多少、差在哪、该不该认、认了之后怎么补账？"**

它是药库药房管理中唯一允许"把账上数量改成柜子里数量"的地方。其他所有子模块对数量的改变都有一个共同的约束——**必须有一份对应的单据能解释这个变化**（采购单、出库单、调拨单、发药单）。只有盘点和盘点后的调整没有。

这就决定了它的核心设计原则：

> **调整必须有依据，依据必须来自盘点，盘点必须有见证。**

```
┌──────────────────────────────────────────────────────────────┐
│                    数量变化的合法来源                          │
├──────────────────────────────────────────────────────────────┤
│  M14-03 采购入库      ← 有采购单、验收单、发票                │
│  M14-04 出库调拨      ← 有出库单、调拨单、领用科室签字         │
│  M14-07 门诊发药      ← 有处方、有患者                     │
│  M14-08 住院摆药      ← 有医嘱、有摆药单                   │
│  M14-09 麻精专用      ← 有逐支登记、双人签字                │
│  ─────────────────────────────────────────────────────────  │
│  M14-05 盘点调整      ← 只有一张盘点表 + 一份差异说明        │
│                     ↑ 这里最容易被"手工抹平"              │
└──────────────────────────────────────────────────────────────┘
```

因此 M14-05 的价值不在于"让系统能改数量"，而在于**让每一次改都能被查到、被追问、被追责**。

整体数据流：

```
   ┌─────────────┐
   │ 创建盘点单  │ 选定范围：全盘 / 抽盘 / 循环盘
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 冻结盘点范围│ 冻结期间该范围禁止出入库
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 生成盘点表  │ 按当前批次快照生成账面数量
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 逐批录入实盘│ 手工录入 / PDA 扫码 / 多次补录
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 提交待审    │ 差异自动分级
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 差异审批    │ 按差异金额与品类分级审批
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 生成调整单  │ 盘盈 STOCKTAKE_IN / 盘亏 STOCKTAKE_OUT
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 执行调整    │ 调用 M14-01 唯一入口写入库存流水
   └──────┬──────┘
          ▼
   ┌─────────────┐
   │ 解除冻结    │ 差异报告归档
   └─────────────┘
```

### 1.2 为什么独立成子模块

有人会问：盘点不就是"数一数、改个数"吗？为什么要单独一个子模块？

**理由一：盘点是唯一能"无单据改数量"的操作，风险最高。**

采购入库少了 100 支，供应商会来吵；发药发错了，患者会来找。但盘亏 100 支，如果没人盯着，就是"账上少了 100 支，原因不明"。这是所有药房舞弊最常见的路径：

1. 私自拿走药品
2. 盘点时把账调平
3. 无人追问

要堵住这条路，盘点必须有：**范围冻结 / 差异分级审批 / 双人见证 / 完整留痕 / 差异率监控**。这套机制复杂度已经超过"一个功能"，必须是独立子模块。

**理由二：盘点的对象和时序与其他子模块完全不同。**

| 维度 | 其他子模块 | M14-05 |
|---|---|---|
| 触发时机 | 业务驱动（有处方、有订单） | 周期驱动（月盘、年盘、循环盘） |
| 操作对象 | 单条单据、单个批次 | 整个仓库或指定范围的全部批次 |
| 数据量 | 几张到几十行 | 几百到几万行 |
| 执行时长 | 秒级 | 分钟到小时级 |
| 并发要求 | 高频 | 极低频但必须独占 |
| 跨天 | 通常不跨 | 大仓盘点常跨夜 |

盘点一晚上要处理 3,000 个批次，期间要求整个仓库冻结——这个"独占 + 长事务"特性与日常业务完全不同，混在一起做会互相干扰。

**理由三：盘点结果的用途远超"改数量"。**

盘点差异率是药房管理水平的核心 KPI：

- 差异率 > 2% → 管理失控，需要专项整改
- 某类药品（如高值耗材、麻精）差异率异常 → 舞弊信号
- 某个人经手的库存差异异常 → 责任问题
- 批次效期账实不符 → GSP 检查直接扣分

如果盘点只是"改数量的功能"，这些分析就无处安放。

### 1.3 与相邻子模块的分工

| 能力 | 归属 | 说明 |
|---|---|---|
| 创建盘点单、生成盘点范围 | **M14-05** | ✅ 唯一责任 |
| 冻结/解冻盘点范围的出入库 | **M14-05** | ✅ 唯一责任 |
| 录入实盘数量 | **M14-05** | ✅ 唯一责任 |
| 差异计算与分级 | **M14-05** | ✅ 唯一责任 |
| 差异审批 | **M14-05** | ✅ 唯一责任 |
| 生成调整单（盘盈/盘亏） | **M14-05** | ✅ 唯一责任 |
| 实际写入库存流水 | M14-01 | ❌ 调 M14-01 `stock/apply` |
| 库存数量查询 | M14-01 | ❌ 从 M14-01 读 |
| 批次信息与效期 | M14-01 | ❌ 从 M14-01 读 |
| 盘点期间的出库管控 | M14-04 | ❌ M14-05 只提供"冻结标记"，M14-04 负责拦截 |
| 盘点差异的财务处理 | M17 | ❌ M14-05 只提供差异报告 |

**边界口诀：**

> **M14-05 只回答"账实差多少、该不该认"。**
> **数量怎么改是 M14-01 的事，冻结期间能不能出库是 M14-04 的事，损失怎么记账是 M17 的事。**

### 1.4 概念辨析

#### 1.4.1 盘点 ≠ 抽查

| 项 | 盘点 | 抽查 |
|---|---|---|
| 范围 | 覆盖指定范围内**全部**批次 | 随机或指定部分批次 |
| 目的 | 确认账实一致，出具调整依据 | 了解现状、发现问题 |
| 结果 | 产生调整单，改库存 | 不改库存，只出报告 |
| 审批 | 必须 | 不需要 |

抽查是"看看情况"，盘点要"动账"。M14-05 两者都支持，但抽查产生的记录明确标记 `check_type = 'SAMPLE'`，**不允许生成调整单**。

#### 1.4.2 盘盈 ≠ 采购入库

两者都会让库存数量增加，但含义完全不同：

| 项 | 盘盈 | 采购入库 |
|---|---|---|
| 来源 | 账上没有、实物有 | 供应商送来 |
| 流水类型 | `STOCKTAKE_IN` | `PURCHASE_IN` |
| 金额处理 | 按当前批次成本估价，计入"盘盈"科目 | 按发票金额计入采购成本 |
| 是否需要发票 | 不需要（没有发票） | 需要 |
| 税务 | 视为非经营性收入，需做进项转出 | 正常抵扣 |
| 是否需要审批 | 是（差异金额分级） | 是（采购审批） |

如果盘盈也走采购入库，就会凭空多出一笔"采购"，财务账和供应商账全对不上。

#### 1.4.3 盘亏 ≠ 报损

| 项 | 盘亏 | 报损 |
|---|---|---|
| 实物 | **找不到**（账上有，实物无） | **找得到**（药还在，但坏了/过期了） |
| 可核查性 | 无法拍照证明"没有" | 可以拍照证明"坏了" |
| GSP 要求 | 记录差异原因 | 记录销毁全过程 + 监销人 |
| 舞弊风险 | **高**（无法自证清白） | 低（有实物可查） |
| 流水类型 | `STOCKTAKE_OUT` | `LOSS_OUT` |
| 控制手段 | 差异率监控 + 分级审批 + 双人盘点 | 审批 + 监销 + 照片 |

正因为盘亏无法自证清白，M14-05 在盘亏上的控制强度必须高于报损：**差异率告警、连续盘亏告警、超阈值强制双人复核**。

#### 1.4.4 循环盘点 ≠ 全盘

| 项 | 全盘 | 循环盘点 |
|---|---|---|
| 频率 | 月度/季度/年度 | 每日按规则抽一部分 |
| 范围 | 一次覆盖全部批次 | 每次只覆盖一小部分，周期内轮完一遍 |
| 冻结时长 | 长（数小时） | 短（几分钟） |
| 影响业务 | 大（停业或限流） | 几乎无感 |
| 适用 | 药库（品类少、批量大） | 药房（品类多、周转快） |

对二级眼科医院，推荐：**药库月全盘 + 药房每日循环盘 + 麻精每周专项盘 + 年度全院盘点**。

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 盘点覆盖率 | 药库 100%/月 | 每个批次每月至少盘一次 |
| 盘点差异率 | < 0.5% | 差异金额 / 账面金额 |
| 差异处理及时率 | 100%/48h | 盘点结束 48 小时内完成审批与调整 |
| 冻结窗口 | < 4h | 全盘冻结时长 |
| 盘点表生成 | < 5s | 3,000 批次规模 |
| 调整单生成 | < 3s | 1,000 行差异 |
| 数据可追溯 | 100% | 每笔调整可追到盘点单与录入人 |

### 1.6 关键业务角色

| 角色 | 职责 | 权限 |
|---|---|---|
| 药库管理员 | 创建盘点单、录入实盘数 | `m14:stocktake:apply` |

## 2. 业务范围与边界

### 2.1 范围内

| 功能 | 说明 |
|---|---|
| 盘点单管理 | 创建、编辑、提交、作废 |
| 盘点范围定义 | 全仓 / 指定药品 / 指定库位 / 指定批次 / ABC 分类 |
| 范围冻结与解冻 | 冻结期间的出入库拦截标记 |
| 盘点表生成 | 按当前库存快照生成待盘列表 |
| 实盘录入 | 手工录入、PDA 扫码、批量导入 |
| 差异计算 | 逐批差异 + 汇总差异 + 差异率 |
| 差异分级 | 按金额、品类、差异率分级 |
| 差异审批 | 单级/多级审批链 |

| 循环盘点规则 | 按 ABC / 随机 / 高值 / 麻精 定期自动生成盘点任务 |
| 差异分析 | 按药品、按仓库、按人员、按时段分析差异 |

### 2.2 范围外

| 能力 | 归属 | 说明 |

## 3. 业务模型

### 3.1 盘点单模型

#### 3.1.1 盘点类型

| 代码 | 名称 | 说明 | 默认冻结 |
|---|---|---|---|
| `FULL` | 全盘 | 盘点仓库内全部批次 | 是 |
| `PARTIAL` | 抽盘 | 按条件筛选批次 | 是 |
| `CYCLE` | 循环盘 | 按规则自动生成，只盘一小部分 | 否 |
| `SAMPLE` | 抽查 | 了解现状，不产生调整 | 否 |
| `SPECIAL` | 专项盘 | 麻精/高值/冷链等专项 | 是 |

#### 3.1.2 盘点单状态机

```
                  ┌──────────┐
                  │  DRAFT   │  草稿：可改范围
                  └────┬─────┘
                       │ submit
                       ▼
                  ┌──────────┐
       ┌──────────│ GENERATED│  已生成盘点表（账面快照已锁定）
       │          └────┬─────┘
       │               │ start_counting（可选，或直接录入）
       │               ▼
       │          ┌──────────┐
       │          │COUNTING  │  盘点中：可反复录入
       │          └────┬─────┘
       │               │ submit_count
       │               ▼
       │          ┌──────────┐
       │          │ SUBMITTED│  待审批
       │          └────┬─────┘
       │        ┌──────┴──────┐
       │  approve│             │reject
       │        ▼             ▼
       │   ┌─────────┐   ┌──────────┐
       │   │APPROVED │   │ REJECTED │──► 回到 COUNTING
       │   └────┬────┘   └──────────┘
       │        │ execute
       │        ▼
       │   ┌──────────┐
       │   │ EXECUTING│
       │   └────┬─────┘
       │    ┌───┴────┐
       │    ▼        ▼
       │ ┌───────┐ ┌─────────┐
       │ │CLOSED │ │EXEC_FAIL│──► 可重试
       │ └───────┘ └─────────┘
       │
       └────► ┌──────────┐
              │CANCELLED │  作废（解冻范围）
              └──────────┘
```

**关键约束：**

| 约束 | 说明 |
|---|---|
| `GENERATED` 之后账面数量锁定 | 生成盘点表时把当时的 `qty_on_hand` 快照进 `book_qty`，之后系统库存怎么变都不影响 |
| `SUBMITTED` 之后实盘数量锁定 | 防止审批期间改数 |
| `APPROVED` 之后不能回退 | 只能执行或作废，作废需重新盘点 |
| `CLOSED` 是终态 | 已产生库存流水，不可逆 |

#### 3.1.3 为什么要 GENERATED 和 COUNTING 两个状态

看起来"生成盘点表"和"开始盘"可以合并，但实际运营中必须分开：

**场景：** 药库月初要盘 3,000 个批次，但盘点表要提前一天打出来给盘点人员熟悉。这时候：

- 盘点表昨天就生成了（`GENERATED`），账面数已锁定
- 但今天早上又来了一批货，入库正常进行（因为还没开始盘，不该冻结）
- 下午盘点人员到岗，才开始盘（`COUNTING`），此时才冻结

如果合并成一个状态，要么昨天生成时就冻结（导致一天不能收货），要么今天开始盘时才生成（盘点表打不出来）。

### 3.2 盘点范围模型

#### 3.2.1 范围定义方式

| 方式 | 参数 | 示例 |
|---|---|---|
| 全仓 | `warehouse_id` | 中心药库全部批次 |
| 按药品 | `drug_ids` / `drug_category` | 全部滴眼液 |
| 按库位 | `location_codes` | A 区 1-10 号货架 |
| 按批次 | `batch_ids` | 指定 20 个批次 |
| 按 ABC 分类 | `abc_class` | A 类高值药品 |
| 按管理类别 | `management_class` | 麻醉药品 |
| 按效期 | `expiry_before` | 6 个月内到期 |
| 按动销 | `slow_moving_days` | 90 天无动销 |

**组合方式：** 多个条件取交集。例如「中心药库 + A 类 + 6 个月内到期」= 在中心药库里、A 类分类、且半年内过期的那部分批次。

#### 3.2.2 范围快照

生成的盘点范围会落成 `m14_stocktake_scope` 表（记录范围定义参数）与 `m14_stocktake_item` 表（记录具体批次）。

**为什么范围要快照而不是每次实时计算？**

因为盘点可能跨天，期间药品主数据可能变更（新增一个 A 类药品、某个批次被移库）。如果每次实时算：

- 第一天盘了 500 行
- 第二天范围多出 3 个新批次
- 用户看到"还有 3 行没盘"，其实是新增的，不是漏盘

快照后范围固定，用户看到的就是"这次要盘什么"，不会变。

#### 3.2.3 空范围的防护

如果范围条件没有匹配任何批次（比如"6 个月内到期"但所有批次都是新的），要明确报错 55402，而不是生成一个空盘点单。

空盘点单会造成两个问题：

1. 用户以为"盘完了没问题"，实际上什么都没盘
2. 差异率计算时分母为 0，产生除零异常

### 3.3 账面数量与实盘数量模型

#### 3.3.1 三个数量

| 字段 | 含义 | 何时确定 |
|---|---|---|
| `book_qty` | 账面数量（生成盘点表时的快照） | `GENERATED` 时 |
| `system_qty` | 当前系统数量（执行调整时实时读） | `EXECUTING` 时 |
| `actual_qty` | 实盘数量（人眼看到的） | 录入时 |

**为什么要区分 `book_qty` 与 `system_qty`？**

盘点从生成到执行之间，系统库存可能发生变化。如果 `system_qty ≠ book_qty`，说明账面在盘点期间被动过，这时候不能直接用 `actual_qty - book_qty` 做调整。

处理方式：

| 情况 | 处理 |
|---|---|
| `system_qty == book_qty` | 正常，差异 = `actual_qty - book_qty` |
| `system_qty ≠ book_qty` 且差额可解释 | 提示用户，用 `system_qty` 重新计算差异 |
| `system_qty ≠ book_qty` 且差额无法解释 | **阻断执行**，报 "1405007"，需人工排查 |

#### 3.3.2 差异类型

| 代码 | 名称 | 条件 | 流水类型 |
|---|---|---|---|
| `MATCH` | 账实相符 | `actual_qty == book_qty` | 无 |
| `PROFIT` | 盘盈 | `actual_qty > book_qty` | `STOCKTAKE_IN` |
| `LOSS` | 盘亏 | `actual_qty < book_qty` | `STOCKTAKE_OUT` |

**数量精度的处理：**

药品数量可能以"盒""支""片"计价，精度 4 位小数。盘点时：

- 整盒药品按盒盘（`1.0000`）
- 可拆零药品可能盘出 `3.0000` 支
- 允许 `0.0001` 的误差容忍（`QTY_TOLERANCE`）

差异小于等于 `QTY_TOLERANCE` 视为 `MATCH`，不产生调整。这是为了避免"账上 100.0000 支、实物 99.9999 支"这种毫无意义的差异。

#### 3.3.3 差异金额

```
diff_qty   = actual_qty - book_qty
diff_amount = ROUND(diff_qty × unit_cost, 2)
```

`unit_cost` 取该批次的进价（`m14_stock_batch.unit_cost`）。如果批次没有成本价（如受赠药品），用药品主数据的 `purchase_price` 兜底。

**为什么用成本价而不是零售价？**

盘亏的实际损失是采购成本，不是零售价。100 元的药丢了，损失是 60 元（成本），不是 100 元。财务记账用成本价，管理报表才可能用零售价。

### 3.4 差异分级模型

#### 3.4.1 分级维度

差异按三个维度综合分级：

**维度一：差异金额（`abs(diff_amount)`）**

| 金额区间 | 级别 |
|---|---|
| 0 < 金额 ≤ 500 | `SMALL` |
| 500 < 金额 ≤ 5,000 | `MEDIUM` |
| 5,000 < 金额 ≤ 50,000 | `LARGE` |
| 金额 > 50,000 | `HUGE` |

**维度二：药品管理类别**

| 类别 | 级别提升 |
|---|---|
| 普通药品 | — |
| 高值药品（`is_high_risk`） | 提升一级 |
| 麻精毒放 | 提升两级，直接 `LARGE` 起 |
| 冷链药品 | 提升一级 |

**维度三：差异率**

| 差异率 | 处理 |
|---|---|
| < 1% | 正常 |
| 1% ~ 5% | 全部差异人工复核 |
| > 5% | 强制专项审计 + 通报 |

#### 3.4.2 审批矩阵

| 级别 | 审批链 | 时限 |
|---|---|---|
| `SMALL` | 药房组长 | 48h |
| `MEDIUM` | 药械科主任 | 48h |
| `LARGE` | 药械科主任 + 财务主管 | 72h |
| `HUGE` | 药械科主任 + 财务主管 + 院长 | 72h |

**质量相关强制路径：** 如果差异药品包含冷链/效期问题（`is_quality_related = TRUE`），审批链必须加质量负责人（不占级别，并联审批）。

#### 3.4.3 盘盈也要审批

很多人以为盘盈是"多了药"，是好事，不用审。这是误解。

盘盈意味着：

- 入库时少记了（供应商多给了，但入库单按订单数记）
- 出库时少扣了（发了药但没记录）
- 药品被人放错位置（从别处移过来的）
- 系统账本来就错

**盘盈最常见的真实原因是"出库没记录"**——药发出去了，系统里没扣，所以账上还有。这种情况下，账实相符是假象，必须查清。

### 3.5 冻结模型

#### 3.5.1 冻结粒度

| 粒度 | 键 | 说明 |
|---|---|---|
| 仓库级 | `m14:stocktake:freeze:wh:{warehouse_id}` | 该仓库全部冻结 |
| 药品级 | `m14:stocktake:freeze:drug:{warehouse_id}:{drug_id}` | 该仓库该药品冻结 |

**冻结范围怎么选？**

- 全盘 → 仓库级冻结
- 抽盘/循环盘 → 药品级冻结（只冻结涉及的药品）

理由：全盘本身就要停业几小时，仓库级冻结合理；抽盘只盘 20 个药，冻结整个仓库会导致其他药品无法出库，影响太大。

#### 3.5.2 冻结的执行

M14-05 只负责**写冻结标记**，拦截由 M14-04 做：

```
M14-05 写 Redis 标记
    │
    ▼
m14:stocktake:freeze:wh:7 = {
    "take_no": "PD20261021001",
    "take_id": 123,
    "warehouse_id": 7,
    "expire_at": "2026-10-21T23:59:59",
    "scope": "FULL"
}   TTL 与盘点时长绑定
    │
    ▼
M14-04 出库/调拨前置检查
    │
    ├── 命中冻结 → 报 55351（M14-04 的错误码）
    └── 未命中 → 正常执行
```

**为什么冻结标记放 Redis 而不是数据库？**

因为拦截必须极快（每次出库都要查）。Redis 查询 1ms，数据库至少 3ms。出库是高频操作，3ms × 每天 500 次 = 1.5 秒，不算多，但能在 Redis 解决就没必要动数据库。

**Redis 挂了怎么办？**

Redis 挂了直接报 "1405013"，不允许绕过。理由是：Redis 挂时无法判断是否冻结，如果放行，可能在全盘期间出库，导致盘点白做。

#### 3.5.3 冻结的超时保护

盘点单不可能无限期冻结仓库。如果盘点人员下班走了忘记解冻，第二天整个药房不能发药。

**机制：**

1. 冻结标记带 `expire_at`，默认 `created_at + 8h`
2. 每小时有一个扫描任务检查"已过期但仍冻结"的情况，自动解冻并告警
3. 冻结中盘点单处于 `COUNTING`/`SUBMITTED` 时，`expire_at` 会续期（每次录入动作续 2h）

这样既防止遗忘，又不影响正常盘点的长时占用。

### 3.6 循环盘点模型

#### 3.6.1 循环盘点规则

| 参数 | 说明 | 默认 |
|---|---|---|
| `cycle_type` | 分类方式：`ABC` / `RANDOM` / `HIGH_VALUE` / `NARCOTIC` / `SLOW_MOVING` | `ABC` |
| `frequency` | 频率：`DAILY` / `WEEKLY` / `MONTHLY` | `DAILY` |
| `items_per_cycle` | 每周期盘几个药品 | 20 |
| `warehouse_ids` | 参与循环盘的仓库 | — |
| `count_time` | 自动生成时间 | `06:00` |

#### 3.6.2 ABC 分类与盘点频率对应

| 分类 | 判定 | 建议频率 | 理由 |
|---|---|---|---|
| A 类 | 年消耗金额占前 70% | 每周 | 金额大，差异影响大 |
| B 类 | 占比 70%~90% | 每月 | 金额中等 |
| C 类 | 占比后 10% | 每季 | 金额小，可放宽 |

**对二级眼科医院的实际情况：**

眼科用药高度集中，A 类通常就是玻璃酸钠滴眼液、左氧氟沙星滴眼液、雷珠单抗等高值药。这些药一个月消耗金额可能占全院药品的 60% 以上，盘亏一支就上百元，必须高频盘。

#### 3.6.3 循环盘的自动生成

每日 `06:00` 由 Celery 任务扫描生效的循环盘规则：

```
for rule in active_cycle_rules:
    targets = select_targets(rule)      # 按规则选出本周期该盘的药品
    if not targets: continue
    take = create_stocktake(FULL, targets, auto_generated=True)
    generate_items(take)
    notify_warehouse_keeper(take)       # 推送到待办
```

自动生成的盘点单状态直接是 `GENERATED`，等待人工录入。

#### 3.6.4 未盘惩罚

如果某个药品连续 N 个周期没有被盘到（因为每次随机抽没抽中），系统会**提升其优先级**，下次优先选入。保证"每个药品一个季度至少盘一次"。

### 3.7 调整单模型

#### 3.7.1 调整单的生成

盘点审批通过后，按差异逐批生成调整记录：

| 差异类型 | 调整方向 | 流水类型 | 数量 |
|---|---|---|---|
| `PROFIT` | 增加 | `STOCKTAKE_IN` | `+diff_qty` |
| `LOSS` | 减少 | `STOCKTAKE_OUT` | `-abs(diff_qty)` |

**为什么每批单独一条调整记录？**

因为盘盈盘亏是**批次级**的，不是药品级的。同一个药品：

- A260101 批次盘盈 10 支
- A260803 批次盘亏 10 支

如果合并成"该药品无差异"，就漏掉了两个批次的问题——可能 A260101 多的是从 A260803 挪过来的（实物挪位但批次标签没挪），也可能是真的多进少出。

#### 3.7.2 调整的幂等

调整单执行时调 M14-01 `stock/apply`，幂等键：

```
STOCKTAKE:{take_no}:{batch_id}
```

这样即使 Celery 任务重试、网络超时重发，也不会重复调整。

#### 3.7.3 调整失败的处理

| 失败原因 | 处理 |
|---|---|
| M14-01 服务超时 | 重试（最多 3 次，间隔 5s/30s/120s） |
| 库存不足（盘亏时） | 严重异常。说明盘点期间库存被动了 → 报 "1405008" |
| 批次不存在 | 严重异常，批次被删除 → 报 "1405009" |
| 幂等冲突 | 说明已执行过，查流水确认后标成功 |

**盘亏时为什么可能"库存不足"？**

盘亏就是要扣库存。如果账面 100 支、实盘 60 支，要扣 40 支，此时库存 = 0 才对。但如果盘点期间又发了 80 支（系统账已扣到 20），此时扣 40 支就会变负。

这种情况说明**盘点期间有出库发生，违背了冻结约束**。必须人工排查是冻结失效还是有人绕过。

### 3.8 差异归因模型

#### 3.8.1 差异原因代码

| 代码 | 名称 | 说明 | 后续动作 |
|---|---|---|---|
| `UNRECORDED_ISSUE` | 出库未记录 | 药发了没扣账 | 查发药记录补录 |
| `UNRECORDED_RECEIPT` | 入库未记录 | 药收了没记账 | 查验收记录补录 |
| `MISPLACED` | 摆放错误 | 放错库位/放错货架 | 移库纠正 |
| `BATCH_MIXED` | 批次混放 | 不同批次混在一起 | 重新贴标 |
| `DAMAGED_UNDETECTED` | 破损未报 | 坏了还没报废 | 转报损流程（M14-04） |
| `THEFT` | 被盗/私自取用 | 有舞弊嫌疑 | 上报纪检 |
| `SYSTEM_ERROR` | 系统错误 | 流水丢失、并发异常 | 技术排查 |
| `UNKNOWN` | 原因不明 | 查不出 | 记入差异台账 |

#### 3.8.2 归因的强制要求

| 差异级别 | 归因要求 |
|---|---|
| `SMALL` | 可选（可留 `UNKNOWN`） |
| `MEDIUM` | 必填 |
| `LARGE` | 必填 + 附文字说明 ≥ 20 字 |
| `HUGE` | 必填 + 说明 ≥ 50 字 + 必须上传调查报告 |
| `THEFT` | 任何级别都必须填写报案/上报说明 |

**为什么要强制归因？**

因为不归因的盘点就是"把账调平就完事"，这样盘点失去了管理意义。归因才能驱动改进：如果 80% 的差异都是 `UNRECORDED_ISSUE`，说明发药流程有漏洞；如果是 `THEFT`，说明有内控问题。

### 3.9 盘点报告模型

#### 3.9.1 报告内容

| 维度 | 指标 |
|---|---|
| 总体 | 盘点批次数、相符数、盘盈数、盘亏数、相符率、差异率 |
| 按仓库 | 各仓库的相符率与差异金额 |
| 按药品类别 | 各类别的差异分布 |
| 按管理类别 | 普通/高值/麻精/冷链 的差异对比 |
| 按人员 | 各盘点人录入的批次与差异 |
| 按原因 | 各原因代码的出现次数与金额 |
| 趋势 | 与上 N 次盘点的差异率对比 |

#### 3.9.2 相符率与差异率

```
相符率 = MATCH 批次数 / 总盘点批次数 × 100%
差异率 = Σ|diff_amount| / Σ(book_qty × unit_cost) × 100%
```

**注意差异率的分母是账面金额，分子是差异金额绝对值之和。** 不能用净差异（盘盈减盘亏），因为盘盈和盘亏可能互相抵消——比如盘盈 500、盘亏 500，净差异是 0，但实际有 1,000 元的账实不符。

#### 3.9.3 异常检测

报告自动标出以下异常：

| 异常 | 阈值 | 说明 |
|---|---|---|
| 差异率超标 | > 2% | 整体管理失控 |
| 单药品差异率超标 | > 10% 且连续 2 次 | 该药品疑似被盯上 |
| 连续盘亏 | 同药品连续 3 次盘亏 | 存在系统性流失 |
| 麻精差异 | 任何非零差异 | 立即上报 |
| 差异集中在同一人 | 某人录入的差异占 50% 以上 | 排查本人 |

```python
import hashlib

from sqlalchemy import and_, func, or_, select, text, update
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.exceptions import BizError
from app.models.m14 import (
    M14Stocktake, M14StocktakeAdjust, M14StocktakeApproval,
    M14StocktakeCycleRule, M14StocktakeItem, M14StocktakeLog,
    M14StocktakeScope,
)
from app.services.m14.client import M14StockClient, RedisClient

CENT = Decimal("0.01")
QTY_EPS = Decimal("0.0001")

# 差异金额分级（绝对值下界）
LEVEL_TIERS = [
    (Decimal("500"), "SMALL"),
    (Decimal("5000"), "MEDIUM"),
    (Decimal("50000"), "LARGE"),
]
TOP_LEVEL = "HUGE"

# 品类提级
CATEGORY_RAISE = {
    "NARCOTIC": 2,
    "PSYCHOTROPIC": 2,
    "TOXIC": 2,
    "HIGH_VALUE": 1,
    "COLD_CHAIN": 1,
}

LEVEL_ORDER = ["SMALL", "MEDIUM", "LARGE", "HUGE"]

# 审批链
APPROVAL_CHAIN = {
    "SMALL": ["DEPT_LEADER"],
    "MEDIUM": ["DEPT_DIRECTOR"],
    "LARGE": ["DEPT_DIRECTOR", "FINANCE"],
    "HUGE": ["DEPT_DIRECTOR", "FINANCE", "PRESIDENT"],
}

ROLE_NAME = {
    "DEPT_LEADER": "药房组长",
    "DEPT_DIRECTOR": "药械科主任",
    "FINANCE": "财务主管",
    "PRESIDENT": "院长",
    "QUALITY": "质量负责人",
}


def money(value):
    """金额两位小数四舍五入"""
    return Decimal(str(value)).quantize(CENT, rounding=ROUND_HALF_UP)


class StocktakeService:
    """盘点与库存调整服务"""

    # ---- 盘点单 ----

    @classmethod
    async def create(cls, body, user):
        """创建盘点单"""
        db = await cls._db()
        wh = await M14StockClient.get_warehouse(body.warehouse_id)
        if wh is None or wh.get("is_deleted"):
            raise BizError("55401", "仓库不存在")
        if wh.get("status") != "ENABLED":
            raise BizError("55401", "仓库已停用")

        await cls._check_no_running(db, body.warehouse_id)
        await cls._check_plan_date(body.plan_date)

        take_no = await cls._next_take_no(db)
        take = M14Stocktake(
            take_no=take_no,
            warehouse_id=body.warehouse_id,
            warehouse_name=wh.get("name"),
            take_type=body.take_type,
            plan_date=body.plan_date,
            freeze_mode=body.freeze_mode,
            status="DRAFT",
            created_by=user.id,
            remark=body.remark,
        )
        db.add(take)
        await db.flush()

        scope = M14StocktakeScope(
            take_id=take.id,
            scope_json=json.dumps(body.scope or {},
                                  ensure_ascii=False),
        )
        db.add(scope)
        await db.commit()

        if body.auto_generate:
            return await cls.generate(take.id, user)
        return await cls.get(take.id, user)

    @classmethod
    async def generate(cls, take_id, user):
        """生成盘点表（锁定账面快照）"""
        db = await cls._db()
        take = await cls._get_for_update(db, take_id)
        if take.status not in ("DRAFT", "GENERATED"):
            raise BizError("55406", "当前状态不允许生成盘点表")

        scope = await cls._load_scope(db, take.id)
        batches = await M14StockClient.list_batches(
            warehouse_id=take.warehouse_id, scope=scope)
        if not batches:
            raise BizError("55402", "盘点范围为空，未匹配到任何批次")
        if len(batches) > cls.MAX_SCOPE:
            raise BizError(
                "55404",
                "盘点范围 %d 个批次超出上限 %d，请分批盘点"
                % (len(batches), cls.MAX_SCOPE))

        if take.status == "GENERATED":
            await db.execute(
                text("DELETE FROM m14_stocktake_item "
                     "WHERE take_id = :tid"), {"tid": take.id})

        total_amount = Decimal("0")
        for b in batches:
            book_qty = Decimal(str(b.get("qty_on_hand") or 0))
            unit_cost = Decimal(str(b.get("unit_cost") or 0))
            total_amount += money(book_qty * unit_cost)
            db.add(M14StocktakeItem(
                take_id=take.id,
                batch_id=b["batch_id"],
                drug_id=b["drug_id"],
                drug_code=b.get("drug_code"),
                drug_name=b.get("drug_name"),
                specification=b.get("specification"),
                batch_no=b.get("batch_no"),
                expiry_date=b.get("expiry_date"),
                location_code=b.get("location_code"),
                book_qty=book_qty,
                unit_cost=unit_cost,
                management_class=b.get("management_class"),
                is_cold_chain=bool(b.get("is_cold_chain")),
                count_status="UNCOUNTED",
            ))

        take.status = "GENERATED"
        take.total_count = len(batches)
        take.book_amount = money(total_amount)
        take.generated_at = datetime.now()

        await cls._log(db, take, "GENERATE", user,
                       "生成 %d 个批次" % len(batches))
        await db.commit()

        if take.freeze_mode == "WAREHOUSE":
            await cls._freeze_warehouse(take)
        return await cls.get(take.id, user)

    @classmethod
    async def start_counting(cls, take_id, user):
        """开始盘点"""
        db = await cls._db()
        take = await cls._get_for_update(db, take_id)
        if take.status != "GENERATED":
            raise BizError("55406", "只有已生成盘点表的单据可以开始盘点")
        take.status = "COUNTING"
        take.counting_started_at = datetime.now()
        await cls._log(db, take, "START_COUNTING", user, None)
        await db.commit()
        if take.freeze_mode == "WAREHOUSE":
            await cls._freeze_warehouse(take)
        return await cls.get(take.id, user)

    @classmethod
    async def count_one(cls, item_id, body, user):
        """录入单条实盘"""
        db = await cls._db()
        item = await db.get(M14StocktakeItem, item_id)
        if item is None:
            raise BizError("55409", "盘点明细不存在")
        take = await cls._get_for_update(db, item.take_id)
        if take.status != "COUNTING":
            raise BizError("55406", "只有盘点中状态可以录入")

        qty = cls._parse_qty(body.actual_qty)
        if item.management_class in ("NARCOTIC", "PSYCHOTROPIC"):
            await cls._require_second_checker(db, item, body, user)

        item.actual_qty = qty
        item.diff_qty = qty - item.book_qty
        item.diff_type = cls._diff_type(item.diff_qty)
        item.diff_amount = money(item.diff_qty * item.unit_cost)
        item.count_status = "COUNTED"
        item.counted_by = user.id
        item.counted_by_name = user.name
        item.counted_at = datetime.now()
        item.remark = body.remark

        take.counted_count = await cls._count_counted(db, take.id)
        await cls._touch_freeze(take)
        await db.commit()
        return cls._item_dict(item)

    @classmethod
    async def submit(cls, take_id, body, user):
        """提交审批"""
        db = await cls._db()
        take = await cls._get_for_update(db, take_id)
        if take.status != "COUNTING":
            raise BizError("55406", "只有盘点中状态可以提交审批")

        unchecked = take.total_count - take.counted_count
        if unchecked > 0 and not body.confirm_unchecked:
            raise BizError(
                "55406",
                "还有 %d 个批次未录入，请确认后再提交" % unchecked)

        stats = await cls._calc_stats(db, take.id)
        level = cls._resolve_level(stats, take.id, db)
        quality_required = await cls._need_quality_sign(
            db, take.id, stats)

        take.match_count = stats["match"]
        take.profit_count = stats["profit"]
        take.loss_count = stats["loss"]
        take.profit_amount = stats["profit_amount"]
        take.loss_amount = stats["loss_amount"]
        take.diff_amount = stats["diff_amount"]
        take.diff_rate = stats["diff_rate"]
        take.diff_level = level
        take.quality_required = quality_required
        take.status = "SUBMITTED"
        take.submitted_at = datetime.now()

        chain = list(APPROVAL_CHAIN[level])
        if quality_required and "QUALITY" not in chain:
            chain.append("QUALITY")
        for idx, role in enumerate(chain, start=1):
            db.add(M14StocktakeApproval(
                take_id=take.id, step_no=idx, role_code=role,
                role_name=ROLE_NAME[role],
                status="PENDING" if idx == 1 else "WAITING",
                deadline_at=datetime.now() + timedelta(hours=48),
            ))
        take.total_steps = len(chain)

        await cls._log(db, take, "SUBMIT", user,
                       "差异级别 %s" % level)
        await db.commit()
        return await cls.get(take.id, user)

    @classmethod
    def _resolve_level(cls, stats, take_id, db):
        """差异分级"""
        amount = abs(stats["diff_amount"])
        level = TOP_LEVEL
        for bound, name in LEVEL_TIERS:
            if amount <= bound:
                level = name
                break
        if level == TOP_LEVEL and amount <= Decimal("50000"):
            level = "LARGE"

        raise_cnt = max(
            CATEGORY_RAISE.get(c, 0)
            for c in stats["raise_classes"]) if stats["raise_classes"] \
            else 0
        if raise_cnt:
            idx = min(LEVEL_ORDER.index(level) + raise_cnt,
                      len(LEVEL_ORDER) - 1)
            level = LEVEL_ORDER[idx]

        if stats["diff_rate"] > cls.RATE_ESCALATE:
            idx = min(LEVEL_ORDER.index(level) + 1,
                      len(LEVEL_ORDER) - 1)
            level = LEVEL_ORDER[idx]
        return level

    # ---- 冻结 ----

    @classmethod
    async def _freeze_warehouse(cls, take):
        """写仓库级冻结标记"""
        key = "m14:stocktake:freeze:wh:%d" % take.warehouse_id
        val = json.dumps({
            "take_id": take.id,
            "take_no": take.take_no,
            "warehouse_id": take.warehouse_id,
            "scope": "WAREHOUSE",
            "expire_at": (datetime.now()
                          + timedelta(hours=cls.FREEZE_HOURS)
                          ).isoformat(),
        }, ensure_ascii=False)
        ok = await RedisClient.set(key, val,
                                   ex=cls.FREEZE_HOURS * 3600)
        if not ok:
            raise BizError("55413", "冻结服务不可用，请稍后重试")

    @classmethod
    async def _freeze_drugs(cls, take, drug_ids):
        """写药品级冻结标记"""
        pipe = RedisClient.pipeline()
        for drug_id in drug_ids:
            key = "m14:stocktake:freeze:drug:%d:%d" % (
                take.warehouse_id, drug_id)
            pipe.set(key, take.take_no,
                     ex=cls.FREEZE_HOURS * 3600)
        await pipe.execute()

    @classmethod
    async def _touch_freeze(cls, take):
        """录入动作续期冻结（每次续 2 小时）"""
        if take.freeze_mode != "WAREHOUSE":
            return
        key = "m14:stocktake:freeze:wh:%d" % take.warehouse_id
        await RedisClient.expire(key, cls.FREEZE_RENEW_HOURS * 3600)

    @classmethod
    async def _unfreeze(cls, take):
        """解除冻结"""
        key = "m14:stocktake:freeze:wh:%d" % take.warehouse_id
        await RedisClient.delete(key)

    # ---- 审批 ----

    @classmethod
    async def approve(cls, take_id, body, user):
        """审批通过"""
        db = await cls._db()
        take = await cls._get_for_update(db, take_id)
        if take.status != "SUBMITTED":
            raise BizError("55406", "只有待审批状态可以审批")
        await cls._assert_not_participant(db, take, user)

        step = await cls._current_step(db, take.id)
        if step is None:
            raise BizError("55406", "审批链已结束")
        if step.role_code not in user.role_codes:
            raise BizError("55414", "当前节点需要 %s 审批"
                           % step.role_name)

        step.status = "APPROVED"
        step.approver_id = user.id
        step.approver_name = user.name
        step.comment = body.comment
        step.approved_at = datetime.now()

        nxt = await cls._next_step(db, take.id, step.step_no)
        if nxt is None:
            take.status = "APPROVED"
            take.approved_at = datetime.now()
        else:
            nxt.status = "PENDING"
            nxt.deadline_at = datetime.now() + timedelta(hours=48)

        await cls._log(db, take, "APPROVE", user, body.comment)
        await db.commit()
        return await cls.get_approval(take.id, user)

    @classmethod
    async def reject(cls, take_id, body, user):
        """审批驳回"""
        db = await cls._db()
        take = await cls._get_for_update(db, take_id)
        if take.status != "SUBMITTED":
            raise BizError("55406", "只有待审批状态可以驳回")
        if not body.reason or len(body.reason.strip()) < 10:
            raise BizError("55417", "驳回原因不少于 10 个字")

        step = await cls._current_step(db, take.id)
        step.status = "REJECTED"
        step.approver_id = user.id
        step.approver_name = user.name
        step.comment = body.reason
        step.approved_at = datetime.now()

        take.status = "COUNTING"
        take.reject_reason = body.reason
        await cls._log(db, take, "REJECT", user, body.reason)
        await db.commit()
        return await cls.get_approval(take.id, user)

    # ---- 调整 ----

    @classmethod
    async def adjust(cls, take_id, body, user):
        """生成并执行调整单"""
        db = await cls._db()
        take = await cls._get_for_update(db, take_id)
        if take.status not in ("APPROVED", "EXEC_FAIL"):
            raise BizError("55406", "只有已审批状态可以执行调整")
        if take.status == "APPROVED":
            exists = await cls._has_adjust(db, take.id)
            if exists:
                raise BizError("55421", "差异已执行，不可重复调整")

        items = await cls._diff_items(db, take.id)
        success = 0
        failed = 0
        txn_ids = []
        profit_qty = Decimal("0")
        loss_qty = Decimal("0")

        for item in items:
            cur = await M14StockClient.get_batch(item.batch_id)
            if cur is None:
                failed += 1
                await cls._save_adjust(
                    db, take, item, "FAILED", "批次不存在")
                continue
            system_qty = Decimal(str(cur.get("qty_on_hand") or 0))
            if abs(system_qty - item.book_qty) > QTY_EPS:
                failed += 1
                await cls._save_adjust(
                    db, take, item, "FAILED",
                    "账面数量已从 %s 变为 %s"
                    % (item.book_qty, system_qty))
                continue
            if item.diff_type == "LOSS" and system_qty < abs(
                    item.diff_qty):
                failed += 1
                await cls._save_adjust(
                    db, take, item, "FAILED", "库存不足")
                continue

            txn_type = ("STOCKTAKE_IN"
                        if item.diff_type == "PROFIT"
                        else "STOCKTAKE_OUT")
            payload = {
                "warehouse_id": take.warehouse_id,
                "batch_id": item.batch_id,
                "drug_id": item.drug_id,
                "txn_type": txn_type,
                "direction": "IN" if txn_type == "STOCKTAKE_IN"
                             else "OUT",
                "qty": abs(item.diff_qty),
                "biz_no": take.take_no,
                "biz_type": "STOCKTAKE",
                "idem_key": "STOCKTAKE:%s:%d"
                            % (take.take_no, item.batch_id),
                "operator_id": user.id,
                "remark": "盘点调整",
            }
            try:
                res = await M14StockClient.apply_stock(payload)
                txn_ids.append(res["txn_id"])
                success += 1
                await cls._save_adjust(
                    db, take, item, "SUCCESS", None,
                    res["txn_id"])
            except BizError as exc:
                failed += 1
                await cls._save_adjust(
                    db, take, item, "FAILED", str(exc))

            if item.diff_type == "PROFIT":
                profit_qty += item.diff_qty
            else:
                loss_qty += abs(item.diff_qty)

        take.adjust_success_count = success
        take.adjust_fail_count = failed
        if failed == 0:
            take.status = "CLOSED"
            take.closed_at = datetime.now()
            await cls._unfreeze(take)
        else:
            take.status = "EXEC_FAIL"
            await cls._unfreeze(take)
            await cls._alert(db, take, failed)

        await cls._log(db, take, "ADJUST", user,
                       "成功 %d 失败 %d" % (success, failed))
        await db.commit()

        return {
            "take_no": take.take_no,
            "status": take.status,
            "adjust_count": len(items),
            "profit_qty": profit_qty,
            "loss_qty": loss_qty,
            "success_count": success,
            "fail_count": failed,
            "stock_txn_ids": txn_ids,
            "unfrozen": take.status in ("CLOSED", "EXEC_FAIL"),
        }

    # ---- 报告 ----

    @classmethod
    async def report(cls, warehouse_id, start_date, end_date, user):
        """盘点报告"""
        db = await cls._db()
        d1 = date.fromisoformat(start_date)
        d2 = date.fromisoformat(end_date)
        if (d2 - d1).days > cls.MAX_REPORT_DAYS:
            raise BizError("55404", "查询时间跨度不能超过 %d 天"
                           % cls.MAX_REPORT_DAYS)

        rows = await cls._report_rows(db, warehouse_id, d1, d2)
        by_wh = await cls._report_by_warehouse(db, warehouse_id, d1, d2)
        by_reason = await cls._report_by_reason(db, d1, d2)

        return {
            "take_count": rows["take_count"],

            "match_rate": rows["match_rate"],
            "diff_rate": rows["diff_rate"],
            "profit_amount": rows["profit_amount"],
            "loss_amount": rows["loss_amount"],

    # ---- 工具 ----

    @classmethod
    def _diff_type(cls, diff_qty):
        if abs(diff_qty) <= QTY_EPS:
            return "MATCH"
        return "PROFIT" if diff_qty > 0 else "LOSS"

    @classmethod
    def _parse_qty(cls, raw):
        try:
            qty = Decimal(str(raw))
        except Exception:
            raise BizError("55410", "实盘数量格式不正确")
        if qty < 0:
            raise BizError("55410", "实盘数量不能为负")
        if -qty.as_tuple().exponent > 4:
            raise BizError("55410", "实盘数量最多 4 位小数")
        return qty

    @classmethod
    async def _check_no_running(cls, db, warehouse_id):
        stmt = select(func.count()).select_from(M14Stocktake).where(
            M14Stocktake.warehouse_id == warehouse_id,
            M14Stocktake.status.in_(
                ["GENERATED", "COUNTING", "SUBMITTED"]),
            M14Stocktake.is_deleted.is_(False),
        )
        cnt = (await db.execute(stmt)).scalar()
        if cnt:
            raise BizError("55411", "该仓库已存在进行中的盘点")

    @classmethod
    async def _check_plan_date(cls, plan_date):
        if plan_date < date.today():
            raise BizError("55403", "计划盘点日不能早于今天")

    @classmethod
    async def _next_take_no(cls, db):
        day = datetime.now().strftime("%Y%m%d")
        stmt = select(func.count()).select_from(M14Stocktake).where(
            M14Stocktake.take_no.like("PD" + day + "%"))
        seq = (await db.execute(stmt)).scalar() + 1
        return "PD%s%03d" % (day, seq)

    @classmethod
    async def _calc_stats(cls, db, take_id):
        rows = (await db.execute(
            select(M14StocktakeItem)
            .where(M14StocktakeItem.take_id == take_id))).scalars().all()
        match = profit = loss = 0
        profit_amt = loss_amt = Decimal("0")
        book_amt = Decimal("0")
        raise_classes = set()
        for it in rows:
            book_amt += money(it.book_qty * it.unit_cost)
            if it.diff_type == "MATCH":
                match += 1
            elif it.diff_type == "PROFIT":
                profit += 1
                profit_amt += it.diff_amount or Decimal("0")
                if it.management_class:
                    raise_classes.add(it.management_class)
            elif it.diff_type == "LOSS":
                loss += 1
                loss_amt += abs(it.diff_amount or Decimal("0"))
                if it.management_class:
                    raise_classes.add(it.management_class)
            if it.is_cold_chain:
                raise_classes.add("COLD_CHAIN")
        diff_amt = profit_amt + loss_amt
        rate = (diff_amt / book_amt) if book_amt > 0 else Decimal("0")
        return {
            "match": match, "profit": profit, "loss": loss,
            "profit_amount": money(profit_amt),
            "loss_amount": money(loss_amt),
            "diff_amount": money(diff_amt),
            "diff_rate": rate,
            "book_amount": money(book_amt),
            "raise_classes": raise_classes,
        }

    @classmethod
    async def _need_quality_sign(cls, db, take_id, stats):
        cls_list = stats["raise_classes"] & {
            "NARCOTIC", "PSYCHOTROPIC", "TOXIC", "COLD_CHAIN"}
        return bool(cls_list)

    @classmethod
    async def _log(cls, db, take, action, user, detail):
        db.add(M14StocktakeLog(
            take_id=take.id, take_no=take.take_no,
            action=action, detail=detail,
            operator_id=getattr(user, "id", None),
            operator_name=getattr(user, "name", None),
        ))

    @classmethod
    async def _get_for_update(cls, db, take_id):
        stmt = select(M14Stocktake).where(
            M14Stocktake.id == take_id).with_for_update()
        take = (await db.execute(stmt)).scalar_one_or_none()
        if take is None:
            raise BizError("55406", "盘点单不存在")
        return take
```

### 6.6 循环盘点自动生成实现

```python
from datetime import datetime

from sqlalchemy import select

from app.models.m14 import M14StocktakeCycleRule


class CycleStocktakeRunner:
    """循环盘点自动生成器（Celery 调用）"""

    @classmethod
    async def run_all(cls):
        """按规则批量生成循环盘点单"""
        db = await StocktakeService._db()
        now = datetime.now()
        stmt = select(M14StocktakeCycleRule).where(
            M14StocktakeCycleRule.status == "ENABLED",
            M14StocktakeCycleRule.is_deleted.is_(False),
        )
        rules = (await db.execute(stmt)).scalars().all()
        created = []
        for rule in rules:
            if not cls._hit_time(rule, now):
                continue
            if not cls._hit_frequency(rule, now):
                continue
            ids = await cls._select_targets(db, rule)
            if not ids:
                continue
            take = await StocktakeService.create(
                cls._build_body(rule, ids),
                cls._system_user())
            created.append(take["take_no"])
        return created

    @classmethod
    def _hit_time(cls, rule, now):
        return (now.hour == rule.run_hour
                and now.minute < 30)

    @classmethod
    def _hit_frequency(cls, rule, now):
        if rule.frequency == "DAILY":
            return True
        if rule.frequency == "WEEKLY":
            return now.weekday() == rule.run_weekday
        if rule.frequency == "MONTHLY":
            return now.day == rule.run_day
        return False

    @classmethod
    async def _select_targets(cls, db, rule):
        """按分类方式选取本轮要盘的药品"""
        if rule.cycle_type == "NARCOTIC":
            return await cls._select_by_class(db, rule, "NARCOTIC")
        if rule.cycle_type == "HIGH_VALUE":
            return await cls._select_by_class(db, rule, "HIGH_VALUE")
        if rule.cycle_type == "ABC":
            return await cls._select_by_abc(db, rule)
        if rule.cycle_type == "SLOW_MOVING":
            return await cls._select_slow_moving(db, rule)
        return await cls._select_random(db, rule)
```
