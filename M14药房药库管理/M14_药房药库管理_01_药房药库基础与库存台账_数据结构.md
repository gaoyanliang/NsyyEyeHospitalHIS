```
┌──────────────────────────────────────────────────────────────────────────┐

│           ▼                              ▼                               │

│  │  m14_stock_batch   ★ 数量唯一真相                     │                │

│  │ ★ 只增不改        │   │ 日快照，月分区        │                        │
│  │ 月分区            │   └──────────────────────┘                        │
│  │ reverse_of_txn_id │                                                   │
│  └───┬───────────────┘                                                   │
│      │                                                                   │
│      ▼                                                                   │
│  ┌──────────────────────────┐                                            │
│  │ m14_stock_reconcile_log  │  L1 对账结果（流水 vs 结存）               │
│  └──────────────────────────┘                                            │
└──────────────────────────────────────────────────────────────────────────┘
```

**设计说明**

| 决策 | 内容 | 理由 |
|---|---|---|
| 无物理外键 | 全部引用为逻辑引用 | 与 M16 一致；HIS 数据迁移与修复成本优先 |
| 名称快照 | `m14_stock_batch` 冗余 `drug_code`/`drug_name`/`specification`/`package_unit` | 药品改名后历史批次仍显示当时的名称 |
| 生成列 | `qty_available` 为 `GENERATED ALWAYS AS` | 三数量恒等式由数据库强制，不靠应用层自觉 |
| 只增表 | `m14_stock_txn` / `m14_stock_snapshot` / `m14_stock_reconcile_log` | 触发器禁止 UPDATE/DELETE，保证可审计 |
| 批号四元组唯一 | `(warehouse_id, drug_id, batch_no, expiry_date)` | 见详细设计 3.3.1，宁可多一行不可无法入库 |

### 4.2 表：`m14_warehouse`（仓库定义表）

**表说明：** 定义全院药事仓库。仓库是独立盘点、独立核算、独立权限的最小库存单元。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | 自增 | 主键 |
| warehouse_code | VARCHAR(32) | N | — | 仓库编码，如 `WH01`，全局唯一 |
| warehouse_name | VARCHAR(64) | N | — | 仓库名称 |
| warehouse_type | VARCHAR(32) | N | — | 类型：CENTER / OUTPATIENT / INPATIENT / EMERGENCY / OPERATING / WARD / QUARANTINE / VIRTUAL |
| is_accounting | BOOLEAN | N | FALSE | 是否参与成本核算 |
| is_dispense | BOOLEAN | N | FALSE | 是否可对外发药 |
| is_central | BOOLEAN | N | FALSE | 是否为全院唯一中心药库 |
| parent_id | BIGINT | Y | NULL | 上级仓库（病区药柜挂靠的住院药房） |
| dept_id | BIGINT | Y | NULL | 归属科室（M01-01） |
| dept_name | VARCHAR(64) | Y | NULL | 科室名称快照 |
| address | VARCHAR(128) | Y | NULL | 物理位置 |
| manager_id | BIGINT | Y | NULL | 负责人（M01-02 职工） |
| manager_name | VARCHAR(64) | Y | NULL | 负责人姓名快照 |
| phone | VARCHAR(32) | Y | NULL | 联系电话 |
| work_time | VARCHAR(64) | Y | NULL | 工作时间描述，如 `08:00-21:00` |
| is_24h | BOOLEAN | N | FALSE | 是否 24 小时 |
| sort_no | INTEGER | N | 0 | 列表排序 |
| status | VARCHAR(16) | N | 'DRAFT' | 状态：DRAFT / ENABLED / DISABLED / CLOSED |
| enabled_at | TIMESTAMP | Y | NULL | 启用时间 |
| disabled_at | TIMESTAMP | Y | NULL | 停用时间 |
| closed_at | TIMESTAMP | Y | NULL | 关闭时间 |
| close_reason | VARCHAR(255) | Y | NULL | 关闭原因 |
| remark | VARCHAR(512) | Y | NULL | 备注 |
| version | INTEGER | N | 0 | 乐观锁版本号 |
| created_by | BIGINT | N | — | 创建人 |
| created_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 更新时间（触发器维护） |
| is_deleted | BOOLEAN | N | FALSE | 逻辑删除 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m14_warehouse | PRIMARY | id | 主键 |
| uk_m14_warehouse_code | UNIQUE | warehouse_code WHERE is_deleted = FALSE | 编码唯一 |
| idx_m14_warehouse_type | NORMAL | warehouse_type, status | 按类型查 |
| idx_m14_warehouse_parent | NORMAL | parent_id | 查下级药柜 |
| idx_m14_warehouse_dept | NORMAL | dept_id | 按科室查 |
| uk_m14_warehouse_central | UNIQUE | is_central WHERE is_central = TRUE AND is_deleted = FALSE | **全院只能有一个中心药库** |

**约束说明**

```sql
ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_code
    CHECK (warehouse_code ~ '^[A-Z0-9]{2,32}$');

ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_type
    CHECK (warehouse_type IN (
        'CENTER', 'OUTPATIENT', 'INPATIENT', 'EMERGENCY',
        'OPERATING', 'WARD', 'QUARANTINE', 'VIRTUAL'));

ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_status
    CHECK (status IN ('DRAFT', 'ENABLED', 'DISABLED', 'CLOSED'));

-- 中心药库、虚拟库、待检区不可对外发药
ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_dispense
    CHECK (is_dispense = FALSE
           OR warehouse_type NOT IN ('CENTER', 'VIRTUAL', 'QUARANTINE'));

-- 只有 CENTER 类型可置 is_central
ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_central
    CHECK (is_central = FALSE OR warehouse_type = 'CENTER');

-- 关闭必须有原因
ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_closed
    CHECK (status <> 'CLOSED'
           OR (closed_at IS NOT NULL AND close_reason IS NOT NULL));

-- 病区药柜必须有上级仓库
ALTER TABLE m14_warehouse
    ADD CONSTRAINT ck_m14_warehouse_ward
    CHECK (warehouse_type <> 'WARD' OR parent_id IS NOT NULL);
```

**状态机**

```
  ┌─────────┐   启用   ┌──────────┐   停用   ┌───────────┐
  │ DRAFT   │────────►│ ENABLED  │────────►│ DISABLED  │
  └─────────┘         └────┬─────┘◄────────└───────────┘
                           │       重新启用
                           │ 关闭（库存为 0）
                           ▼
                      ┌─────────┐
                      │ CLOSED  │  终态
                      └─────────┘
```

| 年增长 | 0~2 |
| 单行大小 | 约 500 B |

### 4.3 表：`m14_location`（库位定义表）

**表说明：** 定义仓库内的存储区域。库位绑定了温控要求与药品类型约束，是冷藏与麻精药品管理的物理基础。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | 自增 | 主键 |
| warehouse_id | BIGINT | N | — | 所属仓库 |
| warehouse_code | VARCHAR(32) | N | — | 仓库编码快照 |
| location_code | VARCHAR(32) | N | — | 库位编码，同仓库内唯一 |
| location_name | VARCHAR(64) | N | — | 库位名称 |
| storage_type | VARCHAR(32) | N | — | 存储类型：NORMAL / COOL / COLD / NARCOTIC_CABINET / TOXIC_CABINET / SPLIT / RETURN / REJECT / QUARANTINE |
| temp_min | NUMERIC(5,2) | Y | NULL | 温度下限（℃） |
| temp_max | NUMERIC(5,2) | Y | NULL | 温度上限（℃） |
| humidity_min | NUMERIC(5,2) | Y | NULL | 湿度下限（%） |
| humidity_max | NUMERIC(5,2) | Y | NULL | 湿度上限（%） |
| capacity | INTEGER | Y | NULL | 容量上限（盒/支） |
| is_locked | BOOLEAN | N | FALSE | 是否加锁管理（麻精柜必为 TRUE） |
| requires_double_sign | BOOLEAN | N | FALSE | 是否需双人签收 |
| shelf_codes | JSONB | Y | NULL | 货架位列表，如 `["A-01","A-02"]` |
| sort_no | INTEGER | N | 0 | 排序 |
| status | VARCHAR(16) | N | 'ENABLED' | 状态：ENABLED / DISABLED / CLOSED |
| remark | VARCHAR(512) | Y | NULL | 备注 |
| created_by | BIGINT | N | — | 创建人 |
| created_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 逻辑删除 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m14_location | PRIMARY | id | 主键 |
| uk_m14_location_code | UNIQUE | warehouse_id, location_code WHERE is_deleted = FALSE | 同仓库内编码唯一 |
| idx_m14_location_wh | NORMAL | warehouse_id, status | 按仓库查库位 |
| idx_m14_location_type | NORMAL | storage_type | 按存储类型查（找冷藏柜） |

**约束说明**

```sql
ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_code
    CHECK (location_code ~ '^[A-Z0-9-]{2,32}$');

ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_type
    CHECK (storage_type IN (
        'NORMAL', 'COOL', 'COLD', 'NARCOTIC_CABINET',
        'TOXIC_CABINET', 'SPLIT', 'RETURN', 'REJECT',
        'QUARANTINE'));

ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_status
    CHECK (status IN ('ENABLED', 'DISABLED', 'CLOSED'));

-- 冷链库位必须填温控上下限
ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_temp
    CHECK (storage_type NOT IN ('COLD', 'COOL')
           OR (temp_min IS NOT NULL AND temp_max IS NOT NULL
               AND temp_min < temp_max));

-- 冷藏范围必须在 0~15℃
ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_cold_range
    CHECK (storage_type <> 'COLD'
           OR (temp_min >= 0 AND temp_max <= 15));

-- 麻精柜必须加锁且双人签收
ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_narcotic
    CHECK (storage_type NOT IN ('NARCOTIC_CABINET', 'TOXIC_CABINET')
           OR (is_locked = TRUE AND requires_double_sign = TRUE));

-- 容量必须为正
ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_capacity
    CHECK (capacity IS NULL OR capacity > 0);

-- JSONB 类型校验
ALTER TABLE m14_location
    ADD CONSTRAINT ck_m14_location_shelf_json
    CHECK (shelf_codes IS NULL
           OR jsonb_typeof(shelf_codes) = 'array');
```

### 4.4 表：`m14_stock_batch`（批次库存台账表）

**表说明：** M14 最核心的表。每一行代表"某仓库的某药品某批号某效期的库存结存"。所有出入库最终都会更新这张表的数量。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |

| warehouse_id | BIGINT | N | — | 仓库 ID |
| warehouse_code | VARCHAR(32) | N | — | 仓库编码快照 |
| warehouse_name | VARCHAR(64) | N | — | 仓库名称快照 |
| location_id | BIGINT | Y | NULL | 库位 ID |
| location_code | VARCHAR(32) | Y | NULL | 库位编码快照 |
| drug_id | BIGINT | N | — | 药品 ID（M01-03） |
| drug_code | VARCHAR(32) | N | — | 药品编码快照 |
| drug_name | VARCHAR(128) | N | — | 药品名称快照 |
| drug_generic_name | VARCHAR(128) | Y | NULL | 通用名快照 |
| specification | VARCHAR(128) | N | — | 规格快照 |
| package_unit | VARCHAR(16) | N | — | 包装单位（盒/支/瓶） |
| min_unit | VARCHAR(16) | Y | NULL | 最小单位（片/ml） |
| conversion_ratio | NUMERIC(12,4) | Y | NULL | 转换比（1 包装 = N 最小单位） |
| batch_no | VARCHAR(64) | N | — | 批号 |
| production_date | DATE | Y | NULL | 生产日期 |
| expiry_date | DATE | N | — | 有效期至 |
| manufacturer | VARCHAR(128) | Y | NULL | 生产厂家快照 |

| supplier_id | BIGINT | Y | NULL | 首次入库供应商 |

| purchase_price | NUMERIC(12,4) | Y | NULL | 采购单价（商业敏感） |
| qty_on_hand | NUMERIC(14,4) | N | 0 | **在库数量** |

| opened_at | TIMESTAMP | Y | NULL | 开封时间 |
| opened_expiry_date | DATE | Y | NULL | 开封后到期日 |
| status | VARCHAR(16) | N | 'NORMAL' | 状态：NORMAL / NEAR_EXPIRY / EXPIRED / HOLD / REJECTED / RECALLED / DESTROYED |
| hold_reason | VARCHAR(255) | Y | NULL | 冻结原因 |
| hold_at | TIMESTAMP | Y | NULL | 冻结时间 |
| hold_by | BIGINT | Y | NULL | 冻结操作人 |
| hold_by_name | VARCHAR(64) | Y | NULL | 冻结操作人姓名 |
| first_in_at | TIMESTAMP | Y | NULL | 首次入库时间 |
| last_in_at | TIMESTAMP | Y | NULL | 最近入库时间 |
| last_out_at | TIMESTAMP | Y | NULL | 最近出库时间 |
| version | INTEGER | N | 0 | 乐观锁版本号（**并发控制核心**） |
| remark | VARCHAR(512) | Y | NULL | 备注 |
| created_by | BIGINT | N | — | 创建人 |
| created_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 逻辑删除 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m14_stock_batch | PRIMARY | id | 主键 |
| uk_m14_stock_batch_key | UNIQUE | warehouse_id, drug_id, batch_no, expiry_date WHERE is_deleted = FALSE | **批次四元组唯一** |

**生成列定义**

```sql
-- qty_available 为生成列，应用层不可写
ALTER TABLE m14_stock_batch
    ALTER COLUMN qty_available SET DEFAULT NULL;

ALTER TABLE m14_stock_batch
    DROP COLUMN IF EXISTS qty_available;

ALTER TABLE m14_stock_batch
    ADD COLUMN qty_available NUMERIC(14,4)
    GENERATED ALWAYS AS (qty_on_hand - qty_locked) STORED;

COMMENT ON COLUMN m14_stock_batch.qty_available IS
    '可用数量=在库-锁定，生成列由数据库强制';
```

**为什么用生成列而不是应用层计算**

如果 `qty_available` 是普通列，应用层三处代码（发药、调拨、盘点）都要记得同步更新它。任何一处漏了，就会出现"on_hand=100, locked=0, available=20"这种自相矛盾的数据，而数据库不会报错。

生成列把恒等式写进表结构，**从语法上就不可能不一致**。

**状态机**

```
     ┌────────────┐
     │  NORMAL    │◄─────────┐
     └──────┬─────┘          │ 解冻
            │ 进入预警期       │
            ▼                │
     ┌────────────┐     ┌────┴─────┐
     │ NEAR_EXPIRY│────►│   HOLD   │ 冻结
     └──────┬─────┘     └────┬─────┘
            │ 过期             │ 质检不合格
            ▼                ▼
     ┌────────────┐     ┌──────────┐
     │  EXPIRED   │     │ REJECTED │
     └──────┬─────┘     └────┬─────┘
            │ 销毁             │ 销毁
            ▼                ▼
        ┌──────────────────────┐
        │     DESTROYED        │  终态
        └──────────────────────┘

  旁支：NORMAL/NEAR_EXPIRY ──厂家召回──► RECALLED（可退厂）
```

**量级估算**

| 项 | 数值 |
|---|---|
| 批次总数（稳态） | 3,400 |
| 年新增批次 | 约 1,800 |
| 单行大小 | 约 1,200 B |
| 数据量/年 | 约 2 MB |
| 保留 | 永久（批次可追溯要求） |

**分区：** 不分区。理由是批次唯一约束需要跨年生效（同一批号可能跨年入库），分区会迫使唯一索引含分区键。

**只增触发器**

```sql
CREATE OR REPLACE FUNCTION trg_m14_stock_txn_immutable()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION 'm14_stock_txn 为不可变流水表，禁止删除';
    END IF;
    IF TG_OP = 'UPDATE' THEN
        -- 只允许改状态类字段与冲销引用，禁止改数量与业务标识
        IF NEW.qty <> OLD.qty
           OR NEW.direction <> OLD.direction
           OR NEW.txn_type <> OLD.txn_type
           OR NEW.batch_id IS DISTINCT FROM OLD.batch_id
           OR NEW.drug_id <> OLD.drug_id
           OR NEW.warehouse_id <> OLD.warehouse_id
           OR NEW.qty_before <> OLD.qty_before
           OR NEW.qty_after <> OLD.qty_after THEN
            RAISE EXCEPTION
                'm14_stock_txn 数量与业务标识不可修改，请使用冲销';
        END IF;
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_m14_stock_txn_immutable
    BEFORE UPDATE OR DELETE ON m14_stock_txn
    FOR EACH ROW
    EXECUTE FUNCTION trg_m14_stock_txn_immutable();
```

**为什么冲销不能删除原流水**

如果允许删除，`10:30 发药 -20` 这条一行删掉，账面就"从来没发过"。但患者手上拿着药，实物少了 20。

正确做法是新增一条 `REVERSE +20` 流水，两条记录并存。这样任何人都能看到"发过然后冲销了"，而不是"什么都没发生"。

**量级估算**

| 项 | 数值 |
|---|---|
| 日均流水 | 2,400 条（发药 1,400 + 入库 300 + 调拨 200 + 退药 100 + 其他 400） |
| 年流水 | 876,000 条 |
| 单行大小 | 约 700 B |
| 数据量/年 | 约 610 MB |
| 索引/年 | 约 180 MB |
| 保留（热数据） | 3 年（在线）；3 年以上转归档表 |

**分区：** 按 `created_at` 月度 RANGE 分区，预建 36 个月。

```sql
CREATE TABLE m14_stock_txn (
    ...
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
) PARTITION BY RANGE (created_at);

CREATE TABLE m14_stock_txn_2026_10
    PARTITION OF m14_stock_txn
    FOR VALUES FROM ('2026-10-01') TO ('2026-11-01');
```

**关于分区与唯一索引的权衡**

`uk_m14_stock_txn_idem` 是全局幂等键，加入分区键后会退化为"每月唯一"，可能跨月重复。

**折中方案：** 幂等键表中额外包含月份戳，由应用层在写入幂等键时拼接 `YYYYMM`：

```python
idem_key = "%s:%s" % (month_str, raw_key)
```

这样即使跨月，键本身不同，唯一索引仍然有效。同一幂等键跨月重复的概率极低（同一笔业务的重试窗口以分钟计），且月份戳保证了同一月内严格唯一。

| idx_m14_stock_reconcile_open | NORMAL | handled_status WHERE handled_status IN ('OPEN','INVESTIGATING') | 待处理差异 |

**约束说明**

```sql
ALTER TABLE m14_stock_reconcile_log
    ADD CONSTRAINT ck_m14_stock_reconcile_type
    CHECK (reconcile_type IN ('L1', 'L2'));

ALTER TABLE m14_stock_reconcile_log
    ADD CONSTRAINT ck_m14_stock_reconcile_result
    CHECK (result IN ('PASS', 'MISMATCH'));

ALTER TABLE m14_stock_reconcile_log
    ADD CONSTRAINT ck_m14_stock_reconcile_status
    CHECK (handled_status IN ('OPEN', 'INVESTIGATING',
                              'RESOLVED', 'IGNORED'));

-- 差异行必须有三项数量且差额自洽
ALTER TABLE m14_stock_reconcile_log
    ADD CONSTRAINT ck_m14_stock_reconcile_diff
    CHECK (result <> 'MISMATCH'
           OR (qty_book IS NOT NULL AND qty_ledger IS NOT NULL
               AND qty_diff = qty_book - qty_ledger
               AND qty_diff <> 0));

-- 通过行不得有差额
ALTER TABLE m14_stock_reconcile_log
    ADD CONSTRAINT ck_m14_stock_reconcile_pass
    CHECK (result <> 'PASS'
           OR qty_diff IS NULL OR qty_diff = 0);

-- 已处理必须有处理人与说明
ALTER TABLE m14_stock_reconcile_log
    ADD CONSTRAINT ck_m14_stock_reconcile_handled
    CHECK (handled_status IN ('OPEN', 'INVESTIGATING')
           OR (handled_by IS NOT NULL
               AND handled_at IS NOT NULL));
```

**为什么对账结果要持久化**

如果只打日志告警，第二天日志被轮转，就再也查不到"10 月 19 日出现过 2 个批次不平"。这两个批次是谁、差多少、后来怎么处理的——全都丢了。

持久化后，可以回答：`SELECT * FROM m14_stock_reconcile_log WHERE result='MISMATCH' ORDER BY reconcile_date DESC`，一目了然地看到历史问题及其闭环情况。

**量级估算**

| 项 | 数值 |
|---|---|
| 每天汇总行 | 1 行（全院汇总） |
| 每天差异行 | 0~5 行 |
| 年行数 | 约 550 行 |
| 保留 | 5 年 |

**分区：** 不分区。
