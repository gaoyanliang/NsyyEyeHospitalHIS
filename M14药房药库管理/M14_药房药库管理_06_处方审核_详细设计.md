## 1. 模块概述

### 1.1 模块定位

**一句话：** M14-06 是药师对处方进行**专业审查**并**签字背书**的地方 —— 它回答"这张处方能不能发药"。

```
┌──────────────────────────────────────────────────────────────────────┐
│                          处方从开具到发药的完整链路                     │
└──────────────────────────────────────────────────────────────────────┘

  医生                    M14-06                     M14-07
   │                        │                          │
   │ ① 开具处方              │                          │
   │   (M07-05)             │                          │
   ├───────────────────────►│                          │
   │                        │                          │
   │                        │ ② 进入审核队列             │
   │                        │   m07.rx.signed           │
   │                        │                          │
   │                        │ ③ 药师审查                │
   │                        │   合理性/相互作用/剂量/     │
   │                        │   配伍/诊断相符/用法       │
   │                        │                          │
   │                        │ ④ 审核结论                │
   │◄───────────────────────┤                          │
   │  on-reviewed           │                          │
   │  on-returned           │                          │
   │                        │                          │
   │ ⑤ 患者缴费 (M16)        │                          │
   │                        │                          │
   │                        ├─────────────────────────►│
   │                        │  ⑥ 通过 → 可调配           │
   │                        │     on-dispensed ◄────────┤
   └────────────────────────┴──────────────────────────┘
```

**核心职责：**

| 职责 | 说明 |
|---|---|
| 接收审核任务 | 订阅 `m07.rx.signed`，把新处方放入审核队列 |
| 自动审核 | 调用规则引擎做机器初审（剂量、相互作用、重复用药、适应证） |
| 人工审核 | 药师逐项确认，可整单通过或逐条通过 |
| 审核结论 | 通过 / 退回医生修改 / 拒绝调配 / 有条件通过（嘱患者） |
| 回写医生站 | 通过或退回结果实时回写 M07-05 |
| 审核留痕 | 每次审核的药师、时间、判定项、意见全部留档（GSP 要求保存 2 年） |

### 1.2 为什么处方审核要独立成子模块

**第一，它是法定职责，不是流程节点。**

《医疗机构处方审核规范》（国卫办医发〔2018〕14 号）第十二条明确：

> 药师是处方审核工作的第一责任人。所有处方均应当经审核通过后方可进入调配环节。

这意味着：

- 处方**必须有**药师签字才能调配，没有签字的处方发药是违规行为
- 药师签字是**个人责任**，不是系统行为
- 审核不通过的处方**不能**调配

如果把它做成发药页面上的一个"审核"按钮，会有三个问题：

1. 忙的时候药师可能不点就发了（技术上拦不住）
2. 审核记录混在发药记录里，药监检查时拿不出独立的审核台账
3. 药师责任无法追溯（哪个药师审的哪张处方，查不清）

**第二，审核和调配的输入输出完全不同。**

| 维度 | 审核（M14-06） | 调配（M14-07） |
|---|---|---|
| 输入 | 处方内容（药名、剂量、用法、诊断） | 已审核通过的处方 |
| 处理 | 知识判断（合理性分析） | 物理操作（取药、核对、贴标签） |
| 输出 | 审核结论（通过/退回） | 实物药品 + 发药记录 |
| 人员 | 药师 | 药师或药士 |
| 耗时长 | 30 秒~3 分钟 | 1~3 分钟 |
| 出错后果 | 用药安全事故 | 发错药（也是事故但性质不同） |
| 法规 | GSP 处方审核规范 | GSP 调配规范 |

合并成一个页面会导致药师"边审边调"，注意力分散在知识判断和取药扫描之间，两边都容易出错。

**第三，眼科有特殊的审核复杂度。**

普通综合医院药房审核主要看"剂量、相互作用、重复用药"。眼科不一样：

| 眼科特有风险 | 说明 | 审核要点 |
|---|---|---|
| 滴眼液含激素 | 长期用致青光眼、白内障 | 使用时长 > 2 周必须提示 |
| 复方制剂混用 | 两种滴眼液都含防腐剂 | 同时使用 > 4 次/日需提示 |
| 眼别错误 | 左眼药点右眼 | 处方必须标眼别，审核需核对 |
| 散瞳药禁忌 | 前房浅患者散瞳致急性闭角型青光眼 | 需核对诊断 |
| 角膜接触镜配戴 | 含防腐剂滴眼液损伤镜片 | 需提示摘镜 |
| 儿童用眼药 | 阿托品浓度需按年龄 | 需核对年龄与浓度 |

这些规则的判断逻辑比"查药品相互作用表"复杂得多，值得独立设计。

**第四，退回的处方需要独立的处理流程。**

处方被退回后：

- 医生要收到通知（M03-05 消息）
- 处方状态要改（M07-05 的处方回到 `RETURNED`）
- 患者要知道"医生还没改好"（叫号屏或窗口提示）
- 如果医生不在，处方可能被挂起很久

这一整套状态流转放进调配模块会让调配模块的状态机变得极其复杂。

### 1.3 与相邻子模块的分工

| 能力 | 归属 | 说明 |
|---|---|---|
| 处方开具、签名、作废 | **M07-05** | 医生的工作 |
| 处方保存与版本 | **M07-05** | M07 管处方主档 |
| **处方合理性审核** | **M14-06** ✅ | 唯一责任 |
| **审核结论与留痕** | **M14-06** ✅ | 唯一责任 |
| 药品知识库（相互作用、剂量上限） | **M01-03 / M18** | M14-06 只消费 |
| 药房库存与批次 | **M14-01** | — |
| 按批次调配、发药、退药 | **M14-07** | — |
| 处方收费 | **M16** | 审核通过与收费无先后强约束 |
| 住院用药审核 | **M14-08** | 住院是长期医嘱，审核模式不同 |

**边界要点：** M14-06 **不创作**任何药品知识 —— 所有"这个剂量超上限""这两个药有相互作用"的判断，规则全部来自 M01-03 药品主数据或 M18 知识库。M14-06 只负责**执行**与**留痕**。

### 1.4 概念辨析

#### 1.4.1 审核 vs 复核

| 概念 | 定义 | 谁做 | 依据 |
|---|---|---|---|
| **审核** | 审查处方的**合理性**（该不该开、开得对不对） | 药师（专业判断） | 处方内容 + 诊断 + 患者信息 |
| **复核** | 核对调配出的药品**是否与处方一致**（发出的对不对） | 第二人或同一人二次 | 处方 vs 实物 |

审核解决"该不该发"，复核解决"发得对不对"。M14-06 只做审核，复核在 M14-07。

#### 1.4.2 处方审核 vs 医嘱审核

| 概念 | 场景 | 审核对象 | 时间特征 |
|---|---|---|---|
| **门诊处方审核** | 门诊 | 一次开具的若干药 | 即时，几秒到几分钟 |
| **住院医嘱审核** | 住院 | 长期医嘱（每日重复） | 一次性审核，后续按变动重新审核 |

M14-06 主语是**门诊处方**。住院医嘱审核由 M14-08 负责，虽然规则引擎是同一套，但流程不同（住院有"抽查审核"制度）。

#### 1.4.3 审核不通过 vs 拒审

| 概念 | 场景 | 处方状态 | 后续 |
|---|---|---|---|
| **审核不通过**（退回） | 处方有可修正的问题（剂量大、缺诊断） | 回到医生处修改 | 医生改完可重新送审 |
| **拒审** | 处方有不可通过的问题（药品已停用、超执业范围） | 处方作废 | 医生需重新开具 |

区别在于"能否在同一张处方上修改后重审"。退回是 true，拒审是 false。

#### 1.4.4 自动审核 vs 人工审核

| 维度 | 自动审核（机器） | 人工审核（药师） |
|---|---|---|
| 覆盖 | 100% 处方 | 100% 处方（法定要求） |
| 判断依据 | 规则引擎（硬编码规则） | 药师专业知识 |
| 能发现 | 剂量超限、相互作用、重复用药、禁忌证 | 适应证不符、用法不当、眼科特殊风险 |
| 不能发现 | 诊断与用药不符（需要理解病情） | — |
| 耗时 | < 50ms | 30 秒~3 分钟 |
| 结论 | 只给"提示"与"警告"，不给最终结论 | 给出最终结论 |

**两者是串联的：** 自动审核先跑，结果作为药师审核时的参考（减少药师翻查资料的负担）。**最终结论永远由人工给出**，这是法规要求。

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 审核覆盖率 | 100% | 所有处方必须经审核 |
| 自动审核耗时 | P95 ≤ 50ms | 不阻塞药师工作 |
| 人工审核平均耗时 | ≤ 90 秒/张 | 眼科处方药品种类少 |
| 审核队列等待 | P95 ≤ 5 分钟 | 从进入队列到开始审核 |
| 退回率 | 3%~8% | 过低说明审核草率，过高说明医生开方质量差 |
| 严重问题拦截率 | 100% | 禁忌、超量、相互作用必须拦截 |
| 回写医生站延迟 | P95 ≤ 100ms | 医生能尽快看到结果 |

### 1.6 关键业务角色

| 角色 | 职责 | 关键权限 |
|---|---|---|
| **审方药师** | 逐张审核处方、给出结论 | `m14:rx-review:review` |
| **审方药师组长** | 处理疑难处方、复核药师结论 | `m14:rx-review:senior` |

## 3. 业务模型

### 3.1 审核任务模型

**审核任务**是 M14-06 的核心对象 —— 一张处方对应一个审核任务。

```
┌────────────────────────────────────────────────────────────────┐
│                        审核任务（RxReview）                     │
├────────────────────────────────────────────────────────────────┤
│  基本信息                                                       │
│    review_id          审核任务 ID                               │
│    review_no          审核单号  YS + YYYYMMDD + 5位             │
│    rx_id              处方 ID（来自 M07-05）                    │
│    rx_no              处方号                                    │
│    encounter_id       就诊 ID                                   │
│    patient_id         患者 ID                                   │
│    patient_name       患者姓名                                  │
│    patient_age        患者年龄                                  │
│    patient_sex        患者性别                                  │
│    dept_id            开方科室                                  │
│    doctor_id          开方医生                                  │
│                                                                │
│  审核状态                                                       │
│    status             状态                                      │
│    priority           优先级                                    │
│    queue_at           入队时间                                  │
│    started_at         开始审核时间                              │
│    reviewed_at        审核完成时间                              │
│    reviewer_id        审核药师                                  │

```

### 3.2 审核状态机

```
                        ┌──────────┐
                        │ PENDING  │ 待审核（已入队）
                        └────┬─────┘
                             │ 药师点击"开始审核"
                             ▼
                        ┌──────────┐
                    ┌──►│ REVIEWING│ 审核中（已锁定）
                    │   └────┬─────┘
                    │        │
                    │        ├──► PASSED      通过
                    │        ├──► RETURNED    退回医生修改
                    │        ├──► REJECTED    拒审（作废）
                    │        ├──► CONDITIONAL 有条件通过（嘱患者）
                    │        └──► CONSULTING  疑难会诊中
                    │                        │
                    │                        │ 会诊结束
                    │                        └──► REVIEWING
                    │
                    └─── 退回后医生已修改并重新送审（新审核任务）
```

| 状态 | 名称 | 终态 | 说明 |
|---|---|---|---|
| `PENDING` | 待审核 | 否 | 已入队等待药师处理 |
| `REVIEWING` | 审核中 | 否 | 药师已锁定，其他人看不到 |
| `CONSULTING` | 会诊中 | 否 | 提请临床药师协助 |
| `PASSED` | 审核通过 | **是** | 可调配 |
| `RETURNED` | 退回修改 | **是** | 医生修改后重新送审（生成新任务） |
| `REJECTED` | 拒审 | **是** | 处方作废，需重新开具 |
| `CONDITIONAL` | 有条件通过 | **是** | 可调配，但需向患者交代注意事项 |
| `TIMEOUT` | 超时 | 否 | 超过 30 分钟未审核，自动升级 |

**为什么 `RETURNED` 是终态而不是回到 `PENDING`？**

医生修改后的处方是**另一个版本的处方**（M07-05 会给它新的版本号）。如果把同一个审核任务改回 `PENDING`：

- 审核台账里看不到"这张处方被退回过几次"
- 复查时无法区分"第一次审核的药师"和"第二次审核的药师"
- 药监检查问"这张处方审了几次"，答不上来

所以退回即终结。医生改完重新签名 → 发新的 `m07.rx.signed` → 生成新的审核任务。台账里就能看到完整链条：

```
审核单号        处方版本   结论      药师      时间
YS2026102100001  V1        RETURNED  李药师    10:20
YS2026102100002  V2        PASSED    李药师    10:26
```

### 3.3 审核优先级模型

| 优先级 | 代码 | 触发条件 | 目标响应时间 |
|---|---|---|---|
| 特急 | `URGENT` | 急诊科处方 / 含抢救药 | ≤ 2 分钟 |
| 加急 | `HIGH` | 60 岁以上 / 儿童（< 14 岁）/ 孕妇 / 特殊管理药品 | ≤ 5 分钟 |
| 普通 | `NORMAL` | 默认 | ≤ 15 分钟 |
| 低 | `LOW` | 复诊续方且无变化 | ≤ 30 分钟 |

**优先级判定规则（自上而下，命中即停）：**

1. 开方科室是急诊科 → `URGENT`
2. 处方含麻醉药品或第一类精神药品 → `URGENT`
3. 含第二类精神药品 → `HIGH`
4. 患者年龄 ≥ 65 或 ≤ 14 → `HIGH`
5. 处方药品数 ≥ 5 → `HIGH`（多药联用风险）
6. 处方含高警示药品 → `HIGH`
7. 复诊且与上次处方完全相同 → `LOW`
8. 其余 → `NORMAL`

### 3.4 自动审核规则模型

自动审核由**规则引擎**执行，每条规则分三类严重度：

| 严重度 | 代码 | 含义 | 处理 |
|---|---|---|---|
| **阻断** | `BLOCK` | 必须处理，不能通过 | 审核界面红字，药师必须选"退回"或"拒审"才能提交 |
| **警告** | `WARN` | 需药师确认 | 审核界面黄字，药师可勾选"已确认"后通过 |
| **提示** | `INFO` | 仅供参考 | 审核界面灰字，不影响审核 |

**规则清单（19 条）：**

#### 3.4.1 剂量类（DOSAGE）

| 规则码 | 规则 | 严重度 | 判断依据 |
|---|---|---|---|
| `DOSE_SINGLE_MAX` | 单次剂量超上限 | BLOCK | `mdm_drug_prescription.max_single_dose` |
| `DOSE_DAILY_MAX` | 日剂量超上限 | BLOCK | `mdm_drug_prescription.max_daily_dose` |
| `DOSE_DURATION_MAX` | 用药天数超上限 | WARN | `mdm_drug_prescription.max_duration_days` |
| `DOSE_PEDIATRIC` | 儿童剂量需按体重计算 | WARN | 患者年龄 < 14 |
| `DOSE_RENAL` | 肝肾功能不全需调整剂量 | WARN | 检验值 eGFR < 60 |

#### 3.4.2 相互作用类（DDI）

| 规则码 | 规则 | 严重度 | 判断依据 |
|---|---|---|---|
| `DDI_CONTRA` | 绝对禁忌的相互作用 | BLOCK | `mdm_drug_ddi.severity = 'CONTRAINDICATED'` |
| `DDI_MAJOR` | 严重相互作用 | WARN | `mdm_drug_ddi.severity = 'MAJOR'` |
| `DDI_MODERATE` | 中度相互作用 | INFO | `mdm_drug_ddi.severity = 'MODERATE'` |
| `DDI_FOOD` | 食物相互作用 | INFO | 药品主数据 `food_interaction` |

#### 3.4.3 重复用药类（DUPLICATE）

| 规则码 | 规则 | 严重度 | 判断依据 |
|---|---|---|---|
| `DUP_SAME_DRUG` | 同一药品重复开具 | BLOCK | 同一 `drug_id` 出现 2 次 |
| `DUP_SAME_ATC` | 同药理分类重复（ATC 前 4 位相同） | WARN | `mdm_drug.atc_code` |
| `DUP_SAME_CLASS` | 同治疗类别重复 | WARN | `mdm_drug.pharmacology_class` |
| `DUP_OPHTHALMIC` | 眼科同类滴眼液重复 | WARN | `mdm_drug.ophthalmic_class` |

#### 3.4.4 适应证类（INDICATION）

| 规则码 | 规则 | 严重度 | 判断依据 |
|---|---|---|---|
| `IND_NO_DIAG` | 无诊断开方 | BLOCK | 就诊无诊断记录 |
| `IND_MISMATCH` | 诊断与用药不符 | WARN | 药品 `indication_codes` 不含诊断 |
| `IND_OFF_LABEL` | 超说明书用药 | WARN | 药品主数据标记 `is_off_label_required` |

#### 3.4.5 禁忌类（CONTRA）

| 规则码 | 规则 | 严重度 | 判断依据 |
|---|---|---|---|
| `CONTRA_ALLERGY` | 患者过敏 | **BLOCK** | 过敏史含该药或其成分 |
| `CONTRA_PREGNANT` | 孕妇禁用 | BLOCK | `pregnancy_grade IN ('X', 'D')` 且患者孕期 |
| `CONTRA_RENAL` | 肾功能禁忌 | BLOCK | 肌酐清除率低于阈值 |
| `CONTRA_HEPATIC` | 肝功能禁忌 | BLOCK | 转氨酶超上限 3 倍 |

**眼科特殊规则（6 条，严重度为 WARN 或 INFO）：**

| 规则码 | 规则 | 严重度 |
|---|---|---|
| `OPH_STEROID_LONG` | 激素类滴眼液使用 > 14 天 | WARN |
| `OPH_PRESERVATIVE_MULTI` | 多种含防腐剂滴眼液同时使用 | WARN |
| `OPH_MYDRIATIC_ANGLE` | 散瞳药用在前房浅/闭角型青光眼患者 | **BLOCK** |
| `OPH_CONTACT_LENS` | 含防腐剂滴眼液 + 角膜接触镜配戴 | INFO |
| `OPH_PEDIATRIC_CONC` | 儿童使用高浓度阿托品 | WARN |
| `OPH_EYE_SIDE_MISSING` | 滴眼液未标注眼别 | WARN |

### 3.5 审核结论模型

| 结论 | 代码 | 可调配 | 处方后续 | 需填意见 |
|---|---|---|---|---|
| 通过 | `PASSED` | ✅ | 正常流转到调配 | 否 |
| 有条件通过 | `CONDITIONAL` | ✅ | 正常流转，但发药时须交代注意事项 | **是** |
| 退回修改 | `RETURNED` | ❌ | 回医生处修改 | **是** |
| 拒审 | `REJECTED` | ❌ | 处方作废，需重新开具 | **是** |

**"有条件通过"的场景：**

| 场景 | 药师意见示例 |
|---|---|
| 用药注意事项需告知 | 请告知患者：滴眼后按压内眦 2 分钟，避免药液经鼻泪管吸收 |
| 用法需调整 | 建议改为每日 3 次（原为每日 4 次），减少防腐剂累积 |
| 需监测指标 | 激素类用药，请 2 周后复查眼压 |
| 需患者签字确认 | 超说明书用药，需患者签署知情同意 |

**有条件通过的实现：** 结论置 `CONDITIONAL`，`suggestion` 字段必填。发药时 M14-07 会读取该字段并展示给发药人员，形成"药师意见 → 发药交代"的闭环。

### 3.6 审核队列模型

```
┌─────────────────────────────────────────────────────────────┐
│                      审核队列（按优先级）                     │
├─────────────────────────────────────────────────────────────┤
│  URGENT   │ rx_no: 007 处方 │ 急诊科 │ 等待 0:32            │
│  URGENT   │ rx_no: 012 处方 │ 眼科   │ 等待 1:05            │
│  HIGH     │ rx_no: 021 处方 │ 眼科   │ 等待 2:18            │
│  HIGH     │ rx_no: 019 处方 │ 眼科   │ 等待 4:51            │
│  NORMAL   │ rx_no: 034 处方 │ 眼科   │ 等待 6:12            │
│  NORMAL   │ rx_no: 031 处方 │ 眼科   │ 等待 8:40            │
│  LOW      │ rx_no: 005 处方 │ 眼科   │ 等待 12:20           │
└─────────────────────────────────────────────────────────────┘
```

**排序规则：** 先按优先级（URGENT > HIGH > NORMAL > LOW），同优先级按入队时间正序（FIFO）。

**Redis 实现：** 4 个 ZSet，`member = review_id`，`score = 入队时间戳`：

```
m14:rxreview:queue:URGENT   ZSet
m14:rxreview:queue:HIGH     ZSet
m14:rxreview:queue:NORMAL   ZSet
m14:rxreview:queue:LOW      ZSet
```

取队首：依次 `ZRANGE ... 0 0` 从 URGENT 到 LOW，第一个非空的即为队首。

### 3.7 会诊模型

药师遇到疑难处方时可以提请临床药师协助。

| 环节 | 操作 | 状态 |
|---|---|---|
| 药师发起 | 选择会诊药师、填写问题描述 | `CONSULTING` |
| 会诊药师回复 | 填写会诊意见 | `CONSULTING` |
| 药师采纳 | 填写审核结论 | `REVIEWING` → 终态 |

**会诊不改变审核结论的最终责任人** —— 无论是否会诊，签字负责的都是原审方药师。会诊意见只作参考，记入 `review_logs`。

### 3.8 超时升级模型

| 等待时长 | 动作 |
|---|---|
| > 5 分钟（URGENT/HIGH） | 前端标红闪烁 |
| > 15 分钟（NORMAL） | 推送消息给药房组长 |
| > 30 分钟（任一优先级） | 状态置 `TIMEOUT`，升级给药房主任，同时通知医生"处方尚在审核" |
| > 60 分钟 | 药房主任可强制指派其他药师 |

**为什么超过 30 分钟要通知医生？**

患者已经在窗口等了半小时，如果没人告诉他"处方还在审核"，他会认为药房把他忘了。通知医生让医生可以主动向患者解释。

### 3.9 审核质量指标

| 指标 | 计算 | 目标 | 意义 |
|---|---|---|---|
| 审核通过率 | PASSED + CONDITIONAL / 总数 | 92%~97% | 过低说明医生开方质量差 |
| 退回率 | RETURNED / 总数 | 3%~8% | 过高需培训医生 |
| 拒审率 | REJECTED / 总数 | < 1% | 过高需排查流程问题 |
| 平均审核时长 | AVG(reviewed_at − started_at) | ≤ 90 秒 | 药师效率 |
| 自动审核发现问题率 | 有问题处方 / 总数 | 15%~30% | 规则有效性 |
| 药师日均审核量 | COUNT / 工作日 | 80~150 张 | 工作量基准 |
| 超时率 | TIMEOUT / 总数 | < 2% | 人力配置是否足够 |

**为什么"通过"也必须填审核意见？**

法规要求药师对审核结论负责。如果只是点"通过"没有意见，事后无法判断药师是真审查过还是随手点的。强制填意见（哪怕写"未见明显用药问题"）能：

- 留下审查痕迹
- 让复查时有依据
- 让药师自己更审慎

| 「确认提交」 | `POST /reviews/{id}/submit` | 成功 → 回 P01，队列刷新 |
| 「取消」 | 关闭弹窗 | 结论不保存 |

### 6.5 Service 层核心逻辑

```python
import logging
from datetime import datetime, timedelta
from decimal import Decimal

from sqlalchemy import select, update, and_
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.exceptions import BizError
from app.models.m14 import M14RxReview, M14RxReviewConsult
from app.services.m14.auto_review_engine import AutoReviewEngine
from app.services.m14.queue_service import QueueService
from app.services.m14.dispatch_client import DispatchClient

logger = logging.getLogger(__name__)

MAX_BATCH_PASS = 50
MIN_OPINION_LEN = 10
LOCK_MINUTES = 30
TIMEOUT_MINUTES = 30

CONCLUSIONS = ("PASSED", "CONDITIONAL", "RETURNED", "REJECTED")


class RxReviewService:
    """处方审核服务"""

    def __init__(self, db: AsyncSession):
        self.db = db
        self.engine = AutoReviewEngine()
        self.queue = QueueService()
        self.dispatch = DispatchClient()

    # ---------------- 创建审核任务 ----------------
    async def internal_create(self, body: dict) -> dict:
        """接收 M07 的处方签名事件，创建审核任务"""
        rx_id = body["rx_id"]
        rx_version = body.get("rx_version", 1)
        idem = body.get("idempotency_key") or "RX:%s:V%s" % (
            rx_id, rx_version)

        exist = await self._find_by_idem(idem)
        if exist:
            return self._dict(exist, is_idempotent=True)

        # 1. 取处方详情（阻断依赖）
        rx = await self._load_rx(rx_id)
        patient = await self._load_patient(rx["patient_id"])
        diagnosis = await self._load_diagnosis(rx["encounter_id"])

        # 2. 执行自动审核
        auto = await self.engine.run(rx, patient, diagnosis)

        # 3. 判定优先级
        priority = self._resolve_priority(rx, patient)

        # 4. 落库
        review_no = await self._next_review_no()
        obj = M14RxReview(
            review_no=review_no,
            rx_id=rx_id,
            rx_no=rx["rx_no"],
            rx_version=rx_version,
            encounter_id=rx["encounter_id"],
            patient_id=rx["patient_id"],
            patient_name=patient.get("name"),
            patient_age=patient.get("age"),
            patient_sex=patient.get("sex"),
            dept_id=rx.get("dept_id"),
            dept_name=rx.get("dept_name"),
            doctor_id=rx.get("doctor_id"),
            doctor_name=rx.get("doctor_name"),
            drug_count=len(rx.get("items", [])),
            priority=priority,
            status="PENDING",
            queue_at=datetime.now(),
            auto_result=auto["result"],
            auto_issues=auto["issues"],
            risk_level=auto.get("risk_level", "LOW"),
            idempotency_key=idem,
            trace_id=body.get("trace_id"),
        )
        self.db.add(obj)
        await self.db.commit()
        await self.db.refresh(obj)

        # 5. 入队
        await self.queue.push(obj.id, priority)

        logger.info(
            "审核任务创建",
            extra={
                "review_no": review_no, "rx_no": obj.rx_no,
                "priority": priority,
                "block": auto["result"]["block_count"],
                "warn": auto["result"]["warn_count"],
            })
        return self._dict(obj, is_idempotent=False)

    # ---------------- 领取（锁定） ----------------
    async def lock(self, review_id: int, user) -> dict:
        """药师领取处方，加锁"""

        # 1. Redis 分布式锁
        ok = await self.queue.lock_review(review_id, user["id"], LOCK_MINUTES)
        if not ok:
            holder = await self.queue.get_lock_holder(review_id)
            raise BizError(55465, "该处方已被%s领取" % (
                holder.get("reviewer_name") or "其他药师"))

        # 2. 数据库状态校验（乐观：WHERE status='PENDING'）
        stmt = (
            update(M14RxReview)
            .where(and_(
                M14RxReview.id == review_id,
                M14RxReview.status == "PENDING"))
            .values(
                status="REVIEWING",
                reviewer_id=user["id"],
                reviewer_name=user["employee_name"],
                started_at=datetime.now(),
                lock_expire_at=datetime.now() + timedelta(
                    minutes=LOCK_MINUTES))
        )
        result = await self.db.execute(stmt)
        await self.db.commit()

        if result.rowcount == 0:
            await self.queue.unlock_review(review_id)
            raise BizError(55466, "审核任务状态已变更，请刷新")

        await self.queue.remove(review_id)

        logger.info(
            "审核锁定",
            extra={"review_id": review_id,
                   "reviewer": user["employee_name"]})
        return {
            "review_id": review_id,
            "status": "REVIEWING",
            "reviewer_id": user["id"],
            "reviewer_name": user["employee_name"],
            "locked_at": datetime.now().isoformat(),
            "lock_expire_at": (
                datetime.now() + timedelta(minutes=LOCK_MINUTES)
            ).isoformat(),
            "next_action": "SUBMIT",
        }

    # ---------------- 释放锁定 ----------------
    async def release(self, review_id: int, force: bool, user) -> dict:
        obj = await self._get(review_id)

        if obj.status != "REVIEWING":
            raise BizError(55466, "只有审核中的处方可以释放")

        # 强制释放需超时且是组长
        if force:
            elapsed = (datetime.now() - obj.started_at).total_seconds()
            if elapsed < TIMEOUT_MINUTES * 60:
                raise BizError(
                    55458, "未超过 %d 分钟的审核不能强制释放"
                    % TIMEOUT_MINUTES)
        elif obj.reviewer_id != user["id"]:
            raise BizError(55469, "只能释放自己领取的处方")

        await self.db.execute(
            update(M14RxReview)
            .where(M14RxReview.id == review_id)
            .values(
                status="PENDING",
                reviewer_id=None,
                reviewer_name=None,
                started_at=None,
                lock_expire_at=None))
        await self.db.commit()
        await self.queue.unlock_review(review_id)
        await self.queue.push(review_id, obj.priority)

        return {"review_id": review_id, "status": "PENDING"}

    # ---------------- 指派 ----------------
    async def assign(self, review_id: int, reviewer_id: int,
                     user) -> dict:
        obj = await self._get(review_id)
        if obj.status != "PENDING":
            raise BizError(55466, "只有待审核的处方可以指派")

        staff = await self._get_staff(reviewer_id)
        if not staff or not staff.get("online"):
            raise BizError(55457, "不能指派给离线药师")

        await self.queue.lock_review(review_id, reviewer_id, LOCK_MINUTES)
        await self.db.execute(
            update(M14RxReview)
            .where(and_(
                M14RxReview.id == review_id,
                M14RxReview.status == "PENDING"))
            .values(
                status="REVIEWING",
                reviewer_id=reviewer_id,
                reviewer_name=staff["employee_name"],
                started_at=datetime.now(),
                lock_expire_at=datetime.now() + timedelta(
                    minutes=LOCK_MINUTES),
                assigned_by=user["id"]))
        await self.db.commit()
        await self.queue.remove(review_id)
        await self._notify(reviewer_id, "您有 1 张指派处方待审核")

        return {
            "review_id": review_id,
            "status": "REVIEWING",
            "reviewer_id": reviewer_id,
            "reviewer_name": staff["employee_name"],
        }

    # ---------------- 提交审核结论 ----------------
    async def submit(self, review_id: int, body, user) -> dict:
        obj = await self._get(review_id)

        # 1. 状态校验
        if obj.status not in ("REVIEWING",):
            raise BizError(55466, "当前状态（%s）不能提交结论"
                           % obj.status)
        if obj.reviewer_id != user["id"]:
            raise BizError(55469, "只能提交自己领取的处方")

        # 2. 结论校验
        if body.conclusion not in CONCLUSIONS:
            raise BizError(55456, "请选择审核结论")
        if not body.review_opinion or len(
                body.review_opinion.strip()) < MIN_OPINION_LEN:
            raise BizError(55455, "审核意见至少 %d 字" % MIN_OPINION_LEN)
        if body.conclusion == "CONDITIONAL" and not body.suggestion:
            raise BizError(55454, "有条件通过必须填写药师建议")

        # 3. 规则校验（关键）
        await self._check_issues(obj, body)

        # 4. 更新
        now = datetime.now()
        duration = int((now - obj.started_at).total_seconds())
        await self.db.execute(
            update(M14RxReview)
            .where(M14RxReview.id == review_id)
            .values(
                status=body.conclusion,
                conclusion=body.conclusion,
                review_opinion=body.review_opinion,
                suggestion=body.suggestion,
                reviewed_at=now,
                duration_seconds=duration,
                confirmed_issues=body.confirmed_issue_ids or [],
                lock_expire_at=None))
        await self.db.commit()

        # 5. 回写 M07-05
        writeback = await self._writeback(obj, body.conclusion)

        # 6. 消息通知医生
        if body.notify_doctor:
            await self._notify_doctor(obj, body)

        # 7. 审计
        await self._audit(obj, body, user)

        await self.queue.unlock_review(review_id)

        logger.info(
            "审核完成",
            extra={
                "review_no": obj.review_no, "rx_no": obj.rx_no,
                "conclusion": body.conclusion,
                "reviewer": user["employee_name"],
                "duration_seconds": duration,
            })

        return {
            "review_id": review_id,
            "review_no": obj.review_no,
            "rx_no": obj.rx_no,
            "conclusion": body.conclusion,
            "status": body.conclusion,
            "reviewer_id": user["id"],
            "reviewer_name": user["employee_name"],
            "reviewed_at": now.isoformat(),
            "duration_seconds": duration,
            "writeback": writeback,
            "notify": {"sent": bool(body.notify_doctor)},
        }

    async def _check_issues(self, obj, body) -> None:
        """校验问题处理情况"""
        issues = obj.auto_issues or []

        if body.conclusion in ("PASSED", "CONDITIONAL"):
            # 有 BLOCK 级问题不能通过
            blocks = [i for i in issues if i.get("severity") == "BLOCK"]
            if blocks:
                raise BizError(
                    55451,
                    "存在 %d 条阻断级问题（%s），不能通过"
                    % (len(blocks), blocks[0].get("rule_code")))

            # 有未确认的 WARN 不能通过
            confirmed = set(body.confirmed_issue_ids or [])
            unconfirmed = [
                i for i in issues
                if i.get("severity") == "WARN"
                and i.get("issue_id") not in confirmed]
            if unconfirmed:
                raise BizError(
                    55452,
                    "存在 %d 条未确认的警告，请先确认或退回"
                    % len(unconfirmed))

        if body.conclusion in ("RETURNED", "REJECTED"):
            # 退回与拒审必须有意见说明，已由通用校验保证
            pass

    async def _writeback(self, obj, conclusion: str) -> dict:
        """回写 M07-05 处方状态"""
        passed = conclusion in ("PASSED", "CONDITIONAL")
        target = ("/internal/v1/m07/prescriptions/on-reviewed"
                  if passed
                  else "/internal/v1/m07/prescriptions/on-returned")
        payload = {
            "rx_id": obj.rx_id,
            "review_id": obj.id,
            "review_no": obj.review_no,
            "conclusion": conclusion,
            "passed": passed,
            "reviewer_id": obj.reviewer_id,
            "reviewer_name": obj.reviewer_name,
            "reviewed_at": obj.reviewed_at.isoformat(),
            "opinion": obj.review_opinion,
            "suggestion": obj.suggestion,
        }
        try:
            resp = await self.dispatch.post(target, payload, timeout=3.0)
            ok = resp.get("code") == 0
        except Exception as exc:
            logger.error(
                "回写医生站失败，入补偿队列",
                extra={"review_id": obj.id, "error": str(exc)})
            await self._enqueue_writeback(obj.id, target, payload)
            ok = False

        return {
            "target": "M07-05",
            "interface": "POST " + target,
            "success": ok,
            "affected": 1 if ok else 0,
        }

    # ---------------- 批量通过 ----------------
    async def batch_pass(self, body, user) -> dict:
        if len(body.review_ids) > MAX_BATCH_PASS:
            raise BizError(
                55472, "批量通过最多 %d 张" % MAX_BATCH_PASS)

        results = []
        passed = 0
        failed = 0

        for rid in body.review_ids:
            try:
                obj = await self._get(rid)
                if obj.status != "PENDING":
                    raise BizError(55466, "状态不允许")

                issues = obj.auto_issues or []
                if any(i.get("severity") in ("BLOCK", "WARN")
                       for i in issues):
                    raise BizError(55453, "该处方存在审核问题")

                await self.lock(rid, user)
                await self.submit(
                    rid,
                    _BatchPassBody(
                        conclusion="PASSED",
                        review_opinion=body.opinion,
                        suggestion=None,
                        notify_doctor=False,
                        confirmed_issue_ids=[]),
                    user)
                results.append({
                    "review_id": rid,
                    "review_no": obj.review_no,
                    "success": True,
                    "status": "PASSED"})
                passed += 1
            except BizError as exc:
                obj = await self._safe_get(rid)
                results.append({
                    "review_id": rid,
                    "review_no": obj.review_no if obj else None,
                    "success": False,
                    "status": exc.message})
                failed += 1

        return {
            "total": len(body.review_ids),
            "passed": passed,
            "failed": failed,
            "results": results,
        }

    # ---------------- 优先级判定 ----------------
    def _resolve_priority(self, rx: dict, patient: dict) -> str:
        """按规则判定优先级"""
        items = rx.get("items", [])
        dept_code = rx.get("dept_code", "")
        age = patient.get("age") or 0

        # 1. 急诊科
        if dept_code.startswith("EMERG"):
            return "URGENT"

        # 2. 麻醉/一类精神
        if any(i.get("management_class") in ("NARCOTIC", "PSYCHOTROPIC_1")
               for i in items):
            return "URGENT"

        # 3. 二类精神
        if any(i.get("management_class") == "PSYCHOTROPIC_2"
               for i in items):
            return "HIGH"

        # 4. 老人儿童
        if age >= 65 or (0 < age <= 14):
            return "HIGH"

        # 5. 多药
        if len(items) >= 5:
            return "HIGH"

        # 6. 高警示
        if any(i.get("is_high_alert") for i in items):
            return "HIGH"

        # 7. 续方且无变化
        if rx.get("is_refill") and rx.get("same_as_last"):
            return "LOW"

        return "NORMAL"

    async def get_report(self, start_date: str, end_date: str,

        d1 = datetime.strptime(start_date, "%Y-%m-%d").date()

        duration_sum = sum(
            r["duration_sum"] for r in rows)
        duration_cnt = sum(r["duration_cnt"] for r in rows) or 1
        auto_hit = sum(r["auto_hit"] for r in rows)

        return {
            "start_date": start_date,
            "end_date": end_date,
            "summary": {
                "total": total,
                "passed": passed,
                "passed_rate": round(passed / total, 4),

                "rejected": rejected,
                "rejected_rate": round(rejected / total, 4),
                "conditional": sum(r["conditional"] for r in rows),
                "timeout": timeout,
                "timeout_rate": round(timeout / total, 4),
                "avg_duration_seconds": int(
                    duration_sum / duration_cnt),
                "auto_hit": auto_hit,
                "auto_hit_rate": round(auto_hit / total, 4),
            },
            "by_reviewer": rows,
```

```python
        items = rx.get("items", [])
        for i, a in enumerate(items):
            for b in items[i + 1:]:
                ddi = await self._lookup_ddi(
                    a.get("drug_id"), b.get("drug_id"))
                if ddi and ddi.get("severity") == severity:
                    hits.append({
                        "title": "%s 与 %s 存在相互作用" % (
                            a["drug_name"], b["drug_name"]),
                        "detail": ddi.get("description", ""),
                        "evidence": {
                            "drug_a": a["drug_name"],
                            "drug_b": b["drug_name"],
                            "severity": severity,
                            "mechanism": ddi.get("mechanism"),
                        },
                        "suggestion": ddi.get("management", ""),
                        "drug_id": a.get("drug_id"),
                        "line_no": a.get("line_no"),
                    })
        return hits
```

**容量估算**

| 项 | 估算 |
|---|---|
| 队列 ZSet（4 个） | 20 个成员 × 100 B = 2 KB |
| 审核锁 | 5 并发 × 200 B = 1 KB |
| 规则配置 | 26 条 × 200 B = 5 KB |
| 患者过敏史 | 活跃 500 人 × 300 B = 150 KB |
| 药品缓存 | 600 种 × 800 B = 480 KB |
| 报表缓存 | 20 份 × 20 KB = 400 KB |
| **合计** | **约 1.1 MB** |

```python
import asyncio
import logging
from datetime import datetime, timedelta

from celery import shared_task

logger = logging.getLogger(__name__)


@shared_task(name="m14.rxreview.timeout_scan", max_retries=3)
def timeout_scan_task():
    """扫描超时的审核任务并升级"""
    return asyncio.run(_timeout_scan())


async def _timeout_scan():
    from app.db.session import AsyncSessionLocal
    from app.services.m14.rx_review_service import RxReviewService

    async with AsyncSessionLocal() as db:
        svc = RxReviewService(db)
        rows = await svc.scan_timeout()
        for row in rows:
            await svc.escalate_timeout(row)
            logger.warning(
                "审核超时升级",
                extra={"review_id": row["id"],
                       "rx_no": row["rx_no"],
                       "wait_minutes": row["wait_minutes"]})
        return {"scanned": len(rows)}


@shared_task(name="m14.rxreview.lock_expire", max_retries=3)
def lock_expire_task():
    """释放过期的审核锁"""
    return asyncio.run(_lock_expire())


async def _lock_expire():
    from app.db.session import AsyncSessionLocal
    from sqlalchemy import update, and_

    async with AsyncSessionLocal() as db:
        from app.models.m14 import M14RxReview
        stmt = (
            update(M14RxReview)
            .where(and_(
                M14RxReview.status == "REVIEWING",
                M14RxReview.lock_expire_at < datetime.now()))
            .values(
                status="PENDING",
                reviewer_id=None,
                reviewer_name=None,
                started_at=None,
                lock_expire_at=None)
        )
        result = await db.execute(stmt)
        await db.commit()
        logger.info("释放过期审核锁", extra={"count": result.rowcount})
        return {"released": result.rowcount}


@shared_task(name="m14.rxreview.writeback_retry", max_retries=3)
def writeback_retry_task():
    """重试回写医生站失败的审核结论"""
    return asyncio.run(_writeback_retry())


async def _writeback_retry():
    from app.db.session import AsyncSessionLocal
    from app.services.m14.rx_review_service import RxReviewService

    async with AsyncSessionLocal() as db:
        svc = RxReviewService(db)
        return await svc.retry_pending_writebacks()


@shared_task(name="m14.rxreview.quality_report", max_retries=3)
def quality_report_task():
    """每日 01:30 生成审核质量日报"""
    return asyncio.run(_quality_report())


async def _quality_report():
    from app.db.session import AsyncSessionLocal
    from app.services.m14.rx_review_service import RxReviewService

    async with AsyncSessionLocal() as db:
        svc = RxReviewService(db)
        yesterday = (datetime.now() - timedelta(days=1)).date()
        report = await svc.build_daily_report(yesterday)
        await svc.save_daily_report(yesterday, report)
        logger.info("审核质量日报生成",
                    extra={"date": str(yesterday), **report["summary"]})
        return report


@shared_task(name="m14.rxreview.queue_rebuild", max_retries=3)
def queue_rebuild_task():
    """队列重建：Redis 重启或数据不一致时从库重建队列"""
    return asyncio.run(_queue_rebuild())


async def _queue_rebuild():
    from app.db.session import AsyncSessionLocal
    from app.services.m14.queue_service import QueueService
    from sqlalchemy import select

    async with AsyncSessionLocal() as db:
        from app.models.m14 import M14RxReview
        stmt = (
            select(M14RxReview.id, M14RxReview.priority,
                   M14RxReview.queue_at)
            .where(M14RxReview.status == "PENDING")
            .order_by(M14RxReview.queue_at)
        )
        rows = (await db.execute(stmt)).all()
        queue = QueueService()
        await queue.reset()
        for row in rows:
            await queue.push(row.id, row.priority,
                             row.queue_at.timestamp())
        logger.info("审核队列重建完成",
                    extra={"count": len(rows)})
        return {"rebuilt": len(rows)}


@shared_task(name="m14.rxreview.clean_history", max_retries=1)

async def _clean_history():
    from app.db.session import AsyncSessionLocal
    from sqlalchemy import delete, and_

    async with AsyncSessionLocal() as db:
        from app.models.m14 import M14RxReviewLog
        stmt = (
            delete(M14RxReviewLog)
            .where(and_(M14RxReviewLog.created_at < cutoff,
                        M14RxReviewLog.keep_forever == False))
        )
        result = await db.execute(stmt)
        await db.commit()
        logger.info("清理历史审核日志",
                    extra={"deleted": result.rowcount})
        return {"deleted": result.rowcount}
```

| DA-04 | 审核记录可追溯 | 任一审核记录可查到药师、时间、结论、意见、问题清单 |
| DA-05 | 幂等键唯一 | 重复创建审核任务只有 1 条记录 |
| DA-06 | 已有审核的任务不能重复创建 | `uk_m14_rx_review_rx_version` 生效 |
| DA-07 | 日志只读 | 触发器阻止 UPDATE/DELETE |
| DA-08 | 审核保留 2 年 | 每月对账脚本确认无过早删除 |
| DA-09 | 回写补偿队列可追溯 | 每次回写失败有记录与最终结果 |
| DA-10 | 统计数据一致 | `m14_rx_review` 表统计 = 报表统计 |

### 12.4 安全验收

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| SC-01 | 未授权访问 | 无权限码调用接口返回 403 |
| SC-02 | 数据权限 | 药师只能审本科室处方 |
| SC-03 | 审核人 ≠ 医生 | 同一人既是医生又是药师时拒绝自审 |
| SC-04 | 会诊人 ≠ 发起人 | 报 "1406010" |
| SC-05 | 审核记录不可篡改 | 数据库层面阻止 |
| SC-06 | 审计日志完整 | M02-06 有全部审核操作记录 |
| SC-07 | 内部接口隔离 | 外网无法访问 `/internal/` |
