## 4. 数据结构设计

### 4.1 ER 关系图

```
┌─────────────────────┐
│ m14_purchase_plan   │ 采购申请
│  plan_no / status   │
└──────┬───────┬──────┘
       │1:N    │1:N
       ▼       ▼
┌──────────────┐ ┌──────────────────────┐
│...plan_item  │ │ m14_purchase_approval│
│ 申请明细      │ │ 审批记录（多级）      │
└──────────────┘ └──────────────────────┘
       │
       │ 审批通过后转订单
       ▼
┌─────────────────────┐
│ m14_purchase_order  │ 采购订单
│  order_no / status  │
└──────┬──────────────┘
       │1:N
       ▼
┌─────────────────────┐
│...order_item        │ 订单明细
│  received_qty       │
└─────────────────────┘
       ▲
       │ N:1（部分到货）
       │
┌─────────────────────┐        ┌────────────────────┐
│ m14_receipt         │ 1:N ──►│ m14_receipt_item   │
│  receipt_no / result│        │ 批号/效期/验收项    │
└──────┬──────────────┘        └─────────┬──────────┘
       │                                 │ 不合格
       │ 1:1                             ▼
       │                       ┌────────────────────┐
       │                       │ m14_reject         │
       │                       │ 拒收单             │
       │                       └────────────────────┘
       │
       │ 入库 → 调 M14-01 写 PURCHASE_IN
       ▼
┌──────────────────┐
│  m14_stock_txn   │（M14-01，本子模块只调用）
└──────────────────┘

┌──────────────────────┐
│ m14_purchase_return  │ 采购退货 → 调 M14-01 写 PURCHASE_RETURN
│  return_no / status  │
└──────────────────────┘
```

**设计说明**

| 决策 | 内容 | 理由 |
|---|---|---|
| 申请与订单分离 | `plan` → `order` 一对多 | 一个申请可按供应商拆成多张订单 |
| 验收与订单分离 | `order` ← `receipt` 一对多 | 支持分批到货，每批独立验收独立入库 |
| 验收与拒收分离 | `receipt` → `reject` 一对一（部分拒收时） | 拒收要独立走质量流程，不能混在验收单里 |
| 明细快照药品名 | 所有明细表冗余 `drug_code`/`drug_name`/`specification` | 药品主数据改名后历史单据不应变化 |
| 不直接写库存流水 | 无 `m14_stock_txn` 外键 | 库存唯一入口在 M14-01，解耦后可独立演进 |

| item_count | SMALLINT | N | 0 | 明细行数 |
| total_amount | NUMERIC(14,2) | N | 0.00 | 估算总金额 |
| status | VARCHAR(16) | N | 'DRAFT' | 状态 |
| approval_tier | VARCHAR(8) | Y | NULL | 审批层级：L1 / L2 / L3 |
| current_step | SMALLINT | N | 0 | 当前审批步骤 |
| urgent_reason | VARCHAR(512) | Y | NULL | 加急理由 |
| resolution_no | VARCHAR(64) | Y | NULL | 药事会决议号（新药） |
| submitted_at | TIMESTAMP | Y | NULL | 提交时间 |
| approved_at | TIMESTAMP | Y | NULL | 审批通过时间 |
| converted_at | TIMESTAMP | Y | NULL | 转订单时间 |
| cancelled_at | TIMESTAMP | Y | NULL | 作废时间 |
| cancel_reason | VARCHAR(255) | Y | NULL | 作废原因 |
| remark | VARCHAR(512) | Y | NULL | 备注 |

| created_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 更新时间 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m14_purchase_plan | PRIMARY | id | 主键 |
| uk_m14_plan_no | UNIQUE | plan_no WHERE is_deleted = FALSE | 单号唯一 |
| idx_m14_plan_status | NORMAL | status, created_at DESC | 按状态查 |
| idx_m14_plan_dept | NORMAL | apply_dept_id, created_at DESC | 按科室查 |
| idx_m14_plan_applicant | NORMAL | applicant_id, created_at DESC | 按申请人查 |
| idx_m14_plan_pending | NORMAL | submitted_at WHERE status = 'SUBMITTED' | 待审批 |

**约束说明**

```sql
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_type
    CHECK (plan_type IN ('ROUTINE', 'NEW_DRUG', 'DEPT',
                         'EMERGENCY'));

ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_urgency
    CHECK (urgency IN ('NORMAL', 'URGENT'));

ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_status
    CHECK (status IN ('DRAFT', 'SUBMITTED', 'APPROVED',
                      'REJECTED', 'CONVERTED', 'CANCELLED'));

ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_tier
    CHECK (approval_tier IS NULL
           OR approval_tier IN ('L1', 'L2', 'L3'));

ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_amount
    CHECK (total_amount >= 0 AND item_count >= 0);

-- 加急必须填写理由
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_urgent
    CHECK (urgency <> 'URGENT'
           OR (urgent_reason IS NOT NULL
               AND char_length(btrim(urgent_reason)) >= 10));

-- 新药申请必须有关联决议
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_new_drug
    CHECK (plan_type <> 'NEW_DRUG' OR resolution_no IS NOT NULL);

-- 已提交必须有提交时间
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_submitted
    CHECK (status = 'DRAFT' OR submitted_at IS NOT NULL);

-- 已通过必须有审批时间
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_approved
    CHECK (status <> 'APPROVED' OR approved_at IS NOT NULL);

-- 作废必须有原因与时间
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_cancelled
    CHECK (status <> 'CANCELLED'
           OR (cancelled_at IS NOT NULL AND cancel_reason IS NOT NULL));

-- 单号格式
ALTER TABLE m14_purchase_plan
    ADD CONSTRAINT ck_m14_plan_no
    CHECK (plan_no ~ '^CG[0-9]{8}[0-9]{4}$');
```

**状态机**

```
   ┌────────┐  提交   ┌────────────┐  审批通过  ┌───────────┐
   │ DRAFT  │────────►│ SUBMITTED  │──────────►│ APPROVED  │
   └────────┘         └─────┬──────┘            └─────┬─────┘
        ▲                   │ 驳回                    │
        │                   ▼                         │ 转订单
        │            ┌──────────┐                     ▼
        └────────────│ REJECTED │              ┌───────────┐
        修改重提     └──────────┘              │ CONVERTED │
                                                └───────────┘

   DRAFT / SUBMITTED / APPROVED / REJECTED ──► CANCELLED
```

| 年行数 | 360 |
| 单行大小 | 约 500 B |
| 保留 | 10 年（财务凭证） |

### 4.3 表：`m14_purchase_plan_item`（采购申请明细表）

**表说明：** 采购申请的每一行药品需求。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | 自增 | 主键 |
| plan_id | BIGINT | N | — | 采购申请 ID |
| line_no | SMALLINT | N | — | 行号 |
| drug_id | BIGINT | N | — | 药品 ID |
| drug_code | VARCHAR(32) | N | — | 药品编码快照 |
| drug_name | VARCHAR(128) | N | — | 药品名称快照 |
| specification | VARCHAR(128) | Y | NULL | 规格快照 |
| package_unit | VARCHAR(16) | Y | NULL | 包装单位 |
| conversion_ratio | NUMERIC(12,4) | N | 1 | 换算比 |
| request_qty | NUMERIC(14,4) | N | — | 需求数量 |
| current_stock | NUMERIC(14,4) | N | 0 | 申请时库存快照 |
| monthly_usage | NUMERIC(14,4) | N | 0 | 月均用量快照 |
| reference_price | NUMERIC(12,4) | N | 0 | 参考单价 |
| estimated_amount | NUMERIC(14,2) | N | 0.00 | 估算金额 |
| source_type | VARCHAR(32) | N | 'MANUAL' | 来源 |
| source_id | BIGINT | Y | NULL | 来源 ID（补货建议 ID） |
| converted_qty | NUMERIC(14,4) | N | 0 | 已转订单数量 |
| created_at | TIMESTAMP | N | CURRENT_TIMESTAMP | 创建时间 |

**索引设计**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m14_plan_item | PRIMARY | id | 主键 |
| uk_m14_plan_item_line | UNIQUE | plan_id, line_no | 行号唯一 |
| uk_m14_plan_item_drug | UNIQUE | plan_id, drug_id | **同一申请内药品不重复** |
| idx_m14_plan_item_drug | NORMAL | drug_id, created_at DESC | 按药品查历史 |

**约束说明**

```sql
ALTER TABLE m14_purchase_plan_item
    ADD CONSTRAINT ck_m14_plan_item_qty
    CHECK (request_qty > 0 AND converted_qty >= 0
           AND converted_qty <= request_qty);

ALTER TABLE m14_purchase_plan_item
    ADD CONSTRAINT ck_m14_plan_item_price
    CHECK (reference_price >= 0);

-- 估算金额 = 参考单价 × 需求数量
ALTER TABLE m14_purchase_plan_item
    ADD CONSTRAINT ck_m14_plan_item_amount
    CHECK (ABS(estimated_amount
               - ROUND(reference_price * request_qty, 2)) <= 0.01);

ALTER TABLE m14_purchase_plan_item
    ADD CONSTRAINT ck_m14_plan_item_source
    CHECK (source_type IN ('REPLENISH', 'MANUAL',
                           'DEPT_REQUEST', 'NEW_DRUG'));

ALTER TABLE m14_purchase_plan_item
    ADD CONSTRAINT ck_m14_plan_item_ratio
    CHECK (conversion_ratio >= 1);
```

**`uk_m14_plan_item_drug` 的意义**

同一张申请单里如果出现两次"玻璃酸钠滴眼液 200 支"和"玻璃酸钠滴眼液 100 支"，会产生三个问题：

1. 审批人看到两行不知道该批哪一行
2. 转订单时可能只转其中一行，漏了另一行
3. 统计"申请了 300 支"，但实际两行分别被拆到不同订单，对不上

用唯一索引从表结构上排除。需要补量时改 `request_qty` 而不是加一行。

    ADD CONSTRAINT ck_m14_order_item_tax
    CHECK (amount_without_tax IS NULL OR tax_amount IS NULL
           OR ABS(amount_without_tax + tax_amount - amount) <= 0.01);

    ADD CONSTRAINT ck_m14_order_item_tax_calc
    CHECK (amount_without_tax IS NULL
           OR ABS(amount_without_tax
                  - ROUND(amount / (1 + tax_rate), 2)) <= 0.01);

    CHECK (conversion_ratio >= 1);

**为什么 `amount_without_tax` 必须按 `amount / (1 + tax_rate)` 算**

假设采购 1000 元（含税），税率 13%：

- **正确**：不含税 = 1000 / 1.13 = 884.96，税额 = 1000 − 884.96 = 115.04
- **错误**：税额 = 1000 × 13% = 130.00，不含税 = 870.00

差 15 元。如果一个月 100 张订单，进项税额多算 1500 元，年度汇算清缴时会被税务师事务所调整，还要补税加滞纳金。

这是**价内税**与**价外税**的区别：国内增值税是价内税（价格已含税），所以要从含税金额倒算。这个约束直接落在数据库上，任何绕过服务层的写入都会失败。

**`ck_m14_receipt_amount`（到货 = 入库 + 拒收）的价值**

- 入库数量算错（少入了几支，库存对不上）
- 拒收数量算错（拒收单金额与验收单不符）
- 数据被外部修改

三种情况都必须立刻发现。这个约束让数据库在写入时就拦截，而不是等月底盘点差几百支才追溯。

                if not self.attachments:
                    raise ValueError("质量问题必须上传照片")
        return self
