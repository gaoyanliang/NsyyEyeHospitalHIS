        │  qty_on_hand / qty_locked                     │
        │  qty_available  ← 生成列 = on_hand − locked   │

                            │ 1:N（仅序列号管理耗材）
                            ▼
        ┌───────────────────────────────────────────────┐

        │  id (PK) / serial_no (UK，全局唯一)            │
        │  status: AVAILABLE/LOCKED/ISSUED/USED/        │
        │          EXPIRED/DAMAGED/RECALLED             │

**设计说明：**

| 决策 | 内容 | 理由 |
|---|---|---|
| 无物理外键 | 全部引用（`material_code`、`warehouse_id`、`location_id`）为逻辑引用 | 与 M14/M16 一致；跨模块与高频写入表加外键会引入锁竞争，且 M01-04 是独立服务 |
| 名称快照 | `m15_stock` 冗余 `material_name` / `spec`；`m15_stock_batch` 再冗余一份 | 耗材改名后历史台账仍显示当时的名称；查询汇总不用 JOIN M01-04 |
| 生成列 | `qty_available` 为 `GENERATED ALWAYS AS (qty_on_hand - qty_locked) STORED` | 三数量恒等式由数据库强制，不靠应用层自觉 |
| 只增表 | `m15_stock_txn` 用触发器禁止 UPDATE/DELETE | GSP 与财务审计要求可追溯不可篡改 |
| 批次粒度 vs 序列号粒度 | `m15_stock` 按批次记数量，`m15_stock_batch` 按序列号记实例 | 普通耗材一次出库 500 片不能写 500 条；高值耗材必须一物一码 |
| 分区 | 仅 `m15_stock_txn` 按月 RANGE 分区 | 主表都有跨年唯一约束，分区会迫使唯一索引含分区键从而破坏语义 |
| 成本法 | 批次实际成本（`unit_cost` 存于台账行） | 高值耗材单价 3,000~15,000 元，移动加权平均会稀释批次真实成本 |

## 4.2 表：`m15_warehouse`（仓库定义表）

**表说明：** 定义 M15 物资域的全部仓库。仓库类型决定业务规则（谁能入库、谁能出库、是否需双人、是否计入资产），全局只能有一个一级总库。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | IDENTITY | 主键 |
| warehouse_code | VARCHAR(32) | N | — | 仓库编码，格式 `^[A-Z0-9-]{3,32}$`，全局唯一 |
| warehouse_name | VARCHAR(100) | N | — | 仓库名称 |
| warehouse_type | VARCHAR(32) | N | — | 仓库类型：`CENTRAL` 一级总库 / `SECONDARY` 二级库 / `OPERATING` 手术室库 / `HIGH_VALUE_CABINET` 高值柜 / `CONSIGNMENT` 寄售库 / `QUARANTINE` 待检区 / `VIRTUAL` 虚拟库 |
| is_central | BOOLEAN | N | FALSE | 是否一级总库（全局仅一条 TRUE） |
| is_secondary | BOOLEAN | N | FALSE | 是否二级库（必须有上级仓库） |
| parent_warehouse_id | BIGINT | Y | NULL | 上级仓库 ID（二级库/高值柜必填） |
| dept_id | BIGINT | Y | NULL | 归属科室 ID（二级库对应使用科室） |
| dept_name | VARCHAR(100) | Y | NULL | 归属科室名称（快照） |
| manager_id | BIGINT | Y | NULL | 仓库负责人（库管员）职工 ID |
| manager_name | VARCHAR(64) | Y | NULL | 负责人姓名（快照） |
| phone | VARCHAR(32) | Y | NULL | 联系电话 |
| address | VARCHAR(200) | Y | NULL | 物理位置描述 |
| dual_control | BOOLEAN | N | FALSE | 是否双人管理（高值柜必须 TRUE） |
| allow_negative | BOOLEAN | N | FALSE | 是否允许负库存 |
| sort_no | SMALLINT | N | 0 | 排序号 |
| status | VARCHAR(16) | N | 'DRAFT' | 状态：`DRAFT` / `ENABLED` / `DISABLED` / `CLOSED` |
| enabled_at | TIMESTAMP | Y | NULL | 启用时间 |
| disabled_at | TIMESTAMP | Y | NULL | 停用时间 |
| closed_at | TIMESTAMP | Y | NULL | 关闭时间 |
| close_reason | VARCHAR(200) | Y | NULL | 关闭原因（≥5 字） |
| remark | VARCHAR(500) | Y | NULL | 备注 |
| version | INTEGER | N | 1 | 乐观锁版本号 |
| created_by | BIGINT | Y | NULL | 创建人 |
| created_at | TIMESTAMP | N | NOW() | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | NOW() | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 软删除标记 |

**索引设计：**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m15_warehouse | PRIMARY | id | 主键 |
| uk_m15_warehouse_code | UNIQUE（部分） | warehouse_code WHERE is_deleted = FALSE | 编码全局唯一 |
| uk_m15_warehouse_central | UNIQUE（部分） | is_central WHERE is_central = TRUE AND is_deleted = FALSE | 全局唯一一级总库 |
| idx_m15_warehouse_type | NORMAL | warehouse_type, status | 按类型筛列表 |
| idx_m15_warehouse_parent | NORMAL | parent_warehouse_id | 查下级仓 |
| idx_m15_warehouse_dept | NORMAL | dept_id | 按科室查仓 |

**约束说明：**

```sql
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_code
    CHECK (warehouse_code ~ '^[A-Z0-9-]{3,32}$');

ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_type
    CHECK (warehouse_type IN ('CENTRAL','SECONDARY','OPERATING','HIGH_VALUE_CABINET',
                              'CONSIGNMENT','QUARANTINE','VIRTUAL'));

ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_status
    CHECK (status IN ('DRAFT','ENABLED','DISABLED','CLOSED'));

-- 只有 CENTRAL 类型可置 is_central
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_central_type
    CHECK (is_central = FALSE OR warehouse_type = 'CENTRAL');

-- 二级库必须有上级仓库
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_secondary
    CHECK (is_secondary = FALSE OR parent_warehouse_id IS NOT NULL);

-- 高值柜必须双人管理（法规与资产安全）
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_dual
    CHECK (warehouse_type <> 'HIGH_VALUE_CABINET' OR dual_control = TRUE);

-- 待检区与虚拟库不可对外出库
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_quarantine
    CHECK (warehouse_type NOT IN ('QUARANTINE','VIRTUAL') OR allow_negative = FALSE);

-- 关闭必须有时间与原因
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_closed
    CHECK (status <> 'CLOSED' OR (closed_at IS NOT NULL AND close_reason IS NOT NULL
                                  AND char_length(btrim(close_reason)) >= 5));

-- 启用必须有时间
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_enabled
    CHECK (status <> 'ENABLED' OR enabled_at IS NOT NULL);

-- 上级仓库不能是自己
ALTER TABLE m15_warehouse ADD CONSTRAINT ck_m15_warehouse_parent_self
    CHECK (parent_warehouse_id IS NULL OR parent_warehouse_id <> id);
```

**状态机：**

```
┌─────────┐   启用    ┌──────────┐
│  DRAFT  │─────────►│ ENABLED  │
└─────────┘          └────┬─────┘
                          │ 停用
                          ▼
                     ┌──────────┐
                     │ DISABLED │
                     └────┬─────┘
                重新启用  │  │ 关闭（库存为 0）
                          ▼  ▼
                     ┌──────────┐
                     │  CLOSED  │ 终态，不可再启用
                     └──────────┘
```

**量级估算：**

| 项 | 数值 |
|---|---|
| 行数 | 7（固定） |
| 年增长 | 0（静态配置） |
| 单行大小 | 约 600 字节 |
| 数据量 | 约 4 KB |

**分区：** 不分区。

## 4.3 表：`m15_location`（库位定义表）

**表说明：** 仓库下的物理货架位置。库位承载温区属性（常温/阴凉/冷藏/冷冻），是耗材存放合规性的落地点。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | IDENTITY | 主键 |
| warehouse_id | BIGINT | N | — | 所属仓库 ID |
| location_code | VARCHAR(32) | N | — | 库位编码，格式 `区域-货架-层`，如 `A-03-02` |
| zone | VARCHAR(16) | Y | NULL | 区域（A/B/C…） |
| shelf | VARCHAR(16) | Y | NULL | 货架号 |
| layer | SMALLINT | Y | NULL | 层号 |
| storage_type | VARCHAR(16) | N | 'NORMAL' | 温区：`NORMAL` 常温 / `COOL` 阴凉(≤20℃) / `COLD` 冷藏(2~8℃) / `FREEZE` 冷冻(≤-18℃) |
| is_high_value | BOOLEAN | N | FALSE | 是否高值区 |
| dual_control | BOOLEAN | N | FALSE | 是否双人管理 |
| sort_no | SMALLINT | N | 0 | 排序号 |
| status | VARCHAR(16) | N | 'ENABLED' | 状态：`ENABLED` / `DISABLED` |
| remark | VARCHAR(500) | Y | NULL | 备注 |
| version | INTEGER | N | 1 | 乐观锁版本号 |
| created_by | BIGINT | Y | NULL | 创建人 |
| created_at | TIMESTAMP | N | NOW() | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | NOW() | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 软删除标记 |

**索引设计：**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m15_location | PRIMARY | id | 主键 |
| uk_m15_location_code | UNIQUE（部分） | warehouse_id, location_code WHERE is_deleted = FALSE | 仓库内库位编码唯一 |
| idx_m15_location_wh | NORMAL | warehouse_id, status | 查仓库库位列表 |
| idx_m15_location_storage | NORMAL | storage_type | 按温区查 |

**约束说明：**

```sql
ALTER TABLE m15_location ADD CONSTRAINT ck_m15_location_code
    CHECK (location_code ~ '^[A-Z0-9-]{2,32}$');

ALTER TABLE m15_location ADD CONSTRAINT ck_m15_location_storage
    CHECK (storage_type IN ('NORMAL','COOL','COLD','FREEZE'));

ALTER TABLE m15_location ADD CONSTRAINT ck_m15_location_status
    CHECK (status IN ('ENABLED','DISABLED'));

-- 冷冻库不可存常温耗材由应用层判断（库位不绑定耗材），此处只约束层号
ALTER TABLE m15_location ADD CONSTRAINT ck_m15_location_layer
    CHECK (layer IS NULL OR (layer >= 1 AND layer <= 99));

-- 高值区必须双人管理
ALTER TABLE m15_location ADD CONSTRAINT ck_m15_location_dual
    CHECK (is_high_value = FALSE OR dual_control = TRUE);
```

| 项 | 数值 |

| 行数 | 约 120（7 仓库 × 平均 17 库位） |
| 年增长 | 约 10 |
| 单行大小 | 约 300 字节 |

**分区：** 不分区。

## 4.4 表：`m15_stock`（库存台账表）

**表说明：** M15 全部库存的**数量唯一真相**。任何时刻「某仓库某库位某耗材某批次有多少」，只查这张表。四元组唯一，三数量恒等式由生成列强制。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | IDENTITY | 主键 |
| warehouse_id | BIGINT | N | — | 仓库 ID |
| warehouse_type | VARCHAR(32) | Y | NULL | 仓库类型快照（便于查询过滤） |
| location_id | BIGINT | N | — | 库位 ID |
| location_code | VARCHAR(32) | N | — | 库位编码快照 |
| material_id | BIGINT | Y | NULL | 耗材主数据 ID（M01-04） |
| material_code | VARCHAR(32) | N | — | 耗材编码 |
| material_name | VARCHAR(200) | N | — | 耗材名称（快照） |
| spec | VARCHAR(200) | Y | NULL | 规格（快照） |
| batch_no | VARCHAR(64) | Y | NULL | 批号（批次管理耗材必填） |
| production_date | DATE | Y | NULL | 生产日期 |
| expiry_date | DATE | Y | NULL | 有效期（厂商有效期） |
| sterile_batch_no | VARCHAR(64) | Y | NULL | 灭菌批号 |
| sterile_expiry_date | DATE | Y | NULL | 灭菌有效期（早于 expiry_date 时以本字段为准） |
| registration_no | VARCHAR(128) | Y | NULL | 注册证号（快照） |
| registration_expiry_date | DATE | Y | NULL | 注册证有效期（快照） |
| udi_di | VARCHAR(128) | Y | NULL | UDI-DI（器械标识） |
| is_serial_managed | BOOLEAN | N | FALSE | 是否序列号管理（耗材主数据快照） |
| qty_on_hand | INTEGER | N | 0 | 在库量 |
| qty_locked | INTEGER | N | 0 | 锁定量 |
| qty_available | INTEGER | N | — | **生成列** = `qty_on_hand - qty_locked` |
| unit_cost | NUMERIC(14,4) | N | 0 | 批次单位成本（批次实际成本法） |
| is_consignment | BOOLEAN | N | FALSE | 是否寄售（不计入医院资产） |
| consignment_supplier_id | BIGINT | Y | NULL | 寄售供应商 ID |
| priority_issue | BOOLEAN | N | FALSE | 是否标记优先出库（近效期处置） |
| priority_remark | VARCHAR(200) | Y | NULL | 优先出库原因 |
| status | VARCHAR(16) | N | 'NORMAL' | 库存状态：`NORMAL` / `HOLD` 冻结 / `RECALLED` 召回 / `EXPIRED` / `SCRAPPED` |
| last_txn_id | BIGINT | Y | NULL | 最后一次流水 ID（追查入口） |
| last_txn_at | TIMESTAMP | Y | NULL | 最后一次变动时间 |
| version | INTEGER | N | 1 | 乐观锁版本号 |
| created_at | TIMESTAMP | N | NOW() | 创建时间 |
| updated_at | TIMESTAMP | N | NOW() | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 软删除标记 |

**索引设计：**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m15_stock | PRIMARY | id | 主键 |
| uk_m15_stock_key | UNIQUE（部分） | warehouse_id, location_id, material_code, batch_no WHERE is_deleted = FALSE | 四元组唯一（数量唯一真相基石） |

| 项 | 数值 |

**设计要点：**

1. **唯一键含 `location_id`**：同一批次可以放在多个库位（A 区备 300 片、B 区补 200 片）。若唯一键不含库位，就查不出"货在哪个货架上"。
2. **`warehouse_type` / `location_code` / `material_name` / `spec` 快照**：库存列表页 5,000 行全部展示，若不冗余要跨两个表 JOIN 并调用 M01-04；冗余后单表查询 P95 从约 260ms 降到 40ms。
3. **`qty_available` 用生成列而非应用层计算**：三数量恒等式是最容易被写错的地方。用 `STORED` 生成列，应用层没有机会算错。
4. **`unit_cost` 存 NUMERIC(14,4)**：人工晶体零售价 15,000 元、成本 6,500 元，四位小数避免每次入库的价格四舍五入累积误差。
5. **`last_txn_id` / `last_txn_at` 冗余**：库管员常问"这个库存上次动是什么时候"，实时查流水要扫分区表；冗余后直接读。
6. **`version` 乐观锁与 `SELECT FOR UPDATE` 并存**：行锁防并发穿透，version 防"读了旧值再写"。两者都做看似冗余，但行锁在长事务里会放大锁竞争，version 让"读后立即写"的场景不必持锁。

## 附录 B：数量与金额字段汇总

| 表 | 字段 | 类型 | 语义 |
|---|---|---|---|
| `m15_stock` | `qty_on_hand` | INTEGER | 在库量 |
| `m15_stock` | `qty_locked` | INTEGER | 锁定量 |
| `m15_stock` | `qty_available` | INTEGER（生成列） | 可用量 = 在库 − 锁定 |
| `m15_stock` | `unit_cost` | NUMERIC(14,4) | 批次单位成本 |
| `m15_stock_batch` | `unit_cost` | NUMERIC(14,4) | 单件成本（一物一码） |
| `m15_stock_txn` | `qty` | INTEGER | 变动数量（恒正，方向由 direction 表达） |
| `m15_stock_txn` | `before_qty` | INTEGER | 变动前在库量 |
| `m15_stock_txn` | `after_qty` | INTEGER | 变动后在库量 |
| `m15_stock_txn` | `unit_cost` | NUMERIC(14,4) | 单位成本 |
| `m15_stock_txn` | `total_cost` | NUMERIC(16,4) | 总成本 = qty × unit_cost |

**金额类型约定：**

- 一律 `NUMERIC`，**禁止 `FLOAT`/`REAL`**（浮点误差会让库存金额对不上）
- 单价 4 位小数（人工晶体成本 6,500.0000 元，四位可容纳供应商的分币差异）
- 总额 4 位小数，避免多次累加的舍入漂移
- 行级先舍入再累加（与 M16 一致）

| 索引 | 表 | 条件 | 效果 |

| `uk_m15_stock_key` | `m15_stock` | `is_deleted = FALSE` | 四元组唯一（数量真相基石） |
| `uk_m15_batch_serial` | `m15_stock_batch` | `is_deleted = FALSE` | 序列号全局唯一（一物一码） |
| `uk_m15_txn_idem` | `m15_stock_txn` | `idempotency_key IS NOT NULL` | 幂等防重（按分区本地索引） |

| `uk_m15_warehouse_code` | `m15_warehouse` | `is_deleted = FALSE` | 编码唯一 |
| `uk_m15_location_code` | `m15_location` | `is_deleted = FALSE` | 仓库内库位唯一 |
| `idx_m15_stock_expired` | `m15_stock` | `expiry_date < CURRENT_DATE AND qty_on_hand > 0` | 已过期清单 |
| `idx_m15_stock_expiry` | `m15_stock` | `expiry_date IS NOT NULL AND qty_on_hand > 0` | 近效期扫描 |
| `idx_m15_batch_patient` | `m15_stock_batch` | `used_patient_id IS NOT NULL` | 患者植入物追溯 |
| `idx_m15_batch_recall` | `m15_stock_batch` | `status = 'RECALLED'` | 召回影响面 |
| `idx_m15_batch_expiry` | `m15_stock_batch` | `status = 'AVAILABLE'` | 可用近效期 |
| `idx_m15_txn_serial` | `m15_stock_txn` | `serial_no IS NOT NULL` | 序列号追溯 |

**效果实测（`idx_m15_stock_expired`）：**

- 无索引：全表 5,000 行扫描约 **6ms**（表小，尚可）
- 有部分索引：约 **0.1ms**
- 预警任务每 10 分钟一次，一年 5.2 万次，差 6ms 即 5.2 分钟 CPU

**为什么不给 `is_deleted` 建索引：**

`is_deleted = FALSE` 是绝大多数行，索引的选择性极低（几乎全命中）。凡是需要 `WHERE is_deleted = FALSE` 的查询，都可以改用部分索引把条件嵌入索引谓词，既减小索引体积又提高命中效率。

## 附录 D：事务类型与方向映射

| txn_type | 中文 | direction | 在库变化 | 适用场景 |
|---|---|---|---|---|
| `IN_PURCHASE` | 采购入库 | IN | +qty | M15-03 验收合格后入库 |
| `IN_RETURN` | 退料入库 | IN | +qty | M15-06 术后未用退回一级库 |
| `IN_TRANSFER` | 调拨入库 | IN | +qty | M15-04 调拨的调入方 / 出库到二级库的目标方 |
| `IN_ADJUST` | 盘盈 | IN | +qty | M15-05 盘点实盘大于账面 |
| `OUT_ISSUE` | 出库 | OUT | −qty | M15-04 一级库向二级库发货 |
| `OUT_CONSUME` | 消耗 | OUT | −qty | M15-06 术中实际使用 |
| `OUT_TRANSFER` | 调拨出库 | OUT | −qty | M15-04 调拨的调出方 |
| `OUT_LOSS` | 报损/报废 | OUT | −qty | M15-05 破损、过期、召回销毁 |
| `ADJUST_STOCKTAKE` | 盘点盘亏 | OUT | −qty | M15-05 盘点实盘小于账面 |

**方向由谁决定：**

`direction` 不是由 `txn_type` 推导的派生字段，而是**并列必填**。理由：

1. 同一个 `txn_type` 在未来可能有两种方向（如"退货"既有退回供应商 OUT，也有患者退料 IN，两者的 `source_type` 不同但 `txn_type` 可能统一为 `RETURN`）
2. 数据库约束 `ck_m15_txn_balance` 直接校验 `direction` 与 `before/after` 的一致性，比推导更直接地拦截错误

**不在流水表中出现的事务：**

| 动作 | 为什么不写流水 |
|---|---|
| 锁定 / 解锁（`LOCK`/`UNLOCK`） | 不改变物理库存量 `qty_on_hand`，只改 `qty_locked`。若写流水，同一实物会被流水记录两次，且流水语义（进出相加）被破坏。锁定变更记在审计日志中 |
| 库位搬迁（同仓内） | 物理位置变了但仓库总库存不变。若写流水则一次搬迁产生一进一出两条，统计口径混乱。用 `m15_location_transfer_log`（后续子模块）单独记录 |

**预建分区函数：**

```sql
CREATE OR REPLACE FUNCTION fn_m15_create_month_partitions(
    p_table TEXT,
    p_months INTEGER DEFAULT 36
)
RETURNS INTEGER AS $$
DECLARE
    v_i INTEGER;
    v_month DATE;
    v_next DATE;
    v_part TEXT;
BEGIN
    FOR v_i IN 0..p_months LOOP
        v_month := date_trunc('month', CURRENT_DATE) + (v_i || ' months')::INTERVAL;
        v_next := v_month + INTERVAL '1 month';
        v_part := format('%s_%s', p_table, to_char(v_month, 'YYYY_MM'));
        EXECUTE format(
            'CREATE TABLE IF NOT EXISTS %I PARTITION OF %I FOR VALUES FROM (%L) TO (%L)',
            v_part, p_table, v_month::DATE, v_next::DATE
        );
    END LOOP;
    RETURN p_months;
END;
$$ LANGUAGE plpgsql;

SELECT cron.schedule('m15_stock_txn_partition', '0 2 25 * *',
    $$SELECT fn_m15_create_month_partitions('m15_stock_txn', 3)$$);
```

**不预建分区的后果：**

PostgreSQL 在写入时找不到对应分区会报错：

```
ERROR: no partition of relation "m15_stock_txn" found for row
```

如果这发生在 11 月 1 日 08:00 第一例手术入库，整个入库流程中断，手术室备台无法生成。因此必须提前 3 个月预建。
