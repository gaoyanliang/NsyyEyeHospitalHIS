## 1. 模块概述

### 1.1 模块定位

M15-06 回答三个问题：**这台手术备了哪些耗材、实际用了哪些、没用的怎么退**。

它是 M15 物资管理链路的**末端**，也是物资数据与医疗数据交汇的地方：

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                          M15 物资管理链路（自前向后）                          │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  M15-03 采购入库 ──► M15-01 一级库台账 ──► M15-04 出库 ──► M15-06 二级库      │
│                                                          （手术室）           │
│                                                             │                │
│                                              ┌──────────────┼──────────────┐ │
│                                              ▼              ▼              ▼ │
│                                         备台登记        术中消耗       术后退料 │
│                                       （术前 1 天）   （手术进行中）   （术毕清点）│
│                                              │              │              │ │
│                                              └──────────────┼──────────────┘ │
│                                                             ▼                │
│                                          ┌──────────────────────────────┐    │
│                                          │ 消耗结算（→ M16-01 计费）      │    │
│                                          │ 成本归集（→ M17）             │    │
│                                          │ 植入物登记（→ M15-07）         │    │
│                                          │ 消耗上报（→ M06-06 U-10）      │    │
│                                          └──────────────────────────────┘    │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

**一句话职责：** M15-06 是手术室二级库的"记账员"——备台时记下"领了什么放在哪"，术中记下"用了什么给谁用"，术毕记下"剩什么怎么处理"，最后把消耗推给计费与成本。

### 1.2 为什么手术室二级库与消耗独立成子模块

| # | 理由 | 展开 |
|---|---|---|
| **1** | **出库 ≠ 消耗**，两者在时间、责任人、库存变化上完全不同 | M15-04 出库是「一级库 → 二级库」，术前 1 天由库管员完成，库存从总库减少；M15-06 消耗是「二级库 → 患者」，术中由器械护士完成，库存从二级库减少。若合并成一张单，备台 50 项、实耗 38 项、退回 12 项，一张表既说不清「备了没用」也说不清「备了坏了」 |
| **2** | **手术室二级库是独立库房形态** | 一级库按「货架/库位」管理，二级库按「术间/备台车/高值柜」管理；一级库由库管员管，二级库由器械护士管；一级库盘点按月，二级库按台清点 |
| **3** | **消耗数据是计费与成本的唯一来源** | 患者账单里「人工晶体 8,600 元」这个数字，只能来自 M15-06 的消耗记录。若 M15-06 只做库存不做计费关联，M16 就必须自己去猜「这台手术用了哪些耗材」 |
| **4** | **备台齐套率与退料率直接决定手术能否按时开台** | 术前备台 50 项缺 1 项（如 +21.0D 晶体），手术就得推迟。M06-06 的「材料退回率 ≥90%」指标直接依赖本子模块的「备台未用退回」数据 |
| **5** | **法规要求可追溯** | 《医疗器械监督管理条例》要求高值耗材「一物一码」可追溯到患者。追溯的最后一环就是本子模块的消耗记录（哪一片晶体给了哪个患者） |

### 1.3 与相邻子模块的分工

| 子模块 | 负责 | M15-06 不负责 |
|---|---|---|
| M15-01 物资仓库与库存台账 | 一级库台账、批次、流水（唯一真相源） | 不改一级库台账，只通过接口扣减 |
| M15-02 耗材库存分配与 UDI 管理 | FEFO 分配、序列号锁定、UDI 解析 | 不重复做分配算法，直接调 P-01 |
| M15-03 采购与入库 | 采购、验收、入库 | 不涉及采购 |
| M15-04 出库与二级库 | 出库单、调拨、二级库台账写入、交接 | 不做术中消耗与退料 |
| **M15-06（本模块）** | **备台登记、术中消耗、术后退料、消耗结算、成本归集** | — |
| M15-07 植入物追溯与召回 | 植入物使用登记、患者追溯、召回影响分析 | 消耗记录由本模块产生，追溯由 M15-07 展开 |

### 1.4 概念辨析

| 概念 A | 概念 B | 差异 |
|---|---|---|
| **出库** | **消耗** | 出库 = 库房 → 二级库（库存总量不变，只是位置变了）；消耗 = 二级库 → 患者（库存真正减少，产生成本） |
| **备台** | **消耗** | 备台是"预备"，可以没用；消耗是"实际用"，一定有用 |
| **退料** | **退货** | 退料 = 二级库 → 一级库（未用耗材回库）；退货 = 医院 → 供应商（M15-03 采购退货） |
| **报损** | **盘亏** | 报损是二级库发现破损主动报废（有实物、有照片）；盘亏是盘点发现账实不符（无实物、原因不明） |
| **计费消耗** | **成本消耗** | 计费 = 向患者收多少钱（零售价）；成本 = 医院花了多少钱（采购价）。同一片晶体可能「计费 8,600 / 成本 6,500」 |
| **消耗记录** | **植入物登记** | 消耗记录是「用了什么」（M15-06）；植入物登记是「装到哪个患者身上、序列号多少」（M15-07）。普通耗材只有消耗记录，高值植入物两者都有 |

## 2. 业务范围与边界

### 2.1 范围内

1. **手术备台登记**：按手术台次（`schedule_id`）登记预计使用的耗材清单，含计划数量与实际领用数量

8. **消耗成本归集**：将消耗记录推送 M17 财务

## 3. 业务模型

### 3.1 四层单据模型

```
┌────────────────────────────────────────────────────────────────────────┐
│ 第 1 层：出库单（M15-04）                                                │
│   一级库 → 二级库。术前 1 天，库管员操作                                  │
│   状态：DRAFT → SUBMITTED → APPROVED → ISSUED → RECEIVED               │
└────────────────────────────┬───────────────────────────────────────────┘
                             │ 签收（RECEIVED）
                             ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 第 2 层：备台单（M15-06，本模块）                                        │
│   按台次登记"本台手术准备了哪些耗材"。器械护士操作                         │
│   状态：DRAFT → PENDING → READY → IN_USE → COMPLETED                    │
└────────────────────────────┬───────────────────────────────────────────┘
                             │ 术中实际使用
                             ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 第 3 层：消耗记录（M15-06）                                              │
│   一条记录 = 一次消耗（一片晶体、一包缝线、一支粘弹剂）                    │
│   状态：DRAFT → CONFIRMED → BILLED → SETTLED                            │
└────────────────────────────┬───────────────────────────────────────────┘
                             │ 术毕核对
                             ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 第 4 层：退料单 / 报损单（M15-06）                                       │
│   未使用的退回一级库；破损的报废                                          │
│   退料：DRAFT → SUBMITTED → RECEIVED（一级库确认）                       │
│   报损：DRAFT → SUBMITTED → APPROVED → CONFIRMED                        │
└────────────────────────────────────────────────────────────────────────┘
```

**为什么四层分开：**

- **出库单是物流动作**（货从总库到了手术室），**备台单是准备动作**（这台手术要用哪些），**消耗记录是事实**（实际用了什么），**退料是纠正**（没用的回库）。四件事的责任人与时点都不同。
- 出库单在 M15-04 已定稿，本模块不重复，只是通过 `issue_id` 引用。
- 备台单必须独立，因为**一单出库可能服务多台手术**（周一早上一次性领本周用量），而备台单一定是**一台手术一份**。

### 3.2 备台单状态机（5 态）

```
        ┌─────────┐  提交   ┌──────────┐  齐套确认  ┌─────────┐
        │  DRAFT  │ ─────► │ PENDING  │ ────────► │  READY  │
        └─────────┘         └──────────┘           └────┬────┘
             │                    │                     │
       取消  │              取消  │               开始使用 │
             ▼                    ▼                     ▼
        ┌────────────────────────────┐          ┌─────────┐
        │        CANCELLED           │          │ IN_USE  │
        └────────────────────────────┘          └────┬────┘
                                                      │ 术毕
                                                      ▼
                                                 ┌──────────┐
                                                 │COMPLETED │（终态）
                                                 └──────────┘
```

**关键设计：`PENDING` 与 `READY` 分开**

- `PENDING` = 已提交备台清单，但耗材还没到齐（可能在等出库签收）
- `READY` = 全部耗材到位，可以开台

**为什么必须分：** 手术能否按时开台的判断依据是「备台单是否 READY」而不是「备台单是否提交」。若合并成一个状态，手术室看板无法区分「已提交但缺 3 项」与「已提交且齐备」。

### 3.3 消耗记录状态机（4 态）

```
        ┌─────────┐  确认   ┌───────────┐  推送计费  ┌────────┐  结算  ┌─────────┐
        │  DRAFT  │ ─────► │ CONFIRMED │ ────────► │ BILLED │ ─────► │ SETTLED │
        └─────────┘        └───────────┘            └────────┘        └─────────┘
             │                   │
        作废 │              作废 │
             ▼                   ▼
        ┌────────────────────────────┐
        │        CANCELLED           │（终态）
        └────────────────────────────┘
```

**为什么 `BILLED` 与 `SETTLED` 分开：**

- `BILLED` = 已推送 M16-01 生成计费项，但患者还没结账
- `SETTLED` = 患者已结账

若合并，退费时无法区分「计费项已生成但未收费」（可直接作废）与「已收费」（需走退费流程）。

### 3.4 数量恒等式

本模块的核心数量关系：

```
备台数量（planned_qty）
   ├── 实际消耗（consumed_qty）
   ├── 退回数量（returned_qty）
   └── 报损数量（damaged_qty）

约束：consumed_qty + returned_qty + damaged_qty + remaining_qty = planned_qty
其中：remaining_qty = 二级库中仍未处理的备台量（术毕应为 0）
```

**三级校验（数据库层强制）：**

| 层级 | 约束 | 说明 |
|---|---|---|
| L1 单行 | `consumed_qty <= planned_qty` | 单项消耗不超过备台量 |
| L2 单行 | `consumed_qty + returned_qty + damaged_qty + remaining_qty = planned_qty` | 五项恒等式 |
| L3 汇总 | 备台单 `total_planned >= total_consumed + total_returned + total_damaged` | 跨明细汇总 |

### 3.5 手术备台模型

**备台清单的来源（三个渠道）：**

1. **手术套包**（首选）：M01-04 `mdm_surgery_kit` + `mdm_surgery_kit_detail` 按术式自动带出
2. **历史参考**：同术式最近 10 台手术的实际消耗（取中位数）
3. **手工添加**：器械护士按需添加

**为什么以套包为主：** 眼科手术标准化程度极高（白内障超声乳化、玻璃体腔注药），手术套包定义清晰。按套包带出可把备台录入时间从 8 分钟降到 1 分钟以内。

**备台清单的耗材分类：**

| 分类 | 说明 | 数量特征 |
|---|---|---|
| 手术包（`SURGERY_PACK`） | 一次性手术包，按套领用 | 1~2 套 |
| 植入物（`IMPLANT`） | 人工晶体、引流阀等，一物一码 | 1~2 件 |
| 高值耗材（`HIGH_VALUE`） | 粘弹剂、生物羊膜、缝线 | 2~8 件 |
| 普通耗材（`NORMAL`） | 纱布、棉片、注射器 | 10~30 件 |
| 药品类耗材（`DRUG_LIKE`） | 灌注液、消毒液（归 M14 管库存，本模块只记录消耗） | 2~5 件 |

### 3.6 术中消耗登记模型

**三种登记方式：**

| 方式 | 适用 | 耗时 | 准确率 |
|---|---|---|---|
| **扫码消耗** | 有一物一码的耗材（晶体、引流阀） | 3~5 秒 | 100% |
| **备台勾选** | 备台清单中已有的普通耗材 | 1~2 秒 | 高 |
| **手工添加** | 备台未备、术中临时需要 | 15~30 秒 | 中（需审核） |

**为什么必须有扫码：** 人工勾选容易出现「勾了但实际没用」或「用了但没勾」。人工晶体单价 3,000~15,000 元，勾错一件既影响计费也影响追溯。

**手工添加的管控：**

- 术中临时添加必须填原因（≥5 字）
- 单价 ≥3,000 元的临时添加需巡回护士确认
- 术后 24 小时内，手工添加项占比 >20% 触发护士长复核

### 3.7 消耗与计费的衔接

```
消耗记录（CONFIRMED）
    │
    │ ① 按 M01-04 charge_rel 找到收费项目
    │ ② 按 charge_qty_factor 换算数量
    ▼
计费明细 ──► M16-01（生成结算单明细行）
    │
    │ ③ 回写 billed_at + billing_item_id
    ▼
消耗记录（BILLED）
    │
    │ ④ 患者结账 → M16 回调
    ▼
消耗记录（SETTLED）
```

**关键设计：消耗不以「金额」为权威，以「数量」为权威**

- 消耗记录存的是 `consumed_qty` 与 `unit_cost`（成本价）
- 计费金额由 M16-01 按 `mdm_material_charge_rel` 关联的收费项目价格计算
- 理由：耗材成本价与零售价调价周期不同，若消耗记录存「计费金额」，调价后历史记录与账单就会不一致

### 3.8 退料与报损模型

**退料（Return to Primary）：**

```
二级库 → 一级库
条件：耗材未使用、包装完好、批次可追溯
流程：器械护士发起 → 巡回护士确认 → 库管员签收入库（M15-04 执行库存增加）
```

**报损（Damage Report）：**

```
二级库 → 报废
原因：破损 / 过期 / 灭菌失效 / 污染 / 丢失
流程：器械护士发起 → 护士长审批（≥5,000 元需科长）→ 库存扣减
```

**为什么退料与报损必须分开：**

退料是「还能用，还给库房」（库存总量不变，二级库减少一级库增加）；报损是「不能用了，销毁」（库存总量减少）。若合并成一张「二级库调整单」，财务就无法区分「退货成本为 0」与「报废成本 N 元」。

### 3.9 二级库盘点模型

**与一级库盘点的差异：**

| 维度 | 一级库盘点（M15-05） | 二级库盘点（本模块） |
|---|---|---|
| 频次 | 月度全面 + 每日循环 | **每台手术后台清点 + 每周全面** |
| 粒度 | 耗材 + 批次 + 库位 | 耗材 + 批次 + 术间 |
| 责任人 | 库管员 + 复核人 | 器械护士 + 巡回护士 |
| 冻结 | 需冻结出库 | 不冻结（手术不能停） |
| 差异处置 | 走盘点审批 → 调整单 | **当场确认**，异常才走审批 |

**每台手术后台清点：** 术后器械护士与巡回护士共同核对备台清单，勾选「已用/退回/报损/剩余」，剩余必须为 0 才能完成备台单。

### 3.10 消耗数据的三条去向

| 去向 | 接口 | 时机 | 失败处理 |
|---|---|---|---|
| **计费**（M16-01） | `POST /internal/v1/m16/settlements/{id}/charge` | 消耗确认后立即 | 补偿重试 10 次，失败进人工队列 |
| **成本**（M17） | `POST /internal/v1/m17/cost/consume` | 每日 02:00 批量 | 异步重试 5 次 |
| **植入物追溯**（M15-07） | `POST /internal/v1/m15/implant/usage` | 消耗确认后立即 | 补偿重试 10 次 |

**为什么计费必须即时、成本可以批量：**

- 计费即时：患者可能在术毕就去缴费窗口，若材料费未生成，收费员会漏收
- 成本批量：成本核算是月度工作，每日批量足够，且批量可降低 M17 压力

                "line_no": idx,

                "unit_cost": unit_cost,

                "is_implant": bool(brief.get("is_implant")),

                c.material_name,
                MAX(c.spec)                       AS spec,
                MAX(c.unit)                       AS unit,
                MAX(c.unit_cost)                  AS unit_cost,
                percentile_cont(0.5) WITHIN GROUP (ORDER BY r.sched_qty) AS median_qty,
                MAX(c.is_implant)                 AS is_implant,
                MAX(c.material_category)          AS material_category
            FROM (
                SELECT i.id,
                       SUM(r2.consumed_qty) AS sched_qty,
                       i.material_code, i.material_name, i.spec, i.unit,
                       i.unit_cost, i.is_implant, i.material_category

                JOIN m15_or_prepare_item i ON i.id = r2.prepare_item_id
                WHERE p2.operation_name = :opname

                  AND r2.is_deleted = FALSE
                GROUP BY i.id, i.material_code, i.material_name, i.spec, i.unit,
                         i.unit_cost, i.is_implant, i.material_category
            ) r
            JOIN m15_or_prepare_item c ON c.id = r.id
            GROUP BY c.material_code, c.material_name
            ORDER BY median_qty DESC
            LIMIT :lim
        """)

                "prepare_id": prepare_id,
                "item_count": 0,
                "items": [],
                "message": "该术式无历史数据，请按套包带出",
            }

        await db.execute(
            text("UPDATE m15_or_prepare_item SET is_deleted = TRUE WHERE prepare_id = :pid"),
            {"pid": prepare_id},
        )

        total = Decimal("0.00")
        line_rows = []
        for idx, r in enumerate(rows, start=1):
            qty = Decimal(str(r["median_qty"] or 1)).quantize(Decimal("1"))
            if qty <= 0:
                qty = Decimal("1")
            unit_cost = money4(r["unit_cost"])
            amount = money(unit_cost * qty)
            total += amount
            line_rows.append({
                "line_no": idx,
                "material_code": r["material_code"],
                "material_name": r["material_name"],
                "spec": r["spec"],
                "unit": r["unit"],
                "planned_qty": qty,
                "remaining_qty": qty,
                "unit_cost": unit_cost,
                "planned_amount": amount,
                "is_implant": bool(r["is_implant"]),
                "material_category": r["material_category"],
            })

        for row in line_rows:
            db.add(M15OrPrepareItem(prepare_id=prepare_id, **row))

        await db.execute(
            text("""
                UPDATE m15_or_prepare
                   SET item_count = :cnt,
                       total_planned_amount = :amt,
                       updated_at = CURRENT_TIMESTAMP
                 WHERE id = :pid
            """),
            {"cnt": len(line_rows), "amt": money(total), "pid": prepare_id},
        )
        await db.commit()

        return {
            "prepare_id": prepare_id,
            "item_count": len(line_rows),
            "total_planned_amount": float(money(total)),
            "items": line_rows,
        }

    @classmethod

    @classmethod
    async def check_shortage(cls, db, prepare_id: int, user) -> dict:
        """缺货检查。"""
        sql = text("""
            SELECT
                i.material_code,
                i.material_name,
                i.spec,
                i.unit,
                i.remaining_qty                       AS required_qty,
                COALESCE(SUM(k.qty_on_hand - k.qty_locked), 0) AS available_qty
            FROM m15_or_prepare_item i
            LEFT JOIN m15_sec_stock k
                   ON k.material_code = i.material_code AND k.is_deleted = FALSE
            WHERE i.prepare_id = :pid AND i.is_deleted = FALSE
            GROUP BY i.material_code, i.material_name, i.spec, i.unit, i.remaining_qty
            HAVING COALESCE(SUM(k.qty_on_hand - k.qty_locked), 0) < i.remaining_qty
        """)
        rows = (await db.execute(sql, {"pid": prepare_id})).mappings().all()
        items = [
            {
                "material_code": r["material_code"],
                "material_name": r["material_name"],
                "spec": r["spec"],
                "unit": r["unit"],
                "required_qty": float(r["required_qty"]),
                "available_qty": float(r["available_qty"]),
                "shortage_qty": float(r["required_qty"]) - float(r["available_qty"]),
            }
            for r in rows
        ]
        return {"prepare_id": prepare_id, "items": items, "total": len(items)}

    @classmethod
    async def _get_prepare(cls, db, prepare_id: int, for_update: bool = False) -> dict:
        """加载备台单（含台次信息）。可选加锁。"""
        lock_sql = " FOR UPDATE OF p" if for_update else ""
        sql = text("""
            SELECT
                p.*,
                s.schedule_no    AS schedule_no,
                s.patient_name   AS patient_name,
                s.eye_side       AS eye_side,
                s.operation_name AS operation_name,
                s.room_code      AS room_code,
                s.surgery_start_at AS schedule_start_at
            FROM m15_or_prepare p
            LEFT JOIN m06_or_schedule s ON s.id = p.schedule_id
            WHERE p.id = :pid AND p.is_deleted = FALSE
        """ + lock_sql)
        row = (await db.execute(sql, {"pid": prepare_id})).mappings().first()
        if not row:
            raise BizException("1506002", "备台单不存在")
        return dict(row)

    @classmethod
    async def _sec_available(cls, db, material_code: str) -> float:
        """二级库可用量。"""
        sql = text("""
            SELECT COALESCE(SUM(qty_on_hand - qty_locked), 0) AS avail
            FROM m15_sec_stock
            WHERE material_code = :code AND is_deleted = FALSE
        """)
        return float((await db.execute(sql, {"code": material_code})).scalar_one())

    @classmethod
    async def _config_amount(cls, db, code: str, default: Decimal) -> Decimal:
        """读取金额类配置。"""
        sql = text("""
            SELECT param_value FROM m15_consume_config
            WHERE param_code = :code AND scope = 'GLOBAL' AND is_deleted = FALSE
            LIMIT 1
        """)
        val = (await db.execute(sql, {"code": code})).scalar()
        if val is None:
            return default
        try:
            return Decimal(str(val))
        except Exception:
            return default

    @classmethod
    async def _next_prepare_no(cls, db) -> str:
        """生成备台单号 PREP-YYYY-MMDD-NNNN。"""
        sql = text("""
            SELECT COUNT(*) + 1 AS seq FROM m15_or_prepare
            WHERE DATE(created_at) = CURRENT_DATE
        """)
        seq = (await db.execute(sql)).scalar_one()
        today = date.today()
        return "PREP-%04d-%02d%02d-%04d" % (today.year, today.month, today.day, seq)

    @classmethod
    async def list_records(cls, db, query, user) -> dict:
        """消耗记录列表。"""
        where = ["c.is_deleted = FALSE"]
        params = {}
        if query.schedule_id:
            where.append("c.schedule_id = :sid")
            params["sid"] = query.schedule_id
        if query.material_code:
            where.append("c.material_code = :mcode")
            params["mcode"] = query.material_code
        if query.status:
            where.append("c.status = :st")
            params["st"] = query.status
        if query.date_from:
            where.append("DATE(c.created_at) >= :d1")
            params["d1"] = query.date_from
        if query.date_to:
            where.append("DATE(c.created_at) <= :d2")
            params["d2"] = query.date_to

        where_sql = " AND ".join(where)
        count_sql = text("SELECT COUNT(*) FROM m15_or_consume c WHERE " + where_sql)
        total = (await db.execute(count_sql, params)).scalar_one()

        list_sql = text("""
            SELECT
                c.id, c.record_no, c.schedule_id, c.material_code, c.material_name,
                c.spec, c.unit, c.batch_no, c.serial_no, c.consumed_qty,
                c.unit_cost, c.consumed_amount, c.status, c.consume_type,
                c.created_at
            FROM m15_or_consume c
            WHERE """ + where_sql + """
            ORDER BY c.id DESC
            LIMIT :lim OFFSET :off
        """)
        params["lim"] = query.page_size
        params["off"] = (query.page - 1) * query.page_size
        rows = (await db.execute(list_sql, params)).mappings().all()
        pages = (total + query.page_size - 1) // query.page_size
        return {
            "items": [dict(r) for r in rows],
            "total": total,
            "page": query.page,
            "page_size": query.page_size,
            "pages": pages,
        }

                       SET consumed_qty = consumed_qty + :d,
                           remaining_qty = remaining_qty - :d,
                           updated_at = CURRENT_TIMESTAMP
                     WHERE id = :iid
                """),
                {"d": delta, "iid": item_id},
            )

    @classmethod
    async def confirm(cls, db, record_id: int, body, user) -> dict:
        """确认消耗（推送计费 + 植入物登记 + 库存扣减）。"""
        record = await cls._get_record(db, record_id, for_update=True)
        if record["status"] != "DRAFT":
            raise BizException("1506003", "消耗记录状态不允许此操作")

        # ① 手术是否结束检查（U-01）
        schedule = await ScheduleClient.get_schedule(record["schedule_id"])
        if schedule and schedule.get("status") in ("SCHEDULED", "CHECKED_IN", "IN_SURGERY"):
            raise BizException("1506013", "手术未结束不可确认消耗")

        # ② 生成消耗记录 → CONFIRMED
        await db.execute(
            text("""
                UPDATE m15_or_consume
                   SET status = 'CONFIRMED', confirmed_at = CURRENT_TIMESTAMP,
                       updated_at = CURRENT_TIMESTAMP
                 WHERE id = :rid
            """),
            {"rid": record_id},
        )
        await db.commit()

        # ③ 扣减二级库 + 一级库（U-04，补偿队列）
        stock_result = await cls._consume_sec_stock(db, record)
        if not stock_result["success"]:
            await cls._enqueue_compensation(db, "STOCK_CONSUME", record_id, stock_result["error"])

        # ④ 推送计费（U-09，补偿队列）
        billing_result = {"pushed": False}
        try:
            billing_result = await BillingClient.charge(
                schedule_id=record["schedule_id"],
                material_code=record["material_code"],
                quantity=record["consumed_qty"],
                unit_cost=record["unit_cost"],
                source="M15-06",
                source_id=record_id,
            )
            if billing_result.get("pushed"):
                await db.execute(
                    text("""
                        UPDATE m15_or_consume
                           SET status = 'BILLED', billing_item_id = :bid,
                               billed_amount = :amt, billed_at = CURRENT_TIMESTAMP,
                               updated_at = CURRENT_TIMESTAMP
                         WHERE id = :rid
                    """),
                    {
                        "bid": billing_result.get("billing_item_id"),
                        "amt": billing_result.get("billing_amount"),
                        "rid": record_id,
                    },
                )
                await db.commit()
        except Exception as exc:  # noqa: BLE001
            logger.warning("推送计费失败 record_id=%s: %s", record_id, exc)
            await cls._enqueue_compensation(db, "BILLING", record_id, str(exc))

        # ⑤ 植入物登记（U-08，补偿队列）
        implant_result = {"pushed": False}
        if record.get("is_implant"):
            try:
                implant_result = await ImplantClient.register_usage(
                    schedule_id=record["schedule_id"],
                    material_code=record["material_code"],
                    serial_no=record["serial_no"],
                    batch_no=record["batch_no"],
                    source="M15-06",
                    source_id=record_id,
                )
            except Exception as exc:  # noqa: BLE001
                logger.warning("植入物登记失败 record_id=%s: %s", record_id, exc)
                await cls._enqueue_compensation(db, "IMPLANT", record_id, str(exc))

        return {
            "record_id": record_id,
            "old_status": "DRAFT",
            "new_status": "BILLED" if billing_result.get("pushed") else "CONFIRMED",
            "consumed_qty": float(record["consumed_qty"]),
            "consumed_amount": float(record["consumed_amount"]),
            "billing": billing_result,
            "implant_usage": implant_result,
        }

    @classmethod
    async def _lock_sec_stock(cls, db, material_code: str, qty: Decimal) -> None:
        """锁定二级库库存（按 FEFO 顺序）。"""
        sql = text("""
            SELECT id, qty_on_hand, qty_locked FROM m15_sec_stock
            WHERE material_code = :code AND is_deleted = FALSE
              AND qty_on_hand - qty_locked > 0
            ORDER BY expiry_date NULLS LAST, id
            FOR UPDATE
        """)
        rows = (await db.execute(sql, {"code": material_code})).mappings().all()
        need = qty
        for r in rows:
            if need <= 0:
                break
            avail = Decimal(str(r["qty_on_hand"])) - Decimal(str(r["qty_locked"]))
            take = min(avail, need)
            if take <= 0:
                continue
            await db.execute(
                text("""
                    UPDATE m15_sec_stock
                       SET qty_locked = qty_locked + :q, updated_at = CURRENT_TIMESTAMP
                     WHERE id = :sid
                """),
                {"q": take, "sid": r["id"]},
            )
            need -= take
        if need > 0:
            raise BizException("1506026", "二级库库存不足")

    @classmethod
    async def _unlock_sec_stock(cls, db, material_code: str, qty: Decimal) -> None:
        """释放二级库锁定。"""
        sql = text("""
            SELECT id, qty_locked FROM m15_sec_stock
            WHERE material_code = :code AND qty_locked > 0 AND is_deleted = FALSE
            ORDER BY expiry_date NULLS LAST, id
            FOR UPDATE
        """)
        rows = (await db.execute(sql, {"code": material_code})).mappings().all()
        release = qty
        for r in rows:
            if release <= 0:
                break
            take = min(Decimal(str(r["qty_locked"])), release)
            await db.execute(
                text("""
                    UPDATE m15_sec_stock
                       SET qty_locked = qty_locked - :q, updated_at = CURRENT_TIMESTAMP
                     WHERE id = :sid
                """),
                {"q": take, "sid": r["id"]},
            )
            release -= take

    @classmethod
    async def _consume_sec_stock(cls, db, record: dict) -> dict:
        """扣减二级库并调用 M15-01 扣减一级库。"""
        try:
            # 二级库扣减：锁定 → 减少现存量
            await db.execute(
                text("""
                    UPDATE m15_sec_stock
                       SET qty_on_hand = qty_on_hand - :q,
                           qty_locked  = qty_locked - :q,
                           updated_at  = CURRENT_TIMESTAMP
                     WHERE material_code = :code
                       AND qty_locked >= :q
                       AND is_deleted = FALSE
                """),
                {"q": record["consumed_qty"], "code": record["material_code"]},
            )
            await db.commit()
        except Exception as exc:  # noqa: BLE001
            await db.rollback()
            return {"success": False, "error": str(exc)}

        # 一级库通过 M15-01 扣减（幂等键）
        try:
            idem = "CONSUME:%d" % record["id"]
            await StockClient.outbound(
                warehouse_id=record["warehouse_id"],
                material_code=record["material_code"],
                batch_no=record["batch_no"],
                qty=record["consumed_qty"],
                txn_type="OUT_CONSUME",
                source_type="M15-06",
                source_id=record["id"],
                idempotency_key=idem,
            )
        except Exception as exc:  # noqa: BLE001
            return {"success": False, "error": str(exc)}
        return {"success": True, "error": None}

    @classmethod
    async def _enqueue_compensation(cls, db, biz_type: str, source_id: int, error: str) -> None:
        """写入补偿队列。"""
        await db.execute(
            text("""
                INSERT INTO m15_consume_compensation
                    (biz_type, source_id, error_message, retry_count, status, created_at)
                VALUES (:bt, :sid, :err, 0, 'PENDING', CURRENT_TIMESTAMP)
            """),
            {"bt": biz_type, "sid": source_id, "err": error[:500]},
        )
        await db.commit()

    @classmethod
    async def _next_record_no(cls, db) -> str:
        """生成消耗单号 CSM-YYYY-MMDD-NNNN。"""
        sql = text("""
            SELECT COUNT(*) + 1 FROM m15_or_consume
            WHERE DATE(created_at) = CURRENT_DATE
        """)
        seq = (await db.execute(sql)).scalar_one()
        today = date.today()
        return "CSM-%04d-%02d%02d-%04d" % (today.year, today.month, today.day, seq)

        if prepare["status"] not in ("READY", "IN_USE", "COMPLETED"):
            raise BizException("1506003", "备台单状态不允许此操作")

        prepare_item_sql = text("""
            SELECT * FROM m15_or_prepare_item
            WHERE prepare_id = :pid AND material_code = :mcode AND is_deleted = FALSE
        """)
        item = (await db.execute(prepare_item_sql, {
            "pid": body.prepare_id, "mcode": body.material_code,
        })).mappings().first()
        if not item:
            raise BizException("1506018", "耗材不在备台清单中")

        if body.return_qty > remaining:
            raise BizException("1506022", "退料数量不能超过备台未用量")

        # 同批次不能同时退料与报损
        dup_sql = text("""
            SELECT COUNT(*) FROM m15_or_damage
            WHERE schedule_id = :sid AND material_code = :mcode
              AND batch_no = :batch AND status <> 'REJECTED' AND is_deleted = FALSE
        """)
        dup = (await db.execute(dup_sql, {
            "sid": prepare["schedule_id"], "mcode": body.material_code, "batch": body.batch_no,
        })).scalar_one()
        if dup > 0:
            raise BizException("1506025", "同一批次不能同时退料与报损")

        unit_cost = money4(item["unit_cost"])
        amount = money(unit_cost * body.return_qty)
        return_no = await cls._next_return_no(db)

        ret = M15OrReturn(
            return_no=return_no,
            prepare_id=body.prepare_id,
            schedule_id=prepare["schedule_id"],
            item_count=1,
            total_amount=amount,
            status="SUBMITTED",

            created_by=user["employee_id"],
            created_by_name=user["employee_name"],

        await db.flush()

            return_id=ret.id,
            line_no=1,
            material_code=body.material_code,
            material_name=item["material_name"],
            spec=item["spec"],
            unit=item["unit"],
            batch_no=body.batch_no,

                       remaining_qty = remaining_qty - :q,
                       updated_at = CURRENT_TIMESTAMP
                 WHERE id = :iid

        await db.commit()

            "return_id": ret.id,
            "return_no": return_no,
            "status": "SUBMITTED",
            "item_count": 1,
            "total_amount": float(amount),
        }

        if row["status"] != "SUBMITTED":
            raise BizException("1506023", "退料单状态不允许此操作")

            text("""
                UPDATE m15_or_return
                   SET status = 'RECEIVED', received_qty = :q,
                       received_at = CURRENT_TIMESTAMP, received_by = :uid,

class SecStockService:
    """二级库台账服务。"""

    @classmethod
    async def summary(cls, db, user) -> dict:
        """二级库汇总。"""
        sql = text("""
            SELECT
                location_code,
                COUNT(DISTINCT material_code) AS material_count,
                SUM(qty_on_hand)              AS total_on_hand,
                SUM(qty_locked)               AS total_locked,
                SUM(qty_on_hand - qty_locked) AS total_available,
                SUM(qty_on_hand * unit_cost)  AS total_amount
            FROM m15_sec_stock
            WHERE is_deleted = FALSE
            GROUP BY location_code
            ORDER BY location_code
        """)
        rows = (await db.execute(sql)).mappings().all()
        items = [
            {
                "location_code": r["location_code"],
                "material_count": r["material_count"],
                "total_on_hand": float(r["total_on_hand"] or 0),
                "total_locked": float(r["total_locked"] or 0),
                "total_available": float(r["total_available"] or 0),
                "total_amount": float(r["total_amount"] or 0),
            }
            for r in rows
        ]
        return {
            "items": items,
            "total_material_count": sum(x["material_count"] for x in items),
            "total_on_hand": round(sum(x["total_on_hand"] for x in items), 4),
            "total_available": round(sum(x["total_available"] for x in items), 4),
            "total_amount": round(sum(x["total_amount"] for x in items), 2),
        }

    @classmethod
    async def list_stock(cls, db, location_id, category, keyword, page, page_size, user) -> dict:

            params["lid"] = location_id
        if category:
            where.append("material_category = :cat")
            params["cat"] = category
        if keyword:
            where.append("(material_code LIKE :kw OR material_name LIKE :kw)")
            params["kw"] = "%" + keyword + "%"
        where_sql = " AND ".join(where)
        count_sql = text("SELECT COUNT(*) FROM m15_sec_stock WHERE " + where_sql)
        total = (await db.execute(count_sql, params)).scalar_one()
        list_sql = text("""
            SELECT id, location_code, material_code, material_name, spec, unit,
                   batch_no, qty_on_hand, qty_locked, (qty_on_hand - qty_locked) AS qty_available,
                   unit_cost, expiry_date
            FROM m15_sec_stock
            WHERE """ + where_sql + """
            ORDER BY material_code, expiry_date NULLS LAST
            LIMIT :lim OFFSET :off

### 6.7 专题：为什么备台单与消耗记录必须分开

**真实场景推演：**

手术室周一早上从一级库领了一大批耗材（出库单 E-001，共 200 项），用于本周 5 天共 60 台手术。周二上午 OP-12 白内障超声乳化，器械护士领了 30 项放在手术间备台车上。

**如果只有出库单没有备台单：**

1. **无法知道这 30 项是哪台手术的**——库管员只知道「出库了 200 项」，但「OP-12 用了哪几项」无从查起
2. **术中出现缺货无法预警**——不知道 OP-12 需要 +21.0D 晶体，无法提前发现二级库为 0
3. **成本无法归集到手术**——M17 需要「每台手术的耗材成本」，只有出库记录只能算到「这周一共花了多少」
4. **退料无法追溯**——术后剩下的耗材退回，但退的是哪台手术的备台量说不清

**如果只有备台单没有消耗记录：**

1. **无法区分「备了没用」与「备了用了」**——备台 30 项、实际用 12 项、剩 18 项，但哪 12 项用了？
2. **无法计费**——患者账单的材料费只能来自消耗记录
3. **无法追溯植入物**——「这一片晶体给了谁」必须有消耗记录

**四层单据各自的不可替代性：**

| 层 | 回答的问题 | 不可替代的原因 |
|---|---|---|
| 出库单 | 医院这周从总库领了多少？ | 库存总量变化的唯一依据（M15-01 流水） |
| **备台单** | 这台手术准备了哪些？准备了够不够？ | 齐套率、缺货预警、退料率的分母 |
| **消耗记录** | 这台手术实际用了什么？给谁用了？ | 计费、成本、植入物追溯的唯一来源 |
| 退料/报损单 | 没用/坏了的怎么处理？ | 库存准确性的校正 |

**合并的代价（以备台+消耗合并为例）：**

若做成一张 `m15_or_material` 表，每条记录包含 `planned_qty` 与 `consumed_qty`：

- **无法记录「备了但没用」的具体批次**：备台时是「+21.0D 晶体 1 片」，消耗时拿到的是「批次 B2609 序列号 SN-8829310」。合并后表里要么丢掉批次信息（无法追溯），要么备台时就强制指定批次（实际备台时还不知道用哪一批）
- **状态机冲突**：备台单是 `DRAFT → PENDING → READY → IN_USE → COMPLETED`；消耗记录是 `DRAFT → CONFIRMED → BILLED → SETTLED`。合并后一台手术 30 个明细各有各的计费状态，主单状态无法表达
- **计费粒度错位**：计费是按消耗记录推的（12 条），不是按备台项推的（30 条）。合并后需要区分「哪些行计费哪些不计费」

**结论：** 四层分开不是过度设计，而是每一层都对应一个**不可合并的业务语义**。合并任何两层都会失去一类数据。

                )
                logger.warning("补偿重试失败 id=%s retry=%s: %s", row["id"], retry, exc)
        await db.commit()

### 9.3 数据权限

```python
"""M15-06 数据权限注入。"""

from sqlalchemy import and_, or_

from app.core.permissions import has_permission

# 数据权限域
SCOPE_ALL = "ALL"
SCOPE_DEPT = "DEPT"
SCOPE_SELF = "SELF"


def resolve_consume_scope(user: dict) -> tuple:
    """解析用户的数据权限域。"""
    if has_permission(user, "m15:consume:all"):
        return SCOPE_ALL, "全部"
    if user.get("dept_type") in ("OPERATING", "MATERIAL"):
        return SCOPE_DEPT, "本科室"
    return SCOPE_SELF, "本人"


def apply_consume_scope(stmt, model, user: dict, domain: str = "DEPT"):
    """给查询语句注入数据权限过滤。"""
    scope, _ = resolve_consume_scope(user)
    if scope == SCOPE_ALL:
        return stmt
    if scope == SCOPE_DEPT:
        return stmt.where(model.dept_id == user["dept_id"])
    if scope == SCOPE_SELF:
        return stmt.where(
            or_(
                model.operator_id == user["employee_id"],
                model.created_by == user["employee_id"],
            )
        )
    return stmt.where(model.id == -1)
```

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 异常 | 处理 |
|---|---|---|
| 参数异常 | 参数校验失败 | 返回 400 + 具体字段 |
| 业务异常 | `BizException` | 返回对应错误码 |
| 依赖异常 | 上游超时/不可用 | 阻断或补偿（见 2.4） |
| 数据异常 | 数量不自洽/状态冲突 | 返回错误码 + 记录日志 |
| 并发异常 | 乐观锁冲突/死锁 | 重试 3 次，仍失败返回 `"1506003"` |
| 系统异常 | 未捕获异常 | 返回 500 + trace_id |

import logging

**三条敏感参数的政策来源与篡改后果：**

| 参数 | 政策来源 | 篡改后果 |
|---|---|---|
| `PREPARE_APPROVAL_AMOUNT` | 手术室物资管理规定 | 调高 → 大额备台无需审批，术中临时大量使用无管控 |
| `HIGH_VALUE_THRESHOLD` | 高值耗材管理制度 | 调低 → 全部耗材都要双人核对，护士工作量剧增导致敷衍；调高 → 真正的高值耗材无核对 |
| `MANUAL_ADD_LIMIT_RATIO` | 消耗登记规范 | 调高 → 手工添加激增，数据质量下降且无法追溯 |
