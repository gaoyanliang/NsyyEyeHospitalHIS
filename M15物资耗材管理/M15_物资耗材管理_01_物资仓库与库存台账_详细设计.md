## 1. 模块概述

### 1.1 模块定位

M15-01 是 M15 物资耗材管理的**库存唯一真相源**。它回答四个问题：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    M15-01 回答的四个问题                             │
├─────────────────────────────────────────────────────────────────────┤
│  ① 货在哪？        → 仓库 → 库位（一级总库 / 二级库 / 手术室 / 高值柜）│
│  ② 有多少？        → 库存台账（按时点、按批次、按序列号）             │
│  ③ 是哪一批的？    → 批次 / 序列号 / UDI-DI（一物一码）              │
│  ④ 怎么会变成现在这样？→ 库存流水（只增不可改，逐笔可追溯）           │
└─────────────────────────────────────────────────────────────────────┘
```

**技术定位：**

- 是 M15-02~07 的**数据底座**：分配要查库存、入库要写库存、出库要扣库存、盘点要改库存、消耗要减库存、追溯要查谁用的
- 是 M01-04 耗材主数据的**消费方**：只读 `mdm_material` / `mdm_material_barcode` / `mdm_material_stock_policy`，不回写
- 是 M09 手术麻醉的**上游**：手术室二级库的备台、消耗、退料全部以 `m15_stock` 为数量准绳
- 是 M16 收费结算的**成本源**：材料费按 `m15_stock.unit_cost` 归集

**核心原则：库存数字只有一处是真的，其余都是它的投影。**

```
              ┌──────────────────────┐
              │  m15_stock (台账)    │ ← 唯一数量真相
              │  qty_on_hand/locked  │
              └──────────┬───────────┘
                         │ 每一次变化都写一条流水
                         ▼
              ┌──────────────────────┐
              │ m15_stock_txn (流水) │ ← 只增不改，可重算出台账
              └──────────────────────┘

  汇总查询 ──► m15_stock（台账）  ← 不走流水聚合，性能
  对账校验 ──► m15_stock_txn ∪ m15_stock  ← 每日 04:00 双向核对
```

### 1.2 为什么独立成子模块

**理由一：库存是所有业务的汇聚点，必须唯一。**

M15 有七个环节（采购入库、分配、出库、盘点、消耗、退料、追溯），每个环节都会导致库存变化。如果每个环节自己维护"库存"字段：

- M15-03 采购入库改 `m15_material.qty`
- M15-04 出库改 `m15_material.qty`
- M15-06 消耗改 `m15_material.qty`

三个地方抢着改同一列，任何并发或异常都会导致数字漂移，且**没有人能回答"现在是几点几分、谁改了、改了多少、为什么"**。

正确做法是：库存只有一张表 `m15_stock`，所有变化通过 `m15_stock_txn` 记录的**事务**进行，禁止任何子模块直接 UPDATE 数量。

**理由二：仓库与库位是耗材特有的多维结构。**

药品仓库相对简单（药库 → 药房 → 病区药柜三层），但耗材有：

| 仓库类型 | 说明 | 数量（本院） |
|---|---|---|
| 一级总库 | 全院采购入库、向二级库补货 | 1 |
| 二级库（手术室） | 手术室耗材周转库，备台从这里出 | 1 |
| 二级库（门诊） | 门诊治疗室耗材 | 1 |
| 高值柜（人工晶体） | 单独柜位，双人管理 | 1 |
| 寄售库 | 供应商寄售，用后结算 | 1 |
| 待检区 | 验收不合格 / 召回 / 过期隔离 | 1 |
| 虚拟库（在途） | 采购在途、调拨在途 | 1 |

七类仓库的**权限、盘点频率、成本核算方式、出入库规则完全不同**。混在一个"库存"概念里，任何一条规则都要写七个分支。

**理由三：批号与序列号是两种不同的粒度，必须同时支持。**

| 耗材类型 | 管理粒度 | 举例 |
|---|---|---|
| 普通耗材（纱布、缝线） | 批号 | 一批 500 片，用掉 3 片，剩 497 片 |
| 高值耗材（人工晶体、玻璃体替代物） | **序列号（一物一码）** | 一片晶体一个序列号，用掉就是 1 片 |
| 无菌包 | 批号 + 灭菌批号 | 灭菌批次决定有效期 |
| 试剂 | 批号 + 开封效期 | 开封后 30 天失效 |

如果只做批号，高值耗材无法追溯到"哪一片晶体植入了谁的眼睛"——这是**《医疗器械监督管理条例》第三十八条的强制要求**。如果只做序列号，普通耗材一次出库 500 片要写 500 条记录，性能无法接受。

所以 M15-01 设计成：**`m15_stock` 按批次粒度记数量，`m15_stock_batch` 按序列号粒度记实例**，两者通过 `(warehouse_id, material_id, batch_no)` 关联。

**理由四：库存流水是医疗器械 GSP 与财务成本核算的法定要求。**

- 《医疗器械经营质量管理规范》要求"购进、验收、储存、销售、出库复核"全记录可追溯
- 财务成本核算要求"每一次出库按批次的实际成本计入，不允许移动加权平均"

流水表 `m15_stock_txn` 的每一条都带 `unit_cost` 与 `before_qty`/`after_qty`，既满足追溯，也满足成本归集。

### 1.4 概念辨析

| 概念对 | 区别 |
|---|---|
| **库存** vs **库存量** | 库存是业务概念（有这个东西），库存量是数字（有 37 片）。本文统一用"库存量"指数字 |
| **批次** vs **序列号** | 批次是"同一批生产的一群"，序列号是"具体到这一件"。普通耗材到批次，高值耗材到序列号 |
| **在库** vs **可用** | 在库 `qty_on_hand` 是物理存在；可用 `qty_available = on_hand − locked` 才能被分配。锁定的是"已备台未出库"的 |
| **仓库** vs **库位** | 仓库是逻辑单元（手术室二级库），库位是物理货架（A 区 3 号柜第 2 层）。一个耗材在仓库里必须落到具体库位 |
| **一级库** vs **二级库** | 一级库面对供应商（采购入库），二级库面对使用科室（补货出库）。二级库是小水柜，一级库是大水塔 |
| **出库** vs **消耗** | 出库是"从一级库搬到二级库"（库存仍在院内），消耗是"从二级库用到患者身上"（库存永久减少）。详见 §3.6 |
| **寄售** vs **自有** | 寄售是供应商放在院内、用后结算的货。库存物理在院内，但**不是医院资产**，不能计入资产负债表 |
| **移动加权平均** vs **批次实际成本** | 前者把不同批次的成本混成一个平均价，后者每批独立计价。高值耗材（人工晶体 3,000~15,000 元）必须用后者 |

## 2. 业务范围与边界

### 2.1 范围内

- **仓库管理**：新建、启用、停用、关闭；仓库类型（一级/二级/手术室/高值柜/寄售/待检/虚拟）；仓库负责人；是否允许负库存
- **库位管理**：库位编码、区域/货架/层、温区（常温/阴凉/冷藏/冷冻）、是否高值柜、是否双人管理
- **库存台账**：按 `(仓库, 库位, 耗材, 批次)` 记录的在库量、锁定量、可用量、单位成本
- **批次管理**：批号、生产日期、有效期、灭菌批号、灭菌有效期、注册证号、供应商
- **序列号管理**：高值耗材的一物一码实例（序列号、UDI-DI、状态流转）
- **库存流水**：全部增减变动的事务记录，含事务类型、方向、数量、前后结存、成本、来源单号
- **库存查询**：按耗材/仓库/批次/效期/序列号多维度查询
- **库存快照**：每日 00:00 全库快照（用于报表与追溯"某天库存是多少"）
- **库存对账**：每日 04:00 核对"流水累计 = 台账结存"，不一致则告警
- **基本预警**：低于安全库存、近效期（90 天内）、已过期、冻结（待检/召回）

## 3. 业务模型

### 3.1 四层库存结构

```
┌────────────────────────────────────────────────────────────────────────┐
│  第 1 层：仓库（m15_warehouse）                                        │
│  一级总库 / 二级库 / 手术室库 / 高值柜 / 寄售库 / 待检区 / 虚拟库      │
└───────────────────────────┬────────────────────────────────────────────┘
                            │ 1:N
┌───────────────────────────▼────────────────────────────────────────────┐
│  第 2 层：库位（m15_location）                                         │
│  A 区-3 号柜-2 层 ｜ 温区：常温/阴凉/冷藏/冷冻 ｜ 高值柜 ｜ 双人管理   │
└───────────────────────────┬────────────────────────────────────────────┘
                            │ N:1（同一耗材可占多个库位）
┌───────────────────────────▼────────────────────────────────────────────┐
│  第 3 层：库存台账（m15_stock）★ 数量唯一真相                           │
│  (warehouse_id, location_id, material_id, batch_no) 唯一               │
│  qty_on_hand − qty_locked = qty_available（生成列）                    │
│  unit_cost（批次实际成本） ｜ expiry_date ｜ udi_di ｜ is_consignment   │
└───────────────────────────┬────────────────────────────────────────────┘
                            │ 1:N（序列号管理耗材才有）
┌───────────────────────────▼────────────────────────────────────────────┐
│  第 4 层：序列号实例（m15_stock_batch）                                │
│  (material_id, serial_no) 唯一                                         │
│  状态：AVAILABLE / LOCKED / ISSUED / USED / EXPIRED / DAMAGED / RECALLED│
│  一物一码：一片人工晶体 = 一条记录，从入库到植入全程可追                │
└────────────────────────────────────────────────────────────────────────┘
                            ▲
                            │ 每一次增减都写一条
┌───────────────────────────┴────────────────────────────────────────────┐
│  旁路：库存流水（m15_stock_txn）★ 只增不改，月度分区                    │
│  txn_type + direction + qty + before_qty + after_qty + unit_cost       │
│  source_type + source_id（哪张单） + idempotency_key（防重）           │
└────────────────────────────────────────────────────────────────────────┘
```

**为什么台账在第 3 层而不是第 4 层：**

序列号实例（第 4 层）只在"序列号管理耗材"时存在。普通耗材（纱布、缝线）只有批次，没有序列号。如果台账建在第 4 层，普通耗材就没有地方记录数量了。

**为什么 `m15_stock` 的唯一键含 `location_id`：**

同一批次可以存放在多个库位（比如一批纱布既在 A 区也补到 B 区）。如果唯一键不含库位，就无法知道"这 500 片纱布具体在哪个货架上"。

### 3.2 数量三要素与恒等式

```sql
qty_on_hand   -- 在库量：物理上在这个库位里有多少
qty_locked    -- 锁定量：已备台/已分配但未出库的数量
qty_available = qty_on_hand - qty_locked  -- 可用量（生成列）
```

**恒等式由数据库生成列强制：**

```sql
qty_available INTEGER GENERATED ALWAYS AS (qty_on_hand - qty_locked) STORED
```

**约束：**

```sql
CHECK (qty_on_hand >= 0)
CHECK (qty_locked >= 0)
CHECK (qty_locked <= qty_on_hand)
```

**为什么要区分锁定与在库：**

手术前一晚备台时，器械护士已经把 50 项耗材从二级库取到备台车上。此时：

- 物理上耗材还在手术室（`qty_on_hand` 不变）
- 但不能再被另一台手术领用（`qty_locked += 50`）

如果只有 `qty_on_hand`，同时排两台手术的备台就会把同一批耗材分给两次。

### 3.3 批次与效期模型

**批次四要素：**

| 要素 | 说明 | 必填条件 |
|---|---|---|
| `batch_no` | 厂商批号 | `mdm_material.is_batch_managed = TRUE` 时必填 |
| `production_date` | 生产日期 | 同上 |
| `expiry_date` | 有效期 | `mdm_material.is_expiry_managed = TRUE` 时必填 |
| `sterile_batch_no` / `sterile_expiry_date` | 灭菌批号 / 灭菌有效期 | `mdm_material.is_sterile = TRUE` 时建议填 |

**为什么灭菌有效期要单列：**

一次性无菌包（手术洞巾、无菌手套）的厂商有效期可能是 3 年，但**灭菌有效期只有 6 个月**。以厂商有效期为准则会出现"灭菌在 3 个月前就失效但系统显示还有效"的严重问题。

```
厂商有效期：2028-05-31（包装完整性）
灭菌有效期：2025-12-31（无菌状态）
                     ↑ 实际可用性以此为准
```

**近效期三档：**

| 档位 | 条件 | 处理 |
|---|---|---|
| 正常 | `expiry_date > today + 90 天` | 正常出库 |
| **近效期** | `today ≤ expiry_date ≤ today + 90 天` | 优先出库（FEFO），出库时提示 |
| **禁止出库** | `expiry_date < today + expiry_forbid_days` | 阻断，只能报废 |
| **已过期** | `expiry_date < today` | 阻断，自动置 `EXPIRED`，只能报废 |

`expiry_forbid_days` 来自 M01-04 `mdm_material_stock_policy`，默认 0（到期才禁），高值植入物建议设 30（近效期 30 天内不得植入）。

### 3.4 序列号实例模型

**序列号状态机（7 态）：**

```
              ┌──────────┐
              │ AVAILABLE│ ← 入库即此状态
              └────┬─────┘
        锁定备台 │  │ 报废/召回/过期
                ▼  ▼
        ┌──────────┐  ┌───────────┐
        │  LOCKED  │  │  DAMAGED  │
        └────┬─────┘  │  EXPIRED  │
   出库手术室│  │ 解锁  │  RECALLED │
            ▼  ▼       └───────────┘
     ┌──────────┐
     │  ISSUED  │ ← 已出库到手术室二级库
     └────┬─────┘
    术中植入│  │ 退料
          ▼  ▼
    ┌──────────┐  ┌──────────┐
    │   USED   │  │AVAILABLE │
    └──────────┘  └──────────┘
```

| 状态 | 含义 | 可否被分配 |
|---|---|---|
| `AVAILABLE` | 在库可用 | ✅ |
| `LOCKED` | 已被某台手术锁定 | ❌ |
| `ISSUED` | 已出库到手术室二级库，尚未使用 | ✅（限本台次） |
| `USED` | 已植入/已使用 | ❌ 终态 |
| `EXPIRED` | 已过期 | ❌ |
| `DAMAGED` | 破损/污染 | ❌ |
| `RECALLED` | 已召回 | ❌ 终态 |

**为什么 `ISSUED` 出现两次（一处在 AVAILABLE 之后、一处在锁定之后）：**

实际业务有两条路径：

- 路径 A（提前出库）：手术前一天出库到手术室二级库 → `ISSUED`，手术当天术中扫码 → `USED`
- 路径 B（当天锁定）：手术当天从二级库锁定 → `LOCKED`，术中确认 → `USED`

两条路径都是合规的，取决于医院管理习惯。M15-02 的分配逻辑要同时支持。

### 3.5 库存流水模型

**每一条流水必须回答六个问题：**

| 问题 | 字段 |
|---|---|
| 什么时候 | `occurred_at` |
| 谁操作的 | `operator_id` / `operator_name` |
| 什么事务 | `txn_type` + `direction`（IN/OUT） |
| 具体多少 | `qty` + `before_qty` + `after_qty` |
| 什么成本 | `unit_cost` + `total_cost`（生成列） |
| 因为哪张单 | `source_type` + `source_id` + `source_no` |

**事务类型与方向（8 类）：**

| txn_type | 方向 | 说明 | 调用方 |
|---|---|---|---|
| `IN_PURCHASE` | IN | 采购入库 | M15-03 |
| `IN_RETURN` | IN | 退料入库（手术室未用退回一级库） | M15-06 |
| `IN_TRANSFER` | IN | 调拨入库（调入方） | M15-04 |
| `IN_ADJUST` | IN | 盘盈 | M15-05 |
| `OUT_ISSUE` | OUT | 出库（一级库 → 二级库） | M15-04 |
| `OUT_CONSUME` | OUT | 消耗（二级库 → 患者） | M15-06 |
| `OUT_TRANSFER` | OUT | 调拨出库（调出方） | M15-04 |
| `OUT_LOSS` | OUT | 报损/过期报废 | M15-05 |
| `ADJUST_STOCKTAKE` | IN/OUT | 盘点调整（盘盈 IN / 盘亏 OUT） | M15-05 |

**为什么 `ADJUST_STOCKTAKE` 一个类型有两个方向：**

盘点差异可能是盘盈（实际比账多）也可能是盘亏（实际比账少）。如果拆成 `ADJUST_UP` 和 `ADJUST_DOWN` 两个类型，统计"盘点调整总额"就要 UNION 两次。用 `direction` 区分更清晰。

**幂等键：**

```sql
idempotency_key VARCHAR(128)  -- 如 "PURCHASE:20261024001:IN"
```

部分唯一索引：

```sql
CREATE UNIQUE INDEX uk_m15_txn_idem ON m15_stock_txn (idempotency_key)
    WHERE idempotency_key IS NOT NULL;
```

**为什么必须幂等：** 网络超时后调用方会重试。如果入库接口重试两次，库存就会多加一次。幂等键让第二次调用直接返回第一次的结果。

### 3.6 出库与消耗的区分

这是 M15 最容易混淆的地方，也是 M15-04 与 M15-06 拆分的核心理由。

| 动作 | 时点 | 库存变化 | 责任 | 事务类型 |
|---|---|---|---|---|
| **出库** | 手术前一晚备台 | 一级库 −50 / 手术室库 +50 | 库管员 | `OUT_ISSUE` + `IN_TRANSFER` |
| **锁定** | 备台时 | `qty_locked += 50` | 器械护士 | 无（只改锁定量） |
| **消耗** | 术中实际使用 | 手术室库 −38 | 器械护士 | `OUT_CONSUME` |
| **解锁** | 术后未用的 | `qty_locked -= 12` | 器械护士 | 无 |
| **退料** | 术后未用退回 | 手术室库 −12 / 一级库 +12 | 器械护士 | `OUT_TRANSFER` + `IN_RETURN` |
| **报损** | 备台中发现破损 | 手术室库 −1 | 护士长 | `OUT_LOSS` |

**如果合并出库与消耗：**

备台 50 项、实耗 38 项、退回 12 项。一张表只有"数量"字段的话：

- 写 50（出库数）→ 消耗是多少？
- 写 38（消耗数）→ 那 12 项去哪了？还在手术室还是退回了？
- 只能用备注文字描述，无法统计

**M06-06 的"材料退回率 ≥90%"指标**统计的正是"备台未用退回"比例：

```
退回率 = 退回数量 / (备台数量 - 消耗数量)
       = 12 / (50 - 38)
       = 100%
```

这个指标直接关系到患者费用（退回的材料不该收费）与成本（退回的材料要重新入库不能算损耗）。M06-06 已把它列为关键指标（当前 55%，目标 ≥90%，年多收患者约 360 万元）。

**分离后：** 出库、锁定、消耗、退料各是独立事务，各有独立的单号与流水，任何环节都可独立审计。

### 3.7 寄售库模型

**寄售耗材的特点：**

- 供应商把货放在医院，物理在医院内
- 使用前医院的账上**没有这笔资产**（所有权仍归供应商）
- 使用后按合同价结算，此时才成为医院成本

**M15 的处理：**

```sql
m15_stock.is_consignment BOOLEAN NOT NULL DEFAULT FALSE
```

| 场景 | is_consignment | 计入库存量 | 计入资产 | 成本 |
|---|---|---|---|---|
| 自有耗材入库 | FALSE | ✅ | ✅ | 采购价 |
| 寄售后备货入库 | TRUE | ✅（可用） | ❌ | 0（未结算） |
| 寄售耗材被消耗 | TRUE | 减少 | — | 合同价（此时才产生） |

**统计口径必须分开：**

```
自营库存金额 = Σ(qty_on_hand × unit_cost) WHERE is_consignment = FALSE
寄售库存金额 = Σ(qty_on_hand × contract_price) WHERE is_consignment = TRUE
```

混算会虚增医院资产。财务报表上寄售库存只能列在"备查簿"而非"存货"。

### 3.8 库存快照模型

**每日 00:00 全库快照：**

```sql
m15_stock_snapshot (
    snapshot_date DATE,
    warehouse_id, location_id, material_id, batch_no,
    qty_on_hand, qty_locked, qty_available,
    unit_cost, total_cost,
    expiry_date, status,
    PRIMARY KEY (snapshot_date, id)
) PARTITION BY RANGE (snapshot_date)
```

**为什么需要快照：**

台账只记录"现在有多少"，记录不了"10 月 15 日那天有多少"。而月度库存报表、库存周转率、成本核算都要用期末库存。

**能否用流水重算：**

能，但慢。台账户数约 5,000，重算一个月的流水约 2 万条，日积月累后单次重算 10 年流水要数十秒。快照把"重算"变成"查表"。

**快照与流水的双向对账（每日 04:00）：**

```
期末台账 = 期初台账 + Σ流水（IN − OUT）
```

不一致则告警，并输出差异明细。这是库存准确率的**唯一客观检验**。

### 3.9 库存分层与责任

| 层级 | 存放 | 谁负责 | 盘点频率 |
|---|---|---|---|
| 一级总库 | 库房（含常温区、阴凉区、冷藏区） | 库管员 | 每月全盘 |
| 二级库（手术室） | 手术室内 | 手术室护士长 | 每周抽盘 + 每月全盘 |
| 高值柜 | 手术室/库房内单独柜 | 库管员 + 护士长双人 | 每日班次交接 |
| 寄售库 | 库房内单独区域 | 库管员 + 供应商代表 | 每月对账 |
| 待检区 | 库房内隔离区 | 库管员 | 不影响主库存 |

**高值柜为什么每日班次交接：**

人工晶体单价 3,000~15,000 元，一个高值柜里可能有 60 片，总价值 30~90 万元。任何一片丢失都是重大事件，必须每班清点。

### 3.10 库存变更的七步事务

任何改变库存的操作都必须按这七步执行：

```
① 幂等检查      查 idempotency_key 是否已处理
② 前置校验      状态是否允许、参数是否合法
③ 锁定台账       SELECT ... FOR UPDATE（按 warehouse_id + material_id + batch_no 顺序加锁防死锁）
④ 校验可用量    qty_available 是否足够（出库类）
⑤ 写台账        更新 qty_on_hand / qty_locked
⑥ 写流水        记录 before_qty / after_qty / unit_cost
⑦ 更新序列号    序列号管理耗材同时更新 m15_stock_batch.status
```

**第 ③ 步的加锁顺序为什么重要：**

一次出库涉及多个耗材。如果线程 A 锁仓库 1 的耗材 X 再锁耗材 Y，线程 B 锁耗材 Y 再锁耗材 X，就会死锁。

统一按 `(warehouse_id, material_id, batch_no)` 排序后逐个加锁，所有线程顺序一致，不会死锁。

| 区域 | 字段 | 说明 |
|---|---|---|
| 筛选 | 时间区间（≤92 天）/ 仓库 / 耗材 / 事务类型 / 来源单号 / 操作人 | 时间区间必填 |
| 汇总 | 条数 / 入总 / 出总 / 净变化 | 当前筛选条件 |
| 明细 | 时间 / 事务类型 / 方向 / 数量 / 结存后 / 单号 / 操作人 | 结存后 = `after_qty` |

**交互说明：**

| 操作 | 触发 | 结果 |
|---|---|---|
| 点单号 | 链接 | 跳原单详情（采购单/出库单/盘点单） |
| 点结存后 | 单元格 | 显示该笔流水前后的完整快照 |
| 对账 | 按钮 | 发起区间对账（重算流水 vs 台账） |

**校验规则：**

| 编号 | 规则 | 说明 |
|---|---|---|
| V-24 | 时间区间必填且 ≤ 92 天 | 全表扫描保护 |
| V-25 | 流水不可修改删除 | 触发器 `fn_m15_txn_readonly()` |
| V-26 | `after_qty = before_qty ± qty` | DB 约束强制 |
| V-27 | 单号点击跳转原单 | 双向可追溯 |

**为什么结存后（`after_qty`）必须存：**

如果只存数量，任何一天想验证"当时的库存是不是对的"，都要从该耗材第一天开始累加全部流水。存了 `after_qty` 后，随便挑一条流水就能直接看到当时的结存。

| 发起盘点 | 按钮 | 跳 M15-05 盘点单，预填差异耗材 |
| 保存配置 | 按钮 | 校验范围后保存，清缓存 |

**校验规则：**

| 编号 | 规则 | 错误码 |
|---|---|---|
| V-28 | 近效期提醒天数 1~365 | `"1501030"` |
| V-29 | 对账差异 > 阈值触发告警 | — |
| V-30 | 快照时间与对账时间不能相同 | `"1501031"` |
| V-31 | 快照/对账时间变更后次日生效 | — |

**为什么对账时间设为 04:00 而不是 00:00：**

- 00:00 是全院日结（M16-09）与库存快照的时段，数据库压力最大
- 02:00 是 M09-06 运营统计
- 04:00 是业务低峰，且对账必须在当天业务开始（08:00）前完成

```python
"""M15-01 物资仓库与库存台账 —— 服务层。"""

import logging
from datetime import date, datetime, timedelta
from decimal import Decimal, ROUND_HALF_UP
from typing import Optional

from fastapi import HTTPException
from sqlalchemy import func, or_, select, text, update
from sqlalchemy.exc import IntegrityError
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.biz import BizException
from app.models.m15_warehouse import (
    M15Warehouse, M15Location, M15Stock, M15StockBatch,
    M15StockTxn, M15WarehouseConfig, M15ReconcileTask, M15ReconcileDiff,
)
from app.utils.redis_client import redis_client

logger = logging.getLogger("m15.warehouse")

CENT = Decimal("0.0001")
MAX_QUERY_DAYS_TXN = 92
MAX_EXPORT_ROWS = 50000


def money(v) -> Decimal:
    if v is None:
        return Decimal("0.0000")
    return Decimal(str(v)).quantize(CENT, rounding=ROUND_HALF_UP)


def _next_no(prefix: str, seq: int, date_part: str) -> str:
    return "%s%s%05d" % (prefix, date_part, seq)


class StockTxnService:
    """库存事务服务：唯一允许改写 m15_stock 数量的入口。"""

    TTL_SEQ = 172800  # 48 小时

    # ---------- 幂等 ----------

    @classmethod
    async def _check_idem(cls, db: AsyncSession, idem_key: str) -> Optional[M15StockTxn]:
        if not idem_key:
            return None
        r = await db.execute(
            select(M15StockTxn).where(M15StockTxn.idempotency_key == idem_key)
        )
        return r.scalar_one_or_none()

    # ---------- 台账加锁 ----------

    @classmethod
    async def _lock_stock(
        cls, db: AsyncSession, warehouse_id: int, material_code: str, batch_no: Optional[str]
    ) -> Optional[M15Stock]:
        """按 (warehouse_id, material_code, batch_no) 顺序加行锁，防死锁。"""
        sql = (
            "SELECT * FROM m15_stock "
            "WHERE warehouse_id = :wh AND material_code = :mc "
            "AND batch_no IS NOT DISTINCT FROM :bn AND is_deleted = FALSE "
            "FOR UPDATE"
        )
        r = await db.execute(
            text(sql).bindparams(wh=warehouse_id, mc=material_code, bn=batch_no)
        )
        row = r.first()
        if row is None:
            return None
        return await db.get(M15Stock, row.id)

    @classmethod
    async def _get_or_create_stock(
        cls, db: AsyncSession, body, unit_cost: Decimal
    ) -> M15Stock:
        stock = await cls._lock_stock(db, body.warehouse_id, body.material_code, body.batch_no)
        if stock is not None:
            return stock
        stock = M15Stock(
            warehouse_id=body.warehouse_id,
            location_id=body.location_id,
            location_code=body.location_code,
            material_code=body.material_code,
            material_name=body.material_name,
            spec=body.spec,
            batch_no=body.batch_no,
            expiry_date=body.expiry_date,
            is_serial_managed=body.is_serial_managed,
            qty_on_hand=0,
            qty_locked=0,
            unit_cost=unit_cost,
            is_consignment=body.is_consignment,
        )
        db.add(stock)
        await db.flush()
        return stock

    # ---------- 流水编号 ----------

    @classmethod
    async def _next_txn_no(cls) -> str:
        day = datetime.now().strftime("%Y%m%d")
        key = "m15:txn:seq:%s" % day
        seq = await redis_client.incr(key)
        if seq == 1:
            await redis_client.expire(key, cls.TTL_SEQ)
        return _next_no("TX", seq, day)

    # ---------- 写台账 + 写流水 ----------

    @classmethod
    async def _apply_txn(
        cls,
        db: AsyncSession,
        stock: M15Stock,
        txn_type: str,
        direction: str,
        qty: int,
        unit_cost: Decimal,
        body,
    ) -> M15StockTxn:
        before = stock.qty_on_hand
        if direction == "IN":
            after = before + qty
        else:
            after = before - qty
            if after < 0:
                raise BizException("1501025", "库存扣减后为负，仓库不允许负库存")

        stock.qty_on_hand = after
        stock.updated_at = datetime.now()
        if unit_cost > 0:
            stock.unit_cost = unit_cost

        total_cost = money(unit_cost * qty)
        txn = M15StockTxn(
            txn_no=await cls._next_txn_no(),
            txn_type=txn_type,
            direction=direction,
            warehouse_id=stock.warehouse_id,
            location_id=stock.location_id,
            material_code=stock.material_code,
            material_name=stock.material_name,
            spec=stock.spec,
            batch_no=stock.batch_no,
            qty=qty,
            before_qty=before,
            after_qty=after,
            unit_cost=unit_cost,
            total_cost=total_cost,
            source_type=body.source_type,
            source_id=body.source_id,
            source_no=body.source_no,
            idempotency_key=body.idempotency_key,
            operator_id=body.operator_id,
            operator_name=body.operator_name,
            occurred_at=datetime.now(),
        )
        db.add(txn)
        await db.flush()

        logger.info(
            "stock txn applied txn_no=%s type=%s qty=%s before=%s after=%s",
            txn.txn_no, txn_type, qty, before, after,
            extra={"module": "M15-01", "action": "APPLY_TXN"},
        )
        return txn

    # ---------- 入库 ----------

    @classmethod
    async def inbound(cls, db: AsyncSession, body) -> dict:
        # ① 幂等
        exist = await cls._check_idem(db, body.idempotency_key)
        if exist is not None:
            stock = await cls._lock_stock(db, exist.warehouse_id, exist.material_code, exist.batch_no)
            return {
                "stock_id": stock.id if stock else None,
                "txn_id": exist.id,
                "txn_no": exist.txn_no,
                "qty_before": exist.before_qty,
                "qty_after": exist.after_qty,
                "qty_locked": stock.qty_locked if stock else 0,
                "qty_available": stock.qty_available if stock else 0,
                "serial_count": 0,
                "is_duplicated": True,
            }

        # ② 前置校验
        await cls._validate_inbound(db, body)

        # ③~⑤ 台账
        unit_cost = money(body.unit_cost)
        stock = await cls._get_or_create_stock(db, body, unit_cost)

        # ⑥ 写流水
        txn = await cls._apply_txn(db, stock, "IN_PURCHASE", "IN", body.qty, unit_cost, body)

        # ⑦ 序列号
        serial_count = 0
        if body.is_serial_managed and body.serials:
            serial_count = await cls._register_serials(db, stock, body, unit_cost)

        await db.commit()
        return {
            "stock_id": stock.id,
            "txn_id": txn.id,
            "txn_no": txn.txn_no,
            "qty_before": txn.before_qty,
            "qty_after": txn.after_qty,
            "qty_locked": stock.qty_locked,
            "qty_available": stock.qty_available,
            "serial_count": serial_count,
            "is_duplicated": False,
        }

    @classmethod
    async def _validate_inbound(cls, db: AsyncSession, body) -> None:
        if body.qty <= 0:
            raise BizException("1501022", "入库数量必须大于 0")
        if body.is_batch_managed and not body.batch_no:
            raise BizException("1501016", "该耗材启用批次管理，必须指定批号")
        if (not body.is_batch_managed) and body.batch_no:
            raise BizException("1501015", "该耗材非批次管理，无需指定批号")
        if body.expiry_date and body.production_date and body.expiry_date < body.production_date:
            raise BizException("1501018", "有效期早于生产日期")
        # 灭菌有效期
        if body.sterile_expiry_date and body.sterile_expiry_date < date.today():
            raise BizException("1501019", "灭菌批次已过灭菌有效期")
        # 注册证
        if body.registration_expiry_date and body.registration_expiry_date < date.today():
            raise BizException("1501039", "注册证已过期，该批次不可用")
        # 序列号数量一致
        if body.is_serial_managed:
            if not body.serials:
                raise BizException("1501028", "序列号管理耗材入库必须提供序列号")
            if len(body.serials) != body.qty:
                raise BizException("1501028", "序列号数量与入库数量不一致")
            dup = len(set(body.serials)) != len(body.serials)
            if dup:
                raise BizException("1501028", "同一批入库存在重复序列号")
            r = await db.execute(
                select(M15StockBatch.serial_no).where(M15StockBatch.serial_no.in_(body.serials))
            )
            exists = [x for x in r.scalars().all()]
            if exists:
                raise BizException("1501028", "序列号已存在：%s" % exists[0])

    @classmethod
    async def _register_serials(cls, db: AsyncSession, stock: M15Stock, body, unit_cost: Decimal) -> int:
        n = 0
        for sn in body.serials:
            db.add(M15StockBatch(
                stock_id=stock.id,
                warehouse_id=stock.warehouse_id,
                material_code=stock.material_code,
                material_name=stock.material_name,
                spec=stock.spec,
                batch_no=stock.batch_no,
                serial_no=sn,
                udi_di=body.udi_di,
                production_date=body.production_date,
                expiry_date=body.expiry_date,

                status="AVAILABLE",

            n += 1
        await db.flush()
        return n

    # ---------- 出库 ----------

    @classmethod
    async def outbound(cls, db: AsyncSession, body) -> dict:
        exist = await cls._check_idem(db, body.idempotency_key)
        if exist is not None:
            return {"txn_ids": [exist.id], "is_duplicated": True}

        stock = await cls._lock_stock(db, body.warehouse_id, body.material_code, body.batch_no)
        if stock is None:
            raise BizException("1501013", "库存记录不存在")
        if stock.expiry_date and stock.expiry_date < date.today():
            raise BizException("1501020", "耗材批次已过期，不可出库")
        if stock.qty_available < body.qty:
            raise BizException("1501022", "可用库存不足，当前可用 %d" % stock.qty_available)

        # 序列号校验
        if body.serials:
            r = await db.execute(
                select(M15StockBatch).where(
                    M15StockBatch.serial_no.in_(body.serials),
                    M15StockBatch.status.in_(("AVAILABLE", "LOCKED")),
                ).with_for_update()
            )
            batches = r.scalars().all()
            if len(batches) != len(body.serials):
                raise BizException("1501027", "序列号状态不允许出库")

        txn = await cls._apply_txn(db, stock, "OUT_ISSUE", "OUT", body.qty, stock.unit_cost, body)

        # 序列号状态
        if body.serials:
            await db.execute(
                update(M15StockBatch)
                .where(M15StockBatch.serial_no.in_(body.serials))
                .values(status="ISSUED", issued_at=datetime.now(),
                        issued_source_no=body.source_no, updated_at=datetime.now())
            )

        # 目标仓入库（二级库）
        inbound_txn_id = None
        if body.target_warehouse_id:
            inbound_txn_id = await cls._mirror_inbound(db, stock, body)

        await db.commit()
        return {
            "txn_ids": [txn.id] + ([inbound_txn_id] if inbound_txn_id else []),
            "qty_before": txn.before_qty,
            "qty_after": txn.after_qty,
            "qty_available": stock.qty_available,
            "serials_updated": len(body.serials or []),
            "inbound_stock_id": None,
        }

    @classmethod
    async def _mirror_inbound(cls, db: AsyncSession, src: M15Stock, body) -> Optional[int]:
        target = await cls._lock_stock(db, body.target_warehouse_id, src.material_code, src.batch_no)
        if target is None:
            target = M15Stock(
                warehouse_id=body.target_warehouse_id,
                location_id=body.target_location_id,
                location_code=body.target_location_code,
                material_code=src.material_code,
                material_name=src.material_name,
                spec=src.spec,
                batch_no=src.batch_no,
                expiry_date=src.expiry_date,
                is_serial_managed=src.is_serial_managed,
                qty_on_hand=0,
                qty_locked=0,
                unit_cost=src.unit_cost,
                is_consignment=src.is_consignment,
            )
            db.add(target)
            await db.flush()
        txn = await cls._apply_txn(db, target, "IN_TRANSFER", "IN", body.qty, src.unit_cost, body)
        return txn.id

    # ---------- 消耗 ----------

    @classmethod
    async def consume(cls, db: AsyncSession, body) -> dict:
        exist = await cls._check_idem(db, body.idempotency_key)
        if exist is not None:
            return {"txn_ids": [exist.id], "is_duplicated": True}

        stock = await cls._lock_stock(db, body.warehouse_id, body.material_code, body.batch_no)
        if stock is None:
            raise BizException("1501013", "库存记录不存在")
        if stock.qty_available < body.qty:
            raise BizException("1501022", "可用库存不足，当前可用 %d" % stock.qty_available)

        txn = await cls._apply_txn(db, stock, "OUT_CONSUME", "OUT", body.qty, stock.unit_cost, body)

        if body.serials:
            await db.execute(
                update(M15StockBatch)
                .where(M15StockBatch.serial_no.in_(body.serials))
                .values(status="USED", used_at=datetime.now(),
                        updated_at=datetime.now())
            )

        await db.commit()
        return {"txn_ids": [txn.id], "qty_after": txn.after_qty, "is_duplicated": False}

    # ---------- 锁定 ----------

    @classmethod
    async def lock(cls, db: AsyncSession, body) -> dict:
        stock = await cls._lock_stock(db, body.warehouse_id, body.material_code, body.batch_no)
        if stock is None:
            raise BizException("1501013", "库存记录不存在")

        if body.action == "LOCK":
            new_locked = stock.qty_locked + body.qty
            if new_locked > stock.qty_on_hand:
                raise BizException("1501023", "锁定量超过在库量")
        else:
            new_locked = stock.qty_locked - body.qty
            if new_locked < 0:
                raise BizException("1501024", "解锁量超过已锁定量")

        stock.qty_locked = new_locked
        stock.updated_at = datetime.now()

        if body.serials:
            new_status = "LOCKED" if body.action == "LOCK" else "AVAILABLE"
            await db.execute(
                update(M15StockBatch)
                .where(M15StockBatch.serial_no.in_(body.serials))
                .values(status=new_status, updated_at=datetime.now())
            )

        await db.commit()
        return {
            "stock_id": stock.id,
            "qty_on_hand": stock.qty_on_hand,
            "qty_locked": stock.qty_locked,
            "qty_available": stock.qty_available,
        }

    # ---------- 盘点调整 ----------

    @classmethod
    async def adjust(cls, db: AsyncSession, body) -> dict:
        exist = await cls._check_idem(db, body.idempotency_key)
        if exist is not None:
            return {"txn_ids": [exist.id], "is_duplicated": True}

        stock = await cls._lock_stock(db, body.warehouse_id, body.material_code, body.batch_no)
        if stock is None:
            raise BizException("1501013", "库存记录不存在")

        diff = body.actual_qty - stock.qty_on_hand
        if diff == 0:
            return {"txn_ids": [], "is_duplicated": False, "diff": 0}

        direction = "IN" if diff > 0 else "OUT"
        txn_type = "IN_ADJUST" if diff > 0 else "ADJUST_STOCKTAKE"
        if body.adjust_reason == "SCRAP":
            txn_type = "OUT_LOSS"
            if not body.adjust_remark or len(body.adjust_remark.strip()) < 10:
                raise BizException("1501021", "报废必须填写原因（≥10 字）")

        txn = await cls._apply_txn(db, stock, txn_type, direction, abs(diff), stock.unit_cost, body)

        if body.serials and txn_type == "OUT_LOSS":
            await db.execute(
                update(M15StockBatch)
                .where(M15StockBatch.serial_no.in_(body.serials))
                .values(status="DAMAGED", updated_at=datetime.now())
            )

        await db.commit()
        return {
            "txn_ids": [txn.id],
            "diff": diff,
            "qty_before": txn.before_qty,
            "qty_after": txn.after_qty,
            "is_duplicated": False,
        }
```

```python
        # 流水累计（自建库以来全部）

        for r in rows:
            checked += 1
            key = (r["warehouse_id"], r["material_code"], r["batch_no"])
            expect = flow.get(key, 0)
            actual = int(r["qty_on_hand"])

                    "warehouse_id": r["warehouse_id"],
                    "location_code": r["location_code"],
```

### 6.7 专题：为什么库存流水必须"只增不改"

**场景推演：**

2026-10-15，库管员发现"眼科缝线 10-0"台账显示 60 片，实际货架只有 40 片，差 20 片。

**做法 A（允许改流水）** —— 直接在最后一条流水上把 `qty` 从 -20 改成 -40，让 `after_qty` 对齐 40。

- 表面上账平了
- 但**这 20 片是怎么丢的，永远查不出来**
- 如果实际是入库时少录了 20 片（供应商少发），那么供应商对账会对不上，且没人知道
- 如果是某次出库多扣了 20 片，那么实际库存应该是 80 片，改了流水反而把真实数据改错

**做法 B（只增不改）** —— 走盘点流程，写一条 `ADJUST_STOCKTAKE` 流水，`diff = -20`，带原因"盘点盘亏，货架清点确认 40 片"。

- 账也平了
- **流水里留下了"10-15 有一次 -20 的盘亏"这条记录**
- 财务能统计"本月盘亏金额"
- 质控能分析"哪个库位盘亏多"
- 明年审计能问"10 月那次盘亏查明原因了吗"

**只增不改的代价：**

数据库会持续增长。M15 每日约 1,200 条流水，一年 44 万条，15 年 660 万条。这不是问题——按月份区后单分区 3.7 万条，查询仍是毫秒级。

**实现方式：**

```sql
CREATE OR REPLACE FUNCTION fn_m15_txn_readonly()
RETURNS TRIGGER AS $$
BEGIN
    RAISE EXCEPTION 'm15_stock_txn 为只增表，禁止 UPDATE/DELETE';
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_m15_txn_no_update
    BEFORE UPDATE ON m15_stock_txn
    FOR EACH ROW EXECUTE FUNCTION fn_m15_txn_readonly();

CREATE TRIGGER trg_m15_txn_no_delete
    BEFORE DELETE ON m15_stock_txn
    FOR EACH ROW EXECUTE FUNCTION fn_m15_txn_readonly();
```

**为什么不用应用层保证：**

应用层可被绕过：DBA 手动改、迁移脚本误操作、其他服务的 bug、未来重构时忘了。医疗耗材的库存记录是 GSP 检查与财务审计的依据，**数据库级不可变才是真的不可变**。

```
03:00  耗材主数据同步（M15-01）
04:00  库存对账（M15-01）
...
08:00  近效期预警
09:00  低库存预警
```

**为什么对账在 04:00 而不是 01:00：** 对账要读全表 `m15_stock_txn`，会对全表加读锁。如果与 01:00 日结同期，两个大查询叠加会拖慢整个数据库。04:00 是业务最低谷。

## 8. 业务规则与校验

### 8.1 仓库与库位（R-01~R-08）

| 编号 | 规则 | 错误码 |
|---|---|---|
| R-01 | 仓库编码全局唯一，格式 `^[A-Z0-9-]{3,32}$` | `"1501002"` |
| R-02 | 全局只能有一个一级总库（`is_central = TRUE`） | `"1501003"` |
| R-03 | 有在库库存（`qty_on_hand > 0`）的仓库不可停用/关闭 | `"1501004"` |
| R-04 | 有在库库存的库位不可停用 | `"1501005"` |
| R-05 | 二级库（`is_secondary = TRUE`）必须有上级仓库 | `"1501006"` |
| R-06 | 高值柜（`HIGH_VALUE_CABINET`）必须启用双人管理 | `"1501007"` |
| R-07 | 仓库关闭是终态，不可再启用 | `"1501009"` |
| R-08 | 库位编码在仓库内唯一 | `"1501011"` |

### 8.2 入库（R-09~R-18）

| 编号 | 规则 | 错误码 |
|---|---|---|
| R-09 | 入库数量必须 > 0 | `"1501022"` |
| R-10 | `is_batch_managed = TRUE` 的耗材必须提供批号 | `"1501016"` |
| R-11 | `is_batch_managed = FALSE` 的耗材不得提供批号 | `"1501015"` |
| R-12 | 有效期不得早于生产日期 | `"1501018"` |

| R-17 | 同批号同耗材入库时，有效期必须与已存在批次一致 | `"1501017"` |
| R-18 | 幂等键重复则返回首次结果，不重复入账 | `"1501029"` |

### 8.3 出库与消耗（R-19~R-27）

| 编号 | 规则 | 错误码 |

| R-23 | 出库到二级库时自动生成对方入库流水（`IN_TRANSFER`） | — |
| R-24 | 消耗（`OUT_CONSUME`）只能从二级库/手术室库发起 | — |
| R-25 | 报损（`OUT_LOSS`）必须填原因 ≥10 字 | `"1501021"` |
| R-26 | 已被召回的批次不可出库 | `"1501040"` |
| R-27 | 出库与消耗必须带来源单号（`source_no`） | `"1501029"` |

### 8.4 锁定（R-28~R-31）

| 编号 | 规则 | 错误码 |
|---|---|---|
| R-28 | 锁定量累计不得超过在库量 | `"1501023"` |
| R-29 | 解锁量不得超过已锁定量 | `"1501024"` |
| R-30 | 锁定操作不写库存流水（只改 `qty_locked`） | — |
| R-31 | 锁定的序列号状态变为 `LOCKED`，解锁恢复 `AVAILABLE` | `"1501027"` |

**R-30 的理由：** 锁定不改变物理库存量，只是"预留"。写流水会让流水表膨胀且语义混乱（同一个实物被流水记录两次）。锁定量变化记在专门的审计日志里。

### 9.3 数据权限

```python
def apply_m15_stock_scope(stmt, model, user, domain: str = "WAREHOUSE"):
    """M15 库存数据权限注入。"""
    if user.has_permission("m15:stock:all"):
        return stmt
    if user.has_permission("m15:stock:dept"):
        depts = user.dept_ids or []
        if not depts:
            return stmt.where(model.id == -1)
        sub = select(M15Warehouse.id).where(M15Warehouse.dept_id.in_(depts))
        if hasattr(model, "warehouse_id"):
            return stmt.where(model.warehouse_id.in_(sub))
        return stmt.where(model.id.in_(sub))
    return stmt
```

**数据权限的三层：**

1. `m15:stock:all` —— 全部仓库（库管员、库房主管、财务、审计）
2. `m15:stock:dept` —— 本科室所属仓库（手术室护士长只看手术室二级库）
3. 都没有 —— 无条件（理论上不应该出现，保守返回空）

| `EXPORT_MAX_ROWS` | 50000 | 1000~200000 | LIMIT | ❌ | ✅ | 导出行数上限 |
| `DEFAULT_SAFETY_STOCK` | 0 | 0~10000 | STOCK | ❌ | ✅ | M01-04 未配策略时的默认安全库存 |
| `ALLOW_NEGATIVE_DEFAULT` | false | — | STOCK | ✅ | ✅ | 新仓库默认是否允许负库存 |

**敏感参数说明：**

- `EXPIRY_FORBID_DAYS`：调大能减少近效期使用风险，但可能造成大量报废。需耗材科+医务科共同决定

- `SERIAL_REQUIRED_DEFAULT`：关闭后高值耗材失去一物一码追溯能力

## 附录 D：术语表

| 术语 | 说明 |
|---|---|
| 一级总库（CENTRAL） | 全院唯一的采购入库与调拨中心，面向供应商 |
| 二级库（SECONDARY） | 使用科室的小型周转库，面向使用方 |
| 手术室库（OPERATING） | 手术室内的库，备台耗材从这里出 |
| 高值柜（HIGH_VALUE_CABINET） | 存放人工晶体等高值耗材的专用柜，双人管理 |
| 寄售库（CONSIGNMENT） | 供应商寄放的耗材，用后结算，不计入医院资产 |
| 待检区（QUARANTINE） | 验收不合格/召回/过期耗材的隔离存放区 |
| 虚拟库（VIRTUAL） | 记录在途物资（采购在途、调拨在途），不对应物理位置 |
| 库位（Location） | 仓库内的具体货架位置，如 `A-03-02` 表示 A 区 3 号货架第 2 层 |
| 批次（Batch/Lot） | 同一生产批号的一组耗材 |
| 序列号（Serial No） | 单个耗材的唯一编号，高值耗材一物一码 |
| UDI | Unique Device Identification，医疗器械唯一标识，含 DI（器械标识）与 PI（生产标识） |
| UDI-DI | UDI 的 Device Identifier 部分，标识"这是什么产品" |
| UDI-PI | UDI 的 Production Identifier 部分，标识"这一批/这一件" |
| 在库量（qty_on_hand） | 物理上在库位的数量 |
| 锁定量（qty_locked） | 已分配/已锁定但未出库的数量 |
| 可用量（qty_available） | `qty_on_hand − qty_locked`，可被分配的数量 |
| 灭菌有效期 | 无菌包装保持无菌状态的期限，通常短于厂商有效期 |
| 近效期 | 距有效期 90 天内（可配置）的耗材 |
| FEFO | First Expired First Out，先到期先出 |
| 库存快照 | 每日某时刻全库库存的静态记录 |
| 库存对账 | 核对"流水累计"与"台账结存"是否一致 |
| 幂等键（Idempotency Key） | 保证同一业务操作重复调用只生效一次的标识 |
| 移动加权平均 | 一种成本核算方法（本系统不使用，统一用批次实际成本） |
| 批次实际成本 | 每批次按实际采购价核算成本，不与其他批次平均 |
