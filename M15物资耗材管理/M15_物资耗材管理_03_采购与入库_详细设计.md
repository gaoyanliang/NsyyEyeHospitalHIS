## 1. 模块概述

### 1.1 模块定位

**M15-03 回答一个问题：这些耗材，是怎么从供应商手里，安全地变成医院库存的？**

采购与入库是物资进入医院的**唯一合法入口**。从「科室提需求」到「货摆上货架」的全过程，共经过八个环节：

```
科室提需求 ──► 采购计划 ──► 采购订单 ──► 到货登记 ──► 首营验收 ──► 质量验收 ──► 入库上架 ──► 发票核对
```


### 1.2 为什么采购与入库独立成子模块

| # | 理由 | 反面案例（若合并到 M15-01） |
|---|---|---|
| 1 | **采购是「承诺」，入库是「事实」** | M15-01 只管「现在有多少」，不管「承诺了多少、哪天到」。若合并，供应链管理只能靠 Excel |
| 2 | **采购涉及「外部对象」与「合同/财务」** | 供应商、合同、发票、付款账期、价格谈判——这些与库存台账的职责完全不同，一个子模块装不下 |
| 3 | **入库是库存唯一合法入口，必须严格校验** | 若不独立，「先入库后补验收」「不验收直接调数量」这类破坏性操作就无处拦截。独立后所有入库必须经过「到货→验收→入库」三道门 |
| 4 | **法规要求独立的采购与验收记录** | 《医疗器械监督管理条例》第 45 条要求「进货查验记录」保存至有效期届满后 2 年；GSP 检查必查「采购记录-验收记录-入库记录」三单齐备。合并后无法保证三单独立可查 |
| 5 | **采购有独立的审批链与预算控制** | 5 万以下科长、5~20 万分管院长、20 万以上院办会——库存台账不需要也不应承载这些审批逻辑 |

### 1.4 概念辨析

| 易混概念 | 区别 |
|---|---|
| **采购计划 ≠ 采购订单** | 计划是「我想买什么」（内部申请，可合并拆分），订单是「我向谁买了什么价」（对外承诺，法律文件） |
| **到货 ≠ 验收入库** | 到货是「货送到门口了」（数量可能不符、质量可能不合格、可能没带资质）；验收入库是「核对无误后进库存」。合并会导致「货到就算库存」，未验收的不合格品也被当成可用库存 |
| **合格 ≠ 完全符合** | 100 支里有 98 支合格、2 支外观不良——判「部分合格」，合格部分入库、不合格部分拒收。不允许「整单拒收重发」（会延误手术）也不允许「全部入库」（把不良品混入库存） |
| **采购退货 ≠ 术后退料** | 采购退货是「这批货有问题，退回供应商」（M15-03）；术后退料是「手术没用完，退回二级库」（M15-06）。前者影响应付账款，后者不影响 |
| **含税价 ≠ 不含税价** | 订单可能按含税价谈（常见），库存成本按**不含税价**记账（财务口径）。两者的换算公式与误差必须在设计期明确 |

## 3. 业务模型

### 3.1 七层单据模型

```
采购申请（m15_purchase_plan）
    │ 1 : N（一计划可拆多订单）
    ▼
采购订单（m15_purchase_order）
    │ 1 : N（一订单可分多次到货）
    ▼
到货单（m15_receipt）
    │ 1 : N（一次到货可拆多验收批）
    ▼
验收单（m15_receipt_item）
    │ 1 : 0..1（合格部分生成入库）
    ▼
入库单（m15_inbound）
    │ 1 : N（一次入库可生成多个批次）
    ▼
批次记录（m15_stock_batch，M15-01）
    │ 1 : 0..1（有质量问题可退货）
    ▼
采购退货单（m15_purchase_return）
```

**为什么分七层而不合并：**

| 层 | 独立理由 |
|---|---|
| 计划 → 订单 | 计划是内部需求（可拆可合），订单是对外承诺（法律文件，不能随意改） |
| 订单 → 到货 | 一订单分多次到货是常态（供应商分批送），合并会丢失到货记录 |
| 到货 → 验收 | 到货是「货到了」，验收是「核对过了」。二者之间可能有几小时延迟（等质检报告） |
| 验收 → 入库 | 验收合格后才入库。合并会导致不合格品被计入库存 |
| 入库 → 退货 | 入库后仍可能发现问题（如术后发现包装破损），此时走退货流程而非改一条入库记录 |

### 3.2 单据状态机

**采购申请状态机（9 态）：**

```
┌────────┐  提交   ┌──────────────┐  审批通过  ┌───────────┐

│ 草稿    │        │ 已提交待审批  │          │ 已批准     │
└───┬────┘        └──────┬───────┘          └─────┬─────┘
    │                    │ 驳回                    │ 生成订单
    │ 作废                ▼                        ▼
    │              ┌───────────┐           ┌─────────────┐
    │              │ REJECTED  │           │ CONVERTED   │
    │              │ 已驳回     │           │ 已转订单     │
    │              └─────┬─────┘           └─────────────┘
    │                    │ 重新编辑
    │                    ▼
    │              ┌────────┐
    └─────────────►│DRAFT   │
                   └────────┘

┌──────────────────────┐
│ CANCELLED（已作废）   │  ← 从 DRAFT / SUBMITTED / APPROVED 均可作废
└──────────────────────┘
```

### 3.3 数量恒等式（核心约束模型）

一次采购的数量必须满足以下恒等式：

```
订单数量（order_qty）
  = 累计到货数量（received_qty）
  + 未到货数量（pending_qty）

到货数量（received_qty）
  = 验收合格数量（accepted_qty）
  + 验收不合格数量（rejected_qty）

验收合格数量（accepted_qty）
  = 入库数量（inbound_qty）
  + 待入库数量（pending_inbound_qty）
```

**三者约束在数据库层落地：**

```sql
-- 订单明细：累计到货不超订单数量
CHECK (received_qty >= 0 AND received_qty <= order_qty)

-- 验收明细：合格 + 不合格 = 到货
CHECK (accepted_qty + rejected_qty = received_qty)

-- 入库明细：入库数量 <= 验收合格数量
CHECK (inbound_qty >= 0 AND inbound_qty <= accepted_qty)
```

**为什么不用「允许超量到货」：** 供应商多送会打乱库存计划（多出来的 20 片晶体占资金且可能过期）。若确实需要超量（如厂商整箱发货不拆箱），必须走「变更订单」把 `order_qty` 改大，留下变更记录。

### 3.4 金额与税额模型

**含税与不含税换算：**

```
不含税金额 = 含税金额 / (1 + 税率)
税额       = 含税金额 - 不含税金额
```

**税率来源：**

| 耗材类别 | 典型税率 | 说明 |
|---|---|---|
| 医疗器械（含人工晶体） | 13% | 增值税一般税率 |
| 药品 | 13% | 同一般税率 |
| 防疫物资（部分） | 9% | 政策优惠期 |
| 农产品（如某些中药饮片） | 9% | 视品类 |
| 小规模纳税人供应商 | 3% / 1% | 以供应商资质为准 |

**精确计算规则：**

```
行不含税金额 = ROUND(行含税金额 / (1 + 税率), 2)
行税额       = 行含税金额 - 行不含税金额
订单不含税合计 = SUM(行不含税金额)
订单税额合计   = SUM(行税额)
订单含税合计   = SUM(行含税金额)
```

**为什么「先逐行算，再汇总」而不是「先汇总再算税」：**

含税价 100.00 元、税率 13%，不含税 = 88.4956（保留 2 位 = 88.50），税额 = 11.50。

- 单行：88.50 + 11.50 = 100.00 ✅
- 10 行汇总后算：含税 1000.00 → 不含税 = 884.96（1000/1.13 = 884.9558 → 884.96），税额 = 115.04
- 逐行算再汇总：88.50 × 10 = 885.00，税额 11.50 × 10 = 115.00

**两者差 0.04 元。** 财务要求「发票税额必须等于订单税额」，若汇总后算，10 行差 0.04、100 行差 0.40，长期累积会导致三单匹配持续失败。**逐行先算再汇总，与增值税发票「逐行开票、汇总计税」口径一致。**

### 3.5 首营核查模型

**首营企业（首次与新供应商交易）必须核查：**

| # | 项目 | 校验来源 | 不通过 |
|---|---|---|---|
| 1 | 营业执照在有效期内 | M01-05 | 阻断 |
| 2 | 医疗器械经营许可证在有效期内 | M01-05 | 阻断 |
| 3 | 经营方式包含「批发」或「生产」 | M01-05 | 阻断 |
| 4 | 经营范围包含所购耗材类别 | M01-05 + M01-04 | 阻断 |
| 5 | 法人授权委托书在有效期内 | M01-05 | 阻断 |
| 6 | 销售人员身份证与授权书一致 | M01-05 | 警告（人工确认） |
| 7 | 质量保证协议已签署 | M01-05 | 阻断 |
| 8 | 供应商状态为 ENABLED | M01-05 | 阻断 |

**首营品种（首次采购该耗材）：**

| # | 项目 | 校验来源 | 不通过 |
|---|---|---|---|
| 1 | 医疗器械注册证在有效期内 | M01-04 `mdm_material_registration` | 阻断 |
| 2 | 注册证产品名称与耗材名称一致 | M01-04 | 警告 |
| 3 | 注册证规格型号覆盖本次采购规格 | M01-04 | 阻断 |
| 4 | 生产厂商在合格供应商名录中 | M01-04 + M01-05 | 阻断 |
| 5 | 进口耗材有报关单（首次） | 上传附件 | 阻断 |
| 6 | 检验报告（首次） | 上传附件 | 阻断 |

**为什么首营核查做成独立环节而不是下单时顺手校验：**

下单时校验只能拦住「下单那一刻资质是过期的」，但首营核查还有「资质文件本身是否齐全、是否覆盖本次产品」的判断，需要人工看附件、核签字。做成独立环节后：
1. 首营核查结果可存档（检查必查项）
2. 核查通过后 30 天内同一供应商同一耗材重复采购无需重复核查
3. 采购员不必每次都翻附件，效率提升

### 3.6 冷链耗材的验收模型

| 耗材 | 温度要求 | 到货必查 |
|---|---|---|
| 生物羊膜 | 2~8 ℃（冷藏） | 全程温度记录 + 到货实测温度 |
| 粘弹剂（部分品牌） | 2~25 ℃（室温可控） | 保存温度说明 + 到货实测温度 |
| 硅油 / 重水 | 常温 15~25 ℃ | 到货实测温度 |
| 新鲜角膜（角膜移植） | 2~8 ℃（专用保存液） | 保存液有效期 + 温度曲线 |

**到货温度判定：**

| 实测温度 | 判定 | 处理 |
|---|---|---|
| 在范围内 | 合格 | 正常入库 |
| 超出范围 <30 分钟（依据温度记录仪曲线） | 有条件合格 | 质量负责人签字确认可使用 |
| 超出范围 ≥30 分钟 | 拒收 | 退回供应商并记不良记录 |
| 无温度记录 | 拒收 | 冷链耗材无记录即不合规 |

**为什么「超温 <30 分钟可人工确认」而不是一律拒收：**

真实场景中，供应商保温箱从车上搬到验收台，若验收员忙于其他事务晚了 10 分钟才开箱，箱内温度可能已升到 9 ℃。若一律拒收，供应商会反复投诉「你们验收太慢」。设计上用「温度记录仪曲线」判断：若记录仪显示全程在范围内，只是验收台测量时略高，则合格；若记录仪本身超温，则拒收。**关键在于「记录仪是供应商的还是医院的」——本院要求供应商必须随货提供独立温度记录仪，记录仪数据不可篡改。**

### 3.7 部分合格处理模型

**到货 100 片人工晶体，验收后发现：**

| 编号 | 批号 | 数量 | 验收结果 | 理由 |
|---|---|---|---|---|
| 1 | B240815-01 | 98 | 合格 | 外观完好、效期 2027-08、注册证有效 |
| 2 | B240815-01 | 2 | 不合格 | 包装有压痕（可能影响无菌） |

**处理方式对比：**

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 整单拒收 | 100 片全部退回 | 98 片可使用却被退回，延误 3 台手术 |
| B. 全部入库 | 100 片全入库存 | 2 片不良品混入，可能在术中被发现 |
| **C. 部分合格** | **98 片入库、2 片拒收** | **推荐**：不影响手术、不污染库存、不良可追溯 |

**实施要点：**

1. 验收明细按「批号 + 验收结果」拆分：同一批号可拆成两行（合格行 + 不合格行）
2. 入库单只生成合格行对应的批次
3. 拒收行进入 `m15_reject` 表，随货同行单上注明，供应商签字确认
4. 系统自动通知供应商补送 2 片（生成「补货提醒」）

### 3.8 三单匹配模型

```
        ┌──────────────┐
        │  采购订单     │  订单数量、单价、总额
        │  m15_purchase │
        │  _order       │
        └──────┬───────┘
               │
               │ 匹配维度：
               │  ① 耗材编码一致
               │  ② 单价一致（容差 ±0.01）
               │  ③ 数量：入库 ≤ 订单
               │
        ┌──────┴───────┐
        │  入库单       │  入库数量、不含税金额
        │  m15_inbound  │
        └──────┬───────┘
               │
               │ 匹配维度：
               │  ④ 不含税金额一致（容差 ±0.05）
               │  ⑤ 税额一致（容差 ±0.05）
               │
        ┌──────┴───────┐
        │  发票         │  发票号、不含税金额、税额
        │  m15_invoice  │
        │  _match       │
        └──────────────┘
```

**匹配结果四态：**

| 结果 | 含义 | 后续动作 |
|---|---|---|
| `MATCHED` | 三单完全一致 | 可付款（通知 M17） |
| `QUANTITY_DIFF` | 数量不一致（发票多于入库） | 要求供应商红冲重开或说明 |
| `AMOUNT_DIFF` | 金额超容差 | 财务会计核对 |
| `NOT_MATCHED` | 缺单（缺订单或缺入库单） | 无法匹配，提示补单 |

**为什么容差 0.01 / 0.05：**

- 单价容差 0.01：不同系统保留小数位不同（订单 4 位、发票 2 位），0.01 以内视为一致
- 税额容差 0.05：含税 10000 元 13% 税，理论税额 1150.44，实开票可能 1150.45（发票系统算法差异），0.05 以内可接受
- **超过容差必须人工处理**，不允许自动放行——税务稽查时「税额差 0.1 元」也是问题

### 3.9 采购周期与准时率模型

**采购周期（Lead Time）：**

```
采购周期 = 入库日期 - 申请提交日期
其中分阶段：
  申请审批时长 = 审批完成日 - 提交日
  订单执行时长 = 到货日 - 订单下达日
  验收入库时长 = 入库日 - 到货日
```

**准时率：**

```
行准时率 = 到货日 <= 约定交期 的行数 / 总行数
订单准时率 = 全部行都在约定交期前到齐的订单数 / 总订单数
供应商准时率 = 该供应商订单准时率
```

**为什么「行准时率」和「订单准时率」都要有：**

一个订单 10 行，9 行准时、1 行迟到 3 天。按行算 90%，按订单算 0%（未到齐）。前者反映「大部分货还是来了」，后者反映「这单手术是否受影响」。两者都要，管理者根据场景选择。

### 3.10 高值耗材直送模式

**传统模式（备货入库）：**

```
供应商 → 一级库入库 → 手术室申领 → 二级库出库 → 术中使用 → 术后结算
         （占库存资金）   （周转1~2天）
```

**直送模式（术后结算）：**

```
供应商 → 手术室 （术前送到，不入一级库）
              ↓ 术中使用
         术后确认使用 → 生成入库单 + 消耗单 → 结算
```

**适用条件：**

| 条件 | 说明 |
|---|---|
| 单件价值 ≥3000 元 | 人工晶体、玻璃体填充物、青光眼引流阀 |
| 用量可预测 | 术前排程确定使用何规格 |
| 供应商可及时送达 | 术前 1 天送达手术室 |

**为什么高值耗材要直送：**

人工晶体单件 3000~15000 元，若备货 500 片，占用资金 150 万~750 万。而每月实际用量与排程相关，备货过多会滞销、备货不足会延误手术。直送模式下，「不入库就不占资金」，只有实际使用才形成库存与应付账款。

**系统实现：**

- 术前 M15-06 从 M09 台次获取「预计使用的晶体规格」
- 供应商按此送达，护士在手术室二级库执行「直送登记」（记 `is_direct_delivery=TRUE`）
- 术中使用后，生成「入库单（直送）+ 消耗单」两条记录
- 入库单的 `inbound_at` 与消耗的 `used_at` 同一时刻

```python
def money(value) -> Decimal:
    """统一金额计算：保留两位小数、四舍五入。"""
    return Decimal(str(value)).quantize(CENT, rounding=ROUND_HALF_UP)


def resolve_tier(total: Decimal) -> str:
    """按金额解析审批档位。"""
    for limit, role, _name in APPROVAL_TIERS:
        if limit is None or total <= limit:
            return role
    return "EXECUTIVE_MEETING"


class PlanService:
    """采购申请服务。"""

    CACHE_WORKBENCH = "m15:purchase:workbench:{uid}"

    @classmethod
    async def list_plans(cls, query, user: dict) -> dict:
        """采购申请列表（分页）。"""
        db = get_session()
        async with db as session:
            where = ["is_deleted = FALSE"]
            params = {}
            if query.status:
                where.append("status = :status")
                params["status"] = query.status
            if query.dept_id:
                where.append("dept_id = :dept_id")
                params["dept_id"] = query.dept_id
            if query.plan_date_from:

                params["d0"] = query.plan_date_from
            if query.plan_date_to:
                where.append("plan_date <= :d1")
                params["d1"] = query.plan_date_to
            if query.keyword:
                where.append(
                    "(plan_no ILIKE :kw OR title ILIKE :kw)"
                )
                params["kw"] = "%" + query.keyword + "%"
            where_sql = " AND ".join(where)

            total_sql = "SELECT COUNT(*) FROM m15_purchase_plan WHERE " + where_sql
            total_row = (await session.execute(text(total_sql), params)).scalar()
            total = int(total_row or 0)

            params["lim"] = query.page_size
            params["off"] = (query.page - 1) * query.page_size
            rows = (await session.execute(text(page_sql), params)).all()

                "status_text": cls._status_text(r[8]),

    @classmethod
    async def create(cls, body, user: dict) -> dict:
        """创建采购申请。"""
        today = date.today()
        if body.planned_inbound_date < today + timedelta(days=2):
            raise BizException("1503003", "计划入库日期不早于今天 +2 天")
        if not body.items:
            raise BizException("1503004", "采购明细至少 1 项")

        codes = [it.material_code for it in body.items]
        if len(codes) != len(set(codes)):
            raise BizException("1503005", "同一耗材重复出现")

        # 校验耗材供货关系
        rel = await MaterialClient.supplier_rel(codes)
        missing = [c for c in codes if not rel.get(c)]
        if missing:
            raise BizException(
                "1503007",
                "以下耗材无合格供货关系：%s" % "、".join(missing),
            )

        # 校验数量与包装
        total = Decimal("0")
        for it in body.items:
            info = await MaterialClient.brief(it.material_code)
            factor = Decimal(str(info.get("pack_factor") or 1))
            qty = Decimal(str(it.qty))
            if qty <= 0 or (factor > 1 and qty % factor != 0):
                raise BizException(
                    "1503006",
                    "耗材 %s 数量必须为正且为包装 %s 的整数倍" % (it.material_code, factor),
                )
            total += money4(qty * Decimal(str(it.estimated_unit_price)))

        total = money(total)
        if total <= 0:
            raise BizException("1503010", "采购金额必须大于 0")
        if total > MAX_PLAN_AMOUNT:
            raise BizException("1503010", "采购金额超过单笔上限")

        if len(body.reason.strip()) < 20:
            raise BizException("1503008", "申请理由不足 20 字")
        if body.is_urgent and len((body.urgent_reason or "").strip()) < 20:
            raise BizException("1503009", "紧急采购必须提供紧急理由（≥20 字）")

        tier = resolve_tier(total)

        db = get_session()
        async with db as session:
            async with session.begin():
                plan_no = await cls._next_no(session, "PL")
                plan = M15PurchasePlan(
                    plan_no=plan_no,

                    dept_id=body.dept_id,
                    dept_name=body.dept_name,

                    is_urgent=body.is_urgent,
                    urgent_reason=body.urgent_reason,
                    budget_subject=body.budget_subject,
                    reason=body.reason,
                    total_amount=total,
                    status="DRAFT",
                    plan_date=body.plan_date or today,
                    planned_inbound_date=body.planned_inbound_date,
                    required_approver=tier,
                    required_approver_name=ROLE_NAMES.get(tier, tier),
                    created_by=user["employee_id"],
                    created_by_name=user["name"],
                )
                session.add(plan)
                await session.flush()

                for idx, it in enumerate(body.items, start=1):
                    info = await MaterialClient.brief(it.material_code)
                    session.add(
                        M15PlanItem(
                            plan_id=plan.id,
                            line_no=idx,
                            material_code=it.material_code,
                            material_name=info["material_name"],
                            spec=info.get("spec"),
                            unit=info.get("min_unit"),
                            qty=Decimal(str(it.qty)),
                            estimated_unit_price=money4(it.estimated_unit_price),
                            estimated_amount=money4(
                                Decimal(str(it.qty)) * Decimal(str(it.estimated_unit_price))
                            ),
                            expected_supplier_id=it.expected_supplier_id,
                            expected_supplier_name=it.expected_supplier_name,
                            reason=it.reason,
                            remark=it.remark,
                        )
                    )

        await AuditClient.record(
            module="M15-03",
            action="PLAN_CREATE",
            biz_id=plan.id,
            biz_no=plan_no,
            detail={"total_amount": str(total), "item_count": len(body.items)},
            user=user,
        )
        await cls._clear_cache(user["employee_id"])

        return {
            "plan_id": plan.id,
            "plan_no": plan_no,
            "status": "DRAFT",
            "total_amount": float(total),
            "item_count": len(body.items),
            "required_approver": tier,
            "required_approver_name": ROLE_NAMES.get(tier, tier),
            "created_at": datetime.now().isoformat(),

    @classmethod

                (

                    "SELECT COUNT(*) FROM m15_receipt "

            ).scalar()

        result = {
            "date": date.today().isoformat(),
            "counters": counters,
            "month_amount": money(month_amount or 0),
        }
        await redis_client.setex(cache_key, cls.CACHE_TTL, result)
        return result

    @classmethod
    async def replenish_suggestions(
        cls, warehouse_id: int, limit: int, user: dict
    ) -> dict:
        """补货建议：库存低于补货点的耗材。"""
        db = get_session()
        async with db as session:
            sql = text(
                "SELECT s.material_code, s.material_name, s.spec, s.unit, "
                "       SUM(s.qty_available) AS avail, "
                "       sp.reorder_point, sp.max_stock, sp.reorder_qty, "
                "       m.pack_factor "
                "FROM m15_stock s "
                "JOIN mdm_material_stock_policy sp ON sp.material_id = s.material_id "
                "     AND (sp.warehouse_id = s.warehouse_id OR sp.warehouse_id IS NULL) "
                "JOIN mdm_material m ON m.id = s.material_id "
                "WHERE s.warehouse_id = :wid AND s.is_deleted = FALSE "
                "  AND s.status = 'NORMAL' "
                "GROUP BY s.material_code, s.material_name, s.spec, s.unit, "
                "         sp.reorder_point, sp.max_stock, sp.reorder_qty, m.pack_factor "
                "HAVING SUM(s.qty_available) <= sp.reorder_point "
                "ORDER BY (SUM(s.qty_available) - sp.reorder_point) ASC "
                "LIMIT :lim"
            )
            rows = (await session.execute(sql, {"wid": warehouse_id, "lim": limit})).all()

        items = []
        for r in rows:
            suggest = max(
                Decimal(str(r[5] or 0)) - Decimal(str(r[4] or 0)),
                Decimal(str(r[6] or 0)),
            )
            factor = Decimal(str(r[7] or 1))
            if factor > 1:
                suggest = (suggest / factor).to_integral_value(rounding="ROUND_CEILING") * factor
            items.append({
                "material_code": r[0],
                "material_name": r[1],
                "spec": r[2],
                "unit": r[3],
                "available": float(r[4]),
                "reorder_point": float(r[5] or 0),
                "max_stock": float(r[6] or 0),
                "suggest_qty": float(suggest),
            })
        return {"warehouse_id": warehouse_id, "items": items, "total": len(items)}

    @classmethod
    async def create(cls, body, user: dict) -> dict:
        """创建采购订单。"""
        today = date.today()
        if not body.items:
            raise BizException("1503011", "采购订单至少 1 项明细")
        if body.expected_delivery_date < today + timedelta(days=1):
            raise BizException("1503014", "约定交期不早于下单日 +1 天")

        supplier = await SupplierClient.brief(body.supplier_id)
        if not supplier or supplier.get("status") != "ENABLED":
            raise BizException("1503012", "供应商不存在或资质无效")

        qual = await SupplierClient.qualification(body.supplier_id)
        # 资质不可降级：接口失败直接抛错
        if not qual.get("license_valid"):
            raise BizException("1503012", "供应商经营许可证已失效")

        rel = await MaterialClient.supplier_rel([it.material_code for it in body.items])
        for it in body.items:
            if not rel.get(it.material_code):
                raise BizException(
                    "1503013", "该供应商无此耗材的供货关系：%s" % it.material_code
                )
            if Decimal(str(it.unit_price)) <= 0:
                raise BizException("1503016", "单价非法")

        total_tax = Decimal("0")
        total_net = Decimal("0")
        total_tax_amount = Decimal("0")
        for it in body.items:
            amount = money4(Decimal(str(it.qty)) * Decimal(str(it.unit_price)))
            net = money4(amount / (Decimal("1") + Decimal(str(it.tax_rate))))
            total_tax += amount
            total_net += net
            total_tax_amount += amount - net

        db = get_session()
        async with db as session:
            async with session.begin():
                order_no = await PlanService._next_no(session, "PO")
                order = M15PurchaseOrder(
                    order_no=order_no,
                    supplier_id=body.supplier_id,
                    supplier_name=supplier["supplier_name"],
                    contract_no=body.contract_no,
                    payment_terms=body.payment_terms,
                    expected_delivery_date=body.expected_delivery_date,
                    total_amount_tax=money(total_tax),
                    total_amount_net=money(total_net),
                    total_tax_amount=money(total_tax_amount),
                    status="DRAFT",
                    source_plan_ids=body.source_plan_ids,
                    created_by=user["employee_id"],
                    created_by_name=user["name"],
                )
                session.add(order)
                await session.flush()

                for idx, it in enumerate(body.items, start=1):
                    info = await MaterialClient.brief(it.material_code)
                    amount = money4(Decimal(str(it.qty)) * Decimal(str(it.unit_price)))
                    net = money4(amount / (Decimal("1") + Decimal(str(it.tax_rate))))
                    session.add(
                        M15OrderItem(
                            order_id=order.id,
                            line_no=idx,
                            material_code=it.material_code,
                            material_name=info["material_name"],
                            spec=info.get("spec"),
                            unit=info.get("min_unit"),
                            qty=Decimal(str(it.qty)),
                            unit_price=money4(it.unit_price),
                            tax_rate=Decimal(str(it.tax_rate)),
                            amount_tax=amount,
                            amount_net=net,
                            tax_amount=amount - net,
                            received_qty=Decimal("0"),
                        )
                    )

        await AuditClient.record(
            module="M15-03",
            action="ORDER_CREATE",
            biz_id=order.id,
            biz_no=order_no,
            detail={"total": str(total_tax), "supplier_id": body.supplier_id},
            user=user,
        )

        return {
            "order_id": order.id,
            "order_no": order_no,
            "status": "DRAFT",
            "total_amount_tax": float(money(total_tax)),
            "total_amount_net": float(money(total_net)),
            "total_tax_amount": float(money(total_tax_amount)),
            "item_count": len(body.items),
        }

    @classmethod
    async def list_orders(cls, status, supplier_id, d0, d1, page, page_size, user) -> dict:
        """订单列表。"""
        db = get_session()
        async with db as session:
            where = ["is_deleted = FALSE"]
            params = {}
            if status:
                where.append("status = :status")
                params["status"] = status
            if supplier_id:
                where.append("supplier_id = :sid")
                params["sid"] = supplier_id
            if d0:
                where.append("expected_delivery_date >= :d0")
                params["d0"] = d0
            if d1:
                where.append("expected_delivery_date <= :d1")
                params["d1"] = d1
            where_sql = " AND ".join(where)

            total = int(
                (
                    await session.execute(
                        text("SELECT COUNT(*) FROM m15_purchase_order WHERE " + where_sql),
                        params,
                    )
                ).scalar()
                or 0
            )
            params["lim"] = page_size
            params["off"] = (page - 1) * page_size
            rows = (
                await session.execute(
                    text(
                        "SELECT id, order_no, supplier_name, total_amount_tax, status, "
                        "expected_delivery_date, issued_at, overdue_flag "
                        "FROM m15_purchase_order WHERE " + where_sql + " "
                        "ORDER BY expected_delivery_date DESC, created_at DESC "
                        "LIMIT :lim OFFSET :off"
                    ),
                    params,
                )
            ).all()

        items = []
        for r in rows:
            items.append({
                "order_id": r[0],
                "order_no": r[1],
                "supplier_name": r[2],
                "total_amount_tax": float(r[3]),
                "status": r[4],
                "expected_delivery_date": r[5].isoformat() if r[5] else None,
                "issued_at": r[6].isoformat() if r[6] else None,
                "is_overdue": bool(r[7]),
            })
        return {
            "items": items,
            "total": total,
            "page": page,
            "page_size": page_size,
            "pages": (total + page_size - 1) // page_size,
        }

    @classmethod
    async def inspect(cls, receipt_id: int, body, user: dict) -> dict:
        """提交验收结果。"""
        if len((body.inspection_note or "").strip()) < 5:
            raise BizException("1503028", "验收说明至少 5 字")

        db = get_session()
        async with db as session:
            async with session.begin():
                receipt = (
                    await session.execute(
                        select(M15Receipt)
                        .where(M15Receipt.id == receipt_id)
                        .with_for_update()
                    )
                ).scalar_one_or_none()
                if not receipt:
                    raise BizException("1503024", "到货单不存在")
                if receipt.status != "ARRIVED":
                    raise BizException("1503002", "到货单状态不允许验收")

                # 首营核查
                first_check = await cls._ensure_first_check(session, receipt)
                if first_check.get("need_check") and not first_check.get("passed"):
                    raise BizException("1503024", "首营核查未通过不可验收")

                # 冷链温度判定
                cold = receipt.cold_chain_json or {}
                if cold:
                    max_t = float(cold.get("max_temp") or 0)
                    min_t = float(cold.get("min_temp") or 0)
                    arrive_t = float(cold.get("arrival_temp") or 0)
                    if max_t > 8.0 or min_t < 2.0 or arrive_t > 8.0 or arrive_t < 2.0:
                        raise BizException(
                            "1503030", "冷链耗材温度超范围，不可验收"
                        )

                items = {
                    ri.id: ri
                    for ri in (
                        await session.execute(
                            select(M15ReceiptItem)
                            .where(M15ReceiptItem.receipt_id == receipt_id)
                            .order_by(M15ReceiptItem.line_no)
                        )
                    ).scalars()
                }

                has_reject = False
                total_received = Decimal("0")
                total_accepted = Decimal("0")
                total_rejected = Decimal("0")

                for it in body.items:
                    ri = items.get(it.receipt_item_id)
                    if not ri:
                        raise BizException("1503017", "到货明细不存在")

                    info = await MaterialClient.brief(ri.material_code)
                    reg = await MaterialClient.registration(ri.material_code)
                    if reg and reg.get("expire_date"):
                        if date.fromisoformat(reg["expire_date"]) < date.today():
                            raise BizException(
                                "1503025", "注册证已过期不可验收：%s" % ri.material_code
                            )
                    if ri.sterile_expiry_date and ri.sterile_expiry_date < date.today():
                        raise BizException(
                            "1503026", "灭菌有效期已过不可验收：%s" % ri.material_code
                        )

                    acc = Decimal(str(it.accepted_qty))
                    rej = Decimal(str(it.rejected_qty))
                    if acc + rej != Decimal(str(ri.received_qty)):
                        raise BizException(
                            "1503027",
                            "合格数量与不合格数量之和必须等于到货总量：%s" % ri.material_code,
                        )
                    if rej > 0:
                        if len((it.reject_reason or "").strip()) < 10:
                            raise BizException(
                                "1503028", "不合格数量大于 0 时必须说明原因（≥10 字）"
                            )
                        has_reject = True

                    ri.checks_json = it.checks
                    ri.accepted_qty = acc
                    ri.rejected_qty = rej
                    ri.reject_reason = it.reject_reason
                    total_received += Decimal(str(ri.received_qty))
                    total_accepted += acc
                    total_rejected += rej

                if has_reject and not body.supplier_confirm_url:
                    raise BizException("1503029", "部分合格必须上传供应商确认材料")

                receipt.status = "INSPECTED"
                receipt.inspection_result = body.inspection_result
                receipt.inspection_note = body.inspection_note
                receipt.supplier_confirm_url = body.supplier_confirm_url
                receipt.inspect_by = user["employee_id"]
                receipt.inspect_by_name = user["name"]
                receipt.inspect_at = datetime.now()
                receipt.total_received = total_received
                receipt.total_accepted = total_accepted
                receipt.total_rejected = total_rejected

                    inbound_no=inbound_no,
                    receipt_id=receipt_id,
                    receipt_no=receipt.receipt_no,
                    order_id=receipt.order_id,
                    order_no=receipt.order_no,
                    supplier_name=receipt.supplier_name,
                    status="DRAFT",
                    total_qty=total_accepted,
                    created_by=user["employee_id"],
                )
                session.add(inbound)
                await session.flush()

                for ri in items.values():
                    if ri.accepted_qty <= 0:
                        continue
                    oi = (
                        await session.execute(
                            select(M15OrderItem).where(M15OrderItem.id == ri.order_item_id)

                        M15InboundItem(
                            inbound_id=inbound.id,
                            line_no=line,
                            receipt_item_id=ri.id,
                            material_code=ri.material_code,
                            material_name=ri.material_name,
                            spec=ri.spec,
                            unit=ri.unit,
                            batch_no=ri.batch_no,
                            qty=ri.accepted_qty,
                            unit_price=oi.unit_price,

        await AuditClient.record(
            module="M15-03",
```

### 6.7 专题：为什么入库必须「先写本地入库单，再调库存服务」

入库操作需要同时做两件事：
1. 在 M15-03 写一条入库单（业务单据）
2. 调 M15-01 `POST /internal/v1/m15/stock/inbound` 写库存台账与流水（库存事实）

**为什么不能直接调库存服务，而要先写本地入库单？**

| 方案 | 说明 | 问题 |
|---|---|---|
| A. 只调库存服务 | 入库单业务信息由库存服务负责记录 | M15-01 不认识供应商、订单、验收结果，无法记录入库单的完整信息 |
| B. 只写本地不入库存 | 单据完整但库存没变 | 库存没变，出库时库存不足 |
| **C. 先写入库单（DRAFT）→ 调库存服务 → 更新入库单为 CONFIRMED** | **推荐** | 有中间态，可补偿 |

**方案 C 的三种失败场景与处理：**

| 场景 | 状态 | 处理 |
|---|---|---|
| 写入库单失败 | 无记录 | 直接报错，用户重试 |
| 入库单写成功、调库存服务失败 | 入库单 DRAFT | 用户点「确认入库」重试；后台每 10 分钟扫描 DRAFT 状态超过 30 分钟的入库单自动重试（最多 10 次） |
| 入库单写成功、调库存服务成功、更新入库单失败 | 入库单 DRAFT 但库存已加 | 后台对账任务比对「M15-01 流水中有 IN_PURCHASE 但 M15-03 入库单非 CONFIRMED」的记录，自动修正 |

**幂等保证：**

调库存服务时传 `idempotency_key = INBOUND:{入库单 ID}`，M15-01 侧对同一幂等键第二次调用直接返回上次结果，不重复加库存。这样即使「更新入库单失败、后台重试」，也不会重复加库存。

**两个职责分离设计：**

1. **`purchase:manage` 与 `purchase:approve` 互斥**：耗材科科长只有审批权，不能自己编制计划。这样「编制-审批」两环节由不同人完成。

**为什么 IT 管理员与系统管理员无任何业务查询权限：**

采购与入库记录含供应商名称、采购价格、成本金额，属商业敏感数据。若运维能查看，存在泄露给竞争对手的风险；若运维能修改，审计链断裂。运维排查需由耗材科长授权临时账号（有效期 2 小时），授权记录进审计日志。

### 9.3 数据权限

```python
"""M15-03 数据权限注入。"""

from typing import Tuple

from sqlalchemy import Select

from app.models.m15.purchase import M15PurchasePlan


def apply_purchase_scope(stmt: Select, user: dict, domain: str = "DEPT") -> Select:
    """按数据权限域过滤。

    域：
      - ALL: 不过滤
      - DEPT: 按 dept_id 过滤
      - SELF: 按 created_by 过滤
    """
    if user.get("has_permission", lambda p: False)("m15:purchase:all"):
        return stmt

    if domain == "ALL":
        return stmt

    if domain == "DEPT":
        dept_id = user.get("dept_id")
        if not dept_id:
            return stmt.where(M15PurchasePlan.id == -1)
        return stmt.where(
            (M15PurchasePlan.dept_id == dept_id)
            | (M15PurchasePlan.created_by == user["employee_id"])
        )

    if domain == "SELF":
        return stmt.where(M15PurchasePlan.created_by == user["employee_id"])

    return stmt.where(M15PurchasePlan.id == -1)


def resolve_scope(user: dict) -> Tuple[str, str]:
    """决定默认数据权限域。"""
    if user.get("has_permission", lambda p: False)("m15:purchase:all"):
        return "ALL", "全部"
    if user.get("dept_id"):
        return "DEPT", "本科室"
    return "SELF", "本人"
```

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 场景 | HTTP 状态 | 错误码 | 处理 |
|---|---|---|---|---|
| 参数异常 | 字段校验失败 | 400 | 1503003~1503049 | 前端展示字段级错误 |
| 业务规则异常 | 状态不允许、金额超限 | 400 | 1503002、1503010 等 | 前端提示可操作建议 |
| 权限异常 | 无权限码或数据范围外的数据 | 403 | 1503046 | 前端提示「无权限」 |
| 资源不存在 | 按 ID 查不到 | 404 | 1503001 等 | 前端返回列表 |
| 依赖异常 | U-01~U-06 失败 | 503 | 1503047、1503048 | 提示稍后重试 |
| 系统异常 | 数据库、代码异常 | 500 | — | 统一错误页 + 告警 |


```
  │ 作废            │ 供应商拒接
  ▼                ▼
CANCELLED      REJECTED

任一状态（除 COMPLETED/CANCELLED）──关闭──► CLOSED
```
