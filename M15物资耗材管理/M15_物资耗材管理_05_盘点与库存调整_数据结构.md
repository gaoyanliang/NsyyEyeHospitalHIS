**设计说明：**

| 决策 | 内容 | 理由 |
|---|---|---|
| 无物理外键 | 全部引用为逻辑引用 | 与 M15 其他子模块一致；跨子模块引用加外键会带来锁竞争，且归档迁移困难 |
| 名称快照 | `m15_stocktake_item` 冗余 `material_code`/`material_name`/`spec`/`unit`/`location_code` | 盘点是「某一时刻的事实」，耗材改名、库位调整后历史盘点表仍要能说清 |
| 账面数快照 | `book_qty` 是生成盘点表那一刻的库存量 | 盘点期间账面数可能因冻结漏洞变化，快照保证可比 |
| `diff_qty` 普通列 | 非生成列 | 实盘录入可多次修正，且需保留修改痕迹（`version` 递增 + 日志）；调整时按审批后的单价计算，不能实时生成 |
| `version` 乐观锁 | `m15_stocktake_item.version` | 防止多人同时录入同一明细导致互相覆盖（PDA 与 PC 可能同时操作） |
| 冻结落表 | `m15_stocktake_freeze` 而非仅 Redis | Redis 重启会丢失冻结标记，盘点中途解冻会让账实不可比 |
| 调整单独立 | `m15_stock_adjust` 而非直接写 800 条台账 | 调整单是财务入账凭证，有单据号有审批；M15-01 按调整单粒度幂等 |
| 都是普通表 | 6 表全不分区 | `stocktake_no`/`adjust_no`/`(stocktake_id)` 是跨年唯一约束，分区会迫使唯一索引含分区键从而破坏语义 |

**约束说明：**

```sql
-- 单号格式：ST-YYYY-NNNN
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_no
    CHECK (stocktake_no ~ '^ST-[0-9]{4}-[0-9]{4}$');

-- 盘点类型枚举
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_type
    CHECK (stocktake_type IN ('FULL', 'CYCLE', 'SPECIAL'));

-- 状态枚举
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_status
    CHECK (status IN ('PLANNING', 'TABLE_READY', 'COUNTING', 'COUNTED',
                      'PENDING_APPROVAL', 'APPROVED', 'REJECTED',
                      'ADJUSTING', 'COMPLETED', 'CANCELLED'));

-- 冻结方式枚举
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_freeze_mode
    CHECK (freeze_mode IN ('WAREHOUSE', 'BATCH'));

-- 差异级别枚举
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_diff_level
    CHECK (diff_level IS NULL OR diff_level IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL'));

-- 已录入数不超过总数
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_counted
    CHECK (counted_count >= 0 AND (item_count = 0 OR counted_count <= item_count));

-- 差异项数不超过总项数
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_diff_count
    CHECK (diff_item_count >= 0 AND (item_count = 0 OR diff_item_count <= item_count));

-- 账面金额非负
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_book_amount
    CHECK (total_book_amount >= 0);

-- 生成盘点表后才允许有明细数与账面金额
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_generated
    CHECK (status IN ('PLANNING') OR (item_count > 0 AND generated_at IS NOT NULL));

-- 完成后必须有完成时间
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_completed
    CHECK (status <> 'COMPLETED' OR completed_at IS NOT NULL);

-- 审批通过必须有审批人与时间
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_approved
    CHECK (status NOT IN ('APPROVED', 'ADJUSTING', 'COMPLETED')
           OR (approved_by IS NOT NULL AND approved_at IS NOT NULL));

-- 取消必须有原因
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_cancelled
    CHECK (status <> 'CANCELLED'
           OR (cancel_reason IS NOT NULL AND char_length(btrim(cancel_reason)) >= 10
               AND cancelled_at IS NOT NULL));

-- 驳回必须有原因
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_rejected
    CHECK (status <> 'REJECTED'
           OR (reject_reason IS NOT NULL AND char_length(btrim(reject_reason)) >= 10));

-- 时间序列：生成 <= 完成实盘 <= 提交审批 <= 审批通过 <= 完成
ALTER TABLE m15_stocktake ADD CONSTRAINT ck_m15_stocktake_time_seq
    CHECK ((generated_at IS NULL OR finished_at IS NULL OR finished_at >= generated_at)
       AND (submitted_at IS NULL OR finished_at IS NULL OR submitted_at >= finished_at)
       AND (approved_at IS NULL OR submitted_at IS NULL OR approved_at >= submitted_at)
       AND (completed_at IS NULL OR approved_at IS NULL OR completed_at >= approved_at));

-- ★ 关键：同一仓库同时只允许一个未完成盘点
CREATE UNIQUE INDEX uk_m15_stocktake_warehouse_active
    ON m15_stocktake (warehouse_id)
    WHERE status NOT IN ('COMPLETED', 'CANCELLED') AND is_deleted = FALSE;
```

```
                                                      │
```

**约束说明：**

```sql
-- 行号必须为正
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_line_no
    CHECK (line_no > 0);

-- 账面数量非负
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_book_qty
    CHECK (book_qty >= 0);

-- 实盘数量非负
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_actual_qty
    CHECK (actual_qty IS NULL OR actual_qty >= 0);

-- 差异数量非负检查（可为负）
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_diff_qty
    CHECK (diff_qty IS NULL OR (actual_qty IS NOT NULL
           AND abs(diff_qty - (actual_qty - book_qty)) < 0.0001));

-- 差异金额非负（用绝对值）
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_diff_amount
    CHECK (diff_amount >= 0);

-- 差异金额与差异数量、单价自洽
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_diff_calc
    CHECK (diff_qty IS NULL OR abs(diff_amount - ROUND(abs(diff_qty) * unit_cost, 2)) < 0.01);

-- 未录入时差异必须为 NULL
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_not_counted
    CHECK (actual_qty IS NOT NULL OR (diff_qty IS NULL AND diff_reason IS NULL
           AND counted_at IS NULL));

-- 有差异时必须选原因
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_diff_reason
    CHECK ((diff_qty IS NULL OR diff_qty = 0) OR diff_reason IS NOT NULL);

-- 差异原因为 NULL 时差异必须为 0 或 NULL
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_reason_only_diff
    CHECK (diff_reason IS NULL OR (diff_qty IS NOT NULL AND diff_qty <> 0));

-- 差异原因枚举
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_reason_enum
    CHECK (diff_reason IS NULL OR diff_reason IN (
        'RECEIVING_ERROR', 'UNDAMAGED_REPORT', 'EXPIRED_UNDETECTED',
        'MIXED_BATCH', 'THEFT', 'SYSTEM_ERROR', 'UNKNOWN'));

-- 差异级别枚举
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_level
    CHECK (diff_level IS NULL OR diff_level IN ('LOW', 'MEDIUM', 'HIGH', 'CRITICAL'));

-- 大额差异（≥5000）必须有附件
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_critical_attach
    CHECK (diff_amount < 5000 OR attachment_url IS NOT NULL);

-- 录入后必须有录人人
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_counted_by
    CHECK (actual_qty IS NULL OR (counted_by IS NOT NULL AND counted_at IS NOT NULL));

-- 单价非负
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_unit_cost
    CHECK (unit_cost >= 0);

-- 版本号递增
ALTER TABLE m15_stocktake_item ADD CONSTRAINT ck_m15_sti_version
    CHECK (version >= 1);
```

**设计要点：**

- `book_qty` 是生成盘点表那一刻的快照，**不是实时库存量**。盘点期间即使有冻结漏洞导致库存变化，账面数也不变，才能与实盘比较。
- `diff_amount` 存**绝对值**（盘亏盘盈都是正数），方向由 `diff_qty` 的正负表达。汇总时用 `CASE WHEN diff_qty < 0` 区分。
- `diff_qty = actual_qty − book_qty` 是三方绑定的核心约束，防止「改了数量但差异没更新」的脏数据（那种数据在汇总时会被重复统计）。
- `actual_qty IS NULL` 表示「未盘点」，与 `actual_qty = 0`（盘点后确实是 0）语义完全不同。用 `DEFAULT 0` 会分不清这两种情况。
- `version` 乐观锁：PDA 与 PC 可能同时对同一明细录入，`UPDATE ... WHERE version = :v` 失败则提示「已被他人录入」。

```sql
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_code
    CHECK (param_code ~ '^M15\.STOCKTAKE\.[A-Z][A-Z0-9_.]*$');

-- 类型枚举
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_type
    CHECK (param_type IN ('STRING', 'INT', 'DECIMAL', 'BOOL'));

-- 分组枚举
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_group
    CHECK (param_group IN ('FREEZE', 'DIFF', 'APPROVAL', 'CYCLE', 'LIMIT'));

-- 作用域枚举
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_scope
    CHECK (scope IN ('GLOBAL', 'WAREHOUSE'));

-- GLOBAL 作用域不得有 scope_id
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_global
    CHECK (scope <> 'GLOBAL' OR scope_id IS NULL);

-- 非 GLOBAL 必须有 scope_id
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_scope_id
    CHECK (scope = 'GLOBAL' OR scope_id IS NOT NULL);

-- 数值类型必须有范围
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_range
    CHECK (param_type NOT IN ('INT', 'DECIMAL')
           OR (min_value IS NOT NULL AND max_value IS NOT NULL));

-- 敏感参数必须可编辑
ALTER TABLE m15_stocktake_config ADD CONSTRAINT ck_m15_stcfg_sensitive
    CHECK (is_sensitive = FALSE OR is_editable = TRUE);

-- ★ 关键：唯一索引用 COALESCE 处理 NULL
CREATE UNIQUE INDEX uk_m15_stcfg_key
    ON m15_stocktake_config (param_code, scope, COALESCE(scope_id, ''))
    WHERE is_deleted = FALSE;
```

**为什么唯一索引要 `COALESCE`：**

PostgreSQL 认为 `NULL` 与 `NULL` 互不相等。若直接写 `(param_code, scope, scope_id)`，两条 `scope_id IS NULL` 的 GLOBAL 参数都能插入，`SUM` 查询会得到 2 倍数据。本项目部分环境是 PG 14，不支持 `NULLS NOT DISTINCT`（PG 15+ 才有），所以统一用 `COALESCE(scope_id, '')`。

**量级估算：**

| 项 | 数值 |
|---|---|
| 参数条数 | 17 条（GLOBAL） |
| 单行大小 | 约 400 字节 |
| 数据量 | 约 7 KB |
| 保留期 | 永久 |

**分区：** 不分区。

**九条敏感参数的政策来源与篡改后果：**

| 参数 | 政策来源 | 篡改后果 |
|---|---|---|
| `FREEZE_HOURS` | 盘点作业标准 | 调小 → 盘点未完就到期解冻，业务恢复导致账实再次不符，本次盘点作废 |
| `FREEZE_EXTEND_HOURS` | 盘点作业标准 | 调大 → 盘点人可无限延长冻结，业务停摆 |
| `DIFF_REASON_MIN` | 差异归因制度 | 调高 → 小额差异原因可选，归因率下降；调低 → 每项都要归因，工作量剧增导致敷衍 |
| `DIFF_NOTE_MIN_AMOUNT` | 大额差异查证制度 | 调高 → 大额差异无说明，舞弊无制衡 |
| `DIFF_ATTACH_MIN_AMOUNT` | 大额差异查证制度 | 调高 → 大额差异无调查报告，审计无法追责 |
| `APPROVAL_TIER_1/2/3` | 资产管理内控 | 调高 → 大额调整单人可批，无制衡 |
| `ACCURACY_TARGET` | 库房管理 KPI | 调低 → 目标形同虚设，管理失去改进方向 |

| # | 项目 | 优先级 | 说明 |
|---|---|---|---|
