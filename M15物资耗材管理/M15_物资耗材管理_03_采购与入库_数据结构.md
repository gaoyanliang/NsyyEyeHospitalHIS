**设计说明：**

| 决策 | 内容 | 理由 |
|---|---|---|
| 无物理外键 | 全部引用（`material_code`、`supplier_id`、`plan_id`、`order_id`、`receipt_id`）为逻辑引用 | 与 M14/M16 一致；跨模块与高频写入表加外键会引入锁竞争，且 M01-04/M01-05 是独立服务 |
| 名称快照 | 明细表冗余 `material_name` / `spec` / `unit`；单据头冗余 `supplier_name` / `dept_name` | 耗材改名、供应商改名后历史单据仍显示当时的名称；列表查询无需 JOIN 主数据服务 |
| 金额四列 | `amount_tax` / `amount_net` / `tax_rate` / `tax_amount` 逐行存 | 必须逐行先算再汇总，见附录 B |
| 幂等键 | `m15_purchase_order.idempotency_key`、`m15_inbound.idempotency_key` 部分唯一 | 上游超时重试不得重复生成订单/重复加库存 |
| 只增表 | `m15_receipt_item` 验收结果一旦提交不可改（作废需走退货） | GSP 验收记录不可篡改 |
| 分区 | 全部 9 张表**不分区** | 最大表 `m15_receipt_item` 15 年约 21 万行，单表舒适区；且 `order_no`/`receipt_no`/`inbound_no` 是跨年唯一约束，分区会破坏唯一性语义 |
| 数量恒等 | 三层恒等由 CHECK 强制 | 见附录 B |

## 4.2 表：`m15_purchase_plan`（采购申请单表）

**表说明：** 科室或耗材科提出的采购需求。一张申请单可包含多个耗材明细，按总金额路由到不同审批档位。审批通过后转为采购订单。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | IDENTITY | 主键 |
| plan_no | VARCHAR(32) | N | — | 申请单号，格式 `PLAN-YYYY-NNN`，全局唯一 |
| title | VARCHAR(120) | N | — | 计划主题（10~60 字） |
| dept_id | BIGINT | N | — | 使用科室 ID |
| dept_name | VARCHAR(100) | N | — | 使用科室名称（快照） |
| purchase_type | VARCHAR(16) | N | 'NORMAL' | 采购类型：`NORMAL` 常规 / `URGENT` 紧急 / `STOCK` 备货 / `CONSIGNMENT` 寄售 |
| is_urgent | BOOLEAN | N | FALSE | 是否紧急 |
| urgent_reason | VARCHAR(500) | Y | NULL | 紧急理由（紧急时必填，≥20 字） |
| budget_subject | VARCHAR(64) | Y | NULL | 预算科目（M17） |
| reason | VARCHAR(1000) | N | — | 申请理由（≥20 字） |
| total_amount | NUMERIC(14,2) | N | 0 | 预估总额（明细金额之和） |
| status | VARCHAR(16) | N | 'DRAFT' | 状态：`DRAFT` / `SUBMITTED` / `APPROVED` / `REJECTED` / `CONVERTED` / `CANCELLED` |
| plan_date | DATE | N | CURRENT_DATE | 申请日期 |
| planned_inbound_date | DATE | N | — | 计划入库日期（≥ 申请日 +2 天） |
| required_approver | VARCHAR(32) | N | — | 审批角色：`DEPT_DIRECTOR` / `VICE_PRESIDENT` / `EXECUTIVE_MEETING` |
| required_approver_name | VARCHAR(64) | Y | NULL | 审批角色名称（快照） |
| submitted_at | TIMESTAMP | Y | NULL | 提交时间 |
| submitted_by | BIGINT | Y | NULL | 提交人 |
| approved_by | BIGINT | Y | NULL | 审批人 |
| approved_by_name | VARCHAR(64) | Y | NULL | 审批人姓名（快照） |
| approved_at | TIMESTAMP | Y | NULL | 审批时间 |
| approval_comment | VARCHAR(500) | Y | NULL | 审批意见 |
| reject_reason | VARCHAR(500) | Y | NULL | 驳回原因（≥10 字） |
| converted_at | TIMESTAMP | Y | NULL | 转订单时间 |
| cancelled_at | TIMESTAMP | Y | NULL | 作废时间 |
| cancel_reason | VARCHAR(200) | Y | NULL | 作废原因（≥10 字） |
| created_by | BIGINT | N | — | 创建人 |
| created_by_name | VARCHAR(64) | N | — | 创建人姓名（快照） |
| created_at | TIMESTAMP | N | NOW() | 创建时间 |
| updated_by | BIGINT | Y | NULL | 更新人 |
| updated_at | TIMESTAMP | N | NOW() | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 软删除标记 |

**索引设计：**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m15_purchase_plan | PRIMARY | id | 主键 |
| uk_m15_plan_no | UNIQUE（部分） | plan_no WHERE is_deleted = FALSE | 单号全局唯一 |
| idx_m15_plan_status | NORMAL | status, created_at DESC | 按状态筛列表 |
| idx_m15_plan_dept | NORMAL | dept_id, plan_date DESC | 按科室筛 |
| idx_m15_plan_creator | NORMAL | created_by, created_at DESC | 「我的申请单」 |
| idx_m15_plan_pending | 部分 | created_at WHERE status = 'SUBMITTED' AND is_deleted = FALSE | 待审批列表（通常 0~20 条） |
| idx_m15_plan_title_trgm | GIN | title gin_trgm_ops | 主题模糊搜索 |

**约束说明：**

```sql
-- 单号格式
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_no CHECK (plan_no ~ '^PLAN-[0-9]{4}-[0-9]{3,5}$');

-- 采购类型枚举
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_type
  CHECK (purchase_type IN ('NORMAL', 'URGENT', 'STOCK', 'CONSIGNMENT'));

-- 状态枚举
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_status
  CHECK (status IN ('DRAFT', 'SUBMITTED', 'APPROVED', 'REJECTED', 'CONVERTED', 'CANCELLED'));

-- 审批角色枚举
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_approver
  CHECK (required_approver IN ('DEPT_DIRECTOR', 'VICE_PRESIDENT', 'EXECUTIVE_MEETING'));

-- 计划入库日期必须晚于申请日期（研发期强约束，业务期再校验 +2 天）
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_dates
  CHECK (planned_inbound_date > plan_date);

-- 金额非负
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_amount
  CHECK (total_amount >= 0 AND total_amount <= 50000000);

-- 申请理由至少 20 字
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_reason
  CHECK (char_length(btrim(reason)) >= 20);

-- 紧急采购必须有紧急理由（≥20 字）
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_urgent
  CHECK (is_urgent = FALSE OR (urgent_reason IS NOT NULL AND char_length(btrim(urgent_reason)) >= 20));

-- 已提交必须有提交时间与提交人
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_submitted
  CHECK (status = 'DRAFT' OR (submitted_at IS NOT NULL AND submitted_by IS NOT NULL));

-- 已批准/已转订单必须有审批信息
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_approved
  CHECK (status NOT IN ('APPROVED', 'CONVERTED')
         OR (approved_by IS NOT NULL AND approved_at IS NOT NULL));

-- 已驳回必须有驳回原因
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_rejected
  CHECK (status <> 'REJECTED'
         OR (reject_reason IS NOT NULL AND char_length(btrim(reject_reason)) >= 10));

-- 已作废必须有作废时间与原因
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_cancelled
  CHECK (status <> 'CANCELLED'
         OR (cancelled_at IS NOT NULL AND cancel_reason IS NOT NULL
             AND char_length(btrim(cancel_reason)) >= 10));

-- 已转订单必须有转单时间
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_converted
  CHECK (status <> 'CONVERTED' OR converted_at IS NOT NULL);

-- 时间序：提交 <= 审批 <= 转单
ALTER TABLE m15_purchase_plan
  ADD CONSTRAINT ck_m15_plan_time_seq
  CHECK (approved_at IS NULL OR submitted_at IS NULL OR approved_at >= submitted_at);

COMMENT ON TABLE m15_purchase_plan IS '采购申请单表：科室/耗材科的采购需求，审批通过后转采购订单';
COMMENT ON COLUMN m15_purchase_plan.status IS '状态：DRAFT 草稿 / SUBMITTED 已提交待审批 / APPROVED 已批准 / REJECTED 已驳回 / CONVERTED 已转订单 / CANCELLED 已作废';
COMMENT ON COLUMN m15_purchase_plan.required_approver IS '审批档位（按 total_amount 路由）：DEPT_DIRECTOR ≤5万 / VICE_PRESIDENT 5~20万 / EXECUTIVE_MEETING >20万';
```

**状态机：**

```
DRAFT ──提交──► SUBMITTED ──通过──► APPROVED ──生成订单──► CONVERTED（终态）
  ▲                 │                    │
  │ 撤回            │ 驳回                │ 作废
  └─────────────┐   ▼                    ▼
                └ REJECTED            CANCELLED（终态）
  │
  └──作废──► CANCELLED（终态）
```

**量级估算：**

| 项 | 数值 |
|---|---|
| 年新增单数 | 约 480 单（40 单/月） |
| 单行大小 | 约 1.2 KB |
| 年数据量 | 约 576 KB |
| 15 年数据量 | 约 8.6 MB |

**分区：** 不分区。`plan_no` 是跨年唯一约束（`PLAN-YYYY-NNN` 虽含年份，但业务上要求全局唯一），分区会迫使唯一索引含分区键从而破坏语义；15 年 7,200 行完全在单表舒适区。

## 4.3 表：`m15_plan_item`（采购申请明细表）

**表说明：** 采购申请的耗材明细。数量必须为包装整数倍；同一申请单内同一耗材不得重复。

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| id | BIGINT | N | IDENTITY | 主键 |
| plan_id | BIGINT | N | — | 采购申请 ID |
| line_no | SMALLINT | N | — | 行号（同单内从 1 递增） |
| material_code | VARCHAR(32) | N | — | 耗材编码（M01-04） |
| material_name | VARCHAR(200) | N | — | 耗材名称（快照） |
| spec | VARCHAR(200) | Y | NULL | 规格（快照） |
| model | VARCHAR(128) | Y | NULL | 型号（快照） |
| unit | VARCHAR(16) | Y | NULL | 最小单位（快照） |
| qty | NUMERIC(12,4) | N | — | 申请数量（必须为 pack_factor 整数倍） |
| estimated_unit_price | NUMERIC(14,4) | N | — | 预估单价 |
| estimated_amount | NUMERIC(14,2) | N | — | 预估金额 = ROUND(qty × estimated_unit_price, 2) |
| expected_supplier_id | BIGINT | Y | NULL | 期望供应商 ID |
| expected_supplier_name | VARCHAR(200) | Y | NULL | 期望供应商名称（快照） |
| reason | VARCHAR(500) | Y | NULL | 单项采购理由 |
| remark | VARCHAR(500) | Y | NULL | 备注 |
| converted_qty | NUMERIC(12,4) | N | 0 | 已转为订单的数量（≤ qty） |
| created_at | TIMESTAMP | N | NOW() | 创建时间 |
| updated_at | TIMESTAMP | N | NOW() | 更新时间 |
| is_deleted | BOOLEAN | N | FALSE | 软删除标记 |

**索引设计：**

| 索引名 | 类型 | 字段 | 说明 |
|---|---|---|---|
| pk_m15_plan_item | PRIMARY | id | 主键 |
| uk_m15_plan_item_line | UNIQUE | plan_id, line_no | 同行号唯一 |
| uk_m15_plan_item_material | UNIQUE（部分） | plan_id, material_code WHERE is_deleted = FALSE | 同单同耗材唯一（防重复） |
| idx_m15_plan_item_material | NORMAL | material_code, created_at DESC | 按耗材查历史采购 |

**约束说明：**

```sql
-- 行号范围
ALTER TABLE m15_plan_item
  ADD CONSTRAINT ck_m15_plan_item_line
  CHECK (line_no >= 1 AND line_no <= 500);

-- 数量为正
ALTER TABLE m15_plan_item
  ADD CONSTRAINT ck_m15_plan_item_qty
  CHECK (qty > 0 AND qty <= 1000000);

-- 单价非负
ALTER TABLE m15_plan_item
  ADD CONSTRAINT ck_m15_plan_item_price
  CHECK (estimated_unit_price >= 0 AND estimated_unit_price <= 10000000);

-- 金额自洽（行级先舍入到 2 位）
ALTER TABLE m15_plan_item
  ADD CONSTRAINT ck_m15_plan_item_amount
  CHECK (abs(estimated_amount - ROUND(qty * estimated_unit_price, 2)) < 0.01);

-- 已转订单数量不得超过申请数量
ALTER TABLE m15_plan_item
  ADD CONSTRAINT ck_m15_plan_item_converted
  CHECK (converted_qty >= 0 AND converted_qty <= qty);

COMMENT ON TABLE m15_plan_item IS '采购申请明细表：同单同耗材唯一，数量须为包装整数倍';
COMMENT ON COLUMN m15_plan_item.converted_qty IS '已转订单数量，用于拆分多个订单时的剩余量控制';
```

**量级估算：**

| 项 | 数值 |
|---|---|
| 年新增行数 | 约 3,400 行（每单 7 项） |
| 单行大小 | 约 600 B |
| 15 年数据量 | 约 30 MB |

**分区：** 不分区。

## 4.4 表：`m15_purchase_order`（采购订单表）

  CHECK (abs(amount_tax - ROUND(qty * unit_price, 2)) < 0.01);

  CHECK (received_qty >= 0 AND received_qty <= qty);

## 附录 B：数量与金额字段汇总

### B.1 三层数量恒等式

| 层级 | 恒等式 | 落地位置 |
|---|---|---|
| 订单层 | `received_qty <= qty` | `ck_m15_order_item_received` |
| 到货层 | `accepted_qty + rejected_qty = received_qty` | `ck_m15_receipt_item_balance` |
| 到货头层 | `total_accepted + total_rejected = total_received` | `ck_m15_receipt_balance` |
| 入库层 | `inbound_qty <= SUM(accepted_qty)` | 服务层 + `ck_m15_inbound_amount` |

### B.2 金额计算铁律

```
含税金额      amount_tax  = ROUND(qty × unit_price, 2)
不含税金额    amount_net  = ROUND(amount_tax / (1 + tax_rate), 2)
税额          tax_amount  = amount_tax − amount_net
订单含税合计  total_amount_tax    = SUM(明细 amount_tax)
订单不含税合计 total_amount_net   = SUM(明细 amount_net)
订单税额合计  total_tax_amount    = SUM(明细 tax_amount)
```

**为什么必须逐行先算再汇总：**

| 场景 | 单行结果 | 10 行汇总 |
|---|---|---|
| 含税 100 元、税率 13% | 不含税 88.50，税额 11.50 | 不含税 885.00，税额 115.00 |
| 若先汇总再算 | — | 含税 1000 → 不含税 884.96，税额 115.04 |
| **差额** | — | **0.04 元** |

100 行差 0.40 元，长期累积会使三单匹配持续失败，且与发票「逐行开票」口径不一致。

### B.3 字段精度汇总

| 字段类别 | 类型 | 说明 |
|---|---|---|
| 数量 | `NUMERIC(12,4)` | 支持拆零到 0.0001 |
| 单价 | `NUMERIC(14,4)` | 高值耗材精确成本 |
| 金额 | `NUMERIC(14,2)` | 行级先舍入到 2 位 |
| 税率 | `NUMERIC(5,4)` | 0.1300 = 13% |

**禁止使用 FLOAT / REAL。**

### E.4 上线前运维准备（10 项）

| 序号 | 项 | 优先级 | 说明 |
|---|---|---|---|
| 1 | 配置 M01-04 耗材的 `pack_factor` | 🔴🔴 | 若未配置则包装整数倍校验全部失效，采购可下任意零头数量 |
| 2 | 配置 M01-04 的 `mdm_material_supplier_rel`（合格供货关系） | 🔴🔴🔴 | 无供货关系则下单直接报 `"1503013"`，采购无法进行 |
| 3 | 配置 M01-05 供应商资质与有效期 | 🔴🔴🔴 | **资质不可降级**；接口失败即阻断采购 |
| 4 | 配置 13 条采购参数（含 5 个敏感参数） | 🔴 | 审批档位须与本院采购管理制度一致 |
| 5 | 验证 `pg_trgm` 扩展可用 | 🔴 | 需超级用户；缺失则主题搜索退化为全表扫描 |
| 6 | 导入各耗材的 UP 采购价（`mdm_material_price`） | 🟡 | 缺失则预估单价默认 0，需每次手工填 |
| 7 | 配置 M17 预算科目字典 | 🟡 | 未配置则预算科目只能手填 |
| 8 | 验证 M15-01 `POST /stock/inbound` 联通性与幂等 | 🔴🔴 | 若不幂等，补偿重试会**重复加库存** |
| 9 | 培训验收员八项检查与冷链判定 | 🔴🔴 | 验收是耗材质量最后一道闸门 |
| 10 | 配置 M03-05 供应商联系人（催货短信） | 🟡 | 缺失则催货只能人工电话 |

**第 8 项最需要强调：** 入库补偿任务最多重试 10 次。若 M15-01 的 `POST /stock/inbound` 不具备幂等性（同一 `idempotency_key` 第二次调用未直接返回上次结果），则每次重试都会再加一次库存，10 次重试后库存可能虚增 10 倍。**上线前必须用同一幂等键连调 3 次，验证库存只增加一次。**
