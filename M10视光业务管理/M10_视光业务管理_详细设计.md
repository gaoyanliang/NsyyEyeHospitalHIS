## 1. 模块概述

### 1.1 一句话定位

> **M10 回答「这个人的眼睛现在是什么状态（验光）、他该配什么（处方）、我们卖了他什么、什么时候能把眼镜交到他手上、之后还要不要复查」。**

M10 是眼科医院区别于综合医院的两个专科业务之一（另一个是 M11 屈光手术），也是**唯一不依赖医保、现金流即时**的收入来源——在二级眼科医院的收入结构中，视光占比可达 **25%~40%**。

### 1.2 为什么 M10 是独立模块，而不是 M04 门诊或 M16 收费的一个分支

**四条独立理由：**

**理由一：业务对象不同——视光的核心对象是「屈光度」，门诊的核心对象是「诊断」。**

门诊（M04/M07）围绕「主诉 → 诊断 → 医嘱」展开，主键是就诊号 `registration_id`；视光围绕**球镜（SPH）/ 柱镜（CYL）/ 轴位（AXIS）**这一组光学参数展开，主键是验光单 `optometry_no` 与配镜订单 `order_no`。两者数据结构毫无重叠：门诊没有任何字段能表达「−4.25DS / −0.75DC × 180°」，也没有任何表能承载 4,025 格的光度矩阵校验。

**理由二：客户身份不同——视光可以接待「不是患者」的人。**

一个人可能只是来配副眼镜：不挂号、不就诊、没有诊断、没有病历，甚至不进医院信息系统。M16-04 第 3.7 节已明确「顾客（无就诊记录）模型」：`patient_id` 可以为空，仅有手机号。**这个「顾客」概念在门诊与收费模块里都没有归属**，M10-05 是它唯一的家。

**理由三：交付周期不同——视光是「下单→加工→取镜」的跨日履行业务。**

门诊是一次就诊当场结束（10~30 分钟）；视光配镜在收钱之后还有**平均 3 个工作日、最长 30 天（OK 镜定制 + 厂商来片）**的加工周期。这中间有工序排程、外协、质检、返工、到货、催取五个环节——**这才是 M10 的主体工作量，而它在 M16 的财务视野里完全不可见**：M16 只知道「已付清」，不知道「镜片磨到哪一步了」。

**理由四：专业合规不同——OK 镜是三类医疗器械，必须闭环随访。**

角膜塑形镜（OK 镜）属**第三类医疗器械**，验配必须由有资质的医疗机构完成，且**戴镜后第 1/7/30/90 天必须复查**，漏复查直接威胁角膜安全。这套「验配记录 + 试戴片管理 + 定制参数 + 强制复查」的完整闭环，是视光模块不可分割的一部分，任何「把视光当商品卖」的简化设计都会在合规检查中失败。

### 1.4 概念辨析（最易混淆的四组）

| 概念对 | 区别 | 举例 |
|---|---|---|
| **验光单 vs 配镜处方** | 验光单是「眼睛的客观状态」；处方是「医生决定给他配什么」，两者可以不同 | 验光 −5.00D，处方开 −4.75D（过矫不耐受 / 单眼抑制） |
| **视光顾客 vs 患者** | 顾客可无就诊记录、无 `patient_id`；患者有 M03 主索引 | 路人配副太阳镜 → 顾客；弱视儿童复查 → 患者 |
| **配镜订单（M10）vs 销售单（M16）** | 订单是业务档案（配了什么、加工到哪、谁取走、质保多久）；销售单是财务单据（金额、结算、发票） | 二者 1:1 关联，职责不重叠 |
| **视光会员 vs 全院会员** | 全院会员（M03-03）管等级与积分；视光会员（M10-08）管配镜套餐与视光权益 | 金卡会员 + 儿童近视防控年卡 |

### 2.2 六条拆分主线

#### 主线一：按「一次视光服务的生命周期」分，不按功能清单分

```
[到店] ──①建档/接待──► [选配] ──②验光──► [屈光数据]
   │                                          │
   │                                          ├──③视光专业验配（隐形/OK镜）
   │                                          ▼
   │                                    ④配镜处方
   │                                          │
   │                                          ▼
   │                                     ⑤配镜订单 ──⑥收钱（M16）
   │                                          │
   │                                          ▼
   │                                     ⑦加工 ──⑧取镜交付
   │                                          │
   │                                          ▼
   └──────────────────────────────────⑨复查与视力档案（回到①）
```

每个环节的**主责人不同、可逆性不同、法规约束不同**：

| 环节 | 主责人 | 可逆性 | 关键约束 |
|---|---|---|---|
| ① 建档接待 | 前台/销售 | 可修改 | 允许无患者档案 |
| ② 验光 | 验光师 | **签发前可改，签发后不可改** | 0.25D 步进、轴位规则 |
| ③ 视光验配 | OK 镜验配师/视光师 | 可重验 | **OK 镜必须三类器械 + 强制复查** |
| ④ 配镜处方 | 视光医师 | 审核前可改 | **有效期 + 偏差阈值 + 审核** |
| ⑤ 配镜订单 | 销售 | 付款前可改 | 改单需差额结算 |
| ⑥ 收钱 | 收费员（M16） | 退费走冲红 | **M10 不碰金额** |
| ⑦ 加工 | 加工师 | 可返工 | 工序来自 M01-08，卡点不可跳 |
| ⑧ 取镜交付 | 前台 | **不可逆** | 四道校验 + 顾客签字 |
| ⑨ 复查 | 视光护士 | 可改约 | **漏复查告警** |

**为什么按生命周期而不按功能分：** 若按「验光管理」「处方管理」「订单管理」这样分，每个子模块都要碰 `patient_id/customer_id` 与主数据，且会出现「谁能改验光数据」的争议。按生命周期分，每个环节有明确的输入状态与输出状态，字段写入权归属清晰。

#### 主线二：验光与处方必须分开——这是本模块最重要的拆分

**四条理由：**

1. **专业主体不同**：验光由**验光师**完成（技术操作），处方由**医师**决定（医疗决策）。二者资质不同、责任不同，混在一起会导致「验光师直接改处方」的合规风险。
2. **数据性质不同**：验光是**客观测量**（可重复测量，多次结果应接近），处方是**主观决策**（可因耐受度、用眼需求、年龄而偏离验光值）。
3. **法律效力不同**：验光单是检查记录；配镜处方是医疗文书，必须医师签名、有有效期、可被追溯。
4. **变更频率不同**：一次验光可能对应多个处方（如先开一副看远的、再开一副渐进多焦），一个处方也可能沿用多次复购。

> **拆分效果：** `m10_optometry` 只管"测到了什么"，`m10_prescription` 只管"决定给他配什么"。M10-02 通过 `optometry_no` 关联，永不反向修改验光数据。

#### 主线三：OK 镜必须独立成子模块

OK 镜（角膜塑形镜）与普通隐形眼镜在**五个维度**上根本不同：

| 维度 | 软性隐形眼镜（M10-03） | OK 镜（M10-04） |
|---|---|---|
| 器械类别 | 二类/三类 | **三类**（最高风险） |
| 是否定制 | 按度数备货 | **每片按角膜地形图定制** |
| 关键参数 | 基弧、直径、含水量 | **BC/RC/AC/PC + 降度 + 地形图** |
| 供货周期 | 现货 | **15~30 天** |
| 随访要求 | 一般建议 | **1/7/30/90 天强制复查** |
| 试戴片 | 一般不需要 | **必须有试戴片库并逐片占用** |

如果把 OK 镜塞进 M10-03，试戴片占用、地形图参数、定制单、强制复查这四套逻辑都会「捎带在隐形里」，必然做不完整。

#### 主线四：顾客与订单分开

**理由：顾客的生命周期长于订单。** 一个顾客可能 3 年里下 5 单。如果顾客信息挂在订单上，就会出现：
- 顾客换手机号，要改 5 个订单
- 顾客标签（如"高度近视""近视防控"）无法跨订单沉淀
- 选配会话无法跨订单复用

因此 M10-05 独占顾客档案与选配会话，M10-06 只引用 `customer_id`。

#### 主线五：加工独立，因为它是「跨日执行的作业队列」

**加工单与订单是 1:N 而不是 1:1**：一副眼镜可能拆成两次加工（先做一副单光、后补一副渐进），也可能因质检失败重开加工单。加工单有独立的**派工、工序、外协、质检、返工**五态，且需要看板与产能管理。塞进 M10-06 会让订单表膨胀到 40+ 状态字段。

#### 主线六：库存必须与 M15 划清边界

**M15 是全院库存唯一权威，M10-07 只维护"门店二级库"。**

| 数据 | 权威方 | 说明 |
|---|---|---|
| 主库物理库存 | **M15** | 库房、货位、批次、效期 |
| 门店在架镜架/镜片 | **M10-07**（`m10_stock_batch`） | 视光中心自己的货架 |
| 已预占数量 | **M10-07**（`m10_stock_reserve`） | 下单锁定 |
| 可销售量 | **M10-07** 计算 | `在架 − 预占 − 安全库存` |

**为什么不能让 M10 直接扣主库：** 若 M10 扣 M15 的库存，一旦退单、改单、超时未付，就会出现"扣了没还"的错账，且 M15 的盘点会被 M10 的操作污染。分两层后，M10 的台账与 M15 每日对账，差异可定位、可回溯。

## 3. 核心业务模型

### 3.1 视光闭环（总体设计 5.3 节的落地）

```
验光 → 配镜处方 → 选品 → 订单 → 收费 → 加工 → 取镜 → 复查 → 会员积分
M10-01   M10-02  M10-05 M10-06 M16-04 M10-07 M10-06 M10-09  M03-03/M19

闭环回环点：
  · 复查（M10-09）产生的验光记录 → 回到 M10-01，形成纵向视力档案
  · 复查发现屈光变化 → 触发新一次配镜（M10-02 → M10-06）
  · 取镜完成 → M03-03 积分 → M19 会员运营
```

**闭环的四道"闸门"（不可跳过的校验点）：**

| 闸门 | 位置 | 校验内容 | 不通过后果 |
|---|---|---|---|
| **G-01 光度可供闸** | 下单前（M10-06） | 调 M01-08 `specs/lookup` 校验该度数组合是否可供 | 阻止下单，提示更换产品或走定制 |
| **G-02 处方有效闸** | 下单前（M10-06） | 处方未过期、已审核通过、度数在有效期内 | 阻止下单，要求复验 |
| **G-03 付款闸** | 加工前（M10-07） | 定金/全款已收（`m16.optical.paid`） | 阻止派工，加工单停在 `PENDING` |
| **G-04 交付闸** | 取镜时（M10-06） | 已付清 + 加工完工 + 全部到货 + 顾客确认 | 阻止交付 |

### 3.2 三套状态机及其协同

M10 有三套主要状态机，必须理解它们的**粒度差异与同步方向**：

#### 3.2.1 验光单状态机（M10-01）

```
      ┌────────┐  提交    ┌────────┐  签发    ┌────────┐  归档   ┌──────────┐
      │ DRAFT  ├─────────►│ (校验) ├─────────►│ SIGNED ├────────►│ ARCHIVED │
      │ 草稿    │          │        │          │ 已签发  │         │ 已归档    │
      └───┬────┘          └───┬────┘          └───┬────┘         └──────────┘
          │                   │                   │
     作废 │              作废 │              作废 │（签发后作废需说明+审批）
          ▼                   ▼                   ▼
      ┌────────────────────────────────────────┐
      │              VOID（已作废）              │
      └────────────────────────────────────────┘
```

**关键规则：** `SIGNED` 之后**不可修改任何屈光数据**，只能作废重开。原因：验光单是下游处方、订单、视力档案的共同数据源，若可修改，会导致已开出的处方"与来源不符"。

#### 3.2.2 配镜处方状态机（M10-02）

```
     │ DRAFT  ├──────────►│ PENDING_AUDIT ├────────►│ AUDITED  │
     │ 草稿    │           │ 待审核         │         │ 已审核    │

         │                 │ 已驳回    │            │ 已过期    │

    │  VOID  │
    │ 已作废  │
    └────────┘
```

**关键规则：** 只有 `AUDITED` 且在有效期内的处方才能驱动下单（闸门 G-02）。

#### 3.2.3 配镜订单状态机（M10-06）与 M16 财务态的双层模型

```
    │                       │ 加工完工
    │                       ▼
    │               ┌───────────┐
```

**同步方向铁律：**

### 3.4 关键计算模型

#### 3.4.1 等效球镜（SE）

```
SE = SPH + CYL / 2

示例：-4.25DS / -0.75DC × 180°
SE = -4.25 + (-0.75 / 2) = -4.25 - 0.375 = -4.625 ≈ -4.63 D
```

**用途：** 视力档案纵向比较、近视进展速度计算。**注意：** SE 仅用于趋势分析，不用于配镜。

#### 3.4.2 近视进展速度

```
年化进展速度（D/年） = (末次 SE − 首次 SE) / (间隔月数 / 12)

示例：2025-03 SE=-2.00D，2026-03 SE=-2.75D
→ (−2.75 − (−2.00)) / 12 月 × 12 = −0.75 D/年
→ 判定："预警"（阈值 0.75D/年）

判定分级：
  |速度| < 0.50 D/年  → 正常
  0.50 ≤ |速度| < 0.75 → 关注
  0.75 ≤ |速度| < 1.00 → 预警（发布 m10.vision.alert）
  |速度| ≥ 1.00 → 高危（必须干预方案）
```

**眼轴增速：** 儿童 > 0.20 mm/年 → 预警（与 SE 联合判定，二者同向时可信度更高）。

#### 3.4.3 可销售量

```
可销售量 = 门店在架数量 − 已预占数量 − 安全库存

  在架数量 = SUM(m10_stock_batch.qty)  WHERE status='ON_SHELF' AND qty > 0
  已预占   = SUM(m10_stock_reserve.reserved_qty)  WHERE status='ACTIVE'
  安全库存 = m10_stock_safety.safety_qty（按 SKU 配置，默认 2）

示例：在架 5 副，预占 2 副，安全库存 2 → 可售 1 副
```

**下单规则：** `可销售量 ≥ 需求数量` 才允许"现货交付"；否则转为"定制"或"调货"。

#### 3.4.4 预计交付日期

```
预计交付日 = 下单日 + MAX(镜片供货周期, 镜架备货周期) + 加工周期

其中：
  镜片供货周期 = M01-08 lead_time_days（现货=0，定制=7~30 天）
  加工周期     = M10.LAB.STANDARD_DAYS（默认 3 工作日）
  工作日计算   = 排除周末与法定节假日（M23 日历）

示例：OK 镜定制 21 天 + 加工 3 天 = 24 天后可取镜
```

#### 3.4.5 定金计算

```
定金比例 = 默认 30%；单笔 ≥ 5,000 元 → 50%；定制商品 → 不得为 0
定金金额 = ROUND_HALF_UP(订单总额 × 定金比例, 2)

说明：定金规则与 M16-04 第 3.2 节完全一致，M10 不自行计算，
      实际收款调用 M16-04 POST /internal/v1/m16/optical/order 与收款接口。
```

### 7.3 设备对接策略（眼科特色）

自动验光仪等视光设备多为 Windows 封闭系统，**不保证可直连**。M10 采用 M12/M13 已验证的「双通道」方案：

| 通道 | 方式 | 适用 |
|---|---|---|
| **通道一（首选）** | 设备厂商 API / DICOM / HL7 直连 | 支持开放接口的设备 |
| **通道二（兜底）** | 设备导出 PDF/图片到共享文件夹 → M10 检测到新文件 → OCR 解析关键数值 → 人工确认 | 封闭设备 |
| **通道三（手工）** | 验光师手工录入 + 双人核对（录入人 + 复核人） | 设备完全无法导出 |

**OCR 结果的处置：** 一律进入「待确认」状态，**必须**验光师手工核对后才写入正式验光单，禁止 OCR 结果直接进库。

## 8. 全局业务规则

### 8.1 五条金额铁律

| # | 铁律 | 违反后果 |
|---|---|---|
| **1** | **M10 不计算金额。** 所有金额（售价、加价、折扣、实收）一律由 M16-04 / M16-06 计算 | 必然出现"M10 算的和收银台收的不一致" |
| **2** | **M10 不写 M16 的表。** `m16_optical_order`、`m16_settlement`、`m16_payment` 一律只读 | 破坏资金审计链 |
| **3** | **M10 的金额字段全部是快照**，字段名带 `_snap` 后缀，只由 M16 事件更新 | 历史单据金额漂移 |
| **4** | **行级舍入后累加**：`line_amount = ROUND(unit_price × qty, 2)`，再汇总 | 与 M16-01 的舍入规则冲突，产生分差 |
| **5** | **定金规则与 M16-04 完全一致**：默认 30%、单笔 ≥5000 元 50%、定制不为 0 | 两处规则不同步 |

### 8.2 五条数据一致性铁律

| # | 铁律 | 说明 |
|---|---|---|
| **1** | **光学量禁止浮点** | 所有度数用 `NUMERIC(6,2)`，步进 0.25，校验用 `(v*4) = round(v*4)` |
| **2** | **轴位与柱镜联动** | 柱镜为 0 → 轴位必须 NULL；柱镜 ≠ 0 → 轴位必填 1~180 |
| **3** | **OK 镜弧参数有序** | `RC < BC < AC < PC`，DB CHECK + 应用层双重校验 |
| **4** | **签发后不可改** | 验光单 `SIGNED`、处方 `AUDITED`、取镜单已交付 后，只能作废重开 |
| **5** | **单号唯一且不可改** | 部分唯一索引 `WHERE is_deleted = FALSE` |

### 8.3 视光合规铁律

| # | 规则 | 依据 |
|---|---|---|
| **1** | OK 镜必须是**三类医疗器械**且注册证在有效期内 | 《医疗器械监督管理条例》 |
| **2** | OK 镜验配必须**先准入评估**（年龄/度数/曲率/厚度/地形图），不通过不得试戴 | 角膜塑形镜验配技术规范 |
| **3** | OK 镜戴镜后 **1/7/30/90 天必须复查**，逾期 30 天自动告警 | 同上 |
| **4** | 隐形眼镜、OK 镜**必须凭处方销售** | `is_prescription_required` |
| **5** | 14 岁以下儿童**首次配镜必须睫状肌麻痹验光** | 视光学临床规范（可配置） |
| **6** | 试戴片（`is_trial_lens=true`）**不得销售** | M01-08 规则 |
| **7** | 验光单、处方、验配单**必须电子签名**，记录签发人与时间 | 医疗文书规范 |

### 8.4 三条库存规则

| # | 规则 | 说明 |
|---|---|---|
| **1** | **M15 是主库唯一权威**，M10 只维护门店二级库 | 每日对账，差异定位 |
| **2** | **库存变更走"预占 → 出库确认"两段**，不直接扣减 | 防超卖与"扣了没还" |
| **3** | **预占必须带 TTL**（默认 30 分钟），超时自动释放 | 防止顾客跑单后库存永久锁死 |

## 11. 异常处理与降级策略

### 11.1 异常分类

| 类型 | 示例 | 处理 |
|---|---|---|
| 参数异常 | 度数非 0.25 步进、轴位非法、弧参数关系错 | `40001` + 字段级错误列表 |
| 业务异常 | 光度不可供、处方过期、订单未付清取镜 | 专属错误码 + 友好提示 |
| 合规异常 | OK 镜非三类器械、注册证过期、无资质验配 | 专属错误码 + 阻止 + 审计 |
| 并发异常 | 乐观锁冲突、加工单已被领取 | `40900` + 提示刷新 |
| 依赖异常 | M01-08 / M16-04 / M15 超时或不可用 | 见 11.2 降级表 |
| 系统异常 | DB / Redis 故障 | `50000` + 错误日志 + 告警 |

### 11.2 降级策略

| 依赖 | 不可用时 | 影响 |
|---|---|---|
| Redis | 直连 DB（性能下降，功能可用） | 单号生成降级为 `SELECT ... FOR UPDATE` |
| M01-08 光度校验 | **不降级**，阻断下单 | 无法确认度数可供 |
| M01-08 取价 | **不降级**，阻断下单 | 无法确定金额 |
| M01-08 工序模板 | 阻断派工，加工单停在 `PENDING` | 无法确认加工流程 |
| M16-04 建销售单 | **不降级**，阻断下单 | 无销售单即无收款 |
| M16-04 查询销售单 | 用本地快照 `*_snap` 字段 | 金额可能不是最新 |
| M16-06 优惠试算 | 降级：按原价展示，提示"优惠暂不可用" | 报价不准确 |
| M15 库存 | 降级：显示"库存未知"，允许下单但提示 | 可能超卖 |
| M03-05 消息 | 降级：进补发队列，不阻断业务 | 通知延迟 |
| 设备（验光仪） | 降级：手工录入 + 双人核对 | 效率下降 |
| MQ | 事件落库 `PENDING`，恢复后补投 | 状态同步延迟 |

### 11.3 监控指标

| 指标 | 说明 | 告警阈值 |
|---|---|---|
| 接口错误率 | 5xx / 总请求 | > 1% |
