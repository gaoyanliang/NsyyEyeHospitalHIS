## 1. 全局设计规范

### 1.1 表名前缀

全模块统一前缀 `m10_`，按子模块细分业务域后缀：

| 子模块 | 表名前缀 | 说明 |
|---|---|---|
| M10-01 验光与视功能检查 | `m10_optometry_*` | 验光单、屈光明细、视力、视功能、日志、统计、配置 |
| M10-02 配镜处方与处方审核 | `m10_prescription*` | 处方主表、处方明细、审核、模板、日志 |
| M10-03 隐形眼镜验配 | `m10_contact_*` | 验配单、眼别明细、试戴片用镜、护理计划、配适日志 |
| M10-04 OK镜与RGP验配随访 | `m10_ortho_k_*` | 验配单、准入、角膜地形图、试戴、定制参数、发放、随访 |
| M10-05 顾客与选配工作台 | `m10_customer_*` / `m10_selection_*` | 顾客档案、地址、标签、选配会话 |
| M10-06 配镜订单与取镜交付 | `m10_order*` / `m10_delivery*` / `m10_warranty*` | 订单、明细、状态日志、取镜单、质保 |
| M10-07 视光库存与加工作业 | `m10_lab_*` / `m10_stock_*` | 加工单、工序执行、外协、质检、库存批次、预占、流水 |
| M10-08 视光会员与权益 | `m10_member_*` | 会员档案、套餐、核销、权益、关怀 |
| M10-09 复查与视力档案 | `m10_followup*` / `m10_vision_*` | 复查计划、任务、到访、提醒、视力档案、进展 |

**禁止跨前缀建表。** 一张表只属于一个子模块；跨子模块共享数据通过 `xxx_id` 引用 + 只读快照，不共用表。

### 1.2 公共字段（全模块强制）

| 字段名 | 类型 | 允许空 | 默认 | 说明 |
|---|---|---|---|---|
| `id` | BIGINT | N | IDENTITY | 主键，`GENERATED BY DEFAULT AS IDENTITY` |
| `is_deleted` | BOOLEAN | N | FALSE | 逻辑删除 |
| `created_by` | BIGINT | Y | NULL | 创建人（`m01_employee.id`） |
| `created_at` | TIMESTAMP | N | CURRENT_TIMESTAMP | 创建时间 |
| `updated_by` | BIGINT | Y | NULL | 更新人 |
| `updated_at` | TIMESTAMP | N | CURRENT_TIMESTAMP（触发器维护） | 更新时间 |
| `version` | INT | N | 0 | 乐观锁版本号（仅可编辑主表需要） |
| `org_id` | BIGINT | N | 1 | 院区 ID（多院区隔离） |

**约定：**

1. **不建物理外键**（对齐 README 7.2），跨表一致性由应用层 + 每日对账保证。
2. 枚举字段一律 `VARCHAR(16/24/32)` + `CHECK` 约束，**不使用 PostgreSQL ENUM 类型**（便于扩展）。
3. 时间字段统一 `TIMESTAMP`（不带时区），服务层统一按 `Asia/Shanghai` 写入与展示。
4. 逻辑删除字段统一命名 `is_deleted`（M01 老表为 `deleted`，M10 只读引用老表时不改动）。
5. 统计类预聚合表不需要 `version`；日志类表不需要 `updated_by/updated_at`（只增不改）。

### 1.3 患者与顾客的关系字段（M10 特有）

视光中心允许接待**无就诊记录**的配镜顾客，因此 M10 的中枢关联字段有两个而非一个：

| 字段 | 类型 | 说明 | 必填场景 |
|---|---|---|---|
| `patient_id` | BIGINT | 患者 ID（`m03` 患者主索引），可空 | 有门诊/住院记录、需开票、需会员、OK 镜/隐形验配 |
| `customer_id` | BIGINT | 视光顾客 ID（`m10_customer`），可空 | 到店配镜顾客 |
| `customer_no` | VARCHAR(32) | 顾客号，格式 `KH` + 6 位 | 同上 |
| `patient_name` | VARCHAR(64) | 姓名快照 | 一律必填 |
| `phone` | VARCHAR(32) | 手机号（掩码展示），加密存储原值 | 退换、召回、取镜通知必填 |

**规则：** 至少一个身份标识（`patient_id` 或 `customer_id`）必须存在，由 `CHECK` 约束表达：

```sql
-- 所有含患者/顾客的业务主表统一加此约束
ALTER TABLE m10_order
    ADD CONSTRAINT ck_m10_order_identity
    CHECK (patient_id IS NOT NULL OR customer_id IS NOT NULL);
```

### 1.4 金额、数量与光学量的精度

| 类别 | 字段示例 | 类型 | 精度 | 舍入 |
|---|---|---|---|---|
| 单价 | `unit_price` | `NUMERIC(12,4)` | 4 位 | `ROUND_HALF_UP` |
| 金额 | `amount`、`paid_amount` | `NUMERIC(14,2)` | 2 位（分） | `ROUND_HALF_UP` |
| 比例 | `discount_rate`、`ratio` | `NUMERIC(6,4)` | 4 位 | — |
| **球镜/柱镜/附加度** | `sphere`、`cylinder`、`add_power` | `NUMERIC(6,2)` | 2 位 | 步进 0.25 |
| **棱镜** | `prism` | `NUMERIC(6,2)` | 2 位 | 步进 0.25 |
| **轴位** | `axis` | `SMALLINT` | 整数 | 1~180 |
| **弧曲率** | `base_curve`、`ortho_bc` | `NUMERIC(5,2)` | 2 位（mm） | — |
| **瞳距/瞳高** | `pupil_distance`、`pupil_height` | `NUMERIC(5,2)` | 2 位（mm） | — |
| **眼轴长度** | `axial_length` | `NUMERIC(5,2)` | 2 位（mm） | — |
| **角膜曲率** | `k1`、`k2` | `NUMERIC(5,2)` | 2 位（D） | — |
| **屈光进展速度** | `progression_rate` | `NUMERIC(5,2)` | 2 位（D/年） | — |
| 库存数量 | `qty`、`available_qty` | `INT` | 整数 | — |

> **光学量铁律：** M10 所有光学量字段一律 `NUMERIC(n,2)` 或 `SMALLINT`，**禁止使用 FLOAT/REAL/DOUBLE**。原因：`-4.25` 在浮点下为 `-4.2500000000000002`，会导致「同一度数被判为不等」的光度校验错误。

### 1.5 快照字段策略

M10 大量引用 M01-08（商品）、M16-04（销售单）的数据，为避免跨模块 JOIN 与主数据变更导致的单据信息漂移，采用**快照**：

| 场景 | 是否快照 | 说明 |
|---|---|---|
| 单据上的商品名称、品牌、型号、规格描述 | **快照** | 商品改名后历史单据仍显示原名 |
| 单据上的金额（售价、折扣、实收） | **快照** | 金额真值由 M16 计算并回推 |
| 单据上的患者/顾客姓名、手机号 | **快照** | 患者合并改名后历史单据不变 |
| 单据上的科室、医生、验光师姓名 | **快照** | 人员调动后历史单据不变 |
| **加工工序定义、工序工时** | **不**快照 | 实时读 M01-08，保证工序标准唯一 |
| **商品当前零售价** | **不**快照 | 实时读 M01-08 `pricing` |
| **当前可销售量** | **不**快照 | 实时读 M10-07 `stock/available` |

**命名约定：** 快照字段统一以 `*_snap` 后缀或在字段说明中标注「（快照）」。

### 1.6 逻辑删除与引用完整性

| 规则 | 说明 |
|---|---|
| 主数据类（顾客、会员、套餐） | 允许逻辑删除；被引用时阻止删除并提示引用数 |
| 业务单据类（验光单、处方、订单、加工单） | **禁止删除**，只允许作废（`status = 'VOID'/'CANCELLED'`） |
| 日志类（`*_log`） | **禁止删除与修改**，只增；保留期 24 个月后归档 |
| 统计类（`*_stat`） | 可重算覆盖，允许删除历史分区重建 |

## 4. 索引策略

### 4.1 必备索引

| 索引类型 | 适用场景 | 命名示例 |
|---|---|---|
| 主键 | 全部表 | `pk_m10_optometry` |
| 唯一（部分） | 单号、编码唯一，排除逻辑删除 | `uk_m10_optometry_no` … WHERE `is_deleted = FALSE` |
| 患者时间索引 | 按患者查历史（最高频） | `idx_m10_optometry_patient (patient_id, created_at DESC)` |
| 状态时间索引 | 待办/看板查询 | `idx_m10_order_status (status, created_at DESC)` |
| 部分索引 | 只索引"活跃"记录，减小体积 | `idx_m10_order_active … WHERE status IN ('PAID','IN_PRODUCTION','READY')` |
| 中文模糊 | 姓名/顾客名检索 | `idx_m10_customer_name_trgm` GIN `gin_trgm_ops` |
| 复合业务索引 | 频次最高的组合条件 | `idx_m10_lab_job_assignee (operator_id, status)` |

### 4.2 高频查询与索引对应（性能验收依据）

| 查询场景 | 主力索引 | 目标 P95 |
|---|---|---|
| 按验光单号取验光（P-01，M16-04 下单必调） | `uk_m10_optometry_no` | ≤ 100ms |
| 患者最近一次验光（P-02） | `idx_m10_optometry_patient` | ≤ 100ms |
| 患者有效处方（P-06） | `idx_m10_prescription_valid` | ≤ 100ms |
| 取镜待办列表（前台工作台） | `idx_m10_order_ready` | ≤ 300ms |
| 加工看板（按状态分列） | `idx_m10_lab_job_status` | ≤ 500ms |
| 可销售量查询（P-18，下单必调） | `idx_m10_stock_sku` | ≤ 80ms |
| 到期复查清单（P-24，每日扫描） | `idx_m10_followup_due` | ≤ 200ms |
| 视力档案纵向曲线（P-25） | `idx_m10_vision_record_patient` | ≤ 150ms |

### 4.3 索引维护原则

1. **不为低基数列单独建索引**（如 `is_deleted`、`status` 单独建无意义），必须与时间或其他高基数列组合。
2. **部分索引优先**：状态类查询几乎都带"非终态"过滤，用部分索引可减少 80% 以上索引体积。
3. 单表索引数 **不超过 12 个**（超过需评审，考虑合并或改大宽表）。
4. 全模块统一启用 `pg_trgm` 扩展以支持中文模糊检索：

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

## 6. 约束设计汇总

### 6.1 约束分类

| 类型 | 手段 | 适用 |
|---|---|---|
| 主键唯一 | `PRIMARY KEY` | 全部表 |
| 业务唯一 | 部分唯一索引 `WHERE is_deleted = FALSE` | 单号、编码、手机号 |
| 枚举合法 | `CHECK (col IN (...))` | 全部状态字段 |
| 值域校验 | `CHECK (col >= x AND col <= y)` | 度数、轴位、弧曲率 |
| 跨字段一致性 | `CHECK (A 与 B 同时为空/非空)` | 患者/顾客身份、眼别与度数 |
| 状态必填联动 | `CHECK (status <> 'VOID' OR void_reason IS NOT NULL)` | 作废、驳回、不合格 |
| 时间先后 | `CHECK (end_time >= start_time)` | 工期、试戴、随访 |

### 6.2 视光专业约束（M10 特有，必须实现）

```sql
-- ① 球镜/柱镜必须为 0.25 的整数倍（-30.00 ~ +30.00）
ALTER TABLE m10_optometry_refraction
    ADD CONSTRAINT ck_m10_refraction_sphere_step
    CHECK (sphere IS NULL OR
           (sphere >= -30.00 AND sphere <= 30.00 AND (sphere * 4) = round(sphere * 4)));

ALTER TABLE m10_optometry_refraction
    ADD CONSTRAINT ck_m10_refraction_cylinder_step
    CHECK (cylinder IS NULL OR
           (cylinder >= -10.00 AND cylinder <= 0.00 AND (cylinder * 4) = round(cylinder * 4)));

-- ② 柱镜为 0 时不可填轴位；柱镜不为 0 时轴位必填（1~180）
ALTER TABLE m10_optometry_refraction
    ADD CONSTRAINT ck_m10_refraction_axis
    CHECK ((cylinder IS NULL OR cylinder = 0) AND axis IS NULL
           OR (cylinder IS NOT NULL AND cylinder <> 0
               AND axis IS NOT NULL AND axis BETWEEN 1 AND 180));

-- ③ 眼别合法（OD 右 / OS 左 / OU 双 / NA 不适用）
ALTER TABLE m10_optometry_refraction
    ADD CONSTRAINT ck_m10_refraction_eye_side
    CHECK (eye_side IN ('OD', 'OS', 'OU', 'NA'));

-- ④ OK 镜弧参数关系：RC < BC < AC < PC（M01-08 已定义，M10-04 复现校验）
ALTER TABLE m10_ortho_k_custom_param
    ADD CONSTRAINT ck_m10_ortho_k_arc_relation
    CHECK (ortho_rc < ortho_bc AND ortho_bc < ortho_ac AND ortho_ac < ortho_pc);

-- ⑤ OK 镜直径与降度值域
ALTER TABLE m10_ortho_k_custom_param
    ADD CONSTRAINT ck_m10_ortho_k_diameter
    CHECK (lens_diameter BETWEEN 8.00 AND 14.00);

ALTER TABLE m10_ortho_k_custom_param
    ADD CONSTRAINT ck_m10_ortho_k_reduction
    CHECK (reduction BETWEEN -10.00 AND 0.00);

-- ⑥ 瞳距值域（单眼 20~45mm，双眼 40~90mm）
ALTER TABLE m10_optometry
    ADD CONSTRAINT ck_m10_optometry_pd
    CHECK (pupil_distance IS NULL OR pupil_distance BETWEEN 40.00 AND 90.00);

-- ⑦ 等效球镜 SE = SPH + CYL/2，由应用层计算后落库，约束保证一致性
ALTER TABLE m10_vision_archive_record
    ADD CONSTRAINT ck_m10_vision_record_se
    CHECK (se IS NULL OR sphere IS NULL OR cylinder IS NULL
           OR abs(se - (sphere + cylinder / 2.0)) < 0.005);
```

### 6.3 状态机约束（作废/驳回必须留痕）

```sql
-- 验光单作废必须填原因与时间
ALTER TABLE m10_optometry
    ADD CONSTRAINT ck_m10_optometry_void
    CHECK (status <> 'VOID'
           OR (void_reason IS NOT NULL AND char_length(btrim(void_reason)) >= 10
               AND voided_by IS NOT NULL AND voided_at IS NOT NULL));

-- 处方驳回必须填审核意见
ALTER TABLE m10_prescription
    ADD CONSTRAINT ck_m10_prescription_reject
    CHECK (status <> 'REJECTED'
           OR (reject_reason IS NOT NULL AND char_length(btrim(reject_reason)) >= 5));

-- 订单取消必须填原因
ALTER TABLE m10_order
    ADD CONSTRAINT ck_m10_order_cancel
    CHECK (status <> 'CANCELLED' OR cancel_reason IS NOT NULL);

-- 加工单质检失败必须填缺陷类型
ALTER TABLE m10_lab_job
    ADD CONSTRAINT ck_m10_lab_job_qc_failed
    CHECK (status <> 'QC_FAILED' OR defect_type IS NOT NULL);
```
