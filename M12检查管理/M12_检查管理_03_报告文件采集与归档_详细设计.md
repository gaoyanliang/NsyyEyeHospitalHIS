## 1. 模块概述

### 1.1 模块定位

**本项目最特殊的技术约束是：所有检查设备都无法接入 HIS。**

没有 DICOM、没有 HL7、没有 RIS 接口。设备厂商的软件自成一体，报告只能通过**人工导出 PDF 到共享文件夹**这一条路进入 HIS。

M12-03 就是**把这条唯一的通路管起来**的模块。

```
┌──────────────────────────────────────────────────────────────────┐
│  检查设备（OCT / 眼底相机 / 视野计 / 眼压计 …）                    │
│  ── 无法接入 HIS，无接口、无 DICOM、无主动推送                      │
└────────────────────────┬─────────────────────────────────────────┘
                         │ 技师手工：设备软件 → 导出 → 另存 PDF
                         ▼
┌──────────────────────────────────────────────────────────────────┐
│  \\fileserver\exam-reports\2026\10\22\                            │
│  共享文件夹（设备电脑可直接写入的网络盘）                            │
│  · OCT_20261022_091545.pdf                                       │
│  · DT0120261022007.pdf                                           │
│  · 1000012345.pdf                                                │
└────────────────────────┬─────────────────────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────────────────────┐
│  ★ M12-03 报告文件采集与归档（本文档）                             │
│                                                                  │
│  ① 监听共享文件夹（watchdog inotify，暴力扫描兜底）                 │
│  ② 等待文件写完（大小稳定 + 可独占打开）                            │
│  ③ 计算 SHA-256（去重）                                           │
│  ④ 入库登记 m12_report_file                                       │
│  ⑤ 创建解析任务 → 调 M12-04 做 OCR 与患者绑定                       │
│  ⑥ 归档：只移不删，移入 ARCHIVE\yyyy\MM\dd\                        │
│  ⑦ 每日巡检：抽查 SHA-256，发现丢失告警                             │
└────────────────────────┬─────────────────────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────────────────────┐
│  M12-04 OCR 解析与结构化                                          │
│  "这份 PDF 是谁的、里面写了什么"                                    │
└──────────────────────────────────────────────────────────────────┘
```

**一句话边界：** M12-03 只管**"文件有没有进来、是不是重复、原件在哪"**。管不了"文件里写的是谁"（M12-04）、"报告能不能发"（M12-05）。

### 1.2 为什么独立成子模块

这个模块在标准 HIS 里根本不存在——因为有 DICOM 和 RIS，图像和报告都是设备主动推送的。但本项目不同，理由有四条。

#### 理由一：文件采集是整个方案里唯一不可跳过的环节

标准 HIS 的报告流程是：

```
设备 → 推送 → PACS/RIS → HIS 拉取 → 医生查看
```

本项目的流程是：

```
设备 → 技师手工导出 → 共享文件夹 → ??? → 医生查看
```

中间那个 `???` 就是 M12-03。**如果文件采集失败，后面的 OCR、绑定、审核、推送全部无从谈起。**

这不是一个"锦上添花"的功能，而是整条链路的入口。它的可靠性直接决定了整个检查报告方案能不能用。

#### 理由二：文件本身有大量需要处理的技术细节

一个看似简单的"读文件夹"操作，实际要处理至少这些问题：

| 问题 | 具体表现 | 不处理的后果 |
|---|---|---|
| **文件正在写** | 技师刚点导出，PDF 还在写，读到一半 | 文件损坏，OCR 解析失败 |
| **重复导出** | 技师导了两次，同一个报告两份文件 | 重复报告，医生看到两份 |
| **文件名混乱** | 各种命名（`报告.pdf`、`未命名-1.pdf`、`OCT_20261022.pdf`） | 无法用文件名判断是谁 |
| **多级子目录** | 技师按日期/患者建了子文件夹 | 漏采 |
| **超大文件** | 扫描件 200MB | 内存溢出、OCR 超时、磁盘撑爆 |
| **非 PDF 文件** | 技师存了 JPG、DOCX、压缩包 | 解析器崩溃 |
| **中文路径乱码** | 共享盘编码问题 | 文件打不开 |
| **文件被占用** | 设备软件还开着这个文件 | 移动/读取失败 |
| **设备电脑时间不准** | 设备时钟比服务器慢 20 分钟 | 时间窗绑定错位 |
| **同名覆盖** | 两台设备都叫 `report.pdf` | 后一份覆盖前一份，前一份永久丢失 |

**每一个问题都必须专门处理**，散落在业务代码里必然遗漏。

#### 理由三：S3 方案（原件留在共享文件夹）必须有人负责兜底

用户选择了 S3 方案：**PDF 原件继续留在共享文件夹，数据库只存路径与 SHA-256。**

这个方案的优点是省存储、省带宽、不重复。但它有一个致命风险：

> **共享文件夹是单点存储。服务器故障、误删、勒索病毒，都会导致历史报告全部丢失。**

M12-03 必须承担"兜底"职责，具体三层：

1. **入库即算 SHA-256**：指纹存库，即使文件丢了，也能证明"曾经有一份这样的文件"
2. **归档只移不删**：所有文件按日期移入 `ARCHIVE\yyyy\MM\dd\`，永不删除。即使有人误删当日目录，历史归档还在
3. **每日巡检抽查**：随机抽 N 份文件校验 SHA-256，发现丢失立即告警；同时保留 OCR 解析结果与报告正文，**原件丢了报告还能看**

#### 理由四：采集质量数据是必须可以被度量的

检查科需要知道：

- 今天应该有多少份报告？实际进来多少？差多少？
- 哪些报告超过 SLA 还没进来？
- 哪些文件进了待确认队列（无法绑定）？
- 共享文件夹的写入延迟是多少？

这些数据只能由 M12-03 提供。如果直接塞在 M12-04 里，会导致"解析"与"采集"两类完全不同的指标混在一起。

### 1.4 概念辨析

#### 1.4.1 采集（Collection）≠ 解析（Parsing）

| 概念 | 负责子模块 | 输入 | 输出 |
|---|---|---|---|
| **采集** | **M12-03** | 共享文件夹里的文件 | 一条 `m12_report_file` 记录 + 文件可访问路径 |
| **解析** | M12-04 | 文件路径 | 结构化报告 + 患者绑定关系 |

**为什么要分开？**

因为二者的失败模式完全不同：

| 失败 | 发生环节 | 影响 | 重试策略 |
|---|---|---|---|
| 文件没进来 | 采集 | 报告丢失 | 立即告警 |
| 文件损坏 | 采集 | 无法解析 | 立即告警 |
| **识别不出姓名** | 解析 | 进待确认队列 | 人工处理 |
| **同名无法唯一绑定** | 解析 | 进待确认队列 | 人工处理 |

如果混在一起，日志里就分不清"是文件没进来，还是进来了但识别不出"。

#### 1.4.2 采集文件（File）≠ 报告（Report）

**一份报告可以有多个文件。** 这是本项目最容易被误解的一点。

真实场景：

```
患者张某做 OCT：
  技师导出了 PDF 报告（含图像 + 测量值）

患者李某做眼底照相：

  技师导出了 3 个文件：
    · 右眼照片.pdf
    · 左眼照片.pdf
    · 汇总报告.pdf

患者王某做 OCTA：
  技师导出了 PDF，但设备软件还附带导出了一张病灶标注图（PNG）
```

所以数据模型是：

```
m12_report_file（文件，1:N）
      │
      ▼
m12_exam_window / m12_report（报告，1:1 或 1:N）
```

M12-03 管**文件**，M12-04/M12-05 管**报告**。

#### 1.4.3 归档（Archive）≠ 删除（Delete）

| 概念 | 动作 | 数据保留 | 可恢复 |
|---|---|---|---|
| **归档** | 从 `INBOX` 移到 `ARCHIVE\yyyy\MM\dd\` | 完整保留 | 是，只是换了目录 |
| **删除** | 物理删除 | 永久丢失 | 否 |

M12-03 **永不删除文件**。唯一的"清理"是归档（移动），且归档路径可预测（按日期），所以永远找得回来。

**为什么这么严格？**

因为检查报告是**医疗文书**，法定保存期限是门诊病历 15 年、住院病历 30 年。如果原件的文件没了，即使 OCR 结果还在，遇到医疗纠纷时医院也说不清"当时的原始报告是什么样"。

#### 1.4.4 文件指纹（SHA-256）≠ 文件路径

| 概念 | 特点 | 用途 |
|---|---|---|
| **SHA-256** | 内容哈希，路径无关 | 去重、完整性校验 |
| **文件路径** | 位置，随移动而变 | 定位文件 |

**同一份文件换了个路径，SHA-256 不变。** 这正是我们需要的：即使文件被归档移走了，只要 SHA-256 没变，就能证明"还是那份文件"。

反过来，两个文件**内容相同但路径不同**（技师导了两次），SHA-256 相同 → M12-03 判定为重复，只登记一次。

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 文件采集率 | ≥ 99.5% | 应采集文件数 vs 实际采集数 |
| 采集延迟 | ≤ 60 秒 | 文件落地到入库登记的时长 |
| 重复文件识别率 | 100% | 同 SHA-256 只登记一次 |
| 文件完整性判定准确率 | ≥ 99.9% | 不采集未写完的文件 |
| 归档成功率 | ≥ 99.9% | 归档任务成功比例 |
| 巡检覆盖率 | 100% | 每日必须完成巡检 |
| 文件丢失发现时效 | ≤ 24 小时 | 从丢失到告警 |
| 下载响应 | P95 ≤ 500ms | 10MB 以内文件 |
| 目录扫描（1 万文件） | ≤ 30 秒 | 暴力兜底扫描 |

**为什么采集率是 99.5% 而不是 100%？**

因为存在真实无法采集的情况：

- 技师导出时选了错误目录（导到了桌面）
- 技师导出后立刻把文件删了
- 设备软件崩溃，文件没写出来

这些系统无法自动处理，只能靠"应采集数 vs 实际采集数"的差异告警，由人工补齐。

### 1.6 关键业务角色

| 角色 | 职责 | 主要操作 |
|---|---|---|
| 检查技师 | 导出 PDF | 把文件存到指定共享目录（不在系统内操作） |
| 检查科护士 | 补采集 | 手工上传漏采的文件 |
| 检查科主任 | 采集质量监控 | 查看采集率、待确认队列、告警处理 |
| 医务科 | 报告追溯 | 按患者查原件 |
| 系统管理员 | 共享盘配置 | 配置监听目录、归档策略、巡检参数 |

## 3. 业务模型

### 3.1 文件采集流程总览

```
┌────────────────────────────────────────────────────────┐
│  共享文件夹 \\fileserver\exam-reports\                  │
│  ├── INBOX\          ← 设备电脑直接写入这里             │
│  ├── ARCHIVE\        ← 归档目标                         │
│  │   └── 2026\10\22\                                   │
│  ├── QUARANTINE\     ← 可疑文件隔离区                   │
│  └── MANUAL\         ← 手工上传暂存                     │
└────────────────────────────────────────────────────────┘
        │
        │ ① watchdog 监听 INBOX（inotify）
        │    实时事件：created / moved / modified
        ▼
┌──────────────────────────────────────┐
│  ② 文件稳定性判定                     │
│  · 大小连续 2 次采样不变（间隔 3 秒）  │
│  · 可独占打开（非共享锁定）            │
│  · PDF 魔数 %PDF- 校验                │
│  · 文件年龄 > 5 秒（避开刚创建）       │
└──────────────┬───────────────────────┘
               │ 稳定
               ▼
┌──────────────────────────────────────┐
│  ③ 预筛选                             │
│  · 扩展名必须是 .pdf                  │
│  · 大小 1KB ~ 200MB                  │
│  · 路径不含临时文件标识（~$ .tmp）    │
└──────────────┬───────────────────────┘
               │ 通过
               ▼
┌──────────────────────────────────────┐
│  ④ 计算 SHA-256                       │
│  · 流式读取（1MB 分块）               │
│  · 同时校验 PDF 页数（pypdf）          │
└──────────────┬───────────────────────┘
               │
        ┌──────┴───────┐
        │ 已存在？      │
        ├──── 是 ──────┤
        │              │ 否
        ▼              ▼
┌──────────────┐  ┌───────────────────────────┐
│ 标记重复      │  │  ⑤ PDF 预解析               │
│ duplicate_of  │  │  · 页数、是否加密、是否扫描件 │
│ 不派发解析     │  │  · 提取文本（判断是否可 OCR）│
└──────────────┘  └──────────┬────────────────┘
                             │
                             ▼
                ┌────────────────────────────┐
                │  ⑥ 入库登记                 │
                │  m12_report_file            │
                │  status = 'COLLECTED'       │
                └────────────┬───────────────┘
                             │

                ┌────────────────────────────┐

                │  移到 ARCHIVE\2026\10\22\  │
                │  更新 file_path            │
                └────────────────────────────┘
```

### 3.2 文件稳定性判定模型

这是采集环节最关键的判定。**文件正在写时读到的内容是不完整的**，如果直接处理，会导致 PDF 损坏、OCR 失败。

```
时间轴：

T0  技师点【导出】
    │
    ▼
T0     文件创建，size = 0
T0+1s  写入中，size = 2MB
T0+3s  写入中，size = 8MB
T0+5s  写入中，size = 12MB
T0+6s  写入完成，size = 12.4MB
    │
    ▼
判定逻辑（每 3 秒采样一次）：

采样1（T0+0.5s）: size=0        → 不稳定（size=0）
采样2（T0+3.5s）: size=8MB      → 与上次不同，不稳定
采样3（T0+6.5s）: size=12.4MB   → 与上次不同，不稳定
采样4（T0+9.5s）: size=12.4MB   → 与上次相同 ✓
                    ↓
              尝试独占打开 → 成功 ✓
                    ↓
              校验 PDF 魔数 %PDF- → 成功 ✓
                    ↓
              文件年龄 9.5s > 5s ✓
                    ↓
              ★ 判定为稳定，可以采集
```

**四个条件缺一不可：**

| 条件 | 阈值 | 为什么需要 |
|---|---|---|
| 大小连续两次相同 | 间隔 3 秒 | 排除写入中 |
| 可独占打开 | 操作系统独占锁 | 排除被其他进程占用 |
| PDF 魔数 | `%PDF-` 开头 | 排除伪装扩展名的文件 |
| 文件年龄 | > 5 秒 | 排除刚创建还没开始写的空文件 |

**为什么是两次采样而不是三次？**

三次会增加 3 秒延迟。实测显示，设备导出 PDF 通常 2~10 秒完成，两次采样（间隔 3 秒）已经足够。如果三次，平均采集延迟会从 9 秒变成 12 秒。

**如果文件一直在写（超大扫描件，写了 3 分钟）怎么办？**

大小采样始终不稳定，系统会：
1. 重试最多 20 次（约 1 分钟）
2. 超过 20 次仍未稳定 → 标记为 `TIMEOUT`，等待下轮扫描
3. 如果 30 分钟后仍不稳定 → 移入 `QUARANTINE`，告警

### 3.3 去重模型

```
文件 A：OCT_20261022_0915.pdf  size=12.4MB  sha256=abc123...
文件 B：报告(1).pdf            size=12.4MB  sha256=abc123...
                                                     ↓
                                         相同！判定为重复
```

**为什么用 SHA-256 而不是"文件名 + 大小"？**

| 方案 | 问题 |
|---|---|
| 文件名 | 技师经常改文件名，同一个报告导出两次名字可能不同 |
| 文件名 + 大小 | 两个不同患者同一天做同一项目，报告大小可能恰好相同 |
| **SHA-256** | 内容完全一致才判重，几乎不可能误判 |

SHA-256 的碰撞概率是 2^-128，比中彩票还低几个数量级。

**重复文件的处理：**

| 情况 | 处理 |
|---|---|
| 同一份 PDF 被导出两次 | 保留第一条记录，第二条标 `duplicate_of = 第一条 id` |
| 第二条已被解析 | 不影响，第一条正常继续 |
| 第一条解析失败，第二条可用 | 允许将第二条提升为主文件（手工操作） |

**为什么要保留重复记录而不直接丢弃？**

因为重复文件的存在本身就是一条信息：技师导了两次，说明第一次可能出了问题（比如导出到错误目录）。保留记录可以复盘。

### 3.4 归档模型

```
INBOX\                               ARCHIVE\
├── OCT_001.pdf        ──────────►  ├── 2026\
├── DT0120261022007.pdf ─────────►  │   └── 10\
└── 报告(1).pdf        ──────────►  │       └── 22\
                                    │           ├── OCT_001.pdf
                                    │           ├── DT0120261022007.pdf
                                    │           └── 报告(1).pdf
                                    └── 2026\10\23\ ...
```

**归档规则：**

| 规则 | 说明 |
|---|---|
| 归档时机 | 入库后立即异步归档（延迟 ≤ 5 分钟） |
| 目标路径 | `ARCHIVE\yyyy\MM\dd\`，日期取**文件创建时间**（不是归档时间） |
| 文件名冲突 | 追加 `_{sha256前8位}`，如 `OCT_001_a1b2c3d4.pdf` |
| 只移不删 | 永不删除 |
| 路径可预测 | 给定文件创建时间和 SHA-256，能唯一确定归档路径 |
| 失败重试 | 3 次，间隔 1/5/15 分钟 |
| 失败告警 | 3 次失败后告警，文件留在 INBOX |

**为什么按"文件创建时间"而不是"归档时间"分组？**

因为技师可能隔天才导出（比如昨天的检查今天才导），按归档时间分组会导致同一批报告散落在不同日期目录。按文件创建时间分组更符合"这批报告是哪天做的"的直觉。

**但"文件创建时间"从哪来？**

从 `os.stat().st_mtime`（修改时间）取，因为：

- Windows 共享盘的 `st_ctime` 在不同系统上语义不一致（Linux 是 inode 变更时间，Windows 是创建时间）
- `st_mtime` 在文件写入完成后不再变化，是最可靠的

**如果 mtime 不可信（设备时钟错误）怎么办？**

参数 `M12.COLLECT.USE_FILE_MTIME` 控制：
- `TRUE`（默认）：用文件 mtime
- `FALSE`：用采集入库时间

如果是已知的设备时钟问题，可以关掉。

### 3.5 文件完整性契约（巡检模型）

S3 方案下，原件在共享文件夹，数据库只存路径。这带来一个风险：**文件可能在无人察觉的情况下丢失。**

巡检模型：

```
每日 02:00 执行巡检：

① 按比例抽查
   · 近 30 天：抽 20%
   · 30~180 天：抽 10%
   · 180 天以上：抽 2%
   · 每日最少 200 份

② 逐个校验
   for each sampled file:
       if not exists(path):
           记录为 MISSING，告警
           continue
       actual_sha256 = sha256(path)
       if actual_sha256 != record.sha256:
           记录为 CORRUPTED，告警
           continue
       记录为 OK

③ 汇总报告
   · 抽查总数、OK 数、MISSING 数、CORRUPTED 数
   · 丢失率 = MISSING / 抽查总数
   · 丢失率 > 0.1% 触发严重告警
```

**发现丢失后怎么补救？**

三层补救：

| 层级 | 措施 | 效果 |
|---|---|---|
| 1 | 从 ARCHIVE 目录按可预测路径找回 | 最常见，90% 能找回 |
| 2 | 从备份系统恢复 | 需 IT 配合，T+1 |
| 3 | **使用已保存的 OCR 解析结果与报告正文** | 立即生效，报告仍可查看 |

第三层是关键：因为 M12-04 已经把 PDF 内容解析成结构化数据存库，所以**原件丢了报告正文还在**。医生查看报告不受影响，只是"下载原件"按钮会提示"原件已失效"。

### 3.6 采集失败分类模型

| 失败类型 | 代码 | 可否自动恢复 | 处理 |
|---|---|---|---|
| 文件不稳定（写不完） | `UNSTABLE` | 自动重试 | 等待下轮 |
| 文件被占用 | `LOCKED` | 自动重试 | 等待下轮 |
| 非 PDF 文件 | `NOT_PDF` | 否 | 移入 QUARANTINE |
| 文件损坏 | `CORRUPTED` | 否 | 移入 QUARANTINE，告警 |
| 文件过小 | `TOO_SMALL` | 否 | 移入 QUARANTINE |
| 文件过大 | `TOO_LARGE` | 否 | 移入 QUARANTINE，告警 |
| PDF 加密 | `ENCRYPTED` | 否 | 标记待处理，人工输入密码 |
| 路径乱码 | `BAD_PATH` | 否 | 告警 |
| 共享盘不可用 | `SHARE_UNAVAILABLE` | 是 | 暂停采集，恢复后继续 |
| 磁盘满 | `DISK_FULL` | 是 | 告警，清理后可继续 |

**为什么"加密 PDF"单独一类？**

因为设备软件有时会给 PDF 加密码（防止篡改）。这种文件不是"坏文件"，而是"需要密码才能读"。系统应当：
1. 不丢弃
2. 标记 `need_password = TRUE`
3. 在页面上提供"输入密码"入口
4. 密码由管理员维护（通常所有报告用同一个密码）

### 3.7 共享目录结构模型

```
\\fileserver\exam-reports\
│
├── INBOX\                          ← 设备电脑直接写入
│   ├── OCT\                        ← 可选：按设备分子目录
│   │   └── *.pdf
│   ├── FUNDUS\
│   └── VF\
│
├── ARCHIVE\                        ← 归档（系统只写这个目录）
│   ├── 2026\10\22\
│   ├── 2026\10\23\
│   └── 2025\...
│
├── QUARANTINE\                     ← 隔离区（有问题的文件）
│   ├── NOT_PDF\
│   ├── CORRUPTED\
│   └── OVERSIZE\
│
└── MANUAL\                         ← 手工上传暂存区
    └── *.pdf
```

**为什么要分子目录？**

如果 6 台设备所有 PDF 都堆在 `INBOX\` 根目录，一天 400 个文件，一个月 1.2 万个。Windows 资源管理器打开会卡，而且技师找文件也困难。

按设备分子目录后：

- 每台设备日均 70 个文件，清爽
- 采集器可以按目录并行处理
- 出问题容易定位是哪台设备

**但这个分层不是强制的。**

参数 `M12.COLLECT.RECURSIVE` 控制是否递归扫描子目录。默认 `TRUE`，无论技师建几层目录都能采到。

```python
"""M12-03 报告文件采集与归档 —— 路由层。"""
from datetime import date
from typing import List, Optional

from fastapi import APIRouter, BackgroundTasks, Depends, File, Form, Query, UploadFile

from app.api.deps import CurrentUser, require_permission

    user: CurrentUser = Depends(require_permission("m12:collect:query")),
):
    """采集监控看板：应采/已采/采集率/流水/未采任务/告警。"""
    return ok(await CollectService.get_dashboard(target_date, user))

async def stream(
    limit: int = Query(20, ge=1, le=200),
    user: CurrentUser = Depends(require_permission("m12:collect:query")),
):
    """实时采集流水。"""
    return ok(await CollectService.recent_stream(limit, user))


@router.get("/pending-tasks")
async def pending_tasks(
    min_wait_minutes: int = Query(0, ge=0),
    page_no: int = Query(1, ge=1),
    page_size: int = Query(20, ge=1, le=100),
    user: CurrentUser = Depends(require_permission("m12:collect:query")),
):
    """未采集任务列表。"""
    data = await CollectService.pending_tasks(min_wait_minutes,
                                              page_no, page_size, user)
    return page(data["items"], data["total"], page_no, page_size)

    body: "UrgeIn",

    return ok(await CollectService.urge(body.task_ids, user))
```

```python
"""M12-03 报告文件采集 —— 核心服务。"""
import hashlib
import logging
import os
import shutil
import time
from datetime import datetime, timedelta
from pathlib import Path

from sqlalchemy import select

from app.core.exception import BizException
from app.core.redis_client import redis
from app.models.m12_exam import M12ReportFile, M12CollectConfig
from app.services.m12.no_seq import next_file_no

logger = logging.getLogger(__name__)

# 文件状态
ST_COLLECTED = "COLLECTED"
ST_PARSING = "PARSING"
ST_PARSED = "PARSED"
ST_PARSE_FAILED = "PARSE_FAILED"
ST_QUARANTINE = "QUARANTINE"
ST_ORPHAN = "ORPHAN"
ST_DUPLICATE = "DUPLICATE"

# 归档状态
ARC_PENDING = "PENDING"
ARC_ARCHIVED = "ARCHIVED"
ARC_FAILED = "FAILED"

# 绑定状态（由 M12-04 维护）
BIND_UNCONFIRMED = "UNCONFIRMED"
BIND_BOUND = "BOUND"
BIND_ORPHAN = "ORPHAN"

# 默认阈值
DEFAULT_SAMPLE_INTERVAL = 3
DEFAULT_MIN_AGE_SECONDS = 5
DEFAULT_MIN_SIZE = 1024
DEFAULT_MAX_SIZE = 200 * 1024 * 1024
DEFAULT_MAX_RETRY = 20
PDF_MAGIC = b"%PDF-"


class CollectService:
    """文件采集服务。"""

    @staticmethod
    async def register_file(body) -> dict:
        """登记文件（唯一入口，自动扫描与手工上传都走这里）。"""
        db = get_session()

        # 1. 去重：同 SHA-256 已存在则标记重复
        existing = await db.scalar(
            select(M12ReportFile).where(
                M12ReportFile.sha256 == body.sha256,
                M12ReportFile.status != ST_DUPLICATE,
                M12ReportFile.is_deleted.is_(False),
            ).order_by(M12ReportFile.id.asc()).limit(1)
        )

        now = datetime.now()
        if existing:
            record = M12ReportFile(
                file_no=await next_file_no(db),
                file_name=body.file_name,
                original_path=body.original_path,
                current_path=body.original_path,
                size_bytes=body.size_bytes,
                sha256=body.sha256,
                file_mtime=_parse_dt(body.file_mtime),
                device_code=body.device_code,
                source=body.source,
                status=ST_DUPLICATE,
                archive_status=ARC_PENDING,
                bind_status=None,
                is_duplicate=True,
                duplicate_of_file_id=existing.id,
                collected_at=now,
                collected_by=body.operator_id,
                is_deleted=False,
                created_at=now,
                updated_at=now,
            )
            db.add(record)
            await db.commit()
            logger.info(
                "文件重复 file=%s sha256=%s duplicate_of=%d",
                body.file_name, body.sha256[:16], existing.id,
                extra={"module": "M12-03", "action": "FILE_DUPLICATE"})
            return {
                "file_id": record.id,
                "is_duplicate": True,
                "duplicate_of": existing.id,
                "status": ST_DUPLICATE,
                "parse_dispatched": False,
                "next_action": "NONE",
            }

        # 2. PDF 预解析（页数、加密、扫描件）
        meta = await CollectService._probe_pdf(body.original_path)

        # 3. 入库
        record = M12ReportFile(
            file_no=await next_file_no(db),
            file_name=body.file_name,
            original_path=body.original_path,
            current_path=body.original_path,
            size_bytes=body.size_bytes,
            sha256=body.sha256,
            file_mtime=_parse_dt(body.file_mtime),
            device_code=body.device_code,
            source=body.source,
            page_count=meta.get("page_count"),
            is_encrypted=meta.get("is_encrypted", False),
            is_scanned=meta.get("is_scanned"),
            status=ST_COLLECTED,
            archive_status=ARC_PENDING,
            bind_status=None,
            is_duplicate=False,
            collected_at=now,
            collected_by=body.operator_id,
            is_deleted=False,
            created_at=now,
            updated_at=now,
        )
        db.add(record)
        await db.flush()

        # 4. 加密 PDF 不移交解析，等待密码
        if meta.get("is_encrypted"):
            record.status = ST_COLLECTED
            record.need_password = True
            await db.commit()
            logger.warning("发现加密 PDF，等待密码 file=%s", body.file_name,
                           extra={"module": "M12-03",
                                  "action": "FILE_ENCRYPTED"})
            return {
                "file_id": record.id,
                "is_duplicate": False,
                "duplicate_of": None,
                "status": ST_COLLECTED,
                "parse_dispatched": False,
                "next_action": "NEED_PASSWORD",
            }

        record.status = ST_PARSING
        await db.commit()

        # 5. 派发解析（异步，失败降级不阻断采集）
        from app.tasks.m12_tasks import dispatch_parse_task
        try:
            dispatch_parse_task.delay(record.id)
            parse_dispatched = True
        except Exception:
            logger.exception("派发解析失败 file_id=%d", record.id)
            parse_dispatched = False

        logger.info(
            "文件入库 file=%s file_id=%d size=%d sha256=%s",
            body.file_name, record.id, body.size_bytes, body.sha256[:16],
            extra={"module": "M12-03", "action": "FILE_COLLECTED"})

        return {
            "file_id": record.id,
            "is_duplicate": False,
            "duplicate_of": None,
            "status": record.status,
            "parse_dispatched": parse_dispatched,
            "next_action": "PARSING" if parse_dispatched else "RETRY_LATER",
        }

    @staticmethod
    async def is_file_stable(path: str, max_retry: int = DEFAULT_MAX_RETRY) -> bool:
        """判定文件是否已写完（可安全读取）。

        四个条件缺一不可：
          1. 大小连续两次采样相同（间隔 N 秒）
          2. 可独占打开
          3. PDF 魔数校验通过
          4. 文件年龄 > 最小年龄
        """
        interval = DEFAULT_SAMPLE_INTERVAL
        min_age = DEFAULT_MIN_AGE_SECONDS

        if not os.path.exists(path):
            return False

        try:
            stat = os.stat(path)
        except OSError:
            return False

        # 条件 4：文件年龄
        age = time.time() - stat.st_mtime
        if age < min_age:
            logger.debug("文件年龄不足 path=%s age=%.1fs", path, age)
            return False

        # 条件 1：大小连续两次相同
        last_size = stat.st_size
        for attempt in range(max_retry):
            await asyncio.sleep(interval)
            try:
                cur_size = os.path.getsize(path)
            except OSError:
                return False
            if cur_size != last_size:
                logger.debug("文件仍在写入 path=%s %d -> %d",
                             path, last_size, cur_size)
                last_size = cur_size
                continue

            # 条件 2：可独占打开
            if not CollectService._can_open_exclusive(path):
                logger.debug("文件被占用 path=%s", path)
                await asyncio.sleep(interval)
                continue

            # 条件 3：PDF 魔数
            if not CollectService._check_pdf_magic(path):
                logger.warning("非 PDF 文件 path=%s", path)
                return False

            return True

        logger.warning("文件稳定性判定超时 path=%s retry=%d",
                       path, max_retry)
        return False

    @staticmethod
    def _can_open_exclusive(path: str) -> bool:
        """尝试独占打开文件。"""
        try:
            with open(path, "rb") as fh:
                fh.read(1)
            return True
        except (OSError, PermissionError):
            return False

    @staticmethod
    def _check_pdf_magic(path: str) -> bool:
        """校验 PDF 魔数 %PDF-。"""
        try:
            with open(path, "rb") as fh:
                return fh.read(5) == PDF_MAGIC
        except OSError:
            return False

    @staticmethod
    def compute_sha256(path: str, chunk_size: int = 1024 * 1024) -> str:
        """流式计算 SHA-256（1MB 分块，避免大文件占内存）。"""
        digest = hashlib.sha256()
        with open(path, "rb") as fh:
            while True:
                chunk = fh.read(chunk_size)
                if not chunk:
                    break
                digest.update(chunk)
        return digest.hexdigest()

    @staticmethod
    async def _probe_pdf(path: str) -> dict:
        """PDF 预解析：页数、是否加密、是否扫描件。"""
        try:
            from pypdf import PdfReader
            reader = PdfReader(path)
            page_count = len(reader.pages)
            is_encrypted = reader.is_encrypted
            text_len = 0
            if not is_encrypted and page_count:
                try:
                    text_len = len((reader.pages[0].extract_text() or "").strip())
                except Exception:
                    text_len = 0
            return {
                "page_count": page_count,
                "is_encrypted": is_encrypted,
                # 首页文字少于 20 字符视为扫描件（需 OCR）
                "is_scanned": (not is_encrypted) and text_len < 20,
            }
        except Exception:
            logger.exception("PDF 预解析失败 path=%s", path)
            return {"page_count": None, "is_encrypted": None,
                    "is_scanned": None}

    @staticmethod
    async def archive_file(file_id: int) -> dict:
        """归档：只移不删，移入 ARCHIVE\\yyyy\\MM\\dd\\。"""
        db = get_session()
        record = await db.scalar(
            select(M12ReportFile).where(
                M12ReportFile.id == file_id).with_for_update()
        )
        if not record:
            raise BizException("1203016", "采集任务不存在")
        if record.archive_status == ARC_ARCHIVED:
            raise BizException("1203005", "文件已归档，不可重复归档")

        cfg = await CollectConfigService.get_dict()
        root = cfg["root_path"]
        archive_root = os.path.join(root, cfg["archive_dir"])

        src = record.current_path
        if not os.path.exists(src):
            record.archive_status = ARC_FAILED
            record.archive_error = "源文件不存在"
            await db.commit()
            raise BizException("1203003", "文件已丢失，无法归档")

        group_dt = record.file_mtime or record.collected_at
        target_dir = os.path.join(archive_root,
                                  group_dt.strftime("%Y"),
                                  group_dt.strftime("%m"),
                                  group_dt.strftime("%d"))
        os.makedirs(target_dir, exist_ok=True)

        target = os.path.join(target_dir, record.file_name)
        if os.path.exists(target):
            base, ext = os.path.splitext(record.file_name)
            target = os.path.join(target_dir,
                                  "%s_%s%s" % (base, record.sha256[:8], ext))

        try:
            shutil.move(src, target)
        except Exception as exc:
            record.archive_status = ARC_FAILED
            record.archive_error = str(exc)[:200]
            record.archive_retry = (record.archive_retry or 0) + 1
            await db.commit()
            logger.exception("归档失败 file_id=%d", file_id)
            raise BizException("1203021", "归档失败，文件仍保留在 INBOX")

        record.archive_status = ARC_ARCHIVED
        record.current_path = target
        record.archived_at = datetime.now()
        record.archive_error = None
        await db.commit()

        logger.info("文件归档 file_id=%d target=%s", file_id, target,
                    extra={"module": "M12-03", "action": "FILE_ARCHIVED"})

        return {"file_id": file_id, "archive_status": ARC_ARCHIVED,
                "current_path": target, "archived_at": record.archived_at}

    @staticmethod
    async def on_parsed(file_id: int, body) -> dict:
        """解析结果回写（M12-04 调用）。"""
        db = get_session()
        record = await db.scalar(
            select(M12ReportFile).where(
                M12ReportFile.id == file_id).with_for_update()
        )
        if not record:
            raise BizException("1203016", "采集任务不存在")

        record.parse_id = body.parse_id
        record.parse_status = body.parse_status
        record.bind_status = body.bind_status
        record.bound_task_id = body.bound_task_id
        record.bind_type = body.bind_type
        if body.page_count is not None:
            record.page_count = body.page_count
        if body.is_scanned is not None:
            record.is_scanned = body.is_scanned
        if body.ocr_confidence is not None:
            record.ocr_confidence = body.ocr_confidence

        if body.parse_status == "SUCCESS":
            record.status = ST_PARSED
        elif body.parse_status == "FAILED":
            record.status = ST_PARSE_FAILED
            record.parse_retry = (record.parse_retry or 0) + 1

        await db.commit()
        return {"file_id": file_id, "status": record.status,
                "bind_status": record.bind_status, "updated": True}

    @staticmethod
    async def full_scan(force_recheck: bool = False) -> dict:
        """全量扫描 INBOX 目录（watchdog 的兜底）。"""
        cfg = await CollectConfigService.get_dict()
        root = cfg["root_path"]
        inbox = os.path.join(root, cfg["inbox_dir"])
        recursive = cfg.get("recursive", True)

        if not os.path.isdir(inbox):
            raise BizException("1203001", "共享文件夹不可访问")

        allowed_ext = {"." + e.strip().lower().lstrip(".")
                       for e in cfg.get("allowed_ext", "pdf").split(",")}
        min_size = cfg.get("min_size_kb", 1) * 1024
        max_size = cfg.get("max_size_mb", 200) * 1024 * 1024

        scanned = 0
        collected = 0
        duplicated = 0
        quarantined = 0
        skipped = 0

        for dirpath, _, filenames in os.walk(inbox) if recursive \
                else [(inbox, [], os.listdir(inbox))]:
            for fn in filenames:
                scanned += 1
                full = os.path.join(dirpath, fn)
                ext = os.path.splitext(fn)[1].lower()

                # 预筛选
                if ext not in allowed_ext:
                    skipped += 1
                    continue
                if fn.startswith("~$") or fn.endswith(".tmp"):
                    skipped += 1
                    continue
                try:
                    size = os.path.getsize(full)
                except OSError:
                    skipped += 1
                    continue
                if size < min_size:
                    await CollectService.quarantine(full, "TOO_SMALL")
                    quarantined += 1
                    continue
                if size > max_size:
                    await CollectService.quarantine(full, "TOO_LARGE")
                    quarantined += 1
                    continue

                # 稳定性
                if not await CollectService.is_file_stable(full):
                    skipped += 1
                    continue

                # SHA-256 + 登记
                sha = await asyncio.to_thread(
                    CollectService.compute_sha256, full)
                result = await CollectService.register_file(
                    _build_internal_register(full, fn, size, sha))
                if result["is_duplicate"]:
                    duplicated += 1
                else:
                    collected += 1
                    from app.tasks.m12_tasks import archive_file_task
                    archive_file_task.apply_async(
                        args=[result["file_id"]], countdown=300)

        logger.info(
            "全量扫描完成 scanned=%d collected=%d duplicated=%d "
            "quarantined=%d skipped=%d",
            scanned, collected, duplicated, quarantined, skipped,
            extra={"module": "M12-03", "action": "FULL_SCAN"})

        return {"scanned": scanned, "collected": collected,
                "duplicated": duplicated, "quarantined": quarantined,
                "skipped": skipped}

def _parse_dt(s: str) -> datetime:
    """解析 ISO 时间字符串。"""

def _build_internal_register(full: str, fn: str, size: int, sha: str):
    """构造内部登记请求。"""
    from types import SimpleNamespace
    return SimpleNamespace(
        source="AUTO_SCAN",
        original_path=full,
        file_name=fn,
        size_bytes=size,
        sha256=sha,
        file_mtime=datetime.fromtimestamp(os.path.getmtime(full)).isoformat(),
        device_code=_guess_device(full),
        operator_id=None,

def _guess_device(path: str) -> str:
    """从路径推断设备编码（INBOX\\OCT\\xxx.pdf）。"""
    parts = Path(path).parts
    for p in parts:
        if p.startswith("OCT") or p.startswith("CAM") or \
                p.startswith("VF") or p.startswith("TON") or \
                p.startswith("UBM"):
            return p
    return None
```

**为什么 `register_file` 是唯一入口？**

因为自动扫描和手工上传两条路径如果各写一套逻辑，必然出现不一致（一边做了稳定性判定另一边没做、一边算 SHA 另一边没算）。统一入口后：

1. 所有检查只写一次
2. 测试只需要测一个函数
3. 未来新增采集源（比如邮件附件）也只是多一个调用方

### 6.7 文件巡检算法

```python
"""M12-03 文件巡检 —— 核心算法。"""


class InspectionService:
    """文件巡检服务。"""

    @staticmethod
    async def run(body, triggered_by: str = "SCHEDULE") -> dict:
        """执行一次巡检。"""
        db = get_session()
        cfg = await CollectConfigService.get_dict()

        now = datetime.now()
        recent_cutoff = now - timedelta(days=30)
        mid_cutoff = now - timedelta(days=180)

        # 1. 按时间段抽样
        samples = []
        buckets = [
            ("RECENT", recent_cutoff, now, body.sample_ratio_recent),
            ("MID", mid_cutoff, recent_cutoff, body.sample_ratio_mid),
            ("OLD", None, mid_cutoff, body.sample_ratio_old),
        ]

        for bucket_name, dt_from, dt_to, ratio in buckets:
            conds = [M12ReportFile.is_deleted.is_(False),
                     M12ReportFile.archive_status == "ARCHIVED"]
            if dt_from:
                conds.append(M12ReportFile.collected_at >= dt_from)
            if dt_to:
                conds.append(M12ReportFile.collected_at < dt_to)

            total = await db.scalar(
                select(func.count()).select_from(M12ReportFile).where(*conds)
            ) or 0
            limit = max(1, int(total * ratio))
            if bucket_name == "RECENT" and limit < body.min_sample:
                limit = min(total, body.min_sample)

            rows = (await db.scalars(
                select(M12ReportFile).where(*conds)
                .order_by(func.random()).limit(limit)
            )).all()
            for r in rows:
                samples.append((bucket_name, r))

        # 2. 逐个校验
        results = []
        missing = []
        corrupted = []
        for bucket_name, rec in samples:
            path = rec.current_path
            if not os.path.exists(path):
                missing.append(rec)
                results.append((bucket_name, rec, "MISSING"))
                continue

            sha = await asyncio.to_thread(
                CollectService.compute_sha256, path)
            if sha != rec.sha256:
                corrupted.append(rec)
                results.append((bucket_name, rec, "CORRUPTED"))
                logger.error(
                    "文件内容变更 file_id=%d path=%s 期望=%s 实际=%s",
                    rec.id, path, rec.sha256[:16], sha[:16],
                    extra={"module": "M12-03",
                           "action": "FILE_CORRUPTED"})
                continue

            results.append((bucket_name, rec, "OK"))

        # 3. 落库
        report = M12Inspection(
            inspection_no=await next_inspection_no(db),
            inspection_date=date.today(),
            sample_total=len(samples),
            sample_ok=len([x for x in results if x[2] == "OK"]),
            sample_missing=len(missing),
            sample_corrupted=len(corrupted),
            missing_rate=round(len(missing) / len(samples), 6)
                         if samples else 0.0,
            started_at=now,
            finished_at=datetime.now(),
            triggered_by=triggered_by,
            status="FINISHED",
            created_at=now,
        )
        db.add(report)
        await db.flush()

        for bucket_name, rec, result in results:
            if result == "OK":
                continue
            db.add(M12InspectionDetail(
                inspection_id=report.id,
                file_id=rec.id,
                file_name=rec.file_name,
                file_path=rec.current_path,
                sha256=rec.sha256,
                bucket=bucket_name,
                result=result,
                task_no=rec.task_no,
                created_at=now,
            ))

        # 4. 更新文件校验时间
        for bucket_name, rec, result in results:
            if result == "OK":
                rec.last_verify_at = now
                rec.verify_count = (rec.verify_count or 0) + 1
            elif result == "MISSING":
                rec.is_missing = True
                rec.missing_found_at = now

        await db.commit()

        # 5. 告警
        if missing or corrupted:
            logger.error(
                "巡检发现文件异常 missing=%d corrupted=%d",
                len(missing), len(corrupted),
                extra={"module": "M12-03", "action": "INSPECTION_ALERT"})
            await InspectionService._alert(report, missing, corrupted)

        return {
            "inspection_id": report.id,
            "sample_total": report.sample_total,
            "sample_ok": report.sample_ok,
            "sample_missing": report.sample_missing,
            "sample_corrupted": report.sample_corrupted,
            "missing_rate": float(report.missing_rate),
        }
```

**为什么抽样而不是全量校验？**

全量校验要读 12 万份文件（约 1.5TB），按 200MB/s 算需要 2 小时以上，且会给共享盘造成巨大压力。抽样 320 份（约 4GB）只需约 20 秒。

而抽样的统计意义是足够的：如果丢失率 0.1%，抽 320 份有约 27% 的概率发现；丢失率 1%，抽 320 份几乎必然发现（概率 96%）。配合"丢失率持续监控"，连续多天抽查能可靠发现问题。

### 7.3 watchdog 文件监听

```python
"""M12-03 文件监听（watchdog inotify）。"""
import asyncio
import logging
import threading
import time
from collections import defaultdict

from watchdog.events import FileSystemEventHandler
from watchdog.observers import Observer

logger = logging.getLogger(__name__)

# 防抖：同一路径 5 秒内只处理一次
_DEBOUNCE_SECONDS = 5
_seen = defaultdict(float)


class InboxHandler(FileSystemEventHandler):
    """INBOX 目录事件处理。"""

    def __init__(self, loop):
        self.loop = loop

    def on_created(self, event):
        if event.is_directory:
            return
        self._handle(event.src_path, "created")

    def on_moved(self, event):
        if event.is_directory:
            return
        self._handle(event.dest_path, "moved")

    def on_modified(self, event):
        if event.is_directory:
            return
        # modified 事件告警，但不立即处理（等 created 或扫描）
        logger.debug("文件修改 event=%s", event.src_path)

    def _handle(self, path: str, trigger: str):
        now = time.time()
        if now - _seen.get(path, 0) < _DEBOUNCE_SECONDS:
            logger.debug("防抖跳过 path=%s", path)
            return
        _seen[path] = now

        logger.info("监听到文件 %s trigger=%s", path, trigger,
                    extra={"module": "M12-03", "action": "FILE_DETECTED"})
        # 交给 Celery 处理（不阻塞监听线程）
        from app.tasks.m12_tasks import collect_single_file_task
        collect_single_file_task.delay(path)


class InboxWatcher:
    """INBOX 目录监听器（单例，由 FastAPI lifespan 启停）。"""

    _instance = None
    _observer = None

    @classmethod
    def start(cls, path: str):
        if cls._observer is not None:
            logger.warning("监听器已启动，跳过")
            return
        loop = asyncio.get_event_loop()
        handler = InboxHandler(loop)
        cls._observer = Observer()
        cls._observer.schedule(handler, path, recursive=True)
        cls._observer.start()
        logger.info("INBOX 监听已启动 path=%s", path)

    @classmethod
    def stop(cls):
        if cls._observer:
            cls._observer.stop()
            cls._observer.join(timeout=5)
            cls._observer = None
            logger.info("INBOX 监听已停止")
```

**为什么 watchdog 之外还要定时全量扫描？**

因为 inotify 有已知的不可靠场景：

| 场景 | 原因 |
|---|---|
| 服务重启期间的变更 | 监听器没起来，事件丢失 |
| 网络盘（SMB/NFS） | inotify 对网络文件系统支持有限，可能不触发 |
| 事件队列溢出 | 短时间大量文件，内核队列溢出 |
| 归档目录被手工挪动 | 文件重新出现在 INBOX |

所以必须有定时扫描兜底。两个机制互补：

- **watchdog**：实时，延迟 5 秒内
- **定时扫描**：每 5 分钟，覆盖所有遗漏

**代价是什么？**

全量扫描会给共享盘造成读压力。实测 1 万个文件约 30 秒，平均 IO 很低（主要是 `stat` 调用）。**更关键的是要防止重复处理**：`register_file` 的 SHA-256 去重保证了同一文件不会被登记两次。

```python
def safe_join(root: str, *paths) -> str:
    """安全拼接路径，防止 ../ 跳出根目录。"""
    root_abs = os.path.abspath(root)
    target = os.path.abspath(os.path.join(root_abs, *paths))
    if not target.startswith(root_abs + os.sep) and target != root_abs:
        raise BizException("1203015", "文件路径含非法字符")
    return target
```

```python
                 extra={"module": "M12-03",
                        "action": "SHARE_UNAVAILABLE"})
```
