## 1. 模块概述

### 1.1 模块定位

M12-05 负责把 M12-04 解析出来的"结构化数据"变成"医生可以据以决策的正式医疗文书"。

一句话概括：**M12-05 决定这份报告能不能发、发了之后出事了谁负责、以及出了危急值几分钟内必须让医生知道。**

```
│  parse_record: PARSED + BOUND + is_confirmed=TRUE                    │
└───────────────────────────────┬──────────────────────────────────────┘

                                ▼
                ┌───────────────────────────────┐
                │   M12-05 报告审核与发布        │
                │                               │
                │  ┌─────────────────────────┐  │
                │  │ ① 危急值规则判定          │  │
                │  │   md_exam_critical_rule  │  │
                │  │   → CRITICAL / WARNING   │  │
                │  └───────────┬─────────────┘  │

                │  │ ② 报告审核              │  │
```

### 1.2 为什么独立成子模块

**理由一：审核是法定责任，不是技术流程。**

《医疗机构病历管理规定》《医学影像检查报告书写规范》都要求检查报告"经审核医师签名后生效"。这个"签名生效"的动作有明确的法律后果：报告一旦发布，就是医疗文书，出问题要承担责任。

M12-04 是技术加工（把图片变成数字），M12-05 是法律责任承担（签字确认这份报告可以给医生看）。两者混在一起，会出现"系统自动发布的报告谁负责"这种无法回答的问题。

**理由二：危急值处置的时效要求与解析完全不在一个量级。**

| 维度 | M12-04 解析 | M12-05 危急值 |
|---|---|---|
| 时效要求 | 无硬性要求（10 分钟内解析完即可） | **发现后 15 分钟内医生必须确认** |
| 失败后果 | 报告晚一点到，医生多等一会 | **患者失明风险** |
| 升级机制 | 无 | 15 分钟未确认 → 30 分钟 → 医务科 |
| 记录要求 | 解析日志 | 法规要求的危急值登记本（可追溯 3 年） |

危急值闭环要求"发现—通知—确认—处置"四个环节逐个留痕，这在解析模块里是无法承载的。

**理由三：报告需要"可修改、可重发、可撤回"，这是一套独立的生命周期。**

真实的检查报告经常要改：
- 审核医师发现测量值抄错了
- 医生反馈图像质量不合格需要重做
- 上级医师复核要求修改诊断意见

每一次修改都要保留旧版本、通知已读的医生、留痕。"版本管理 + 推送补偿 + 撤回通知"是完整的一套机制，塞进解析模块会让解析模块的职责彻底模糊。

**理由四：审核质量数据是科室管理的核心指标。**

检查科主任每月要看：审核及时率、报告修改率、危急值发生数、危急值处置及时率、退回重做数。这些指标全都来自审核环节，需要独立的审核记录表来支撑。

### 1.4 概念辨析

**审核 ≠ 复核 ≠ 质控**

| 概念 | 谁做 | 做什么 | 记录在哪 |
|---|---|---|---|
| 审核 | 检查科医师 | 判断报告数据是否准确、结论是否合理，签字负责 | M12-05 `m12_report_review` |
| 复核 | 技师（M12-02） | 判断检查图像质量是否合格、是否需重做 | M12-02 `m12_exam_task` |
| 质控 | 质控科 | 事后抽查报告质量，统计差错误 | M12-05 审核质量分析 + M22 报表 |

**发布 ≠ 推送**

- **发布（PUBLISH）**：报告在 M12 内部变为"已生效"状态，可被查询。这是一个本地状态变更。
- **推送（PUSH）**：调用 M07-04 接口，把报告送到医生工作站。这是一个跨模块调用，可能失败。

发布成功但推送失败是常态（网络抖动、M07-04 重启），必须分开记录、分开重试。

**危急值 ≠ 异常值**

| 概念 | 定义 | 举例 |
|---|---|---|
| 异常值 | 超出参考区间 | 眼压 22 mmHg（参考 10~21） |
| 危急值 | 超出参考区间**且可能立即危及健康**，必须立刻通知 | 眼压 55 mmHg（急性闭角型青光眼发作前兆） |

异常值只影响报告的区间标记（红色箭头），危急值会触发整个通知闭环。

**报告修改 ≠ 报告重发**

- **修改（MODIFY）**：内容变了，需要新版报告，已读的医生要收到变更通知。
- **重发（REPUBLISH）**：内容没变，只是推送失败了，重试一次即可。

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 报告审核及时率 | ≥ 98% | 审核时限内完成的比例（普通 4 小时，加急 1 小时） |
| 平均审核时长 | ≤ 3 分钟/份 | 从报告进入审核队列到审核完成 |
| 危急值发现率 | 100% | 所有符合规则的报告都必须被识别 |
| 危急值通知到达率 | ≥ 99.5% | 通知成功送达的比例 |
| 危急值 15 分钟确认率 | ≥ 95% | 医生在 15 分钟内确认的比例 |
| 危急值 2 小时闭环率 | ≥ 98% | 处置完成的比例 |
| 报告发布推送成功率 | ≥ 99.9% | 首次推送成功率（失败自动重试） |
| 报告修改率 | ≤ 5% | 审核时发现需修改的报告占比 |
| 报告退回率 | ≤ 1% | 审核不通过退回重做的占比 |
| 报告发布时延 | ≤ 5 分钟 | 审核完成到 M07 可见的 P95 时延 |

## 2. 业务范围与边界

### 2.1 范围内

1. **报告生成**：从 M12-04 解析记录构造正式报告（建档、生成报告号、快照结构化数据）
2. **危急值判定**：按 `md_exam_critical_rule` 规则逐字段判定，产出危急值记录
3. **危急值通知闭环**：通知医生（WebSocket / 站内信 / 短信）→ 跟踪确认 → 跟踪处置 → 超时升级
4. **报告审核**：审核队列、审核详情、审核结论（通过/修改/退回）、审核意见
5. **报告发布**：发布状态流转、发布记录、推送 M07-04、推送失败重试
6. **报告版本管理**：修改生成新版本、旧版本保留、变更通知已读医生
7. **报告撤回**：错误发布的报告可撤回（撤回后 M07 不可见）
8. **审核质量分析**：审核及时率、修改率、退回率、危急值统计、医师工作量

### 2.2 范围外

| 功能 | 归属 | 说明 |
|---|---|---|
| PDF 文件采集、归档 | M12-03 | M12-05 只读 `file_id`，可调 `/content` 取原件 |
| OCR、字段抽取、患者绑定 | M12-04 | M12-05 消费其解析结果 |
| 检查执行的图像质量判定 | M12-02 | 技师在 M12-02 做复核 |
| 危急值规则主数据的维护 | M01-09 | `md_exam_critical_rule` 由主数据模块维护 |
| 报告在医生端的展示、查看、处置 | M07-04 | M12-05 只负责推送 |
| 检查申请、预约、执行 | M12-01 / M12-02 | |
| 设备资质、OCR 模板维护 | M12-06 | 模板是技术配置，本研究是业务规则 |
| 报告打印排版 | M12-05 | ✅ 范围内（发布后可打印正式报告） |
| 检查收入核算 | M16 / M17 | |

### 2.4 依赖清单

| 上游 | 接口 | 超时 | 失败影响 | 降级策略 |
|---|---|---|---|---|
| M12-04 | `GET /internal/v1/m12/parse/{id}` | 2s | **阻断**（无解析结果无法建档） | 无（重试） |
| M12-04 | `GET /internal/v1/m12/parse/by-task/{task_id}` | 2s | **阻断** | 无（重试） |
| M12-03 | `GET /internal/v1/m12/collect/files/{id}/content` | 5s | 仅影响预览与打印 | 提示"原件暂不可用"，报告正文仍可看 |
| M12-01 | `GET /api/v1/m12/exec/...` 任务详情 | 2s | 降级（用解析记录冗余的患者信息） | 部分字段显示"未知" |
| M01-09 | `GET /internal/v1/mdm/exam-items/{code}` | 2s | 降级（用缓存） | 本地缓存 1 小时 |
| M01-09 | `GET /internal/v1/mdm/exam-critical-rules/{code}` | 2s | **降级但告警**（无规则 = 无危急值判定） | 缓存 30 分钟，超时记 WARN |
| M01-09 | `GET /internal/v1/mdm/exam-fields/{code}` | 2s | 降级（用解析时的快照） | 本地缓存 1 小时 |
| M01-02 | `GET /internal/v1/employee/{id}/qualification` | 2s | 降级放行并记录（审核资质非实时强校验） | 记录 WARN |
| M07-04 | `POST /internal/v1/m07/reports/on-report-ready` | 5s | **不阻断发布**，进重试队列 | 指数退避重试 10 次 |
| M07-04 | `POST /internal/v1/m07/reports/on-critical-value` | 3s | **不阻断**，但进紧急重试 | 每 1 分钟重试，告警 |
| M03-05 | `POST /internal/v1/message/send` | 3s | 不阻断（其他通道兜底） | 记 WARN |
| M02-06 | `POST /internal/v1/audit/record` | 1s | 不阻断（本地缓冲补录） | 本地 outbox |

**关键设计判断：M12-05 只对"建档必需数据"阻断，对一切通知类动作都不阻断。**

理由：报告审核完成的这一刻，医生能不能看到是"效率问题"，报告本身是否完整是"正确性问题"。如果因为短信发不出去就不让审核通过，医生连报告都看不到，比"没收到短信"严重得多。

## 3. 业务模型

### 3.1 审核状态机

```
                     解析完成（PARSED + BOUND）
                              │
                              ▼
                   ┌────────────────────┐
                   │      PENDING       │ ◄──────┐
                   │   （待审核）        │        │
                   └─────────┬──────────┘        │
                             │ 审核医师打开        │
                             ▼                   │
                   ┌────────────────────┐        │
                   │     REVIEWING      │        │
                   │   （审核中）        │        │
                   └──┬──────┬───────┬──┘        │
                      │      │       │           │
             通过     │      │修改   │退回        │
                      ▼      ▼       ▼           │
        ┌──────────┐ ┌──────────┐ ┌──────────┐   │
        │ PUBLISHED│ │ PUBLISHED│ │ REJECTED │   │
        │（已发布） │ │（已发布） │ │（已退回） │   │
        └────┬─────┘ │ v2       │ └────┬─────┘   │
             │       └──────────┘      │         │
             │ 撤回                    │ 重做后  │
             ▼                         └─────────┘
        ┌──────────┐
        │WITHDRAWN │
        │（已撤回） │
        └──────────┘
```

**状态说明：**

| 状态 | 说明 | 可否操作 |
|---|---|---|
| `PENDING` | 报告已建档，等待审核医师 | 可审核 |
| `REVIEWING` | 审核医师已认领 | 仅认领人可操作 |
| `PUBLISHED` | 审核通过，已发布，已推送 M07 | 可撤回、可修改 |
| `REJECTED` | 审核不通过，退回技师重做 | 不可操作，等新报告 |
| `WITHDRAWN` | 已发布的报告被撤回 | 不可再操作 |

**设计要点：**

1. **为什么要有 `REVIEWING` 而不直接 PENDING → PUBLISHED？**

   审核一份报告通常 1~3 分钟。两个医师同时打开同一份会各自填意见，最后谁赢？`REVIEWING` 是认领标记，实现 `UPDATE ... SET status='REVIEWING', reviewer_id=? WHERE id=? AND status='PENDING'`，`rowcount=0` 表示已被他人认领。

   这与 M12-04 待确认队列的 `HANDLING` 是同一模式。

2. **为什么 `REJECTED` 是终态而不是回到 `PENDING`？**

   因为退回意味着"这份报告不能用"，技师要重新做检查或重新导出 PDF。重做之后产生的是**新文件、新解析、新报告**，不是同一份报告重新排队。

   保留 `REJECTED` 终态才能统计"退回率"，这对科室管理是关键指标（退回率突然升高说明设备或技师有问题）。

3. **为什么 `WITHDRAWN` 而不是直接删除？**

   已发布的报告可能已被医生看过。删除记录会让"医生看的那份报告去哪了"无法回答。撤回是"标记失效 + 通知医生"，记录永久保留。

4. **一份报告多版本时的状态：**

   修改生成 v2 后，v1 状态变为 `SUPERSEDED`（被取代），v2 为 `PUBLISHED`。只有最新版本对医生可见，历史版本供追溯。

### 3.2 审核结论模型

**三种结论：**

| 结论 | 含义 | 后续动作 | 报告内容 |
|---|---|---|---|
| `PASS` 通过 | 数据准确、结论合理 | 直接发布 | 不修改 |
| `MODIFY` 修改后通过 | 发现小错误（数值笔误、错别字） | 修改后发布 | 修改后内容 |
| `REJECT` 退回 | 数据不可信或图像质量差 | 退回技师重做 | 不发布 |

**判定矩阵：**

| 情形 | 结论 | 说明 |
|---|---|---|
| 数据与图像一致，结论合理 | `PASS` | 最常见，约 90% |
| 测量值与图像明显不符 | `MODIFY` | 医师手动改字段值 |
| 结论用词不准确 | `MODIFY` | 医师改结论文本 |
| 患者姓名/眼别错误（绑定错误） | `REJECT` | **必须退回**，说明绑定失败 |
| 图像模糊无法判读 | `REJECT` | 退回重做检查 |
| 关键字段缺失且无法补 | `REJECT` | 退回重新导出 |

**审核意见必填规则：**

| 结论 | 审核意见 | 说明 |
|---|---|---|
| `PASS` | **可选**（但建议填写） | 大量正常报告强制填写会让医师敷衍填"同意" |
| `MODIFY` | **必填，≥10 字** | 必须说明改了什么、为什么改 |
| `REJECT` | **必填，≥20 字** | 必须说明退回原因，技师据此处理 |

**设计要点：为什么 PASS 不强制填意见？**

真实场景：一位医师一天看 60 份报告，其中 54 份正常。如果每份都要写≥10 字意见，实际结果必然是 54 个"同意"或"报告正常"——既没有信息量，又浪费 5 分钟。

法规要求的是"审核医师签字负责"，签字本身就是负责的表示。真正需要详细说明的是**改了什么的**和**为什么退回的**，这两种强制填写才有意义。

### 3.3 危急值识别模型

**规则来源：** M01-09 `md_exam_critical_rule`

| 字段 | 说明 | 示例 |
|---|---|---|
| `exam_code` | 检查项目编码 | `EXAM_OCT_MACULA` |
| `rule_code` | 规则编码 | `CR_OCT_CMT` |
| `rule_name` | 规则名称 | 黄斑中心厚度过高 |
| `field_code` | 关联结构化字段 | `CMT` |
| `indicator_name` | 判定指标名称 | 黄斑中心厚度 |
| `indicator_unit` | 单位 | μm |
| `operator` | 比较符 | `GT` / `LT` / `GTE` / `LTE` / `BETWEEN` / `OUTSIDE` |
| `threshold_min` | 阈值下限 | NULL |
| `threshold_max` | 阈值上限 | 400 |
| `critical_level` | 级别 | `CRITICAL` / `WARNING` |
| `notify_roles` | 通知角色 | `DOCTOR,HEAD_NURSE` |
| `notify_channels` | 通知方式 | `SMS,INBOX` |
| `handle_sla_minutes` | 处置时限 | 60 |
| `handle_requirement` | 处置要求 | 立即联系患者复诊 |

**判定算法：**

```
对每个 rule in rules(exam_code):
    field = parse_fields[rule.field_code]
    if field is None or field.numeric_value is None:
        continue                     # 字段缺失，跳过（不判危急值）
    v = field.numeric_value
    hit = switch rule.operator:
        GT:       v >  rule.threshold_max
        LT:       v <  rule.threshold_min
        GTE:      v >= rule.threshold_max
        LTE:      v <= rule.threshold_min
        BETWEEN:  v >= rule.threshold_min AND v <= rule.threshold_max
        OUTSIDE:  v <  rule.threshold_min OR  v >  rule.threshold_max
    if hit:
        emit CriticalValue(
            rule_code=rule.rule_code,
            value=v,
            unit=rule.indicator_unit,
            severity=rule.critical_level,
            description=format("%s %s %s", rule.indicator_name, op_text, threshold)
        )
```

**边界情形处理：**

| 情形 | 处理 | 理由 |
|---|---|---|
| 字段缺失（未抽到） | 跳过，不判危急值；记 `skipped_rules` | 无法判定不等于"正常"，但也不能凭空报危急值 |
| 字段值为非数值（如 `无法测量`） | 跳过，记 `skipped_rules` | |
| 规则 `operator=GT` 但 `threshold_max` 为 NULL | 规则配置错误，跳过并告警 | 主数据配置问题，应由 M01-09 修正 |
| 同一字段命中多条规则 | 全部产出，按 `critical_level` 排序 | 例如 CMT 同时命中「>400 危重」「>300 警告」，两者都有意义 |
| 无任何规则 | 不判危急值，记 `rules_count=0` | 眼压这类项目必须有规则，无规则说明主数据缺失，需告警 |

**眼科常见危急值规则（参考）：**

| 项目 | 字段 | 规则 | 阈值 | 级别 | 临床意义 |
|---|---|---|---|---|---|
| 眼压 `EXAM_IOP` | IOP | GT | 40 mmHg | CRITICAL | 急性闭角型青光眼发作，需立即降眼压 |
| 眼压 | IOP | GT | 25 mmHg | WARNING | 眼压偏高，需关注 |
| 眼压 | IOP | LT | 5 mmHg | CRITICAL | 眼球破裂或术后低眼压 |
| OCT 黄斑 | CMT | GT | 400 μm | CRITICAL | 重度黄斑水肿 |
| OCT 黄斑 | CMT | GT | 300 μm | WARNING | 黄斑增厚 |
| 视野 | MD | LT | -20 dB | CRITICAL | 重度视野缺损 |
| 视野 | MD | LT | -12 dB | WARNING | 中度视野缺损 |
| 视野 | PSD | GT | 10 dB | WARNING | 视野缺损 |
| 角膜内皮 | ECD | LT | 1000 /mm² | CRITICAL | 角膜失代偿风险高 |
| 角膜内皮 | ECD | LT | 1500 /mm² | WARNING | 内皮细胞减少 |
| 眼轴 | AL | GT | 30 mm | WARNING | 高度近视，视网膜脱离风险 |
| 角膜地形图 | KMAX | GT | 60 D | CRITICAL | 圆锥角膜晚期 |

**设计要点：为什么危急值必须在审核前判定？**

关键点：危急值判定必须在**报告发布前**完成，而不是发布后。

设想：报告先发布，医生可能立刻打开看到。如果危急值通知是异步的、晚 3 分钟到，医生就已经看到了报告，见到"眼压 55"却可能因为没注意到而忽略。

更严重的场景：**审核医师在审核时就应该看到危急值提示**。医师看到"⚠ 眼压 55，超过危急阈值 40"会更加仔细地检查这份报告，这是对审核质量的提升。

所以流程是：建档 → **判定危急值** → 进入审核队列（带危急值标记） → 医师审核（看到危急标记） → 发布 → 推送（含危急值）→ 通知医生。

### 3.4 危急值处置闭环

法规要求（《医疗机构临床实验室管理办法》《三甲医院评审标准》）：

> 危急值出现后，检验/检查人员应立即通知临床科室，临床医护人员接到通知后应在规定时间内确认并处置，全过程必须有完整记录。

**闭环五环节：**

```
① 发现（DETECTED）
   系统自动判定命中规则
   → 记录 critical_value，status='DETECTED'
        │
        ▼
② 通知（NOTIFIED）
   推送 M07（WebSocket + 站内信）+ 短信（危重级别）
   → status='NOTIFIED'，记录 notified_at / channels
        │
        ▼
③ 医生确认（ACKNOWLEDGED）        ◄─── 15 分钟时限
   医生在 M07-04 点"我已确认"
   → M07 回调 POST /internal/v1/m12/critical/{id}/on-acknowledged
   → status='ACKNOWLEDGED'，记录 acknowledged_at / by
        │
        ▼
④ 处置（HANDLED）                 ◄─── 2 小时时限
   医生记录处置措施（联系患者复诊/立即入院/用药）
   → M07 回调 POST /internal/v1/m12/critical/{id}/on-handled
   → status='HANDLED'，记录 handled_at / measure
        │
        ▼
⑤ 闭环（CLOSED）
   医务科或系统在处置后自动置闭环
   → status='CLOSED'，记录 closed_at
```

**超时升级链：**

| 时间点 | 触发动作 | 通知对象 |
|---|---|---|
| 0 分钟 | 通知医生（WebSocket + 站内信） | 申请医师 |
| 危重级别 0 分钟 | 同时发短信 | 申请医师 + 科室主任 |
| 15 分钟未确认 | **一级升级** | 科室主任 |
| 30 分钟未确认 | **二级升级** | 医务科 |
| 60 分钟未确认 | **三级升级** | 医务科 + 分管院长 |
| 2 小时未处置 | 处置超时告警 | 医务科 |
| 24 小时未闭环 | 列入医务科待办清单 | 医务科 |

**状态机：**

```
   DETECTED ──► NOTIFIED ──► ACKNOWLEDGED ──► HANDLED ──► CLOSED
      │            │              │              │
      │            │              │              └─► (24h 未闭环) OVERDUE
      │            │              └─► (15min 未确认) ESCALATED_1
      │            └─► (30min 未确认) ESCALATED_2
      └─► (60min 未确认) ESCALATED_3
```

**设计要点：为什么确认与处置要分开？**

因为两者的时间尺度完全不同：

- **确认（15 分钟）**：医生只需点一下"我已看到"。这个动作的意义是"我知道有这个问题了，不会漏掉"。15 分钟内完成是合理的。
- **处置（2 小时）**：医生需要联系患者（可能患者已离开）、安排复诊、开药、甚至安排急诊手术。2 小时是行业内常见要求。

如果合并成一个"已处理"，医生要么立刻填一堆处置内容（不现实，患者还没联系上），要么就在 15 分钟内点个"已处理"糊弄过去——记录失真，闭环失效。

分开后，"确认"可以立即点（诚实的"我看到了"），"处置"需要真的做了治疗才能填。记录才有价值。

**危急值通知的降级策略：**

| 通道 | 送达时效 | 可靠性 | 用于 |
|---|---|---|---|
| WebSocket | 即时（在线） | 中（需在线） | 第一通道 |
| 站内信（INBOX） | 秒级 | 高（持久化） | 第二通道，医生上线必看到 |
| 短信（SMS） | 秒级 | 高 | CRITICAL 级别强制，WARNING 可选 |
| 电话（人工） | 分钟级 | 最高 | 15 分钟未确认时由护士台人工拨打 |

**设计要点：为什么短信只给 CRITICAL？**

一次眼科检查，WARNING 级危急值（如眼压 26 mmHg）一天可能有 20 例，全部发短信会：
1. 短信费成本（每条 0.05 元，一天 1 元，一年全科 365 元——不算贵）
2. **更要命的是短信疲劳**：医生一天收 20 条"您的患者眼压偏高"，几天后就不看了
3. 真正 CRITICAL（眼压 55、黄斑水肿 500μm）的短信反而被忽略

所以 WARNING 走站内信，医生打开工作站必看到；CRITICAL 走短信 + 电话兜底。

### 3.5 报告发布模型

**发布的前置条件（五项全满足）：**

| 编号 | 条件 | 校验方式 |
|---|---|---|
| C-01 | 审核状态为 `REVIEWING` 且由当前用户认领 | 状态校验 |
| C-02 | 审核结论为 `PASS` 或 `MODIFY` | 结论校验 |
| C-03 | 报告必填字段完整（患者、项目、结论） | 字段校验 |
| C-04 | `MODIFY` 时必须填写修改说明 | 意见校验 |
| C-05 | 审核医师有该项目的审核资质 | 资质校验（降级放行） |

**发布动作序列（七步）：**

```
① 状态校验与乐观锁
   UPDATE m12_report_review
      SET status='PUBLISHED', published_at=NOW()
    WHERE id=? AND status='REVIEWING' AND reviewer_id=?
   → rowcount=0 抛 1205013（已被处理）

② 生成报告版本快照
   把当前 m12_parse_field 的全部字段复制到 m12_report_version
   记录 version_no、snapshot_json

③ 计算危急值（已在建档时完成，此处复用）
   读取 m12_critical_value WHERE report_id=? AND status<>'CLOSED'

④ 写发布记录
   INSERT INTO m12_report_publish (report_id, version_no, action='PUBLISH')

⑤ 推送 M07-04（异步，不阻塞响应）
   push_report_task.delay(report_id, version_no)

⑥ 推送危急值（若存在，异步且紧急）
   for cv in critical_values:
       push_critical_task.delay(cv.id)

⑦ 写审计
   audit(action='REPORT_PUBLISH', ...)
```

**为什么推送要异步？**

同步推送的问题：M07-04 响应慢（P95 200ms，但偶发 5 秒）时，审核医师点了"通过"要等 5 秒才看到反馈。如果审核 60 份，就要等 5 分钟。

异步推送后：点"通过"立刻返回（≤200ms），后台推送。推送成功/失败在 P04 页面显示状态，失败自动重试。

**推送失败的重试策略：**

| 尝试次数 | 间隔 | 累计时间 |
|---|---|---|
| 1 | 立即 | 0 |
| 2 | 10 秒 | 10 秒 |
| 3 | 30 秒 | 40 秒 |
| 4 | 1 分钟 | 1.7 分钟 |
| 5 | 2 分钟 | 3.7 分钟 |
| 6 | 5 分钟 | 8.7 分钟 |
| 7 | 10 分钟 | 18.7 分钟 |
| 8 | 20 分钟 | 38.7 分钟 |
| 9 | 30 分钟 | 68.7 分钟 |
| 10 | 60 分钟 | 128.7 分钟 |

10 次共约 2 小时。仍失败则标记 `PUSH_FAILED` 并告警，运维在 P04 页面手动重推。

**为什么是 2 小时？**

急诊场景下，报告 2 小时没送达医生，医生早已通过电话或直接去检查科问了。继续自动重试的边际价值极低。2 小时后转人工是合理的分界。

### 3.6 报告修改与重发

**两种修改场景：**

| 场景 | 触发人 | 流程 |
|---|---|---|
| 审核时修改 | 审核医师 | 审核页面直接改字段 → 结论 `MODIFY` → 发布 v1（含修改） |
| 发布后修改 | 审核医师/科主任 | 发起"报告修订" → 生成 v2 → 重新审核 → 发布 v2 → 通知已读医生 |

**发布后修改的严格约束：**

| 编号 | 约束 | 理由 |
|---|---|---|
| M-01 | 修改必须填写修订原因（≥20 字） | 医疗文书修改必须留痕 |
| M-02 | 修改后必须重新走审核流程 | 修订稿同样是医疗文书，需签字 |
| M-03 | 原版本不删除，标记 `SUPERSEDED` | 追溯"医生当时看的是哪份" |
| M-04 | 已读该报告的医生收到"报告已更新"通知 | 避免医生基于旧版决策 |
| M-05 | 修改超过 3 次需科主任审批 | 防反复修改的异常情况 |
| M-06 | 报告发布 7 天后不可修改，只能"补充说明" | 时效性：一周后的修改意义有限，且易被质疑 |

**通知已读医生的实现：**

M12-05 不知道哪些医生读过报告（读记录在 M07-04 的 `m07_report_read`）。所以：

1. 调用 `POST /internal/v1/m07/reports/on-report-ready` 时带 `version_no` 和 `is_revision=true`
2. M07-04 收到后：更新报告内容 + 查已读记录 + 给已读医生发"报告已更新"通知

这样职责清晰：**M12-05 只负责"我改了，通知你"，M07-04 负责"通知谁"**。

### 3.7 时效与超时升级

**审核时限（按项目配置）：**

| 项目类型 | `md_exam_item.report_sla_hours` | 说明 |
|---|---|---|
| 普通检查（OCT、视野、眼底照相） | 4 小时 | 当天出报告 |
| 加急检查（急诊） | 1 小时 | |
| 眼压、视力（免审核项目） | 0（不进入审核） | 解析绑定后直接推送 |

**超时升级：**

| 节点 | 动作 |
|---|---|
| 达到 SLA 的 70% | 提醒审核医师（站内信） |
| 达到 SLA 的 100% | 告警 + 通知科主任 |
| 超过 SLA 2 小时 | 通知医务科 |

**免审核项目的判定：**

`md_exam_item.need_review = FALSE` 时，M12-04 解析绑定成功后**直接调用 M12-05 的免审核发布接口**，不进入审核队列。

适用项目：眼压 `EXAM_IOP`、视力 `EXAM_VA`、验光 `EXAM_REFRACTION`、电脑验光。

**为什么这些可以免审核？**

| 项目 | 数据形态 | 为什么可以免审 |
|---|---|---|
| 眼压 | 单个数值 `18 mmHg` | 无主观判断，设备直接读数；医生看到数值即可决策，不需要医师"解读" |
| 视力 | `1.0 / 0.8` | 同上 |
| 验光 | 球镜/柱镜/轴位 | 同上 |

这三个项目占眼科检查量的 **60% 以上**。如果都要审核，检查科医师每天要审 250 份纯数字报告，而审核动作本身没有任何价值（就是看数字对不对，而数字本来就来自设备）。免审核后医师可以集中精力审 OCT、视野这些真正需要解读的报告。

**但免审核不等于无质量把关：**

| 措施 | 说明 |
|---|---|
| 危急值照常判定 | 眼压 55 依然触发危急值闭环 |
| 抽查机制 | 质控科每周抽查 5% 的免审核报告 |
| 异常提示 | 数值远超参考区间时在报告上标红 |
| 可追溯 | 谁做检查、什么时间、设备编号全部留痕 |

强制单份打开，医师至少会看到红色的危急值横幅。这是用交互流程强制专业审慎。

**为什么要把 PDF 原件和结构化数据并排显示？**

审核的核心动作是"核对数据与图像是否一致"。如果只看结构化数据，医师无法判断"这个 486μm 是不是真的"；如果只看 PDF，医师要肉眼从报告上读数字再和系统里的比。

并排显示让这个动作从"读 PDF → 记数字 → 找系统里对应的 → 比较"变成"扫一眼两边"。时间从 15 秒降到 3 秒。

**为什么要把解析质量（模板、置信度、绑定方式）显示给医师？**

这是给医师一个"数据可信度"的提示：

- 模板 `TONOMETRY_V2` + 置信度 0.98 + 绑定方式时间窗（0.95）→ 数据可信，快速通过
- 模板 `GENERIC_V1`（兜底）+ 置信度 0.72 + 绑定方式人工 → 数据可疑，仔细核对

没有这个提示，医师对每份报告花费同样的注意力，既慢又抓不住重点。

**为什么推送失败要人工介入而不是无限自动重试？**

自动重试 10 次（约 2 小时）后转人工。此时失败的根因通常不是网络抖动，而是：
- M07-04 接口契约变了（返回 400，重试多少次都一样）
- 该患者记录在 M07 不存在（数据问题）
- 报告字段超长导致 M07 拒收

这些情况下的"重推"需要人先看错误信息，判断是代码问题还是数据问题，然后决定是修数据还是提 bug。无限重试只是掩盖问题。

**改进建议的生成规则：**

| 触发条件 | 建议文本 |
|---|---|
| 修改原因 Top1 为"测量值笔误"且占比 >30% | 建议核对 {设备} 的 {模板} 字段映射 |
| 退回原因中"绑定患者错误"占比 >15% | 建议检查 {设备} 的投递凭条使用率 |
| 某医师及时率 < 科室均值 - 10% | 建议了解是否存在排班冲突 |
| 某医师退回率 > 3% | 建议复核其审核标准 |
| 危急值 15 分钟确认率 < 90% | 建议加强危急值制度培训 |
| 某模板导致退回 > 5 次/周 | 建议重新回归测试该模板 |

**为什么改进建议要用规则式而不是 AI 生成？**

因为这是要发给科主任做管理决策的东西，说错话的代价高。规则式建议的每一条都可以追溯到一个具体数据（"修改原因 Top1 是测量值笔误 42%"），管理者能验证、能反驳、能据此行动。

AI 生成的建议可能流畅但空洞（"建议加强培训"），也可能是错的。

### 6.6 Service 层核心逻辑

```python
"""M12-05 报告审核与发布 —— Service 层。"""
import asyncio
import logging
from datetime import datetime, timedelta
from decimal import Decimal
from typing import Any, Dict, List, Optional

from sqlalchemy import func, select, text
from sqlalchemy.ext.asyncio import AsyncSession

from app.clients.m07_client import M07Client
from app.clients.m09_client import M09Client
from app.clients.m12_client import M12Client
from app.clients.m03_client import M03Client
from app.core.cache import redis_client
from app.core.exceptions import BizException
from app.core.seq import next_no
from app.db.session import get_session
from app.models.m12_review import (
    M12CriticalValue,
    M12ReportPublish,
    M12ReportReview,
    M12ReportVersion,
    M12ReviewLog,
)
from app.services.m12.critical_rule_engine import CriticalRuleEngine
from app.tasks.m12_review_tasks import push_critical_task, push_report_task

logger = logging.getLogger("m12.review")

APPROVAL_CODES = ("PASS", "MODIFY")


class ReviewService:
    """报告审核服务。"""

    TABLE_TRANSITIONS = {
        "PENDING": ("REVIEWING",),
        "REVIEWING": ("PUBLISHED", "REJECTED"),
        "PUBLISHED": ("WITHDRAWN", "SUPERSEDED"),
    }

    # ---------- 建档 ----------

    @classmethod
    async def create_from_parse(cls, payload: Dict[str, Any]) -> Dict[str, Any]:
        """M12-04 解析完成后建档。"""
        parse_id = int(payload["parse_id"])
        async with get_session() as db:
            # ① 幂等：同一解析记录只建一份报告
            exist = await db.scalar(
                select(M12ReportReview).where(
                    M12ReportReview.parse_id == parse_id,
                    M12ReportReview.is_deleted.is_(False)))
            if exist is not None:
                return {
                    "review_id": exist.id,
                    "report_no": exist.report_no,
                    "is_duplicate": True,
                    "need_review": exist.need_review,
                    "message": "报告已建档",
                }

            # ② 校验解析记录
            parse = await M12Client.get_parse(parse_id)
            if parse is None:
                raise BizException("1205032", "解析记录不存在或未完成")
            if parse["parse_status"] != "PARSED":
                raise BizException("1205032", "解析记录未完成")
            if parse["bind_status"] != "BOUND":
                raise BizException("1205033", "解析记录未绑定患者")

            # ③ 取检查项目，判断是否需审核
            exam = await M09Client.get_exam_item(parse["exam_code"] or "")
            need_review = bool(exam.get("need_review", True))

            # ④ 生成报告号
            report_no = await next_no(db, "RPT", "seq_m12_report_no")

            # ⑤ 建档
            review = M12ReportReview(
                report_no=report_no,
                parse_id=parse_id,
                file_id=parse["file_id"],
                task_id=parse["bound_task_id"],
                patient_id=payload.get("patient_id"),
                patient_name=parse.get("patient_name"),
                patient_gender=parse.get("patient_gender"),
                patient_age=parse.get("patient_age"),
                exam_code=parse.get("exam_code"),
                exam_name=exam.get("exam_name"),
                eye_side=parse.get("eye_side"),
                device_code=parse.get("device_code"),
                conclusion=parse.get("conclusion"),
                is_scanned=parse.get("is_scanned", False),
                extract_mode=parse.get("extract_mode"),
                template_code=parse.get("template_code"),
                overall_confidence=parse.get("overall_confidence"),
                need_review=need_review,
                status="PENDING" if need_review else "PUBLISHED",
                version_no=1,
                sla_deadline_at=cls._calc_sla(need_review),
            )
            db.add(review)
            await db.flush()

            # ⑥ 快照字段
            await cls._snapshot_fields(db, review, parse)

            # ⑦ 危急值判定
            criticals = await CriticalRuleEngine.evaluate(db, review, parse)

            await db.commit()

        # ⑧ 免审核的直接发布
        if not need_review:
            await cls._exempt_publish(review.id)
        else:
            await cls._enqueue(review)

        return {
            "review_id": review.id,
            "report_no": report_no,
            "is_duplicate": False,
            "need_review": need_review,
            "critical_count": len(criticals),
            "message": "报告已建档",
        }

    @classmethod
    def _calc_sla(cls, need_review: bool) -> Optional[datetime]:
        """计算审核时限（分钟数从配置读取）。"""
        if not need_review:
            return None
        hours = 4
        return datetime.now() + timedelta(hours=hours)

    @classmethod
    async def _snapshot_fields(cls, db, review, parse) -> None:
        """把解析字段复制到版本快照。"""
        snapshot = []
        for f in parse.get("fields", []):
            snapshot.append({
                "field_code": f.get("field_code"),
                "field_name": f.get("field_name"),
                "value": f.get("value"),
                "unit": f.get("unit"),
                "ref_min": f.get("ref_min"),
                "ref_max": f.get("ref_max"),
                "confidence": f.get("confidence"),
                "is_critical": f.get("is_critical", False),
            })
        db.add(M12ReportVersion(
            review_id=review.id,
            version_no=1,
            snapshot_json={"fields": snapshot},
            conclusion=review.conclusion,
            created_by=None,
        ))

    # ---------- 认领与释放 ----------

    @classmethod
    async def claim(cls, review_id: int, user) -> Dict[str, Any]:
        """认领报告。"""
        async with get_session() as db:
            result = await db.execute(
                text("""
                    UPDATE m12_report_review
                       SET status = 'REVIEWING',
                           reviewer_id = :uid,
                           reviewer_name = :uname,
                           claimed_at = NOW()
                     WHERE id = :rid
                       AND status = 'PENDING'
                       AND is_deleted = FALSE
                """),
                {"rid": review_id, "uid": user.employee_id,
                 "uname": user.name},
            )
            if result.rowcount == 0:
                row = await db.get(M12ReportReview, review_id)
                if row is None:
                    raise BizException("1205001", "报告不存在或已删除")
                if row.reviewer_id == user.employee_id:
                    return {"review_id": review_id, "status": row.status,
                            "already_claimed": True}
                raise BizException(
                    "1205008",
                    "报告已被 %s 认领" % (row.reviewer_name or "他人"))
            await db.commit()
        return {"review_id": review_id, "status": "REVIEWING",
                "already_claimed": False}

    @classmethod
    async def release(cls, review_id: int, user) -> Dict[str, Any]:
        """释放报告回待审核。"""
        async with get_session() as db:
            result = await db.execute(
                text("""
                    UPDATE m12_report_review
                       SET status = 'PENDING',
                           reviewer_id = NULL,
                           reviewer_name = NULL,
                           claimed_at = NULL
                     WHERE id = :rid
                       AND status = 'REVIEWING'
                       AND reviewer_id = :uid
                       AND is_deleted = FALSE
                """),
                {"rid": review_id, "uid": user.employee_id},
            )
            await db.commit()
            if result.rowcount == 0:
                raise BizException("1205002", "报告状态不允许此操作")
        return {"review_id": review_id, "status": "PENDING"}

    @classmethod
    async def assign(cls, review_id: int, reviewer_id: int,
                     user) -> Dict[str, Any]:
        """科主任分配报告。"""
        async with get_session() as db:
            employee = await M09Client.get_employee(reviewer_id)
            await db.execute(
                text("""
                    UPDATE m12_report_review
                       SET reviewer_id = :rid_,
                           reviewer_name = :rname,
                           assigned_at = NOW(),
                           assigned_by = :aid
                     WHERE id = :id AND status IN ('PENDING','REVIEWING')
                """),
                {"id": review_id, "rid_": reviewer_id,
                 "rname": employee.get("name"),
                 "aid": user.employee_id},
            )
            await db.commit()
        return {"review_id": review_id, "reviewer_id": reviewer_id}

    # ---------- 审核提交 ----------

    @classmethod
    async def submit(cls, review_id: int, payload, user,
                     client_ip: str) -> Dict[str, Any]:
        """提交审核结论。"""
        conclusion = payload.conclusion
        cls._validate_submit(payload)

        async with get_session() as db:
            review = await db.get(M12ReportReview, review_id,
                                  with_for_update=True)
            if review is None or review.is_deleted:
                raise BizException("1205001", "报告不存在或已删除")
            if review.status != "REVIEWING":
                raise BizException("1205002", "报告状态不允许此操作")
            if review.reviewer_id != user.employee_id:
                raise BizException("1205008", "报告已被他人认领")

            # ① 关键字段未确认校验
            unconfirmed = await db.scalar(text("""
                SELECT COUNT(*) FROM m12_review_field
                 WHERE review_id = :rid
                   AND is_critical = TRUE
                   AND is_confirmed = FALSE
                   AND is_deleted = FALSE
            """).bindparams(rid=review_id))
            if conclusion in APPROVAL_CODES and unconfirmed:
                raise BizException(
                    "1205007",
                    "存在 %d 个未确认的关键字段" % unconfirmed)

            # ② 资质校验（降级放行）
            qualified = await M09Client.check_qualification(
                user.employee_id, review.exam_code)
            if not qualified.get("qualified", True):
                logger.warning(
                    "审核资质不足但放行 review_id=%s uid=%s",
                    review_id, user.employee_id,
                    extra={"module": "M12-05", "action": "SUBMIT"})

            now = datetime.now()
            is_overdue = (review.sla_deadline_at is not None
                          and now > review.sla_deadline_at)

            review.conclusion = conclusion
            review.opinion = payload.opinion
            review.sla_reason = payload.sla_reason
            review.modify_reason = payload.modify_reason
            review.reject_reason = payload.reject_reason
            review.reviewed_at = now
            review.review_seconds = int(
                (now - review.claimed_at).total_seconds()
                if review.claimed_at else 0)
            review.is_overdue = is_overdue

            if conclusion in APPROVAL_CODES:
                review.status = "PUBLISHED"
                review.published_at = now
                publish = await cls._publish(db, review, user, client_ip)
                await db.commit()
                return {
                    "review_id": review.id,
                    "report_no": review.report_no,
                    "version_no": review.version_no,
                    "status": "PUBLISHED",
                    "status_text": "已发布",
                    "published_at": now.isoformat(),
                    "push_task_id": publish["push_task_id"],
                    "critical_count": publish["critical_count"],
                    "critical_notified": publish["critical_notified"],
                    "message": "报告已发布，正在推送至医生工作站",
                }

            # REJECT：退回
            review.status = "REJECTED"
            db.add(M12ReviewLog(
                review_id=review.id,
                action="REJECT",
                operator_id=user.employee_id,
                operator_name=user.name,
                detail_json={"reason": payload.reject_reason},
            ))
            await db.commit()

        return {
            "review_id": review.id,
            "report_no": review.report_no,
            "version_no": review.version_no,
            "status": "REJECTED",
            "status_text": "已退回",
            "published_at": None,
            "push_task_id": None,
            "critical_count": 0,
            "critical_notified": False,
            "message": "报告已退回技师重做",
        }

    @classmethod
    def _validate_submit(cls, payload) -> None:
        """审核提交参数校验。"""
        if payload.conclusion not in ("PASS", "MODIFY", "REJECT"):
            raise BizException("1205003", "必须选择审核结论")
        if not payload.verified:
            raise BizException("1205006", "必须勾选已核对数据与图像")
        opinion = (payload.opinion or "").strip()
        if payload.conclusion == "MODIFY" and len(opinion) < 10:
            raise BizException("1205004",
                               "修改结论时审核意见必填且不少于 10 字")
        if payload.conclusion == "REJECT" and len(opinion) < 20:
            raise BizException("1205005",
                               "退回结论时审核意见不少于 20 字")

    # ---------- 发布 ----------

    @classmethod
    async def _publish(cls, db, review, user, client_ip: str) -> Dict[str, Any]:
        """发布动作：写发布记录 + 派发推送任务。"""
        # ① 取危急值
        criticals = (await db.execute(
            select(M12CriticalValue).where(
                M12CriticalValue.review_id == review.id,
                M12CriticalValue.status != "CLOSED",
                M12CriticalValue.is_deleted.is_(False)))).scalars().all()

        # ② 写发布记录
        publish = M12ReportPublish(
            review_id=review.id,
            report_no=review.report_no,
            version_no=review.version_no,
            action="PUBLISH",
            push_status="PENDING",
            published_at=review.published_at,
            published_by=user.employee_id,
            critical_count=len(criticals),
        )
        db.add(publish)
        await db.flush()

        # ③ 日志
        db.add(M12ReviewLog(
            review_id=review.id,
            action="PUBLISH",
            operator_id=user.employee_id,
            operator_name=user.name,
            client_ip=client_ip,
            detail_json={"conclusion": review.conclusion,
                         "critical_count": len(criticals)},
        ))

        # ④ 异步推送（不阻塞响应）
        push_task_id = "push_%d_%d" % (review.id, review.version_no)
        push_report_task.apply_async(
            args=[review.id, publish.id], task_id=push_task_id)

        # ⑤ 危急值紧急推送
        for c in criticals:
            push_critical_task.delay(c.id)

        return {
            "push_task_id": push_task_id,
            "critical_count": len(criticals),
            "critical_notified": len(criticals) > 0,
        }

    # ---------- 修订 ----------

    @classmethod
    async def revise(cls, review_id: int, payload, user) -> Dict[str, Any]:
        """发起报告修订，生成新版本。"""
        async with get_session() as db:
            review = await db.get(M12ReportReview, review_id,
                                  with_for_update=True)
            if review is None or review.is_deleted:
                raise BizException("1205001", "报告不存在或已删除")
            if review.status not in ("PUBLISHED",):
                raise BizException("1205002", "报告状态不允许此操作")
            if review.status == "WITHDRAWN":
                raise BizException("1205015", "报告已撤回不可修改")

            reason = (payload.reason or "").strip()
            if len(reason) < 20:
                raise BizException("1205010", "修订原因不少于 20 字")

            # 发布超过 7 天不可修改
            if review.published_at and (
                    datetime.now() - review.published_at) > timedelta(days=7):
                raise BizException("1205012", "报告发布超过 7 天不可修改")

            # 修改超过 3 次需科主任审批
            if review.version_no >= 3 and "DEPT_DIRECTOR" not in user.roles:
                raise BizException("1205014", "修改超过 3 次需科主任审批")

            # 必须至少改一处
            if not payload.changes:
                raise BizException("1205011", "修订必须至少修改一处内容")

            # 旧版本标记 SUPERSEDED
            review.status = "SUPERSEDED"
            new_version_no = review.version_no + 1

            new_review = M12ReportReview(
                report_no=review.report_no,
                parse_id=review.parse_id,
                file_id=review.file_id,
                task_id=review.task_id,
                patient_id=review.patient_id,
                patient_name=review.patient_name,
                patient_gender=review.patient_gender,
                patient_age=review.patient_age,
                exam_code=review.exam_code,
                exam_name=review.exam_name,
                eye_side=review.eye_side,
                device_code=review.device_code,
                conclusion=payload.conclusion or review.conclusion,
                need_review=True,
                status="PENDING",
                version_no=new_version_no,
                root_review_id=review.root_review_id or review.id,
                revise_reason=reason,
                sla_deadline_at=datetime.now() + timedelta(hours=4),
            )
            db.add(new_review)
            await db.flush()

            # 快照 v2
            await cls._snapshot_v2(db, new_review, review, payload.changes)

            # 危急值重判
            await CriticalRuleEngine.reevaluate(
                db, new_review, payload.changes)

            db.add(M12ReviewLog(
                review_id=review.id,
                action="REVISE",
                operator_id=user.employee_id,
                operator_name=user.name,
                detail_json={"reason": reason,
                             "new_version": new_version_no},
            ))
            await db.commit()

        return {
            "review_id": new_review.id,
            "report_no": new_review.report_no,
            "version_no": new_version_no,
            "status": "PENDING",
            "root_review_id": new_review.root_review_id,
            "message": "修订已提交，等待审核",
        }

    @classmethod
    async def _snapshot_v2(cls, db, new_review, old_review,
                           changes: Dict[str, Any]) -> None:
        """生成 v2 快照（在旧版本基础上应用变更）。"""
        old_snapshot = await db.scalar(
            select(M12ReportVersion).where(
                M12ReportVersion.review_id == old_review.id,
                M12ReportVersion.version_no == old_review.version_no))
        fields = []
        if old_snapshot and old_snapshot.snapshot_json:
            fields = list(old_snapshot.snapshot_json.get("fields", []))
        for f in fields:
            code = f.get("field_code")
            if code in changes:
                f["value"] = changes[code]
                f["is_manual_edited"] = True
        conclusion = changes.get("CONCLUSION", new_review.conclusion)
        db.add(M12ReportVersion(
            review_id=new_review.id,
            version_no=new_review.version_no,
            snapshot_json={"fields": fields},
            conclusion=conclusion,
            created_by=new_review.reviewer_id,
        ))

    @classmethod
    async def get_queue(cls, q, user) -> Dict[str, Any]:
        """待审核队列。"""
        conditions = ["r.status = :status", "r.is_deleted = FALSE"]
        params: Dict[str, Any] = {"status": q.status or "PENDING"}
        if q.device_code:
            conditions.append("r.device_code = :device")
            params["device"] = q.device_code
        if q.exam_code:
            conditions.append("r.exam_code = :exam")
            params["exam"] = q.exam_code
        if q.has_critical is not None:
            conditions.append("r.critical_count > 0")
        where = " AND ".join(conditions)
        offset = (q.page - 1) * q.page_size

        async with get_session() as db:
            sql_count = "SELECT COUNT(*) FROM m12_report_review r WHERE " + where
            total = await db.scalar(
                text(sql_count).bindparams(**params))
            sql_page = (
                "SELECT r.id, r.report_no, r.patient_name, r.patient_gender, "
                "r.patient_age, r.exam_code, r.exam_name, r.eye_side, "
                "r.device_code, r.critical_count, r.critical_level, "
                "r.created_at, r.claimed_at, r.status, r.sla_deadline_at "
                "FROM m12_report_review r WHERE " + where + " "
                "ORDER BY r.critical_level DESC NULLS LAST, "
                "r.created_at ASC "
                "LIMIT :lim OFFSET :off"
            )
            rows = (await db.execute(
                text(sql_page).bindparams(
                    lim=q.page_size, off=offset, **params)
            )).mappings().all()

        items = []
        now = datetime.now()
        for r in rows:
            wait = int((now - r["created_at"]).total_seconds() // 60)
            items.append({
                "review_id": r["id"],
                "report_no": r["report_no"],
                "patient_name": r["patient_name"],
                "gender": r["patient_gender"],
                "age": r["patient_age"],
                "exam_code": r["exam_code"],
                "exam_name": r["exam_name"],
                "eye_side": r["eye_side"],
                "device_code": r["device_code"],
                "priority": ("URGENT" if r["critical_level"] == "CRITICAL"
                             else "HIGH" if r["critical_count"]
                             else "NORMAL"),
                "has_critical": r["critical_count"] > 0,
                "critical_level": r["critical_level"],
                "wait_minutes": wait,
                "is_overdue": (r["sla_deadline_at"] is not None
                               and now > r["sla_deadline_at"]),
                "status": r["status"],
            })
        return {"items": items, "total": total,
                "page": q.page, "page_size": q.page_size}

    @classmethod
    async def batch_pass(cls, payload, user) -> Dict[str, Any]:
        """批量通过。"""
        ids = list(payload.review_ids or [])
        if len(ids) > 20:
            raise BizException("1205019", "批量通过数量超过 20 份")
        if not ids:
            return {"passed": 0, "skipped": [], "message": "未选择报告"}

        passed = 0
        skipped = []
        for rid in ids:
            async with get_session() as db:
                review = await db.get(M12ReportReview, rid)
                if review is None:
                    skipped.append({"review_id": rid,
                                    "reason": "报告不存在"})
                    continue
                if review.critical_count:
                    raise BizException("1205020",
                                       "含危急值的报告不允许批量通过")
                if review.is_urgent:
                    raise BizException("1205021",
                                       "含加急标记的报告不允许批量通过")
                if review.status != "PENDING":
                    skipped.append({"review_id": rid,
                                    "reason": "状态不是待审核"})
                    continue
            sub = type("P", (), {
                "conclusion": "PASS",
                "opinion": payload.opinion or "批量通过",
                "verified": True,
                "modify_reason": None,
                "reject_reason": None,
                "sla_reason": None,
            })()
            try:
                await cls.claim(rid, user)
                await cls.submit(rid, sub, user, "batch")
                passed += 1
            except BizException as exc:
                skipped.append({"review_id": rid,
                                "reason": exc.message})
        return {"passed": passed, "skipped": skipped,
                "message": "批量通过 %d 份" % passed}
```

```python
"""M12-05 危急值规则引擎 —— 规则判定与重判。"""
import logging
from decimal import Decimal, InvalidOperation
from typing import Any, Dict, List, Optional

from sqlalchemy import select, text

from app.clients.m09_client import M09Client
from app.models.m12_review import M12CriticalValue, M12ReportReview

logger = logging.getLogger("m12.critical")

OP_TEXT = {
    "GT": ">", "LT": "<", "GTE": ">=", "LTE": "<=",
    "BETWEEN": "介于", "OUTSIDE": "超出",
}

SEVERITY_LEVELS = ("CRITICAL", "WARNING")
SEVERITY_ORDER = {"CRITICAL": 2, "WARNING": 1}


class CriticalRuleEngine:
    """危急值规则引擎。"""

    @classmethod
    async def evaluate(cls, db, review, parse) -> List[M12CriticalValue]:
        """建档时判定危急值。"""
        rules = await cls._load_rules(review.exam_code)
        if not rules:
            logger.warning(
                "检查项目无危急值规则 exam_code=%s",
                review.exam_code,
                extra={"module": "M12-05", "action": "CRITICAL_EVAL"})
            return []

        field_map = {f.get("field_code"): f
                     for f in parse.get("fields", [])}
        hits: List[Dict[str, Any]] = []
        skipped: List[str] = []
        for rule in rules:
            field = field_map.get(rule.get("field_code"))
            if field is None:
                skipped.append(rule.get("rule_code"))
                continue
            value = cls._to_decimal(field.get("value"))
            if value is None:
                skipped.append(rule.get("rule_code"))
                continue
            if cls._match(rule, value):
                hits.append({
                    "rule": rule,
                    "field": field,
                    "value": value,
                })

        hits.sort(
            key=lambda h: SEVERITY_ORDER.get(
                h["rule"].get("critical_level"), 0), reverse=True)

        created: List[M12CriticalValue] = []
        highest = None
        for h in hits:
            rule = h["rule"]
            level = rule.get("critical_level", "CRITICAL")
            if highest is None or (
                    SEVERITY_ORDER.get(level, 0)
                    > SEVERITY_ORDER.get(highest, 0)):
                highest = level
            cv = M12CriticalValue(
                review_id=review.id,
                report_no=review.report_no,
                parse_id=review.parse_id,
                patient_id=review.patient_id,
                patient_name=review.patient_name,
                task_id=review.task_id,
                exam_code=review.exam_code,
                exam_name=review.exam_name,
                eye_side=review.eye_side,
                rule_id=rule.get("id"),
                rule_code=rule.get("rule_code"),
                rule_desc=cls._describe(rule),
                field_code=rule.get("field_code"),
                indicator_name=rule.get("indicator_name"),
                detected_value=cls._format_value(h["value"]),
                unit=rule.get("indicator_unit"),
                threshold_min=cls._to_decimal(rule.get("threshold_min")),
                threshold_max=cls._to_decimal(rule.get("threshold_max")),
                operator=rule.get("operator"),
                severity=level,
                handle_sla_minutes=rule.get("handle_sla_minutes") or 120,
                handle_requirement=rule.get("handle_requirement"),
                status="DETECTED",
                detected_at=None,
            )
            db.add(cv)
            created.append(cv)

        if created:
            review.critical_count = len(created)
            review.critical_level = highest
            await db.flush()
        return created

    @classmethod
    async def reevaluate(cls, db, review, changes) -> List[Dict[str, Any]]:
        """修订后重判危急值，返回变化列表。"""
        old = (await db.execute(
            select(M12CriticalValue).where(
                M12CriticalValue.review_id == review.root_review_id,
            ))).scalars().all()
        old_codes = {c.rule_code for c in old}

        rules = await cls._load_rules(review.exam_code)
        changes_list: List[Dict[str, Any]] = []
        for rule in rules:
            code = rule.get("field_code")
            if code not in changes:
                continue
            value = cls._to_decimal(changes[code])
            if value is None:
                continue
            matched = cls._match(rule, value)
            rc = rule.get("rule_code")
            was = rc in old_codes
            if matched:
                cv = M12CriticalValue(
                    review_id=review.id,
                    report_no=review.report_no,
                    patient_id=review.patient_id,
                    patient_name=review.patient_name,
                    task_id=review.task_id,
                    exam_code=review.exam_code,
                    exam_name=review.exam_name,
                    eye_side=review.eye_side,
                    rule_id=rule.get("id"),
                    rule_code=rc,
                    rule_desc=cls._describe(rule),
                    field_code=code,
                    indicator_name=rule.get("indicator_name"),
                    detected_value=cls._format_value(value),
                    unit=rule.get("indicator_unit"),
                    severity=rule.get("critical_level", "CRITICAL"),
                    status="DETECTED",
                )
                db.add(cv)
                changes_list.append({
                    "rule_code": rc,
                    "action": "ADDED" if not was else "UPDATED",
                    "value": cls._format_value(value),
                    "severity": rule.get("critical_level"),
                })
            elif was:
                changes_list.append({
                    "rule_code": rc,
                    "action": "REMOVED",
                    "value": cls._format_value(value),
                })
        await db.flush()
        return changes_list

    @classmethod
    async def _load_rules(cls, exam_code: Optional[str]) -> List[dict]:
        """加载危急值规则（缓存 30 分钟）。"""
        if not exam_code:
            return []
        try:
            return await M09Client.get_critical_rules(exam_code)
        except Exception as exc:
            logger.error(
                "加载危急值规则失败 exam_code=%s err=%s",
                exam_code, exc,
                extra={"module": "M12-05", "action": "LOAD_RULES"})
            return []

    @classmethod
    def _match(cls, rule: dict, value: Decimal) -> bool:
        """判断是否命中规则。"""
        op = rule.get("operator")
        lo = cls._to_decimal(rule.get("threshold_min"))
        hi = cls._to_decimal(rule.get("threshold_max"))
        if op == "GT":
            return hi is not None and value > hi
        if op == "LT":
            return lo is not None and value < lo
        if op == "GTE":
            return hi is not None and value >= hi
        if op == "LTE":
            return lo is not None and value <= lo
        if op == "BETWEEN":
            return (lo is not None and hi is not None
                    and lo <= value <= hi)
        if op == "OUTSIDE":
            if lo is None or hi is None:
                return False
            return value < lo or value > hi
        return False

    @classmethod
    def _describe(cls, rule: dict) -> str:
        """生成规则描述文本。"""
        name = rule.get("indicator_name") or rule.get("rule_name") or ""
        op = rule.get("operator")
        lo = rule.get("threshold_min")
        hi = rule.get("threshold_max")
        unit = rule.get("indicator_unit") or ""
        if op in ("GT", "GTE", "LT", "LTE"):
            return "%s %s %s %s" % (
                name, OP_TEXT.get(op, op), hi if op in ("GT", "GTE") else lo,
                unit)
        if op == "BETWEEN":
            return "%s 介于 %s~%s %s" % (name, lo, hi, unit)
        if op == "OUTSIDE":
            return "%s 超出 %s~%s %s" % (name, lo, hi, unit)
        return name

    @staticmethod
    def _to_decimal(value) -> Optional[Decimal]:
        """安全转 Decimal。"""
        if value is None:
            return None
        try:
            return Decimal(str(value).strip())
        except (InvalidOperation, ValueError):
            return None

    @staticmethod
    def _format_value(value: Decimal) -> str:
        """格式化数值（去尾零）。"""
        normalized = value.normalize()
        if normalized == normalized.to_integral():
            return str(normalized.quantize(Decimal("1")))
        return str(normalized)
```

## 7. 缓存与异步任务设计

### 7.1 Redis 缓存

| Key 模式 | 类型 | TTL | 说明 |
|---|---|---|---|
| `m12:review:queue` | ZSet | 无 | **待审核队列**，score = 优先级×10^10 + 创建时间戳 |
| `m12:review:cfg:{code}` | String | 600s | 单个配置项 |
| `m12:review:cfg:all` | Hash | 600s | 全部配置 |
| `m12:review:rule:{exam_code}` | String | 1800s | 危急值规则（JSON） |
| `m12:critical:queue` | ZSet | 无 | 危急值待升级队列，score = 下次检查时间 |
| `m12:critical:seq:{yyyymmdd}` | String | 172800s | 危急值单号序列 |
| `m12:publish:retry` | ZSet | 无 | 推送重试队列，score = 下次重试时间 |
| `m12:review:dashboard:{date}` | String | 60s | 工作台概览缓存 |
| `m12:review:lock:{review_id}` | String | 120s | 审核操作并发锁 |
| `m12:stats:{start}:{end}` | String | 1800s | 统计报表缓存 |

**容量估算：**

| Key | 条数 | 单条 | 小计 |
|---|---|---|---|
| `m12:review:queue` | 20 | 40B | 0.8KB |
| `m12:review:cfg:*` | 25 | 200B | 5KB |
| `m12:review:rule:*` | 20 | 4KB | 80KB |
| `m12:critical:queue` | 5 | 40B | 0.2KB |
| `m12:publish:retry` | 5 | 40B | 0.2KB |
| `m12:review:dashboard:*` | 1 | 3KB | 3KB |
| `m12:stats:*` | 10 | 10KB | 100KB |
| **合计** | | | **约 190KB** |

**为什么 `m12:critical:queue` 用 ZSet 而不是定时扫描表？**

危急值的超时判定需要"到点触发"（15/30/60 分钟）。如果用"每 30 秒扫一遍表"，会有两个问题：

1. 扫描频率与时机精度绑定：30 秒扫一次意味着最多延迟 30 秒。如果要求"15 分钟±10 秒"，就要 10 秒扫一次。
2. 表扫描在数据量大时变慢。

ZSet 的做法：每次发现危急值时，`ZADD m12:critical:queue {critical_id: next_check_at}`。定时任务 `ZRANGEBYSCORE m12:critical:queue -inf now LIMIT 0 100`，精确到秒，成本 O(log N)。

### 7.2 Celery 异步任务

```python
"""M12-05 报告审核与发布 —— Celery 任务。"""
import asyncio
import logging
from datetime import datetime, timedelta

from celery import shared_task

from app.core.cache import redis_client
from app.db.session import get_session
from app.clients.m07_client import M07Client
from app.clients.m03_client import M03Client
from app.models.m12_review import (
    M12CriticalValue,
    M12ReportPublish,
    M12ReportReview,
)

logger = logging.getLogger("m12.review.task")

MAX_PUSH_RETRY = 10
RETRY_DELAYS = [10, 30, 60, 120, 300, 600, 1200, 1800, 3600]
ESCALATION_MINUTES = (15, 30, 60)


@shared_task(bind=True, max_retries=10, default_retry_delay=60)
def push_report_task(self, review_id: int, publish_id: int):
    """推送报告到 M07-04。"""
    try:
        return asyncio.run(_push_report(review_id, publish_id))
    except Exception as exc:
        attempt = self.request.retries + 1
        if attempt >= MAX_PUSH_RETRY:
            asyncio.run(_mark_push_failed(publish_id, str(exc)))
            logger.error("推送最终失败 report_id=%s err=%s",
                         review_id, exc,
                         extra={"module": "M12-05",
                                "action": "PUSH_FINAL_FAIL"})
            return {"success": False, "attempt": attempt}
        raise self.retry(exc=exc, countdown=RETRY_DELAYS[
            min(attempt - 1, len(RETRY_DELAYS) - 1)])


async def _push_report(review_id: int, publish_id: int) -> dict:
    """推送报告实现。"""
    async with get_session() as db:
        review = await db.get(M12ReportReview, review_id)
        publish = await db.get(M12ReportPublish, publish_id)
        if review is None or publish is None:
            return {"success": False, "reason": "not_found"}
        if review.status == "WITHDRAWN":
            publish.push_status = "SKIPPED"
            await db.commit()
            return {"success": False, "reason": "withdrawn"}

        criticals = (await db.execute(
            __import__("sqlalchemy").select(M12CriticalValue).where(
                M12CriticalValue.review_id == review_id,
                M12CriticalValue.is_deleted.is_(False)))).scalars().all()

        payload = {
            "report_id": review.id,
            "report_no": review.report_no,
            "report_type": "EXAM",
            "order_id": review.task_id,
            "encounter_id": review.encounter_id,
            "patient_id": review.patient_id,
            "item_code": review.exam_code,
            "item_name": review.exam_name,
            "eye_side": review.eye_side,
            "status": "FINAL",
            "conclusion": review.conclusion,
            "has_critical": len(criticals) > 0,
            "critical_rule_code": (criticals[0].rule_code
                                   if criticals else None),
            "critical_rule_desc": (criticals[0].rule_desc
                                   if criticals else None),
            "critical_value": (criticals[0].detected_value
                               if criticals else None),
            "version_no": review.version_no,
            "is_revision": review.version_no > 1,
            "published_at": (review.published_at.isoformat()
                             if review.published_at else None),
            "source_module": "M12",
        }
        started = datetime.now()
        resp = await M07Client.push_report(payload)
        cost_ms = int((datetime.now() - started).total_seconds() * 1000)

        publish.push_status = "SUCCESS"
        publish.push_at = datetime.now()
        publish.attempt_count = (publish.attempt_count or 0) + 1
        publish.last_cost_ms = cost_ms
        await db.commit()

    logger.info("推送成功 report_id=%s cost_ms=%s", review_id, cost_ms,
                extra={"module": "M12-05", "action": "PUSH"})
    return {"success": True, "cost_ms": cost_ms, "m07_resp": resp}

async def _push_critical(critical_id: int) -> dict:
    """危急值推送实现。"""
    async with get_session() as db:
        cv = await db.get(M12CriticalValue, critical_id,
                          with_for_update=True)
        if cv is None:
            return {"success": False, "reason": "not_found"}
        if cv.status in ("ACKNOWLEDGED", "HANDLED", "CLOSED"):
            return {"success": False, "reason": "already_handled"}

        payload = {
            "report_id": cv.review_id,
            "order_id": cv.task_id,
            "encounter_id": cv.encounter_id,
            "patient_id": cv.patient_id,
            "item_code": cv.exam_code,
            "item_name": cv.exam_name,
            "eye_side": cv.eye_side,
            "rule_code": cv.rule_code,
            "rule_desc": cv.rule_desc,
            "detected_value": "%s %s" % (cv.detected_value, cv.unit or ""),
            "severity": cv.severity,
            "source_module": "M12",
        }
        resp = await M07Client.push_critical(payload)

        cv.status = "NOTIFIED"
        cv.notified_at = datetime.now()
        cv.notification_channels = ",".join(
            resp.get("notification_channels", []))
        next_at = datetime.now() + timedelta(
            minutes=ESCALATION_MINUTES[0])
        cv.next_escalate_at = next_at
        await db.commit()

    await redis_client.zadd(
        "m12:critical:queue",
        {str(critical_id): int(next_at.timestamp())})

    logger.info("危急值通知成功 critical_id=%s channels=%s",
                critical_id, cv.notification_channels,
                extra={"module": "M12-05", "action": "CRITICAL_NOTIFY"})
    return {"success": True, "m07_resp": resp}


@shared_task

    """检查危急值超时升级。"""

async def _check_escalation() -> dict:
    """扫描到期的危急值并升级。"""
    now = int(datetime.now().timestamp())
    due = await redis_client.zrangebyscore(
        "m12:critical:queue", "-inf", now, start=0, num=100)
    escalated = 0
    async with get_session() as db:
        for item in due:
            critical_id = int(item)
            cv = await db.get(M12CriticalValue, critical_id)
            if cv is None:
                await redis_client.zrem("m12:critical:queue", item)
                continue
            if cv.status in ("ACKNOWLEDGED", "HANDLED", "CLOSED"):
                await redis_client.zrem("m12:critical:queue", item)
                continue
            level = (cv.escalation_level or 0) + 1
            if level > 3:
                await redis_client.zrem("m12:critical:queue", item)
                continue
            cv.escalation_level = level
            cv.status = "ESCALATED_%d" % level
            cv.last_escalated_at = datetime.now()
            escalated += 1
            if level < 3:
                next_at = datetime.now() + timedelta(
                    minutes=ESCALATION_MINUTES[level]
                    - ESCALATION_MINUTES[level - 1])
                cv.next_escalate_at = next_at
                await redis_client.zadd(
                    "m12:critical:queue",
                    {str(critical_id): int(next_at.timestamp())})
            else:
                await redis_client.zrem("m12:critical:queue", item)
        await db.commit()

    if escalated:
        logger.warning("危急值升级 %d 条", escalated,
                       extra={"module": "M12-05",
                              "action": "CRITICAL_ESCALATE"})
    return {"escalated": escalated}
```

**关键设计：**

1. **技师只有 `review:query`**：技师可以看报告审核结果（知道自己提交的报告有没有被退），但不能审核自己的报告——这是 SoD 职责分离的硬要求。
2. **IT 管理员只有 `config`**：可以配参数，但不能看报告内容（报告含患者诊断信息，最小权限原则）。
3. **系统管理员无任何业务权限**：系统管理员账号仅用于运维操作（重启服务、配置数据库），不应有业务数据访问权限。
4. **`review:withdraw` 只有科主任和医务科**：撤回已发布报告是重大操作，会让已看到的医生失去依据，必须由管理岗执行。
5. **`critical:manage` 只有科主任和医务科**：强制标记已通知直接影响危急值统计指标，不能由执行者自己标记。

### 9.4 安全措施

| 措施 | 说明 |
|---|---|
| **审核留痕** | 每次审核记录 `operator_id`、`operator_name`、`client_ip`、`created_at` |
| **电子签名** | 审核提交时记录医师标识，不可抵赖 |
| **并发锁** | 认领用条件更新，发布用 `FOR UPDATE` |
| **PDF 原件访问审计** | 每次调 `original` 接口记录日志 |
| **配置变更审计** | 配置修改全部进 `m12_review_log` |
| **强制标记审计** | 强制标记已通知单独记录，科内审查 |
| **数据不全暴露** | 列表页不带完整身份证、电话、完整报告正文 |
| **越权防护** | 每次操作校验 `reviewer_id = current_user` |

**为什么"强制标记已通知"要单独审计？**

因为这个操作直接改变危急值统计指标。如果一个科室的危急值确认率是 100%，但其中 30% 是强制标记的，那这个 100% 就是假的。

单独记录 `is_force`、`force_remark`、操作人，科主任每月能拉出"强制标记清单"审查，才能保证指标真实性。

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 场景 | 处理策略 |
|---|---|---|
| **业务异常** | 状态不允许、校验失败 | 返回 7 位错误码，不重试 |
| **上游不可用** | M12-04/M01-09 超时 | 阻断或降级，见 §2.4 |
| **下游失败** | M07-04 推送失败 | 重试 10 次，转人工 |
| **数据异常** | 解析记录与报告不一致 | 记录 ERROR，告警 |
| **规则缺失** | 检查项目无危急值规则 | 记录 WARN，不阻断 |
| **并发冲突** | 两医师同时认领 | 后到者提示"已被 X 认领" |
| **超时** | 审核超时 | 告警 + 升级，不阻断 |

### 11.3 监控指标

| 指标 | 采集方式 | 告警阈值 |
|---|---|---|
| 待审核队列长度 | 定时查 `COUNT(*) WHERE status='PENDING'` | >50 告警 |
| 审核超时数 | 定时查 `sla_deadline_at < NOW()` | >5 告警 |
| 平均审核时长 | 日聚合 `AVG(review_seconds)` | >300 秒告警 |
| 危急值未确认数 | 定时查 `status='NOTIFIED'` | >3 告警 |
| 危急值升级率 | `escalation_level > 0 / total` | >10% 告警 |
| 危急值强制标记率 | `is_force / total` | >5% 告警 |
| 推送失败率 | 失败数 / 发布数 | >1% 告警 |
| 推送重试队列长度 | ZSet 长度 | >20 告警 |
| 立案建档失败数 | 日志统计 | >0 告警 |
| 审核并发冲突数 | `1205008` 错误码计数 | >10/天 告警 |

**为什么"危急值强制标记率"要单独监控？**

如果这个指标异常升高（比如超过 5%），说明：
- 要么系统的通知渠道有问题（医生收不到，只好由医务科人工电话+强制标记）
- 要么医务科在为了指标好看而滥用强制标记

两种都是严重问题，必须人工介入调查。

### 12.1 功能验收

| 编号 | 验收项 | 验收方法 | 通过标准 |
|---|---|---|---|
| AC-01 | 建档幂等 | 同一 `parse_id` 调用两次 `on-parsed` | 第二次返回 `is_duplicate=true`，不产生新报告 |
