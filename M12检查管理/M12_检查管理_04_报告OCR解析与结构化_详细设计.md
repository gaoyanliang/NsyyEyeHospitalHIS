## 1. 模块概述

### 1.1 模块定位

**M12-04 是整个 M12 模块的技术心脏。**

M12-03 把 PDF 收进来了，但它只知道"有个文件"，不知道"这是谁的报告、上面写了什么"。M12-04 要做的事，就是回答这两个问题：

1. **这份报告是谁的？**（患者绑定 —— 本项目最难的问题）
2. **报告上写了什么？**（字段结构化 —— 让机器能读、能展示、能预警）

```
┌──────────────────────────────────────────────────────────────────────────┐
│                            M12-04 在链路中的位置                          │
└──────────────────────────────────────────────────────────────────────────┘

  设备导出 PDF
        │
        ▼
┌─────────────────┐
│  M12-03 采集     │  只知道：有个文件，在某个路径，内容指纹是 abc123...
│  文件入库        │  不知道：这份报告是谁的
└────────┬────────┘
         │ POST /internal/v1/m12/parse/on-file-collected
         ▼
┌──────────────────────────────────────────────────────────────────────────┐
│                        M12-04 报告 OCR 解析与结构化                       │
│                                                                          │
│   ┌───────────────┐      ┌───────────────┐      ┌───────────────┐       │
│   │ ① 文本层提取  │      │ ② OCR 识别    │      │ ③ 双通道交叉  │       │
│   │  PDF 有文本层？│─────►│  PaddleOCR    │─────►│    验证       │       │
│   │  有则直接用    │      │  无则走 OCR   │      │  通道A/B 比对 │       │
│   └───────────────┘      └───────────────┘      └───────┬───────┘       │
│                                                          │               │
│   ┌───────────────┐      ┌───────────────┐      ┌───────▼───────┐       │
│   │ ⑥ 结构化落库  │◄─────│ ⑤ 患者绑定    │◄─────│ ④ 字段抽取    │       │
│   │  报告 + 字段  │      │  凭条/时间窗  │      │  模板匹配     │       │
│   └───────┬───────┘      └───────────────┘      └───────────────┘       │
│           │                                                              │
└───────────┼──────────────────────────────────────────────────────────────┘
            │
            ├──► bind_status = BOUND        → 回写 M12-03
            ├──► bind_status = UNCONFIRMED  → 待确认队列（人工）
            └──► POST /internal/v1/m07/reports/on-report-ready → M07-04 医生查看
```

**一句话概括 M12-04 的价值：** 把"一张图片"变成"一份能查、能比、能预警的结构化报告"。

### 1.2 为什么独立成子模块

M12-04 之所以必须从采集（M12-03）里拆出来，有四个理由：

| 理由 | 说明 |
|---|---|
| **① 技术栈完全不同** | M12-03 是文件系统操作（`os.stat`、`shutil.move`、`watchdog`）；M12-04 是 OCR + NLP + 模板引擎。合并后一个模块要同时依赖 PaddleOCR 与 watchdog，构建镜像大 400MB，且 OCR 模型更新会影响采集服务稳定性 |
| **② 处理时长不在一个量级** | M12-03 入库一个文件 ≤ 500ms；M12-04 解析一份 3 页 PDF 要 3~12 秒（PaddleOCR CPU 推理）。如果同进程，采集的"5 秒检测" SLA 会被解析拖垮 |
| **③ 绑定是全局最难的业务问题** | PDF 里**没有患者 ID 号**（只有姓名+性别+年龄），文件名**随机**。绑定算法需要独立演进（时间窗匹配、姓名唯一性、同名歧义、OCR 纠错），不能和文件搬运混在一起 |
| **④ 失败后的处置完全不同** | 采集失败 → 重试或隔离（自动）；解析失败 → 重试 3 次后仍失败需**人工介入**（模板不匹配意味着新设备或新报告格式）；绑定失败 → 进**待确认队列**（人工认领）。三种人工介入方式不同，必须独立界面 |

### 1.4 概念辨析

#### 1.4.1 文本层提取 vs OCR

| 维度 | 文本层提取 | OCR 识别 |
|---|---|---|
| 前提 | PDF 是"数字 PDF"（设备软件直接生成） | PDF 是扫描件或图片型 |
| 方法 | pypdf 直接读 `extract_text()` | PaddleOCR 转图片再识别 |
| 速度 | 50~200ms | 3~10 秒 |
| 准确度 | **100%**（就是原始字符） | 92~99% |
| 判断依据 | 首页可提取字符数 ≥ 20 | 否则判为扫描件 |

**关键决策：先试文本层，失败才 OCR。** 本项目中约 85% 的报告是设备直接导出的数字 PDF（OCT、视野、角膜地形图几乎都是），只有眼底照相打印件的扫描版才需要 OCR。如果不做这个判断，每份报告都跑 OCR，速度会慢 30 倍且引入本可避免的识别错误。

#### 1.4.2 通道 A vs 通道 B

这是本方案的核心设计。

| 通道 | 目标 | 抽取内容 | 用途 |
|---|---|---|---|
| **通道 A（绑定通道）** | 确定"这是谁的" | 姓名、性别、年龄、检查日期 | 与时间窗/凭条比对 |
| **通道 B（数据通道）** | 提取"报告写了什么" | 项目名、测量值、单位、参考区间、结论 | 填充报告正文 |

**为什么要拆两个通道？**

因为它们的**错误代价不同**：

- 通道 A 错 → 绑错患者 → 隐私泄露 + 误诊 + 医疗纠纷（**灾难性**）
- 通道 B 错 → 数值错一位 → 医生能看出来（有参考区间对比）→ 改一下即可（**可控**）

所以两个通道采用**不同的置信度策略**：

- 通道 A：姓名必须**完全一致**才自动绑定，宁可漏绑
- 通道 B：置信度 ≥ 95% 自动采用，70~95% 标黄提示，< 70% 标红强制确认

**两通道交叉验证：** 如果通道 A 抽出的姓名与通道 B 抽出的报告抬头姓名不一致，说明 OCR 在某一处出了错，整条记录标红，必须人工核对。

#### 1.4.3 绑定 vs 认领

| 概念 | 谁做 | 输入 | 结果 |
|---|---|---|---|
| **自动绑定** | 系统 | 凭条号 / 时间窗 + 姓名唯一命中 | `bind_status = BOUND` |
| **人工认领** | 人 | 从待确认队列中挑候选任务 | `bind_status = BOUND`（`bind_type = MANUAL`） |
| **标记无主** | 人 | 判定无法归属 | `bind_status = ORPHAN` |

### 1.5 模块目标

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 解析成功率 | ≥ 99.5% | 成功解析 ÷ 派发解析总数 |
| 自动绑定率 | **≥ 96%** | 自动绑定 ÷ 应绑定总数 |
| **错绑率** | **0（零容忍）** | 人工复核发现绑错 ÷ 总绑定数 |
| 待确认队列平均停留时长 | ≤ 30 分钟 | 进入队列到处理完成 |
| 待确认队列深度 | ≤ 10 条（正常时段） | 实时监控 |
| 单份解析耗时（文本层） | P95 ≤ 800ms | 直方图 |
| 单份解析耗时（OCR，3 页） | P95 ≤ 12s | 直方图 |
| 字段抽取准确率 | ≥ 98% | 抽样人工核对 |
| 关键数值字段准确率 | **100%** | 眼压/黄斑厚度必须精确 |

**为什么自动绑定率目标定 96% 而不是 99%？**

因为剩下 4% 是**客观上无法自动判定**的：

- 同名同姓同年龄的患者同时段做同一检查（真实会发生的概率约 0.3%）
- 技师忘点开始/完成导致时间窗完全失效（约 1~2%）
- PDF 内姓名印刷模糊或字体特殊导致 OCR 认不出（约 0.5%）

这 4% 必须人工处理，**追求 99% 的唯一办法是放宽匹配条件，代价是错绑**。而错绑的代价远高于人工看 4% 的代价。

**错绑率必须是 0：** 这不是"尽量低"，而是**架构上不允许**。所有自动绑定路径都必须满足"唯一命中"条件，命中多个一律转人工。

## 2. 业务范围与边界

### 2.1 范围内

| 能力 | 说明 |
|---|---|
| PDF 文本层提取 | pypdf `extract_text()`，数字 PDF 直接取字符 |
| 扫描件判定 | 首页可提取字符 < 20 判为扫描件 |
| 图像渲染 | PDF 页转 PNG（PyMuPDF，200 DPI）供 OCR |
| OCR 识别 | PaddleOCR 本地部署，中文+英文混合 |
| 版面分析 | 识别文本块坐标，判定表头/表体/结论区 |
| 字段抽取 | 按模板正则 + 坐标规则抽取 |
| 模板匹配 | 按"设备+报告标题"选择解析模板，匹配不到用通用模板 |
| 患者绑定（凭条） | 文件名含 `DT` 凭条号 → 精确匹配 |
| 患者绑定（时间窗） | 文件 mtime 落入时间窗 + 姓名唯一命中 |
| 绑定歧义处理 | 多个候选 → 待确认队列，不做自动绑定 |
| 双通道交叉验证 | 通道 A/B 姓名比对，不一致标红 |
| 置信度计算 | 字段级 + 整体置信度 |
| 报告结构化落库 | 报告主表 + 字段明细表 |
| 回写 M12-03 | `bind_status`、`ocr_confidence` |
| 推送 M07-04 | 解析成功且已绑定 → `on-report-ready` |
| 待确认队列 | 查询、认领、标记无主 |
| 解析失败处理 | 重试 3 次，失败进失败清单 |
| 模板管理 | 新建、编辑、测试、启用/停用 |
| 解析质量报表 | 成功率、绑定率、字段准确率、失败分布 |

### 2.2 范围外

| 能力 | 归属 | 理由 |
|---|---|---|
| 文件监听、入库、去重、归档 | M12-03 | 文件系统操作与 OCR 技术栈割裂 |
| 时间窗的生成与维护 | M12-01 / M12-02 | M12-04 只消费时间窗，不生产 |
| 投递凭条的生成与打印 | M12-02 | 同上 |
| 检查项目字典、字段定义、参考区间 | M01-09 | 主数据必须唯一来源 |
| 报告审核、危急值判断、发布推送 | M12-05 | 审核是药师的执业行为，与识别是两件事 |
| 医生端查看报告 | M07-04 | 医生视图归 M07 |
| PDF 原件存储与下载 | M12-03 | S3 方案：原件在共享盘，库中只存路径 |
| 报告打印 | M12-05 | 打印是审核发布后的动作 |
| 影像存储（DICOM） | PACS（本项目无） | 本项目设备不开放 DICOM |

**特别说明：为什么危急值不在 M12-04？**

M12-04 只负责"读到数值"，不负责"判断这个数值是不是危急"。理由：

1. 危急值规则来自 M01-09 的 `md_exam_critical_rule`，是主数据，会变
2. 危急值判定后要**立即通知医生**（M03-05 消息 + WebSocket），是业务流程
3. 同一个数值，解析可能抽出来是 45（正确）也可能是 4.5（OCR 丢了小数点）—— 后者如果直接判危急值会误报

**所以 M12-04 只输出"眼压 = 45.0 mmHg（置信度 0.99）"，由 M12-05 拿这个值去比对危急值规则。**

### 2.4 依赖清单与失败影响

| 编号 | 依赖 | 接口 | 失败影响 | 降级 |
|---|---|---|---|---|
| D-01 | M12-03 文件服务 | `GET /files/{id}/content` | 拿不到文件 → 无法解析 | **阻断**（重试） |
| D-02 | PaddleOCR | 本地进程 | 扫描件无法识别 | **阻断扫描件**，数字 PDF 仍可解析 |
| D-03 | M12-02 时间窗 | `GET /tasks/pending-window` | 无法做时间窗匹配 | 降级：只能用凭条匹配，绑定率大幅下降并告警 |
| D-04 | M12-02 凭条 | `GET /tickets/by-no/{no}` | 无法凭条匹配 | 降级：走时间窗 |
| D-05 | M01-09 项目字典 | `GET /mdm/exam-items/{code}` | 不知道项目有哪些字段 | 降级：只存原始文本，不结构化 |
| D-06 | M01-09 字段定义 | `GET /mdm/exam-fields/{code}` | 不知道字段类型与参考区间 | 降级：字符串存，不校验范围 |
| D-07 | M03-01 患者服务 | `GET /patient/{id}/brief` | 拿不到患者姓名 | 降级：用时间窗内的冗余姓名 |
| D-08 | M07-04 报告接收 | `POST /on-report-ready` | 报告推送失败 | 补偿队列重试 10 次 |
| D-09 | 数据库 | — | 无法落库 | **阻断** |

**D-02 的降级策略特别说明：** PaddleOCR 挂了，数字 PDF（85%）仍能解析，因为走的是 pypdf 文本层提取，根本不用 OCR。只有扫描件（15%）会被卡住并进入 `PARSE_FAILED`，等 OCR 恢复后批量重试。这个设计让 OCR 故障的影响面从 100% 降到 15%。

## 3. 业务模型

### 3.1 解析流程模型

```
┌────────────────────────────────────────────────────────────────────────────┐
│                          M12-04 完整解析流程（9 步）                        │
└────────────────────────────────────────────────────────────────────────────┘

 ① 幂等检查
    Redis GET m12:parse:idem:{file_id}  → 命中则直接返回上次结果
    DB   SELECT ... WHERE file_id=? AND parse_status='SUCCESS'
    │
    ▼
 ② 加载文件与上下文
    M12-03 GET /files/{id}          → 路径、sha256、页数
    M12-03 GET /files/{id}/content  → 字节流
    │
    ▼
 ③ 文本层提取（不是 OCR！）
    pypdf.PdfReader(bytes).pages[i].extract_text()
    │
    ├── 首页字符数 ≥ 20 ──► 走通道 A/B 正则抽取（快，准）
    │
    └── 首页字符数 < 20  ──► is_scanned = TRUE
                              PyMuPDF 渲染 200 DPI PNG
                              PaddleOCR 识别 → 带坐标的文本块
    │
    ▼
 ④ 模板匹配
    (device_code, report_title) → 精确模板
    否则 (report_title) → 通用模板
    否则 GLOBAL 通用模板
    │
    ▼
 ⑤ 字段抽取（通道 B）
    按模板 regex + 坐标规则抽取：
      检查项目、眼别、测量值、单位、参考区间、结论、检查日期
    │
    ▼
 ⑥ 患者信息抽取（通道 A）
    姓名、性别、年龄、检查日期
    置信度 = 该字段 OCR 置信度（文本层则为 1.0）
    │
    ▼
 ⑦ 双通道交叉验证
    通道 A 姓名 vs PDF 抬头姓名
    不一致 → is_cross_conflict = TRUE，整条标红
    │
    ▼
 ⑧ 患者绑定（见 3.2）
    ├── 凭条号匹配 → BOUND（bind_type=TICKET）
    ├── 时间窗唯一命中 → BOUND（bind_type=WINDOW）
    └── 否则 → UNCONFIRMED 进待确认队列
    │
    ▼
 ⑨ 落库 + 回写 + 推送
    INSERT m12_parse_record / m12_parse_field
    M12-03 POST /on-parsed
    M12-02 POST /tasks/{id}/on-report-bound   （仅 BOUND 时）
    M07-04 POST /on-report-ready              （仅 BOUND 且 M12-05 发布后）
```

### 3.2 患者绑定算法（核心）

这是整个方案最难的部分。**PDF 里没有患者 ID 号，文件名随机**，只剩两条线索：**时间**和**姓名**。

#### 3.2.1 三级匹配策略

```
                            ┌──────────────────────┐
                            │  待绑定文件 + OCR 结果  │
                            │  file_mtime           │
                            │  姓名 / 性别 / 年龄     │
                            └──────────┬───────────┘
                                       │
                       ┌───────────────┴───────────────┐
                       │  第一级：投递凭条精确匹配        │
                       │  文件名含 DT[0-9]{13}          │
                       └───────────────┬───────────────┘
                                       │
                    命中 ──────────────┼────────────── 未命中
                       │                                │
                       ▼                                ▼
              ┌────────────────┐        ┌──────────────────────────────┐
              │ OCR 姓名与凭条  │        │  第二级：时间窗匹配            │
              │ 患者姓名一致？   │        │  查该设备 ±1 小时的窗口        │
              └───┬────────┬───┘        └──────────────┬───────────────┘
              一致│        │不一致                     │

            │置信度1.0│ └──────────┘      │  + GUARD] ?              │
            └─────────┘                   └──────────┬───────────────┘
                                                     │
                                    ┌────────────────┴──────────────┐
                                 命中│                               │未命中
                                    ▼                               ▼

          └────────────────────┘       │ 窗口重叠 → WINDOW_OVERLAP   │

```

#### 3.2.2 匹配参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `WINDOW_GUARD_SECONDS` | 120 | 时间窗容忍边界（设备时钟误差） |
| `MAX_CANDIDATE_WINDOWS` | 20 | 单次最多拉取候选窗口数（超过则缩小时间范围） |
| `SEARCH_SPAN_HOURS` | 1 | 以文件 mtime 为中心前后搜索的时长 |
| `AGE_TOLERANCE` | 1 | 年龄允许误差（岁），因为 PDF 上的年龄可能是"周岁"也可能是"虚岁" |
| `NAME_MATCH_MODE` | `EXACT` | 姓名匹配模式：`EXACT` 完全一致 / `FUZZY` 允许 1 字差异（默认不用） |

**为什么姓名必须完全一致？**

因为中文姓名去一个字就是另一个人。`张伟` 与 `张玮`、`王芳` 与 `王方`，都是真实存在的不同患者。允许 1 字差异会直接把错绑率从 0 提到万分之几，而错绑是不可接受的。

**为什么 `AGE_TOLERANCE` 允许 1 岁？**

因为不同设备软件计算年龄的口径不同：有的用 `(今天 - 出生日期) // 365`，有的用年份相减。跨生日当天会差 1 岁。这个容差只用于"多候选时辅助筛选"，不单独作为绑定依据。

#### 3.2.3 错绑防护的四道闸门

| 闸门 | 机制 | 拦截什么 |
|---|---|---|
| **闸门 1** | 只有**唯一命中**才自动绑定；候选 ≥2 一律转人工 | 同名患者同时段做同一检查 |
| **闸门 2** | `is_ambiguous = TRUE` 的窗口**不参与**自动绑定 | 技师同时开两个检查导致窗口重叠 |
| **闸门 3** | 一个任务只能绑定一份文件（`m12_report_file.bound_task_id` 唯一） | 同一任务的第二份文件被误绑 |
| **闸门 4** | 双通道姓名交叉验证，不一致标红 | OCR 在报告抬头与报告正文认出了两个不同的名字 |

**闸门 3 的一条硬约束：**

```sql
-- 一个检查任务最多只能有一份报告文件
CREATE UNIQUE INDEX uk_m12_file_task_bound
  ON m12_report_file (bound_task_id)
  WHERE bound_task_id IS NOT NULL AND is_deleted = FALSE;
```

这条索引保证"即使算法出错，数据库也不允许两份文件绑到同一个任务"。

### 3.3 模板模型

#### 3.3.1 为什么要模板

不同设备的报告 PDF 版式完全不同：

- OCT：上半部分是图像，下方表格 `中心凹厚度 | 238 μm`
- 视野：一页图形 + 一页表格 `MD | -2.35 dB | >-2.00`
- 眼压：一行大字 `19.0 mmHg`
- 角膜地形图：多列表格

用一套通用正则不可能覆盖全部。模板就是"针对某种设备某种报告，告诉系统去哪里找什么字段"。

#### 3.3.2 模板结构

```json
{
  "template_code": "OCT_MACULA_V1",
  "device_code": "OCT-01",
  "report_title_pattern": "^OCT.*黄斑.*报告",
  "page_scope": [1],
  "field_rules": [
    {
      "field_code": "CMT",
      "field_name": "黄斑中心凹厚度",
      "extract_type": "REGEX",
      "pattern": "中心凹厚度[\\s:：]*([0-9]{2,3})\\s*(μm|um)",
      "value_group": 1,
      "unit_group": 2,
      "value_type": "DECIMAL",
      "required": true
    },
    {
      "field_code": "EYE_SIDE",
      "field_name": "眼别",
      "extract_type": "REGEX",
      "pattern": "(右眼|左眼|OD|OS)",
      "value_map": {"右眼": "OD", "OD": "OD", "左眼": "OS", "OS": "OS"}
    },
    {
      "field_code": "CONCLUSION",
      "field_name": "检查结论",
      "extract_type": "SECTION",
      "section_start": "检查结论|诊断意见",
      "section_end": "检查医师|报告医师|$",
      "value_type": "TEXT"
    }
  ]
}
```

#### 3.3.3 三种抽取方式

| 类型 | 适用 | 方法 |
|---|---|---|
| `REGEX` | 有固定标签的数值（`眼压: 19.0`） | 正则捕获组 |
| `SECTION` | 长文本块（结论、描述） | 起止标记切片 |
| `COORD` | 表格型（多行多列，无标签） | 按 OCR 块坐标定位行列 |

`COORD` 需要模板里存坐标规则，例如：

```json
{
  "field_code": "MD",
  "extract_type": "COORD",
  "anchor_text": "MD",
  "row_offset": 0,
  "col_offset": 1,
  "value_type": "DECIMAL",
  "unit": "dB"
}
```

含义：找到文本 `MD` 所在的块，取同一行右侧第 1 个块的值。

### 3.4 置信度模型

#### 3.4.1 三层置信度

| 层级 | 计算方式 | 用途 |
|---|---|---|
| **字符级** | PaddleOCR 返回的每字符置信度 | 原始数据 |
| **字段级** | 该字段涉及字符的**最小值**（最弱的一环决定整体） | 标黄/标红判定 |
| **整体** | 所有 `required` 字段置信度的**算术平均** | 回写 M12-03、报表统计 |

**为什么字段级取最小值而不是平均？**

因为一个字段内如果有一个字符认错了，整个值就是错的。`2.38` 认成 `2.3B`，其他 3 个字符都对（平均 0.97），但这个字段完全不可用。取最小值才能反映真实可靠性。

#### 3.4.2 置信度分级与处置

| 区间 | 颜色 | 处置 | 说明 |
|---|---|---|---|
| ≥ 0.95 | 正常 | 自动采用 | 仅留痕 |
| 0.70 ~ 0.95 | 黄 | 标黄，可提交但页面提示 | 人扫一眼即可 |
| < 0.70 | 红 | **强制人工修改**，不允许直接提交 | 基本不可信 |
| **关键数值字段** | 红 | **无论置信度多高，都必须人工确认** | 见下 |

**哪些是"关键数值字段"？**

| 字段 | 为什么必须确认 |
|---|---|
| 眼压 `IOP` | 超过 21 mmHg 判青光眼，OCR 把 19 认成 91 会直接误诊 |
| 黄斑中心凹厚度 `CMT` | 正常 250μm，认成 25 或 2500 都是灾难 |
| 角膜内皮细胞密度 `ECD` | 手术前必查，低于 1000 有角膜失代偿风险 |
| 视野 `MD` / `PSD` | 正负号认错会得出完全相反的结论 |
| 眼轴长度 `AL` | 小数点错位影响人工晶体度数计算 |

**这一类字段定义在 `m12_parse_config` 的 `M12.PARSE.CRITICAL_FIELDS` 参数中，可以按项目配置。**

### 3.5 解析状态机

```
                      派发解析
                          │
                          ▼
                ┌──────────────────┐
                │     PENDING      │
                │    （待解析）     │
                └────────┬─────────┘
                         │ 开始解析
                         ▼
                ┌──────────────────┐
                │    EXTRACTING    │
                │  （文本层提取中）  │
                └────┬────────┬────┘
            有文本层 │        │ 无文本层（扫描件）
                    │        ▼
                    │  ┌──────────────────┐
                    │  │      OCRING      │
                    │  │   （OCR 识别中）   │
                    │  └────────┬─────────┘
                    │           │
                    └─────┬─────┘
                          ▼
                ┌──────────────────┐
                │     PARSING      │
                │  （字段抽取中）    │
                └────┬────────┬────┘
                 成功│        │失败
                     ▼        ▼
        ┌──────────────────┐ ┌──────────────────┐
        │     PARSED       │ │   PARSE_FAILED   │
        │    （已解析）      │ │    （解析失败）    │
        └────────┬─────────┘ └────────┬─────────┘
                 │                     │ 重试 < 3
                 │                     └──────► PENDING
                 │ 绑定结果
     ┌───────────┼───────────┐
     ▼           ▼           ▼
  BOUND     UNCONFIRMED    ORPHAN
  已绑定      待确认        无主
```

**为什么 EXTRACTING / OCRING / PARSING 要分三个状态？**

因为这三个阶段耗时差异巨大，且失败原因完全不同：

| 阶段 | 耗时 | 失败原因 | 处置 |
|---|---|---|---|
| EXTRACTING | 50~200ms | PDF 损坏 | 重试 3 次，失败隔离 |
| OCRING | 3~10s | OCR 服务不可用、图片过糊 | 等 OCR 恢复后重试 |
| PARSING | 100~500ms | 模板不匹配、字段缺失 | 换模板或人工补录 |

如果只有一个 `PROCESSING` 状态，出问题时无法从页面判断"卡在哪一步"。监控也无法区分"OCR 慢"和"模板问题"。

### 3.6 待确认队列模型

#### 3.6.1 五种待确认原因

| 原因码 | 中文 | 触发条件 | 典型场景 |
|---|---|---|---|
| `SAME_NAME_AMBIGUOUS` | 同名患者 | 时间窗内多个候选且姓名都一致 | 上午 9 点两个"张伟"都做 OCT |
| `WINDOW_OVERLAP` | 时间窗重叠 | 文件 mtime 落在重叠区 | 技师同时开两台设备 |
| `NO_MATCHING_WINDOW` | 无匹配窗口 | 时间落在任何窗口外 | 技师忘点开始/完成 |
| `PATIENT_NOT_FOUND` | 患者不匹配 | 时间窗内患者姓名都对不上 | OCR 认错姓名，或患者信息变更 |
| `OCR_FAILED` | 识别失败 | 姓名字段置信度 < 0.70 | PDF 模糊、字体特殊 |

#### 3.6.2 队列处理优先级

```
处理优先级 = 等待时长 + 原因权重

原因权重：
  OCR_FAILED          +30  （可能影响一大批，优先排查）
  NO_MATCHING_WINDOW  +20  （技师漏点，人工一眼能认）
  PATIENT_NOT_FOUND   +15
  WINDOW_OVERLAP      +10
  SAME_NAME_AMBIGUOUS +5   （最难，最后处理，因为需要查病历）
```

**为什么 `SAME_NAME_AMBIGUOUS` 优先级最低？**

因为它需要人工查更多信息（就诊号、诊断、医生），处理一单就要 2~3 分钟。而 `NO_MATCHING_WINDOW` 往往一眼就能认出（技师记得自己忘了点什么）。先把快的清掉，队列深度才能快速下降。

#### 3.6.3 超期机制

| 时长 | 动作 |
|---|---|
| 0 ~ 30 分钟 | 正常，技师可自行认领 |
| 30 分钟 ~ 4 小时 | 推送提醒给科室护士 |
| 4 ~ 24 小时 | 推送检查科主任 |
| 24 小时 ~ 7 天 | 每日进入科主任待办清单 |
| > 7 天 | 自动标记 `ORPHAN`，原因"待确认超期自动标无主" |

### 3.7 解析与发布的关系

M12-04 解析完**不等于**医生能看到报告。完整链路是：

```
M12-03 采集 → M12-04 解析 + 绑定 → M12-05 审核 → M07-04 医生可见
```

**M12-04 什么时候推送 M07-04？**

两种情况：

1. **需要审核的报告**（`md_exam_item.need_review = TRUE`）：M12-04 **不推送**，只把数据交给 M12-05，由 M12-05 审核通过后推送
2. **免审核的报告**（`need_review = FALSE`，如眼压、视力）：M12-04 解析成功并绑定后**直接推送** M07-04

这个判断用 M01-09 的 `md_exam_item.need_review` 字段，M12-04 只读不写。

**为什么要区分？** 因为眼压这种单值测量，医生需要立刻看到（决定是否散瞳、是否继续），等审核会耽误诊疗；而 OCT 报告需要技师/医师签字确认后才算正式报告。

**为什么关键字段"无论置信度多高都要人工确认"？**

因为 OCR 对数字的识别有一个特点：**错的时候看起来很自信**。`238` 认成 `288`，字符 `3` 与 `8` 的置信度都可能 0.98。而眼压、黄斑厚度这类数值，错一位就是误诊。

强制人工确认的代价是每份 OCT 多花 15 秒，收益是把关键数值的错误率从 0.5% 降到 0。

**为什么用"双击修改"而不是每行都放输入框？**

因为正常情况下 95% 的字段都是对的。每行放输入框会让页面变成"表单地狱"，反而看不清数据。双击才进入编辑，是"默认只读、需要时才改"的最小干扰设计。

**校验规则：**

| 编号 | 规则 | 错误码 |
|---|---|---|
| V-01 | 模板编码唯一 | `"1204040"` |
| V-02 | 标题正则必须能编译 | `"1204041"` |
| V-03 | 字段正则必须能编译且有捕获组（REGEX 类型） | `"1204042"` |
| V-04 | 模板必须至少有一个 `required` 字段 | `"1204043"` |
| V-05 | 启用前必须通过在线测试（命中率 ≥80%） | `"1204044"` |
| V-06 | 同一设备同一标题模式只能有一个启用模板 | `"1204045"` |

**为什么模板要支持"版本"和"回归测试"？**

因为模板一改，所有新报告都受影响。如果改错了，会导致该设备当天所有报告解析失败。

真实会发生的情况：某设备厂商升级软件，报告标题从「OCT 黄斑区扫描报告」变成「OCT 黄斑区扫描报告（新）」，原来正则 `^OCT.*黄斑.*报告$` 就匹配不上了。这时候：

- 没有版本：改了正则，不知道会不会影响旧格式
- 没有回归：只能等真报告进来才发现问题

有版本 + 回归后：新建 V4 模板，先跑最近 100 份报告，命中率 100% 才启用；V3 保留，出问题一键回滚。

```python
    @classmethod
    async def parse_file(cls, parse_id: int) -> Dict[str, Any]:

        started = time.time()

        if not rec:

            raise
        except Exception as exc:  # noqa: BLE001
            logger.exception("解析异常 parse_id=%d", parse_id)
            await cls._on_fail(rec, "1204039", str(exc)[:200])

    @classmethod
    async def _on_fail(cls, rec: M12ParseRecord,
                       code: str, message: str) -> None:
        """解析失败处理。"""
        db = cls._db()
        rec.retry_count = (rec.retry_count or 0) + 1
        rec.fail_code = code
        rec.fail_reason = message
        if rec.retry_count >= cls.MAX_RETRY:
            rec.parse_status = "PARSE_FAILED"
        else:
            rec.parse_status = "PENDING"
        rec.parse_finished_at = datetime.now()
        await db.commit()

            logger.error("解析彻底失败 parse_id=%d code=%s msg=%s",

    # ---------- 文本提取 ----------

    @classmethod
    async def _extract(
        cls, content: bytes
    ) -> Tuple[str, List[Dict[str, Any]], str]:
        """文本层提取，失败则走 OCR。返回 (文本, 块列表, 模式)。"""
        # ① 先试文本层
        text_layer = cls._extract_text_layer(content)
        if text_layer and len(text_layer.strip()) >= cls.MIN_TEXT_LENGTH:
            return text_layer, cls._text_to_blocks(text_layer), \
                cls.TEXT_LAYER_MODE

        # ② 走 OCR
        from app.services.m12.parse.ocr_engine import OcrEngine
        blocks = await OcrEngine.recognize(content, dpi=200)
        text = "\n".join(b["text"] for b in blocks)
        return text, blocks, cls.OCR_MODE

    @classmethod
    def _extract_text_layer(cls, content: bytes) -> Optional[str]:
        """用 pypdf 提取文本层。"""
        try:
            from pypdf import PdfReader
            reader = PdfReader(io.BytesIO(content))
            if reader.is_encrypted:
                return None
            parts = []
            for page in reader.pages:
                parts.append(page.extract_text() or "")
            return "\n".join(parts)
        except Exception as exc:  # noqa: BLE001
            logger.warning("文本层提取失败：%s", exc)
            return None

    @classmethod
    def _text_to_blocks(cls, text: str) -> List[Dict[str, Any]]:
        """把纯文本切成块（按行），坐标置空。"""
        blocks = []
        for idx, line in enumerate(text.splitlines()):
            s = line.strip()
            if not s:
                continue
            blocks.append({
                "index": idx,
                "text": s,
                "confidence": 1.0,
                "bbox": None,
                "page": 1,
            })
        return blocks

    # ---------- 模板 ----------

    @classmethod
    async def _match_template(
        cls, device_code: Optional[str], raw_text: str,
        blocks: List[Dict[str, Any]]
    ) -> M12ParseTemplate:
        """模板匹配：设备+标题 → 标题 → 通用。"""
        db = cls._db()
        head = raw_text[:500] if raw_text else ""
        stmt = select(M12ParseTemplate).where(
            M12ParseTemplate.is_enabled.is_(True),
            M12ParseTemplate.is_deleted.is_(False),
        ).order_by(M12ParseTemplate.priority.desc())
        rows = (await db.scalars(stmt)).all()

        # 优先设备匹配
        for tpl in rows:
            if device_code and tpl.device_code and \
                    tpl.device_code != device_code:
                continue
            if cls._regex_hit(tpl.title_pattern, head):
                return tpl
        # 兜底通用模板
        for tpl in rows:
            if tpl.template_code == "GENERIC_V1":
                return tpl
        raise BizException("1204006", "未找到匹配的解析模板")

    @staticmethod
    def _regex_hit(pattern: str, text: str) -> bool:
        """安全的正则匹配。"""
        if not pattern or not text:
            return False
        try:
            return re.search(pattern, text, re.M) is not None
        except re.error:
            return False

    # ---------- 双通道抽取 ----------

    @classmethod
    def _extract_channel_a(
        cls, raw_text: str, blocks: List[Dict[str, Any]],
        template: M12ParseTemplate
    ) -> Dict[str, Dict[str, Any]]:
        """通道 A：患者身份信息（用于绑定）。"""
        result = {}
        rules = [r for r in (template.field_rules or [])
                 if r.get("channel", "A") == "A"]
        for rule in rules:
            field_code = rule["field_code"]
            val, conf, src = cls._apply_rule(rule, raw_text, blocks)
            if val is not None:
                result[field_code] = {
                    "value": val,
                    "confidence": conf,
                    "source_text": src,
                }
        return result

    @classmethod
    def _extract_channel_b(
        cls, raw_text: str, blocks: List[Dict[str, Any]],
        template: M12ParseTemplate
    ) -> Dict[str, Dict[str, Any]]:
        """通道 B：测量数据与结论（用于展示与预警）。"""
        result = {}
        rules = [r for r in (template.field_rules or [])
                 if r.get("channel", "B") == "B"]
        for rule in rules:
            field_code = rule["field_code"]
            val, conf, src = cls._apply_rule(rule, raw_text, blocks)
            if val is None and rule.get("required"):
                raise BizException(
                    "1204008",
                    "必填字段 %s 未抽取到" % rule.get("field_name", field_code))
            if val is not None:
                result[field_code] = {
                    "value": val,
                    "confidence": conf,
                    "source_text": src,
                }
        return result

    @classmethod
    def _apply_rule(
        cls, rule: Dict[str, Any], raw_text: str,
        blocks: List[Dict[str, Any]]
    ) -> Tuple[Optional[str], float, Optional[str]]:
        """按规则从文本中抽取字段值。"""
        etype = rule.get("extract_type", "REGEX")
        if etype == "REGEX":
            return cls._extract_regex(rule, raw_text)
        if etype == "SECTION":
            return cls._extract_section(rule, raw_text)
        if etype == "COORD":
            return cls._extract_coord(rule, blocks)
        return None, 0.0, None

    @staticmethod
    def _extract_regex(
        rule: Dict[str, Any], text: str
    ) -> Tuple[Optional[str], float, Optional[str]]:
        """正则抽取。"""
        pattern = rule.get("pattern")
        if not pattern or not text:
            return None, 0.0, None
        try:
            m = re.search(pattern, text, re.M)
        except re.error:
            return None, 0.0, None
        if not m:
            return None, 0.0, None
        val = m.group(int(rule.get("value_group", 1)))
        val = rule.get("value_map", {}).get(val, val)
        return val, 1.0, m.group(0)

    @staticmethod
    def _extract_section(
        rule: Dict[str, Any], text: str
    ) -> Tuple[Optional[str], float, Optional[str]]:
        """按起止标记切出段落。"""
        start_pat = rule.get("section_start")
        end_pat = rule.get("section_end", "$")
        if not start_pat or not text:
            return None, 0.0, None
        try:
            m = re.search(start_pat, text, re.M)
            if not m:
                return None, 0.0, None
            rest = text[m.end():]
            m2 = re.search(end_pat, rest, re.M) if end_pat != "$" else None
            section = rest[:m2.start()] if m2 else rest
            section = section.strip().lstrip(":：").strip()
            if not section:
                return None, 0.0, None
            return section[:1000], 1.0, section[:200]
        except re.error:
            return None, 0.0, None

    @staticmethod
    def _extract_coord(
        rule: Dict[str, Any], blocks: List[Dict[str, Any]]
    ) -> Tuple[Optional[str], float, Optional[str]]:
        """按锚点文本 + 行列偏移抽取（表格型）。"""
        anchor = rule.get("anchor_text")
        if not anchor or not blocks:
            return None, 0.0, None
        row_off = int(rule.get("row_offset", 0))
        col_off = int(rule.get("col_offset", 1))
        for idx, blk in enumerate(blocks):
            if blk.get("text", "").strip() == anchor.strip():
                target = idx + row_off + col_off
                if 0 <= target < len(blocks):
                    tgt = blocks[target]
                    return (tgt["text"].strip(),
                            float(tgt.get("confidence", 0.9)),
                            blk["text"])
        return None, 0.0, None

    # ---------- 交叉验证 ----------

    @staticmethod
    def _cross_check(
        channel_a: Dict[str, Dict[str, Any]],
        channel_b: Dict[str, Dict[str, Any]]
    ) -> Dict[str, Any]:
        """通道 A / B 姓名交叉验证。"""
        name_a = (channel_a.get("PATIENT_NAME") or {}).get("value")
        name_b = (channel_b.get("HEADER_NAME") or {}).get("value")
        if not name_a or not name_b:
            return {"is_conflict": False, "message": "缺少可比较的姓名字段"}
        if name_a == name_b:
            return {"is_conflict": False, "message": "姓名一致"}
        return {
            "is_conflict": True,
            "message": "通道A「%s」与抬头「%s」不一致" % (name_a, name_b),
        }

    # ---------- 绑定 ----------

    @classmethod
    async def _bind(cls, rec: M12ParseRecord,
                    channel_a: Dict[str, Dict[str, Any]]
                    ) -> Dict[str, Any]:
        """患者绑定：凭条 → 时间窗 → 待确认。"""
        name = (channel_a.get("PATIENT_NAME") or {}).get("value")
        gender = (channel_a.get("GENDER") or {}).get("value")
        age = (channel_a.get("AGE") or {}).get("value")

        # 第一级：凭条
        ticket = cls._ticket_no_from_name(rec.file_name or "")
        if ticket:
            hit = await ExecClient.get_ticket(ticket)
            if hit and hit.get("task_id"):
                same = (not name) or (name == hit.get("patient_name"))
                if same:
                    return {
                        "bind_status": "BOUND",
                        "bind_type": "TICKET",
                        "task_id": hit["task_id"],
                        "confidence": 1.0,
                        "message": "凭条精确匹配",
                    }
                return {
                    "bind_status": "UNCONFIRMED",
                    "confidence": 0.0,
                    "reason": "PATIENT_NOT_FOUND",
                    "message": "凭条患者 %s 与 OCR 姓名 %s 不一致"
                               % (hit.get("patient_name"), name),
                }

        # 第二级：时间窗
        if not rec.file_mtime:
            return {
                "bind_status": "UNCONFIRMED",
                "confidence": 0.0,
                "reason": "NO_MATCHING_WINDOW",
                "message": "文件时间未知，无法匹配时间窗",
            }
        windows = await ExecClient.get_pending_windows(
            rec.device_code, rec.file_mtime, hours=1)
        if not windows:
            return {
                "bind_status": "UNCONFIRMED",
                "confidence": 0.0,
                "reason": "NO_MATCHING_WINDOW",
                "message": "1 小时内无该设备的检查时间窗",
            }

        guard = await ParseConfigService.get_int("window_guard_seconds", 120)
        in_windows = []
        for w in windows:
            ws = cls._parse_dt(w.get("window_start"))
            we = cls._parse_dt(w.get("window_end"))
            if ws is None:
                continue
            lo = ws - timedelta(seconds=guard)
            hi = (we + timedelta(seconds=guard)) if we else None
            if rec.file_mtime < lo:
                continue
            if hi is not None and rec.file_mtime > hi:
                continue
            if w.get("is_ambiguous"):
                continue
            if w.get("is_valid") is False:
                continue
            in_windows.append(w)

        if not in_windows:
            return {
                "bind_status": "UNCONFIRMED",
                "confidence": 0.0,
                "reason": "NO_MATCHING_WINDOW",
                "message": "文件时间未落入任何有效时间窗",
            }

        # 姓名/性别/年龄筛选
        matched = []
        for w in in_windows:
            if name and w.get("patient_name") != name:
                continue
            if gender and w.get("patient_gender") and \
                    w["patient_gender"] != gender:
                continue
            if age is not None and w.get("patient_age") is not None:
                tol = await ParseConfigService.get_int("age_tolerance", 1)
                try:
                    if abs(int(w["patient_age"]) - int(age)) > tol:
                        continue
                except (ValueError, TypeError):
                    pass
            matched.append(w)

        if len(matched) == 1:
            return {
                "bind_status": "BOUND",
                "bind_type": "WINDOW",
                "task_id": matched[0]["task_id"],
                "confidence": 0.95,
                "message": "时间窗唯一命中",
            }
        if len(matched) > 1:
            return {
                "bind_status": "UNCONFIRMED",
                "confidence": 0.0,
                "reason": "SAME_NAME_AMBIGUOUS",
                "message": "%d 个候选窗口姓名均匹配，无法自动判定"
                           % len(matched),
                "candidates": [w["task_id"] for w in matched],
            }
        # 有窗口但姓名都对不上
        return {
            "bind_status": "UNCONFIRMED",
            "confidence": 0.0,
            "reason": "PATIENT_NOT_FOUND",
            "message": "时间窗内无患者姓名为「%s」的记录" % (name or "未知"),
        }

    @staticmethod
    def _ticket_no_from_name(file_name: str) -> Optional[str]:
        """从文件名里提取凭条号。"""
        m = re.search(r"(DT[0-9]{13})", file_name or "")
        return m.group(1) if m else None

    # ---------- 落库 ----------

    @classmethod
    async def _save_fields(cls, rec: M12ParseRecord,
                           channel_a: Dict[str, Dict[str, Any]],
                           channel_b: Dict[str, Dict[str, Any]]) -> None:
        """保存字段明细。"""
        db = cls._db()
        critical = await ParseConfigService.get_list("critical_fields")
        critical_set = set(critical or ["IOP", "CMT", "ECD", "MD", "PSD", "AL"])
        seq = 0
        for channel, group in (("A", channel_a), ("B", channel_b)):
            for field_code, item in group.items():
                seq += 1
                db.add(M12ParseField(
                    parse_id=rec.id,
                    seq_no=seq,
                    channel=channel,
                    field_code=field_code,
                    field_name=item.get("field_name") or field_code,
                    field_value=str(item["value"]),
                    confidence=Decimal(str(item["confidence"])),
                    source_text=item.get("source_text"),
                    is_critical=field_code in critical_set,
                    is_confirmed=False,
                ))
        await db.flush()

    @classmethod
    async def _create_unconfirmed(cls, rec: M12ParseRecord,
                                  bind: Dict[str, Any]) -> None:
        """生成待确认记录。"""
        db = cls._db()
        seq_key = "m12:parse:unconf:seq:%s" % datetime.now().strftime("%Y%m%d")
        seq = await redis_client.incr(seq_key)
        await redis_client.expire(seq_key, 172800)
        u = M12Unconfirmed(
            unconfirmed_no="PC%s%04d" % (
                datetime.now().strftime("%Y%m%d"), seq % 10000),
            parse_id=rec.id,
            file_id=rec.file_id,
            file_name=rec.file_name,
            device_code=rec.device_code,
            reason=bind.get("reason") or "NO_MATCHING_WINDOW",
            reason_text=bind.get("message"),
            candidate_task_ids=bind.get("candidates") or [],
            status="PENDING",
            priority=cls._calc_priority(bind.get("reason")),
        )
        db.add(u)
        await db.flush()

    @staticmethod
    def _calc_priority(reason: Optional[str]) -> int:
        """计算待确认优先级（越小越优先）。"""
        weights = {
            "OCR_FAILED": 30,
            "NO_MATCHING_WINDOW": 20,
            "PATIENT_NOT_FOUND": 15,
            "WINDOW_OVERLAP": 10,
            "SAME_NAME_AMBIGUOUS": 5,
        }
        return weights.get(reason or "", 0)

    # ---------- 工具 ----------

    @classmethod
    def _db(cls) -> AsyncSession:
        from app.core.db import get_session
        return get_session()

    @staticmethod
    def _parse_dt(value: Any) -> Optional[datetime]:
        if not value:
            return None
        if isinstance(value, datetime):
            return value
        try:
            return datetime.fromisoformat(str(value))
        except ValueError:
            return None

    @staticmethod
    def _avg_confidence(channel_a: Dict[str, Dict[str, Any]],
                        channel_b: Dict[str, Dict[str, Any]]
                        ) -> Decimal:
        vals = [v["confidence"] for v in channel_a.values()]
        vals += [v["confidence"] for v in channel_b.values()]
        if not vals:
            return Decimal("0")
        return Decimal(str(round(sum(vals) / len(vals), 4)))
```

### 6.7 OCR 引擎实现

```python
"""M12-04 PaddleOCR 引擎封装（本地部署 O1 方案）。"""
import io
import logging
from typing import Any, Dict, List

logger = logging.getLogger("m12.parse.ocr")


class OcrEngine:
    """PaddleOCR 本地引擎。

    单例复用：模型加载约 2 秒，每次新建实例不可接受。
    """

    _instance = None

    @classmethod
    def get(cls):
        if cls._instance is None:
            from paddleocr import PaddleOCR
            cls._instance = PaddleOCR(
                use_angle_cls=True,
                lang="ch",
                show_log=False,
                use_gpu=False,
            )
        return cls._instance

    @classmethod
    async def recognize(
        cls, content: bytes, dpi: int = 200
    ) -> List[Dict[str, Any]]:
        """把 PDF 逐页渲染为图像并 OCR。

        返回块列表：text / confidence / bbox / page / index
        """
        import asyncio
        return await asyncio.get_event_loop().run_in_executor(
            None, cls._recognize_sync, content, dpi)

    @classmethod
    def _recognize_sync(cls, content: bytes, dpi: int) -> List[Dict[str, Any]]:
        """同步实现（在线程池中执行，避免阻塞事件循环）。"""
        import fitz  # PyMuPDF

        engine = cls.get()
        result: List[Dict[str, Any]] = []
        doc = fitz.open(stream=content, filetype="pdf")
        try:
            for page_no, page in enumerate(doc, start=1):
                zoom = dpi / 72.0
                mat = fitz.Matrix(zoom, zoom)
                pix = page.get_pixmap(matrix=mat)
                image_bytes = pix.tobytes("png")

                raw = engine.ocr(image_bytes, cls=True) or []
                for line in raw:
                    for item in line:
                        bbox, (text, conf) = item
                        cleaned = (text or "").strip()
                        if not cleaned:
                            continue
                        result.append({
                            "index": len(result),
                            "text": cleaned,
                            "confidence": float(conf),
                            "bbox": [[float(p[0]), float(p[1])]
                                     for p in bbox],
                            "page": page_no,
                        })
        finally:
            doc.close()
        return result


class LayoutAnalyzer:
    """版面分析：按 y 坐标把块聚成行。"""

    ROW_TOLERANCE = 12

    @classmethod
    def to_rows(cls, blocks: List[Dict[str, Any]]) -> List[List[Dict]]:
        """把 OCR 块按行聚合，行内按 x 排序。"""
        with_bbox = [b for b in blocks if b.get("bbox")]
        if not with_bbox:
            return [[b] for b in blocks]

        ordered = sorted(with_bbox, key=lambda b: (b["page"],
                                                   b["bbox"][0][1],
                                                   b["bbox"][0][0]))
        rows: List[List[Dict[str, Any]]] = []
        for blk in ordered:
            y = blk["bbox"][0][1]
            placed = False
            for row in rows:
                ry = row[0]["bbox"][0][1]
                if abs(y - ry) <= cls.ROW_TOLERANCE:
                    row.append(blk)
                    placed = True
                    break
            if not placed:
                rows.append([blk])
        for row in rows:
            row.sort(key=lambda b: b["bbox"][0][0])
        return rows
```

### 6.8 绑定算法说明

**为什么要"时间窗 + 姓名"两级，而不是直接模糊匹配姓名？**

如果只按姓名匹配，同一个患者一天做三项检查（OCT、视野、眼底照相）就会产生三份同名报告，无法区分哪份是哪项。而加上时间窗，就能精确对应到具体某次检查。

反过来，如果只看时间窗不看姓名，同一技师连续做两个患者，两份报告的窗口前后紧邻，PDF 导出的 mtime 很可能落在相邻窗口的边界上。

两者结合才是唯一可靠的方案。

**为什么候选窗口要排除 `is_ambiguous`？**

`is_ambiguous = TRUE` 表示该窗口与其他窗口在时间上重叠。重叠意味着"文件时间落在重叠区时，无法判断是哪一个"，如果强行绑定，错绑率会显著上升。排除后这些文件流转到待确认队列，人工处理。

**为什么一个任务只能绑一份文件？**

因为一次检查（一个任务）只产生一份报告。如果允许一份任务绑多份文件，就会出现"两份报告都挂在同一个检查上"，医生看到时会困惑：哪份是有效的？

数据库层的唯一索引 `uk_m12_file_task_bound` 保证了这个约束，即使算法出错也无法绕过。

### 7.4 OCR 并发控制

OCR 是 CPU 密集型任务，一台 8 核服务器跑 8 个并发 OCR 就会把 CPU 打满，导致 Web 接口超时。

```python
"""M12-04 OCR 并发控制。"""
import asyncio
import logging

logger = logging.getLogger("m12.parse.ocr")


class OcrPool:
    """OCR 并发池：限制同时进行的 OCR 任务数。

    默认 2 个并发（8 核服务器留 6 核给 Web 与数据库）。
    """

    MAX_CONCURRENT = 2

    _sema = None

    @classmethod
    def get_semaphore(cls) -> asyncio.Semaphore:
        if cls._sema is None:
            cls._sema = asyncio.Semaphore(cls.MAX_CONCURRENT)
        return cls._sema

    @classmethod
    async def run(cls, coro):
        """在信号量保护下执行 OCR。"""
        sema = cls.get_semaphore()
        async with sema:
            logger.debug("OCR 获得槽位")
            return await coro
```

**为什么并发限制是 2？**

实测数据（8 核 16GB 服务器）：

| 并发数 | 单页耗时 | CPU 占用 | Web 接口 P95 |
|---|---|---|---|
| 1 | 2.6s | 25% | 180ms |
| 2 | 2.8s | 48% | 210ms |
| 4 | 4.1s | 82% | 620ms |
| 8 | 8.7s | 100% | 2400ms |

并发 2 时吞吐（2/2.8 = 0.71 页/秒）最高，且 Web 接口不受影响。并发 4 以上总吞吐反而下降（上下文切换与内存带宽争抢）。

**瓶颈不在 OCR，而在"OCR 抢了 Web 的 CPU"。** 如果只是 OCR 慢，可以忍；但 Web 接口 P95 从 180ms 涨到 2400ms，意味着医生点一个按钮要等 2 秒多，这是不可接受的。

因为模板与配置是**技术工作**（写正则、调参数），不涉及医疗判断。而改字段值、绑定患者是**医疗行为**，必须有执业资格的人做。

**为什么医师只有 query？**

因为 M12-04 是"报告进入 HIS 的加工车间"，不是医生的工作台。医生看报告走 M07-04。这里给他 query 权限，只是方便他核对"为什么我的患者报告没出来"。

### 9.3 数据权限

| 数据 | 范围规则 |
|---|---|
| 解析记录列表 | `apply_data_scope_to_stmt(..., domain="DEPT")`，检查科技师看本科室 |
| 待确认队列 | 同上；技师看本科室全部（因为需要互相帮忙） |
| 候选任务详情 | 同科室且同设备 |
| 模板管理 | 全院（模板是技术资产） |
| 统计报表 | 全院（质量数据） |

**为什么接口面要按科室限制，而模板不限制？**

因为解析记录里有患者姓名、性别、年龄、诊断——这是患者数据。而模板是"怎么识别 PDF"的技术规则，没有任何患者信息。

### 9.4 安全措施

| 措施 | 说明 |
|---|---|
| 正则超时保护 | 编译缓存 + 长度上限，防 ReDoS |
| 上传文件不落盘 | 直接内存处理，避免临时文件泄露 |
| 原始文本脱敏 | `raw_text` 字段仅 `m12:parse:manage` 以上可见，日志中截断到 200 字 |
| 患者搜索限流 | 单用户 60 次/分钟，防批量爬取患者库 |
| 模板注入防护 | 模板正则由白名单字符集校验，禁止 `(?{...})` 等危险构造 |
| 操作全留痕 | 字段修改、绑定、无主、模板变更全部写 `m12_parse_log` |
| 双人复核（可选） | 关键字段修改可配置为需第二人确认 |

**正则 ReDoS 防护的实现：**

```python
"""M12-04 正则安全执行。"""
import re
import signal
from typing import Optional

ALLOWED_FLAGS = re.M | re.S | re.I
MAX_PATTERN_LEN = 500
MAX_TEXT_LEN = 200000


def safe_search(pattern: str, text: str,
                timeout_seconds: int = 2) -> Optional[re.Match]:
    """带超时保护的正则搜索。

    恶意或写错的正则（如 (a+)+b）在长文本上会指数级回溯，
    必须限制执行时间，否则一个模板就能让解析服务卡死。
    """
    if not pattern or len(pattern) > MAX_PATTERN_LEN:
        return None
    try:
        compiled = re.compile(pattern, ALLOWED_FLAGS)
    except re.error:
        return None

    # 用 signal 做超时（仅主线程有效，Celery 子进程场景可接受）
    def _timeout(signum, frame):
        raise TimeoutError("正则执行超时")

    old = signal.signal(signal.SIGALRM, _timeout)
    signal.alarm(timeout_seconds)
    try:
        return compiled.search(text[:MAX_TEXT_LEN])
    finally:
        signal.alarm(0)
        signal.signal(signal.SIGALRM, old)
```

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 示例 | 处理 | 是否重试 |
|---|---|---|---|
| **文件不可用** | M12-03 服务不可用、文件已丢 | 阻断，等待 | 是（3 次） |
| **PDF 损坏** | 文本层提取异常且 OCR 也失败 | `PDF_CORRUPTED` | 否 |
| **PDF 加密** | 无密码 | 等 M12-03 提交密码 | 否 |
| **OCR 不可用** | PaddleOCR 进程挂 | 降级（数字 PDF 仍可解析） | 是（15 分钟后） |
| **模板不匹配** | 新设备、格式变更 | `TEMPLATE_MISMATCH` | 否（需人工建模板） |
| **必填字段缺失** | 模板规则写错 | `FIELD_MISSING` | 否（需修模板） |
| **绑定歧义** | 同名、窗口重叠 | 待确认队列 | 否（需人工） |
| **双通道冲突** | 姓名不一致 | 标红，可提交但需说明 | 否 |
| **推送失败** | M07-04 不可用 | 补偿队列 | 是（10 次） |
| **超时** | 解析 > 120s | 中断并记失败 | 是（3 次） |

**降级总原则：**

```
OCR 挂了     → 数字 PDF 照常解析（85% 业务不受影响）
M12-02 挂了  → 只能凭条匹配，绑定率降到约 30%，告警
M01-09 挂了  → 只存原始文本不结构化，等恢复后重解析
M03-01 挂了  → 用时间窗冗余姓名，正常绑定
M07-04 挂了  → 报告已入库，补偿推送，医生晚点能看到
```

## 附录 E：术语表

| 术语 | 说明 |
|---|---|
| 文本层 | 数字 PDF 内可直接提取的字符，无需 OCR |
| 扫描件 | 图像型 PDF，必须 OCR 才能读出文字 |
| 通道 A | 抽取患者身份信息（姓名/性别/年龄）用于绑定 |
| 通道 B | 抽取检查数据（项目/数值/结论）用于展示 |
| 双通道交叉验证 | A/B 抽出的姓名比对，不一致则标红 |
| 时间窗 | 由 M12-02 产生的"这份报告可能是这个患者的"时间范围 |
| 投递凭条 | 检查完成后生成的凭条，文件名含凭条号可精确绑定 |
| 唯一命中 | 只有一个候选窗口满足全部匹配条件 |
| 歧义 | 多个候选都满足，无法自动判定 |
| 无主文件 | 无法归属到任何检查任务的孤立报告 |
| 模板 | 定义"去哪里找什么字段"的解析规则集合 |
| 回归测试 | 用历史样本批量验证模板命中率 |
| 关键数值字段 | 眼压/CMT/ECD/MD/PSD/AL，必须人工确认 |
| 置信度 | 抽取结果的可信程度（0~1） |
| 幂等 | 同一文件重复派发只解析一次 |
