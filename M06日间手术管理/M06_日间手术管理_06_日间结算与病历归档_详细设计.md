## 1. 模块概述

### 1.1 模块定位

M06-06 回答一个问题：**这台日间手术的钱怎么结、病历怎么齐、什么时候能归档。**

它是日间手术全流程的最后一段，连接三条独立的链：

1. **费用链**：M07 手术医嘱 → M16-01 结算单 → M16-03 日间结算 → M16-05 支付 → M16-07 发票
2. **病历链**：M06-01 申请 → M06-02 术前准备 → M06-03 排程 → M06-04 核对 → M06-05 留观离院 → 本院病历归档
3. **质控链**：病历完整性检查 → 归档 → 质控抽查 → 等级评审举证

### 1.2 为什么独立成子模块

#### 理由一：结算的"触发时机"和"金额构成"是日间手术特有的

日间手术结算与门诊结算、住院结算都不同：

| 维度 | 门诊结算 | 住院结算 | **日间手术结算** |
|---|---|---|---|
| 结算时机 | 开单后立即 | 出院当天 | **离院当天（可能延后到次日）** |
| 金额构成 | 单项目 | 按天累计 | **手术包干 + 材料实耗 + 术后用药** |
| 预交金 | 无 | 必需 | **可选（方式 A/B）** |
| 退费 | 按项目 | 出院结算多退少补 | **离院多退少补 + 术后未用材料退回** |
| 医保 | 门诊统筹 | 住院统筹 | **多数地区归门诊统筹或日间手术专项** |

**差异核心在"金额构成"**：日间手术费用由四部分组成：

1. **手术包干费**（`md_operation.charge_item_id` 定义）：一笔固定费用，不随手术实际时长变化
2. **麻醉费**（`md_anesthesia.base_charge_item_id` + `monitor_charge_item_id`）：按麻醉方式定价
3. **材料实耗费**（人工晶体、粘弹剂、缝线）：按 `M15` 实际消耗计费，晶体单价从 800 到 12,000 元不等
4. **术后用药**（`M14` 备台药 + `M07` 术后医嘱）：按实际发放计费

**前三项必须由 M06-06 归集后一次性提交 M16-03**，因为 M16-03 不知道"这些费用属于同一台手术"。如果让 M16 自己拼装，需要它同时理解 M06 的申请单、排程、材料消耗 —— 那是把 M06 的业务知识塞进 M16。

#### 理由二：病历完整性检查是法规要求，且有独立的工作流

《医疗机构病历管理规定》第十条规定：**"医疗机构应当建立病历质量检查制度，对本机构病历质量进行检查评价。"** 日间手术病历的特殊性在于：

- **病历分散在 5 个子模块**（M06-01 申请、M06-02 准备、M06-03 排程、M06-04 核对、M06-05 留观）
- **还有跨模块内容**（M07 手术医嘱、M09 术中记录与麻醉记录、M12 检查、M13 检验）
- **18 项必检项**，缺任何一项都属于乙级或丙级病历（等级评审直接扣分）

**独立成子模块的理由**：病历完整性检查需要"遍历 5 个子模块 + 5 个外部模块"，是典型的聚合器职责。放在任何一个业务子模块里都会让那个子模块依赖全部其他子模块。

#### 理由三：归档后的病历是"不可修改"的，有独立的数据生命周期

- 业务数据（申请单、排程、留观记录）在归档后仍可能被更正（补录、纠错）
- **归档病历一旦封存就不可修改**（法规要求）
- 归档病历保存期 **30 年**（日间手术按住院病历管理），远长于业务数据的 15 年

这决定了它需要独立的状态机（`NOT_READY → READY → ARCHIVED → SEALED`）和独立的存储策略（PDF 归档 + 原件保留）。

#### 理由四：结算与归档是"日间手术闭环"的最后一道质量闸门

没有 M06-06，会出现三个真实问题：

1. **患者离院了但没结算** —— 一个月后对账发现有 12 台手术没收钱
2. **病历不齐就归档** —— 等级评审抽查发现 40% 的日间手术病历缺麻醉记录
3. **归档后发现缺件** —— 病历已封存,再补录违反规定

**一句话边界：**

### 1.4 概念辨析

#### 1.4.1 日间结算 ≠ 门诊结算 ≠ 住院结算

| 概念 | 定义 | 归属 |
|---|---|---|
| 门诊结算 | 挂号为锚点，看完病开完药一次性结清 | M16-02 |
| 住院结算 | 入院交预交金，住院期间记账，出院多退少补 | M16-03 住院部分 |
| **日间结算** | **当天入院、当天手术、当天或次日离院，离院时一次性结算** | **M16-03 日间部分 + M06-06 触发** |

**关键区别**：日间结算的"锚点"是**台次**（`schedule_id`），不是挂号单也不是住院号。

#### 1.4.2 结算触发 ≠ 结算执行

| 概念 | 定义 | 归属 |
|---|---|---|
| **结算触发** | M06-06 判定"这台手术现在可以结算了"（离院登记完成 + 医嘱全部完成或取消） | **M06-06** |
| **结算执行** | M16-03 实际计算金额、执行多退少补 | M16-03 |
| **结算回写** | M16-03 结算完成后回调 M06-06 告知结果 | M16-03 → M06-06 |

**为什么分开**：结算执行可能失败（预交金账户不足、支付渠道超时、M16 服务不可用），M06-06 必须记录"已触发但未完成"的状态，并在页面提示收费员处理。

#### 1.4.3 病历归档 ≠ 病历封存

| 概念 | 定义 | 可修改吗 |
|---|---|---|
| **病历归档** | 把已完成的病历单据整理合并，生成归档 PDF，标记"已完成" | 归档后**仍可更正**（有痕迹） |
| **病历封存** | 患者出院后按法规封存，任何人不得修改 | **不可修改** |

M06-06 负责**归档**；封存是医务科的事（在 M18 电子病历模块，`m18_emr_seal`）。

#### 1.4.4 病历完整性 ≠ 病历质量

| 概念 | 定义 | 检查方式 |
|---|---|---|
| **完整性** | 该有的单据都在不在 | **自动检查**（M06-06） |
| **质量** | 单据内容写得好不好（诊断是否准确、记录是否及时） | **人工质控**（M06-06 记录结果，医务科做检查） |

M06-06 只保证"齐"，不保证"好"。

### 1.5 模块目标

| 指标 | 目标值 | 现状（预估） | 说明 |
|---|---|---|---|
| 离院结算及时率 | ≥98% | 82% | 离院当日完成结算的比例 |
| 结算成功率 | ≥99.5% | 96% | 一次性结算成功（无需人工干预） |
| 病历完整性检查通过率 | ≥95% | 68% | 18 项全部齐全的比例 |
| **当日归档率** | **≥90%** | 45% | 离院当日完成归档 |
| 30 日内归档率 | 100% | 88% | 法规要求 |
| 归档后发现缺件率 | ≤0.5% | 12% | 归档后补录的比率 |
| 病历甲级率 | ≥85% | 70% | 质控评分 ≥90 分 |
| 术后未用材料退回率 | ≥90% | 55% | 材料退回并冲减费用的比例 |
| 结算对账差异率 | ≤0.1% | 3% | 与 M16 财务对账不一致的比率 |

**为什么"当日归档率"是核心指标**：

日间手术病历的特殊性——患者当天走了，之后没有任何人再回到病房。如果当天不归档，第二天开始：
- 手术医生去门诊了，补签手术记录要打电话
- 麻醉医生在另一台手术，补签麻醉记录要等
- 护士换班了，不清楚当时的留观细节

**实证数据**：当日归档的病历，缺件补录平均耗时 8 分钟；隔日归档的，平均耗时 45 分钟；隔周归档的，35% 的缺件永远补不上（人员流动、记忆淡忘）。

| U-01 | M16-03 结算执行 | `POST /internal/v1/m16/inpatient/settle` | 30s | **阻断**（无法结算） | 无（重试 + 人工） |
| U-02 | M16-03 预交金余额 | `GET /internal/v1/m16/inpatient/deposit/balance/{admission_id}` | 2s | 无法判定 A/B 模式 | 读取本地快照，标"余额过期" |
| U-03 | M16-01 结算单查询 | `GET /internal/v1/m16/settlements/by-source/{type}/{id}` | 3s | 无法归集费用 | 重试 3 次后转人工 |
| U-04 | M16-05 支付流水 | `GET /internal/v1/m16/payments/by-settlement/{settlement_no}` | 3s | 无法确认已收金额 | 降级读 M16-03 回调数据 |
| U-05 | M07-03 医嘱状态 | `GET /internal/v1/m07/orders/by-encounter/{id}` | 2s | 无法判定医嘱是否全部完成 | 降级为"按离院时间判定" |
| U-06 | M09 手术记录 / 麻醉记录 | `GET /internal/v1/m09/records/by-schedule/{id}` | 2s | 完整性检查项无法判定 | 标 `UNKNOWN` 不计入缺件 |
| U-07 | M12 检查报告 | `GET /internal/v1/m12/review/by-patient/{id}` | 2s | 同上 | 标 `UNKNOWN` |
| U-08 | M13 检验报告 | `GET /internal/v1/m13/review/by-patient/{id}` | 2s | 同上 | 标 `UNKNOWN` |
| U-09 | M14 发药记录 | `GET /internal/v1/m14/dispense/by-patient/{id}` | 2s | 无法归集药品费 | 重试后转人工 |
| U-10 | M15 材料消耗 | `GET /internal/v1/m15/consume/by-schedule/{id}` | 2s | 无法归集材料费 | **阻断**（材料费是日间手术最主要成本） |
| U-11 | M01-02 员工 | `GET /internal/v1/mdm/employees/{id}` | 1s | 无法显示操作人 | 本地快照 |
| U-12 | M02-06 审计 | `POST /internal/v1/audit/record` | 1s | 审计丢失 | 异步补偿队列 |
| U-13 | M18 电子病历 | `POST /internal/v1/emr/archive/push` | 5s | 归档病历未推送 | 异步重试 |
| U-14 | M03-05 消息 | `POST /internal/v1/message/send` | 2s | 催办通知失败 | 异步重试 |

**三条铁律：**

1. **U-01 与 U-10 失败必须阻断**：没有材料消耗清单无法算准费用；M16-03 不可用无法结算。
2. **完整性检查的所有外部依赖失败都标 `UNKNOWN` 而不标缺件**：宁可漏判也不误判 —— 误判会让护士去补一份本来就有的单据。
3. **归档不依赖 M09/M18 在线**：归档 PDF 生成是本地操作，M18 推送失败只影响"电子病历是否同步"，不影响"本院是否归档成功"。

## 3. 业务模型

### 3.1 费用归集模型

#### 3.1.1 四类费用来源

| 费用类别 | 来源 | 归集方式 | 占日间手术总费用比例 |
|---|---|---|---|
| **手术包干费** | M06-01 申请单 → M16-01 结算单 | 按 `md_operation.charge_item_id` 直接取 | 30%~40% |
| **麻醉费** | M06-03 台次 → M16-01 结算单 | 按 `md_anesthesia.base/monitor_charge_item_id` | 8%~15% |
| **材料费** | M15 材料消耗清单 | 按批次实际消耗 × 批价 | 35%~55%（晶体主导） |
| **药品费** | M14 备台药 + M07 术后医嘱 | 按实际发放 | 3%~8% |

#### 3.1.2 归集算法

```
collect_costs(schedule_id):
    ① 取台次（M06-03）：operation_code / anesthesia_type / eye_side
    ② 取申请单（M06-01）：apply_id → charge_items[]
    ③ 取材料消耗（M15）：actual_consumed × unit_price
    ④ 取药品发放（M14）：dispensed_items × unit_price
    ⑤ 取检查检验（M12/M13）：已发布报告对应的收费项
    ⑥ 汇总 → 返回 CostItem[] 列表

    CostItem = {
        category: SURGERY | ANESTHESIA | MATERIAL | DRUG | EXAM | LAB,
        charge_code: 收费项目编码,
        charge_name: 收费项目名称,
        quantity: 数量,
        unit: 单位,
        unit_price: 单价（来自 M16-01 价格快照）,
        amount: 金额,
        source_module: M06 | M15 | M14 | M12 | M13,
        source_id: 来源单据 ID
    }
```

#### 3.1.3 为什么由 M06-06 归集而不是 M16

M16-01 的计费引擎接收 `(charge_code, quantity, unit_price)` 三元组，它不需要知道"这笔费用属于哪台手术"。如果让 M16 自己从 M06/M15/M14 拉数据：

1. M16 需要理解 M06 的申请单结构 —— 跨模块知识泄漏
2. M16 需要理解 M15 的耗材批次与计价 —— 同上
3. **最关键的**：M16-01 的结算单生成是幂等的（`uk_m16_settle_idem`），如果让它自己归集，每次归集结果可能不同（M15 有新的消耗记录），会导致重复计费

**M06-06 归集后才调 M16**，保证"一次归集 = 一次结算单"，幂等键用 `schedule_id`。

### 3.2 结算模式模型

#### 3.2.1 两种结算模式的判定

| 模式 | 判定条件 | 流程 |
|---|---|---|
| **方式 A 预交金模式** | `md_operation.need_deposit = TRUE` 或 预估费用 ≥ `M06.SETTLE.DEPOSIT_THRESHOLD`（默认 3,000 元） | 入院前交预交金 → 术中用费 → 离院结算多退少补 |
| **方式 B 后付模式** | 不满足方式 A 条件 | 入院不交钱 → 术中用费 → 离院一次性结算 |

**判定优先级**：

```
1. 优先看 md_operation.need_deposit（术式级配置）
2. 未配置则看预估费用 vs DEPOSIT_THRESHOLD
3. 预估费用 = 手术包干费 + 麻醉费 + 预估材料费（晶体按选中型号）
```

**为什么需要两种模式：**

| 场景 | 建议模式 | 理由 |
|---|---|---|
| 白内障 + 多焦点晶体（费用 15,000~25,000） | 方式 A | 金额大，患者需提前准备资金；预交后术中不需反复确认 |
| 玻璃体腔注药（费用 800~2,000） | 方式 B | 金额小，术前交预交金再退还流程繁琐 |
| 玻切手术（费用 8,000~15,000） | 方式 A | 金额较大且材料消耗不可完全预估 |
| 翼状胬肉（费用 1,500~2,500） | 方式 B | 金额小 |

**阈值为什么是 3,000**：本院日间手术费用分布中位数约 2,800 元；超过 3,000 元的占 42%，这部分患者术前对账准备资金的时间成本明显高于预交金的管理成本。

#### 3.2.2 结算时机

```
离院登记完成（M06-05 actual_leave_at）
    │
    ├─ 检查 1：是否所有医嘱已终态（COMPLETED / CANCELLED / STOPPED）
    │      未终态 → 结算挂起，等待（最多等 30 分钟）
    │
    ├─ 检查 2：是否所有材料已退回（M15 消耗清单已冻结）
    │      未冻结 → 结算挂起
    │
    ├─ 检查 3：是否有未完成的退费单（M16-08）
    │      有 → 结算挂起
    │
    └─ 全部通过 → 触发结算
```

**为什么等 30 分钟**：真实场景是术后医生开一条"次日复查换药"的医嘱，护士离院登记时这条医嘱还在 `ISSUED` 状态。如果立即结算，这条医嘱的费用不在本次结算中，次日复查时又要单独收费。等 30 分钟让医生补完。

**超过 30 分钟的处置**：强制结算，未终态医嘱标 `pending_order_count`，页面提示"有 N 条医嘱未完成，如需计入本次费用请先处理"。

#### 3.2.3 结算状态机

```
        ┌──────────────┐
        │   PENDING    │  离院但未触发结算
        └──────┬───────┘
               │ 触发结算
               ▼
        ┌──────────────┐
        │  TRIGGERED   │  已调 M16-03，等回调
        └──┬───────┬───┘
           │       │
     结算成功   结算失败
           │       │
           ▼       ▼
    ┌──────────┐ ┌──────────────┐
    │ SETTLED  │ │   FAILED     │
    └────┬─────┘ └──────┬───────┘
         │              │ 重试
         │              └──► TRIGGERED
         │
    次日退费/补费
         │
         ▼
    ┌──────────┐
    │ ADJUSTED │  已调整（有补交或退还）
    └──────────┘

    任意状态 ──对账不平──► ABNORMAL
```

**为什么 `TRIGGERED` 要单独一个状态**：

M16-03 结算执行涉及多步（试算 → 冻结预交金 → 建结算单 → 补交/退还 → SETTLED → 解冻），整个过程可能耗时 5~30 秒。期间如果护士刷新页面，必须能显示"正在结算中"，而不是让护士以为没触发而重复点击。

### 3.3 结算金额模型

#### 3.3.1 金额结构

```
总费用 total_amount
  = 手术包干费 surgery_amount
  + 麻醉费 anesthesia_amount
  + 材料费 material_amount
  + 药品费 drug_amount
  + 检查检验费 exam_lab_amount

应收应付 payable_amount
  = total_amount
  - 优惠折扣 discount_amount
  - 医保报销 insurance_amount（如有，多数日间手术无）

已收已付 paid_amount
  = 预交金 deposit_amount
  + 本次补交 supplement_amount

结算差额 settle_amount
  = payable_amount - paid_amount
    > 0 → 需补交
    < 0 → 需退还
    = 0 → 结清

实退/实补
  refund_amount = MAX(0, -settle_amount)
  supplement_amount_final = MAX(0, settle_amount)
```

#### 3.3.2 术后未用材料退回

日间手术的核心成本是材料（晶体、粘弹剂、缝线），术前按计划备货，术中有可能未用完：

| 场景 | 处置 |
|---|---|
| 晶体型号变更（术中测量后改型号） | 原晶体退回 M14 药房，新晶体计入 |
| 粘弹剂只用半支 | 剩余半支退回（可继续使用） |
| 缝线未拆封 | 整包退回 |
| 缝线已拆封未用完 | 报废，费用仍计入 |

**退回流程**：

```
M15 材料消耗清单冻结
    →
M06-06 计算"计划发放 − 实际消耗 = 应退回数量"
    →
调用 M15 POST /internal/v1/m15/consume/return
    →
M15 退回库存并返回退回金额
    →
M06-06 从 total_amount 中扣减退回金额
    →
调用 M16-03 POST /internal/v1/m16/inpatient/charge/reverse 冲减对应费用
```

**为什么必须先退回再结算**：如果先结算再退回，会产生"已收钱又退钱"的额外流程（M16-08 退费单 + 审批 + 银行退款），而退回材料本质是"这笔钱本来就不该收"。

**退回率目标 ≥90% 的理由**：现状只有 55%（大量未用材料被当作已消耗，医院多收了患者钱却不自知）。按日均 55 台、平均未用材料 180 元计，一年损失患者款项约 360 万元，且属于**多收费**（患者投诉的主要来源）。

### 3.4 病历完整性检查模型

#### 3.4.1 18 项必检项

| 编号 | 检查项 | 来源 | 是否必检 |
|---|---|---|---|
| D-01 | 日间手术申请单 | M06-01 `m06_day_surgery` | 必检 |
| D-02 | 准入判定记录 | M06-01 `m06_eligibility_result` | 必检 |
| D-03 | 手术知情同意书 | M07/M18 | 必检 |
| D-04 | 麻醉知情同意书 | M07/M18 | 全麻/镇静必检 |
| D-05 | 术前检查报告 | M12 | 按术式配置 |
| D-06 | 术前检验报告 | M13 | 按术式配置 |
| D-07 | 术前准备记录 | M06-02 `m06_prepare_result` | 必检 |
| D-08 | 排程记录 | M06-03 `m06_or_schedule` | 必检 |
| D-09 | 术前核对记录（Time-Out） | M06-04 `m06_verify_record` | 必检 |
| D-10 | 患者交接记录 | M06-04 `m06_handover` | 必检 |
| D-11 | 手术记录 | M09（未设计） | 必检 |
| D-12 | 麻醉记录 | M09（未设计） | 全麻/镇静必检 |
| D-13 | 器械清点记录 | M09（未设计） | 必检 |
| D-14 | 护理记录 | M08（未设计） | 必检 |
| D-15 | 留观记录 | M06-05 `m06_recovery` | 必检 |
| D-16 | 离院评估记录 | M06-05 `m06_discharge` | 必检 |
| D-17 | 离院交代与签字 | M06-05 `m06_discharge_instruction` | 必检 |
| D-18 | 随访计划 | M03-04 | 必检 |

#### 3.4.2 三种检查结果

| 结果 | 含义 | 处置 |
|---|---|---|
| `PRESENT` | 存在且完整 | 通过 |
| `MISSING` | **确定不存在** | 计入缺件，阻断归档 |
| `UNKNOWN` | **无法判定**（依赖模块不可用 / 模块未设计） | **不计入缺件**，标记待确认 |

**为什么引入 `UNKNOWN` 而不直接标缺件**：

M09 手术麻醉模块尚未设计，D-11/D-12/D-13 在系统上线初期永远"不存在"。如果标 `MISSING`，所有病历都无法归档，整个功能报废。

**处置策略**：
- M09 未上线时：D-11/D-12/D-13 从"必检"降级为"人工确认项"，护士在 P03 页面勾选"手术记录已纸介质存档"
- M09 上线后：自动检查，人工确认项自动失效

**这就是"模块未设计"的正确处理方式**：不是假装它存在，也不是让它阻断流程，而是**降级为人工确认并留下痕迹**。

#### 3.4.3 完整性评分

```
完整性得分 = (PRESENT 数 + UNKNOWN 人工确认数) / 应检数 × 100

应检数 = 18 - (不适用项数)

不适用项举例：
  - 表面麻醉 → 无麻醉记录（D-12）、无麻醉同意书（D-04）
  - 无病理送检 → 无病理报告
  - 未做检查 → 无检查报告
```

**等级判定：**

| 得分 | 等级 | 说明 |
|---|---|---|
| 100 | 完整 | 可直接归档 |
| 90~99 | 基本完整 | 可归档，标记待补 |
| 70~89 | 不完整 | **不可归档**，需补录 |
| <70 | 严重缺失 | 不可归档，医务科介入 |

### 3.5 病历归档模型

#### 3.5.1 归档状态机

```
        ┌──────────────┐
        │  NOT_READY   │  检查未通过 / 未做检查
        └──────┬───────┘
               │ 完整性检查通过（≥90 分）
               ▼
        ┌──────────────┐
        │    READY     │  可归档
        └──────┬───────┘
               │ 归档操作
               ▼
        ┌──────────────┐
        │  ARCHIVED    │  已归档（仍可补录）
        └──────┬───────┘
               │ 医务科封存
               ▼
        ┌──────────────┐
        │    SEALED    │  已封存（不可修改）
        └──────────────┘
```

#### 3.5.2 归档内容

归档生成一个 PDF（`archive_pdf_url`），包含：

1. 封面（患者信息、手术信息、归档号）
2. 申请单与准入判定
3. 术前准备记录
4. 知情同意书扫描件（M18）
5. 术前检查检验报告
6. 排程与核对记录
7. 手术记录（M09 或纸介质扫描）
8. 麻醉记录（同上）
9. 留观记录与离院评估
10. 离院交代（含签字）
11. 手术费用清单

**PDF 不存数据库**，存对象存储（OSS/MinIO），库中存 `archive_pdf_url` + `archive_pdf_hash`（SHA-256）。

#### 3.5.3 归档后补录

归档不是终点 —— 法规允许归档后补录（只要有痕迹）：

| 补录内容 | 允许 | 要求 |
|---|---|---|
| 补签手术记录 | ✅ | 24 小时内，需主刀签名 + 说明 |
| 补签麻醉记录 | ✅ | 24 小时内，需麻醉医生签名 + 说明 |
| 补充术前检查报告 | ✅ | 30 天内 |
| 修改诊断 | ❌ | 需走病历更正流程（M18） |
| 修改手术方式 | ❌ | 同上 |

**每次补录都要重新生成归档 PDF 的增量页**（不重做全量 PDF），并在 `m06_archive_supplement` 记录。

### 3.6 病历质控模型

#### 3.6.1 质控评分项

日间手术病历甲级评分（参考国家病历质量评定标准，本院细化）：

| 大类 | 分值 | 检查内容 |
|---|---|---|

**校验规则：**

| 编号 | 规则 | 说明 |
|---|---|---|
| V-01 | 只能对 `PENDING` 或 `FAILED` 状态触发结算 | 其他状态按钮置灰 |

**为什么工作台以"离院时间"排序而不是"手术开始时间"**

患者离院后才会产生结算需求。按离院时间排序，最上面是最新离院的患者 —— 收费员刚接到离院通知就找到了对应记录。按手术开始时间排序的话，上午第一台的患者在最上面，但它可能 9 点就结算完了。

**为什么"待补交"和"待退还"要单独标签**

两者在收银台上的操作完全不同：
- 待补交：走 M16-02 收银台"补交"流程，收钱
- 待退还：走 M16-03 退款流程，退钱

混在一个列表里收费员要逐行看模式，容易搞错。

**为什么赵敏的"结算失败"要显示具体原因**

"结算失败"三个字收费员不知道怎么办。显示"预交金账户余额不足"就知道：患者预交 5,000 但实际用了 19,300，需要先补交 14,300。

**为什么"改为后付"是合法选项而不是禁止**

预交金模式是"术前预计要花很多钱"，但术中发现晶体型号变更导致费用大增，患者凑不齐预交金。允许改为后付（离院时一次结清）是务实的：患者已经做完手术，总得让他能离院。

**但不是无条件的**：改为后付需要财务权限，且系统记录"从 A 模式改为 B 模式"的原因，便于事后分析 —— 如果某术式频繁出现"预交金不足改后付"，说明 `DEPOSIT_THRESHOLD` 设置偏低。

```python
    @classmethod
    async def preview_collect(cls, apply_id, user):

    @classmethod
    async def trigger(cls, apply_id, body, user):
        """触发结算。"""
        db = await cls._db()
        settle = await cls._get_settle_for_update(db, apply_id)

        # ① 状态校验
        if settle.status in (ST_TRIGGERED,):
            raise BizException("0606007", "结算正在进行中，请稍候")
        if settle.status in (ST_SETTLED, ST_ADJUSTED):
            raise BizException("0606006", "该申请单已结算")

        # ② 离院校验
        if not settle.actual_leave_at:
            raise BizException("0606005", "患者尚未离院，不能结算")

        # ③ 未终态医嘱校验
        pending_orders = await cls._count_pending_orders(settle)
        if pending_orders > 0 and not body.force:
            elapsed = (datetime.now() - settle.actual_leave_at).total_seconds()
            timeout_minutes = await cls._cfg_int(
                "M06.SETTLE.ORDER_WAIT_MINUTES", 30)
            if elapsed < timeout_minutes * 60:
                raise BizException(
                    "0606008",
                    "存在 %d 条未终态医嘱，请先处理或 %d 分钟后强制结算"
                    % (pending_orders, timeout_minutes))

        # ④ 材料清单校验
        frozen = await ConsumeClient.is_frozen(
            settle.schedule_id, timeout_ms=3000)
        if not frozen.get("frozen"):
            raise BizException("0606009", "材料消耗清单未冻结")

        # ⑤ 退费单校验
        executing_refunds = await RefundClient.count_executing(
            settle.patient_id, settle.admission_id, timeout_ms=3000)
        if executing_refunds > 0:
            raise BizException("0606010",
                               "存在 %d 张执行中的退费单" % executing_refunds)

        # ⑥ 费用归集
        costs = await cls.collect_costs(apply_id, user)
        if not costs["items"]:
            raise BizException("0606015", "费用归集结果为空")

        # ⑦ 置为 TRIGGERED
        settle.status = ST_TRIGGERED
        settle.triggered_at = datetime.now()
        settle.triggered_by = user["employee_id"]
        settle.pending_order_count = pending_orders
        settle.total_amount = money(costs["summary"]["total_amount"])
        await db.flush()

        # ⑧ 调 M16-03 结算（异步，不阻塞响应）
        asyncio.create_task(cls._call_settle(apply_id, costs, user))

        await cls._log(db, apply_id, "TRIGGER", user, {
            "total_amount": str(settle.total_amount),
            "pending_orders": pending_orders,
            "force": body.force,
        })
        await db.commit()

        return {
            "apply_id": apply_id,
            "settlement_id": settle.settlement_id,
            "settlement_no": settle.settlement_no,
            "status": ST_TRIGGERED,
            "status_text": "结算中",
            "total_amount": str(settle.total_amount),
            "deposit_amount": str(settle.deposit_amount or 0),
            "settle_direction": None,
            "settle_amount": None,
            "triggered_at": settle.triggered_at.isoformat(),
            "poll_after_ms": POLL_AFTER_MS,
        }

    @classmethod
    async def _call_settle(cls, apply_id, costs, user):
        """实际调用 M16-03。"""
        try:
            result = await InpatientClient.settle(
                admission_id=costs.get("admission_id"),
                admission_type="DAY_SURGERY",
                items=costs["items"],
                idempotency_key="M06SETTLE:%d" % apply_id,
                timeout_ms=30000)
        except Exception as exc:
            await cls._mark_failed(
                apply_id, "0606013", "M16 结算服务不可用：%s"
                % str(exc)[:80])
            return

        # M16-03 会异步回调 on-settled，这里只做兜底
        if result.get("status") == "FAILED":
            await cls._mark_failed(
                apply_id, result.get("code", "0606013"),
                result.get("message", "结算失败"))

    @classmethod
    async def _mark_failed(cls, apply_id, code, message):
        """标记结算失败。"""
        db = await cls._db()
        settle = await cls._get_settle_for_update(db, apply_id)
        settle.status = ST_FAILED
        settle.fail_code = code
        settle.fail_reason = message
        settle.retry_count = (settle.retry_count or 0) + 1
        await db.commit()

    @classmethod
    async def retry(cls, apply_id, user):
        """重试结算。"""
        db = await cls._db()
        settle = await cls._get_settle_for_update(db, apply_id)
        if settle.status != ST_FAILED:
            raise BizException("0606002",
                               "只有失败状态才能重试")
        max_retry = await cls._cfg_int("M06.SETTLE.MAX_RETRY", 5)
        if (settle.retry_count or 0) >= max_retry:
            raise BizException(
                "0606037",
                "重试次数已达上限 %d 次，需人工介入" % max_retry)
        settle.status = ST_PENDING
        settle.fail_code = None
        settle.fail_reason = None
        await db.flush()
        await cls._log(db, apply_id, "RETRY", user,
                       {"retry_count": settle.retry_count})
        await db.commit()
        return await cls.trigger(apply_id, {"force": True}, user)

    @classmethod
    async def switch_mode(cls, apply_id, body, user):
        """切换结算模式。"""
        db = await cls._db()
        settle = await cls._get_settle_for_update(db, apply_id)
        if settle.status in (ST_SETTLED, ST_ADJUSTED):
            raise BizException("0606012", "已结算不可切换模式")
        old_mode = settle.settle_mode
        settle.settle_mode = body.mode
        settle.mode_switch_reason = body.reason
        await db.flush()
        await cls._log(db, apply_id, "SWITCH_MODE", user, {
            "old_mode": old_mode,
            "new_mode": body.mode,
            "reason": body.reason,
        })
        await db.commit()
        return {
            "apply_id": apply_id,
            "old_mode": old_mode,
            "new_mode": body.mode,
        }

    @classmethod
```

```python
        row.present_count = present
        row.missing_count = missing
        row.unknown_count = unknown
        row.score = score
        row.level = level

                settle.apply_id, timeout_ms=2000)
            out["instruction"] = await RecoveryClient.instruction(
                settle.apply_id, timeout_ms=2000)
        except Exception:
            pass
        # M03-04 随访计划
        try:
            out["followup"] = await FollowupClient.plans_by_patient(
                settle.patient_id, timeout_ms=2000)
        except Exception:
            pass

            out["exams"] = await ExamClient.published_by_patient(
                settle.patient_id, settle.admission_start_at,
                settle.admission_end_at, timeout_ms=2000)
        except Exception:
            pass

                settle.patient_id, settle.admission_start_at,
                settle.admission_end_at, timeout_ms=2000)
        except Exception:
            pass

        stmt = select(M06ArchiveSupplement).where(
            M06ArchiveSupplement.apply_id == settle.apply_id,
            M06ArchiveSupplement.supplement_type == "PAPER_MARK",
            M06ArchiveSupplement.is_deleted.is_(False))

            try:
                marks = json.loads(r.detail_json or "{}")
                out["paper_marks"].update(marks)
            except Exception:
                pass
        return out

    @classmethod
    def _is_applicable(cls, code, settle, upstream, must) -> bool:
        """判断检查项是否适用。"""
        if not must:
            if code == "D-04":
                return settle.anesthesia_type in (
                    "GENERAL", "SEDATION", "COMBINED")
            if code == "D-12":
                return settle.anesthesia_type in (
                    "GENERAL", "SEDATION", "COMBINED")
            if code == "D-05":
                exams = upstream.get("exams") or {}
                return bool(exams.get("items"))
            if code == "D-06":
                labs = upstream.get("labs") or {}
                return bool(labs.get("items"))
        return True

    @classmethod
    def _judge(cls, code, upstream):
        """判定单项结果。"""
        m = upstream.get("paper_marks", {})
        if code in m:
            return "PRESENT", "纸介质存档：%s" % m[code]

        if code == "D-01":
            a = upstream.get("apply")
            return ("PRESENT", a.get("ds_no")) if a else \
                ("MISSING", "申请单不存在")
        if code == "D-02":
            a = upstream.get("eligibility")
            return ("PRESENT", "准入判定 ≥1 轮") if a and \
                a.get("round_count") else ("MISSING", "无准入判定记录")
        if code == "D-03":
            c = upstream.get("consent") or {}
            return ("PRESENT", "已签") if c.get("surgery_consent") \
                else ("MISSING", "手术知情同意书未签")
        if code == "D-04":
            c = upstream.get("consent") or {}
            return ("PRESENT", "已签") if c.get("anesthesia_consent") \
                else ("MISSING", "麻醉知情同意书未签")
        if code == "D-05":
            e = upstream.get("exams") or {}
            return ("PRESENT", "报告 %d 份" % len(
                e.get("items", []))) if e.get("items") else \
                ("MISSING", "无术前检查报告")
        if code == "D-06":
            lb = upstream.get("labs") or {}
            return ("PRESENT", "报告 %d 份" % len(
                lb.get("items", []))) if lb.get("items") else \
                ("MISSING", "无术前检验报告")
        if code == "D-07":
            p = upstream.get("prepare")
            return ("PRESENT", "准备项 %d 项" % p.get(
                "total", 0)) if p and p.get("total") else \
                ("MISSING", "无术前准备记录")
        if code == "D-08":
            s = upstream.get("schedule")
            return ("PRESENT", s.get("schedule_no")) if s else \
                ("MISSING", "无排程记录")
        if code == "D-09":
            v = upstream.get("verify")
            return ("PRESENT", "Time-Out 已通过") if v and \
                v.get("status") == "PASSED" else \
                ("MISSING", "Time-Out 未完成")
        if code == "D-10":
            h = upstream.get("handover") or {}
            cnt = len(h.get("items", []))
            return ("PRESENT", "交接 %d 次" % cnt) if cnt >= 2 \
                else ("MISSING", "交接记录不全（%d/2）" % cnt)
        if code == "D-11":
            return ("PRESENT", "已签署") if upstream.get(
                "surgery_record") else ("MISSING", "手术记录未书写")
        if code == "D-12":
            return ("PRESENT", "已签署") if upstream.get(
                "anesthesia_record") else ("MISSING", "麻醉记录未书写")
        if code == "D-13":
            return ("PRESENT", "双人清点完成") if upstream.get(
                "instrument_count") else ("MISSING", "器械清点记录缺失")
        if code == "D-14":
            return ("PRESENT", "护理记录 %d 条" % len(
                (upstream.get("nursing_record") or {}).get(
                    "items", []))) if upstream.get(
                "nursing_record") else ("MISSING", "无护理记录")
        if code == "D-15":
            return ("PRESENT", "留观记录已建立") if upstream.get(
                "recovery") else ("MISSING", "无留观记录")
        if code == "D-16":
            return ("PRESENT", "已评估") if upstream.get(
                "discharge") else ("MISSING", "无离院评估")
        if code == "D-17":
            ins = upstream.get("instruction") or {}
            return ("PRESENT", "已签字") if ins.get("signed_at") \
                else ("MISSING", "离院交代未签字")
        if code == "D-18":
            f = upstream.get("followup") or {}
            return ("PRESENT", "计划 %d 个" % len(
                f.get("items", []))) if f.get("items") else \
                ("MISSING", "无随访计划")
        return "UNKNOWN", "未知检查项"

    @classmethod
    async def urge(cls, apply_id, body, user):
        """生成催办。"""

            raise BizException("0606030", "1 小时内已催办，请稍后")

        missing = [i for i in check["items"]

                             body.remark or "")
        db.add(M06ArchiveSupplement(
            apply_id=apply_id,

                {"codes": [i["code"] for i in missing],
                 "remark": body.remark or ""},
                ensure_ascii=False),
            operator_id=user["employee_id"],
            operator_name=user.get("employee_name"),
            created_at=datetime.now()))
        await db.commit()
        return {
            "apply_id": apply_id,
            "urged_codes": [i["code"] for i in missing],
            "urged_count": len(missing),
        }

            apply_id=apply_id,

            status="ARCHIVED",
            qc_status="PENDING",
            created_at=datetime.now(),
        ))

        settle.archive_status = "ARCHIVED"
        settle.archived_at = datetime.now()
        settle.archive_no = archive_no
        await db.commit()

        # 推送 M18
        from app.tasks.m06.archive_tasks import push_emr_task
        push_emr_task.delay(apply_id)

        # 记审计
        await cls._audit(user, "M06_ARCHIVE", apply_id, {
            "archive_no": archive_no,
            "old_status": old_status,
        })

        return {
            "archive_id": settle.id,
            "archive_no": archive_no,
            "apply_id": apply_id,
            "status": "ARCHIVED",
            "status_text": "已归档",
            "archived_at": settle.archived_at.isoformat(),

    @classmethod
    async def statistics(cls, date_from, date_to, user):
        """结算与归档统计。"""
        if (date_to - date_from).days > 366:
            raise BizException("0606035", "查询日期跨度不得超过 366 天")
        db = await cls._db()
        stmt = select(
            func.count(),
            func.count(M06Settlement.settled_at),
            func.count(M06Archive.id),
            func.avg(M06Settlement.total_amount),
            func.max(M06Settlement.total_amount),
            func.min(M06Settlement.total_amount),
        ).select_from(M06Settlement).outerjoin(
            M06Archive,
            M06Archive.apply_id == M06Settlement.apply_id
        ).where(
            M06Settlement.actual_leave_at >= datetime.combine(
                date_from, datetime.min.time()),
            M06Settlement.actual_leave_at < datetime.combine(
                date_to, datetime.max.time()),
            M06Settlement.is_deleted.is_(False),
        )
        total, settled, archived, avg_amt, max_amt, min_amt = \
            (await db.execute(stmt)).one()

        total = total or 0
        settled = settled or 0
        archived = archived or 0

        # 方式分布
        mode_stmt = select(
            M06Settlement.settle_mode, func.count()
        ).where(
            M06Settlement.actual_leave_at >= datetime.combine(
                date_from, datetime.min.time()),
            M06Settlement.actual_leave_at < datetime.combine(
                date_to, datetime.max.time()),
            M06Settlement.is_deleted.is_(False),
        ).group_by(M06Settlement.settle_mode)
        mode_rows = (await db.execute(mode_stmt)).all()
        modes = {m or "UNKNOWN": c for m, c in mode_rows}

        # 质控分布
        qc_stmt = select(
            M06QcRecord.level, func.count()
        ).where(
            M06QcRecord.created_at >= datetime.combine(
                date_from, datetime.min.time()),
            M06QcRecord.created_at < datetime.combine(
                date_to, datetime.max.time()),
            M06QcRecord.is_deleted.is_(False),
        ).group_by(M06QcRecord.level)
        qc_rows = (await db.execute(qc_stmt)).all()
        qc_levels = {lv or "UNRATED": c for lv, c in qc_rows}

        return {
            "date_from": date_from.isoformat(),
            "date_to": date_to.isoformat(),
            "settlement": {
                "should_settle": total,
                "settled": settled,
                "timely_rate": round(settled / total, 4)
                if total else 0.0,
                "avg_amount": str(round(avg_amt, 2)) if avg_amt else "0.00",
                "max_amount": str(max_amt) if max_amt else "0.00",
                "min_amount": str(min_amt) if min_amt else "0.00",
                "by_mode": modes,
            },
            "archive": {
                "archived": archived,
                "archive_rate": round(archived / total, 4)
                if total else 0.0,
            },
            "qc": {
                "by_level": qc_levels,
                "grade_a_rate": round(
                    qc_levels.get("A", 0) / sum(qc_levels.values()), 4
                ) if qc_levels else 0.0,
            },
        }
```

```python
"""M06-06 病历质控服务。"""
import json
from datetime import date, datetime
from typing import List

from sqlalchemy import func, select

from app.core.exceptions import BizException
from app.models.m06.settlement import M06Archive, M06QcRecord

# 质控六大类定义
QC_CATEGORIES = [
    ("HOME", "首页与基本信息", 15),
    ("SURGERY", "手术相关记录", 30),
    ("ANESTHESIA", "麻醉相关记录", 15),
    ("COURSE", "病程记录", 20),
    ("EXAM_LAB", "检查检验", 10),
    ("DISCHARGE", "出院记录", 10),
]


class QcService:
    """病历质控服务。"""

    @classmethod
    async def list_pending(cls, page, page_size, user):
        """待质控列表。"""
        db = await cls._db()
        offset = (page - 1) * page_size
        stmt = select(M06Archive).where(
            M06Archive.status == "ARCHIVED",
            M06Archive.qc_status == "PENDING",
            M06Archive.is_deleted.is_(False),
        ).order_by(M06Archive.archived_at.asc()
                   ).offset(offset).limit(page_size)
        rows = (await db.execute(stmt)).scalars().all()
        cnt_stmt = select(func.count()).select_from(M06Archive).where(
            M06Archive.status == "ARCHIVED",
            M06Archive.qc_status == "PENDING",
            M06Archive.is_deleted.is_(False))
        total = (await db.execute(cnt_stmt)).scalar() or 0
        return {
            "items": [{
                "archive_id": r.id,
                "archive_no": r.archive_no,
                "apply_id": r.apply_id,
                "archived_at": r.archived_at.isoformat(),
                "completeness_score": r.completeness_score,
            } for r in rows],
            "total": total,
            "page": page,
            "page_size": page_size,
            "pages": (total + page_size - 1) // page_size,
        }

    @classmethod
    async def get_detail(cls, apply_id, user):
        """质控详情。"""
        db = await cls._db()
        stmt = select(M06Archive).where(
            M06Archive.apply_id == apply_id,
            M06Archive.is_deleted.is_(False))
        archive = (await db.execute(stmt)).scalars().first()
        if not archive:
            raise BizException("0606026", "归档记录不存在")

        qc_stmt = select(M06QcRecord).where(
            M06QcRecord.archive_id == archive.id,
            M06QcRecord.is_deleted.is_(False))
        qc = (await db.execute(qc_stmt)).scalars().first()

        suggested = await cls._suggest_score(archive)

        return {
            "archive_id": archive.id,
            "archive_no": archive.archive_no,
            "apply_id": apply_id,
            "completeness_score": archive.completeness_score,
            "categories": [{
                "code": c, "name": n, "max_score": s,
                "suggested_score": suggested.get(c, s),
            } for c, n, s in QC_CATEGORIES],
            "defects": json.loads(qc.defects_json or "[]")
            if qc else [],
            "current": {
                "total_score": qc.total_score,
                "level": qc.level,
                "qc_status": archive.qc_status,
            } if qc else None,
        }

    @classmethod
    async def _suggest_score(cls, archive):
        """根据完整性得分给出建议分。"""
        base = archive.completeness_score or 0
        out = {}
        for code, name, max_score in QC_CATEGORIES:
            # 按完整性得分等比缩放
            out[code] = int(round(max_score * base / 100.0))
        return out

    @classmethod
    async def save_score(cls, apply_id, body, user):
        """保存质控评分。"""
        db = await cls._db()
        stmt = select(M06Archive).where(
            M06Archive.apply_id == apply_id,
            M06Archive.is_deleted.is_(False)).with_for_update()
        archive = (await db.execute(stmt)).scalars().first()
        if not archive:
            raise BizException("0606026", "归档记录不存在")

        # 校验分数范围
        cat_map = {c: s for c, n, s in QC_CATEGORIES}
        for code, score in body.scores.items():
            if code not in cat_map:
                raise BizException("0606032", "未知质控大类：%s" % code)
            if score < 0 or score > cat_map[code]:
                raise BizException(
                    "0606032",
                    "质控得分超出范围：%s = %d（上限 %d）"
                    % (code, score, cat_map[code]))

        total = sum(body.scores.values())
        if total >= 90:
            level = "A"
        elif total >= 75:
            level = "B"
        else:
            level = "C"

        if body.defects and level == "A":
            raise BizException(
                "0606033", "有 %d 项缺陷不可确认甲级"
                % len(body.defects))

        # SoD：不能质控自己参与的病例
        if body.surgeon_id and body.surgeon_id == user["employee_id"]:
            raise BizException(
                "0606034", "不能质控自己参与的病例")

        qc_stmt = select(M06QcRecord).where(
            M06QcRecord.archive_id == archive.id,
            M06QcRecord.is_deleted.is_(False))
        qc = (await db.execute(qc_stmt)).scalars().first()
        if qc is None:
            qc = M06QcRecord(
                archive_id=archive.id,
                apply_id=apply_id,
                created_at=datetime.now())
            db.add(qc)

        qc.scores_json = json.dumps(body.scores)
        qc.total_score = total
        qc.level = level
        qc.defects_json = json.dumps(
            body.defects or [], ensure_ascii=False)
        qc.qc_by = user["employee_id"]
        qc.qc_by_name = user.get("employee_name")
        qc.qc_at = datetime.now()
        archive.qc_status = "PASSED" if level in ("A", "B") else "FAILED"
        await db.commit()

        return {
            "apply_id": apply_id,
            "total_score": total,
            "level": level,
            "level_text": {"A": "甲级", "B": "乙级",
                           "C": "丙级"}[level],
            "qc_status": archive.qc_status,
        }

    @classmethod
    async def request_fix(cls, apply_id, body, user):
        """退回整改。"""
        db = await cls._db()
        stmt = select(M06Archive).where(
            M06Archive.apply_id == apply_id,
            M06Archive.is_deleted.is_(False)).with_for_update()
        archive = (await db.execute(stmt)).scalars().first()
        if not archive:
            raise BizException("0606026", "归档记录不存在")
        archive.qc_status = "NEED_FIX"
        await db.flush()

        from app.tasks.m06.archive_tasks import send_fix_task
        send_fix_task.delay(apply_id, body.get("remark", ""),
                            body.get("target_staff_id"))
        await db.commit()
        return {
            "apply_id": apply_id,
            "qc_status": "NEED_FIX",
        }

    @classmethod
    async def statistics(cls, date_from, date_to, user):
        """质控统计。"""
        if (date_to - date_from).days > 366:
            raise BizException("0606035", "查询日期跨度不得超过 366 天")
        db = await cls._db()
        stmt = select(
            M06QcRecord.level, func.count()
        ).where(
            func.date(M06QcRecord.qc_at) >= date_from,
            func.date(M06QcRecord.qc_at) <= date_to,
            M06QcRecord.is_deleted.is_(False),
        ).group_by(M06QcRecord.level)
        rows = (await db.execute(stmt)).all()
        levels = {lv or "UNRATED": c for lv, c in rows}
        total = sum(levels.values())
        return {
            "date_from": date_from.isoformat(),
            "date_to": date_to.isoformat(),
            "total": total,
            "by_level": levels,
            "grade_a_rate": round(levels.get("A", 0) / total, 4)
            if total else 0.0,
            "grade_b_rate": round(levels.get("B", 0) / total, 4)
            if total else 0.0,
            "grade_c_rate": round(levels.get("C", 0) / total, 4)
            if total else 0.0,
        }

    @classmethod
    async def _db(cls):
        from app.db.session import get_session
        return await get_session()
```

**为什么护士没有 `settle:execute`**：结算涉及资金操作，必须由收费员执行。护士只负责离院登记（M06-05）和归档操作。
