## 1. 模块概述

### 1.1 模块定位

M06-04 回答一个问题：**「现在这一分钟，把这位患者的这只眼，交给这位医生，可以吗？」**

它是日间手术全流程中**唯一一个"必须有人当场签字才能继续"的环节**。前面三个子模块（申请准入、术前准备、排程）都是"事前判断"，M06-04 是"**现场确认**"。

```
患者到院
   │
   ▼
┌──────────────────────────────────────────────────────────────────────────┐
│  M06-04 术前核对与患者交接（三次核对 + 两次交接）                          │
│                                                                          │
│  ① 病房核对（Ward Verification）                                          │
│     护士 + 患者共同确认：身份 / 术式 / 术眼 / 腕带 / 准备项 / 同意书        │
│     → 签「病房核对单」                                                    │
│                              │                                            │
│                              ▼                                            │
│  ② 交接一：日间病房 → 手术室（Handover A）                                 │
│     病房护士 交给 手术室巡回护士：患者 / 病历 / 影像 / 晶体 / 药品          │
│     → 双方电子签名，物品逐项勾选                                          │
│                              │                                            │
│                              ▼                                            │
│  ③ 手术间三方核对（Time-Out）                                             │
│     手术医生 + 麻醉医生 + 巡回护士 + 患者，在手术间内、麻醉前               │
│     共同确认：患者身份 / 术式 / 术眼 / 部位标记 / 体位 / 器械 / 特殊用药     │
│     → 三方电子签名（法规强制）                                            │
│                              │                                            │
│                              ▼                                            │
│  ④ 交接二：手术室 → 复苏室（Handover B）                                  │
│     巡回护士 交给 复苏护士：患者 / 术中情况 / 用药 / 标本 / 植入物           │
│     → 双方电子签名                                                        │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
   │
   ▼
M06-05 术后复苏与离院评估
```

**一句话边界**：M06-04 只管「核对与交接」这个过程及其证据链，不判断能不能手术（方案有没有问题归主刀），不判断准备是否完成（归 M06-02），不做术中记录（归 M09）。

### 1.2 为什么独立成子模块

| 理由 | 说明 |
|---|---|
| **法规强制、飞检必查** | 《医疗质量安全核心制度要点》第十五条（手术安全核查制度）、《患者安全目标》要求手术安全核查表三时段签署；国家卫健委「手术安全核查」专项检查会抽查纸质或电子记录。无独立记录无从举证 |
| **留痕要求最高** | 一次核对涉及 4 类角色、最多 6 个签名、20+ 个核对项、2 类物品交接。这些证据必须能被单独检索、单独打印、单独作为法律证据导出——混在其他业务表里做不到 |
| **与术前准备是两件事** | M06-02 回答「该准备的是不是都准备好了」（事前，可反复）；M06-04 回答「**此刻**这个人这只眼能不能进手术间」（现场，一次性，不可重来）。一个可以提前一天完成，一个只能在术前 30 分钟做 |
| **错眼、错人、错术式是眼科最严重的可预防事件** | 眼科手术术后无法"重做"（晶体已植入、视网膜已处理）。错眼事故对患者是不可逆的。M06-04 是最后一关 |
| **交接物品有实物约束** | 人工晶体、生物羊膜、特殊药品都是「实物随人走」，丢失一次就是几千到几万元损失 + 手术无法进行。必须有逐项签收 |

### 1.3 与相邻子模块分工

| 能力 | M06-02 术前准备 | **M06-04 术前核对** | M06-03 排程 |
|---|---|---|---|
| 判断「准备项做完了吗」 | ✅ 唯一责任 | ❌ 只读取结论 | ❌ |
| 判断「能不能进手术间」 | ❌ 给就绪结论供参考 | ✅ 唯一责任（现场判定） | ❌ |
| 分配手术间与台次 | ❌ | ❌ 只读取 | ✅ 唯一责任 |
| 腕带打印与激活 | ❌ | ✅ 唯一责任 | ❌ |
| 术眼标记确认 | ❌（只看标记是否做过） | ✅ 核对标记**是否与申请单一致** | ❌ |
| 三方 Time-Out 签署 | ❌ | ✅ 唯一责任 | ❌ |
| 物品交接签收 | ❌ | ✅ 唯一责任 | ❌ |
| 术中记录 | ❌ | ❌ | ❌ 归 M09 |

**一句话分工**：M06-02 是「准备好没有」，M06-03 是「排在哪里」，M06-04 是「现在能不能交付」。

### 1.4 概念辨析

#### 1.4.1 核对 ≠ 检查

- **核对（Verification）**：确认「文件上写的东西」与「眼前的事实」是否一致。护士拿着申请单问患者「您是张伟吗？做的是左眼白内障吗？」——这是对照，不是判断。
- **检查（Examination）**：用专业手段发现新问题。测血压、听心肺、看瞳孔。

M06-04 只做核对。发现新问题（如患者发烧）→ 记录异常 → 交给医生判断（可能触发 M06-02 的异常处置）。

#### 1.4.2 三方核对 vs 四方核对

| 名称 | 参与方 | 场景 |
|---|---|---|
| **三方核对** | 手术医生 + 麻醉医生 + 巡回护士 | 《手术安全核查制度》标准要求 |
| **四方核对** | 三方 + **患者本人**（或法定代理人） | 本院加严要求，尤其眼科——**术眼必须患者自己确认** |

**为什么眼科要加患者本人**：眼科手术术眼左右极易混淆（两只眼睛都在脸上，同一术式）。患者是唯一能在术前最后确认「医生说做左眼」的人。若患者无法确认（全麻、意识不清、儿童、认知障碍）→ 法定代理人确认，并在记录中注明代理人关系。

#### 1.4.3 交接 ≠ 核对

- **核对**：确认「人对了、眼对了、方案对了」。
- **交接（Handover）**：确认「**责任转移**」——从这一刻起，这个患者归谁负责。

交接必须包含**责任转移声明**和**物品清单**。M06-04 有两次交接：
- 交接一：日间病房护士 → 手术室巡回护士（患者 + 病历 + 影像 + 晶体 + 药品）
- 交接二：手术室巡回护士 → 复苏护士（患者 + 术中情况 + 标本 + 植入物）

#### 1.4.4 腕带 vs 手写标识

腕带是患者身份的唯一电子凭证，包含：姓名、性别、年龄、住院号（`admission_no`）、条码（含 patient_id 与 admission_id）。**扫描腕带 = 确认身份**，不允许手输住院号替代（手输会打错）。

### 1.5 模块目标

| 指标 | 目标值 | 现状 |
|---|---|---|
| 病房核对完成率 | 100% | 纸质核对表，偶有漏签 |
| 三方核对（Time-Out）完成率 | 100% | 纸质核查表，抽查缺席约 15% |
| 电子签名齐全率 | 100% | 0%（全纸质） |
| 术眼一致率（申请单 ↔ 核对单 ↔ 患者确认） | 100% | 无系统校验，历史发生过 1 次错眼 |
| 物品交接签收率 | 100% | 晶体偶尔口头交接 |
| 交接耗时（病房 → 手术室） | ≤ 5 分钟 | 约 10~15 分钟（找病历、找晶体） |
| 核对异常拦截率 | 100% | 无系统拦截 |
| 核对记录可追溯年限 | ≥ 15 年 | 纸质存放 3 年 |

### 2.4 依赖清单与失败影响

| 依赖 | 用途 | 失败影响 | 降级策略 |
|---|---|---|---|
| M06-01 申请单 | 术式/术眼/患者 | 无法开始核对 | **阻断**（无申请单不能核对） |
| M06-03 排程 | 台次上下文 | 无法定位核对场景 | **阻断**（无排程不能核对） |
| M06-02 就绪结论 | 一个核对项 | 该项标 `NOT_EVALUATED` | 手工确认 + 告警 |
| M03-01 患者信息 | 腕带与身份核对 | 用申请单快照 | 降级放行 + 标记 |
| M01-02 员工资质 | 签署人角色校验 | 手工确认角色 | 降级 + WARN |
| M18 同意书状态 | 同意书核对项 | 该项标 `NOT_EVALUATED` | 手工确认 + 纸质件拍照 |
| M09 手术麻醉 | Time-Out 完成后放行 | 无法通知 | 重试队列 + 电话通知 |

**核心判据**：M06-04 的两个核心依赖（申请单、排程）**必须阻断**——没有这两样，核对不知道"核对什么"。其余依赖全部可降级到"手工确认 + 留痕"。

**为什么同意书与患者信息可以降级**：核对是人在现场做的。系统查不到同意书状态，护士可以看纸质同意书原件并勾选「已见纸质同意书」，这个勾选也有法律效力（比"系统说签了但实际没签"更可靠）。

## 3. 业务模型

### 3.1 四次核对（三次核对 + 一次交接前核对）的时序模型

```
时刻        T-60min    T-45min     T-30min      T-20min    T-0
            │          │           │            │          │
病房核对     ●──────────┤           │            │          │
（核对 1）   │  5~10min │           │            │          │
            │          │           │            │          │
交接一      │          ●───────────┤            │          │
            │          │  5min     │            │          │
            │          │           │            │          │
进手术间    │          │           ●────────────┤          │
            │          │           │  准备+麻醉前│          │
            │          │           │            │          │
Time-Out    │          │           │            ●──────────┤
（核对 2）  │          │           │            │  5~8min  │
            │          │           │            │          │
开台        │          │           │            │          ●
```

**关键时序约束**
- `T-60min`：患者到院报到（`check-in`），此时**首次扫描腕带**确认身份。
- `T-60 ~ T-45`：病房核对必须有结果。**未通过核对的患者不允许进入手术室**。
- `T-45 ~ T-40`：交接一。**未完成交接的患者，手术室不接收**。
- `T-20`：进入手术间（等候区）。此时做**第二次腕带扫描**（在手术间门口）。
- `T-0`：Time-Out。**必须在麻醉开始前、切皮前完成**。

**为什么 T-60 就要核对**：如果到 T-5 才核对发现术眼不对，已经浪费了 55 分钟准备、占用了台次、患者已经禁食一夜，改期代价极大。早核对 = 早发现 = 有补救时间。

### 3.2 核对项模型

M06-04 的核对项与 M06-02 的准备项不同：

| 维度 | M06-02 准备项 | **M06-04 核对项** |
|---|---|---|
| 时间 | 术前 7 天 ~ 术前 15 分钟 | 术前 60 分钟 ~ 麻醉前 |
| 执行人 | 护士/医生/患者 | **必须两人以上** |
| 记录 | 单项状态（PENDING/DONE/NA/FAILED） | **核对项的类型与判定** |
| 可否事后补 | 可以 | **不可以**（现场行为，事后补无效） |
| 判定 | 完成/未完成 | **一致 / 不一致 / 不适用** |

**核对项三态判定**

| 值 | 中文 | 含义 | 后续 |
|---|---|---|---|
| `MATCH` | 一致 | 文件与事实相符 | 通过 |
| `MISMATCH` | 不一致 | 文件与事实不符 | **阻断**，必须处置 |
| `NA` | 不适用 | 该项与本次手术无关 | 通过（需填原因） |

**为什么不用「已核对/未核对」二态**：护士扫一眼就勾"已核对"是常态，二态无法区分"认真核过且一致"和"随便勾了"。三态强制护士在发现不一致时主动标出来，否则**默认必须选择"一致"**——而选择"一致"这个动作本身有心理成本（要点一下），比"已核对"更有约束力。

**更进一步**：关键核对项（术眼、患者身份、术式）要求护士**输入验证值**而非点选：
- 术眼核对：要求输入「左 / 右」，系统与申请单比对。
- 患者身份核对：要求扫描腕带条码，系统比对 `patient_id`。
- 术式核对：要求复述术式名称前 4 个字，系统比对。

**这是「强制校验」而非「自觉确认」**——点选可以盲选，输入/扫描无法盲输。

### 3.3 核对项清单

#### 3.3.1 病房核对（核对 1，共 14 项）

| 编号 | 核对项 | 类型 | 判定方式 | 关键 |
|---|---|---|---|---|
| `V-01` | 患者姓名 | `IDENTITY` | 扫描腕带 + 患者自述 | ✅ |
| `V-02` | 患者性别年龄 | `IDENTITY` | 目视 + 自述 | ✅ |
| `V-03` | 住院号/就诊号 | `IDENTITY` | 腕带条码 | ✅ |
| `V-04` | 手术术式 | `OPERATION` | 患者复述前 4 字 | ✅ |
| `V-05` | **手术眼别** | `EYE_SIDE` | **患者自述左/右 + 护士目视核对** | ✅✅ |
| `V-06` | 术眼标记 | `EYE_MARK` | 目视标记位置与申请单一致 | ✅✅ |
| `V-07` | 手术侧腕带 | `WRISTBAND` | 扫描腕带确认 | ✅ |
| `V-08` | 术前准备就绪 | `PREP_READY` | 调 M06-02 结论 | ✅ |
| `V-09` | 手术同意书 | `CONSENT` | 调 M18 或见纸质件 | ✅ |
| `V-10` | 麻醉同意书 | `CONSENT` | 调 M18 或见纸质件 | ✅ |
| `V-11` | 禁食情况 | `FASTING` | 患者自述最后进食时间 | ✅✅ |
| `V-12` | 过敏史 | `ALLERGY` | 患者自述 + 病历对比 | ✅ |

**✅✅ 表示「关键项」**：判定为 `MISMATCH` 时**硬阻断**，不允许继续。关键项任何不一致都必须回 M06-02 或 M06-01 处置。

#### 3.3.2 Time-Out（核对 2，共 20 项，分四组）

**A 组：患者与术式（由手术医生主持）**

|---|---|---|---|---|
| `T-01` | 患者身份 | `IDENTITY` | 三方共同看腕带 | 三方 |
| `T-02` | 手术术式 | `OPERATION` | 三方共同看申请单 | 三方 |
| `T-03` | **手术眼别** | `EYE_SIDE` | **三方共同看 + 患者确认** | 三方 + 患者 |
| `T-04` | 术眼标记 | `EYE_MARK` | 手术医生确认标记位置 | 手术医生 |
| `T-05` | 手术部位（眼内具体位置） | `SITE` | 医生说明 | 手术医生 |
| `T-06` | 体位 | `POSITION` | 护士核对体位要求 | 巡回护士 |

**B 组：麻醉（由麻醉医生主持）**

| 编号 | 核对项 | 类型 | 判定方式 | 签署人 |
|---|---|---|---|---|
| `T-07` | 麻醉方式 | `ANESTHESIA` | 麻醉医生确认 | 麻醉医生 |

| `T-11` | 禁食确认 | `FASTING` | 麻醉医生最后确认 | 麻醉医生 |
| `T-12` | 麻醉监测设备 | `EQUIPMENT` | 血氧、心电、血压已连接 | 麻醉医生 |

| 编号 | 核对项 | 类型 | 判定方式 | 签署人 |
|---|---|---|---|---|
| `T-13` | 手术器械包 | `INSTRUMENT` | 器械清点无误 | 器械护士 + 巡回护士 |
| `T-14` | **人工晶体型号与度数** | `IMPLANT` | **三方共同看晶体标签与申请单** | 三方 |
| `T-15` | 显微设备就位 | `EQUIPMENT` | 显微镜、超乳仪、玻切机 | 巡回护士 |
| `T-16` | 特殊器械/耗材 | `MATERIAL` | 生物羊膜、粘弹剂等 | 器械护士 |
| `T-17` | 影像资料就位 | `IMAGING` | 术前检查影像已调出 | 巡回护士 |

| 编号 | 核对项 | 类型 | 判定方式 | 签署人 |
|---|---|---|---|---|
| `T-18` | 预计出血量/特殊风险 | `RISK` | 手术医生说明 | 三方 |
| `T-19` | 抗生素预防用药 | `MEDICATION` | 用药已执行或确定执行时刻 | 三方 |
| `T-20` | 关键事件预案 | `CONTINGENCY` | 应急预案已明确 | 三方 |

**T-14 人工晶体核对是最特殊的一项**：晶体是植入物，型号或度数错 = 患者术后屈光误差 = 需要二次手术取出重新植入。核对流程要求：
1. 巡回护士读申请单上的晶体型号与度数；
2. 器械护士读晶体包装盒上的标签；
3. 手术医生复述两者一致；
4. **三方共同确认后才拆包**；
5. 拆包后将包装盒标签贴入病历（纸质或扫描）。

**这是 M06-04 中唯一要求「三方共读」的核对项**，其余核对项都可以由单方确认。理由是晶体错误率虽低但后果最重。

### 3.4 核对状态机

```
        ┌──────────────┐
        │   PENDING    │  待核对（台次 CONFIRMED 后自动创建）
        └──────┬───────┘
               │ 扫描腕带 + 开始核对
               ▼
        ┌──────────────┐
        │  IN_PROGRESS │  核对中
        └──┬───────┬───┘
           │       │
      全部一致   有 MISMATCH
           │       │
           ▼       ▼
   ┌──────────┐  ┌───────────────┐
   │  PASSED  │  │  ABNORMAL     │
   └────┬─────┘  └───────┬───────┘
        │                │ 处置完成
        │                ▼
        │        ┌──────────────┐
        │        │ IN_PROGRESS  │  （回到核对）
        │        └──────────────┘
        │
        │ 超时未完成（T+15 分钟）
        ▼
   ┌──────────────┐
   │   EXPIRED    │  终态，需重开
   └──────────────┘
```

**状态说明**

| 状态 | 中文 | 可否编辑 | 说明 |
|---|---|---|---|
| `PENDING` | 待核对 | 仅可开始 | 台次确认后自动生成，无需人工创建 |
| `IN_PROGRESS` | 核对中 | 可编辑 | 已开始核对但未提交 |
| `PASSED` | 通过 | **不可编辑** | 全部核对项一致或 NA |
| `ABNORMAL` | 异常 | 可处置 | 存在 MISMATCH，等待处置 |
| `EXPIRED` | 已超时 | **不可编辑** | 超时未完成，需医务科授权重开 |

**为什么 PASSED 不可编辑**：核对记录是法律证据。通过后还能改，等于证据可伪造。**发现问题必须走「异常处置」流程新建一条记录**，原记录保持只读。

**为什么 EXPIRED 需要医务科授权才能重开**：超时说明流程已经脱节（可能是排程变更没通知、可能是护士忘了）。重开记录本身是重要事件，需要有人负责。

### 3.5 交接模型

#### 3.5.1 交接一：日间病房 → 手术室

**发起方**：日间病房护士
**接收方**：手术室巡回护士
**交接内容**：5 类

| 类别 | 项目 | 是否必选 |
|---|---|---|
| `PATIENT` | 患者本人（担架/轮椅/步行） | ✅ 必选 |
| `DOCUMENT` | 病历本、手术申请单、术前准备单 | ✅ 必选 |
| `IMAGING` | 术前 OCT、眼底照相、角膜地形图等 | 按术式 |
| `IMPLANT` | 人工晶体、生物羊膜 | 按术式（`is_implant_surgery`） |
| `MEDICATION` | 术前用药（散瞳药、抗生素） | 按规则 |
| `BELONGINGS` | 随身物品（交给家属或寄存） | 可选 |

**签名要求**：发起方 + 接收方**各签一次**，不可代签。

**物品逐项勾选**：每一类物品下的每个具体条目都要单独勾选。比如 `DOCUMENT` 类下有 3 个条目（病历、申请单、准备单），必须逐个勾。

**为什么逐项勾而不是整类勾**：整类勾会变成"我看了一眼有东西就勾了"。逐项勾时护士必须找到这 3 样东西，找到的动作本身就是核对。

#### 3.5.2 交接二：手术室 → 复苏室

**发起方**：手术室巡回护士
**接收方**：复苏护士
**交接内容**：6 类

| 类别 | 项目 | 是否必选 |
|---|---|---|
| `PATIENT` | 患者（含气道、管路、监护） | ✅ 必选 |
| `INTRAOP_INFO` | 术式、术中情况、出血量、并发症 | ✅ 必选 |
| `MEDICATION` | 术中用药、麻醉用药 | ✅ 必选 |
| `SPECIMEN` | 病理标本（如摘除的晶体、切除组织） | 按需 |
| `IMPLANT` | 植入物（晶体型号批次、IOL 序列号） | 按需 |
| `EQUIPMENT` | 随患者转出的设备（输液泵、监护仪） | 可选 |

**交接二是 M09 术中记录的下游**：术中情况、用药、标本、植入物都来自 M09。M09 未设计期间，由巡回护士在手术间手工录入（M06-04 提供录入界面），M09 上线后改为自动带出。

### 3.6 腕带模型

```
┌──────────────────────────────────────────────┐
│  日间手术  眼科医院                            │
│                                              │
│           张 伟                              │
│          男  68 岁                            │
│                                              │
│  ┌──────────────────────────────────┐        │
│  │ ███ ██ ████ ██ ███ ██ ████ ██   │        │
│  │ ██ ████ ██ ███ ██ ████ ██ ███   │        │
│  └──────────────────────────────────┘        │
│                                              │
│  住院号：DS202610240001                      │
│  床  位：日间 03 床                           │
│  术  眼：**左眼** ← 高亮                     │
│  术  式：白内障超声乳化+人工晶体植入          │
└──────────────────────────────────────────────┘
```

**腕带关键设计**

1. **条码内容**：`patient_id|admission_id|identity_hash`
   - `identity_hash = SHA256(patient_id|admission_id|腕带生成时间戳)` 前 16 位。
   - 加 hash 是为了防伪：有人拿旧腕带换人不扫描 hash 验不出来。

2. **术眼印在腕带上**：这是眼科腕带的特殊之处。一般医院的腕带只有身份信息，眼科腕带额外印术眼并用红框高亮——因为**术眼错误是眼科最高风险**，腕带上有一道显式提示，护士扫腕带时会看到。

3. **腕带必须与申请单同步**：申请单术眼变更 → 腕带必须重打。系统校验：扫描腕带时比对 `eye_side` 与申请单 `eye_side`，不一致 → 拦截。

4. **补打限制**：同一患者腕带补打不超过 3 次，超过需护士长授权。补打次数写入记录，用于分析"为什么老是补打"（打印机问题 / 护士忘记 / 腕带材质差）。

5. **腕带状态**：`ACTIVE`（在用）/ `VOID`（作废）/ `REPLACED`（被新腕带取代）。

### 3.7 异常处置模型

核对出现 `MISMATCH` 时，护士不能简单标记"已处理"就继续——必须选择**处置动作**。

| 处置动作 | 含义 | 对流程影响 | 权限 |
|---|---|---|---|
| `RECORRECT` | 重新核对（实际一致，前次操作失误） | 回到核对，新建核对轮次 | 护士 |
| `UPDATE_APPLY` | 修正申请单（文件错了，事实对） | 阻塞，等 M06-01 修正后再核对 | 医生 + 科主任 |
| `CANCEL` | 取消手术 | 阻塞，回 M06-01 取消流程 | 科主任 + 医务科 |
| `ESCALATE` | 上报异常（无法判断，等上级决定） | 阻塞，等医务科 | 医务科 |
| `DEFER` | 延期（准备不足需补，改期） | 阻塞，回 M06-03 改期 | 科主任 |

**为什么处置动作要建模而不能只写备注**：每种处置的动作不同（重新核对要新建轮次、修正申请单要调 M06-01、取消要回 M06-01 审批链）。只写备注无法驱动下游流程。

**核对轮次模型**：一次台次可能有多次核对，用 `round_no` 区分。
- `round 1`：病房核对
- `round 2`：重核（RECORRECT 后）
- `round 3`：Time-Out 是独立轮次（用 `verify_type` 区分）
- `round 4`：交接一
- `round 5`：交接二

**更精确的做法**：`verify_type` 区分核对类型（`WARD` / `TIMEOUT` / `HANDOVER_A` / `HANDOVER_B`），每个类型下各有 `round_no`，从而 `(schedule_id, verify_type, round_no)` 唯一。

### 3.8 核对记录的不可变性模型

核对记录（`m06_verify_record`）一旦状态变为 `PASSED`，其所有核对项（`m06_verify_item`）**不可修改**。

**实现方式**
1. 应用层：更新时校验状态。
2. **数据库层触发器**：`PASSED` 状态下的项，`UPDATE`/`DELETE` 抛异常。
3. 签名表（`m06_verify_signature`）**只增不删**。

**为什么不用软删除**：核对记录是法律证据，`is_deleted` 字段给了"删掉重来"的口子。改用状态机 + 触发器，删除必须走「作废」状态（`VOID` + 原因 + 审批），且**作废记录仍然可查**。

**校验规则：**

**处置动作分派表：**

| 动作 | 后续流程 | 记录 |
|---|---|---|
| `RECORRECT` | 新建核对轮次（`round_no + 1`），回 P02 | 原轮次标记 `ABNORMAL` 保持可查 |
| `UPDATE_APPLY` | 通知 M06-01 修正，阻塞等回执 | 记录修正前后的值 |
| `CANCEL` | 触发 M06-01 取消流程（科主任+医务科双签） | 记录取消原因 |
| `ESCALATE` | 通知医务科，本台次全部阻塞 | 记录上报时刻 |
| `DEFER` | 触发 M06-03 改期 | 记录改期原因 |

| 编号 | 规则 | 说明 |
|---|---|---|
| `V-34` | 处置说明 ≥ 20 字 | 强制详细 |
| `V-35` | 关键项异常只能选 `UPDATE_APPLY` / `CANCEL` / `ESCALATE` / `DEFER` | **不允许 RECORRECT** |
| `V-36` | 处置人必须满足该动作的权限 | 严格角色控制 |
| `V-37` | 处置后原核对记录不可修改 | 只增 |
| `V-38` | 等待超过 30 分钟 → 自动通知护士长与医务科 | 超时升级 |

**为什么关键项异常不允许 `RECORRECT`**：`RECORRECT` 的语义是「前次操作失误」——如果是术眼不一致，说"我们核错了"意味着承认系统里的核对是假的。这在法律上极其危险。关键项异常必须走「修正申请单」或「取消」，让事实与文件真正对齐。

### 6.2 错误码规范

**错误码前缀**：`"0604"` + 三位序号（`0604001` ~ `0604099`）

| 错误码 | 说明 | 触发场景 |
|---|---|---|
| `"0604001"` | 台次不存在或状态不允许核对 | start 时台次非 CONFIRMED/CHECKED_IN |

                passed.append(brief)

            "pending": pending,

            "passed": passed,

    @classmethod
    async def verify_item(
        cls, db: AsyncSession, record_id: int, item_code: str,
        body: Dict, user: Dict,
    ) -> Dict:
        """单项核对。"""
        rec = await cls._get_record(db, record_id)
        if rec.status not in ("IN_PROGRESS", "ABNORMAL"):
            raise BizException(
                "0604007", "核对状态不允许修改：%s" % rec.status)

        result = await db.execute(
            select(M06VerifyItem).where(
                M06VerifyItem.record_id == record_id,
                M06VerifyItem.item_code == item_code,
            )
        )
        it = result.scalar_one_or_none()
        if not it:
            raise BizException("0604008", "核对项不存在：%s" % item_code)
        if not it.editable:
            raise BizException(
                "0604007", "该核对项为自动填充，不可手动修改")

        verdict = body.get("verdict")
        if verdict not in ("MATCH", "MISMATCH", "NA"):
            raise BizException("0604009", "核对判定值非法：%s" % verdict)

        actual = body.get("actual_value")
        na_reason = body.get("na_reason")

        # ① 判定一致性校验
        if verdict == "MISMATCH":
            if not body.get("mismatch_desc"):
                raise BizException(
                    "0604009", "不一致必须填写说明")
        if verdict == "NA" and (not na_reason or len(na_reason) < 5):
            raise BizException("0604009", "不适用必须填写原因（≥5 字）")

        # ② 关键项的强制校验
        if it.is_key and it.item_type == "EYE_SIDE" and actual:
            if actual != it.expected_value:
                verdict = "MISMATCH"
        if it.is_key and it.item_type == "OPERATION" and actual:
            if not actual.startswith(
                    (it.expected_value or "")[:4]):
                verdict = "MISMATCH"

        it.verdict = verdict
        it.actual_value = actual
        it.na_reason = na_reason
        it.mismatch_desc = body.get("mismatch_desc")
        it.verified_by = user["staff_id"]
        it.verified_by_name = user.get("staff_name")
        it.verified_at = datetime.now()

        # ③ MISMATCH 生成异常记录
        if verdict == "MISMATCH":
            abn = M06VerifyAbnormal(
                record_id=record_id,
                schedule_id=rec.schedule_id,
                apply_id=rec.apply_id,
                item_code=item_code,
                item_name=it.item_name,
                expected_value=it.expected_value,
                actual_value=actual,
                mismatch_desc=body.get("mismatch_desc"),
                is_key=it.is_key,
                status="PENDING",
                detected_by=user["staff_id"],
                detected_by_name=user.get("staff_name"),
                detected_at=datetime.now(),
                created_at=datetime.now(),
            )
            db.add(abn)
            rec.status = "ABNORMAL"

        await db.commit()

        return {
            "item_code": it.item_code,
            "verdict": it.verdict,
            "verdict_text": VERDICT_TEXT.get(it.verdict),
            "record_status": rec.status,
        }

    @classmethod
    async def submit(
        cls, db: AsyncSession, record_id: int, body: Any, user: Dict,
    ) -> Dict:
        """提交核对。"""
        rec = await cls._get_record(db, record_id)
        if rec.status not in ("IN_PROGRESS",):
            raise BizException(
                "0604007", "核对状态不允许提交：%s" % rec.status)

        # ① 超时检查
        elapsed = (datetime.now() - rec.started_at).total_seconds() / 60
        timeout_min = await cls._cfg_int(
            db, "M06.VERIFY.TIMEOUT_MINUTES", 60)
        if elapsed > timeout_min:
            rec.status = "EXPIRED"
            await db.commit()
            raise BizException(
                "0604013", "核对已超时（%.0f 分钟），请重新发起" % elapsed)

        # ② 写入核对项
        result = await db.execute(
            select(M06VerifyItem).where(
                M06VerifyItem.record_id == record_id)
        )
        items = {x.item_code: x for x in result.scalars().all()}

        for v in body.verdicts:
            it = items.get(v.item_code)
            if not it:
                continue
            it.verdict = v.verdict
            it.actual_value = v.actual_value or it.actual_value
            it.na_reason = v.na_reason
            it.remark = v.remark
            it.verified_by = user["staff_id"]
            it.verified_by_name = user.get("staff_name")
            it.verified_at = datetime.now()

        # ③ 校验完整性
        null_items = [c for c, x in items.items() if x.verdict is None]
        if null_items:
            raise BizException(
                "0604011", "存在未核对项：%s" % ",".join(null_items[:5]))

        key_mismatch = [
            c for c, x in items.items()
            if x.is_key and x.verdict == "MISMATCH"
        ]
        if key_mismatch:
            raise BizException(
                "0604010", "关键项不一致，不可提交：%s"
                % ",".join(key_mismatch[:5]))

        any_mismatch = [
            c for c, x in items.items() if x.verdict == "MISMATCH"
        ]
        if any_mismatch:
            rec.status = "ABNORMAL"
        else:
            rec.status = "PASSED"
            rec.verified_at = datetime.now()

        rec.match_count = sum(
            1 for x in items.values() if x.verdict == "MATCH")
        rec.mismatch_count = len(any_mismatch)
        rec.na_count = sum(
            1 for x in items.values() if x.verdict == "NA")
        rec.remark = body.remark

        await db.commit()

        # ④ 发事件
        if rec.status == "PASSED":
            from app.tasks.m06_verify import publish_verify_passed
            publish_verify_passed.delay(rec.id)

        return {
            "record_id": rec.id,
            "status": rec.status,
            "status_text": rec.status_text,
            "total_items": len(items),
            "match_count": rec.match_count,
            "mismatch_count": rec.mismatch_count,
            "na_count": rec.na_count,
            "verified_by": user["staff_id"],
            "verified_by_name": user.get("staff_name"),
            "verified_at": datetime.now().isoformat(),
            "next_action": "HANDOVER_A" if rec.status == "PASSED" else None,
            "next_action_text": "下一步：发起交接一"
            if rec.status == "PASSED" else None,
        }

    @classmethod
    async def timeout_sign(
        cls, db: AsyncSession, schedule_id: int, body: Any, user: Dict,
    ) -> Dict:
        """Time-Out 签名。"""
        result = await db.execute(
            select(M06VerifyRecord).where(
                M06VerifyRecord.schedule_id == schedule_id,
                M06VerifyRecord.verify_type == "TIMEOUT",
                M06VerifyRecord.is_deleted.is_(False),
            ).order_by(M06VerifyRecord.round_no.desc()).limit(1)
        )
        rec = result.scalar_one_or_none()
        if not rec:
            raise BizException("0604006", "Time-Out 记录不存在")

        # ① 20 项必须全部核对
        item_result = await db.execute(
            select(func.count()).select_from(M06VerifyItem).where(
                M06VerifyItem.record_id == rec.id,
                M06VerifyItem.verdict.is_(None),
            )
        )
        if item_result.scalar() > 0:
            raise BizException(
                "0604011", "存在未核对项，不可签名")

        # ② 角色与人员校验
        schedule = await ScheduleClient.get_by_id(db, schedule_id)
        if body.signer_role == "SURGEON":
            if body.signer_id != schedule.get("surgeon_id"):
                raise BizException(
                    "0604016", "签名人与排程主刀不一致")
        elif body.signer_role == "ANESTHETIST":
            if body.signer_id != schedule.get("anesthetist_id"):
                raise BizException(
                    "0604016", "签名人与排程麻醉医生不一致")

        # ③ 写签名
        sig = M06VerifySignature(
            record_id=rec.id,
            signer_role=body.signer_role,
            signer_id=body.signer_id,
            signer_name=body.signer_name,
            signature_type=body.signature_type,
            signature_data=body.signature_data,
            signed_at=datetime.now(),
            created_at=datetime.now(),
        )
        db.add(sig)
        await db.commit()

        # ④ 返回当前签名进度
        sig_result = await db.execute(
            select(M06VerifySignature).where(
                M06VerifySignature.record_id == rec.id)
        )
        sigs = sig_result.scalars().all()

        return {
            "record_id": rec.id,
            "signer_role": body.signer_role,
            "signer_name": body.signer_name,
            "signed_at": sig.signed_at.isoformat(),
            "total_signatures": len(sigs),
            "roles": sorted({s.signer_role for s in sigs}),
        }

    @classmethod
    async def timeout_complete(
        cls, db: AsyncSession, schedule_id: int, body: Any, user: Dict,
    ) -> Dict:
        """完成 Time-Out。"""
        result = await db.execute(
            select(M06VerifyRecord).where(
                M06VerifyRecord.schedule_id == schedule_id,
                M06VerifyRecord.verify_type == "TIMEOUT",
                M06VerifyRecord.is_deleted.is_(False),
            ).order_by(M06VerifyRecord.round_no.desc()).limit(1)
        )
        rec = result.scalar_one_or_none()
        if not rec:
            raise BizException("0604006", "Time-Out 记录不存在")
        if rec.status == "PASSED":
            raise BizException("0604012", "Time-Out 已完成不可重复")

        # ① 20 项完整性
        null_result = await db.execute(
            select(func.count()).select_from(M06VerifyItem).where(
                M06VerifyItem.record_id == rec.id,
                M06VerifyItem.verdict.is_(None))
        )
        if null_result.scalar() > 0:
            raise BizException("0604011", "存在未核对项")

        # ② 关键项校验
        item_result = await db.execute(
            select(M06VerifyItem).where(
                M06VerifyItem.record_id == rec.id)
        )
        items = {x.item_code: x for x in item_result.scalars().all()}

        # ③ T-03 患者确认
        if not body.patient_confirmed:
            raise BizException(
                "0604017", "手术眼别必须经患者本人（或代理人）确认")

        # ④ T-14 三方共读
        if items.get("T-14"):
            rb = body.implant_readback
            if not (rb.surgeon_confirmed and rb.scrub_confirmed
                    and rb.circular_confirmed):
                raise BizException(
                    "0604018", "人工晶体必须三方共读确认")

        # ⑤ 四方签名
        sig_result = await db.execute(
            select(M06VerifySignature).where(
                M06VerifySignature.record_id == rec.id)
        )
        sigs = sig_result.scalars().all()
        roles = {s.signer_role for s in sigs}
        required = {"SURGEON", "ANESTHETIST", "CIRCULAR_NURSE"}
        if not required.issubset(roles):
            missing = required - roles
            raise BizException(
                "0604015", "签名不齐全，缺失：%s" % ",".join(missing))
        if body.patient_confirm_by == "SELF":
            required = required | {"PATIENT"}
        if not required.issubset(roles):
            raise BizException(
                "0604015", "签名不齐全，缺失患者确认")

        # ⑥ 麻醉时间校验
        schedule = await ScheduleClient.get_by_id(db, schedule_id)
        if schedule.get("actual_start_at"):
            raise BizException(
                "0604014", "麻醉已开始（%s），Time-Out 不可再完成"
                % schedule["actual_start_at"])

        # ⑦ 状态更新
        rec.status = "PASSED"
        rec.verified_at = datetime.now()
        rec.remark = body.remark
        rec.match_count = sum(
            1 for x in items.values() if x.verdict == "MATCH")
        rec.mismatch_count = sum(
            1 for x in items.values() if x.verdict == "MISMATCH")
        rec.na_count = sum(
            1 for x in items.values() if x.verdict == "NA")
        await db.commit()

        # ⑧ 通知 M09 允许开台
        notified = False
        notified_at = None
        try:
            await SurgeryClient.on_timeout_completed(
                db, schedule_id, rec.id)
            notified = True
            notified_at = datetime.now().isoformat()
        except Exception as e:
            logger.warning(
                "通知 M09 失败：%s", e,
                extra={"module": "M06-04", "action": "NOTIFY_M09_FAIL",
                       "schedule_id": schedule_id})
            from app.tasks.m06_verify import retry_notify_m09
            retry_notify_m09.delay(schedule_id, rec.id)

        logger.info(
            "完成 Time-Out",
            extra={"module": "M06-04", "action": "TIMEOUT_COMPLETE",
                   "record_id": rec.id, "schedule_id": schedule_id,
                   "operator_id": user["staff_id"]},
        )

        return {
            "schedule_id": schedule_id,
            "record_id": rec.id,
            "status": "PASSED",
            "status_text": "Time-Out 已完成",
            "signature_count": len(sigs),
            "signatures": [
                {
                    "role": s.signer_role,
                    "staff_id": s.signer_id,
                    "staff_name": s.signer_name,
                    "signed_at": s.signed_at.isoformat(),
                } for s in sigs
            ],
            "completed_at": datetime.now().isoformat(),
            "m09_notified": notified,
            "m09_notified_at": notified_at,
        }

    @classmethod
    async def dispose(
        cls, db: AsyncSession, record_id: int, body: Any, user: Dict,
    ) -> Dict:
        """处置异常。"""
        rec = await cls._get_record(db, record_id)
        if rec.status != "ABNORMAL":
            raise BizException(
                "0604007", "仅异常状态可处置：%s" % rec.status)

        action = body.action
        action_def = DISPOSE_ACTIONS.get(action)
        if not action_def:
            raise BizException("0604031", "处置动作非法：%s" % action)

        # ① 权限
        user_roles = user.get("roles", [])
        if not any(r in user_roles for r in action_def["roles"]):
            raise BizException(
                "0604028", "无该处置动作的执行权限：%s" % action)

        # ② 说明长度
        if not body.dispose_desc or len(body.dispose_desc.strip()) < 20:
            raise BizException(
                "0604030", "处置说明不足 20 字")

        # ③ 关键项不允许 RECORRECT
        if action == "RECORRECT":
            abn_result = await db.execute(
                select(M06VerifyAbnormal).where(
                    M06VerifyAbnormal.record_id == record_id,
                    M06VerifyAbnormal.status == "PENDING")
            )
            abns = abn_result.scalars().all()
            bad = [a.item_code for a in abns
                   if a.item_code in KEY_ITEMS_NO_RECORRECT]
            if bad:
                raise BizException(
                    "0604029",
                    "关键项异常不允许重新核对：%s" % ",".join(bad))

        # ④ 更新异常记录
        abn_result = await db.execute(
            select(M06VerifyAbnormal).where(
                M06VerifyAbnormal.record_id == record_id,
                M06VerifyAbnormal.status == "PENDING")
        )
        for abn in abn_result.scalars().all():
            abn.status = "DISPOSED"
            abn.dispose_action = action
            abn.dispose_desc = body.dispose_desc
            abn.disposed_by = user["staff_id"]
            abn.disposed_by_name = user.get("staff_name")
            abn.disposed_at = datetime.now()

        # ⑤ 按动作分派
        next_action = None
        if action == "RECORRECT":
            rec.status = "EXPIRED"
            # 提示前端新建轮次
            next_action = "NEW_ROUND"
        elif action == "UPDATE_APPLY":
            rec.status = "ABNORMAL"
            next_action = "WAIT_APPLY_FIX"
            await ApplyClient.request_fix(
                db, rec.apply_id, body.dispose_desc)
        elif action == "CANCEL":
            rec.status = "ABNORMAL"
            next_action = "CANCEL_FLOW"
            await ApplyClient.request_cancel(
                db, rec.apply_id, body.dispose_desc)
        elif action == "ESCALATE":
            rec.status = "ABNORMAL"
            next_action = "WAIT_MEDICAL_AFFAIRS"
            from app.tasks.m06_verify import notify_medical_affairs
            notify_medical_affairs.delay(record_id, body.dispose_desc)
        elif action == "DEFER":
            rec.status = "ABNORMAL"
            next_action = "RESCHEDULE_FLOW"

        await db.commit()

        return {
            "record_id": rec.id,
            "action": action,
            "action_text": action_def["text"],
            "record_status": rec.status,
            "next_action": next_action,
            "disposed_at": datetime.now().isoformat(),
        }

    @classmethod
    async def get_statistics(
        cls, db: AsyncSession, date_from, date_to,
        dept_id: Optional[int], user: Dict,
    ) -> Dict:
        """核对统计。"""
        if (date_to - date_from).days > 366:
            raise BizException("0604038", "查询日期跨度不得超过 366 天")

        stmt = select(
            M06VerifyRecord.verify_type,
            M06VerifyRecord.status,
            func.count().label("cnt"),
        ).where(
            M06VerifyRecord.verify_date >= date_from,
            M06VerifyRecord.verify_date <= date_to,
            M06VerifyRecord.is_deleted.is_(False),
        ).group_by(
            M06VerifyRecord.verify_type,
            M06VerifyRecord.status,
        )
        rows = (await db.execute(stmt)).all()

        by_type: Dict[str, Dict[str, int]] = {}
        for r in rows:
            by_type.setdefault(r.verify_type, {})[r.status] = r.cnt

        total_by_type = []
        for vt, cnts in by_type.items():
            total = sum(cnts.values())
            passed = cnts.get("PASSED", 0)
            total_by_type.append({
                "verify_type": vt,
                "verify_type_text": VERIFY_TYPE_TEXT.get(vt, vt),
                "total": total,
                "passed": passed,
                "abnormal": cnts.get("ABNORMAL", 0),
                "expired": cnts.get("EXPIRED", 0),
                "pending": cnts.get("PENDING", 0)
                + cnts.get("IN_PROGRESS", 0),
                "pass_rate": round(passed / total, 4) if total else 0,
            })

        # 关键项异常统计
        abn_stmt = select(
            M06VerifyAbnormal.item_code,
            M06VerifyAbnormal.item_name,
            func.count().label("cnt"),
        ).where(
            M06VerifyAbnormal.detected_at >= datetime.combine(
                date_from, datetime.min.time()),
            M06VerifyAbnormal.detected_at < datetime.combine(
                date_to + timedelta(days=1), datetime.min.time()),
        ).group_by(
            M06VerifyAbnormal.item_code,
            M06VerifyAbnormal.item_name,
        ).order_by(func.count().desc()).limit(10)
        abn_rows = (await db.execute(abn_stmt)).all()

        return {
            "date_from": date_from.isoformat(),
            "date_to": date_to.isoformat(),
            "by_type": total_by_type,
            "top_abnormal_items": [
                {
                    "item_code": r.item_code,
                    "item_name": r.item_name,
                    "count": r.cnt,
                } for r in abn_rows
            ],
        }

            "ward_status": ward.get("status"),
            "ward_passed": ward.get("status") == "PASSED",
            "timeout_status": timeout.get("status"),
            "timeout_passed": timeout.get("status") == "PASSED",
            "can_proceed": (ward.get("status") == "PASSED"),

    @classmethod
    async def save_config(
        cls, db: AsyncSession, body: Any, user: Dict,
    ) -> Dict:
        """参数保存。"""
        saved = 0
        for item in body.items:
            result = await db.execute(
                select(M06VerifyConfig).where(
                    M06VerifyConfig.param_code == item.param_code,
                    M06VerifyConfig.is_deleted.is_(False))
            )
            cfg = result.scalar_one_or_none()
            if not cfg:
                continue
            if not cfg.is_editable:
                continue
            if cfg.min_value and cfg.max_value:
                try:
                    v = float(item.param_value)
                    if v < float(cfg.min_value) or v > float(cfg.max_value):
                        raise BizException(
                            "0604036", "参数 %s 超出范围 [%s, %s]"
                            % (item.param_code, cfg.min_value,
                               cfg.max_value))
                except (ValueError, TypeError):
                    raise BizException(
                        "0604036", "参数 %s 值非法" % item.param_code)
            cfg.param_value = item.param_value
            cfg.version = cfg.version + 1
            cfg.updated_by = user["staff_id"]
            cfg.updated_at = datetime.now()
            saved += 1

            await redis_client.delete(
                "m06:verify:cfg:%s" % cfg.param_code)

        await db.commit()
        return {"saved": saved}

            return cls._out(existing)

        now = datetime.now()
        wb_no = await cls._next_no(db)

            schedule["patient_id"], schedule["admission_no"], now.isoformat())

        wb = M06Wristband(
            wristband_no=wb_no,
            schedule_id=body.schedule_id,
            apply_id=schedule["apply_id"],
            patient_id=schedule["patient_id"],
            patient_name=schedule["patient_name"],
            gender=schedule.get("patient_gender"),
            age=schedule.get("patient_age"),
            admission_no=schedule["admission_no"],
            bed_no=schedule.get("bed_no"),
            eye_side=schedule["eye_side"],
            operation_name=schedule["operation_name"],
            identity_hash=identity_hash,
            barcode="%s|%s|%s" % (schedule["patient_id"],
                                 schedule["admission_no"], identity_hash),
            print_count=0,
            status="ACTIVE",
            created_by=user["staff_id"],
            created_at=now,
            updated_at=now,
        )

        cls, db: AsyncSession, wristband_id: int, body: Any, user: Dict,

                raise BizException(
                    "0604032",
                    "补打次数已达 %d 次，需护士长授权" % cls.MAX_REPRINT)

        if not body.reason or len(body.reason.strip()) < 10:
            raise BizException("0604032", "补打原因不足 10 字")

        # 作废旧腕带，生成新腕带
        wb.status = "REPLACED"
        wb.void_reason = "补打：%s" % body.reason
        wb.voided_at = datetime.now()

        schedule = await ScheduleClient.get_by_id(db, wb.schedule_id)
        now = datetime.now()
        new_raw = "%s|%s|%s" % (
            wb.patient_id, wb.admission_no, now.isoformat())
        new_hash = hashlib.sha256(
            new_raw.encode("utf-8")).hexdigest()[:16]

        new_wb = M06Wristband(
            wristband_no=await cls._next_no(db),
            schedule_id=wb.schedule_id,
            apply_id=wb.apply_id,
            patient_id=wb.patient_id,
            patient_name=wb.patient_name,
            gender=wb.gender,
            age=wb.age,
            admission_no=wb.admission_no,
            bed_no=wb.bed_no,
            eye_side=wb.eye_side,
            operation_name=wb.operation_name,
            identity_hash=new_hash,
            barcode="%s|%s|%s" % (wb.patient_id, wb.admission_no, new_hash),
            print_count=wb.print_count,
            reprint_from=wb.id,
            status="ACTIVE",
            created_by=user["staff_id"],
            created_at=now,
            updated_at=now,
        )
        db.add(new_wb)
        await db.commit()

        return cls._out(new_wb)

    @classmethod
    def decode(cls, code: str) -> Dict:
        """解析腕带条码。"""
        if not code or code.count("|") != 2:
            raise BizException("0604002", "腕带条码格式非法")
        parts = code.split("|")
        try:
            patient_id = int(parts[0])
        except ValueError:
            raise BizException("0604002", "腕带条码格式非法")
        return {
            "patient_id": patient_id,
            "admission_no": parts[1],
            "identity_hash": parts[2],
        }

                "error_code": "0604003",

                "schedule_admission_no": schedule["admission_no"],
            }
        # ② 术眼（腕带里的术眼由 M06Wristband.eye_side 提供）
        return True, "校验通过", {
            "error_code": None,
            "gender_age": None,

        cls, db: AsyncSession, biz_date, status: Optional[str],
        keyword: Optional[str], user: Dict,
    ) -> Dict:
        """腕带列表。"""
        stmt = select(M06Wristband).where(
            M06Wristband.is_deleted.is_(False))
        if biz_date:
            stmt = stmt.where(
                M06Wristband.created_at >= datetime.combine(
                    biz_date, datetime.min.time()))
            stmt = stmt.where(
                M06Wristband.created_at < datetime.combine(
                    biz_date + timedelta(days=1), datetime.min.time()))
        if status:
            stmt = stmt.where(M06Wristband.status == status)
        if keyword:
            stmt = stmt.where(or_(
                M06Wristband.patient_name.ilike("%%%s%%" % keyword),
                M06Wristband.admission_no.ilike("%%%s%%" % keyword),
            ))
        stmt = stmt.order_by(M06Wristband.created_at.desc()).limit(200)
        rows = (await db.execute(stmt)).scalars().all()
        return {"items": [cls._out(x) for x in rows], "total": len(rows)}

### 6.7 专题：为什么核对要「输入验证值」而不是「点选确认」

**问题**：核对页面完全可以让护士点「已确认」按钮就完成，为什么 M06-04 要求关键项必须输入或扫描？

**点选式的失效模式**

| 阶段 | 护士的行为 | 结果 |
|---|---|---|
| 第 1 天 | 认真看申请单，对照患者姓名、术眼，点确认 | 有价值 |
| 第 30 天 | 手指已经记住位置，点完 14 项不到 20 秒 | 形式主义 |
| 第 90 天 | 一边点一边和别人说话 | 完全不看 |

这不是护士的责任心问题，而是**点选这个动作的心理成本太低**——点错了没有任何后果，点对了也没有任何代价。

**输入式的约束**

| 核对项 | 要求 | 为什么有效 |
|---|---|---|
| 患者身份 | **扫描腕带条码** | 必须找到腕带、必须有扫码枪、必须对准；且系统自动比对，护士无法绕过 |
| 手术术式 | **输入前 4 字** | 必须看申请单、必须打字；打错系统立刻提示 |
| 手术眼别 | **患者自述后选择** | 必须问患者、必须听到回答；选错与申请单不符立刻标红 |
| 禁食情况 | **输入最后进食时间** | 必须问出具体时间；输"已禁食"系统不认 |

**成本与收益**

- 成本：每个核对项多花 3~5 秒，14 项多花约 1 分钟。
- 收益：把「心理上的核对」变成「物理上的校验」。

**代价是值得的**：全院日均 55 台手术，每台多 1 分钟 = 每天多 55 分钟护士工时。但一次错眼事故的代价是：患者永久视力损害 + 医疗纠纷赔偿 30~100 万 + 主刀停牌 + 医院声誉损失。**用 55 分钟/天 换 0 次错眼，任何医院都会选**。

**为什么不是所有项都要求输入**：`V-13 随身物品`、`V-14 身份代理人` 这类项没有客观的"正确答案"，强制输入只会产生垃圾数据。**只在有客观期望值的项上做强制校验**，这是"精准加严"而不是"全面加严"。

| `m06:verify:lock:{apply_id}` | String | 30s | 核对并发锁 |
| `m06:wb:seq:{yyyymmdd}` | String | 172800s | 腕带号序列 |
| `m06:ho:seq:{prefix}:{yyyymmdd}` | String | 172800s | 交接单号序列 |
| `m06:verify:abnormal:cnt` | String | 60s | 异常队列计数 |
| `m06:verify:board:{date}` | String | 30s | 工作台快照 |
| `m06:verify:timeout:{schedule_id}` | Hash | 300s | Time-Out 实时状态 |
| `m06:verify:apply:{apply_id}` | String | 300s | 申请单快照（降级用） |

**容量估算**

| Key | 数量 | 单条大小 | 小计 |
|---|---|---|---|
| 参数缓存 | 20 | 100 B | 2 KB |
| 全参数 Hash | 1 | 2 KB | 2 KB |
| 核对草稿 | 10 并发 | 3 KB | 30 KB |
| 并发锁 | 10 | 100 B | 1 KB |
| 序列 | 3 | 64 B | 192 B |
| 异常计数 | 1 | 64 B | 64 B |
| 工作台快照 | 2 | 20 KB | 40 KB |
| Time-Out 实时 | 5 | 2 KB | 10 KB |
| 申请单快照 | 55 | 1 KB | 55 KB |
| **合计** | | | **约 140 KB** |

**为什么 Time-Out 实时状态要缓存在 Redis**：Time-Out 有 4 个客户端（大屏 + 3 个 Pad）同时操作，如果用 WebSocket 推送，服务端需要维护 4 个连接的状态。把状态放 Redis Hash，各方读同一份，写入时 `HSET` 并发布 `PUBLISH` 通知，比维护连接状态简单得多。

| 任务 | Cron | 说明 |
|---|---|---|
| `job_m06_verify_expire` | `*/5 * * * *` | 超时核对标记为 EXPIRED |
| `job_m06_verify_abnormal_timeout` | `*/10 * * * *` | 异常等待 > 30 分钟通知 |
| `job_m06_verify_board_warmup` | `0 7 * * *` | 工作台缓存预热 |
| `job_m06_verify_timeout_alert` | `*/2 * * * *` | Time-Out 临近开台未完成告警 |
| `job_m06_verify_daily_stat` | `40 1 * * *` | 每日统计推送 M22 |
| `job_m06_verify_clean_draft` | `30 3 * * *` | 清理过期草稿 |
| `job_m06_verify_wristband_check` | `0 8 * * *` | 检查今日腕带是否全部生成 |

**为什么超时检查是 5 分钟粒度**：核对的超时判定是分钟级（`TIMEOUT_MINUTES=60`），但不需要秒级精度。5 分钟扫描一天 288 次，每次查 10 条以内的记录，开销可忽略。1 分钟扫描一天 1440 次显得过密。

**为什么 Time-Out 告警是 2 分钟**：Time-Out 未完成意味着手术不能开台，是**实时阻塞**问题。2 分钟粒度能保证在开台前发现并提醒，1 分钟扫描也没必要（手术开台不会精确到秒）。

**为什么手术医生没有 `execute` 权限**：医生不执行核对，只签署 Time-Out。执行核对是护士的工作（对照文件与事实），医生签署是在核对完成后确认。若医生有 `execute`，会出现"医生自己核对、自己签字"——没有第三人复核，等于没核对。

**为什么系统管理员没有 `query` 权限**：最小权限原则。系统管理员负责部署与备份，不应看到患者姓名、术式、术眼等信息。

| `U-07` | M09 | `POST /internal/v1/m09/surgery/on-timeout-completed` | 完成通知 | 2s | 重试队列（5 次） |
| `U-08` | M09 | `GET /internal/v1/m09/surgery/{schedule_id}` | 术中情况（交接二） | 2s | 手工录入 |
| `U-09` | M02-06 | `POST /internal/v1/audit/record` | 审计 | 1s | 异步补偿 |
| `U-10` | M03-05 | `POST /internal/v1/message/send` | 通知 | 2s | 异步重试 |

**为什么 U-01 与 U-02 必须阻断**：核对的核心就是"核对申请单上写的与眼前的事实"。没有申请单，核对不知道核对什么；没有排程，不知道这个患者今天是不是做这台手术。二者缺一，核对立不住。

### 10.2 对外提供契约

| 编号 | 接口 | 调用方 | 用途 | SLA |
|---|---|---|---|---|
| `P-01` | `GET /internal/v1/m06/verify/status/{apply_id}` | M09、M06-05、M06-06 | 查询核对完成状态 | P95 ≤ 100ms |
| `P-02` | `GET /internal/v1/m06/verify/timout-status/{schedule_id}` | M09（开台前必须校验） | Time-Out 是否完成 | **P95 ≤ 50ms** |
| `P-03` | `POST /internal/v1/m06/verify/on-anesthesia-start` | M09 | 麻醉开始回写 | ≤ 100ms |
| `P-04` | `GET /internal/v1/m06/verify/handover-items/{apply_id}` | M06-05 | 交接清单 | ≤ 100ms |
| `P-05` | `POST /internal/v1/m06/verify/on-apply-changed` | M06-01 | 申请单变更（术眼）回写 | ≤ 100ms |
| `P-06` | `GET /internal/v1/m06/verify/statistics/daily` | M22 | 每日核对统计 | ≤ 300ms |

**P-02 的 SLA 是最严的（≤50ms）**：M09 开台前调用 P-02 校验 Time-Out 是否完成，这个调用在"医生准备切皮"这个关键时刻。若超过 50ms，医生会感知到卡顿。实现上用 Redis 缓存 Time-Out 状态（TTL 300s），缓存命中率 >99%。

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 异常 | 处理 |
|---|---|---|
| **业务校验异常** | 腕带不符、关键项不一致、签名缺失 | 返回错误码，前端提示，**不记录为系统异常** |
| **状态冲突** | 核对已通过再修改、交接重复完成 | 返回错误码 `"0604007"`，提示刷新 |
| **依赖不可用** | M06-01/M06-03 不可用 | 返回 `"0604040"` / `"0604041"`，页面提示"系统繁忙" |
| **依赖降级** | M06-02/M18 不可用 | 项标 `NOT_EVALUATED`，允许手工确认，告警 |
| **硬件异常** | 腕带打印机离线 | 返回 `"0604044"`，提示检查打印机 |
| **并发冲突** | 两人同时操作同一核对 | Redis 锁 + 乐观锁，返回提示"记录已被他人修改" |
| **系统异常** | 数据库连接失败、Redis 不可用 | 返回 `"50000"`，记录 ERROR 日志 + 告警 |

### 11.3 监控指标

| 指标 | 采集方式 | 告警阈值 |
|---|---|---|
| 核对完成率 | 每日 `PASSED / (PASSED+ABNORMAL+EXPIRED)` | < 98% |
| Time-Out 完成率 | 每日 `TIMEOUT PASSED / 应做台次` | < 99% |
| 核对异常率 | `ABNORMAL / 总核对数` | > 3% |
| 关键项异常数 | `is_key=TRUE 的异常数` | > 0（任何一条都告警） |
| 核对平均耗时 | `verified_at - started_at` | > 5 分钟 |
| 交接平均耗时 | `completed_at - started_at` | > 3 分钟 |
| 腕带补打率 | `补打次数 / 总腕带数` | > 10% |
| 麻醉先于 Time-Out | `on_anesthesia_start` 时未完成计数 | > 0（严重告警） |
| P-02 接口延迟 | APM 采集 | P95 > 50ms |
| 依赖降级次数 | 各类降级计数 | 日 > 10 次 |

**「关键项异常数 > 0 即告警」是最严格的**：关键项包括术眼、术眼标记、人工晶体、禁食。任何一次关键项异常说明**已经出现了接近事故的情况**（患者说错了、标记做错了、晶体拿错了），必须当日复盘。

| `DA-07` | 核对记录唯一 | `(apply_id, verify_type, round_no)` 唯一 |
| `DA-08` | 交接唯一 | 同申请同类型仅一个进行中 |
| `DA-09` | 时间戳一致性 | 所有 CHECK 约束生效 |
| `DA-10` | 分区自动创建 | `m06_verify_log` 预建 36 个月 |

### 12.4 安全验收

| 编号 | 验收项 | 标准 |
|---|---|---|
| `SC-01` | 未登录访问 | 返回 `"40100"` |
| `SC-02` | 无权限访问 | 返回 `"40300"` |
| `SC-03` | 越权查他人记录 | 返回 403 或过滤 |
| `SC-04` | SQL 注入防护 | 参数化查询，无拼接 |
| `SC-05` | 签名图片鉴权 | 未登录不可访问 URL |
| `SC-06` | 证据包鉴权 | 下载链接带时效令牌 |
| `SC-07` | 敏感信息脱敏 | 日志不含完整身份证、手机号 |
| `SC-08` | 审计完整性 | 全部关键动作有审计记录 |
| `SC-09` | 腕带防伪 | 条码含 hash，改码后校验失败 |
| `SC-10` | 职责分离 | SoD-01~05 全部生效 |

## 附录 E：术语表

| 术语 | 说明 |
|---|---|
| **Time-Out** | 手术安全核查，麻醉前、切皮前在三方（医生、麻醉、护士）共同参与下核对的环节 |
| **三方核对** | 手术医生、麻醉医生、巡回护士共同核对 |
| **四方核对** | 三方核对 + 患者本人（或法定代理人）确认 |
| **腕带** | 患者身份识别凭证，含姓名、住院号、条码、术眼 |
| **交接** | 责任转移的过程，含患者与物品清单，双方签名 |
| **MISMATCH** | 核对不一致 |
| **NA** | 不适用，该项与本次手术无关 |
| **RECORRECT** | 重新核对，前次操作失误 |
| **术眼标记** | 手术前在术眼上方（一般是上睑外侧）做的物理标记 |
| **共读** | 三方各自朗读核对内容并互相确认 |
| **患者确认** | 患者本人说出的术眼，是独立信源 |
| **EXPIRED** | 核对超时未完成状态 |
| **KEY_ITEMS** | 关键核对项，MISMATCH 时硬阻断 |
