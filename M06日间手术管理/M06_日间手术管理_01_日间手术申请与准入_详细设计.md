## 1. 模块概述

### 1.1 模块定位

M06-01 是日间手术全流程的**入口与闸门**。它回答两个问题：

1. **这个患者能不能做日间手术？**（医学准入）
2. **这位医生有没有资格做这台日间手术？**（资质准入）

**M06-01 的产出物是一张「日间手术申请单」（`m06_day_surgery`）**，它是后续六个子模块的共同锚点。这张单子从「申请」到「结案」贯穿整个流程，状态机横跨 M06 全部七个子模块。

### 1.2 为什么独立成子模块

**理由一：准入判定是安全闸门，与排程是两件完全不同的事。**

排程解决"排得下吗"（资源问题），准入解决"该不该做"（医疗问题）。把两件事放进同一个子模块，会出现两个后果：

- 排程算法为了"提高手术间利用率"，会倾向于放宽准入条件——这是**把商业压力施加到医疗判断上**
- 准入不通过的申请与资源不足的申请混在同一个列表里，无法分别统计"多少人被医学原因拒绝"和"多少人是排不上"

**理由二：准入不通过必须有独立的记录与理由，且要能被追溯。**

一家二级眼科医院日均 30~60 台日间手术。假设申请 60 台、实际做 45 台，剩下 15 台去哪了？可能是：

| 原因 | 归属 | 后果 |
|---|---|---|
| 医学准入不通过（如血压 190/110） | **M06-01** | 转住院或转内科治疗 |
| 主刀资质不足 | **M06-01** | 换主刀 |
| 患者主动放弃 | M06-01 | 记录，随访 |
| 术前准备未完成（检查异常） | M06-02 | 延期 |
| 手术间排不下 | M06-03 | 改期 |
| 患者临时取消 | M06-04 | 记录 |

**如果没有独立的准入记录，"60 台申请只做了 45 台"这个数字永远说不清。**

**理由三：日间手术准入标准是科室级可配置的，不是写死的代码。**

不同医院的日间手术准入标准差异很大：

| 项目 | 宽松标准 | 严格标准 |
|---|---|---|
| 年龄上限 | 无限制 | ≤ 75 岁 |
| 血压 | 收缩压 <180 | 收缩压 <160、舒张压 <100 |
| 血糖 | 空腹 <11.1 | 空腹 <8.0 |
| ASA 分级 | I~III | I~II |
| BMI | <35 | <30 |
| 独眼患者 | 允许 | 禁止（怕双眼都失明） |
| 抗凝药停用 | 停 3 天 | 停 7 天 + INR 复查 |

这些标准要能被医务科随时调整，且**每次调整都要留痕**（因为调整会影响"哪些患者能做"），所以准入规则必须独立成表、独立成页面。

**理由四：与 M01-07 主数据的边界必须清晰。**

M01-07 定义"**手术本身的属性**"（`is_day_surgery` 这个手术能不能做日间），M06-01 定义"**这个患者 + 这个手术 + 这位医生 + 这个时间**"能否组合成一次日间手术。前者是静态知识，后者是动态判定。

### 1.4 概念辨析

#### 1.4.1 日间手术 vs 门诊手术 vs 住院手术

| 维度 | 门诊手术 | 日间手术 | 住院手术 |
|---|---|---|---|
| 定义 | 门诊诊疗室内完成，不做麻醉或仅表面麻醉 | 当日入院、当日手术、当日或次日出院（**≤24 小时**） | 入院后择期或急诊手术，住院 ≥1 晚 |
| 麻醉 | 表面麻醉 / 局部浸润 | 表面 / 球周 / 球后 / Tenon / 静脉镇静 / 全麻 | 同左，重症更多 |
| 床位 | 不占床 | **占日间病床（当日释放）** | 占住院床位 |
| 结算 | 门诊结算（M16-02） | **日间手术结算（M16-03，`admission_type='DAY_SURGERY'`）** | 住院结算（M16-03） |
| 病历 | 门诊病历 | **日间手术病历（含入院记录+手术记录+出院记录）** | 住院病历 |
| 系统归属 | 门诊业务 | **M06 日间手术管理** | M05 住院管理 |
| 眼科典型 | 睑板腺按摩、结膜异物取出 | **白内障超乳、玻腔注药、翼状胬肉、斜视矫正、部分青光眼** | 玻切+硅油、角膜移植、眶减压 |

**关键判定：日间手术的硬指标是「在院时间 ≤24 小时」。** 超过 24 小时必须转住院（M05），这是医保与病案管理的硬性要求，不是系统选择。

#### 1.4.2 日间手术申请 vs 手术医嘱

| 维度 | 日间手术申请（M06-01） | 手术医嘱（M07-03） |
|---|---|---|
| 谁发起 | 门诊医生（术前评估后） | 门诊医生（同一次接诊内） |
| 解决什么 | **能不能做、什么时候做、排到哪** | **开单与收费** |
| 收费 | 不收费 | 生成收费项（手术费 + 材料费 + 麻醉费） |
| 状态 | 申请单状态机（10 态） | 医嘱状态机（DRAFT/ISSUED/PAID/...） |
| 能否独立存在 | 可以（申请了但患者不做了） | 不可以（必须有医嘱） |
| 关系 | 申请单**引用**医嘱号，医嘱**触发**申请单 | 1 申请单 ↔ N 医嘱（手术 + 麻醉 + 材料 + 用药） |

**为什么两者必须分开？**

- 申请单要能被"取消"（患者放弃、医学准入不通过），此时**手术医嘱可能已经开了也收了费**，需要退费流程（M16-08）
- 医嘱是收费凭证，一旦开具就进入 M16 的账务体系；申请单是业务单据，不直接产生财务影响
- 一次日间手术可能对应 5~8 条医嘱（手术费、麻醉费、人工晶体、粘弹剂、术后用药），不能让申请单承担这些

#### 1.4.3 医学准入不通过 vs 患者放弃 vs 排程失败

三种「没做成」的原因完全不同，必须分开统计：

| 分类 | 触发方 | 典型场景 | 后续动作 |
|---|---|---|---|
| **医学准入不通过** | 系统判定（M06-01） | 血压 190/110、空腹血糖 15.2、独眼患者 | 转内科控制后重新申请 / 转住院 |
| **资质准入不通过** | 系统判定（M06-01） | 三级手术由主治医师申请 | 换主刀 / 上调审批 |
| **患者主动放弃** | 患者 | 费用、家庭原因、害怕 | 记录原因，可随访 |
| **术前准备未完成** | M06-02 | 检查异常、抗凝未停 | 延期 |
| **排程失败** | M06-03 | 手术间满、麻醉医生不足 | 改期 |
| **当天取消** | M06-04 | 患者临时不适、设备故障 | 记录，改期或退款 |

**M06-01 只负责前 3 类（医学准入、资质准入、患者主动放弃）。**

#### 1.4.4 ASA 分级

日间手术准入最核心的分级指标，采用美国麻醉医师协会（ASA）标准：

| 分级 | 定义 | 日间手术适用性 |
|---|---|---|
| `ASA_I` | 正常健康患者 | ✅ 适用 |
| `ASA_II` | 轻度系统性疾病，无功能受限 | ✅ 适用 |
| `ASA_III` | 重度系统性疾病，功能受限 | ⚠️ 需麻醉科会诊，多数医院限制 |
| `ASA_IV` | 持续威胁生命的重度系统性疾病 | ❌ 不适用 |
| `ASA_V` | 濒死，预计不手术不能存活 24 小时 | ❌ 不适用 |
| `ASA_VI` | 脑死亡器官捐献者 | ❌ 不适用 |

**为什么 ASA 必须由麻醉医生评定而不是手术医生：** ASA 分级的核心判断是"麻醉风险"，只有麻醉医生有资质与专业能力评定。系统层面表现为：ASA 字段只能由具有麻醉资质的员工填写（见 8.2 节 R-08）。

### 1.5 模块目标

| **M07-03 医嘱** | 提供手术医嘱、接收申请单状态 | 双向 |
| **M07-02 诊断** | 提供主诊断与眼别 | 同步查询（降级用快照） |
| **M16-01 计费引擎** | 提供手术费预估价（给患者知情） | 同步查询（可降级） |
| **M02-06 审计** | 记录准入判定、规则变更 | 异步 |

### 2.4 依赖清单与失败影响

| 依赖 | 用途 | 超时 | 失败影响 | 降级策略 |
|---|---|---|---|---|
| M01-07 `operations/{code}/full-config` | 手术完整配置 | 300ms | **阻断** | 无降级（配置是准入基础） |
| M01-07 `auth/check` | 医师资质校验 | 300ms | **降级** | 标记「待人工复核」，允许提交但不得进入排程 |
| M01-07 `operations/{code}/prep-rule` | 术前准备规则 | 300ms | 降级 | 生成空清单 + 告警，M06-02 可手工补 |
| M01-07 `operations/{code}/followup-rule` | 随访规则 | 300ms | 降级 | 不触发随访，M06-06 归档时补 |
| M01-02 `employee/{id}` | 医师信息 | 200ms | 降级 | 用本地快照 |
| M03-01 `patient/{id}/brief` | 患者信息 | 200ms | 降级 | 用医嘱带入的快照 |
| M07-02 `diagnosis/by-encounter` | 诊断 | 200ms | 降级 | 用医嘱带入的快照 |
| M16-01 `billing/price` | 费用预估 | 500ms | 降级 | 不显示预估价（标注「费用以实际结算为准」） |
| M02-06 审计 | 落审计 | 1s | 异步 | 进补偿队列 |
| M03-04 随访 | 触发随访计划 | 1s | 异步 | 进补偿队列 |

> **降级铁律：资质校验是唯一「降级但不放行」的依赖。** M01-07 不可用时，申请单可以保存为「待人工复核」，但**不允许进入 M06-03 排程**。理由：让一个资质存疑的医生上台，风险远高于让患者多等一天。

### 3.2 申请单状态机（10 态）

```
                        ┌──────────┐
                        │  DRAFT   │ 草稿（医生填写中）
                        └────┬─────┘
                             │ 提交准入判定
                             ▼
                        ┌──────────┐
           ┌───────────►│ ELIGIBLE │ 准入通过（可排程）

           │                 ▼
           │            ┌──────────┐
           │            │ PREPARED │ 术前准备就绪
           │            └────┬─────┘

           ├────────────│INELIGIBLE│ 准入不通过（终态，需重新申请）

           │
           │            ┌──────────┐

                        └──────────┘
```

**状态转移规则**

| 从 | 到 | 触发方 | 前置条件 |
|---|---|---|---|
| `DRAFT` | `ELIGIBLE` | M06-01 | 医学准入全通过 + 资质准入通过 |
| `DRAFT` | `INELIGIBLE` | M06-01 | 任一「阻断级」准入项不通过 |
| `DRAFT` | `PENDING_REVIEW` | M06-01 | 资质校验降级 或 命中「需人工复核」项 |
| `PENDING_REVIEW` | `ELIGIBLE` | 医务科/科主任 | 人工复核通过 |
| `PENDING_REVIEW` | `INELIGIBLE` | 医务科/科主任 | 人工复核不通过 |
| `ELIGIBLE` | `SCHEDULED` | M06-03 | 排程成功 |
| `SCHEDULED` | `PREPARED` | M06-02 | 全部必做准备项完成 |
| `PREPARED` | `CHECKED_IN` | M06-04 | 患者报到 + 床位分配 |
| `CHECKED_IN` | `IN_SURGERY` | M06-04 → M09 | Time-Out 通过 |
| `IN_SURGERY` | `RECOVERING` | M09 | 手术结束 |
| `RECOVERING` | `DISCHARGED` | M06-05 | 离院评估通过 |
| `DISCHARGED` | `CLOSED` | M06-06 | 结算完成 + 病历归档 |
| 任意非终态 | `CANCELLED` | M06-01 | 取消申请审批通过 |

**终态：** `CLOSED`、`INELIGIBLE`、`CANCELLED`。

**为什么 `INELIGIBLE` 是终态而不是回到 `DRAFT`？**

患者血压 190/110 被拒，去内科控制了两周血压回到 150/90，重新申请。此时这是一次**新的医疗决策**，不是"把上次的申请改一改"。保留 `INELIGIBLE` 终态才能统计"多少人被拒、因为什么被拒、后来回来了多少"。如果允许从 `INELIGIBLE` 改回 `DRAFT`，这个数字就永远算不出来。

### 3.3 医学准入模型

#### 3.3.1 准入项分类

对准入判定按三项属性分类，这是整个模型的核心：

| 属性 | 取值 | 含义 |
|---|---|---|
| **判定方式** | `AUTO` 自动 / `MANUAL` 人工 / `HYBRID` 混合 | 系统能否独立判定 |
| **严重度** | `BLOCK` 阻断 / `WARN` 警告 / `INFO` 提示 | 不通过时的后果 |
| **类别** | 见下表 | 用于统计与配置 |

| 类别代码 | 中文名 | 判定方式 | 典型项 |
|---|---|---|---|
| `AGE` | 年龄 | AUTO | 年龄上限、下限 |
| `VITAL` | 生命体征 | AUTO | 血压、心率、体温、血氧 |
| `METABOLIC` | 代谢指标 | AUTO | 空腹血糖、糖化血红蛋白 |
| `CARDIO` | 心血管 | HYBRID | ASA 分级、心电图结果 |
| `COAG` | 凝血 | AUTO | 凝血四项、INR、抗凝药停用天数 |
| `INFECTION` | 感染 | AUTO | 传染病八项、体温、感染灶 |
| `OCULAR` | 眼科专科 | AUTO | 独眼、眼压、角膜内皮、眼表感染 |
| `AIRWAY` | 气道 | MANUAL | Mallampati 分级、张口度 |
| `GENERAL` | 全身状况 | HYBRID | BMI、贫血、肝肾功能 |
| `LOGISTIC` | 后勤条件 | AUTO | 陪护人、住址距离（术后出血能否及时回来） |
| `CONSENT` | 知情同意 | AUTO | 同意书是否已签 |

#### 3.3.2 准入判定算法

```
输入：申请单 + 患者快照 + 手术配置（M01-07）+ 术式准入规则（m06_eligibility_rule）

Step 1  拉取规则
        优先取术式专属规则（operation_code 精确匹配）
        其次取亚专科规则（eye_specialty）
        最后取全院默认规则（rule_scope = 'GLOBAL'）
        规则按优先级排序：EXACT > SPECIALTY > GLOBAL

Step 2  逐项判定
        for rule in rules:
            value = 从申请单/患者快照中取 rule.item_code 对应的值
            if value is None:
                if rule.is_required: 该项记为 NOT_EVALUATED（未评估）
                else: 跳过
                continue
            verdict = evaluate(rule, value)   # PASS / WARN / BLOCK
            results.append({rule, value, verdict, threshold_snapshot})

Step 3  汇总
        if 任一 result.verdict == BLOCK:
            eligibility = INELIGIBLE
        elif 任一 result 为 NOT_EVALUATED 或 任一 result.verdict == WARN 且 rule.need_review:
            eligibility = PENDING_REVIEW
        else:
            eligibility = ELIGIBLE

Step 4  落库
        写 m06_eligibility_result（逐项结果，含阈值快照）
        更新 m06_day_surgery.eligibility_status / eligibility_result_json / rule_version
```

**关键设计：阈值快照。**

每条判定结果都存一份**当时使用的阈值快照**（`threshold_json`）。理由：医务科半年后修改了血压阈值（从 180 改成 160），此时查看一位老患者的准入记录，必须能回答"当时是按 180 还是 160 判的"。如果只存规则 ID，规则被改了之后就再也还原不出当时的判定依据。

#### 3.3.3 判定结果四态

| 结果 | 代码 | 含义 | 对申请单的影响 |
|---|---|---|---|
| 通过 | `PASS` | 该指标在允许范围内 | 不阻断 |
| 警告 | `WARN` | 超出理想范围但在可接受范围 | 不阻断，需记录「已知悉风险」 |
| 阻断 | `BLOCK` | 超出可接受范围，不可日间手术 | **整单 INELIGIBLE** |
| 未评估 | `NOT_EVALUATED` | 必填项缺失（如没做凝血检查） | 转 `PENDING_REVIEW` |

**为什么 WARN 要单独一档而不是合并进 PASS：**

血压 165/95 的患者，按"严格标准"（<160）是超标的，但按"宽松标准"（<180）是允许的。这条记录进入 `WARN` 后：

1. 医生在提交前会看到黄色提示"该患者血压偏高，确认是否继续"
2. 系统记录医生点了"已知悉"（`acknowledged_by`）
3. 万一术后出现高血压相关并发症，这条记录是"医生在知情情况下做了决策"的证据

如果并进 `PASS`，这些都不存在。

### 3.4 资质准入模型

资质校验**完全委托 M01-07**，M06-01 只做三件事：调用、记录、判定降级。

```
M06-01                                  M01-07
   │                                       │
   │  POST /internal/v1/surgery/auth/check │
   │  {staff_id, operation_code,           │
   │   surgery_level, is_day_surgery}      │
   ├──────────────────────────────────────►│
   │                                       │ 查 md_operation_staff_auth
   │                                       │ 查 md_surgery_level_rule
   │  {allowed, reason, requiredLevel,     │ 查 md_operation.min_surgery_level
   │   approved, auth_scope, expire_at}    │
   │◄──────────────────────────────────────┤
   │                                       │
   ├─ allowed=true  → 资质 PASS
   ├─ allowed=false → 资质 BLOCK，reason 写入结果
   └─ 超时/异常     → 资质 NOT_EVALUATED（降级）
```

**M01-07 返回的字段处理**

| 字段 | 用法 |
|---|---|
| `allowed` | 直接决定 PASS / BLOCK |
| `reason` | 写入 `m06_eligibility_result.reason` 供医生看 |
| `requiredLevel` | 写入快照，用于统计"是资质级别不够还是白名单没加" |
| `approved` | 若为 false 且 `need_chief_approve=true`，转审批流程 |
| `auth_scope` | `LEVEL` / `WHITELIST` / `BOTH`，写入快照 |
| `expire_at` | 授权有效期，若 30 天内到期则给 `WARN` |

**资质准入的降级策略（重要）**

M01-07 不可用时的处理：

```
资质 NOT_EVALUATED
    ↓
申请单置 PENDING_REVIEW
    + 加备注「资质校验服务不可用，需人工复核」
    + 告警医务科
    ↓
人工在 P06 页面复核（查 M01-07 页面或纸质授权目录）
    ↓
复核通过 → ELIGIBLE
```

**绝不允许的降级方式：** 报错放行。理由：手术资质是《医疗机构手术分级管理办法》的硬性要求，让资质不符的医生上台，出事后医院要承担全部责任。

### 3.5 术前准备清单生成模型

M06-01 在准入通过后，自动从 M01-07 拉取术前准备规则并展开为清单：

```
M01-07 md_operation_prepare_rule
    ├── fasting_required / fasting_solid_hours / fasting_liquid_hours
    ├── eye_mark_required（术眼标记）
    ├── dilate_pupil_required / dilate_drop_type / dilate_minutes（散瞳）
    ├── antibiotic_prophylaxis / antibiotic_timing（预防用药）
    ├── consent_required / consent_types（知情同意）
    ├── anesthesia_visit（麻醉访视）
    └── pre_op_checklist（术前核对清单 JSON）

    + M01-07 md_operation_prepare_item（明细项：CHECK/DRUG/NURSING/PREP）

    + M01-07 md_operation_exam_item_rel（术前检查：视力/眼压/IOL Master/B超）
    + M01-07 md_operation_lab_item_rel（术前检验：血常规/凝血/肝肾/传染病）

        ↓ 展开（M06-01）

m06_prepare_item（术前准备清单，逐项可勾选）
    ├── item_type: FASTING / EYE_MARK / DILATE / ANTIBIOTIC / CONSENT
    │              / ANESTHESIA_VISIT / EXAM / LAB / NURSING / PREP
    ├── item_code / item_name
    ├── is_required（必做）
    ├── timing（执行时机，如「术前 1 天 22:00」「术前 30 分钟」）
    ├── source_rule_id（来自哪条 M01-07 规则）
    └── status: PENDING / DONE / NA / FAILED

        ↓ M06-02 逐项执行与闭环
```

**为什么清单要落库而不是实时算：**

1. **M01-07 规则变更后，历史申请的清单不能变**——患者是按当时的规则准备的
2. **每项都要独立记录执行人与执行时间**，实时算无法承载状态
3. **M06-02 要在手机/PDA 上逐项勾选**，必须有持久化的行

### 3.6 重复申请检测模型

同一患者短期内重复申请日间手术是常见的业务异常，需要检测。检测分三层：

| 层 | 判定 | 处理 |
|---|---|---|
| **精确重复** | 同患者 + 同 `operation_code` + 同眼别 + 状态非终态 | **阻断**（`"0601007"`），提示已有申请单 |
| **近似重复** | 同患者 + 同 `operation_code` + 30 天内 + 状态为 `CLOSED`/`CANCELLED` | **警告**，需填「重复申请原因」 |
| **双眼手术间隔** | 同患者 + 另一眼 + 同一术式 + 14 天内 | **警告**，提示「双眼手术建议间隔」 |

**为什么「双眼手术间隔」要警告：**

双眼白内障分两次做是标准做法（避免双眼同时感染导致双盲），但间隔太短（<14 天）会导致第一只眼还在恢复期就做第二只，术后用药冲突、随访混乱。系统不禁止，但必须提示。

### 3.7 取消与改期模型

| 类型 | 触发时点 | 是否需审批 | 影响 |
|---|---|---|---|
| **准入前取消** | `DRAFT` / `PENDING_REVIEW` | 否 | 申请单作废，无下游动作 |
| **准入后取消** | `ELIGIBLE` / `SCHEDULED` | 是（科主任） | 通知 M06-03 释放台次 |
| **已准备后取消** | `PREPARED` | 是（科主任 + 医务科） | 释放台次 + 作废准备项 + M16-08 退费 |
| **报到后取消** | `CHECKED_IN` | 是（科主任 + 医务科） | 释放台次 + 释放床位 + 退费 |
| **术中终止** | `IN_SURGERY` | 是（医务科） | 转 M06-05 或转住院 M05 |

**改期与取消的区别：** 改期保留申请单（状态回 `ELIGIBLE`），取消则进入终态。改期不释放准入结论（准入仍然有效），但**若改期超过 30 天，需重新做准入判定**（患者身体状况可能已变化）。

**为什么指标区要有【带入】按钮而不是自动带入：**

自动带入会覆盖医生手工修正的值。实际场景：M13 里的血糖是三个月前的，医生刚在诊室测了一个最新的想用新的——如果自动带入，医生要反复改。手工触发带入，是"以医生的判断为准"。

| 汇总 | 四项计数 | 通过 / 警告 / 阻断 / 未评估 |
| 汇总 | 规则版本 | 本次判定使用的规则版本 |
| 阻断项 | 项目名 / 实际值 / 阈值 | `verdict='BLOCK'` 的结果 |
| 警告项 | 项目名 / 实际值 / 阈值 / 说明 | `verdict='WARN'` 的结果 |
| 警告项 | 已知悉勾选框 | 必须勾选才能继续 |
| 未评估项 | 项目名 / 原因 | `verdict='NOT_EVALUATED'` 的结果 |
| 通过项 | 折叠，默认收起 | `verdict='PASS'` |

**交互说明：**

| 操作 | 触发 | 结果 |
|---|---|---|
| 勾选「已知悉风险」 | 单击 | 记录 `acknowledged_at`；全部勾选后【确认并提交审批】才可用 |
| 点击【去填写】 | 点击 | 跳回 P02 并定位到该字段 |
| 返回修改 | 点击 | 回到 P02，保留已填内容 |
| 确认并提交审批 | 点击 | 状态 → `ELIGIBLE`（无阻断）或 `PENDING_REVIEW`（有未评估） |
| 放弃申请 | 点击 | 弹确认框 → 状态 → `CANCELLED` |
| 展开/收起通过项 | 点击 | 折叠面板切换 |

**校验规则：**

| 编号 | 规则 | 错误码 |
|---|---|---|
| V-16 | 存在 BLOCK 项时不允许提交（只能放弃申请） | `"0601013"` |
| V-17 | 存在 WARN 项且未勾选知悉时不允许提交 | `"0601014"` |
| V-18 | 存在 NOT_EVALUATED 且为必填时，提交后状态为 `PENDING_REVIEW`（非 `ELIGIBLE`） | — |
| V-19 | 判定结果超过 30 分钟未确认，需重新判定（数据可能已过期） | `"0601015"` |

**为什么通过项要折叠起来：**

18 项判定里通常 15 项通过。如果把 15 项通过全展开，医生要滚过 15 行才能看到 2 行警告——而警告才是他需要看的。折叠是"默认收起不重要信息"的标准实践。但**阻断项永远展开**（哪怕只有 1 项），因为那是决策点。

**为什么判定结果 30 分钟过期：**

判定用的是提交那一刻的指标值。如果医生填完判定结果，去处理别的患者，30 分钟后回来点确认——这期间患者可能又测了一次血压、或者用了药。**过期的判定结果等同于没有判定**。30 分钟是门诊医生处理一个患者的大致时长，超过这个时间就应该重新拉数据。

**字段说明：**

| 字段 | 类型 | 说明 |
|---|---|---|
| 作用域 | 下拉 | `GLOBAL` 全院默认 / `SPECIALTY` 亚专科 / `OPERATION` 术式专属 |
| 准入项 | 文本 | 项名称（如「收缩压」） |
| 类别 | 下拉 | 11 类（见 3.3.1） |
| 判定方式 | 下拉 | `AUTO` / `MANUAL` / `HYBRID` |
| 严重度 | 下拉 | `BLOCK` / `WARN` / `INFO` |
| 阈值 | 表达式 | 如 `<180`、`50~100`、`≥7`、`MUST_BE_FALSE` |
| 需复核 | 开关 | 命中时转人工复核 |
| 启用 | 开关 | 停用的规则不参与判定 |

**交互说明：**

| 操作 | 触发 | 结果 |
|---|---|---|
| 编辑规则 | 点击【编辑】 | 弹窗修改，保存后进入待审批状态 |
| 新建规则 | 点击【新建规则】 | 弹窗，需选作用域 |
| 查看历史版本 | 点击 | 弹出历史版本列表，可比对差异 |
| 审批 | 医务科长 | 双签通过后次日生效 |
| 阈值校验 | 保存时 | 表达式语法校验 + 与已有规则的冲突检测 |

**校验规则：**

| 编号 | 规则 | 错误码 |
|---|---|---|
| V-31 | 阈值表达式语法合法 | `"0601026"` |
| V-32 | 同一作用域 + 同一 `item_code` 只能有一条启用规则 | `"0601027"` |
| V-33 | `severity='BLOCK'` 的规则不得设为「不需复核」且「可停用」 | `"0601028"` |
| V-34 | 规则变更必须双签（科主任 + 医务科长） | `"0601029"` |
| V-35 | 规则变更次日 00:00 生效（不可立即生效） | `"0601030"` |

**为什么规则变更不能立即生效：**

如果医务科上午 10 点把血压阈值从 180 改成 160 并立即生效，那么：

- 上午 9:59 提交的申请按 180 判，通过了
- 上午 10:01 提交的申请按 160 判，可能不通过

同一天、同样的患者情况，系统给出两个结论。次日 00:00 生效让变更有一个明确的时间边界，任何时刻的判定都能对应到唯一确定的规则版本。

**为什么 BLOCK 级规则不可停用：**

规则的 `severity` 是医务科的判断，但**「独眼患者」「手术同意书未签」这类规则属于法规底线**，把它「停用」意味着系统不再检查它——那是不可接受的。所以规则有一个 `is_mandatory` 标记（`md_operation` 体系中对应的项），`is_mandatory=TRUE` 的规则永远不可停用、不可降级为 WARN。

### 6.2 错误码规范

| 错误码 | 说明 | 触发场景 |
|---|---|---|
| `"0601001"` | 该手术项目不支持日间手术 | `is_day_surgery=FALSE` |
| `"0601002"` | 手术项目不存在或已停用 | M01-07 查询失败 |
| `"0601003"` | 眼别不合法（单眼手术不得选双眼） | `allow_bilateral=FALSE` 且 `eye_side='OU'` |

| `"0601008"` | 抗凝药停用天数不足 | 拟停药天数 < 规则要求 |

class ApplyService:
    """日间手术申请单服务。"""

    # ---------- 工作台 ----------

    @classmethod
    async def get_workbench(cls, user) -> Dict[str, Any]:
        """工作台概览。"""
        db = user.db
        emp_id = user.employee_id

        # 我的待办
        todos = await cls._load_todos(db, emp_id, user)
        # 本月概览
        overview = await cls._load_month_overview(db, emp_id)
        # 待准入列表
        pending = await cls._load_pending(db, emp_id)

        return {
            "todos": todos,
            "overview": overview,
            "pending_list": pending,
            "server_time": datetime.now().isoformat(),
        }

    @classmethod
    async def _load_todos(cls, db, emp_id: int, user) -> Dict[str, Any]:
        """加载待办。"""
        # ① 准入待复核（本人提交且状态 PENDING_REVIEW）
        rows1 = (await db.execute(
            select(M06DaySurgery.id, M06DaySurgery.ds_no,
                   M06DaySurgery.patient_name, M06DaySurgery.operation_name,
                   M06DaySurgery.eye_side, M06DaySurgery.review_reason)
            .where(and_(
                M06DaySurgery.creator_id == emp_id,
                M06DaySurgery.status == "PENDING_REVIEW",
                M06DaySurgery.is_deleted.is_(False),
            ))
            .order_by(M06DaySurgery.created_at.desc())
            .limit(20)
        )).all()
        items1 = [{
            "type": "PENDING_REVIEW",
            "type_text": "准入待复核",
            "id": r[0], "ds_no": r[1], "patient_name": r[2],
            "operation_name": r[3], "eye_side": r[4],
            "reason": r[5],
            "action": "go_review",
        } for r in rows1]

        # ② 警告待确认（已判定 warn 但未确认）
        rows2 = (await db.execute(
            select(M06DaySurgery.id, M06DaySurgery.ds_no,
                   M06DaySurgery.patient_name, M06DaySurgery.operation_name,
                   M06DaySurgery.eye_side, M06DaySurgery.warn_unacked_count)
            .where(and_(
                M06DaySurgery.creator_id == emp_id,
                M06DaySurgery.status == "DRAFT",
                M06DaySurgery.eligibility_status == "PENDING_REVIEW",
                M06DaySurgery.warn_unacked_count > 0,
                M06DaySurgery.is_deleted.is_(False),
            ))
            .limit(20)
        )).all()
        items2 = [{
            "type": "WARN_UNACKED",
            "type_text": "警告待确认",
            "id": r[0], "ds_no": r[1], "patient_name": r[2],
            "operation_name": r[3], "eye_side": r[4],
            "reason": "%d 项警告待确认" % r[5],
            "action": "go_acknowledge",
        } for r in rows2]

        # ③ 准备未完成（状态 PREPARED 之前、准备项未全完成）
        rows3 = (await db.execute(text(
            "SELECT d.id, d.ds_no, d.patient_name, d.operation_name, d.eye_side, "
            "       COUNT(p.id) FILTER (WHERE p.status IN ('DONE','NA')) AS done_cnt, "
            "       COUNT(p.id) AS total_cnt "
            "FROM m06_day_surgery d "
            "JOIN m06_prepare_item p ON p.apply_id = d.id AND p.is_deleted = FALSE "
            "WHERE d.creator_id = :emp AND d.status IN ('SCHEDULED','PREPARED') "
            "  AND d.is_deleted = FALSE "
            "GROUP BY d.id, d.ds_no, d.patient_name, d.operation_name, d.eye_side "
            "HAVING COUNT(p.id) FILTER (WHERE p.status IN ('DONE','NA')) < COUNT(p.id) "
            "LIMIT 20"
        )).bindparams(emp=emp_id)).all()
        items3 = [{
            "type": "PREPARE_INCOMPLETE",
            "type_text": "术前准备未完成",
            "id": r[0], "ds_no": r[1], "patient_name": r[2],
            "operation_name": r[3], "eye_side": r[4],
            "reason": "术前准备 %d/%d" % (r[5], r[6]),
            "action": "view_prepare",
        } for r in rows3]

        all_items = items1 + items2 + items3
        return {"total": len(all_items), "items": all_items[:20]}

    @classmethod
    async def _load_month_overview(cls, db, emp_id: int) -> Dict[str, Any]:
        """本月概览（缓存 60 秒）。"""
        today = date.today()
        month_start = today.replace(day=1)
        cache_key = "m06:apply:overview:%d:%s" % (emp_id, month_start.isoformat())
        cached = await redis.get(cache_key)
        if cached:
            return __import__("json").loads(cached)

        rows = (await db.execute(text(
            "SELECT status, COUNT(*) FROM m06_day_surgery "
            "WHERE creator_id = :emp AND apply_date >= :d0 "
            "  AND is_deleted = FALSE GROUP BY status"
        ))).bindparams(emp=emp_id, d0=month_start).all()
        stat = {r[0]: r[1] for r in rows}
        total = sum(stat.values())
        passed = sum(v for k, v in stat.items()
                     if k in ("ELIGIBLE", "SCHEDULED", "PREPARED", "CHECKED_IN",
                              "IN_SURGERY", "RECOVERING", "DISCHARGED", "CLOSED"))
        review = stat.get("PENDING_REVIEW", 0)
        failed = stat.get("INELIGIBLE", 0)
        cancelled = stat.get("CANCELLED", 0)

        # 不通过原因分布
        reason_rows = (await db.execute(text(
            "SELECT r.item_code, r.item_name, COUNT(*) AS cnt "
            "FROM m06_eligibility_result r "
            "JOIN m06_day_surgery d ON d.id = r.apply_id "
            "WHERE d.creator_id = :emp AND d.apply_date >= :d0 "
            "  AND r.verdict = 'BLOCK' AND d.is_deleted = FALSE "
            "GROUP BY r.item_code, r.item_name ORDER BY cnt DESC LIMIT 10"
        ).bindparams(emp=emp_id, d0=month_start)).all())

        result = {
            "month": month_start.strftime("%Y-%m"),
            "total": total,
            "passed": passed,
            "passed_rate": round(passed / total, 4) if total else 0,
            "pending_review": review,
            "ineligible": failed,
            "cancelled": cancelled,
            "block_reasons": [

                for r in reason_rows
            ],
        }
        await redis.setex(cache_key, 60, __import__("json").dumps(result))
        return result

    # ---------- 创建 ----------

    @classmethod
    async def create(cls, body, user) -> Dict[str, Any]:
        """创建申请单。"""
        db = user.db

        # ① 幂等检查（同一医嘱只能建一张）
        if body.order_id:
            exists = (await db.execute(
                select(M06DaySurgery)
                .where(and_(
                    M06DaySurgery.order_id == body.order_id,
                    M06DaySurgery.is_deleted.is_(False),
                ))
            )).scalar_one_or_none()
            if exists:
                raise BizException("0601036", "该手术医嘱已存在日间手术申请单",
                                   data={"ds_no": exists.ds_no})

        # ② 拉取手术配置（阻断）
        cfg = await SurgeryClient.get_full_config(body.operation_code)
        if not cfg:
            raise BizException("0601002", "手术项目不存在或已停用")
        if not cfg["operation"]["is_day_surgery"]:
            raise BizException("0601001", "该手术项目不支持日间手术")

        # ③ 眼别校验
        op = cfg["operation"]
        if op["laterality_required"] and body.eye_side not in ("OD", "OS", "OU"):
            raise BizException("0601003", "该手术必须指定眼别")
        if body.eye_side == "OU" and not op["allow_bilateral"]:
            raise BizException("0601003", "该手术不支持双眼同时手术")

        # ④ 手术日期校验
        today = date.today()
        if body.scheduled_date <= today:
            raise BizException("0601004", "拟手术日期至少为明天")

        # ⑤ 麻醉医生校验
        if cfg["anesthesia"]:
            is_needed = any(a.get("need_anesthetist") for a in cfg["anesthesia"])
            if is_needed and not body.anesthetist_id:
                raise BizException("0601005", "该麻醉方式需指定麻醉医生")

        # ⑥ ASA 权限校验
        if body.vitals.asa_level and body.vitals.asa_assessed_by:
            ok_ana = await EmployeeClient.has_anesthesia_qualification(
                body.vitals.asa_assessed_by)
            if not ok_ana:
                raise BizException("0601006", "ASA 分级只能由麻醉医生评定")

        # ⑦ 重复申请检测
        await cls._check_duplicate(db, body)

        # ⑧ 抗凝停药天数
        if body.anticoagulant and body.anticoagulant.in_use:
            req_days = cls._required_stop_days(cfg, op)
            if body.anticoagulant.planned_stop_days < req_days:
                raise BizException("0601008",
                    "抗凝药停用天数不足（要求 ≥%d 天）" % req_days)

        # ⑨ 陪护人必填
        if not (body.logistics.companion_name
                and body.logistics.companion_relation
                and body.logistics.companion_phone):
            raise BizException("0601010", "日间手术必须填写陪护人信息")

        # ⑩ 患者信息（降级用快照）
        patient = await PatientClient.get_brief_safe(body.patient_id)

        # ⑪ 生成单号
        ds_no = await cls._next_ds_no(db)

        # ⑫ 落库
        row = M06DaySurgery(
            ds_no=ds_no,
            patient_id=body.patient_id,
            patient_name=patient.get("name"),
            gender=patient.get("gender"),
            age=patient.get("age"),
            id_card_hash=patient.get("id_card_hash"),
            visit_no=body.visit_no,
            encounter_id=patient.get("encounter_id"),
            order_id=body.order_id,
            order_no=body.order_no,
            operation_code=body.operation_code,
            operation_name=op["name"],
            surgery_level=op["surgery_level"],
            eye_specialty=op.get("eye_specialty"),
            is_implant_surgery=op.get("is_implant_surgery", False),
            eye_side=body.eye_side,
            anesthesia_code=body.anesthesia_code,
            surgeon_id=body.surgeon_id,
            anesthetist_id=body.anesthetist_id,
            dept_id=user.dept_id,
            scheduled_date=body.scheduled_date,
            apply_date=today,
            primary_diagnosis_code=body.primary_diagnosis_code,
            primary_diagnosis_name=body.primary_diagnosis_name,
            comorbidities=body.comorbidities or [],
            anticoagulant_json=body.anticoagulant.model_dump() if body.anticoagulant else None,
            vitals_json=body.vitals.model_dump(),
            logistics_json=body.logistics.model_dump(),
            consents=body.consents or [],
            remark=body.remark,
            status="DRAFT",
            rule_version=await cls._current_rule_version(db),
            creator_id=user.employee_id,
            creator_name=user.name,
        )
        db.add(row)
        try:
            await db.flush()
        except IntegrityError:
            await db.rollback()
            raise BizException("0601036", "申请单已存在")

        # ⑬ 生成术前准备清单
        await cls._generate_prepare_items(db, row, cfg)

        # ⑭ 日志
        await cls._log(db, row, "CREATE", user, remark="创建申请单")

        await db.commit()
        return await cls.get_detail(row.id, user)

    @classmethod
    async def _check_duplicate(cls, db, body) -> None:
        """重复申请检测（三层）。"""
        today = date.today()

        # 层 1：精确重复（同患者+同术式+同眼别+非终态）
        exact = (await db.execute(
            select(M06DaySurgery.ds_no, M06DaySurgery.status)
            .where(and_(
                M06DaySurgery.patient_id == body.patient_id,
                M06DaySurgery.operation_code == body.operation_code,
                M06DaySurgery.eye_side == body.eye_side,
                M06DaySurgery.status.notin_(list(TERMINAL)),
                M06DaySurgery.is_deleted.is_(False),
            ))
        )).first()
        if exact:
            raise BizException("0601007",
                "该患者已有进行中的同术式申请（%s，%s）"
                % (exact[0], STATUS_TEXT.get(exact[1], exact[1])),
                data={"ds_no": exact[0]})

        # 层 2：近似重复（30 天内同术式，已终态）
        window_start = today - timedelta(days=30)
        near = (await db.execute(
            select(func.count()).select_from(M06DaySurgery)
            .where(and_(
                M06DaySurgery.patient_id == body.patient_id,
                M06DaySurgery.operation_code == body.operation_code,
                M06DaySurgery.apply_date >= window_start,
                M06DaySurgery.status.in_(["CLOSED", "CANCELLED"]),
                M06DaySurgery.is_deleted.is_(False),
            ))
        )).scalar() or 0
        if near > 0 and not body.repeat_reason:
            raise BizException("0601009",
                "30 天内已有该术式申请，请填写重复申请原因")

        # 层 3：双眼手术间隔（另一眼同术式 14 天内）
        other_eye = "OS" if body.eye_side == "OD" else "OD"
        if body.eye_side in ("OD", "OS"):
            gap_start = today - timedelta(days=14)
            other = (await db.execute(
                select(M06DaySurgery.ds_no, M06DaySurgery.scheduled_date)
                .where(and_(
                    M06DaySurgery.patient_id == body.patient_id,
                    M06DaySurgery.operation_code == body.operation_code,
                    M06DaySurgery.eye_side == other_eye,
                    M06DaySurgery.apply_date >= gap_start,
                    M06DaySurgery.status.in_(
                        ["CLOSED", "DISCHARGED", "SCHEDULED", "PREPARED"]),
                    M06DaySurgery.is_deleted.is_(False),
                ))
            )).first()
            if other:
                logger.warning("双眼手术间隔过短 patient=%s other=%s",
                               body.patient_id, other[0])

    @classmethod
    def _required_stop_days(cls, cfg: Dict, op: Dict) -> int:
        """抗凝停药要求天数（从 M01-07 准备规则取）。"""
        prep = cfg.get("prepareRule") or {}
        days = prep.get("anticoagulant_stop_days")
        if days:
            return int(days)
        # 默认：内眼手术 7 天，外眼手术 3 天
        return 7 if op.get("is_implant_surgery") or "INTRACULAR" in str(
            op.get("operation_category", "")) else 3

    @classmethod

        """从 M01-07 规则展开术前准备清单。"""

        if prep.get("eye_mark_required", True):
            items.append({
                "item_type": "EYE_MARK", "item_code": "EYE_MARK",
                "item_name": "术眼标记",
                "item_desc": "标记手术眼",
                "is_required": True,
                "timing": "术前 1 天",
            })

        # 散瞳
        if prep.get("dilate_pupil_required"):
            items.append({
                "item_type": "DILATE", "item_code": "DILATE_PUPIL",
                "item_name": "散瞳",
                "item_desc": "药物：%s" % (prep.get("dilate_drop_type") or ""),
                "is_required": True,
                "timing": "术前 %d 分钟" % (prep.get("dilate_minutes") or 60),
            })

        # 预防用药
        if prep.get("antibiotic_prophylaxis"):
            items.append({
                "item_type": "ANTIBIOTIC", "item_code": "ANTIBIOTIC_PROPHYLAXIS",
                "item_name": "预防性抗菌药物",
                "item_desc": "时机：%s" % (prep.get("antibiotic_timing") or "术前0.5-1小时"),
                "is_required": True,
                "timing": prep.get("antibiotic_timing") or "术前 0.5~1 小时",
            })

        # 知情同意
        if prep.get("consent_required", True):
            types = (prep.get("consent_types") or "手术").split(",")
            for t in types:
                t = t.strip()
                if not t:
                    continue
                items.append({
                    "item_type": "CONSENT", "item_code": "CONSENT_%s" % t,
                    "item_name": "%s同意书" % t,
                    "is_required": True,
                    "timing": "术前 1 天",
                })

        # 麻醉访视
        if prep.get("anesthesia_visit"):
            items.append({
                "item_type": "ANESTHESIA_VISIT", "item_code": "ANESTHESIA_VISIT",
                "item_name": "麻醉术前访视",
                "is_required": True,
                "timing": "术前 1 天",
            })

        # 术前检查
        for e in (cfg.get("examItems") or []):
            items.append({
                "item_type": "EXAM", "item_code": e["item_code"],
                "item_name": e["item_name"],
                "is_required": e.get("is_required", True),
                "timing": e.get("timing") or "术前 3 天",
                "source_item_id": e.get("item_id"),
            })

        # 术前检验
        for e in (cfg.get("labItems") or []):
            items.append({
                "item_type": "LAB", "item_code": e["item_code"],
                "item_name": e["item_name"],

                "source_item_id": e.get("item_id"),
            })

        # 明细准备项
        for e in (cfg.get("prepareItems") or []):
            items.append({
                "item_type": e.get("item_type") or "PREP",
                "item_code": e.get("item_code") or str(e.get("item_id")),
                "item_name": e["item_name"],
                "is_required": e.get("is_required", True),
                "timing": e.get("timing"),
                "source_item_id": e.get("item_id"),
            })

        for seq, it in enumerate(items, start=1):
            db.add(M06PrepareItem(
                apply_id=row.id,
                seq_no=seq,
                item_type=it["item_type"],
                item_code=it["item_code"],
                item_name=it["item_name"],
                item_desc=it.get("item_desc"),
                is_required=it.get("is_required", True),
                timing=it.get("timing"),
                source_item_id=it.get("source_item_id"),

            ))

    @classmethod
    async def _next_ds_no(cls, db) -> str:
        """生成申请单号 DS + YYYYMMDD + 4 位。"""
        today = date.today().strftime("%Y%m%d")
        seq = await redis.incr("m06:ds:seq:%s" % today)
        await redis.expire("m06:ds:seq:%s" % today, 172800)
        if seq > 9999:
            raise BizException("0601034", "当日申请单号已用尽")
        return "DS%s%04d" % (today, seq)

    @classmethod
    async def _current_rule_version(cls, db) -> str:
        """当前生效的准入规则版本。"""
        cached = await redis.get("m06:rule:current_version")
        if cached:
            return cached.decode() if isinstance(cached, bytes) else cached
        row = (await db.execute(text(
            "SELECT version_no FROM m06_rule_version "
            "WHERE status = 'EFFECTIVE' AND is_deleted = FALSE "
            "ORDER BY effective_date DESC LIMIT 1"
        ))).first()
        ver = row[0] if row else "V1"
        await redis.setex("m06:rule:current_version", 600, ver)
        return ver

    @classmethod
    async def on_status_changed(cls, apply_id: int, body) -> Dict[str, Any]:
        """状态变更回写（由 M06-02~05 调用）。"""
        db = await _get_db()
        row = (await db.execute(
            select(M06DaySurgery).where(M06DaySurgery.id == apply_id)
            .with_for_update()
        )).scalar_one_or_none()
        if not row:
            raise BizException("0601033", "申请单不存在")

        if row.status != body.from_status:
            logger.warning("状态回写不匹配 apply=%s expect=%s actual=%s",
                           apply_id, body.from_status, row.status)
            return {
                "ds_no": row.ds_no,
                "old_status": row.status,
                "new_status": row.status,
                "accepted": False,
                "reason": "当前状态与来源状态不一致",
            }

        cls._check_transition(row.status, body.to_status)
        old = row.status
        row.status = body.to_status
        row.status_changed_at = datetime.now()

        # 记录关键时间戳
        if body.to_status == "SCHEDULED":
            row.scheduled_at = body.changed_at
        elif body.to_status == "PREPARED":
            row.prepared_at = body.changed_at
        elif body.to_status == "CHECKED_IN":
            row.admission_at = body.changed_at
        elif body.to_status == "IN_SURGERY":
            row.surgery_start_at = body.changed_at
        elif body.to_status == "RECOVERING":
            row.surgery_end_at = body.changed_at
        elif body.to_status == "DISCHARGED":
            row.discharge_at = body.changed_at
        elif body.to_status == "CLOSED":
            row.closed_at = body.changed_at

        await cls._audit_status(db, row, body, old)
        await db.commit()

        return {
            "ds_no": row.ds_no,
            "old_status": old,
            "new_status": row.status,
            "accepted": True,
            "next_action": cls._next_action_hint(row.status),
        }

    @classmethod
    def _check_transition(cls, old: str, new: str) -> None:
        allowed = TRANSITIONS.get(old, set())
        if new not in allowed:
            raise BizException("0601034",
                "状态不允许从「%s」变更为「%s」"
                % (STATUS_TEXT.get(old, old), STATUS_TEXT.get(new, new)))

    @classmethod
    def _next_action_hint(cls, status: str) -> str:
        return {
            "ELIGIBLE": "等待排程（M06-03）",
            "SCHEDULED": "术前准备（M06-02）",
            "PREPARED": "等待患者报到（M06-04）",
            "CHECKED_IN": "术前核对（M06-04）",
            "IN_SURGERY": "手术进行中（M09）",
            "RECOVERING": "术后复苏（M06-05）",
            "DISCHARGED": "结算与归档（M06-06）",
            "CLOSED": "流程结束",
        }.get(status, "")

async def _review_timeout():
    """2 小时未复核 → 提醒；4 小时未复核 → 升级医务科长。"""
    from app.db.session import AsyncSessionLocal
    from app.models.m06 import M06DaySurgery
    from app.clients.message_client import MessageClient
    from sqlalchemy import and_, select
    now = datetime.now()
    async with AsyncSessionLocal() as db:
        rows = (await db.execute(
            select(M06DaySurgery)
            .where(and_(
                M06DaySurgery.status == "PENDING_REVIEW",
                M06DaySurgery.is_deleted.is_(False),
            ))
        )).scalars().all()
        for row in rows:
            if not row.review_submitted_at:
                continue
            waited = (now - row.review_submitted_at).total_seconds() / 60
            if waited >= 240 and not row.review_escalated:
                await MessageClient.send(
                    channel="INBOX", biz_type="M06_REVIEW_ESCALATE",
                    biz_id=str(row.id),
                    title="【升级】日间手术申请复核超时 4 小时",
                    content="申请单 %s 已等待 %d 分钟未复核"
                            % (row.ds_no, int(waited)),
                    role_codes=["MEDICAL_AFFAIRS_CHIEF"],
                )
                row.review_escalated = True
            elif waited >= 120 and not row.review_reminded:
                await MessageClient.send(
                    channel="INBOX", biz_type="M06_REVIEW_REMIND",
                    biz_id=str(row.id),
                    title="日间手术申请待复核（已等待 2 小时）",
                    content="申请单 %s 请尽快复核" % row.ds_no,
                    role_codes=["MEDICAL_AFFAIRS"],
                )
                row.review_reminded = True
        await db.commit()

## 11. 异常处理与日志

### 11.1 异常分类

| 类型 | 示例 | 处理 |
|---|---|---|
| **参数校验异常** | 眼别非法、日期过早 | 返回 `"0601xxx"`，前端定位到字段 |
| **业务规则异常** | 准入有阻断项、重复申请 | 返回错误码 + 可操作提示 |
| **依赖降级异常** | M01-07 超时 | 降级 + 标记待复核 + 告警 |
| **并发冲突** | 乐观锁版本不一致 | 返回 `"40900"`，提示刷新重试 |
| **数据不一致** | 状态回写来源不匹配 | 记录 WARN 日志，返回 `accepted=false` |
| **系统异常** | 数据库连接失败 | 返回 `"50000"`，记录 ERROR 日志 + 告警 |

"""M06-01 日志规范。"""
import logging

logger = logging.getLogger("m06.apply")
