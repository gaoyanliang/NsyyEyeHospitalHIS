## 1. 模块概述

### 1.1 模块定位

M06-07 是日间手术管理的**度量与洞察层**。前六个子模块回答「能不能做、怎么准备、排在哪、对不对、能不能走、钱与病历结没结」，M06-07 回答：

> **「这个月日间手术做得怎么样？哪里出了问题？谁该负责？下个月该改什么？」**

**M06-07 的三层职责：**

| 层次 | 内容 | 使用者 | 决策周期 |
|---|---|---|---|
| **L1 实时看板** | 今日台数、准点率、在院人数、延期离院 | 手术室护士长、科主任 | 分钟级 |
| **L2 周期报表** | 日/周/月/季/年 42 项核心指标 | 科主任、医务科、院领导 | 日/周/月 |
| **L3 专题分析** | 取消原因、术前准备缺陷、并发症、效率瓶颈 | 质量改进小组 | 季度/年度 |

**M06-07 不产生业务动作，只读不写业务数据。** 它唯一写的是自己的统计结果表（`m06_stat_*`）。

### 1.2 为什么独立成子模块

**理由一：统计口径是"制度"不是"计算"，必须独立管理且可追溯。**

同一个"日间手术占比"，可以有至少四种算法：

| 算法 | 分子 | 分母 | 结果示例 |
|---|---|---|---|
| 按台次 | 日间台次 | 全部台次 | 82% |
| 按患者 | 日间患者数 | 全部手术患者数 | 78% |
| 按住院号 | 日间住院号数 | 全部住院号数 | 76% |
| 按费用 | 日间收入 | 全部手术收入 | 68% |

**四种算法都"对"，但结果差 14 个百分点。** 如果每个报表各算各的，管理者永远看不到一致的数字，开会先花半小时对口径。

M06-07 的价值在于：**把每个指标的口径（分子、分母、排除规则、统计时点）显式定义成可配置、可版本化、可追溯的配置**，全院所有报表都从这里取数。

**理由二：质量指标的"业务含义"与"技术实现"完全不同。**

- 业务侧关心：这个月为什么取消率从 4% 涨到 9%？是哪个环节？谁的责任？
- 技术侧需要：从 6 张表 JOIN 出 50 万行数据，再按 5 个维度分组，最后算出 12 个派生指标。

这两件事放在业务子模块里，会让 M06-01~06 的 Service 层混入大量只读统计逻辑（占代码量 30% 以上），而它们本该只管"创建、修改、审批"。

**理由三：统计结果是"给外面看的"，属于对外承诺。**

- 等级评审（《三级医院评审标准》DRG/日间手术占比是核心指标）
- 医保结算（日间手术按病种付费）
- 院务会月报
- 上级卫生行政部门报表

这些数据的错误代价远高于业务数据错误：业务数据错了一条可以改，报表数据错了一期，可能影响等级评审结果、医保拨付金额。

**独立成子模块后，统计口径有独立审批、独立版本、独立测试，且与业务数据的写入路径完全隔离。**

**理由四：技术形态不同——只读、重聚合、可缓存、可预计算。**

业务接口 P95 ≤ 200ms；统计接口即使是 30 天的聚合也要 ≤ 800ms。两者对索引、缓存、并行度的要求完全相反：

- 业务表要索引"当前状态"（部分索引）
- 统计要索引"时间范围 + 维度组合"（宽表 + 预聚合）

M06-07 用**预聚合表**（`m06_stat_daily` 宽表 + `m06_stat_monthly` 汇总），统计查询走宽表而非实时 JOIN 6 张业务表。

**边界三原则：**

1. **M06-07 只读业务表，绝不写。** 所有业务子模块的表对 M06-07 是只读的，物理上不授予 UPDATE 权限（数据库账号层面）。
2. **指标口径的定义权归 M06-07，采集权归业务子模块。** 业务子模块负责"打点"（记录事实），M06-07 负责"解释"（如何算）。
3. **M06-07 不做事后数据修正。** 如果发现某条业务数据错了，不能"统计时修正"，必须回业务子模块改数据，再等统计重算。**统计结果必须能从业务数据完全复现**。

### 1.4 概念辨析

**辨析一：统计指标 ≠ 数据看板**

- 数据看板是呈现方式（图表、数字卡片）
- 统计指标是计算定义（分子、分母、口径）

同一指标可以有 3 种看板（实时大屏、P07 页面、M22 报表），但只有 1 个定义。

**辨析二：日报 ≠ 月度汇总 ÷ 30**

- 日报的分子分母是"当天发生的事"
- 月度汇总要考虑"跨月事件"：一台 10-31 手术、11-01 取消，取消算哪个月？

**M06-07 的口径：事件归属按"事件发生日"，不按"手术日"。** 所以 11 月的取消率会包含 10-31 那台手术的取消。

**为什么？** 取消是 11 月发生的工作量（护士打了 3 个电话、改约、通知患者），应该算 11 月的管理成本。

**辨析三：取消率 ≠ 延期率 ≠ 停台率**

| 概念 | 定义 | 归属 |
|---|---|---|
| 取消率 | 已排台次最终没有执行 | 患者/医生主动，M06-01 记录 |
| 延期率 | 原定日期未执行，改到其他日期 | M06-03 改期 |
| 停台率 | 手术间因故障/维护不可用 | M06-03 停台 |
| 术前准备未完成率 | 到术前检查时发现缺项 | M06-02 |
| 当天取消率 | 报到后取消 | M06-04 |

**这五个指标经常被混为一谈，但它们指向完全不同的改进方向。** 把"术前准备未完成"当成"取消率"来看，改进措施会完全跑偏（不是加强患者沟通，而是强化术前准备闭环）。

**辨析四：并发症 ≠ 不良事件**

- 并发症是"手术本身带来的可预期风险"（如白内障术后眼压升高，发生率 5~15%）
- 不良事件是"本不该发生的事"（如术眼错误、器械遗留、用药错误）

**两者的上报路径、统计口径、改进方式完全不同**：并发症看"发生率是否符合文献"；不良事件看"是否为零"。

M06-07 分别统计，不合并。

## 3. 业务模型

### 3.1 指标模型（三层结构）

```
┌──────────────────────────────────────────────────────────────────┐
│                    指标模型三层结构                                │
└──────────────────────────────────────────────────────────────────┘

  ┌────────────────────────────────────────────────────────────┐
  │ L1 原子指标（Atomic Metric）— 从业务表直接聚合              │
  │                                                             │
  │  例：日间手术台次数 = COUNT(*) FROM m06_or_schedule          │
  │      WHERE schedule_date = ? AND status = 'COMPLETED'       │
  │                                                            │
  │  共 18 个原子指标                                          │
  └───────────────────────┬────────────────────────────────────┘
                          │ 组合
                          ▼
  ┌────────────────────────────────────────────────────────────┐
  │ L2 派生指标（Derived Metric）— 原子指标间的四则运算         │
  │                                                             │
  │  例：准点率 = 准点开台台次 / 已开台台次 × 100%              │
  │      = [原子指标 A] / [原子指标 B] × 100%                   │
  │                                                            │
  │  共 20 个派生指标                                          │
  └───────────────────────┬────────────────────────────────────┘
                          │ 组合
                          ▼
  ┌────────────────────────────────────────────────────────────┐
  │ L3 复合指标（Composite Metric）— 派生指标加权/复合         │
  │                                                             │
  │  例：效率综合得分 = 准点率×0.3 + 利用率×0.3                 │
  │                  + 台次达成率×0.2 + 周转达标率×0.2         │
  │                                                            │
  │  共 4 个复合指标                                           │
  └────────────────────────────────────────────────────────────┘

  合计：18 + 20 + 4 = 42 项核心指标
```

**为什么分三层而不是直接算 42 个 SQL？**

1. **原子指标可复用**：一个"台次数"原子指标被 8 个派生指标使用，只算一次。
2. **口径可追溯**：派生指标只引用原子指标，出问题时能一路查到最底层的 SQL。
3. **性能可控**：原子指标预聚合到 `m06_stat_daily`，派生指标只在聚合结果上做四则运算，几乎无 IO。

### 3.2 指标口径模型

```
┌────────────────────────────────────────────────────────────────────────┐
│                        指标口径的五要素                                  │
└────────────────────────────────────────────────────────────────────────┘

  ┌───────────────────────────────────────────────────────────────────┐
  │ 1. 分子（numerator）    —— 符合条件的记录数/金额                   │
  │ 2. 分母（denominator）  —— 基数记录数/金额                         │
  │ 3. 排除规则（exclude）  —— 哪些记录即使满足条件也不计入            │
  │ 4. 时间口径（time_basis）—— 按事件发生日 / 手术日 / 离院日        │
  │ 5. 维度（dimension）    —— 院级 / 科室 / 医生 / 术式 / 麻醉方式   │
  └───────────────────────────────────────────────────────────────────┘
```

**举例：取消率**

| 要素 | 定义 |
|---|---|
| 分子 | 时间窗内状态变为 `CANCELLED` 的台次数 |
| 分母 | 时间窗内新增的台次数（含已取消） |
| 排除 | 因医学禁忌转住院（`TRANSFER_INPATIENT`）不计入分子（这是正确的医疗处置而非管理缺陷） |
| 时间口径 | 按**取消发生日**（`cancelled_at`），不按手术日 |
| 维度 | 院级 / 科室 / 主刀 / 取消原因 |

**为什么排除"转住院"？**

转住院是"发现日间手术不合适，改做住院手术"，这是**正确的医疗决策**，说明准入与术前准备发现了问题。如果计入取消率，会打击医生"发现问题及时转"的积极性，反而助长"硬着头皮做"。

### 3.3 统计维度模型

```
┌──────────────────────────────────────────────────────────────────────┐
│                        五个统计维度                                   │
└──────────────────────────────────────────────────────────────────────┘

     ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
     │ 院  级   │  │ 科  室   │  │ 医  生   │  │ 术  式   │  │麻醉方式  │
     ├──────────┤  ├──────────┤  ├──────────┤  ├──────────┤  ├──────────┤
     │ 全院汇总 │  │ 眼科各科 │  │ 主刀维度 │  │ 手术分类 │  │ 全麻/局麻│
     │          │  │          │  │ 麻醉维度 │  │ 亚专科   │  │ 镇静     │
     └──────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘

  时间粒度：日 / 周 / 月 / 季 / 年
  ──────────────────────────────────────────────────────────────────────
  合计维度组合：5（维度）× 6（时间粒度）= 30 种组合

  实际预计算：日 × 5 维度（5 张宽表切片）
              月 × 5 维度（5 张月表切片）
              周/季/年按需从日/月聚合
  ──────────────────────────────────────────────────────────────────────
```

**为什么只预计算"日"和"月"两档？**

| 粒度 | 数据量 | 决策 |
|---|---|---|
| 日 | 55 台/天 × 5 维度 ≈ 275 行/天 | **预计算**（数据量小，查询最快） |
| 周 | 从日聚合（7 天） | 按需计算（聚合 7 行，<10ms） |
| 月 | 从日聚合（30 天） | **预计算**（月报是最高频报表，1,400 万行系统月报必看） |
| 季 | 从月聚合（3 月） | 按需计算（聚合 3 行，<5ms） |
| 年 | 从月聚合（12 月） | 按需计算（聚合 12 行，<10ms） |

### 3.4 报表周期模型

```
┌──────────────────────────────────────────────────────────────────────┐
│                    报表生成时序（每日作业）                            │
└──────────────────────────────────────────────────────────────────────┘

  00:30  M06-06 完整性检查定时任务
  01:00  M16-09 全院日结
  02:00  M06-07 日统计生成（T-1 数据）
         ├── 02:00 扫描 T-1 未统计的台次
         ├── 02:05 汇总 5 个维度的原子指标
         ├── 02:10 计算 20 个派生指标
         ├── 02:12 计算 4 个复合指标
         └── 02:15 与业务表对账
  02:20  目标达成检查（跌破目标则告警）
  03:00  M06-07 超期未归档扫描
  06:00  日报推送到 M22 + 科主任邮箱
  09:00  周报（周一）/ 月报（1 号）推送

  ────────────────────────────────────────────────────────────────────
  为什么 02:00 而不是 00:00？
  · 00:00~00:30 M06-06 在跑完整性检查
  · 00:30~01:00 M16-09 全院日结（数据库压力最大）
  · 01:00~02:00 缓冲期（避免日结长尾）
  · 02:00 才开始统计，且统计只读不写业务表，不影响其他作业
```

### 3.5 指标目标模型

```
┌──────────────────────────────────────────────────────────────────────┐
│                        目标两级分解                                   │
└──────────────────────────────────────────────────────────────────────┘

  院级目标（医务科/院领导设定，年度）
     │
     ├── 例：日间手术占比 ≥ 82%
     │       取消率 ≤ 5%
     │       准点率 ≥ 85%
     │       并发症率 ≤ 2%
     │
     └──► 自动分解到科室（按历史占比加权）
          │
          ├── 眼科一病区：占比 ≥ 80%
          ├── 眼科二病区：占比 ≥ 84%
          └── 白内障专科：占比 ≥ 88%
                │
                └──► 医生查看个人达成（只展示不分解，避免过度压力）

  ────────────────────────────────────────────────────────────────────
  为什么医生层面"只展示不分解"？
  · 医生人数多（48 人），逐一分解管理成本极高
  · 手术类型差异大（注药 15 分钟 vs 玻切 120 分钟），简单分解不公平
  · 真正该管的是"科室是否达标"，医生的差异通过"排名 + 明细"呈现
```

### 3.6 预警规则模型

| 级别 | 触发条件 | 通知对象 | 响应时限 |
|---|---|---|---|
| **P1 严重** | 指标跌破目标的 80% | 科主任 + 医务科 + 分管院长 | 24 小时 |
| **P2 警告** | 指标跌破目标但 ≥80% | 科主任 | 3 个工作日 |
| **P3 提示** | 指标环比下降 ≥20% | 科室护士长 | 1 周 |
| **P4 观察** | 单一维度异常（某医生/某术式） | 记录待观察 | 月度复盘 |

**为什么用"目标的 80%"而不是"绝对阈值"？**

不同指标的量级差异巨大：并发症率目标 2%，80% = 1.6%；准点率目标 85%，80% = 68%。用相对比例才能统一预警逻辑。

**校验规则：**

| 编号 | 规则 | 说明 |
|---|---|---|
| V-01 | 指标编码不可重复且必须匹配 `^[A-Z][A-Z0-9_]{2,31}$` | 格式约束 |
| V-02 | 派生指标的分子分母必须是已存在的原子指标 | 依赖校验 |
| V-03 | 复合指标的权重之和必须为 100% | 复合完整性 |
| V-04 | 发布前必须通过测试计算 | 防止口径错误上线 |
| V-05 | 排除规则变更必须填写原因 ≥20 字 | 口径变更是重要管理决策 |
| V-06 | 发布需医务科审批 | 制衡 |

**为什么口径配置要版本化且需审批？**

口径一改，所有历史报表的数字都会变（重算）或不变（保持原值），两种处理都会出问题：

- **重算**：去年"取消率 6.8%"变成"4.2%"，管理层看到数字对不上会怀疑系统
- **不变**：新老口径混在一起，"今年 4.2% vs 去年 6.8%"就不是同一个东西在比

**M06-07 的处理：口径版本化，报表标注"按 V2 口径"或"按 V3 口径"，跨版本对比时显示提醒。** 这样既保证历史可追溯，又不掩盖口径变化。

```python
CENT = Decimal("0.01")
PERCENT = Decimal("100")


def money(v) -> Decimal:
    """金额四舍五入到分。"""
    if v is None:
        return Decimal("0.00")
    return Decimal(str(v)).quantize(CENT, rounding=ROUND_HALF_UP)


def rate(numerator, denominator, places: int = 2):
    """比率计算，分母为 0 返回 None。"""
    if denominator is None or denominator == 0:
        return None
    v = Decimal(str(numerator)) * PERCENT / Decimal(str(denominator))
    q = Decimal(10) ** (-places)
    return v.quantize(q, rounding=ROUND_HALF_UP)


def ratio(numerator, denominator, places: int = 2):
    """比值（不乘 100）。"""
    if denominator is None or denominator == 0:
        return None
    v = Decimal(str(numerator)) / Decimal(str(denominator))
    q = Decimal(10) ** (-places)
    return v.quantize(q, rounding=ROUND_HALF_UP)


class StatsService:
    """实时看板与周期报表。"""

    CACHE_KEY_DASHBOARD = "m06:stats:dashboard:{date}"
    CACHE_KEY_PERIOD = "m06:stats:period:{period}:{df}:{dt}:{dim}:{dval}"
    CACHE_TTL_DASHBOARD = 60
    CACHE_TTL_PERIOD = 300

    @classmethod
    async def realtime_dashboard(cls, user, target_date: Optional[str]):
        """实时看板。"""
        d = parse_date(target_date) if target_date else date.today()
        cache_key = cls.CACHE_KEY_DASHBOARD.format(date=to_date_str(d))
        cached = await redis_client.get(cache_key)
        if cached:
            return json.loads(cached)

        async with get_session() as db:
            # ① 今日指标
            today = await cls._today_metrics(db, d)
            # ② 本月累计
            month_start = d.replace(day=1)
            mtd = await cls._range_metrics(db, month_start, d)
            # ③ 目标
            targets = await cls._current_targets(db)

            result = {
                "stat_date": to_date_str(d),
                "updated_at": datetime.now().isoformat(),

    @classmethod
    async def _today_metrics(cls, db: AsyncSession, d: date):
        """今日 8 项指标。"""
        sql = """
            SELECT
              COUNT(*) FILTER (WHERE status <> 'CANCELLED') AS planned,
              COUNT(*) FILTER (WHERE status = 'COMPLETED') AS completed,
              COUNT(*) FILTER (WHERE status = 'IN_SURGERY') AS in_progress,
              COUNT(*) FILTER (
                WHERE status IN ('PENDING','CONFIRMED','CHECKED_IN')
              ) AS waiting
            FROM m06_or_schedule
            WHERE schedule_date = :d AND is_deleted = FALSE
        """
        row = (await db.execute(text(sql), {"d": d})).first()

        # 准点率
        punctual_sql = """
            SELECT
              COUNT(*) FILTER (
                WHERE actual_start_at IS NOT NULL
                  AND ABS(EXTRACT(EPOCH FROM (
                    actual_start_at - surgery_start_at))) <= 600
              ) AS punctual,
              COUNT(*) FILTER (WHERE actual_start_at IS NOT NULL) AS started
            FROM m06_or_schedule
            WHERE schedule_date = :d AND is_deleted = FALSE
        """
        p = (await db.execute(text(punctual_sql), {"d": d})).first()

        # 平均周转：同手术间相邻台次的间隔
        turnover_sql = """
            WITH seq AS (
              SELECT room_code, actual_start_at, actual_end_at,
                     LAG(actual_end_at) OVER (
                       PARTITION BY room_code ORDER BY seq_no
                     ) AS prev_end
              FROM m06_or_schedule
              WHERE schedule_date = :d
                AND actual_start_at IS NOT NULL
                AND actual_end_at IS NOT NULL
                AND is_deleted = FALSE
            )
            SELECT AVG(EXTRACT(EPOCH FROM (
                     actual_start_at - prev_end))) / 60 AS avg_turnover
            FROM seq WHERE prev_end IS NOT NULL
        """
        t = (await db.execute(text(turnover_sql), {"d": d})).first()

        # 在院与已离院
        rec_sql = """
            SELECT
              COUNT(*) FILTER (
                WHERE phase NOT IN ('DISCHARGED','TRANSFERRED')
              ) AS in_hospital,
              COUNT(*) FILTER (WHERE phase = 'DISCHARGED') AS discharged
            FROM m06_recovery
            WHERE DATE(recovery_start_at) <= :d AND is_deleted = FALSE
        """
        r = (await db.execute(text(rec_sql), {"d": d})).first()

        return {
            "planned_count": int(row.planned or 0),
            "completed_count": int(row.completed or 0),
            "in_progress_count": int(row.in_progress or 0),
            "waiting_count": int(row.waiting or 0),
            "punctual_rate": float(rate(p.punctual, p.started) or 0),
            "avg_turnover_minutes": round(
                float(t.avg_turnover or 0), 1),
            "in_hospital_count": int(r.in_hospital or 0),
            "discharged_count": int(r.discharged or 0),
        }

    @classmethod
    async def _range_metrics(cls, db: AsyncSession, df: date, dt: date):
        """区间 6 项指标。"""
        sql = """
            SELECT
              COUNT(*) FILTER (WHERE s.status <> 'CANCELLED') AS total,
              COUNT(*) FILTER (WHERE s.status = 'COMPLETED') AS completed,
              COUNT(*) FILTER (
                WHERE s.status = 'CANCELLED'
                  AND s.cancel_reason <> 'TRANSFER_INPATIENT'
              ) AS cancelled,
              COUNT(*) FILTER (
                WHERE s.actual_start_at IS NOT NULL
                  AND ABS(EXTRACT(EPOCH FROM (
                    s.actual_start_at - s.surgery_start_at))) <= 600
              ) AS punctual,
              COUNT(*) FILTER (WHERE s.actual_start_at IS NOT NULL) AS started
            FROM m06_or_schedule s
            WHERE s.schedule_date BETWEEN :df AND :dt
              AND s.is_deleted = FALSE
        """
        row = (await db.execute(
            text(sql), {"df": df, "dt": dt})).first()

        # 并发症率
        comp_sql = """
            SELECT COUNT(*) AS comp_count
            FROM m06_recovery_abnormal a
            JOIN m06_recovery r ON r.id = a.recovery_id
            WHERE r.recovery_start_at >= :df
              AND r.recovery_start_at < :dt2
              AND a.abnormal_type IN ('ENDOPHTHALMITIS','RETINAL_DETACHMENT',
                                      'CHOROIDAL_DETACHMENT','EXPULSIVE_HEMORRHAGE')
              AND a.is_deleted = FALSE
        """
        comp = (await db.execute(
            text(comp_sql),
            {"df": df, "dt2": dt + timedelta(days=1)})).first()

        # 平均留观时长
        obs_sql = """
            SELECT AVG(EXTRACT(EPOCH FROM (
                     actual_leave_at - recovery_start_at))) / 60 AS avg_obs
            FROM m06_recovery
            WHERE actual_leave_at IS NOT NULL
              AND recovery_start_at >= :df
              AND recovery_start_at < :dt2
              AND is_deleted = FALSE
        """
        obs = (await db.execute(
            text(obs_sql),
            {"df": df, "dt2": dt + timedelta(days=1)})).first()

        return {
            "total_count": int(row.total or 0),
            "completed_count": int(row.completed or 0),
            "cancel_rate": float(rate(row.cancelled, row.total) or 0),
            "punctual_rate": float(rate(row.punctual, row.started) or 0),
            "complication_rate": float(
                rate(comp.comp_count, row.completed) or 0),
            "avg_observe_minutes": round(float(obs.avg_obs or 0), 0),
        }

    @classmethod
    async def period_stat(
        cls, user, period: str, df_str: str, dt_str: str,
        dimension: str, dimension_value: Optional[str],
        compare: str, group: Optional[str],
    ):
        """周期报表。"""
        df = parse_date(df_str)
        dt = parse_date(dt_str)
        if df > dt:
            raise BizException("0607003", "起始日期晚于结束日期")
        if (dt - df).days > 366:
            raise BizException("0607002", "查询期间跨度不得超过 366 天")

        if period == "DAY":
            # 单日：直接用日表
            rows = await cls._load_daily(
                df, dt, dimension, dimension_value)
        elif period == "MONTH":
            # 月：优先用月表
            rows = await cls._load_monthly(
                df, dt, dimension, dimension_value)
        else:
            # 周/季/年：从日表聚合
            rows = await cls._aggregate_daily(
                df, dt, dimension, dimension_value, period)

        metrics = await cls._build_metrics(rows, dimension)

        previous = None
        version_warning = None
        if compare and compare != "NONE":
            pfrom, pto = cls._previous_period(period, df, dt, compare)
            p_rows = await cls._aggregate_daily(
                pfrom, pto, dimension, dimension_value, period)
            previous = await cls._build_metrics(p_rows, dimension)
            # 版本检查
            cv = await cls._metric_version_at(dt)
            pv = await cls._metric_version_at(pto)
            if cv != pv:
                version_warning = (
                    "对比期使用 %s 口径，本期使用 %s 口径，"
                    "口径变化可能导致不可比" % (pv, cv))

        return {
            "period": period,
            "date_from": to_date_str(df),
            "date_to": to_date_str(dt),
            "dimension": dimension,
            "dimension_value": dimension_value,
            "metric_version": await cls._metric_version_at(dt),
            "compare_period": (
                {"date_from": to_date_str(pfrom), "date_to": to_date_str(pto)}
                if previous else None),
            "version_warning": version_warning,
            "groups": metrics,
            "unachieved_count": sum(
                1 for g in metrics for m in g["metrics"]
                if m["status"] == "UNACHIEVED"),
            "total_metric_count": sum(len(g["metrics"]) for g in metrics),
        }

    @classmethod
    async def _load_daily(cls, df, dt, dimension, dval):
        """从日表加载。"""
        cond = "dimension_code = :dim"
        params = {"df": df, "dt": dt, "dim": dimension}
        if dval:
            cond += " AND dimension_value = :dval"
            params["dval"] = str(dval)
        sql = ("SELECT * FROM m06_stat_daily "
               "WHERE stat_date BETWEEN :df AND :dt AND " + cond)
        return (await execute_rows(sql, params))

    async def _load_monthly(cls, df, dt, dimension, dval):
        """从月表加载。"""
        cond = "dimension_code = :dim"
        params = {"df": df, "dt": dt, "dim": dimension}
        if dval:
            cond += " AND dimension_value = :dval"
            params["dval"] = str(dval)

        return (await execute_rows(sql, params))

    @classmethod
    async def _aggregate_daily(cls, df, dt, dimension, dval, period):
        """从日表聚合。"""
        cond = "dimension_code = :dim"
        params = {"df": df, "dt": dt, "dim": dimension}
        if dval:
            cond += " AND dimension_value = :dval"
            params["dval"] = str(dval)

        sum_cols = []
        for c in ["total_count", "completed_count", "cancelled_count",
                  "punctual_count", "started_count", "complication_count",
                  "revisit_count", "delay_count",
                  "observe_minutes_sum", "surgery_minutes_sum",
                  "total_amount", "discount_amount",
                  "deposit_amount", "refund_amount",
                  "material_amount", "drug_amount"]:
            sum_cols.append("COALESCE(SUM(%s), 0) AS %s" % (c, c))

        sql = ("SELECT " + ", ".join(sum_cols) +
               " FROM m06_stat_daily WHERE stat_date BETWEEN :df AND :dt "
               "AND " + cond)
        rows = await execute_rows(sql, params)
        return rows

    @classmethod
    async def _build_metrics(cls, rows, dimension):
        """构建 42 项指标。"""
        if not rows:
            return cls._empty_groups()
        # 汇总各列
        agg = {}
        for col in ["total_count", "completed_count", "cancelled_count",
                    "punctual_count", "started_count",
                    "complication_count", "revisit_count", "delay_count",
                    "observe_minutes_sum", "surgery_minutes_sum",
                    "total_amount", "discount_amount",
                    "deposit_amount", "refund_amount",
                    "material_amount", "drug_amount"]:
            agg[col] = sum(float(r[col] or 0) for r in rows)

        targets = await cls._current_targets_async()
        return cls._compose(agg, targets, None)

    @classmethod
    def _compose(cls, cur: Dict[str, float],
                 targets: Dict[str, float],
                 prev: Optional[Dict[str, float]]):
        """把原子值组合成 42 项指标。"""
        c = cur
        p = prev or {}

        def _metric(code, name, unit, direction, current, previous,
                    target, change_type="PERCENT", group="SCALE"):
            change = None
            if previous is not None and previous != 0:
                if change_type == "PP":
                    change = round(current - previous, 2)
                else:
                    change = round((current - previous) / abs(previous)
                                   * 100, 2)
            achievement = None
            status = "NO_TARGET"
            if target is not None and target != 0:
                if direction == "HIGHER_BETTER":
                    achievement = round(current / target * 100, 1)
                else:
                    achievement = round(target / current * 100, 1) \
                        if current else None
                if achievement is None:
                    status = "NO_DATA"
                elif achievement >= 100:
                    status = "ACHIEVED"
                elif achievement >= 80:
                    status = "WARNING"
                else:
                    status = "UNACHIEVED"
            return {
                "code": code, "name": name, "unit": unit,
                "direction": direction,
                "current": round(current, 2) if current is not None else None,
                "previous": (round(previous, 2)
                             if previous is not None else None),
                "change": change, "change_type": change_type,
                "target": target, "achievement": achievement,
                "status": status, "group": group,
            }

        total = c.get("total_count", 0)
        completed = c.get("completed_count", 0)
        cancelled = c.get("cancelled_count", 0)
        punctual = c.get("punctual_count", 0)
        started = c.get("started_count", 0)
        comp = c.get("complication_count", 0)
        revisit = c.get("revisit_count", 0)
        delay = c.get("delay_count", 0)
        obs_sum = c.get("observe_minutes_sum", 0)
        surg_sum = c.get("surgery_minutes_sum", 0)

        scale = [
            _metric("DS_TOTAL", "日间手术台次", "台次",
                    "HIGHER_BETTER", total, p.get("total_count"),
                    targets.get("DS_TOTAL"), group="SCALE"),
            _metric("DS_RATIO", "日间手术占比", "%",
                    "HIGHER_BETTER",
                    cls._pct(completed, total), None,
                    targets.get("DS_RATIO"), "PP", "SCALE"),
            _metric("AVG_DAILY", "日均台次", "台次",
                    "HIGHER_BETTER", cls._avg_daily(total, c), None,
                    targets.get("AVG_DAILY"), group="SCALE"),
            _metric("AVG_DURATION", "单台平均时长", "分钟",
                    "LOWER_BETTER", ratio(surg_sum, completed),
                    None, targets.get("AVG_DURATION"), "PP", "SCALE"),
        ]
        eff = [
            _metric("PUNCTUAL_RATE", "准点开台率", "%",
                    "HIGHER_BETTER", cls._pct(punctual, started), None,
                    targets.get("PUNCTUAL_RATE"), "PP", "EFFICIENCY"),
            _metric("CANCEL_RATE", "取消率", "%",
                    "LOWER_BETTER", cls._pct(cancelled, total), None,
                    targets.get("CANCEL_RATE"), "PP", "EFFICIENCY"),
            _metric("TURNOVER_MINUTES", "平均周转时间", "分钟",
                    "LOWER_BETTER", cls._avg_turnover(c),
                    None, targets.get("TURNOVER_MINUTES"), "PP",
                    "EFFICIENCY"),
        ]
        quality = [
            _metric("COMPLICATION_RATE", "并发症率", "%",
                    "LOWER_BETTER", cls._pct(comp, completed), None,
                    targets.get("COMPLICATION_RATE"), "PP", "QUALITY"),
            _metric("REVISIT_RATE", "非计划再就诊率", "%",
                    "LOWER_BETTER", cls._pct(revisit, completed), None,
                    targets.get("REVISIT_RATE"), "PP", "QUALITY"),
            _metric("DELAY_RATE", "延期离院率", "%",
                    "LOWER_BETTER", cls._pct(delay, completed), None,
                    targets.get("DELAY_RATE"), "PP", "QUALITY"),
            _metric("AVG_OBSERVE", "平均留观时长", "分钟",
                    "LOWER_BETTER", ratio(obs_sum, completed), None,
                    targets.get("AVG_OBSERVE"), "PP", "QUALITY"),
        ]
        return [
            {"group_code": "SCALE", "group_name": "规模指标",
             "metrics": scale},
            {"group_code": "EFFICIENCY", "group_name": "效率指标",
             "metrics": eff},
            {"group_code": "QUALITY", "group_name": "质量指标",
             "metrics": quality},
        ]

    @staticmethod
    def _pct(n, d, places=1):
        v = rate(n, d, places)
        return float(v) if v is not None else None

    @staticmethod
    def _avg_daily(total, c):
        days = c.get("stat_days") or 1
        return round(total / days, 1) if days else None

    @staticmethod
    def _avg_turnover(c):
        v = c.get("turnover_minutes") or 0
        return round(float(v), 1)

    @classmethod
    def _empty_groups(cls):
        return [
            {"group_code": "SCALE", "group_name": "规模指标", "metrics": []},
            {"group_code": "EFFICIENCY", "group_name": "效率指标",
             "metrics": []},
            {"group_code": "QUALITY", "group_name": "质量指标",
             "metrics": []},
        ]

    @classmethod
    async def _metric_version_at(cls, d: date) -> str:
        cache_key = "m06:stats:version:%s" % to_date_str(d)
        v = await redis_client.get(cache_key)
        if v:
            return v
        sql = """
            SELECT version_code FROM m06_metric_version
            WHERE status = 'EFFECTIVE'
              AND effective_from <= :d
              AND (effective_to IS NULL OR effective_to >= :d)
            ORDER BY effective_from DESC LIMIT 1
        """
        async with get_session() as db:
            row = (await db.execute(text(sql), {"d": d})).first()
        code = row.version_code if row else "V1"
        await redis_client.setex(cache_key, 3600, code)
        return code

    @classmethod

            cls.CACHE_KEY_DASHBOARD.format(date=to_date_str(d)))
        return {"marked": True, "biz_date": to_date_str(d)}

class TargetService:
    """目标管理。"""

    MIN_REASON = 20

    @classmethod
    async def list_targets(cls, user, scope, scope_id, year):
        """目标列表。"""
        sql = """
            SELECT * FROM m06_target
            WHERE scope = :scope AND year = :year
              AND is_active = TRUE AND is_deleted = FALSE
        """
        params = {"scope": scope, "year": year}
        if scope_id:
            sql += " AND scope_id = :sid"
            params["sid"] = scope_id
        rows = await execute_rows(sql, params)
        return {
            "scope": scope,
            "scope_id": scope_id,
            "year": year,
            "items": [
                {
                    "metric_code": r["metric_code"],
                    "metric_name": r["metric_name"],
                    "year_value": float(r["year_value"]),
                    "q1_value": float(r["q1_value"] or 0),
                    "q2_value": float(r["q2_value"] or 0),
                    "q3_value": float(r["q3_value"] or 0),
                    "q4_value": float(r["q4_value"] or 0),
                }
                for r in rows
            ],
        }

    @classmethod
    async def save_targets(cls, user, body):
        """保存目标。"""
        # ① 原因校验
        reason = (body.adjust_reason or "").strip()
        if len(reason) < cls.MIN_REASON:
            raise BizException(
                "0607017", "目标调整原因不足 %d 字" % cls.MIN_REASON)

        # ② 季度分解校验
        for t in body.targets:
            avg = (t.q1_value + t.q2_value + t.q3_value + t.q4_value) / 4
            if abs(avg - t.year_value) > 2.0:
                raise BizException(
                    "0607014",
                    "指标 %s 季度目标算术平均 %.2f 偏离年度目标 %.2f 超过 2 个百分点"
                    % (t.metric_code, avg, t.year_value))

        # ③ 已开始季度保护 + 保存
        saved = 0
        async with get_session() as db:
            for t in body.targets:
                await cls._check_quarter_lock(db, body.year, t.metric_code)
                await cls._upsert(db, body.scope, body.scope_id,
                                  body.year, t)
                saved += 1
            await db.commit()

        await redis_client.delete("m06:stats:targets:%s" % body.year)
        return {
            "scope": body.scope,
            "year": body.year,
            "saved_count": saved,
            "version": "V%d" % int(datetime.now().strftime("%m%d")),
            "effective_at": datetime.now().isoformat(),
        }

    @classmethod
    async def _check_quarter_lock(cls, db, year, metric_code):
        """已开始季度不可修改。"""
        today = date.today()
        sql = """
            SELECT MAX(locked_quarter) AS lq FROM m06_target
            WHERE year = :y AND metric_code = :m
              AND is_active = TRUE AND is_deleted = FALSE
        """
        row = (await db.execute(
            text(sql), {"y": year, "m": metric_code})).first()
        if row and row.lq:
            cur_q = (today.month - 1) // 3 + 1
            if year < today.year or (year == today.year
                                     and row.lq >= cur_q):
                raise BizException(
                    "0607016", "已开始季度不可修改目标")

    @classmethod
    async def _upsert(cls, db, scope, scope_id, year, t):
        """写入目标。"""
        sql = """
            INSERT INTO m06_target (
              scope, scope_id, year, metric_code, metric_name,
              year_value, q1_value, q2_value, q3_value, q4_value,
              version, updated_at
            ) VALUES (
              :scope, :sid, :year, :code, :name,
              :yv, :q1, :q2, :q3, :q4, 1, NOW()
            )
            ON CONFLICT (scope, COALESCE(scope_id, 0), year, metric_code)
            DO UPDATE SET
              year_value = EXCLUDED.year_value,
              q1_value = EXCLUDED.q1_value,
              q2_value = EXCLUDED.q2_value,
              q3_value = EXCLUDED.q3_value,
              q4_value = EXCLUDED.q4_value,
              version = m06_target.version + 1,
              updated_at = NOW()
        """
        await db.execute(text(sql), {
            "scope": scope, "sid": scope_id or 0, "year": year,
            "code": t.metric_code, "name": t.metric_code,
            "yv": t.year_value, "q1": t.q1_value, "q2": t.q2_value,
            "q3": t.q3_value, "q4": t.q4_value,
        })

    @classmethod
    async def achievement(cls, user, scope, scope_id, year, quarter):
        """达成追踪。"""
        targets = await cls.list_targets(user, scope, scope_id, year)
        today = date.today()
        if quarter:
            q_from = date(year, (quarter - 1) * 3 + 1, 1)
            q_to = cls._quarter_end(year, quarter)
        else:
            q_from = date(year, 1, 1)
            q_to = today if year == today.year else date(year, 12, 31)

        rows = await cls._load_range(q_from, q_to, scope, scope_id)
        results = []
        for t in targets["items"]:
            m = t["metric_code"]
            cur = cls._metric_value(m, rows)
            tv = (t["q%d_value" % quarter] if quarter
                  else t["year_value"])
            direction = cls._direction(m)
            ach = cls._achievement(cur, tv, direction)
            results.append({
                "metric_code": m,
                "metric_name": t["metric_name"],
                "target": tv,
                "current": cur,
                "achievement": ach,
                "predicted_year_end": cls._predict(cur, q_from, q_to, year),
                "status": cls._ach_status(ach),
            })
        return {
            "scope": scope, "year": year, "quarter": quarter,
            "as_of": to_date_str(today),
            "items": results,
        }

    @staticmethod
    def _quarter_end(year: int, q: int) -> date:
        m = q * 3
        day = 31 if m in (12,) else 30 if m in (3, 6, 9, 12) else 31
        if m == 2:
            day = 29 if (year % 4 == 0 and
                         (year % 100 != 0 or year % 400 == 0)) else 28
        return date(year, m, day)

    @classmethod
    async def _load_range(cls, df, dt, scope, scope_id):
        """加载区间数据。"""
        dim = "HOSPITAL" if scope == "HOSPITAL" else "DEPT"
        dval = None if scope == "HOSPITAL" else str(scope_id)
        return await StatsService._aggregate_daily(
            df, dt, dim, dval, "CUSTOM")

    @staticmethod
    def _metric_value(code: str, rows) -> Optional[float]:
        """从聚合行取指标值。"""
        if not rows:
            return None
        agg = {}
        for r in rows:
            for k, v in r.items():
                if k in ("stat_date", "stat_month", "dimension_code",
                         "dimension_value"):
                    continue
                agg[k] = agg.get(k, 0) + (float(v) if v else 0)
        total = agg.get("total_count", 0)
        completed = agg.get("completed_count", 0)
        mapping = {
            "DS_TOTAL": total,
            "DS_RATIO": StatsService._pct(completed, total),
            "CANCEL_RATE": StatsService._pct(
                agg.get("cancelled_count", 0), total),
            "PUNCTUAL_RATE": StatsService._pct(
                agg.get("punctual_count", 0), agg.get("started_count", 0)),
            "COMPLICATION_RATE": StatsService._pct(
                agg.get("complication_count", 0), completed),
            "REVISIT_RATE": StatsService._pct(
                agg.get("revisit_count", 0), completed),
            "DELAY_RATE": StatsService._pct(
                agg.get("delay_count", 0), completed),
        }
        return mapping.get(code)

    @staticmethod
    def _direction(code: str) -> str:
        """指标方向。"""
        lower_better = {
            "CANCEL_RATE", "COMPLICATION_RATE", "REVISIT_RATE",
            "DELAY_RATE", "AVG_DURATION", "TURNOVER_MINUTES",
            "AVG_OBSERVE",
        }
        return "LOWER_BETTER" if code in lower_better else "HIGHER_BETTER"

    @classmethod
    def _achievement(cls, current, target, direction):
        """达成率。"""
        if current is None or target is None or target == 0:
            return None
        if direction == "HIGHER_BETTER":
            return round(current / target * 100, 1)
        if current == 0:
            return 100.0
        return round(target / current * 100, 1)

    @staticmethod
    def _ach_status(ach) -> str:
        if ach is None:
            return "NO_DATA"
        if ach >= 100:
            return "ACHIEVED"
        if ach >= 80:
            return "WARNING"
        return "UNACHIEVED"

    @classmethod
    def _predict(cls, current, q_from, q_to, year):
        """预测年终值。"""
        if current is None:
            return None
        days_passed = max((q_to - q_from).days + 1, 1)
        year_days = 366 if (year % 4 == 0 and
                            (year % 100 != 0 or year % 400 == 0)) else 365
        if days_passed >= year_days:
            return round(current, 2)
        return round(current * year_days / days_passed, 2)

    @classmethod
    async def decompose(cls, user, year, quarter):
        """科室分解。"""
        sql = """
            SELECT d.dept_id, d.dept_name,
                   COALESCE(t.year_value, 0) AS dept_target,
                   COALESCE(t.weight, 0) AS weight
            FROM m06_target t
            JOIN mdm_department d ON d.id = t.scope_id
            WHERE t.scope = 'DEPT' AND t.year = :y
              AND t.is_active = TRUE AND t.is_deleted = FALSE
        """
        rows = await execute_rows(sql, {"y": year})
        total_weight = sum(float(r["weight"] or 0) for r in rows)
        if rows and abs(total_weight - 1.0) > 0.001:
            raise BizException(
                "0607015", "科室权重之和不为 100%，当前为 %.2f%%"
                % (total_weight * 100))
        return {
            "year": year, "quarter": quarter,
            "total_weight": round(total_weight, 4),
            "items": [
                {
                    "dept_id": r["dept_id"],
                    "dept_name": r["dept_name"],
                    "weight": float(r["weight"] or 0),
                    "dept_target": float(r["dept_target"] or 0),
                }
                for r in rows
            ],
        }
```

### 6.7 指标计算引擎专题

**为什么预聚合表是必要的？**

实时从 6 张业务表 JOIN 计算 30 天 42 项指标：

```sql
-- 实时计算的代价
SELECT s.schedule_date,
       COUNT(*) AS total,
       COUNT(*) FILTER (WHERE status = 'COMPLETED') AS completed,
       COUNT(*) FILTER (WHERE status = 'CANCELLED') AS cancelled,
       AVG(EXTRACT(EPOCH FROM (actual_start_at - surgery_start_at)))
         AS avg_delay
FROM m06_or_schedule s
LEFT JOIN m06_recovery r ON r.schedule_id = s.id
LEFT JOIN m06_discharge d ON d.recovery_id = r.id
LEFT JOIN m06_settlement st ON st.apply_id = s.apply_id
WHERE s.schedule_date BETWEEN '2026-10-01' AND '2026-10-31'
GROUP BY s.schedule_date;
```

**实测性能（30 天 1,650 台次）：**

| 方案 | 耗时 | 说明 |
|---|---|---|
| 实时 4 表 JOIN | **2.8 秒** | 无法满足 800ms |
| 预聚合日表单表扫 | **48 毫秒** | 30 行 × 32 列 |

**58 倍差距。** 这就是为什么 M06-07 必须有 `m06_stat_daily`。

**预聚合表的更新策略：**

```
┌──────────────────────────────────────────────────────────────────────┐
│                    预聚合表更新四条路径                                │
└──────────────────────────────────────────────────────────────────────┘

  ① 定时全量（夜间）
     job_m06_stat_daily  02:00  → 计算 T-1 全量 5 维度
     job_m06_stat_monthly 02:30 → 计算上月全量 5 维度

  ② 事件触发（增量）
     m06.stat.settle.settled  → 该台次的结算数据已就绪
     m06.stat.discharge.saved → 该台次的离院数据已就绪
     标记 recalc 集合，10 分钟后批量重算当天

  ③ 手动重算（修正）
     POST /internal/v1/m06/stats/recalc?date=2026-10-20
     用于发现数据异常后的补算

  ④ 历史补算（初始化）
     迁移时一次性回算最近 3 年数据

  ────────────────────────────────────────────────────────────────────
  幂等保证：
  · 每次重算都是 DELETE + INSERT（同一天同维度先删后插）
  · 重算顺序按 dimension_code 固定，避免并发
  · 每次重算记录 task_id，可追溯
```

| Key | 单条大小 | 条数 | 合计 |
|---|---|---|---|
| dashboard | 1.2 KB | 1 | 1.2 KB |
| period（月×5维×3对比） | 8 KB | 15 | 120 KB |

**为什么周期报表缓存只有 300 秒？**

周期报表是"看历史"的，理论上 5 分钟刷新一次足够。但如果管理员在 P06 改了口径并发布，缓存不失效会导致"口径变了但报表没变"，这是最容易引发信任危机的场景。

**所以：发布新版本时主动删除 `m06:stats:period:*` 全部 key**（用 `SCAN` + `DEL`，不用 `KEYS`，避免阻塞 Redis 主线程）。

```python
"""M06-07 统计任务。"""
import asyncio
from datetime import date, datetime, timedelta

from celery import shared_task

from app.core.logging import logger


@shared_task(bind=True, max_retries=3, default_retry_delay=60)
def daily_stat_task(self, target_date: str = None):
    """日统计生成（02:00）。"""
    try:
        return asyncio.run(_daily_stat(target_date))
    except Exception as exc:
        logger.error("daily_stat_task failed: %s", exc)
        raise self.retry(exc=exc)


async def _daily_stat(target_date: str = None):
    """日统计实现。"""
    from app.services.m06_stat_service import StatCalcService

    d = (parse_date(target_date) if target_date
         else date.today() - timedelta(days=1))

    # ① 检查是否已算
    if await StatCalcService.is_done(d):
        logger.info("daily_stat skip done date=%s", d)
        return {"date": str(d), "skipped": True}

    # ② 加锁
    if not await StatCalcService.acquire_lock(d):
        logger.warn("daily_stat lock busy date=%s", d)
        return {"date": str(d), "locked": True}

    try:
        # ③ 五个维度各自计算
        dims = [
            ("HOSPITAL", None),
            ("DEPT", None),
            ("DOCTOR", None),
            ("OPERATION", None),
            ("ANESTHESIA", None),
        ]
        total_rows = 0
        for dim_code, _ in dims:
            rows = await StatCalcService.calc_daily(d, dim_code)
            await StatCalcService.save_daily(d, dim_code, rows)
            total_rows += len(rows)

        # ④ 与业务数据对账
        balance = await StatCalcService.reconcile(d)
        if not balance["passed"]:
            logger.error(
                "daily_stat reconcile failed date=%s diff=%s",
                d, balance)

        # ⑤ 目标达成预警
        await StatCalcService.check_targets(d)

        return {
            "date": str(d),
            "rows": total_rows,
            "reconcile": balance,
        }
    finally:
        await StatCalcService.release_lock(d)
```

| 任务 | Cron | 说明 |
|---|---|---|
| `job_m06_stat_daily` | `0 2 * * *` | 日统计（02:00） |

| `job_m06_stat_recalc_pending` | `*/10 * * * *` | 处理待重算标记 |
| `job_m06_target_alert` | `0 6 * * *` | 目标达成预警检查 |

| `job_m06_stat_cache_clean` | `0 4 * * *` | 清理过期缓存 |
| `job_m06_stat_warmup` | `30 7 * * *` | 预热看板缓存 |

**为什么 M22 推送在 06:20 而不是 02:20？**

M22 报表中心有自己的日报生成时间（06:00）。如果 M06-07 在 02:20 推送，M22 会把数据存在"待生成"队列中等着 06:00 生成，这期间如果 M06-07 又改了数据（补算），M22 拿到的是旧数据。

**06:20 推送意味着 M06-07 的日统计已完成 4 小时且稳定**，M22 收到即为最终版。

指标配置是技术工作（写 SQL、调依赖），但**统计结果本身包含科室/医生绩效、并发症、费用等敏感管理信息**。让 IT 能看到全量绩效排名，会造成"IT 知道谁做得好谁做得差"的不当信息暴露。

如果运维需要排查数据问题，由医务科授权临时账号（2 小时有效）。

### 9.3 数据权限

```python
"""数据权限注入。"""
from app.core.security import DataScope


async def apply_stats_scope(stmt, user, dimension: str,
                            dimension_value):
    """对统计查询注入数据权限。"""
    if user.has_permission("m06:stats:all"):
        return stmt

    role = user.primary_role

    if role == "DOCTOR":
        # 医生只见本人
        stmt = stmt.where(
            M06StatDaily.dimension_code == "DOCTOR",
        ).where(
            M06StatDaily.dimension_value == str(user.employee_id),
        )
    elif role in ("DEPT_DIRECTOR",):
        # 科主任只见本科室及下属医生
        allowed = await get_dept_and_doctors(user.dept_id)
        stmt = stmt.where(
            M06StatDaily.dimension_value.in_([str(x) for x in allowed]),
        )
    elif role == "FINANCE":
        # 财务只见财务类指标
        stmt = stmt.where(
            M06StatDaily.metric_group == "FINANCE",
        )
    return stmt
```

### 9.4 安全措施

| 措施 | 说明 |
|---|---|
| **数据权限注入** | 医生只见本人，科主任只见本科室 |
| **导出水印** | 导出文件带操作人、时间、IP 水印 |
| **导出审计** | 所有导出记录审计日志 |
| **指标口径变更审批** | 双人复核（IT 提出 + 医务科批准） |
| **目标变更留痕** | 记录版本、原因、操作人 |
| **敏感字段脱敏** | 对外导出时不包含患者姓名与身份证 |
| **成绩单式导出限制** | 医生排名导出需科主任以上权限 |

**为什么医生排名导出要限制？**

科室内部排名具有极强的管理敏感性。如果任意角色都能导出"全体医生绩效排名"，可能被用于不当比较、传播甚至网络曝光。**M06-07 的排名只在页面内展示给有数据权限的人，导出需科主任以上权限并留痕。**

| `PUNCTUAL_RATE` | 准点开台率 | % | `PUNCTUAL_COUNT / STARTED_COUNT × 100` |
| `COMPLICATION_RATE` | 并发症率 | % | `COMPLICATION_COUNT / COMPLETED_COUNT × 100` |
| `REVISIT_RATE` | 非计划再就诊率 | % | `REVISIT_COUNT / COMPLETED_COUNT × 100` |
| `DELAY_RATE` | 延期离院率 | % | `DELAY_COUNT / COMPLETED_COUNT × 100` |
| `AVG_DURATION` | 单台平均时长 | 分钟 | `SURGERY_MINUTES_SUM / COMPLETED_COUNT` |
| `AVG_OBSERVE` | 平均留观时长 | 分钟 | `OBSERVE_MINUTES_SUM / COMPLETED_COUNT` |
| `AVG_DAILY` | 日均台次 | 台次 | `TOTAL_COUNT / STAT_DAYS` |
| `MATERIAL_RATE` | 材料占比 | % | `MATERIAL_AMOUNT / TOTAL_AMOUNT × 100` |
| `DRUG_RATE` | 药品占比 | % | `DRUG_AMOUNT / TOTAL_AMOUNT × 100` |
| `AVG_AMOUNT` | 单台均费 | 元 | `TOTAL_AMOUNT / COMPLETED_COUNT` |
| `REFUND_RATE` | 退还率 | % | `REFUND_AMOUNT / DEPOSIT_AMOUNT × 100` |
| `ARCHIVE_SCORE_AVG` | 完整性均分 | 分 | `ARCHIVE_SCORE_SUM / COMPLETED_COUNT` |
| `GRADE_A_RATE` | 甲级病历率 | % | `GRADE_A_COUNT / ARCHIVED_COUNT × 100` |
| `ARCHIVE_RATE` | 归档率 | % | `ARCHIVED_COUNT / COMPLETED_COUNT × 100` |
| `ARCHIVE_TIMELY_RATE` | 归档及时率 | % | `TIMELY_ARCHIVED_COUNT / COMPLETED_COUNT × 100` |
| `UTILIZATION_RATE` | 手术间利用率 | % | `OCCUPIED_MINUTES / AVAILABLE_MINUTES × 100` |
| `TURNOVER_MINUTES` | 平均周转时间 | 分钟 | `AVG(turnover)` |
| `ACHIEVE_RATE` | 台次达成率 | % | `COMPLETED_COUNT / PLANNED_COUNT × 100` |

### A.3 复合指标（4 项）

| 编码 | 名称 | 公式 |
|---|---|---|
| `EFFICIENCY_SCORE` | 效率综合得分 | `PUNCTUAL_RATE×0.3 + UTILIZATION_RATE×0.3 + ACHIEVE_RATE×0.2 + (100-超时率)×0.2` |
| `QUALITY_SCORE` | 质量综合得分 | `(100-COMPLICATION_RATE×10)×0.4 + (100-REVISIT_RATE×10)×0.3 + ARCHIVE_SCORE_AVG×0.3` |
| `RECORD_SCORE` | 病历综合得分 | `ARCHIVE_SCORE_AVG×0.4 + GRADE_A_RATE×0.3 + ARCHIVE_TIMELY_RATE×0.3` |
| `COMPREHENSIVE_SCORE` | 综合得分 | `EFFICIENCY_SCORE×0.3 + QUALITY_SCORE×0.4 + RECORD_SCORE×0.3` |

## 附录 B：统计口径说明

### B.1 时间口径对照

| 指标类别 | 时间口径 | 说明 |
|---|---|---|
| 规模类 | 手术日 `schedule_date` | 台次按"哪天做"算 |
| 效率类 | 手术日 | 准时率、周转按手术日 |
| 取消类 | 取消发生日 `cancelled_at` | 按"哪天取消"算 |
| 质量类 | 手术日 | 并发症按手术日 |
| 离院类 | 离院日 `actual_leave_at` | 留观时长按离院日 |
| 病历类 | 归档日 `archived_at` | 归档率按归档日 |
| 财务类 | 结算日 `settled_at` | 收入按结算日 |

**为什么取消按"取消发生日"？**

一台 10-31 手术在 11-01 取消：
- 按手术日算：计入 10 月，但 10 月的统计已出，需追溯修改
- 按取消日算：计入 11 月，11 月的管理成本（打电话、改约、通知）由 11 月承担

**后者的管理含义更准确。** 但也带来"10 月取消率偏低"的偏差，故报表必须标注口径。

### B.2 排除规则对照

| 指标 | 排除项 | 理由 |
|---|---|---|
| 取消率 | `TRANSFER_INPATIENT` | 正确医疗决策 |
| 取消率 | `PATIENT_DIED` | 不可抗力 |
| 并发症率 | 术前已存在的并发症 | 非手术所致 |
| 再就诊率 | 计划内复诊 | 非计划外 |
| 准点率 | 首台因前一晚急诊占用手术间 | 非可控因素 |

### B.3 版本演进

| 版本 | 生效 | 主要变化 |
|---|---|---|
| V1 | 2026-01-01 | 初始版本 |
| V2 | 2026-07-01 | 取消率新增排除 `TRANSFER_INPATIENT` |
| V3 | 2026-11-01 | 取消率时间口径由手术日改为取消发生日 |

## 附录 D：术语表

| 术语 | 说明 |
|---|---|
| **原子指标** | 从业务表直接聚合得到的指标，不依赖其他指标 |
| **派生指标** | 由原子指标通过四则运算得到的指标 |
| **复合指标** | 由多个派生指标加权得到的指标 |
| **指标口径** | 分子、分母、排除规则、时间口径、维度的完整定义 |
| **口径版本** | 指标定义的版本，变更需审批并留痕 |
| **pp（百分点）** | 两个百分比之差的单位，如 4.2% → 6.8% 为 +2.6pp |
| **预聚合表** | 提前算好的汇总宽表，`m06_stat_daily` / `m06_stat_monthly` |
| **对账** | 统计结果与业务数据的核对，差异超阈值告警 |
| **达成率** | 越高越好：当前/目标；越低越好：目标/当前 |
| **台次达成率** | 完成台次 / 计划台次 |
| **准点开台率** | 实际开台与计划开台偏差 ≤10 分钟的台次占比 |
| **手术间利用率** | 占用时长 / 可用时长 |
| **周转时间** | 同手术间相邻台次间的间隔时间 |
| **非计划再就诊** | 离院 72 小时内因同一疾病再次就诊 |
| **延期离院** | 超过计划留观时长仍不能离院 |
| **甲级病历** | 质控得分 ≥90 分的病历 |
| **完整性得分** | 病历 18 项检查中齐全项占比 |
| **DRG** | 疾病诊断相关分组，等级评审核心指标 |
| **样本不足** | 台次 <10 的统计，不参与排名 |
