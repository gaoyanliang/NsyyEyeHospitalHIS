#### 1.2.2 `updated_at` 触发器

```sql
CREATE OR REPLACE FUNCTION trg_set_updated_at()

BEGIN

    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 每张含 updated_at 的表都需创建：
CREATE TRIGGER trg_mpi_patient_updated
    BEFORE UPDATE ON mpi_patient
    FOR EACH ROW EXECUTE FUNCTION trg_set_updated_at();
```

### 1.3 索引与约束规范

#### 1.3.1 敏感字段三列模式（M03 强制）

**M03 涉及大量患者隐私数据，所有敏感字段必须存三列：**

| 列 | 类型 | 用途 |
|---|---|---|
| `xxx`（加密值） | VARCHAR(256) | AES-256-GCM 密文，需解密才能读 |
| `xxx_hash` | CHAR(64) | SHA-256，用于**等值查询与唯一性判断** |
| `xxx_mask` | VARCHAR(64) | 展示用，如 `110***********1234` |

**适用字段：**

| 表 | 字段 |
|---|---|
| `mpi_patient` | `primary_id_no_*` |
| `mpi_patient_identifier` | `identifier_no_*` |
| `mpi_patient_contact` | `contact_value_*` |
| `mpi_patient_address` | `address_detail_*` |
| `mpi_patient_relation` | `relation_phone_*` |
| `mpi_portal_account` | `phone_*` |
| `mpi_portal_register_task` | `id_no_*`、`phone_mask` |

```sql
-- 示例：mpi_patient 敏感字段
primary_id_no_enc   VARCHAR(256),   -- 加密值
primary_id_no_hash  CHAR(64),       -- 哈希
primary_id_no_mask  VARCHAR(64),    -- 掩码

-- 唯一性判断用哈希
CREATE UNIQUE INDEX uk_mpi_patient_id_no
    ON mpi_patient (primary_id_type, primary_id_no_hash)
    WHERE primary_id_no_hash IS NOT NULL AND is_deleted = FALSE;
```

> **禁止：** 任何敏感字段不得以明文存储、明文返回给调用方（需权限+解密+审计）。

#### 1.3.2 索引原则

| 原则 | 说明 |
|---|---|
| 主键 | 每表必有 |
| 唯一 | 业务唯一键（含 `is_deleted`） |
| 查询索引 | 高频 WHERE 字段 |
| 组合索引 | 区分度高的字段在前 |
| 部分索引 | 用于 `is_deleted=FALSE` 等 |
| JSONB | 需要检索时建 GIN 索引 |
| 中文姓名 | `pg_trgm` + GIN |

#### 1.3.3 中文检索

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- 患者姓名模糊检索
CREATE INDEX idx_mpi_patient_name_trgm
    ON mpi_patient USING GIN (patient_name gin_trgm_ops);
```

#### 1.3.4 跨模块外键

**M03 与 M01/M02 及其他业务模块之间不建物理外键**，由应用层校验：

| M03 表.字段 | 引用 | 说明 |
|---|---|---|
| `mpi_patient.*` | — | 权威表 |
| `mpi_member.patient_id` | `mpi_patient.id` | 同模块，可建 |
| `mpi_followup_plan.patient_id` | `mpi_patient.id` | 同模块，可建 |
| `mpi_portal_binding.patient_id` | `mpi_patient.id` | 同模块，可建 |
| `mpi_*.created_by` | `mdm_employee.id` | **逻辑引用** |
| `mpi_*.dept_id` | `mdm_department.id` | **逻辑引用** |
| `mpi_*.created_by`（门户） | `mpi_portal_account.account_id` | 逻辑引用 |

> **注意：** 同模块内的 `patient_id` 可考虑建物理外键（有级联保护），但考虑到患者合并需要重定向，**建议不建物理 FK，由应用层保证**。

### 1.4 分区策略

| 表 | 分区键 | 粒度 | 保留期 |
|---|---|---|---|
| `mpi_patient_log` | `created_at` | 月度 | 永久（含院可配 10 年，**不可下线归档**） |
| `mpi_patient_sync_log` | `created_at` | 月度 | 1 年 |
| `mpi_merge_log` | `created_at` | 月度 | 永久 |
| `mpi_message_record` | `created_at` | 月度 | 3 年 |
| `mpi_message_receipt` | `created_at` | 月度 | 3 年 |
| `mpi_portal_binding_log` | `created_at` | 月度 | 3 年 |
| `mpi_portal_access_log` | `created_at` | 月度 | 1 年 |
| `mpi_followup_task_log` | `created_at` | 月度 | 3 年 |

**分区创建示例：**

```sql
CREATE TABLE mpi_patient_log (
    ...
) PARTITION BY RANGE (created_at);

-- 每月由定时任务创建下月分区
CREATE TABLE IF NOT EXISTS mpi_patient_log_2026_11
    PARTITION OF mpi_patient_log
    FOR VALUES FROM ('2026-11-01') TO ('2026-12-01');
```

**注意：** 分区表的主键必须包含分区键。

```sql
PRIMARY KEY (id, created_at)
-- 或使用唯一索引
CREATE UNIQUE INDEX uk_patient_log_id ON mpi_patient_log (id, created_at);
```

> **法规注意：** `mpi_patient_log`（患者变更日志）与 `mpi_merge_log`（合并日志）**不得删除**，属于医疗数据溯源的法定要求。即使分区也不可 DROP，应转冷存储。
