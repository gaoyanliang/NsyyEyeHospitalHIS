## 1. 模块概述

### 1.1 模块定位

M05-04 住院费用联动与预交金是 M05 与 M16 收费结算管理之间的**桥梁子模块**。它把「患者住院了、住的是几级护理、住了几天」这些临床事实，转换成 M16-03 能记账的收费事实。

```
┌──────────────────────────────────────────────────────────────────┐
│                     M05-04 在链路中的位置                         │
└──────────────────────────────────────────────────────────────────┘

  M05-01 入院登记       M05-03 在院管理        M08 护理站      M12/M13/M14/M09
  （住院单创建）        （病情/护理等级）      （治疗执行）     （检查/检验/发药/手术）
        │                    │                    │                 │
        │ 预交金收取           │ 等级变更             │ 执行完成          │ 执行完成
        ▼                    ▼                    ▼                 ▼
  ┌───────────────────────────────────────────────────────────────────┐
  │                    M05-04 住院费用联动与预交金                       │
  │  ──────────────────────────────────────────────────────────────── │
  │  ① 每日床日费自动计费（床位费 + 护理费 + 诊查费）                    │
  │  ② 预交金催缴与欠费预警                                             │
  │  ③ 费用汇总视图与患者费用查询                                        │
  │  ④ 退费申请（协调 M16-08）                                          │
  │  ⑤ 计费任务失败补偿与对账                                            │
  └──────────────────────────────┬────────────────────────────────────┘
                                 │ 全部通过 M16 接口记账
                                 ▼
  ┌───────────────────────────────────────────────────────────────────┐
  │              M16-03 住院与日间手术结算（唯一记账方）                  │
  │  m16_inpatient_charge / m16_deposit_account / m16_inpatient_settle │
  └───────────────────────────────────────────────────────────────────┘
```

**一句话定位：** M05-04 **不自己算钱、不自己记账**，它负责「知道今天该给谁记什么费」，并把这件事交给 M16-03 执行，然后盯住记账结果、催缴预交金、汇总费用给临床看。

### 1.2 为什么独立成子模块

| # | 理由 | 详述 |
|---|---|---|
| 1 | **每日自动计费是 M05 唯一主动发起计费的地方** | 医嘱类费用（药/检/治/手）由执行方（M14/M12/M09）自己调 M16 记账；只有床位费、护理费、诊查费这类「每天发生一次、无人执行」的费用必须有人定时触发，这个责任只能落在 M05 |
| 2 | **只有 M05 知道「今天该按几级护理收费」** | 护理等级存在 `m05_stay.nursing_level`，M16 拿不到。住院期间护理等级可能从二级变成一级，费用必须跟着变 |
| 3 | **计费失败必须有补偿与对账闭环** | 每日 00:30 一次的任务涉及几百个患者、上千条记账，任何一条失败（网络、M16 抖动、参数缺失）都必须在次日发现并补记，否则直接漏收。这是一套独立的补偿/对账逻辑 |
| 4 | **预交金催缴是独立的运营动作** | 「余额不足」不是收费，是提醒临床和家属去交钱。它有独立的阈值、通知策略、停机规则（余额为负是否停止治疗） |
| 5 | **临床需要一个「费用视角」的住院视图** | 医生查房时要看「这个患者已经花了多少、预交金还剩多少」；护士要知道「这个患者是否欠费」；住院处要按科室汇总。这些视图不属于 M16（M16 面向财务） |

**反证：** 若不独立，把每日计费塞进 M05-03 的出院/等级变更流程里，会得到三处不一致的计费触发点；把催缴塞进 M16-03，会让 M16 从「记账」变成「治理欠费」，职责越界。

| 事项 | M05-04 | M16-03 | M08 / M12 / M14 / M09 |
|---|---|---|---|
| 每日床位费/护理费/诊查费触发 | ✅ **唯一触发方** | ❌ 只接收记账请求 | ❌ |

| 欠费预警与催缴 | ✅ **唯一负责方** | ❌ | ❌ 只订阅提醒 |

### 1.4 概念辨析

| 概念 | 定义 | 归属 |
|---|---|---|
| **预交金（Deposit）** | 住院前/住院中预先交纳的款项，是「医院的负债」，不确认收入 | M16-03 持有账户，M05-04 发起收取 |
| **记账（Charge）** | 住院期间发生的费用，是「患者对医院的债务」，记在 `m16_inpatient_charge` | M16-03 落库 |
| **结算（Settlement）** | 出院时把「记账总额」与「预交金可用额」对冲，算出补交或退还 | M16-03 |
| **床日费（Daily Charge）** | 按天计收的床位费/护理费/诊查费，与具体执行动作无关 | M05-04 触发 |
| **欠费（Owed）** | `预交金可用余额 < 已记账金额`，即患者欠医院的钱 | M05-04 监控 |
| **中途结算（Interim）** | 长期住院期间按周期做一次结算，避免预交金池无限累积 | M16-03 执行，M05-04 触发 |
| **冲销（Reverse）** | 对已记账的费用做红冲，不动原始记录，另写负数记录 | M16-03 |
| **退费（Refund）** | 把钱退给患者，走 M16-08 退费流程 | M16-08 |

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 每日计费成功率 | ≥ 99.9% | 失败项必须在次日 08:00 前补记完成 |
| 每日计费准时率 | 100% | 00:30 启动，01:00 前完成 |
| 床日费漏记率 | 0 | 任何在院患者每天都必须有床日费记录 |

| 预交金余额实时性 | ≤ 60 秒 | 收预交金后 60 秒内余额可查 |
| 欠费预警及时性 | 100% | 余额低于阈值当日必须通知 |
| 费用查询响应 | P95 ≤ 300ms | 30 天明细 |
| 对账差异发现率 | 100% | 每日 03:00 对账任务 |
| 中途结算触发准确率 | 100% | 按周/按金额触发，不漏不重 |

## 2. 业务范围与边界

### 2.1 范围内

1. **每日床日费自动计费**
   - 床位费：按当前床位类型 × 病床日计价（`md_bed_type.daily_fee`）
   - 护理费：按当前护理等级对应收费项目（`NURSE` 分类）× 天
   - 诊查费：按科室对应诊查费 × 天
   - 触发时机：每日 00:30，对「目标日全天在院」的患者生成
   - 幂等键：`DAILY:{admission_id}:{charge_date}:{charge_item_code}`

2. **预交金管理**
   - 收取（现金/银行卡/扫码/转账/医保预付）
   - 打印预交金收据
   - 退还（未使用部分，需审批）
   - 余额查询（实时从 M16-03 取，不本地存）

3. **欠费预警与催缴**
   - 余额低于阈值触发提醒（每日 09:00、15:00 各一次扫描）
   - 余额为负触发停机提醒（是否停医嘱由医生判断）
   - 通知对象：病区护士站、责任医生、患者家属（M03-05 短信）

4. **费用查询与汇总**
   - 患者费用明细（按日期/按类别）
   - 按科室、病区、费用类别汇总
   - 费用对照（已记账 vs 已收预交金 vs 差额）

5. **退费申请协调**
   - 对已记账的费用发起退费申请，转向 M16-08
   - 退费原因、审批链路沿用 M16-08

6. **计费补偿与对账**
   - 失败补偿队列（指数退避）
   - 每日 03:00 对账：`在院患者 × 在院天数` vs `m16_inpatient_charge` 中的 DAILY 记录
   - 床日费漏记自动补记并告警

### 2.2 范围外

| 事项 | 归属 | 说明 |
|---|---|---|
| 住院费用记账落库 | M16-03 | M05-04 只发请求 |
| 预交金账户余额存储与冻结 | M16-03 | M05-04 只查询 |
| 出院结算与中途结算计算 | M16-03 | M05-04 只发起与接收 |
| 医嘱类费用（药/检/治/手/材）记账 | 执行方触发 → M16-03 落库 | 不经 M05-04 |
| 医保结算 | 医保接口 / 未来模块 | 预留 `insurance_amount` |
| 费用清单打印格式 | M16-03 | M05-04 提供数据 |
| 收费项目与价格维护 | M01-06 | 只读 |
| 欠费核销（坏账） | M17 财务 | — |

### 2.3 与相邻模块的分工边界（一句话）

- M05-04 说「**今天该给这个患者记多少钱**」
- M16-03 说「**已经记了多少、预交金还剩多少、出院该补还是该退**」
- M08/M12/M14/M09 说「**我刚执行完一个动作，应该记一笔**」
- M17 说「**这个月的住院收入是多少**」

## 3. 业务模型

### 3.1 每日计费全景

```
每日 00:30
    │
    ▼
┌────────────────────────────────────────────────────────────────────┐
│ ① 确定目标日：charge_date = 昨天（00:30 补记前一天）                  │
│ ② 查在院患者：stay_status ∈ {IN_HOSPITAL, TRANSFERRING, DISCHARGING} │
│    且 admitted_at::date <= charge_date                              │
│    且 (discharged_at IS NULL OR discharged_at::date > charge_date)  │
│ ③ 逐患者生成计费任务                                                  │
└────────────────────────────┬───────────────────────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
  ┌──────────┐        ┌──────────┐        ┌──────────┐
  │ 床位费    │        │ 护理费    │        │ 诊查费    │
  └────┬─────┘        └────┬─────┘        └────┬─────┘
       │                   │                   │
       └───────────┬───────┴───────────────────┘
                   ▼
       ┌────────────────────────────────┐
       │ 写 m05_charge_task（PENDING）    │
       └───────────────┬────────────────┘
                       │
                       ▼
       ┌────────────────────────────────┐
       │ 逐条调 M16-03 charge 接口        │
       │ 幂等键 DAILY:{adm}:{date}:{code} │
       └───────────────┬────────────────┘
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
   ┌─────────────┐          ┌─────────────┐
   │ SUCCESS     │          │ FAILED      │
   │ 记录 charge_id│          │ 进补偿队列    │
   └─────────────┘          └──────┬──────┘
                                   │
                                   ▼
                         ┌──────────────────┐
                         │ 指数退避重试 10 次 │
                         │ 2/4/8/.../512 分钟│
                         └──────────────────┘
```

### 3.2 床日费的三类项目与来源

| 费用类别 | `charge_category` | 来源 | 定价方式 |
|---|---|---|---|
| **床位费** | `BED` | `md_bed_type.charge_item_code` | 按天（`daily_fee`） |
| **护理费** | `NURSING` | `m05_charge_config` 的「护理等级 → 收费项目」映射 | 按天，等级不同项目不同 |
| **诊查费** | `CLINIC` | `m05_charge_config` 的「科室 → 诊查费项目」映射 | 按天 |

**为什么护理费与诊查费要建映射表而非直接调 M01：**
`md_charge_item.charge_class` 只有 `NURSE` / `DIAG` 大类，一个医院可能有多个护理费项目（一级护理 ¥30/天、二级护理 ¥20/天、三级护理 ¥10/天、特级护理 ¥60/天）。映射「护理等级 → 具体收费项目编码」是医院运营配置，不是主数据，放 M05-04 自己的配置表里，且允许按病区差异化（如 ICU 病区特级护理项目不同）。

### 3.3 计费范围判定（谁需要记今天的费）

```python
# 判定逻辑（伪代码，实现见 6.6）
def needs_daily_charge(stay, charge_date):
    # ① 入院日 <= 目标日
    if stay.admitted_at.date() > charge_date:
        return False
    # ② 出院日 > 目标日（出院当天仍记一天）
    if stay.discharged_at and stay.discharged_at.date() <= charge_date:
        return False
    # ③ 状态允许
    if stay.stay_status not in ("IN_HOSPITAL", "TRANSFERRING", "DISCHARGING"):
        return False
    return True
```

**为什么出院当天仍然记一天床日费：**
患者上午办出院，上午之前一直在床上。医院收费惯例是「入院日计、出院日不计」或「两头都计」，眼科医院取**「入院日计、出院日计、住院天数 = 出院日 - 入院日 + 1」**，与 M05-03 的 `stay_days` 公式一致。**这两处必须一致**，否则床日费条数 ≠ 住院天数，对账天天报警。

### 3.4 计费幂等设计

**三层幂等：**

| 层 | 机制 | 说明 |
|---|---|---|
| L1 应用层 | 先查 `m05_charge_task` 是否已有 `(admission_id, charge_date, charge_item_code)` 的 SUCCESS 记录 | 快速失败，避免无谓调用 |
| L2 Redis | `SET m05:charge:lock:{admission_id}:{charge_date}:{code} NX EX 300` | 防同一任务被两个 Celery worker 同时执行 |
| L3 M16 层 | M16-03 的 `uk_m16_inpcharge_source (source_type, source_id)` 部分唯一索引 | 最终防线，`source_id` 由 M05-04 生成 |

**`source_id` 生成规则：** 由于 M16-03 的 `source_id` 是 `BIGINT`，而日结业务需要「住院号 + 日期 + 项目」三元组，M05-04 采用 **哈希压缩**：

```
source_id = abs(hash64("DAILY:{admission_id}:{charge_date}:{charge_item_code}")) % (2^53)
```

同时在 `m05_charge_task` 上记录 `idempotency_key`（字符串原文），用于对账与排查。**为什么不用自增 ID：** 自增 ID 每次重试都会变，失去幂等性。

### 3.5 预交金模型

```
┌─────────────────────────────────────────────────────────────┐
│  预交金账户（M16-03 m16_deposit_account，M05-04 只读）         │
│  ─────────────────────────────────────────────────────────  │
│  total_deposit      累计预交金                                 │
│  total_refund       累计退还                                   │
│  frozen_amount      结算时冻结额                                │
│  available_balance  = total_deposit - total_refund - frozen   │
│  accumulated_charge 累计记账额（M16 维护）                       │
└─────────────────────────────────────────────────────────────┘

欠费判定：
  owed_amount = accumulated_charge - available_balance
  is_owed     = owed_amount > 0

阈值预警（M05.CHARGE.WARN_RATIO，默认 0.20）：
  available_balance < 预计未来 3 天费用 × 0.20  → 提醒续交
```

**为什么 M05-04 不本地存余额：**
预交金余额是资金数据，必须只有一个真相源（M16-03）。M05-04 本地存快照只用于 **列表/看板展示**（`m05_admission_deposit_snap`，M05-01 已建），实时业务判断（能否出院、是否停机）必须实时查 M16-03。

### 3.7 费用汇总模型

**四个口径：**

| 口径 | 计算方式 | 用途 |
|---|---|---|
| **患者实时** | `Σ m16_inpatient_charge.amount`（status='NORMAL'，含负数冲销） | 患者床头费用查询 |
| **科室日结** | 按 `dept_id` + `charge_date` 聚合 | 科室成本核算 |
| **病区日结** | 按 `ward_id` + `charge_date` 聚合 | 病区运营考核 |
| **全院日结** | 按 `charge_date` 聚合 | 财务记账 |

**为什么不冗余存储：** `m16_inpatient_charge` 是唯一数据源，M05-04 提供视图与预聚合表（`m05_charge_daily_stat`）。预聚合表每日 01:30 由 Celery 任务刷新，历史数据不变，当天数据实时算。

### 3.8 中途结算触发

长期住院（如角膜移植术后观察、眼外伤）会累积大额预交金池，需中途结算。

**触发条件（三选一）：**

| 条件 | 默认值 | 参数 |
|---|---|---|
| 住院天数 ≥ N 天 | 30 天 | `M05.CHARGE.INTERIM_DAYS` |
| 累计费用 ≥ N 元 | 50000 元 | `M05.CHARGE.INTERIM_AMOUNT` |
| 预交金余额 ≥ N 元 | 100000 元 | `M05.CHARGE.INTERIM_DEPOSIT` |

**执行流程：** M05-04 检测到条件 → 生成提醒任务（不自动结算）→ 住院处人工发起 → 调 M16-03 `interim-settle`。**为什么不自动：** 中途结算涉及退钱/补钱，必须有人的确认。

### 3.9 退费申请

M05-04 发起退费，走 M16-08：

```
M05-04 检测应退（冲销笔/多收笔）
    │
    ▼
POST /api/v1/m16/refund（M16-08）
    │  body: {scene:"MANUAL_ADJUST", admission_id, items[], reason, attachment}
    ▼
M16-08 审批 → 执行 → 回写 M16-03 → 发事件 m16.refund.success
    │
    ▼
M05-04 订阅事件 → 刷新费用视图
```

**M05-04 只做「发起」，不参与审批与执行。**

### 3.10 数量与金额铁律

1. **金额一律 `NUMERIC(12,2)`**，禁止 float
2. **单价 `NUMERIC(12,4)`**（M16-03 定义）
3. **行级先舍入再汇总**：`amount = ROUND(unit_price × quantity, 2)`
4. **床日费 quantity 恒为 1**（一天一次）
5. **冲销用负数**，不改原记录
6. **预交金不接受小数位 > 2 的金额**
7. **幂等键必须含日期与项目编码**，否则重跑会重复记

```python
"""M05-04 住院费用联动与预交金 —— Service 层"""

import asyncio
import hashlib
import logging
from datetime import date, datetime, timedelta
from decimal import ROUND_HALF_UP, Decimal
from typing import Any, Dict, List, Optional

from fastapi import HTTPException
from sqlalchemy import func, select, text
from sqlalchemy.ext.asyncio import AsyncSession

from app.models.m05_charge import (
    M05ChargeAlert,
    M05ChargeConfig,
    M05ChargeDailyStat,
    M05ChargeTask,
    M05ChargeTaskLog,
)
from app.models.m05_stay import M05Stay
from app.utils.exception import BizException

logger = logging.getLogger(__name__)

CENT = Decimal("0.01")
ZERO = Decimal("0.00")


def money(value) -> Decimal:
    """金额规范化：两位小数，四舍五入。"""
    return Decimal(str(value)).quantize(CENT, rounding=ROUND_HALF_UP)


# ==================== 计费任务状态 ====================

TASK_PENDING = "PENDING"
TASK_SUCCESS = "SUCCESS"
TASK_FAILED = "FAILED"
TASK_DEAD = "DEAD"
TASK_SKIPPED = "SKIPPED"

# 计费类别 → m16 charge_category 映射
CHARGE_CATEGORY_MAP = {
    "BED": "BED",
    "NURSING": "NURSING",
    "CLINIC": "CLINIC",
}

# 重试退避：2^n 分钟（1~10 次）
RETRY_BACKOFF_MINUTES = [2, 4, 8, 16, 32, 64, 128, 256, 512, 1024]
MAX_RETRY = 10

# 病区在院状态
ALIVE_STATUS = ("IN_HOSPITAL", "TRANSFERRING", "DISCHARGING")


class ChargeService:
    """计费服务。"""

    def __init__(self, db: AsyncSession, user: Optional[Dict[str, Any]]):
        self.db = db
        self.user = user

    # ==================== 每日计费核心 ====================

    async def generate_daily_tasks(
        self, charge_date: date, ward_id: Optional[int] = None
    ) -> Dict[str, Any]:
        """生成指定日期的计费任务（Celery 调用）。"""
        stays = await self._load_inpatient_stays(charge_date, ward_id)
        created = 0
        skipped = 0
        for stay in stays:
            try:
                plans = await self._build_charge_plans(stay, charge_date)
            except BizException as exc:
                logger.warning(
                    "build plans failed stay=%s date=%s err=%s",
                    stay.id, charge_date, exc.message,
                )
                continue
            for plan in plans:
                existed = await self._task_exists(
                    stay.admission_id, charge_date, plan["charge_item_code"]
                )
                if existed:
                    skipped += 1
                    continue
                task = M05ChargeTask(
                    admission_id=stay.admission_id,
                    admission_no=stay.admission_no,
                    stay_id=stay.id,
                    patient_id=stay.patient_id,
                    patient_name=stay.patient_name,
                    ward_id=stay.ward_id,
                    bed_no=stay.bed_no,
                    charge_date=charge_date,
                    charge_category=plan["charge_category"],
                    charge_item_code=plan["charge_item_code"],
                    charge_item_name=plan["charge_item_name"],
                    unit_price=plan["unit_price"],
                    quantity=plan["quantity"],
                    amount=plan["amount"],
                    idempotency_key=plan["idempotency_key"],
                    status=TASK_PENDING,
                    retry_count=0,
                )
                self.db.add(task)
                created += 1
        await self.db.flush()
        logger.info(
            "m05 daily charge generated date=%s ward=%s created=%d skipped=%d",
            charge_date, ward_id, created, skipped,
        )
        return {"charge_date": str(charge_date), "created": created,
                "skipped": skipped, "stay_count": len(stays)}

    async def _load_inpatient_stays(
        self, charge_date: date, ward_id: Optional[int]
    ) -> List[M05Stay]:
        """加载目标日需要计费的在院患者。"""
        stmt = select(M05Stay).where(
            M05Stay.is_deleted.is_(False),
            M05Stay.stay_status.in_(ALIVE_STATUS),
            func.date(M05Stay.admitted_at) <= charge_date,
        )
        if ward_id:
            stmt = stmt.where(M05Stay.ward_id == ward_id)
        result = await self.db.execute(stmt)
        rows = result.scalars().all()
        # 出院日在目标日之后（含出院当天仍计）
        return [
            r for r in rows
            if r.discharged_at is None or r.discharged_at.date() >= charge_date
        ]

    async def _build_charge_plans(
        self, stay: M05Stay, charge_date: date
    ) -> List[Dict[str, Any]]:
        """为一个患者生成三类计费计划。"""
        plans: List[Dict[str, Any]] = []

        # ① 床位费
        bed_item = await self._resolve_bed_charge_item(stay)
        if bed_item:
            plans.append(self._make_plan(stay, charge_date, "BED", bed_item))

        # ② 护理费
        nurse_item = await self._resolve_nursing_charge_item(stay)
        if nurse_item:
            plans.append(self._make_plan(stay, charge_date, "NURSING", nurse_item))

        # ③ 诊查费
        clinic_item = await self._resolve_clinic_charge_item(stay)
        if clinic_item:
            plans.append(self._make_plan(stay, charge_date, "CLINIC", clinic_item))

        return plans

    def _make_plan(
        self, stay: M05Stay, charge_date: date,
        category: str, item: Dict[str, Any],
    ) -> Dict[str, Any]:
        """构造计费计划，生成幂等键。"""
        unit_price = money(item["unit_price"])
        amount = money(unit_price * 1)
        raw_key = "DAILY:%d:%s:%s" % (
            stay.admission_id, charge_date.isoformat(), item["code"]
        )
        return {
            "charge_category": CHARGE_CATEGORY_MAP[category],
            "charge_item_code": item["code"],
            "charge_item_name": item["name"],
            "unit_price": unit_price,
            "quantity": 1,
            "amount": amount,
            "idempotency_key": raw_key,
        }

    # ==================== 执行计费 ====================

    async def execute_task(self, task_id: int) -> Dict[str, Any]:
        """执行单条计费任务（Celery 调用）。"""
        task = await self._get_task_for_update(task_id)
        if task.status == TASK_SUCCESS:
            return {"task_id": task_id, "status": TASK_SUCCESS,
                    "is_idempotent": True}
        if task.retry_count >= MAX_RETRY:
            task.status = TASK_DEAD
            await self.db.flush()
            raise BizException("0504009", "已达最大重试次数")

        lock_key = "m05:charge:lock:%d" % task_id
        if not await self._acquire_lock(lock_key):
            return {"task_id": task_id, "status": "LOCKED"}

        try:
            result = await self._call_m16_charge(task)
            task.status = TASK_SUCCESS
            task.charge_id = result.get("charge_id")
            task.charge_no = result.get("charge_no")
            task.charged_at = datetime.now()
            task.fail_reason = None
            await self._write_log(task, "SUCCESS", "记账成功")
            await self.db.flush()
            logger.info(
                "m05 charge task success id=%d adm=%d date=%s code=%s amount=%s",
                task_id, task.admission_id, task.charge_date,
                task.charge_item_code, task.amount,
            )
            return {"task_id": task_id, "status": TASK_SUCCESS,
                    "charge_id": task.charge_id, "charge_no": task.charge_no}
        except Exception as exc:  # noqa: BLE001
            task.retry_count += 1
            task.status = (
                TASK_DEAD if task.retry_count >= MAX_RETRY else TASK_FAILED
            )
            task.fail_reason = str(exc)[:500]
            task.next_retry_at = datetime.now() + timedelta(
                minutes=RETRY_BACKOFF_MINUTES[min(task.retry_count - 1, 9)]
            )
            await self._write_log(task, "FAIL", str(exc)[:500])
            await self.db.flush()
            logger.error(
                "m05 charge task failed id=%d retry=%d err=%s",
                task_id, task.retry_count, exc,
                extra={"task_id": task_id, "admission_id": task.admission_id},
            )
            return {"task_id": task_id, "status": task.status,
                    "error": str(exc)[:200]}
        finally:
            await self._release_lock(lock_key)

    async def _call_m16_charge(self, task: M05ChargeTask) -> Dict[str, Any]:
        """调用 M16-03 记账接口。"""
        from app.clients.m16 import InpatientChargeClient

        client = InpatientChargeClient(self.db)
        payload = {
            "admission_id": task.admission_id,
            "admission_no": task.admission_no,
            "patient_id": task.patient_id,
            "source_type": "DAILY",
            "source_id": self._hash_source_id(task.idempotency_key),
            "charge_item_code": task.charge_item_code,
            "charge_item_name": task.charge_item_name,
            "charge_item_spec": "",
            "quantity": float(task.quantity),
            "unit_price": float(task.unit_price),
            "charge_date": task.charge_date.isoformat(),
            "charge_category": task.charge_category,
            "dept_id": task.dept_id,
            "exec_dept_id": task.dept_id,
            "operator_id": 0,
            "operator_name": "系统",
            "remark": "每日自动计费 %s" % task.idempotency_key,
        }
        return await client.charge(payload)

    @staticmethod
    def _hash_source_id(key: str) -> int:
        """幂等键 → BIGINT source_id。"""
        digest = hashlib.sha256(key.encode("utf-8")).digest()
        raw = int.from_bytes(digest[:8], "big")
        return raw % (2 ** 53)

    async def get_workbench(
        self, ward_id: Optional[int], stat_date: Optional[date]
    ) -> Dict[str, Any]:
        """费用工作台。"""
        target = stat_date or (date.today() - timedelta(days=1))
        stays = await self._load_inpatient_stays(date.today(), ward_id)
        admitted_ids = [s.admission_id for s in stays]

        task_stats = await self._task_statistics(target, ward_id)
        owed = await self._owed_list(admitted_ids)

        pending: List[Dict[str, Any]] = []

                "type": "CHARGE_FAILED", "bed_no": row.bed_no,
                "patient_name": row.patient_name,
                "amount": float(row.amount), "message": row.fail_reason,
                "task_id": row.id,
            })
        for item in owed:
            pending.append({
                "type": "OWED", "bed_no": item["bed_no"],
                "patient_name": item["patient_name"],
                "amount": item["owed_amount"],
                "message": "已住院 %d 天" % item["stay_days"],
                "alert_id": item["alert_id"],
            })

        return {
            "date": target.isoformat(),
            "ward_id": ward_id,
            "summary": {
                "in_hospital": len(stays),
                "charge_count": task_stats["total"],
                "charge_amount": task_stats["amount"],
                "failed_count": task_stats["failed"],
                "owed_patient_count": len(
                    [o for o in owed if o["owed_amount"] > 0]
                ),
                "deposit_balance": deposit_total,
            },
            "pending_items": pending,
            "by_category": task_stats["by_category"],
            "refreshed_at": datetime.now().isoformat(),
        }

    async def _task_statistics(
        self, charge_date: date, ward_id: Optional[int]
    ) -> Dict[str, Any]:
        """计费任务统计。"""
        stmt = select(
            M05ChargeTask.charge_category,
            M05ChargeTask.status,
            func.count(M05ChargeTask.id),
            func.coalesce(func.sum(M05ChargeTask.amount), 0),
        ).where(
            M05ChargeTask.charge_date == charge_date,
            M05ChargeTask.is_deleted.is_(False),
        )
        if ward_id:
            stmt = stmt.where(M05ChargeTask.ward_id == ward_id)
        stmt = stmt.group_by(
            M05ChargeTask.charge_category, M05ChargeTask.status
        )
        rows = (await self.db.execute(stmt)).all()

        by_cat: Dict[str, Dict[str, Any]] = {}
        total = 0
        amount = ZERO
        failed = 0
        for cat, status, cnt, amt in rows:
            entry = by_cat.setdefault(cat, {
                "category": cat, "success": 0, "failed": 0,
                "amount": ZERO, "rate": 0.0,
            })
            if status == TASK_SUCCESS:
                entry["success"] += cnt
                entry["amount"] += money(amt)
                amount += money(amt)
                total += cnt
            elif status in (TASK_FAILED, TASK_DEAD):
                entry["failed"] += cnt
                failed += cnt

        for entry in by_cat.values():
            denom = entry["success"] + entry["failed"]
            entry["rate"] = round(entry["success"] / denom, 4) if denom else 1.0
            entry["amount"] = float(entry["amount"])

        return {"total": total, "amount": float(amount), "failed": failed,
                "by_category": list(by_cat.values())}

    async def retry_task(self, task_id: int, force: bool = False) -> Dict[str, Any]:
        """重试单条任务。"""
        task = await self._get_task_for_update(task_id)
        if task.status == TASK_SUCCESS and not force:
            raise BizException("0504008", "计费任务状态不允许此操作")
        if task.retry_count >= MAX_RETRY and not force:
            raise BizException("0504009", "已达最大重试次数")
        if force:
            task.retry_count = 0
        task.status = TASK_PENDING
        await self.db.flush()
        result = await self.execute_task(task_id)
        await self.db.commit()
        return result

    async def manual_charge(self, body: Any) -> Dict[str, Any]:
        """人工补记。"""
        if not body.manual_reason or len(body.manual_reason.strip()) < 10:
            raise BizException("0504011", "补记原因不足 10 字")
        task = await self._get_task_for_update(body.task_id) \
            if body.task_id else None
        if task is None:
            task = M05ChargeTask(
                admission_id=body.admission_id,
                charge_date=body.charge_date,
                charge_category=body.charge_category,
                charge_item_code=body.charge_item_code,
                charge_item_name=body.charge_item_name,
                unit_price=money(body.unit_price),
                quantity=Decimal(str(body.quantity)),
                amount=money(body.amount),
                idempotency_key="MANUAL:%d:%s:%s" % (
                    body.admission_id, body.charge_date, body.charge_item_code
                ),
                status=TASK_PENDING,
                is_manual=True,
                manual_reason=body.manual_reason,
            )
            self.db.add(task)
            await self.db.flush()
        task.is_manual = True
        task.manual_reason = body.manual_reason
        task.retry_count = 0
        task.status = TASK_PENDING
        await self.db.flush()
        result = await self.execute_task(task.id)
        await self.db.commit()
        return result

class DepositService:
    """预交金服务。"""

    MAX_SINGLE = Decimal("50000.00")
    MAX_TOTAL = Decimal("200000.00")
    REFUND_APPROVAL = Decimal("5000.00")
    REASON_MIN_LEN = 10

    def __init__(self, db: AsyncSession, user: Optional[Dict[str, Any]]):
        self.db = db
        self.user = user

    async def create(self, body: Any) -> Dict[str, Any]:
        """收取预交金。"""
        amount = money(body.amount)
        if amount <= ZERO:
            raise BizException("0504012", "预交金金额必须大于 0")
        if amount > self.MAX_SINGLE:
            raise BizException("0504013", "单笔预交金超过上限")

        stay = await self._load_stay(body.admission_id)
        balance = await self.balance(body.admission_id)
        if money(Decimal(str(balance["total_deposit"]))) + amount > self.MAX_TOTAL:
            raise BizException("0504014", "累计预交金超过上限")

        from app.clients.m16 import InpatientChargeClient

        client = InpatientChargeClient(self.db)
        try:
            result = await client.create_deposit({
                "admission_id": body.admission_id,
                "admission_no": stay.admission_no,
                "patient_id": stay.patient_id,
                "amount": float(amount),
                "payment_method": body.payment_method,
                "cash_received": (
                    float(body.cash_received) if body.cash_received else None
                ),
                "remark": body.remark or "",
                "operator_id": self.user.get("employee_id"),
                "operator_name": self.user.get("name", ""),
            })
        except Exception as exc:  # noqa: BLE001
            raise BizException("0504015", "预交金收取失败: %s" % exc)

        logger.info(
            "m05 deposit created admission=%s amount=%s method=%s",
            body.admission_id, amount, body.payment_method,
            extra={"operator": self.user.get("employee_id")},
        )
        return {
            "deposit_id": result.get("deposit_id"),
            "deposit_no": result.get("deposit_no"),
            "admission_id": body.admission_id,
            "admission_no": stay.admission_no,
            "patient_name": stay.patient_name,
            "amount": float(amount),
            "payment_method": body.payment_method,
            "balance_before": balance.get("available_balance", 0.0),
            "balance_after": float(
                money(Decimal(str(balance.get("available_balance", 0)))
                      + amount)
            ),
            "receipt_no": result.get("receipt_no"),
            "paid_at": datetime.now().isoformat(),
            "printed": bool(body.print_receipt),
        }

            logger.error("m05 deposit balance failed adm=%s err=%s",
                         admission_id, exc)
            raise BizException("0504019", "余额查询服务不可用")
        return {
            "admission_id": admission_id,
            "total_deposit": data.get("total_deposit", 0.0),
            "total_refund": data.get("total_refund", 0.0),
            "frozen_amount": data.get("frozen_amount", 0.0),
            "available_balance": data.get("available_balance", 0.0),
            "accumulated_charge": data.get("accumulated_charge", 0.0),
        }

    async def refund(self, admission_id: int, body: Any) -> Dict[str, Any]:
        """退还预交金。"""
        amount = money(body.amount)
        if amount <= ZERO:
            raise BizException("0504012", "预交金金额必须大于 0")
        if not body.reason or len(body.reason.strip()) < self.REASON_MIN_LEN:
            raise BizException("0504017", "退还原因不足 10 字")

        balance = await self.balance(admission_id)
        available = money(Decimal(str(balance["available_balance"])))
        if amount > available:
            raise BizException("0504016", "退还金额超过可用余额")

        need_approval = amount > self.REFUND_APPROVAL
        from app.clients.m16 import InpatientChargeClient

        result = await InpatientChargeClient(self.db).refund_deposit({
            "admission_id": admission_id,
            "amount": float(amount),
            "reason": body.reason,
            "refund_channel": body.refund_channel,
            "need_approval": need_approval,
            "operator_id": self.user.get("employee_id") if self.user else 0,
        })
        logger.info(
            "m05 deposit refund requested adm=%s amount=%s approval=%s",
            admission_id, amount, need_approval,
        )
        return {
            "admission_id": admission_id,
            "refund_no": result.get("refund_no"),
            "amount": float(amount),
            "status": result.get("status", "PENDING_APPROVAL"
                                if need_approval else "SUCCESS"),
            "need_approval": need_approval,
            "approval_url": result.get("approval_url"),
        }

    async def receipt(self, admission_id: int, deposit_id: int) -> Dict[str, Any]:
        """预交金收据数据。"""
        from app.clients.m16 import InpatientChargeClient

        stay = await self._load_stay(admission_id)
        data = await InpatientChargeClient(self.db).get_deposit(deposit_id)
        return {
            "receipt_no": data.get("receipt_no"),
            "deposit_no": data.get("deposit_no"),
            "admission_no": stay.admission_no,
            "patient_name": stay.patient_name,
            "ward_name": stay.ward_name,
            "bed_no": stay.bed_no,
            "amount": data.get("amount"),
            "amount_text": data.get("amount_text"),
            "payment_method": data.get("payment_method"),
            "paid_at": data.get("paid_at"),
            "operator_name": data.get("operator_name"),
            "hospital_name": "南石眼科医院",
        }

    async def on_received(self, body: Any) -> Dict[str, Any]:
        """预交金到账回写（M16-03 调用）。"""
        logger.info(
            "m05 on_deposit_received admission=%s amount=%s",
            body.admission_id, body.amount,
        )
        return {"admission_id": body.admission_id,
                "received": True, "updated_at": datetime.now().isoformat()}

    async def _load_stay(self, admission_id: int) -> M05Stay:
        stmt = select(M05Stay).where(
            M05Stay.admission_id == admission_id,
            M05Stay.is_deleted.is_(False),
        ).order_by(M05Stay.id.desc()).limit(1)
        stay = (await self.db.execute(stmt)).scalar_one_or_none()
        if not stay:
            raise BizException("0504003", "住院主档不存在")
        return stay
```

### 6.7 专题：为什么床日费由 M05 触发而不是 M16

| 方案 | 判定「今天该收几级护理」 | 判定「今天该收什么床位」 | 判定「患者今天是否在院」 | 结论 |
|---|---|---|---|---|
| **A M16 自己算** | ❌ M16 无 `nursing_level` 数据 | ❌ M16 无 `bed_type` 数据 | ❌ M16 只有结算单，无在院状态 | 不可行 |
| **B 各模块各自触发** | 护理费由 M08 触发 | 床位费由 M05-02 触发 | 诊查费无处触发 | 三处不一致 |
| **C M05-04 统一触发** | ✅ 读 `m05_stay` | ✅ 读 `m05_bed` + `m05_stay` | ✅ 读 `m05_stay` | ✅ 采用 |
| D 用数据库存储过程 | ✅ 能读到 | ✅ 能读到 | ✅ 能读到 | ❌ 无法调 M01 取价，逻辑不可测 |

**采用 C 的三个具体理由：**

1. **数据可得性**：护理等级、床位类型、在院状态三个判据全在 M05，只有 M05 能一次性拿全。
2. **单一触发点**：一天一次、一个任务、一套幂等键，对账时能明确回答「这个患者 10-27 的床位费记了没有」。
3. **可测试性**：计费规则（哪些患者要记、记多少）能写成纯函数跑 pytest，存储过程不行。

**代价与缓解：** M05-04 挂了当天费用记不上。缓解 —— ①每日 00:30 跑，即使延迟到 08:00 也不影响业务 ②补偿队列重试 10 次 ③03:00 对账自动补记 ④P05 页面能看到所有失败项。

### 6.8 专题：中途结算提醒为什么只是提醒

中途结算涉及「退钱」或「补钱」，一旦自动执行，可能出现「患者不在场、钱退不出去」的情况。M05-04 只生成提醒，由住院处在患者/家属在场时发起。

**触发检测每日 09:00 执行一次**，三个条件任一命中即生成提示：

```
interim_needed = (
    stay_days >= M05.CHARGE.INTERIM_DAYS
    or accumulated_charge >= M05.CHARGE.INTERIM_AMOUNT
    or available_balance >= M05.CHARGE.INTERIM_DEPOSIT
)
```

**去重：** 同一住院单 24 小时内只生成一条提示（`uk_m05_charge_alert (admission_id, alert_type, alert_date)`）。

## 8. 业务规则与校验

| 编号 | 规则 | 错误码 |
|---|---|---|
| R-01 | 每日 00:30 生成昨日计费任务，覆盖所有目标日在院患者 | — |
| R-02 | 出院当天仍计一天床日费，住院天数 = 出院日 - 入院日 + 1 | — |
| R-03 | 同一患者同一天同一项目只能成功计费一次（幂等） | `"0504007"` |
| R-04 | 计费失败自动重试 10 次，退避 2/4/8/…/512 分钟 | — |
| R-05 | 失败 10 次后状态置 `DEAD`，只能人工补记 | `"0504009"` |
| R-06 | 人工补记必须填写 ≥10 字原因 | `"0504010"` `"0504011"` |
| R-07 | 收费项目必须存在且价格 > 0 | `"0504001"` `"0504002"` |
| R-08 | 护理等级与诊查费必须有映射配置 | `"0504031"` `"0504032"` |
| R-09 | 床位类型必须有 `charge_item_code` | `"0504033"` |
| R-10 | 预交金单笔 ≤ ¥50000 | `"0504013"` |
| R-11 | 预交金累计 ≤ ¥200000 | `"0504014"` |
| R-12 | 退还金额 ≤ 可用余额 | `"0504016"` |
| R-13 | 退还原因 ≥ 10 字 | `"0504017"` |
| R-14 | 退还 > ¥5000 需审批 | `"0504018"` |
| R-15 | 现金收款必须录实收金额 | `"0504012"` |
| R-16 | 同一患者每日短信催缴 ≤ 1 次 | `"0504021"` |
| R-17 | 22:00~08:00 不发短信 | `"0504022"` |
| R-18 | 1 小时内已缴费不催缴 | `"0504023"` |
| R-19 | 批量催缴 ≤ 50 条 | `"0504024"` |
| R-20 | 费用明细分页查询跨度 ≤ 92 天 | `"0504025"` |
| R-21 | 统计查询跨度 ≤ 366 天 | `"0504026"` |
| R-22 | 导出 ≤ 50000 行 | `"0504027"` |
| R-23 | 对账每日 03:00 执行一次，差异 > 5 笔告警 | `"0504034"` `"0504035"` |
| R-24 | 中途结算只提醒不自动执行 | — |
| R-25 | 同一住院单 24 小时内只生成一条同类型预警 | — |
| R-26 | 金额一律 `NUMERIC(12,2)`，行级先舍入 | — |
| R-27 | 幂等键 = `DAILY:{admission_id}:{charge_date}:{charge_item_code}` | — |
| R-28 | 系统管理员无业务数据查询权 | `"0504028"` |

**关键规则的理由说明：**

- **R-02 出院当天仍计费**：与 M05-03 `stay_days` 一致，否则床日费条数 ≠ 住院天数，对账天天报警。
- **R-04 退避 2^n**：M16 短时故障通常几秒到几十分钟恢复；第 1 次 2 分钟后重试能覆盖绝大多数瞬时故障，最后一次 1024 分钟（约 17 小时）覆盖长时间维护窗口。
- **R-14 退还 > 5000 需审批**：预交金退还本质是资金流出，大额必须双人控制。
- **R-24 中途结算只提醒**：涉及退钱/补钱，必须有患者/家属在场确认。
- **R-28 系统管理员无查询权**：费用明细含患者姓名、住院号、诊断与治疗项目，属敏感医疗数据。

**关键设计：**

- **系统管理员无任何业务查询权**（`m05:charge:query` = ❌）：费用数据含患者病情与经济信息，IT 岗不应看到。运维排查走「审计日志只读」且姓名脱敏。
- **病区护士可催缴但不可收费**：催缴是提醒动作无资金风险；收费是资金入口必须住院处。
- **财务可审批退预交金但不可收取**：审批与执行分离（SoD）。
- **医务科无 config**：计费参数属财务域，医务科只监督不配置。

通过 `apply_data_scope_to_stmt(stmt, M05ChargeTask, user, domain="DEPT")` 注入。

### 9.4 脱敏

| 字段 | 列表视图 | 详情视图 | 导出 |
|---|---|---|---|
| 患者姓名 | `张**` | 完整 | 完整 |
| 住院号 | 完整 | 完整 | 完整 |
| 身份证 | — | 不显示 | 不显示 |
| 手机号 | `138****5678` | `138****5678` | 完整 |
| 金额 | 完整 | 完整 | 完整 |

**导出不脱敏的理由：** 导出是受控操作（需 `m05:charge:export` + 审计留痕），脱敏会让数据失去对账价值。控制点在「谁能导出 + 导出必留痕」。

### 9.5 安全措施

| 措施 | 说明 |
|---|---|
| 收费幂等 | 预交金收取带 `idempotency_key`，防重复扣款 |
| 金额后端重算 | 前端传的 `amount` 一律忽略，后端按 `unit_price × quantity` 重算 |
| 退还审批 | > ¥5000 强制审批，审批人 ≠ 申请人 |
| 补记留痕 | 人工补记写入 `manual_reason` + 操作人 + 时间 |
| 审计 | 所有写操作记 M02-06 审计日志 |
| SQL 注入 | 全部参数化，动态 where 只拼固定常量 |
| 越权 | 数据权限后端注入，不接受前端传参 |
| 敏感日志 | 日志中患者姓名脱敏，金额保留 |

## 11. 异常处理与日志

### 11.1 异常分类

| 类别 | 场景 | 处理 |
|---|---|---|
| **业务异常** | 参数非法、状态不允许、金额超限 | `BizException` → HTTP 400 + 错误码 |
| **依赖异常** | M16/M01 超时、返回错误 | 计费任务进补偿队列；查询接口降级 |
| **数据异常** | 幂等键冲突、任务状态不一致 | 记录告警，人工介入 |
| **系统异常** | 代码 bug、DB 连接失败 | HTTP 500 + 全量错误日志 + 告警 |

### 11.2 日志规范

```python
logger.info(
    "m05 charge task success id=%d adm=%d date=%s code=%s amount=%s",
    task_id, admission_id, charge_date, item_code, amount,
    extra={
        "trace_id": trace_id,
        "operator_id": operator_id,
        "ward_id": ward_id,
    },
)

logger.error(
    "m05 charge task failed id=%d retry=%d err=%s",
    task_id, retry_count, error,
    extra={"task_id": task_id, "admission_id": admission_id},
)
```

**日志级别约定：**

| 级别 | 场景 |
|---|---|
| `INFO` | 每次计费成功、预交金收取/退还 |
| `WARNING` | 逐笔失败（将重试）、余额预警、降级 |
| `ERROR` | 任务置 DEAD、对账差异、依赖长时间不可用 |
| `CRITICAL` | 每日计费整体失败、对账差异 > 50 笔 |

| 补偿队列 | 失败任务带退避的重试队列 |
| 对账 | 核算「应记」与「实记」是否一致 |
| SoD | 职责分离（Segregation of Duties） |
| DAILY | M16-03 的 `source_type`，表示日结自动记账 |
