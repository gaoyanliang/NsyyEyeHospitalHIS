## 1. 总体定位

### 1.1 一句话定位

**M05 回答「这个患者现在是不是住在我们医院、住在哪个床、由谁管、住了多久」，并管住从入院到出院这条链上的每一次床位流转。**

### 1.2 为什么 M05 是模块而不是 M04 的一个分支

| 维度 | 门诊（M04） | 住院（M05） |
|---|---|---|
| 时间跨度 | 分钟级（一次就诊 10~30 分钟） | **天级**（平均 5~7 天，眼科手术住院 3~5 天） |
| 空间归属 | 诊室（患者来医院） | **床位**（患者住医院） |
| 主键 | 挂号单 `registration_id` | **住院号 `admission_id`** |
| 核心资源 | 号源、诊室 | **床位**（有限且必须独占） |
| 费用模式 | 先付费后诊疗 | **先交预交金、诊疗后结算** |
| 责任归属 | 接诊医生 | **责任医生 + 责任护士 + 病区** |
| 状态数量 | 5 态（挂号状态机） | **12 态（入院单 + 床位 + 在院状态三套状态机）** |

**四条独立理由：**

1. **核心资源完全不同。** 门诊卖的是「号源」，是一天内的时段切片；住院卖的是「床位」，是持续占用且有独占性——同一张床同一时刻只能有一个患者。号源超卖扣分了事，床位超卖患者就无处安置。
2. **住院有门诊完全不存在的「床位流转」。** 入院分床、转床、转科、包床、加床、离院占床、床位消毒——这一整套是住院管理的核心工作量，门诊没有任何对应概念。
3. **住院有独立的法定文书体系。** 住院病案首页、入院记录、出院小结、住院医嘱单——这些文件的完整性检查（M06-06 的 D-01~D-14）、归档、保存期限都由住院规则决定，与门诊病历不同。
4. **费用模型不同。** 住院是「预交金 + 记账 + 出院结算」三段式，存在「欠费」这个门诊不存在的状态；床位费按天自动计费，需要每日定时任务；医保住院报销与门诊结算规则完全不同。

### 1.3 M05 与各模块的分工

| 能力 | 归属 | 说明 |
|---|---|---|

### 2.2 六条拆分主线

#### 主线一：按「一次住院的时间轴」分，不按功能清单分

```
[想住院] ──①入院登记──► [已开单] ──②分床──► [已入科]
                                                   │
                        ┌──────────────────────────┼──────────────────┐
                        ▼                          ▼                  ▼
                   ③转床/转科               ④在院日常管理        ⑤费用催缴
                        │                          │                  │
                        └──────────────────────────┴──────────────────┘
                                                   ▼
                                            ──⑥出院办理──► [已出院]
                                                   ▼
                                            ──⑦病案首页──► [已归档]
                                                   ▼
                                            ──⑧统计──► [床位释放]
```

每个环节的**主责人不同、可逆性不同、法规约束不同**：

| 环节 | 主责人 | 可逆性 | 关键约束 |
|---|---|---|---|
| ① 入院登记 | 住院处收费员 | 可作废（未入科前） | 需先交预交金 |
| ② 分床 | 病区护士 / 住院处 | 可退床 | **床位必须空闲** |
| ③ 转床转科 | 病区护士长 | 可撤销 | 需原病区与新病区双确认 |
| ④ 在院日常 | 责任医生 / 责任护士 | — | 病情等级影响护理费 |
| ⑤ 费用催缴 | 住院处 | — | 预交金不足需提醒 |
| ⑥ 出院办理 | 责任医生 + 住院处 | **不可逆** | 必须已结算 |
| ⑦ 病案首页 | 病案室 | 可修改（限 7 天内） | 需通过 12 项质控 |
| ⑧ 统计 | 系统 | — | 床日数按自然日切分 |

**为什么按时间轴而不按功能分：** 如果按「床位管理」「转科管理」「出院管理」分，每个子模块都要碰 `m05_admission` 主表，都会产生「谁能改这个字段」的争议。按时间轴分，每个环节有明确的输入状态与输出状态，主表字段的写入权归属清晰。

#### 主线二：床位必须独立成子模块

**四条理由：**

1. **M01 只有「床位类型」，没有「床位实例」。** `M01主数据管理MDM/M01_主数据管理MDM_13_组织辅助与患者索引_详细设计.md:47` 明确写「床位明细（具体床位号）| **M05 住院管理** | —」。M01 的 `md_ward` 有 `bed_count`（规划床位）与 `actual_bed_count`（**M05 维护**），但具体「3 床、12 床」这张台账在 M05。
2. **床位的状态变化频率远高于患者状态。** 一张床一年可能被 60 个患者轮流使用，每次都有「空 → 预约 → 占用 → 预出院 → 空」的循环。如果床位状态与患者状态放一张表，患者出院后那条记录就无意义了，但床位还在。
3. **床位的独占性需要数据库级保障。** 同一床同一时刻只能一个患者——这必须用唯一索引（`uk_m05_bed_patient_active`）而不是应用层检查，否则两个护士同时分床就会一张床两个人。
4. **床位是医院最贵的资源之一，需要独立的管理视图。** 床位使用率、周转次数、平均住院日都是医院核心 KPI，必须建立在准确的床位台账上。

#### 主线三：M05 不管钱，但必须管「钱的状态」

M05 **不实现**任何金额计算、预交金存取、费用明细、结算——这些全在 M16-03（已完整设计，见 §4）。M05 只做三件事：

1. **在入院登记时调用 M16-03 C-01 收预交金**（或要求先到收费处交）
2. **在出院办理时调用 M16-03 C-06 试算 / C-07 结算**，拿到结算完成结果
3. **每日触发床日费用**（床位费、护理费、诊查费）到 M16-03 C-03 记账

**为什么这么切：** 钱的计算有唯一答案，且必须有审计；M16 已经有 9 个子模块专门管这事。如果 M05 也算一遍，就会出现「M05 算出的欠费和 M16 的预交金余额不一致」——这是 HIS 最常见的扯皮问题。**M05 只显示 M16 给的余额，不自己算。**

#### 主线四：病案首页独立，且必须做质控

**病案首页是住院病案的第一页，也是唯一必须上报卫健委的结构化数据。** 与 M05 其他文书相比有三点不同：

1. **格式由国家规定**（《住院病案首页数据填写质量规范》），字段有 300+ 项且分必填/条件必填/选填。
2. **12 项质控规则**（DRG 入组必需项，如主诊断必填、主手术必填、入院病情必填），不通过无法上报。
3. **决定 DRG/DIP 支付**——病案首页填错，医院拿到的医保结算金额就是错的，直接影响收入。

因此独立成 M05-06，而不是塞进 M05-05 出院办理。

#### 主线五：统计独立，因为口径必须唯一

床位使用率有四种算法（按实际占用床日/按出院人数/按开放床日/按规划床位），算出来能差 36 个百分点（见 M09-06 的同类论证）。如果各病区自己算，报表永远对不上。M05-07 集中定义口径并提供预聚合。

#### 主线六：M06 日间手术不并入 M05

M06 是**独立业务形态**（当天来当天走，不占床位、按日间结算），不是住院的一种。两者区别：

| 维度 | 日间手术（M06） | 住院（M05） |
|---|---|---|
| 是否占床位 | 不占长期床位（用日间观察床 2~6 小时） | **占床位，按天计费** |
| 结算方式 | 术后一次结算 | 预交金 + 记账 + 出院结算 |
| 病历 | 日间手术病历（M06-06） | 住院病案（M05-06 首页 + M18 内容） |
| 业务主线 | `m06_or_schedule`（台次） | `m05_admission`（住院号） |
| 两者关系 | **M06 可转 M05**（`TRANSFERRED`），通过 `POST /internal/v1/m05/admission/from-day-surgery` | M05 接收，生成新住院号 |

### 3.3 关键契约细节（已核实原文）

**P-07 `on-settled` 的发起方与时机：**
- M16-03 已定义 U-04 `POST /internal/v1/m05/admission/on-settled`，SLA ≤ 200ms，失败进补偿队列
- 触发时机：M16-03 结算记录置 `SETTLED` 后
- 请求体需包含：`admission_id`、`settle_type`（`DISCHARGE`/`INTERIM`）、`settlement_no`、`total_amount`、`settle_amount`、`settled_at`
- M05 收到后：`DISCHARGE` → 住院单置 `SETTLED`；`INTERIM` → 只记录中途结算次数

**P-08 `from-day-surgery` 的请求体：**
- 由 M06-06 在 `m06_delay` 审批结论为「转住院」时调用
- 请求体需包含：`day_surgery_id`、`schedule_id`、`patient_id`、`diagnosis`、`operation_code`、`eye_side`、`transfer_reason`、`requested_by`
- M05 收到后：创建 `m05_admission`（`admission_type='FROM_DAY_SURGERY'`），状态 `PENDING_BED`，等待分床
- **注意：M06-05 的 `m06_delay` 表中并未定义 `m06_transfer` 表**（已 grep 确认 `m06_transfer` 在 M06 数据结构中零命中，只在详细设计 `:1156` 文字提到）→ **文档债 T-M06-05-01**

**P-11 住院文书完整性（对应 M06-06 的 D-01~D-10）：**
M06-06 有 14 项完整性检查 D-01~D-14，其中 D-01~D-10 是住院病案项、D-14 是护理记录（归 M08）。M05 负责提供住院侧文书状态。

## 5. 眼科住院的特殊性

### 5.1 住院日短，床位周转快

眼科住院平均 **5~7 天**（白内障 1~2 天、玻璃体切割 3~5 天、角膜移植 7~10 天），远短于综合医院（8~10 天）。后果：

- **床位使用率的分母要更精细。** 一天可能上午出院 3 人、下午入院 4 人，床位数在日内变化。M05-02 的床位台账必须记时刻而不是只记日期。
- **出院小结的及时性要求更高。** 患者出院当天就走，出院小结必须在当天出——M05-05 要有「出院小结未完成」的阻断与催办。

### 5.2 双眼手术与分次住院

眼科患者常需双眼分期手术（一次住院做一只眼，隔 1~4 周再做另一只）。出院时不能关闭「手术未完成」的标记，需要在住院单上记录 `eye_side` 与 `operation_sequence`（第几期）。

**数据模型影响：** `m05_admission` 需有 `eye_side` 与 `surgery_plan_sequence` 字段；M05-05 出院时要检查「双眼是否都完成」，未完成则生成「待二期入院」提醒。

### 5.3 日间手术转住院的比例

日间手术（M06）术前评估或术后观察不合格时会转住院（M06-05 `TRANSFERRED`）。眼科这个比例约 **2~5%**，主要原因是术后眼压升高、前房积血需要持续观察。

**影响：** M05 的 `from-day-surgery` 入口必须支持「当天即时转入」，不能要求重新走完整的入院登记（患者已在院内）。

### 5.4 体位护理是住院管理的一部分

视网膜脱离术后需要**面朝下体位 7~10 天**，这期间患者全天卧床、吃饭上厕所都受限，护理工作量远超普通住院。影响：

- 病情等级评定要能映射为护理费等级（一级/特级护理）
- 床位类型的「加床」在眼科极少用（因为需要卧床陪护空间）
- 出院标准里要包含「体位依从性评估达标」

### 5.5 老年患者与合并症

眼科住院患者 60 岁以上占 **60~70%**（白内障、黄斑变性、青光眼均与年龄相关），糖尿病、高血压合并症比例高。影响：

- 入院登记时需采集合并症与用药史
- 床位分配不能简单按性别分（需要考虑行动不便、加护需求）
- 每日需监测血压血糖——但这归 M08-04，M05 只记录「是否高危」标记

### 5.6 医保住院的特殊要求

住院医保结算（DRG/DIP）需要病案首页数据完整。二级眼科医院多数执行 DRG 或按病种付费，病案首页填错直接影响收入。

**M05-06 病案首页的 12 项质控规则**（DRG 入组必需）：

| 编号 | 校验项 | 级别 |
|---|---|---|
| Q-01 | 主诊断必填且有效 | BLOCK |
| Q-02 | 主手术必填（有手术时） | BLOCK |
| Q-03 | 入院病情必填（主诊断） | BLOCK |
| Q-04 | 出院情况必填 | BLOCK |
| Q-05 | 离院方式必填 | BLOCK |
| Q-06 | 主诊断与主手术不能冲突 | BLOCK |
| Q-07 | 手术分级与主刀职称匹配 | WARN |
| Q-08 | 住院天数与入出院日期一致 | BLOCK |
| Q-09 | 费用合计与 M16 结算金额一致 | WARN |
| Q-10 | 眼别（眼科特有）必填 | WARN |
| Q-11 | 麻醉方式与麻醉记录一致 | WARN |
| Q-12 | 血型与输血记录一致 | WARN |

## 6. 状态机

### 6.1 住院单状态机（12 态）

```
                    ┌─────────────────────────────────────────┐
                    │  ①DRAFT（入院申请草稿，M07 开单）         │
                    └──────────────┬──────────────────────────┘
                                   │ 提交
                                   ▼
                    ┌─────────────────────────────────────────┐
                    │  ②PENDING（待登记，等待患者到住院处）     │
                    └──────────────┬──────────────────────────┘
                                   │ 入院登记 + 交预交金
                                   ▼
                    ┌─────────────────────────────────────────┐
                    │  ③REGISTERED（已登记，待分床）           │
                    └──────────────┬──────────────────────────┘
                                   │ 分床
                                   ▼
                    ┌─────────────────────────────────────────┐
                    │  ④IN_HOSPITAL（在院）◄──────┐            │
                    └──┬────────────────┬────────┴────────────┘
                       │                │      转科/转床
                       │                │ (回到 IN_HOSPITAL)
                       │                │
        出院办理         │                │ 中途结算
                       ▼                ▼
        ┌──────────────────────────┐  ┌──────────────────────┐
        │ ⑤DISCHARGING（出院办理中）│  │ ⑨INTERIM_SETTLED     │
        └──────┬───────────────────┘  │（中途结算已完成）      │
               │                      └──────────────────────┘
       ┌───────┴────────┐
       ▼                ▼
┌──────────────┐  ┌──────────────────┐
│⑥DISCHARGED   │  │⑦DISCHARGED_OWED  │（欠费出院）
│（已出院）      │  │                  │
└──────┬───────┘  └────────┬─────────┘
       │                   │
       ▼                   ▼
┌──────────────────────────────────┐
│ ⑧SETTLED（已结算，终态）            │
└──────────────────────────────────┘

旁支：
  ②PENDING / ③REGISTERED ──► ⑩CANCELLED（作废，退预交金）
  ④IN_HOSPITAL ──► ⑪TRANSFER_OUT（转院）
  ④IN_HOSPITAL ──► ⑫DECEASED（死亡，必须走死亡流程）
```

**为什么 `DISCHARGED` 与 `SETTLED` 是两个状态：** 现实中「已出院但尚未结算」是常态（患者先走，家属后补交钱）。如果合并，床位上就永远显示「占用」直到钱交完，床位使用率失真。两状态分开后，床位在 `DISCHARGED` 时即释放，`SETTLED` 只影响财务。

**为什么 `DECEASED` 独立：** 死亡需要走独立的死亡病例讨论、死亡记录归档、病理报告等法定流程，不能与普通出院共用。

### 6.2 床位状态机（6 态）

```
┌────────┐   预约   ┌────────┐   患者入住   ┌────────┐
│ ①EMPTY │────────►│②RESERVED│────────────►│③OCCUPIED│
│（空闲） │◄────────│（已预约）│◄────────────│（占用）  │
└───┬────┘  取消预约 └────────┘   患者转出    └───┬────┘
    │                                              │
    │    ┌─────────────────┐                       │ 患者出院
    └───►│ ⑥DISABLED（停用） │◄──────────────────────┘
         └─────────────────┘        消毒
                │                    ▼
                │              ┌──────────────┐
                │              │④CLEANING     │（消毒中）
                │              └──────┬───────┘
                │   启用               │ 消毒完成
                └──────────────────────┘
                                       ▼
                                ⑤MAINTENANCE（维修中）
```

**`CLEANING` 必须独立：** 患者出院后床位不能立刻给下一个人——必须消毒。眼科术后患者使用滴眼液、眼罩，感染控制要求高。消毒时长由 `m05_ward_config.clean_minutes` 配置（默认 30 分钟）。

### 6.3 在院状态机（`m05_stay`，5 态）

`IN_WARD`（在病区）⇄ `OUT_WARD`（临时外出：手术/检查/请假）；`IN_WARD` → `PENDING_DISCHARGE`（预出院，医生已下出院医嘱但未办手续）。

**`OUT_WARD` 的意义：** 患者去手术室、去检查，床位仍占用但患者不在病区。护理交接班与查房都需要知道患者在哪。

## 10. 实施顺序

**六阶段 18 周：**

| 阶段 | 子模块 | 周期 | 理由 |
|---|---|---|---|
| ① | **M05-01 入院登记与住院主档** | 3 周 | 数据地基。没有 `m05_admission` 谁也无处挂靠 |
| ② | **M05-02 床位管理** | 3 周 | 紧随其后。分床是入院登记之后第一个动作 |
| ③ | **M05-03 在院管理与转科转床** | 3 周 | 在院日常。转科会联动 M16-03 的 `TRANSFER` 记账 |
| ④ | **M05-04 住院费用联动** | 2 周 | 依赖 M16-03 已上线。床日计费是医院最关注的收入来源 |
| ⑤ | **M05-05 出院办理** | 3 周 | 与 M07-06（出院小结）、M16-03（出院结算）三方联调 |
| ⑥ | **M05-06 病案首页 + M05-07 统计** | 4 周 | 病案首页是最后一块，依赖全部临床数据齐全 |

**为什么 M05-04 排第④而不是最后：** 床位费是住院收入最大一块（占 8~15%），没有自动计费只能人工补录，很容易漏收。M16-03 已完整设计，M05-04 只需要调接口，工作量小但对收入影响大。

**为什么 M05-06/07 排最后：** 病案首页依赖诊断（M07-02）、手术（M09）、出院（M05-05）、费用（M16-03）全部就绪，缺任何一项都无法填写完整。统计则依赖全流程数据。

## 附录 B：术语表

| 术语 | 说明 |
|---|---|
| **住院号**（`admission_no`） | 患者一次住院的唯一编号，格式 `ZY` + YYYYMMDD + 4 位 |
| **住院流水号**（`admission_id`） | 数据库主键，全院唯一 |
| **入科** | 患者完成分床，正式归属于某病区 |
| **分床** | 为已登记的患者分配具体床位 |
| **转床** | 同一病区内换床 |
| **转科** | 从一个病区转到另一个病区（跨科室） |
| **包床** | 单人间/加护房，同床只能一个患者但仍按床位收费 |
| **加床** | 在走廊或病房额外增设的床（眼科极少用） |
| **预出院** | 医生已下出院医嘱，但出院手续未办 |
| **床日数** | 患者占用床位的自然日计数，按 0 时切分 |
| **床位使用率** | 实际占用床日 / 实际开放床日 |
| **平均住院日** | 总床日数 / 出院人数 |
| **病案首页** | 住院病案第一页，DRG/DIP 入组必需的结构化数据 |
| **DRG / DIP** | 按病种付费的医保支付方式，依赖病案首页数据 |
| **离院方式** | 医嘱离院/转院/自动离院/死亡/其他 |
| **入院病情** | 危/急/一般 |
