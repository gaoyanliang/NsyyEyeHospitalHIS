## 1. 模块概述

### 1.1 模块定位

M05-03 在院管理与转科转床负责**患者从分床到出院之间的一切状态变化**：病情等级调整、护理等级调整、转科、转床、转院、离院方式登记、以及出院通知与出院小结的触发。

```
┌──────────────────────────────────────────────────────────────────────┐
│                M05 住院管理 —— 七个子模块的分工                        │
└──────────────────────────────────────────────────────────────────────┘

  门诊/急诊            ┌──────────────────┐
  医生开住院单  ──────►│  M05-01          │
                       │  入院登记与住院主档 │  创建住院单 m05_admission
                       └────────┬─────────┘
                                │
                                ▼
                       ┌──────────────────┐
                       │  M05-02          │  分配具体床位 m05_bed
                       │  床位管理与病区    │  EMPTY → OCCUPIED
                       └────────┬─────────┘
                                │
                                ▼
   ┌──────────────────────────────────────────────────────┐
   │  M05-03  在院管理与转科转床   ◄── 本子模块             │
   │  ────────────────────────────────────────────────────  │
   │  ① 在院日常维护 m05_stay（病情/护理等级/主治医师/饮食）   │
   │  ② 转科转床 m05_transfer（换病区/换床位/换主诊）          │
   │  ③ 出院流程 m05_discharge（出院通知/离院方式/出院登记）     │
   │  ④ 出院小结触发（调 M07-06 生成 DISCHARGE_SUMMARY）      │
   │  ⑤ 在院状态回写（→ M08 护理、M14 药房、M16 收费）        │
   └───────────────────┬──────────────────────────────────┘
                       │
                       ▼
              ┌──────────────────┐
              │  M05-05          │
              │  出院办理与病历归档 │  出院小结、病案归档
              └──────────────────┘
```

**一句话定位：** M05-01 回答「这个患者住院了」，M05-02 回答「他住在哪张床」，**M05-03 回答「他现在是什么状态、要转到哪去、什么时候能走」**。

### 1.2 为什么独立成子模块

**理由一：在院期间是住院周期中最长、变化最频繁的一段。**
一次住院 5~7 天，其中入院登记只发生 1 次、出院办理 1 次，中间的病情变化、护理等级调整、转床、转科平均发生 2~4 次。若把这段逻辑分散到 M05-01 与 M05-05，会导致「住院主档表」既要承担入院创建又要承担在院维护，违反「创建过程与使用过程分离」的原则（M05-01 §1.2 已论证）。

**理由二：转科转床是「一次业务、多方联动」的复合操作。**
一次转床要做六件事：释放旧床（M05-02）、占用新床（M05-02）、更新住院单床位（M05-01）、写转床记录（本子模块）、通知护理站（M08）、触发床位费差额调整（M05-04）。若分散到三个子模块各写一段，任何一处失败都会造成数据不一致。集中到一个子模块，才能在一个事务里编排。

**理由三：出院流程有独立的「三段式」结构。**
医学上的「出院」是一个过程而非一个时刻：

| 阶段 | 谁发起 | 状态 | 典型时长 |
|---|---|---|---|
| 出院通知（医生下医嘱） | 责任医生 | `DISCHARGING` | — |
| 出院小结书写与签字 | 责任医生 | `DISCHARGING` | 1~4 小时 |
| 出院办理（出院登记 + 费用结算） | 住院处 | `DISCHARGED` → `SETTLED` | 30~60 分钟 |

这三段跨越了医生站、住院处、收费三个岗位，若都在 M05-01 里，会让「入院登记」这个子模块同时承担两个极端角色的职责。

**理由四：转科/转院涉及科室间责任转移与费用归属切换。**
转到另一个科室后，责任医生变更、护理单元变更、科室成本核算变更、医保结算科室归属变更。M05-03 必须在转科时刻精确记录「转出科室、转入科室、转科时间、转科原因」，因为 M16 的住院费用按科室统计、M17 的成本核算按科室分摊都是基于这个时刻切分的。

**关键边界表述：**

- **M05-03 说「这个患者现在病情危重、一级护理、主诊医师是王医生」**，具体住哪张床由 M05-02 决定，具体收多少钱由 M16 决定。

- **M05-03 说「医生下了出院医嘱，进入出院流程」**，费用结算与病案归档分别由 M16-03 与 M05-05 完成。

### 1.4 概念辨析

**辨析一：转科 vs 转床 vs 转院**

| 概念 | 改变什么 | 是否换病区 | 是否换科室 | 是否离开本院 |
|---|---|---|---|---|
| 转床 | 床位号 | ❌ | ❌ | ❌ |
| 转科 | 科室 + 病区 + 床位 + 主诊医师 | ✅ | ✅ | ❌ |
| 转院 | 离院至其他医疗机构 | — | — | ✅ |

三者都记录在 `m05_transfer` 表，用 `transfer_type` 区分。**注意：** 转床时如果跨越了病区（比如眼科一病区 301 床转到眼科二病区 401 床），业务上属于转科，`transfer_type = 'TRANSFER_WARD'` 而非转床。

**辨析二：病情等级 vs 护理等级**

| 概念 | 分级 | 谁定 | 决定什么 | 收费关联 |
|---|---|---|---|---|
| 病情等级 | 危 / 急 / 一般 | 责任医生 | 查房频次、护理力度 | 不直接收费 |
| 护理等级 | 特级 / 一级 / 二级 / 三级 | 责任医生（医嘱） | 护理内容与频次 | **决定护理费**（M01-06 `NURSE` 分类） |

两者不同但不能割裂：**护理等级必须根据病情等级来定**。M05-03 校验「病情危重但护理三级」为异常（警告而非阻断，因为存在临终关怀等特殊情况）。

**辨析三：出院通知 vs 出院小结 vs 出院登记**

| 概念 | 产物 | 责任方 | 何时发生 | 可否撤销 |
|---|---|---|---|---|
| 出院通知 | `m05_admission.status = 'DISCHARGING'` | 责任医生 | 医生决定患者可以出院 | ✅ 可撤销（病情变化） |
| 出院小结 | M07-06 的 `DISCHARGE_SUMMARY` 文书 | 责任医生书写 | 出院通知后 4 小时内 | ✅ 可作废重写 |
| 出院登记 | `m05_discharge` 记录 + `status = 'DISCHARGED'` | 住院处 | 患者实际离院时 | ❌ 不可撤销（可重新入院） |

**关键点：** 出院通知下的**不是**「出院」，而是「准备出院」。只有出院登记才真正离院。这个区分避免了「医生上午下了出院医嘱、患者下午病情变化继续住」时系统里出现「已出院还在院」的矛盾。

**辨析四：离院方式 vs 出院类型**

- **离院方式**（M01-10 字典 `DISCHARGE_TYPE`）：医嘱离院 / 转院 / 自动离院 / 死亡 / 其他。病案首页必填，医保结算依据。
- **出院类型**（本模块 `discharge_type`）：`NORMAL` 正常出院 / `TRANSFER` 转院 / `AGAINST_ADVICE` 自动离院 / `DECEASED` 死亡 / `READMITTED` 再入院。
- 两者一一对应，前者是主数据字典（可在 M01 维护显示名），后者是本模块枚举（代码使用）。

### 1.5 模块目标

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 在院状态准确率 | 100% | 每日 03:00 对账无差异 |
| 转床成功率 | ≥ 99.9% | 转床操作成功数 / 总操作数 |
| 转床事务原子性 | 100% | 无「新床占用旧床未释放」记录 |
| 出院通知到出院登记时长 | ≤ 8 小时（P90） | 时间差统计 |
| 出院小结按时完成率 | ≥ 98% | 离院前完成数 / 出院数 |
| 病程记录完整率 | ≥ 95% | 有当日病程记录的住院患者 / 全部在院 |
| 转科责任医生变更准确率 | 100% | 转科后主诊医师与转入科室匹配 |
| 病情等级变更留痕率 | 100% | 每次变更都有记录与操作人 |
| 护理等级与病情等级匹配率 | ≥ 99% | 合理组合占比（异常告警数） |
| 出院登记平均耗时 | ≤ 5 分钟 | 从打开出院登记页到提交 |

### 2.4 依赖清单与失败影响

| 编号 | 依赖 | 类型 | 失败影响 | 应对 |
|---|---|---|---|---|
| D-01 | M05-01 `GET /internal/v1/m05/admission/{id}` | 同步 | 无法读取住院单 | 阻断，报 `"0503001"` |
| D-02 | M05-01 `POST /internal/v1/m05/admission/on-stay-changed` | 异步 | 住院单在院字段未更新 | 重试 3 次后进补偿队列 |
| D-03 | M05-02 `POST /internal/v1/m05/bed/assign` | 同步 | 无法完成分床 | 阻断，报 `"0503002"` |
| D-04 | M05-02 `POST /internal/v1/m05/bed/change` | 同步 | 无法完成换床 | 阻断 |
| D-05 | M05-02 `POST /internal/v1/m05/bed/on-admission-closed` | 同步 | 床位未释放 | 阻断（出院登记必须先释放床位） |

### 3.2 在院状态机

```
              ┌───────────────────────────────────────────────┐
              │                                               │
              ▼                                               │
     ┌────────────────┐   转科/转床申请   ┌────────────────┐   │
     │  IN_HOSPITAL   │───────────────►│  TRANSFERRING  │   │
     │   在院中        │◄───────────────│   转科转床中    │   │
     └───────┬────────┘   取消/驳回     └───────┬────────┘   │
             │                                  │            │
             │ 医生下出院医嘱        转科/转床完成  │            │
             ▼                                  └────────────┘
     ┌────────────────┐
     │  DISCHARGING   │
     │   出院流程中     │
     └───────┬────────┘
             │
             │ 撤销出院通知（病情变化）
             └──────────────────────────► IN_HOSPITAL

             │ 出院登记
             ▼
     ┌────────────────┐
     │    CLOSED      │
     │   已结案        │
     └────────────────┘
```

**状态说明：**

| 状态 | 中文 | 说明 | 可出院登记 | 计入在院人数 |
|---|---|---|---|---|
| `IN_HOSPITAL` | 在院中 | 正常在院，可进行各类操作 | ✅ | ✅ |
| `TRANSFERRING` | 转科转床中 | 申请已提交，等待审批/执行 | ❌ | ✅ |
| `DISCHARGING` | 出院流程中 | 医生已下出院医嘱，等出院小结与登记 | ✅ | ✅ |
| `CLOSED` | 已结案 | 患者已离院 | ❌ | ❌ |

**为什么 `TRANSFERRING` 要独立于 `IN_HOSPITAL`？**
转科期间（申请到执行之间，可能几小时）不能让护士看到「在院中」的状态去做执行，否则会出现「医嘱开在旧科室，患者已到新科室」的情况。标记为 `TRANSFERRING` 让 M08 护理站显式提示「该患者正在转科，暂停执行」。

**为什么 `DISCHARGING` 仍计入在院人数？**
患者还在床上。只有真正离院（`CLOSED`）才从在院人数中移除，否则「上午 40 人、下午 35 人、实际一个都没走」的统计失真。

### 3.3 转科转床模型（`m05_transfer`）

一次转科/转床/转院对应一条 `m05_transfer` 记录。

**五种转科类型（`transfer_type`）：**

| 代码 | 中文 | 换科室 | 换病区 | 换床位 | 需审批 | 说明 |
|---|---|---|---|---|---|---|
| `CHANGE_BED` | 转床 | ❌ | ❌ | ✅ | ❌ | 同病区内换床，护士长确认即可 |
| `CHANGE_WARD` | 转病区 | ❌ | ✅ | ✅ | ✅ | 同科室不同病区，科室主任审批 |
| `CHANGE_DEPT` | 转科 | ✅ | ✅ | ✅ | ✅ | 跨科室，双方主任 + 医务科审批 |
| `CHANGE_DOCTOR` | 换主诊 | ❌ | ❌ | ❌ | ❌ | 只换主治医师，科室内部调整 |
| `TRANSFER_OUT` | 转院 | — | — | — | ✅ | 转至外院，医务科审批 |

**为什么转床不需要审批而转科需要？**
转床只是物理位置变化（患者还是同一个医生管），护士长确认即可保证执行。转科涉及责任医生变更、科室成本归属变更、医保结算科室变更，必须有科室主任确认「我接收这个患者」。

**转科审批流程：**

```
  医生发起转科申请
        │
        ▼
  ┌──────────────────┐
  │  PENDING_APPLY   │  待申请（草稿）
  └────────┬─────────┘
           │ 提交
           ▼
  ┌──────────────────┐     转出科室主任同意
  │  PENDING_OUT     │──────────────┐
  │  待转出科室审批    │              │
  └────────┬─────────┘              │
           │                        ▼
           │              ┌──────────────────┐
           │              │  PENDING_IN      │  待转入科室审批
           │              └────────┬─────────┘
           │                       │ 转入科室主任同意
           │                       ▼
           │              ┌──────────────────┐
           │              │  PENDING_MEDICAL │  待医务科审批（仅 CHANGE_DEPT）
           │              └────────┬─────────┘
           │                       │ 医务科同意
           │                       ▼
           │              ┌──────────────────┐
           └─────────────►│    APPROVED      │  已批准，待执行
                          └────────┬─────────┘
                                   │ 执行（换床+更新住院单）
                                   ▼
                          ┌──────────────────┐
                          │    EXECUTED      │  已执行（终态）
                          └──────────────────┘

  任一审批环节可驳回 → REJECTED（终态）
  申请可撤销 → CANCELLED（终态）
```

**七态转科状态机：**

| 状态 | 说明 | 下一步 |
|---|---|---|
| `PENDING_APPLY` | 草稿，尚未提交 | 提交 → `PENDING_OUT` |
| `PENDING_OUT` | 待转出科室主任审批 | 同意 → `PENDING_IN` / 驳回 → `REJECTED` |
| `PENDING_IN` | 待转入科室主任审批 | 同意 → `PENDING_MEDICAL`（转科）或 `APPROVED`（转病区） |
| `PENDING_MEDICAL` | 待医务科审批 | 同意 → `APPROVED` / 驳回 → `REJECTED` |
| `APPROVED` | 已批准，待执行 | 执行 → `EXECUTED` |
| `EXECUTED` | 已执行（终态） | — |
| `REJECTED` | 已驳回（终态） | — |
| `CANCELLED` | 已撤销（终态） | — |

**为什么审批要分「转出」与「转入」两步？**
转出科室主任确认「这个患者我可以放出」（排除患者还没稳定就转走），转入科室主任确认「我能接收」（资源、医生、床位）。若只有一步，转入科室可能被动接收。

### 3.4 出院流程模型

**出院流程七个步骤：**

```
  ① 医生下出院医嘱
       │  → m05_admission.status = 'DISCHARGING'
       │  → m05_stay.stay_status = 'DISCHARGING'
       │  → m05_stay.discharge_notified_at = now()
       ▼
  ② 护士通知患者（口头 + 出院须知发放）
       │  → 记录 m05_discharge.notified_at
       ▼
  ③ 医生书写出院小结（M07-06 DISCHARGE_SUMMARY）
       │  → 调 M07-06 generate-by-order
       │  → m05_discharge.summary_status = 'WRITING'
       ▼
  ④ 出院小结签字
       │  → m05_discharge.summary_status = 'SIGNED'
       ▼
  ⑤ 住院处费用结算（M16-03）
       │  → 调 M16-03 settle/preview → settle
       │  → m05_discharge.settle_status = 'SETTLED'
       ▼
  ⑥ 出院登记（录入离院方式与离院时间）
       │  → 调 M05-02 释放床位
       │  → m05_admission.status = 'DISCHARGED'
       │  → m05_stay.stay_status = 'CLOSED'
       │  → 计算 stay_days
       ▼
  ⑦ 病案流转到 M05-05 归档
```

**出院登记的三个前置校验：**

| 编号 | 校验 | 阻断级别 | 例外 |
|---|---|---|---|
| P-01 | 出院小结状态为 `SIGNED` | 阻断 | 转院/自动离院/死亡可豁免（标记 `summary_exempt=TRUE`） |
| P-02 | 费用已结算或已审批欠费出院 | 阻断 | 欠费出院需医务科审批 |
| P-03 | 所有在院医嘱已停止或完成 | 警告 | 未完成医嘱自动作废 |

**为什么 P-01 对死亡/自动离院豁免？**
- 患者死亡来得突然，出院小结来不及写，事后由医生补写（病案首页必填死亡时间与原因）
- 自动离院是患者未经医生同意强行离开，医生无法在此之前完成小结

### 3.5 离院方式模型

**五种离院方式：**

| 代码 | 中文 | 医保术语 | 病案首页必填信息 | 是否算正常出院 |
|---|---|---|---|---|
| `NORMAL` | 医嘱离院 | 医嘱离院 | — | ✅ |
| `TRANSFER` | 转院 | 转院 | 接收医院名称 | ❌（计入转院率） |
| `AGAINST_ADVICE` | 自动离院 | 非医嘱离院 | 自动离院原因、是否签署知情同意 | ❌（计入自动离院率） |
| `DECEASED` | 死亡 | 死亡 | 死亡时间、死亡原因、是否尸检 | ❌（计入死亡率） |
| `OTHER` | 其他 | 其他 | 具体说明 | ❌ |

**`stay_days` 的计算规则：**

```
stay_days = DATEDIFF(discharge_date, admission_date) + 1
```

- 入院与出院同一天出院，计 1 天（日间手术）
- 举例：10 月 20 日入院，10 月 25 日出院 → 6 天

**为什么 +1？** 因为入院当天也算一天住院日。这是医院统计的标准口径（与医保结算一致），不加 1 会导致「当天出院的日间手术患者住院日为 0」的荒谬结果。

### 3.6 病情与护理等级联动模型

**病情等级 → 护理等级推荐：**

| 病情等级 | 推荐护理等级 | 巡视间隔 | 说明 |
|---|---|---|---|
| `CRITICAL` 危 | 特级 / 一级 | 特级：持续监护；一级：每 1 小时 | 危及生命 |
| `URGENT` 急 | 一级 / 二级 | 每 1~2 小时 | 病情不稳定 |
| `GENERAL` 一般 | 二级 / 三级 | 每 2~3 小时 | 病情稳定 |

**M05-03 的校验规则：**

- `CRITICAL` + `LEVEL_3`（危重 + 三级护理）：**阻断**，报 `"0503011"`（"病情危重不能开三级护理"）
- `CRITICAL` + `LEVEL_2`：**警告**（"病情危重建议一级或特级护理"）
- `GENERAL` + `SPECIAL`（一般 + 特级）：**警告**（"病情一般但为特级护理，请确认必要性"）
- 其他组合：通过

**为什么 `CRITICAL + LEVEL_3` 要阻断而不是警告？**
这是典型的文书差错：病情等级与护理等级严重不匹配会导致护理站按三级护理（每 3 小时巡视）去执行危重患者，出事后医院无法举证已尽到注意义务。允许例外要通过「病情等级变更」流程而非直接开冲突医嘱。

### 3.7 护理等级与费用联动

护理等级决定护士工作量，也决定护理费。M01-06 的 `md_charge_item` 中有 `charge_class = 'NURSE'` 的分类：

| 护理等级 | 收费项目示例 | 单价 | 计费方式 |
|---|---|---|---|
| `SPECIAL` | 特级护理费 | ¥150/日 | 按天 |
| `LEVEL_1` | 一级护理费 | ¥60/日 | 按天 |
| `LEVEL_2` | 二级护理费 | ¥30/日 | 按天 |
| `LEVEL_3` | 三级护理费 | ¥15/日 | 按天 |

**联动机制：** M05-03 修改护理等级 → 发事件 `m05.stay.nursing_level_changed` → M05-04 收到后从**变更次日 00:30** 起按新等级计费。

**为什么变更次日生效而不是当天？**
当日计费任务 00:30 已经跑过（按变更前的等级记了当天费用）。若当天立即改，会导致同一天重复计费。次日起改为新等级，符合医院实际惯例。

**跨等级变更的当天费用归属：**
- 上午 10:00 从三级改一级：当天仍按三级收，次日起按一级收
- 这是保守做法，避免需退补当天费用

### 3.8 转科时的责任与费用切分

**转科时刻 T0 必须切分四件事：**

| 切分对象 | 切分规则 |
|---|---|
| 责任医生 | T0 前医嘱由原医生签字，T0 后由新医生签字 |
| 护理单元 | T0 前由原病区执行护理任务，T0 后由新病区执行 |
| 费用归属科室 | M16 记账的 `dept_id` 按 T0 切分：T0 前的费用计入原科室，T0 后的计入新科室 |
| 床位费用 | T0 当天：若在 T0 之前的 12:00 前转科，当天费用计入新科室床位类型；否则计入原科室 |

**床位费跨科室的简化的规则：**
转科当天的床位费按「T0 时刻所在的患者实际床位」归属科室，不拆分小时。理由：床位费按天计价，拆分半天会让账单极难理解。

### 3.10 在院统计指标

| 指标 | 计算方式 | 用途 |
|---|---|---|
| 在院人数 | `COUNT(stay_status = 'IN_HOSPITAL' OR 'DISCHARGING')` | 床位使用、医护配置 |
| 危重人数 | `COUNT(patient_condition = 'CRITICAL')` | 护理调度、应急准备 |
| 各护理等级分布 | `GROUP BY nursing_level` | 护理工作量测算 |
| 平均住院日 | `AVG(stay_days)` WHERE `status = CLOSED` | 效率指标 |
| 当日新入院 | `COUNT(admitted_at::date = today)` | 业务量 |
| 当日出院 | `COUNT(closed_at::date = today)` | 业务量 |
| 待出院人数 | `COUNT(stay_status = 'DISCHARGING')` | 出院流程积压 |
| 超长住院 | `stay_days > 30` | 医保核查 |
| 当日病情变更次数 | `COUNT(m05_stay_log WHERE change_type = 'CONDITION')` | 护理工作量 |

```python
def _stay_days(admitted_at: datetime, closed_at: Optional[datetime]) -> int:
    """计算住院天数（含首尾）。"""
    end = closed_at or datetime.now()
    delta = (end.date() - admitted_at.date()).days
    return max(delta + 1, 1)


def _check_combination(condition: str, level: str) -> Tuple[str, Optional[str]]:
    """校验病情与护理等级组合，返回 (结果, 提示)。"""
    matrix = CONDITION_LEVEL_MATRIX.get(condition, {})
    return matrix.get(level, ("ALLOW", None))

class StayQueryService:
    """在院查询服务。"""

    def __init__(self, db: AsyncSession):
        self.db = db

    async def list_stays(
        self,
        user: dict,
        ward_id: Optional[int] = None,
        dept_id: Optional[int] = None,
        attending_doctor_id: Optional[int] = None,
        nursing_level: Optional[str] = None,
        patient_condition: Optional[str] = None,
        stay_status: Optional[str] = None,
        keyword: Optional[str] = None,
        page: int = 1,
        page_size: int = 20,
    ) -> Dict[str, Any]:
        """在院患者列表。"""
        stmt = select(M05Stay).where(M05Stay.is_deleted.is_(False))
        stmt = self._apply_scope(stmt, user)

        if ward_id is not None:
            stmt = stmt.where(M05Stay.ward_id == ward_id)
        if dept_id is not None:
            stmt = stmt.where(M05Stay.dept_id == dept_id)
        if attending_doctor_id is not None:
            stmt = stmt.where(M05Stay.attending_doctor_id == attending_doctor_id)
        if nursing_level:
            stmt = stmt.where(M05Stay.nursing_level == nursing_level)
        if patient_condition:
            stmt = stmt.where(M05Stay.patient_condition == patient_condition)
        if stay_status:
            stmt = stmt.where(M05Stay.stay_status == stay_status)
        else:
            # 默认只查在院（未结案）
            stmt = stmt.where(M05Stay.stay_status.in_(ACTIVE_STAY_STATUSES))
        if keyword:
            kw = keyword.strip()
            stmt = stmt.where(
                or_(
                    M05Stay.bed_no.ilike(f"%{kw}%"),
                    M05Stay.patient_name.ilike(f"%{kw}%"),
                    M05Stay.admission_no.ilike(f"%{kw}%"),
                )
            )

        total = await self.db.scalar(
            select(func.count()).select_from(stmt.subquery())
        ) or 0

        stmt = stmt.order_by(
            M05Stay.ward_id, M05Stay.bed_no, M05Stay.id
        ).offset((page - 1) * page_size).limit(page_size)

        rows = (await self.db.scalars(stmt)).all()
        items = [self._brief(r) for r in rows]

        return {
            "items": items,
            "total": total,
            "page": page,
            "page_size": page_size,
            "pages": (total + page_size - 1) // page_size if page_size else 0,
        }

    def _apply_scope(self, stmt, user: dict):
        """注入数据权限。"""
        scopes = user.get("data_scopes", [])
        if "*" in scopes or "ALL" in scopes:
            return stmt
        ward_ids = [
            s.get("ward_id") for s in scopes if s.get("ward_id") is not None
        ]
        dept_ids = [
            s.get("dept_id") for s in scopes if s.get("dept_id") is not None
        ]
        if ward_ids:
            stmt = stmt.where(M05Stay.ward_id.in_(ward_ids))
        elif dept_ids:
            stmt = stmt.where(M05Stay.dept_id.in_(dept_ids))
        else:
            stmt = stmt.where(text("1 = 0"))
        return stmt

                    r.from_dept_name, r.from_ward_name, r.from_bed_no

                "to_location": self._location(
                    r.to_dept_name, r.to_ward_name, r.to_bed_no
                ),
                "reason_code": r.reason_code,
                "reason_text": TRANSFER_REASONS.get(r.reason_code),
                "remark": r.remark,
                "applied_by_name": r.applied_by_name,
                "executed_at": (
                    r.executed_at.strftime("%Y-%m-%d %H:%M:%S")
                    if r.executed_at else None
                ),
            }
            for r in rows
        ]

    @staticmethod
    def _location(dept: Optional[str], ward: Optional[str],
                  bed: Optional[str]) -> str:
        parts = [x for x in (dept, ward, bed) if x]
        return "/".join(parts) if parts else "-"

    async def workbench(
        self, user: dict, ward_id: Optional[int] = None
    ) -> Dict[str, Any]:
        """在院工作台。"""
        stmt = select(M05Stay).where(
            M05Stay.is_deleted.is_(False),
            M05Stay.stay_status.in_(ACTIVE_STAY_STATUSES),
        )
        stmt = self._apply_scope(stmt, user)
        if ward_id is not None:
            stmt = stmt.where(M05Stay.ward_id == ward_id)
        rows = (await self.db.scalars(stmt)).all()

        today = now().date()
        in_hospital = [r for r in rows]
        critical = [r for r in rows if r.patient_condition == "CRITICAL"]
        discharging = [r for r in rows if r.stay_status == "DISCHARGING"]
        today_discharge = [
            r for r in rows
            if r.closed_at and r.closed_at.date() == today
        ]
        today_admitted = [
            r for r in rows if r.admitted_at.date() == today
        ]

        level_dist = {"SPECIAL": 0, "LEVEL_1": 0, "LEVEL_2": 0, "LEVEL_3": 0}
        for r in rows:
            if r.nursing_level in level_dist:
                level_dist[r.nursing_level] += 1

        closed = [
            r for r in rows
            if r.stay_status == "CLOSED" and r.closed_at is not None
        ]
        avg_days = 0.0
        if closed:
            total_days = sum(_stay_days(r.admitted_at, r.closed_at) for r in closed)
            avg_days = round(total_days / len(closed), 1)

        return {
            "ward_id": ward_id,
            "summary": {
                "in_hospital": len(in_hospital),
                "critical": len(critical),
                "discharging": len(discharging),
                "today_discharge": len(today_discharge),
                "today_admitted": len(today_admitted),
                "avg_stay_days": avg_days,
            },
            "nursing_level_distribution": level_dist,
            "need_attention": self._attention_items(rows, today),
            "today_discharge_list": [
                self._brief(r) for r in today_discharge[:20]
            ],
            "today_admitted_list": [
                self._brief(r) for r in today_admitted[:20]
            ],
            "refreshed_at": now().strftime("%Y-%m-%d %H:%M:%S"),
        }

    def _attention_items(self, rows: List[M05Stay],
                         today: date) -> List[Dict[str, Any]]:
        """计算需关注项。"""
        items: List[Dict[str, Any]] = []
        for r in rows:
            reasons: List[str] = []
            if r.patient_condition == "CRITICAL":
                reasons.append("病情危重")
            days = _stay_days(r.admitted_at, r.closed_at)
            if days > 30:
                reasons.append("超长住院（%d 天）" % days)
            if r.stay_status == "DISCHARGING" and r.discharge_notified_at:
                hours = (now() - r.discharge_notified_at).total_seconds() / 3600
                if hours > 4:
                    reasons.append("待出院超 %.1f 小时" % hours)
            check, _ = _check_combination(r.patient_condition, r.nursing_level)
            if check != "ALLOW":
                reasons.append("病情与护理等级不匹配")
            if reasons:
                items.append({
                    "stay_id": r.id,
                    "bed_no": r.bed_no,
                    "patient_name": r.patient_name,
                    "attending_doctor_name": r.attending_doctor_name,
                    "stay_days": days,
                    "reasons": reasons,
                })
        return items[:30]

    async def statistics(
        self,
        user: dict,
        ward_id: Optional[int] = None,
        date_from: Optional[str] = None,
        date_to: Optional[str] = None,
    ) -> Dict[str, Any]:
        """在院统计。"""
        start = (
            datetime.strptime(date_from, "%Y-%m-%d").date()
            if date_from else now().date() - timedelta(days=30)
        )
        end = (
            datetime.strptime(date_to, "%Y-%m-%d").date()
            if date_to else now().date()
        )
        if end < start:
            raise BizException("0503028", "结束日期不能早于开始日期")
        if (end - start).days > 366:
            raise BizException("0503028", "日期跨度超过 366 天")

        stmt = select(M05Stay).where(
            M05Stay.is_deleted.is_(False),
            M05Stay.admitted_at >= datetime.combine(start, datetime.min.time()),
            M05Stay.admitted_at < datetime.combine(
                end + timedelta(days=1), datetime.min.time()
            ),
        )
        stmt = self._apply_scope(stmt, user)
        if ward_id is not None:
            stmt = stmt.where(M05Stay.ward_id == ward_id)
        rows = (await self.db.scalars(stmt)).all()

        closed = [r for r in rows if r.stay_status == "CLOSED"]
        stay_days_list = [_stay_days(r.admitted_at, r.closed_at) for r in closed]
        avg_days = (
            round(sum(stay_days_list) / len(stay_days_list), 2)
            if stay_days_list else 0.0
        )
        over_30 = sum(1 for d in stay_days_list if d > 30)

        return {
            "date_from": str(start),
            "date_to": str(end),
            "ward_id": ward_id,
            "admitted_count": len(rows),
            "closed_count": len(closed),
            "in_hospital_count": sum(
                1 for r in rows if r.stay_status in ACTIVE_STAY_STATUSES
            ),
            "avg_stay_days": avg_days,
            "max_stay_days": max(stay_days_list) if stay_days_list else 0,
            "over_30_days_count": over_30,
            "critical_count": sum(
                1 for r in rows if r.patient_condition == "CRITICAL"
            ),
            "transfer_count": await self._transfer_count(start, end, ward_id),
            "calculated_at": now().strftime("%Y-%m-%d %H:%M:%S"),
        }

    async def _transfer_count(self, start: date, end: date,

    async def internal_daily_statistics(
        self, stat_date: Optional[str] = None
    ) -> Dict[str, Any]:
        target = (
            datetime.strptime(stat_date, "%Y-%m-%d").date()
            if stat_date else now().date()
        )
        stmt = select(M05Stay).where(
            M05Stay.is_deleted.is_(False),
            M05Stay.stay_status.in_(ACTIVE_STAY_STATUSES),
        )
        rows = (await self.db.scalars(stmt)).all()
        levels = {"SPECIAL": 0, "LEVEL_1": 0, "LEVEL_2": 0, "LEVEL_3": 0}
        by_ward: Dict[int, Dict[str, Any]] = {}
        for r in rows:
            if r.nursing_level in levels:
                levels[r.nursing_level] += 1
            bucket = by_ward.setdefault(
                r.ward_id,
                {"ward_id": r.ward_id, "ward_name": r.ward_name,
                 "count": 0, "critical": 0},
            )
            bucket["count"] += 1
            if r.patient_condition == "CRITICAL":
                bucket["critical"] += 1
        return {
            "stat_date": str(target),
            "in_hospital": len(rows),
            "critical": sum(1 for r in rows if r.patient_condition == "CRITICAL"),
            "discharging": sum(1 for r in rows if r.stay_status == "DISCHARGING"),
            "nursing_level_distribution": levels,
            "by_ward": list(by_ward.values()),
            "calculated_at": now().strftime("%Y-%m-%d %H:%M:%S"),
        }

    def _check_scope(self, row: M05Stay, user: dict) -> None:
        scopes = user.get("data_scopes", [])
        if "*" in scopes or "ALL" in scopes:
            return
        ward_ids = [
            s.get("ward_id") for s in scopes if s.get("ward_id") is not None
        ]
        dept_ids = [
            s.get("dept_id") for s in scopes if s.get("dept_id") is not None
        ]
        if row.ward_id in ward_ids or row.dept_id in dept_ids:
            return
        raise BizException("0503030", "无权查看该病区")

class StayService:

    async def change_condition(
        self, stay_id: int, body: Any, user: dict
    ) -> Dict[str, Any]:
        """变更病情等级。"""
        row = await self._get_for_update(stay_id)
        if row.stay_status != "IN_HOSPITAL":
            raise BizException("0503003", "在院状态不允许此操作")

        new_condition = body.patient_condition
        if new_condition == row.patient_condition:
            raise BizException("0503003", "病情等级未发生变化")

        result, message = _check_combination(new_condition, row.nursing_level)
        if result == "BLOCK":
            raise BizException(
                "0503011",
                message,
                data={
                    "current_condition": row.patient_condition,
                    "new_condition": new_condition,
                    "nursing_level": row.nursing_level,
                    "suggestion": "建议先调整护理等级为一级或特级",
                },
            )

        old = row.patient_condition
        row.patient_condition = new_condition
        row.last_changed_at = now()
        row.last_changed_by = user["employee_id"]
        row.last_changed_by_name = user.get("employee_name")
        row.version += 1

        await self._write_log(
            row, "CONDITION", "patient_condition", old, new_condition,
            body.reason, user,
        )
        await self._writeback_admission(row, user)
        await self.db.commit()

        warnings = []
        if result == "WARN" and message:
            warnings.append({"code": "0503012", "message": message})

        return {
            "stay_id": row.id,
            "old_condition": old,
            "new_condition": new_condition,
            "nursing_level": row.nursing_level,
            "combination_check": {"passed": True, "warnings": warnings},
            "changed_by": user["employee_id"],
            "changed_at": row.last_changed_at.strftime("%Y-%m-%d %H:%M:%S"),
            "version": row.version,
        }

    async def update_stay(
        self, stay_id: int, body: Any, user: dict
    ) -> Dict[str, Any]:
        """更新在院信息（饮食/隔离/过敏）。"""
        row = await self._get_for_update(stay_id)
        if row.stay_status == "CLOSED":
            raise BizException("0503003", "已结案不能修改")

        changed: List[str] = []
        if body.diet_type is not None and body.diet_type != row.diet_type:
            await self._write_log(
                row, "DIET", "diet_type", row.diet_type, body.diet_type,
                body.reason, user,
            )
            row.diet_type = body.diet_type
            changed.append("diet_type")
        if (body.need_isolation is not None
                and body.need_isolation != row.need_isolation):
            await self._write_log(
                row, "ISOLATION", "need_isolation",
                str(row.need_isolation), str(body.need_isolation),
                body.reason, user,
            )
            row.need_isolation = body.need_isolation
            changed.append("need_isolation")
        if (body.allergy_history is not None
                and body.allergy_history != row.allergy_history):
            await self._write_log(
                row, "ALLERGY", "allergy_history",
                row.allergy_history or "", body.allergy_history,
                body.reason, user,
            )
            row.allergy_history = body.allergy_history
            changed.append("allergy_history")

        row.last_changed_at = now()
        row.last_changed_by = user["employee_id"]
        row.last_changed_by_name = user.get("employee_name")
        row.version += 1
        await self.db.commit()

        return {
            "stay_id": row.id,
            "changed_fields": changed,
            "version": row.version,
        }

def _parse_value(raw: str, ptype: str) -> Any:
    """按参数类型解析值。"""
    if ptype == "INT":
        return int(raw)
    if ptype == "DECIMAL":
        return float(raw)
    if ptype == "BOOL":
        return raw.lower() in ("true", "1", "yes")
    if ptype == "JSON":
        try:
            return json.loads(raw)
        except Exception:
            return raw
    return raw
```

### 6.7 专题：转科执行的分布式事务

转科执行需要跨三个子模块/模块做六件事：

```
  M05-03 执行转科
       │
       ├── ① M05-02 释放旧床（旧床 → CLEANING）
       ├── ② M05-02 占用新床（新床 → OCCUPIED）
       ├── ③ M05-03 更新 m05_stay（科室/病区/床位/主诊医生）
       ├── ④ M05-01 更新 m05_admission（dept/ward/bed/attending）
       ├── ⑤ M05-04 通知费用归属科室切换
       └── ⑥ M08 通知护理站患者转科
```

**问题：** ①②是 M05-02 的接口调用（HTTP），③在本模块事务内，④是 M05-01 的接口，⑤⑥是异步事件。无法用单一数据库事务保证。

**方案对比：**

| 方案 | 一致性 | 实现复杂度 | 失败恢复 | 采用 |
|---|---|---|---|---|
| A 全同步调用，任一步失败全部回滚 | 强一致（近似） | 高（要写补偿逻辑） | 难（回滚②若失败则两床都丢） | ❌ |
| B 全异步事件驱动 | 最终一致 | 低 | 中（事件丢失需人工） | ❌ |
| C **本地事务 + 有序同步 + 补偿队列** | 最终一致 | 中 | 好（每步独立重试） | ✅ |
| D 分布式事务（Saga/2PC） | 强一致 | 很高 | 复杂 | ❌ |

**采用方案 C 的具体编排：**

```
  ① 创建 m05_transfer 记录，status = 'EXECUTING'（本地事务提交）
       │  此时留有「执行中」标记，若后续失败可被补偿任务发现
       ▼
  ② 调 M05-02 change-bed（同步，超时 5 秒）
       │  成功 → 继续
       │  失败 → 回滚 ①（status 改回 APPROVED），报 "0503002"
       ▼
  ③ 本地事务：更新 m05_stay 的 dept/ward/bed/doctor + 写 m05_transfer_log
       │  成功 → 继续
       │  失败 → 调 M05-02 反向 change-bed 恢复原床，回滚 ①
       ▼
  ④ 调 M05-01 notify-stay-changed（同步，超时 3 秒）
       │  成功 → 继续
       │  失败 → 进补偿队列（每 2 分钟重试，最多 10 次）
       ▼
  ⑤ 发事件 m05.transfer.executed（异步）
       │  M05-04 订阅 → 切换费用归属
       │  M08 订阅 → 更新护理站患者归属
       ▼
  ⑥ 更新 m05_transfer.status = 'EXECUTED'（本地事务提交）
```

**关键设计：为什么 ②③ 必须同步而 ④⑤ 可以异步？**

- ②③ 是**资金与位置的真相**：床位状态和住院单床位必须同时正确，否则出现「新床已占、旧床未释放、住院单还显示旧床」的三方矛盾
- ④ 回写住院主档是**冗余**：`m05_stay` 才是权威，`m05_admission` 的 bed 字段只是快照。短暂不一致不影响业务，重试可修正
- ⑤ 事件驱动是**通知性质**：护理站多看到「患者还在原床」几分钟不影响医疗安全

**补偿队列表（`m05_transfer_compensation`）：**

| 字段 | 说明 |
|---|---|
| `transfer_id` | 转科记录 |
| `step_code` | `M05_01_WRITEBACK` / `M05_04_NOTIFY` / `M08_NOTIFY` |
| `payload` | JSONB 请求体 |
| `retry_count` | 0~10 |
| `next_retry_at` | 下次重试时间 |
| `status` | `PENDING` / `SUCCESS` / `FAILED` |

**重试策略：** 指数退避 `2^n` 分钟，上限 512 分钟（约 8.5 小时），10 次失败后标 `FAILED` 并告警。

**僵尸记录清理：** 定时任务每 10 分钟扫描 `m05_transfer.status = 'EXECUTING' AND updated_at < now() - 30 分钟` 的记录（说明执行中途进程崩溃），回滚为 `APPROVED` 并告警。

```python
import asyncio
from datetime import date, datetime, timedelta

from celery import shared_task

from app.core.logging import get_logger

@shared_task(bind=True, max_retries=10, default_retry_delay=60)
def writeback_admission_task(self, stay_id: int) -> dict:
    """回写住院主档（带重试）。"""
    async def _run():

    try:
        return asyncio.run(_run())

@shared_task
def retry_compensation_task() -> dict:
    """补偿队列重试（每 2 分钟）。"""
    async def _run():
        retried = 0
        async with async_session() as db:
            rows = (
                await db.scalars(
                    select(M05TransferCompensation).where(
                        M05TransferCompensation.status == "PENDING",
                        M05TransferCompensation.next_retry_at <= datetime.now(),
                        M05TransferCompensation.is_deleted.is_(False),
                    ).limit(50)
                )
            ).all()
            for row in rows:
                ok = await _dispatch_compensation(row)
                row.retry_count += 1
                if ok:
                    row.status = "SUCCESS"
                elif row.retry_count >= 10:
                    row.status = "FAILED"
                    logger.error(
                        "转科补偿最终失败",
                        extra={"compensation_id": row.id,
                               "step": row.step_code},
                    )
                else:
                    minutes = min(2 ** row.retry_count, 512)
                    row.next_retry_at = datetime.now() + timedelta(minutes=minutes)
                retried += 1
            await db.commit()
        return {"retried": retried}
    return asyncio.run(_run())


async def _dispatch_compensation(row: M05TransferCompensation) -> bool:
    """按步骤类型分发补偿。"""
    import json
    payload = json.loads(row.payload) if isinstance(row.payload, str) else row.payload
    try:
        if row.step_code == "M05_01_WRITEBACK":
            await M05Client.notify_stay_changed(**payload)
        elif row.step_code == "M05_04_NOTIFY":
            await M05ChargeClient.notify_stay_changed(**payload)
        elif row.step_code == "M08_NOTIFY":
            await M08Client.notify_stay_changed(**payload)
        else:
            logger.error("未知补偿步骤", extra={"step_code": row.step_code})
            return False
        return True
    except Exception as exc:
        logger.warning(
            "补偿重试失败",
            extra={"compensation_id": row.id, "error": str(exc)},
        )
        return False


@shared_task
def check_executing_transfer_task() -> dict:
    """清理僵尸转科记录（每 10 分钟）。"""
    async def _run():

                        M05Transfer.status == "EXECUTING",

                    extra={"transfer_id": row.id, "transfer_no": row.transfer_no},
                )
            await db.commit()
        return {"rolled_back": len(rows)}
    return asyncio.run(_run())

@shared_task
def daily_statistics_task(stat_date: str) -> dict:
    """在院日报统计（每日 01:00）。"""
    async def _run():
        target = datetime.strptime(stat_date, "%Y-%m-%d").date()
        async with async_session() as db:
            rows = (
                await db.scalars(
                    select(M05Stay).where(
                        M05Stay.is_deleted.is_(False),
                        M05Stay.stay_status.in_(
                            ("IN_HOSPITAL", "TRANSFERRING", "DISCHARGING")
                        ),
                    )
                )
            ).all()
            levels = {"SPECIAL": 0, "LEVEL_1": 0, "LEVEL_2": 0, "LEVEL_3": 0}
            for r in rows:
                if r.nursing_level in levels:
                    levels[r.nursing_level] += 1
            result = {
                "stat_date": str(target),
                "in_hospital": len(rows),
                "critical": sum(
                    1 for r in rows if r.patient_condition == "CRITICAL"
                ),
                "discharging": sum(
                    1 for r in rows if r.stay_status == "DISCHARGING"
                ),
                "nursing_level_distribution": levels,
            }
            await RedisClient.setex(
                "m05:stay:stat:%s" % target, 86400 * 7, str(result)
            )
            return result
    return asyncio.run(_run())


@shared_task
def auto_close_patient_left_task() -> dict:

                await db.scalars(

                        M05Stay.stay_status == "IN_HOSPITAL",

            flagged = 0
            for stay in rows:

                if days >= 3:

                        },
                    )
                    flagged += 1
        return {"flagged": flagged}
    return asyncio.run(_run())
```

## 8. 业务规则与校验

| 编号 | 规则 | 说明 |
|---|---|---|
| R-01 | 在院状态为 `CLOSED` 后任何字段不可修改 | 终态保护 |
| R-02 | 病情等级与护理等级组合必须通过校验 | `CRITICAL + LEVEL_3` 阻断 |
| R-03 | 护理等级变更次日 00:30 生效 | 避免当日重复计费 |
| R-04 | 转床必须同病区内；跨病区属于转病区 | 类型校验 |
| R-05 | 转病区/转科/转院必须走审批 | `CHANGE_BED`/`CHANGE_DOCTOR` 免审 |
| R-06 | 同一住院单同时只能有一个进行中的转科申请 | 唯一性校验 |
| R-07 | 转科审批人不能是申请人 | SoD |
| R-08 | 转科执行必须原子完成（释放旧床+占用新床+更新在院） | 事务编排 |
| R-09 | 出院通知不等于出院，状态为 `DISCHARGING` | 可撤销 |
| R-10 | 出院登记必须前置检查通过（小结/费用/签字） | 三前置 |
| R-11 | 死亡/自动离院/转院可豁免出院小结 | `summary_exempt` |
| R-12 | 住院天数 = 出院日 − 入院日 + 1 | 含首尾 |
| R-13 | 出院时未完成医嘱自动作废 | 需用户确认 |
| R-14 | 出院登记后床位立即转 `CLEANING` | 不等结算 |
| R-15 | 离院方式必须与出院类型一致 | 病案首页依据 |
| R-16 | 死亡必须填死亡时间、原因、是否尸检 | 病案必填 |
| R-17 | 转院必须填接收医院并 ≥20 字说明 | 转院审批依据 |
| R-18 | 自动离院必须签知情同意 | 法律依据 |
| R-19 | 每次在院变更必须写日志 | 100% 留痕 |
| R-20 | 系统管理员无任何业务查询权 | 最小权限 |
| R-21 | 所有查询接口必须注入数据权限 | 只能在管辖病区 |
| R-22 | 转科执行中途崩溃 30 分钟内必须回滚 | 僵尸清理 |
| R-23 | 出院通知后 8 小时未完成出院需告警 | 流程积压 |
| R-24 | 住院超 30 天需医保核查提醒 | 超长住院 |
| R-25 | 患者合并时若双方均有在院记录则拒绝合并 | 数据一致性 |
| R-26 | 已关账期间不能办理出院登记 | 财务期间锁定 |

| 责任医生 | 本人主诊的在院患者 + 本病区全部 | `attending_doctor_id = self OR ward_id IN ward_ids` |
| 病区护士长/护士 | 所辖病区 | `ward_id IN ward_ids` |
| 住院处 | 全院 | 无过滤 |
| 医务科/护理部/统计员 | 全院 | 无过滤 |
| 系统管理员 | 无 | 拒绝 |

### 9.4 脱敏规则

| 字段 | 列表页 | 详情页 | 导出 |
|---|---|---|---|
| 患者姓名 | `陈**` | 全名 | 全名（受控） |
| 身份证号 | 不显示 | `1101**********1234` | 全量（受控） |
| 手机号 | 不显示 | `138****5678` | 全量（受控） |
| 诊断 | 显示 | 显示 | 显示 |
| 床号 | 显示 | 显示 | 显示 |

**导出为什么不全脱敏？** 导出是受控操作（仅特定角色 + 有审计），脱敏会让数据失去业务价值。

### 9.5 安全措施

| 编号 | 措施 | 说明 |
|---|---|---|
| S-01 | 所有写接口参数校验 | Pydantic 强类型 + 业务校验 |
| S-02 | 所有查询注入数据权限 | `_apply_scope` |
| S-03 | 版本号乐观锁 | 防并发覆盖 |
| S-04 | 行锁 `FOR UPDATE` | 转科执行、出院登记 |
| S-05 | Redis 分布式锁 | 防重复提交（TTL 30s） |
| S-06 | 只增审计日志 | 通过 `M02-06` 记录 |
| S-07 | 敏感操作二次确认 | 出院登记、转科执行 |
| S-08 | 电子签名 | 出院登记需患者/家属签字 |
| S-09 | SQL 注入防护 | 全部参数化，动态条件只拼固定常量 |
| S-10 | 幂等设计 | 出院登记用 `stay_id + version` 幂等 |

| 出院小结 | 医生书写的住院经过与出院医嘱，M07-06 文书 |
| 出院登记 | 患者实际离院时的正式手续 |
| 离院方式 | 医嘱离院/转院/自动离院/死亡/其他，病案首页必填 |
| 住院日 | 从入院到出院的天数（含首尾） |
| SoD | 职责分离（Separation of Duties） |
| 豁免（Exempt） | 特殊情形下放宽前置校验（如死亡可免出院小结） |
| 补偿队列 | 异步失败后的重试队列 |
