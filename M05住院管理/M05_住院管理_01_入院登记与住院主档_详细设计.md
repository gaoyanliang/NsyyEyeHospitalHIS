## 1. 模块概述

### 1.1 模块定位

**M05-01 回答一个问题：这个患者现在是不是住在我们医院？如果是，他的住院号是多少？**

它是 M05 全模块的**数据地基**。M05-02 床位管理、M05-03 在院管理、M05-04 费用联动、M05-05 出院办理、M05-06 病案首页、M05-07 统计全部通过 `m05_admission.id`（住院流水号）挂上来。

```
┌──────────────────────────────────────────────────────────────────┐
│                      M05-01 在整条链上的位置                       │
├──────────────────────────────────────────────────────────────────┤
│                                                                    │
│  门诊接诊（M07-01）                                                 │
│       │                                                            │
│       │ 医生判定需住院 → next_action = 'ADMIT'                      │
│       ▼                                                            │
│  ┌────────────────────────────────────────┐                        │
│  │ ①入院申请（m05_admission_request）      │  ← M05-01 本文档        │
│  │   状态：DRAFT → PENDING                 │                        │
│  └───────────────┬────────────────────────┘                        │
│                  │ 患者到住院处                                       │
│                  ▼                                                 │
│  ┌────────────────────────────────────────┐                        │
│  │ ②入院登记（m05_admission）              │  ← M05-01 本文档        │
│  │   状态：PENDING → REGISTERED            │                        │
│  │   动作：核身份 / 收入院途径 / 交预交金     │                        │
│  └───────────────┬────────────────────────┘                        │
│                  │                                                  │
│                  │ 出院床（M05-02）                                  │
│                  ▼                                                  │
│  ┌────────────────────────────────────────┐                        │
│  │ ③在院（m05_stay）                      │  ← M05-03              │
│  └───────────────┬────────────────────────┘                        │
│                  │                                                  │
│                  ▼                                                  │
│  ┌────────────────────────────────────────┐                        │
│  │ ④出院（m05_discharge）→ ⑤结算 SETTLED   │  ← M05-05 / M16-03     │
│  └────────────────────────────────────────┘                        │
│                                                                    │
└──────────────────────────────────────────────────────────────────┘
```

**除了上面这条主链路，M05-01 还有两个入口：**

1. **日间手术转住院**（M06-06 → `POST /internal/v1/m05/admission/from-day-surgery`）——患者已在院内，跳过入院申请直接建住院单
2. **急诊/门诊直收**（无门诊接诊记录）——由住院处直接建住院单

### 1.2 为什么独立成子模块

**理由一：住院主档是 M05 全模块的唯一主键来源，它的创建过程与使用过程必须分离。**

`m05_admission.id` 被 M08 护理站、M14-08 住院药房、M16-03 住院结算、M09 手术麻醉、M06-06 病案归档五方依赖。如果「创建住院单」这件事散落在 M05-02（床位）、M05-05（出院）里，就会出现：

- M05-02 分床时发现住院单不存在，自己建一个
- M05-05 出院时发现住院单字段不全，自己补一个
- 两处建出的住院单字段口径不一致（一个记了 `insurance_type`，一个没记）

M05-01 独占「创建住院主档」的写入权，其他子模块**只读**。

**理由二：入院登记承担的是「身份核验 + 费用门槛 + 法规登记」三重责任，与其他环节性质完全不同。**

| 责任 | 具体内容 | 为什么必须在此环节 |
|---|---|---|
| **身份核验** | 姓名、性别、年龄、证件号、EMPI 与本人核对 | 住院是全流程最贵的一次消费（数千到数万元），身份错了整个病案都废 |
| **费用门槛** | 必须先交预交金才能入科 | 不设门槛就会大量欠费出院，眼科尤其（术后即走） |
| **法规登记** | 入院途径、入院病情、入院时间 | 《住院病案首页数据填写质量规范》要求这三项在入院时确定 |

这三件事在任何其他环节做都不合适：床位管理只关心「哪张床」，出院办理只关心「离开时怎么走」。

**理由三：入院登记是一个有独立状态机的完整流程，且存在「作废重开」的现实场景。**

状态机：`DRAFT → PENDING → REGISTERED → （分床后由 M05-03 接管）`

现实中的异常分支：

- 患者登记后不来了 → 作废，退预交金
- 患者身份信息登记错（同名同姓）→ 作废重开
- 患者登记后要求换科室 → 作废重开（不能改科室，因为科室决定病区与床位池）

如果并入 M05-03 在院管理，「作废」这个动作没法表达（在院患者不能作废）。独立成子模块后，「登记前」和「登记后」是两个清晰的世界。

**理由四：病案首页的入院信息块（约 40 个字段）在入院登记时采集，出院时只补离院信息。**

病案首页分「入院信息」「诊疗信息」「离院信息」三块。其中入院信息块（患者基本信息、入院途径、入院时间、入院时情况、入院诊断）在登记时采集。如果 M05-01 与 M05-06 不分开，这 40 个字段就没有明确定义采集时机。

### 1.4 概念辨析

| 概念对 | 区别 | 举例 |
|---|---|---|
| **入院申请 ≠ 入院单** | 申请是「我建议住院」，单是「你住进来了」 | 医生开申请（DRAFT/PENDING）→ 患者到院登记（REGISTERED），两态两张表 |
| **入院登记 ≠ 入科** | 登记是办手续，入科是分到床 | 登记后状态 `REGISTERED`（待分床），分床后 `IN_HOSPITAL`（在院） |
| **住院号 ≠ 就诊号** | 住院号（`ZY...`）记一次住院；就诊号（`V...`）记一次就诊窗口；一个患者一生可有多个住院号 | 王五 2026-03 住一次（`ZY20260301001`），2026-10 再住一次（`ZY20261015001`），是两个住院号 |
| **住院号 ≠ 门诊卡号** | 前者一次住院一个，后者终生一个 | — |
| **入院病情 ≠ 病情等级** | 入院病情（危/急/一般）在入院时填一次，进病案首页；病情等级（特级/一级/二级/三级护理）随病情变化动态调整，决定护理费 | 白内障患者入院病情「一般」、护理等级「二级」；术后当天临时升「一级」 |
| **预交金 ≠ 押金** | 医院官方术语是预交金；押金是口语 | 统一用「预交金」 |
| **作废 ≠ 出院** | 作废是住院没发生（退预交金）；出院是住院结束（结算） | 登记后不来了 → 作废；住完走了 → 出院 |

### 1.5 模块目标

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 入院登记平均耗时 | **≤ 90 秒** | 从打开登记页到提交成功 |
| 入院登记一次成功率 | **≥ 99%**（无字段返工） | 提交成功 ÷ 打开登记页 |
| 住院号唯一性 | **100%** | 每日对账检查 |
| 住院号与患者绑定正确率 | **100%** | 抽查 30 例/日 |
| 预交金收取及时率 | **100%**（入科前已收） | 分床时校验 |
| 入院申请到入院登记的平均间隔 | ≤ 4 小时 | 统计报表 |
| 入院申请作废率 | ≤ 5% | 作废数 ÷ 申请数 |
| 住院主档字段完整率 | **100%**（必填项） | 每日扫描 |
| 病案首页入院信息块可自动回填率 | **≥ 85%** | 自动回填字段 ÷ 总字段 |

| 角色 | 主要操作 | 权限域 |
|---|---|---|

## 3. 业务模型

### 3.1 入院申请模型

**入院申请是一张「建议住院」的单子，还不是住院单。**

| 状态 | 含义 | 谁能改 |
|---|---|---|
| `DRAFT` | 医生正在填，未提交 | 开单医生 |
| `PENDING` | 已提交，等患者到住院处 | 不可改，只能作废 |
| `REGISTERED` | 已被登记，转为住院单 | 不可改 |
| `CANCELLED` | 作废（患者不来 / 信息错 / 换科室） | 住院处、医务科 |

**申请单的关键字段：**

| 字段 | 必填 | 说明 |
|---|---|---|
| `request_no` | ✅ | `SQ` + YYYYMMDD + 4 位 |
| `patient_id` | ✅ | 患者 ID |
| `source_type` | ✅ | `OUTPATIENT`（门诊接诊）/ `EMERGENCY`（急诊直收）/ `DAY_SURGERY`（日间转住院）/ `SELF`（自主入院，罕见） |
| `source_id` | 条件 | 门诊接诊时为 `encounter_id`；日间手术时为 `schedule_id` |
| `dept_id` | ✅ | 申请入住科室 |
| `doctor_id` | ✅ | 开单医生 |
| `primary_diagnosis` | ✅ | 主要诊断（ICD-10） |
| `expected_admission_date` | ✅ | 预计入院日期 |
| `expected_stay_days` | ✅ | 预计住院天数 |
| `admission_way` | ✅ | 入院途径：门诊/急诊/转院/其他 |
| `patient_condition` | ✅ | 入院病情：危/急/一般 |
| `eye_side` | 条件 | 眼科特有，`OD`/`OS`/`OU`/`NA` |
| `surgery_plan` | ❌ | 计划手术（术式代码） |
| `surgery_plan_sequence` | ❌ | **第几期手术**（双眼分期时 1 或 2） |
| `need_isolation` | ❌ | 是否需隔离 |
| `need_companion` | ❌ | 是否需陪护 |
| `remark` | ❌ | 备注 |

### 3.2 住院主档模型

`m05_admission` 是**一次住院**的完整档案，不是患者档案。同一患者多次住院对应多条记录。

**字段分六组：**

| 组 | 字段 | 采集时机 |
|---|---|---|
| **A 标识组** | `id` / `admission_no` / `patient_id` / `empi_no` / `visit_no` | 登记时 |
| **B 患者快照组** | `patient_name` / `gender` / `age` / `birth_date` / `id_card_no` / `phone` / `address` | 登记时从 M03 快照 |
| **C 入院信息组** | `admission_way` / `patient_condition` / `admission_time` / `admission_dept_id` / `admission_ward_id` / `attending_doctor_id` / `resident_doctor_id` / `nurse_id` | 登记时 |
| **D 诊疗信息组** | `admission_diagnosis` / `eye_side` / `surgery_plan` / `surgery_plan_sequence` / `insurance_type` | 登记时 + 后续更新 |
| **E 状态组** | `status` / `bed_id` / `bed_no` / `discharge_time` / `actual_stay_days` | 全生命周期 |
| **F 费用快照组** | `deposit_total` / `deposit_used` / `total_charge` / `settle_amount` | 由 M16 事件更新 |

**为什么患者信息要快照：** 患者后来改了手机号，2020 年住院记录里的联系方式不应跟着变——病案要还原「当时的信息」。

### 3.3 住院号生成规则

**格式：** `ZY` + `YYYYMMDD` + 4 位顺序号 → `ZY202610280001`

| 部分 | 长度 | 说明 |
|---|---|---|
| `ZY` | 2 | 固定前缀（住院） |
| `YYYYMMDD` | 8 | 入院日期 |
| 顺序号 | 4 | 当日从 0001 起，上限 9999 |

**为什么按日期分段：** ①可读性好，看一眼就知道哪天住的 ②跨日序号重置，不会无限增长 ③日 9999 上限对二级医院（实际日均入院 20~40 人）绰绰有余。

**并发保障：** Redis `INCR m05:admission:seq:{yyyymmdd}`，配合 DB 唯一索引 `uk_m05_admission_no` 兜底。

**注意：** 住院号与 `admission_id`（数据库主键）是两个东西。住院号是给人看的，`admission_id` 是给程序用的。业务上**一律用住院号传递**，因为它是稳定的业务标识。

### 3.4 预交金门槛模型

**规则：入科前必须已交预交金，否则不予分床。**

| 模式 | 说明 | 参数 |
|---|---|---|
| `REQUIRED` | 必须交，否则不能登记（默认） | `M05.ADMISSION.MIN_DEPOSIT` = 2000.00 |
| `ZERO_ALLOWED` | 允许零预交金入院，但需医务科审批 | 审批单号记入 `approval_id` |
| `BY_DEPT` | 按科室配置不同金额 | `m05_ward_config.min_deposit` |

**为什么需要「零预交金」例外：** 现实中有三类患者必须先入院再交钱——①紧急情况（急诊直收，患者昏迷/大出血）②民政救助对象（先救治后由民政结算）③单位记账客户（事后统一结）。

**预交金与住院单的关系：**

```
住院单.deposit_total   ← 从 M16 事件同步（m16.inpatient.deposit.created）
住院单.deposit_used    ← 从 M16 charge 事件同步
住院单.balance         ← deposit_total − deposit_used（不落库，实时查 M16 C-02）
```

**关键约束：M05 不算预交金余额，只显示 M16 给的数。** 因为余额计算涉及冻结预交金、冲销、中途结算，只有 M16 知道。M05 若自己算，必然与 M16 对不上。

### 3.5 入院途径与入院病情

**入院途径（`admission_way`，病案首页必填）：**

| 代码 | 名称 | 说明 |
|---|---|---|
| `OUTPATIENT` | 门诊 | 最常见（眼科 90%+） |
| `EMERGENCY` | 急诊 | 眼外伤、急性青光眼 |
| `TRANSFER` | 转院 | 其他医院转入 |
| `OTHER` | 其他 | — |

**入院病情（`patient_condition`，病案首页必填）：**

| 代码 | 名称 | 眼科典型场景 |
|---|---|---|
| `CRITICAL` | 危 | 眼化学伤、眼球穿通伤 |
| `URGENT` | 急 | 急性闭角型青光眼发作、视网膜中央动脉阻塞 |
| `GENERAL` | 一般 | 白内障、翼状胬肉、斜视等择期手术 |

**这两项决定病案首页的「入院情况」字段，也影响 DRG 入组。**

### 3.6 双眼分期手术模型

**眼科特有：同一患者的双眼手术通常分两次住院完成。**

典型方案：白内障患者右眼先做（住院 1~2 天），出院后 1~4 周再做左眼。

| 字段 | 说明 |
|---|---|
| `eye_side` | OD/OS/OU/NA |
| `surgery_plan_sequence` | 第几期（1 = 第 1 次住院，2 = 第 2 次），非手术患者为 NULL |
| `related_admission_id` | 关联的对侧住院号（保证双眼记录能串起来） |

**出院办理时的检查：** 若 `surgery_plan_sequence = 1` 且 `eye_side = 'OD'`（或 OS），M05-05 出院时生成「待二期入院」提醒，并把建议日期与术式写入待办。

**为什么必须建模：** ①医保对双眼分期手术有专门的审核要求（不能同一次住院做完双眼，否则按一次收费）②患者随访需要知道「双眼是否都完成」③晶体度数换算需知道对侧眼参数。

### 3.7 入院登记流程（八步）

```
① 扫描/输入患者信息
   ├─ 扫住院证条码 → 带出申请单
   ├─ 输住院号 / 门诊卡号 / 身份证号 → 查患者
   └─ 无申请单 → 走「直收入院」（需医务科权限）
        │
② 核身份（与患者本人核对）
   ├─ 姓名、性别、年龄
   ├─ 证件号后 4 位
   └─ 与 M03 患者主索引比对，不一致报 "0503001"
        │
③ 选择入院途径、入院病情
   └─ 从申请单带出，可改（改入院途径需理由）
        │
④ 选择责任科室、责任医生、病区（可选）
   └─ 病区不选则不预占床，由 M05-02 分床时决定
        │
⑤ 收取预交金
   ├─ 调 M16-03 C-01 收预交金（默认 MIN_DEPOSIT）
   └─ 零预交金 → 需医务科审批单号
        │
⑥ 生成住院号
   └─ ZY + YYYYMMDD + 4 位
        │
⑦ 打印腕带 / 住院证
   └─ 腕带条码：patient_id|admission_no|identity_hash
        │
⑧ 提交登记 → 状态 REGISTERED
   ├─ 发 m05.admission.created 事件
   ├─ 申请单置 REGISTERED
   └─ 进入 M05-02 待分床队列
```

**为什么第 ⑤ 步（收费）在第 ⑥ 步（生成住院号）之前：** 因为 M16-03 的预交金接口需要 `admission_id` 与 `admission_no` 作为参数。**实际实现时采用「先生成住院号、后收费」的顺序**，若收费失败则把住院单置 `CANCELLED` 并释放住院号。这样既满足 M16 接口要求，又不留悬挂记录。

### 3.9 住院主档与各模块的数据同步

| 数据 | 方向 | 触发 | 方式 |
|---|---|---|---|
| 患者基本信息 | M03 → M05 | 登记时 | 同步调用 |
| 患者信息变更 | M03 → M05 | 患者改信息 | 订阅 `mpi.patient.updated`，只更新未出院患者的快照 |
| 预交金余额 | M16 → M05 | 充值/记账 | 订阅 `m16.inpatient.deposit.created` |
| 费用总额 | M16 → M05 | 记账 | 订阅 `m16.inpatient.charge.created` |
| 结算完成 | M16 → M05 | 结算 | 回调 `POST /internal/v1/m05/admission/on-settled` |
| 床位信息 | M05-02 → M05-01 | 分床/转床 | 同模块内更新 |
| 住院主档 | M05 → M08/M14/M16 | 查询 | 内部契约 P-01~P-06 |

### 3.10 患者信息合并的重定向

M03-02 发现两个患者是同一个人时合并。M05 必须处理：

| 场景 | 处理 |
|---|---|
| 合并后患者还有在院记录 | 住院单 `patient_id` 改为合并后的主 ID，`merge_from_patient_id` 记录原 ID |
| 合并时两个患者都有在院记录 | **拒绝合并**，提示「双方均有在院记录，请先出院或作废」 |
| 合并后历史住院记录 | 批量重定向 `patient_id`，保留 `merge_from_patient_id` |

订阅事件：`mpi.patient.merged`

class AdmissionRequestService:

    async def create_direct(self, body, user) -> Dict[str, Any]:
        """直收入院：无门诊接诊记录，住院处直接创建申请单。"""
        if not body.direct_reason or len(body.direct_reason.strip()) < 10:

        patient = await M03Client.get_patient_brief(body.patient_id)

        request_no = await self._next_request_no()

            create_type="DIRECT",
            direct_reason=body.direct_reason,
            created_by=user.employee_id,
        )
        self.db.add(req)
        await self.db.flush()

        await self._log(
            request_id=req.id,
            action="CREATE_DIRECT",
            operator_id=user.employee_id,
            detail={"reason": body.direct_reason},
        )
        await self.db.commit()
        return {"request_id": req.id, "request_no": request_no}

    async def cancel(self, request_id: int, body, user) -> Dict[str, Any]:
        """作废入院申请。"""
        req = await self.db.get(M05AdmissionRequest, request_id)
        if not req:
            raise BizException("0501034", "未找到匹配的入院申请")
        if req.status not in ("DRAFT", "PENDING"):
            raise BizException("0501006", "申请单状态不允许此操作")

        if not body.reason_code:
            raise BizException("0501023", "作废原因未选择")
        if not body.reason_detail or len(body.reason_detail.strip()) < 10:
            raise BizException("0501007", "作废原因不足 10 字")

        old_status = req.status
        req.status = "CANCELLED"

        req.cancel_reason = body.reason_detail

class AdmissionService:
    """入院登记与住院主档服务。"""

    def __init__(self, db: AsyncSession):
        self.db = db

    # ==================== 入院登记 ====================

    async def create(self, body, user, request=None) -> Dict[str, Any]:
        """入院登记核心流程。

        步骤：
         1. 患者校验
         2. 重复在院校验
         3. 身份核验校验
         4. 科室与医生校验
         5. 眼别与手术分期校验
         6. 生成住院号
         7. 创建住院单
         8. 调 M16-03 收预交金
         9. 更新申请单
        10. 发事件
        """
        # ① 患者校验
        patient = await M03Client.get_patient_brief(body.patient_id)
        if not patient:
            raise BizException("0501009", "患者服务不可用")

        # ② 重复在院校验（同一患者只能有一个未结束的住院单）
        existing = await self._find_active(body.patient_id)
        if existing:
            raise BizException(
                "0501013",
                "该患者已有未结束的住院单（%s，%s）"
                % (existing.admission_no, existing.status),
                data={
                    "existing_admission_id": existing.id,
                    "existing_admission_no": existing.admission_no,
                    "existing_status": existing.status,
                },
            )

        # ③ 身份核验
        if not body.identity_verified:
            raise BizException("0501003", "患者身份核验未完成")

        # ④ 科室与医生
        dept = await M01Client.get_dept(body.dept_id)
        if not dept or dept.get("dept_category") not in ("INPATIENT", "BOTH"):
            raise BizException("0501004", "责任科室必须是住院科室")
        doctor = await M01Client.get_staff_brief(body.attending_doctor_id)
        if not doctor or doctor.get("dept_id") != body.dept_id:
            raise BizException("0501005", "责任医生不在该科室或无执业资格")

        # ⑤ 眼别与分期
        if body.surgery_plan and not body.eye_side:
            raise BizException("0501010", "手术患者必须选择眼别")
        if body.surgery_plan and not body.surgery_plan_sequence:
            raise BizException("0501011", "有手术计划时必须填写手术分期")

        # ⑥ 入院时间
        if body.admission_time > datetime.now():
            raise BizException("0501012", "入院时间不能晚于当前时间")

        # ⑦ 预交金门槛
        config = await self._load_config()
        min_deposit = Decimal(str(config.get("M05.ADMISSION.MIN_DEPOSIT", "2000.00")))
        is_zero_deposit = body.deposit is None or body.deposit.amount == 0
        if is_zero_deposit:
            if not config.get("M05.ADMISSION.ZERO_ALLOWED", False):
                raise BizException("0501016", "零预交金入院必须提供审批单号")
            if not body.approval_no:
                raise BizException("0501016", "零预交金入院必须提供审批单号")
        elif body.deposit.amount < min_deposit:
            if not body.approval_no:
                raise BizException("0501014", "预交金低于应收金额需审批")

        # ⑧ 生成住院号
        admission_no = await self._next_admission_no(body.admission_time.date())

        # ⑨ 创建住院单
        adm = M05Admission(
            admission_no=admission_no,
            patient_id=body.patient_id,
            empi_no=patient.get("empi_no"),
            visit_no=body.visit_no,
            patient_name=patient["name"],
            gender=patient.get("gender"),
            age=patient.get("age"),
            birth_date=patient.get("birth_date"),
            id_card_no=patient.get("id_card_no"),
            phone=patient.get("phone"),
            address=patient.get("address"),
            admission_way=body.admission_way,
            patient_condition=body.patient_condition,
            admission_time=body.admission_time,
            admission_dept_id=body.dept_id,
            admission_dept_name=dept.get("name"),
            ward_id=body.ward_id,
            attending_doctor_id=body.attending_doctor_id,
            attending_doctor_name=doctor.get("name"),
            resident_doctor_id=body.resident_doctor_id,
            eye_side=body.eye_side or "NA",
            surgery_plan=body.surgery_plan,
            surgery_plan_sequence=body.surgery_plan_sequence,
            insurance_type=body.insurance_type,
            need_isolation=body.need_isolation,
            need_companion=body.need_companion,
            status="REGISTERED",
            request_id=body.request_id,
            approval_no=body.approval_no,
            remark=body.remark,
            created_by=user.employee_id,
        )
        self.db.add(adm)
        await self.db.flush()

        # ⑩ 收预交金（在同一事务内，失败整体回滚）
        deposit_result = None
        if not is_zero_deposit:
            try:
                deposit_result = await M16Client.create_deposit(
                    admission_id=adm.id,
                    admission_no=admission_no,
                    patient_id=body.patient_id,
                    amount=str(body.deposit.amount),
                    payment_method=body.deposit.payment_method,
                    operator_id=user.employee_id,
                    operator_name=user.name,
                )
                adm.deposit_total = money(body.deposit.amount)
            except Exception as exc:
                await self.db.rollback()
                raise BizException("0501015", "预交金收取失败：%s" % exc)

        # ⑪ 更新申请单
        if body.request_id:
            req = await self.db.get(M05AdmissionRequest, body.request_id)
            if req:
                if req.status != "PENDING":
                    await self.db.rollback()
                    raise BizException("0501035", "该申请单已被其他窗口登记")
                req.status = "REGISTERED"
                req.registered_admission_id = adm.id

        await self._log(
            admission_id=adm.id,
            action="REGISTER",
            operator_id=user.employee_id,
            detail={"admission_no": admission_no, "way": body.admission_way},
        )
        await self.db.commit()

        return {
            "admission_id": adm.id,
            "admission_no": admission_no,
            "status": "REGISTERED",
            "status_text": "已登记待分床",
            "deposit": deposit_result,
            "next_step": "WAIT_BED",
        }

    async def cancel(self, admission_id: int, body, user) -> Dict[str, Any]:
        """作废住院单（仅 REGISTERED 状态可作废）。"""
        adm = await self._get(admission_id)
        if adm.status != "REGISTERED":
            raise BizException("0501024", "已登记的住院单不能作废")

        if not body.reason_detail or len(body.reason_detail.strip()) < 10:
            raise BizException("0501007", "作废原因不足 10 字")

        old_status = adm.status
        adm.status = "CANCELLED"
        adm.cancel_reason = body.reason_detail
        adm.cancelled_by = user.employee_id
        adm.cancelled_at = datetime.now()

        # 退预交金
        if adm.deposit_total and adm.deposit_total > 0:
            try:
                await M16Client.refund_deposit(
                    admission_id=admission_id,
                    amount=str(adm.deposit_total),
                    reason="入院单作废",
                    operator_id=user.employee_id,
                )
            except Exception as exc:
                await self.db.rollback()
                raise BizException("0501025", "退预交金失败：%s" % exc)

        await self._log(
            admission_id=admission_id,
            action="CANCEL",
            operator_id=user.employee_id,
            detail={"old_status": old_status, "reason": body.reason_detail},
        )
        await self.db.commit()
        return {"admission_id": admission_id, "status": "CANCELLED"}

    # ==================== 预交金 ====================

    async def create_deposit(self, admission_id: int, body, user) -> Dict[str, Any]:
        """收预交金（转调 M16-03 C-01）。"""
        adm = await self._get(admission_id)
        if adm.status in ("SETTLED", "DISCHARGED_OWED"):
            raise BizException("0501032", "该住院单状态不允许修改")

        if body.amount <= 0:
            raise BizException("0501017", "预交金金额必须大于 0")

        config = await self._load_config()
        max_single = Decimal(str(config.get("M05.ADMISSION.MAX_SINGLE_DEPOSIT", "50000")))
        max_total = Decimal(str(config.get("M05.ADMISSION.MAX_TOTAL_DEPOSIT", "200000")))
        if body.amount > max_single:
            raise BizException("0501018", "单笔预交金超出上限")
        if money(adm.deposit_total) + body.amount > max_total:
            raise BizException("0501019", "累计预交金超出上限")

        result = await M16Client.create_deposit(
            admission_id=admission_id,
            admission_no=adm.admission_no,
            patient_id=adm.patient_id,
            amount=str(body.amount),
            payment_method=body.payment_method,
            operator_id=user.employee_id,
            operator_name=user.name,
        )
        adm.deposit_total = money(adm.deposit_total) + body.amount
        await self._log(
            admission_id=admission_id,
            action="DEPOSIT",
            operator_id=user.employee_id,
            detail={"amount": str(body.amount), "method": body.payment_method},
        )
        await self.db.commit()
        return result

    async def get_deposit(self, admission_id: int, user) -> Dict[str, Any]:
        """查预交金（余额计算交给 M16-03）。"""
        adm = await self._get(admission_id)
        try:
            balance = await M16Client.get_deposit_balance(admission_id)
        except Exception:
            balance = {"available_balance": None, "degraded": True}
        return {
            "admission_id": admission_id,
            "admission_no": adm.admission_no,
            "deposit_total": float(money(adm.deposit_total)),
            "account": balance,
        }

    async def refund_deposit(self, admission_id: int, body, user) -> Dict[str, Any]:
        """退预交金。"""
        adm = await self._get(admission_id)
        config = await self._load_config()
        threshold = Decimal(str(config.get("M05.ADMISSION.REFUND_APPROVE_LIMIT", "5000")))
        if body.amount > threshold and not body.approval_no:

            action="DEPOSIT_REFUND",
            operator_id=user.employee_id,

            operator_id=0,

                "settle_type": settle_type,

    async def _get(self, admission_id: int) -> M05Admission:

        """查找患者未结束的住院单。"""
        row = await self.db.execute(
            select(M05Admission).where(
                M05Admission.patient_id == patient_id,
                M05Admission.status.in_(
                    ("DRAFT", "PENDING", "REGISTERED", "IN_HOSPITAL", "DISCHARGING",
                     "DISCHARGED", "DISCHARGED_OWED", "PENDING_BED")
                ),
                M05Admission.is_deleted == False,  # noqa: E712
            )
        )
        return row.scalar_one_or_none()

    async def _next_admission_no(self, d: date) -> str:
        """生成住院号 ZY + YYYYMMDD + 4 位。"""
        key = "m05:admission:seq:%s" % d.strftime("%Y%m%d")
        seq = await redis_client.incr(key)
        await redis_client.expire(key, 172800)
        if seq > 9999:
            raise BizException("0501008", "住院号生成失败请重试")
        admission_no = "ZY%s%04d" % (d.strftime("%Y%m%d"), seq)
        # DB 唯一索引兜底：若冲突则抛 0501008
        return admission_no

    async def _load_config(self) -> Dict[str, Any]:
        """加载参数（Redis 缓存 600 秒）。"""
        cached = await redis_client.hgetall("m05:admission:config")
        if cached:
            return {k: self._parse(v) for k, v in cached.items()}

        rows = await self.db.execute(
            select(M05AdmissionConfig).where(
                M05AdmissionConfig.is_deleted == False  # noqa: E712
            )
        )
        config = {}
        for c in rows.scalars():
            config[c.param_code] = c.param_value
            await redis_client.hset(
                "m05:admission:config", c.param_code, c.param_value
            )
        await redis_client.expire("m05:admission:config", 600)
        return {k: self._parse(v) for k, v in config.items()}

    @staticmethod
    def _parse(value: Any) -> Any:
        """参数值解析（字符串转 bool / Decimal / int）。"""
        if isinstance(value, bool):
            return value
        if isinstance(value, str):
            low = value.lower()
            if low in ("true", "1"):
                return True
            if low in ("false", "0"):
                return False
        return value

    @staticmethod
    def _stay_days(adm: M05Admission) -> int:
        """计算已住天数（按自然日）。"""
        if not adm.admission_time:
            return 0
        end = adm.discharge_time or datetime.now()
        return max(1, (end.date() - adm.admission_time.date()).days + 1)

                biz_type="ADMISSION",
                biz_id=admission_id,
                action=action,
                operator_id=operator_id,
                detail_json=detail,
            )
        )

### 6.7 专题：住院号生成的并发与唯一性

**问题：** 两台登记窗口在同一秒点击「登记」，Redis `INCR` 返回 1 和 2，不会冲突。但若 Redis 重启丢数据、或网络分区导致本地缓存计数，可能出现重复。

**三层防护：**

| 层级 | 机制 | 覆盖场景 |
|---|---|---|
| ① Redis INCR | 原子自增，日粒度键 + 48h 过期 | 正常并发 |
| ② DB 唯一索引 | `uk_m05_admission_no` | Redis 异常后重建 |
| ③ 冲突重试 | 捕获 `IntegrityError` → 重新取号（最多 3 次） | 极端情况 |

**为什么不用数据库序列：** 序列跨日不重置，会得到 `ZY20261028047382` 这种不可读的号；且序列无法按日统计。

**为什么不用日期+时间戳：** `ZY20261028092015123` 太长，患者念不出来，护士核对时容易错。

**实测性能：** Redis INCR 约 0.2ms，DB 唯一索引校验约 0.5ms，合计 <1ms，对 90 秒的登记耗时无影响。

### 9.4 脱敏

| 字段 | 列表页 | 详情页 | 导出 |
|---|---|---|---|
| 身份证号 | `1101**********1234` | `1101**********1234` | 完整 |
| 手机号 | `138****5678` | `138****5678` | 完整 |
| 住址 | 不显示 | 完整 | 完整 |
| 诊断 | 完整 | 完整 | 完整 |

**导出为什么完整：** 导出是受控操作（需 `m05:admission:export` 权限 + 审计留痕），脱敏会让导出数据失去业务价值（如给医保的报表）。控制方式改为「谁能导出 + 导出必留痕」。

### 9.5 安全措施

| 措施 | 说明 |
|---|---|
| 身份核验强制 | 不勾选不可提交，防止登记错人 |
| 住院号唯一索引 | 数据库层保证不重复 |
| 预交金同事务 | M16 收费失败则住院单回滚，不留悬挂记录 |
| 作废留痕 | 作废原因、操作人、时间全部记录且不可改 |
| 审计日志 | 所有写操作记录到 `m05_admission_log`（只增触发器） |
| 并发控制 | 申请单登记锁 `m05:admission:lock:{request_id}` TTL 30s |
| 敏感字段脱敏 | 见 9.4 |
| IP 限制 | 入院登记仅允许院内网段（通过 M02-07 `check-ip`） |
