**设计说明：**

1. **不建物理外键**：与 M05-01/M05-02/M05-03 保持一致。理由 —— ①归档主表创建时会同时插入 15 条检查明细与若干缺陷，外键每行都要查 `m05_archive`，批量插入开销明显 ②`m05_archive` 可能因「撤销归档 + 重新归档」被多次更新，与明细的引用关系由应用层事务保证 ③建表顺序解耦。
2. **`m05_archive.admission_id` 唯一（非部分索引）**：一个住院单只能有一条归档单。撤销归档时**复用同一条记录**（`status` 回 `REOPENED`，`archive_batch_seq` 递增），不新建记录 —— 否则「某住院单有几份归档记录」会随时间膨胀，且「最后一份有效」要靠 `archived_at` 排序推断。
3. **`m05_archive_check` 是「一次检查一批」**：`check_batch_no` 区分检查批次，同一归档单可有多次检查（初始检查 + 整改后复检）。旧批次的明细保留，因为「第一次检查发现了什么」本身是质控数据。
4. **`m05_archive_defect` 与 `m05_archive_check` 无强关联**：缺陷是「需要人处理的动作」，检查明细是「判定结果」。一条检查明细可以生成 0 或 1 条缺陷；缺陷可以跨批次存续（第一次检查发现，第二次检查仍缺）。因此缺陷表冗余 `item_code` / `item_name`，不引用 `check.id`。
5. **`m05_archive_log` 按 `operated_at` 月度分区**：日志只增，15 年约 30 万行，分区后历史归档与清理更方便。
6. **`m05_archive_seal` 与归档主表 1:N**：同一份病历可能被多次封存（第一次纠纷解决解封，第二次又有新纠纷再封），因此是 1:N 关系，`status='SEALED'` 的记录最多一条（部分唯一索引保证）。

**约束说明：**

```sql
-- 归档单号格式
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_no
    CHECK (archive_no ~ '^ARC[0-9]{12}$');

-- 状态枚举（10 态）
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_status
    CHECK (status IN ('PENDING', 'CHECKING', 'DEFECT', 'READY',
                      'ARCHIVED', 'REOPENED', 'SEALED', 'UNSEALED',
                      'CANCELLED', 'FAILED'));

-- 离院方式枚举
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_discharge_type
    CHECK (discharge_type IN ('NORMAL', 'TRANSFER',
                              'AGAINST_ADVICE', 'DECEASED'));

-- 出院小结状态枚举
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_summary_status
    CHECK (summary_status IN ('SIGNED', 'DRAFT', 'MISSING', 'EXEMPT'));

-- 转院/自动离院/死亡可豁免出院小结
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_summary_exempt
    CHECK (summary_status <> 'EXEMPT'
           OR discharge_type IN ('TRANSFER', 'AGAINST_ADVICE', 'DECEASED'));

-- 已归档必须有批次号与归档时刻
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_archived
    CHECK (status NOT IN ('ARCHIVED', 'SEALED')
           OR (archive_batch_no IS NOT NULL
               AND archived_at IS NOT NULL
               AND archived_by IS NOT NULL));

-- 已归档不能有未整改缺陷
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_archived_no_missing
    CHECK (status NOT IN ('ARCHIVED', 'SEALED') OR COALESCE(missing_count, 0) = 0);

-- 检查计数非负
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_counts
    CHECK (present_count >= 0 AND missing_count >= 0
           AND unknown_count >= 0 AND exempt_count >= 0
           AND document_count >= 0);

-- UNKNOWN 豁免完整性
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_unknown_waive
    CHECK (unknown_waived = FALSE
           OR (unknown_waive_reason IS NOT NULL
               AND char_length(btrim(unknown_waive_reason)) >= 10
               AND unknown_waive_by IS NOT NULL
               AND unknown_waive_at IS NOT NULL));

-- 质控豁免完整性
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_quality_waive
    CHECK (quality_waived = FALSE
           OR (quality_waive_reason IS NOT NULL
               AND char_length(btrim(quality_waive_reason)) >= 20
               AND quality_waive_by IS NOT NULL));

-- 撤销归档完整性
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_reopen
    CHECK (status <> 'REOPENED'
           OR (reopen_reason IS NOT NULL
               AND char_length(btrim(reopen_reason)) >= 20
               AND reopened_at IS NOT NULL
               AND reopened_by IS NOT NULL));

-- 封存必须有前置状态
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_sealed
    CHECK (status <> 'SEALED' OR pre_seal_status IS NOT NULL);

-- 批次号格式
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_batch_no
    CHECK (archive_batch_no IS NULL
           OR archive_batch_no ~ '^BA[0-9]{8}-[0-9]{3}$');

-- 批次序号范围
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_batch_seq
    CHECK (archive_batch_seq >= 1 AND archive_batch_seq <= 99);

-- 提交重试次数范围
ALTER TABLE m05_archive ADD CONSTRAINT ck_m05_archive_submit_retry
    CHECK (submit_retry >= 0 AND submit_retry <= 10);

-- 唯一索引（不用 nulls distinct）
CREATE UNIQUE INDEX uk_m05_archive_no ON m05_archive (archive_no)
    WHERE is_deleted = FALSE;
CREATE UNIQUE INDEX uk_m05_archive_admission ON m05_archive (admission_id)
    WHERE is_deleted = FALSE;

COMMENT ON TABLE m05_archive IS '病历归档主表：一住院单一条，撤销归档复用原记录';
COMMENT ON COLUMN m05_archive.admission_id IS '住院单 ID，唯一；撤销归档复用此记录不新建';
COMMENT ON COLUMN m05_archive.archive_batch_no IS '归档批次号，撤销后重新归档序号递增';
COMMENT ON COLUMN m05_archive.pre_seal_status IS '封存前状态，解除封存时回退到此状态';
COMMENT ON COLUMN m05_archive.summary_status IS '出院小结状态，EXEMPT 仅限转院/自动离院/死亡';
```

**状态机：**

```
             ┌──────────┐
             │ PENDING  │ ── 创建（出院登记触发）
             └────┬─────┘
                  │ run_check
                  ▼
             ┌──────────┐
             │ CHECKING │
             └────┬─────┘
        missing>0 │ │ missing=0 且 unknown=0
                  ▼ ▼
        ┌────────────┐   ┌──────────┐
        │  DEFECT    │──►│  READY   │
        └────┬───────┘   └────┬─────┘
             │ 整改完成重检     │ submit
             │                ▼
             │          ┌────────────┐
             │          │ ARCHIVED   │
             │          └──┬──────┬──┘
             │             │      │ seal
             │      reopen │      ▼
             │             │  ┌──────────┐
             │             │  │ SEALED   │
             │             │  └────┬─────┘
             │             │       │ unseal
             │             │       ▼
             │             │  ┌──────────┐
             │             │  │ UNSEALED │ → 回 pre_seal_status
             │             │  └──────────┘
             │             ▼
             │       ┌────────────┐
             └──────►│  REOPENED  │ ── rearchive → ARCHIVED
                     └────────────┘

  旁支：PENDING → CANCELLED（误创建）
        CHECKING → FAILED（依赖全挂）→ CHECKING
        submit 失败 5 次 → FAILED
```

**设计要点：**

1. **`admission_id` 唯一而非「一次归档一条」**：撤销后复用同一条，`archive_batch_seq` 递增。这样「某住院单的病历归档状态」永远是一行，查询简单，且历史批次可通过 `m05_archive_log` 追。
2. **`summary_status` 与 `discharge_type` 联动**：转院/自动离院/死亡的患者无法要求医生当日写小结，故允许 `EXEMPT`。DB 约束 `ck_m05_archive_summary_exempt` 保证只有这三位才可豁免，防止「普通出院也走豁免」。
3. **`ck_m05_archive_archived_no_missing`**：已归档状态下 `missing_count` 必须为 0。这是「归档的病历一定是完整的」的数据库级保证。若撤销后补正再归档，`missing_count` 已在复检时归零。
4. **三个豁免字段组（`unknown_waive_*` / `quality_waive_*` / `reopen_*`）各自完整**：DB 约束保证「有标记必须有人、有原因、有时间」，避免「系统自动放行」这种无从追责的状态。
5. **`pre_seal_status` 存封存前状态**：解除封存时回到封存前的状态（可能是 `ARCHIVED`、`REOPENED`）。不存就无法回退。
6. **`m18_archive_id` 存 M18 返回的病案库 ID**：撤销归档时要用它调 M18 释放。
7. **`is_fast_track` + `priority`**：日间手术患者当天出院当天回家，必须走同步路径。`priority=100` 让工作台排序时排在最前。
8. **不分区**：15 年约 22 万行（与住院单数一致），单表完全可承受。若按 `discharged_at` 年度分区，`uk_m05_archive_admission` 必须含分区键，「一住院单一归档单」的唯一性会退化为「同年唯一」，跨年出院再归档（极端情形）可重复。

4. **`ck_m05_archive_check_missing` 要求责任角色**：MISSING 项必须能定位到责任角色，否则无法催办。
5. **不存 `archive_batch_no`**：检查明细与归档批次无关，检查发生在归档之前。

2. **`uk_m05_archive_defect_key` 只约束未关闭**：同一缺陷项可能被整改后关闭，之后又因复检不合格重新打开 —— 应该复用原记录（`status` 回 `PENDING`）还是新建？本设计选择**新建**，因为「第一次整改了吗、谁整改的、为什么复检还是不合格」需要完整历史。所以唯一索引带 `status <> 'CLOSED'` 条件，保证同时只有一条在办。
3. **`responsible_dept_id` / `responsible_id` 默认 0**：`ANESTHESIA` 角色的责任人可能是科室而非具体某位麻醉医生（值班轮转），此时 `responsible_id=0`。
4. **`deadline_at` 由应用层按角色类型计算**：医生 4h、住院处 2h、麻醉科 4h、护士 4h、编码员 8h。不写成 DB 生成列，因为时限是配置项（`M05.ARCHIVE.ESCALATE_*`）。
5. **`escalated_to` 只存最高级别**：多次升级时只保留最高级别（如 4h 升科主任，12h 升医务科，`escalated_to` 最终为 `MEDICAL_AFFAIRS`），完整升级历史在 `m05_archive_log`。

**约束说明：**

```sql
-- 封存单号格式
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_seal_no
    CHECK (seal_no ~ '^FS[0-9]{12}$');

-- 封存原因枚举
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_seal_reason
    CHECK (seal_reason IN ('MEDICAL_DISPUTE', 'COURT',
                           'COMPLAINT', 'INSURANCE', 'OTHER'));

-- 状态枚举
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_seal_status
    CHECK (status IN ('SEALED', 'UNSEALED'));

-- 封存原因说明 ≥20 字
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_seal_desc
    CHECK (char_length(btrim(seal_desc)) >= 20);

-- 解除封存必须有完整信息（双签 + 说明 ≥20 字）
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_unseal
    CHECK (status <> 'UNSEALED'
           OR (unsealed_at IS NOT NULL
               AND unsealed_by IS NOT NULL
               AND unseal_note IS NOT NULL
               AND char_length(btrim(unseal_note)) >= 20
               AND medical_affairs_signer IS NOT NULL
               AND director_signer IS NOT NULL
               AND medical_affairs_signer <> director_signer));

-- 到期时刻必须晚于封存时刻
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_seal_until
    CHECK (seal_until IS NULL OR seal_until > sealed_at);

-- 解除时刻必须晚于封存时刻
ALTER TABLE m05_archive_seal ADD CONSTRAINT ck_m05_archive_unseal_at
    CHECK (unsealed_at IS NULL OR unsealed_at > sealed_at);

-- 同归档同时只允许一条在封
CREATE UNIQUE INDEX uk_m05_archive_seal_active
    ON m05_archive_seal (archive_id)
    WHERE status = 'SEALED';

COMMENT ON TABLE m05_archive_seal IS '病历封存表：纠纷/司法场景下病历强制只读的留痕记录';
COMMENT ON COLUMN m05_archive_seal.seal_desc IS '封存原因说明，≥20 字';
COMMENT ON COLUMN m05_archive_seal.medical_affairs_signer IS '解除封存需医务科与病案室主任双签，两人不能相同';
```

**设计要点：**

1. **`uk_m05_archive_seal_active` 部分唯一索引**：同一份病历同时只能处于一个封存状态。多次封存（解封后再封）会产生多条记录，但 `status='SEALED'` 的只有一条。
2. **`ck_m05_archive_unseal` 要求双签且两人不同**：解除封存是削弱证据保全的动作，必须两个岗位同时确认。DB 约束 `medical_affairs_signer <> director_signer` 防止同一人代签。
3. **`seal_until` 允许为 NULL**：多数封存无限期（纠纷解决才解封），少数有明确期限（如法院调取 30 天）。有值的走定时任务自动解封，但解封时仍要求填 `unseal_note` 与双签 —— 因为「到期自动解封」也需要留痕。
4. **`m18_synced` 记录同步状态**：M18 是病历实际存储方，若同步失败需要补偿。字段设为 `FALSE` 时可被 `seal_sync_retry_task` 扫描重试。
5. **不设 `is_deleted`**：封存记录是法律证据，永不可删。

**量级估算：**

| 项目 | 数值 |
|---|---|
| 年归档单数 | 14,600 |
| 年封存数 | 约 15 次（纠纷率约 0.1%） |
| 年行数 | 15 |
| 单行大小 | 约 520 字节 |
| 年数据量 | 约 8 KB |
| 保留期 | 永久 |
| 10 年行数 | 约 150 行 |
| 10 年数据量 | 约 78 KB（含索引约 150 KB） |

**分区：** 不分区（行数极少）。

### E.3 分区建表 SQL

```sql
-- m05_archive_log 月分区
CREATE TABLE m05_archive_log (
    id               BIGINT GENERATED BY DEFAULT AS IDENTITY,
    archive_id       BIGINT       NOT NULL,
    admission_no     VARCHAR(20)  NOT NULL,
    action           VARCHAR(24)  NOT NULL,
    from_status      VARCHAR(16),
    to_status        VARCHAR(16),
    message          VARCHAR(500),
    operated_by      BIGINT       NOT NULL DEFAULT 0,
    operated_by_name VARCHAR(64),
    trace_id         VARCHAR(64),
    operated_at      TIMESTAMP    NOT NULL DEFAULT NOW(),
    PRIMARY KEY (id, operated_at)
) PARTITION BY RANGE (operated_at);

DO $$
DECLARE
    i INT;
    p_start DATE;
    p_end   DATE;
    p_name  TEXT;
BEGIN
    FOR i IN 0..35 LOOP
        p_start := (DATE '2026-10-01' + (i || ' months')::interval)::date;
        p_end   := (DATE '2026-10-01' + ((i + 1) || ' months')::interval)::date;
        p_name  := 'm05_archive_log_p' || to_char(p_start, 'YYYYMM');
        EXECUTE format(
            'CREATE TABLE %I PARTITION OF m05_archive_log '
            'FOR VALUES FROM (%L) TO (%L)',
            p_name, p_start, p_end
        );
    END LOOP;
END $$;
```
