## 1. 模块概述

### 1.1 模块定位

M13-05 是检验域的**规则中心**。它回答三个问题：

1. 这个检验项目在本院**意味着什么**（本地扩展属性、标本要求、外送标记）
2. 这个数值在**什么范围内算正常**（参考区间，按性别、年龄、生理状态分层）
3. 这个数值**到什么程度算危急**（危急阈值，触发通知闭环）

```

│                      M13-05 的位置与作用                              │
```

**一句话定位：** M13-05 是"这个数值正不正常、要不要报警"这条判断链路上的唯一规则来源，其余四个子模块全部只读它。

### 1.2 为什么独立成子模块

**理由一：参考区间不是常量，而是"随时间、随人群变化的多版本规则"。**

一个具体的场景：

- 2026 年 11 月，检验科换了一台新的生化分析仪（Beckman AU5800 → AU6800）
- 新仪器的血钾参考区间从 `3.5~5.5 mmol/L` 变成 `3.4~5.3 mmol/L`
- 2026 年 11 月 15 日起生效
- 2026 年 11 月前的历史报告必须继续按旧区间标红/标蓝
- 2026 年 11 月 15 日当天的报告，上午做的按旧区间，下午做的按新区间

如果区间只是 `md_lab_item.ref_range_text` 一个字符串字段，改一次会把历史报告全部变成"按新区间判定"的样子——医生回看老报告时会看到标红的值实际在当时的区间内，质疑系统可靠性。

M13-05 的方案是**三段式版本化区间**：`valid_from` / `valid_to` / `is_current`。查询时按"检验执行时刻"匹配区间版本，历史判定永远可复现。

**理由二：分层规则的数量级远超主数据字段能承载的能力。**

一个项目需要多少条参考区间？

| 分层维度 | 取值数 | 示例 |
|---|---|---|
| 性别 | 3（男/女/未知） | 血红蛋白男 130~175、女 115~150 |
| 年龄段 | 4~6（新生儿/儿童/成人/老年/妊娠） | 碱性磷酸酶儿童 100~400、成人 40~150 |
| 生理状态 | 2~3（妊娠期/月经期/正常） | 妊娠期 D-二聚体上限升高 |
| 仪器/方法学 | 1~3 | 不同分析仪的校准差异 |
| 合计 | **最多 3×6×3×3 ≈ 160 条** | 实际单项目常见 2~12 条 |

血常规 24 项 × 平均 6 条 = 144 条区间。生化 40 项 × 平均 8 条 = 320 条。合计近 500 条参考区间，加上版本化（每 2 年迭代一次）就是 1500 条。**这是业务数据表，不是主数据字段。**

**理由三：危急阈值是医疗安全红线，必须有独立的授权、变更、审计链路。**

危急阈值决定"什么数值触发 15 分钟必须确认的闭环"。它和普通主数据字段的风险等级完全不同：

- 把血钾危急下限从 3.0 改成 2.5 → 患者血钾 2.8 时系统不再报警 → 患者可能心搏骤停
- 把血红蛋白危急下限从 60 改成 50 → 重度贫血患者不再触发绿色通道 → 延误输血

所以阈值变更必须：独立权限（不是普通主数据维护权限）、双人复核（改了要复核，不是自己改自己批）、生效时间可控（不能立刻生效，给临床一个缓冲）、全程审计（谁改的、改前是什么、为什么改）。

**理由四：报告格式模板是"解析配置"与"展示配置"的交汇点，需要一个统一的管理入口。**

M13-03 的 OCR 解析模板管"怎么从 PDF 里抽数字"，M13-05 的报告格式模板管"这个项目在医生端的展示形态"：

- 血常规血钾是数值型（带单位、参考区间、高低标记）
- 尿常规白细胞是定性型（阴性/+/++/+++，没有参考区间，只有正常/异常）
- 凝血 PT 是数值型但需要显示 INR 比值
- 血气分析是数值型 + 分组显示

这些"展示形态"必须和"判定规则"绑定在一起，否则会出现"系统说是危急值但医生看不到红色"的割裂。

### 1.3 与相邻子模块分工

| 能力 | M01-09 临床主数据 | **M13-05（本子模块）** | M13-03 解析 | M13-04 审核 |
|---|---|---|---|---|
| 检验项目编码/名称 | ✅ 唯一真相源 | ❌ 只同步 | 读 | 读 |
| LOINC 编码、标本类型 | ✅ 定义 | ❌ 只同步 | 读 | 读 |
| 项目是否启用 | ✅ 定义 | ❌ 只同步 | 读 | 读 |
| **本地收费关联** | ❌ | ✅ 维护 | ❌ | ❌ |
| **本地报告格式** | ❌ | ✅ 维护 | 读 | 读 |
| **版本化参考区间** | ⚠️ 仅通用一条 | ✅ **完整分层规则** | 读 | 读 |
| **危急阈值** | ⚠️ 仅通用一条 | ✅ **完整规则 + 变更审批** | 初判时读 | 判定与闭环 |
| 字段抽取规则（正则） | ❌ | ❌ | ✅ 维护 | ❌ |
| 数值转结构化 | ❌ | ❌ | ✅ 执行 | ❌ |
| 高低标记判定 | ❌ | ❌ | ✅ 执行 | 复核 |
| 危急值通知闭环 | ❌ | ❌ | ❌ | ✅ 执行 |

**边界一句话：** M13-05 管"规则是什么、从什么时候生效、谁批准改的"；M13-03 与 M13-04 管"按规则算出结果"。

**唯一责任原则：**

- M13-05 **不产生**任何业务单据（不是申请、不是报告）
- M13-05 **不判定**任何具体数值（判定是 M13-03/M13-04 的职责）
- M13-05 **只回答规则问题**：这个项目有哪些分层区间、此刻生效的是哪一版、危急阈值是多少

### 1.4 概念辨析

**辨析一：M01-09 的参考区间 vs M13-05 的参考区间**

| 项 | M01-09 `md_lab_reference_range` | M13-05 `m13_ref_range` |
|---|---|---|
| 定位 | 全院通用标准区间（来源：教科书/卫健委标准） | 本院子模块的实际使用区间（来源：仪器说明书 + 本实验室验证） |
| 粒度 | 单项目 1~3 条 | 单项目最多 160 条（性别×年龄×生理状态×仪器） |
| 版本化 | 无（直接覆盖） | **有（valid_from/valid_to/is_current）** |
| 变更流程 | 主数据审批（M01-11） | 检验科主任双人复核 |
| 谁读 | M07-04 医生端展示（参考区间文字） | M13-03 判定、M13-04 复核、M07-04 展示 |

**这不是重复建设，是"国标"与"本地标准"的关系。** 就像药品有国家药典标准，但医院实际用的是本院批准的院内制剂规格——M01 存国家/行业标准值，M13-05 存经本实验室验证的实际使用值。两者并存，M13-05 的规则集始终优先。

**辨析二：参考区间 vs 危急阈值 vs 异常值**

以血钾（K）为例：

```
                3.4      3.5                    5.3     5.5
    ─────────────┼─────────┼──────────────────────┼───────┼──────────►
      低危(报警)  参考下限          正常区间           参考上限   高危(报警)
         ▲                                                        ▲
         └─ 危急低值 3.0（低于此值→CRITICAL_LOW，15 分钟闭环）      │
                                                                   │
                                    └─ 危急高值 6.0（高于此值→CRITICAL_HIGH）
```

- **参考区间**（`3.5~5.3`）：正常的统计范围，超出标 HIGH/LOW，但只是**提示**，不进闭环
- **危急阈值**（低 `<3.0` / 高 `>6.0`）：危及生命的范围，超出触发**15 分钟确认 + 2 小时处置**的强制闭环
- **异常值**：统称，包含 HIGH/LOW 与 CRITICAL_HIGH/CRITICAL_LOW

三者关系：`参考区间 ⊂ 异常值范围`，`危急阈值 ⊂ 极端异常值`。**危急阈值必然在参考区间之外，且与参考区间之间有缓冲区。** 这个缓冲区（3.0~3.5）是"异常但不危急"，医生可以下午处理。

**辨析三：单点参考区间 vs 分层参考区间**

| 类型 | 示例 | 适用项目 |
|---|---|---|
| 单点区间 | 血钾 3.5~5.3（男女通用） | 电解质、肝肾功能的多数项目 |
| 性别分层 | 血红蛋白男 130~175、女 115~150 | 血常规、铁代谢 |
| 年龄分层 | 碱性磷酸酶 1~12 岁 100~400、成人 40~150 | 儿童相关项目 |
| 性别+年龄 | 血红蛋白 1~5 岁 110~160、成人男 130~175 | 血常规 |
| 生理状态 | 妊娠期 D-二聚体上限 500→1000 | 凝血、内分泌 |
| 定性判定 | 尿蛋白 阴性 / 弱阳性 / 阳性 | 尿常规、便常规 |

**判定时的匹配顺序（自上而下，命中即用）：**

```
1. 精确匹配：性别 + 年龄段 + 生理状态 + 仪器 全匹配
2. 降级匹配：性别 + 年龄段 + 生理状态（忽略仪器）
3. 降级匹配：性别 + 年龄段（忽略生理状态与仪器）
4. 降级匹配：性别（忽略年龄与生理状态）
5. 兜底匹配：全 NULL 的通用区间
6. 无匹配：从报告原文抽取区间（ref_source='REPORT'）
7. 仍然无：不标高低（ref_source='NONE'）
```

### 1.5 模块目标

| 目标 | 指标 | 现状（类比实现） |
|---|---|---|
| 区间规则覆盖率 | 已配区间项目 / 已启用项目 ≥ 95% | 约 60% |
| 危急规则覆盖率 | **已配危急阈值项目 / 有临床意义的测量类项目 = 100%** | 约 40% |
| 区间判定准确率 | 与手工核对一致率 100% | — |
| 危急阈值变更 | 全部经双人复核 + 审计 | — |
| 区间版本可追溯 | 任意历史报告可还原当时判定区间 | 不可 |
| 报告格式一致性 | 定义格式与医生端展示形态一致 | — |
| 规则查询性能 | P95 ≤ 10ms（本地缓存命中） | — |

**危急规则覆盖率是硬指标 100%，不是 95%。** 其他项目可以逐步补齐，但危急阈值缺失意味着"这个项目没有安全网"——患者出现了危急值系统不会报警。这条不允许有任何例外。

| D-02 | M01-09 `md_specimen` | 标本类型 | 标本类型显示为空 | 用本地快照 |
| D-03 | M01-09 `md_lab_combo` | 组合项目 | 组合启用项维护不可用 | 用本地快照 |
| D-04 | M01-01 `mdm_department` | 科室 | 科室下拉为空 | 用本地快照 |
| D-05 | M01-06 `md_charge_item` | 收费项目关联 | 无法配置收费关联 | 阻断该项目收费关联配置 |
| D-06 | M01-02 `mdm_employee` | 复核人身份 | 无法复核 | **阻断**（复核必须实名） |
| D-07 | M02-06 审计 | 变更留痕 | 变更不可审计 | **阻断**（法规要求） |
| D-08 | M02-04 权限引擎 | 权限校验 | 无法鉴权 | **阻断** |

**为什么 D-01 是阻断？** 检验项目字典是 M13-05 的唯一数据来源，没有项目就无从谈起"维护规则"。这不是性能问题，是数据不存在问题。

**为什么 D-07 是阻断？** 危急阈值变更如果没有审计留痕，等于"改了没人知道"。这类变更一旦出事（患者因未报警而延误），无法举证。宁可让系统不可用，也不能允许无留痕的变更。

## 3. 业务模型

### 3.1 项目本地扩展模型

M13-05 为 M01-09 的每个检验项目挂一条本地扩展记录 `m13_lab_item_ext`，承载院内特有的属性。

```

│                                                                  │
│  【本院扩展，可维护】                                             │

│    charge_item_code  本地收费项目编码                             │

│    display_order     医生端排序                                   │

│    is_critical_ready 危急阈值是否已配齐                           │
│    is_range_ready    参考区间是否已配齐                           │
│    is_outsourced_local 本次是否走外送                             │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

**为什么 `alias_names` 要做成数组而不是单字段？**

现实中一个血钾有 5 种叫法：

- 医生口头：血钾、钾、K
- 报告原文：钾（K⁺）、Potassium
- 收费项目：血钾测定
- LOINC：2823-3

这些都要能搜到，否则医生在 M07-04 搜"血钾"搜不到。别名数组用 GIN 索引，`WHERE alias_names && ARRAY['血钾']` 就能命中。

**为什么 `is_critical_ready` / `is_range_ready` 两个状态位要落库而不是实时算？**

因为它们是**覆盖率看板**的核心指标，每 5 分钟要统计一次。实时算需要 JOIN 两张子表（`m13_ref_range` 与 `m13_critical_rule`）对每个项目做 `COUNT(*)`，500 个项目就是 500 次子查询，耗时 2~3 秒。

落库后，覆盖率看板一条 SQL：

```sql
SELECT
    COUNT(*) FILTER (WHERE is_enabled) AS total_enabled,
    COUNT(*) FILTER (WHERE is_enabled AND is_range_ready) AS range_ready,
    COUNT(*) FILTER (WHERE is_enabled AND is_critical_ready) AS critical_ready
FROM m13_lab_item_ext
WHERE is_deleted = FALSE;
```

耗时 < 10ms。状态位在区间/阈值增删改时同步维护，每日 03:00 全量重算一次校正偏差。

### 3.2 参考区间版本模型

**核心思想：区间记录不修改，只新增版本。**

```
                               时间轴 ──────────────────────────────────►

  2024-01-01                    2026-11-15                    2027-06-01
      │                             │                             │
      ▼                             ▼                             ▼
┌──────────────────┐  ┌──────────────────────┐  ┌──────────────────────┐
│ 版本 V1          │  │ 版本 V2              │  │ 版本 V3              │
│ 3.5 ~ 5.5        │  │ 3.4 ~ 5.3            │  │ 3.4 ~ 5.3            │
│ valid_from:      │  │ valid_from:          │  │ valid_from:          │
│   2024-01-01     │  │   2026-11-15         │  │   2027-06-01         │
│ valid_to:        │  │ valid_to:            │  │ valid_to: NULL       │
│   2026-11-14     │  │   2027-05-31         │  │ （开放）             │
│ is_current: F    │  │ is_current: F        │  │ is_current: T        │
│ 审核: 张主任     │  │ 审核: 张主任          │  │ 审核: 张主任         │
└──────────────────┘  └──────────────────────┘  └──────────────────────┘

查询逻辑（按检验执行时刻 test_date 匹配）：
  2025-06-01 的报告 → 命中 V1（3.5~5.5）
  2026-12-20 的报告 → 命中 V2（3.4~5.3）
  2027-08-01 的报告 → 命中 V3（3.4~5.3）
```

**为什么不用"有效记录 + 历史表"的双表方案？**

双表方案（当前表 + 历史表）需要：
1. 每次修改：拷贝当前记录到历史表 → 更新当前记录
2. 查询历史：去历史表查
3. 问题：**"当前生效"的定义变得模糊**——如果 11 月 15 日才生效的新版本，10 月就已经录入到当前表，那 10 月 20 日的报告查询时用的是新区间还是旧区间？

单表版本化方案（本设计）用 `valid_from`/`valid_to` 明确表达"这条规则从什么时候到什么时候有效"，查询时一句 `WHERE valid_from <= :test_date AND (valid_to IS NULL OR valid_to >= :test_date)` 就能精确匹配。**生效时间是一等公民，不是一个隐式状态。**

**为什么 `valid_to` 要显式填而不是靠下一条的 `valid_from` 推导？**

假设 V1 是 `2024-01-01 起生效`，V2 是 `2026-11-15 起生效`。

如果靠推导，V1 的 `valid_to` = `2026-11-14`。但如果 V2 录错了、被撤回，V1 的 `valid_to` 就要改回 NULL——又是一个"改历史"的动作。

显式填 `valid_to` 让每条记录自己完整，不受其他记录影响。代价是新建 V2 时要同时更新 V1 的 `valid_to`，但这是一次性的、可校验的（`ck_m13_range_no_overlap` 保证不重叠）。

**区间重叠的防护：**

数据库层用 PostgreSQL 的 `EXCLUDE USING gist` 约束：

```sql
ALTER TABLE m13_ref_range
    ADD CONSTRAINT ex_m13_range_no_overlap
    EXCLUDE USING gist (
        lab_code WITH =,
        COALESCE(gender, '') WITH =,
        age_min WITH =,
        age_max WITH =,
        COALESCE(physiological_state, '') WITH =,
        COALESCE(device_code, '') WITH =,
        daterange(valid_from, valid_to, '[]') WITH &&
    ) WHERE (is_deleted = FALSE);
```

这条约束保证：**同一个"项目+性别+年龄段+生理状态+仪器"组合下，任意两个版本的有效期不重叠。** 这是"任意时刻恰好有一条生效区间"的数学保证。

**不加这条约束会发生什么？** 录入 V2 时忘了改 V1 的 `valid_to`，两版都覆盖 2026-11-15，查询时 `ORDER BY valid_from DESC LIMIT 1` 取到哪个取决于索引扫描顺序——**同一个数值可能今天判正常、明天判异常**。这类 bug 极其难排查。

### 3.3 危急阈值模型

**危急阈值 = 一条规则 = 一个阈值 + 一个级别 + 一组通知要求。**

```
┌────────────────────────────────────────────────────────────────────┐
│                   m13_critical_rule 的结构                          │
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│  lab_code        检验项目        "LAB_K"（血钾）                    │
│  rule_code       规则编码        "LAB_K_LOW"                        │
│  rule_name       规则名称        "血钾危急低值"                      │
│                                                                    │
│  【阈值定义】                                                       │
│  lb_threshold    低限            "3.0"                             │
│  ub_threshold    高限            NULL（只判低）                     │
│  operator        运算符          LT                                │
│  unit            单位            "mmol/L"                          │
│                                                                    │
│  【级别与通知】                                                     │
│  severity        级别            CRITICAL / WARNING                │
│  notify_roles    通知角色        ["DOCTOR", "DEPT_DIRECTOR"]       │
│  notify_channels 通知渠道        ["WEBSOCKET", "INBOX", "SMS"]     │
│  ack_minutes     确认时限        15                                │
│  handle_minutes  处置时限        120                               │
│                                                                    │
│  【适用条件】                                                       │
│  gender          性别            NULL（通用）                       │
│  age_min/max     年龄段          NULL / NULL                       │
│  apply_scope     适用范围        ALL / INPATIENT / OUTPATIENT      │
│                                                                    │
│  【版本控制】                                                       │
│  valid_from      生效开始        2026-01-01                        │
│  valid_to        生效结束        NULL（开放）                       │
│  is_current      是否当前版      TRUE                              │
│  approval_status 审批状态        APPROVED                          │
│  approved_by     审批人          1024（张主任）                     │
│  approved_at     审批时刻        2025-12-20 14:30                  │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

**四种 `operator` 的判定逻辑：**

| operator | 含义 | 判定 | 示例 |
|---|---|---|---|
| `LT` | 低于阈值 | `value < lb_threshold` | 血钾 < 3.0 |
| `GT` | 高于阈值 | `value > ub_threshold` | 白细胞 > 30.0 |
| `BETWEEN` | 阈值之间 | `lb ≤ value ≤ ub` | 少见（中性值报警） |
| `OUTSIDE` | 阈值之外 | `value < lb OR value > ub` | 双向报警合一条规则 |

**为什么 `OUTSIDE` 有时比拆两条好？**

有些项目高低两个方向的临床意义相同（比如血糖低于 2.5 或高于 25 都是立即可致命的低血糖/高血糖危象），拆成两条规则会让 M13-04 生成两个危急值记录、发两条通知、走两次闭环。用 `OUTSIDE` 一条规则，闭环只有一条，医生确认一次即可。

但血钾高低意义不同（低钾心律失常、高钾心脏骤停），处置方向相反，必须拆两条 `LT` 和 `GT`。**拆与不拆由临床决定，不是技术决定。**

**WARNING 与 CRITICAL 的区别：**

| 级别 | 典型阈值 | 通知方式 | 确认时限 | 升级链路 |
|---|---|---|---|---|
| `CRITICAL` | 血钾 < 2.5 | 站内信 + 短信 + 弹窗 | 15 分钟 | 15/30/60 分钟三级升级 |
| `WARNING` | 血钾 2.5~3.0 | 仅站内信 | 无强制 | 不升级 |

**为什么不是所有异常都 CRITICAL？** 如果 WARNING 也发短信，一位医师一天 20 条短信，会直接忽略掉真正的 CRITICAL 短信（**短信疲劳**）。分级的意义就是让 CRITICAL 保持稀缺。

### 3.4 报告格式模型

**报告格式决定"这个项目在医生端长什么样"。**

| 格式 | 适用 | 展示形态 | 示例 |
|---|---|---|---|
| `NUMERIC` | 定量项目 | 数值 + 单位 + 参考区间 + 高低标记 | 血钾 `4.2 mmol/L [3.5-5.3]` 正常 |
| `QUALITATIVE` | 定性项目 | 结果 + 正常值集合比对 | 尿蛋白 `阴性`，正常 |
| `SEMI_QUANTITATIVE` | 半定量 | 分级结果 + 有序级别 | 尿蛋白 `+`，正常值为 `阴性`/`±` |
| `TEXT` | 纯文本 | 原样展示 | 细菌培养 `未见细菌生长` |
| `GROUPED` | 分组 | 主值 + 附加指标 | 血气 `pH 7.38 / pCO₂ 42 / pO2 88` |

**为什么格式、单位、精度要落库在同一张表（`m13_lab_item_ext`）而不是分散？**

因为它们是**同一个展示决策的三个面**：

- 格式是 NUMERIC → 必须显示单位
- 格式是 QUALITATIVE → 不显示单位、显示正常值集合
- 精度 2 位 → `4.20`；精度 0 位 → `4`

分散到三处会导致组合错误（比如 NUMERIC 项目掉了单位、QUALITATIVE 项目配了参考区间）。一张表一个决策，一致性有保障。

### 3.5 变更审批模型

**两级审批，按"风险等级"区分。**

| 变更类型 | 审批要求 | 生效时间 | 谁能改 |
|---|---|---|---|
| 项目别名、排序、简称 | 无需审批，直接生效 | 立即 | 信息员 |
| 收费关联 | 需要复核 | 立即 | 信息员提交 + 主任复核 |
| 报告格式 | 需要复核 | 立即 | 信息员提交 + 主任复核 |
| **参考区间** | 需要复核 | **可设定生效时间** | 信息员提交 + 主任复核 |
| **危急阈值** | **双人复核（主任 + 医务科）** | **必须延后生效（≥24 小时）** | 主任提交 + 医务科复核 |

**为什么危急阈值必须"双人复核 + 延后生效"？**

因为改错了后果是灾难性的，而且**改错的人自己看不出来**：

- 主任把血糖危急高限从 25 改成 2.5（少打了个 5）→ 所有血糖正常的患者都触发危急值
- 主任把血钾危急低限从 3.0 改成 0.3（多打了个 0）→ 所有低钾患者都不报警

这两种错误在自己复核时都"看着对"（毕竟是自己的输入）。双人复核引入第二双眼睛，延后生效给临床一个"上线前发现"的窗口。

**为什么延后 ≥24 小时？**

因为床旁血糖仪、急诊医嘱套餐、护士站的危急值看板都内置了阈值快照。突然变更会导致：

- 昨天打印的检验申请单上的参考区间是旧的
- 今天做的检验按新阈值判定
- 医生对比时会困惑

24 小时的缓冲让系统内所有快照自然过期（大多数缓存 TTL 24 小时），减少不一致窗口。

### 3.6 变更影响面评估模型

**提交变更时系统必须回答"这个改动会影响谁"。**

```
┌──────────────────────────────────────────────────────────────────────┐
│                    危急阈值变更的影响面清单                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  变更内容：血钾危急低限  3.0 → 2.8 mmol/L                             │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 【历史影响】最近 90 天按旧阈值（<3.0）判定的危急值               │    │
│  │   共 42 条。变更后这些记录【不回溯重判】                        │    │
│  │   → 历史判定按当时规则，符合法规要求                            │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 【未来影响】最近 90 天血钾在 2.8~3.0 之间的例数                 │    │
│  │   共 18 例。变更后这些患者【不再触发危急值】                    │    │
│  │   → 建议：先与临床沟通，确认这批患者无需强制闭环                │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 【配置影响】有 3 个组合项目包含血钾                              │    │
│  │   电解质六项 / 肾功能套餐 / 术前八项                            │    │
│  │   → 无需改动（阈值按项目编码匹配，组合自动继承）                │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 【单据影响】冻结 0 张待审核报告                                  │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 【覆盖检查】变更后血钾危急规则：                                │    │
│  │   ∃ 低限规则 ✓   ∃ 高限规则 ✓   → 覆盖率保持 100%              │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么"历史不回溯重判"？**

法规要求："检验报告的判定依据是报告出具时的有效标准。"这不是技术选择，是《医疗机构临床实验室管理办法》的明文要求。如果系统能按新标准重判历史报告，就会出现"同一份报告，患者昨天看是正常的，今天看是危急的"，这会让一切历史记录失去可信度。

**但为什么还要显示"最近 90 天有 18 例会受影响"？**

因为**未来**会受影响。如果这 18 例的临床决策依赖危急值闭环（比如低钾患者需要立即补钾），阈值放宽后这类患者就不再被强制追踪了。系统要提示决策者"你放宽的这个阈值，以前会拦下 18 个人"。

### 3.7 规则查询模型

**M13-03/M13-04 在判定时需要一条明确的查询链路。**

```
输入：lab_code="LAB_K", test_time="2026-10-22 09:15", gender="M", age=58
                    │
                    ▼
    ┌────────────────────────────────────┐
    │ 1. 查本地缓存（Redis Hash）         │
    │    key: m13:rule:{lab_code}         │
    │    命中 → 直接返回（< 1ms）         │
    └────────────┬───────────────────────┘
                 │ miss
                 ▼
    ┌────────────────────────────────────┐
    │ 2. 查 DB：按 test_time 匹配版本     │
    │    WHERE lab_code = :code           │
    │      AND valid_from <= :test_time   │
    │      AND (valid_to IS NULL          │
    │           OR valid_to >= :test_time)│
    │      AND (gender IS NULL            │
    │           OR gender = :gender)      │
    │      AND (age_min IS NULL           │
    │           OR age_min <= :age)       │
    │      AND (age_max IS NULL           │
    │           OR age_max >= :age)       │
    │    ORDER BY 匹配精确度 DESC LIMIT 1 │
    └────────────┬───────────────────────┘
                 │
                 ▼
    ┌────────────────────────────────────┐
    │ 3. 结果写缓存（TTL 300s）           │
    └────────────┬───────────────────────┘
                 │
                 ▼
输出：{lb: 3.5, ub: 5.3, ref_text: "3.5-5.3",
       critical: [{rule: K_LOW, lb: 3.0, sev: CRITICAL}]}
```

**"匹配精确度"的排序逻辑：**

```sql
ORDER BY
    (CASE WHEN gender IS NOT NULL THEN 8 ELSE 0 END
   + CASE WHEN age_min IS NOT NULL
               OR age_max IS NOT NULL THEN 4 ELSE 0 END
   + CASE WHEN physiological_state IS NOT NULL THEN 2 ELSE 0 END
   + CASE WHEN device_code IS NOT NULL THEN 1 ELSE 0 END) DESC,
    valid_from DESC
LIMIT 1
```

**为什么按精确度降序而非"命中即返回"？**

如果先查到的是一条"仅性别匹配"的粗粒度区间，再查到的是一条"性别+年龄+生理状态"的精细区间，两者都存在时应该用精细的。**精确度排序保证"最具体的规则优先"。**

**缓存的 key 设计与失效：**

| key | 内容 | TTL | 失效时机 |
|---|---|---|---|
| `m13:rule:{lab_code}` | 该项目全部区间 + 阈值（JSON） | 300s | 该项目任一条规则变更时主动删除 |
| `m13:rule:version:{lab_code}` | 该项目规则集版本号 | 300s | 同上 |

**为什么缓存 300s 而不是 1 小时？**

因为危急阈值变更必须尽快生效。300s 是最坏情况下的延迟上限。变更时主动删除缓存可以把实际延迟降到接近 0，但主动删除可能失败（Redis 抖动），所以 TTL 是兜底。

**300s 与"必须延后 24 小时生效"矛盾吗？** 不矛盾。延后 24 小时是**审批流程**的要求（给临床缓冲），缓存 300s 是**技术生效**的要求（规则一旦生效，各节点尽快同步）。

### 3.8 覆盖率监控模型

**覆盖率是"规则管理做得好不好"的唯一客观指标。**

```
┌──────────────────────────────────────────────────────────────────────┐
│                        覆盖率定义与计算                               │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  区间覆盖率 = 已配有效区间的项目数 / 已启用项目数                      │
│             = COUNT(is_range_ready=TRUE AND is_enabled=TRUE)         │
│               / COUNT(is_enabled=TRUE)                               │
│                                                                      │
│  危急覆盖率 = 已配危急阈值的项目数 / 适宜配危急阈值的项目数            │
│             = COUNT(is_critical_ready=TRUE AND is_enabled=TRUE       │
│                     AND is_critical_applicable=TRUE)                 │
│               / COUNT(is_enabled=TRUE AND is_critical_applicable=TRUE)│
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │ is_critical_applicable 的判定（哪些项目"适宜"配危急阈值）        │  │
│  │                                                                │  │
│  │ ✅ 需要配（真实数据）：                                         │  │
│  │   · 电解质：钾 钠 氯 钙 镁 磷                                   │  │
│  │   · 血糖、血氨、乳酸                                            │  │
│  │   · 血常规：血红蛋白、血小板、白细胞                            │  │
│  │   · 凝血：PT、APTT、D-二聚体、纤维蛋白原                        │  │
│  │   · 心肌标志物：肌钙蛋白、肌酸激酶                              │  │
│  │   · 肝肾功能：ALT、AST、肌酐、尿素氮                            │  │
│  │   · 胆红素（尤其新生儿）                                        │  │
│  │                                                                │  │
│  │ ❌ 不需要配：                                                    │  │
│  │   · 定性/半定量项目（尿常规、便常规）                            │  │
│  │   · 分类型项目（血型、HLA）                                     │  │
│  │   · 纯文本项目（细菌培养描述）                                   │  │
│  │   · 计算派生项（某些比值）                                       │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么危急覆盖率的分母要排除"不适宜"的项目？**

如果分母是全部启用项目（500 个），而其中 350 个是定性项目根本不适用危急阈值，那覆盖率永远上不去，每次都低于 30%，这个指标就没人看了。分母只算"适宜"的项目（约 150 个），才能真实反映"该配的配了没有"。

**止血带项目：** 覆盖率看板有"缺失清单"，列出全部 `is_critical_applicable=TRUE AND is_critical_ready=FALSE` 的项目，标注"该项目多久没配"、"影响哪些使用中的组合"。

**关键约束：未配齐区间的项目不允许启用。**

因为一旦启用，医生就能开单，患者就能做检验，但系统无法判定高低——报告上只有数值没有标记，医生要自己心算比区间。这比"项目不可用"糟得多。

**但为什么允许"区间就绪但阈值未就绪"时启用？**

因为危急阈值只适用于部分项目。定性项目的 `is_critical_applicable=FALSE`，`is_critical_ready` 自动为 TRUE。所以"启用前置条件"是：`is_range_ready=TRUE AND (is_critical_applicable=FALSE OR is_critical_ready=TRUE)`。

**为什么"别名"必须有至少 1 个？**

因为搜索依赖别名。如果只有项目正式名称"钾"，医生搜"血钾"、"K"都搜不到，就会以为系统没有这个项目。别名是**可用性要求**，不是可选装饰。

**为什么"启用前置校验"不允许绕过？**

上一节已论述：启用一个没有区间的项目，等于让医生收到"只有数值没有标记"的报告。系统以为在帮他，实际在害他。宁可让项目不可用（报缺配置），也不能让半成品流到临床。

因为实际变更往往是"90% 不变，改 1~2 条"。从空白开始填 12 条区间容易漏；复制后只改需要改的，漏改的概率低。这也符合"版本是演进不是重写"的语义。

| 编号 | 规则 | 说明 | 错误码 |
|---|---|---|---|
| V-41 | 规则编码项目内唯一 | 大小写敏感 | `"1305021"` |
| V-42 | 运算符与阈值组合合法 | LT 需下限、GT 需上限、BETWEEN 需两个、OUTSIDE 需两个 | `"1305022"` |
| V-43 | **危急阈值必须位于参考区间之外** | 在区间内的阈值无意义 | `"1305023"` |
| V-44 | CRITICAL 必须有确认与处置时限 | 15/120 分钟 | `"1305024"` |
| V-45 | WARNING 不强制确认时限 | 可为 NULL | `"1305025"` |
| V-46 | **变更必须双人复核** | 提交人 ≠ 复核人 | `"1305026"` |
| V-47 | 变更原因 ≥20 字 | 强制说明 | `"1305027"` |
| V-48 | 生效时间不早于提交后 24 小时 | 缓冲期 | `"1305028"` |
| V-49 | 同一项目同一时刻每类阈值唯一 | 不能有两个 `< X` | `"1305029"` |
| V-50 | 取消"适宜配置"必须填原因 ≥20 字 | 防止随意降低覆盖率考核 | `"1305030"` |

**为什么 V-43 要校验"阈值在参考区间之外"？**

如果参考区间是 3.5~5.3，而危急低值配成 4.0，那么**每个低于 4.0 的正常患者（3.5~4.0）都会触发危急值**。这会让危急值泛滥，医生完全忽略。虽然参考区间和危急阈值由不同人维护、不同表存储，但系统必须检查它们的相对位置。

**为什么"立即生效"选项存在但不推荐？**

真实场景：检验科发现某项目的危急阈值配错了（比如把 6.5 配成 0.65），正在大量误报。这时候需要立即纠正。但正常的规则调整都应该走 24 小时缓冲。所以"立即生效"保留但标注"不推荐"，且需要额外权限（`m13:critical:approve_urgent`）。

**为什么示意图里要标"缓冲区"？**

缓冲区（3.0~3.5 与 5.3~6.5）是"异常但不危急"的地带。这个地带的存在让医生可以区分"需要关注"与"立即处理"。如果危急阈值紧贴参考区间（比如低值配 3.5），就没有缓冲区，所有异常都是危急，分级失去意义。示意图帮配置者直观发现"缓冲区太窄"。

### 6.2 错误码规范

| 错误码 | 说明 | 触发场景 |
|---|---|---|
| `"1305001"` | 检验项目不存在 | M01-09 查不到该 `lab_code` |
| `"1305002"` | 别名数量或长度非法 | 别名数组为空、超过 10 个或单项超长 |
| `"1305003"` | 别名重复 | 同项目内别名重复 |
| `"1305004"` | 报告格式非法 | 不在 5 种枚举内 |
| `"1305005"` | 收费项目不存在或已停用 | M01-06 校验失败 |
| `"1305006"` | 默认仪器非法 | 不是检验类设备 |
| `"1305007"` | 配置未就绪不可启用 | 区间或危急阈值未配齐 |
| `"1305008"` | 承诺周转时间超范围 | 不在 1~168 小时 |
| `"1305009"` | 医生端排序超范围 | 不在 0~9999 |
| `"1305010"` | 项目状态不允许此操作 | 已停用项目被修改 |
| `"1305011"` | 区间下限不小于上限 | `lb >= ub` |
| `"1305012"` | 区间与已有版本重叠 | `EXCLUDE` 约束冲突 |
| `"1305013"` | 区间有效期非法 | `valid_from >= valid_to` |
| `"1305014"` | 生效日期早于当前版本 | 不允许插入历史 |
| `"1305015"` | 同项目同协议存在多个当前版 | `is_current` 重复 |
| `"1305016"` | 定性项目必须配置正常值集合 | `result_type=QUALITATIVE` 但无正常值 |
| `"1305017"` | 年龄区间非法 | `age_min > age_max` |
| `"1305018"` | 年龄超出合法范围 | 不在 0~150 |
| `"1305019"` | 导出行数超出限制 | 超过 50000 行 |
| `"1305020"` | 版本已批准不可编辑 | 对 `APPROVED` 版本调用编辑 |
| `"1305021"` | 危急规则编码重复 | 同项目内 `rule_code` 重复 |
| `"1305022"` | 运算符与阈值组合非法 | LT 缺低限、BETWEEN 缺一限等 |
| `"1305023"` | 危急阈值必须位于参考区间之外 | 阈值落在参考区间内 |
| `"1305024"` | CRITICAL 级别必须设置时限 | 缺确认或处置时限 |
| `"1305025"` | WARNING 级别不可设置确认时限 | 设置了确认时限 |
| `"1305026"` | 不能审批自己提交的变更 | 双人复核校验 |
| `"1305027"` | 变更原因不足 | 少于 20 字符 |
| `"1305028"` | 生效时间过早 | 早于提交后 24 小时 |
| `"1305029"` | 同类型阈值冲突 | 同项目已有同类规则 |
| `"1305030"` | 取消适用性必须说明原因 | 原因不足 20 字符 |
| `"1305031"` | 无审批权限 | 权限码或层级不匹配 |
| `"1305032"` | 审批层级不匹配 | 医务科才能批危急阈值 |
| `"1305033"` | 驳回原因不足 | 少于 10 字符 |
| `"1305034"` | 变更状态不允许此操作 | 已审批的变更再次操作 |
| `"1305035"` | 变更已超时自动驳回 | 超过 7 天 |
| `"1305036"` | 查询日期跨度超限 | 超过 366 天 |
| `"1305037"` | 变更历史不可修改删除 | 尝试 UPDATE/DELETE |
| `"1305038"` | 规则服务不可用 | 内部契约调用超时 |
| `"1305039"` | 项目同步失败 | M01-09 不可用 |
| `"1305040"` | 批内存在非法编码 | 批量规则查询含未知项目 |

```python
"""M13-05 检验项目与参考区间管理 —— 路由层。"""
from datetime import date, datetime
from typing import Optional

from fastapi import APIRouter, Body, Depends, Query

from app.core.deps import CurrentUser, require_permission
from app.schemas.m13_lab_item import (

    HistoryQuery,

    LabItemQuery,

    OverlapCheckIn,

    RuleBatchQuery,
)
from app.services.m13_lab_item import (
    CoverageService,
    CriticalService,
    HistoryService,
    ImpactService,
    ItemService,
    RangeService,
)

router = APIRouter(
    prefix="/api/v1/m13/lab-item",
    tags=["M13-05 检验项目与参考区间管理"])
internal_router = APIRouter(
    prefix="/internal/v1/m13/lab-item",
    tags=["M13-05 内部契约"])


# ---------- 总览与统计 ----------

@router.get("/dashboard", summary="规则健康看板")
async def dashboard(
    stat_date: Optional[date] = Query(None),
    user: CurrentUser = Depends(
        require_permission("m13:item:query")),
):
    """规则健康看板。"""
    data = await CoverageService.dashboard(stat_date or date.today())
    return {"code": 0, "message": "success", "data": data}


@router.get("/coverage", summary="覆盖率明细")
async def coverage(
    stat_date: Optional[date] = Query(None),
    category: Optional[str] = Query(None, max_length=32),
    user: CurrentUser = Depends(
        require_permission("m13:item:query")),
):
    """按类别统计覆盖率。"""
    data = await CoverageService.coverage(
        stat_date or date.today(), category)
    return {"code": 0, "message": "success", "data": data}


@router.get("/missing", summary="缺失清单")
async def missing(
    missing_type: str = Query(
        "CRITICAL", pattern="^(RANGE|CRITICAL)$"),
    category: Optional[str] = Query(None, max_length=32),
    page: int = Query(1, ge=1),
    page_size: int = Query(50, ge=1, le=200),
    user: CurrentUser = Depends(
        require_permission("m13:item:query")),
):
    """区间或危急规则缺失清单。"""
    data = await CoverageService.missing(
        missing_type, category, page, page_size)
    return {"code": 0, "message": "success", "data": data}

    body: MissingQuery,

        require_permission("m13:item:query")),
):
    """导出缺失清单 CSV。"""
```

```python
def _weight(gender, age_min, age_max, state, device) -> int:
    """计算区间匹配精确度权重。"""
    w = 0
    if gender:
        w += PREC_GENDER
    if age_min is not None or age_max is not None:
        w += PREC_AGE
    if state:
        w += PREC_STATE
    if device:
        w += PREC_DEVICE
    return w


def _range_cache_key(lab_code: str) -> str:
    """规则缓存 key。"""
    return "m13:labitem:rule:%s" % lab_code


class ItemService:
    """项目本地属性服务。"""

    MAX_ALIAS = 10
    ALIAS_MIN_LEN = 2
    ALIAS_MAX_LEN = 50
    TURNAROUND_MIN = 1
    TURNAROUND_MAX = 168
    SORT_MIN = 0
    SORT_MAX = 9999

    @classmethod
    async def list_items(cls, q) -> Dict[str, Any]:
        """项目列表。"""
        stmt = select(M13LabItemExt).where(
            M13LabItemExt.is_deleted.is_(False))
        if q.keyword:
            kw = "%" + q.keyword + "%"
            stmt = stmt.where(or_(
                M13LabItemExt.lab_code.ilike(kw),
                M13LabItemExt.lab_name.ilike(kw),
                M13LabItemExt.alias_names.any(q.keyword)))
        if q.category:
            stmt = stmt.where(
                M13LabItemExt.lab_category == q.category)
        if q.status == "READY":
            stmt = stmt.where(
                M13LabItemExt.is_enabled.is_(True),
                M13LabItemExt.is_range_ready.is_(True))
        elif q.status == "MISSING":
            stmt = stmt.where(or_(
                M13LabItemExt.is_range_ready.is_(False),
                and_(M13LabItemExt.is_critical_applicable.is_(True),
                     M13LabItemExt.is_critical_ready.is_(False))))
        elif q.status == "DISABLED":
            stmt = stmt.where(
                M13LabItemExt.is_enabled.is_(False))
        total = await _count(q, stmt)
        stmt = stmt.order_by(
            M13LabItemExt.lab_category,
            M13LabItemExt.display_order,
            M13LabItemExt.lab_code,
        ).offset((q.page - 1) * q.page_size).limit(q.page_size)
        rows = (await _session().execute(stmt)).scalars().all()
        return {
            "items": [_item_brief(r) for r in rows],
            "total": total,
            "page": q.page,
            "page_size": q.page_size,
        }

    @classmethod
    async def get_item(cls, lab_code: str) -> Dict[str, Any]:

        return await cls._detail(row)

    @classmethod
    async def update_item(
        cls, lab_code: str, body: Any, user: Any
    ) -> Dict[str, Any]:
        """更新本地扩展属性。"""
        # ① 加载
        row = await cls._get(lab_code)
        # ② 校验别名
        aliases = cls._normalize_aliases(body.alias_names)
        # ③ 校验格式
        if body.report_format not in FORMATS:
            raise BizException(
                "1305004",
                "报告格式必须是 %s 之一" % "/".join(FORMATS))
        # ④ 收费项目校验（可降级）
        await cls._check_charge_item(body.charge_item_code)
        # ⑤ 默认仪器校验（可降级）
        await cls._check_device(body.default_device)
        # ⑥ 数值范围
        if body.turnaround_hours is not None and not (
                cls.TURNAROUND_MIN <= body.turnaround_hours
                <= cls.TURNAROUND_MAX):
            raise BizException("1305008", "承诺周转时间须在 1~168 小时")
        if body.display_order is not None and not (
                cls.SORT_MIN <= body.display_order <= cls.SORT_MAX):
            raise BizException("1305009", "医生端排序须在 0~9999")
        # ⑦ 收集变更项
        snapshot = _item_dict(row)
        changed = []
        for field_name in (
                "alias_names", "short_name", "report_format",
                "default_device", "charge_item_code",
                "display_order", "is_panel_visible",
                "turnaround_hours", "is_manual_only"):
            new_val = getattr(body, field_name, None)
            if new_val is None:
                continue
            old_val = getattr(row, field_name)
            if _diff(old_val, new_val):
                changed.append({
                    "field": field_name,
                    "old": old_val,
                    "new": new_val,
                })
                setattr(row, field_name, new_val)
        if not changed:
            return {"lab_code": lab_code, "changed": 0}
        row.alias_names = aliases
        row.updated_by = user.employee_id
        row.updated_at = datetime.now()
        # ⑧ 写变更日志
        await cls._log(
            lab_code, "ITEM_ATTR", "UPDATE",
            "更新本地属性 %d 项" % len(changed),
            snapshot, _item_dict(row), changed, user,
            impact={"affected_combos": 0})
        await _session().commit()
        # ⑨ 清缓存
        await redis_client.delete(_range_cache_key(lab_code))
        return {"lab_code": lab_code, "changed": len(changed)}

    @classmethod
    async def change_enabled(
        cls, lab_code: str, enabled: bool, user: Any,
        reason: Optional[str] = None,
    ) -> Dict[str, Any]:
        """启用或停用项目。"""
        row = await cls._get(lab_code)
        if enabled:
            # 启用前置校验
            if not row.is_range_ready:
                raise BizException(
                    "1305007",
                    "参考区间未配齐，请先到 P03 配置区间")
            if (row.is_critical_applicable
                    and not row.is_critical_ready):
                raise BizException(
                    "1305007",
                    "危急阈值未配齐，请先到 P04 配置阈值")
        else:
            if not reason or len(reason.strip()) < 10:
                raise BizException(
                    "1305010", "停用必须说明原因（不少于 10 字）")
        old = row.is_enabled
        if old == enabled:
            return {"lab_code": lab_code, "enabled": enabled,
                    "changed": False}
        row.is_enabled = enabled
        row.updated_by = user.employee_id
        row.updated_at = datetime.now()
        await cls._log(
            lab_code, "ITEM_ATTR",
            "UPDATE" if enabled else "DISABLE",
            "启用" if enabled else "停用：%s" % reason,
            {"is_enabled": old}, {"is_enabled": enabled},
            [{"field": "is_enabled", "old": old, "new": enabled}],
            user, impact={"affected_combos": 0})
        await _session().commit()
        await redis_client.delete(_range_cache_key(lab_code))
        return {"lab_code": lab_code, "enabled": enabled,
                "changed": True}

    # ---------- 规则查询（内部契约） ----------

    @classmethod
    async def query_rule(
        cls, lab_code: str, test_time: datetime,
        gender: Optional[str], age: Optional[int],
        state: Optional[str],
    ) -> Dict[str, Any]:
        """查询某项目在特定时刻的生效规则。"""
        # ① 查缓存
        cached = await cls._get_cached_rule(lab_code)
        if cached:
            picked = cls._pick(cached, test_time, gender, age, state)
            if picked:
                picked["cache_hit"] = True
                picked["computed_at"] = cached["computed_at"]
                return picked
        # ② 查 DB
        data = await cls._load_rule(lab_code)
        # ③ 写缓存
        await cls._set_cached_rule(lab_code, data)
        picked = cls._pick(data, test_time, gender, age, state)
        if not picked:
            raise BizException(
                "1305001", "检验项目不存在或未配置规则: %s" % lab_code)
        picked["cache_hit"] = False
        picked["computed_at"] = data["computed_at"]
        return picked

    @classmethod
    async def _load_rule(cls, lab_code: str) -> Dict[str, Any]:
        """从 DB 加载项目全部规则。"""
        item = await cls._get(lab_code)
        ranges = (await _session().execute(
            select(M13RefRange).where(
                M13RefRange.lab_code == lab_code,
                M13RefRange.is_enabled.is_(True),
                M13RefRange.is_deleted.is_(False),
            ).order_by(
                M13RefRange.valid_from.desc(),
                M13RefRange.version_no.desc())
        )).scalars().all()
        rules = (await _session().execute(
            select(M13CriticalRule).where(
                M13CriticalRule.lab_code == lab_code,
                M13CriticalRule.is_enabled.is_(True),
                M13CriticalRule.approval_status == "APPROVED",
                M13CriticalRule.is_deleted.is_(False),
            ).order_by(M13CriticalRule.rule_code)
        )).scalars().all()
        return {
            "lab_code": lab_code,
            "lab_name": item.lab_name,
            "result_type": item.result_type,
            "unit": item.result_unit,
            "decimal_places": item.decimal_places,
            "ranges": [_range_dict(r) for r in ranges],
            "criticals": [_critical_dict(c) for c in rules],
            "computed_at": datetime.now().strftime(
                "%Y-%m-%d %H:%M:%S"),
        }

    @classmethod
    def _pick(
        cls, data: Dict[str, Any], test_time: datetime,
        gender: Optional[str], age: Optional[int],
        state: Optional[str],
    ) -> Optional[Dict[str, Any]]:
        """按时刻与患者特征挑选最精确的区间。"""
        tdate = test_time.date() if isinstance(
            test_time, datetime) else test_time
        cands = []
        for r in data["ranges"]:
            vf = _to_date(r["valid_from"])
            vt = _to_date(r["valid_to"])
            if vf > tdate:
                continue
            if vt is not None and vt < tdate:
                continue
            if r["gender"] and r["gender"] != gender:
                continue
            amin = r["age_min"]
            amax = r["age_max"]
            if amin is not None and (age is None or age < amin):
                continue
            if amax is not None and (age is None or age > amax):
                continue
            if r["physiological_state"]:
                if r["physiological_state"] != state:
                    continue
            w = _weight(
                r["gender"], amin, amax,
                r["physiological_state"], r["device_code"])
            cands.append((w, _to_date(r["valid_from"]), r))
        if not cands:
            return None
        cands.sort(key=lambda x: (x[0], x[1]), reverse=True)
        best = cands[0][2]
        # 组装危急规则（按 test_time 过滤生效版本）
        criticals = [
            c for c in data["criticals"]
            if _valid_at(c, tdate)
        ]
        return {
            "lab_code": data["lab_code"],
            "lab_name": data["lab_name"],
            "result_type": data["result_type"],
            "unit": data["unit"],
            "decimal_places": data["decimal_places"],
            "range_version": best["version_no"],
            "range": {
                "lb": best["lb"],
                "ub": best["ub"],
                "ref_text": best["ref_text"],
                "ref_source": "LOCAL",
                "gender": best["gender"],
                "age_min": best["age_min"],
                "age_max": best["age_max"],
                "physiological_state": best["physiological_state"],
                "device_code": best["device_code"],
            },
            "criticals": [_critical_dict(c) for c in criticals],
        }

    @classmethod
    async def _get_cached_rule(
        cls, lab_code: str
    ) -> Optional[Dict[str, Any]]:
        """从 Redis 取规则缓存。"""
        raw = await redis_client.get(_range_cache_key(lab_code))
        if not raw:
            return None
        try:
            return json.loads(raw)
        except Exception:
            await redis_client.delete(_range_cache_key(lab_code))
            return None

    @classmethod
    async def _set_cached_rule(
        cls, lab_code: str, data: Dict[str, Any]
    ) -> None:
        """写规则缓存。"""
        await redis_client.setex(
            _range_cache_key(lab_code), 300,
            json.dumps(data, default=str))

    @classmethod
    async def query_rules_batch(
        cls, body: Any
    ) -> Dict[str, Any]:
        """批量规则查询。"""
        items = []
        not_found = []
        hits = 0
        for code in body.lab_codes:
            try:
                r = await cls.query_rule(
                    code, body.test_time, body.gender,
                    body.age, body.physiological_state)
            except BizException:
                not_found.append(code)
                continue
            if r.get("cache_hit"):
                hits += 1
            items.append({
                "lab_code": r["lab_code"],
                "range_version": r["range_version"],
                "range": {
                    "lb": r["range"]["lb"],
                    "ub": r["range"]["ub"],
                    "ref_text": r["range"]["ref_text"],
                },
                "critical_count": len(r["criticals"]),
            })
        if not_found and len(not_found) == len(body.lab_codes):
            raise BizException(
                "1305040", "批内全部项目编码非法")
        return {
            "items": items,

        }

        if len(aliases) > cls.MAX_ALIAS:

        seen = set()
        for a in aliases:
            if not isinstance(a, str):
                raise BizException("1305002", "别名必须是字符串")
            s = a.strip()

            if s in seen:
                raise BizException(
                    "1305003", "别名重复：%s" % s)
            seen.add(s)
            out.append(s)
        return out

class RangeService:

    @classmethod
    async def list_versions(
        cls, lab_code: str
    ) -> Dict[str, Any]:

        for r in rows:

        for v in sorted(by_version.keys(), reverse=True):

            versions.append({
                "version": v,
                "valid_from": _fmt_date(head.valid_from),
                "valid_to": _fmt_date(head.valid_to),
                "is_current": head.is_current,

            "lab_name": item.lab_name,
            "result_type": item.result_type,
            "unit": item.result_unit,
            "current_version": next(
                (v["version"] for v in versions
                 if v["is_current"]), None),
            "versions": versions,
        }

    @classmethod
    async def create_version(
        cls, lab_code: str, body: Any, user: Any
    ) -> Dict[str, Any]:
        """新建区间版本（复制当前版）。"""
        item = await ItemService._get(lab_code)
        cur = await cls._current_version(lab_code)
        new_version = 1 if cur is None else cur + 1
        if new_version > 100:
            raise BizException(
                "1305015", "版本号已达上限 100")
        # 复制当前版区间
        src = (await _session().execute(
            select(M13RefRange).where(
                M13RefRange.lab_code == lab_code,
                M13RefRange.version_no == cur,
                M13RefRange.is_deleted.is_(False))
        )).scalars().all() if cur else []
        if not src and body.ranges:
            src = []
        targets = body.ranges or [_range_from_model(r) for r in src]
        cls._validate_ranges(targets, item.result_type)
        # 生效日期校验
        if cur is not None:
            cur_vf = _to_date(src[0].valid_from) if src else None
            new_vf = _to_date(body.valid_from)
            if cur_vf and new_vf < cur_vf:
                raise BizException(
                    "1305014",
                    "新版本生效日期不得早于当前版本 %s" % cur_vf)
        # 重叠预检
        conflicts = await cls._find_overlap(
            lab_code, new_version, targets, body.valid_from,
            body.valid_to)
        if conflicts:
            raise BizException(
                "1305012",
                "与已有版本重叠：%s" % conflicts[0]["suggestion"])
        # 落库
        for i, t in enumerate(targets, start=1):
            _session().add(M13RefRange(
                lab_code=lab_code,
                version_no=new_version,
                seq_no=i,
                gender=t.get("gender"),
                age_min=t.get("age_min"),
                age_max=t.get("age_max"),
                physiological_state=t.get(
                    "physiological_state"),
                device_code=t.get("device_code"),
                lb=t.get("lb"),
                ub=t.get("ub"),
                ref_text=t.get("ref_text"),
                unit=t.get("unit") or item.result_unit,
                normal_values=t.get("normal_values"),
                valid_from=body.valid_from,
                valid_to=body.valid_to,
                is_current=False,
                approval_status="DRAFT",
                is_enabled=True,
                created_by=user.employee_id,
                created_at=datetime.now(),
            ))
        await _session().commit()
        return {
            "lab_code": lab_code,
            "version": new_version,
            "approval_status": "DRAFT",
            "range_count": len(targets),
        }

    @classmethod
    def _validate_ranges(
        cls, ranges: List[Dict], result_type: str
    ) -> None:
        """校验区间列表。"""
        if not ranges:
            raise BizException("1305016", "至少配置 1 条区间")
        if len(ranges) > cls.MAX_RANGES_PER_VERSION:
            raise BizException(
                "1305016", "单版本区间不得超过 50 条")
        for i, r in enumerate(ranges, start=1):
            if result_type == "QUALITATIVE":
                nv = r.get("normal_values") or []
                if not nv:
                    raise BizException(
                        "1305016",
                        "第 %d 行：定性项目必须配置正常值集合" % i)
                continue
            lb, ub = r.get("lb"), r.get("ub")
            if lb is None and ub is None:
                raise BizException(
                    "1305011", "第 %d 行：区间上下限至少填一个" % i)
            if lb is not None and ub is not None and lb >= ub:
                raise BizException(
                    "1305011",
                    "第 %d 行：下限必须小于上限" % i)
            amin, amax = r.get("age_min"), r.get("age_max")
            if amin is not None and amax is not None and amin > amax:
                raise BizException(
                    "1305017", "第 %d 行：年龄下限大于上限" % i)
            for a in (amin, amax):
                if a is not None and not (0 <= a <= 150):
                    raise BizException(
                        "1305018",
                        "第 %d 行：年龄须在 0~150" % i)

    @classmethod
    async def check_overlap(
        cls, body: Any
    ) -> Dict[str, Any]:
        """重叠预检。"""
        conflicts = await cls._find_overlap(
            body.lab_code, None, [body.candidate],
            body.candidate["valid_from"],
            body.candidate.get("valid_to"))
        return {"has_overlap": bool(conflicts),
                "conflicts": conflicts}

    @classmethod
    async def _find_overlap(
        cls, lab_code: str, exclude_version: Optional[int],
        targets: List[Dict], valid_from, valid_to
    ) -> List[Dict[str, Any]]:
        """查找有效期重叠的历史版本。"""
        stmt = select(M13RefRange).where(
            M13RefRange.lab_code == lab_code,
            M13RefRange.is_deleted.is_(False))
        if exclude_version is not None:
            stmt = stmt.where(
                M13RefRange.version_no != exclude_version)
        rows = (await _session().execute(stmt)).scalars().all()
        out = []
        for t in targets:
            t_vf = _to_date(valid_from)
            t_vt = _to_date(valid_to) if valid_to else None
            for r in rows:
                if not _same_key(t, r):
                    continue
                r_vf = _to_date(r.valid_from)
                r_vt = _to_date(r.valid_to)
                if not _overlap(t_vf, t_vt, r_vf, r_vt):
                    continue
                out.append({
                    "version": r.version_no,
                    "valid_from": _fmt_date(r.valid_from),
                    "valid_to": _fmt_date(r.valid_to),
                    "ref_text": r.ref_text,
                    "overlap_from": _fmt_date(max(
                        t_vf, r_vf)),
                    "overlap_to": _fmt_date(_min_date(
                        t_vt, r_vt)),
                    "suggestion": (
                        "请先将 V%d 的 valid_to 设为 %s"
                        % (r.version_no,
                           (t_vf - timedelta(days=1))
                           .isoformat())),
                })
        return out

    @classmethod
    async def _current_version(
        cls, lab_code: str
    ) -> Optional[int]:
        """当前版本号。"""
        v = (await _session().execute(
            select(func.max(M13RefRange.version_no)).where(
                M13RefRange.lab_code == lab_code,
                M13RefRange.is_deleted.is_(False))
        )).scalar()
        return v


class CriticalService:
    """危急阈值服务。"""

    SEVERITIES = ("CRITICAL", "WARNING")
    OPS = ("LT", "GT", "BETWEEN", "OUTSIDE")
    MIN_REASON_LEN = 20
    MIN_EFFECTIVE_HOURS = 24

    @classmethod
    async def list_rules(
        cls, lab_code: str, include_history: bool
    ) -> Dict[str, Any]:
        """项目危急规则列表。"""
        item = await ItemService._get(lab_code)
        stmt = select(M13CriticalRule).where(
            M13CriticalRule.lab_code == lab_code,
            M13CriticalRule.is_deleted.is_(False))
        if not include_history:
            stmt = stmt.where(
                M13CriticalRule.is_current.is_(True))
        rows = (await _session().execute(
            stmt.order_by(M13CriticalRule.rule_code))
        ).scalars().all()
        return {
            "lab_code": lab_code,
            "lab_name": item.lab_name,
            "unit": item.result_unit,
            "is_critical_applicable":
                item.is_critical_applicable,
            "is_critical_ready": item.is_critical_ready,
            "rules": [_critical_dict(r) for r in rows],
        }

    @classmethod
    async def save_rules(
        cls, lab_code: str, body: Any, user: Any
    ) -> Dict[str, Any]:
        """保存危急规则并生成待审批变更。"""
        item = await ItemService._get(lab_code)
        cls._validate_rules(item, body.rules)
        # 计算影响面
        impact = await ImpactService.evaluate(
            lab_code,
            body.rules[0].rule_code,
            body.rules[0].lb_threshold,
            body.rules[0].ub_threshold, 90)
        # 生效时间校验
        if body.effective_mode == "DELAYED":
            eff = _to_dt(body.effective_at)
            min_eff = datetime.now() + timedelta(
                hours=cls.MIN_EFFECTIVE_HOURS)
            if eff < min_eff:
                raise BizException(
                    "1305028",
                    "生效时间不得早于提交后 24 小时")
        elif body.effective_mode == "IMMEDIATE":
            if not _has_perm(user, "m13:critical:approve_urgent"):
                raise BizException(
                    "1305028",
                    "立即生效需要紧急审批权限")
            eff = datetime.now()
        else:
            raise BizException("1305022", "生效方式非法")
        # 原因校验
        if len((body.change_reason or "").strip()) < cls.MIN_REASON_LEN:
            raise BizException(
                "1305027", "变更原因不得少于 20 个字符")
        change_no = await _next_change_no()
        before = {
            r.rule_code: _critical_snapshot(r)
            for r in (await cls._current_rules(lab_code))
        }
        after = {r["rule_code"]: r for r in _rules_payload(body)}
        for rule in body.rules:
            await cls._upsert_rule(
                lab_code, rule, change_no, eff, user)
        await ItemService._log(
            lab_code, "CRITICAL_RULE", "UPDATE",
            "提交危急规则变更 %d 条" % len(body.rules),
            before, after,
            _diff_rules(before, after), user,
            impact=impact)
        await _session().commit()
        return {
            "change_no": change_no,
            "approval_status": "PENDING",
            "approval_step": "MEDICAL_AFFAIRS",
            "effective_at": _fmt(eff),
            "impact": impact,
        }

    @classmethod
    def _validate_rules(
        cls, item: Any, rules: List[Any]
    ) -> None:
        """校验规则集合。"""
        if not rules:
            raise BizException("1305022", "至少 1 条规则")
        seen = set()
        for r in rules:
            if r.rule_code in seen:
                raise BizException(
                    "1305021", "规则编码重复：%s" % r.rule_code)
            seen.add(r.rule_code)
            if r.severity not in cls.SEVERITIES:
                raise BizException(
                    "1305022", "级别非法：%s" % r.severity)
            if r.operator not in cls.OPS:
                raise BizException(
                    "1305022", "运算符非法：%s" % r.operator)
            cls._check_op(r)
            cls._check_level(r)
            cls._check_outside_range(item, r)

    @classmethod
    def _check_op(cls, r: Any) -> None:
        """运算符与阈值组合校验。"""
        lb, ub = r.lb_threshold, r.ub_threshold
        if r.operator == "LT" and lb is None:
            raise BizException(
                "1305022", "%s：LT 必须配置低限" % r.rule_code)
        if r.operator == "GT" and ub is None:
            raise BizException(
                "1305022", "%s：GT 必须配置高限" % r.rule_code)
        if r.operator in ("BETWEEN", "OUTSIDE"):
            if lb is None or ub is None:
                raise BizException(
                    "1305022",
                    "%s：%s 必须同时配置上下限"
                    % (r.rule_code, r.operator))
            if lb >= ub:
                raise BizException(
                    "1305022",
                    "%s：低限必须小于高限" % r.rule_code)

    @classmethod
    def _check_level(cls, r: Any) -> None:
        """级别与时限组合校验。"""
        if r.severity == "CRITICAL":
            if not r.ack_minutes or not r.handle_minutes:
                raise BizException(
                    "1305024",
                    "%s：CRITICAL 必须设置确认与处置时限"
                    % r.rule_code)
        elif r.severity == "WARNING":
            if r.ack_minutes:
                raise BizException(
                    "1305025",
                    "%s：WARNING 不可设置强制确认时限"
                    % r.rule_code)

    @classmethod
    def _check_outside_range(cls, item: Any, r: Any) -> None:
        """危急阈值必须位于参考区间之外。"""
        ref = getattr(item, "_cached_range", None)
        if not ref:
            return
        lb, ub = r.lb_threshold, r.ub_threshold
        rlb, rub = ref.get("lb"), ref.get("ub")
        if (r.operator == "LT" and rlb is not None
                and lb is not None and lb >= rlb):
            raise BizException(
                "1305023",
                "%s：低限 %s 未低于参考下限 %s"
                % (r.rule_code, lb, rlb))
        if (r.operator == "GT" and rub is not None
                and ub is not None and ub <= rub):
            raise BizException(
                "1305023",
                "%s：高限 %s 未高于参考上限 %s"
                % (r.rule_code, ub, rub))

    @classmethod
    async def _upsert_rule(
        cls, lab_code: str, r: Any, change_no: str,
        eff: datetime, user: Any,
    ) -> None:
        """插入新版本规则并将旧版本置为历史。"""
        olds = (await _session().execute(
            select(M13CriticalRule).where(
                M13CriticalRule.lab_code == lab_code,
                M13CriticalRule.rule_code == r.rule_code,
                M13CriticalRule.is_current.is_(True),
                M13CriticalRule.is_deleted.is_(False))
        )).scalars().all()
        for o in olds:
            o.is_current = False
            o.valid_to = (eff - timedelta(days=1)).date()
        _session().add(M13CriticalRule(
            lab_code=lab_code,
            rule_code=r.rule_code,
            rule_name=r.rule_name,
            operator=r.operator,
            lb_threshold=r.lb_threshold,
            ub_threshold=r.ub_threshold,
            unit=r.unit,
            severity=r.severity,
            notify_roles=r.notify_roles,
            notify_channels=r.notify_channels,
            ack_minutes=r.ack_minutes,
            handle_minutes=r.handle_minutes,
            valid_from=eff.date(),
            valid_to=None,
            is_current=False,
            approval_status="PENDING",
            change_no=change_no,
            created_by=user.employee_id,
            created_at=datetime.now(),
        ))

    @classmethod
    async def _current_rules(
        cls, lab_code: str
    ) -> List[M13CriticalRule]:
        """当前生效规则。"""
        return (await _session().execute(
            select(M13CriticalRule).where(
                M13CriticalRule.lab_code == lab_code,
                M13CriticalRule.is_current.is_(True),
                M13CriticalRule.is_deleted.is_(False))
        )).scalars().all()

    @classmethod
    async def set_applicable(
        cls, lab_code: str, body: Any, user: Any
    ) -> Dict[str, Any]:
        """设置危急适用性。"""
        item = await ItemService._get(lab_code)
        if not body.is_critical_applicable:
            if len((body.reason or "").strip()) < 20:
                raise BizException(
                    "1305030",
                    "取消适用性必须说明原因（不少于 20 字）")
        old = item.is_critical_applicable
        item.is_critical_applicable = body.is_critical_applicable
        item.updated_by = user.employee_id
        item.updated_at = datetime.now()
        await ItemService._log(
            lab_code, "CRITICAL_RULE", "UPDATE",
            "设置危急适用性 %s → %s"
            % (old, body.is_critical_applicable),
            {"is_critical_applicable": old},
            {"is_critical_applicable":
                 body.is_critical_applicable},
            [{"field": "is_critical_applicable",
              "old": old,
              "new": body.is_critical_applicable}],
            user, impact={"affected_combos": 0})
        await _session().commit()
        return {"lab_code": lab_code,
                "is_critical_applicable":
                    body.is_critical_applicable}

    @classmethod
    async def list_applicable(cls) -> Dict[str, Any]:
        """危急适用项目清单。"""
        rows = (await _session().execute(
            select(M13LabItemExt).where(
                M13LabItemExt.is_enabled.is_(True),
                M13LabItemExt.is_critical_applicable.is_(True),
                M13LabItemExt.is_deleted.is_(False))
        )).scalars().all()
        return {
            "items": [{
                "lab_code": r.lab_code,
                "lab_name": r.lab_name,
                "result_type": r.result_type,
                "is_critical_ready": r.is_critical_ready,
            } for r in rows],
            "total": len(rows),
            "ready": sum(1 for r in rows if r.is_critical_ready),
        }


class ImpactService:
    """影响面评估服务。"""

    @classmethod
    async def evaluate(
        cls, lab_code: str, rule_code: str,
        lb_threshold: Optional[float],
        ub_threshold: Optional[float],
        lookback_days: int,
    ) -> Dict[str, Any]:
        """评估阈值变更的影响面。"""
        end = date.today()
        start = end - timedelta(days=lookback_days)
        # 查历史结果值
        hist = (await _session().execute(text("""
            SELECT
                COUNT(*) AS total,
                COUNT(*) FILTER (
                    WHERE :lb IS NOT NULL
                      AND numeric_value < :lb::numeric) AS new_hit,
                COUNT(*) FILTER (
                    WHERE :ub IS NOT NULL
                      AND numeric_value > :ub::numeric) AS new_hit_ub
            FROM m13_lab_result
            WHERE lab_code = :code
              AND test_date BETWEEN :start AND :end
              AND numeric_value IS NOT NULL
        """).bindparams(
            lb=lb_threshold, ub=ub_threshold,
            code=lab_code, start=start, end=end)
        )).first()
        total = hist[0] or 0
        new_hit = (hist[1] or 0) + (hist[2] or 0)
        # 旧阈值命中数
        cur = await cls._current_threshold(lab_code, rule_code)
        if cur:
            old_hit = await cls._count_hit(
                lab_code, start, end, cur)
        else:
            old_hit = 0
        combos = await cls._combos_of(lab_code)
        item = await ItemService._get(lab_code)
        return {
            "lab_code": lab_code,
            "current_threshold": cur.get("lb") if cur else None,
            "new_threshold": lb_threshold,
            "lookback_days": lookback_days,
            "history_total": total,
            "history_in_range": old_hit,
            "future_no_alert": max(old_hit - new_hit, 0),
            "future_new_alert": max(new_hit - old_hit, 0),
            "affected_combos": combos,
            "coverage_before": 1.0 if item.is_critical_ready else 0.0,
            "coverage_after": 1.0,
            "notify_delta_per_day": round(
                (new_hit - old_hit) / max(lookback_days, 1), 2),
            "warning": (
                "下调后 %d 例原会触发危急值的结果将不再进入强制闭环，"
                "请确认临床可接受" % max(old_hit - new_hit, 0)),
        }

    @classmethod
    async def _current_threshold(
        cls, lab_code: str, rule_code: str
    ) -> Optional[Dict[str, Any]]:
        """当前阈值。"""
        r = (await _session().execute(
            select(M13CriticalRule).where(
                M13CriticalRule.lab_code == lab_code,
                M13CriticalRule.rule_code == rule_code,
                M13CriticalRule.is_current.is_(True))
        )).scalar_one_or_none()
        if r is None:
            return None
        return {"lb": r.lb_threshold, "ub": r.ub_threshold}

    @classmethod
    async def _count_hit(
        cls, lab_code: str, start: date, end: date,
        cur: Dict[str, Any],
    ) -> int:
        """统计旧阈值命中数。"""
        lb, ub = cur.get("lb"), cur.get("ub")
        row = (await _session().execute(text("""
            SELECT COUNT(*) FROM m13_lab_result
            WHERE lab_code = :code
              AND test_date BETWEEN :start AND :end
              AND numeric_value IS NOT NULL
              AND ((:lb IS NOT NULL
                    AND numeric_value < :lb::numeric)
                OR (:ub IS NOT NULL
                    AND numeric_value > :ub::numeric))
        """).bindparams(
            code=lab_code, start=start, end=end,
            lb=lb, ub=ub)
        )).scalar()
        return row or 0

    @classmethod
    async def _combos_of(
        cls, lab_code: str
    ) -> List[Dict[str, str]]:
        """包含该项目的组合项目。"""
        rows = (await _session().execute(text("""
            SELECT c.combo_code, c.combo_name
            FROM md_lab_combo_detail d
            JOIN md_lab_combo c ON c.id = d.combo_id
            WHERE d.lab_code = :code AND d.is_deleted = FALSE
        """).bindparams(code=lab_code))).all()
        return [{"combo_code": r[0], "combo_name": r[1]}
                for r in rows]

    @classmethod
    async def build_report(cls, change_no: str) -> Any:
        """生成影响面 PDF。"""
        detail = await HistoryService.get_change(change_no)
        return await _render_pdf(detail)


class CoverageService:
    """覆盖率服务。"""

    RANGE_TARGET = 0.95
    CRITICAL_TARGET = 1.0

    @classmethod
    async def dashboard(cls, stat_date: date) -> Dict[str, Any]:
        """规则健康看板。"""
        row = (await _session().execute(text("""
            SELECT
                COUNT(*) FILTER (WHERE is_enabled) AS enabled,
                COUNT(*) FILTER (
                    WHERE is_enabled AND is_range_ready) AS r_ready,
                COUNT(*) FILTER (
                    WHERE is_enabled
                      AND is_critical_applicable) AS c_applic,
                COUNT(*) FILTER (
                    WHERE is_enabled
                      AND is_critical_applicable
                      AND is_critical_ready) AS c_ready
            FROM m13_lab_item_ext
            WHERE is_deleted = FALSE
        """))).first()
        enabled = row[0] or 0
        r_ready = row[1] or 0
        c_applic = row[2] or 0
        c_ready = row[3] or 0
        pending = (await _session().execute(text("""
            SELECT COUNT(*) FROM m13_item_change_log
            WHERE approval_status = 'PENDING'
        """))).scalar() or 0
        pending_over = (await _session().execute(text("""
            SELECT COUNT(*) FROM m13_item_change_log
            WHERE approval_status = 'PENDING'
              AND created_at < NOW() - INTERVAL '48 hours'
        """))).scalar() or 0
        changes_30d = (await _session().execute(text("""
            SELECT COUNT(*) FROM m13_item_change_log
            WHERE created_at >= NOW() - INTERVAL '30 days'
        """))).scalar() or 0
        cat_rows = (await _session().execute(text("""
            SELECT
                lab_category AS category,
                COUNT(*) FILTER (WHERE is_enabled) AS enabled,
                COUNT(*) FILTER (
                    WHERE is_enabled AND is_range_ready) AS r_ready,
                COUNT(*) FILTER (
                    WHERE is_enabled
                      AND is_critical_applicable) AS c_applic,
                COUNT(*) FILTER (
                    WHERE is_enabled
                      AND is_critical_applicable
                      AND is_critical_ready) AS c_ready
            FROM m13_lab_item_ext
            WHERE is_deleted = FALSE
            GROUP BY lab_category
            ORDER BY lab_category
        """))).all()
        alerts = []
        if c_ready < c_applic:
            alerts.append({
                "level": "CRITICAL",
                "type": "CRITICAL_NOT_READY",
                "message": "危急阈值缺失 %d 项，目标覆盖率 100%%"
                           % (c_applic - c_ready),
                "count": c_applic - c_ready,
            })
        if enabled and r_ready / enabled < cls.RANGE_TARGET:
            alerts.append({
                "level": "WARNING",
                "type": "RANGE_NOT_READY",
                "message": "参考区间缺失 %d 项，覆盖率低于 95%%"
                           % (enabled - r_ready),
                "count": enabled - r_ready,
            })
        if pending_over:
            alerts.append({
                "level": "WARNING",
                "type": "APPROVAL_PENDING_TOO_LONG",
                "message": "%d 项变更待审批超过 48 小时"
                           % pending_over,
                "count": pending_over,
            })
        return {
            "stat_date": stat_date.isoformat(),
            "enabled_items": enabled,
            "range_ready": r_ready,
            "range_coverage": round(r_ready / enabled, 4)
                              if enabled else 0.0,
            "critical_applicable": c_applic,
            "critical_ready": c_ready,
            "critical_coverage": round(c_ready / c_applic, 4)
                                 if c_applic else 0.0,
            "pending_changes": pending,
            "pending_overdue": pending_over,
            "changes_30d": changes_30d,
            "alerts": alerts,
            "category_summary": [{
                "category": r[0],
                "category_name": r[0],
                "enabled": r[1],
                "range_ready": r[2],
                "range_coverage": round(r[2] / r[1], 4)
                                  if r[1] else 0.0,
                "critical_applicable": r[3],
                "critical_ready": r[4],
                "critical_coverage": round(r[4] / r[3], 4)
                                     if r[3] else 0.0,
            } for r in cat_rows],
        }

    @classmethod
    async def coverage(
        cls, stat_date: date, category: Optional[str]
    ) -> Dict[str, Any]:
        """按类别覆盖率明细。"""
        return await cls.dashboard(stat_date)

    @classmethod
    async def missing(
        cls, missing_type: str, category: Optional[str],
        page: int, page_size: int,
    ) -> Dict[str, Any]:
        """缺失清单。"""
        if missing_type == "CRITICAL":
            where = ("is_enabled = TRUE"
                     " AND is_critical_applicable = TRUE"
                     " AND is_critical_ready = FALSE")
        else:
            where = "is_enabled = TRUE AND is_range_ready = FALSE"
        params = {}
        if category:
            where += " AND lab_category = :cat"
            params["cat"] = category
        total = (await _session().execute(
            text("SELECT COUNT(*) FROM m13_lab_item_ext"
                 " WHERE is_deleted = FALSE AND " + where)
            .bindparams(**params))).scalar() or 0
        rows = (await _session().execute(
            text("SELECT lab_code, lab_name, lab_category,"
                 " result_type, updated_at"
                 " FROM m13_lab_item_ext"
                 " WHERE is_deleted = FALSE AND " + where
                 + " ORDER BY lab_category, lab_code"
                 " LIMIT :lim OFFSET :off")
            .bindparams(lim=page_size,
                        off=(page - 1) * page_size, **params))
        ).all()
        items = []
        for r in rows:
            items.append({
                "lab_code": r[0],
                "lab_name": r[1],
                "category": r[2],
                "result_type": r[3],
                "missing_rule": ("ALL"
                                 if missing_type == "CRITICAL"
                                 else "ALL"),
                "missing_desc": ("未配置任何危急规则"
                                 if missing_type == "CRITICAL"
                                 else "未配置参考区间"),
                "affected_combos": [
                    c["combo_name"]
                    for c in await ImpactService._combos_of(r[0])],
                "assigned_to": None,
                "days_missing": (date.today()
                                 - r[4].date()).days
                                if r[4] else 0,
            })
        return {"items": items, "total": total,
                "page": page, "page_size": page_size}

    @classmethod
    async def export_missing(cls, body: Any) -> Any:
        """导出缺失清单。"""
        data = await cls.missing(
            body.missing_type, body.category, 1, 50000)
        return _to_csv(
            ["lab_code", "lab_name", "category", "result_type",
             "missing_desc", "affected_combos", "days_missing"],
            data["items"])

    @classmethod
    async def daily_snapshot(cls, stat_date: date) -> Dict[str, Any]:
        """每日覆盖率快照。"""
        d = await cls.dashboard(stat_date)
        return {
            "stat_date": stat_date.isoformat(),
            "enabled_items": d["enabled_items"],
            "range_coverage": d["range_coverage"],
            "critical_coverage": d["critical_coverage"],
            "range_missing": (d["enabled_items"]
                              - d["range_ready"]),
            "critical_missing": (d["critical_applicable"]
                                 - d["critical_ready"]),
        }


class HistoryService:
    """变更历史与审批服务。"""

    MIN_REJECT_LEN = 10

    @classmethod
    async def list_changes(
        cls, q: Any, user: Any
    ) -> Dict[str, Any]:
        """变更审批列表。"""
        stmt = select(M13ItemChangeLog)
        if q.scope == "PENDING_ME":
            stmt = stmt.where(
                M13ItemChangeLog.approval_status == "PENDING")
        elif q.scope == "MY_SUBMIT":
            stmt = stmt.where(
                M13ItemChangeLog.operator_id
                == user.employee_id)
        else:
            stmt = stmt.where(
                M13ItemChangeLog.approval_status.in_(
                    ("APPROVED", "REJECTED")))
        total = (await _session().execute(
            select(func.count()).select_from(
                stmt.subquery()))).scalar() or 0
        rows = (await _session().execute(
            stmt.order_by(M13ItemChangeLog.id.desc())
            .offset((q.page - 1) * q.page_size)
            .limit(q.page_size))).scalars().all()
        return {
            "items": [_change_brief(r) for r in rows],
            "total": total,
            "page": q.page,
            "page_size": q.page_size,
        }

    @classmethod
    async def get_change(cls, change_no: str) -> Dict[str, Any]:
        """变更详情。"""
        row = (await _session().execute(
            select(M13ItemChangeLog).where(
                M13ItemChangeLog.change_no == change_no))
        ).scalar_one_or_none()
        if row is None:
            raise BizException(
                "1305034", "变更记录不存在: %s" % change_no)
        return {
            "change_no": row.change_no,
            "lab_code": row.lab_code,
            "change_type": row.change_type,
            "action": row.action,
            "summary": row.summary,
            "approval_status": row.approval_status,
            "approval_step": row.approval_step,
            "operator_id": row.operator_id,
            "operator_name": row.operator_name,
            "created_at": _fmt(row.created_at),
            "before": row.before_json,
            "after": row.after_json,
            "changes": row.changes_json,
            "impact": row.impact_json,
            "approved_by_name": row.approved_by_name,
            "approved_at": _fmt(row.approved_at),
            "reject_reason": row.reject_reason,
            "effective_at": _fmt(row.effective_at),
        }

    @classmethod
    async def approve(
        cls, change_no: str, body: Any, user: Any
    ) -> Dict[str, Any]:
        """批准变更。"""
        row = await cls._get_for_update(change_no)
        if row.approval_status != "PENDING":
            raise BizException(
                "1305034", "变更状态不允许审批")
        if row.operator_id == user.employee_id:
            raise BizException(
                "1305026", "不能审批自己提交的变更")
        # 层级校验
        need = row.approval_step
        if need == "MEDICAL_AFFAIRS" and not _has_perm(
                user, "m13:critical:approve"):
            raise BizException(
                "1305032", "危急阈值变更须医务科审批")
        if need == "DEPT_DIRECTOR" and not _has_perm(
                user, "m13:range:approve"):
            raise BizException(
                "1305031", "无审批权限")
        if not getattr(body, "acknowledged_impact", False):
            raise BizException(
                "1305033", "请先确认已查看影响面评估")
        row.approval_status = "APPROVED"
        row.approved_by = user.employee_id
        row.approved_by_name = user.employee_name
        row.approved_at = datetime.now()
        row.approve_comment = body.comment
        # 同步子表状态
        await cls._sync_sub_status(
            row.change_no, "APPROVED", row.effective_at)
        await _session().commit()
        return {
            "change_no": change_no,
            "approval_status": "APPROVED",
            "approved_by_name": user.employee_name,
            "approved_at": _fmt(row.approved_at),
            "effective_at": _fmt(row.effective_at),
            "scheduled_job": "m13_005_apply_rules",
        }

    @classmethod
    async def reject(
        cls, change_no: str, body: Any, user: Any
    ) -> Dict[str, Any]:
        """驳回变更。"""
        row = await cls._get_for_update(change_no)
        if row.approval_status != "PENDING":
            raise BizException(
                "1305034", "变更状态不允许驳回")
        if len((body.reason or "").strip()) < cls.MIN_REJECT_LEN:
            raise BizException(
                "1305033", "驳回原因不得少于 10 个字符")
        row.approval_status = "REJECTED"
        row.reject_reason = body.reason
        row.approved_by = user.employee_id
        row.approved_by_name = user.employee_name
        row.approved_at = datetime.now()
        await cls._sync_sub_status(
            row.change_no, "REJECTED", None)
        await _session().commit()
        return {"change_no": change_no,
                "approval_status": "REJECTED"}

    @classmethod
    async def _get_for_update(
        cls, change_no: str
    ) -> M13ItemChangeLog:
        """加行锁取变更。"""
        row = (await _session().execute(
            select(M13ItemChangeLog)
            .where(M13ItemChangeLog.change_no == change_no)
            .with_for_update()
        )).scalar_one_or_none()
        if row is None:
            raise BizException("1305034", "变更记录不存在")
        return row

    @classmethod
    async def _sync_sub_status(
        cls, change_no: str, status: str,
        effective_at: Optional[datetime],
    ) -> None:
        """同步规则子表状态。"""
        await _session().execute(text("""
            UPDATE m13_critical_rule

    async def list_history(cls, q: Any) -> Dict[str, Any]:
        """变更历史查询。"""
        stmt = select(M13ItemChangeLog)
        if q.lab_code:
            stmt = stmt.where(
                M13ItemChangeLog.lab_code == q.lab_code)
        if q.change_type:
            stmt = stmt.where(
                M13ItemChangeLog.change_type == q.change_type)
        if q.action:
            stmt = stmt.where(
                M13ItemChangeLog.action == q.action)
        if q.start_date:
            stmt = stmt.where(
                M13ItemChangeLog.created_at
                >= datetime.combine(q.start_date,
                                    datetime.min.time()))
        if q.end_date:
            stmt = stmt.where(
                M13ItemChangeLog.created_at
                <= datetime.combine(q.end_date,
                                    datetime.max.time()))

            stmt = stmt.where(
                M13ItemChangeLog.operator_id == q.operator_id)
        total = (await _session().execute(
            select(func.count()).select_from(
                stmt.subquery()))).scalar() or 0
        rows = (await _session().execute(
            stmt.order_by(M13ItemChangeLog.id.desc())
            .offset((q.page - 1) * q.page_size)
            .limit(q.page_size))).scalars().all()
        return {
            "items": [_change_brief(r) for r in rows],
            "total": total,
            "page": q.page,
            "page_size": q.page_size,
        }

    @classmethod
    async def audit_summary(cls, days: int) -> Dict[str, Any]:
        """自动生成审计要点。"""

                    WHERE approval_status = 'PENDING') AS pending,
                COUNT(*) FILTER (
                    WHERE summary IS NULL
                       OR length(trim(summary)) = 0) AS no_reason
            FROM m13_item_change_log
            WHERE created_at >= NOW()
                  - make_interval(days => :d)

        items = [

             "ok": True},
            {"label": "无原因变更",
             "text": "共 %d 条" % (row[5] or 0),
             "ok": (row[5] or 0) == 0},
        ]
        return {"days": days, "items": items,
                "all_ok": all(i["ok"] for i in items)}

    @classmethod
    async def export(cls, body: Any) -> Any:
        """导出变更历史。"""
        q = HistoryQuery(

             "created_at"],
            data["items"])
```

### 6.7 规则生效定时应用

**审批通过的规则不会立即生效，而是由定时任务在生效时刻应用。**

```python
"""M13-05 规则生效应用。"""
import logging
from datetime import date, datetime

from sqlalchemy import select, text
from sqlalchemy.ext.asyncio import AsyncSession

from app.core.redis_client import redis_client
from app.models.m13_lab_item import (
    M13CriticalRule,
    M13LabItemExt,
    M13RefRange,
)

logger = logging.getLogger("m13.labitem.apply")


class RuleApplyService:
    """规则生效应用服务。"""

    @classmethod
    async def apply_due_rules(cls) -> dict:
        """应用到期的规则变更。"""
        now = datetime.now()
        applied_rules = await cls._apply_critical(now)
        applied_ranges = await cls._apply_range(now)
        await cls._refresh_ready_flags()
        await cls._clear_caches(applied_rules, applied_ranges)
        await cls._audit(applied_rules, applied_ranges)
        return {
            "applied_critical": applied_rules,
            "applied_range": applied_ranges,
            "applied_at": now.strftime("%Y-%m-%d %H:%M:%S"),
        }

    @classmethod
    async def _apply_critical(cls, now: datetime) -> list:
        """应用到期的危急规则。"""
        rows = (await _session().execute(text("""
            UPDATE m13_critical_rule
               SET is_current = TRUE
             WHERE approval_status = 'APPROVED'
               AND is_current = FALSE
               AND valid_from <= :today
               AND is_deleted = FALSE
            RETURNING lab_code, rule_code
        """).bindparams(today=now.date()))).all()
        return ["%s:%s" % (r[0], r[1]) for r in rows]

    @classmethod
    async def _apply_range(cls, now: datetime) -> list:
        """应用到期的参考区间版本。"""
        rows = (await _session().execute(text("""
            WITH due AS (
                SELECT lab_code, version_no
                  FROM m13_ref_range
                 WHERE approval_status = 'APPROVED'
                   AND valid_from <= :today
                   AND is_deleted = FALSE
                 GROUP BY lab_code, version_no
                HAVING MAX(is_current::int) = 0
                   AND (MAX(valid_to) IS NULL
                        OR MAX(valid_to) >= :today)
            )
            UPDATE m13_ref_range r
               SET is_current = TRUE
              FROM due
             WHERE r.lab_code = due.lab_code
               AND r.version_no = due.version_no
               AND r.is_deleted = FALSE
            RETURNING r.lab_code, r.version_no
        """).bindparams(today=now.date()))).all()
        return ["%s:V%d" % (r[0], r[1]) for r in rows]

    @classmethod
    async def _refresh_ready_flags(cls) -> None:
        """刷新就绪标记。"""
        await _session().execute(text("""
            UPDATE m13_lab_item_ext i
               SET is_range_ready = EXISTS (
                       SELECT 1 FROM m13_ref_range r
                        WHERE r.lab_code = i.lab_code
                          AND r.is_current = TRUE
                          AND r.is_enabled = TRUE
                          AND r.is_deleted = FALSE),
                   is_critical_ready = (
                       i.is_critical_applicable = FALSE
                       OR EXISTS (
                           SELECT 1 FROM m13_critical_rule c
                            WHERE c.lab_code = i.lab_code
                              AND c.is_current = TRUE
                              AND c.approval_status = 'APPROVED'
                              AND c.is_deleted = FALSE)),
                   updated_at = NOW()
             WHERE i.is_deleted = FALSE
        """))
        await _session().commit()

    @classmethod
    async def _clear_caches(
        cls, rules: list, ranges: list
    ) -> None:
        """清除受影响项目的规则缓存。"""
        codes = set()
        for r in rules:
            codes.add(r.split(":")[0])
        for r in ranges:
            codes.add(r.split(":")[0])
        for c in codes:
            await redis_client.delete("m13:labitem:rule:%s" % c)

    @classmethod
    async def _audit(cls, rules: list, ranges: list) -> None:
        """写审计日志。"""
        logger.info(
            "规则生效应用",
            extra={
                "module": "M13-05",
                "action": "apply_rules",
                "critical_count": len(rules),
                "range_count": len(ranges),
                "critical_items": rules[:20],
                "range_items": ranges[:20],
            })
```

**为什么规则生效要用定时任务而不是"审批通过后立即写 `is_current`"？**

因为 `is_current` 的语义是"此刻正在使用"。如果审批时（可能距生效还有 24 小时）就把新版本置为 `is_current`，那这 24 小时内的判定就会用新规则——24 小时缓冲完全失效。

定时任务每分钟执行一次，检查"`approval_status='APPROVED'` 且 `valid_from <= today` 且 `is_current=FALSE`"的记录，把它置为当前。这样**审批与生效彻底解耦**，生效时刻由数据而不是流程决定。

## 7. 缓存与异步任务设计

### 7.1 Redis 缓存

| Key 模式 | 类型 | TTL | 说明 |
|---|---|---|---|
| `m13:labitem:rule:{lab_code}` | String | 300s | 项目完整规则（区间+阈值）JSON |
| `m13:labitem:coverage:{date}` | String | 300s | 覆盖率快照 |
| `m13:labitem:change:seq:{yyyymmdd}` | String | 172800s | 变更号序列 |
| `m13:labitem:applicable` | String | 600s | 危急适用项目清单 |
| `m13:labitem:config` | Hash | 600s | 配置项 |
| `m13:labitem:apply:lock` | String | 120s | 生效任务互斥锁 |

**容量估算：**

| Key 模式 | 条数 | 单条 | 合计 |
|---|---|---|---|
| rule | 186 | 3KB | 558KB |
| coverage | 1 | 4KB | 4KB |
| change:seq | 1 | 20B | 20B |
| applicable | 1 | 12KB | 12KB |
| config | 1 | 2KB | 2KB |
| apply:lock | 1 | 50B | 50B |
| **合计** | — | — | **约 576KB** |

**为什么规则缓存 TTL 只有 300s？**

因为规则是判定依据，缓存陈旧会导致"按旧阈值报警"或"不报警"。300 秒是"最坏情况下陈旧多久"的上限。变更时主动失效（`RuleApplyService._clear_caches`）把实际延迟降到接近 0，TTL 只是 Redis 抖动时的兜底。

**为什么规则缓存存"项目全部版本"而不是"当前生效版本"？**

因为判定需要按 `test_time` 匹配历史版本。M13-03 补解析一份 2025 年的报告时，需要 2025 年那时的区间。缓存全部版本（通常 2~3 个，最多 10 个）代价可控，避免了"历史查询永远穿透缓存"的问题。

**为什么覆盖率快照要缓存？**

覆盖率看板每 5 分钟被多个人（主任、信息员、质控）打开，每次都要扫 186 行 + 5 个聚合查询。缓存 5 分钟后，同一时刻只有第一个人付数据库成本。

```python
async def _approval_timeout():
    """处理超时审批。"""
    # 48 小时提醒
    remind = (await _session().execute(text("""
        SELECT change_no, operator_name, approval_step
          FROM m13_item_change_log
         WHERE approval_status = 'PENDING'
           AND created_at < NOW() - INTERVAL '48 hours'
           AND reminded_at IS NULL
    """))).all()
    # 7 天自动驳回
    expired = (await _session().execute(text("""
        UPDATE m13_item_change_log
           SET approval_status = 'REJECTED',
               reject_reason = '超过 7 天未审批，系统自动驳回',
               approved_at = NOW()
         WHERE approval_status = 'PENDING'
           AND created_at < NOW() - INTERVAL '7 days'
        RETURNING change_no
    """))).all()
    await _session().commit()
    return {
        "reminded": len(remind),
        "auto_rejected": len(expired),
    }


@shared_task(bind=True, max_retries=2)
def missing_alert_task(self):
    """危急覆盖率低于 100% 时告警。"""
    try:
        return asyncio.run(_missing_alert())
    except Exception as exc:
        logger.exception("缺失告警任务失败")
        raise self.retry(exc=exc)


async def _missing_alert():
    """发送缺失告警。"""
    row = (await _session().execute(text("""
        SELECT
            COUNT(*) FILTER (
                WHERE is_enabled
                  AND is_critical_applicable
                  AND NOT is_critical_ready) AS missing
        FROM m13_lab_item_ext
        WHERE is_deleted = FALSE
    """))).scalar() or 0
    if missing:
        logger.warning(
            "危急阈值缺失 %d 项", missing,
            extra={"module": "M13-05",
                   "action": "missing_alert"})
    return {"missing": missing}
```

**为什么"应用到期规则"每分钟跑？**

因为生效时刻可能设定为任意分钟（比如 `2026-10-23 00:00`）。如果每小时跑一次，最坏延迟 59 分钟。每分钟跑一次，最坏 60 秒。这个任务的单次成本很低（通常 0 行更新，偶尔 1~3 行），1 分钟一次完全可接受。

**为什么"同步项目"每日跑一次而不是实时？**

M01-09 的项目变更频率极低（一周可能新增 1~2 个），每日同步完全够用。实时同步（M01 改了就推）需要两模块间的事件机制，复杂度高、收益低。真需要即时可见时，用户点"立即同步"按钮（API-10）即可。

**为什么检验科主任能编辑危急阈值但不能审批？**

因为双人复核要求"自己改的不能自己批"。如果主任既能改又能批，双人复核就名存实亡。主任负责**提出**（基于临床经验判断阈值是否合适），医务科负责**批准**（从全院医疗安全角度审核）。这是一个制衡结构。

**为什么医务科没有 `critical:edit`？**

因为阈值的技术判断（配多少、配几条、用什么运算符）需要检验专业知识。医务科的角色是审核"这个变更的风险临床能否接受"，不是"这个阈值配得对不对"。让医务科去编辑阈值，是让他们做不专业的事。

**为什么 IT 管理员有 `item:manage` 但完全没有 `range:edit` / `critical:edit`？**

项目属性（别名、格式、排序）是配置工作，IT 可以做。但参考区间和危急阈值是**医学判断**，IT 只有系统知识，不能决定"血钾多少算危急"。

**为什么"紧急立即生效"单独一个权限？**

因为它绕过了 24 小时缓冲——这正是双人复核设计的核心保护。授予这个权限等于授予"可以无视临床缓冲"的能力，应该是极少数人（主任 + 医务科），且每次使用都进审计。

### 9.3 数据权限

| 角色 | 可见范围 |
|---|---|
| 检验科主任/信息员/技师 | 全院检验项目与规则 |
| 医务科 | 全院（含全部历史版本与变更） |
| 临床医师 | 全院项目规则（只读，规则本身无患者信息） |
| 质控科 | 全院（只读） |
| IT 管理员 | 全院（技术配置，不含患者数据） |

**为什么这里的数据权限基本等于"全院"？**

因为 M13-05 管的是**规则**而不是**患者数据**——"血钾的参考区间是 3.5~5.3"这条信息对全院、所有科室都相同，不存在"某科室的参考区间不同"。真正需要按科室隔离的是**业务数据**（报告、申请），那些在 M13-01/03/04 中控制。

### 9.4 安全措施

| 措施 | 说明 |
|---|---|
| SQL 注入防护 | 全部走 SQLAlchemy 参数化或 `bindparams` |
| 变更审计 | 所有变更写 `m13_item_change_log`（只增） |
| 双人复核 | 危急阈值与区间变更强制 |
| 生效缓冲 | 危急阈值变更 ≥24 小时延后 |
| 权限校验 | 每个写接口 `require_permission` |
| 内部契约鉴权 | 内部接口校验 `X-Internal-Token` |
| 导出限制 | ≤50000 行，防大批量数据外泄 |
| 敏感操作二次确认 | 立即生效、取消适用性需勾选确认 |

**为什么变更日志要"只增"（DB 触发器禁止 UPDATE/DELETE）？**

因为它是**审计证据**。如果可以被改，那么"谁改了什么"这件事就没有可信度。数据库层的触发器比应用层更可靠——应用层可以被绕过（DBA 手动 SQL、其他服务误写），触发器不会。

**SLA 为什么这么严？**

因为 P-01 在检验结果判定的**热路径**上。一份血常规 24 个项目，每个项目都要查一次规则；如果单次 100ms，整份报告判定要多花 2.4 秒。P95 ≤ 10ms 的要求把判定逻辑的规则查询开销压到可忽略。

**如何做到 ≤10ms？** 三层：①Redis 缓存 300s（命中率 >99%）②未命中时查 DB（单条记录查询约 3~5ms）③批量接口把 24 次单查合并为 1 次批量查。

**为什么"立即生效调用次数 > 0"要告警？**

因为立即生效绕过了 24 小时缓冲，是本设计特意保留的"应急通道"。每次使用都应该有明确理由并被复核。如果一个月出现多次，说明 24 小时缓冲的设计与本医院实际流程不匹配，需要重新评估；如果一次都没有，说明这个通道可能根本不需要。**无论哪种情况都需要人看一眼。**

## 附录 B：参考区间分层维度

| 维度 | 取值 | 数据来源 | 匹配优先级 |
|---|---|---|---|
| 性别 | `M` / `F` / `NULL`(通用) | M03-01 患者 | 8 |
| 年龄段 | `age_min` ~ `age_max`（整数年） | 由出生日期算 | 4 |

| 仪器 | `device_code` | M01-09 设备 | 1 |

**匹配算法（权重降序 + 有效期降序）：**

```
1. 过滤：valid_from <= test_date <= (valid_to or ∞)
2. 过滤：gender 为 NULL 或等于患者性别
3. 过滤：年龄段包含患者年龄
4. 过滤：生理状态为 NULL 或等于患者状态
5. 排序：权重 DESC, valid_from DESC
6. 取第一条
```

| 乳酸 LAB_LAC | LAC_HIGH | GT | 4.0 mmol/L | CRITICAL |

**为什么血钾危急低值建议 2.5 而参考下限是 3.5？**

中间 1.0 mmol/L 的缓冲区（2.5~3.5）就是"异常但不危急"的地带。低钾血症 3.0~3.5 通常口服补钾即可（门诊傍晚处理没问题），2.5~3.0 需要关注但不必立即干预，< 2.5 则可能诱发严重心律失常必须立即处理。这个分级是临床经验的沉淀，不是随意设定的数字。
