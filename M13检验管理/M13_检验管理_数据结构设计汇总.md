## 1. 全局设计规范

### 1.1 表名前缀

```
m13_lab_*          检验申请、项目、任务
m13_specimen*      标本
m13_recollect      重采
m13_report_*       报告文件、版本、发布、组装
m13_parse_*        OCR 解析
m13_collect_*      文件采集
m13_inspection*    文件巡检
m13_review_*       审核
m13_critical_*     危急值、危急阈值
m13_ref_range      参考区间
m13_lab_item_*     项目扩展与配置
m13_item_change*   规则变更留痕
m13_coverage*      覆盖率快照
m13_report_format  报告格式模板
m13_micro_*        微生物
m13_referral_*     外送
m13_sys_config     系统参数
```

### 1.2 字段规范

**每张业务表必须有 6 个标准字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 主键 |
| `created_at` | `TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP` | 创建时间 |
| `created_by` | `BIGINT` | 创建人 |
| `updated_at` | `TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP` | 更新时间 |
| `updated_by` | `BIGINT` | 更新人 |
| `is_deleted` | `BOOLEAN NOT NULL DEFAULT FALSE` | 软删除标记 |

**软删除 + 部分唯一索引是 M13 的硬性约定。** 所有唯一索引必须带 `WHERE is_deleted = FALSE`。

### 1.3 枚举用 VARCHAR + CHECK

同 M12。M13 的 4 个高频枚举在开发期会增删值：

- 标本拒收原因（8 类，可能扩展）
- 解析失败原因（8 类）
- 待确认原因（5 类）
- 危急值状态（9 态）

**PG ENUM 的 `ALTER TYPE ... ADD VALUE` 不能在事务中执行**，会阻塞迁移脚本。用 `VARCHAR + CHECK` + 应用层 `Literal` 双重约束。

### 1.4 时间语义

| 类型 | 用途 | 示例 |
|---|---|---|
| `TIMESTAMP` | 业务时刻（东八区本地时间） | `collected_at`、`reviewed_at` |
| `DATE` | 业务日期 | `test_date`、`seq_date` |
| `TIME` | 时段 | 不常用 |

**同 M12：不用 `TIMESTAMPTZ`。** 单院区单时区部署。

### 1.5 金额与数值

| 类型 | 用途 | 精度 |
|---|---|---|
| `NUMERIC(12,2)` | 金额 | 元，2 位 |
| `NUMERIC(12,4)` | **检验结果数值**（血钾 5.2530） | 4 位 |
| `NUMERIC(5,4)` | 置信度 | 0.0000~1.0000 |
| `NUMERIC(8,6)` | 覆盖率/错误率 | 0.000000~1.000000 |
| `NUMERIC(7,4)` | 税率/折扣率 | 百分比数值（13.0000 = 13%） |
| `INTEGER` | 计数、分钟、秒 | — |

**禁止 `FLOAT`。** 检验结果用 `NUMERIC(12,4)` 而非 `FLOAT` 的关键理由：区间判定是"与边界比较"，浮点误差会让 `3.5000` 被判成 `3.4999999` 从而误判为 LOW。

**`MIC` 值例外用 `VARCHAR(16)`：** MIC 的标准表达是 `>32` / `<=0.25`，带运算符，无法用 NUMERIC 表示。

### 1.6 参考区间的两个数值类型

`m13_ref_range` 中：

| 字段 | 类型 | 说明 |
|---|---|---|
| `range_low` | `NUMERIC(12,4)` | 下限 |
| `range_high` | `NUMERIC(12,4)` | 上限 |
| `range_low_display` | `VARCHAR(32)` | 展示形式（`<0.5`、`阴性`） |

**为什么要 display 字段：** 有些区间无法用数值表达（`<0.5`、`阴性`、`未见`）。数值用于判定，display 用于报告展示。

### 1.7 字符集与排序

同 M12：`UTF8` / `zh_CN.utf8` / `pg_trgm` + GIN

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX idx_m13_parse_name_trgm ON m13_parse_record
    USING gin (patient_name gin_trgm_ops);
```

### 1.8 必需的 PostgreSQL 扩展

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;      -- 中文模糊搜索
CREATE EXTENSION IF NOT EXISTS btree_gist;   -- 参考区间排他约束
```

**`btree_gist` 是 M13-05 的硬依赖。** `m13_ref_range` 的 `EXCLUDE USING gist` 排他约束需要它。上线前必须由 DBA 创建。

### 1.9 updated_at 自动维护

```sql
CREATE OR REPLACE FUNCTION fn_m13_set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

每张业务表挂 `BEFORE UPDATE` 触发器。

### 3.4 关联方式：逻辑外键

**42 张表全部不加物理外键。** 理由同 M12：

1. 性能（高频写入）
2. 解耦（独立归档）
3. 分区兼容

**一致性三层保证：**

| 层 | 手段 |
|---|---|
| 应用层 | 事务内成对写入 |
| 约束层 | `CHECK` 验证关联标识非空 |
| 巡检层 | 每日 04:00 查孤儿数据 |

**（2）部分保护（仅核心字段不可改）**

```sql
CREATE OR REPLACE FUNCTION fn_m13_chg_log_readonly()
RETURNS TRIGGER AS $$
BEGIN
    IF TG_OP = 'DELETE' THEN
        RAISE EXCEPTION 'm13_item_change_log 禁止 DELETE';
    END IF;
    IF (NEW.change_no    IS DISTINCT FROM OLD.change_no
     OR NEW.lab_code     IS DISTINCT FROM OLD.lab_code
     OR NEW.change_type  IS DISTINCT FROM OLD.change_type
     OR NEW.action       IS DISTINCT FROM OLD.action
     OR NEW.changes_json IS DISTINCT FROM OLD.changes_json
     OR NEW.operator_id  IS DISTINCT FROM OLD.operator_id
     OR NEW.created_at   IS DISTINCT FROM OLD.created_at) THEN
        RAISE EXCEPTION 'm13_item_change_log 核心字段不可修改';
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

适用：`m13_item_change_log`

### 6.5 部分唯一索引中 `COALESCE` 的必要性

```sql
CREATE UNIQUE INDEX uk_m13_template_current
    ON m13_parse_template (COALESCE(device_code, ''), template_key)
    WHERE is_current = TRUE AND is_deleted = FALSE;

CREATE UNIQUE INDEX uk_m13_parse_config
    ON m13_parse_config (param_code, scope, COALESCE(scope_id, ''))
    WHERE is_deleted = FALSE;

CREATE UNIQUE INDEX uk_m13_collect_config
    ON m13_collect_config (param_code, scope, COALESCE(scope_id, ''))
    WHERE is_deleted = FALSE;
```

**PostgreSQL 认为 `NULL` 与 `NULL` 不相等。** 不加 COALESCE：

- 两条 `device_code IS NULL` 的通用模板都能是"当前版"
- 同一参数可以有两份 `scope_id=NULL` 的 GLOBAL 记录

**为什么不用 `NULLS NOT DISTINCT`：** PG 15+ 特性，本项目部分测试环境仍是 PG 14。

### 6.6 参考区间的排他约束详解

**这是 M13 最复杂的一条约束。**

```sql
ALTER TABLE m13_ref_range
    ADD CONSTRAINT ex_m13_range_no_overlap
    EXCLUDE USING gist (
        lab_code WITH =,
        COALESCE(gender, '') WITH =,
        COALESCE(age_min, -1) WITH =,
        COALESCE(age_max, 999) WITH =,
        COALESCE(physiological_state, '') WITH =,
        COALESCE(device_code, '') WITH =,
        daterange(valid_from, valid_to, '[]') WITH &&
    ) WHERE (is_deleted = FALSE AND approval_status IN ('APPROVED', 'PENDING'));
```

**六个要点：**

1. **必须 `COALESCE` 每一个可空的分层维度**——否则两条 `gender IS NULL` 的通用区间可都覆盖同一时段
2. **`age_min` 用 `-1`，`age_max` 用 `999`**——语义相反（无下限 vs 无上限）
3. **`daterange(..., '[]')` 闭区间**——有效日期包含首尾两天
4. **`WITH &&`**——时间段重叠
5. **`WHERE` 过滤**——只对 `APPROVED`/`PENDING` 的生效，草稿和历史不参与
6. **前置依赖 `btree_gist`**——标准 gist 不支持标量列的 `=` 比较

**为什么用 `valid_from`/`valid_to` 的 `daterange` 而不加显式 `is_current` 参与约束：** `is_current` 是派生字段（由定时任务按 `valid_from <= today` 打标），把它放进约束会导致"定时任务还没跑时约束判定错误"。

### 9.2 参数表统一结构

```sql
CREATE TABLE m13_parse_config (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    param_code   VARCHAR(64)  NOT NULL,
    param_name   VARCHAR(128) NOT NULL,
    param_value  VARCHAR(500) NOT NULL,
    param_type   VARCHAR(16)  NOT NULL,
    param_group  VARCHAR(32)  NOT NULL,
    scope        VARCHAR(16)  NOT NULL DEFAULT 'GLOBAL',
    scope_id     VARCHAR(64),
    min_value    VARCHAR(64),
    max_value    VARCHAR(64),
    is_sensitive BOOLEAN      NOT NULL DEFAULT FALSE,
    is_editable  BOOLEAN      NOT NULL DEFAULT TRUE,
    sort_no      INTEGER      NOT NULL DEFAULT 0,
    remark       VARCHAR(500),
    version      INTEGER      NOT NULL DEFAULT 1,
    created_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    is_deleted   BOOLEAN      NOT NULL DEFAULT FALSE,
    CONSTRAINT ck_m13_pcfg_code
        CHECK (param_code ~ '^M13\.[A-Z][A-Z0-9_]*\.[A-Z][A-Z0-9_]*$'),
    CONSTRAINT ck_m13_pcfg_type
        CHECK (param_type IN ('STRING', 'INT', 'FLOAT', 'BOOL')),
    CONSTRAINT ck_m13_pcfg_scope
        CHECK (scope IN ('GLOBAL', 'DEVICE', 'LAB_CODE')),
    CONSTRAINT ck_m13_pcfg_global
        CHECK (scope <> 'GLOBAL' OR scope_id IS NULL),
    CONSTRAINT ck_m13_pcfg_scope_id
        CHECK (scope = 'GLOBAL' OR scope_id IS NOT NULL),
    CONSTRAINT ck_m13_pcfg_range
        CHECK (param_type NOT IN ('INT', 'FLOAT')
               OR (min_value IS NOT NULL AND max_value IS NOT NULL)),
    CONSTRAINT ck_m13_pcfg_sensitive
        CHECK (is_sensitive = FALSE OR is_editable = TRUE)
);

CREATE UNIQUE INDEX uk_m13_parse_config
    ON m13_parse_config (param_code, scope, COALESCE(scope_id, ''))
    WHERE is_deleted = FALSE;
```

### 9.3 六个关键参数（安全红线）

| 参数 | 默认值 | 只读/敏感 | 后果 |
|---|---|---|---|
| `M13.VERIFY.MIN_REGRESSION_RATE` | 0.98 | 敏感 | 调低会让质量差的模板通过 |
| `M13.PARSE.CRITICAL_FIELDS` | `WBC,HGB,PLT,K,NA,GLU,ALT,CR,PT,INR` | 敏感 | 改错会让关键字段不再强制确认 |
| `M13.PARSE.CONFIDENCE_AUTO` | 0.95 | 敏感 | 调低会让低质量数据被自动采用 |
| `M13.CRITICAL.ESCALATE_1_MINUTES` | 15 | 敏感 | 调大延误危急值通知 |
| `M13.LABITEM.CRITICAL_TARGET` | 1.0 | **只读** | 安全红线，min=max=1.0 |
| `M13.MICRO.INTRAOCULAR_MIN_DAYS` | 5 | 敏感 | 调小会降低眼内感染检出率 |

**`M13.LABITEM.CRITICAL_TARGET` 是唯一一个 `is_editable=FALSE` 且 `is_sensitive=TRUE` 的参数。** 它不是"配置"，是"承诺"——危急阈值覆盖率必须 100%，这条数字不允许任何人改。

### 9.4 参数作用域

| scope | 说明 | 示例 |
|---|---|---|
| `GLOBAL` | 全局 | `M13.PARSE.OCR_DPI = 200` |
| `DEVICE` | 仪器级 | `M13.PARSE.OCR_DPI` on `LAB-URINE-01` = 300 |
| `LAB_CODE` | 项目级（M13-05） | 特定项目的特殊阈值 |

**为什么仪器级：** 数字 PDF 的 OCR DPI 200 够用、扫描件需要 300。只有全局参数会导致所有解析按最差配置走。

**为什么绑定参数（姓名匹配、年龄容差）必须全局：** 关系到错绑风险，不能按仪器放松。
