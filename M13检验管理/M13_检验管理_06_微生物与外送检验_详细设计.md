## 1. 模块概述

### 1.1 模块定位

M13-06 是 M13 检验管理里唯一"**结果不是一次出完**"的子模块。它解决两类"慢检验"场景：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        M13-06 微生物与外送检验                       │
│                     "跨天出结果、跨机构出结果"                        │
└─────────────────────────────────────────────────────────────────────┘

   场景 A：微生物培养（院内）              场景 B：外送检验（院外）
   ┌────────────────────────┐            ┌────────────────────────┐
   │ D0  标本接种            │            │ D0  标本采集            │
   │      ↓ 16~24h           │            │      ↓ 冷链打包        │
   │ D1  初报：革兰染色      │            │ D0  物流交接            │
   │      镜检形态 + 染色   │            │      ↓ 次日送达        │
   │      ↓ 16~24h           │            │ D1  外送机构接收        │
   │ D2  中报：菌种鉴定      │            │      ↓ 3~7 天          │
   │      （种属 + 生化）    │            │ D5  报告返回（PDF/接口）│
   │      ↓ 16~24h           │            │      ↓                 │
   │ D3  终报：药敏 + 结论   │            │ D5  M13-02/03 解析      │
   │      （MIC + 敏感度）   │            │      ↓                 │
   └────────────────────────┘            │ D5  合并到任务          │
                                          └────────────────────────┘

   共同难点：
   ① 一份标本对应 N 个检验任务，结果分多批产生
   ② 每批结果的"就绪"时刻不同，不能一次性推送 M07
   ③ 最终报告要"汇总多次结果"，且医生端只应看到一份完整报告
   ④ 中间结果（初报："找到革兰阳性球菌"）对临床有即时价值，
      但不能与终报混为一谈
```

**M13-06 的核心职责**：管理"结果分批产生"这件事的**全过程与最终组装**。

| 职责 | 说明 |
|---|---|
| 分批结果登记 | 初报/中报/终报三批结果各自独立登记，各自独立推送 |
| 培养过程跟踪 | 培养天数、阳性天数、阴性满 5 天可出阴性报告 |
| 药敏结果管理 | 多药物 × 多浓度（MIC）的敏感度判定 |
| 外送委托 | 委托单生成、打包清单、物流跟踪 |
| 外送回报 | 报告回传（PDF / 接口 / 手工录入）、结果合并、费用登记 |
| 组装最终报告 | 把 N 批结果组装成医生端看到的"一份报告" |
| 逾期管理 | 培养超时、外送回传超时、外送报告缺失 |

**一句话区分与相邻子模块：**

- **M13-01** 管"标本到了没有"（物理流转）
- **M13-02/03** 管"文件进来了、数据解析出来了"（技术处理）
- **M13-04** 管"这一批结果能不能发布给医生"（审核签字）
- **M13-06** 管"**这一份标本的多批结果怎么积累、最后怎么拼成一份**"（跨周期组装）
- **M13-05** 管"规则长什么样"（区间与阈值）

### 1.2 为什么独立成子模块

**理由一：微生物的结果模型与"一次性数值"根本不同。**

血常规是"20 项各一个数值，一次出完"。微生物是：

```
标本：左眼玻璃体液（M13-01 生成 1 个标本，3 个任务）
  ├── 任务1：涂片革兰染色 → D0 当日出（数值型：找到 G+ 球菌）
  ├── 任务2：细菌培养+鉴定 → D1 初报、D2 中报、D4 终报
  └── 任务3：真菌培养     → D3 阴/阳，D7 出终报
```

三个任务、四个时间点、若干批结果。用 M13-04 的"I 份解析对应 1 份报告"模型装不下——**M13-04 的 `uk_m13_review_parse` 是"一解析一报告"，而微生物需要"多任务多批次汇总成一份"**。

**理由二：中间结果有即时临床价值，必须独立发布。**

眼科最典型场景：玻璃体液涂片今天下午出"革兰阳性球菌"，医生当晚就要调整抗生素（万古霉素→头孢他啶+万古霉素联合）；而培养+药敏要到第 4 天才出。

如果强制"等终报一起发"，医生第 4 天才知道该用什么药；如果只发终报不发表述过程，医生不知道"中间调过药是基于什么"。所以**中间结果必须能发布、能留痕、能在最终报告里排成时间线**。

**理由三：外送检验的"机构外部"是全新的信任边界。**

院内检验：数据从我们自己控制的仪器出来，质量我自己负责。
外送检验：数据从**第三方机构**回来，我既不控制过程也不知道方法学细节，但**报告上盖的仍是我院的章**。

这带来院内检验没有的一组问题：

- 资质核验（外送机构是否有 CMA/CNAS 资质、是否在委托目录内）
- 标本保存与运输温度记录（冷链断了结果作废）
- 回报方式多样（PDF 邮件、SFTP、接口、电话口述、纸质邮寄）
- **回报缺失发现**（送了 20 份只回来 19 份，谁去追）
- **结果责任划分**（结果有误时，是我院解释还是外送机构）

把这些问题塞进 M13-04 会让 M13-04 从"审核签字"膨胀成"外部供应链管理"。

**理由四：超时管理的对象与口径完全不同。**

| 子模块 | 超时对象 | 口径 | 处置 |
|---|---|---|---|
| M13-01 | 送检超时 | 采集到签收 | 提示护士 |
| M13-04 | 审核超时 | 报告到发布 | 升级主任 |
| **M13-06** | **培养超时 / 外送逾期 / 回报缺失** | **接种到出结果 / 外送到回报** | **主动追、补录、作废重送** |

外送报告缺失是最容易"静默失败"的场景——没人天天对账"上个月送了 100 份，回来了 98 份"。M13-06 的逾期扫描是唯一防线。

| 外送委托与物流 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ |
| 外送报告回传接收 | ❌ | ✅（文件） | ✅（解析） | ❌ | ❌ | ✅（业务登记） |

**唯一责任说明：**

- M13-06 **是**"多批结果的累积、拼装、以及跨机构委托回报"的唯一责任方
- M13-06 **不是**"单批结果的审核与推送"——那仍然是 M13-04 的职责。M13-06 把每一批登记好后，**调 M13-04 走正常审核流程**，M13-04 审完后推送 M07
- M13-06 **不是**"文件的采集与解析"——外送回来的 PDF 照样走 M13-02 采集 + M13-03 解析，M13-06 只在解析出结构后做业务登记

**为什么不做"微生物模块独立于 M13"？**

因为微生物的标本流转（采集、送检、签收）与生化免疫完全一样，走 M13-01 的标本条码体系；审核发布也完全一样，走 M13-04。独立成模块会造成"两套标本条码、两套审核流程"，护士和医生要记两套规则。**只有"跨周期组装"这一层是复用的边界外，其余全部复用。**

### 1.4 概念辨析

| 概念 | 定义 | 与本子模块关系 |
|---|---|---|
| **培养（Culture）** | 把标本接种到培养基，给微生物提供生长条件 | M13-06 跟踪其全过程 |
| **分离（Isolation）** | 从混合菌中分出单克隆菌落 | 培养阳性后的第一步 |
| **鉴定（Identification）** | 确定菌种的属、种 | 中报内容 |
| **药敏（AST, Antimicrobial Susceptibility Test）** | 测定菌株对多种抗菌药物的敏感性 | 终报内容 |
| **MIC** | 最低抑菌浓度（Minimum Inhibitory Concentration） | 药敏的定量表达 |
| **S/I/R** | 敏感（Susceptible）/ 中介（Intermediate）/ 耐药（Resistant） | 药敏的定性判读 |
| **初报（Preliminary）** | 涂片镜检结果，最早 16~24 小时 | 第一批 |
| **中报（Interim）** | 菌种鉴定结果，2~3 天 | 第二批 |
| **终报（Final）** | 鉴定 + 药敏 + 结论，3~5 天 | 第三批 |
| **补充报告（Supplementary）** | 终报后新增药敏或更正 | 可追加 |
| **阴性报告** | 培养满 5 天无生长，出"无细菌生长" | 一种终报形态 |
| **外送（Outsourced）** | 委托院外机构完成的检验 | M13-06 管委托与回报 |
| **外送机构（Reference Lab）** | 受托方 | 需资质核验 |
| **委托单（Referral Order）** | 一份外送委托，含多项目 | M13-06 生成 |
| **回报（Return）** | 外送机构返回的结果 | M13-06 接收与合并 |
| **合并（Merge）** | 把回报结果写入本院对应任务 | M13-06 的核心动作 |

**一个易混点：外送项目 vs 外送标本。**

- **外送项目**（`md_lab_item.is_outsourced=TRUE`）：这个项目本院没有能力做，永远外送。如泪液 EB 病毒 DNA。
- **外送标本**：某个项目本院能做，但这个标本特殊（如需要特殊培养条件的眼内液真菌培养），临时外送。`external_flag` 标记。

两者都会生成委托单，但前者是"常规"计划内，后者是"临时"决策外。**报表口径不同**：外送项目占比反映"本院能力短板"，临时外送占比反映"临时应变频繁度"。

### 1.5 模块目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 微生物终报及时率 | ≥ 90% | 接种后 5 天内出终报 |
| 涂片初报及时率 | ≥ 95% | 接种后 24 小时内出初报 |
| 外送报告 7 日内回收率 | ≥ 98% | 送检 7 天内回报 |
| 外送报告缺失率 | ≤ 0.2% | 逾期 15 天仍未回报 |
| 外送报告数据完整率 | ≥ 97% | 关键字段齐全 |
| 培养污染率 | ≤ 3% | 眼内标本要求更严 |
| 药敏结果录入准确率 | ≥ 99.5% | 与原始报告一致 |
| 外送委托单打印准确率 | 100% | 标本与项目必须一致 |
| 逾期自动发现时间 | ≤ 24 小时 | 从逾期到告警 |

**为什么眼内标本的污染率要求这么严？**

眼内液（房水、玻璃体）标本量极小（0.1~0.2 ml），污染意味着整份标本报废且**无法重采**（再次穿刺有视网膜脱离、眼内感染扩散风险）。普通标本污染率 3% 可接受，眼内标本的目标是 0。

## 2. 业务范围与边界

### 2.1 范围内

1. **微生物培养过程管理**
   - 接种登记（接种人、接种时刻、培养基）
   - 培养观察记录（每日观察、阳性/阴性、生长情况）
   - 培养天数追踪（第 1 天、第 2 天…）
   - 阴性自动满期判定（满 5 天无生长 → 阳性可能性终止）

2. **分批结果管理**
   - 初报（涂片/镜检）登记与发布
   - 中报（菌种鉴定）登记与发布
   - 终报（鉴定 + 药敏 + 结论）登记与发布
   - 补充报告（终报后更正或新增）
   - 每批结果的独立审核（调 M13-04）

3. **药敏结果管理**
   - 药物清单（读 M01-09 或本院配置）
   - MIC 数值 + S/I/R 判读
   - 专家规则修正（如 ESBL 阳性时某些药改判 R）
   - 药敏结果合理性校验（与菌种不匹配的药物告警）

4. **外送委托管理**
   - 委托单生成（一单可含多项目、多标本）
   - 外送机构选择与资质核验
   - 打包清单打印
   - 物流交接记录（交接人、快递单号）
   - 外送申请审批（超阈值金额或特殊项目）

5. **外送回报管理**
   - 报告回传接收（PDF 走 M13-02/03，接口直连，手工录入）
   - 结果合并到本院任务
   - 费用登记（外送成本）
   - 缺失发现与追单
   - 回报质量校验（关键字段完整性）

6. **多批结果组装**
   - 按标本维度汇总多任务多批结果
   - 生成"时间线"视图
   - 组装最终报告供 M13-04 审核
   - 版本管理（补充报告产生新版本）

7. **逾期与告警**
   - 培养超时（超承诺天数未出终报）
   - 外送回传超时（超承诺天数未回报）
   - 外送缺失（超 15 天未回报）
   - 外送机构响应超时

8. **统计报表**
   - 微生物阳性率、菌种分布、耐药率
   - 外送项目占比、外送机构分布、回报及时率
   - 外送费用统计（给 M17 财务）

| 参考区间与危急阈值 | M13-05 | 规则是通用能力 |
| 微生物项目主数据定义 | M01-09 | 主数据归 M01 |
| 抗菌药物主数据 | M01-03 | 药品归 M01 |

### 2.4 依赖清单与失败影响

| 编号 | 依赖 | 接口 | 超时 | 失败影响 | 降级策略 |
|---|---|---|---|---|---|
| D-01 | M13-01 标本与任务 | `GET /internal/v1/m13/specimens/{id}` | 2s | 无法登记结果 | **阻断** |
| D-02 | M13-04 提交审核 | `POST /internal/v1/m13/review/create` | 3s | 结果无法发布 | Celery 重试 10 次 |
| D-03 | M01-09 项目字典 | `GET /internal/v1/mdm/lab-items/{code}` | 2s | 无法校验项目 | 本地快照缓存 1h |
| D-04 | M01-03 抗菌药物 | `GET /internal/v1/mdm/drugs/{code}/brief` | 2s | 无法校验药物 | 本地快照缓存 1h |
| D-05 | M13-05 规则 | `GET /internal/v1/m13/lab-item/rule/{code}` | 1s | 无参考区间 | 降级为无标记，记 WARN |
| D-06 | M16-01 结算单 | `GET /internal/v1/m16/settlements/by-source` | 2s | 外送费用无法登记 | 补偿队列 |
| D-07 | M02-06 审计 | `POST /internal/v1/audit/record` | 1s | 审计丢失 | 异步补偿队列 |

**D-02 失败为什么要重试 10 次？**

结果已经出来了但不能发布，比"结果没出来"更让医生焦虑。重试 10 次（指数退避，累计约 2 小时）覆盖绝大多数 M13-04 短时故障。超过 2 小时转人工队列，此时大概率不是网络抖动而是接口契约变更或数据问题。

## 3. 业务模型

### 3.1 微生物培养过程模型

```
接种（D0）
   │
   ├─→ 每日观察（D1, D2, D3, D4, D5）
   │      │
   │      ├── 有生长 ──────────────────────────────┐
   │      │     │                                  │
   │      │     ├─→ 涂片镜检 ──→ 初报（D1）        │
   │      │     │                                  │
   │      │     ├─→ 分离纯化                        │
   │      │     │     │                            │
   │      │     │     ├─→ 鉴定 ──→ 中报（D2~D3）  │
   │      │     │     │                            │
   │      │     │     └─→ 药敏 ──→ 终报（D3~D5）◄─┘
   │      │     │
   │      │     └─→ 污染 ──→ 报污染（D1）──→ 建议重采
   │      │
   │      └── 无生长
   │            │
   │            └─→ 满 5 天 ──→ 阴性终报（"无细菌生长"）
   │
   └─→ 超 7 天未出结果 ──→ 培养超时告警
```

**培养状态（`culture_status`，8 态）：**

| 状态 | 中文 | 触发 | 下一状态 |
|---|---|---|---|
| `INOCULATED` | 已接种 | 技师登记接种 | `OBSERVING` |
| `OBSERVING` | 培养观察中 | 接种完成 | `POSITIVE` / `NEGATIVE_PENDING` / `CONTAMINATED` |
| `POSITIVE` | 培养阳性 | 观察发现生长 | `IDENTIFIED` |
| `IDENTIFIED` | 已鉴定 | 中报登记 | `AST_DONE` |
| `AST_DONE` | 药敏完成 | 终报登记 | `FINAL` |
| `NEGATIVE_PENDING` | 阴性待满期 | 观察无生长但未满 5 天 | `NEGATIVE` |
| `NEGATIVE` | 阴性 | 满 5 天无生长 | 终态 |
| `CONTAMINATED` | 污染 | 观察发现污染 | 终态（建议重采） |
| `FINAL` | 已出终报 | 终报审核通过 | 终态 |

**为什么 `NEGATIVE_PENDING` 要单独一个状态？**

因为"培养 2 天没长"和"培养 5 天没长"在临床上完全不同：

- 2 天没长：还不能报阴性（有些菌要 3~5 天）
- 5 天没长：可以报阴性

如果不设这个状态，技师每次观察都要人脑记"已经几天了"，且系统无法区分"还在培养"和"已可出阴性报告"。

### 3.2 结果批次模型

**四类批次（`batch_type`）：**

| 批次 | 中文 | 时机 | 典型内容 | 是否可缺省 |
|---|---|---|---|---|
| `PRELIMINARY` | 初报 | D1 | 涂片革兰染色镜检、细胞计数 | 培养阴性时无 |
| `INTERIM` | 中报 | D2~D3 | 菌种鉴定（属/种）、初步药敏 | 阴性时无 |
| `FINAL` | 终报 | D3~D5 | 完整鉴定 + 完整药敏 + 结论 | 必有 |
| `SUPPLEMENTARY` | 补充报告 | 终报后 | 新增药敏、更正鉴定、追加培养 | 可选 |

**为什么中报不是必有的？**

有些菌长得快，D1 涂片就能直接做到种（如金黄色葡萄球菌在血平板上的典型形态 + 触酶阳性 + 凝固酶阳性），中报可以省略，直接出终报。强制要求中报会让技师为了填饱流程而"造一个中报"。

**批次独立性：**

每个批次独立走 M13-04 审核流程，独立推送 M07。这带来一个重要设计问题：

> 医生在 D1 收到"涂片：革兰阳性球菌"（初报）；D4 收到"金黄色葡萄球菌，MRSA 耐药"（终报）。
>
> 这两份报告在 M07-04 的 `m07_report` 表里是两条还是一条？

**设计选择：两批结果在 M13-06 内是两条 `m13_micro_result`，但推给 M07 的是"同一份报告的两次版本更新"**——通过 `report_no` 保持一致，M07 侧表现为"同一报告被更新"（`version` 递增），医生打开报告看到的是时间线。

这个设计的实现：M13-06 在推送前调 M13-04，由 M13-04 判断"这是新报告还是已有报告的新版本"。判断依据是 M13-06 传入的 `report_key`（= `specimen_no`）。

### 3.3 药敏结果模型

```
药敏结果（一个菌株一份）
  ├── 药物 A：MIC = 0.5, 判读 = S
  ├── 药物 B：MIC > 32, 判读 = R
  ├── 药物 C：纸片扩散 18mm, 判读 = S
  └── ...
```

**药敏方法（`ast_method`，4 种）：**

| 方法 | 中文 | 结果表达 |
|---|---|---|
| `MIC` | 微量肉汤稀释/自动化 | 数值（μg/ml）+ 判读 |
| `DISK` | 纸片扩散（K-B 法） | 抑菌圈直径（mm）+ 判读 |
| `E_TEST` | E 试验 | 数值（μg/ml，梯度）+ 判读 |
| `AUTOMATED` | 自动仪器（VITEK 等） | 数值 + 判读 |

**判读结果（`interpretation`，4 种）：** `S` 敏感 / `I` 中介 / `R` 耐药 / `SDD` 剂量依赖敏感

**为什么需要 `SDD`？**

CLSI 从 2019 年起对某些肠杆菌科对头孢吡肟等引入了 SDD（Susceptible Dose-Dependent，剂量依赖敏感）——不是"中介"也不是"敏感"，而是"加大剂量则有效"。这是与 I 不同的独立判读，必须支持。

**专家规则修正（专家系统）：**

| 规则 | 触发条件 | 修正动作 |
|---|---|---|
| ESBL 阳性 | 大肠埃希菌/肺炎克雷伯菌 ESBL 表型阳性 | 所有三代头孢、氨曲南改判 R |
| MRSA | 金黄色葡萄球菌 mecA 阳性/苯唑西林 R | 所有 β-内酰胺类（除头孢洛林）改判 R |
| CRE | 碳青霉烯类耐药肠杆菌 | 碳青霉烯类改判 R，提示院感 |
| VRE | 肠球菌万古霉素 R | 氨苄西林通常同时 R |
| 诱导型克林霉素耐药 | 红霉素 R + D 试验阳性 | 克林霉素改判 R |

修正由系统自动应用，同时**保留原始判读**（`original_interpretation`）以便追溯。

**眼科最关心的药敏药物清单（青光眼过滤）：**

| 类别 | 药物 | 眼科用途 |
|---|---|---|
| β-内酰胺类 | 头孢他啶、头孢曲松、头孢呋辛 | 眼内感染首选 |
| β-内酰胺类 | 万古霉素（糖肽类） | 眼内感染（G+） |
| 氨基糖苷类 | 阿米卡星、庆大霉素 | 联合用药 |
| 喹诺酮类 | 左氧氟沙星、莫西沙星 | 表面感染 |
| 糖肽类 | 万古霉素 | 玻璃体注射 |
| 抗真菌 | 氟康唑、伏立康唑、两性霉素B | 真菌性角膜炎 |

### 3.4 外送委托模型

```
外送委托单（referral_order）
  │  一单 = 一个外送机构 + 一次物流交接
  │
  ├── 委托项 1：标本 A（玻璃体液）+ 项目 X（EBV DNA）
  ├── 委托项 2：标本 A（玻璃体液）+ 项目 Y（真菌培养）
  └── 委托项 3：标本 B（血清）+     项目 Z（IGRA）

状态机：
  DRAFT ─→ PENDING_APPROVAL ─→ APPROVED ─→ PACKED ─→ SHIPPED
                │                                        │
                └──→ REJECTED                      ──→ RECEIVED（外送机构确认收到）
                                                          │
                                                     ──→ REPORTING（出报告中）
                                                          │
                                                     ──→ PARTIALLY_RETURNED
                                                          │
                                                     ──→ RETURNED（全部回报）
                                                          │
                                                     ──→ CLOSED（结案）

  旁支：CANCELLED（未寄出前可作废）
        OVERDUE（超时限未回报，标黄色）
        MISSING（超 15 天未回报，标红色）
```

**委托单状态（11 态）：** `DRAFT` / `PENDING_APPROVAL` / `APPROVED` / `PACKED` / `SHIPPED` / `RECEIVED` / `REPORTING` / `PARTIALLY_RETURNED` / `RETURNED` / `CLOSED` / `CANCELLED`

**为什么分 `PARTIALLY_RETURNED` 与 `RETURNED`？**

一单 5 个项目可能有 3 个先回来、2 个后回来（不同项目不同周期）。如果只有 `RETURNED`，那"部分回报"状态就无法表达，逾期扫描会在明明有进展的情况下报警。

**为什么需要 `CLOSED` 而不在 `RETURNED` 终态？**

`RETURNED` 后还有结案动作：核对回报份数、登记外送费用、归档委托单。有人忘记结案，逾期扫描会一直报"未结案"。所以 `CLOSED` 是"业务完结"的显式标志，缺失的回报在 `CLOSED` 时若仍未回来，转入缺失清单。

### 3.5 外送回报模型

**三种回报方式（`return_method`）：**

| 方式 | 中文 | 典型场景 | 处理路径 |
|---|---|---|---|
| `PDF_FILE` | PDF 文件 | 机构发邮件/放共享盘 | M13-02 采集 → M13-03 解析 → M13-06 业务登记 |
| `INTERFACE` | 接口直连 | 大型连锁检验机构 | M13-06 直接调接口拉取结果 |
| `MANUAL` | 手工录入 | 电话口述/纸质邮寄 | 技师手工录入（需双人核对） |

**为什么 `MANUAL` 必须双人核对？**

手工录入是从"另一个系统/纸面"抄到"我院系统"，是整条链路里唯一"数据不经过任何自动校验"的环节。双人核对的成本是每份 1 分钟，收益是消灭最原始的人为错误——尤其在鉴定结果和药敏判读（S/R）这种一字之差的场景。

**回报数据完整性校验（7 项必检）：**

| 编号 | 检查项 | 缺失后果 |
|---|---|---|
| V-01 | 患者姓名 + 性别 + 年龄 | 无法核对身份 |
| V-02 | 标本类型 + 采集日期 | 无法核对标本 |
| V-03 | 检验项目名称 | 无法核对项目 |
| V-04 | 结果（数值/定性） | 无数据 |
| V-05 | 单位（定量项目） | 无法判读 |
| V-06 | 参考区间（定量项目） | 无法标注 |
| V-07 | 检验日期 + 报告日期 | 无法判定时效 |

**校验失败的处理：**

- 缺 V-01/V-02/V-03：**拒收**，退回外送管理员核查
- 缺 V-04：**拒收**，无结果等于没回报
- 缺 V-05/V-06：**收下但标 `incomplete=TRUE`**，推送 M07 时提示"该报告缺参考区间，无法标注异常"
- 缺 V-07：**收下并告警**，用文件的 mtime 兜底

**为什么不全部拒收？**

外送机构不会因为你拒收就立刻重发一份完整报告——实际会打电话沟通、补发。而患者可能急需这个结果。**分级处理让"关键缺失拒收、次要缺失收下标记"**，既保证数据质量又不阻塞临床。

### 3.6 多批结果组装模型

**组装流程：**

```
标本 SPLxxx（左眼玻璃体液）
  │
  ├─ 任务1：涂片革兰染色
  │    └─ 批次1（PRELIMINARY）D1 → m13_micro_result #1
  │
  ├─ 任务2：细菌培养+鉴定+药敏
  │    ├─ 批次1（PRELIMINARY）D1 → #2
  │    ├─ 批次2（INTERIM）    D2 → #3
  │    └─ 批次3（FINAL）      D4 → #4
  │
  └─ 任务3：真菌培养
       └─ 批次1（FINAL）      D7 → #5

     ↓ 组装（M13ReportAssembler）

报告 RPT0001（report_key = SPLxxx）
  ├── version 1：含 #1（D1 涂片）
  ├── version 2：含 #1 + #2 + #3（D2 中报）
  ├── version 3：含 #1 + #2 + #3 + #4（D4 细菌终报）
  └── version 4：含 #1~#5（D7 真菌终报，完整）
```

**为什么用版本而不是"一份报告只推一次"？**

因为微生物结果的价值在于"尽早知道"。如果"一份报告只推一次"，只能等到全部完成才推，医生 D1 看不到涂片结果，眼内感染患者要等 7 天。

**为什么用报告版本而不是每次推独立报告？**

因为医生端应当看到"一份完整的玻璃体液培养报告"，里面按时间线排好每次结果。如果推 5 份独立报告，医生要在列表里找"哪几条是同一个标本的"。

**版本生成的重复推送问题：**

每次追加批次都生成新版本并推送，医生会收到多次"报告更新"通知。这在微生物场景是**期望行为**——每次更新都意味着"有新的临床信息"。但要控制频率：同一报告 1 小时内多次更新合并为一次推送。

### 3.7 阴性判定模型

**培养阴性的判定规则：**

| 标本类型 | 最短培养天数 | 说明 |
|---|---|---|
| 一般细菌培养 | 3 天 | 常见病原菌 |
| 真菌培养 | 5 天 | 真菌生长慢 |
| 分枝杆菌培养 | 42 天 | 结核分枝杆菌 |
| 厌氧菌培养 | 5 天 | 严格厌氧 |
| 眼内液培养 | 5 天 | 眼科保守标准 |

**为什么眼内液要 5 天而不是 3 天？**

眼内液标本量极少、病原载量低，3 天培养阴性不能排除感染。临床经验：眼内炎患者玻璃体液培养阳性率仅 40~60%，延迟培养能提高检出。5 天是多数眼科中心的实践标准。

**阴性报告的自动生成：**

```
每天 08:00 定时任务
  FOR EACH 培养中标本
    IF 当前日期 - 接种日期 >= 该标本类型的 min_days
       AND 无任何阳性观察记录
    THEN
       生成阴性终报（"经 X 天培养无细菌生长"）
       状态置 NEGATIVE
       走正常审核发布
```

**为什么自动生成而不是技师手工出？**

每天几十份阴性报告，手工出会漏（技师忘了）或拖（攒到周末一起出）。自动生成 + 审核把关，技师只需要审核，不需要逐份填。

### 3.8 外送费用模型

**外送成本登记（4 类）：**

| 费用类型 | 说明 | 计算方式 |
|---|---|---|
| `TEST_FEE` | 检验费 | 按项目 × 单价 |
| `LOGISTICS_FEE` | 物流费 | 按单或按重量 |
| `URGENT_FEE` | 加急费 | 固定加成 |
| `OTHER_FEE` | 其他 | 手工填 |

**为什么外送成本要登记？**

外送检验的收费是收患者的（M16-01），成本是付给外送机构的（M17 财务）。两者差价是科室的成本控制空间。不登记成本，无法回答"外送业务是赚是亏"。

**成本不参与收费计算。** 收费由 M16-01 按 M01-06 收费项目价格计算，与外送成本无关。M13-06 只负责把成本数据交给 M17。

| V-17 | 初报不能包含鉴定结果与药敏 | 阻断 |

**为什么特殊耐药表型是"多选"而不是"系统自动推断"？**

系统可以从药敏结果推断部分表型（如苯唑西林 R 推断 MRSA），但有些表型需要额外实验（ESBL 需要双纸片确证试验，CRE 需要碳青霉烯酶试验）。技师手工勾选"我做了这个实验且阳性"是可靠的；系统推断只能作为"应当检查"的提示。

**为什么"修正列"要有单独说明？**

专家规则修正是"系统推翻了技师录入的判读"。如果技师可以无声无息地改，就失去了专家规则的意义；如果有说明（如"D 试验阳性"），事后追溯时能判断"这个修正对不对"。

**为什么"催单"和"登记已回复"要分开？**

- **催单**：我给外送机构打了电话/发了消息，但还没结果。这是"我在追"。
- **登记已回复**：机构告诉我"这份标本量不够，做不了"。这是"追到了，结果是失败"。

两者混在一起会让"外送及时率"指标失真——"追了但没结果"不该算作及时。

**为什么允许"标记缺失"？**

超过 15 天还没有回报，业务上必须有个了结。标记缺失后：
- 委托单可结案
- 该项目的检验任务标记为 `FAILED`（结果不可得）
- 计入缺失率统计
- 生成对外送机构的考核数据

| 外送金额 | `SUM(item_amount) + SUM(other_fee)` | 成本口径 |

**为什么"阳性率"按标本算而不是按任务算？**

一个标本可能同时送"细菌培养"和"真菌培养"两个任务。按任务算会得出"阳性率 40%"（其中细菌阳性 52 + 真菌阳性 20 = 72 / 180 任务），但按标本算才是"多少个患者感染了"（72 个任务可能只来自 52 个标本）。**临床上关心的是患者是否有感染，不是做了多少个检测。**

    async def create_culture(
        cls, user: Dict[str, Any], body: Any,
    ) -> Dict[str, Any]:
        """登记接种。"""
        db: AsyncSession = user["db"]

        # ① 幂等：同标本同项目只能接种一次
        exists = await db.scalar(
            select(func.count()).select_from(M13MicroCulture)
            .where(
                M13MicroCulture.specimen_no == body.specimen_no,
                M13MicroCulture.lab_code == body.lab_code,
                M13MicroCulture.is_deleted.is_(False)))

            raise BizException(
                "1306001", "该标本该项目的培养已存在")

        # ② 调 M13-01 校验标本
        try:
            specimen = await SpecimenClient.get(
                body.specimen_no, timeout=2.0)
        except Exception as exc:
            logger.warning(
                "M13-01 不可用", extra={
                    "module": "M13-06",
                    "specimen_no": body.specimen_no,
                    "error": str(exc)})
            raise BizException(
                "1306015", "标本服务不可用，请稍后重试")

        if specimen["status"] not in ("ACCEPTED", "COMPLETED"):
            raise BizException(
                "1306019", "标本状态不允许接种")

        # ③ 确定最短培养天数
        specimen_type = body.culture_type or "GENERAL"
        min_days = MIN_CULTURE_DAYS.get(
            specimen_type, MIN_CULTURE_DAYS["GENERAL"])

        today = date.today()
        culture = M13MicroCulture(
            culture_no=cls._next_culture_no(today),
            specimen_no=body.specimen_no,
            specimen_type=specimen_type,
            patient_id=specimen["patient_id"],

            task_no=body.task_no,

            inoculate_date=today,
            inoculate_by=user["employee_id"],
            inoculate_by_name=user["employee_name"],
            inoculate_at=datetime.now(),
            min_culture_days=min_days,
            expected_final_date=today + timedelta(days=min_days),
            is_deleted=False,

        await db.flush()

    @classmethod
    async def observe(
        cls, user: Dict[str, Any], culture_id: int,
        body: Any,
    ) -> Dict[str, Any]:
        """登记培养观察。"""
        db: AsyncSession = user["db"]
        today = date.today()

        culture = await cls._get_for_update(db, culture_id)

        # ① 状态校验
        if culture.culture_status not in (
                "INOCULATED", "OBSERVING",
                "NEGATIVE_PENDING"):
            raise BizException(
                "1306002",
                "当前状态（%s）不允许登记观察"
                % culture.culture_status)

        # ② 同日重复观察
        if culture.last_observe_date == today:
            raise BizException(
                "1306003", "今天已登记过观察")

        # ③ 记录观察
        culture.last_observe_date = today
        culture.last_observe_at = datetime.now()
        culture.last_observe_result = body.observe_result
        culture.observe_count = (culture.observe_count or 0) + 1

        if body.observe_result == "POSITIVE":
            if body.observation is None \
                    or len(body.observation.strip()) < 10:
                raise BizException(
                    "1306006",
                    "阳性观察必须填写生长描述（≥10 字）")
            culture.culture_status = "POSITIVE"
            culture.positive_date = today
            culture.positive_days = (
                today - culture.inoculate_date).days + 1
            culture.observation = body.observation
        elif body.observe_result == "NEGATIVE":
            days = (today - culture.inoculate_date).days + 1
            if days >= culture.min_culture_days:
                culture.culture_status = "NEGATIVE_PENDING"
            else:
                culture.culture_status = "OBSERVING"
        else:
            raise BizException(
                "1306002",
                "观察结果只能是 POSITIVE 或 NEGATIVE")

        await cls._log(
            db, culture_id, "OBSERVE", user,
            "观察：%s %s" % (
                body.observe_result,
                body.observation or ""))

        return {
            "culture_id": culture.id,
            "culture_status": culture.culture_status,
            "culture_days": (
                today - culture.inoculate_date).days + 1,
            "observed_at": culture.last_observe_at.strftime(
                "%Y-%m-%d %H:%M:%S"),
            "next_action": (
                "可登记初报"
                if body.observe_result == "POSITIVE"
                else "继续观察"),
        }

    @classmethod
    async def _get_for_update(
        cls, db: AsyncSession, culture_id: int,
    ) -> M13MicroCulture:
        """加行锁读取培养。"""
        row = (await db.execute(
            select(M13MicroCulture)
            .where(M13MicroCulture.id == culture_id,
                   M13MicroCulture.is_deleted.is_(False))
            .with_for_update())).scalar_one_or_none()
        if row is None:
            raise BizException("1306001", "培养记录不存在")
        return row

    @classmethod
    def _next_culture_no(cls, today: date) -> str:
        """培养编号。"""
        return "MC%s%06d" % (
            today.strftime("%Y%m%d"),
            int(datetime.now().timestamp()) % 1000000)

    @classmethod
    async def on_specimen_accepted(
        cls, payload: Dict[str, Any],
    ) -> Dict[str, Any]:
        """标本签收后自动创建培养记录。"""
        db: AsyncSession = payload["db"]
        specimen_no = payload["specimen_no"]
        tasks = payload.get("tasks", [])

        created = 0
        for task in tasks:
            lab_code = task.get("lab_code", "")
            # 只对微生物类项目创建培养记录
            if not cls._is_micro_item(lab_code):
                continue
            exists = await db.scalar(
                select(func.count())
                .select_from(M13MicroCulture)
                .where(
                    M13MicroCulture.specimen_no
                    == specimen_no,
                    M13MicroCulture.lab_code == lab_code,
                    M13MicroCulture.is_deleted.is_(False)))
            if exists:
                continue
            culture = M13MicroCulture(
                culture_no=cls._next_culture_no(
                    date.today()),
                specimen_no=specimen_no,
                specimen_type=task.get(
                    "specimen_type", "GENERAL"),
                patient_id=payload["patient_id"],
                patient_name=payload["patient_name"],
                patient_gender=payload.get("gender"),
                patient_age=payload.get("age"),
                task_no=task.get("task_no"),
                lab_code=lab_code,
                lab_name=task.get("lab_name"),
                culture_type=task.get(
                    "culture_type", "GENERAL"),
                culture_status="PENDING_INOCULATE",
                min_culture_days=MIN_CULTURE_DAYS.get(
                    task.get("culture_type", "GENERAL"), 3),
                is_deleted=False,
            )
            db.add(culture)
            created += 1

        await db.flush()
        return {"specimen_no": specimen_no,
                "created": created}

    @classmethod
    def _is_micro_item(cls, lab_code: str) -> bool:
        """判断是否微生物类项目。"""
        prefixes = ("LAB_CULTURE", "LAB_MICRO",
                    "LAB_FUNGAL", "LAB_AFB")
        return any(lab_code.startswith(p) for p in prefixes)

class MicroResultService:
    """微生物结果批次服务。"""

    @classmethod
    async def create(
        cls, user: Dict[str, Any], body: Any,
    ) -> Dict[str, Any]:
        """登记结果批次。"""
        db: AsyncSession = user["db"]
        today = date.today()

        culture = (await db.execute(
            select(M13MicroCulture)
            .where(M13MicroCulture.id == body.culture_id,
                   M13MicroCulture.is_deleted.is_(False))
            .with_for_update())).scalar_one_or_none()
        if culture is None:
            raise BizException("1306001", "培养记录不存在")
        if culture.culture_status == "CONTAMINATED":
            raise BizException(
                "1306006", "已污染的培养不可登记结果")

        # ① 批次类型推导：终报之后登记的都算补充
        batch_type = body.batch_type
        has_final = await db.scalar(
            select(func.count()).select_from(M13MicroResult)
            .where(
                M13MicroResult.culture_id == culture.id,
                M13MicroResult.batch_type == "FINAL",
                M13MicroResult.is_deleted.is_(False)))
        if has_final and batch_type != "SUPPLEMENTARY":
            batch_type = "SUPPLEMENTARY"

        # ② 初报要素
        if batch_type == "PRELIMINARY":
            if body.isolate or body.ast_results:
                raise BizException(
                    "1306008", "初报不可包含鉴定与药敏")
            if culture.culture_status not in (
                    "POSITIVE", "IDENTIFIED"):
                raise BizException(
                    "1306008", "培养未阳性不可出初报")

        # ③ 中报要素
        if batch_type == "INTERIM":
            if not body.isolate:
                raise BizException(
                    "1306008", "中报必须包含鉴定结果")

        # ④ 终报要素
        if batch_type == "FINAL":
            if not body.isolate:
                raise BizException(
                    "1306008", "终报必须包含鉴定结果")
            if not body.ast_results or \
                    len(body.ast_results) < 1:
                raise BizException(
                    "1306008", "终报必须包含至少 1 条药敏")
            if not body.conclusion or \
                    len(body.conclusion.strip()) < 20:
                raise BizException(
                    "1306014", "结论不得少于 20 字")

        # ⑤ 鉴定置信度
        if body.isolate and body.isolate.identify_confidence:
            if body.isolate.identify_confidence < 90 \
                    and not user.get("is_senior"):
                raise BizException(
                    "1306009",
                    "鉴定置信度 %.1f%% 低于 90%%，需组长复核"
                    % body.isolate.identify_confidence)

        # ⑥ 序号
        seq = await db.scalar(
            select(func.coalesce(func.max(
                M13MicroResult.batch_seq), 0))
            .where(M13MicroResult.culture_id
                   == culture.id))
        seq = (seq or 0) + 1

        result = M13MicroResult(
            result_no=cls.next_result_no(today),
            culture_id=culture.id,
            specimen_no=culture.specimen_no,
            batch_type=batch_type,
            batch_seq=seq,
            patient_id=culture.patient_id,
            patient_name=culture.patient_name,
            lab_code=culture.lab_code,
            lab_name=culture.lab_name,
            ast_method=body.ast_method,
            conclusion=body.conclusion,
            suggestion=body.suggestion,
            status="DRAFT",
            registered_by=user["employee_id"],
            registered_by_name=user["employee_name"],
            registered_at=datetime.now(),
            is_deleted=False,
        )
        db.add(result)
        await db.flush()

        # ⑦ 分离菌株
        isolate = None
        if body.isolate:
            isolate = await cls._save_isolate(
                db, culture, body.isolate, user)
            result.isolate_id = isolate.id
            result.isolate_name = isolate.isolate_name

        # ⑧ 药敏结果
        corrected = 0
        if body.ast_results:
            corrected = await cls._save_ast(
                db, result, isolate, body.ast_results, user)

        # ⑨ 更新培养状态
        if batch_type == "INTERIM":
            culture.culture_status = "IDENTIFIED"
            culture.identify_date = today
            culture.isolate_name = (
                isolate.isolate_name if isolate else None)
            result.status = "DRAFT"
        elif batch_type == "FINAL":
            culture.culture_status = "FINAL"
            culture.final_result_id = result.id

        await db.flush()

        return {
            "result_id": result.id,
            "result_no": result.result_no,
            "culture_id": culture.id,
            "batch_type": batch_type,
            "culture_status": culture.culture_status,
            "ast_count": len(body.ast_results or []),
            "corrected_count": corrected,
            "status": result.status,
        }

    @classmethod
    async def _save_ast(
        cls, db: AsyncSession, result: Any, isolate: Any,
        ast_list: List[Any], user: Dict[str, Any],
    ) -> int:
        """保存药敏结果，返回修正条数。"""
        corrected = 0
        seen = set()

        for item in ast_list:
            key = item.drug_code
            if key in seen:
                raise BizException(
                    "1306012",
                    "药物 %s 重复录入" % item.drug_name)
            seen.add(key)

            # 方法匹配校验
            if result.ast_method in ("MIC", "E_TEST",
                                     "AUTOMATED"):
                if not item.mic_value:
                    raise BizException(
                        "1306010",
                        "方法 %s 必须填写 MIC 值"
                        % result.ast_method)
            elif result.ast_method == "DISK":
                if not item.zone_diameter:
                    raise BizException(
                        "1306010",
                        "纸片法必须填写抑菌圈直径")

            # 专家规则修正
            exp = cls._apply_expert_rule(
                isolate, item)
            final_interp = item.interpretation
            if exp:
                final_interp = exp
                corrected += 1
                if not item.correction_reason:
                    item.correction_reason = (
                        "专家规则自动修正")

            ast = M13MicroAst(
                result_id=result.id,
                isolate_id=isolate.id if isolate else None,
                drug_code=item.drug_code,
                drug_name=item.drug_name,
                drug_class=item.drug_class,
                ast_method=result.ast_method,
                mic_value=item.mic_value,
                mic_unit=item.mic_unit,
                zone_diameter=item.zone_diameter,
                interpretation=final_interp,
                original_interpretation=item.interpretation,
                is_corrected=(exp is not None),
                correction_reason=item.correction_reason,
                is_deleted=False,
            )
            db.add(ast)

        return corrected

    @classmethod
    def _apply_expert_rule(
        cls, isolate: Any, ast_item: Any,
    ) -> Optional[str]:
        """应用专家规则，返回修正后的判读。"""
        if isolate is None:
            return None
        phenotypes = isolate.special_phenotypes or []
        if not phenotypes:
            return None

        for rule in EXPERT_RULES:
            if rule["phenotype"] not in phenotypes:
                continue
            if isolate.isolate_name not in rule["species"]:
                continue
            if ast_item.drug_class not in rule[
                    "drug_classes"]:
                continue
            if ast_item.drug_name in rule[
                    "exclude_drugs"]:
                continue
            return rule["force"]
        return None

    @classmethod
    async def interpret_ast(
        cls, user: Dict[str, Any], body: Any,
    ) -> Dict[str, Any]:
        """药敏判读计算。"""
        results = []
        corrected = 0
        for item in body.items:
            try:
                mic = float(
                    str(item.mic_value).replace(">", "")
                    .replace("<", "").replace("=", ""))
            except (TypeError, ValueError):
                mic = None

            if mic is None or not body.breakpoints:
                interp = item.interpretation or "I"
            else:
                interp = cls._interpret_mic(
                    mic, body.breakpoints)

            results.append({
                "drug_code": item.drug_code,
                "drug_name": item.drug_name,
                "mic_value": item.mic_value,
                "interpretation": interp,
            })

        return {
            "results": results,
            "corrected_count": corrected,
        }

    @classmethod
    def _interpret_mic(
        cls, mic: float, breakpoints: Any,
    ) -> str:
        """按折点判定 S/I/R。"""
        s_max = breakpoints.get("s_max")
        r_min = breakpoints.get("r_min")
        if s_max is not None and mic <= float(s_max):
            return "S"
        if r_min is not None and mic >= float(r_min):
            return "R"
        return "I"

    @classmethod
    async def submit(
        cls, user: Dict[str, Any], result_id: int,
    ) -> Dict[str, Any]:
        """提交结果到 M13-04 审核。"""
        db: AsyncSession = user["db"]

        result = (await db.execute(
            select(M13MicroResult)
            .where(M13MicroResult.id == result_id,
                   M13MicroResult.is_deleted.is_(False))
            .with_for_update())).scalar_one_or_none()
        if result is None:
            raise BizException("1306001", "结果批次不存在")
        if result.status not in ("DRAFT", "REJECTED"):
            raise BizException(
                "1306002", "当前状态不允许提交")

        # ① 组装报告版本
        version = await cls._next_report_version(
            db, result.specimen_no)

        # ② 调 M13-04 创建审核
        try:
            review = await ReviewClient.create(
                {
                    "report_key": result.specimen_no,
                    "report_version": version,
                    "result_id": result.id,
                    "result_no": result.result_no,
                    "batch_type": result.batch_type,
                    "patient_id": result.patient_id,
                    "specimen_no": result.specimen_no,
                    "lab_code": result.lab_code,
                    "lab_name": result.lab_name,
                    "conclusion": result.conclusion,
                    "source_module": "M13",
                    "source_sub": "M13-06",
                },
                timeout=3.0)
        except Exception as exc:
            logger.error(
                "M13-04 审核创建失败", extra={
                    "module": "M13-06",
                    "result_id": result_id,
                    "error": str(exc)})
            raise BizException(
                "1306015", "审核服务不可用，请稍后重试")

        result.status = "SUBMITTED"
        result.review_id = review["review_id"]
        result.report_version = version
        result.submitted_at = datetime.now()

        # ③ 写报告组装记录
        db.add(M13ReportAssembly(
            report_key=result.specimen_no,
            report_version=version,
            result_id=result.id,
            batch_type=result.batch_type,
            status="SUBMITTED",
            created_at=datetime.now(),
            is_deleted=False,
        ))

        return {
            "result_id": result.id,
            "status": "SUBMITTED",
            "review_id": review["review_id"],
            "report_key": result.specimen_no,
            "report_version": version,
            "submitted_at": datetime.now().strftime(
                "%Y-%m-%d %H:%M:%S"),
        }

        cls, db: AsyncSession, report_key: str,
    ) -> int:
        """下一个报告版本号。"""
        v = await db.scalar(
            select(func.coalesce(func.max(
                M13ReportAssembly.report_version), 0))
            .where(
                M13ReportAssembly.report_key == report_key,
                M13ReportAssembly.is_deleted.is_(False)))
        return (v or 0) + 1

    @classmethod
    async def on_reviewed(
        cls, result_id: int, payload: Dict[str, Any],
    ) -> Dict[str, Any]:
        """审核结果回写。"""
        db: AsyncSession = payload["db"]
        result = (await db.execute(
            select(M13MicroResult)
            .where(M13MicroResult.id == result_id)
            .with_for_update())).scalar_one_or_none()
        if result is None:
            return {"updated": False,
                    "reason": "not_found"}

        conclusion = payload.get("conclusion")
        if conclusion in ("PASS", "MODIFY"):
            result.status = "PUBLISHED"
            result.published_at = datetime.now()
            await db.execute(
                update(M13ReportAssembly)
                .where(
                    M13ReportAssembly.report_key
                    == result.specimen_no,
                    M13ReportAssembly.report_version
                    == result.report_version)
                .values(status="PUBLISHED",
                        published_at=datetime.now()))
        else:
            result.status = "REJECTED"
            result.reject_reason = payload.get(
                "opinion", "")[:500]

        return {
            "result_id": result_id,
            "status": result.status,
            "report_key": result.specimen_no,
            "report_version": result.report_version,
        }

class ReferralOrderService:
    """外送委托单服务。"""

    APPROVAL_THRESHOLD = Decimal("2000.00")

    @classmethod
    async def list_orders(
        cls, user: Dict[str, Any], status: Optional[str],
        keyword: Optional[str], page: int, page_size: int,
    ) -> Dict[str, Any]:
        """委托单列表。"""
        db: AsyncSession = user["db"]
        stmt = select(M13ReferralOrder).where(
            M13ReferralOrder.is_deleted.is_(False))
        if status:
            stmt = stmt.where(
                M13ReferralOrder.status == status)
        if keyword:
            stmt = stmt.where(or_(
                M13ReferralOrder.order_no.ilike(
                    "%%%s%%" % keyword),
                M13ReferralOrder.lab_org_name.ilike(
                    "%%%s%%" % keyword)))

        total = await db.scalar(
            select(func.count()).select_from(
                stmt.subquery()))
        rows = (await db.execute(
            stmt.order_by(
                M13ReferralOrder.created_at.desc())
            .limit(page_size)
            .offset((page - 1) * page_size))
        ).scalars().all()

        items = []
        for row in rows:
            items.append({
                "order_id": row.id,
                "order_no": row.order_no,
                "lab_org_code": row.lab_org_code,
                "lab_org_name": row.lab_org_name,
                "item_count": row.item_count,
                "returned_count": row.returned_count,
                "total_amount": float(
                    row.total_amount or 0),
                "status": row.status,
                "expected_return_date": (
                    row.expected_return_date.isoformat()
                    if row.expected_return_date else None),
                "shipped_at": (
                    row.shipped_at.strftime(
                        "%Y-%m-%d %H:%M")
                    if row.shipped_at else None),
                "created_at": row.created_at.strftime(
                    "%Y-%m-%d %H:%M"),
            })
        return {"items": items, "total": total or 0,
                "page": page, "page_size": page_size}

    @classmethod
    async def create(
        cls, user: Dict[str, Any], body: Any,
    ) -> Dict[str, Any]:
        """创建委托单。"""
        db: AsyncSession = user["db"]
        today = date.today()

        if not body.items:
            raise BizException(
                "1306018", "委托项目不得为空")

        # ① 同一标本同一项目去重
        seen = set()
        for item in body.items:
            key = (item.specimen_no, item.lab_code)
            if key in seen:
                raise BizException(
                    "1306020",
                    "标本 %s 的项目 %s 重复委托"
                    % (item.specimen_no, item.lab_code))
            seen.add(key)

        # ② 校验标本状态
        for item in body.items:
            try:
                specimen = await SpecimenClient.get(
                    item.specimen_no, timeout=2.0)
            except Exception:
                raise BizException(
                    "1306015", "标本服务不可用")
            if specimen["status"] not in (
                    "ACCEPTED", "COMPLETED"):
                raise BizException(
                    "1306019",
                    "标本 %s 未签收不可外送"
                    % item.specimen_no)

        # ③ 计算金额
        total = Decimal("0.00")
        for item in body.items:
            price = await LabItemClient.get_price(
                item.lab_code, timeout=2.0)
            total += money(
                Decimal(str(price))
                * Decimal(str(item.quantity or 1)))
        if body.is_urgent:
            total = money(total * Decimal("1.5"))

        # ④ 是否需要审批
        need_approval = total > cls.APPROVAL_THRESHOLD

        order = M13ReferralOrder(
            order_no=cls._next_order_no(today),
            lab_org_code=body.lab_org_code,
            lab_org_name=body.lab_org_name,
            is_urgent=body.is_urgent,
            transport_mode=body.transport_mode,
            item_count=len(body.items),
            returned_count=0,
            total_amount=total,
            status="DRAFT",
            expected_return_date=(
                today + timedelta(
                    days=2 if body.is_urgent else 5)),
            remark=body.remark,
            created_by=user["employee_id"],
            created_by_name=user["employee_name"],
            created_at=datetime.now(),
            is_deleted=False,
        )
        db.add(order)
        await db.flush()

        seq = 0
        for item in body.items:
            seq += 1
            price = await LabItemClient.get_price(
                item.lab_code, timeout=2.0)
            db.add(M13ReferralItem(
                order_id=order.id,
                line_no=seq,
                specimen_no=item.specimen_no,
                lab_code=item.lab_code,
                lab_name=item.lab_name,
                quantity=item.quantity or 1,
                unit_price=Decimal(str(price)),
                amount=money(
                    Decimal(str(price))
                    * Decimal(str(item.quantity or 1))),
                return_status="PENDING",
                is_deleted=False,
            ))

        await db.flush()

        return {
            "order_id": order.id,
            "order_no": order.order_no,
            "status": order.status,
            "item_count": order.item_count,
            "total_amount": float(total),
            "need_approval": need_approval,
        }

    @classmethod
    async def approve(
        cls, user: Dict[str, Any], order_id: int,
    ) -> Dict[str, Any]:
        """审批通过。"""
        db: AsyncSession = user["db"]
        order = await cls._get_for_update(db, order_id)

        if order.status != "PENDING_APPROVAL":
            raise BizException(
                "1306023", "当前状态不允许审批")
        if order.created_by == user["employee_id"]:
            raise BizException(
                "1306024", "不能审批自己提交的委托单")

        order.status = "APPROVED"
        order.approved_by = user["employee_id"]
        order.approved_by_name = user["employee_name"]
        order.approved_at = datetime.now()

        return cls._brief(order)

    @classmethod
    async def ship(
        cls, user: Dict[str, Any], order_id: int,
        tracking_no: str,
    ) -> Dict[str, Any]:
        """登记寄出。"""
        db: AsyncSession = user["db"]
        order = await cls._get_for_update(db, order_id)

        if order.status not in ("PACKED", "APPROVED"):
            raise BizException(
                "1306023", "当前状态不允许寄出")
        if not tracking_no:
            raise BizException(
                "1306023", "必须填写快递单号")

        order.status = "SHIPPED"
        order.tracking_no = tracking_no
        order.shipped_at = datetime.now()
        order.shipped_by = user["employee_id"]

        return cls._brief(order)

    @classmethod
    async def _get_for_update(
        cls, db: AsyncSession, order_id: int,
    ) -> M13ReferralOrder:
        """加锁读取委托单。"""
        row = (await db.execute(
            select(M13ReferralOrder)
            .where(M13ReferralOrder.id == order_id,
                   M13ReferralOrder.is_deleted.is_(False))
            .with_for_update())).scalar_one_or_none()
        if row is None:
            raise BizException("1306016", "委托单不存在")
        return row

    @classmethod
    def _brief(cls, order: Any) -> Dict[str, Any]:
        """委托单简要。"""
        return {
            "order_id": order.id,
            "order_no": order.order_no,
            "status": order.status,
            "item_count": order.item_count,
            "total_amount": float(order.total_amount or 0),
        }

    def _next_order_no(cls, today: date) -> str:
        """委托单号。"""
        return "RO%s%03d" % (
            today.strftime("%Y%m%d"),
            int(datetime.now().timestamp()) % 1000)

                    % item.lab_name)
            if body.return_date < order.created_at.date():

                    "1306030", "报告日期早于委托日期")
            if body.return_date > today:
                raise BizException(
                    "1306030", "报告日期不得晚于今天")

        # ③ 生成回报记录
        ret = M13ReferralReturn(
            return_no=cls._next_return_no(today),

            return_method=body.return_method,
            return_date=body.return_date,
            returned_count=len(body.items),

            operator_name=user["employee_name"],
            verifier_id=body.verifier_id,
            created_at=datetime.now(),
            is_deleted=False,
        )
        db.add(ret)
        await db.flush()

        # ④ 更新委托单进度

            order.returned_count or 0) + len(body.items)
        order.status = (
            "RETURNED"
            if order.returned_count >= order.item_count
            else "PARTIALLY_RETURNED")
        order.last_return_at = datetime.now()

            "return_id": ret.id,

            "returned_count": ret.returned_count,
            "order_status": order.status,
        }

### 6.7 专题：多批结果组装的版本一致性

微生物的"多批结果"在 M13-06 内是**多条独立记录**，在 M07-04 侧应当是**一份报告的多个版本**。这个转换必须有严格的一致性保证，否则会出现"医生看到的报告内容与记录不符"。

**一致性保证的四个机制：**

**机制一：`report_key` 是整个链路的主键。**

`report_key = specimen_no`（标本号），不随批次变化。所有批次共享同一个 `report_key`，M13-04 收到后按 `report_key` 查找已有报告：

```
M13-06 提交第 1 批 → report_key=SPL...052, version=1 → M13-04 新建报告
M13-06 提交第 2 批 → report_key=SPL...052, version=2 → M13-04 更新报告
M13-06 提交第 3 批 → report_key=SPL...052, version=3 → M13-04 更新报告
```

**机制二：版本号只增不减，由 M13-06 统一分配。**

`m13_report_assembly` 表的 `(report_key, report_version)` 唯一约束保证并发提交时不会出现两个 version=3。分配在事务内用 `SELECT MAX(version) FOR UPDATE` 完成。

**机制三：每次提交先写组装记录，再调 M13-04。**

```
BEGIN
  1. INSERT m13_report_assembly (report_key, version, result_id, status='SUBMITTING')
  2. CALL M13-04 create_review
  3. UPDATE m13_report_assembly SET status='SUBMITTED', review_id=?
COMMIT
```

如果第 2 步失败，事务回滚，组装记录不落库——不会出现"有组装记录但 M13-04 说没收到"的不一致。

**如果第 2 步成功但响应超时？**

M13-04 侧用 `report_key + report_version` 做幂等键。M13-06 重试时 M13-04 返回已有的 review_id。这是标准的"客户端超时重试"模式。

**机制四：审核通过后回写组装状态。**

M13-04 审核完成后调 `POST /internal/v1/m13/micro/results/{id}/on-reviewed`。M13-06 收到后：

- 更新 `m13_micro_result.status = 'PUBLISHED'`
- 更新 `m13_report_assembly.status = 'PUBLISHED'`
- 这两个更新在同一个事务内

**如果回写丢失？**

组装的"已发布"状态与结果的"已发布"会不一致。补正机制：每天 04:00 扫描 `status='SUBMITTED'` 且 `review_id` 非空但超过 24 小时的记录，向 M13-04 查询审核状态并对齐。

**版本一致性检查清单：**

| 检查项 | 频率 | 不一致时 |
|---|---|---|
| 组装记录数 = 结果批次数 | 每日 04:00 | 告警 + 人工核查 |
| 组装版本号连续 | 每日 04:00 | 告警（可能有并发缺陷） |
| 组装状态与结果状态一致 | 每日 04:00 | 自动对齐 + 告警 |
| M13-04 侧报告版本 = 组装最大版本 | 每日 04:00 | 告警 |

### 9.4 安全措施

**SoD-01：手工录入的双人核对。**
录入人与核对人必须是不同员工，DB 层通过约束保证（见数据结构 `ck_m13_return_double`），应用层双重校验。理由：手工录入是唯一不经自动校验的环节，单人无法自证。

**SoD-02：外送委托不能自审。**
`created_by ≠ approved_by`，DB 约束 + 服务层校验。

**SoD-03：结果登记与审核分离。**
微生物技师登记结果，M13-04 的审核医师签字。登记人不能同时是最终签发人（即使有审核权限）。

**SoD-04：外送机构资质变更需双人。**
修改外送机构资质信息需科主任 + 质控科双签。

**SC-01：外送金额脱敏。**
非财务角色查看外送清单时，金额显示为 `***`。

**SC-02：培养详情不显示患者完整证件号。**
只显示姓名 + 性别 + 年龄，与 M07 一致。

**SC-03：外送机构联系人电话部分脱敏。**
显示为 `138****5678`。

**SC-04：所有外送委托操作必须审计。**
创建、审批、寄出、回报、结案全部记审计。

**SC-05：药敏结果不可删除。**
只能通过补充报告更正，原始记录永久保留。

**SC-06：培养记录不可删除。**
只能标记污染或出阴性报告。

**SC-07：跨机构数据交换加密。**
外送接口传输必须 HTTPS + 双向认证。

**SC-08：未登录返回 `"40100"`。**

**SC-09：无权限返回 `"40300"`。**

**SC-10：手工录入附件必须可追溯。**
附件与回报记录强绑定，附件被删则回报记录失效。

**为什么外送金额要脱敏？**

外送成本是科室的成本控制信息。技师看到"这个项目外送花了 350 元"可能会影响其开单判断（"这么贵，还是不要送了"）——这不是技师该做的决策。**成本信息的可见性必须与决策权匹配**。
